06. Softmax 与交叉熵

模型输出的分数怎样变成概率，又怎样用正确答案的概率衡量预测好坏

需要的预备知识：知道指数函数 $e^x$ 和自然对数 $\ln x$ 是什么（中学数学）
整理：Joyce（@JOYCE9896）

一、从一个分类问题说起

假设我们要做一个影评分类器：输入一句影评，判断它是正面、负面还是中性。这类"从几个固定选项里选一个"的任务叫分类，几个选项叫类别。

无论模型内部多复杂，它的最后一步通常是给每个类别打一个分数。分数是任意实数，可以是正数、负数或零，越大表示模型越倾向这个类别。比如对影评"演员很用心，剧情也不拖沓"，模型给出：

类别分数
正面2.0
负面0.5
中性−1.0

这组原始分数在英文里叫 logits，课程笔记里常直接用这个词。只看分数，我们知道模型最倾向"正面"，但说不出它有多确定。2.0 比 0.5 大，大多少才算有把握？分数也没有统一的范围，换一个模型可能给出 200 和 50。

我们更想要概率：每个类别一个 0 到 1 之间的数，所有类别加起来等于 1。这样"模型认为有 79% 的可能是正面"就有了明确的含义，不同模型之间也能比较。softmax 就是把一组分数变成概率的函数。

二、Softmax：把分数变成概率

1. 两步计算

要得到概率，需要满足两个条件：每个数都不能是负的；所有数加起来等于 1。softmax 分两步分别解决这两件事。

第一步，对每个分数取指数 $e^x$。$e$ 约等于 2.718，$e^x$ 对任何实数 $x$ 都大于 0，所以负分数也会变成正数。指数函数是单调递增的，原来分数大的，取完指数后仍然大，顺序不变。

类别分数 $z$$e^z$
正面2.07.389
负面0.51.649
中性−1.00.368

第二步，每个数除以它们的总和。总和是 $7.389 + 1.649 + 0.368 = 9.406$，于是：

类别$e^z$概率 $= e^z / 9.406$
正面7.3890.786
负面1.6490.175
中性0.3680.039

三个数加起来是 1，每个都在 0 和 1 之间。模型认为这条影评有 78.6% 的概率是正面。

2. 一般公式

把上面的过程写成公式。设一共有 $K$ 个类别，模型给第 $i$ 个类别的分数是 $z_i$（$i$ 取 1 到 $K$）。softmax 输出的第 $i$ 个概率是：

$$p_i = \frac{e^{z_i}}{\sum_{j=1}^{K} e^{z_j}}$$

分母里的 $\sum_{j=1}^{K}$ 读作"对 $j$ 从 1 到 $K$ 求和"，也就是把所有类别的 $e^{z_j}$ 加起来，对应上面的 9.406。分子是当前类别自己的 $e^{z_i}$。这里用 $j$ 而不用 $i$，只是为了区分"正在算的这个类别"和"求和时遍历的所有类别"。

3. 为什么用指数，不直接除以总和

一个自然的想法是跳过指数，直接用分数除以分数之和。这样行不通，原因有两个。分数可能是负数，除完得到负的"概率"；分数之和也可能是 0，没法做除法。

指数还有一个性质：它会放大差距。分数 2.0 和 0.5 相差 1.5，取指数后 7.389 和 1.649 相差约 4.5 倍。分数差 1，概率之比就差 $e \approx 2.7$ 倍；分数差 2，概率之比差 $e^2 \approx 7.4$ 倍。所以分数最高的类别通常拿到明显更大的概率，但其他类别的概率也不会变成 0。"softmax"这个名字就来自这一点：它像取最大值（max），但给其他选项保留了一些份额，是一个"软"的最大值。

4. 只有分数之差有意义

如果把所有分数同时加上 100，变成 102.0、100.5、99.0，softmax 的结果完全不变，仍然是 0.786、0.175、0.039。原因是 $e^{z+100} = e^{z} \cdot e^{100}$，分子和分母同时乘上 $e^{100}$，约掉了。

这说明 softmax 只关心分数之间的差，不关心分数本身的大小。实际编程时会利用这一点：先把所有分数减去其中的最大值，再取指数。这样最大的指数是 $e^0 = 1$，不会因为分数太大导致 $e^z$ 超出计算机能表示的范围。PyTorch 等框架里的 softmax 已经自动做了这一步。

5. 温度

在把分数送进 softmax 之前，可以先把所有分数除以一个正数 $T$，叫温度（temperature）：

$$p_i = \frac{e^{z_i / T}}{\sum_{j} e^{z_j / T}}$$

$T = 1$ 就是普通的 softmax。用同一组分数试几个温度：

温度正面负面中性
$T = 0.5$0.9500.0470.002
$T = 1$0.7860.1750.039
$T = 2$0.5900.2790.132

温度低于 1 时，分数之差被放大，概率集中到最高的类别上；温度高于 1 时，差距被缩小，概率分布更平均。用聊天机器人时看到的"温度"参数就是这个：生成文字时温度越高，模型越可能选到概率不是最高的词，输出更多样，也更容易出错。这部分在第 14 篇"解码"里还会讲到。

三、交叉熵：给预测打分

1. 我们需要一个"错得有多离谱"的数

现在模型输出了概率，我们也知道正确答案（训练数据里每条影评都标注了类别）。训练模型需要一个数来衡量这次预测有多差，这个数叫损失（loss）。损失越小，预测越好；训练就是不断调整模型，让损失变小。下一篇会讲怎样调整，这里先决定损失怎样算。

直观上，好的预测应该给正确答案分配高概率。假设这条影评的正确答案是"正面"，模型给了 0.786，算是不错；如果模型只给了 0.039，就很差。所以损失应该只看正确答案拿到的概率，概率越高损失越小。

2. 负对数

分类任务里最常用的损失是正确类别概率的负对数：

$$\text{损失} = -\ln p_{\text{正确}}$$

$\ln$ 是以 $e$ 为底的自然对数。概率在 0 和 1 之间，它的对数是负数，前面加负号后损失就是正数。用上面的例子分别假设三个类别是正确答案：

正确答案模型给它的概率损失 $-\ln p$
正面0.7860.241
负面0.1751.741
中性0.0393.241

这个函数有几个合适的性质。概率为 1 时损失为 0，完全预测对了就没有损失。概率越接近 0，损失增长得越快，趋向无穷大：模型对正确答案"很有把握地说不可能"，会受到很重的惩罚。概率从 0.5 提高到 0.9，损失从 0.693 降到 0.105；从 0.01 提高到 0.05，损失从 4.605 降到 2.996。也就是说，把一个错得离谱的预测纠正过来，损失下降得最多。

3. 为什么是对数

选对数有一个比"性质合适"更根本的原因。训练数据有很多条，比如一万条影评。我们希望模型在每一条上都给正确答案高概率。如果把各条数据看作互相独立，模型"同时猜对全部数据"的概率是每条概率的乘积：

$$P(\text{全部猜对}) = p^{(1)} \times p^{(2)} \times \cdots \times p^{(10000)}$$

上标 $(1)$、$(2)$ 表示第几条数据。训练的目标就是让这个乘积尽量大。这个做法有个名字，叫最大似然估计。但一万个小于 1 的数相乘，结果小到计算机无法表示，会直接变成 0。对数把乘法变成加法：$\ln(ab) = \ln a + \ln b$。取对数之后，让乘积最大就等价于让每条数据的 $\ln p$ 之和最大，也就是让每条数据的 $-\ln p$ 之和最小。所以负对数损失就是最大似然估计换了一种好算的写法。实际训练时通常取平均值而不是总和，这样损失的大小不会随数据量变化。

4. 为什么叫"交叉熵"

这一小节可以跳过，不影响后面的理解。

正确答案也可以写成一个概率分布：正确类别的概率是 1，其他类别是 0。正确答案是"正面"时，这个分布是 $y = (1, 0, 0)$，叫独热（one-hot）向量。模型的预测是另一个分布 $p = (0.786, 0.175, 0.039)$。信息论里有一个衡量两个分布差异的量，叫交叉熵：

$$H(y, p) = -\sum_{i=1}^{K} y_i \ln p_i$$

因为 $y$ 只有正确类别那一项是 1，其他项都是 0，求和之后只剩下 $-\ln p_{\text{正确}}$，和上面的损失完全一样。所以分类任务里的负对数损失通常就叫交叉熵损失。

课程里还会看到 KL 散度，它也衡量两个分布的差异，和交叉熵的关系是 $H(y, p) = H(y) + \mathrm{KL}(y \,\|\, p)$。其中 $H(y)$ 只取决于正确答案，和模型无关，所以让交叉熵变小与让 KL 散度变小是同一件事。CMU 11-711 第二讲讲了这个等价关系。

四、Softmax 和交叉熵放在一起

实际训练中，softmax 和交叉熵几乎总是一起出现：分数先过 softmax 得到概率，再用交叉熵算损失。PyTorch 甚至把两步合成了一个函数 cross_entropy，直接输入分数和正确类别，输出损失。

合在一起有一个很有用的结果。训练时需要知道"每个分数变一点，损失会怎么变"，这在数学上叫损失对分数的导数（下一篇详细讲）。对 softmax 加交叉熵，这个导数的形式非常简单：

$$\frac{\partial\, \text{损失}}{\partial z_i} = p_i - y_i$$

也就是"模型给的概率"减去"正确答案的概率"。用例子算一下，正确答案是"正面"，$y = (1, 0, 0)$：

类别$p_i$$y_i$$p_i - y_i$
正面0.7861−0.214
负面0.17500.175
中性0.03900.039

导数为负，说明增大这个分数会让损失减小；导数为正，说明减小这个分数会让损失减小。所以训练会把"正面"的分数往上推，把另外两个往下压。被压得最多的是"负面"，因为它占走的概率最多。正确类别的概率已经越接近 1，$p_i - y_i$ 就越接近 0，调整幅度也越小。这个结果在下一篇手算反向传播时会再用到。

五、在语言模型里

ChatGPT 这类语言模型做的事情，从这个角度看也是分类。给定前面的文字，模型要预测下一个 token（token 是模型处理文字的基本单位，大致是一个词或词的一部分，第 9 篇会讲）。类别就是词表里的所有 token。GPT-2 的词表有 50,257 个 token，现在的模型通常在十万到二十万之间。

每生成一个位置，模型就给词表里的每个 token 打一个分数，softmax 把这几万个分数变成概率，训练时用交叉熵比较模型的预测和文本里真实出现的下一个 token。比如训练文本是"今天天气很好"，读到"今天天气很"时，正确答案是"好"，损失就是 $-\ln p(\text{好})$。一段文本有多少个位置，就有多少次这样的预测，损失取它们的平均。

论文和课程里常见的困惑度（perplexity）也来自这里：困惑度等于平均交叉熵损失的指数 $e^{\text{平均损失}}$。如果模型每一步都在 10 个 token 之间平均犹豫，每个给 0.1 的概率，损失是 $-\ln 0.1 = 2.303$，困惑度就是 $e^{2.303} = 10$。困惑度越低，模型越确定。

所以本篇讲的东西在大模型里没有任何变化，只是类别从 3 个变成了几万个。

六、小结

模型最后一层输出的是分数（logits）。softmax 先取指数让分数变正，再除以总和让它们加起来为 1，得到概率；分数之差越大，概率越悬殊，温度可以调节这种悬殊程度。交叉熵损失是正确类别概率的负对数，它等价于最大似然估计，正确答案的概率越低，惩罚越重。两者合在一起时，损失对每个分数的导数是 $p_i - y_i$，训练会推高正确类别的分数、压低其他类别。语言模型预测下一个 token 用的是同一套方法。
