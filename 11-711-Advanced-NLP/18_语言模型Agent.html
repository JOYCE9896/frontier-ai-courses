第十八讲：基于语言模型的 Agent

什么算 Agent，观察空间（文本、可访问性树、截图与标记集），动作空间（原始动作、API、自己归纳的技能），工具的类别与学习，内部状态与记忆，基准与框架，训练 Agent 基座模型的数据，从独立自主到与人协作

主讲：Zora Wang（客座讲者） · 2026 年 3 月 19 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容；录像从讲座开头几分钟之后开始，前面的引入部分依据幻灯片整理） · 主要阅读：World of Bits；WebGPT；SWE-agent；OSWorld

一、从语言模型到 Agent

这一讲由 Zora Wang（Zhiruo Wang）主讲，她的研究方向是计算机使用类 Agent，所以很多例子来自这个领域。一张图概括基于语言模型的 Agent：环境给出观察（观察空间），语言模型作为骨干，在内部状态（大致就是提示）下按 $\text{LM}(\cdot\mid\text{prompt})$ 生成动作（动作空间），动作作用于环境，如此循环。

Agent 的例子很多：数字 Agent，比如软件工程、网页导航和计算机使用（OSWorld）；具身 Agent，比如 Minecraft 里的 Voyager、交互式文本世界 ALFWorld；物理 Agent，即机器人，比如模仿动物学习敏捷运动的工作；社会 Agent，人们关心它们能否像人一样交流、达成社交目标，比如一起喝咖啡、散步。斯坦福的 Generative Agents 搭了一个小镇，模拟不同人设的 Agent 相互交往。

什么大概不算 Agent

Zora 先说明，Agent 不是二元定义，更像一个谱系，看系统有多"agentic"。Russell 和 Norvig《人工智能：一种现代方法》的定义：凡是可以看作通过传感器感知环境、通过执行器作用于环境的东西，都是 Agent。对应开头那张图里的观察空间和动作空间。

  • 检索增强生成（RAG）系统：有感知阶段，检索一堆文档，但不采取行动，模型生成输出就完了，不改变环境。仔细想，这里的环境是什么都不清楚。
  • 推理模型：只生成 token，没有环境概念，也不在环境里执行。
  • Program-of-Thought：可能算。让模型生成程序形式的推理链，程序能在解释器里执行，有执行输出，会改变变量的值，至少比文本思维链更 agentic。

有学生问：搜索 Agent 算 Agent，RAG 不算，可 RAG 也是在数据库里搜。Zora 说如果搜索 Agent 生成的是点击之类的动作，并在浏览器里执行、跳转到新页面，她会认为它很 agentic；她说的 RAG 是那种老式的两阶段固定流程，事先有一个文档池，检索器检索、生成器生成答案，只做这两步，没有开头那个循环。

Agent 的活动大致三类（Wang 等，What Are Tools Anyway?，COLM 2024）：感知，从环境收集数据或观察，即怎样设计观察空间，把状态表示得足够好、便于语言模型使用；行动，执行动作、改变环境状态，即设计怎样的动作空间能让 Agent 更有效地行动；计算，一般的计算行为，比如计算文档相似度或复杂处理，更像内部的推理或处理阶段。检索增强系统和推理模型主要落在感知和计算上。

二、观察空间

取决于环境。下面按模态举例。

1. 文本：文件

最常见的大概是编程 Agent。环境是一个大代码库，可能还有能执行代码的环境；观察用文本表示：代码文件内容，以及终端的执行输出。有工作专门优化代码的呈现方式，比如 SWE-agent 设计了一个文件查看器，每次让 Agent 看一定行数的代码，尽量提高与问题的相关性。

2. 文本：网页

网页也可以转成文本输入。动机是语言模型擅长处理文本，虽然 GPT、Claude 能接收图像，但处理得仍然很差。可以直接用 HTML；更好的是可访问性树（accessibility tree），简单说是 HTML 的简化版，保留结构化表示，去掉那些嘈杂、没什么语义信息的标签（WebArena）。即使这样，一个网页的内容还是很多，比如 Agent 只想点搜索按钮，只需关注一小块。于是有方法过滤可访问性树里的无关元素，有的用语言模型预测哪些和当前任务相关（Mind2Web），但当时并不准确，47% 的情况下会漏掉所有相关元素。现在模型能处理的上下文变长，直接看整个网页反而效果更好。

有学生问这种表示能否保留元素在页面上的空间位置关系。一般保留得不多，树结构能看出某些元素在某个大类按钮下面，但复杂布局的信息大多丢了。这不一定是坏事，很多布局只是为了方便人看，其实就是一列条目，对机器无所谓。但有时丢掉的信息很重要，比如视觉信息：在购物网站上，人决定点哪件 T 恤往往取决于图片，文本表示捕捉不到。

3. 图像：截图与标记集

图像表示很重要，但语言模型处理图像普遍很差，尤其是不能先分割出哪些区域可点击、再理解每块的意思。有工作先识别页面上所有可交互的元素，用整数之类编号，再把编号以文本形式交给语言模型，性能大幅提升，这叫标记集（Set of Marks），开源项目 browser-use 就这样做。

4. 图像：视觉定位

这是很难的任务，很多人在为它造基准、训练模型（Gou 等 2024；Xie 等 2025）。有专门测试模型在各种购物网站上定位能力的数据集，定位就是把一个文本里的实体名称对应到界面上的元素；后来扩展到电脑上的各种软件和应用，比如 Slack，任务包括文本匹配、理解整体布局、识别某些元素等。

总结：人们一般利用语言模型擅长文本的能力，尽量用文本表达一切；但会丢信息，于是也传入图像；又因为模型处理图像能力有限，还在想各种辅助办法。

三、动作空间

1. 默认动作与专门动作

常用的计算机使用动作有点击、按键或输入、滚动，这些是人在电脑上也会做的，AI 和人类共享的基础动作。幻灯片右栏列了一些有代表性的 Agent 架构在用的专门动作（来自 Zora 等的研究 How Do AI Agents Do Human Work?），相当于工具：有的很重视图像，有图像搜索、生成图像；有的很重视规划，有任务跟踪工具，先生成计划，执行过程中逐项勾掉。

2. 工具胜过原始动作

人们设计这些更复杂的工具，是因为它们比原始的低层动作更好用。例子：回答"匹兹堡今天天气如何"。只允许点击和输入，Agent 要点某个元素 ID、输入"Pittsburgh Weather"、按回车、再点击……大约 20 步；如果做的就是回答天气的 Agent，有一个专门的工具 check_weather("Pittsburgh")，只需要地点参数，调用远程服务器返回 API 输出，一步完成。某种意义上，工具把经常一起使用的一串低层动作合并起来，让任务更高效。

3. 人工设计的 API

Song 等（2024，Beyond Browsing）在网页场景里比较了 Agent 用低层浏览动作和用 API 的表现。比如在 GitLab 网站上，可以用低层动作一路点击，也可以写程序调 API 获取信息。结论：在一些网站上，用 API 的表现好得多。但这很依赖网站：GitLab、GitHub 这类面向工程师、API 维护得很完善的网站，模型能很好地调用 API 完成很多任务；购物网站、Reddit 这类视觉信息多、API 维护不好的网站，用 API 的能力很有限，这时低层动作是不错的默认选择。很自然的方案是两套动作都给，混合模式在所有网站上表现最好。

学生问这些 API 是网站原有的还是专门造的。WebArena 里的 GitLab（GitHub 的开源替代）本来就有很多 API，直接用；Reddit 的开源替代没有现成 API，研究者手写了一些。总之这些 API 都是为人类工程师造的，不是专门给 Agent 的；现在 Agent 很会写代码，概念上更像人类工程师，而绝大多数人类其实不会编程。怎样让 Agent 用这两类动作？没什么魔法：把低层动作和 API 都写成函数放进语言模型的上下文，让模型觉得需要时随便用。Reddit 上例子不多，可能只是多解对了三十来个任务，但提升很明显；还有些任务 API 只能完成一部分，必须把 API 和低层动作交替使用。

4. Agent 自己归纳技能

人工设计 API 的局限是得有人去造，网站没有现成 API 时怎么办？那就让 Agent 像人类工程师一样自己造。

  • 编程式任务（TroVE，Wang、Fried、Neubig，ICML 2024）：数学、结构化数据分析、视觉推理这类能靠生成程序解决的任务。给定自然语言问题，Agent 先根据问题背景生成一个可复用的函数，再用它写出解答。
  • 网页导航（ASI，Inducing Programmatic Skills for Agentic Tasks）：在 Reddit 类网站上，用户要"找出提到 disappointed 的评论"，没有 API 时 Agent 会做一串低层动作：点 Reports，点 By Products，在搜索框填 disappointed，点搜索按钮，回复"有 127 条评论提到 disappointed"。可以提示 Agent 把轨迹的若干片段归纳成可复用的技能，比如第三、四步变成 search_reviews(search_box_id, search_button_id, search_term)，原来的轨迹替换成更高效的代码；其他片段同样处理，比如 open_marketing_reviews()。之后的任务直接调用这些技能，轨迹更干净，只需三步左右。

成功率提高，一是不用处理一堆低层细节，比如一个字符的偏差就让整个任务失败，人和 Agent 都很难发现，封装成函数就避免了这类小错；二是效率大幅提升，步数少得多。幻灯片上的数字是准确率提高 34.8%，效率提高 27.2%。

一个具体例子来自购物网站：用户说"我刚搬家，把账单地址改成 231 Willow Way, Suite 100, Chicago, IL, 60601，再把收货地址改成 987 Sycamore Circle, Philadelphia, PA, 19102"。基线方法没有先验知识也不学技能，只能在网站里摸索，受限于上下文和理解，在这种要几十上百步的长任务里会迷路，做很多冗余步骤，耗尽步数后被迫终止。用 AWM（Agent Workflow Memory）能正确照着流程走，五步完成第一个地址；ASI 把轨迹切成几块、每块用一个函数概括：navigate_to_address_settings 一步到达地址设置页，update_address_details 一步更新账单地址，再一步更新收货地址。基线可能要三五十步还做错，有了这些工具就快得多。

再往前一步，考虑部署时用户发来的一连串任务：输入一串任务，期望最后得到一个可复用的工具箱和每个任务的解答。开始时工具箱为空；遇到没见过的任务，Agent 创建可复用工具，用它写出解答，经过验证后加入工具箱；下次遇到需要类似逻辑的任务，就从工具箱里选现有工具来用，如此循环。

归纳技能还方便人做验证。Agent 自主行动，但人仍然要负责，监督必须高效。研究让人验证两种系统的解答：不用工具的 Agent 写了一长串代码（取 2015 年和 2016 年的行，取值，算变化率，中间还有一处把 2016 写成了 2015 的错），用自建工具的 Agent 只有一行 calc_rate_of_change(df, "Vacation days", "Year", 2015, 2016)。人判断得更准，速度也快得多。

学生问这个框架里有没有人参与，比如工程师看模型的推理再造技能。这些工作里没有。技能是程序，可以执行，验证质量的好办法就是执行它，有各种方法检查技能的正确性和鲁棒性，比如这项工作采样多组"工具加解答"，用多数投票选出最可能正确的解答，再据此选工具。但实际中公司不敢完全信任自主系统，会有工程师把关。这和最近 Claude 的 Skills 很相关，它鼓励用户为自己的 Agent 写技能，那就完全没有 Agent 自主性了。另一个问题：技能只是把低层动作拼起来，还是会写新的东西？看工具多复杂。购物网站或固定的计算（比如两行数据之间的变化率），模型通常就是把常一起用的动作包起来；但编程语言还有条件和循环这些原语，比如对一百个学生在同一页面录入信息，写成一个 for 循环比写一百遍步骤容易得多。

5. 工具的类别

  • 知识获取：查询数据库、结构化数据，或者上网搜索。
  • 计算：数学场景的计算器，编程场景的 Python 解释器。
  • 与真实世界相连：语言模型的训练数据有截止日期，和 ChatGPT、Claude 聊天时它们可能不知道现在几点、今天几号。学生说 Claude 报的时间总有三小时左右的偏差，问大厂是不是每次都和真实世界交互。Zora 凭使用经验认为没有，很多场景不需要，用户也常自己提供，比如"现在是周四晚上，别长篇大论，我要交东西"；但如果是帮人管理日历的应用，每次调用都需要这个信息。
  • 扩展模态：语言模型只能处理文本，有工具让它接触图像、音频、音乐乃至更复杂的模态。
  • 专门技能的语言模型：为问答、翻译等特定任务定制的小模型。与上面几类的区别在于它们的输出不确定，计算器给确定的输出，问答和翻译则不是；需要这种更灵活的支持时，就把语言模型当作这个更大的规划"大脑"的一个工具。

学生问逻辑回归这类传统机器学习模型（比如预测某季度收入）算哪类。这个分类是自下而上的归纳，边界不清：专门预测收入的，可以算专门技能，也在做计算。另一个学生问多个工具和人的信息同时进来时，模型怎样判断谁更重要。可能隐含在模型训练里，也可以在提示里说"多关注某个工具的结果"，Zora 不记得有专门研究模型偏好哪种来源的工作；但实际部署中人的回应比其他信息重要得多，用 Agent 系统时你可以随时暂停它，即使它正在调用工具也会停下。

6. 让模型学会用工具

  • 提示与少样本：在上下文里提供工具信息。很早但很有代表性的是 Toolformer（Schick 等，NeurIPS 2023），把一些常用工具（比如问答）包起来，给出输入输出示例，在上下文里教模型使用，希望测试时模型能类似地调用。但语言模型训练数据里没见过这些工具，模型能力一般时效果更差。
  • 训练：更根本的办法是训练模型使用工具。ToolkenGPT（Hao 等，NeurIPS 2023）提出 toolken：把每个工具名当作一个单独的 token 加进词表，不按普通文本处理；训练时用大量包含工具调用的问答对，测试时模型至少见过这些例子。Zora 说不确定这种做法现在有多常用。

动作空间小结：从默认动作开始，人工设计专门 API，更可扩展的是让模型在测试时自己归纳工具；工具种类取决于应用。

四、内部状态

内部状态代表模型掌握的知识，以及在决定采取什么动作之前的内部推理过程。现有工作在所谓 Agent 记忆里通常存几类信息：

  • 事实与偏好知识：早期工作 MemGPT（Packer 等 2023）把事实信息（比如某人的生日）存进系统的工作记忆，并且允许对记忆做编辑，发现信息更新时可以改写。
  • 程序性知识：自我反思。Reflexion（Shinn 等，NeurIPS 2023）提出自我反思的范式，类似人做事的方式。以前用户提问，Agent 生成一条轨迹，评估对错就结束；现在刻意让 Agent 反思：把它自己的解答、任务指令，以及环境允许时的执行输出（比如报错或结果）一起交给语言模型，让它用文本给出推理并修改同一问题的解答，由此得到"解这类任务什么做法好、什么不好"的反思信息，一般能提升表现。
  • 程序性知识：可复用的工作流。Agent Workflow Memory（Wang 等，ICML 2025）让 Agent 归纳越来越复杂的工作流并存入记忆，像人一样。在地图网站上，从很简单的"按名称找地点"开始，逐步建立"查某地邮编"、"找 A 到 B 的路线"，最后完成更复杂的任务。

学生问：一切都停留在 token 层面，让模型在上下文里拿到足够信息，而不是微调模型来更了解你？目前讲的都是能在上下文里快速体现的改动，当然也可以改模型权重，后面会讲。

更高级的记忆设计有几个方向：分类，参照心理学文献里的情景记忆、语义记忆等概念，把它们作为偏置放进 Agent 的记忆结构，提示系统归纳特定类别的信息存入对应部分；结构，前面的记忆只是一堆文本加到输入里，有人认为大脑里的信息是结构化、相互连接的，用图之类的结构表示；模态，记住的不只是文本，还有音频、视觉，乃至气味和感受，做具身或物理 Agent 的人会关心这些。

实践中，记忆和技能一样，是创业公司的热门话题，也是实现个性化 Agent 的主要途径。Mem0 宣传的就是个性化：记住"这位用户长途航班喜欢靠窗座位"之类，在处理查询时在后台传给 Agent，让结果更贴合。Letta 提出有状态的 Agent，让 Agent 记住你以前做过什么。一个有趣的现象是记忆成了大公司争夺用户的手段：ChatGPT 先有记忆功能，后来 Claude 也有了，人们发现可以把 ChatGPT 里的记忆导出、导入 Claude。

小结：观察空间是怎样表示环境（文本如 HTML、可访问性树，图像如截图、标记集），动作空间是 Agent 怎样在环境里行动（工具使用的提示与训练，造工具与学技能），内部状态是 Agent 存什么知识、怎样做内部处理（反思、指南、工作流等）。

五、构建真实世界的 Agent

1. 基准

Agent 基准很多，覆盖网页导航、编程、规划、旅行等场景。TheAgentCompany（Xu 等 2024）包含所有组成部分：

  • 任务：一条自然语言指令。有些任务指令很长、说明得很完整，给 Agent 所需的全部信息。
  • 环境：通常最费力。这项工作模拟了工作中可能用到的各种应用：类似 Slack 的 RocketChat 收发消息、项目管理、在云端浏览文件；有些工作还模拟环境里的其他参与者，因为有的工作需要沟通；大多数 Agent 都有能执行代码的环境。
  • 评估：很多基准只看最终任务是否成功，有一组细则或可执行的验证器，在环境最终状态上运行，偶尔也在 Agent 的轨迹上检查。更复杂、需要很多中间步骤的任务会加入基于检查点的评估，在任务的多个阶段用类似的验证器，给出更细粒度的奖励，也可以用来训练。评估可以基于规则，也可以基于 LLM。

学生问模拟的同事是不是也用 LLM：大多是，但会用特定方式提示。比如处理数据文件需要从同事那里拿文件，模拟同事的角色就是在 Agent 要文件时给它；而开头那种社会 Agent 研究的目标是看 Agent 在社会里的行为是否像人，那里更自由，看交互中会涌现什么。另一个学生问 Agent 卡在某一步反复犯同样的错、从错误状态开始反思怎么办。实际中会设一个检测循环的机制，比如同一件事重复超过三次就停下，或者换一个更完整的提示，"试试别的办法，别重复前几步"。除此之外没有特别处理，一个原因是 2024 年前后 Agent 刚火时这类错误很常见，后来模型能力跟上了，模型开发者也训练了跳出循环的行为，现在少见了。

Agent 基准的类别（Zora 等 2026，How Well Does AI Agent Reflect Real-World Work?）：网页导航；信息搜寻，类似深度研究，让 Agent 回答问题；一般工作相关，类似 TheAgentCompany，写报告、分析文件；软件工程，编程 Agent；AI for science，很多是数学，也有化学、生物等新学科；小部分是社会导向，模拟社会场景。

2. 框架

商用的通用 Agent 有 Manus、ChatGPT Agent，Claude 的计算机使用、Claude Cowork 也可以算通用 Agent，都是闭源的；做研究可以用开源的，比如 OpenHands。面向编程的有 OpenHands、Claude Code。很多 Agent 创业公司和开发者提升表现的一个办法是为自己的产品场景构建专门技能，类似为 Agent 设计专门工具，比如 Manus 的专门函数调用 manus-create-react-app，以及 Skills。

3. 训练更好的 Agent 基座模型

很多人发现只从外部改上下文，效果有限，所以训练 Agent 的骨干模型也很重要。这和普通的语言模型训练有点不同：语言模型在网页文本上训练，不是为观察与动作的循环量身定制的。Agent 训练的输入有任务要求和状态观察（网页观察或代码文件内容），输出不是一段文字，而是至少包含可执行的动作，比如点击。主要障碍是很难拿到大量训练数据，也很难靠 Agent 自举，因为它们本来就做不对。几种办法：

  • 把间接的操作指南知识变成直接演示（Synatra，Ou 等，NeurIPS 2024）：有网站专门教你在现实生活里怎么做事，用语言模型合成，把它们变成 Agent 格式的训练数据，给定任务意图，合成 Agent 完成任务应走的轨迹。
  • 通过探索环境合成演示（BAGEL，Murty 等 2024；NNetNav）：不基于已有资源，而是让模型自己探索环境、积累经验，这能解决质量问题。常用做法是把 Agent 放到网页环境里随意浏览，得到动作轨迹，回头根据它做了什么标注一条自然语言任务指令，这样指令和轨迹保证对齐，再用来训练。这种基于探索的数据合成至少在较小的模型上、网页导航任务上很有效。
  • 收集人类的计算机使用演示（OpenCUA，Wang 等 2025）：做了一个记录人在电脑上点击、输入等活动的工具，让人完成各种任务，用人的演示作为标准答案训练。Zora 指出它在计算机使用之外可能有局限：网页导航上 AI 和人都只能这样操作，但很多任务，比如处理数据，人的记录可能是在表格上点点按按，上千步；能力强的 Agent 其实一步写个 Python 脚本就能正确完成。对很容易编程解决的任务，直接学人的演示未必最好。

六、从独立自主到以人为中心

以上都在优化 Agent 的独立自主能力。但 Agent 最终是给人用的，要考虑人怎样与它交互。一个信号：SWE-bench 快饱和了。2026 年 2 月 23 日有一篇文章叫"为什么 SWE-bench Verified 不再能衡量前沿编程能力"，模型成功率接近 80%；论文 2023 年底刚发布时，GPT-4 报告的数字不到 1%，进步非常快。

但高分不一定是好事：模型的回答比人类工程师的标准解冗长得多，人很难验证，不利于可验证性、可解释性和信任。对实际使用的分析发现了很多问题：有研究显示用 AI 的开发者完成同样任务反而更慢；人们普遍不信任 Agent 的输出，在调试和测试它产生的代码时有困难。Agent 能把事情自动化，人却不知道拿它的输出怎么办。Agent 按自己的方式做事，打乱了人的工作流程，对人不友好，并没有真正提高人的生产力。

以 Zora 等的研究为例：人自己做任务有一条轨迹；交给 AI 后，AI 确实做了，但你得先审查，可能还得修，而且因为执行那一步不是你做的，要额外花时间和精力理解上下文。他们提倡构建以人为中心的编程 Agent（Position: Humans are Missing from AI Coding Agent Research）：构建时追求更强的通用能力、能长时间运行的更高自主性没问题，但部署给用户时选择哪一级自主性是另一回事。用户关心：任务对齐，Agent 是否真正理解我的话，会不会做我没要求的多余动作；可控性，会不会一直跑不停、把我带到无法控制的地方；验证，输出太冗长让人消化不了，怎样只提供人能观察、相关的信息，让人更有效地与 Agent 协作；个性化，人不想反复告诉 Agent 同样的事（比如喜欢简短回答），Agent 最好记住。

缩小差距的方向：规模化地建模人；实现高效的监督；定义衡量交互的指标；走出软件工程。几个从自主走向协作的例子：

  • CowPilot（Huq 等 2025）：网页导航场景，Agent 驱动任务，人在一旁看着 Agent 的每个动作，觉得不对就暂停，甚至接手自己操作，觉得 Agent 能做完剩下的再把控制权交回。整体成功率比只有人或只有 Agent 都高。
  • Collaborative Gym（Shao 等 2024）：异步协作的 Agent，双方不必等对方完成，人可以暂停 Agent，或者让它在后台跑的同时传入新请求，背后有大量工程处理怎样把新信息同步进语言模型调用。

这个方向才刚开始，更多有意思的工作正在出现。

八、小结

基于语言模型的 Agent 通过观察感知环境、通过动作改变环境，"是不是 Agent"是一个谱系，只检索不行动的 RAG 和只生成 token 的推理模型不太算。观察空间可以是文件、HTML 或可访问性树，也可以是截图，标记集和视觉定位帮助模型理解图像。动作空间从点击、输入这类原始动作，到人工 API，再到 Agent 自己从轨迹中归纳可复用的技能，后者更准确、更高效，也更便于人验证；模型可以通过提示或训练学会用工具。内部状态包括事实与偏好记忆、自我反思和工作流记忆，记忆也是个性化产品的核心。构建真实 Agent 需要包含任务、环境和评估的基准，开源与闭源的框架，以及通过指南转化、环境探索或人类演示得到的训练数据。随着 SWE-bench 等基准接近饱和，研究重心开始转向以人为中心、能与人协作的 Agent。
