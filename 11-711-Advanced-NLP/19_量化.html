第十九讲：量化

模型为什么放不进笔记本，计算机怎样表示整数和浮点数，FP32、FP16 与 BF16，absmax 与零点量化，离群值与 LLM.int8()，GGML、GGUF 与 llama.cpp，量化感知训练与 QLoRA

主讲：Sean Welleck · 2026 年 3 月 26 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容；这节课前有小测，最后的训练部分讲得很快） · 课堂代码 · 主要阅读：LLM.int8()（Dettmers 等，2022）；QLoRA（Dettmers 等，2023）

一、动机：模型太大

这一讲既有有意思的想法，也非常实用，比如想在笔记本上跑语言模型。缩放定律告诉我们扩大参数量能换来性能，模型越来越大，带来几个困难：在各种设备上做推理（笔记本、单块 GPU），在各种设备上微调，以及预训练时在固定预算下能处理的 token 变少（模型大了，成本公式里每个 token 更贵）。

具体例子：Hugging Face 上的 Qwen3-8B 有 80 亿参数，每个参数用 16 位存储。8 位等于 1 字节，1 GB 大约十亿字节，所以存模型要 80 亿 × 2 字节 = 16 GB。推理还要存前向计算中的激活等，粗略假设需要模型权重的 1.5 倍，共 24 GB。Sean 的便宜款 MacBook Air 只有 16 GB 共享内存，推理时要么崩溃，要么根据实现开始把数据换到磁盘上，非常慢；Colab 免费的 T4 GPU 也只有 16 GB 显存，要么卸载到 CPU 内存、速度大降，更常见的是直接报内存不足。

学生问这里的内存指 GPU 的显存还是 CPU 的内存。只看存权重的话，取决于在什么设备上跑。有 GPU 就尽量把数据放在 GPU 里最快的存储上，GPU 内部还有存储层级，下一讲细讲；在 CPU 内存和 GPU 之间来回读写要付出代价。

量化的核心想法：每个权重只是一个数，用更少的位来表示它。用 4 位的话模型约 6 GB，乘 1.5 倍也能在笔记本上推理。Hugging Face 上确实有这样的版本，名字里带 bnb（bitsandbytes）和 4bit，大小 6.07 GB。

本讲先复习计算机怎样表示数，有了这套词汇再讲量化，主要讲推理时的量化，最后简单介绍训练和微调时怎样结合量化。

二、计算机怎样表示数

数据以二进制存储，一位（bit）是 0 或 1，一字节（byte）是 8 位，比如 00000000、01011001。同一串位怎样解读，取决于数的类型：无符号整数（0, 1, 2, …），有符号整数（0, −1, 1, −2, …），实数（12.34, −0.001, …）。

1. 无符号整数

每一位代表 2 的一个幂，数值是值为 1 的那些位对应的幂之和。例如：

$$1\times 2^6 + 1\times 2^4 + 1\times 2^2 + 1\times 2^1 = 64 + 16 + 4 + 2 = 86$$

U8（8 位无符号整数）能表示 0 到 $2^8 - 1 = 255$；U16 是 0 到 $2^{16}-1 = 65535$；U32 是 0 到 4,294,967,295，大约 40 亿。8 位只有 256 种取值，后面会看到，甚至能用 4 位整数存神经网络的权重，有点令人惊讶。

2. 有符号整数

最左边一位表示正负，常用的解读算法叫补码（two's complement），归结为"所有位取反再加 1"。INT8 的范围是 $[-128, 127]$，还有 INT16、INT32。和 U8 相比，绝对值范围缩小了一半。这些缩写会经常见到。

3. 浮点数

要表示任意实数需要无穷多位，所以只能约定一种协议，表示实数的一个子集，这就是浮点数。它由三部分组成：符号位、指数位、尾数位（significand，即"1.xxx"里小数点后面的部分）。可以看作以 2 为底的科学计数法：

$$\text{value} = (-1)^{\text{sign}}\times(1.\text{significand})\times 2^{\text{exponent} - \text{bias}}$$

指数按无符号整数存储，再减去一个固定的偏置（bias，比如 127），这样存的是 128 时实际指数是 1。要注意二进制的 $1.101$ 不是"一点一零一"，而是 $1 + 1\times 2^{-1} + 0\times 2^{-2} + 1\times 2^{-3}$。比如 $1.101\times 2^3 = (1 + 0.5 + 0.125)\times 8 = 13$。

完整例子：符号位 0，为正；指数位 10000001 = 129，减去偏置 127 得 2；尾数 1.011000…0：

$$1 + 0\times 2^{-1} + 1\times 2^{-2} + 1\times 2^{-3} = 1 + 0.25 + 0.125 = 1.375, \qquad 1.375\times 2^2 = 5.5$$

学生问 M4 芯片和 Intel 芯片是否都遵守这个约定。这不是宇宙固有的东西，是人约定的，硬件支持哪些数的表示可能不同。标准浮点如今普及到几乎所有硬件都支持；但后面会看到有人专门为神经网络和量化设计数的格式，比如由 NVIDIA 设计，可能只有 NVIDIA 的 GPU 支持。

4. 浮点类型

  • Float32（"全精度"）：1 位符号，8 位指数，23 位尾数。
  • Float16（"半精度"）：指数和尾数都缩减，共 16 位（5 位指数，10 位尾数）。
  • BFloat16：保持 8 位指数不变，只截短尾数（7 位）。

指数决定能表示的范围，要表示大数就需要较多指数位；尾数决定能有多精细，因为它的位对应越来越小的 2 的负幂。B 代表什么？有学生猜 big，答案是 Brain：BF16 是 Google Brain（Google 研究院里一个做了很多有影响力工作的组，现在大概已不存在）专为训练神经网络发明的，那时可能还不是语言模型，只是为了让深度学习跑起来。他们发现能表示大数非常重要，模型会让 Float16 溢出、训练崩溃，所以把位数预算更多放在指数上。代价是精度更低。Qwen3-8B 用的 16 位正是 BF16。

三、推理时的量化

1. 什么是量化

一般意义上，量化是把一个大集合（通常连续）的输入值映射到一个小集合（通常离散）的输出值。对我们来说，就是把高精度格式（如 float32）映射到低精度格式（如 INT8）。INT8 只有 −128 到 127，把 float32 塞进去听起来很冒进，但出人意料地能用。最简单的量化是四舍五入取整：$Q(x) = \text{round}(x)$。量化误差是输入值与量化值的差：$Q(1.4) = 1$，误差 0.4；$Q(0.8) = 1$，误差 0.2。

对大型 Transformer 语言模型，前馈层和注意力投影层及其矩阵乘法占了 95% 的参数、65% 到 85% 的计算（Ilharco 等 2020）。所以通常不必量化全部权重，只量化这些参与矩阵乘法的权重，就能节省很多。目标：把这些参数量化成更少的位（比如从 [b]float16 或 float32 到 INT8），并使用低位精度的矩阵乘法，从而降低内存需求，在各种设备上运行大模型推理。

2. 8 位量化：absmax

记 $X_{f16}\in\mathbb{R}^{T\times h}$ 为 FP16 输入矩阵（比如激活），$X_{i8}\in\mathbb{Z}^{T\times h}$ 为 INT8 量化后的矩阵。absmax 把输入按最大绝对值缩放到 8 位范围 $[-127, 127]$，再取整：

$$X_{i8} = \text{round}\left(\frac{127\cdot X_{f16}}{\max_{ij}\big(|X_{f16_{ij}}|\big)}\right)$$

就是在取整之前加了一个缩放因子。反量化时把公式倒过来。课堂代码演示了在小数组上量化再反量化，误差不为零但很小，即使原数组是带小数的值也是如此。第一次看到能在小数和整数之间这样来回转换，可能会觉得反直觉。

矩阵乘法：把两个矩阵各自量化，做 8 位矩阵乘法，结果累加到一个 INT32 缓冲区（两个 8 位数相乘可能超出 8 位的范围，所以要更多位的缓冲），再乘上两个矩阵的缩放因子还原：

$$XW\approx\frac{1}{s_x s_w}Z_{i32}, \qquad Z_{i32} = Q(X)Q(W)$$

更聪明一点：矩阵乘法可以拆成行与列的运算，对 $X$ 的每一行、$W$ 的每一列分别量化，各自记录缩放因子（absmax 的缩放因子就是 127 除以最大值），误差比用一个全局缩放因子更低。这叫向量级量化（vector-wise quantization），后面 LLM.int8() 论文里就用到了。代码例子里量化 $X$ 和 $W$，乘法结果先存在高位缓冲里，再按缩放因子还原成小数，均方误差不为零但相当小。

3. 8 位量化：零点

absmax 有个大缺点：它只用最大值，没有平移数据。数据很不对称时效果差，比如经过 ReLU 后的激活全是正数，absmax 缩放后用不到任何负整数，只用了低精度类型大约一半的取值。网络里有大量 ReLU 激活，而低精度的预算又这么小，当然希望用满整个范围。

零点量化（zero-point）加入平移：把最大值映射到类型的最大值 127，把最小值映射到最小值 −128，中间的范围全部用上：

$$\text{INT8} = \text{round}(s\cdot\text{FP}) + \text{offset}, \qquad s = \frac{255}{\max - \min}, \qquad \text{offset} = -\text{round}\left(\frac{255\cdot\min}{\max - \min}\right) - 128$$

反量化：$\text{FP} = (\text{INT8} - \text{offset})/s$。读阅读材料会看到零点量化、按行或按列量化这些术语，它们是早期有影响力的大模型量化方法的基础。代码例子展示了原数组、量化数组、反量化数组，以及缩放和零点，可以试着构造零点比 absmax 误差更小的例子。

4. 信息损失与离群值

无论怎么做，从 float32 映射到小集合都会损失信息，均方误差不为零。上面都是 5×5 的小矩阵，几十亿参数会不会完蛋？经验上大多数情况不会，但有一样东西会严重干扰这些方法：它们依赖用最小值和最大值做归一化，而最值对离群值极为敏感。代码例子：原数组里的值都在 0.1、3 这种量级，量化误差很小；插入一个 100，所有值都按这个异常大的最大值缩放，坍缩到很少几个低精度取值上，误差大得多。

学生问这些方法是否与架构无关，CPU、GPU 都能用、只是速度不同。是的，GPU 并行做矩阵乘法所以更快；另外 INT8 乘法需要硬件厂商或其他人实现相应算法。另一个学生问能否把重要的元素挑出来不量化，只量化其余的。这正是接下来要讲的。

四、LLM.int8()

Tim Dettmers（现在是 CMU 的教授）等人 2022 年的 LLM.int8() 是这个领域很有影响的论文。他们观察到 Transformer 语言模型的激活里有离群特征（outlier features）：某些列的值异常大。在 6.7B 及以上参数的模型里，100% 的层都有离群值，小模型里不一定有。听起来要完蛋，但虽然每一层都有，却只出现在很少的维度上，只有约 0.1% 的激活特征是离群值，所以只需在每层小心处理这些离群值。

他们的假设是：量化带来的大幅性能下降，正是这些离群特征造成的。回头看并不意外，零点量化遇到离群值就会出问题。代码例子：把某一列乘以 100 引入离群特征，均方误差变得很高；层层前向传播下来，误差会不断累积。

做法：涉及离群值的计算用高精度做，其余用低精度做，最后合并结果。具体是把矩阵乘法拆开，取出离群的列和 $W$ 中对应的行单独用 16 位计算，其余部分用 8 位向量级量化计算，再相加。

关键图：横轴是模型大小，直接量化到 8 位，模型变大到一定程度后性能骤降；处理离群值后仍然省了内存，表现与 16 位模型大致相当。表格里的零样本准确率和验证困惑度也说明了这一点，困惑度和 32 位模型基本一样。用 8 位整数表示大部分权重听起来很疯狂，经验上却行得通。表格里也能看到零点量化、向量级量化这些前面讲过的概念。

五、GGML、GGUF 与 llama.cpp

llama.cpp 在大模型刚火起来时非常流行，让人们能在笔记本上跑大模型（课上只有少数人听说过）。它由三部分组成：

  • GGML：一个做张量运算的库，相当于 PyTorch 的替代，有自己的量化方法。
  • GGUF：一种存储神经网络结构和权重的文件格式。
  • llama.cpp：用 GGML 和 GGUF 做大模型推理的库，支持多种后端，比如现代 Mac 上的 Metal、ARM CPU、CUDA GPU，并尽量高效实现。

模型发布量化版本后可以加载进 llama.cpp 运行，名字很怪，比如 Q4_K。它的量化其实比处理离群值的方法更朴素，Sean 不确定是否专门处理离群值：把权重矩阵分块，每块做零点式量化。Q4_K 的意思是：权重分成超块（super-block），每个超块 8 块，每块 32 个权重，每个权重 4 位；每块计算缩放和偏移，以 6 位的稍高精度存储。Q4_K_S 是对所有张量都用 Q4_K；Q4_K_M 对某些注意力和前馈张量的一半改用 6 位、不同块大小的格式（Q6_K）。具体描述在 llama.cpp 的一个 pull request 里，作者说不想为此写论文，只想做个工具。Sean 坦言自己也不清楚全部细节，大意是给出一个量化算法，再按在哪些权重上用什么精度做出不同变体。

这确实流行起来了：Qwen 官方团队（不是爱好者）就发布了 GGUF 版本，有 Q6_K、Q8_0 等。精度越高，存储越大，量化误差越小、性能越好。课堂代码就一行，在 Mac 上用 llama.cpp 运行这个模型。这个小模型回答得不太聪明，但速度还行。开头说这个模型在笔记本上跑不了，量化之后就能跑了。

量化成了很重要的方向，人们还在开发整数之外的新数据类型，比如 NVIDIA 随 Blackwell 架构推出的 4 位格式 NVFP4，并开发支持相应运算（比如矩阵乘法）的硬件。权衡始终存在：量化降低运行模型所需的内存，但实际中可能带来性能下降，程度取决于量化方法。

六、训练时的量化

时间不多，Sean 只简单介绍两类，有兴趣可以课后看。

  • 量化感知训练（Quantization-Aware Training，QAT）：如果知道模型之后要量化，能不能让它提前做好准备？做法是在计算图里插入人为的量化操作，在模型层中加入"量化再反量化"，然后微调。这样准备过的模型量化后效果更好（PyTorch 和 NVIDIA 的博客有介绍）。有些模型会在整个后训练中原生地这样做，比如做 INT4 量化。
  • QLoRA（Dettmers 等 2023）：用量化和内存卸载降低微调大模型所需的 GPU 显存。基座模型用 4 位存储，LoRA 适配器用更高精度；32 位的优化器状态放不进显存，就卸载到 CPU 内存，这部分会慢。细节很多也很棘手，但各种微调库里都能见到这个方法。

量化已经成为很大的研究领域，Hugging Face 的量化文档列出了许多其他方法。有几个课程项目就在做量化。

八、小结

一个 80 亿参数的 BF16 模型光权重就要 16 GB，加上推理开销放不进 16 GB 的笔记本或 T4，量化把每个权重用更少的位表示来解决这个问题。整数按 2 的幂编码，浮点数由符号、指数和尾数组成，BF16 保留 FP32 的指数位、牺牲精度换范围。absmax 按最大绝对值缩放到 INT8，零点量化再加平移以用满范围；按行、按列分别量化误差更小。量化依赖最值，对离群值很敏感，而大模型的激活里有系统性的离群特征，LLM.int8() 把这约 0.1% 的离群维度用 16 位计算、其余用 8 位，保住了性能。llama.cpp 用分块的 k-quants 和 GGUF 格式让模型能在笔记本上运行。训练端有量化感知训练，以及用 4 位基座加适配器做微调的 QLoRA。
