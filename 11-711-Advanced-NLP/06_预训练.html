第六讲：预训练

先预训练再适配，掩码语言模型与 BERT，自回归预训练为什么是在拟合分布、也是在学压缩，GPT-2 与 LLaMA，预训练中的评估，网页数据的抽取、过滤、去重与配比，以及 Adam 优化器

主讲：Sean Welleck · 2026 年 1 月 29 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容） · 课堂代码 · 主要阅读：GPT-2 论文（Radford 等，2019）；FineWeb（Penedo 等，2024）

一、从"一个模型一个任务"到"预训练再适配"

到目前为止，课堂代码都是从零训练模型，一个模型只做一件事，比如生成人名、给影评分类。现在 NLP 和很多领域换了一种范式：先预训练一个模型，再把它适配到很多任务上。

流程是：收集尽可能多的数据，用某种预训练算法得到一个模型。有人叫它基础模型（foundation model），Sean 叫它 base model。然后把它适配到情感分析、翻译、对话、指令遵循、解题等任务上。适配主要有两种方式：

  • 提示（下一讲）：不训练，只在输入里描述任务。比如"把这句话翻译成英文：この映画が嫌い"。五到七年前，这听起来不可思议；令人意外的就是，预训练大模型之后，模型获得了零样本或少样本地完成各种任务的能力，只需要提示里的那一点数据。
  • 微调（第 8 讲）：从基础模型出发，用任务数据（比如日英句对）更新参数，得到一个更擅长这个任务的模型。第 8 讲还会讲指令微调，一种通用的微调方式。

为了说明这一讲在全局中的位置，Sean 展示了 AI2（一个非营利机构）2025 年 12 月发布的 OLMo 3 的训练流程。AI2 公开模型权重、数据和一篇很长的论文，能让人看清训练一个大语言模型的全部细节。现在的训练是多阶段的：预训练、中期训练（mid-training）、监督微调、各种强化学习或偏好优化。预训练是第一阶段，结束时模型在一组评测上的得分已经明显高于零（约 65），后续阶段再逐步提升。预训练给了模型广泛的知识基础，是后续一切的起点。

为什么要预训练

  • 迁移学习：机器学习里的经典思想，在一个任务上学到的"知识"可以用到另一个任务上。预训练任务很通用，学到的表示可以迁移到下游任务。
  • 需要更少的任务数据：达到同样的效果，需要的标注数据更少，比如日英句对，这类数据往往难收集。
  • 更好的任务表现：同样多的数据，预训练过的模型能达到比从零训练更高的水平。
  • 一个模型多种用途：预训练很贵，大公司做一次要花几百万美元；但如果适配到每个任务都很便宜（数据少，甚至只要提示），摊下来反而省钱，不用为每个任务从头训练。它也是做研究、做项目的好起点。

区分各个模型的四个因素

BERT、GPT-3、Llama、DeepSeek-V3、OLMo……它们主要在四个方面不同：

  • 架构：现在大多是 Transformer，但细节不同，比如前置还是后置归一化、是否用分组查询注意力，或者在注意力机制上有所创新。
  • 任务：模型预测什么。BERT 是掩码语言模型，其他大多是用下一个 token 预测训练的自回归模型。
  • 数据：各公司花大量精力构建比竞争对手更好的数据集，这直接导致模型不同。
  • 超参数：学习率、学习率调度、批大小等。大规模训练时，代码怎样实现、怎样在上千张 GPU 上并行，都会影响最终模型。人们会做大量实验，预测最终那次大规模训练的最优超参数。

有学生问 DeepSeek 为什么效率高那么多。Sean 说这四个因素每一个都像冰山，往下看有很多细节。比如架构上还有混合专家模型，可能更省数据；并行方式也会影响结果。后面讲混合专家时会回头看 DeepSeek 的架构。

二、掩码语言模型

1. 任务

2018 年前后大规模使用的预训练任务是掩码语言建模（Masked Language Modeling，MLM）：把序列里随机一些 token 换成 [MASK]，让模型预测被遮住的是什么。比如 "The cat [M] on the [M]"，预测 sat 和 mat。直觉上，在整个互联网的文本上做这件事，模型被迫学到很多有用的东西：即使是这个简单例子，它也要学会 "the" 该怎么用；如果句子是"美国总统是 [MASK]"，见得多了，总统是谁的信息就会存进模型的表示里。

有学生确认：这不是预测下一个 token，而是找回缺失的 token。另一个学生问能否往回看：可以，模型是双向的，任何位置都能关注其他任何位置，被遮住的 token 之间也可以相互关注。

$$\mathcal{L}_{\text{MLM}}(\theta; D) = -\frac{1}{|D|}\sum_{x\in D}\mathbb{E}_{M\sim\text{corrupt}(x)}\sum_{t\in M}\log p_\theta(x_t\mid x_{\neg M})$$

对每个样本 $x$，用某种方式把它"损坏"（加 [MASK]），有很多种损坏方式，所以写成期望；然后对每个被遮住的位置 $t \in M$，根据未被遮住的部分 $x_{\neg M}$ 预测它。可以把它看作一种去噪（denoising）：先加噪声，再重建。去噪是机器学习和生成模型里很多学习目标背后的经典思想。

它看起来像最大似然，但不一样：自回归模型看的是前面的位置，满足链式法则的分解；这里给模型的是一个被遮住的序列，不保证在对整个序列的联合概率建模。所以这个损失叫伪似然（pseudo-likelihood）。

2. BERT

真正让这个思路在 NLP 里流行、并引发范式转变的是 BERT（Devlin 等 2018）。架构是 Transformer，双向注意力（和自回归模型的因果注意力不同）；数据是 BooksCorpus 加英文维基百科，在当时算很大的数据量；任务是掩码语言建模。输入是成对的两个句子，因为当时很多任务都是两句话的形式，比如自然语言推断：判断句子 1 和句子 2 是矛盾还是蕴含。他们加了特殊 token：开头的 [CLS]，句子之间和结尾的 [SEP]。

遮盖方式：随机选 15% 的位置，其中 80% 换成 [MASK]，10% 换成随机 token，10% 保持不变，都要预测原来的 token。后两种的理由是：如果只遮住再预测，模型知道哪些位置被遮了；换成随机词或保持原样，迫使模型去判断一个看起来正常的 token 到底是真的，还是噪声。这类细节后来很多人试过，比例可以调整，有些可能并不必要，实际中是靠实验选出效果最好的配置。

3. 怎么用

掩码语言模型不擅长生成文本：它没有一致的生成顺序，自回归模型可以从空序列出发一个个往后生成，而掩码模型的训练顺序是随机的。有论文尝试用它生成，但长期看没有胜过从左到右的模型。（讲扩散时会提到，目前在文本上能用的扩散方法看起来和掩码语言模型很像，只是加噪过程能让模型见到各种程度的遮盖。）

它真正的用途是微调。把它当作特征提取器：加一个输出层，把某个最终隐藏向量映射成分数。惯例是用 [CLS] 位置的向量，因为注意力是双向的，每个 token 都看过其他所有 token。然后用带标签的数据（比如影评和正面、中性、负面三类标签），以 BERT 初始化，最小化交叉熵，只训练输出层 $W$ 或者训练所有权重。微调的意思是：预训练之后不重置权重，接着训练。

论文结果和之前的最好方法、OpenAI 第一代 GPT、基于 LSTM 的预训练方法相比，带来了很大的提升，有些任务上甚至超过了专门为该任务设计的方法。此前常见做法是为每个任务从零训练模型；BERT 之后，领域转向"预训练模型加少量微调"。BERT 现在仍然有用，尤其是训练分类器：示例代码很多，还有在科学文本等领域数据上训练的版本。只是现在大量精力投在自回归模型上，它们见过的数据多得多，往往更有优势。

有学生问为什么用 [CLS] 而不用别的位置。Sean 说这个问题总有人问，他没有好答案。一个可能的解释是：训练时 [CLS] 从来不承担任何损失，它的最终表示没有被训练去做某个特定任务（比如预测缺失词），也许留有一些额外的容量。

三、自回归预训练

根据前面的 token 预测下一个 token，损失就是最大似然：

$$\mathcal{L}_{\text{MLE}}(\theta; D) = -\sum_{x\in D}\sum_{t=1}^{|x|}\log p_\theta(x_t\mid x_{<t})$$

在整个互联网的文本上做这件事，可以从两个角度理解它在做什么。

1. 拟合数据分布

这是第三次看到这个推导，Sean 说他很喜欢它。把产生互联网所有文本的过程看作一个数据分布 $p^*$。最小化 $D_{KL}(p^*\|p_\theta)$，展开、去掉常数项，得到 $-\mathbb{E}_{x\sim p^*}\log p_\theta(x)$，再用数据集的样本平均近似，就是最大似然。误差来源有两个：用有限的数据集近似期望；模型表达力不够，比如参数太少或架构不合适（上次漏讲了这一点）。所以预测下一个 token，就是在拟合一个极其复杂的数据分布。

重排一下三个量的关系：

$$H(p^*, p_\theta) = D_{KL}(p^*\,\|\,p_\theta) + H(p^*)$$

交叉熵（损失）等于 KL 散度加上数据分布的熵。即使模型完美，$p_\theta = p^*$，KL 为零，交叉熵损失也不会为零，而是等于数据本身的熵。所以熵常被称为不可约损失（irreducible loss），KL 是可约损失（reducible loss）。下一讲的缩放定律论文喜欢用这些说法。

2. 学习压缩

信息论里的经典问题：要把来自某个分布的数据压缩成 0 和 1 组成的二进制串，$c(x_{1:n}) \to \{0,1\}^*$，这个映射叫编码，目标是期望编码长度最短。有一种技术叫算术编码（arithmetic coding），能把一个自回归模型变成编码：大致是把下一个 token 的分布排好序、划分区间，看数据里的那个 token 落在哪个区间，用 0 和 1 标识它。课上有意不讲细节，也不考，感兴趣可以读 DeepMind 的论文《Language Modeling Is Compression》（Delétang 等）。

Shannon 1948 年的经典结论：最短的期望编码长度等于数据分布的熵 $H(p^*) = \mathbb{E}_{x\sim p^*}\big[-\sum_i\log_2 p^*(x_i\mid x_{<i})\big]$。用一个不完美的模型 $p_\theta$ 做算术编码，期望编码长度是交叉熵 $H(p^*, p_\theta)$。由上面的关系式，要达到最优压缩，就要最小化 KL 散度，而这就是最大似然在做的事。所以训练语言模型预测下一个 token，就是在学一个越来越好的压缩器。

这给了一些直觉：怎样压缩数据最高效？如果数据里有大量规律，学到底层的规律就能简洁地表示数据；如果是算法性的数据，比如一大堆加法题和答案，最高效的压缩可能就是学会加法算法本身。这些都只是直觉，但提供了一种理解在海量语料上预训练到底在做什么的方式。

四、两个例子：GPT-2 与 LLaMA

从损失函数可以看出能改的东西：更好的架构，更多的数据（数据集是对整个分布的近似），不同的训练数据（改变模型要拟合的分布），以及优化用的超参数。数据很关键：它决定模型拟合什么分布，而且多半越多越好。

1. GPT-2

OpenAI 2019 年的 GPT-2：1.5B 参数的 Transformer（当时算很大），在 WebText（数百万个网页）上训练。有意思的是它能零样本完成很多任务：在提示里描述任务，让模型生成答案。最小的模型就超过了此前的最好结果，而且模型越大越好。为什么能零样本？论文展示了预训练数据里自然出现的例子，比如一段英文文章里写"他们用法语写了……，意思是……"。互联网上的数据如此之多，以至于包含了下游任务的有用信号。这自然引出了问题：继续加大模型、加多数据会怎样？由此进入了大语言模型的时代。

2. LLaMA

几年后 Meta 的 LLaMA：模型有 6.7B、13B、32B、65B 几种，训练数据达 1.4 万亿 token，来源包括 Common Crawl 和 C4（网页数据）、代码、维基百科、arXiv、Stack Exchange 等。

训练损失曲线上能看到几点。有学生指出：从 33B 到 65B 参数翻倍，损失的改善不像从 7B 往上那样明显，规模扩大可能有收益递减，下一讲会讲。所有模型都是训练的 token 越多损失越低；末尾看似趋平，可能只是因为学习率被退火到零。还有损失尖峰（loss spike）：大规模训练时会出现，甚至导致训练崩溃，需要留意，有时甚至据此选择超参数。

五、预训练过程中怎样评估

  • 损失（训练、验证、测试）：诊断训练轨迹，比较同一系列的模型，比如大模型比小模型好，或者两版预训练数据哪版在验证集上损失更低。
  • 少样本提示：训练过程中要频繁评估，所以要便宜。GPT-3 论文的做法是在提示里放几个翻译示例，最后放测试输入，让模型续写。这样不用微调就能在很多任务上评估。
  • 微调：更贵。

LLaMA 的少样本表现随训练推进总体在提升，但比损失曲线更嘈杂：比如 33B 和 65B 很接近，差别可能不显著。下游任务准确率上，损失更好的模型有时持平甚至更差。但总体上，语言建模损失和大量下游任务是相关的，这也是在海量多样数据上预训练的理由之一。

怎样选评估任务：OLMo 3 的做法

看大量模型在大量基准上的结果，如果两个任务对模型的排序很相似（比如两个代码数据集），就把它们归为一类。对这些排序做聚类，重要的任务类别自动浮现出来：代码、数学、中间填空（FIM）、多项选择、问答。评估集里每类挑几个，不必跑全部任务。

他们还把任务分成两组。预训练要在小规模上做大量实验（数据、超参数），所以需要一组"简单"任务，在小模型上就能给出好信号：用更多计算训练的模型应该得分更高，好任务能反映这一点；同时它们要能代表真实的下游任务，大模型上的排序和真实任务一致。另一组是真正关心的下游任务，小模型上都是零分，没有信号，只在较大的模型上评估。整个流程每个阶段都很复杂。

实用工具：Hugging Face 是集中下载预训练模型的地方，提供分词器和模型的统一代码接口，课堂代码里有加载示例。

六、预训练数据

数据要考虑三方面：数量（有多少）、质量（对训练有没有帮助）、覆盖面（是否覆盖了关心的领域，比例是否合适）。

1. 数量

预训练数据集越来越大：LLaMA 1 是 1.4 万亿 token，LLaMA 2 是 1.8 万亿，LLaMA 3 是 15 万亿。作为参照，整个维基百科不到 100 亿 token。这么多数据主要来自网页。大公司可能自己写爬虫，一般人可以用 Common Crawl：一个非营利机构定期爬取互联网并公开的快照。这些数据质量很低：大量噪声和重复，全是 HTML，可能夹着 base64 编码的图片。所以要做抽取、过滤、去重。

2. 抽取

从 HTML 得到文本：去掉每个页面都有的样板内容（boilerplate），我们不想让模型学 HTML。对数学数据要小心保留 LaTeX、代码等。早期语言模型没注意这一点，数学公式被转成了乱七八糟的文本，这也许是它们面对用 LaTeX 写的数学题表现很差的原因之一。OpenWebMath（Paster 等 2023）显示，定制的抽取方式比默认方式能带来更好的模型；FineWeb（Penedo 等 2024，本讲阅读）也显示抽取方式会影响最终模型质量。

3. 过滤

过滤掉不想要的文本：识别语言（不同公司面向不同语言，至少要知道各语言的占比），重复的文本，短行太多的页面，空文档，等等。这些底层过滤规则同样能带来更好的模型。

4. 去重

Common Crawl 在不同时间拍快照，每次有新页面，也会漏掉一些页面；起初想用尽可能多的数据，但快照之间、页面之间有大量重复内容。去重先要定义什么算重复：两篇文档完全一样？还是有一段 2000 个 token 的子串相同？然后要有能在这个规模上找出重复的算法，常用的是 MinHash，一种模糊的近似方法，几乎出现在每个去重流程里。去重也会影响模型质量。去得太狠可能有害：FineWeb 发现按快照分别去重比全局去重更好。课堂代码里可以直接浏览 AI2 的预训练数据 Dolma。

5. 覆盖面与分类器过滤

数据决定了数据分布，也就决定了模型 $p_\theta \approx p_{\text{data}}$。网页数据和数学数据、教育数据、代码数据都不一样，决定数据的配比很重要。常用技术是分类器过滤：训练一个分类器识别想要的数据，过滤掉不想要的。难点在于怎样拿到训练分类器的标签。

  • OpenWebMath：为了得到"是否是数学内容"的标签，他们把文档里的 LaTeX 全删掉，让分类器预测原文有没有 LaTeX。模型必须看上下文来判断，这是"是不是数学"的一个好代理。由此得到 MathScore 分类器。
  • FineWeb-Edu：提示一个语言模型，判断约 50 万个网页是否有教育价值（比如打 1 到 5 分），用这些标签训练一个又快又高效的分类器，再在 15 万亿 token 的 FineWeb 上运行，筛出 1.4 万亿 token 的 FineWeb-Edu。分类器必须快，因为要在整个数据集上跑。只用教育数据训练，达到同样效果所需的 token 远少于通用数据。

6. 配比

策略不是只用教育数据，而是构建各种专门子集，再按比例混合成预训练语料。OLMo 3 的语料包括 Common Crawl、科学 PDF、arXiv、数学网页等，每类有一个百分比。怎样选比例？先把文档按主题和质量分类；用不同的随机配比训练很多小模型；对每个评估任务拟合一个回归模型，输入配比、预测任务表现；然后在约束下（token 预算、每份数据最多重复几次）求解平均表现最好的配比；上采样时偏向高质量文档。这样优化出的配比确实带来提升。

学生问了两个问题。怎样避免训练数据里混进 AI 生成的文本？要么不避免，甚至有意加入 AI 生成的数据；要么训练一个分类器检测并过滤，又是一个分类问题。数据的日期呢？这很重要：要决定模型的截止日期，也就是语料里最新的日期，以及语料中日期的分布。

七、Adam 优化器

作业里要实现 AdamW，Adam 的一个变体。Adam 是目前最流行的优化器之一，每个参数在某种意义上有自己的学习率。它结合了两个已有方法的思想：

  • 动量（momentum）：SGD 用当前梯度更新，动量换成过去梯度的滑动平均：$m_t = \beta_1 m_{t-1} + (1-\beta_1)\nabla_\theta$，$\theta_{t+1} = \theta_t - \alpha m_t$。梯度来回振荡时，滑动平均把振荡平滑掉，训练更稳定，也能在多次更新间平滑噪声。$m_t$ 是对 $\mathbb{E}[\nabla_\theta]$ 的滑动估计，$\beta_1 = 0$ 时就是普通 SGD。
  • RMSProp：按梯度大小归一化更新幅度。维护梯度平方的滑动平均 $v_t = \beta_2 v_{t-1} + (1-\beta_2)(\nabla_\theta)^2$，用 $\theta_{t+1} = \theta_t - \frac{\alpha}{\sqrt{v_t}+\epsilon}\nabla_\theta$ 更新。梯度平方大，步子变小；小，步子变大。这避免了某次更新过大，也让训练更稳定。RMSProp 据说是 Geoffrey Hinton 在课上提出的，从没发表过论文。

Adam 把两者合起来。还有一点：训练开始时 $m$ 和 $v$ 初始化为零，前期的估计会被人为地拉小，Adam 论文对此做了偏差修正：

$$\hat m_t = \frac{m_t}{1-\beta_1^t}, \qquad \hat v_t = \frac{v_t}{1-\beta_2^t}, \qquad \theta_t = \theta_{t-1} - \frac{\eta}{\sqrt{\hat v_t}+\epsilon}\,\hat m_t$$

要强调的是，$m$ 和 $v$ 对每个参数各有一个值，相当于给每个参数单独归一化更新。在一个数值例子里，Adam、动量和 SGD 的优化轨迹明显不同。作业里实现的 AdamW 只是略有差别，它就是训练很多大语言模型的算法。

九、小结

现在的范式是先在海量数据上预训练一个基础模型，再通过提示或微调适配到各种任务；这样需要的任务数据更少、效果更好，成本也摊薄了。模型由架构、任务、数据、超参数四个因素决定。掩码语言模型（BERT）预测被遮住的 token，优化的是伪似然，适合微调做分类，不擅长生成。自回归预训练用最大似然预测下一个 token，等价于拟合数据分布，也等价于学一个更好的压缩器；损失的下限是数据本身的熵。从 GPT-2 到 LLaMA，模型和数据都在扩大。训练中用损失、少样本提示来评估，任务要按排序相似性分类、并区分小规模信号任务和真实任务。数据来自网页，要经过抽取、过滤、去重，再用分类器筛出数学、教育等子集，按优化出的比例混合。Adam 结合动量和 RMSProp，为每个参数自适应地调整步长。
