第二十一讲：混合专家模型

用稀疏激活在不增加每样本计算的前提下扩大参数量，专家放在哪、要多少、细粒度专家与共享专家，top-k 词元选择路由与专家选择路由，负载均衡损失与 z-loss，专家并行，稀疏升级，DeepSeekMoE 与 OLMoE

主讲：Sean Welleck · 2026 年 4 月 2 日
资料来源：课程幻灯片（参考斯坦福 CS336 2025 年春第 4 讲） · 课堂录像（本文依据录像字幕整理课堂口述内容） · 主要阅读：A Review of Sparse Expert Models in Deep Learning（Fedus 等，2022）；OLMoE（AI2，2025）；DeepSeekMoE（2024）

一、核心想法：稀疏

这一讲回到架构，同时延续规模化的主题：混合专家（Mixture of Experts，MoE）在扩大参数量时有很好的性质。听到"混合专家"，你可能想到多个语言模型、从中挑一个。在现代语言模型里不是这样：只有一个模型，把 Transformer 每个块里的前馈网络（FFN）换成一种新的层。新层里有多个 FFN 副本（比如 FFN1 到 FFN4），并且对每个输入选出其中一个或多个来用（Fedus 等 2022）。

它利用的关键概念是稀疏（sparsity）。稀疏向量里大部分元素为零，只有少数非零或"活跃"。对网络参数而言，就是训练和推理做前向、反向时，只有一部分参数参与计算（活跃），其余不参与（不活跃）。于是可以把总参数量扩得很大，只要实现得当，训练或推理时活跃的只是一小部分，所需的显存等也小得多。

为什么值得用

  • 新的扩展维度：以前把模型从 7B 扩到 50B，每个样本的前向计算也随之增加；MoE 可以扩大参数量、同时保持每样本 FLOPs 不变。专家数从 1 增加到 2 再到 256，每样本 FLOPs 不变，测试损失越来越低；Switch Transformer 与参数量相近的 T5-Base 相比，专家越多表现越好。
  • 达到同等性能所需的 FLOPs 更少：AI2 的开放 MoE 模型 OLMoE 公开了所有细节并做了大量消融，本讲会反复引用。预训练到 1300 亿 token 时，MoE 比稠密架构更快达到更低的测试损失。
  • 训练更快：有人会担心 MoE 实现起来很慢，按计算量算省了，实际时间却没省。Fedus 等的图横轴是墙钟时间，只要实现得好（比如下面的专家并行），实际训练时间也更短。
  • 推理成本与性能的权衡更好：总参数必须存下来，但推理时只激活一小部分，所需的激活显存等远小于总参数对应的量。拿 MoE 模型和同等活跃参数的稠密模型比，几乎不公平，MoE 好得多（DeepSeek、Mistral 的图）。OLMoE 总共 7B 参数、活跃 1B，比 1B 的稠密模型好得多，在给定 FLOPs 预算下也比 7B 稠密模型好。
  • 顶尖模型都在用：gpt-oss、Qwen3，以及 2025 年 11 月 18 日发布的 Gemini 3 Pro（Sean 去年做这一讲当天发布，标明用了稀疏 MoE）。Qwen3-30B-A3B 这类名字的意思是总参数 30B、活跃（A）参数 3B。

学生问那张图里 1B 和 7B 是什么：底下两个是普通的稠密 Transformer，上面的 MoE 总参数 7B，前向时只选其中 1B 来用。另一个学生问活跃参数是平均值还是严格规则：用 top-k 选专家，比如 $k = 1$，就可以按总参数除以专家数算出活跃参数。

可能的缺点

回顾历史，有大量论文，长期以来 MoE 很难训练，尤其难以大规模训练；2017 年和 2022 年两篇 Google 论文之所以影响大，就是找到了能扩展的配方。原因在于系统更复杂：要协调专家的使用；需要新的损失和新的超参数（每次选几个、总共多少个专家）；要管理大量设备来存放全部参数，需要新的并行策略；训练可能不稳定、很棘手。现在可以事后回看什么有效，本讲会列出各种设计选择，并说明主流做法，缩小搜索空间。

学生问这是否依赖硬件，比如用 CUDA 和别的架构做法不同。可以在不同抽象层次上优化：比如确保各设备之间专家使用均匀，这是设备层面的，与设备如何实现无关；也肯定有针对特定硬件的更底层优化。

二、MoE 层是什么

这个思想更一般：2017 年的论文引用了 2013 年的工作，那时还没有 Transformer，指的是拥有大量参数、每次只路由到一小部分的概念。在当今语言模型里，指的是 Transformer 块里的前馈层。标准 Transformer 层：

$$\tilde h_{1:T} = \text{Attn}(h_{1:T}) + h_{1:T}, \qquad h'_{1:T} = \text{FFN}(\tilde h_{1:T}) + \tilde h_{1:T}$$

MoE 层把 $\text{FFN}(\tilde h_{1:T})$ 换成 $\text{MoE}(\tilde h_{1:T})$：

$$h'_{1:T} = \text{MoE}(\tilde h_{1:T}) + \tilde h_{1:T}$$

MoE 内部有若干前馈网络 $\text{FFN}_1, \dots, \text{FFN}_N$，称为专家，各有独立参数 $\theta_1, \dots, \theta_N$，所以参数量确实增加了；还有一个带参数的路由器（router），为每个输入选择一个或多个 FFN，把输出组合起来。

三、专家的设计

1. 放在哪里

主要放在前馈层。也有人在注意力层试过，但可能不稳定。前馈层结构简单，就是大的权重矩阵，容易拆开；即便是前馈层，训练起来也会有不稳定和不可微的部分，换成更复杂的注意力层就更不稳定。有些论文每隔四层放一个 MoE 层，但现在的最先进模型通常每个 FFN 层都用。

2. 专家数量：增加参数

策略一：直接增加参数，2N、4N、8N、16N……专家从 16 增加到 128，通常越多越好，但收益递减；参数越多，存储、训练和推理时的路由所需计算资源也越多。所以不会无限加，要么看在哪里开始收益递减，要么按想要的总参数和推理时的活跃参数来定。

3. 细粒度专家

策略二：固定参数量，通过切分隐藏维度增加专家数，DeepSeek 称为细粒度专家切分（fine-grained expert segmentation），做出更多维度为 $d/n$ 的专家。例子：基线每层 8 个专家、维度 $d$、激活 2 个；细粒度版本每层 16 个专家、维度 $d/2$（每个原专家切成两个）、激活 4 个，参数预算不变。好处是更灵活：基线每层有 $\binom{8}{2} = 28$ 种组合，细粒度版本有 $\binom{16}{4} = 1820$ 种，也许能增加表达能力或专家的专门化。OLMoE 在固定参数下比较 8、32、64 个专家，越细粒度困惑度越好。推到极端，可以把维度切成单个向量，但到一定粒度后收益递减；路由器要在更多专家间保持均衡，还要决定把专家放在哪些设备上，专家太多管理不好会增加通信成本。

4. 共享专家

始终保持一组固定的专家活跃，其余靠路由选。比如 1 个共享专家，再从 31 个专家里路由选 3 个。DeepSeek 的论点（Sean 强调这是论点或假设，因为结果不一）：各专家之间可能有共同信息，每个专家都存一份就有冗余，用一个总被选中的共享专家学习共同信息，减少冗余。DeepSeek 的消融显示共享专家很有帮助，没有它差很多，细粒度专家也一贯有帮助。但在 OLMoE 的设置里，有无共享专家大致相同或略差。它还降低了建模的灵活性。设置或数据不同，结论可能不同，需要自己实验。

学生问这些设计是否取决于数据或任务复杂度。这是比较高层的决定，考虑的是预训练规模，要在海量数据上跑，不能做太多依赖数据或领域的决定：比如想训练几个模型，有一定的总参数和推理活跃参数，再看哪些技术能改进。也可能某些选择随数据集（通用分布还是特定领域）不同，Sean 不太清楚这种情况多常见。这些决定通常靠较小规模的初步实验，OLMoE 用 1300 亿 token 做架构决定，而预训练可能要几万亿 token；没有预算做实验，就参考别人的做法。

四、路由

1. 基本想法

为每个（token，专家）对计算一个分数，再按某种策略选专家。决定以 token 为粒度，即决定每个 token 送到哪些专家。几类策略：

  • 词元选择（token choice）：每个 token 选分数最高的 top-k 个专家。
  • 专家选择（expert choice）：每个专家选分数最高的 top-k 个 token。
  • 全局选择：其他任何算法，给定分数矩阵求一个分配。

前两种最常见，尤其是词元选择。学生问专家选择里的 top-k 是在批里还是序列里选：最一般的形式是在序列的 token 里选，再考虑计算上发送整片批次是否更高效。

2. 计算路由分数

出人意料地简单：为每个专家引入一个权重向量 $e_i$，用每个 token 的隐藏状态与每个专家的权重向量做点积，没有非线性，也不是一个网络。然后归一化：词元选择对每个 token 在专家维度上做 softmax，专家选择则在另一个维度上做。softmax 强制一个总和为 1 的预算，每个分数在 0 到 1 之间。这很重要，因为后面的损失会惩罚分给某个专家过多概率质量的情况，不归一化可能出现奇怪的边界情况，比如把一切设为零就能让损失最小。

为什么用这么简单的点积？Sean 说没有最好的答案，可以推想：后面会有一个单独的损失把路由推向均匀，路由器也许不必太聪明；简单的做法在各论文里都管用，那参数不如花在模型的其他地方。学生问 30B 模型选 3B 时，是否要对每个专家都算一遍：路由计算只是每个专家一个向量的点积，很便宜；路由完再对被选中的专家运行昂贵的前馈网络。路由器很贵就违背了初衷。

3. top-k 词元选择路由

$$s_{i,t} = \text{softmax}_i\big(\tilde h_t^\top e_i\big)$$ $$g_{i,t} = \begin{cases} s_{i,t} & s_{i,t}\in\text{Topk}\big(\{s_{j,t}\mid 1\le j\le N\}, K\big) \\ 0 & \text{otherwise}\end{cases}$$ $$h'_t = \sum_{i=1}^N\big(g_{i,t}\,\text{FFN}_i(\tilde h_t)\big) + \tilde h_t$$

例子：路由分数为 0.65、0.3、0.05，$K = 2$，就把输入送给前两个前馈网络，按分数加权组合输出，再接残差和层归一化。写成这样可以看出它是一个门控：进入 top-k 的门值非零，其余为零，很多专家被置零，这就是稀疏。必须严格为零，否则就得真的去算。

4. 负载均衡与容量

失效模式：某个专家收到太多 token，或太少 token。设想每个专家在不同设备（GPU）上，批里很多 token 同时路由过来，设备可能真的内存不足，或者每个专家有固定容量上限（比如 2），第三个 token 怎么办？实际做法是丢弃 token（token dropping）：忽略它，直接传给下一层，相当于跳过了网络的一部分，只因为碰巧撞车，显然不好。反过来，设备有剩余容量却没用上，也是浪费。所以希望路由在专家之间比较均匀，实际做法是在损失里加一项。学生问能不能把溢出的 token 送给下一个分数最高的专家：设备显存是固定的，即使总有办法把第三个 token 送到某个专家，也可能还是内存不足，容量受实际约束限制。

top-k 词元选择的优点：保证每个 token 都分到专家，比较简单。潜在缺点：负载均衡不好做，比如所有 token 选同一个专家；token 丢弃；选择操作不可微，梯度只流过被选中的元素，未被选中的分数得不到梯度，可能让训练困难或不稳定。但如后面所见，忽略这个问题、加上损失函数，效果还行。记住：如今每个主流 MoE 大模型都用 top-k 词元选择路由。

5. 其他路由方式

  • 专家选择：每个专家选固定数量的 token，按定义训练时就负载均衡；模型还能给某些 token 分配更多容量，比如难的 token 可能被多个专家选中。缺点：生成时一次只处理一个 token，需要另外设计选择机制，没有"这个 token 选哪些专家"那么干净；仍有 token 丢弃，某个 token 没被任何专家选中。OLMoE 的实验里词元选择更好。
  • 更简单：哈希（Roller 等 2021），不学习，用确定性哈希函数为 token 选专家。这个无学习的基线效果出人意料地好，有专门的论文论证，但从发展来看人们更多用学出来的路由器，学习还是有益的。
  • 更复杂：强化学习。对不可微的硬决策，强化学习是有原则的方案：策略是路由器，动作空间是前馈网络的编号。但 MoE 本来就不稳定难训，强化学习也是，叠在一起实际上没能胜出。Clark 等 2022（DeepMind）在规模上实现了各种方法，花大力气能让强化学习工作，但相比简单方法收益不大。还有把它看作线性分配、最优传输等方法。

五、训练 MoE

要考虑：模型要好（困惑度、任务指标）；硬件要用得充分；路由决策不可微。做法有强化学习（Bengio 2016；Clark 2022）；2017 年那篇论文注入噪声来探索不同路由决策，不是完整的强化学习；最流行的是启发式的均衡损失（Fedus 2022 及现今方法）。

顺带说路由器怎样训练：路由器的点积就在计算图里，前向时一起计算，最后是语言建模损失，反向传播时路由器的权重自然有梯度。不加任何额外损失也能训练，但会出现下面的问题，所以实际做法是在语言建模损失上再加负载均衡损失。

1. 专家均衡损失

直觉：某个专家收到太多 token、或者得到太多概率质量，就惩罚它。

$$L = \alpha\sum_{i=1}^N f_i P_i$$

$f_i$ 是序列中被路由到专家 $i$ 的 token 比例（序列可以换成批，专家可以换成一组专家或设备），$P_i$ 是分配给专家 $i$ 的路由概率比例，由 softmax 算出，梯度经由它流回路由器（Switch Transformer 的原式还乘了专家数 $N$）。两者越大损失越高。它是启发式的，但出人意料地有效，被广泛使用（Zoph 等 2022）。

OLMoE 的实验说明它很重要：不用均衡损失时，每种颜色代表一个专家，训练一开始所有 token 都路由到一个专家，后来大致平均地分给两个专家，其余六个专家基本没用上，分配问题是真实存在的。性能上也有差别：有均衡损失的训练损失和验证损失（Pile）更好。模型并没有完全崩溃，只用两个专家也能工作，但这只是 100 亿 token，到上万亿 token 差距会更明显。

变体：按设备均衡，每个设备放一组专家，把损失作用在组上而不是单个专家上。实际中在专家均衡损失之外再加这一项，DeepSeekMoE 就同时用了专家级和设备级的均衡损失。

2. 稳定性：混合精度

联系量化那一讲：Google 2022 年的论文发现路由计算用更高精度（float32）很有好处，模型其他部分大多用 BF16。路由决策可能有很极端的值，比如训练初期把所有东西都送给一个专家，导致不稳定。但即使用更高精度，大 logit（强烈偏好某个专家）仍然是问题。

3. 稳定性：z-loss

用一个损失显式惩罚归一化前过大的路由 logit：

$$L_Z(x) = \frac{1}{B}\sum_{i=1}^B\Big(\log\sum_{j=1}^N e^{x_{i,j}}\Big)^2$$

$B$ 是批中 token 数，$N$ 是专家数，$x\in\mathbb{R}^{B\times N}$ 是路由器的 logit。括号里就是 softmax 的分母，这一项越大损失越高，基本想法是让 softmax 的分母变小。过高的分数会变得规整一些，同时一个分数仍可以相对高于另一个，照样能做有用的路由决策。OLMoE 的实验显示：有 z-loss 训练仍可能不稳定，但没有它时不稳定明显得多。负载均衡损失和 z-loss 是两大主要技巧。

六、系统层面与其他话题

1. 专家并行

上一讲有数据并行、流水线并行、张量并行和分片，这里再加专家并行：把不同的专家放在不同设备上，输入数据动态地分发到专家所在设备、再取回结果。选中专家就要把输入传过去，$K>1$ 时还要从多个专家收集输出，有通信成本。它是并行策略组合里的又一项。Fedus 等综述里的图：数据并行在每个设备复制全部权重；模型并行把模型拆到不同设备；可以混合，比如把设备分成四组，组间数据并行，组内再拆模型；专家并行则把不同专家放到不同设备，比如四个专家各占一个设备。图的下半部分画的是数据怎样切分。

2. 稀疏升级

稀疏升级（sparse upcycling）名字听着很高级，其实是把稠密模型变成 MoE：把预训练好的稠密模型的 MLP 复制多份，引入路由器参数（每个专家一个向量），继续预训练。它在固定 FLOPs 下"稠密预训练 + 稀疏升级"优于"直接稀疏预训练"时才有用，说到底是怎样分配计算预算。缺点：可能让优化有偏，稠密模型的优化已经沿着某条轨迹找到了一组权重，可能已经专门化到这个模型上，引入专家后改进空间不大；而从头稀疏预训练，整个过程都在为这些专家找合适的权重。还可能被原模型的超参数绑住，比如不太自然地把 MLP 一切两半。提出者当然会证明它有效，Mistral 用过；但 OLMoE 的结果不一：只有在不超过稠密模型预算 25% 时有利，再往后从头稀疏预训练很快追上，追平点在约 6500 亿 token，而他们的预训练目标可能是几万亿。

3. 领域专门化

训练里没有任何东西让专家具有特定语义，但可以事后去找规律，比如某些层的某些专家在特定领域的数据上激活得更频繁。下结论要小心，要确认在不同专家和不同设置下都稳健成立。

七、案例

DeepSeekMoE

  • 架构：总参数 16B，活跃 2.8B；共 66 个专家，激活 8 个，其中 2 个是共享专家；所有 FFN 都用 MoE 层。
  • 路由：按 token 路由。用流水线并行，没有专家并行，所以没有 token 丢弃。
  • 损失：专家均衡损失，权重 0.001；设备级均衡损失。
  • 效率：用 40% 的预训练计算就达到了稠密 DeepSeek 7B 的性能，这就是开头那些图说的好处。

OLMoE

  • 总参数 6.9B，活跃 1.3B；64 个小专家，激活 8 个，"小专家"的 FFN 维度为 1024；没有共享专家。
  • 不丢弃 token（dropless）。
  • 专家均衡损失权重 0.01，路由器 z-loss 权重 0.001。
  • 预训练吞吐：MoE 每 GPU 每秒 23,600 token，稠密模型 37,500；但达到稠密模型的性能快一倍。

其他可以去看的模型：DeepSeek-V3、Mixtral、Qwen3、gpt-oss 等。

九、小结

混合专家把 Transformer 的前馈层换成多个专家加一个路由器，每个 token 只激活少数专家，于是可以扩大总参数而不增加每样本计算，同等计算下性能更好，训练和推理也更划算，如今顶尖模型普遍采用。设计上，专家通常放在每个 FFN 层；专家数越多越好但收益递减；细粒度专家在同样参数下提供更多组合；共享专家在 DeepSeek 上有效、在 OLMoE 上无益。路由用 token 隐藏状态与专家向量的点积加 softmax，主流是 top-k 词元选择，它不可微，还有负载不均和 token 丢弃的问题。训练靠在语言建模损失之外加负载均衡损失（惩罚分到太多 token 和概率的专家）和 z-loss（压住过大的路由 logit），路由计算用高精度。系统上用专家并行把专家放到不同设备。稀疏升级可以把稠密模型变成 MoE，但从头稀疏预训练往往很快追上。DeepSeekMoE 用 40% 计算达到 7B 稠密模型，OLMoE 吞吐略低但达到同等性能快一倍。
