01. Will Brown（Prime Intellect）：训练会用工具的推理 Agent

直播位置 0:11:54–0:23:59 · 英文原题 Training Agentic Reasoners。字幕从演讲中途开始。

RL 在做什么：优势估计

字幕开始时他正在讲各种 RL 算法的共同结构：有一组任务，也就是问题的不同版本，基本就是提示词；有 Rollout，即模型的一次完整输出，可能包含很多步交互；有评估，可能穿插在过程中，也可能在结尾。要估计的是优势（Advantage）：LLM 是不确定的，温度大于 0 时每次掷骰子结果不同，有时这次比那次做得好。RL 要回答的是：到底是哪里变了导致奖励更高，是在哪个 token 上走上了好路径而不是坏路径。不管用 PPO 还是 GRPO（两种常用的策略优化算法），都是靠这种机制拿到信号，再很精准地让模型多做好的事，同时不大改整体。

他认为这也是 DPO（直接偏好优化，用一对好坏回答直接训练）没像大家期望的那样好用的原因：只给一个完整的好回答和一个完整的坏回答，很难知道复杂分叉过程里信号具体在哪。PPO 有细粒度的优势估计，但很贵；GRPO 成了不错的折中，计算更省、实现简单，靠采样本身也能得到分叉信号。

别被每天的新论文牵着走

论文太多了，每天都有，标题还很耸动，比如“Qwen 不行”或者“一切只在 Qwen 上有效”，后者某种程度上是真的，但背后还有更多故事；还有“把损失函数改成这样就有效”之类的实现细节。他建议大多数人别陷进单个实验和单篇论文，想清楚 RL 整体在做什么，哪些实现细节可以留给别人去调好、最后以软件的形式交给你，哪些部分对你要解决的问题真的重要。

他认为大多数人关心的是解决真实世界软件问题，Agent 是这个方向的具体形态，而 Agent 之所以是 Agent，在于工具，也就是和环境、系统交互的能力。他说大会上很多人对 MCP（Model Context Protocol，让模型以统一方式调用外部工具和数据的协议）很兴奋，而 MCP 说到底就是工具，让 LLM 能改文件、发请求、编辑和运行代码。这方面还有没解决的问题。现有的 RL 代码库大多只适合代码和数学任务。他说这有一部分怪他：他发过一段在 GSM8K（一个较简单的小学数学数据集）上做 RL 的代码，火了，很多人就一直停留在“在数学上做 RL”。数学容易评估，有清楚的对错信号，但真实任务更乱，光在当下流行的问答基准上爬坡，得不到好的软件系统。

奖励作弊说明评测难做

奖励作弊（Reward Hacking）指模型找到了提高奖励但没有真正完成任务的捷径。他说这一课告诉我们 RL 有效但不总是有效，难点在于做好评测。你希望模型直接做好任务比钻评测空子更容易；模型会沿着阻力最小的路径走，它们想学，但学的是在奖励信号上做得更好，所以奖励信号必须指向你真正在意的东西，否则模型会找到作弊方法。

R1 出来时他猜下一步会是什么。人们常说“生成-验证差距”：很多问题检查答案比解题容易，但这是一个连续的谱。已有迹象表明，对更模糊的任务，可以把评估拆成小块，用 LLM 作为评估里的子程序，相当于加强版的 LLM 裁判，甚至专门训练一个擅长细粒度评估的 LLM。他喜欢用“评分细则”（Rubric）作为总称，涵盖奖励模型、奖励函数、LLM 裁判这些评判标准。他提到 DeepSeek 几个月前的一篇论文，训练能针对具体问题即时生成评分细则的奖励模型；最近还有一篇把这种方法用在创意写作上，发现确实能训练出针对任务即时给出细致标准的奖励模型，得到足够细的分数来持续做 RL。

多轮 Agent 和 verifiers 库

他认为方向是多轮：Agent 式搜索、工具调用、软件、游戏、长程规划、电脑操作、记忆，靠更多工具调用解决更难的问题。他的概念对应关系是：环境就是 Harness（包住模型、提供工具和运行循环的外壳），奖励就是评测，任务就是提示词，RL 意义上的策略（Policy）最好就是一个 LLM API。合适的编程接口应该让你像写一个普通的循环 Agent 一样写代码，同时它又能直接拿去做 RL。

这就是他最近几个月在做的开源库 verifiers，已经可以用 pip 安装。核心的 Rollout 函数很简单：设置初始状态，while 循环判断是否结束，没结束就再走一轮，传入的 client 对象就是一个 OpenAI 兼容的 API。库里还有解析器（Parser）和评分细则（Rubric）这类可选的构建块。

他的例子是训练一个玩 Wordle 的 Agent：对人来说不难，但要把代码写成能做学习的多轮交互协议并不容易，现在简单多了。奖励函数也简单：最终猜中给奖励，轮数越少奖励越多。用的是 7B 模型，效果还行，一个原因是先做 SFT 热身（Supervised Fine-Tuning，用示范数据做监督微调）。环境同时也可以当合成数据循环或评测来用：接上 Claude、DeepSeek 或 OpenAI 的 API 就能测试，不必通过 RL 来调试环境和奖励；确认没问题后，用你有权使用的 API 生成合成数据，做 SFT，再开始 RL，这对小模型帮助很大。

他还在解决效率问题：让计算资源被充分利用，全部异步，不用操心批处理，训练和推理同时进行，可以稍微离策略（Off-policy，用稍旧版本模型生成的数据训练）。想深挖可以 fork 仓库，不想管也不必管。现在在几块 GPU 上就能做不少有意思的研究，门槛比以前低很多。最后他说了句“顺便说一下，我们卖 GPU”，因为时间关系没有问答。

02. Greg Kamradt（ARC Prize Foundation 总裁）：衡量 AGI，交互式推理基准与 ARC-AGI-3

直播位置 0:24:00–0:42:21 · 英文原题 Measuring AGI: Interactive Reasoning Benchmarks

玩 Pokemon 不等于 AGI

他从 Claude 玩 Pokemon 的演示讲起，看一个小 Agent 自己做决定玩童年游戏很特别；OpenAI 也做了，前几天 Gemini 还通关了。但 Claude 会在同一个地方卡三天，需要人工干预，会幻想出不存在的操作，而且模型里本来就有大量 Pokemon 的训练数据。所以这是 Agent 探索世界的好例子，但还有很多可改进的地方。

ARC Prize 的思路：以人为标尺

ARC Prize 是非营利组织，使命是做通往开放 AGI 的北极星，去年由 François Chollet 和 Mike Knoop 创立。去年 12 月 OpenAI 邀请他们上直播，一起公布 o3 预览版在 ARC-AGI 上的成绩。他们的立场是：最好的目标是人类，因为人类是我们知道的唯一一个通用智能的实例。他们出人能做、AI 难做的题，这带来两点：一是形成差距，可以度量还有多少题人能做而 AI 不能；二是引导研究，告诉研究者这类问题里有值得研究的东西。

他引用两个智能定义。一个来自 John McCarthy：AI 是让机器完成它从未见过、事先没准备过的任务的科学和工程，如果题型已经在训练数据里，就只是在重复记忆。另一个是 Chollet 的三个词：技能获取效率（Skill Acquisition Efficiency），既要能学新东西，还要学得高效，而人类在这方面效率极高。Chollet 在 2019 年的论文《On the Measure of Intelligence》里提出这个定义，并给出了基准 ARC-AGI-1：左边给几组输入网格到输出网格的变换示例，让你学会这个小技能，右边让你用网格编辑器演示出来，做对了就说明有一定的泛化能力。

最新的 ARC-AGI-2 有一千多道题，每道题都是新颖、独特的，一道题需要的技能不会在另一道题里再考，测的是很多小技能，而不是重复已学会的技能。为了证明人能做，他们去圣迭戈租电脑、线下测了 400 多人（线下是为了数据隐私），确保收录的每道题都有人能解出。

为什么要做交互式基准

ARC-AGI 是单轮的，测试时需要的信息全摆在面前，不需要探索。他认为要测类人智能，基准必须是交互式的：测试一个 Agent（生物或人工）能否探索开放世界、搞清目标、根据奖励行动。这和 Rich Sutton 刚发表的《Welcome to the Era of Experience》一致：Agent 要适应人类世界，就要与开放世界交互、收集观测数据、建立世界模型、自己总结规则，否则会被人类数据的上限卡住。

交互式推理基准的定义是：受控的环境，明确的规则，可能只有稀疏的奖励，Agent 要自己探索才能弄清状况并完成目标。游戏很适合做载体，因为它是复杂规则、明确范围和高度灵活性的交汇。有人会说十年前不是做过 Atari 游戏了吗？他列了 Atari 时代的问题：奖励很稠密；成绩报告不规范，大家用不同尺度，难以比较；没有隐藏测试集；最大的问题是开发者知道是哪些游戏，会把自己的智能注入模型，表现出来的智能其实是借来的。

他用一个阶梯说明目标：AI 能打败一个游戏，象棋、围棋都已证明；在算力和训练数据无限的情况下，AI 能打败 50 个已知游戏，Agent57 和 MuZero 做到过。他们要做的论断是：AI 打败 100 个它自己和开发者都没见过的游戏。能做到，就能对这个 AI 做出目前市场上还没人能做的能力论断。

ARC-AGI-3 的三个特点

  • 公开训练集、公开评测集，外加私有评测集。公开训练集大约 40 个新游戏，让开发者和 AI 熟悉界面。所有成绩都在私有评测集上报告，不联网、数据不外泄，所以分数来自 AI 和开发者都没见过的游戏，可以说它泛化到了开放领域。
  • 通过探索来理解。他不满意现有游戏基准给 AI 太多说明（“你在玩赛车游戏”“你在玩 FPS”）。ARC-AGI-3 会把 AI 和人直接扔进世界，不告诉规则。他展示了第一批游戏之一，叫 Locksmith，他自己看截图也不知道要干什么，要探索才发现有东西可以捡、有墙、有目标。
  • 只依赖核心知识先验（Core Knowledge Priors），延续 ARC-AGI-1 和 2：没有语言、文字、符号，也不考常识问答。他说别的基准请世界上最聪明的人出最难的题，他叫这类题“PhD++”，但 AI 在很多领域已经超人；ARC 看的是下限和可靠性。四类核心知识是人天生或出生后马上具备的：基础数学（数到 10 左右）、基础几何和拓扑（认识形状）、主体性（Agentness，知道世界上有其他会行动的主体，类似心智理论）、物体性（Objectness）。

他引用了 Dwarkesh 的一篇文章：人类厉害在于能积累上下文、追问自己的失败、在练习中一点点改进和提效。他说目前没有能测这种能力的基准环境，ARC-AGI-3 就是要做这个。

怎么打分和时间表

回到 Chollet 的定义，用技能获取效率打分，以人为基线：测几百个人玩同样的游戏，记录用时和操作步数，再用同样方式衡量 AI，看它能否探索环境、直觉理解、自己设定目标，并比人更快完成。他的论断是：做不到就还没有 AGI；只要还能出人能做而机器不能做的题，就还没有 AGI。

时间表：下个月在旧金山发布沙盒预览，放出 5 个游戏，并办一个小型 Agent 竞赛，设少量奖金，尽早接触现实；目标是 2026 年第一季度推出约 120 个游戏。每个游戏有多关卡，内容很深，制作是不小的运营挑战。他希望得到捐款（可抵税）、介绍慈善捐赠人、找对抗测试者，也在招游戏开发者和设计师：他们一开始用 Unity，发现对 64×64 的小游戏来说太重，正在自己写一个轻量的 Python 引擎。

问答

  • 新基准多久会被刷满？他说以年计，不会是几十年。
  • 效率会不会算能耗或时间？他很看重效率。理想的两个分母，一是能耗，因为知道人脑消耗多少能量；二是需要的训练数据量。两者对闭源模型都拿不到，所以用成本作代理；交互式评测还多了一个代理，就是操作次数。游戏是回合制，不计墙钟时间。
  • 什么是物体性？就是知道一团东西会一起行动，比如一个像素周围一堆像素一起移动，就把它们当成一个整体；进化上讲，就是知道那些都属于同一棵树。
  • 人也做不到的任务怎么办？这不在他们通往 AGI 的论点范围内，那属于超级智能的讨论。

03. Aakanksha Chowdhery（Reflection AI）：用强化学习后训练开放模型，做自主编程

直播位置 0:44:50–1:04:17 · 英文原题 Post-Training Open Models with RL for Autonomous Coding

讲者

她在 Google 工作了六年多，主持了 PaLM 的研究（主持人介绍她是 PaLM 论文第一作者），也是 Gemini 的主要研究员之一，现在在 Reflection AI 用强化学习推进自主编程（Autonomous Coding）的前沿。她先回顾了大模型一路怎么走到这里，再讲为什么是自主编程、为什么是现在。

从扩展定律到思维链再到 RLHF

2020 年的扩展定律（Scaling Laws）论文，30 秒概括就是：模型的测试损失和算力、数据、参数量之间是幂律关系，投入越多性能越好，而且会泛化到训练领域之外。模型变大后各项基准持续提升，现在已经接近饱和；还出现了涌现能力，即小模型没有、大模型才有的能力。

她放了 PaLM 工作中的经典幻灯片：给模型一道网球数量的数学题作示例，再问第二道题，模型直接答错；如果让模型输出推理链，答案就对了。她提醒这是 2021 年、四年前的事。LaMDA 和 PaLM 是三年前最强的模型，PaLM 扩展到 5400 亿参数；她说现在没人公布参数量了，只能看三年前的图或 DeepSeek、Qwen 这些开源模型。图上随着参数增加，初中数学应用题的解题率上升，主要是在用思维链（Chain of Thought）提示时上升，于是出现了“一步步想”、甚至贿赂模型之类的提示技巧。这种能力还泛化到其他语言的问答、谜题、多任务语言理解。

模型会推理之后就能遵循指令，于是有了 ChatGPT、Gemini 这些聊天机器人。让模型学会遵循指令的是强化学习，数据来自人类反馈（RLHF）：给人看两个回答，问更喜欢哪个，数据够多就能训练模型偏好更好的回答。她说这在代码上也有效，图上显示代码应用同样有提升。

推理时扩展和可验证领域

去年很多人在争论大模型是不是撞墙了，预训练是否不再带来收益。她指出预训练要花几千万美元，推理则很便宜（她说这些是公开来源的数字，不代表她任职过的公司）。既然一味扩大模型不再划算，能不能在推理时拿到收益？

  • 多数投票：让模型独立生成多个答案，取多数一致的那个，也叫自洽性（Self-consistency），被证明有效。
  • 顺序修正：像人一样写完第一版再检查、发现错误再改，让 LLM 根据之前的版本修正，也就是更长的思维链。
  • 在能验证答案的领域，比如有单元测试的数学和编程，这些技术收益最明显。她展示了一位斯坦福同事已发表的论文：横轴是采样数，纵轴是 pass@k 覆盖率（k 次采样中至少一次做对的比例），用开源 DeepSeek 模型多采样，在 SWE-bench Verified（一个真实 GitHub 问题修复基准）上的得分超过了 2024 年底的最好水平。她说现在这个基准大家已经到 80% 左右。

她的结论是：推理时的计算能可预期地带来收益，特别是在能验证的领域；知道怎么验证答案，就知道怎么把它转化成智能。编程就是有验证能力的领域，这给在自主编程之上构建超级智能带来巨大优势。自动验证在数学里可以是计算器或形式化证明，在编程里是单元测试和编译器，比如用 PyTorch 编译器当验证器。没有这种验证的领域，生成大量答案再多数投票，收益就小得多。

但推理时扩展还不够。她放了 GSM8K 等数学基准上多个模型的图：按正确比例排序，正确的生成可能极其稀少，谁有时间采样一万次才找到正确答案？所以正确答案虽然在某处存在，单靠多数投票或更长的推理链并不能普遍奏效。要让模型在训练中学会生成正确答案。

RL 是下一个扩展前沿，难在哪

Reflection 的看法是下一个扩展前沿是强化学习，前沿实验室已经有证据。她引用 David Silver 和 Sutton 最近的文章：从 AlphaGo、AlphaZero 的模拟时代，到用人类数据做 RL 的大模型时代，今年开始进入经验时代，这会通向超级智能。o1 的结果显示，在 AIME（美国数学邀请赛题目）上，推理时计算增加和训练时计算增加都会提高准确率；她说这个基准一年内就饱和了。

为什么不是人人都在做？她从做大模型的经验说，机器学习加系统这一整套很难。用 PPO 做 RLHF 要同时放四份模型副本，大模型乘以四，还要在大集群的 GPU 上排布，排布本身是个有趣但很难的问题；DeepSeekMath 提出的 GRPO 去掉了价值模型，只剩三份，仍然很难。RL 比扩展普通 LLM 更难，因为有多份模型副本，还有训练循环和推理循环。机器学习这边还有奖励作弊：如果判断答案对错的是一个神经网络奖励模型，就容易被钻空子。自主编程里有执行反馈和单元测试，SWE-bench Verified 的分数就是这样算出来的，所以能设计更好的奖励函数。

真实世界的影响是另一个问题：软件工程里写代码只是一部分，端到端工作流还有很多环节，怎样让系统泛化到所有这些环节，就是 Reflection 要解决的问题。他们的使命是构建超级智能，把自主编程作为根节点问题，团队约 35 人。

问答

  • 该用一个通用模型还是按语言、代码库专门化？她说做编程 Agent 需要多种能力，肯定要多次 LLM 调用；是一个模型还是多个模型，目前是各家的秘方。
  • AlphaGo 那类“模拟时代”也用 MCTS 和合成数据，和现在的“经验时代”区别在哪？她说游戏里可以推演接下来会发生什么，用于 RL 的 Rollout；真实世界大多只有不完整的 Rollout，你不完全知道系统会怎样运行。在机器人、物理 AI 这类能建世界模型的领域可以模拟，但他们针对的真实应用里，必须真去经历、收集数据，而这些数据既不完整，也覆盖不了指数级的搜索空间。

04. Ryan Marten（Bespoke Labs）：OpenThoughts，推理模型的数据配方

直播位置 1:05:05–1:24:28 · 英文原题 OpenThoughts: Data Recipes for Reasoning Models

缺的是数据配方

他是 Bespoke Labs 的创始工程师，OpenThoughts 项目的目标是做最好的开源推理数据集。他说这场会从 RL 转到推理本身。过去几个月模型在 AIME（竞赛数学）这类基准上大幅进步，靠的是推理和测试时扩展：模型能一步步想、输出长思维链。

他对 DeepSeek R1 特别感兴趣的一点是：最终发布的 R1 权重其实是一个 SFT 模型，是在 DeepSeek V3 Base 上用 80 万条 SFT 样本微调出来的，其中 60 万条是推理数据。RL 在其中很重要，用来训练生成这些数据的模型，但最后一步主要是 SFT，加一点用于对齐的 RL。另一个惊喜是 DeepSeek 发布的几个小推理模型（蒸馏模型）很强。可这些数据集几乎没有公开细节，所以训练配方有了，数据配方没有，这就是缺失的一环。蒸馏（Distillation）指用强模型（老师）生成答案，再拿这些答案去训练小模型（学生）。

为什么要自己训练推理模型？他引用前一天 Amir 关于开源和企业的演讲：性能、隐私、速度和成本、以及掌控自己的命运。RL 是解决推理任务的好工具，但他接下来要说明的是，SFT 就像 Nathan 当天上午说的，极其简单，也极其有效。

OpenThoughts 3 的结果

他们当天宣布了 OpenThoughts 3，两小时前刚发布，是当时最好的推理数据集配方。图上横轴是数据规模，纵轴是 AIME、LiveCodeBench（竞赛代码）、GPQA Diamond（科学题）三项准确率。他说 RL 扩展难，SFT 扩展容易得多。他们在同一个基座模型上对比了自己的数据和 NVIDIA 为 Llama-Nemotron Nano 公开的训练数据，差距明显，等于把扩展曲线整体往上移。最终得到当时最好的 7B 开放数据推理模型：原定目标是复现 DeepSeek-R1-Distill-Qwen-7B，结果大幅超过它；和基座不同的 Nemotron Nano 相比，部分基准更好，其余相当。

他解释了两种提升方式：沿着横轴扩大数据量总能提升，但成本指数增长；把曲线往上移就是改进数据配方。要把性能推到极限，就要找到最好的配方。

流水线和实验规模

他们把数据流水线拆成几步：获取问题、混合不同来源的问题、过滤出高质量问题、用老师模型生成答案（蒸馏）、过滤坏答案，最后比较选哪个老师模型。他们在 Hugging Face 上创建了 5000 多个数据集、近 3000 个模型，这个项目本身大约做了 1000 次实验。他说这多少揭开了前沿实验室的做法：在尽可能小的规模上找信号，试尽可能多的东西，按实验结果选最好的再扩大；有时扩大后发现小规模的最优不成立，但如果运气好、科学做得好，最后那次“YOLO 训练”会是最好的。

有效的做法

  • 每道题采样多个答案效果很好。固定 3 万条样本规模，3 万道题各采样一次，和 3 万的十六分之一道题各采样 16 次，效果差不多。这意味着可以把数据扩大 16 倍，超过一个数量级。
  • 自身基准成绩更好的模型不一定是更好的老师，就像出色的研究者可能是糟糕的讲师。他们发现 Qwen 的 32B 推理模型（字幕作 Quen 32B，OpenThoughts 论文里是 QwQ-32B）比 DeepSeek R1 更适合当老师，于是换掉了大家常用的 R1。
  • 合成问题的数据源质量不错，选出的几个最好来源里有完全合成的，比论坛抓取或人工撰写的来源还好。合成问题能扩展，这是好消息。
  • 问题过滤有效：让 LLM 评估题目难度只留最难的，或者让 LLM 答题、看回答长度（越难的题模型想得越多、答案越长）。这两种都比嵌入向量方法或 fastText 分类器好，而后两者是预训练数据过滤的常用方法，说明后训练的数据过滤和预训练很不同。

没用的做法

  • 少量高质量来源比追求多样性、混很多来源更好，这很反直觉。
  • 验证对 RL 很重要，但对 SFT 和蒸馏，按答案对错过滤似乎完全没帮助。他提到文献里有一些解释：对最难的题，即使答案错了，保留下来看老师怎么尝试也可能有用，最终输出之外的过程也有价值。

想做专门领域的推理模型怎么办

他的建议：不同领域的最优选择可能不同，从他们的配方开始，有算力就每一步多试几种。他们自己就是按代码、科学、数学分别研究的，比如问题过滤，代码题用难度标签效果好，数学和科学用回答长度效果好。原因不难理解：AIME 的答案只是 0 到 999 之间的一个数，长度主要来自思考；而代码题即使很简单，答案也可能有很多行。数据少的领域可以把现有数据改写成问题、作为上下文示例去生成更多数据，他们为此开源了一个库叫 Curator。

他强调评测最重要，不知道模型好坏就不能对数据配方做有原则的决策。他们开源了评测库 Evalchemy，处理分片和并行。评测集很小时要多跑几次取平均：AIME 每年只有 30 题，他们每次评测把 30 题跑 10 遍再平均，否则噪声太大。

还有一个令人兴奋的发现：在某些领域，蒸馏能超过老师。通常认为只有 RL 能推进前沿，蒸馏只是追赶老师。他们在法律推理领域做了实验，任务是对美国最高法院判决分类：取 2000 道不同的题，每题采样 5 个答案，这次做了验证并且有用，扔掉错误答案。微调出的 7B 模型超过了 R1 这个又强又大的推理模型。所有东西都开源：论文当天上午发布，权重、数据集、数据生成和评测的代码仓库都有。

问答

  • 这和普通 SFT 有区别吗？没有，就是普通 SFT。那 SFT 怎么让模型想很久？因为训练用的答案里包含思考过程，模型学会利用上下文窗口、生成长思考，人们称 SFT 为模仿，它也能学会这种格式。
  • 为什么更小的 QwQ 32B 比 R1 更适合当老师？还需要研究。两者推理轨迹的长度分布不同，可能是用了更多 token、更多步骤，也可能是输出格式更好。他还说他们试过 Claude 当老师，作为很强的模型，它却是个很糟糕的老师。
  • 推理链在哪一步出错有没有规律？他们没做这种细粒度分析，文献里有很多关于“关键出错步”的研究。他们试过修改推理轨迹的各种方法，都没有帮助，还有很多可探索的。

05. Kyle Corbitt（OpenPipe 联合创始人）：用强化学习训练可靠的 Agent，ART·E 案例

直播位置 2:48:45–3:08:42 · 英文原题 How to Train Your Agent: Building Reliable Agents with RL

ART·E：回答邮箱问题的 Agent

OpenPipe 用强化学习让 Agent 更可靠，客户多是财富 500 强一类的大公司。这次他讲一个具体案例的经验，代码全部开源。项目叫 ART·E，一个用自然语言回答你邮箱里问题的助手。例子是“Sherry 搬去 Portland 计划在什么时候？”Agent 有搜索工具、读邮件工具，最后给出答案。屏幕上能看到它用关键词搜索、拿到邮件、读其中一封、作答。

第一课：先用提示词把基线做到最好

为什么用 RL？他说一开始不该用，他们第一版也完全没用 RL，只用提示词驱动的模型。他建议训练（包括 RL）之前，先尽量把提示词模型的表现做到最好，理由有三：一是先排除环境里的 bug，比如工具实现不对、拿不到你以为它能拿到的数据，这比在训练循环里调试轻松得多；二是可能发现提示词就够用了，省下大量时间；三是如果尽力做好基线后 RL 还能超过它，那感觉很棒，可以发到 X 上配图。

结果：准确率、成本、延迟

训练曲线上有 o3、o4-mini、Gemini、GPT-4.1 几条提示词基线，他们训练的模型从 Qwen 2.5 14B 起步，一开始远不如这些模型；训练初期有个陡升，大概是学会了正确调用工具，之后缓慢爬升，最终明显超过所有提示词模型。换一种看法：最好的提示词模型 o3 准确率 90%，他们的 RL 模型 96%，相当于消除了 o3 约 60% 的错误。他说错误减半对用户体验影响很大。

  • 成本：做 1000 次搜索，o3 要 55 美元，他认为多数场景从单位经济上讲负担不起；o4-mini 8 美元，仍然贵；换成 Qwen 2.5 14B 又降了一个数量级，因为模型小，但针对任务专门训练后效果仍很好。
  • 延迟：一是小模型本身更快，读内存少、矩阵乘法少；二是训练它用更少的轮次查询邮箱；三是这次没用但对小模型很有效的推测解码（Speculative Decoding，用小的草稿模型先猜后面的 token，再由主模型批量确认），专门任务的小模型接受率更高。
  • 投入：这次训练 GPU 花了约 80 美元，工程上用了大约一周，而且是一位熟悉这个领域、有机器学习和 RL 经验的工程师。他预计随着行业摸清套路，投入会继续下降，专门模型的回本周期也会缩短。

两个难题：真实的环境和奖励函数

他说每次用 RL 都会遇到两个难题。第一是真实的环境：训练数据、输入输出、可用工具都要和生产里一样，否则模型会优化错误的东西。对 ART·E 来说，需要一个大而多样、看起来像真实邮件的邮箱，但不能找一千个人要他们的私人邮件。解决办法来自一家“对开放数据生态贡献很大的历史性公司”：Enron。这家 1990 到 2000 年代的能源公司因大规模欺诈被司法部关停，诉讼的证据开示过程中公开了约 50 万封邮件，于是他们有了包含数万封真实往来邮件的邮箱环境。

第二是奖励函数，即怎么判断 Agent 做得好不好。有的领域很容易，比如 Nathan 团队提出的 RLVR（可验证奖励的强化学习），在可验证领域直接判对错；很多领域则比较难。他们把问题反过来做成了可验证的：每次从邮箱取 20 封邮件给 Gemini 2.5 Pro，让它出几个用户可能会问、答案就在这些邮件里的问题，同时给出答案和来源邮件。很多问题看起来不现实，他们又加了一步过滤，留下像真人会问的问题，最后得到几千个带已验证答案的问题。评判时让 Agent 去搜邮箱作答，再用一个简单的 LLM 裁判，对比问题、标准答案和模型答案，判断对不对。裁判需要迭代校准什么算对，但总体效果不错。之后就是不断循环：Agent 尝试，判好坏，好就奖励、坏就惩罚，模型逐渐学会什么是好。

奖励函数里可以加“附加分”

他们在主目标之外加了大约 8 个小的附加奖励，他讲了两个：

  • 少用轮次。答案都对时，更少的往返意味着更少 token、更低延迟和成本。训练早期模型摸索时平均轮次一度升到 6 以上，学会高效用工具、构造关键词后降下来，比所有提示词模型都少。这部分奖励相比答对的奖励很小。
  • 减少幻觉。找不到答案时说“我不知道”比编一个好。如果裁判判答案错误，模型却给了答案，奖励就远低于直接说不知道。结果幻觉率明显低于包括 o3 在内的所有提示词模型。

他说这些附加目标可以同时优化。

奖励作弊的真实例子

他放了 OpenAI 近十年前发布的经典视频：船本该跑完赛道，却学会在赛道外绕小圈刷分。他说奖励作弊的根源是你想让模型做的事和你能测量、奖励的事之间有差距，训练时间够长，模型几乎总会找到漏洞。两个例子：

  • 团队一位工程师训练模型玩 NYT Connections（16 个词分成 4 组，需要大量常识和发散思维）。一直学不会，到第 40 步左右分数突然飙升。去看模型在干什么，原来验证代码有 bug，没检查每组是不是只有 4 个词，模型把所有词放进每一组就能拿满分。
  • 他自己训练模型给 Hacker News 帖子起能获得高赞的标题，奖励模型是用已有帖子和赞数训练的。前一千步左右学得不错，他作为 HN 重度用户也觉得标题像样；到第 1200 步左右分数突然跳升，原来模型发现可以完全无视帖子内容，每篇都起同一个标题“Google 裁员 80%”。他说这个标题在 HN 上大概确实会火。修复办法是加一个 LLM 裁判，检查标题里有没有内容不支持的说法，效果很好。

他的建议是要去看 Rollout，不能盲目相信奖励函数；修复通常是改奖励函数，惩罚这类行为。最后他给了完整写法、代码、数据集的链接，还有 OpenPipe 开源 RL 训练项目的 Discord。

06. Nathan Lambert（AI2）：下一代推理模型的能力分类

直播位置 3:09:30–3:28:49 · 英文原题 A taxonomy for next-generation reasoning models

推理已经普及，问题是往哪走

Kyle 介绍他是开放生态里谈后训练和强化学习最有影响的声音之一，有通讯和播客，在 AI2 主导多个项目，做最好的完全开放模型。Nathan 说他想反思 o1 和 DeepSeek 之后、可验证奖励强化学习（RLVR）流行六个月的状况。现在人人都有推理模型，大家都知道训练时扩展 RL 分数会涨，这和推理时扩展高度相关，所以这些基础有点无聊了。真正的问题是方向在哪，除了用每题一万个 token 刷高基准分之外还要做什么，OpenAI 等公司可能已经在做的事情是什么，而从他们那里越来越难得到信号。

推理带来了新应用

  • 他作为 RL 研究者常要找 OpenAI 那个赛船刷分的例子，总忘了它叫 CoastRunners，要搜二十遍 “overoptimization”。问 o3，它直接给了下载链接。这种用法从以数学和代码为起点的推理训练里冒出来，很不寻常。o3 是他找信息用得最多的模型。
  • Deep Research 很好，可以创造性地用，比如让它只看你网站上的内容找错别字，比想象的更可控。
  • Claude Code 用起来感觉好、有意思。他不是专业软件工程师，不用它做难事，用它做好玩的事，比如给他在线写的书做网站。
  • Codex 这类完全自主的 Agent，形态明显能行得通。做机器学习任务时它还没有 GPU，刚加上联网，以前没法去 Hugging Face 来回查配置。他说六个月内这些都会成为日常工具。

他放了一张常被讨论的图：纵轴是模型大致能完成多长时间的任务。到 2024 年 GPT-4o 时期已经接近饱和，o1 这类新模型把前沿往外推。他说这并不是一条注定的路径，进步不是白来的，要想清楚模型需要会什么才能继续推前沿，大量的人力投入在维持这个趋势。他认为在推理技能之外，规划以及换一种方式思考训练，会推动这些还处于早期的应用和产品。

四个特质：技能、校准、策略、抽象

  • 技能（Skills）：数学、代码这些，基本已经做到，推理时扩展帮了忙，越往后越偏研究。
  • 校准（Calibration）：对产品很关键。模型严重过度思考，需要让输出 token 量和问题难度匹配，每个任务花的钱越多越重要。
  • 策略（Strategy）：属于规划，指朝正确方向走，知道可以尝试哪些不同做法。语言模型可以稍微回溯，但很难推翻整个计划重来。
  • 抽象（Abstraction）：也属于规划。任务很难时，模型要自己决定怎样拆成可处理的子任务，或者把某部分交给更大的模型。现在多由人来做，模型不会天然这样做。

他展示的 RLVR 示意图很简单：拿提示词，模型生成回答，给回答打分，用打过分的回答更新权重。到目前为止基本是单轮的，加入多轮和工具会复杂一些。在一组当时最难的评测上，从 GPT-4o 到 o1 再到 o3，进步很大，主要来自加入这种新训练。他的核心论点是：要让规划能力起作用，也需要做类似的事。

技能清单会继续变长，最近 DeepSeek 和 Qwen 的新模型都加入了工具使用，会出现更多像 o3 的模型；o3 用起来不一样，因为它把工具使用和推理结合了起来。在工具使用之上的“Agent 性”大家多说 Claude 最好，但还没有公认的衡量方式。

校准：现在推给了用户

现在校准的负担在用户身上：ChatGPT 的模型选择器、Claude 扩展思考的开关、Gemini 的类似设置、API 里的推理强度参数，对用户都很麻烦。让模型自己知道该花多少，就更容易为任务选对模型，减少无谓的 token 开销，拖得越久问题越大。他举了过度思考的例子：问“2 加 3 等于几”，推理模型用几百到一千个 token，而本来一个 token 就够；对比普通指令模型和 QwQ 推理模型的输出长度，换成推理模型 token 花费会涨 10 到 100 倍，浪费的话会拖垮基础设施和成本。作为用户，他不想为简单问题等几分钟，也不想为此换模型或换厂商。

策略和规划

他从 Epoch AI 网站上取了一道 FrontierMath 示例题，看新的 DeepSeek R1-0528 开始时有没有任何规划。它直接说“首先我需要构造一个多项式”，一头扎进去，没有先勾勒问题。这可能输出 1 万到 4 万个 token，再扩大 10 倍的话，方向一错就是好几美元和大量延迟。很多应用预期延迟在 1 到 30 分钟之间，有超时限制，方向错了或者在子问题上想太久，用户就走了。

他说这些模型自己几乎不做规划，Deep Research 和 Claude Code 开头的规划很可能是提示词要求的，要让规划变成模型原生能力。规划之后还有很多实现细节：怎样管理记忆（Claude Code 在上下文窗口满时压缩记忆，但不知道对所有应用是否最优）；避免重复犯错，Greg 讲的玩 Pokemon 就是例子；拆出可处理的部分；难的部分把思考外包；同时并行调用多个模型。现在有人开 tmux 在十个窗口里跑 Claude Code，他认为没有理由语言模型自己不能这样做，只是要学会正确的方法。

他回顾 Q* 到 Strawberry 到 o1 的故事：它之所以长期是新闻，是因为 OpenAI 花了 12 到 18 个月构建最初的推理轨迹，用来训练出带有回溯、验证这类行为的初始模型，需要大量人工数据。规划也要走类似的路。但规划的训练数据比推理直观得多：让人写一段 1 万 token、带回溯的推理轨迹几乎做不到，而很多专家能写出很好的 5 到 10 步计划，或者检查 Gemini、OpenAI 写的初始计划。所以他对在规划上爬坡更乐观。流程同样是先有初始数据做 SFT，难的是更大任务上的 RL 能否强化这些规划风格。他提出一个设想：现在是思考 token 在回答 token 之前，也可以加更多结构，让模型在思考之前先规划。

他用 o3 区分技能和规划：o3 搜索技能极强，能找到领域研究者知道但记不住关键词的冷门信息；可放进 Deep Research 后，缺乏规划使结果有时是杰作、有时是废品。比如让它推荐买什么电子产品，你很难信任，因为它不知道该拉取哪些信息、该做到多全面。规划变好后会更周全可靠。他说这四类可以继续扩充，策略和抽象可以合并，他描述的很多也可以叫上下文管理；分类的意义是把训练问题拆开，为每类考虑数据获取或新算法。

并行计算和持续学习

他说 o1 Pro 很长时间都是最好、最稳的模型之一，他很期待 o3 Pro。但并行计算解决问题的方式和传统推理时扩展不同：推理时扩展让很多原本做不到的事从 0 变成 1，并行计算让结果更稳、更精致。RL 训练鼓励探索，并行时投入更多计算则更像利用，得到打磨得很好的答案，有用的时候用，但解决不了所有问题。

现场很多讨论谈到持续学习（Continual Learning），即不断用很长程的 RL 任务更新模型、减少对预训练的依赖。他认为持续学习有很大的算法瓶颈，而继续扩大 RL 是可行的，也正在发生。

他在 AI2 的研究计划，和一个挑衅性的说法

  1. 收集大量跨领域、带已验证答案的问题，大多数会是数学和代码，因为现有数据就是这些。
  2. 按基座模型的难度过滤问题。各家配方论文都有这一步：基座模型 100 次里 0 次做对或 100 次全对的题不要，既浪费算力，又让 RL 的梯度更嘈杂。
  3. 做一次稳定的 RL 训练，跑完所有问题，分数持续上涨。核心就是稳定的基础设施和数据。之后再用论文里的各种方法，比如过长样本过滤、不同的裁剪方式、重置参考模型，在上面多拿几个百分点。

他的挑衅说法是：要不要把“后训练”改名叫“训练”。如果 o1 的后训练计算量是预训练的 1%，OpenAI 说 o3 又提高了 10 倍，那后训练和预训练的 GPU 时数很快会接近持平，一年前没人会相信。DeepSeek 的数据点：DeepSeek V3 论文里后训练只占 GPU 时数的 0.18%，预训练大约两个月；他们一位 RL 研究员发过一条后来删掉的推文，说 R1 的训练花了几周。如果做几个很强、可能不完全准确的假设（RL 用了整个集群），那已经相当于 10% 到 20% 的计算量。他也承认 DeepSeek 的预训练效率可能远高于其 RL 代码。但扩展 RL 是真实在发生的事。

07. Christian Szegedy（前 xAI 联合创始人）：走向可验证的超级智能

直播位置 3:32:05–3:52:56 · 英文原题 Towards Verified Superintelligence。通过 Zoom 远程演讲，3:32 到 3:41 左右音量极低，字幕大段缺失。

讲者和前半段（字幕不清）

主持人介绍他在 Google 做了很长时间研究，后来是 xAI 联合创始人，在那里待了几年，现在在做一家新创业公司，因临时有事只能远程。前半段他在回顾从 2011 年前后开始的深度学习历程，字幕只能辨认出零星词句。可以听出的结论是一串历史经验：深度学习确实有效；可以扩展；后来强化学习和推理时计算带来新的扩展维度。他要讲的是下一个大趋势，方法是看每个趋势的瓶颈在哪里。

AI 自我改进的瓶颈是人

他列出的瓶颈依次是：人工标注、人类生成的数据，现在是人类设计的任务、人类监督，甚至人类构造的可验证问题。要扩大 RL 就需要大量环境。他的说法是：学习过程中凡是依赖人类输入的环节，都会出问题，要么增加摩擦，要么数据有限，而人类数据越来越不够。互联网数据已经用完，现在人类构造的训练环境也很有限，人们花大量钱请人造环境和任务。他引用 Nathan 的话说，开放式的自我改进是未来。

他总结 AI 需要四样东西：算力、自主性（Agency）、挑战，以及反馈，也就是给 Agent 奖励的验证信号。

三个要解决的瓶颈

  • 安全又自由的环境。自主性和安全之间有张力：给 AI 完全的自主权会危险，可能搞坏你的电脑或云环境。他希望环境里 Agent 可以完全自由，有 root 权限甚至联网，同时能撤销决定，比如装错了包、写错了程序、删了重要工具时可以回退、换条路。这对推理时执行重要，对 RL 更重要，因为要在大量问题上跑 Agent。所以需要一个能大量分支和撤销的沙盒（Sandbox，隔离的运行环境），像版本控制系统一样管理快照。
  • 好的可验证问题不够。下一代 AI 要能给自己编课程：只给一个高层目标（字幕里的例子是“学会做一个好的 RS 程序员”，可能指 Rust），它自己上网找重要内容提升技能，而不是给定题集。还要能持续学习，像 Nathan 说的那样边执行有用任务边学习。
  • 强大的验证器和校验器。验证器（Verifier）检查解答是否正确，可以是外部工具，不一定需要模型，比如运行代码或调用证明检查器做形式化验证。校验器（Validator）检查问题表述有没有被正确理解，也就是人的意图有没有被正确解读，它检查的是人和机器之间的对齐，应当基于模型。

可验证的产物

他认为下一代 AI 会产出安全、能独立验证的产物：代码要自带正确性保证。今天芯片都会经过大量验证，软件却不会；他预测未来五年内 AI 驱动的网络攻击会严重到在某些用途上没人敢运行未经完全形式化验证的软件。所以 AI 不应只生成代码，还要生成代码正确性的证明，同时还要不断提高自身的对齐，越来越会揣摩和尊重人的意图。

他把这称为自监督强化学习，也叫可验证的超级智能，两个名字说的是同一件事。他认为这会是像从监督学习（训练标注数据）跳到在整个互联网上训练那样大的一步：Agent 自己出题、自己当验证器，从互联网（或你指定的部分）自举，自己找问题、出问题、解问题，不再需要人给题。

无限的问题从哪来？他认为关键是验证：从互联网挖掘真实问题，转化成可形式化验证的产物，比如代码或数学问题，用定理证明器检查逻辑正确性，难但并非做不到，而且越来越可行。同时用这些信号构造对齐奖励：比如从网上拿到一个问题，写出解答，再问这个解答是否符合原意，可以用循环一致性（Cycle Consistency）一类的奖励信号来自举。正确性和对齐相互作用：输出不正确就谈不上对齐。他认为大部分正确性检查可以不依赖模型，像 NP 问题那样总有一个验证器；对齐则只能基于模型。两者互相促进。他还认为验证应该始终是 Agent 式的：验证器要有工具权限，能进入产物所在的环境，比如进入一个软件系统，在各种场景下测试。

架构草图和应用

他的路线图草图是：一个生成器 Agent，一个校验器/验证器 Agent，可以共享同一个模型，都连到他们正在做的 Morph Cloud 上，这个云可以分出大量沙盒、尝试不同版本、回滚。生成器把解答交给验证器，验证器和校验器回传奖励信号训练生成器，双方互相给奖励。任务来自网络，由 Agent 自己生成或爬取，不由人挑选。最重要的是产物要能完全独立验证：你不想信任 AI，你想验证它。他要的性质是：一等公民的验证、一等公民的对齐，从底层就是被强化的目标；可以在没有 AI 介入的情况下检查的可验证产物，证明可能要靠大量 AI 计算才能生成，但检查不需要；由此得到无限供应的难题。

应用领域：AI 软件工程师是必需的场景。今天模型每 100 行代码出一个 bug 还能接受，但要让模型连续数小时自主做复杂项目，这个错误率就什么都做不成，所以过程中要持续验证。还有网络安全，防止外部 AI 入侵；工程，需要大量数学和推理；科学；数学，他认为未来几年数学大多会被 AI Agent 形式化验证。目标是“无需信任即可对齐”（Trustlessly Aligned）的 AI：不靠信任 AI，要能真的检查它。因为超时，没有问答，Kyle 宣布分会场结束，4 点主舞台还有主题演讲。
