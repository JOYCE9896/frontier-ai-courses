01. Clemens Rawert（Langfuse 联合创始人）：经济史能告诉我们关于 AI 时刻的什么

直播位置 0:00:00–0:17:20 · 英文原题 What Can Economic History Teach Us About the AI Moment?

Langfuse 是一个开源的 LLM 应用可观测性和评测平台。录像开始时他正在讲经济增长的来源：增加劳动力，给劳动者加资本，或者更好地把劳动和资本变成产出，最后这一项就是经济学说的生产率提升。长期来看，经济增长主要靠生产率，生产率又来自技术进步和与之密切相关的组织进步。他说要用历史来对照他开头提到的“AI 生产率之谜”（开头部分不在录像里）。

通用目的技术

他说工业革命开启了现代经济增长，但它的核心技术蒸汽机在发明后几十年里对生产率几乎没有贡献，过了一百多年数据里才看到增长。经济史上有一类技术叫通用目的技术（General Purpose Technologies），缩写恰好也是 GPT。它有三个特征：渗透到几乎所有经济部门；能在很长时间里持续改进；有互补性，即应用改进会提高这项技术的价值，反过来技术改进又提高应用的回报。常被归入这一类的有水车、蒸汽机、铁路、电力和计算机，但没有官方名单。

另一类技术是改进研发本身的发明，比如印刷术、显微镜、企业和大学的研究实验室，以及机器学习。他认为 AI 有理由同时属于这两类，并说最近几周数学领域已经能看到 AI 改进发明过程的例子。

2% 的增长有多难

他展示了美国过去约 150 年的人均 GDP（对数坐标），长期稳定在每年约 2%，有繁荣和萧条，但趋势线拟合得很好。2% 听起来不多，但复利下来，140 年里人均收入（经通胀调整）大约增长了 10 倍。他说 1880 到 2020 年是创新极多的时代，汽车、航空、航天、生物技术、互联网都是这期间出现的，加在一起才维持了 2%。

他说 AI 可能做两件事：让这个趋势延续更久，这本身已经很了不起；或者让它加速。经济学家对加速幅度没有共识，估计从每年只比趋势高 0.1 个百分点，到考虑递归自我改进、“智能爆炸”的模型给出的高个位数百分点都有。因为生活水平是复利增长的，最终进入哪种增长状态差别会很大。

三段历史

  • 蒸汽机：让机械动力摆脱对肌肉和河流的依赖，能更大规模、更不受地点限制地提供动力。1712 年由 Thomas Newcomen 发明（字幕误作 Newman），后来 James Watt 大幅改进，但一直改进到 19 世纪才被工业广泛采用。直到高压蒸汽机普及、动力价格下降几个数量级，生产率和 GDP 才在统计上抬头。还需要互补品一起到位：新机床、铁路、轮船、新的熟练劳动力，整个经济系统围绕它发展起来。从 1712 年到最早 1830 年代看到生产率提升，过了一百多年。
  • 美国电气化：Thomas Edison 在纽约建了第一座电站 Pearl Street Station（字幕里年份是 1812，实际是 1882 年），但工厂过了三四十年才有像样的电气化。这次需要改的是工厂设计。蒸汽时代的工厂只有一个动力源，用皮带和传动轴连接所有机器（他展示了一张用 AI 生成的示意图），厂房布局要服从动力传输，常常是多层的。把蒸汽机直接换成电动机很快，但不是用电的最好方式。电的独特优势是发电和用电可以在不同地点，于是出现了“单元驱动”：每台机器有自己的电机，关掉一台不影响整个厂，工厂可以按工作流程布局，容易扩建和改产。这个改造又慢又贵，50 年后工厂用电才占到 80%。
  • 计算机：经济学家 Robert Solow 1987 年说，到处都能看到计算机时代，就是在生产率统计里看不到。当时个人电脑已经很普及，信息处理、存储和通信的成本急剧下降，但要到 1990 年代中后期生产率才有反应。这次需要的主要是组织变革：企业开发企业软件和数据库技术，重新设计供应链以适应数字化的货物核算，给员工部署大量软硬件，培养新技能。他说这种关系有时叫 J 曲线：一开始采用技术、学新流程、买硬件的投入会拖慢生产率，之后才加速。

资本市场也会和技术不同步

他比较了几次投资热潮的规模：1840 年代英国议会几乎同时批准了数百条铁路线，廉价资本、煤炭等货运需求上升，加上“每个城镇都要通铁路”的信念，铁路投资在某一年达到 GDP 的 5% 到 7%。1990 年代末商业互联网起步，美国放松管制，新运营商争相铺设长途光纤，过度建设，1999 年这波热潮约占 GDP 的 1% 到 1.5%。今天美国 AI 基础设施投资今年已经约占 GDP 的 1.8%，超过了光纤热潮，预计 2028 年达到约 3%。

他说不评论是不是泡沫，他不知道。但历史上有一个规律：不管投资者最后的私人回报如何，建出来的基础设施会留下来，后来变得有用。过剩的铁路后来带来了更便宜的运输，互联网泡沫时期铺下的“暗光纤”后来支撑了流媒体和移动时代。

技术的两个时钟

他的总结是技术走两个时钟：一个是技术创新和原型的快时钟，一个是深度融入企业和经济的慢时钟。蒸汽机需要核心技术本身继续进步，电力需要重新设计工厂，计算机需要大规模的组织变革、新技能和软硬件部署。他说生成式 AI 时代已经四年了，请大家想一想，让 AI 提升所有人的生产率需要什么：基础模型继续进步，还没被触及的行业采用，应用层的互补品，还是劳动力的再培训。他说自己没有答案。最后他说，发明创造可能性，把可能性变成增长还需要扩散、投资、互补品和组织变革；把 AI 带进企业、重组工作方式、培训员工、从零创办新公司，就是在场大多数人每天在做的事。

02. Kitze（Sizzy 创始人）：AI 工程的下一个阶段

直播位置 0:18:44–0:45:05（主持人介绍从 0:17:45 开始）· 英文原题 The Next Level of AI Engineering

主持人介绍 Kitze 是 X 上以“暴论”出名的开发者，自称“master tinkerer”（爱折腾的人）；演讲后又补充说他是 AI Engineer YouTube 频道上观看量最高的讲者之一。Kitze 说如果大家在 X 上认识他，大概和他吵过架。他说还有 20 多分钟就得去赶 Uber。他只放了一张自我介绍的幻灯片：一个给喜欢折腾本地 LLM、硬件、自托管的人建的社群（字幕作 thinker.club）。

从 vibe coding 到软件工厂

他之前在 AI Engineer 讲过“从 vibe coding 到 vibe engineering”，他说现在讲仍然适用，很多人还在这个转变中。但他已经感觉到下一步：大家在说的“软件工厂”（software factory），他戏称为“slop 工厂”，他预计今年第四季度和明年会越来越多。

他先回顾这几年：很多人还在用 Copilot 按 Tab，管这叫 AI；后来从 ChatGPT 复制粘贴，那时它连一个函数都写不完，要求它继续；再后来求它只输出干净的 JSON 别带 Markdown，它照样给你 Markdown 加 JSON。之后只让 AI 改一个文件，觉得这已经很危险；然后有了 Agent，但大家每个权限请求都仔细审。一年后，Agent 问能不能跑某个命令，他说“我怎么知道，大概可以吧”，现在他认识的人全都开着全权限模式在跑。

三类人

  • “扔 slop 手雷的人”（slop grenade thrower）：他说多数人都是，包括想避免的人。让 Agent 生成一堆代码，自己不读，扔给同事，“祝你好运，希望别炸了生产环境”。
  • “肉身代理”（meat proxy），这是他最近最喜欢的词：上级让你做一件事，你把他的话原样贴进 LLM，结果几乎不看就交回去，你只是个人肉转发器。他说很多公司已经是一层层肉身代理在互相对话，他预计明年会很残酷，很多人会被裁。
  • 真正的 AI 工程师：人不多，他们给自己的流程建系统，但他说还没人有对的系统。

他说 GitHub 上已经能看到“slop 手雷大战”：有人用 LLM 开了一个带 emoji、分段、分隔线的漂亮 PR，同事回了一份更长更漂亮的 review，两个肉身代理服务两个 LLM 在对话，谁也没意识到。

工具和方法

他说一直有桌面派和命令行派。他以前讨厌终端，喜欢能点的漂亮 UI。他吐槽三年里从 Cursor 到 Conductor 出了那么多编排器（orchestrator，同时管理多个 Agent 会话的应用），全是一个布局：左边会话列表，中间对话，右边 git diff，“我们刚融了 3,700 万做一个新编排器”，截图一看分不清是 Codex 还是 Cursor。命令行派里还有极端的人，在虚拟机里套 Proxmox 再套 oh-my-pi，问他们交付了什么，回答是“反正我的工厂能跑”。他以前嘲笑自托管的人，劝大家付钱给 Vercel、Railway，后来自己也跑去弄 Linux 机器和 Tailscale 了。

他把自己试过的方法依次讲了一遍：

  • 一个会话一直提示到做完：只开一个会话，把任务都排进队列，Codex 的自动压缩（compaction，上下文快满时把历史对话压缩成摘要）让它能一个接一个做下去。但任务之间没有管理，不会启动子 Agent 审查或测试，只能希望它都做完。
  • 一个任务一个会话：如果不用 git worktree（同一仓库的多个独立工作目录），就得猜功能会不会互相冲突；用了 worktree，又需要一个会话来管理这些会话。
  • worktree 加祈祷：他说七周前大家才知道 worktree，现在人人都是 git 工程师。问题是 worktree 不是完全隔离的系统，照样能删掉你的数据库。
  • 各种新术语，比如“gauntlet loop”，有的有用有的没用，他说学起来让人不堪重负。软件工厂也一样，让 AI 去搜关于软件工厂的文章能读到崩溃，但几乎没人真的有一个，大家对它应该是公司级还是个人级都没有共识。

他的设置：笔记本只当遥控器

  • 他最近回到命令行，用一个类似 tmux 的工具（字幕作 Herder），远程编码时会话不会断，并按机器整理好。他说两周前只用它加最简单的终端，交付得最多，开始怀疑大家把软件工厂想复杂了，但也取决于你是独立开发还是团队。
  • 他改用 Pi。他说以前也嘲笑用 Pi 的人，但他的 Claude 额度用完就切到 Codex CLI 或 Cursor CLI，每个工具启动子 Agent、做压缩的方式都不一样，在它们之上做编排器很难。Pi 是一个开箱什么都不带的 CLI，压缩、子 Agent 都要装插件，流程完全自己控制，他称之为“Harness 里的 Linux”。
  • 他有一次把奶昔洒在笔记本上，差点丢掉一个月没推送的代码，于是决定笔记本和手机只作为遥控器，活都在别处跑。他先放到 Mac Studio，发现 macOS 不适合远程 Agent；租了每月 128 美元的 VPS，算了算两年的钱够买台 Linux 机器；于是把游戏 PC 格式化装了 Linux，内存不够又升级，最后从零组了第二台 Linux PC。朋友建议装 Proxmox，他就让 Agent 去装。他说凡是他提到的这些，都默认他自己搞不定，是 Agent 配的。
  • Proxmox 上可以跑多台 Linux、Windows 虚拟机和容器，他给自己的 Hermes 等 Agent 各分配一台小虚拟机，让它们无法越界。远程编码时，他建议让 Agent 配好 Traefik 和 PM2，所有进程都有好记的子域名，而不是一串 IP。他说有人问他配置里有什么，他说两年没看过配置了，“许个愿事情就发生了”。

额度、连接器和技能

  • 额度：他付了四个每月 200 美元的订阅，说仍然比雇人便宜，但要管理用量。他用一个 Codex 负载均衡器，把多个账号合成一个端点，按日限额和周限额自动选账号，同一个端点还能做实时语音和生成图片。Cursor、Gemini 等放在另一个代理（CLIProxyAPI）后面，最上面再套一个 AI 路由器作为总端点。他自嘲说做了这么多还没交付多少，大家用 Pi 加那个终端工具可能更高效。
  • 连接器：他强烈推荐 Executor，说比当初推 OpenClaw 还卖力。每次换一套 Agent 设置都要重新连 Gmail、日历、GitHub、Cloudflare，Executor 把所有连接器收进一个 MCP，换 Pi、Claude、Codex 或任何机器人时只要接这一个 MCP。
  • 技能：他开源了 Skillbox。他认为把技能（skill，给 Agent 的说明文件和脚本）放在一堆 Markdown 文件里是错的，换台电脑就没了。他做了一个用单个 MCP 提供所有技能的服务，做的过程中 MCP 规范正式加入了“skills over MCP”。Skillbox 还有技能包（skill bundle）：个人 Agent 只需要四个技能，编程 Agent 需要另外 20 个，互不干扰。
  • 他在想更高一层，Codex app 把它叫插件（plugin），装一个插件会同时装好 MCP 和技能。他提到 Kent C. Dodds 的 Kody（字幕作 Kodi），部署在 Cloudflare Workers 上，把 Agent 的“大脑”打包后可以移植到任何地方；Executor 的第二版也会往这个方向走。

最后落地的流程：一个任务、一台一次性小机器、一个 PR

他说一个会话塞很多任务会冲突，多个会话会互相踩，worktree 也有问题。他有一次只用 worktree，Agent 为了测试去 seed 数据库，结果删掉了生产数据库，幸好有备份，因为 worktree 不是沙箱。他现在的目标是一个会话、一个 worktree、一个高质量 PR，带类型检查和 lint，全部自动化。他说以前作为独立开发者连 PR 都不用，全推到 main。

他讲到 Amp 的一位工程师提出的“orb”：每个任务给 Agent 一台小沙箱或小虚拟机，它边做边通过一个隧道暴露 URL，人可以打开去看、去点、去测，人的角色变成 AI 的测试员。他说自己一开始在 X 上嘲笑“orb 不会成为一个词”，走完上面这一圈后改口了，认为这是做出隔离、测过、走完工厂流程的东西最稳的办法。他的 Proxmox 机器为每个任务起一台一次性虚拟机，里面有数据库、种子数据、浏览器等一切，用 Podman 运行，拿不到生产凭证；有队列，同时最多 8 个，不然电脑会挂。

护栏（Guardrails）方面，他说没有硬性约束时 Agent 会去 ESLint 配置里关掉一半规则然后说“完成了，没有错误”。他用三件套：Oxlint、Ultracite 和一个叫 Anti-Slop 的库（作者名字幕不清）。很多规则 lint 表达不了，比如“永远用 shadcn 的按钮，别自己写按钮”，他就让 Agent 写了一个自己的检查 CLI，叫 police。最后还有一个他开源的工具（字幕拼法不一，像 Jeff），类似 CodeRabbit，用自然语言写不希望出现的规则，它便宜又快地检查整个 PR，比如注释是否无用。

演示：Bench

他最后快速展示了自己的编排器 Bench，说这是“你这辈子见到的第一个好看的 Agent 编排器”，像 Steve Jobs 会做的那种，没有左侧边栏。它按项目组织，每个项目有待办、计划、心跳（heartbeat）等。点进“工厂”能看到每个任务的流程：一个编码 Agent 写，另一个审查，两者循环直到审查通过，再由测试 Agent 去点击检查功能是否完成，最后进入一个审阅界面。他现场添加任务没跑起来，说正常应该自动进入就绪并走完整个流程。他说 Bench 会在 X 上发布，有了它他不再用 CLI 或 Codex app，用任何低配设备甚至手机就能指挥整个“slop 工厂”。

03. Lélio Renard Lavaud（Mistral 工程 VP）：构建前沿 AI

直播位置 0:45:54–1:11:45 · 英文原题 Building Frontier AI

主持人（自称在 Replit 工作）介绍 Lélio 是 Mistral 的工程 VP，也是公司第三号员工。去年他在同一场合讲过开源与企业落地（见本系列第 17 篇）。

Mistral 这一年

  • 规模：公司成立三年零四个月，现在有 1,300 人。他说 Mistral 是欧洲顶尖的前沿 AI 实验室，使命是把 AI 交到客户手上、改变企业的运营方式；他们追求的是有用，并不追 AGI，所以有专门团队把概念验证变成生产系统。
  • 大会：今年注册 700 多人，50 多位讲者。
  • 收购 Koyeb：去年邀请他来讲的承办方 Koyeb 如今并入了 Mistral。他解释原因：工作负载在转向 Agent，“成群的 Agent 到处跑”，需要一个专注沙箱、专注运行 Agent 工作负载所需计算单元的团队。他引用 Koyeb CEO Yann 去年的话：从第一天起就贴近硬件，在全球 10 个地点的裸金属服务器上运行数万个应用。Mistral 自己需要安全、快速的后台异步执行时，就用这套技术。
  • 5 月宣布收购 Emmi AI（字幕作 Emmy AI），一家做物理 AI 仿真的公司，目标是帮工业客户设计下一代飞机、汽车和半导体，把仿真和对物理世界建模的能力带回模型里。
  • 今年早些时候宣布了一项 1.5 亿美元的合作（字幕作 Orbus，从上下文看应是 Airbus），用于构建这类客户的专用模型。
  • 上周宣布 D 轮融资 30 亿欧元，他说是欧洲科技公司最大的一轮，投资者来自欧洲和全世界。

他说知道大家想听某个新的大模型（名字字幕不清），今天不发布，但团队在努力。

未来的工作方式：一套统一的 Harness

Mistral 的产品线：面向开发者的 Studio，在模型之上提供进生产需要的原语，比如长时间运行的工作流和前面说的沙箱；面向终端用户的 Vibe；解决方案团队给客户做用例；科学团队训练通用和专用模型。

他用一个人物举例：Steven 在 Mistral 财务部，负责确保收入用得合理，是个“tinkerer”，但没时间像前一位讲者那样在地下室组装工作站。他需要既能问简单问题、又能构建应用的工具，比如做一个应用去交叉核对数据湖、Excel 和 Notion 里的数据，再分享给同事。他身处有数据使用规范的企业环境，统一版 Vibe 要服务这种“懂得越来越多的普通用户型构建者”。

工程师的例子：从半夜一条 Slack 告警到 Agent 自动调查。值班工程师起床走到电脑前时，异步 Agent 已经在沙箱里跑起来，通过 Grafana、Sentry、GitHub 连接器查看哪些 PR 可能导致了回退，把线索发回 Slack，工程师可以接着对话。他展示了一条 Sentry 告警和 Agent 的即时回复。他说以前做这件事要大量胶水工作：Agent 跑在哪、给它接哪些连接器。现在的方向是 Steven 也能输入的简单提示，比如“面试反馈缺失时，给忘了写的面试官发一条个性化提醒”，不用再去想接哪个招聘系统的 MCP。Vibe 理解意图后，在后台启动 Agent、写代码、跑、测、部署、托管，自己迭代几分钟到几小时，交付一个能分享、按你的权限设好访问控制的结果。

他说这种用例到处都有人在做，但通常是让任何 Agent 不受控地访问任何数据，所以进不了生产。他们的思路是把各种角色合并：用户不用会写软件，只要指挥 Agent；用一套统一的 Harness，财务、法务、工程用同一个产品，模型根据场景调整用什么、显示什么；会话可以在本地笔记本开始，“传送”到网页上，在沙箱里执行，在手机 app 上查看和引导，推到 GitHub、检查 CI 并迭代。平台随使用变得更有价值：有人创建技能或应用就能分享给团队；Agent 运行一周后，通过看执行轨迹（trace），技能可以自我修正，比如发现第一次调 Grafana MCP 用错了一个没文档的选项，之后改正，更省 token、更快。

Agent 安全

他说过去十天大家家里大概都有人问过“AI 会不会毁灭世界”，Mistral 不会，并在 Agent 安全上大量投入。他列的威胁模型：Agent 有访问大量连接器和数据的特权；它不确定，很难写死“如果你这样做就别做”的规则，因为下一次它可能不这样做；还有攻击者控制的输入，即提示注入（Prompt Injection，把恶意指令藏在 Agent 会读取的内容里），越来越复杂，模型层面防御总会被越狱，只要读外部数据就有风险。

防御手段：在模型层面让它更会分辨注入、真实指令和不可信上下文；限制 Agent 权限，运行时只给需要的，并按步骤和工作流动态调整；沙箱；运行时护栏，观察 Agent 的底层轨迹。他说沙箱的价值在于能看到每一个系统调用和网络调用，由此推断 Agent 是在走正常模式还是异常。难点是护栏加满后，强大的 Agent 什么也做不了。他们的解法是“动态协作”：在需要且有理由的时刻授予恰当的权限，并过滤哪些操作应当允许、为什么。

他放了一段演示：让 Vibe CLI 根据一个 GitHub issue 执行任务，issue 里藏着提示注入，Agent 照做发出一条命令，把一个密钥外泄出去。然后演示企业管理员的防护：定义规则，选择分类器（PII、密钥、公司知识等）、来源、阈值、审核方式和触发后的动作；把规则挂到一个策略上，指定作用于哪些产品界面（网页版 Vibe、手机 app、CLI）；启用后再跑同样的任务，在网络层被拦下，用户自己什么都不用配置。他说这就是企业级控制的作用，用户不需要主动选择被保护。

主权

他说只有安全不够，AI 还要有主权。他分了几层：数据主权（数据存在哪、保留多久、谁能访问、哪家云厂商或公司因为司法管辖可能读到）；智能主权（分析模型行为、微调在哪里进行）；算力主权（即使到处签了零数据留存 ZDR 协议，数据仍会经过某些地方）；运营主权（清楚公司里发生了什么、安全和审计日志）。

他说 Mistral 从模型公司变成产品公司，现在在建自己的数据中心。他展示了巴黎附近一座 10 兆瓦的设施，使用 NVIDIA B300，说是欧洲配备这类最新硬件的最大数据中心之一。这里运行 Mistral 的关键内部工作负载，也承载最敏感的客户工作负载，从而提供从 Agent 安全到推理和训练的端到端主权路径。他还说会在欧洲各地投资数据中心。

模型

模型分通用和专用两类。通用模型有不同尺寸，他说大家在等一个大的，希望很快能交付。专用模型又分两种：服务很多场景的，比如 OCR 和语音；以及为有特定数据的客户微调的，比如稀有语言，或者某些公司内部有别人没听过的编程语言，默认的编程模型不擅长。还有几个实验性模型用来探索科学前沿：一个做形式化证明的模型（字幕作 linstrol），一个上个月发布、用很快的架构回答内容审核问题的安全模型（名字字幕不清）。

  • Voxtral 语音模型家族。他先播放两段音频，内容是他去年在 AI Engineer 上说过的话，让观众猜哪段是 AI 生成的，然后揭晓其中一段是合成的，用来展示声音克隆能力；他们在提高准确度，模仿各种声音和口音。语音转文字方面，他说已有最先进的模型，正在做实时说话人分离（diarization，区分谁在说话）、更多语言、准确时间戳和嘈杂环境。他放了一段实时转写加翻译的视频，内容是一家银行讲 KYC（了解你的客户，开户时的身份审核）流程：他们和 Mistral 为比利时的企业客户做了两个 Agent，送到中台时资料不全的文件从 80% 降到 10%。他强调这是真实的实时转写和翻译，并说他们不追求刷基准，追求对客户有实际效果。
  • OCR：今年夏天发布的 OCR 模型（字幕作 4.1），能转写手写和 1960 年代的扫描旧文档，区分标题、正文、表格、图片和图注。它用在 Vibe 的文档库里：用户上传可能多达 TB 级的非结构化文档，需要时都经过 OCR 流水线，运行时可查询，这也是他们给客户做高级 RAG 流水线的基础。一个月前加入了边界框（bounding box）输出。这些模型都可以在 Studio 的 playground 里试。

他最后概括了四个方向：超越聊天助手、合并终端用户和构建者的新工作方式；Agent 安全；主权和数据中心；以及继续推进模型，他说科学团队规模从未这么大。他说 Mistral 有 1,300 人但仍在招人，并感谢 Jen、Alistair（字幕拼法不一）等组织团队和主持人。
