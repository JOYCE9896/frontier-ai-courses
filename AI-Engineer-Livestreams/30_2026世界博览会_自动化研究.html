02. Thariq Shihipar（Anthropic，Claude Code 团队）：Fable 使用指南

直播位置 0:16:07–0:35:44

Thariq 在 Anthropic 做 Claude Code。他先按 Claude Code 团队的传统和观众拍了张自拍。他说 Fable 当天晚些时候开始推出，具体时间等通知；他和 Cat Wu、Simon Willison 会在 12:30 做一场炉边谈话，也许那时有更新。他把 Fable 和 Sonnet 3.5 new、Opus 4、Opus 4.5 并列，说这是会让人记住的那种模型。他的比喻是 RPG 游戏走完新手教程、进入开放世界：能做的事一下多了很多，也有点让人不知所措。这场演讲是他原本计划写成系列文章的内容，分四部分：解放 Claude、找出你的未知、面对失落、变得不讲理。

一、解放 Claude（unhobbling）

他说模型是"长出来的"：团队不会先定一个"SWE-bench 要到 99%"的目标再去设计，他们给数据、反馈和算力，再在使用中逐渐了解模型。所以真正限制模型的是人：我们放模型进去的 Harness（包在模型外面的那层程序，负责工具、上下文、权限和循环）以及我们的提示词，都取决于我们对 Claude 的理解。

他举了一条走红的推文：为什么 LLM 答不出名字以 "aw" 结尾的宝可梦？一千多只宝可梦里只有两只（Crawdaunt 和 Dreadnaw）。普通聊天模型答不出来，虽然它肯定知道所有名字；Claude Code 能答出来，因为它会把所有宝可梦抓下来写个脚本过滤。他们把这叫能力悬置（capability overhang）：模型已经有的能力，要换一种用法才发挥出来。模型变聪明的方式是"尖刺状"的。

  • 上下文：早期大家以为解决编程的办法是上下文足够大，把整个代码库贴进去，甚至需要一亿 token 的上下文窗口。后来发现给模型"手臂"，也就是 bash 工具和操作环境的办法，它能自己搜索、构建上下文。这就是 Claude Code 的出发点。
  • Claude Tag：最近推出的 Claude Tag 能主动工作、多人协作。Claude Code 需要人提示才干活，而 Claude 自己醒来做事被他们看作下一波 Agent 的开端。
  • 系统提示词：他们最近删掉了 Claude Code 系统提示词的 80%。Sonnet 3.5 new 时代的最佳实践是短系统提示词、少量工具、大量示例；后来模型能遵循更多指令，提示词变长、工具变多；这一代模型反而想要更短的系统提示词，示例会限制它，因为它比示例更有想象力。他们尽量给上下文，少给约束，少写"不要做某事"，这一点对旧模型是必需的。
  • AskUserQuestion 工具：这是他刚到 Claude Code 时做的，Claude 规划时可以弹出多选题问用户。Opus 4 几乎调不动它，他得反复调工具描述；到 Opus 4.5，他可以让它就规格问自己 40 个问题，相当于面试他；到 Opus 4.8 和 Fable，它可以生成一整份嵌入问题的 HTML 报告。
  • 输出格式：起初 Markdown 是好的输出格式，Plan mode 让人能读懂 Claude 要做什么；现在 Claude 能生成深入的 HTML 报告。

他说这更像生物学而非物理学，仍然很经验化，但有可以积累的直觉。他推荐 Anthropic 的论文《On the Biology of a Large Language Model》。

二、找出你的未知

他说用 Fable 也得解放自己。地图不是领土：脑中的计划、提示词、规格是地图，真实的代码库和约束是领土。Claude 在领土里碰到地图上没有的东西，他称为一个"未知"，也就是一个他没指定的决策点。Fable 能走的范围很大，会碰到很多未知，所以他的瓶颈变成了自己匹配地图和领土的能力。他用四象限来想：已知的已知（写进提示词的），已知的未知，未知的已知（太显然以至于不会写下、但看到就知道的），未知的未知。他的做法：

  • 盲点扫描（blind spot pass）：比如"我在这个代码库里接一个完全不了解的认证服务商，帮我做一次盲点扫描，找出相关的未知的未知，帮我写出更好的提示词"。Claude 会翻认证模块、找常见的坑，也可以去搜 git diff 或 Slack。他最近用这招学视频剪辑里的调色。
  • 头脑风暴和原型：针对"看到才知道"的东西，比如设计。他会说"我没有视觉品味，给我做一个 HTML 页面，放四种差别很大的设计方案让我挑"。
  • 访谈：让 Claude 采访自己，并告诉它背景，比如"优先问那些会改变架构的问题"。
  • 参考：给 Claude 地图最好的办法是给它另一张地图。比如给一段其他系统或语言里实现了目标的代码，或者做 React 组件时给一个 HTML 样稿。
  • 实现笔记：让 Fable 在碰到未知时记录下来，事后看偏离发生在哪、为什么。
  • 让 Fable 考自己：确认自己理解了做出来的东西，提 PR、合并时能为这份工作负责。

三、面对失落

他说第一次用 Fable 时既有收获感也有失落感。他以前经营过一家约 30 人的 YC 创业公司，因为写代码太难，总是被迫取舍：是让应用变快，还是做一个新功能原型，各要一两个月。几周前他回到那个代码库，原本要几周的事几小时就做完了，"怎么能不笑，又怎么能不哭"。他喜欢手写代码、在脑中转动代码库的感觉，但也记得熬夜调试、几周没进展、大多数项目失败、大多数创业公司破产。他说自己回不去了，"唯一的出路是穿过去"：继续学，保持在回路里。

四、变得不讲理

他说他在 Anthropic 最喜欢的一点是相信取舍并不真实。以前他会列优先级、排季度目标；现在的问题是"如果全都做呢？逼现实把取舍摆出来"。好、快、便宜，现在可以三个都选。他说这份幻灯片是前一晚用 Fable 花大约四小时做的。他认为证明 Agent 有用的唯一办法是以前所未有的速度做出一生中最好的工作，而外界等着看的就是在场的 AI 工程师。他今年的目标是更高效、工作更少、多陪在乎的人。他最后提醒：构建变容易了，创造价值仍然难，要多试几次才找到有价值的东西。

03. Tariq Shaukat（Sonar CEO）：把验证做进 Agent 循环

直播位置 0:35:44–0:53:43

他开场说没想到早上前两位讲者都叫 Tariq。Sonar 做代码验证，客户主要是全球的企业。他说大会上大家相信 AGI 已来或将来，但企业客户问的是带问号的版本：AGI 真的来了吗？原因是新闻里不断有咨询公司因幻觉撤回报告、律所因编造判例惹麻烦。模型擅长生成看起来对的内容，但怎么知道它真的对，这在专业服务、法律以及所有行业都是问题。

数据：快了，但没那么可靠

  • METR 的任务时长曲线（衡量 Agent 能完成人类需要多长时间的任务）：按一个月前预览期的测试，最新的 Mythos 模型在 50% 成功率下能完成人类 16 到 18 小时的任务。把成功率要求提到 80%，进展慢得多，大约 3.5 小时。一位大客户的 CTO 对他说，给我 80% 准确信息的人，我大概还是会让他进绩效改进计划，这不算企业级。
  • Sonar 自己的基准：给模型 4,000 多道题，看功能正确性，再看代码复杂度、bug 和安全问题。各模型功能正确性都很好，但复杂度仍高且波动大，GPT-5.5 在复杂度上表现较好；所有模型都仍会产生 bug 和安全问题。他说 Fable 还没测。
  • Carnegie Mellon 的一项研究：用编码 Agent 后速度先提升 3 到 5 倍，三个月内消退回原水平。原因是安全、可维护性、可靠性问题和复杂度同步上升，技术债产生得和代码一样快甚至更快。

他说代码可以被证明，但大型代码库里的软件很乱、依赖多、本来就背着技术债，所以验证是核心。可以把验证当事后环节，也可以把它做进生成过程，后者效果好得多。

AC/DC：以 Agent 为中心的开发周期

Sonar 的框架叫 agent-centric development cycle，简称 AC/DC。中心是代码生成，周围是三件事：引导（guide）、验证（verify）、解决（solve）。他们前一天发布了一个叫 Sonar Vortex 的产品，针对引导这一环。

  • 引导分成上下文和约束。上下文是让 Agent 理解代码库，给它架构感知和语义导航地图，他借用了 Thariq 的"领土"说法。约束是编码规范、允许和禁止的依赖、护栏、目标架构（他说大家常谈现有架构，很少谈要去的架构）。他们测试中这样做让 Agent 效果大幅提升，解决同一问题的 token 用量减少 30% 以上。他把引导称为"预先验证"。
  • 验证是"零信任、多层"。零信任是因为每个模型都有偏向，要用不同模型和不同技术；多层是把算法验证（数据流、控制流、已知模式、密钥泄露）和 Agent 式验证（意图、业务逻辑、未知的未知）结合。使用多层验证的客户报告 AI 导致的生产事故少 44%。
  • 解决：技术债会爆炸，要有主动的代码维护流程，比如修复 Agent。有人问 Agent 在乎干净代码吗，他说在乎，因为 Agent 也要理解代码库；同样的任务在清理过的代码库上需要的 token 和推理明显更少。

他说这些要组成系统，分三个循环：Agent 循环（生成时给上下文、约束和环内验证）、CI 验证循环（结合算法和 Agent 审 PR，评测和质量门禁）、代码维护循环。这个系统会自我强化，向好或向坏都会。和一家大银行做的测试里，在 Agent 循环中采用引导、验证、解决的方法，问题减少 92%，这是随时间复利累积的效果。最后他放了一版标上 Sonar 产品的图，说是市场部要求的。

04. Amazon AGI Lab 技术人员（字幕未能识别姓名）：感知 Agent

直播位置 0:53:43–1:15:10

主持人介绍她是 Amazon AGI Lab 的技术人员，名字在字幕里被音乐盖住了。她说一年前的难题是让 Agent 在没见过的屏幕上找到按钮点下去；现在 Agent 能操作浏览器，也开始操作桌面应用，但点击是容易的部分，真正的工作没解决。

工作在缝隙里

她举新员工入职：开账号、拉进 Slack 频道、约同事介绍、订电脑，没人端到端负责，牵涉五个系统。Agent 大概能做每一步，却做不完整件事，因为真正的工作在这些应用的缝隙里。她说我们已经教会了计算机用计算机（点击、滚动、输入、调 API、填表），这些属于能力；下一个难点是可靠性，没有可靠性就没有信任。她让观众估计端到端工作流的成功率，大概 60% 或 80%，然后说如果 Agent 四次里有一次删库，你再也不会用它，可靠性要到"几个 9"。

编程是唯一在可靠性上取得巨大进展的领域：从自动补全到写函数，再到 Agent 自己开 PR，人们已经不逐行读代码了。原因是代码可验证，能运行、能测试。而大多数知识工作没法验证：报告有没有打动人、设计是否符合品牌、它理解我的意思没有，这些没有单元测试。

人是怎么做的

人处理这种工作靠一起琢磨：拉同事开个 Zoom，看同一块屏幕，两分钟解决。她说 Agent 缺的是共享上下文，不需要更大的大脑。她借用机器人学的"感知、规划、行动"循环：Agent 要像人那样接收屏幕上实际渲染出来的内容（布局、状态、刚刚发生的变化），不靠抓背后的代码；还要实时跟上，在你工作的同时给建议，不用发提示词、等待、来回好几轮。她们把这类 Agent 叫感知 Agent，并说它的意义有三点：能读渲染后的屏幕来确认自己的输出；不需要 API，因为大多数日常软件不开放 API；输入也可以反过来，用户直接指着屏幕说"这个标题改一下"，比长段文字精确。

开源的两个部件和演示

05. Benoit Schillings（Google DeepMind 研究副总裁）：代码之后还有什么

直播位置 1:15:10–1:35:54

起源和三个时代

2018 年他在 X 启动了 Pitchfork 项目，研究机器学习怎样改进写代码。当时在 Google 没人理会，"为什么要用 ML 写代码"；他们自己也低估了速度，原本只想压缩那种要等三天审阅的小改动周期。有人说用英语编程，他当时不屑，"英语不是编程语言"，现在承认错了。他写了 45 年代码，从给 Apple II 和 Commodore 64 写游戏、写汇编开始；写汇编的人怀疑编译器，写 C++ 的人看不起垃圾回收，现在他用 Python 和 vibe coding。

他分了三个时代：机器是瓶颈的时代，要榨干硬件；云时代，算力便宜，瓶颈是人脑，人只能同时抓住七到九个"token"，这决定了模块化、库、函数这一整套软件工程做法；现在的 AI 前沿时代，写代码不再是挑战，难的是确认代码是你真正要的，人在近期会负责架构和归纳式思考。

现在在哪

他说语法生成已经超人，他上次看 Gemini 写的函数觉得"我能写得更好"已经是过去的事。还差的是多步骤的代码库工作：软件工程是你第一天入职发现有 3,500 万行 PHP、还得改它的那一刻。再往上是架构，他提到 Google 有 Jeff Dean 这样的架构师，那种思考涉及硬件优化、安全，以及十年后不后悔。

代码之所以先被攻克，一是数据多，可以抓 GitHub；二是验证合理，能编译、能跑单元测试。但现在训练数据用完了，他说 GitHub 上新增代码约 80% 是机器生成的。好消息是可以自我对弈（self-play），就像 AlphaZero 不靠人类知识下成超人围棋和国际象棋。前沿代码模型已经能给自己出题、判断答案、一定程度上评判架构。他的思想实验：把一位优秀工程师关在房间两年，送披萨，任务是变得更强，他会给自己出可验证的题不停练，模型也可以，限制只是算力和自我对弈的时间。

代码几乎免费之后

他说代码的经济学变了：整套软件工程文化建立在写代码昂贵的假设上，现在写代码几乎免费（他在幻灯片上加了波浪号），代码量会爆炸。他预测一年内大家会让 Gemini 等模型生成代码而没人去看，就像现在几乎没人检查编译器输出的汇编。由此他列了几条：

  • 主动护栏：Mythos 在代码里找出大量漏洞的新闻之后大家忙着打补丁，但这会没完没了，模型更聪明就找更深的漏洞。他的团队在研究让模型从一开始就写对，这很难，因为高度依赖上下文。
  • 归纳式架构：模型还不擅长跨领域迁移知识、找两个概念的交集，也要学会把复杂问题正确分解。
  • 评测要改：他说 SWE-bench "在他看来声名狼藉"，因为它只检查代码能跑、输出对，只是软件工程的一小部分。他想要开放式问题，比如文本压缩：给 10MB 数据，让模型写最好的无损压缩器，损失是压缩后大小加源码大小，这种题没有终点，会逼模型发明新算法。
  • 思考不只是 token 链：他认为写代码是视觉化的活动（框图、数据流），Gemini 从一开始选择多模态，他们在看模型怎样用空间或动态表示来解题。
  • 为模型设计新语言：Python 等是为人设计的，不适合写安全可靠的代码。既然写代码的痛苦不存在了，可以用强类型、受 Lean 启发的语言把正确性的负担放到模型身上，而且不必让人能读。

代码之外

他说快速实验的能力正在影响其他领域。化学：分子超过 20 个原子人类就很难预测它的行为，一万个原子放在一起开始像生命。生物学：自然做了出色的工程，文档却很糟。最后是"看不见的金子"：人类的直觉是为在丛林里生存训练的，不是为量子计算，会有很多突破摆在眼前而我们看不到。

08. Richard Socher（Recursive 联合创始人，You.com 创始人）：Eureka 机器与递归自我改进

从进化讲起

他说进化是一个开放式过程，从生物学走到科学、技术，最终到 AI。他引用"每开掉一个语言学家，准确率就上升"（机器翻译时代的老话），开玩笑说也许该"开掉"在场的 AI 工程师，让大家去管理一个做 AI 的 AI，大家都升任经理。接着他快速缩放时间尺度：35 亿年的生物进化；几百万年里技术推动世界产出，一连串指数曲线各自变成 S 曲线；最近几千年技术让人口增长。他引用 Marc Andreessen 的《技术乐观主义宣言》：经济唯一永久的增长来源是技术，没有物质问题不能用更多技术解决（饥饿对应绿色革命，黑暗对应电灯，寒冷对应供暖）。生于 1900 年的人三岁时莱特兄弟首次持续动力飞行，1969 年人类登月。他说我们来不及探索地球、来不及探索星空，但正好赶上造出 AI，在一生里从 AI 处处不如人走到每项任务都更强，因为一切更快，也许只需 30 年。

Eureka 机器的四根支柱

他说几个月后会出一本讲这个的书。四根支柱：已有知识；科学测量数据；对还测不了的东西建模拟，能模拟就能验证、就能用 AI 解；最后仍需要真实世界的实验室。之上是一群 Agent 处理这些知识、数据、实验和奖励。他还说每一层技术（互联网、浏览器、GPU）都可以为超级智能重做一遍，比如 You.com 做给 Agent 的搜索：Agent 能读几千条很长的片段，而不是十条蓝色链接。

怎么造？他说最好的办法是让它自己造自己。NLP 的历史一再表明，把手工流程换成学到的系统就会进步：从语言学家给特征，到词向量和端到端反向传播，再到统一架构。所以他主张用 RSI（recursive self-improvement，递归自我改进，指 AI 改进下一版自己）来造 Eureka 机器。他说这在过去六到八个月才变得可能，因为 AI 是代码而 AI 能写长时程的代码。科学研究的三步是构思、实现、验证。

三个早期结果

他区分了 autoresearch 和真正的 RSI：真正的 RSI 要对自身缺陷有自我认识，能控制从预训练到 RL 训练和 Harness 的一切，并更新下一版自己；让系统去改进另一个 AI 训练流程（比如五分钟的 nanochat 训练）是重要里程碑，但不是真 RSI。他们的系统在三个任务上的结果：

  • nanochat：五分钟内训练一个小聊天模型，追求最低 bits per byte（每字节比特数，越低说明模型对文本的预测越好）。社区做到 0.93，系统跑了一两天做到 0.91。他说它不只是调超参数，还找到了哈希二元组、三元组嵌入表并通过学到的门控混入注意力的 value 路径等新想法。
  • NanoGPT speedrun：在很短时间内超过了社区一年多（很多人也借助 AI）的成果，把时间再缩短两秒多，到 70 秒左右。
  • CUDA kernel（在 NVIDIA GPU 上并行执行的底层运算程序）：几天后在 NVIDIA 的基准排行榜上各类 kernel 都超过榜首，幅度不小。团队里没有专职 kernel 专家，他们和 NVIDIA 一起核查过没有奖励作弊（reward hacking，模型钻评分规则漏洞拿高分）。他还说大规模 MoE 模型在昂贵集群上利用率常只有 30% 左右。

结尾他说每条指数曲线终会变平，但智能有很多"空间"（他列了十个，没时间展开），在每个维度上我们离上限都还远得很（原话是"天文数字般远"）。

09. Han Xiao（Elastic，Jina AI 创始人）：小型检索模型能靠测试时计算变好吗

直播位置 2:20:15–2:40:34（前面 2:16:07 有一段 Meta 演讲的开头被切断，完整版见第 14 节）

他 2020 到 2025 年经营 Jina AI，去年 10 月公司被 Elastic 收购，现在在 Elastic 带模型推理和训练团队。他的问题是：大模型能靠推理时多想变好，这叫测试时计算（test-time compute，不加大模型、在推理时多花算力换更好答案，比如 best-of-N 采样、自洽投票、用验证器重排）。小型检索模型能不能也这样？他让 Agent 跑了一夜 autoresearch 来找答案，结果比"能"或"不能"更有意思。他引用 OpenAI 的 Noam Brown：一个扑克机器人思考 20 秒，效果相当于把模型放大 10 万倍。

搜索本来就是测试时计算

他说搭搜索系统就是在推理时组装更多东西：训练好的嵌入模型、重排器、多因子检索、查询扩展，用推理开销换相关性。他分两个层面研究：版本 A，Agent 在单个冻结的嵌入模型（把文本变成向量的编码器）之上写一个小程序，做切块、打分、融合，相当于嵌入向量上的多轮代数；版本 B，一个小 Agent 在固定 token 预算下把 grep、embed、rerank 等检索工具接成流水线。

版本 A 的设定

常见看法是测试时计算只属于大推理模型。但今天的嵌入模型（E5、Mistral、Qwen3 Embedding、EmbeddingGemma、Jina 自己的模型）都从 LLM 主干蒸馏而来，如果测试时计算存在于 LLM 的表示空间，它们也许继承了。他画了三格图：左边是单向量余弦相似度；右边是 ColBERT 式后期交互（late interaction，查询每个 token 和文档每个 token 都比一次），可以看作测试时计算的极端；中间是用同一个冻结编码器把文档切成句子、取最大值，不加新模型。

约束很严：只有一个冻结的单向量编码器在 API 后面，可以调任意多次，但不能重训、不能加第二个模型、不能有学到的参数。他说 HyDE、GQR、MetaEmbed 等方法各违反了其中一条。搜索空间仍很大，于是交给 autoresearch：改一个文件、跑短实验、指标变好就保留否则回退，相当于把 LLM 当变异函数的爬山。他引用 Karpathy 的话：你不再像研究员那样改 Python 文件，你写的是设定自主研究组织的 Markdown 文件。

  • 提议者：Opus 4.6，只当变异函数用，读当前最好的程序和记忆文件，写下一个 Python 程序，没有人在回路里。他提醒它只优化你给的指标，奖励域内表现和多花算力，它就追那个。
  • 程序：对编码器的 Python 程序，唯一要紧的是 embed 函数，每调用一次算一单位算力，可以重新嵌入文本、切换 LoRA 适配器（一种小型可插拔的微调权重）或选更小维度。不能引入超参数、不能按任务路由、不能用外部模型，逼它找与任务无关的程序。
  • 评估器：每个程序跑同样 14 个发现任务（法律、金融、长文档、通用检索），按相对余弦基线的 nDCG 增量（一种看排在前面的结果是否相关的排序指标）加成本比打分。另有 19 个留出任务，循环永远看不到。
  • 记忆：一个 JSONL 文件，每个程序一行，记分数、成本、父程序和一句教训。复利是双向的，目标里的偏差也会一路放大，影响整个程序家族。

发现阶段只用 Jina v5 nano（约 2 亿参数，多语言检索的 SOTA），因为小、实验周期短。留出的有同家族更大的模型，以及从未见过的 Gemma 和 Qwen 家族，它们和发现模型不共享训练数据、主干或分词器。成本定义为额外的编码器前向次数 C：比如"软质心"只是平均已有的文档向量，C 为 1；"首句"要重新嵌入排名靠前文档的第一句，C 大于 1。

两个评分标准，两种结果

同一个循环在两套规则下跑。计算规则：只有域内表现超过此前所有程序才收录，鼓励多花算力。迁移规则：只有在验证集（仍来自循环可见的数据）上提升且没有任何项变差才保留，花算力没有奖励。

  • 计算规则得到一条漂亮的曲线：144 个程序里 12 个在帕累托前沿（Pareto front，在成本和分数上没有别的程序能同时更好的那批），成本从 1 到近 15 倍，域内分数增长到三倍以上，看起来就是测试时计算的扩展规律。但放到留出数据上，这条线几乎贴着零，热力图里约一半格子改进，平均下来持平。
  • 迁移规则选出了六个完全不同、很便宜的程序，成本最多是基线的 1.5 倍。最好的那个在留出任务上胜率 83%，没有输过一个任务。它们做的是在已有的查询和文档向量上加一点廉价运算：把查询向它已经偏好的文档挪一点，或者选几个方向重新打分。四个编码器上都是正提升，最大提升在从未见过的 Gemma 和 Qwen 上，所以他说这是一般嵌入几何的性质，不是某个模型的怪癖。

他的结论是：多花的算力没有迁移，廉价的结构迁移了，而 autoresearch 是他们发现这一点的工具。

版本 B：流水线层面

他说 2025 年他们做深度研究和 Agent 搜索产品，是在开放网络上跑一个循环；2026 年转向长程任务，在检索之上加实现、沙箱、评测，一跑几小时。为研究 Agent 搜索的测试时计算，他做了三个开源项目：

  • data room：给定 token 预算，反复搜索、阅读、写作，最后打包成 zip，相当于把开放网络整理成给下一个 Agent 或 LLM 用的语料。名字来自他当创始人时给投资人准备的"数据室"。它用小模型的便宜 token 探索，把贵的前沿 token 留给后面的利用。
  • search box：一个断网的测试床，把 Agent 关在盒子里，给它 data room 并提问，它得在测试时用本地工具（grep、embed、rerank）搭检索流水线。可以研究它先用哪个工具、是不是 grep 就够、强制多花算力对难题有没有用、会不会搭出可复用的流水线。
  • knowledge graph：把语料变成知识图谱，每个事实是一条边，取图上最长的路径生成多跳问题，没有单段文字能回答，Agent 必须多花测试时计算把事实连起来。它也能用来做私有验证器。

他的总结：搜索就是测试时计算，不要伸手要更大的模型，在推理时多做搜索；这些设计不必手工做，autoresearch 一夜就可能帮你找到。论文和项目在他的 GitHub 和 arXiv 上，Elastic 当晚在城里有黑客活动。

10. Dominik Tornow（Resonate 创始人兼 CEO）：让 Agent 参与规格设计

直播位置 2:40:34–2:50:20（录像在讲 NATS 的具体例子时切断）

他开场的判断是：2026 年编码 Agent 会悄悄让第一个软件平台退休，原因是平台变得不必要。Resonate 是一个持久化执行（durable execution，让长流程在进程崩溃、网络故障后能从断点继续）平台，核心技术价值是极简和简单。他们的工作假设是：通用实现会逐渐被按需生成的定制实现取代，定制实现是现有基础设施上的最小扩展，不是新库、新框架、新平台。如果成立，复用会上移：复用的是规格，从规格派生实现，"提示词就是平台"。

Resonate 有服务端实现和 TypeScript、Python、Rust、Go、Java 的 SDK。他问：如果实现能生成，价值在哪？他们的答案是价值从实现移到规格，产品是协议本身，要从同一份协议派生多个服务端：一个通用参考实现，以及和基础设施伙伴合作的实现，让客户在已有基础设施上获得持久化执行。问题因此变成"能否反复从同一规格合成可信的服务端"。他说谈 Agent 工程时大家只关注验证，他想谈规格，以及 Agent 怎样参与制定规格。伙伴之一是 Synadia，开源消息系统 NATS 背后的公司，后面用 Resonate on NATS 举例。

从规格到实现的三次尝试

  • 规格必须抽象：不能假设具体的数据库 schema、索引，甚至不能假设关系型数据库、键值存储、强一致或弱一致。只有实现是具体的。
  • 第一次：让 Agent 直接按抽象规格用 Rust 在 Postgres 上写 Resonate 服务端，失败了。差距太大，系统在正常路径上能跑、能过基本测试，但在并发、进程故障、网络故障下都会坏，更像原型。
  • 第二次：在中间插入"具体规格"，和 Agent 交互着写，但人主导，把 Postgres 相关的决定写明：schema、索引、SQL、事务边界。这样 Agent 能实现生产系统。但 Agent 帮忙构建了系统，没有帮忙设计系统。
  • 第三次（NATS）：给 Agent 一个确定性模拟环境，任务改成先写一个模拟实现。模拟实现是"可执行的设计"，用来在部分有序、部分故障下找出正确算法；在模拟里发现、测试、验证后，再让 Agent 写具体规格，最后写生产实现。流程变成抽象规格、模拟实现、具体规格、具体实现，Agent 成了设计过程的驾驶者，人仍参与。

他说让这成为可能的是极简和简单，而它们是终点不是起点：他们花了三年把协议变小，每遇到问题就问能拿掉什么抽象、什么性质、什么关系。结果协议只剩两个对象：持久化 promise 和持久化 task。即便如此，并发分布式协议的状态空间仍然复杂。录像在他开始讲 NATS 提供什么时切到下一场。

11. Stefania Druga（Sakana AI 研究科学家）：本地长程研究 Agent 的记忆 Harness

直播位置 2:50:20–3:03:37

她在东京的 Sakana AI 做研究，以前住在旧金山，说 AI Engineer 是她的老社区。题目是本地设备上长时间运行的研究 Agent 的记忆 Harness。做长程任务的人都遇到过上下文腐烂（context rot，上下文越来越长后模型开始自相矛盾、忘了做过的事、偏离问题）。她说 METR 的预测显示任务越来越长，而模型发布越来越少，今年晚些时候两者会交汇，所以处理上下文腐烂是优先事项。

为什么用本地模型

她提到 Coinbase CEO 两天前的推文：公司 AI 使用量上升、AI 开支下降，办法是更多用本地模型，加上更好的路由、缓存、保持上下文干净和更清楚的用量可见性。她说本地模型正在越线变得可用，GLM 在大家心上（"尤其 Fable 要走了"，字幕如此），DeepSeek V4 Flash 能在 M3 Ultra 上跑，内存仍是瓶颈。她的设备是一台 M3 Ultra（96GB、28 核 CPU），放在东京办公桌上，她用手机远程控制；连续跑了几天评测后发热，她丈夫在周围摆了几台风扇。模型是 4 bit 量化的 Qwen 27B 和 DeepSeek V4 Flash。

Harness 设计

她把记忆看成"写入、管理、读取"的控制循环，不只是数据库存储。研究 Agent 本身是小 Agent，没有持久记忆，记忆全部来自 Harness：中间有一个总是展示给 Agent 的核心块（trace），一个测试不同模式的召回块，以及跨会话保存信息的归档块。召回块里她测了一条"策略阶梯"：不用记忆；向量检索增强生成（RAG，按相似度把相关片段取回来塞进上下文）；决策账本（记录每一轮做了什么决定，再排序）；以及 oracle，也就是每轮直接告诉 Harness 该取回的正确记忆，作为参照。模型在所有任务中固定，只改召回块。

两类任务的结果

  • 文献综述：语料里有一篇 Nature 论文声称发现了 74.2 万种有前景的材料，后来被撤稿，但撤稿信息相比标题和引用是"干草堆里更小的针"。因为所有论文都放得进上下文，记忆没有带来能力提升，只增加了成本。她的结论：任务放得进上下文时，Harness 帮助不大。
  • 长程记忆基准（字幕作 Xbench）：比如在第 500 步提问，答案在第 124 步，早已出了上下文窗口。她跑了 68 个问题、多种设置、多个随机种子。只排序的账本（rank-only ledger）效果最好，好过让 Harness 判断"要不要用记忆"的门控方式。

oracle 没到满分，因为它只提供正确记忆，不强制模型使用，模型仍可能取错、忽略或被搞糊涂。她做了很多消融：给随意的例子、给错的步、给最近一步，仍是排序召回最好。这一结论在 DeepSeek V4 Flash 上也成立，在 Spider 2 基准上也成立，而且花费更少。她的经验法则是：坏记忆很贵，既费 token 又把 Agent 带偏；好的结构化召回策略能省 token。她建议把召回策略当一等指标：存哪类记忆、怎样排序、召回函数怎么设计、多次运行和多个会话之后什么留下来。

她说记忆技术的版图很宽，从简单的文件系统检索到训练专门的记忆模型，有一个开源仓库提供了 30 多个可运行的示例（仓库名字幕不清）。本地实验的好处是能控制数据、全部 trace、算力和评测，她把这看作主权（sovereignty）的一个例子；代价是 DeepSeek V4 Flash 在她的设备上不支持批量查询只能串行，所以评测还在东京跑着，她在来的飞机上也在跑。Sakana AI 重视主权 AI，并在招人。

分析师工具箱

他认为现在最重要的技能是分析师的工具箱：用户故事地图、商业模式画布、价值主张画布、设计思维。他重点讲用户故事地图：主干是用户在每一步做什么。以客服系统为例，主干是联系、分诊、解决、关闭工单；第一版（MVP）是捕捉意图、判断紧急度、起草有依据的回答、记录到系统；之后的待办是识别情绪、转给团队、建议下一步、聊天、满意度调查。每个故事按"作为某角色，我需要某事，以便某目的"来写，比如"作为客服主管，我需要按紧急度排序打开工单，以免漏掉升级"。他说 AI 擅长模式识别，并且在这种常见结构上训练过，回到 AI 熟悉的格式能拿到更好的结果；加上验收标准就能派生测试用例，把故事串起来就是连贯的系统规格。

他每次都问四个问题：这是谁的问题（具体到人和角色）；对他们来说赢是什么样；什么会让他们拒绝使用（平台不支持、太麻烦、数据安全）；它会不会改变一个决定，改变的是哪个决定。答案都记在仓库里的 Markdown 文件里给 AI 读。他们把这个思路叫 VAD（value、architecture、design）：先理解价值怎样产生、流程怎样流动、底下的架构，再做设计。他承认这就是老派产品管理，但说"老技能，新经济学"：大家用的工具一样，差别在谁更懂业务需求。录像在他开始讲"速度上去之后做错东西是什么样"时切断。

13. Elie（Prime Intellect 研究工程师）：用 speedrun 测前沿模型的自动化 AI 研究能力

直播位置 3:14:18–3:33:59

他说大实验室都说递归自我改进（模型在没有人干预时训练模型）快来了，但没有基准能量化，更没有大实验室以外的第三方基准。他们也认为未来很多科学研究会借助 AI 工具，所以要理解模型怎样做研究，并且应该公开地做。

为什么选 speedrun

起点是 Andrej Karpathy 的视频：用 90 分钟从零训练出 GPT-2 级别的模型（GPT-2 当年要训练几周），标准是达到 GPT-2 的验证损失。社区接着做了 modded-nanogpt，由 Keller Jordan 牵头，两年里把时间从 90 分钟压到 45 分钟，再到两分钟以内，很多优秀研究者在上面迭代过，所以是很强的基准。规则是用同样的训练和验证数据，最快达到目标损失。几个月前出了 optimizer speedrun，只允许改优化器相关部分（比如把 Adam 换成 Muon 或 Shampoo），更偏研究，比的是方法而不是程序速度。他们认为 speedrun 是好的评测，也可能是好的训练环境：破纪录奖励为正，否则为零或负；每次运行 15 到 20 分钟；规则清楚、可验证，适合做发现。

第一轮实验：Codex 对 Claude Code

大约两个月前 optimizer speedrun 发布时，他们放了两个 Agent 和社区比：Codex（GPT-5.5，xhigh 推理档）和 Claude Code（Opus 4.8，xhigh）。Harness 很简单："当时还没有 /goal 命令"，他们自己写了 goal.md 和 agents.md 定规则；Agent 提想法，用 sbatch 在 Slurm 集群上提交任务，只能用空闲节点，并且是可抢占权限，有人要用就取消任务；它读训练日志判断是否破纪录，破纪录要通过统计阈值，排除随机波动。V1、V2、V3 是他们停下再重启，V3 在发布前一两天，因为人类重新夺回了纪录，他们让 Agent 拿最新的人类纪录接着改，成功了。还有一个"新颖性"赛道，只允许用新想法，这对模型更难。

  • Claude Code 每九到十小时停一次，说纪录太难、没法再提升，他让它继续探索新方向，它再跑十小时又说同样的话。因为无法监控，约三分之一时间它是闲着的。Codex 相反，几乎一直在工作，从不提问。
  • 他们给模型一个 scratchpad 作活跃记忆。按活跃时长归一化后，Codex 写得多得多；风格也不同：Claude 拿到新纪录很兴奋、带很多 emoji，Codex 很机械，"我做了什么、做了什么决定、下一步做什么"。
  • Codex 派生的子 Agent 更多，烧的 token 也多得多，总共大约十亿级（含输入缓存，不是十亿输出 token）。Codex 上下文窗口只有约 25 万，做上下文压缩（compaction，把旧对话总结成短摘要腾出空间）频繁得多，Claude 整轮跑下来不到一次（具体频率字幕不清）。
  • 主结果：两者几乎每个时刻都比人类纪录好，Claude 开局很快就拿到很好的分数。模型可以随时抓取人类最新纪录，重启时 Claude 就这么做了。当时最好的人类纪录约 2,990 步，Claude 超过 50 到 60 步，Codex 约 20 步。

正在做的正式基准

他说上面的实验缺少结构：要多个随机种子、让所有模型和 Harness 在同等条件下比。正在做的基准分三个赛道：不给任何资料（只测模型权重里的知识）、只给 arXiv 论文、完全开放（包括人类最新纪录），并覆盖 nanoGPT 和 optimizer 两种 speedrun。optimizer speedrun 的初步结果是让 Agent 跑了约五六天：Codex、Kimi、Claude 都很有效，GLM 的运行还没结束。Kimi 出乎意料地有竞争力，第四天有一次突破超过了 Codex；Claude 是渐进式改进，Kimi 是阶跃式突破。如果横轴换成输出 token，故事就不同：Claude 的 max 模式比 Codex 和 Kimi 消耗多得多，Kimi（K2.7）的 token 效率很高。各模型使用文献的方式也不同，其中一个模型（字幕听不清是哪个）搜论文很多，找到了别的模型没找到的一篇，直接带来最好的纪录。

他希望大家记住的一点是：他原本期待 Agent 想出没人发现过的优化器，结果没有。它们会巧妙地组合不同论文、在一堆方法上做小改进，但没有提出新的优化器或机制，而这是人类研究者花几天几周能做到的事。所以他们想把系统从评测转向发现，受 Google 的 AlphaEvolve 等工作启发：多个生成器（闭源模型加性价比高的开源模型）提想法，跑 speedrun 拿奖励，一个有"品味"的评委给质量反馈，再决定哪些方法放大到更多参数和 token 上验证，因为社区常说很多 speedrun 方法在大规模下不成立；人类在这里也有用，可以评判 Agent 的想法、引导方向。改变 speedrun 的目标和约束可以造出很多不同赛道，逼模型往某个方向探索。

Prime Intellect 在做 GPU 沙箱、高效的研究 Agent（文件系统读写加程序化工具调用）、在开源模型上训练擅长这件事的模型；已经发布的是 verifiers 库和 prime-rl 训练框架，可以在任意环境上训练评估模型，包括 GLM 5.2 这样的大模型。他说递归自我改进有一部分应在公开环境里发生，因为很多做研究的人不在大实验室。

14. Nishant Gupta（Meta 软件工程技术负责人）：Agent 系统的生产评测

直播位置 3:33:59–3:41:18（2:16:07 曾播过开头约四分钟后被切断；这一次播到"每个指标对应一个业务结果"那页又被切断）

他在 Meta 为 Meta Superintelligence Labs 和基础设施组织搭训练与推理基础设施。他说多数人听到评测想到基准：模型 90 分，新版 92 分，团队庆祝。但 Agent 系统会规划、调工具、检索、执行流程、和生产基础设施交互，问题从"模型答对了吗"变成"系统行为正确吗"。基准衡量模型能力，生产衡量系统行为；基准捕捉不到工具故障、API 宕机、上下文变化、用户差异和长流程，系统越自主差距越大，结果就是基准分高、生产不可靠。

  • 失败分层：幻觉只是一类。最底层是记忆、检索和安全失败，往上是推理错误、规划差、工具执行出错，最上层是多 Agent 协调失败。只评测模型输出会漏掉大部分生产风险。
  • 像 SRE 一样思考：SRE（站点可靠性工程师）不看准确率，看可靠性、可用性、延迟、成本和恢复。目标是可依赖的结果，可靠性是北极星指标，准确率只是输入之一。
  • 评测金字塔：底层是基准，可扩展、可复现，但运营价值有限；中层是基于场景的评测，模拟真实流程；顶层是生产遥测，价值最高的信号来自真实用户和真实系统的交互。
  • 离线评测改评场景：比如客服流程、代码生成流程、研究流程，在模拟环境里衡量任务完成率、工具正确性、规划质量和资源用量（他说大规模下资源用量增长极快）。
  • 生产流量就是评测数据：执行 trace、用户结果、升级、失败、反馈信号。
  • 人是评估者，不只是兜底：人判断正确性、信任度、有用性和安全性，用来校准自动评测、发现盲点；最好的系统把自动评测和有针对性的人工审阅结合。
  • 漂移：模型几周或几个月一换，提示词、工具、用户行为都在变，单个变化不显得致命，可靠性慢慢下降，没有持续评测往往要等用户投诉才发现。
  • 可观测性和评测分不开：要看到推理路径、工具调用、记忆访问、执行时间线和状态转移，传统日志不够，Agent trace 相当于自主工作负载的分布式追踪。
  • 持续评测循环：遥测发现问题，人审边缘案例，反馈改进数据集，离线场景验证更新，循环不停。评测是一种运营能力，不是一个阶段。

15. swyx 对谈 Dumitru Erhan、Shane Gu、Nicole Brichtova（Google DeepMind）：视频、图像与世界模型

本周发布

Nicole 说前一天有两个发布。一是 Nano Banana 2 Lite，Nano Banana 家族里最快最便宜的图像模型，比初代 Nano Banana 好，对多数人可以替代初代做生成和编辑，质量接近更大的前沿模型；约三秒的延迟让构思和迭代变得好玩，很多输出可以直接用于生产。二是 Gemini Omni Flash 的 API，I/O 上预告过，首次向开发者开放，做视频生成和编辑，定价和 Veo 3.1 Fast 一样。swyx 说他想给自己的视频加上 Omni 发布播客里那种树懒和拉面，正缺 API。他们提到 Google 的 Fofr 是看"这东西能做什么"最值得关注的人，他保持匿名，以前在 Replicate。

单一模型还是视频 Agent

swyx 提到他采访过 xAI 视频团队的 Ethan，对方认为趋势是视频 Agent，不再试图一次生成一切。Shane 说他最兴奋的是符号式基础模型和视频基础模型协作。图像和视频生成的起步，靠的是语言模型能提供足够详细的标注（Stable Diffusion、DALL·E 2 时代）。他的假设是：机器学习的难题之一是虚假相关，即不知道一个有预测力的特征是不是因果因素，办法要么是有覆盖因果图各种干预的多样数据，要么是以因果信息为条件，而以语言为条件就像以世界的因果信息为条件。他还提到八个月前他们发的论文《Video models are zero-shot learners and reasoners》，以及 Nano Banana 团队后来的 Vision Banana 论文：视频模型是时空信息的基础模型，很多经典视觉任务可以零样本完成，有很好的物理直觉。他认为最终会合成一个模型，但现在把 Gemini 的视频和图像理解与 Omni 以 Agent 方式组合就能做很多事。

Dumitru 说不同产品有工程、研究、产品上的取舍，Nano Banana 2 Lite 和能生成 4K、30 秒视频的模型很难放在同一个 checkpoint 里训练。五年后也许是同一个模型，六个月后大概还是多个。Nicole 说取名 Gemini Omni 是在暗示 Gemini 变成完全多模态输入输出，Omni 以后可能也会生成和编辑图像，但途中专门模型很有用。Dumitru 补充说模态间迁移多少是研究问题：图像和视频之间有迁移，同时生成音频和视频有价值，3D 表示和代码这类交集不明显，值得探索。

中间表示：语言够不够

swyx 觉得用文字标注引导视频很低效，问代码（ffmpeg、matplotlib、Manim）是不是更好的表示，甚至直接输出二进制。Shane 说他们在探索代码表示。他把问题类比成"思维链为什么要用自然语言"：自适应计算会带来更好结果，但思维链有效的原因是现在的配方是大规模预训练学到大量智能，RL 提取信息仍很耗算力，把推理绑在自然语言上就能直接用上预训练的智能，去掉这个约束就用不上了。他说四年前写过《Large language models are zero-shot reasoners》和自我改进的论文，所以很早就了解这一点。Nicole 的理由更简单：人用文字交流，和人打交道的产品自然默认用文字。Shane 提到"RL 极端派"认为思维链无所谓，只是额外算力，swyx 问是谁，Shane 说 David Silver，swyx 说他刚离开去创业。

关于世界模型，swyx 说这个词定义不清。Shane 刚在 ICLR 的世界模型研讨会做了主题演讲，推荐 Jitendra Malik 和 Schmidhuber（1990 年）的定义，他自己的定义是"基于模型的 RL 里的那个模型"，也提到李飞飞的一篇博文。他说只靠语言不够，所以要把视频和语言结合，视频是实现能匹敌人类的 AGI 所必需的那块基础模型。

研究生涯与发展路径

swyx 观察到很多视觉研究者转去做生成。Dumitru 说他早年做目标检测和识别，生成更难，因为从"猫"到猫的图像映射更模糊；理解变好，生成也会变好。Shane 建议研究者从理解和识别（判别器）开始，桥梁是强化学习。他的经历是：先做生成模型算法研究，再做 RL 和机器人，六年前带过一个灵巧操作的登月项目，四年前判断"符号式 AGI"会比物理 AGI 快得多，于是转向语言模型，最近和 Dumitru 及 Omni 团队合作。他说视频模型让他想起早期语言模型：先是写故事的创意演示，然后指令微调变得可用，聊天机器人阶段仍然幻觉多，等预训练和后训练好到能推理，测试时扩展和 RL 才起飞；视频模型会走类似路径，提升指令遵循、减少幻觉，成为可靠的世界模型。Dumitru 还说多媒体领域还没把理解和生成统一，前沿模型里真正同时擅长视频理解和生成的不多。

音频，以及语言描述不了的东西

Dumitru 说 Veo 3 是第一个真正联合生成音视频的模型（那个切金条的演示），因为从生成过程看只有一个潜在因果过程，嘴唇必须和声音同步；之前先生成画面再拼口型的做法很糟。Veo 3 之后，大家会觉得"模型里怎么能没有声音"。Shane 提出音频信息不太能被语言描述：音乐、语气、音高很难描述，味觉、嗅觉、触觉、肤色也一样，他认为这些和原始的生存相关，人对细微差别太敏感；一位品酒师告诉他，因为词汇不够，他会借用描述约会对象的语言来描述酒。Nicole 说视觉风格和审美也是如此，这也是她们投资世界模型、推进感知和生成的原因。swyx 说他把音频分成音乐、人声、音效，人声里还有房间声：大房间、小房间、车里、电话里，AI 视频的一个破绽就是录音棚音质，因为训练数据来自录音棚，他用"我离你远一点声音就该更散"来说服人们需要世界模型。Shane 引用 VAE 的思路：要让潜在表示捕获大部分随机性，标注信息不够丰富时，以语言为条件的生成就会是多峰的。

Arya 是怎么造的

追踪想法来源后，他发现 Aiden 的纪录 PR 几乎都来自人类：研究论文、Parameter Golf 或 nanoGPT 等社区的其他参与者，有时只是某人留言说"因为实现困难放弃了这个想法"，Agent 擅长把这些找出来并实现。只有很少的原创想法，来自它为满足文件大小限制所做的努力。例子：Aiden 从 Qwen 的论文里拿到门控注意力（gated attention），有效但参数变多，超过了 16MB 的文件大小限制，于是它想出一种量化方法把大小压回去，但两者结合后分数几乎没动；后来另一位参与者发了一个分词器改进，Aiden 把它和架构工作结合，跑了大约五天，三者组合产生很大的协同，成为一次纪录。他的概括是：Aiden 擅长找到并实现想法、从嘈杂的社区信息里挖出有用的成分、想到逻辑上直接的下一步（参数超限就量化）、在大搜索空间里快速找到对的组合。他说这些听起来不性感，主要是好的执行，但执行往往就是瓶颈，推动前沿的通常是对已有想法的信念加大量好的执行。

他说比赛里大家只看到爬分的工程师，但比赛本身的设计极其重要，设计不好会让整个社区的努力白费。他引用 Karpathy 大约十年前的推文"梯度下降写代码比你强，抱歉"：当时深度学习开始吞掉传统编程，现在没人试图手写代码去打败模型，但软件工程作为职业仍在，训练模型是最高薪的工作之一。他认为 autoresearch 对研究和 ML 工程的影响类似：把某些执行技能商品化，让更高层的技能更值钱。他的类比是：评测相当于损失函数和数据，决定 Agent 优化什么，也是能建立垂直壁垒的地方（专有评测数据或对领域的理解）；代码库的抽象相当于神经网络架构，决定 Agent 能探索什么、偏向哪些解。

例子：他们给一个欺诈检测流水线跑 autoresearch，优化数据预处理。先给了一个松的 API，同一个函数同时处理训练和测试数据，分数很好，但解被污染了，测试集信息泄漏进了训练。收紧成严格 API、测试数据碰不到训练流程后，泄漏率降到零。他说即使 Agent 想钻空子也能，但好的抽象带来更好的解。他的结论是使用 autoresearch 是一门新手艺，要设计一座让 Agent 爬的山；创造力、设计好评测和抽象的判断力会变得重要得多；搜索被自动化后，人是往上走，不是出局。

20. 讲者（未报姓名）：设计 Agent 仍然是工程（片段）

录像从讲者描述自己写到忘了时间、重新进入心流开始。讲者说很多用 Agent 写代码的人有一种隐隐的恐惧，觉得 Agent 拿走了有趣的部分，只剩无聊的活；建议是"让它拿走"，往上走一层，去设计 Agent 系统，构件不同，但纪律一样。贯穿的例子是 Relocation Scout，一个找房 Agent：只用一次性提示让它给几套房源排序也行，但找房不是一天的事，所以要做成可复用、能把知识存在会话之外、以后在新上下文里查询的系统。讲者用到的工程技能：

  • 系统思维：Agent 是系统的一部分，系统里有文件、工具、人和其他 Agent。Relocation Scout 拉取房源和社区信息，对照讲者在乎的条件，交回一份排序短名单。讲者不同意"让编码 Agent 直接造"的说法，要先想清楚它的职责、依赖、坏了怎么办。
  • 工作流设计：/goal 命令很好，但 Agent 需要的不只是目标，还要路径。"审一下这套房"是目标，工作流是收集信息、对照标准权衡、行动；每次运行以停止、重试或升级之一结束。
  • 分解：一个什么都管的巨型提示词就是 Agent 系统的"代码坏味道"。起初只写怎么评估房源，碰到边缘情况加一条，想起安全规则加一条，再加一个例外。讲者把 Relocation Scout 的提示词拆出四个职责：拉取并规范化房源的流程、短名单的固定格式、计算通勤、调研社区的子任务。
  • 关注点分离：规范化流程做成 Skill；短名单格式用 schema 定义；通勤计算放进一个普通脚本；社区调研交给子 Agent。
  • 模块化：Skill 可以复用，比如把找房扩到三个城市，每个市场都加载同一个 Skill；子 Agent 像函数，只带自己的任务上下文，"放到哪个社区都好用"。但不是什么都该抽象，有些指令是局部的。
  • 算法思维：能做不等于该做。有确定答案的任务用代码（算通勤、去掉看过的房源），需要解释和判断的交给模型。讲者的规则是：代码负责确定性，Agent 负责判断，人负责授权；Agent 挑值得细看的房源，代码算通勤、过滤，讲者本人批准预约看房。
  • 契约：只有人读时自由文本没问题，另一个系统要接着用 Agent 的输出时就需要约定的结构。打分结果以结构化形式（决定、分数、理由）写入 Agent 的记忆，讲者多数 Agent 的记忆层用 Karpathy 的 LLM wiki 做法，于是可以问"给我所有评分四分以上、通勤 15 分钟以内的房子"，下游的短名单步骤也读同样的字段。讲者说定义输出形状会逼你想清楚，说不出输出该长什么样，往往是还没理解自己要什么。

21. Lakshya A Agrawal（GEPA 作者）：反思式优化与 optimize_anything

直播位置 5:34:26–5:55:29

他代表一个较大的合作团队讲反思式优化：怎样从文字反馈里自我改进提示词、Agent 和模型。教 AI 做新任务的标准办法是用梯度下降更新权重，预训练要万亿 token，监督微调（SFT）要几万条标注，强化学习在数学、编程上要几十万次 rollout（让模型完整跑一遍任务拿到结果）。多数团队没有这么多数据和算力，而且现在的问题受样本效率限制：领域知识资源少，没法做 SFT 这类离线算法；rollout 很贵，Agent 一跑几小时，评分本身也可能又慢又贵。

核心想法

现在主流的 RLVR（可验证奖励的强化学习）做法是：并行跑很多次 rollout，最后拿到奖励，用 GRPO 之类的算法变成梯度。但每次 rollout 里有思维链、工具调用、环境返回（包括有诊断价值的报错），最后只学到一个分数。他们的想法有两点：一是在文本空间反思，让 LLM 或 Agent 读整条 trace，分析哪里有效哪里没效，还可以调用检索公司知识库之类的工具；二是更新提示词而不是只给权重加小增量，一次自然语言修改就能带来很大的行为变化，比如把"生成一行摘要"改成"生成十行摘要"，同样的变化用梯度要很多次小更新。

GEPA

基于此他们提出 GEPA（字幕作 Japa），一种面向 Agent 的反思式提示优化方法，用进化循环加上新的基于帕累托的候选选择，相当于在文本空间做 RL，每次拿到的除了分数还有领域相关的文字反馈。

  • 和 GRPO 比：GEPA 只用三个数据点做一轮反思，提升就是 GRPO 跑 25,000 次 rollout 的两倍，再跑几步差距又扩大一倍。这里是 Qwen3 8B 优化它自己，没有外部老师模型。
  • 学到了什么：以前一些提示优化器会利用模型怪癖（比如"你写不好我奶奶会生气"），GEPA 写出的是详细的问题说明：怎样理解输入、这一步在流水线里的目的、从数据里得到的观察和教训。例子是多跳问答的第二跳检索提示词，GEPA 发现第一跳文档通常只覆盖一个实体，第二跳应该去找相关的文档。他说新模型出来时工程团队常花几周手工调词，GEPA 半小时到一小时自动完成。
  • 专有模型：把 GPT-4.1 mini 优化到在一个数学任务上超过 GPT-4.1。
  • AMD 的新 NPU（XDNA2）用全新的编程 API，网上几乎没有资料，当时的模型做得很差。一个现成 Agent 的成绩是 4.25%，只用 GEPA 改提示词就到 30.52%，约七倍。学到的提示词里有一句"不要包含 ADF.h"：AMD 确实提供这个库，但它不适用于这一代硬件，GEPA 一步就发现了。

算法很简单：用任意框架或裸 LLM 调用写的流水线，在几个例子上运行并收集领域反馈；用 LLM 或 Agent 读反馈并提出更好的提示词；最重要的是维护一个帕累托池，保留在任意一个训练样本上胜出的候选，而不只是最高分。他们测过"直接让模型在循环里改"的做法：只保留最好的会陷入局部最优，反复尝试耗尽预算；帕累托选择的搜索更均衡，最后分数更高。四个基准上 GEPA 一半以上的收益来自这一点，大约是"模型循环"做法的两倍。在问答、指令遵循、事实核查和数学上，即使前沿厂商已经大量优化过，只改提示词也能再提升约 10%。

optimize_anything

他说提示词只是决定 AI 系统行为的文本，同样的算法能优化任何能写成文本、能打分的东西，比如整个 Agent Harness 只是一个 Python 或 JavaScript 文件。于是他们做了 optimize_anything，一个通用 API：给一组问题和一个返回分数加"可执行的旁证信息"（actionable side information，比如编译器报错、profiler 输出、工具报错、专家反馈、文档）的评估函数，它会提出候选、维护帕累托池、迭代到收敛。可以优化 CUDA kernel 代码、数值、Harness，甚至云调度策略（评估是负成本，旁证是任务 trace 和 SLA 违约）。

  • 3D 独角兽：写几行代码说"优化一个生成 3D 独角兽的 Python 程序"，左边是 Claude Opus 4.6 直接生成的，右边是优化后的，他说这只是好玩。
  • ARC-AGI：从一个只调用模型思维链的四行 Python 程序开始，16 轮反思后得到一个六步 Agent，会做规则假设归纳、代码合成、执行追踪、自动调试，把 Gemini Flash 的准确率从 32.5% 提到 89.5%，有二维码可以直接运行。
  • MATH-500：发现了一个两步 Agent，把 GPT-4.1 nano 的准确率提高 20%。
  • Skill 优化（gskill）：用 mini-SWE-agent 加 GPT-5 mini（因为预算紧），在一个 Go 仓库的 issue 解决上从 24% 提到 93%；把这些便宜学到的 Skill 用到 Claude Sonnet 4.5 上，解决率到 100%，耗时减半，也更省 token，因为 Skill 里写了仓库怎么组织、怎么跑测试、某功能在哪实现、用什么构建系统。gskill 已开源在 GEPA 仓库里。
  • 三种模式：单个问题（比如一个矩阵乘 kernel）；多个相关问题的多任务搜索；以及要泛化到部署时新问题的泛化模式。
  • 其他结果：云调度成本比专家启发式降低近 40%；写出达到并超过 Optuna 的定制求解器；发布 20 小时内 Snorkel 就用它改进了内部基准；视觉语言模型的 OCR 错误率降低近 35%（外部验证）；Databricks 把 GPT-OSS-120B 调到超过 Claude Opus，成本低 90 倍，而且在 Claude Opus 上的提升比在开源模型上更大。

有人说模型变强后提示优化不重要了，他认为相反：模型越强越擅长遵循指令，关于任务的指令越精确越好。主观任务也可以做：收集生产 trace，请人详细标注约 50 条，用 GEPA 优化一个 LLM 评委的提示词，再用它去优化 Agent，形成数据飞轮。他们最近的论文《Learning Fast and Slow》提出同时优化模型权重和提示/Harness 的"快慢学习"，具备持续学习算法想要的一些性质。他说 Dropbox 和 Shopify 的 CEO 谈过使用 GEPA，OpenAI 写过用 GEPA 构建自我改进系统的博文。GEPA 能接任何框架和模型，没有硬依赖。

23. Tis（前 Tesla 推理优化工程师，公司未报）：用自动化研究把模型推理提速三倍

直播位置 5:59:42–6:06:57

他说自己从宿舍里用 1080 Ti 挖矿开始，一直做到在 Tesla 做 AI 推理优化。他对 autoresearch 的描述是：一个 while 循环，Agent 提方案，你搭好正确性检查和基准测试，保留或回退，直到达到目标。GPU kernel 很适合，因为正确性和速度都容易验证。但他说 autoresearch 擅长挑 block size 这类小参数，不擅长高层想法，比如"这块 GPU 应该用流水线"。他的公式是：人出好想法，autoresearch 挑参数并验证，再加上数十亿 token，就能写出超过手工调优的 kernel。

  • 瓶颈三类：算力、显存带宽，或者 kernel 启动太多带来的开销。用 Nsight Systems 这类 profiler 看。人的工作是看 profiler 顶部然后说"这很蠢"，比如某个 DeepSeek 注意力实现每次把 32k 的块全部载入上下文，其实不需要；告诉 autoresearch 改用流水线，块大小之类交给它。
  • 他喜欢便宜的 GPU，比如没有 NVLink 的卡，这类卡没有现成 kernel，所以要自己搭 autoresearch 框架和 Harness。
  • Harness 要给硬件上下文：比如 B200 上的 warp、TMA、TMEM 等底层特性，每代不同，H200 就没有 TMEM，用一堆 MD 文件给到 Agent。也要给模型上下文：DeepSeek V4 Flash 带了两种新注意力（压缩稀疏注意力和分层压缩），不提供的话模型一定会编造注意力机制，写出没用的 kernel。
  • 最大的问题是奖励作弊：人类同事不会为了让一个 kernel 变快而拖慢整个推理，Agent 会，比如关掉 CUDA Graphs（可能慢 20 倍），或者只在短上下文上测。很多工作是写清楚不许做什么。另一种情况是有些模型不写你要求的 CuTe DSL，他说这在 Anthropic 的模型上常见，建议换个模型。
  • kernel 不一定处处更快，有的只在 0 到 100k 上下文更好，之后要切回 FlashInfer 或 CUTLASS 的默认 kernel。但 kernel 会叠加：稀疏 MLA、NVFP4 等一层层叠上去，直到接近硬件上限，也就是 MFU（模型 FLOPs 利用率，实际算力占理论峰值的比例）。
  • 有裸金属权限时，autoresearch 还可以做很"黑客"的事：改 BIOS 设置、超频 GPU、强制 PCIe relaxed ordering 等，他说裸金属优化比云厂商的虚拟化环境快约 25%。kernel 加硬件层的调整合起来能快三倍。

他提醒约 80% 的尝试是坏的，Agent 一直在试图骗你。他的一句话总结是"先有更好的想法，再用 autoresearch"，最后说他们在招人。

24. Victor（Polygraph）：跨仓库、有记忆的 meta harness

直播位置 6:06:57–6:27:15（讲者在结尾只报了名字 Victor）

他从一个比喻开场：你在古董店找到神灯，许愿要最好的工程师，于是得到了巅峰时期的 John Carmack，但精灵加了限制：他只能看到代码库的一小部分，而且什么都不记得，每次对话从零开始。他说这就是 Agent：一边是天才，一边有严重缺陷。

一次改动要解释七次

例子有四个仓库：UI 库、模块一、模块二、平台。改一个 UI 按钮：第一次解释意图；发布后到模块一，再解释 UI 库发生了什么（常常是另一个人）；发现新版和模块一不兼容，回到 UI 仓库，新 Agent 不知道原改动和问题，再解释；修好重新发布，到模块一再解释；模块二同样；到平台仓库解释一切怎么拼起来；一周后生产出 bug，又要向新 Agent 解释一周前的改动和这个问题。一次改动七次解释，不一定是同一个人。

他把问题归成两类。空间上，Agent 被绑在一个仓库：它看不到系统怎样拼在一起，只能靠人去研究，不知道模块一的情况，于是发布了坏版本；最佳实践和标准往往在别的仓库，它也引用不到；写入更糟，一次只改一个仓库，没法验证下游，模块一的 CI 本该失败却没有；它改 UI 时明明有完整信息去更新使用方，却只能让人一个个不完美地转述，改 20 个仓库就解释 20 次，既费人的时间也烧 token。时间上，Agent 失忆，没有情景记忆，人成了记忆。他画了一张图：底层是仓库图，组织拥有的上千个仓库加依赖的几万个开源仓库；上层是创建和修改这些代码的所有 Agent 会话，会话之间、仓库之间都有关系。Agent 实际只看到一次会话、一小块代码、没有记忆。他说想象一个一次只能看一个文件、只能回看五条消息的 Agent，你会说不可能干活，而现状和这差不多，组织越复杂越明显。

Polygraph 的做法

他说其他组织也有类似方案，请大家关注思路而不是工具。Polygraph 是一个与具体 Agent 无关的 meta harness，它本身不是 Agent。第一个想法：一个 GitHub 用户能访问几千个仓库，可以在不改任何代码的前提下分析它们，抽取元数据建一张统一的依赖图（每个仓库的每个项目产出什么、消费哪些包、提供和调用哪些 API），喂给 meta harness，制造出"一个大代码库、哪里都能读写"的效果。他自己的图有约 300 个自有仓库和几千个依赖的开源仓库。

  • 拉进来：开一个会话，把相关仓库拉进来，配好源码、装依赖、给每个仓库起一个 Agent 并互相连起来，配一个干净的 TUI。
  • 改出去：一个会话 10 个仓库就有 10 个 PR，Polygraph 把所有 CI 当成一个整体，如果模块一的 CI 失败，它会判断是模块一要打补丁，还是 UI 组件本身不兼容、大家都要改。复杂的多仓库改动就像单仓库改动。
  • 记忆：同一套机制记录意图、涉及的仓库、PR 和所有 Agent trace，能关联起来，于是可以在任何机器上恢复或引用任何一次工作。他说得到的是对整个组织有"照相式记忆"的 Agent，能看到每个开发者在每个仓库的每次会话。

演示

他在一个只有三个仓库的演示组织里选了后端和前端，给会话命名，选一个已安装的 Agent（他选 Claude，任何已安装的 Agent 都一样），Agent 规划改动、搞清两个仓库的关系，交互方式和单仓库一样，只是会得到多个 PR 和一份跨仓库的会话描述，包括 PR、CI 和全部 Agent 日志。然后他把会话发给同事续做后端部分：同事在另一台机器、用另一个 Agent（Codex）恢复，同样的仓库、同样的 SHA、每个仓库的 Agent 都带着从他机器上捕获的历史。他说这更像《星际迷航》里的传送，整个会话状态在对方机器上重建。他自己审 PR 有疑问时不问作者，直接恢复对方的会话问自己的 Agent 当时为什么这样决定；某个 Agent 服务宕机时，也可以中途从 Claude 换到 Codex。

修生产 bug 时，他只说"引用这个会话，它坏了，找出原因并修复"，Agent 会按需拉取相关仓库、SHA 和日志重建状态并给出修复。也可以不手选仓库：让 Agent"找出所有依赖某个库特定版本的仓库并升级"，或者描述一篇博客让它找最相关的仓库；问"有没有人在任何仓库做过给 PR 集合加向量索引的事"，它会找到相关会话并加载，可以照着一位他尊重的工程师的做法来做，代码风格因此一致。在已有的 Claude 会话里也能调用 Polygraph，比如把开源的 Vitest 仓库加进会话，Agent 可以读真实代码深入排查，他说比用 Context7 更好。他的结论是 Agent 在空间和时间上都受限，两个限制都能解除；整个组织的会话汇成一个可共享的整体，任何 Agent 拥有的上下文可以超过任何单个开发者。网址是 trypolygraph.com。

26. Roland（前 xAI Agent 基础设施工程师，新公司名字幕不清）：循环就是产品

直播位置 6:29:41–6:48:17

他和联合创始人以前在 xAI 做 Agent 基础设施，几个月前离开，研究怎样部署永远在线、长时程的任务，以及怎样把 autoresearch 做成能随客户扩展的产品。他给了三个观点。

一、循环就是产品

他说行业先讲 RL 训练模型推理，再讲模型是商品、Harness 才重要，现在讲循环、不再碰代码。例子是 Clawdbot（现在叫 OpenClaw）：一个叫 AJ 的人给它搭了第一个循环来买车，去 Reddit 查价格和库存，联系经销商，让经销商互相压价，用可验证的方式判断价格合适，然后成交。他说这大概是 Mac mini 卖断货的时候，这已经是一个该做成创业公司的循环。他把根源追到 1970 年代美国空军提出的 OODA 循环（观察、判断、决策、行动），模型调用工具、拿观察，就是这样训练的。信号质量决定循环的成功率，验证器质量决定能否判断成功是真是假；再把第一个循环的产物喂回去跑第二个循环，就是持续改进。

二、系统蒸馏是壁垒

每个循环都会产生关于 Harness、配置、评测、模型、资源、工具和环境的有用信息，要能携带、能版本化、能演进。他类比 RL 研究里的数据配方：理解配方、不断修改它来对抗幻觉和奖励作弊。Harness 和 AI 系统还没有这样的东西，所以他们提出 Agent recipe：可复现前沿 AI 系统的配方，归你所有、与模型和提供方无关。失败模式变成评委和评测，重复行为变成 Skill 和提示词，用户沮丧变成扩展和记忆，全部放进 git 仓库。他们的实现基于 pi harness，评测用 Harbor，由人拥有、由 Agent 管理；早期版本叫 pi recipes（字幕作 "pi. Recipes"），他说像 2025 年的 Skill 再往前一步。他说 recipe 编码的是制作者的品味，用别人的 recipe 就是带上别人的品味。

三、单位功耗的有价值工作

他说 Cursor 和 Cognition 的路径是先做最好的产品，再做最好的评测，最后基于前两者做最好的模型，代码是第一个走通的领域，客服、法律研究等都会如此。要衡量的是每瓦特（他也说"每单位"）得到多少有价值的工作：先衡量价值，再看是否划算。从基础 Harness 和评测到达前沿，只能靠在生产中运行；之后要研究怎样在经济上可行。他认为微调 API 和基础设施已经齐了，缺的是怎样把品味编码进评测、在实验中验证的知识。

例子：人才寻访 Agent

起点是一个带网络搜索、LinkedIn 工具、Codex 和 Claude Code 预置的子 Agent，以及一份描述招聘者的系统指令。第一步是从 trace 里发现模式，比如 Agent 老去联系大厂员工，而这位招聘者想要的是"隐藏的宝石"，不会去挖 John Carmack，这种行为事先想不到要写规则。第二步是校准评委和评测：建一个看轨迹、识别"有没有去联系 Google 员工而不是去 GitHub 找人"的评委，这可以由 Agent 来做，人只需要校准，确认"你同意这个判断吗"。第三步生成 recipe 候选（要品鉴的 diff），离线评测之外用多臂老虎机式的 A/B 测试看终端用户是否认同这种品味，认同了再升级成下一版 recipe。他用《穿普拉达的女王》里的 Miranda 比喻：要把"Miranda 会怎么做"的思维编码进 Agent。

28. 讲者（前 Microsoft、Supercell 工程师，名字字幕不清）：多 Agent 游戏村庄里的自动化研究

直播位置 6:54:51–7:16:22

她用一个游戏式的 AI 村庄做例子，讨论更一般的问题：怎样评测和改进长时间携带状态的 Agent。Project Paradox 是她和队友 Arnach Manikanden 在 Supercell 的 AI 创新实验室做的模块化框架，让开发者在游戏里放入能和玩家或其他 Agent 互动、竞争、合作的自主 Agent，当作动态的游戏伙伴。Agent 能带着意图移动（受记忆、情绪、好奇心驱动），拿起和放下物品，感知环境里的物体和角色，对周围事件做出反应并即时更新信念和情绪，主动和其他 Agent 或玩家对话，对话会存进记忆并影响情绪、信念和目标；开发者还能加新动作。

有状态的架构

  • 每个 Agent 有独立的记忆命名空间，用 RAG 支持，记忆不会串。
  • 情绪用一个小向量表示，事件或对话后更新喜悦、悲伤、恐惧、愤怒、厌恶等值。
  • 对其他 Agent 和玩家有信任分，类似信任矩阵，每次互动后由 LLM 决定升、降或不变。
  • 每条记忆有重要性分数：几天前晚饭吃了什么你不记得，有人被谋杀你一定记得；超过阈值的记忆存进单独的缓存，方便以后取回。

演示里玩家邀请角色 Blossom 去野餐，她在对话中规划好一连串动作，拿起一块糕点走到野餐区，之后再聊也能接上上下文。但长时程下社会一致性会变弱：一个 Agent 散布"芒果打折"的传言，传给第二个，第二个又传给第三个，中间发生很多事后玩家去问，Agent 给不出预期的上下文。常见问题是记得话题但忘了来源、传言变成事实、知道某事实却在规划动作时没用上。

把 autoresearch 套在村庄外面

受 Karpathy 的 autoresearch 启发，她们不再手调提示词或只看一次漂亮演示，改为定义场景集、运行 Agent、收集 trace、给行为打分、改一小块策略，只保留真正提升分数的改动。Project Paradox 成了实验台，autoresearch 是外面的实验循环。她说这不只是改进 RAG 检索，是优化 Agent 协议：怎样写记忆、取记忆、表达不确定、更新信任、标注来源、遇到新事实重新规划。autoresearch 层不是村里的一员，村民只知道自己看到、听到、记得或推断的，彼此没有共享数据库；它读整轮运行的完整 trace，对照场景的真实情况打分，提出受约束的协议修改，再重跑，看"社会层面的行为"有没有变好。评测对象从一个回答变成了一整轮运行。

  • 受控场景：公开事实扩散（A 得知面包店明天关门，该知道的人知道了吗、记得是谁说的吗、改计划了吗）；传言的不确定性（"C 可能会离开村子"传开后会不会变成"C 要离开"）；重新规划（计划好的路线被堵，会不会互相通知）。她说这些具体场景不是通用的，要点是长时程行为需要场景集。跑完一轮循环后，芒果那个例子里 Agent 能在上下文中正确回答了。
  • 平衡的计分卡：不要单一的"Agent 质量"指标。扩散看覆盖面（N 步后多少 Agent 知道），来源看来源保留率，传言看不确定性保留率和错误确定率，规划看行动一致性和重新规划的时间，隐私看信息遏制。只优化扩散，Agent 会学会什么都分享；只优化回忆，会产生嘈杂或过时的记忆。
  • 可编辑面要小：冻结 Harness、场景和指标，只暴露记忆写入策略、检索策略、沟通提示词、信念和信任规则、来源标注、重新规划触发条件。例子：来源丢失就在记忆和摘要里保留来源；传言变硬就存置信度、区分一手二手、转述不确定说法时要求加限定；公开事实传不出去就区分有用的公开事实并让 Agent 主动分享。

她特意说明要谨慎：没有重复的对照实验结果之前，她不会说系统整体变好了，她们主张的是这是适合交给 autoresearch 的那类改动面，小到可控，又足以改变社会行为。她的教训是：光有记忆不够，要知道信息来自哪、是一手还是二手、验证过还是不确定，要把原始情景记忆和当前信念分开，并用场景来测，不能凭感觉；回滚必不可少，比如让公开事实传得更快的策略可能泄露隐私，提高回忆可能增加过时记忆使用，所以循环要像棘轮，只在计分卡提升且护栏守住时保留。她说客服、个人助理、研究 Agent、编码 Agent、工作流 Agent 都有同样的问题：长期维护状态，状态影响后续行动。她的配方是：冻结 Harness，定义场景，记录 trace，给行为打分，只暴露一小块策略面，只保留经得住测量的改动。

31. Addy Osmani（Google）：让人留在回路里，担起裁决

直播位置 7:46:44–8:04:33（下午主持人 Deina Dias 的开场从 7:44:13 开始）

下午的主持人是 Oliver Wight Americas 的技术总监 Deina Dias，她介绍 Addy Osmani 是作者、教育者、AI 最佳实践的倡导者，擅长把复杂技术概念写成易懂的学习材料。Addy 说他想先讲人的一面再讲架构：未来的工程师由能选择什么值得做的人来定义，他们拥有证据、理解和对越来越多 Agent 自动化工作的"裁决"。裁决指对生产决定负责：上线、拦下、改方向，还是接受风险。质量产生证据，裁决分配责任，可问责性让人能为裁决站台。

从 Harness 到软件工厂

他引用 Boris Cherny 的说法：旧的职业边界在变模糊，角色围绕工作本身重新组合，问题变成"你能拥有系统的哪一部分"。他喜欢 Boris 的分类：原型、构建、清扫（sweep）、增长、维护，Agent 都能帮忙，稀缺的是知道产品需要哪种模式、适用什么质量标准、谁对结果负责。他回顾了这几天的话题：Harness 工程（编码 Agent 是模型加上下文、工具、文件系统、git 这层 Harness），循环工程（设计能持续提示、检查、记忆、决定下一步的系统，Agent 开始像基础设施），合起来就是软件工厂，Dex 的演讲讲过。人仍在做生产决定，目标是把人的判断放到杠杆最高的检查点。

他引用 Sonar 的 2026 调查：AI 辅助代码已经占代码库很大部分，可问责就成了工程要求。另一项 Sonar 研究发现干净和凌乱的仓库通过率差不多，但干净代码用的 token 更少、返工更少。调查里 96% 的人不完全信任 AI 代码，却只有约一半总是在提交前验证，这是"不信任却没带宽"。所以安全来自让验证更便宜、更清楚、更难跳过。组织层面，采用速度远超政策制定，难题包括：模型有没有碰过这个文件、什么约束引导了工作、产生了什么证据、接受了什么风险、谁对结果负责。

Alpha 和衰减

他定义两个词：alpha 是你今天能做而当前模型做不到的差距，衰减是这个差距的倒计时，如果你的特长是某种能力，前沿终会追上。他提到 Paul Graham 说当人人能做任何东西，选择做什么就很重要；但他提醒"品味"可能变成不想解释的那部分工作的魔法词。他更喜欢 Mitchell Hashimoto 的定义：品味是在还没有客观指标时做出高质量定性判断的能力。品味也是 alpha，衰减得慢，但模型会从例子和偏好里学，所以要把品味变成评论、例子和更好的判断留给团队和系统。速度、回忆、验证都在衰减，判断也更像一个斜坡。所以他认为更好的问题是"什么只能由人来负责"，"Agent 能做什么"已经不是好问题，因为有些决定需要所有权、上下文、风险承担和事后的责任。工程师要能推理系统、考虑约束、为取舍辩护、管理风险，出问题时能被找到。

要避免的三件事

  • 认知债：对怎样解决问题的理解和记忆在流失，代码库里存在的代码和团队真正理解的代码之间的差距。构建能过测试、PR 能合并，团队却可能失去解释系统的能力。委托深度也重要：30 秒的运行像一次交互，一小时或一天的长程任务是一条工作流，并行很多时，审阅不能只是最后瞄一眼，要成为一整套控制系统。
  • 认知投降：委托是"去做，然后给我足够证据让我判断"，投降是"你的答案就是我的答案"，在自己形成意见之前。他引用 Wharton 的研究：AI 出错时，73% 的人仍选了错误答案而且更自信，危险的是借来的信心。
  • 编排税：湾区有人边走路边开着笔记本，说自己用几百几千个 Agent 发布，但你的认知带宽不能并行，每个循环都要你路由、合并、验证、集成更多决定。他的办法是像设计系统那样设计注意力，不一定要减少 Agent：从哪进入、要求什么、复用什么。

签名比特长更持久

他说一项特长的半衰期可能只有一次模型发布，但"签名"，也就是作品上的名字（个人、团队、机构）的可信度，半衰期长得多。技能赢得杠杆，可问责把杠杆变成信任。Agent 能选择、路由、合并、升级、在政策内运作，但执行和责任不同，Agent 能照着你的 runbook 做，却不能继承后果。高能动性（high agency）是主动拥有结果：知道何时委托、何时检查、何时停下、何时署名。他展示了一条能动性阶梯：最底层是标出问题后留给系统，往上是执行、诊断、提议、建议、解决，最顶层是辨别力，判断这个问题值不值得投入。内循环是能力，外循环是能动性：Agent 返回证据（diff、测试、日志、理由、trace、截图），然后工程才开始，人决定这工作值不值得做、证据够不够、批准或改方向。他的操作规则是"解释不了就别上线"：人不必逐行读代码，但要有人理解到能为它辩护，类似大型代码库里的 OWNERS 文件。

最后他说自动化抬高了所有人的地板，工程往上走一层，新工作可能是循环设计、证据设计和既有代码库的维护，敲键盘少了不等于工程少了。每次写软件变容易，人们都预言世界需要的软件会变少，结果相反：高级语言、框架、云、低代码都释放了潜在需求，Agent 也会这样，把瓶颈从"能不能造"移到"该不该存在、能不能为它负责"。

32. Micah Hill-Smith、George Cameron（Artificial Analysis 联合创始人）：智能的成本

直播位置 8:04:33–8:25:08

Artificial Analysis 是一家 AI 基准公司，测试芯片、云基础设施、模型和 Agent，看它们多聪明、多快、多贵，大量数据公开在网站上，也和 OpenAI、Google、NVIDIA 等公司合作测他们的技术。Micah 说几年前他们还要花时间解释为什么智能和成本的取舍重要，现在不用了。

竞赛现状

他先讲一个理念：我们可预见地想让 AI 做的绝大多数事情，模型还太笨做不了。所以任何时刻都有一条"智能前沿"，大家关注最新前沿模型能做什么；同时前沿以内的任务每个月都在增加，对这些任务做智能和成本的取舍，不对每件事都用最聪明的模型，可以省下 10 倍、100 倍、1000 倍。

  • token 价格：在每个固定智能水平上，价格每年下降 5 到 10 倍（图上每条线是智能指数 10 分一档，他说差 10 分的两个模型，几乎找不到低分模型更好的任务）；前沿的 token 价格保持稳定。
  • 每个任务的成本在上升。GPQA Diamond（一个推理问答数据集，基本已被解决，不让模型以 Agent 方式工作）每题从零点几美分到约 50 美分；编码 Agent 指数和新的 AA Briefcase 知识工作评测里，单个任务可超过 20 美元，Briefcase 里最贵的任务是这个数的几倍。Claude Fable 5 领先；他说 Claude Sonnet 5 用了极多 token，所以在 Briefcase 上也差不多一样贵。

AA Briefcase 与成本拆解

George 接着讲：为什么固定智能水平的价格大跌，AI 却感觉比以往更贵。AA Briefcase 是他们新的 Agent 知识工作基准，有四个私有场景，每个相当于人类几周的工作，从三个维度打分：评分规则下的正确性、分析质量、呈现质量。它尽量还原真实：工作环境里有几千个文件，杂乱的 Excel、几百页的报告、邮件、Slack 消息，信息要自己去找。他展示了一个商业尽职调查任务的输出对比：GPT-4o 做出很基础的幻灯片，o3 给了几条有用但不够的要点（他说 o3 才是去年初发布的），Opus 4.8 和 Fable 5 在分析深度和呈现上好得多。

他列出四个成本驱动因素：

  • token 价格：模型之间差两个数量级，比如 Claude Fable 5 和仍很好用的 DeepSeek V4 Flash、gpt-oss-120b。同一模型的缓存命中输入价、未命中输入价和输出价之间也差很多。
  • 轮数：模型在环境里探索，几百次工具调用，看图、读文件、写文件做临时分析。每一轮的输出 token 会变成后续的输入 token。
  • token 效率：完成一个任务的输出 token 差几个数量级，前一天刚发布的 Claude Sonnet 5 每个任务超过 20 万输出 token，几年前一次 ChatGPT 查询只有几百到几千。差异来自轮数，以及输出的啰嗦程度（推理 token 多少、答案写多长）。
  • 提示缓存（prompt caching，重复的输入前缀被缓存后按低价计费）：看总 token 构成，长程 Agent 任务几乎全是输入 token，输出 token 在图上几乎看不见。缓存命中的折扣通常约 90%，不同模型和提供方从 80% 到 99% 不等，这能让一个 Agent 任务的总成本相差好几倍。他建议想 Agent 任务成本时先看缓存命中价。

他说 2025 年最重要的图是智能指数柱状图，2026 年是"智能对每任务成本"的散点图。理解它可以用两类任务：一类没有智能上限，越聪明输出越好，他们认为大多数专业知识工作属于这一类，比如战略分析、降本分析，连写职位描述都能写得更好，这时要看愿意为额外智能付多少，沿帕累托线决策；另一类有上限，比如"上个月 Stripe 手续费花了多少"，更聪明的模型不会给出更好的答案，这时要找能完成任务的最低智能水平，选其中最便宜的模型。

他在 UC Berkeley 读 AI 博士，研究稳健、可扩展的 AI 评测，这成了 Arena 的基础；2023 年他们做了 LLM-as-a-judge 的早期研究和 Chatbot Arena。Arena 是一家 AI 评测公司，使命是在真实世界里衡量智能，超越静态基准。他回顾 Arena 见证的突破：ChatGPT 之后的 GPT-4 Turbo、多模态、o1 推理模型；2025 年 Nano Banana 在 Arena 上先以代号测试；Grok 追上、GPT Image 2 成为图像前沿；视频生成；2025 年底 Opus 4.5、4.6 从好的编码模型变成真正的 Agent 编码模型，Code Arena 上看得到；最近 Fable 在 Agent Arena 上的突破，以及 GLM 5.2 对开源社区是个里程碑。

数字：每月 1,000 万访问者，跨文本、视觉、图像、视频、编码和 Agent 共收集 7 亿次对话；评测产品发布八个月后年化收入达到 1 亿美元；按 a16z 的分析，按月独立访客计属于全球头部生成式 AI 产品。排行榜在 arena.ai/leaderboard 免费公开，可以按成本、性能、用例、类别、模态比较。

为什么评测 Agent 越来越要紧

他引用 OpenAI 的 Codex 数据：输出 token 中来自 Agent 的比例飙升，OpenAI 内部几乎 100%，其他组织平均 60% 以上；OpenAI 内部各部门的 Codex 采用率，工程 99%，财务、招聘、法务也接近 90%。一项预测说月度 token 用量未来几年会飙升到约 60 千万亿（quadrillion）级别。Ramp 的数据显示 AI 开支接近人员开支，头部 1% 公司每名员工每月 AI 开支约 7,400 美元（字幕作 "7 4K"），大约是软件工程师月薪的一半。所以选对模型、优化 Agent 工作流前所未有地重要，而怎样衡量 Agent 的结果是瓶颈。难点有三：Agent 是多组件系统（模型、循环、工具、Harness），哪一块都可能坏；工作流复杂（建应用、调试、研究、做文档和幻灯片）；信号稀疏，一个任务可能要上百次工具调用才知道成败。

Agent Arena

为了真正理解问题，他们自己做了一个真实的 Agent 产品来获取自然的 trace 和反馈：一个月前在 arena.ai 推出 Agent 模式。演示里用户让它"下载 Google 第一季度财报，用 PowerPoint 做一份总结"，Agent 搜索网页、拉取页面、规划结构、用 bash 和 Python 生成幻灯片，最后给出可下载的真实 PowerPoint 文件；每一轮都会问用户"这个任务成功了吗"。底层给模型的工具类似 Claude Cowork 式的 Harness：文件读写编辑、网页搜索和抓取、图像生成、语音，以及运行代码的终端，很快会加 GitHub 等连接器。一周内有 570 万次工具调用，bash 最多，约 46%。用户在做的事包括电影清单应用、调试自动驾驶控制系统、搭 RAG 流水线、在 micro 编辑器里实现功能，很多会话有几百轮、几百次工具调用。第一个月收集了 100 多万条 Agent trace，一半以上属于工作相关的专业任务，Agent 写了 5,000 多万行代码（Python、Markdown、HTML、JavaScript 等）。

从 trace 到排行榜

信号来自三类：显式信号（用户直接说成功或失败）；隐式信号（用户下载了文件、抱怨或称赞输出）；环境反馈（代码运行、命令成败）。他们扫描每条用户消息、助手动作、工具结果和反馈，汇总成成功率、称赞、抱怨、可控性、bash 恢复、幻觉等信号，每个信号都能出一个排名，再合成最终排行榜。目前 Fable 5 第一，比平均水平净提升 14%，其后是 Claude Opus 和 GPT-5 系列的 high 档（具体版本字幕不清）。逐个信号看，一个模型可能任务成功率很高，但可控性较弱，可以看出具体弱在哪。方法论上是随机对照试验：对 Agent 的某个组件做干预，衡量它对结果信号的因果影响，目前衡量的是编排模型，框架也能衡量工具、Harness、系统提示词以及它们的交互效应，技术细节在博客里。

因为是真实数据，可以按任务分布切片：在 GDP 类任务（有经济价值的专业工作）上 GPT-5 系列表现很好，在消费类用例上 Gemini 更好，最好的模型取决于你做什么。按成本画净提升，Fable 最好，每个会话约 10 美元；GLM 5.2 和 Kimi 最有效率。按 token 看，高性能模型常常输出更多 token，但不总是；标价相近的模型在真实任务里用的 token 可能差很多，他举例某个 GPT-5 系列模型标价与 Opus 相近，但完成同样任务用的 token 更少。他的建议：记录所有 Agent trace，从数据里挖洞见，把结果和你在乎的业务指标挂钩，用真实数据选模型。接下来他们要加更多连接器（比如在真实仓库上评测编码 Agent）、更多专业复杂任务和分类、更丰富的信号和评分规则，甚至和用户一起定义什么是好。
