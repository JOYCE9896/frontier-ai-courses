AI Engineer Paris 2025 · 第一天晚间开幕主题演讲

第一场在美国以外举办的 AI Engineer 大会开幕：swyx 回顾 2025 年 Agent 的进展，Mistral 工程负责人讲开源模型怎样落地到企业

主办：AI Engineer（swyx、Ben Dunphy）· 直播日期：YouTube 记录为 2025 年 9 月 24 日（开幕在第二天的前一晚）· 时长：1 小时 25 分 · 整理：Joyce（@JOYCE9896）

这一场的内容

AI Engineer Paris 2025 在巴黎的创业园区 Station F 举办，由法国云服务公司 Koyeb 承办。这是 AI Engineer 第一场由社区伙伴组织、也是第一场在美国以外办的大会。第一天晚上是欢迎酒会，主要活动在展区和走廊交流，直播只转播了开场致辞和两场主题演讲：swyx 的“这一年的 Agent”，以及 Mistral 工程负责人 Lélio Renard Lavaud 讲开源怎样推动企业落地。

直播前 37 分钟是暖场音乐，结尾是散场音乐，本文都略过。两场演讲里反复出现的话题有：MCP 之外还缺什么、企业数据分散在各个系统里的问题，以及推理速度（swyx 提到的“快 Agent”，Lélio 在讲模型性能时也接了这个话头）。

01. 开场致辞：MC、Ben Dunphy、Yann Léger、Marwan

直播位置 0:37:30–0:49:54

MC：大会概况

MC 是一位开发者体验工程师（字幕里名字拼法不一，大致是 Ralph），他负责两天的主持。他说巴黎有 Mistral AI、Black Forest Labs 等一批欧洲实验室和创业公司，正在开放模型和生成式媒体上做前沿工作，所以选在这里办。他回顾了 AI Engineer 在旧金山和纽约的前几届：今年旧金山的 World's Fair 有 150 多场分享、18 个专场，主题包括软件工程 Agent、MCP、生成式媒体、机器人、图数据库和 AI 基础设施。白金赞助商是 Neo4j 和 Docker，金牌赞助商有 Sentry、Arize AI、DeepMind 和 Algolia。

Ben Dunphy：为什么第一次交给社区伙伴

AI Engineer 联合创始人 Ben Dunphy（MC 介绍他做过 Reactathon）说，他和 swyx 两年多前创办 AI Engineer 时，就想学 JSConf 那样，让社区成员在世界各地办活动，他们自己作为参会者到场。他说这在实践中不容易，因为对内容、品牌和体验的要求高，需要一个有眼光、能扛风险、做事专业的伙伴，所以第一场社区活动选伙伴选得很严，最后选了 Koyeb。他说今晚自己以参会者身份欢迎大家，这个社区已经走出了创始人和旧金山。

Yann Léger（Koyeb）：承办方

Koyeb 联合创始人兼 CEO Yann Léger 说，巴黎是他和公司的家乡，团队花了三个月筹备，这也是 Koyeb 第一次办这么大规模的活动。他给出的数字：大约 70% 的参会者来自法国以外；两天有 30 多位讲者，内容包括怎样构建基础模型、怎样大规模部署 MCP、vibe coding 的经验等，并特意邀请了多位在欧洲创办和运营 AI 公司的负责人。他介绍 Koyeb 提供高性能的 Serverless 基础设施，可以把 Agent、推理服务和模型部署到 CPU、GPU 和各类加速器上。

Marwan（Station F）：场地

Station F 创业项目与合作负责人 Marwan 介绍，Station F 八年前开园，同一个园区里有约 1,000 家创业公司（字幕里另一处说的是 10,000，原话前后不一致），参加至少 30 个孵化项目。园区每年评选 40 家最好的公司，Koyeb 在列。他说园区 70% 的创业公司做 AI 或核心产品里有 AI 成分，最有名的校友是 Hugging Face，2017 到 2018 年在这里起步。他预告 Station F 几周内会公布面向 AI 创业者的新计划。

02. swyx（Latent Space / AI Engineer 联合创始人）：这一年的 Agent

直播位置 0:49:54–1:02:46 · 英文原题 The Year in Agents

swyx 是 Latent Space 的主理人、AI Engineer 的联合创始人。他说主办方给他的任务是讲讲现状。今年 AI Engineer 一开始就围绕“Agent 之年”这个说法，这次演讲是他年初在第一届 AI Engineer Summit 上那场 Agent 演讲的更新版。

Agent 的定义

年初很多人说 2025 是 Agent 之年，Satya Nadella、OpenAI 的 Greg Brockman、Sam Altman 都这么讲过。至于 Agent 是什么，他引用 Simon Willison 上周的文章：Agent 就是一个 LLM 在循环里调用工具，去完成一个目标。他自己之前整理过更细的拆分：意图（intent）、记忆（memory）、规划（planning）、权限（authority）、控制流（control flow）和工具（tools）。他希望大家讨论 Agent 时去碰难的部分，别把它想得太简单，好的记忆、规划和信任边界能做出用户不讨厌的 Agent。

史上最大规模的基础设施建设

他说今年在发生“有史以来最大的基础设施建设之一”。年初 Stargate 宣布时，很多人怀疑钱是否真的到位，现在已经能看到数千亿美元在投入。对“AI 没人用”的怀疑，他的回应是 ChatGPT 再过两个月就会到 10 亿用户。他借用 Andrej Karpathy 在 YC Startup School 上的说法：接下来十年都是 Agent 的十年，2025 只是开头。他说这是大家职业生涯里见过最大的顺风，方向是确定的，可以把职业和公司往那边对准。

模型越来越“Agentic”

  • 他展示了一张今年所有重要模型发布的清单（完整版在他的网站上），加粗的是他认为能经得住时间的，包括一款 Mistral 模型（字幕不清，可能是 Magistral）、中国的 Qwen3 Coder 和 GLM 4.5，以及几家前沿实验室的模型。
  • 他对 Agentic 模型最简短的描述是“用工具思考”（thinking with tools）：模型的思考过程里会穿插工具调用（Tool Call，即模型输出一个结构化请求去调用外部函数）。Latent Space 在 GPT-5 开发者预览期间写过一篇文章讲这件事。
  • 第二个可见的变化是自主运行时间变长。他举 Replit 新 Agent 的例子，可以自主运行 200 分钟，他预计会出现数小时乃至数天的自主运行，模型正在被专门后训练（Post-training）来做到这一点。
  • 第三是强化学习（RL）用在 LLM 上已经成熟到这种程度：后训练花的算力开始和预训练相当。他说今年之前从来不是这样，并引用 xAI 的说法，Grok 4 就是这么做的，Grok 4 Fast 也类似。

工程这一侧：Agent 产品、协议、实验室

他说大多数 AI 工程师控制不了模型，能做的是模型周围的东西：Agent 产品、Agent 协议和 Agent Labs。

  • 产品：他列了一批重要的 Agent。他说九个月里变化很快，OpenAI Deep Research 现在看已经显得很老，Codex CLI 四月发布，最近才火起来。
  • 协议：AI Engineer 在上一届 Summit 上押注 MCP（Model Context Protocol，让模型以统一方式连接外部工具和数据的开放协议），还办了一场观看量很高的 workshop，现在 MCP 已经普及。他说 MCP 之上还会出现什么，仍是开放问题。Google 推出了 A2A，他更想推荐 Zed 的 ACP（Agent Client Protocol），它在成为 Claude Code、Codex 这类终端 Agent 之间的互操作层。他的观察是，大家现在换的已经是整个 Agent 连同界面，换 model 字符串只是其中一小部分。
  • 标准工具集：他说 Mistral 的 Agents API 把一个趋势固定了下来，每家模型实验室都有一个 Agent API，附带一套“标准库”：代码执行沙箱、网页搜索、文档库，也许还有图像生成，再用 MCP 连接其他一切。他把这当作 Karpathy 2023 年“LLM OS”设想的更新版：搜索、代码执行、文档库、多模态输入输出、MCP 都已经有了，还缺的是好的记忆和好的编排（orchestration），有一些候选者但还没人胜出。
  • 代码 Agent 实验室：他最近写过一篇关于 Cognition 的博客，观点是“代码 AGI”会在实现完整 AGI 所需时间的 20% 内达成，却能拿走 80% 的价值。所以 AI Engineer 11 月在纽约办第一届专门讲编程 Agent 的 CODE Summit。

几个还没有答案的争论

  • 要不要做评测（Eval，用一组固定测试衡量模型或系统表现）。他引用 Claude Code 负责人 Boris 的话：我们很努力地想建评测，但最后全靠 vibes。他说今年最成功的编程 Agent 有 5 亿美元收入，没有评测，只有 vibes。他的看法是：在需要爬坡优化的小领域里评测有意义，但在很通用的领域，不一定要先做评测，或者把评测当成产品开发的卡点。他说这有争议，所以只当问题提出来。
  • 怎样把上下文工程（Context Engineering，决定放进模型上下文窗口的内容和顺序）做好。Cognition 说别做多 Agent，Anthropic 说做多 Agent，他认为多 Agent 之争属于上下文工程之争的一部分。目前没有标准做法，只有几篇博客，他觉得这里会出现值得做的创业公司。
  • 快 Agent。他说这个在硅谷听得越来越多，但还没形成共识。普通模型服务每秒 100 到 200 个 token，Cerebras Code 能到每秒 2,000 个，SambaNova 和 Groq 也有类似产品。他认为速度每提升 10 倍，用户行为和产品的可能性都会变。

最后他列了明年会有很多进展的方向：邮件客户端、浏览器 Agent、语音电话、vibe coding、低代码和教育 Agent。他说联合创始人 Ben 对教育特别感兴趣，AI Engineer 很快会宣布一场教育主题的 Summit。

03. Lélio Renard Lavaud（Mistral 工程负责人）：开源怎样推动企业成功落地 AI

直播位置 1:03:38–1:22:15（含问答，问答从 1:18:58 开始）· 英文原题 How open source drives successful enterprise adoption

Mistral 是谁

他说 Mistral 两年多前在巴黎成立，创始人是 Gemini、Llama、Chinchilla 等论文的作者，目标是把 AI 带进企业，同时推动开源和开放模型。几个月后他们发布了 Mistral 7B，当时最好的小模型，引发了社区大量实验、微调（Fine-tuning，在已有模型上用特定数据继续训练）和新用法。之后发布了第一个混合专家模型 Mixtral 8x7B。混合专家（Mixture of Experts，MoE）指模型里有多组“专家”子网络，每个 token 只激活其中一部分。

他讲了一个经历：2024 年春天在旧金山 GTC，一家全球最大、最老牌的公司之一的人找到他，说他们在 Mixtral 8x7B 上做了微调并已投入生产，回报很好，可 Mistral 从没听说过他们，双方也没合作过。他说那时才看到，用开源模型把 AI 带给大众，和服务企业是可以兼容的。

Mistral 做什么

  • 基础模型，由科学团队训练；也和特定客户做继续预训练，加入稀有语言或特定能力。
  • Mistral AI Studio：模型之上的一层，提供构建复杂应用需要的工具和 API，从补全 API 到对话 API、有状态 API。
  • 产品：助手 Le Chat，以及编程工具 Mistral Code。
  • 定制方案：由解决方案工程师和应用工程师团队为客户实施。公司从 7 个人起步，现在有 100 多位工程师、100 位研究员和 100 位应用工程师。

他说大家都见过“概念验证在生产中失败”“企业很难从 AI 拿到价值”这类数字，他不展开数字，讲他们怎么克服这些障碍。他列的障碍是：数据、可观测性、内外部的技能缺口，有时也是模型本身不够好，他说“有时是我们的错”。

数据：分散、无结构，RAG 也不能直接解决

企业积累了几十年数据，放在各种地方，当时没有 AI 治理，所以数据被困在不同供应商的孤岛里，也没有 AI 系统需要的元数据。现在每家 SaaS 都知道数据值钱，都在做自己的 AI 助手，他说用 SaaS 的人会发现手上有 15 个不同的助手，底下都是包一层 OpenAI、Claude 或 Mistral 的 API，各自只看自己的数据，互相不通。MCP server 有帮助，但通常不够：搜索质量要靠供应商，Google Drive、Microsoft Teams、Slack 对访问控制（RBAC，基于角色的权限）的理解也各不相同，很难统一“谁能看什么”。

他用一个例子说明检索增强生成（RAG，先从知识库检索相关片段再交给模型回答）的局限：假如你在一家做全世界最好的袜子的公司，问“去年袜子销量是多少”，RAG 可能找回 2013 年的年报 PDF，又找回 2014 年的，五个分块都叫“年报 PDF”，分别在不同文件夹，模型拿不到区分它们的上下文。他的结论是要建一个“上下文引擎”：用启发式规则理解散落在不同系统里的实体之间的关系，映射到一个本体（ontology），做一种以 AI 为先的数据组织。

黑箱问题、观察、改进模型

大家都想观察和解释一个本身不确定的技术。他的做法是提供能建立信任的工具：没法保证模型一定对，但可以给出可核查的来源，或者用分类器根据输入判断输出是否合理、模型有没有跑偏。安全也取决于场景，审核 Reddit 评论和给儿童聊天机器人提供支持，标准完全不同，而且监管变化快，需要向很多方证明自己做对了。

他说企业里要观察员工怎么工作、用了什么工作流、给一个任务会发哪些查询，再把这些自动化。ChatGPT 式的助手给个人带来价值，但没有转化成公司的利润改善。收集到的数据还能用来改进模型：聊天助手这几年变好，靠的是收集大量数据去优化，企业场景也要这样做，可以得到更好或更小、针对特定工具和连接器优化过的模型。

走向成熟的三件事

  • 模型性能，他说这部分是 Mistral 自己的责任：系统提示越来越长，要求模型严格遵守；结构化输出和工具调用要可靠；要理解意图；还要快。他接 swyx 的话说，用过快的模型就很难回去，所以让模型更小、优化推理也是重点。
  • 专业能力：客户的员工、Mistral 自己的员工都需要培训，理解模型为什么这样表现、系统提示怎么起作用、怎样做评测而不是只凭感觉调提示词。他说不然客户会发来一个问题说“好像能用”，但真的在所有情况下都能用吗。
  • 变革：AI 当工具用，就是一个有终点的项目；当成一种能力，就能改变做生意的方式。

他说自己很少讲 Agent，因为他不喜欢讲不懂的东西，他不知道 Agent 是什么：它可以只是包一个 MCP 调用的小动作，也可以执行一串复杂任务。重要的是要端到端解决的业务问题，Agent 可能是其中一部分，也可能不是。企业的诉求分两面：增长（新用例、新产品、处理以前没处理的数据，带来新收入）和效率（降成本、简化流程、节省时间）。

结论

  • 按自己的方式构建 AI：建立“构建、部署、观察、改进”的循环，按用例定制，不要指望输入凭证就开箱即用。
  • 借助社区：发布开源模型让他们学到很多。他举例说发现了一个角色扮演社区，他们提供很长的提示词和很怪的场景，这帮助模型对齐，学会理解复杂指令。
  • 打破壁垒：完全依赖 MCP server，就要指望很多供应商实现并维护好 server、写好文档和 OpenAPI 规范，有时行不通，所以社区也在推自定义浏览器或浏览器插件，免得在 15 个 SaaS 上重复登录。要避免供应商锁定，把一切汇集到一个统一表示的上下文引擎里。

问答

MC 问 Mistral 怎样帮企业整理数据孤岛。他说这其实是个循环：用 AI 去解析数据孤岛、分类、理解本体、整理顺序，人只负责引导 AI，不必让人去收拾一个 15 年的老网盘。

MC 问怎样平衡企业业务和开源。他说一开始只做开放模型，后来看到很多公司在他们花钱训练的模型上获取了大量价值。他们仍然相信预训练模型会变成大宗商品、并且主要是开源的；但后训练、加入语言或领域知识的继续预训练、把大模型蒸馏成小模型（例如高效地用 FP8 做）需要大量科研、工程和算力，很多客户没有，这就是企业业务的位置。他说他们尽量把能开放的都开放，同时保留一些优势来赚钱，并且陪客户一起做，告诉他们放什么数据、模型是否在往对的方向收敛、数据够不够多样。
