01. swyx（AI Engineer 联合创始人、Latent Space）：开场视频，几条行业趋势

直播位置 0:00:00–0:02:25（录音从中途开始）

swyx 没有到现场，开场是一段视频。他说自己擅长总结主题，准备了六条趋势给这次大会“定调”。录音从他讲第一条开始，后面几条讲得很快，有些句子字幕不清。

  • AI 越来越多地发生在模型之外。他放了 OpenAI 的两张截图，说模型越来越多地等于 Harness（模型外面那一层：提示、工具、循环和运行环境）。他还提到 AI21 在转向（转向什么字幕不清），AI 也关乎服务、数据、品牌和产品。他说这些趋势对 AI 工程师有利，因为都是模型之外的东西。
  • 模型本身也在变强。他认为最真实的基准是 AI 写了多少代码：他放了一张 GitHub 上 Claude Code 提交量随时间变化的截图，说 2 月时约占全部代码的 4% 到 5%，现在大约 10%，到年底会到 40% 到 50%。他觉得大家还没有充分意识到这件事正在改变世界。
  • Agent 开始自托管，出现了各种分叉版本；他还提到“claw 时刻”，说大家已经听够了，不必多讲（应指 OpenClaw 一类的个人 Agent，字幕不清）。他说这标志着 Agent 开始进入不可验证的领域，也就是没有标准答案可以自动打分的任务。
  • AI 的潜力正在超出一般知识工作，走向前沿科学、技术和数学。

最后他提到杰文斯悖论（Jevons Paradox：效率提高、成本下降后，总用量反而增加），说这是他认为“AI 工程师会是最后一个消失的工作”的理由，祝大家这两天讨论愉快。

02. George Cameron（Artificial Analysis 联合创始人）：2026 年 6 月的 AI 现状：基准、智能与成本曲线、硬件

直播位置 0:03:43–约 0:19:30（主持人介绍从 0:02:25 开始；演讲结尾录音缺失）

主持人介绍

John Allsopp 介绍说，George 是澳大利亚人，现在在旧金山，几年前为了解决自己的问题创办了 Artificial Analysis。他推荐了 swyx 在 Latent Space 播客上对几位创始人的采访。他说这家公司做的事就是“烧大量 token”，在自有和公开的各种基准上客观验证模型的排名和对比，这为上午关于 token 经济学、推理成本怎样进入产品策略的讨论定了背景。

Artificial Analysis 是做什么的

George 说他们是独立的 AI 基准评测公司，网站 artificialanalysis.ai 帮几百万用户了解 AI 的进展、在不同技术之间做选择。他举了几个被业界引用的例子：本周初 Jensen Huang 在 Nemotron 3 Ultra 发布时引用了他们；上周 Anthropic 发布 Opus 4.8 时引用了他们的 GDPVal-AA 基准；再前一周 Sundar Pichai 发布 Gemini 3.5 Flash 时也引用了。他们评测整个 AI 栈：Agent、模型、推理服务商和硬件；模型方面除了文本语言模型，也测图像、视频、语音和音乐模型。

进展没有放慢

他放了一张各大实验室历年主要发布的图，说图很乱，但这几年本来就很乱。他认为“AI 进展放缓”的说法被严重夸大了：2025 年底他听到很多这种说法，后来 Opus 4.6 发布，Agent 能工作的时间长了很多，这种声音就少了。图上最近三个月的点比以往都多，曲线往右上走得很快。

他介绍了 Artificial Analysis Intelligence Index：这是由他们运行的 10 个基准合成的指标，用来对模型的智能做高层次的相对比较。他说上周 Claude Opus 4.8 从 GPT-5.5 手里接过了智能最高的位置。但如果故事到此为止，大家的工作会简单很多；实际上成本、速度和其他权衡仍然让人有理由用别的模型。

几个观察角度

  • 地域：前沿语言模型基本是美国和中国的故事。图上还有法国的 Mistral、韩国的几家实验室（他说韩国的主权 AI 计划很成功），以及阿联酋。澳大利亚没有和前沿竞争的语言模型，他个人认为短期内也不会有。
  • 开放权重和闭源：开放权重模型（俗称开源模型，权重可以下载）一直落后于闭源模型，从 2023 年中 Llama 2 70B 发布算起，大约落后 3 到 9 个月。他说这在几年前并不是定局，当时大家还在问什么商业模式能支撑开放权重。他们认为这个差距会保持，因为有足够的动力：很多用户需要开放权重带来的灵活性和微调（Fine-tuning）能力。按这个差距，Kimi K2.6 或 DeepSeek V4 Pro 这样的开放权重模型大约相当于 Opus 4.5 或 GPT-5.2 的水平，他说用 Opus 4.5 或 GPT-5.2 已经能做很多事。
  • 基准是否对应真实能力：他们尽量让量化基准和真实使用对齐，避免模型在一个和实用性无关的数字上爬坡。GDPVal-AA 是他们用 OpenAI 的 GDPval 数据集改造成的 Agent 基准。他对比了一年前的领先模型 Claude 4 Sonnet 和现在的 GPT-5.5 做同一个知识工作任务：一年前的输出是一张表，现在多了执行摘要、汇总和进一步分析。另一个例子是 GDPVal-AA 里的“音乐视频情绪板”任务，Gemma E4B 能做出来已经不错，但他说自己用不上；GPT-5.5 的版本他觉得能拿来用。他的结论是模型之间仍有真实差距，基准和真实能力是相关的。

智能更便宜，花费却更多

他说有两件事很难调和：拿到 GPT-4 水平的智能比以往都便宜，现在用 Kimi K2.6 比半年前用 Opus 4.5 还便宜；可公司在 AI 上的花费也比以往都多，很多人升级到了每月 200 美元的 Claude Code 或 Codex 套餐。他把原因拆成六个驱动因素，说每个都能单独讲一场：

降低成本的三个：

  • 更小的模型达到更高的智能，以及更高的稀疏度。稀疏度指激活参数占总参数的比例更低；大规模推理时，激活参数量是成本的主要来源，也决定了硬件成本怎样摊销。
  • 软件效率。推理栈里 vLLM、SGLang 每天都在优化，还有 FlashAttention；靠近模型的一侧在探索量化，已经从 BF16 降到 4 位精度，例如 Moonshot 模型用的 INT4 或其他模型用的 NVFP4。
  • 硬件效率。硬件更贵，但提供的更多：大规模服务时，一个 NVL72 节点比 H100 节点的单位成本更低，虽然它本身更贵。

推高成本的三个：

  • 更大的模型。他说对前沿智能的需求是无法满足的，人人都想要更聪明的模型。
  • 推理模型（Reasoning Model）。实验室靠更多的推理 token 提高智能，而大家按 token 付费。
  • Agent。以前是问一个问题、拿回一个回答；现在 Agent 会探索文件、检查自己的工作，输出更好，但同一个任务要跑很多轮。他们的基准里，一个 GDPVal 任务通常要 60 轮，很多知识工作任务 20 到 100 轮是合理的，这成了成本的乘数。

同等智能的价格在 6 到 18 个月内降 10 到 100 倍

他们把模型按智能指数分桶（0 到 10、10 到 20 等），看每一档智能最早在什么时候达到，以及现在能拿到这档智能的最便宜模型是多少钱。结论是在 6 到 18 个月里，同一档智能的成本常常下降 10 到 100 倍。他建议大家利用这一点：一个任务如果当初用 Opus 4.5 能做，现在很可能换一个新发布的便宜模型就能做，便宜的幅度是数量级的，不是 2 倍。

另一张图横轴是运行他们 10 个基准的成本。他说 2023、2024 年刚起步时他们可能负担不起，现在前沿模型跑一遍要 4000 多美元，Opus 4.8 就超过 4000 美元。图上有一条清晰的帕累托曲线（Pareto Curve：在同样成本下智能最高的那些模型连成的边界），曲线上不同选项的成本差距超过 100 倍，选模型时应该按任务对成本的敏感度来选。

硬件和 Agent 类别

他放了一张硬件图：B200 节点每个请求的输出速度更快，系统总吞吐也更高，能支撑更多并发用户，硬件成本被摊到更多用户身上，这是推理成本下降的基础之一。

他们跟踪七类已经找到产品市场契合、增长很快的 Agent：编码 Agent；通用工作 Agent（ChatGPT 之外，还有本地的 Codex、Claude Cowork 一类）；聊天机器人；演示文稿 Agent；OCR；数据分析；客户支持。他说这些已经成熟到能在真实场景使用，但还有很长的路。

他最后展开讲编码 Agent，说编码 Agent 等于模型加 Harness，两者都决定表现：大家实际用的是放在 Claude Code、Cursor CLI 里的 Opus 4.7 或 Opus 4.8。录音到这里中断，直接接到主持人介绍下一位讲者，这部分后面的内容没有录到。

03. Sarah Sachs（Notion AI 负责人）：算力策略就是产品策略，多供应商带来的议价能力

直播位置 0:20:24–0:37:55（主持人介绍从约 0:19:30 开始；远程连线）

John Allsopp 介绍说，Sarah Sachs 是 Notion 的 AI 负责人，之前在 Robinhood 和 Google，负责 AI 建模、推理、Agent 编排和模型基础设施，最近也上过 Latent Space 播客。她开场说，如果她在现场，会和 Artificial Analysis 击掌，因为她完全同意上一场的内容；她要讲的是怎样真正提供这些服务、怎样做选择。她先请在 Fortune 50 公司工作的人举手，只有三四个人；然后问其他人，以及在给客户提供 AI 产品的人。她的问题是：没有那种规模和谈判能力，又想给客户最好的东西，该怎么办。她也放了一页团队成员的照片，说功劳属于他们。

两个真实场景

  • 场景 A：一个推理模型升级了，价格不变。每个 token 价格一样，但跑同样的任务，输出 token 变成了三倍。也许推理更多、效果更好，但你怎么办？
  • 场景 B：出了后继模型，版本号加 0.1，比前一代贵 40%，而前一代四个月后下线，你的整个产品建在它上面。你会把价格涨 40% 吗？她说希望不会。

她说那几个举手的大公司没关系，CEO 可以上 Bloomberg 抱怨，然后拿到很好的价格。大企业有专门的 AI 团队，各自单独谈判，筹码很大。她的假设是这让市场的大部分人被落下，市场并不有效。她的工作是代表“Fortune 5 million”（数百万家普通企业），因为他们是 Notion 的客户；在按用量计费的情况下，AI 的可及性由工作流的价格决定。Notion 每月处理几十万亿 token，有超过一亿用户，所以她可以做规模化谈判，再把成果带给其他人。她说她学到的几条经验不需要每月几万亿 token 也能用。

供应商也是你的竞争对手

她说每月 200 美元能用掉 5000 美元的算力，这是因为 Anthropic 自己的服务成本是按自己算的。她补充说 Notion 和 Anthropic 是很紧密的合作伙伴，对于最前沿的推理任务，她愿意多付钱，因为那些任务还没解决好；但很多场景并不是这样。她问有多少人觉得十年内会在某个产品上和 OpenAI 或 Anthropic 竞争，举手的人不多，她觉得这很有意思。

她看到的第一种情况是锁定：一些和前沿实验室高调合作的大型应用 AI 公司，很可能把全部支出承诺给了一家，换取很大的折扣，但被困住了。明天如果出了更好的开放权重模型或另一家的前沿模型，他们没法走，因为已经承诺了 2000 万美元。

她以 Notion 刚发布的托管 Agent（managed agents）产品为例说明可选性的价值：可以让 Claude Code 写修复，再让 Codex 审查，然后放进任务列表给人复核（产品里另一家 Agent 的名字字幕不清）。Notion 对这些模型按标价收费，最多给一点折扣，用户得到的是周边的体验。她说只看能力已经不够了，她几个月前写过一篇 Twitter 长文，很多人有共鸣：应该一直考虑“每秒每单位能力的成本”，自己没有资源评测的话，Artificial Analysis 是很好的参考。她放了上周的几条新闻标题和推文，说只看能力、不看延迟和成本的人已经吃了亏，而你不该让客户落到那种处境。

不是所有流量都一样

她列了 Notion 里的任务：改一个数据库字段、分拣邮件，这类应该尽快放到 MiniMax 这样的模型上；总结会议纪要也是，GPT-6 或下一代出来时他们不想多付 40%，这些任务要么用开放权重，要么自己做强化学习（RL）。数据分析、深度研究这类前沿任务，则要给客户前沿模型。她说客户需要 Notion 替他们做选择，否则新闻标题里的就是他们，你的产品也会变得用不起。

她说问题在于供应商的激励只有两条路（她说不点名）：要么是最强的推理模型，所有推文都拿你当例子，没人质疑你的价格；要么稍差一点，但每百万 token 便宜一些（字幕里的具体数字不清），就能拿下其余市场。她说这是一种双寡头，价格并不按大多数人的需求来定。她也反复强调，复杂任务用贵的推理模型是合理的，Notion 的用量里能看到这种分化，陷阱是把所有任务都放在那里。

可选性就是筹码

她说最好的前沿模型变得很快，Notion 给客户的默认模型大概每三到四周换一次。这需要大量工作，他们有很先进的评测（Eval）和团队，但她觉得别人不应该非得有这些，公开基准也有很多。如果经常切换，就不能把产品锁在某一家；锁住的话，从一月到二月你就在给用户更差的体验，她认为折扣不值这个风险。对于已经饱和的知识工作场景，锁定也许没问题，但要提供前沿能力就不行。她的说法是：可选性就是筹码，要随时准备走人。

Notion 有一个叫 Auto 的模型选项，就在模型选择器里。她说选择器该刷新了，模型列表越来越长。他们让用户自己选，因为延迟、质量、成本的权衡不能替客户假设：有人愿意在邮件分拣上花很多钱，有人根本不在乎研究任务准不准，她说这本身就是很好的用户研究。大部分时候 Notion 替客户选，75% 的用户留在 Auto，另外 25% 的选择也合理，所以给他们离开的机会。Auto 会根据任务给出需要的质量和最好的价格、延迟；比如设置一个邮件分拣 Agent，Auto 几乎不会选 Opus，否则用户看到第一张按用量计费的账单就会离开。

她的打法

  • 为多模型而构建，准备好切换，了解各家模型供应商。
  • 按价值评估，不按 token 评估。她举了 Notion 几个月前发的网页搜索服务商评测：某家每个 token 或每次请求可能更便宜，但要看你的 Agent 要发多少次请求、结果有多准，应该评估整个任务，而不是单个 API 调用，“供应商就是在单个调用上套住你”。你自己是你那个场景质量的专家。
  • 快速切换、经常切换，并且给供应商反馈。她说那次评测发出去的好处是：对选中的 Parallel 说“选了你，但差距很小，保持住”；对其他家说清楚为什么没选、请改进。她喜欢市场里的竞争。
  • 放弃折扣，换取可选性。
  • 第三个选项是开放权重。中等难度的任务他们在认真考虑开放权重，生产环境里已经有大量开放权重流量，以及经过强化学习训练的模型。她说这些模型撑得住这类负载，短期内不会到能力的右上角，但差距在缩小；开放权重还带来谈判筹码，可以自由选择推理服务商。她说 Kimi K2.6 是第一次在 Notion 自己的任务上和 GPT-5.2 质量相当，她放了这个评测，在他们认为 Auto 需要处理的一部分任务上得分没问题。

她提醒错误率也很重要，因为错误和重试也按 token 计费。成本还要看 token 用量，单价只是一半：她放了平均 token 消耗的对比，Opus 4.7、Opus 4.6 和 Sonnet 之间差别很大，她说先别看 Opus 和 Sonnet 的价格，看 token 消耗量。所以要理解整条轨迹才能理解模型。她推荐了 Philip Kiely 的书《Inference Engineering》，说即使不是推理方面的人也值得读。她说开放权重不需要追上前沿，这只是时间差：六个月前提供的产品客户很喜欢，他们不想明天突然多付钱。要有合适的评测，持续跟进，才能知道开放权重什么时候够用了。

架构比选模型影响更大

她说要赢下这些谈判，先要考虑架构，然后才是选模型。Notion 观察到 Harness 工程和架构决策对价格的影响大约是模型选择的 3 倍。有时是用原生 Harness，比如 Codex 和 Claude 的 API；有时用开源的 Pi；有时自己写 Harness，因为需要特定能力，也清楚提示缓存（Prompt Caching：重复的提示前缀由服务端缓存，再次调用时更便宜更快）之类的因素会怎样影响工作方式。

离开“Token Town”：用 CPU 做的事

她接着问：如果根本不需要 LLM 呢？她说虽然大会主题是“欢迎来到 Token Town”，现在要离开一下，回到用 CPU 干活的时代。她放了一张用 Nano Banana 生成的图：一个工程师想把 CSV 转成 PDF 再发到一个 webhook，这为什么需要 LLM，为什么要让一个重复任务不停地用推理 token 在 MCP 之间导航？她的回答是前沿实验室希望你“token max”，用他们能控制容量的方式消耗 token，但用户想要的是结果最大化。

所以 Notion 在开发者平台里推出了 Workers。Notion 认为很多任务在 CPU 上做得更好，确定性是有价值的，状态机一直都存在，只是钟摆因为可以摆就摆得太远了，那样的软件既不持久也不便宜。他们和 Vercel 合作，Workers 可以调用内部 API、计算沙箱，把一小段代码托管成 LLM 可以调用的动作。她说对部分客户的重复任务，token 成本最多降低了 80%。

结尾

她说这个市场很年轻、很不透明、变化很快，休假一周不看 Twitter 就像冬眠了两年，要注意休息。她觉得大家都在逆来顺受，这让她难过，而如果大家一起为自己争取，谈判能力会强得多，这也是对客户的责任。她提到在加州读到的一个统计：AI 比 ICE（美国移民执法机构）还不受欢迎。她说原因是行业还没有创造有价值的工作，价格也不对，人们没看到价值。她说这是一项强大的技术，有责任以负责任、持久、合适的方式交给客户。

04. Geoff Huntley（Latent Patterns，Ralph 循环的提出者）：软件开发被商品化，以及更小的 AI 优先团队

直播位置 0:39:45–1:00:10（主持人介绍从 0:37:48 开始）

主持人介绍

John Allsopp 说，差不多一年前他们在墨尔本办了一场 unconference，屋里约 50 人；又过了一点时间，在这里的影厅有一两百人。此后 Geoff 去了大约 19 个国家演讲，起因是“Ralph Wiggum”（辛普森一家里的角色）。Ralph 循环是 Geoff 提出的做法：让编码 Agent 在一个循环里反复处理同一个任务，靠测试等“背压”（back pressure）判断有没有做完，一直跑到完成。John 说 12 个月前这些关于背压和循环的想法还很新，现在 Codex 的 goal、Cursor 的 grind 模式这些长时间运行的任务就是 Ralph 的实现。这次从迪肯大学市中心的小屋 50 人，到两个影厅 600 人。

软件被商品化了

Geoff 说他会讲一些很有挑衅性的话，希望大家同意或反对，比如：软件开发现在的成本低于最低工资。他说软件已经被商品化，就像手里的 iPhone：人人都能当摄影师，但不等于是婚礼摄影师；产品经理现在能当软件开发者，但不等于是软件工程师。他声明自己不为任何人工作、不代表任何人，这些是他自己的看法。

他说大约一年半前他提出了长时间运行的任务和 Agent，现在大家天天在用，他一直在想接下来会怎样。他放了一张自己在 Atlassian 演讲的照片，说那是 Atlassian 裁员前大约一周，他讲的是“企业的单位经济学永远变了”。软件变得容易做出来，但不代表你在做对的东西。

他讲了几个例子。大约 100 天前他去了一场 Cursor 的线下聚会，台上的 Roslyn 不是传统意义上的软件开发者，现场有产品经理、设计师，大家玩得很开心，台上没什么软件工程师。他在奥克兰顺路去了指环王的取景地，导游问他做什么，他说做 AI，导游说 AI 太好用了，自己在做各种东西。他问：一个导游都在“token maxing”，这对我们的职业意味着什么？

他说以前软件是有门槛的：要么你懂得怎样控制计算机，要么你有一个可以点选配置的界面来得到业务结果，现在这些范式都被打碎了，人人都能控制计算机、写代码。社会是围绕知识稀缺组织起来的，软件开发者会说“不行，那要两周”；会计、律师等白领职业也是靠专业知识收高价。他举了 PewDiePie 的例子：这位 YouTuber 写的测试比在场大多数软件工程师都好，用的是基于性质的测试（Property-based Testing：随机生成大量输入，检查某些性质始终成立），工具字幕作“Antivisys”“Bomadil”，可能是 Antithesis 的 Bombadil；而你们还在用 Playwright。原本稀缺的技能现在变得充裕。

两次“oh fuck”时刻

他说 2024 年左右他第一次意识到事情要变了，写文章说以后没人用 IDE，别人说他疯了，说自己爱 IntelliJ、爱 JetBrains。他说 IDE 已经完了，被别的工作流取代，现在 IDE 主要是审查 diff 的工具。第二次是去年圣诞节，社会整体慢慢经历了同样的时刻。他的解释是：LLM 在 2024 年对社会冲击来说就已经够好了，只是当时需要很多技巧才能用好，现在基本是设定好就能跑；但人们要等到假期这种空闲时间坐下来，才意识到它变好了。

他说身边那些真正用好 AI 的人从 2024 年甚至更早就在刻意练习，把它当乐器而不是计算器：音乐人不会拿起吉他弹一下，觉得不好就扔在地上。公司现在把吉他硬塞给员工，“请弹吉他”，搞 token 排行榜之类，其实这就是一个好奇心测试：你会不会拿起吉他，投资你自己？他认为不是每个人都有这个天分。

两类公司

他说现在有两类公司。一类是已经很精简的，比如过去一年的创业公司，说除了现场工程（field engineering）之外绝不超过 50 人；另一类是其他所有公司，它们得走一个 J 曲线式的转型项目，要三四年。平常这没问题，但现在有按“斜率之上的斜率”速度构建的、Clayton Christensen 所说的那种破坏式创新创业公司，模型越强，它们越能攻击其他所有公司。

他提到 Block 因为 AI 裁掉近一半员工的新闻，说外面争论很多，他的看法是 Jack Dorsey 是对的，AI 会让大多数公司重新设计组织架构。他拿 Spotify 举例：Spotify 发了两段讲敏捷、squad、tribe、guild 的视频，几乎所有公司都照抄。他说现在也只需要一个案例：Jack、Shopify 的 Tobi Lütke 和另外几位高管正把自己的组织像一副扑克牌抛向空中，可能会害死公司，也可能找到制胜的蓝图，只要一家找到，大家就会复制。

资本和 SaaS 的问题

过去五个月他从澳大利亚到韩国、新西兰、旧金山、欧洲，和风险投资人聊。他说每个 LP 都在问 GP：现在为什么还需要融种子轮？以前融资是为了招团队把东西做出来，现在只要说清楚你想要什么就能做出来。所以冲击不只在软件开发和产品，也在上游的金融：如果公司只有五个人，资本有什么用？他说软件仍然值得投资，但要按结果的单位经济学收费，按席位收费是传统 SaaS。

他说要找个“沙袋”，就选 SAP Concur：按 LinkedIn 的数据，SAP 有 6800 人的固定开销，这 6800 人都要经历 J 曲线式的人员转型。大多数公司是这样建起来的：先有做事的人，再在上面加一层中层管理。新公司不想这样建，Block 这类公司愿意做激进的实验。每个高管心里的问题是：转型 6800 人要多久，在业务被冲击之前来不来得及？他说冲击你的不一定是 AI 本身，更可能是 AI 让新的竞争者进入了市场。如果你的 A 级员工觉得公司转型太慢，就会辞职去创办新公司。他说现在实验室的“最低招聘级别”都是 CTO 了，比如 Workday 负责内部人员转型的人，可能会去实验室工作，再反过来去打 Workday。

他说大家都知道小团队效果更好。他讲了一位新西兰创始人的故事：公司没有裁员，只是不再补缺，实际上缩减了三分之二，从 60 人到 20 人，产出比以往任何时候都多；那位创始人说，最好的决定之一是让那些听腻了 AI、反对 AI 的人离开。他指出那条帖子的日期是三年前，所以如果你现在才考虑因 AI 调整组织，不算晚，但也不算早。他说很多人没说出口的一点是：说是“AI 裁员”不太准确，实际情况是职位空出来不再补人，这已经发生了一段时间。他认为这会很难，因为没有人会主动放弃权力，转型过程会变成“饥饿游戏”。旧金山已经有公司在做支持这种组织形态的产品，被称为“AI 操作系统”。他说自己不知道这会走向哪里。

对工程师个人的建议

他说可以确定的是，今天的软件开发经验不保证明天的相关性。软件开发者用时间和技能换钱；公司采用 AI 有问题，是公司的问题，不是你的问题。如果你所在的公司完全禁止 AI，他建议你辞职，把家庭放在第一位，投资自己。

他展示了一年半前在 Canva 当技术负责人时画的一张图，来自他自己的经历和对 Canva 其他工程师的访谈：一开始是“AI 不够好，证明给我看”，慢慢开始试，然后有一个“我将来还有工作吗”的时刻，接着成为 AI 的使用者，再去理解它底层怎么工作，最后成为用 AI 构建东西的人。他问在场的管理者，怎样帮员工跨过这道鸿沟。他说今年这张图上多了一条线，原因很简单：他不再招线左边的人。

他说这条线是：高级工程师应该能解释 AI 的底层原理。问一个人什么是主键，对方会觉得你在考他；可问软件工程师 Agent 是什么，让他在白板上画一个、写一个，很多人就僵住了。他说 Agent 很简单，就是一个 while true 循环：把提示加进一个数组，发去推理，看返回里是否需要执行工具，自动把工具结果贴回去，再发起下一轮。高级工程师应该能把它画成时序图，这是他面试的新标准，看对方能讲多深。他有一个工作坊，教大家自己做一个 Cursor、Claude Code 或 Pi 这样的编码 Agent，大约 300 行代码。

他说不知道会走向哪里，谁说自己确定知道就是在忽悠。让他担心的是很多人觉得什么都没变；社会上已经有反 AI 的声音，比如“耗水太多”，他说那是闭环系统。很多人假装什么都没变，但 AI 正在掏空很多家庭的安全网，等某天醒来没了工作，问是不是 AI 造成的，还是自己没有投资自己。

收尾的几点

  • 去掉系统和流程里的浪费，比 AI 本身更能加速。他在澳大利亚有一个银行客户，设计库 Atom 里每个 UI 组件一个 Git 仓库，他说这就是浪费；一部分东西在 Jira、一部分在 Google Docs，多个事实来源也是浪费，要建立单一事实来源。
  • 招工程经理时，应该问对方：AI 打破了哪些系统和流程？还用敏捷吗？怎样不用敏捷？改了什么，浪费在哪里，结果是什么？他说这是招工程经理的领先指标。
  • 以前说“想法一文不值，执行才是一切”，现在反过来了。他说他想要某个功能时，会去一家公司官网截一张营销图，丢给编码 Agent，就得到了那个功能，像逛街挑手袋一样挑 SaaS 功能。执行被商品化了，做什么才是最难的问题。
  • 身份认同被抹掉了。有人说“我是 Golang 开发者”，他会问你用 Neovim、IntelliJ 还是 VS Code，然后说这些都不重要了；“我在这家银行、用这个技术栈、有十年经验”也不重要。他说这让很多人卡住，他认为几乎所有领域都是这样，软件只是其中之一。

他最后说，公司推行 AI 是在给你一个信号：拿起吉他，去学这些东西底层怎么工作。过去一年有很多工程师实现了他的一些想法，然后立刻升职。他请大家自己动手做一个 Agent，弄懂工具调用（Tool Call）这些机制，不要只做一个纯粹的使用者。John 说这场演讲他听过好几次，看着它在一年里不断演变。

05. Igor Costa（Autohand AI 创始人，前 GitHub Copilot AI 负责人之一）：编码 Agent 为什么会忘事，以及记忆的架构

直播位置 1:01:21–约 1:16:00（主持人介绍从 1:00:22 开始；远程连线；结尾录音缺失）

John Allsopp 说他这几个月和 Igor 熟悉起来，是因为对他在做的进化算法很感兴趣，他自己对进化算法着迷了 40 年。Igor 曾是 GitHub Copilot 背后 AI 工作的负责人之一，过去一年左右创办了 Autohand。Igor 开场问在场有多少人现在同时跑着至少 100 个 Agent，没有人举手。

无状态的 Agent

他放了一张墨尔本的老广告，写着电力是一件巨大的新事物，说电力让每户人家拥有无数不要工资、不睡觉、不休息的工人的力量，这和现在在做的事很像；Copilot 那样的小人形标志，19 世纪 80 年代也有过类似的形象，电力花了大约 150 年才走到今天。问题是现在的 Agent 不够聪明，它们是无状态的（stateless：每次会话不保留之前的经验）。他说这就是他离开 GitHub 自己做的原因，他觉得行业解决这个问题的方式不对；在 AI 时代自筹资金创业很贵，需要勇气。

他们先做了一个编码 CLI，优化目标很简单：每天能同时跑二三十个实例。他测试过各家前沿实验室的 Agent，说同时跑不了 20 个以上，电脑会被内存占满。他还说一个会话进行到一半，大概 10 到 15 条消息，Agent 就忘了自己在做什么。

上下文和记忆是两回事

他说行业的做法是不断往里加东西，加大上下文窗口（Context Window：模型一次能看到的 token 上限）。他们在 2021 年 8 月推出 Copilot，他说那是第一个交到大众手里的生成式 AI 产品，三个月后才有 ChatGPT（这是他的说法）。当时上下文只有 4000 token，他们费力地把东西塞进去，只为在自动补全里给出 10 条建议；现在到了一百万 token，而且大致停在那里，没有再往上走。他认为行业把上下文和记忆当成了一回事，它们很不一样，也可能是一回事，他说自己也不知道答案，还在探索。

四种记忆

他说他读了大约 75 篇论文，记忆可以分成九类，比如工作记忆、情景记忆、语义记忆，为了压缩在 18 分钟里，他只讲四种：

  • 语义记忆（Semantic Memory）：行业的做法是 AGENTS.md 这类文件，定义规则、访问方式、用的框架。他说至少十次里有七次模型不遵守里面写的内容，这是模型的局限。
  • 程序性记忆（Procedural Memory）：他说 Skills 在他看来是史上规模最大的社会实验，让每个人都去写 skill，相当于集体积累经验，用来提高训练数据的质量、把模型训得更好。他说记忆就是经验的积累。但最近每周都有新模型，提升都是边际的，他觉得行业是在无意中扩展规模，“scaling”这个词也被用滥了。
  • 情景记忆（Episodic Memory）：他说最近两周编码 Agent 才开始尝试这种记忆。它在编码 Agent 里很特殊，因为时间是记忆常常忽略的维度。一个人带一群 Agent 还好，团队一起用就很难：每个人意见不同，没有共识就会漂移、崩塌。他说如果 Agent 回你“you're absolutely right”，就该关掉会话，因为它已经完全迷失了。
  • 反思记忆（Reflective Memory）：他说这是最后一种，也很重要，行业开始转向让 Agent 反思会话里发生了什么、下次怎样做得不同，大概有三到五家创业公司在做。

他说也许整个方向都错了。他认为智能应该是分布式的，不应集中在四家公司手里。

Autohand 做了什么

  • 编码 CLI：已开源，功能和 Codex、Claude Code、Gemini CLI、Cursor Agent 相同，但开放透明。他说他们开始做的时候 Pi 还不存在，Mario（Pi 的作者）大约晚三周才开始。CLI 从一开始就有记忆和用户偏好，用最基础的格式：他说没有什么比读 SSD 上的文件更快，有人卖你很厉害的 KV 数据库或向量数据库，就像在采购 SAP，他做过基准测试。
  • Commander：他们开源的 Agent 开发环境（他说两周后 Conductor 的 Charlie 也做了类似产品，现在市面上大约有三四十个这类“agentic development environment”）。这里放的是集体记忆，他说还是实验。他们的编码 CLI 下载了大约 30 万次，每天约 15 万人在用，用得越多越好，因为记忆在积累。上面讲的四种记忆都放进去了，再加上共享记忆：怎样让它成为单一事实来源，怎样让 Agent 像人一样协作、达成共识。他说在人和组织里观察到的行为在 Agent 身上也会发生：它们彼此不同意。

论文 Agent Spawn：模仿遗传

他写了一篇叫 Agent Spawn 的论文，想法来自自然界：孩子从父母各继承一部分体能和智力特征。Agent 只往上下文里装当前任务需要的东西，做反思，然后“生出”一个带着不同观点的新版本。他做这个是因为他执着于能运行很长时间（超过 48 小时）的长时程编码 Agent，他说做的人不多。

他们要解决两个问题。一是检测漂移：模型可能随机地模仿开头给的上下文，回你一句“you're absolutely right”，其实方向已经不对，这时把记忆转给另一个 Agent，新 Agent 的能力、技能或指令可能和之前不同。二是崩塌：Agent 之间达不成一致，说起来简单，看它们一起工作时很难处理。

把记忆做成模型

他说他们放弃了以大语言模型为中心的思路，只把 LLM 当作一个依赖，而不是一等公民。他提到 Sarah 演示里那些模型 logo，说半年到一年后可能就不那么重要了。

为了验证，他说“用 Linus Torvalds 的品味来检验”：他们做了一个把 Linux 内核迁移到 Rust 的应用，跑了 10 个多月，还在跑，还没成功（“对不起 Linus，不是今天”），但越来越近；开始时只有 12% 迁移成功，现在的比例他没有说。

他说背后的关键来自新加坡的一家 AI 实验室提出的分层推理模型（Hierarchical Reasoning Model，HRM），他们的思路是“记忆就是模型”。可以用你已有的数据（客户数据、交易数据、会话数据）训练更小的稠密模型，参数从 2000 万到 20 亿。他们的训练周期从每周一个检查点缩短到三到五个小时。他说他早年训练自己的模型大约花掉 50 万美元，现在大约 500 美元。他说他们还没有解决问题，还很早，但数据给出了不少证据；他对此保持怀疑，因为现在用 Agent 做实验很便宜，所以可以按数据调整方向。他们认为每个人应该拥有自己的 AI，整套栈应该掌握在自己手里。

还没解决的问题

  • 记忆的正确性：很难，他们还在研究，论文还不能发，但快解决了。
  • 把记忆作为训练信号的一等公民：模型负责学习，记忆负责存储，两者现在是分开的。他提到多个 LoRA（LoRA：只训练少量附加参数的轻量微调方法）和递归语言模型怎样更快适配，这句字幕不清。

他说还剩几分钟，开始讲人怎样理解世界，问大家走过来时有没有听到原住民在对你说话。录音在这里中断，直接接到了下一场的中段。

06. Vamsi Ramakrishnan（Google Cloud）：大规模全双工语音 Agent 为什么改用 Rust

直播位置 1:16:24–约 1:19:55（开头和主持人介绍缺失，只有后半段）

章节说明这一场讲 Gemini Live 语音 Agent、Python 的延迟极限，以及为什么全双工系统转向 Rust。全双工（Full Duplex）指用户和 Agent 可以同时说话、随时打断，像打电话一样，而不是一人说完另一人再说。录音从他的总结部分开始：他说这场是分享他们用 Python 构建全双工语音 Agent 时在一线遇到的挑战。场景是两类：一类是印度这样的国家，客户想用低成本的方式每周呼叫大约 1000 万用户；另一类是高价值客户，任何一点卡顿或停顿都会毁掉语音体验。他说这些是付出代价学到的教训。

状态机加正则表达式

他说整场可以用一句话概括：把对话映射成对话阶段，用阶段来控制对话怎么走。状态机和正则表达式很搭，不需要 LLM 一直处理转写文本，用大约一百万条正则模式就能做一个小型 LLM 能做的事，他说这是大家完全忘掉的办法。他举的例子是催收：要引用一条法规，然后问“你明白吗”，用户必须复述才算同意。这类判断可以在对话流里用正则计算，延迟极低，不必浪费一次 LLM 调用，也给一个能处理任意情况的强模型加上一定的确定性。需要确定的地方就必须确定，比如把流程建模成 DAG（有向无环图），要求前三步做完才能做第四步，这就需要控制循环。

他说前沿模型公司的 SDK 都没有这些能力，因为他们还没见过太多客户在这个规模上部署；现在是第一批客户在把极限往外推，这些能力以后会被吸收进产品，但目前还是“狂野西部”。

延迟预算就是架构

他说不是 Python 版的 ADK（Google 的 Agent Development Kit）不好，他的意思是它不适合实时的热路径。如果要在毫秒级预算下大规模运行生产语音 Agent，就得用 Rust。语音 Agent 的延迟预算决定了架构：文本 Agent 有余地，模型在想的时候用户在读；语音没有任何容错空间。所以他们用 Rust 重写了 ADK，做到了每天一百万通外呼、每天超过十万通呼入，服务的是印度多种本地语言、要求很高的呼叫中心。

他说代码仓库和 crates 链接已经分享出来，有贡献指南，欢迎社区贡献，许可证是 Apache 2.0，不会改。

07. John Allsopp（Web Directions）：会务说明，以及给你的 Agent 准备的会议直播流

直播位置 1:20:06–1:25:10

John 说平时这个时候他会花很多时间讲会务，这次内容太多，只讲几件事，主要看屏幕上的几个二维码：

他接着介绍了下午的安排：午休一小时，回来后 AI 工程在这个影厅，软件工程在二号影厅，有领导力通行证的人去 Swinburne 的场地；餐饮和展区主要在 Zinc，休息期间还有 hallway track，有赞助商和受邀讲者的交流。他鼓励大家去看各个合作伙伴，包括主赞助商 Google Cloud 和 Google DeepMind，逛遍所有展位的人里会抽一位送 Mac Mini，“可以把你的 claw 隔离在上面，或者在上面跑很多个 claw”。最后他感谢了上午的讲者和穿红 T 恤的志愿者，说 12:30 准时回来。本文略过之后的午休。
