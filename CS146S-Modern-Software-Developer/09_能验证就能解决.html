第九讲：能验证，Agent 就能解决

客座 Eno Reyes（Factory CTO）：Agent 失败多半怪环境，不怪模型；人类的进步来自让事情变得可检查；检查的精确度和频率两个维度；九个支柱、五个等级的 Agent 就绪度框架；一个下午能做完的改造清单；代码之外，哪些领域 Agent 会先到

讲者：Eno Reyes（Factory 联合创始人、CTO）
资料来源：课件 PDF（2026 年 10 月 22 日，30 页；这一讲没有公开转录，本文依据课件整理，讲者口头补充的内容这里没有）

一、题目和论点

讲座题目是 If you can verify it, an agent can solve it，副标题是 Agent Readiness, and why the world matters more than the brain：能验证的事，Agent 就能解决；环境比“大脑”（模型）更重要。Factory 是做编程 Agent（产品叫 Droid）的公司，上一讲演示的 Agent 就绪度报告就是他们的。

开场先做了个举手调查：这周用过 Agent 的举手；Agent 完全按你说的做了的，继续举着。然后列出 Agent 失败时大家通常怎么归因，都是怪“大脑”：

  • “模型太笨了。”（所有人，凌晨两点）
  • “等下一个模型吧。”（乐观派）
  • “它不懂我们的代码库。”（资深工程师）

他今天的主张：问题主要出在环境。

二、人类的经验：脑子没变，世界变了

脑容量和能做的事

三百万年里，人脑从大约 450 毫升长到大约 1350 毫升，约 3 倍；智人出现在 30 万年前，那时大脑基本定型。可人类能做的事在最近才爆发：一万年前全世界大约 400 万人，今天 80 亿。（课件注明脑容量是化石平均值的近似，人口是常见估计。）

如果三百万年是一天

时刻事件
晚上 9:36智人出现，大脑基本定型
11:50最近两万年开始
11:54农业
11:57文字
11:59:43印刷术
11:59:58晶体管
最后 0.1 秒ChatGPT

结论页只有两句：同一个大脑，新的世界。硬件三十万年几乎没动，是环境改变了一切。

我们造了让事情可检查的工具

时间工具它回答的问题
约公元前 3200 年文字这是我们说好的吗？
约公元前 3000 年度量衡这个量公平吗？
1494 年簿记账平吗？
17 世纪实验这是真的吗？
1990 年代单元测试它能用吗？

每一样都让分辨对错变得便宜。他的总结：我们没有变聪明，我们变得可检查了。进步来自反馈，不来自更大的脑子。

三、同样的故事，在 Agent 身上压缩到五年

基准测试上 Agent 看起来很强

SWE-bench Verified 是一个基准测试，题目是真实开源项目里的 GitHub issue，看 Agent 能解决多少。课件给的曲线（厂商自报数字）：

时间解决比例
2023 年 10 月约 2%（原版 SWE-bench，更难）
2024 年 10 月49%
2025 年 2 月62%
2025 年 5 月73%
2025 年 9 月77%
2025 年 11 月81%

两年里，从几乎解决不了真实 issue，到能解决大多数。

每个基准都自带一个评分器

一道 SWE-bench 题的流程：

  1. 一个来自热门开源仓库的真实 GitHub issue。
  2. Agent 写补丁，看不到答案。
  3. 运行隐藏测试，测试取自当年真正修好这个 issue 的 PR。
  4. 通过或失败，没有部分分，不凭感觉。

他的说法是：基准测试是地球上最 Agent 就绪的代码库。

Agent 是一台猜测加检查的机器

Agent 的循环是：读、计划、编辑、运行、检查、修复。每一步能检查，就多一次早点发现错误的机会。模型负责猜，环境负责检查。

讲座的核心句在这里单独占了一页：If you can verify it, an agent can solve it.

四、两个旋钮：可验证性和粒度

他用一个 2×2 的格子来分任务。纵轴是检查有多精确（从精确到凭感觉），横轴是能多频繁地检查（只在最后查一次，到每一步都查）。每格各举了学校和软件里的例子：

只查一次每一步都查
检查精确碰运气（Long shot）：学校里是一场定生死的期末考；软件里是一次巨大的迁移，最后才测一次自动驾驶（Autopilot）：学校里是有自动评分器的习题；软件里是有快速测试套件的 bug 修复
凭感觉抛硬币（Coin flip）：学校里是“写点好东西”；软件里是“把产品做得更好”有人带（Coached）：学校里是每周有反馈的写作课；软件里是有设计师盯着的 UI 打磨

为什么小步、每步检查会赢

课件算了一笔账：一个 20 步的任务，Agent 每一步做对的概率是 90%。

  • 只在最后检查一次：20 步全对的概率是 0.920 ≈ 12%。
  • 每一步都检查，失败了最多重试 3 次：一步三次都错的概率是 0.13，所以整体成功率是 (1 − 0.13)20 ≈ 98%。

检查越快，能试的次数越多

如果每次尝试都要等检查结果，每小时能试几次：

检查方式耗时每小时尝试次数
Pre-commit hook（提交前自动运行的检查）5 秒720
本地测试1 分钟60
CI 流水线10 分钟6
代码审查1 天不到 1

5 秒的检查比 10 分钟的检查，每小时多 120 倍的尝试机会。

五、Agent 就绪度：你的代码库有多可检查

多数 Agent 失败是环境失败

  1. 没有 pre-commit hook：Agent 等 10 分钟 CI，才知道 linter 5 秒就能告诉它的事。
  2. 环境搭建没写下来：Agent 猜有哪些环境变量，失败，再猜。
  3. 构建步骤只存在于 Slack 聊天里：没有成文的办法检查自己的工作，所以它就不检查。

他补了一句：这三样新员工也一样会卡住。

九个支柱，九个问题

每个支柱都是 Agent 需要能自己检查的一件事：

支柱问题
Style & Validation（风格与校验）格式对不对？
Build System（构建系统）能编译吗？
Testing（测试）能用吗？
Documentation（文档）这里的做法是什么？
Dev Environment（开发环境）能复现吗？
Observability（可观测性）实际发生了什么？
Security（安全）能安全上线吗？
Task Discovery（任务发现）下一步做什么？
Product & Experiments（产品与实验）对用户有帮助吗？

注意：第 5 周作业引用的 Factory 文章写的是八个支柱（Style & Validation、Build System、Testing、Documentation、Dev Environment、Code Quality、Observability、Security & Governance），和这里的九个不完全一样。作业按八个支柱填表。

五个等级

通过某一级 80% 的标准，才解锁下一级。检查越多，自主程度越高。

等级名称含义
1Functional代码能跑，检查靠手动
2Documented写下来了
3Standardized检查自动化并强制执行
4Optimized度量过，反馈快，可以让 Agent 长时间独立运行
5Autonomous放手

好项目不一定就绪

两个例子（Factory 公开报告，2026 年 1 月）：CockroachDB 是 4 级，CI 全面、测试完整；Express 只有 2 级，文档清楚、有安全扫描，用的人极多、久经考验，但缺好几项基础信号。他的结论：流行不等于可检查。

就绪度会复利

检查更好，Agent 就能做更多，工程师省下时间，再投回去改进检查。这对所有 Agent 都有用，不只是 Factory 的；对每个人也有用，这些也就是新同事第一天需要的东西。

六、作业：一个下午让项目 Agent 就绪

  1. 写一份 AGENTS.md：用直白的话写清楚怎样构建、测试、运行。
  2. 加一个 .env.example：不用再猜有哪些环境变量。
  3. 一条命令跑完测试：只要一条，写进 AGENTS.md。
  4. 先写会失败的测试，再让 Agent 修 bug。
  5. 提交时自动 lint 和格式化：用 pre-commit hook，5 秒出反馈。
  6. 运行 /readiness-report：看自己在哪一级，先修最大的缺口。

七、代码之外

这一部分用了一句特朗普 2025 年坐在 Tesla 里说的 “Everything's computer.” 当引子，他说这句话比说的人以为的更对。

代码只是形式化的一种

按检查的成本从便宜到贵，课件排了一串领域和它们各自的“检查器”：

领域检查方式
数学证明检查器
代码测试和类型
会计账要平
芯片仿真
法律审查和判例
医学临床试验
品味你的直觉

任何领域都可以把工作往检查便宜的一端挪，从而变得 Agent 就绪。

检查便宜的地方，Agent 先到

  • 数学：证明检查器给每一步打分。AlphaProof 用 Lean 证明检查器在 2024 年达到国际数学奥赛银牌水平，2025 年达到金牌水平。
  • 代码：测试和类型给每一次改动打分，两年里从约 2% 到约 80% 的真实 GitHub issue。
  • 医学：最终检查是临床试验，每次要好几年。机会在于做出人们能信任的更快检查。

给在座每个人：你的工作是造检查器

稀缺的能力，是把“好”变成机器能验证的东西。

八、三句话

  1. 瓶颈在环境，不在大脑。
  2. 能验证，Agent 就能解决。
  3. 让检查便宜、快、小。

最后一页：不要等更聪明的大脑，去造一个更聪明的世界。
