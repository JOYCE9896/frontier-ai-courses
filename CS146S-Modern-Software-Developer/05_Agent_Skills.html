第五讲：Agent Skill

为什么在 MCP 之外还需要 Skill，Skill 是什么，四类常用 Skill（理解与计划、验证、代码风格、其他如网页解析），写好 Skill 的最佳实践：范围单一、从自己的对话记录里挖、带上触发场景、渐进式披露、组合复用、配一个验证 Skill

主讲：Mihail Eric
资料来源：课件（2026 年 10 月 6 日；这一讲没有公开转录，课上的现场演示没有记录，本文依据课件整理）
课程推荐阅读：pstack、Matt Pocock 的 Skill 集、browse.sh

一、开场事务

  • 作业 3（写一个 Skill，见作业页）周五截止。
  • 发放 Claude Code 额度和 Cursor 额度。
  • cmux 的 Austin 来课上介绍项目（第三讲提到，他会演示怎样同时驱动几十个 Agent）。
  • 周四的客座讲座是 Lee Robinson（见第六讲）。

二、为什么需要 Skill

第四讲讲的 MCP，适合把第三方服务接进编程 Agent。但还有另一类能力：LLM 极其擅长照着一段较长的流程一步步做，把这种能力暴露给 Agent，是任何外壳都很重要的一部分。Skill 就是为这件事准备的。

课件的定义：Agent Skill 是一种动态加载 Agent 能力的标准。它针对特定领域，把代码和提示词结合起来，由 Agent 在需要时加载。典型用途有写文档、做 PPT、数据分析等。回顾第二讲：Skill 一开始只把名字和一句描述放进上下文，任务相关时才把正文拉进来，这就是渐进式披露，也是它比一次性装进所有 MCP 工具省上下文的原因。

文件结构（第四讲课件给过骨架）：一个目录，里面一个 SKILL.md。开头用 --- 包住的元数据写 name 和 description，description 要说明这个 Skill 做什么、什么时候用；正文写给 Agent 的指令，通常分"何时使用"和"具体指令"两块，可以附带脚本和参考文件。课上随后是现场演示，课件只留了一页"DEMO"。

三、四类常用 Skill

  • 代码理解与计划。第三讲的 RePPIT 那组 Skill（研究、提议、计划、实现、审查、探索）就属于这类。课件还推荐了 Matt Pocock 的 grill-me 和 grill-with-docs：让 Agent 反过来追问你，帮你对一个任务建立心智模型。
  • 验证。课件点名的是 create-verification-skill：用一个 Skill 去生成"检查 Agent 自己工作"的 Skill。
  • 代码风格。把代码层面的最佳实践写下来，对代码审查 Agent 尤其有用。第二讲那个"check code quality"就是例子。
  • 其他。比如网页解析，课件给的例子是 browse.sh，让 Agent 的能力延伸到代码仓库之外的网页上。

四、写好 Skill 的最佳实践

课件用两页列了最佳实践，这里逐条解释：

  • 范围要窄。一个 Skill 只做一件定义清楚的事。范围一宽，描述就很难写准，Agent 不知道什么时候该用它。
  • 维护一套自己的 Skill，能方便地带到各个项目。课件引了 poteto 的一句话："厨师换厨房时会带上自己的刀。"
  • 从自己的对话记录里挖。Skill 是用 Markdown 写成的流程。回头翻自己和 Agent 的聊天记录，看哪些地方你插了手、纠正了它，那些纠正就是该写进 Skill 的东西。
  • 别浪费 token 和时间重新发明轮子。给 Agent 配一个命令行工具，把调用它的套路代码包进 Skill 里。这样确定性的部分由工具完成，Skill 只负责告诉 Agent 怎样用。
  • 写上应该触发这个 Skill 的场景和请求措辞。Agent 靠 description 判断要不要加载，用户实际会怎么说，就把那些话写进去。作业 3 专门考这一点：要测三个应该触发的提示和一个不该触发的"擦边"提示。
  • 渐进式披露。正文只放必需的内容，较长的参考资料放在 Skill 目录里的其他文件，需要时再引用具体文件。第三讲的 plan Skill 就把设计文档模板放在单独的文件里。
  • 模块化，让 Skill 能互相组合。
  • 维护一个验证 Skill，让 Agent 检查自己的工作。这样就形成一个改进循环：做完、检查、发现问题、再改。

五、API、MCP、Skill 再对比一次

这一讲重复了第四讲最后那张对比表：API 是给开发者调用的服务接口，认证、重试、分页、校验都由你处理；MCP 是给 Agent 运行时以标准方式调用的工具定义，是和外部资源、数据、服务交互的主要机制；Skill 是教 Agent 怎样完成一项工作的可复用流程，常常编排多个工具，是工作流层面的抽象。用第二讲的话说：MCP 工具是最小的原语，Skill 把工具、脚本和提示词串成多步操作。
