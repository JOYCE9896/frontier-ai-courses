补充二：Boris Cherny 在 Sequoia 的访谈

Claude Code 怎样起步、前六个月为什么不好用，"编程已经解决"对谁成立，他用手机管几百个 Agent 和几十个 loop，跨学科的通才，AI 让哪些商业护城河变弱，以及软件编写会像识字一样普及

讲者：Boris Cherny（Anthropic，Claude Code 的创造者）；主持：Lauren Reeder（Sequoia）
这一篇不是课堂讲座。Boris Cherny 10 月 15 日（第 4 周）在 CS146S 做过客座讲座，但那一讲没有公开课件和录像。这里整理的是他在 Sequoia 活动上的一场公开访谈：Anthropic's Boris Cherny: Why Coding Is Solved, and What Comes Next（Sequoia Capital 频道，2026 年 5 月 4 日上传，24 分 36 秒，后半段是现场提问）。本文依据 YouTube 自动生成的英文字幕整理；访谈时最新的公开模型是 Opus 4.7。
和课程的关系：第 4 周讲定制 Agent 配置；这场访谈讲的是他自己怎样用 Claude Code、团队和行业会怎样变，可以和补充一（三个月后的 YC 访谈）对照着读。

一、Claude Code 是怎样开始的

开场他先在现场做了个调查：多数人主要用 CLI，用桌面版的也不少，用 VS Code 或 JetBrains 插件的不多；他自己"I'm like iOS mostly these days"。

他 2024 年底加入 Anthropic 内部的孵化团队 Anthropic Labs，只有几个人，做出了 Claude Code、MCP 和桌面版，之后团队解散；现在 Labs 由首席产品官 Mike Krieger（Instagram 联合创始人之一）带领重新组建。

做编程工具的理由是 product overhang：模型已经能做到的事，还没有产品把它用起来。2024 年底编程工具的最好水平是"type ahead"，在 IDE 里按 Tab 一次补全一行，这是 Sonnet 3.5 第一次做到的。他们觉得模型快要能迈下一步了，"we can just have the agent write all of the code"。

结果前六个月效果不好，"It was barely usable"，他自己也只用它写一成左右的代码。刚发布时用户不少，但没有现在的指数增长；增长从 2025 年 5 月的 Opus 4 开始，之后每次模型发布（4.5、4.6、4.7）都再上一个台阶。"we knew that it wouldn't have PMF for 6 months because we were building for the next model." PMF（product-market fit）指产品真正满足市场需求。

二、"编程已经解决了"

他又请现场举手：完全手写代码的、完全用 Agent 的、介于两者之间的。主持人说那就算"50% solved"。

对他自己来说是百分之百。Claude Code 的代码库（他说"it leaked, so you know, people know"）只是 TypeScript 加 React，"there's no big secret"。选这两样是因为它们"very on distribution for the model"，也就是在训练数据里很常见，模型最熟。早期模型没那么聪明，语言和框架选择影响很大；现在模型能写任何语言，也能学没见过的框架。大约在 2025 年 10、11 月，Claude Code 的代码就全部由模型写了。

他现在每天提几十个 PR，上周有一天提了 150 个，"That was a record"。但他也说大型复杂代码库、模型不擅长的冷门语言还没解决，"Usually the answer is just wait for the next model."

三、他自己的工作方式

他现在大部分工作在手机上做：打开 Claude 应用左侧的 Code 标签，同时开五到十个会话，每个会话里有一批 Agent，平时总共几百个在跑，晚上有几千个做更深的工作。

管理方式之一是让 Claude 派子 Agent。他用得越来越多的是 /loop："it's like the simplest thing that works"。Claude 用 cron 安排一个重复任务，每分钟、每五分钟或每天跑一次。他手上有几十个 loop，例如：

  • 照看自己的 PR：修 CI、自动 rebase。
  • 保持 CI 健康，遇到不稳定的测试（flaky test）就去修。
  • 每 30 分钟抓一次 Twitter 上的反馈，聚类后给他看。

"I sort of feel like loops are the future at this point." 刚发布的 routine 是同样的功能跑在服务器上，合上电脑也会继续。

四、团队会怎样变

他的预测是通才会多很多，而且是跨学科的通才。今天说"通才"，多数还是工程师，比如 iOS、网页、服务器都能做。以后会有既擅长产品工程又擅长设计的人，或者产品、数据科学、工程都会的人。Claude Code 团队已经是这样："our engineering manager, our product manager, our designers, our data scientist, our finance guy, our user researcher, every single person on our team writes code."

五、写代码便宜了，软件产品会怎样

主持人问会不会出现"SaaS 末日"。他说会发生两件事，都不是大家常讨论的那种。

第一，借用 Hamilton Helmer 的《七种力量》（7 Powers，讲企业的七种持久竞争优势，他是从 Acquired 播客知道的），AI 会让其中一些变弱、一些不变：

  • 变弱的：转换成本，因为可以用模型把东西从一个系统搬到另一个系统；流程优势（process power），因为 Claude 越来越会摸清流程，"especially with 4.7, it can just hill climb anything"，给它一个目标、让它迭代到完成，它就能做到。
  • 不变的：网络效应、规模经济、独占资源。

第二，未来十年颠覆行业的创业公司数量会是过去十年的十倍左右。小公司能做出和大公司一样有价值的东西，正面竞争；大公司要改业务流程、重新培训所有人，会遇到很多内部阻力，从零开始的公司没有这个负担。"it's the best time to be a startup."

六、现场问答

成功靠模型还是靠产品

他说是两者混合，半年前问他大概是一半一半。产品重要的原因是他在 YC 公司做过第一号员工，YC 反复强调 "build something people love"，所以团队很在意细节。但模型越强，Harness 越不重要。他预计一年后模型的对齐会好得多，现在围绕提示词注入、命令的静态校验、权限模式、人工确认的那些安全机制都会变得不那么重要，"cuz the model will just do the right thing"。

编程会不会变成人人都会的技能

"Oh my god, yes." 他说会像发短信一样普通。他平时读科幻和技术史，认为最接近的类比是 15 世纪欧洲的印刷术：之前大约 10% 的人识字，常受雇于不识字的国王和领主；印刷术出现后的 50 年里，欧洲出版的书比之前一千年还多，书价降了约 100 倍；之后几百年，全球识字率升到 70% 左右。现在人人能读写，但仍有职业作家。软件会以快得多的速度走同样的路。

推论之一："The best person to write accounting software, I think maybe even today, is not an engineer, it's a really good accountant because they know the domain really well and coding is the easy part."

Anthropic 内部领先外部多少

他说模型上没有差距：内部也主要用 Opus 4.7 写代码，只是会试用一点 Mythos，它的某个后续版本以后也会对外开放。差距在产品使用和组织流程上。"we use Claude for literally everything"：他的多个 Claude 在 loop 里写代码时，会通过 Slack 和别人的 Claude 沟通、弄清不确定的事；公司里已经没有手写的代码，SQL 也都由模型写。所以领先的地方在组织结构和流程，而这一点创业公司更容易做到。

模型怎样学会自己并行

有人问怎样让模型自己判断何时该派十个子 Agent，而不是靠用户凭直觉。他说产品这边主要靠调提示词；模型变强后会自然这么做。他举例：让 Opus 4.7 拉一份数据，它说"I noticed that the data is changing over time. I'll start a loop and I'll give you a report every 30 minutes"，他回"Can you send it to me over Slack?"，它就用 Slack MCP 发。他的看法是，如果要用户学会怎样摆弄工具，那是产品设计没做好。

本地模型还是云端

"it doesn't matter." 他认为几年后写代码、启动 Agent、搭环境都由模型来做，用本地模型还是云端由模型自己决定，"I don't think these will be decisions that we are making as engineers anymore."

Cowork 怎样接入知识工作者的工具

开发者的工具多在本地，知识工作者的工具多在云端。他说在大公司时花了五年把开发环境搬到远程，而知识工作的工具（Salesforce、文档等）本来就在云上。答案就是 MCP：在 Claude 应用里接好 Salesforce、Google Docs、Google Calendar 的连接器，Cowork、CLI 和各处的 Claude Code 都能用。没有 MCP 的系统就用电脑操作（computer use），"It's very slow, but it does it quite well now"。总之 MCP、API 或任何程序化的接口都行，"To the model, it's just tokens."

今天该做什么样的产品

问他现在会押注什么样的产品，在模型变强后会更有意思。他提到 Claude Design（"It's pretty good today. It's going to get a lot better."），Claude Code 接下来几周要发布的东西，loop、batch 这类大规模并行 Agent 的功能，以及电脑操作。
