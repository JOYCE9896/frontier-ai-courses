Satya Nadella：微软怎么看 AGI

参观 Fairwater 2 数据中心之后，Satya Nadella 和 Dwarkesh、Dylan Patel 聊 AI 时代的商业模式、GitHub Copilot 份额下滑、模型层和应用层谁拿利润、MAI 自研模型、2024 年下半年的建设暂停、自研芯片与 OpenAI 新协议、capex 暴涨，以及世界还会不会信任美国的技术栈

主持：Dwarkesh Patel、Dylan Patel（SemiAnalysis 创始人）· 嘉宾：Satya Nadella（Microsoft CEO）· 发布日期：2025 年 11 月 12 日 · 时长：1 小时 28 分 · 整理：Joyce（@JOYCE9896）

这一期的内容

这期在 Atlanta 录制。Satya Nadella 和 Microsoft 云与 AI 执行副总裁 Scott Guthrie 先带 Dwarkesh 和 SemiAnalysis 的 Dylan Patel 参观了新建成的 Fairwater 2 数据中心。视频描述写道，Microsoft 在建多座 Fairwater，每座有几十万块 GB200 和 GB300，这些互相连通的楼加起来总容量超过 2 GW，单独一座 Fairwater 就比现存任何 AI 数据中心都强。参观之后是访谈，两位主持人轮流提问：Dwarkesh 多从“AGI 真的来了会怎样”的角度追问，Dylan 带着 SemiAnalysis 的营收、算力和芯片数据追问。字幕没有标出说话人，下文写出的提问者名字是按上下文推断的，拿不准的写“主持人”。

Satya 的整体立场比较克制：他相信这可能是工业革命以来最大的事，scaling law 也还在起作用，但他认为技术要真正带来经济增长，得先改变企业的工作方式，这需要时间。几个主要分歧点：Dwarkesh 认为模型会越来越能干，价值会集中到模型公司，持续学习还可能让领先的那一个模型通吃；Satya 认为只要有多家模型竞争和开源模型兜底，就不会有“game set match”，Microsoft 要在基础设施、模型、应用三层各凭本事竞争。Dylan 用数据挑战他：GitHub Copilot 一年内份额从过半跌到 25% 以下，Microsoft 2024 年下半年的建设暂停让 Oracle 有机会做大，Microsoft 自研芯片的订单量远低于 Google 和 Amazon。节目中间两段赞助商广告已略过。

01. 参观 Fairwater 2 数据中心

节目位置 0:00:00–0:04:15 · Fairwater 2

训练算力每 18 到 24 个月涨 10 倍

开头是在 Atlanta 数据中心里边走边聊的片段，字幕里分不清哪句是 Satya、哪句是 Scott Guthrie。导览中说，他们一直在争取每 18 到 24 个月把训练算力提高 10 倍，Fairwater 2 相当于在 GPT-5 训练所用算力的基础上再涨 10 倍。另一个数字是网络光模块：这栋楼里的光学网络器件数量，差不多等于两年半以前整个 Azure 所有数据中心加起来的量，楼里大约有五百万条网络连接。

跨园区、跨地区合起来训练

主持人问，这是不是在押注未来会有一个大到要两个地区一起训练的模型。回答是：目标是能把这些算力（flops，浮点运算能力）聚合起来做一个大训练任务，跨站点拼在一起；但现实中它会先用来训练，再用来生成数据（data gen），再用于各种推理（inference，指训练好的模型对外回答请求），不会永远只跑一种负载。附近在建的 Fairwater 4 也会接到同一张 1 petabit 的网络上，两座楼之间可以高速连通；再通过 AI WAN（连接不同地区数据中心的广域网）连到 Milwaukee，那里还有好几座 Fairwater 在建。

导览中提到，这里的布局能直接看出模型并行和数据并行。模型并行是把一个模型拆到多块芯片上一起算，数据并行是多份模型各自处理不同的数据再同步。园区里的超级计算单元（super pod）是为训练任务设计的，再通过广域网连到 Wisconsin 的数据中心，一个训练任务可以把这些地方的算力全部汇总起来跑。

他们站在一个还没装服务器、没装机柜的 cell（机房单元）里。主持人问一个 cell 有多少机柜、楼里有多少个 cell，对方都说不能透露，主持人开玩笑说“除法很简单”，意思是自己数得出来。主持人问 Satya 看到这些是不是终于知道钱花到哪儿了，Satya 的回答是：“我经营一家软件公司。欢迎来到这家软件公司。”

不想全部按一个规格建

主持人问：一旦选定了 GB200 和 NVLink（Nvidia 用来把多块 GPU 高速连成一体的互连技术），设计空间还剩多大？回答是，从模型架构到最优的物理布局之间是耦合的。这件事也让人害怕：新芯片还会不断出来，比如 Vera Rubin Ultra，它的功率密度和散热要求会完全不同。所以不能全部照一个规格去建，要“随着时间不断扩”，不要一次建完然后被卡住。这一点后面谈建设暂停时 Satya 又展开讲了。

02. AGI 时代的商业模式

节目位置 0:04:15–0:13:42 · Business models for AGI

“还在早期”

Dylan 开场先列了历次技术变革：铁路、互联网、可替换零件、工业化、云计算。每一次从技术被发现到在经济中普及的时间都更短。很多上过 Dwarkesh 节目的人认为这是最后一次技术革命，这次完全不同。仅看市场，三年时间超大规模云厂商（hyperscaler，指 Microsoft、Amazon、Google 这类自建超大数据中心的云公司）明年的 capex（资本支出，主要是建数据中心、买芯片的钱）就要到 5000 亿美元，速度以前没有过。他说 Satya 的说法和那种“AGI 要来了”的“AI bro”很不一样，想听他解释。

Satya 说他也有同样的兴奋，他的出发点是：这可能是工业革命之后最大的事。但他同时觉得现在还是早期。已经做出了很有用的东西，看到了很好的特性，scaling law（模型规模、数据和算力增加时能力按规律提升的经验规律）似乎还在起作用，他乐观地认为还会继续起作用。其中一部分需要真正的科学突破，但也有大量是工程问题。他还认为过去 70 年的计算发展本身也是一段一步步向前的进程。

他引用 CMU 的图灵奖得主 Raj Reddy 在 AGI 这个说法流行以前给 AI 的比喻：AI 应该是“守护天使”或者“认知放大器”。他说这是想清楚 AI 对人有什么用的简单方式，这样看它就是工具。也可以说得很玄，说它超过了工具，因为它在做以前只有人能做的事。但他说以前很多技术也是这样，原来只有人能做，后来有了工具来做。

“Satya token”的利润会流向哪里

Dwarkesh 换了个问法：不用纠结定义，也许五年、十年、二十年后，会有机器在产出“Satya token”，而 Microsoft 董事会认为 Satya token 很值钱。（Satya 插了一句：你们采访我浪费了多少经济价值？Dwarkesh 回：Satya token 的 API 费用我付不起。）他接着说，现在模型的价格是每百万 token 几美元甚至几美分，而一百万个“Satya token”值很多钱，中间有巨大的利润扩张空间。这些利润会流到哪里，Microsoft 能分到多少？

Satya 把问题拉回经济增长：经济增长、企业、生产率会是什么样子。他说工业革命扩散了 70 年之后才开始看到经济增长。即使这次技术扩散得快，要出现真正的经济增长，也要扩散到工作本身、工作产物（work artifact）和工作流程都改变的程度。所以企业真正转型所需要的变革管理不能低估。

主持人问，以后人和人产出的 token 会不会获得更高的杠杆，比如未来的“Dwarkesh token”和“Dylan token”。Satya 反问：没有技术，你们能把 SemiAnalysis 或这个播客做到现在的规模吗？绝不可能。所以问题是这个规模会到多大，会不会再被放大 10 倍。他认为肯定会，不管是营收数字还是受众数字。他的说法是：工业革命用了 70 年、可能 150 年的事，这次也许 20 年、25 年就会发生。他希望“运气好的话”能把工业革命 200 年发生的事压缩到 20 年里。

SaaS 公司遇到高 COGS

主持人接着问 Microsoft 的商业模式转型。Microsoft 以前卖 Windows 授权和光盘，后来卖 365 订阅，是最大的 SaaS（软件即服务，按订阅收费的软件）公司。SaaS 的特点是每多一个用户的增量成本极低，钱主要花在研发和获客上。他说 SaaS 公司（不包括 Microsoft）在股市上大幅跑输，原因是 AI 的 COGS（销货成本，这里指每次调用模型要付出的算力成本）太高，完全打破了原来的商业模式。现在 Copilot 收 20 美元一个月，Microsoft 要怎么过渡到一个 COGS 很重要、每用户增量成本不一样的时代？

Satya 说商业模式的杠杆还是那几种。从消费者到企业，菜单上有：广告单元、交易抽成、AI 设备的硬件毛利、消费者和企业订阅、按用量计费（consumption）。他认为这些“计量方式”都还在。订阅是什么？到目前为止大家喜欢订阅，是因为可以做预算；订阅相当于打包在里面的一定量的使用权。所以订阅包含多少用量，变成一个定价决策。他举编程订阅为例，现在就是这样分 pro 档、标准档等，定价和利润结构会这样分层。Microsoft 的好处是这些计量方式全都有：用量计费、订阅，以及其他消费者端的手段。哪种模式在哪个品类更合理，要时间来回答。

从服务器到云的经验：低 ARPU 反而扩大了市场

他接着谈 SaaS 这边他想得很多的一点。以 Microsoft 365 为例，他说 ARPU（每用户平均收入）低是好事。当年从服务器转向云的时候，他们内部担心：如果只是把原来用 Office 授权和 Office 服务器的同一批用户搬到云上，还要承担 COGS，不仅利润率会缩，公司整体也会变得不那么赚钱。实际发生的是云把市场扩大了很多。以前在印度卖不出几台服务器；上了云以后，印度的每个人都可以按需零碎地买服务器和 IT 资源。

他说当时他最没意识到的一点，是客户在 SharePoint 底下买存储花了多少钱。EMC 最大的业务板块可能就是给 SharePoint 用的存储服务器。上云之后这些都不用买了。那本来是营运资本，也就是现金流出。所以市场大幅扩张。他认为 AI 也会这样。编程就是例子：Microsoft 用几十年建起了 GitHub 和 VS Code，而编程助手一年就长到了这么大。

03. GitHub Copilot 与编程 Agent 的竞争

节目位置 0:13:42–0:20:56 · Copilot

Dylan 的营收图

主持人说市场会扩张，但碰到 Microsoft 的那部分收入会不会扩张？以 Copilot 为例：按 Dylan 的数据，今年早些时候 GitHub Copilot 的收入大约 5 亿美元，没有接近的竞争者；现在 Claude Code、Cursor 和 Copilot 收入差不多，都在 10 亿美元左右，Codex 在追赶，大约 7 到 8 亿美元。Microsoft 能触达这么多界面，它的 Copilot 类产品到底有什么优势？

Satya 说他很喜欢这张图。第一，Microsoft 还在最上面。第二，图上的公司都是最近四五年才成立的，他觉得这是最好的信号：有新的竞争者，有新的生存威胁。现在说“谁会干掉你”，答案是 Claude、Cursor，不是 Borland（上世纪 Microsoft 在开发工具上的老对手）。他说“谢天谢地”，这说明方向对。从无到这个规模，本身就是市场扩张，和云很像。他认为编程加 AI 很可能会是最大的品类之一，叫“软件工厂”品类，甚至可能比知识工作还大，他想保持开放的心态。

订阅数和 GitHub 的结构性机会

他承认会有激烈的竞争。上一季度财报中，Copilot 订阅从 2000 万涨到 2600 万（他说“我想是”）。他对订阅增长和方向感觉不错。更有意思的是：其他那些产生大量代码的公司，它们的代码仓库都放在哪里？都在 GitHub。GitHub 的仓库创建量、PR（pull request，代码合并请求）等各项指标都在历史最高。他说他们希望 GitHub 保持开放，不想把它和自己产品的增长混为一谈。他引用的数据是大约每秒有一名开发者加入 GitHub，其中 80% 会自然进入某种 GitHub Copilot 工作流；很多仓库还会用到默认开启的代码审查 Agent。他说这让 Microsoft 有很多次结构性的出手机会。

Agent HQ 和 Mission Control

他说他们要做的是延续 Git 那一套。GitHub 的基本组件从 Git 到 issues 到 actions，都围绕代码仓库，他们要把这一套扩展下去。上周 GitHub Universe 上发布了 Agent HQ 这个概念，其中有个东西叫 Mission Control。他有时把它说成“所有 AI Agent 的有线电视”：一个订阅里打包了 Codex、Claude、Cognition 的产品、Grok，任何人的 Agent。用户买一个套餐，就可以发任务、引导它们，各个 Agent 在各自独立的分支上工作，用户可以监控它们。

他认为这会是最大的创新点之一，因为现在人们想同时用多个 Agent，想消化多个 Agent 的输出，又想管住自己的仓库。需要一种“抬头显示”，让人能快速引导和分拣编程 Agent 生成的东西。VS Code、GitHub 加上 Mission Control 这类新组件和控制面（control plane）就是做这个的。还有可观测性：每一个部署这些东西的人，都需要知道哪个 Agent 在什么时间对哪个代码库做了什么。他说这是机会所在，同时也同意对方的观点，Microsoft 必须有竞争力、必须创新，否则会被推翻。

份额从过半跌到 25% 以下

Dylan 接着追问。他说要点是不管谁的编程 Agent 胜出，GitHub 都会继续增长，但那个市场每年只增长 10%、15%、20%，虽然远高于 GDP，是很好的复利业务。AI 编程 Agent 则从去年年底大约 5 亿美元的年化收入（run rate，按当前月或季度收入推算的年收入）涨到现在：GitHub Copilot、Claude Code、Cursor、Cognition、Windsurf、Replit、OpenAI Codex 加起来，今年 Q4 年化在 50 到 60 亿美元，涨了 10 倍。软件 Agent 的 TAM（总可寻址市场）是付给程序员的 2 万亿美元工资，还是更多，因为世界上每家公司都能开发更多软件？Microsoft 肯定会分一块，但份额在一年之内从接近 100%，至少远超 50%，跌到了 25% 以下。凭什么相信 Microsoft 会继续赢？

Satya 回答 Dylan 说，这里没有“与生俱来的权利”，唯一能有的信心就是去创新。他说 Microsoft 的幸运在于，这个品类会比以前他们占高份额的任何品类都大得多。他们在 VS Code、在 GitHub 仓库上占过很高份额，那是好市场；但在一个大得多的市场里占一个不错的份额更重要。他举了先例：Microsoft 在客户端/服务器时代的服务器计算上份额很高，在超大规模云上的份额低得多，但后者的业务大了几个数量级。这至少证明，只要所在市场在创造更多价值、并且有多个赢家，份额不如以前也没关系。他说他每个季度都盯着竞争力，因此对 Agent HQ 很乐观，要把 GitHub 变成所有 Agent 都来的地方，有很多次射门机会。有些对手可以和 Microsoft 一起成功，不一定只有一个赢家、一个订阅。

04. 谁的利润率涨得最多：模型层还是应用层

节目位置 0:20:56–0:37:12 · Whose margins will expand most?

Dwarkesh：脚手架会越来越不重要吗

Dwarkesh 说他追问这个，是因为问题不只关于 GitHub，也关于 Office 和 Microsoft 的其他软件。一种设想是模型会一直“残缺”，需要人一直盯着看。另一种设想是模型现在能做两分钟的任务，以后能做 10 分钟、30 分钟，再往后能自主做好几天的工作。那时模型公司可能每月收几千美元，卖的其实是一个同事，这个同事能用任何界面和人沟通、在不同平台之间迁移。如果越来越接近那个状态，为什么不是越来越赚钱的模型公司拿走全部利润？脚手架（scaffolding，指包在模型外面的工具、界面、流程代码）在 AI 越来越强时会越来越不重要，为什么它会那么重要？这就是现在的 Office 和只做知识工作的 AI 同事之间的对比。

Satya：模型可能变成商品

Satya 说价值是全部流向模型，还是在脚手架和模型之间分，要时间来回答。但他认为激励结构是清楚的。他举 GitHub Copilot 里他最喜欢的一个设置叫 auto：买了订阅以后，auto 会根据他要做的事自动挑选模型、做优化，甚至可以完全自主，在多个模型提供的 token 之间做套利来完成任务。照这个逻辑，商品化的会是模型。尤其有开源模型，可以拿一个 checkpoint（训练过程中保存下来的一版模型权重），用自己的一堆数据去训。他认为不管是 Cursor 还是 Microsoft，都会开始有自家的内部模型，然后把大部分任务交给它。

所以有一种说法是：如果你赢下了脚手架，也就是今天处理模型各种“残缺”和智能参差不齐（jaggedness）问题的那一层，你就会因为掌握了数据的流动性（他的原词是 liquidity of the data）而向下整合进模型。可用的 checkpoint 会多得是。他认为从结构上看，世界上总会有一个能力相当不错的开源模型，只要你有数据和脚手架就能用。他的说法是：如果你是模型公司，你可能有“赢家的诅咒”，做了所有艰难的工作和惊人的创新，但离被商品化只差一次复制。之后拥有用于 grounding（让模型依据可靠资料回答）和上下文工程的数据、又有数据流动性的人，就可以拿那个 checkpoint 去训练。他说两边的论证都能成立。

Dylan：Anthropic 的推理毛利率在涨

Dylan 把两种世界观摆出来。一种是模型很多、有开源，模型之间的差异会影响谁赢，但让你赢的是脚手架。另一种是模型才是核心 IP，大家在激烈竞赛，用户可以在 Anthropic 和 OpenAI 之间换。营收曲线能看出来：OpenAI 有了和 Anthropic 能力相近（虽然方式不同）的代码模型之后，收入才开始暴涨。还有一种观点是模型公司拿走全部利润：至少 Anthropic 今年的推理毛利率从远低于 40% 涨到年底 60% 以上。中国开源模型比以往任何时候都多，OpenAI、Google、X/Grok 也都有竞争力，尽管如此模型层的利润率还是大幅扩张了。他问 Satya 怎么看。

Excel Agent：放在中间层的模型

Satya 说几年前大家以为套个模型的壳就能做成一家成功公司，这个想法大概已经被戳破了，原因是模型能力的提升，尤其是工具使用能力。但他举了 Office 365 里的 Excel Agent。他说 Excel Agent 是放在 Office 系统中间层（middle tier）的模型，不在 UI 层。因为 Microsoft 有 GPT 系列的全部 IP，他们把它放进 Office 的核心中间层，教它原生地理解 Excel 及其中的一切：模型对 Excel 的所有原生对象有完整理解，光看像素不够。如果要它做推理任务，它得能改正自己的推理错误，就需要看到“这个公式写错了”并理解它。这些都是在中间层通过教会它 Excel 的所有工具来做的，没有停在 UI 层写个提示词。他说具体做法是给它一份 markdown，教它成为一个熟练 Excel 用户需要的技能。

他的结论是：传统意义上的 Excel 业务逻辑外面会包一层认知层，用的是一个会用这个工具的模型。Excel 以后会自带一个分析师，并带着所有工具使用能力。每家都会做这种东西，所以模型公司也得竞争：如果它们定价太高，像他这样做工具的人就会换掉它们，可能先用一阵子。他说如果有一个模型以巨大差距领先所有人，那会赢家通吃；但只要有多个模型竞争，就像超大规模云之间的竞争一样，再加上开源作为制衡，就有足够空间在模型之上创造价值。

Microsoft 的三层布局

他说 Microsoft 会做支持多种模型的超大规模云业务；还有七年使用 OpenAI 模型的权利，会在其上创新，相当于手上有一个可以完全灵活使用、继续创新的前沿级模型；同时会用 MAI 做自己的模型，所以总会有模型层。然后在安全、知识工作、编程、科学这些领域做自己的应用脚手架，这些应用是 model-forward 的：模型被包进应用里，他说应用不会只是模型外面的一层壳。

Dwarkesh：未来的 AI 会像人一样用电脑

Dwarkesh 说他还是怀疑这种设想没有向前看，是按今天的模型在想：现在的模型截个屏，但看不到每个单元格里的公式是什么。他认为更好的心智模型是：模型会像人一样会用电脑。一个用 Excel 的知识工作者可以看公式、可以用别的软件、需要时可以把数据在 Office 365 和别的软件之间迁移。如果是这样，和 Excel 的集成就没那么重要了。

Satya 说不用担心 Excel 集成。Excel 本来就是给分析师用的工具，那么这个作为分析师的 AI 也应该有它能用的工具。它有电脑，就像人能用电脑一样，电脑就是它的工具。他说他在做的分析师其实就是一个 AI Agent，它恰好预先就知道怎么用所有这些分析工具。Dwarkesh 想确认这是不是一个像他这样的人在用 Excel 时的助手，Satya 说不是，是完全自主的。

两种未来的公司，以及“按 Agent 收费”

Satya 接着描述他认为未来公司的样子。第一种世界是工具业务：他有一台电脑，用 Excel，以后还会有 Copilot，Copilot 底下还有 Agent，但仍然是他在掌控一切，结果都回到他这里。第二种世界是公司直接给一个 AI Agent 配一份计算资源，让它完全自主工作。这个完全自主的 Agent 也会有一套内嵌的同样的工具，光有一台裸电脑不够，因为用工具完成任务更省 token。他认为 Microsoft 今天的业务是面向终端用户的工具业务，以后会变成支持 Agent 干活的基础设施业务。M365 底下建的那些东西仍然很有用：即使是 AI Agent，也需要地方存储、归档、做 discovery（法律意义上的电子取证检索），需要地方管理所有这些活动。

Dwarkesh 确认：理论上一个有真正电脑使用能力的未来 AI，即使不和 Microsoft 合作，也能用 Microsoft 的软件；但如果在 Microsoft 的基础设施上工作，Microsoft 会给它更底层的访问权限，让它做同样的事更高效？Satya 说百分之百。他类比的是：先有服务器，然后有了虚拟化，然后服务器反而多了很多。不要把工具看作终点，要看人类所用工具底下的整个底座，这个底座也是 AI Agent 的起点，因为 AI Agent 需要一台电脑。

他说一个增长很快的信号是：那些用自主 Agent 生成 Office 文档的公司，想给这些 Agent 开通 Windows 365，想给 Agent 配一台电脑。所以 Microsoft 会有一个终端用户计算基础设施业务，增长会比用户数快。很多人问他按用户收费的业务会怎样，他说早期迹象显示应该把它看成“按用户，也按 Agent”。关键是每个 Agent 要配什么：一台电脑、一套安全措施、一个身份、可观测性等管理层，这些都会打包进去。

Dylan：模型会把人从 Office 迁出去吗

Dylan 提出他的看法：模型公司都在搭环境（environment，强化学习里让模型反复练习的模拟任务场景），训练模型用 Excel、在 Amazon 购物、订机票。同时它们也在训练模型做迁移，因为这可能是最能马上产生价值的：把大型机系统迁到标准云系统，把 Excel 里的“数据库”变成真正的 SQL 数据库，把 Word 和 Excel 里做的事变成更程序化、在传统意义上更高效的东西。这些事人也能做，只是让软件开发者去做不划算。他认为未来几年大家都会用 AI 做这个来创造价值。那么如果模型能自己用工具迁移出去，Microsoft 在哪里？Microsoft 在数据库、存储等领域是领先的，但 Office 生态的使用会少很多，就像大型机生态的使用可能变少。不过他也补充，大型机其实过去二十年一直在增长，只是没人再谈。

Satya 同意大型机这一点。他说会有很长一段时间是混合世界：人在用工具，这些工具要和必须用工具的 Agent 一起工作，彼此要沟通；生成什么产物给人看，输入输出都是现实的考虑，不会只是“我迁走了”。但他承认这没有完全回答问题，因为可能出现一个新的高效边界，只有 Agent 和 Agent 打交道、完全优化。即使那样，需要什么基础组件？要不要存储系统？存储系统要不要电子取证？要不要可观测性？要不要一个身份系统，让多个模型共用同一套身份？这些都是今天 Office 系统底下的核心底层轨道，将来也会有。

谈到数据库，他说他很希望整个 Excel 都有数据库后端，而且希望马上实现，并且是个好数据库。他认为数据库会大幅增长：Office 文档结构化得更好，结构化和非结构化数据之间的 join 做得更好，这些会让底层基础设施业务增长，只是消耗它的是 Agent。他也承认，可以说这一切都是模型公司即时生成的软件，这也可能成立；Microsoft 自己也会是一家这样的模型公司，竞争可能变成几家既有模型又有全套基础设施并能自行部署的公司之间的竞争。

05. MAI：Microsoft 自己的模型

节目位置 0:37:12–0:48:42 · MAI

为什么排在 Chatbot Arena 第 36

主持人说，Microsoft AI 两个月前发布的最新模型在 Chatbot Arena（众包盲评打分的模型排行榜，即后文的 LMArena）上排第 36。Microsoft 明明有 OpenAI 的 IP 权利，理论上可以 fork OpenAI 的代码库（monorepo）或蒸馏（distill，用大模型的输出训练小模型）它们的模型，而且有一家领先的模型公司又是 Microsoft 战略的重要部分，为什么还落后？

Satya 说，首先他们会在所有产品里最大限度地使用 OpenAI 模型，未来七年都会这样做，除了用，还会在上面增加价值。前面说的分析师和 Excel Agent 就是例子，他们会做 RL 微调（用强化学习针对具体任务继续训练），会在 GPT 系列之上做一些 mid-training（介于预训练和后训练之间、用特定数据继续训练的阶段），用 Microsoft 独有的数据资产构建能力。

至于 MAI，新协议的好处是 Microsoft 可以很明确地组建一个世界级的超级智能团队，带着很高的雄心去做。同时他们也要聪明地同时用好两样东西：一头高度聚焦产品，另一头高度聚焦研究。因为能用 GPT 系列，他最不想做的就是把自己的算力用在重复、没多少增量价值的事情上。他想让生成 GPT 系列所用的那部分算力价值最大化，而 MAI 的算力用在别的地方。

图像、语音、文本模型，下一站 omni 模型

他举了几个 MAI 的模型。图像模型他说大概在 image arena 排第九，既用于降低成本，也上线在 Copilot 和 Bing 里。Copilot 里还有一个音频模型，有个性，是为他们的产品优化的。文本模型在 LMArena 上首次亮相时排在第 13 左右，而且只用了大约 15,000 块 H100 训练，是个很小的模型，目的是验证核心能力、指令遵循等，确认他们能做到当时的最好水平。他说这让他们知道，按 scaling law，如果给更多算力能做到什么。下一步是做一个 omni 模型，把音频、图像、文本三方面的工作合起来，这是 MAI 的下一个“进站”。

他总结 MAI 的路线图：组建一流的超级智能团队；继续公开发布一些模型，这些模型要么因为延迟低、成本低等原因用在自家产品里，要么具备某种特殊能力；同时做真正的研究，为通往超级智能路上还需要的“五个、六个、七个、八个突破”做准备，同时利用好可以在 GPT 系列之上开发的优势。

七年之后怎么办：人才战

主持人问：假设七年后不再能用 OpenAI 模型，Microsoft 怎么保证自己有领先的 AI 实验室？今天 OpenAI 做出了 scaling、reasoning 等很多突破，Google 做出了 transformer 这样的突破。这也是一场人才游戏：Meta 在人才上花了超过 200 亿美元；Anthropic 去年把 Google 整个 Blueshift 推理团队挖走了；最近 Meta 又从 Google 挖走了一大批推理和后训练团队。这种人才战很烧钱。按理说如果在基础设施上花 1000 亿美元，也应该花相应的钱在使用这些基础设施的人身上。Microsoft 现在比较节省资本，不做重复工作，看起来是明智的；但一旦决定打开钱的水龙头，凭什么说能冲进前五？

Satya 说他们会建一支世界级团队，而且已经开始组建：有 Mustafa（Mustafa Suleyman），有 Karen，有在 Gemini 2.5 做了大量后训练工作的 Amar Subramanya，有在 DeepMind 做了大量多媒体工作的 Nando。他说这周晚些时候 Mustafa 会发布一些内容，说清楚他们的实验室要做什么。

他希望外界知道的是：第一，Microsoft 会建支持多种模型的基础设施。从超大规模云的角度，他们要建规模最大的算力集群，能支持世界需要的所有模型，不管是开源的、OpenAI 的还是其他家的。第二，在自家模型能力上，他们会在产品里用 OpenAI 模型，同时开始做自己的模型；还可能像 GitHub Copilot 里用 Anthropic 那样，把其他前沿模型也包进自家产品。他说最终重要的是产品面对具体任务时的评测结果，从那里倒推需要多少垂直整合；只要产品服务好了市场，成本总能再优化。

持续学习会不会让领先模型通吃

Dwarkesh 提出他的核心担忧。现在的模型在训练和推理之间有明确区分，而且不同模型之间的差距越来越小。但如果期待的是接近人类水平的智能，人是在工作中学习的。Satya token 为什么值钱？是因为他在 Microsoft 积累了 30 年的智慧和经验。如果模型达到人类水平，就会有在工作中持续学习（continual learning，模型部署后还能从新经验中不断学习）的能力。他认为这会给领先的模型公司带来巨大价值，因为同一个模型的许多副本部署在整个经济中，学习做每一种工作，而且和人不同，它们可以把学到的东西合并回那个模型。这是一个持续学习的指数反馈循环，几乎像一种智能爆炸。如果这件事发生时 Microsoft 不是领先的模型公司，那么“换一个模型”的说法是不是就没那么重要了？因为这一个模型会做经济里的每一种工作，长尾里的其他模型不会。

Satya 说，如果有一个模型是全世界唯一部署最广的模型，看到所有数据、做持续学习，那就是“game set match”，大家可以收摊。但他看到的现实是，无论今天哪个模型多强势，都没有出现这种情况。以编程为例，有多个模型，而且一天比一天更不是单一模型被广泛部署。他拿数据库类比：总有人问能不能有一个数据库在所有地方通用，结果没有，不同用途部署着不同类型的数据库。

他承认持续学习会有一些网络效应，他把它叫数据流动性（data liquidity）。但它会在所有领域发生吗？他认为不会。在所有地区？不会。在所有细分市场？不会。在所有品类同时发生？不会。所以设计空间很大，机会很多。

不能把基础设施只为一个模型优化

他接着说，主持人的基本观点是要在基础设施层、模型层、脚手架层都有能力，并且能为各自的目的去组合它们，不限于一个垂直堆栈。你不能建一个只为一个模型优化的基础设施，否则落后了怎么办，建的东西全都浪费。要建能支持多个模型家族和谱系的基础设施。否则资本投下去只为一种模型架构优化，你离出问题只差一次调整，比如出现一个类似 MoE（混合专家模型，每次只激活一部分参数的架构）的突破，整个网络拓扑就作废了，这很可怕。所以基础设施要支持自家模型家族可能出现的任何变化，也要支持其他模型家族，要开放。认真做超大规模云业务就必须认真对待这一点。

反过来，如果认真做模型公司，就要想别人怎样在你的模型之上做事，让你有 ISV（独立软件开发商）生态。除非你觉得自己能拥有每个品类，但那不可能，那样就不会有 API 业务，按定义就永远成不了在各处成功部署的平台公司。所以他认为产业结构会逼着大家专业化。在专业化之中，像 Microsoft 这样的公司应该在每一层凭本事竞争，不要以为这是一条“game set match”之路、自己只要把所有层垂直组合起来就行，他说那不会发生。

06. 超大规模云业务与 2024 年的建设暂停

节目位置 0:48:42–1:03:39 · The hyperscale business

Dylan：为什么放弃了一批站点

Dylan 说，去年 Microsoft 本来有望成为遥遥领先的最大基础设施提供商。2023 年 Microsoft 出手最早，租数据中心、开工建设、锁定电力，什么都做了，按势头会在 2026 或 2027 年超过 Amazon，最晚 2028 年。之后大约在去年下半年，Microsoft 做了一次大暂停，放掉了一批本来要租的站点，这些站点后来被 Google、Meta、有时是 Amazon、还有 Oracle 拿走了。他说他们现在就坐在世界最大的数据中心之一里，显然 Microsoft 还在疯狂扩张，但有些站点确实停了，为什么？

Satya：集群要可互换，不想只给一家当托管商

Satya 说这要回到超大规模云业务是什么。他们的一个关键决定是：如果要让 Azure 在 AI 的所有阶段都出色，从训练到 mid-training、数据生成、推理，就需要集群的可互换性（fungibility of the fleet）。这导致他们没有用某几代特定的硬件去建大量容量。另外，他们到目前为止每 18 个月就把给 OpenAI 各代模型用的训练容量提高 10 倍，他们意识到关键是保持这条路径；但更重要的是平衡，不只训练，还要能在全世界提供这些模型的服务。因为说到底，变现速度决定了能不能持续投入。基础设施还要支持多种模型。认识到这一点以后，他们就修正到了现在这条路径上。

他说现在的路径是：开工的项目多了很多，同时尽可能多地买入可托管的容量，自建、租赁，甚至是 GPU 即服务都要；但都是按他们看到的需求、服务需要和训练需要来建。他们不想只给一家公司当托管商，背上一家客户的巨大订单。他说那不算一门生意，那样的话应该和那家公司垂直整合。既然 OpenAI 会是一家成功的独立公司，这很好，也说得通。他还说，即使 Meta 会用第三方容量，最终它们也都会是自有容量；任何规模足够大的公司自己都会成为一个 hyperscaler。所以 Microsoft 的调整就是：建超大规模云集群和自己的研究算力。他说自己对此感觉很好。

另一个原因是他不想被困在某一代硬件的巨大规模上。刚看到了 GB200，GB300 也快来了。到 Vera Rubin、Vera Rubin Ultra 的时候，数据中心会很不一样，因为每机柜功率、每排功率会很不一样，散热要求也会很不一样。所以他不想一口气建好几个 GW 只能给一代、一个家族用的容量。他说节奏很重要，可互换性和位置很重要，负载多样性和客户多样性也很重要，这是他们在建的方向。

长尾负载和裸金属

他们学到的另一点是：每个 AI 负载除了 AI 加速器，还需要很多其他东西，而 Microsoft 的很多利润结构会在这些其他东西上。所以他们要让 Azure 适合长尾负载，这才是超大规模云业务；同时也知道最高端的训练必须从裸金属（bare metal，直接租整机硬件、不带上层云服务）开始就极有竞争力。但这不能挤掉其他业务，因为 Microsoft 不做“和五个客户签五份合同、给它们当裸金属服务商”的生意。他说那可能是别人的生意，这也挺好。Microsoft 说的是：超大规模云业务说到底是 AI 负载的长尾生意，为此他们会为一部分模型（包括自家模型）提供领先的裸金属即服务能力。他说这就是外界看到的平衡。

任务越来越长，位置还重要吗

主持人接着问可互换性的另一面：数据中心选址，比如在 Atlanta 这样好的人口中心。但随着 AI 任务时间变长，推理提示 30 秒、深度研究 30 分钟、以后软件 Agent 要几小时甚至几天，离人发生交互的时间越来越长，A、B、C 哪个位置还有什么关系？

Satya 说这就是他们思考 Azure region（云服务的地区）是什么样、region 之间网络怎么连的原因之一。随着模型能力演进、token 的使用方式变化（同步还是异步），不能站错位置。还有数据驻留法律。欧盟那边，他们专门建了 EU Data Boundary（欧盟数据边界），意味着即使是异步调用，也不能随便把请求发到任意地方再回来。所以可能需要地区级的高密度设施，再考虑电力成本等。他同意随着建设推进拓扑必须演进：一是每美元每瓦能产出多少 token，经济账怎么算；叠加使用模式，同步还是异步；还有计算和存储的关系，有些场景延迟很重要，存储必须在旁边，比如给会话数据或自主任务用的 Cosmos DB 也得靠近。这些都会塑造超大规模云业务。

Dylan：12–13 GW 变成 9.5 GW，Oracle 将超过你

Dylan 给出 SemiAnalysis 的估算：暂停之前，他们预测 Microsoft 到 2028 年会有 12 到 13 GW，现在大约是 9.5 GW。他说更相关的是，Oracle 会从 Microsoft 体量的五分之一，到 2027 年底变得比 Microsoft 还大。虽然 Oracle 的投入资本回报率达不到 Microsoft 的水平，但它仍有 35% 的毛利率。他的问题是：也许这不是 Microsoft 的生意，但 Microsoft 拒绝了这块业务、放弃了优先购买权（right of first refusal，对方先给你选择权，你不要才能给别人），等于亲手造出了一个新的 hyperscaler。

Satya 说他不想贬低 Oracle 建立业务的成功，祝它好。他认为自己已经回答了：给一家模型公司当托管商、背的是期限有限的 RPO（剩余履约义务，已签合同但尚未确认的收入），对 Microsoft 不合理。他说要想的是未来 50 年做什么，未来五年只是其中一段。他们做了自己的决定，对与 OpenAI 的合作感觉很好，手上有不错的订单，祝 OpenAI 成功。他还说 Microsoft 本身也在买 Oracle 的容量。他说他会跟踪 SemiAnalysis 关于 AWS、Google 和 Microsoft 的那些数据，很有用，但这不代表他必须追；追的标准除了某段时间内的毛利率，更看哪块业务是 Microsoft 独有能力去承接、承接下来也合理的。

Dwarkesh：为什么平台不是 OpenAI 们

Dwarkesh 退一步问：他同意在其他条件相同时，服务一条高利润的长尾客户比给少数实验室提供裸金属更好。但产业会怎么演化？如果 AI 越来越聪明，为什么产业的形态不会是 OpenAI、Anthropic、DeepMind 成为平台，长尾企业在它们上面做生意？它们需要裸金属，但它们是平台。那直接用 Azure 的长尾是什么？

Satya 说用户想用通用的认知核心（cognitive core），但这些模型都会在 Azure 上。如果一个负载要用某个开源模型加一个 OpenAI 模型，今天去 Azure Foundry 就能开通这些模型，买 PTU（预置吞吐量单位，预留的模型推理容量），再拿一个 Cosmos DB、一个 SQL DB、一些存储、一些计算。他说真实的负载就是这样，一次 API 调用远远不够；要做一个应用，需要所有这些东西。模型公司自己要做任何东西也需要这些，不是“我有个 token 工厂”就够了。这就是超大规模云业务，而且不押在任何一个模型上，所有模型都在。想用 Grok 加 OpenAI 加一个开源模型，就来 Azure Foundry 开通、做应用，这里有数据库。另有一块独立的业务是把裸金属服务直接卖给模型公司，问题在于要做多少、不做多少。那是很不一样的细分业务，Microsoft 也在做，但会限制它挤占其他业务的程度。

少了的 3.5 GW 本来可以自己用

Dylan 提了两个问题：一是为什么不能两种都做；二是按他们的估算，Microsoft 2028 年的容量少了 3.5 GW，这部分本可以给 OpenAI 训练和推理，也可以用来跑 Azure、Microsoft 365、GitHub Copilot。Satya 说他本可以建了不给 OpenAI，或者想建在别的地方，比如 UAE、印度、欧洲。他说现在真正的容量约束在于，考虑到监管和数据主权需求，必须在全世界建。美国本土容量很重要，他们也想全都建；但看 2030 年，他有一个全球视角：Microsoft 的业务按第一方（自用）和第三方怎么分，第三方里前沿实验室要多少，和他们想为多模型建的推理容量相比是多少，再加上自家研究算力的需要，这些都在他的计算里。

他说暂停的原因不在“我们不想建了”。他们意识到想建的东西要在负载类型、地理位置和时间上稍有不同。他们会继续增加 GW，问题是节奏和地点。还要考虑怎么“骑着 Moore's law 走”：是 2027 年一下子多建 3.5 GW，还是分摊到 2027–28 年。

黄仁勋给的建议：光速执行

他说一个很大的教训来自 Nvidia：Nvidia 的换代节奏加快了，这是很大的因素。他不想被一代硬件四五年的折旧困住。他说黄仁勋 Jensen Huang 给他的建议有两条，第一条是做到“光速执行”（speed-of-light execution）。他说 Atlanta 这个数据中心从拿到到交付给真实负载大约 90 天，这就是光速执行，他想把这件事做好。这样每一代都按节奏扩，每五年就会有一个均衡得多的集群。（字幕里只听到第一条，第二条没有单独讲出来。）

他说这对一个大规模工业运营来说就像一条流水：不会一下子在某个时间建很多，然后因为被困住而长期停滞，而且困在一个地点，那个地点也许适合训练，但不一定适合推理。比如即使全是异步任务，欧洲也不允许他把请求送到 Texas 再回来。

为什么又向 neocloud 租容量

Dylan 问：这和过去几周的动作怎么对得上？Microsoft 宣布了和 Iris Energy、Nebius、Lambda Labs 的合作，还有几家要宣布，是在向 neocloud（新兴的专做 GPU 租赁的云公司）租容量，而不是自己建。Satya 说这没问题：现在对需求有了清楚的可见度，而且可以在别人建好的地方提供服务，这很好。他们会接受租赁、定制建造（build-to-suit），在自己没容量但需要容量而别人有时，甚至接受 GPU 即服务。他说他甚至欢迎每家 neocloud 都加入 Azure 的市场：如果它们把容量带进 Azure 市场，通过 Azure 来的客户会用 neocloud 的算力，这对它们是大好事，同时会用 Azure 的计算、存储、数据库和其他服务。他说他完全没想着“我应该把这些全吞下来”。

07. 自研芯片与 OpenAI 合作协议

节目位置 1:03:39–1:10:30 · In-house chip & OpenAI partnership

Dylan：Microsoft 的自研芯片订单远低于 Google 和 Amazon

Dylan 说，这种五六年折旧的资产占数据中心 TCO（总拥有成本）的 75%，而 Jensen 在上面拿 75% 的利润率。所以所有 hyperscaler 都在做自己的加速器，想降低这块压倒性的设备成本、提高利润率。看进度，Google 遥遥领先，做得最久，他们会生产大约 500 万到 700 万颗自家 TPU（Google 自研的 AI 芯片）；Amazon 在争取 300 万到 500 万颗（字幕标注为生命周期出货量）。但 Microsoft 订的自家芯片远低于这个数，而 Microsoft 的项目做的时间一样长，问题出在哪？

Satya：最大的对手是上一代 Nvidia

Satya 说有几点。第一，任何新加速器最大的竞争对手其实是上一代 Nvidia。在一个集群里他看的是整体 TCO。他说刚看了 Maia 200 的数据，看起来很好。但他们在通用计算上学到过：先有大量 Intel，然后引入 AMD，再引入自研的 Cobalt，就是这样扩起来的；至少在核心计算上，他们有现成的证据知道怎么做自研芯片，并管理一个三者按某种比例并存的集群。他说 Google 和 Amazon 也都在买 Nvidia，这说得通，因为 Nvidia 在创新，是通用的东西，所有模型都能在上面跑，客户需求也在那里。

如果做自己的垂直芯片，就最好有自己的模型，要么用它训练、要么用它推理，还得自己创造需求或补贴需求。所以要按合适的规模扩。Microsoft 的做法是让 MAI 模型和自研芯片形成闭环，他认为这才给了做自研芯片的“与生俱来的权利”：微架构是根据自己在做的事设计的，再和自己的模型保持同步。

OpenAI 的芯片项目，Microsoft 能拿到全部 IP

他说好消息是 OpenAI 有一个芯片项目，Microsoft 有访问权。主持人问访问到什么程度，他说全部。主持人确认：所以唯一没有的 IP 是消费级硬件？他说就是这样。他补充说 Microsoft 也给了 OpenAI 很多 IP 来帮它起步，因为超级计算机是两家一起建的，是 Microsoft 为 OpenAI 建的，OpenAI 从中受益，这理所应当。现在 OpenAI 创新，哪怕是系统层面的，Microsoft 也能全部拿到；他们先为 OpenAI 实现 OpenAI 设计的东西，然后再扩展。

他总结：Microsoft 想做 Nvidia 最好的“光速执行”合作伙伴，因为坦白说那个集群就是命根子（原话 that fleet is life itself）。他说 Jensen 的利润率显然很好，但 TCO 有很多维度，他想在 TCO 上做得出色。在此之上，他想同时用好 OpenAI 谱系和 MAI 谱系以及系统设计，因为两头的 IP 权利他们都有。

“无状态 API”到底指什么

主持人提到 Satya 几天前的一次采访，他说在和 OpenAI 的新协议里，Microsoft 拥有 OpenAI 无状态（stateless，每次调用都独立、服务端不保存会话）API 调用的独家权利。他们没搞懂有没有任何状态：Satya 刚说复杂负载都需要记忆、数据库、存储，如果 ChatGPT 在会话里存东西，那还算无状态吗？

Satya 说原因就在这里。他们做的战略决定，同时也是为了照顾 OpenAI 采购算力所需要的灵活性：可以把 OpenAI 看成有一块 PaaS（平台即服务）业务和一块 SaaS 业务。SaaS 业务是 ChatGPT，PaaS 业务是它的 API。API 是 Azure 独家的，SaaS 业务可以在任何地方跑。主持人问，OpenAI 可以和任何人合作做 SaaS 产品吗？Satya 说如果它要找合作方，而合作方想用无状态 API，那 Azure 就是获取无状态 API 的地方。主持人追问：如果两家一起做产品，而且是有状态的呢？Satya 说那也得来 Azure。他说这是本着“我们在这段合作里看重什么”的精神做的，同时也确保在 OpenAI 需要的灵活性上做了好伙伴。

主持人举例：Salesforce 想集成 OpenAI，不走 API，两家一起训练一个模型，然后部署在比如 Amazon 上，这允许吗？Satya 说任何这类定制协议都得来 Azure 运行。他们留了少数例外，比如美国政府等，除此之外都要来 Azure。

08. capex 暴涨：从软件公司到资本密集型公司

节目位置 1:10:30–1:16:01 · The CAPEX explosion

自由现金流会归零吗

Dwarkesh 说在参观工厂时，Satya 提到 Microsoft 可以看作软件公司，但现在其实在变成工业公司，有大量 capex 和工程建设。过去两年 Microsoft 的 capex 差不多翻了三倍，往前外推就是巨大的工业爆发。其他 hyperscaler 在借贷，Meta 在 Louisiana 做了一笔 200 亿美元的贷款，还做了公司层面的贷款。看起来每家的自由现金流都在趋向零。他开玩笑说如果 Satya 也想这么做，Amy（Microsoft CFO Amy Hood）肯定会骂他，然后问到底在发生什么。

资本密集，也知识密集

Satya 说结构性变化确实很大。他的说法是 Microsoft 现在既是资本密集型业务，也是知识密集型业务，而且要用知识来提高资本支出的 ROIC（投入资本回报率）。他说硬件公司把 Moore's law 营销得很好，这很了不起；但看他在财报电话会上给的一些数据，对于给定的 GPT 家族，软件优化带来的吞吐量提升，以每美元每瓦的 token 数计，季度环比、年同比都很大，是 5 倍、10 倍，某些情况下也许 40 倍，靠的是优化方法。他说这就是知识密集带来资本效率，是他们必须掌握的。

有人问他传统托管商和 hyperscaler 有什么区别，他的回答是软件。确实资本密集，但只要有系统层面的诀窍、能按负载和按集群做优化的软件能力就行。他说讲可互换性的时候，里面有大量软件，除了集群本身，还包括能驱逐一个负载再调度另一个负载，能不能把这套调度算法管好，这些要做到世界级。所以他认为 Microsoft 仍然是软件公司，但这是一门不同的生意，他们会管好。说到底，Microsoft 的现金流让两条手臂都能运转。

如果 AGI 是 2040 年而不是三年后

Dwarkesh 说，看起来 Satya 短期内更相信事情需要一段时间、进展更参差；但长期也许认为谈 AGI 和 ASI（超级人工智能）的人是对的，Sam（Sam Altman）终究会对。所以一个更大的问题是：hyperscaler 要大量投资一种五年折旧的东西，如果你认为 Sam 预期三年内会出现的东西要到 2040 年才来，那么合理的做法是什么？

Satya 说需要拨出一块研究算力，像做 R&D 一样做，坦白说这也是最好的记账方式，就把它当研发费用。然后问研究算力要多少、怎么扩。比如说在某个时间段内扩一个数量级，两年还是 16 个月，自己选。这是一块，是入场券，是研发支出。其余的全部由需求驱动。最终可以领先需求去建，但需求计划不能完全跑偏。

实验室的营收预测可信吗

主持人问他信不信那些实验室的预测：它们预测 2027–28 年营收 1000 亿美元，并且每年继续以 3 倍、2 倍的速度增长。Satya 说现在市场里有各种激励，这也正常。一家要融资的独立实验室能怎么做？它们必须拿出一些数字去融资，才能付算力账单。他说这是好事，总有人要承担风险，而且它们已经展示了牵引力，不是在没看到业绩的情况下冒险，不管是 OpenAI 还是 Anthropic。他对它们做的事感觉很好，Microsoft 和它们有大量订单。

他说归根到底有两件简单的事。一是要为研发拨款。人才方面，AI 人才很贵，必须花钱；算力上也必须花钱。所以研究员和 GPU 的比例要高，这是在这个世界里成为领先研发公司所需要的；这部分要扩，而且要有能支撑在它成为共识之前很久就去扩的资产负债表。二是要懂得预测需求。

09. 世界会信任美国公司来引领 AI 吗

节目位置 1:16:01–1:28:41 · Will the world trust US companies to lead AI?

从单极到双极

主持人说，美国主导过很多技术栈。美国通过 Microsoft 拥有 Windows，连在中国它也是主要的个人电脑操作系统（当然还有开源的 Linux）；Word 到处都在用，很多技术都部署在全世界。Microsoft 等公司也在欧洲、印度、东南亚、拉美、非洲建数据中心。但现在不一样：技术和算力有了政治属性。美国政府当年不关心互联网泡沫，现在美国政府和全世界其他政府都很关心 AI。世界至少在美中之间是双极的，欧洲、印度等国家又说“我们也要有主权 AI”。90 年代只有一个国家重要，就是美国，美国公司卖遍全球、Microsoft 大受其益；现在在双极世界里，Microsoft 不一定有权赢下整个欧洲、印度或新加坡，那里有真正的主权 AI 项目。Microsoft 怎么应对？

4% 人口、25% GDP、50% 市值

Satya 说这一点很要紧。他认为美国科技行业和美国政府的头号优先事项，是不仅要做领先的创新工作，还要共同在全世界建立对美国技术栈的信任。他说美国是一个历史上独一无二的地方：占世界人口 4%、GDP 的 25%、市值的 50%。他建议大家想想这几个比例。那 50% 之所以存在，是因为世界对美国的信任，不管是对资本市场，还是对它的技术以及在每个时期对领先产业的管理。如果这份信任破裂，对美国不是好事。

他说特朗普总统、白宫、David Sacks 都明白这一点。所以他赞赏美国政府和科技行业一起做的任何事情，比如作为一个行业，把自己的资本投到世界各地去冒险。他希望美国政府把美国公司在全世界的对外直接投资算作自己的功劳。他说这是最少被谈到、却是美国最该做的宣传：除了外国直接投资流入美国，还有最领先的产业，也就是这些 AI 工厂，正在全世界被建起来，由美国和美国公司建。在此基础上再围绕对方的连续性、正当的主权关切签其他协议，包括数据驻留，让对方在隐私上有真正的自主权和保障。

欧洲承诺和主权云

他说 Microsoft 对欧洲的承诺值得一读：他们做了一系列承诺，规定怎样治理在欧洲的超大规模云投资，让欧盟和欧洲各国拥有主权。他们在法国和德国建主权云。Azure 上还有一项叫 Sovereign Services 的服务，提供密钥管理服务和机密计算（confidential computing，在硬件隔离的加密环境中处理数据，连云厂商也看不到），包括 GPU 上的机密计算，这方面他们和 Nvidia 一起做了创新工作。他说对通过技术和政策两方面建立对美国技术栈的信任，他感觉很好。

会像半导体和 TSMC 那样吗

Dwarkesh 问：如果模型层有持续学习的网络效应，hyperscaler 层也许也有类似效应，各国会说“很明显一两个模型最好，我们就用它们，但立法要求权重必须托管在本国”，还是会推动必须用本国训练的模型？他类比半导体：半导体对经济很重要，大家都想要主权半导体，但 TSMC 就是更好，半导体又太重要，所以大家只能去台湾买。AI 会这样吗？

Satya 说最终重要的是 AI 在各国经济里的使用能创造经济价值。这是扩散理论：重要的是能用领先技术形成自己的比较优势，拥有领先产业本身没那么要紧。他认为这会是核心驱动力。但各国也会想要连续性。所以他认为总会有一种制衡，防止“一个模型失控式地被全面部署”，这就是开源会一直存在的原因。按定义会有多个模型。这是各国要求连续性、避免集中风险的一种方式：我要多个模型，还要一个开源模型。他认为只要这些存在，每个国家都会觉得不用担心部署最好的模型并广泛扩散，因为随时可以把自己的数据和流动性搬到另一个模型，开源的、别国的都可以。他说集中风险和主权（他说主权其实就是自主权）这两件事会决定市场结构。

Dylan：“主权有点像骗局”

Dylan 说这在半导体上并不存在。所有冰箱、汽车里都有台湾造的芯片，到现在都是这样。如果台湾被切断，就没有车、没有冰箱了。TSMC Arizona 替代不了任何实质比例的产能。他说主权有点像骗局，有它是值得的、重要的，但那不是真正的主权，我们是全球经济。

Satya 不同意。他说这等于说“到现在我们还没学到韧性意味着什么、需要做什么”。任何国家，包括美国，现在都会尽其所能在一些关键供应链上更自给自足。所以作为跨国公司，他必须把这当作头等要求，否则就是不尊重那个国家长期的政策利益。他不是说各国短期内不会做务实的决定，全球化不可能倒带，这些资本投资也不可能按某种速度一下子完成。但他说，如果有人到华盛顿说“我们不建任何半导体工厂”，会被赶出美国，其他国家也一样。所以公司要尊重学到的教训，不管是疫情把大家叫醒了还是别的什么。大家在说：全球化很棒，让供应链全球化、效率极高，但还有一样东西叫韧性，我们要韧性。所以这个特性会被建起来，问题是速度，这是 Dylan 说的点。不可能一打响指所有 TSMC 工厂连同全部能力都在 Arizona，不会的。但有没有计划？会有。应不应该尊重？当然。他说他想按世界现在的样子和它将来想做的事去对接，不想说“我们有一个不尊重你观点的立场”。

Microsoft 是否“特别占优”

Dwarkesh 确认：意思是每个国家都会要某种数据驻留、隐私等，而 Microsoft 和这些国家有关系，有建主权数据中心的经验，所以特别适合主权要求更多的世界？Satya 说他不想说成 Microsoft 特别占优，他会说这是一项业务要求，Microsoft 几十年来一直在做这些苦功，以后也会继续。他说他对 Dylan 前一个问题的回答是：不管是在美国，白宫和美国政府说“希望你们把更多晶圆投片分配给美国的晶圆厂”，还是欧盟的数据中心和数据边界，Microsoft 都认真对待。尊重各国关心主权的正当理由，并为此在软件和物理设施上做建设，这就是他们要做的。

和中国公司的竞争

最后一个问题：走向美中双极世界，竞争方除了 Microsoft 对面的 Amazon、Anthropic、Google，还有一大批对手。美国怎么重建信任，让各国相信美国公司会是主要供应商？怎么看待和新兴中国公司的竞争，比如 ByteDance、Alibaba，或者 Deepseek、Moonshot？另一位主持人补充：大家在说 AI 正在变成一场工业 capex 竞赛，要在所有供应链上快速建设；至少到现在，一听到这个，人们就会想到中国，这是中国的比较优势。尤其如果明年不会一步登上 ASI，要经历几十年的建设和基础设施，怎么应对中国的竞争？在那样的世界里中国是不是占优？

Satya 说这个问题正好说明了为什么对美国技术的信任可能是最重要的特性，甚至可能比模型能力更重要。问题是“我能不能信任你这家公司，能不能信任你的国家和它的制度，做一个长期供应商”。他说这可能就是赢得世界的东西。访谈到这里结束。
