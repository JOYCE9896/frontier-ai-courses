第十二讲：内存一致性模型

缓存一致性（coherence）和内存一致性（consistency）的区别；四种内存操作顺序；"happens-before"图分析一个两线程程序能打印什么；顺序一致性和开关比喻；为什么要放松：写缓冲区、隐藏写延迟；TSO 和处理器一致性只放松写到读；PSO 再放松写到写；弱序和释放一致性放松全部；栅栏和其他同步原语；x86 和 ARM；数据竞争、同步程序和 "SC for DRF"；语言层面的内存模型

主讲：Kunle Olukotun
资料来源：课堂录像（Stanford Online，2023 年秋季，本讲后半段）、课件；本讲前半段讲完缓存一致性，已并入第十一讲；课件最后语言层面内存模型的几页课上没讲到，依据课件整理

一、共享内存的行为

Kunle 说今天讲缓存一致性那个难缠的伙伴：内存一致性。

  • 直觉说 load 应该返回最新写入的值。什么是"最新"？
    • 缓存一致性（coherence）：只涉及一个内存位置。
    • 内存一致性（consistency）：所有位置上表现出来的顺序，一个线程执行的内存操作以什么顺序对其他线程可见。
  • 它影响：
    • 可编程性：程序员怎样推理程序行为，多线程程序在共享内存上执行时允许有什么行为；
    • 性能：限制了能用哪些软硬件优化，比如重排内存操作来隐藏延迟。

谁应该关心

  • 想实现同步库的人；
  • 将来会做内核（或驱动）开发的人；
  • 想实现无锁数据结构的人（后面一讲的主题）；
  • 开发编译器或底层操作系统代码的人。

Kunle 说，主要用高级语言加编译器开发的应用程序员，或者用内核库、系统库的人，不太需要懂内存一致性模型的细节；但像这门课的同学这样的底层系统开发者，就得懂。

缓存一致性和内存一致性

  • 缓存一致性规定了对同一内存位置的读写要表现出什么行为：所有处理器必须对 X 的读写顺序达成一致；换句话说，能把所有涉及 X 的操作排在一条时间线上，使所有处理器的观察都和这条时间线相符。例子：观察到的 X 上的操作时间线：P0 写 5，P1 读（5），P2 写 10，P2 写 11，P1 读（11）。
  • 内存一致性规定了对不同位置的读写行为（在其他处理器看来）：缓存一致性只保证对 X 的写最终会传播到其他处理器；内存一致性处理对 X 的写相对于对其他地址的读写，何时传播到其他处理器。

换个更直观的说法：

  • 缓存一致性的目标是让并行计算机的内存系统表现得像缓存不存在一样，就像单处理器系统里内存系统表现得像没有缓存一样。
  • 没有缓存的系统就不需要缓存一致性。Kunle 说有缓存的系统都必须一致，这是根本的，没人想在不一致的系统上工作。
  • 内存一致性规定了并行系统里对不同地址的 load 和 store 允许有什么行为。不管有没有缓存，都应该规定内存允许的行为，这就是内存一致性模型做的事。即使没有缓存的系统也需要内存一致性模型。

预告

  • 多处理器会以反直觉的、奇怪的方式重排内存操作；
  • 为了性能，这种行为是必要的；
  • 应用程序员很少看到这种行为；
  • 系统（操作系统和编译器）开发者天天见到它。

二、内存操作的顺序

程序定义了一串 load 和 store，这是它们的"程序顺序"。对任何一个线程，内存系统会保持程序顺序；问题是它怎样对待来自不同线程的访问。四种内存操作顺序（X、Y 是不同的地址）：

  • WX→RY：对 X 的写必须在之后对 Y 的读之前提交；
  • RX→RY：对 X 的读必须在之后对 Y 的读之前提交；
  • RX→WY：对 X 的读必须在之后对 Y 的写之前提交；
  • WX→WY：对 X 的写必须在之后对 Y 的写之前提交。

澄清："写必须在之后的读之前提交"是指：程序顺序里写在读之前时，到读发生时，写必须已经提交（结果已经可见），也就是写改变了内存状态。问题在于内存系统保持哪几种顺序。

多处理器执行：能打印出什么？

// initially A = B = 0

// Proc 0
(1) A = 1
(2) print B

// Proc 1
(3) B = 1
(4) print A

输出是先 P0 打印的 B 再 P1 打印的 A。"01"？"10"？"11"？"00"？Kunle 让大家和邻座讨论一分钟。有人说都可能；有人说只有 11；有人说 01；10 有人说可以有人说不行；00 大家说不行。

理解的有效方式是 "happens-before" 图：为了得到想要的输出，哪件事必须在哪件事之前发生？多处理器上不同线程的指令可以按任何方式在时间上交错；单个线程内的指令按程序顺序执行；交错成怎样的全局顺序，取决于你控制不了的因素。比如想得到 00：需要 print B 发生在 B = 1 之前，print A 发生在 A = 1 之前；而程序顺序要求语句 1 在语句 2 之前，语句 3 在语句 4 之前。把这些箭头都画上，就成了一个环。

  • 程序不应该打印 "00" 或 "10"。
  • "happens-before" 图显示为了得到某个结果，事件必须以什么顺序执行。
  • 如果图里有环，这个结果就不可能：一个事件必须在它自己之前发生！

有同学问：如果有存储缓冲区、乱序执行，让读排到写前面，会不会得到 00？Kunle 说好问题，正要研究。

三、顺序一致性

程序员应该期待什么？按大家目前对共享内存的了解，大概会说：系统里所有访问有一个全局顺序，人人看到的都是它，所有内存访问可以串行化；这个全局顺序里，每个线程的访问按程序顺序。这大致就是 Leslie Lamport 正式定义的顺序一致性（sequential consistency，SC）。（课件写 Lamport 1976，并注明 2013 年图灵奖；顺序一致性的经典论文一般标为 1979 年。）

  • 所有操作按某个顺序执行；
  • 就像它们在操作单个共享内存；
  • 每个线程的操作按程序顺序发生。

顺序一致的内存系统保持全部四种内存操作顺序（WX→RY、RX→RY、RX→WY、WX→WY）。存在一个所有内存操作的时间线，和观察到的值相符。例子：P0 store X←5；P1 store X←10；P0 store Y←1；P1 load X；P0 load X；P1 store Y←20。注意，和缓存一致性的例子不同，现在时间线上列的是对 X 和 Y 两个地址的操作。

开关比喻

四个处理器连着一个开关，开关通向一个内存。所有处理器按程序顺序发出 load 和 store；内存随机选一个处理器，把一个内存操作执行完，再选另一个处理器……开关随机指向某个处理器，从它那里接受随机数量的访问，再翻到另一个处理器。

例子：处理器 0 执行 A = 1; r1 = B;，处理器 1 执行 B = 1; r2 = A;，内存里 A = 0、B = 0。开关一次运行一条指令：先执行处理器 0 的 A = 1，内存 A = 1、B = 0；再执行处理器 1 的 B = 1，A = 1、B = 1；再执行处理器 1 的 r2 = A，得到 1；最后执行处理器 0 的 r1 = B，得到 1。用开关比喻看所有可能的交错，就会看到前面例子里的 00 和 10 都是非法的，顺序一致性下永远得不到。

四、放松内存操作顺序

  • 顺序一致的内存系统保持全部四种顺序。
  • 放松的内存一致性模型允许违反其中某些顺序。

动机：隐藏延迟

  • 为什么想放松顺序要求？为了获得性能，这门课说的永远是性能。
  • 具体是隐藏访存延迟：内存访问操作相互独立时，让它们和其他操作重叠。
  • 记住，缓存一致的系统里，一次内存访问可能比单纯从内存读出位要多做很多工作（找数据、发失效等）。

顺序一致性下，"写 A"做完才"读 B"；放松后两者可以重叠。从程序员角度，顺序一致性最直观；为什么实现者想要别的？比如一次写要缓存缺失，要做很多事，花很长时间；后面一次读也许缓存命中，两个地址无关，为什么不先做读，或者至少让两者重叠？应用希望尽早读到数据，写可以往后推，或者和其他读重叠。

SC 的问题

处理器 0 执行了 A = 1，写要花很长时间，几百个周期。A = 1 和 r1 = B 这两条指令并不冲突，没必要等第一条做完！

优化：写缓冲区

每个处理器读写自己的写缓冲区。写先进写缓冲区，最终会送到内存系统；同时先别占用总线和资源，先发读，因为处理器在等读的结果，早拿到读就性能更好。可以把写缓冲区放在处理器和缓存之间，也可以放在缓存和总线之间。

写缓冲区改变了内存的行为： 

// initially A = B = 0

// Proc 0
(1) A = 1
(2) r1 = B

// Proc 1
(3) B = 1
(4) r2 = A

// Can r1 = r2 = 0?
// SC: No
// Write buffers: yes

同学说：写都还在写缓冲区里，读先执行了，就读到 00。这不是顺序一致的。

写缓冲区的性能：基线是顺序一致的执行，处理器一次发一个内存操作，停顿到完成；W-R 是放松了 W→R 顺序约束，写延迟几乎完全被隐藏。课件引用的数据显示性能提升相当可观。

写缓冲区：谁在乎？

  • 性能提升；
  • 每个现代处理器都用写缓冲区：Intel x86、ARM、SPARC；
  • 需要更弱的内存模型：TSO（Total Store Order，全存储序），比 SC 稍难推理；x86 用的是一种没有完全规定清楚的 TSO 形式。

允许读越过写

放松第一种顺序 WX→RY，让处理器隐藏写延迟：全存储序（TSO）和处理器一致性（PC）。

  • 全存储序（TSO）：处理器 P 可以在它对 A 的写被所有处理器看到之前读 B（处理器可以把自己的读移到自己的写前面）；其他处理器的读，在对 A 的写被所有处理器观察到之前，不能返回 A 的新值。
  • 处理器一致性（PC）：任何处理器都可以在写被所有处理器观察到之前读到 A 的新值。
  • 在 TSO 和 PC 里，只放松了 WX→RY。WX→WY 约束仍然存在，同一线程的写不会被重排（按程序顺序发生）。

Kunle 课上一度把 PC 和 PSO 的名字说混了，自嘲说有个笑话：计算机科学里有两件难事，命名和内存一致性。区别在于大家什么时候看到 store：TSO 里所有人看到 store 的顺序相同；PC 里有的处理器能更早看到。

澄清（一定要弄明白！）

  • 缓存一致性问题存在，是因为硬件实现了"把数据复制到多个处理器缓存"这个优化，数据的各个副本必须保持一致。
  • 放松的内存一致性问题，来自"重排内存操作"这个优化。（一致性模型和系统里有没有缓存无关。）

缓存一致性因为有缓存；内存一致性模型因为需要一种理解程序含义的方式。

允许写被重排

部分存储序（PSO，Partial Store Ordering）再放松 WX→WY。程序 1 的执行可能不符合顺序一致性（P2 可能先看到 flag 的变化，后看到 A 的变化）： 

// Thread 1 (on P1)
A = 1;
flag = 1;

// Thread 2 (on P2)
while (flag == 0);
print A;

用标志位保护对变量的修改，想做同步，结果被重排了，行为就不是预期的了。

为什么要允许更激进的重排？

  • WX→WY：处理器可能在写缓冲区里重排写（比如一个缓存缺失、另一个命中）。
  • RX→WY、RX→RY：处理器可能重排指令流里相互独立的指令（乱序执行）。
  • 记住，如果程序只有一个指令流，这些都是合法的优化。

允许所有重排

  • 对数据上的操作没有任何保证！什么都可以重排。
  • 动机是提高性能：在内存系统里重叠多个读和写；读尽可能早执行、写尽可能晚执行，以隐藏访存延迟。
  • 例子：弱序（WO，Weak Ordering）、释放一致性（RC，Release Consistency）。

Kunle 问谁有手机，手机里的处理器（ARM）用的就是放松的一致性，它的内存一致性模型里一种顺序都不保证。有同学问这是因为实现更简单，还是为了性能？两者都有，但对系统程序员来说处理起来更棘手。

五、同步来救场

  • 内存重排看起来像噩梦（确实是！）。
  • 每种架构都提供同步原语，让内存顺序更严格。
  • 栅栏（内存屏障）指令阻止重排，但很昂贵：栅栏之前的所有内存操作完成后，之后的任何内存操作才能开始。栅栏之间的读写可以重排。
  • 其他（针对单个地址的）同步原语：读改写 / 比较并交换、事务内存……

Kunle：在并行计算里怎样解决任何问题？让东西慢下来。加锁是让东西慢下来的机制，栅栏更糟：它等内存系统安静下来，所有处理器都保证发出的内存操作都完成了，才允许任何一个越过栅栏。这是硬件实现的机制。有 store 栅栏、load 栅栏，这些都相当微妙，细节请参考网上大量的文档。

在放松模型里表达同步

  • Intel x86/x64 近似于全存储序。如果软件需要某种一致性模型不保证的指令顺序，有同步指令可用：
    • mm_lfence（"load 栅栏"：等所有 load 完成）；
    • mm_sfence（"store 栅栏"：等所有 store 完成）；
    • mm_mfence（"内存栅栏"：等所有内存操作完成）。
  • ARM 处理器：非常放松的一致性模型。

课件推荐的资料：Bartosz Milewski 讲 x86 上内存栅栏作用的博文（bartoszmilewski.com，"Who ordered memory fences on an x86?"）；ARM 程序员参考里很好的例子（Barrier Litmus Tests and Cookbook）；剑桥 Peter Sewell 整理的弱内存模型学术论文列表（www.cl.cam.ac.uk/~pes20/weakmemory/）。

问题：数据竞争

到目前为止每个例子都涉及数据竞争：

  • 对同一内存位置的两次访问；
  • 至少一次是写；
  • 没有被同步操作排序。

冲突的数据访问

  • 不同处理器的两次内存访问冲突，如果：访问同一内存位置；至少一次是写。
  • 非同步程序：冲突的访问没有被同步排序（比如栅栏、带 release/acquire 语义的操作、屏障等）。非同步程序含有数据竞争：程序的输出取决于处理器的相对速度（程序结果不确定）。

同步的程序

  • 同步的程序在非 SC 的系统上也得到 SC 的结果。同步的程序是无数据竞争的。
  • 如果没有数据竞争，重排行为就无关紧要：访问被同步排序，而同步强制顺序一致性。
  • 实践中，你遇到的大多数程序都是同步的（通过同步库实现的锁、屏障等），而不是像示例程序那样通过对共享变量随意的读写来同步。

这就是无数据竞争编程的整个思路：不要写对数据做非同步访问的代码，有共享数据就加同步。写同步库的人必须理解底层处理器的内存一致性行为，开发编译器的人必须理解这些问题；应用程序员可以依赖比自己懂得多的人做对了这件事，给了你一个库调用。

小结：放松的一致性

  • 动机：允许重排内存操作（顺序一致性不允许），获得更高性能。
  • 代价之一是软件复杂度：需要特定的操作顺序时，程序员或编译器必须正确地插入同步来保证。但实践中复杂性封装在库里，库提供直观的原语，比如 lock/unlock、屏障（或者更底层的栅栏）。
  • 为常见情况优化：大多数内存访问并不冲突，所以不要设计一个让所有访问都像会冲突那样付出代价的系统。
  • 各种放松的一致性模型，区别在于忽略了哪些内存顺序约束。

六、语言也需要内存模型

Kunle 在课尾提到，内存一致性要在两个层面处理：硬件提供什么，以及语言层面。以下几页课上没时间讲。

  • 有的编译器优化对程序员不可见；有的优化对程序员可见，比如编译器重排共享内存操作。语言要给程序员一个契约，说明编译器会怎样重排他们的内存操作，比如不重排共享内存操作。
  • 现代语言（C11、C++11）和不那么现代的语言（Java 5）保证：无数据竞争的程序是顺序一致的（"SC for DRF"）。编译器会插入必要的同步来应对硬件内存模型。
  • 如果程序含有数据竞争，就没有任何保证！直觉上，大多数程序员会认为有竞争的程序就是有 bug 的。
  • 用同步库！

内存一致性模型小结

  • 规定了硬件和编译器允许对内存操作做哪些重排。
  • 是硬件或编译器与应用软件之间的契约。
  • 好性能必须要弱模型吗？投入多得多的资源，SC 也能表现不错。
  • 内存模型的细节可以隐藏在同步库里，前提是程序无数据竞争（DRF）。
