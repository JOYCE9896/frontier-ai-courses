第一讲：为什么要并行，为什么要高效

课堂上用同学当"处理器"做加法的三个小实验：通信、负载不均和同步怎样吃掉加速比；课程的三个主题；什么是程序、处理器怎样执行指令；指令级并行和超标量，为什么它在每周期四条指令左右就到头了；功耗墙和时钟频率停止增长，"免费午餐"结束；从手机到超算的并行与专用硬件；内存、访存延迟、缓存、缓存行和局部性

主讲：Kayvon Fatahalian、Kunle Olukotun
资料来源：课堂录像（Stanford Online 官方发布，2023 年秋季）、课件

一、并行计算机是什么

一个常见的定义：并行计算机是一组相互协作、快速解决问题的处理单元。这句话里有两层意思：我们关心性能，也关心效率，而手段是用多个处理器。课程名字叫并行计算，但 Kayvon 开场就说，这门课谈效率和谈并行一样多，有时效率重要得多。

来上这门课的人背景各不相同：硬件架构师、写软件的人、等模型训练等得不耐烦的机器学习研究者、做图形的人。一位同学说业界的人告诉他没有比这更好的课。Kayvon 希望大家带走的一点是：计算机比你以为的快得多。尤其是做应用的人，要对"一件事应该跑多快"有直觉。手下的人说"这个计算要跑一整天"，你应该能回答"这个工作量在 10 个核上应该 5 秒跑完"。

加速比

用并行处理的一个主要动机是获得加速。对给定的问题： 

speedup(using P processors) = execution time (using 1 processor)
                              / execution time (using P processors)

二、三个课堂实验

实验一：一个人和两个人

请一位同学上台，把 16 张纸上的数加起来，用了大约 40 秒。怎样更快？可以练习，但更直接的是多找几个人。换一组新数，请两位同学各拿 8 个，一个在讲台前、一个留在教室后排，不许说话，但可以传纸条。结果用了约 41.7 秒，资源翻倍，只快了 10% 左右。

按理说每人算得一样快的话，理想情况是快一倍。实际上第二位同学大约 21 到 23 秒就算完了，然后要走到前面去把部分和交给对方，这段通信就把加速全吃掉了，大家都看到有人在干等。怎样改进？两人一边算一边往中间走，计算和通信重叠；或者允许喊话、发微信，通信成本就大大降低。

  • 通信限制了能达到的最大加速比。这里的通信就是互相告知部分和。
  • 降低通信成本能提高加速比：让"处理器"靠近一点，或者允许喊话。

实验二：四个人

四位同学站在一起、可以交谈，期望大约 12 秒。结果迟迟出不来，因为 Kayvon 故意给其中一人发了多得多、也大得多的数，其他人早算完了在干等。第二次重新分配，先让他们商量策略。他们把所有纸片倒进一个篮子，每人不断取下一张来加，19 秒完成。其实到第 12 秒每个人的部分和都已经算完，后 7 秒花在合并部分和上。

台下的同学提了别的方案：事先把工作平均分成四份；如果谁拿多了就先匀给别人再各自算；留一个人专门负责把另外三人的部分和加起来，一边等一边加；合并时两两相加，而不是等所有部分和都好了才开始。Kayvon 指出，"先分好再各算各的"是一种静态分配，"不断从篮子里拿下一个"是一种持续同步的动态分配，后者能应对有人算得慢、有人拿到大数的情况。

  • 工作分配不均限制了加速比：有些"处理器"没活干了，另一些还在忙。
  • 改进工作分配能提高加速比。

实验三：数一数教室里有多少人

全班一起想办法在一分半内数出教室里的人数。方案五花八门：数排数和每排人数；按区域分开各数各的再汇总；从前后两头往中间数；每人站起来凑十人一组再数组数；所有人往前排挤满再数排数。Kayvon 说同时跑两种方案、看哪种先出结果，这叫推测执行。最后选了"大家往前填满座位"，结果用了两分多钟。

按 16 个数大约一分钟估算，160 人的工作量只是十倍，而且每步只是"加一"，顺序做也不该超过六七分钟，并行做应该快得多。可实际上离这个差得很远，主要成本在通信、同步和把所有人挪来挪去。同学们事后也意识到：留一两个人专门计数可能更快；凑十人一组避免了大家排成一行的依赖。Kayvon 的总结是：这门课虽然讲并行，但其实是在讲把东西挪来挪去，他做过的每个系统里，真正要紧的都是通信和数据移动。

  • 这个问题相对于计算量有大量通信。
  • 通信成本可能主导并行计算，严重限制加速比。

三、课程的三个主题

  1. 设计和编写能扩展的并行程序。并行思维包括：把工作分解成可以安全并行执行的部分；把工作分配给处理器；管理处理器之间的通信和同步，不让它们限制加速比。还要学用流行的并行编程语言实现这些。这正是刚才几个实验里大家在做的。
  2. 并行计算机的硬件实现。高效实现这些抽象的机制、实现的性能特征、性能与方便与成本之间的设计取舍。为什么需要懂硬件？因为机器的特性真的很重要（回想实验里通信速度的问题），也因为你在乎效率和性能。做软件的人要懂一点硬件，才能明白"为什么我的程序要这样组织，为什么不能换个写法"。今年的课比往年更强调硬件实际怎样设计，学期末可能有一个在 FPGA 上做硬件的选做作业。
  3. 思考效率。快不等于高效。程序在并行计算机上跑得更快，并不说明它高效地利用了硬件。在 10 个处理器上得到 2 倍加速，算好结果吗？程序员的视角是用好机器提供的能力；硬件设计者的视角是选择该放进系统的能力（性能和成本，成本可能是芯片面积、功耗等）。

关于第三点，Kayvon 问：实习时被要求加速一个程序，有一台 10 核机器，一个月后你做到了 2 倍加速，会被开除还是被加薪？有人说该开除，10 个处理器只用出 2 倍，说明用得很低效。也有人说可能该加薪：不是所有程序都像加数那么好并行；如果机器便宜，网站响应时间减半能带来大量销售，那就很值；谷歌搜索结果必须在一定时间内返回，否则用户就走了；一个游戏从每秒 15 帧提到 30 帧，可能就是能不能发布的区别。所以有时我们在乎原始性能，有时在乎效率，理想情况是两者兼得。硬件设计者尤其在乎效率，因为芯片上每多加一点硬件，造价就更高，他们想用最少的硬件达到性能目标。

四、课程安排

  • 没有教材，课件基本就是教材，网上有很多好资源。课程网站支持针对每页课件写评论。

五、为什么要并行

先看历史。Kayvon 读书时对并行计算感兴趣，教授会说：干嘛费这个劲，等一年处理器就变快了。Kunle 和 Hammond 2005 年的一张老图显示，单线程 CPU 性能大约每 18 个月翻一番，在对数坐标上是一条直线。这意味着花功夫把代码并行化往往不值得：开发者什么都不用做，明年代码自然就快了。

为什么会这样？有人说是晶体管变小了，但这不是直接通向性能的路。晶体管变小让两件事成为可能：时钟频率可以提高；芯片上可以放更多晶体管，架构师要想出聪明的办法用它们提高性能。所以直到大约十五年前，处理器性能提升有两个主要来源：

  1. 利用指令级并行（超标量执行）；
  2. 提高 CPU 时钟频率。

什么是程序，处理器做什么

Kayvon 让大家互相回答：从处理器的角度看，什么是计算机程序？一位同学说"一段能翻译成硬件指令的文本"，文本那部分不重要，重要的是后半句：程序就是一串处理器指令。下面这段 C 代码编译后是一串 x86 指令（在 Apple 笔记本上会是 ARM 指令），不管是编译还是解释，计算机最终执行的就是一串指令，就像做菜的菜谱。 

int main(int argc, char** argv) {
    int x = 1;
    for (int i = 0; i < 10; i++) {
        x = x + x;
    }
    printf("%d\n", x);
    return 0;
}

那么处理器做什么？"执行指令"。执行一条指令又是什么意思？做算术、跳转到程序的另一处、改变寄存器的值、读写内存。归结起来：指令描述一个操作，执行它通常会修改计算机的状态，而状态就是程序数据的值，存放在处理器的寄存器或内存里。

课程反复用一张简化的处理器示意图，有三个部分，颜色在整个学期保持不变：

  • 取指/译码（橙色）：负责控制，决定指令流里下一条要执行什么。
  • 执行单元 ALU（黄色）：做算术，加、乘、移动值。
  • 执行上下文（蓝色）：状态，寄存器 R0、R1……的值。

执行 add R0 ← R0, R1：取出下一条指令；从寄存器读出操作数 32 和 64；执行单元算出 96；把结果写回 R0。暂时设想这个"非常简单的处理器"每个时钟周期取一条指令、执行它、更新寄存器。

六、指令级并行

a = x*x + y*y + z*z

// assume R0 = x, R1 = y, R2 = z
mul R0, R0, R0
mul R1, R1, R1
mul R2, R2, R2
add R0, R0, R1
add R3, R0, R2
// R3 now stores the value of a

五条指令，每周期一条，要五个周期。能更好吗？

先想清楚这段程序的意思：它要求结果和按 1、2、3、4、5 的顺序执行一样，就像做菜步骤乱了结果会很糟。但只要你换了顺序我看不出区别，那就没问题。第 1、2、3 条乘法互不依赖；第 4 条只依赖 1 和 2；第 5 条依赖 4 和 3。如果每周期能执行两条，可以第一周期做 1 和 2，第二周期做 3 和 4，第三周期做 5，三个周期完成。三条呢？第一周期做 1、2、3，然后 4，然后 5，还是三个周期，因为依赖链限制了它。这段代码不同时刻的并行度不同：开始时是 3，之后是 1、1，这叫指令级并行（ILP）。它其实就是向量点积的形状，机器学习里的关键运算。

关键在于：程序员写的是顺序程序，完全没想并行，但程序里藏着可以并行的东西。

想法一：超标量执行。处理器自动在指令序列里找出相互独立的指令，在多个执行单元上并行执行（或者由编译器在编译时找出独立指令，把依赖关系显式编码进二进制）。这就是更多晶体管能变成更高性能的原因之一：架构师设计的硬件看着你给的程序说"你没写并行，可我发现了这些可以同时做的"，自动重排。示意图上仍是一个核，但有两套取指译码和执行单元，每周期能译码执行两条指令，再加上乱序控制逻辑，代表处理器上有一些智能来判断能不能重排。二十年前的 Pentium 4 套上这个配色，和示意图差别不大，能同时执行三四条不同的指令。

真实程序复杂得多，课件给了一个更长的指令序列和它的依赖图，可以自己验证一下。依赖图限制了单个处理器在你不知情的情况下自动并行化所能达到的总并行度。有同学问想深入了解处理器里实际怎样做：从超标量执行和重排算法（比如 Tomasulo 算法）入手，翻开 Hennessy 和 Patterson 读乱序执行那一章。

收益递减

问题是：前面看到每周期三条和两条一样快，因为指令序列里通常有某种固有的顺序。斯坦福在并行计算早期做过大量研究，看程序员什么都不做时能自动挖出多少并行。横轴是处理器每周期能发射的指令数，纵轴是加速比：大部分可用的 ILP 在每周期发射四条指令的处理器上就被用完了，再造能发射更多的处理器几乎没有收益（Culler 和 Singh 的书，数据来自 Johnson 1991）。程序里根本没有那么多并行。

频率也停了

Herb Sutter 2005 年那篇《免费午餐结束了》里的图：晶体管密度一直在增长（直到最近五年才开始偏离），现代 NVIDIA 芯片大约有八九百亿个晶体管；但每周期指令数早就不再增长，因为加了也没用；时钟频率从 500 MHz、750 MHz、1 GHz、2 GHz 涨到 4 GHz 左右，大约十五年前也停了。

为什么频率不涨了？功耗。

  • 动态功耗 ∝ 电容负载 × 电压² × 频率。
  • 静态功耗：晶体管即使不工作也会因漏电而耗电。
  • 高功耗意味着高发热，功耗是现代处理器的关键设计约束。

课件列了一些热设计功耗：Intel Core i9 10900K 桌面 CPU 95 W，Apple M1 笔记本 13 W，NVIDIA RTX 4090 GPU 450 W，普通微波炉 900 W，手机处理器 0.5 到 2 W，世界最快的超算是兆瓦级。Kayvon 说 4090 满负荷跑机器学习和他厨房的微波炉热昨天的汉堡，功耗只差一倍，这些能量都变成了热，热又要求冷却。最大允许频率由处理器的核心电压决定，频率越高电压越高，一个粗略的经验是功耗大致随频率的平方增长，所以靠提频率来提速是很低效的。

单核性能停滞

  • 单指令流性能的增长速度降到几乎为零：频率受功耗限制，ILP 用尽了。
  • 架构师现在靠增加并行运行的执行单元来造更快的处理器，或者增加专门做某类任务的单元（图形、音视频播放）。
  • 软件必须写成并行的才能获得性能提升，软件开发者的免费午餐结束了。

这就是 Kayvon 读研时的局面：程序员必须亲自告诉处理器"这两件事可以同时做"，才能用上这么多晶体管。幸运的是，机器学习、计算机图形、图像处理、摄影这些领域很容易做到这一点。于是人们开始造有很多核的处理器。

七、到处都是并行硬件

  • Intel "Comet Lake" 第十代 Core i9，10 核 CPU（2020）。
  • 作业 1 的机器：四核 Intel CPU，有 AVX SIMD 向量指令和超线程。基准是用 -O3 编译的单线程 C 程序，用上这颗 CPU 所有并行执行资源的程序快 32 到 40 倍。Kayvon 强调这是编译好的 C++ 和写得好、正确并行化的 C++ 之间的差距，不是和 Python 比；在你的四核笔记本上就是这样。这些术语下一讲讲。
  • AMD Ryzen Threadripper 3990X：64 核，4.3 GHz，由四个 8 核小芯片组成。
  • NVIDIA AD102 GPU（GeForce RTX 4090，2022）：760 亿个晶体管，18432 个 fp32 乘法器，分成 144 个处理块（叫 SM）。要用好它需要极高的并行度。课上会讲 NVIDIA 处理器其实是同一类东西，只是设计空间里的另一个点。
  • GPU 加速的超算 Frontier（橡树岭国家实验室，2022 年秋世界第一）：9472 颗 64 核 AMD CPU（共 606208 个 CPU 核），37888 块 Radeon GPU，21 兆瓦，相当于一座小城市的用电量。
  • 手机：Apple A15 Bionic（iPhone 13、14），150 亿个晶体管，6 核 CPU（2 个大核、4 个小核），5 个 GPU 块。功耗约束也深刻影响着移动系统的设计。
  • 树莓派 3：四核 ARM A53 CPU。嵌入式里也是多核。

不只要并行，还要高效

在现代计算中，软件不只要并行，还必须高效。实现高效是这门课的一个关键主题：现代系统不只用很多处理单元，还用专用的处理单元来达到很高的能效。世界各地的架构师都在说：要更高效，就不能只给你通用的核，得给你专门做特定任务的单元。

  • 还是 A15：2 个大核擅长跑单线程；4 个小核功耗低，适合后台进程；还有 Apple 自研的多核 GPU、做 DNN 加速的神经引擎（NPU）、图像和视频编解码处理器、运动（传感器）处理器。相机、神经网络、传感器、心率监测这些根本不在 CPU 上跑，而在专用处理器上跑。
  • 数据中心：Google 的 TPU（Tensor Processing Unit，做机器学习计算的专用处理器）组成的 TPU pod。
  • 加速 DNN 推理和训练的专用硬件：Google TPU3、华为麒麟 NPU、Apple 神经引擎、GraphCore IPU、带 Tensor Core 的 Ampere GPU、Intel 深度学习推理加速器、Cerebras 晶圆级引擎、SambaNova Cardinal SN10。Facebook 也宣布在开发自己的神经网络芯片，硅谷今天很多公司在专门为机器学习造数据处理基础设施。

八、内存和缓存

课件上一句话单独占一页：实现高效处理，几乎总是归结为高效地访问数据。就像在教室里走来走去看到的，把数据挪到正确的位置，是这门课最重要的话题。

什么是内存

前面说处理器执行指令会改变状态，状态的一部分是内存里的值。那内存是什么？有人说 RAM。Kayvon 说 RAM 是内存的一种实现。写 x86 代码说"把这个值存进内存"时，并不是指存进 DDR4 或芯片上的 HBM，指的是一个抽象：内存在逻辑上就是一个值的数组，给它一个地址，它返回那个地址上存的值。

  • 计算机的内存组织成一个字节数组，每个字节由它在数组里的位置即"地址"标识（假设按字节寻址）。
  • 例子里的地址空间是 32 字节，有效地址是 0x0 到 0x1F。"地址 0x10 上的字节值是 128"，"地址 0x8 上的字节值是 32"。
  • 处理器有两个地方能存值：寄存器和内存。load 指令把内存里的值搬进寄存器：ld R0 ← mem[R2]，意思是"从 R2 里存的地址开始读一个四字节的值，放进 R0"。R2 是 0xff681080，那里存的是 42，执行后 R0 变成 42。

访存延迟和停顿

  • 访存延迟：内存系统把数据交给处理器所需的时间，比如 100 个时钟周期、100 纳秒。示意图里请求发出后两秒才拿到数据。
  • 停顿（stall）：处理器因为后面的指令依赖前面一条还没完成的指令，而无法执行指令流里的下一条，就停顿了。
  • 访存是停顿的主要来源。连续两条 load 之后紧跟一条 add，add 要等两个值都从内存取回来才能执行；数据在 DRAM 里时，访存时间是几百个周期。

缓存

有同学说缓存是"一小块可以频繁访问的东西"。DRAM 是能存很多数据但延迟高的存储机制；缓存是存不了多少数据但延迟很低的存储机制。Kayvon 的比喻是：DRAM 是车库，缓存是办公桌，空间小但伸手就拿到。

  • 缓存是一个硬件实现细节，不影响程序的输出，只影响性能。
  • 缓存是片上存储，保存内存中一部分值的副本。
  • 如果某个地址"在缓存里"，处理器读写它比数据只在 DRAM 里时快。
  • 缓存以缓存行为粒度工作。示意图里缓存能放 2 行，每行 4 字节。

两个例子

设缓存总容量 8 字节，每行 4 字节（能放 2 行），替换策略是 LRU（最近最少使用）。

例 1：依次访问 0x0、0x1、0x2、0x3、0x2、0x1、0x4、0x1。访问 0x0 是冷未命中，把 0x0 那一整行（0x0 到 0x3）装进缓存；接着 0x1、0x2、0x3 都命中；再访问 0x2、0x1 也命中；0x4 冷未命中，装入 0x4 那一行；0x1 命中。这串访问里有两种数据局部性：

  • 空间局部性：装入一个缓存行，相当于"预取"了之后对同一行里其他地址的访问，于是命中。硬件假设你访问了某个数据，也会访问它附近的数据，所以按顺序读内存是划算的。
  • 时间局部性：反复访问同一地址会命中。

例 2：依次访问 0x0 到 0xF，再访问 0x0。0x0 冷未命中装入第 0 行，0x1 到 0x3 命中；0x4 冷未命中装入第 1 行，0x5 到 0x7 命中；0x8 冷未命中，缓存满了，按 LRU 赶出 0x0 那一行；0xC 冷未命中，赶出 0x4 那一行；最后再访问 0x0，它被赶出去了，这叫容量未命中，装入时赶出 0x8 那一行。

小结：处理器访问驻留在缓存里的数据时运行得高效；当处理器访问最近访问过的数据时，缓存降低了访存延迟。缓存也提供高带宽的数据传输。

存储层次

在现代计算机上，线性内存地址空间这个抽象的实现很复杂。"把地址 X 的值装进 R0"这条指令，可能涉及多级数据缓存和 DRAM 的一系列复杂操作。常见的组织是一层层的缓存：L1、L2、L3，容量小的离处理器近、延迟低，容量大的离得远、延迟高。课件的例子：L1 32 KB，L2 256 KB，L3 20 MB，DRAM 64 GB。Kaby Lake CPU 上的访问时间（4 GHz 下的周期数）：

数据在哪里延迟（周期）
L1 缓存4
L2 缓存12
L3 缓存38
DRAM（最好情况）约 248

这一点对后面理解多线程、GPU 怎样掩盖延迟至关重要，下一讲接着讲。

九、小结

  • 今天，单个控制线程的性能提升非常缓慢。要让程序明显变快，就得利用多个处理单元或专用处理硬件，这意味着要懂得怎样推理和编写并行、高效的代码。
  • 写并行程序可能很有挑战：要划分问题、通信、同步；了解机器特性很重要，特别是要理解数据移动。
  • Kayvon 猜大家会发现，只要用得高效，现代计算机的处理能力比你以为的大得多。
