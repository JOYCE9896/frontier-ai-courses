第七讲：电脑操作 Agent

看屏幕、点鼠标、敲键盘的 Agent：它们怎样工作，怎样评估，怎样训练

主讲：Jing Yu Koh · 2026 年 9 月 15 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容） · 指定阅读：WebArena、VisualWebArena、OSWorld、OpenCUA、CUA-Gym、MACU

一、什么是电脑操作 Agent

电脑操作 Agent（Computer Use Agent，CUA）直接在图形界面上工作：看渲染出来的屏幕，执行动作，再检查屏幕发生了什么变化。它面对的界面和人面对的一样，可以是浏览器（跨多个页面购物）、桌面（在多个应用之间编辑文件）或手机（切换屏幕、手势操作）。上一讲的编程 Agent 主要通过命令行和文件操作；CUA 则面对为人设计的界面，没有现成的 API 可调。

这一讲是客座讲座。Daniel Fried 介绍说，主讲人 Jing Yu Koh 在 CMU 读博，导师是 Daniel 和 Ruslan Salakhutdinov；读博前在 Google Research 工作过，还在 Meta 的 TBD 实验室带过一年半的电脑操作 Agent 团队，为他们现在发布的强 Agent 打下了基础。他做过这个领域几个影响很大的基准，课程后面讲搜索时他还会再来。

Koh 开场说，今天大家把电脑操作看成前沿模型理所当然的一项核心能力，但很长一段时间里，人们既不确定是否需要这样的 Agent，也不清楚怎样把它做好。他认为 CUA 和前面讲的编程 Agent、文字 Agent 不太一样，关键区别在于它和人在完全相同的空间里操作，这带来了很多有意思的建模和评估问题。前沿的 CUA 大多用截图作为观测，也有用文字表示的。

1. 观察、推理、行动

CUA 的循环是：用户给出任务，模型根据屏幕截图推理并决定动作，基础设施先校验动作、再执行，然后截一张新图作为观测交回模型。课上以"买一个蓝色马克杯"为例一步步演示：

  1. 模型想："我在屏幕中间看到一个蓝色马克杯，点它。"输出 {"mouse": {"left_click": [33, 201]}}。
  2. 商品页显示"蓝色马克杯，18 美元，数量 1"。模型想："配送信息在下面，往下滚。"输出 {"scroll": {"dy": 520}}。
  3. 模型想："看到邮编输入框了，点它开始输入。"输出点击坐标。
  4. 模型想："输入邮编查配送选项。"输出 {"type_text": "15213"}。

循环一直进行到任务完成，然后计算奖励，比如任务成功得 1.0。这个循环会一直重复，直到模型认为自己完成了，或者用光了预算。奖励可能来自环境、人类用户或另一个裁判模型，通常是 0 或 1，有时也给部分分数。

2. 简要历史

  • 2017 到 2022 年，玩具环境：MiniWoB（Shi 等，ICML 2017）和 MiniWoB++（Liu 等，ICLR 2018）是高度简化的网页界面；WebShop（Yao 等，NeurIPS 2022）用真实商品和自然语言目标模拟购物。
  • 2022 到 2024 年，真实环境：WebArena（Zhou 等，ICLR 2024）和 VisualWebArena（Koh 等，ACL 2024）搭建了逼真的网站；OSWorld（Xie 等，NeurIPS 2024）扩展到完整的桌面工作流。
  • 2025 到 2026 年，真实环境加数据：MyPCBench（Jang 等，2026）把邮件、日历、项目 issue 放进一个带有个人历史的共享世界；CUA-World（Aggarwal 等，2026）用装好数据的专业桌面软件和真实任务。
  • 2026 年 9 月，真实使用：主讲人展示了 GPT-6 Astra 在 SolveSpace（一个 CAD 软件）里完成 OSWorld 2.0 任务的演示，评价是能力很强、速度快，但仍然非常贵。

Koh 在课上先做了一个小调查：大家觉得第一篇 CUA 论文是哪年出现的？多数人猜 2020 年以后。答案是 2017 年，OpenAI 的 World of Bits 项目。它搭了一个非常简化的玩具环境，数据大多是合成的，界面有点像手机，但一点也不真实；当时用的是类似游戏 Agent 的强化学习，而不是今天的大模型强化学习。Koh 说这个项目超前于时代，那时的模型即使在这么简化的任务上也做得很差。

WebArena 是 Graham 实验室的工作，里面的网站填充了从亚马逊、Reddit 等真实网站整理来的数据，比 WebShop 真实得多，模型也是从这时开始在这类任务上变得像样。OSWorld 几乎同时发布，从网页浏览扩展到完整的桌面操作，可以用 Linux、Windows 上的各种应用，现在是最标准的 CUA 基准之一。WebArena 和 OSWorld 用的都是人写好并开源的软件，只是往里面填了真实数据。2025 年以后，编程 Agent 变强了，MyPCBench 这类基准开始用编程 Agent 从零生成整个应用。课上展示的 Gmail 仿制品就完全是编程 Agent 写出来的，里面的数据也全是合成的。Koh 说这类生成的环境效果很好，有时甚至比真实应用更好用，因为更干净、噪声更少。CUA-World 也是 CMU 的项目，用的是更"长尾"的专业软件，比如天文学和生物学软件，数据是从真实使用场景下载的。

关于 GPT-6 Astra，Koh 的评价是：它在电脑操作上是一次巨大的飞跃，基本解决了大多数电脑操作基准，已经超过人类基线；比以前的模型快很多，但仍然又慢又贵。课上播放的 CAD 演示是加速 30 倍的，实际速度慢 30 倍。从 2017 年的玩具环境到今天，九年时间，模型在很多电脑任务上已经达到或超过普通人的水平。

二、怎样评估

1. 什么算成功

同一个任务可以用不同方式评估：看动作，它点到目标了吗，适合快速的定位测试或模仿测试；看结果，购物车里是不是正确的商品，用状态检查或证据判断；看过程，它遵守约束了吗，比如没有结账、没有做多余的修改。评估方式要和想测的能力对应。

Koh 指出，电脑操作比软件工程或数学更难验证。后两者有单元测试或符号验证器，而电脑操作任务"算不算完成"，连人与人之间都未必意见一致，所以程序化的验证器很难写。

基准按范围分四类：静态评估，在固定截图上预测一个动作；网页端到端评估，通过浏览器交互完成任务；桌面和手机端到端评估，跨应用和系统状态完成任务；长程评估，在很长的工作流中持续推进。

2. 静态评估：这一步动作对吗

给一张截图，判断模型点击的坐标是否落在目标框内；对于录制好的动作，检查目标元素、操作类型和输入值是否一致。不需要真正在环境里运行，但一步正确不等于完成了任务。

  • ScreenSpot-Pro（Li 等，2025）：1,581 张截图，23 个应用，3 种操作系统，用高分辨率的专业软件界面测试定位能力。例子是在 Blender 里"构建一个 UV 球体网格"，原图 2560×1440，目标按钮在 (417, 132) 到 (576, 152) 的框里，点在框内得 1 分。
  • Mind2Web（Deng 等，NeurIPS 2023）：137 个网站、31 个领域的 2,350 个任务，离线匹配动作。例子是"在纽约布鲁克林中心租一辆车，4 月 9 日到 15 日"，正确动作是点击 CAR 标签。模仿下一个动作和完成任务是两回事。
  • 其他：AITW（Rawles 等，2023）有 71.5 万个手机操作片段；AndroidControl（Li 等，2024）有 833 个安卓应用的 15,283 个示范，配有高层和低层两种指令，把规划和具体操作分开。

Koh 讲了静态评估的主要缺点：假阴性很多。以租车为例，标准答案是点击 CAR 标签，但 Agent 先去调整日期同样是合理的一步，静态评估却会判它错。静态评估又快又便宜，不需要维护任何环境或模拟器，只要提供截图、比较预测的动作即可；但它测的不是我们真正关心的端到端表现。

3. 网页端到端评估：检查最终状态

以"把一个 20 美元以下的蓝色马克杯加入购物车，不要购买"为例。程序化检查直接读数据库或应用状态：购物车里的商品是蓝色马克杯，价格低于 20，订单数为 0，全部满足就通过。这种方法可重复、精确，但只能覆盖测试写到的条件。

WebArena 有 812 个长程任务，分布在 4 个自托管网站上，评估器检查环境状态，不看轨迹"像不像"。课上举了 476 号任务"创建一个名为 awesome_llm_reading 的空仓库"，它的验证程序打开目标网址，检查页面里有没有这个名字。问题在于它没有检查仓库是否为空。VisualWebArena 有 910 个任务，其中 25.2% 需要看图，视觉理解让更多类型的任务可以被表达出来。

Koh 补充说，WebArena 是完全在本地托管的模拟环境，从不访问真实网络；每个任务的验证程序都是 CMU 的研究生手写的。只看结果、不管中间每一步，这是它相对静态评估的一大进步，但也带来了奖励投机（reward hacking）的风险：Agent 可能去迎合验证器，而不是真正完成任务，这是大多数 Agent 评估和训练中的普遍问题。VisualWebArena 推出时，大多数模型还在用可访问性树（一种简化的 HTML）来做网页任务，这个基准的目的之一就是说服大家转向基于截图的方法，里面的任务只靠 HTML 做不出来。

另一种方式是让 LLM 或 VLM（视觉语言模型）按评分细则看证据判断：给它截图和动作历史，让它逐项确认"有蓝色马克杯、价格低于 20、没有显示购买"。这种方式灵活，但需要用人工标注校准。WebVoyager（He 等，ACL 2024）在 15 个真实网站上有 643 个任务，裁判和人工的一致率为 85.3%；真实性提高了，可复现性就下降了，比如"找 GitHub 上星数最多的气候变化数据可视化项目"，录制时的答案是某个 63 星的项目，但现在的排名已经不同了。Online-Mind2Web（Xue 等，COLM 2025）在 136 个真实网站上有 300 个任务，其 WebJudge 与人工的一致率为 85.7%。真实网站会变，裁判的质量也成了分数的一部分。

WebVoyager 是最早让 Agent 去真实网站上做任务的基准之一。Koh 提到一个细节：去看其中一个菜谱网站 Allrecipes，还能在网站上找到之前 Agent 做这些任务时留下的痕迹，这正说明了为什么不宜在真实网站上评估 Agent。不过它的价值在于尽可能接近真实世界。因为无法查询真实网站的后台状态，只能用视觉语言模型当裁判。按论文摘要，WebVoyager 自己的 Agent 在这个基准上的成功率是 59.1%。Koh 说这两个基准现在已经不太有人用了：一是现代模型基本解决了它们；二是 CUA 越来越普及，大家对在真实网站上部署也更谨慎，网站主人并不喜欢大量 Agent 为了跑基准来访问自己的网站。

还有人工评审，用来处理结果模糊的情况，或者审核自动评估器。比如订单页面显示已下单，评审 A 判通过，评审 B 判失败，根据证据裁决为失败，因为下单是被禁止的。

Koh 说，程序化验证器和 LLM 裁判都只是替代指标，人工评审仍然是判断 Agent 是否成功的"金标准"：让几个人看同一条轨迹，投票决定。但它太贵了，不可能对每个任务、每次调试都做，基准的作者通常只做一两次，用来确认基准本身是合理的。

4. 桌面和手机端到端评估

OSWorld 在 9 个应用上有 369 个任务，每个任务都配有初始化逻辑和针对该应用的状态检查。例子是"根据文件夹里的收据更新记账表"，检查方法是把保存的表格和标准表格按规则比较：A1 到 E8 不能变，C9 到 C13 是支出类别，金额和累计余额要正确，比如 D9 约等于 −186.93，E9 约等于 603.07。WindowsAgentArena（Bonatti 等，2024）在 11 个 Windows 程序上有 154 个任务，用并行虚拟机把需要好几天的评估压缩到 20 分钟。

Koh 说 WindowsAgentArena 的价值在于，世界上大量生产性工作是在 Windows 上完成的，这个基准测的就是企业流程里常见的任务。他也指出，这些 2024 到 2025 年的核心端到端基准，现在大多已被现代 CUA 很好地解决，GPT-6 在其中大部分上都远超人类，研究界的注意力转向了更长程、更专业的基准。WebArena、OSWorld 里的任务，人一般十到二十分钟就能完成；新的长程任务可能要人花好几个小时，用的还是专业软件。

5. 长程评估：同时检查结果和过程

还是买马克杯的例子，如果 Agent 的动作是点商品、加购物车、下单，状态检查会发现商品对了，但过程检查会发现它下了单，最终判失败。只看结果的评分会漏掉这个违规。WeaveBench（Li 等，2026）用考虑轨迹的裁判；OSWorld 2.0 在完成度之外另做一份安全审计。

Koh 解释了长程任务为什么需要更细的评分：只有一个最终结果奖励时，奖励太稀疏了。Agent 在中途可能做了大量有用的工作，却拿不到满分，很多模型最终得分就是 0。所以长程基准通常同时设几种检查：中间状态检查，按评分细则看某个中间任务是否完成；过程检查，看整个任务是否端到端完成；最后再给一个总判断。

  • Odysseys（Jang、Koh、Fried、Salakhutdinov，2026）：200 个真实网页上的长程任务，每个任务平均 6.1 条评分细则，主评估上限 100 步。例子是"策划一次去 Palm Springs 参加婚礼的旅行，比较机场，制定行程"，细则包括比较匹兹堡到洛杉矶和到 Palm Springs 的航班、检查上午 9 点到下午 4 点的驾车时间窗、推荐机场、打开一个有报价的租车选项、评估两条去餐厅的绕路方案、创建可编辑的每日行程、总结完整计划。满足 7 条共 8 条，平均得分 0.875，但完全完成率为 0。
  • OSWorld 2.0（Yuan、Zhou、Xiong 等，2026）：108 个工作流，人类完成时间的中位数是 1.6 小时，Agent 平均调用 318 次。难点从点击转向隐藏状态、变化的需求和自我验证。例子是在 FreeCAD 里建一个支撑架并导出符合图纸的 STEP 模型，文件导出了，但形状是错的。
  • CUA-World-Long（Aggarwal 等，2026）：200 个长任务，每个软件一个，经常需要 500 步以上，用 8 条质量标准的清单让 VLM 验证。
  • 其他：MyPCBench 有 184 个任务，17 个已登录的应用，68% 跨应用；WeaveBench 有 114 个混合使用图形界面和命令行的任务，中位数切换 16 次、工具调用 76 次。

讲完基准后有几个学生提问。

  • 有没有基准会给中间步骤打部分分，比如任务是把一件高分商品加入购物车，Agent 加了但还顺手加了一堆无关商品，会不会被扣分？Koh 说奖励设计在这些基准里都很棘手。WebArena 有些任务确实有这种惩罚，但多数基准会把任务设计得答案没有歧义，因此有些人为。他见过 Agent 为了完成"把评分最高的商品加入购物车"而把一大堆商品都加进去的奖励投机。这类细粒度的惩罚并不常见，部分原因是基准做出来时 Agent 还很弱，打分就宽松一些；总体上大家宁可有假阳性，也不愿有假阴性。
  • 除了截图，用其他模态有没有好处？有。据 OpenAI 说，他们的模型在可用时会使用操作系统的可访问性表示，比如 macOS 为视障用户提供的一种类似 XML 的描述，说明屏幕上哪一块是 Chrome 窗口、哪一块是程序坞。这能让模型更稳健。Koh 个人更喜欢纯截图，因为它最通用：只看截图的模型不需要了解设备内部，在 Windows 上训练，更容易迁移到 Linux 或 Mac，而不同系统的可访问性表示各不相同。
  • 评分细则是人写的还是合成的？怎样防止针对细则的奖励投机？Odysseys 的细则大多由 LLM 生成、再由人核对。一种常见做法是给生成细则的模型"特权信息"，也就是评估时 Agent 拿不到的信息，比如提示或 HTML，让它做得比正常评估时更好，据此写出更准确的细则。工业界的基准也大多是 LLM 生成、人工核对，有时只由另一个掌握不同信息的 LLM 核对。Koh 仍然认为，放进基准的每一样东西，最终都应该有人看过。他还认为，比起只看最终结果，基于细则的奖励更不容易被钻空子，因为要同时满足多条标准，比如"把所有商品都加入购物车"就过不了细则检查。
  • 学术基准会不会被拿来训练？按规矩不应该，因为这等于在测试集上训练。但工业界常见的做法是生成和基准很像的任务来训练，比如"类 OSWorld""类 WebArena"的任务，保证分布一致，又不直接用测试集。有些基准本身就提供训练集，比如 CUA-World。

这个基准的任务涉及医疗、工程、建筑设计等领域。Koh 说今年年初发布时，大多数模型得分都很低，而包括 GPT-6 在内的最新模型已经接近 90%。在他看来，电脑操作，包括长程电脑操作，已经非常接近解决，有人甚至会说已经解决了，因为模型在很多通用软件任务上已经超过人类。

Koh 说他自己都不一定能轻松完成 OSWorld 2.0 里的这类任务，它们已经是专家级：看着参考图纸，在 CAD 软件里建出三维零件，需要在三维空间里导航，知道环境里有哪些工具，还要连续工作很久。课上播放了 GPT-6 做这类任务的录像（同样加速了 30 倍），可以看到它在终端和 CAD 软件之间来回切换，自主建模大约一个小时。跑一次评估要几个小时，但他觉得开始评估、一小时后回来发现 Agent 还在有条不紊地推进，这种感觉很神奇。

三、模型怎样工作

1. 根据视觉历史预测动作

CUA 的模型是一个视觉语言模型。第 0 步，上下文是目标"买一个 20 美元以下的蓝色马克杯"和截图 0，模型输出动作 0，比如点击 (x₀, y₀)。动作 0 被追加进轨迹。第 1 步，上下文变成目标、截图 0、动作 0、截图 1，模型输出动作 1。以此类推，第 t 步的上下文是目标加上交替排列的全部截图和动作，模型输出点击、输入、调用工具或停止。截图和动作交替出现的历史，让策略能参考之前的进度。

在模型内部，文字经过分词器和嵌入层变成向量；截图经过视觉编码器和投影层变成一串视觉向量（它们是连续的向量，不是词表里的编号）。这些向量按"指令、第 0 轮、第 1 轮……第 t 轮"的顺序交替排列，送进因果 Transformer，输出下一个动作，比如 click(x_t, y_t)。不同系统的编码器、token 数量和历史压缩方式各不相同。

学生问了两个实际问题。为什么大多数模型用截图而不用 HTML？Koh 说，HTML 很乱，人们用过简化版的 HTML；但截图简单得多，在网页上拿 HTML 容易，在桌面软件里拿底层的可访问性数据就难了。而且让很多人意外的是，基于截图的方法效果非常好，好到似乎没必要用 HTML 这类结构化表示。他说这一点一年前大家还不太愿意接受。点了按钮之后页面还在加载怎么办？最常见的做法是每执行一个动作就等几秒（比如 3 秒）再截图；如果截到的仍是加载画面，模型会被训练成再等一会儿。更复杂的做法是等到屏幕发生变化再截图，但简单等待最常用。Koh 说，电脑操作比数学、编程麻烦的地方就在于会遇到大量这类边缘情况和基础设施问题。

2. 各家模型的动作格式

模型动作接口输出示例
GPT-6 AstraPython / PyAutoGUI，或原生电脑工具pyautogui.click(x, y)
Fable / Opus 5原生电脑工具调用，每次回复可以有多个tool_use: left_click，参数为坐标
Gemini 3.8 Flash电脑操作函数调用，坐标归一化click，x 和 y 取 0 到 999
Qwen 3.8函数调用，界面动作格式由应用定义XML 风格的 <tool_call>
Muse Spark脚本加直接的界面动作，支持批量工具或脚本输出
Kimi K3函数调用，界面动作格式由应用定义函数名加 JSON 参数

主讲人的评价是：各家输出格式都不一样，复现起来非常麻烦。

四、怎样训练

1. 三个阶段

预训练阶段学界面元素（框、标签、文字识别，用于定位）和动作（点击、输入、滑动，用于控制）。SFT 阶段用人类示范（目标加人类操作轨迹）和合成数据（Agent 生成的轨迹）做行为克隆，也就是模仿。RL 阶段给任务和验证器，用任务奖励训练。

Koh 强调，今天部署的 GPT-6 并不是一个只会操作电脑的专用版本，而是一个通用模型，电脑操作只是它的能力之一，这也是越来越普遍的做法。所以电脑操作相关的训练分散在各个阶段里，和其他能力的数据混在一起。

2. 预训练：认识屏幕上有什么

学习界面上有什么、怎样指向它：把文字"CAR"和对应的元素框或屏幕坐标关联起来；学习动作预测，比如点击 bookCarTab 元素，其他标签还有输入文字、从起点滑到终点。代表工作有 Mind2Web 的训练数据和 OS-Atlas（Wu 等，2025）。

Koh 解释了为什么这类数据适合放在预训练：以联合航空网站的截图为例，只要在网页上跑一段简单的 JavaScript，就能提取出所有元素的边框，于是可以非常容易地大规模生成定位数据。预训练恰好需要大量、有噪声但量大的数据。除了定位，还可以学元素之间的关系，比如 CAR 按钮在 HOTEL 按钮右边。这些能力都很底层，目的只是让模型先学会看懂截图、找到元素，之后学动作会容易一些。

有学生问：在 Mac 上训练的坐标，能不能用到平板或分辨率不同的电脑上？Koh 说，坐标通常是归一化的，不用绝对像素，而是 0 到 1000，(0, 0) 是左上角，(1000, 1000) 是右下角。按他的经验，即使分辨率不同，迁移效果也很好。另一位学生问，能不能不看截图，直接把各元素的位置和作用存进数据库。Koh 说这也合理，而且现在的模型不是单一的"只点鼠标"的 CUA：GPT-6 Astra 会穿插使用 bash 命令、直接写代码，总是尽量用最高效的方式完成任务，训练和推理时都会用到这类数据。

3. SFT：模仿有用的轨迹

损失函数和普通的下一个动作预测一样，示范可以来自人，也可以来自 Agent。MolmoWebMix（Gupta 等，2026）包含 3.6 万条人类轨迹和 10.5 万条合成轨迹；合成的方法是让一个读取可访问性树（AxTree）的教师模型去运行，过滤后保留有用的轨迹。OpenCUA 的 AgentNet（Wang 等，2025）公开了 3 种操作系统上的 22,625 条任务轨迹，平均每条 18.6 步。

示范数据的规模和类型一直在变：2023 年 Mind2Web（2,350 个任务）和 AITW（71.5 万个片段）；2024 年 WebLINX（10 万次交互）、AndroidControl（15,283 个示范）、GUI Odyssey（7,735 个跨应用片段）；2025 年 AgentNet；2026 年 MolmoWebMix。趋势是规模变大，并且越来越多地提供更长、跨应用、多轮的监督。

Koh 特别讲了 MolmoWeb 合成数据的思路，并用特斯拉做类比（他说自己不确定是否属实）：据说特斯拉训练时会让装了激光雷达的车去自动驾驶，有了三维信息开得好得多；收集这些轨迹后丢掉激光雷达数据，只用摄像头画面训练模型。MolmoWeb 也是这样：教师模型拿到的是可访问性树，这是推理时学生模型拿不到的"特权信息"，所以教师做得更好；收集到 10.5 万条合成轨迹后，再用 LLM 裁判或人工筛掉质量差的，最后用它们训练只看截图的模型。合成数据通常比人类数据噪声大、质量低，但可以大规模生成，不需要人来做，所以仍然很有用。

4. RL：从打过分的尝试中学习

RL 的流程是：生成经验、给结果打分、改进策略。SFT 学的是预测下一个动作，RL 按整条轨迹的结果评价。

Koh 说，一年前 CUA 做强化学习还不常见，现在已经很普遍了。SFT 之后，模型已经有一定的电脑操作能力，直接提示就能完成大多数任务，但 RL 阶段非常关键。课上的一张图显示，SFT 之后成功率约 0.5，做完 RL 能提高到 0.6 以上。另外，RL 能教会一些很难靠人类示范教会的能力，尤其是长程操作，因为很长任务的人类示范极其昂贵，很难收集。他也强调，前面几个阶段同样重要，它们为 RL 打下基础。

RL 需要大量反复尝试，不能直接在真实世界里做。课上的例子来自 MyPCBench：任务是"为我即将出发的牙买加航班预约接机"。真实环境里，反复尝试可能产生重复的付费预订（真的花钱）；一次预订可能真的派出司机（影响真实的人）；取消可能要付费，花掉的时间也回不来（无法干净重置）。所以要在可重置的复制环境里探索。

Koh 举的例子是：你在 Uber 上预约接机，能约几次呢？要么被封号，要么钱花光了。在真实网站上做 RL，他形容为"想玩点刺激的"才会这么做，现在基本没人这样做。

  • CUA-Gym（Wang 等，2026）：按"规划、实现、测试"的流程构建了 94 个模拟网页应用，每个应用可以注入初始状态、检查最终状态、每次会话后重置，一个应用支持很多任务。任务、状态和奖励共同生成：分别生成世界和奖励，再测试两者是否一致。加上 16 个桌面应用共 110 个环境，32,112 个经过验证的 RLVR 元组，其中 38% 是跨应用任务。先用 3,578 条 SFT 示范，再在 10,858 个验证过的元组上用 GSPO 训练，OSWorld-Verified 成绩从 62.2% 提高到 72.6%。
  • Gym-Anything（Aggarwal 等，2026）：一个 Agent 负责搭建真实软件环境，另一个独立的审计 Agent 检查证据。覆盖 Linux、Windows、安卓上的 200 个软件，12,103 个任务和环境，覆盖美国标准职业分类的全部 22 个职业大类。任务的生成方式是先执行种子任务，再用 LLM 扩增并过滤；验证用只有评估器能看到的特权证据加加权检查清单，给部分分数并检查完整性。用 Kimi-K2.5 做教师，提炼出约 2,000 条成功轨迹训练 Qwen3-VL-2B-Thinking 学生模型，平均清单得分从 12.7 提高到 22.5（满分 100），清单全部满足的比例从 1.6% 提高到 4.4%。

五、还没解决的问题

  • 速度和成本：任务时间约等于轮数乘以每轮时间。截图和推理让预填充和生成都很贵。Game-TARS（字节跳动 Seed，2025）采用稀疏思考，只在关键决策时推理，常规步骤直接行动；FDM-1（Standard Intelligence，2026）尝试完全不推理，直接预测动作。另一个方向是通过更好的规划和批量操作减少轮数。
  • 个性化：应该用用户自己的文件、历史和偏好，而不是通用默认值。GUM（Shaikh 等，2025）检索和更新带置信度的用户事实，记忆必须能修改。MyPCBench 测试个人上下文。用户的知情同意和"让它忘掉"的能力必不可少。
  • 基础设施和交互体验：不要阻塞用户，在隔离的后台会话里运行，用户照常工作（例如 OpenAI 2026 年的 Codex 后台电脑操作）；实时协作，显示进度，接受纠正、批准和打断；主动行为需要同意、可见，并且能方便地关掉。新的界面和交互方式还有很多可以探索。
  • 多 Agent：MACU 按依赖关系拆分工作，把就绪的子任务派给隔离环境中的 CUA；共享文件和结果，验证工作、从失败中恢复，然后重新规划；以后还可以把 CUA、编程 Agent 和工具 Agent 组合起来，同时控制冲突和开销。并行只有在协调能保证正确性时才有帮助。

课上时间有限，这一节 Koh 只列了几个方向：速度仍然是问题；个性化是非常值得研究的领域；基础设施和交互体验是很大的关注点；他自己对多 Agent 系统特别感兴趣。具体内容见幻灯片，上面按幻灯片整理。

六、指定阅读与参考资料

指定阅读

  • WebArena（Zhou 等，2023）：搭建了一个高度真实、可复现的网页环境，包含电商、社交论坛、协作开发、内容管理四类功能完整的网站，还配有地图等工具和用户手册等外部知识库，鼓励 Agent 像人一样解决问题。任务评估的是功能上是否正确完成。
  • VisualWebArena（Koh 等，2024）：大多数基准只关注基于文字的 Agent，忽略了很多需要视觉信息的自然任务。电脑界面是为人眼设计的，视觉信息常常补充了纯文字模型用不好的内容。这个基准要求 Agent 准确处理图文输入、理解自然语言指令，并在网站上完成需要看图的任务。
  • OSWorld（Xie 等，2024）：第一个可扩展的真实电脑环境，支持在 Ubuntu、Windows、macOS 上设置任务、基于执行结果评估和交互式学习，可以评估涉及任意应用的开放式任务。
  • OpenCUA（Wang 等，2025）：前沿 CUA 系统的关键细节都不公开，而这些 Agent 会越来越多地替人做有后果的决定，研究界需要开放的框架来研究它们的能力、局限和风险。OpenCUA 包括：一套能无缝记录人类操作示范的标注工具；AgentNet，第一个大规模电脑操作任务数据集，覆盖 3 种操作系统和两百多个应用和网站；以及把示范转成训练数据的可扩展流程。
  • CUA-Gym（Wang 等，2026）：带可验证奖励的强化学习在数学、工具使用、软件工程上都有突破，但在 CUA 上受限于缺少有确定性奖励的大规模训练数据。人工整理的基准奖励准确但覆盖的应用太少，用 LLM 裁判的数据集覆盖广但验证不可靠。CUA-Gym 让一个生成 Agent 构造初始状态和目标状态，另一个判别 Agent 根据任务说明独立编写奖励函数，由编排 Agent 推动两者反复迭代，直到一致。
  • Multi-Agent Computer Use（Koh 等，2026）：见第五讲。管理者把任务分解成有向无环图，每一轮把图中"已就绪"的节点派给并行的 CUA 子 Agent，并根据子 Agent 的新发现不断增加、取消或改写节点。

参考资料

  • WebShop（Yao 等，2022）：模拟电商网站，有 118 万件真实商品和 12,087 条众包的文字指令，Agent 要浏览多种页面、执行各种动作来找到、定制并购买商品。论文收集了 1,600 多条人类示范。
  • ReAct（Yao 等，2022）：见第一讲。CUA 的"观察、推理、行动"循环就是 ReAct。
  • Mind2Web（Deng 等，2023）：第一个面向"通用网页 Agent"的数据集，2,000 多个开放式任务来自 31 个领域的 137 个真实网站，并有众包的动作序列。论文还指出真实网站的原始 HTML 往往太大，放不进 LLM，于是先用小模型筛选页面元素。
  • WebVoyager（He 等，2024）、ScreenSpot-Pro（Li 等，2025）：见上文。ScreenSpot-Pro 覆盖五个行业的 23 个应用，发布时最好的定位模型只有 18.9% 的准确率，专业软件的高分辨率界面和很小的目标是主要难点。
  • Gym-Anything（Aggarwal 等，2026）：把任意软件变成 Agent 环境。把"搭环境"本身当作多 Agent 任务：编程 Agent 写安装脚本、下载真实数据、配置软件，同时留下搭建正确的证据；独立的审计 Agent 按质量清单核查。选软件时参照了有经济价值的职业分类，而不是只做电商和系统设置这类价值有限的任务。
  • MolmoWeb（Gupta 等，2026）：主张开放网络上的 Agent 应该开放地构建，发布了完全开放的多模态网页 Agent 系列和训练数据 MolmoWebMix，后者包括来自多条互补流程的 10 万多条合成轨迹、3 万多条人类示范、原子级网页技能轨迹，以及指代定位、截图问答等界面感知数据。
  • 课程网站上标为 MiniWoB 的链接，实际指向的是一篇文本摘要论文（Get To The Point，See 等，2017），应是链接写错了。MiniWoB 对应的是 OpenAI 的 World of Bits 论文（Shi 等，ICML 2017）。

七、小结

CUA 直接在图形界面上观察和行动，面对的界面和人一样。评估要选对指标和层次：单步动作、端到端任务、长程工作流的测量方式不同，而且要同时关注结果和过程。模型是视觉语言模型，根据截图和动作交替的历史预测下一个界面动作，有些也会用代码和工具。训练经过大规模预训练、在人类和合成轨迹上的 SFT、在模拟环境中的 RL 三个阶段。
