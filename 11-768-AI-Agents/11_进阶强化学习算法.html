第十一讲：Agent 的进阶强化学习算法

给每一步分配功劳、减少等待、让更新保持稳定、让奖励可靠，以及向教师模型学习

主讲：Graham Neubig · 2026 年 9 月 29 日
资料来源：课程幻灯片（课程网站尚未发布这一讲的录像，本文依据幻灯片和课程列出的参考资料整理）

一、从上一讲接着讲

上一讲建立了 RL 的基本循环：采样尝试、打分、更新策略。这一讲处理这个循环在实际中遇到的五个问题：怎样得到有用的反馈（每一步的功劳怎么分）；怎样少等待（异步训练）；怎样让更新稳定（重要性采样和裁剪）；怎样让奖励可靠（假阴性、假阳性、奖励作弊）；怎样向教师学习（蒸馏）。下一讲讲大规模执行时的内存、并行和系统问题。

贯穿全讲的例子沿用第六讲的 bug：训练一个编程 Agent 修复"重试次数设为 0 应该禁用重试，但代码返回了 3"，同时保持其他情况不变。初始代码是 return config.get("retries") or 3。验证器是四个测试：缺失时返回 3，None 返回 3，0 返回 0，2 返回 2。一条成功的轨迹是：读函数，发现 0 变成了 3；修改默认值的处理；跑测试，还有一个失败；再改；再跑，四个全过。四个测试都通过奖励为 1，否则为 0。

目标仍然是 $J(\theta) = \mathbb{E}_{\tau\sim p_\theta(\cdot\mid x)}[R(\tau)]$。普通 REINFORCE 用最终奖励给这次尝试里的每个动作加权：成功的尝试，所有动作的概率都提高；失败的尝试，奖励为 0，完全不产生更新。那么失败的尝试怎样才能提供学习信号？

二、功劳分配与更密集的反馈

1. 组内比较

对同一个任务采样四次，第一次通过，其余三次失败。以组内平均 (1+0+0+0)/4 = 0.25 为基线，权重分别是 +0.75、−0.25、−0.25、−0.25。失败的尝试现在也有贡献了：它们的动作被赋予负权重。

2. 问题：同一条轨迹里每一步权重相同

成功的轨迹里可能有一步走错了，失败的轨迹里可能有一步很有帮助。比如轨迹 A 成功（R=1），但第 2 步是个错误；轨迹 B 失败（R=0），但第 3 步其实做对了。组内权重对一条轨迹里的所有步骤都一样。如果有每一步的奖励，就能知道每条轨迹里该强化哪些步骤。

3. 剩余奖励与价值

剩余奖励（reward-to-go）$R_t$ 是从某一步之后收到的奖励总和。只有最终奖励时，轨迹 A 每一步的 $R_t$ 都是 1，轨迹 B 每一步都是 0，还是分不出哪一步有用。

换个思路：从 B 在第 3 步时的历史 $h_3$ 出发，用同样的策略 μ 继续跑 10 次，假设其中 3 次成功，平均 0.3。这个"从某个历史出发、所有可能后续的平均剩余奖励"就是价值：

$$V^\mu(h_3) = \mathbb{E}_\mu[R_3 \mid h_3]$$

10 次采样给出的是它的一个估计。

4. 训练一个价值模型（critic）

不可能在每个历史上都重跑 10 次。可以训练一个 critic $V_\phi(h)$ 来预测剩余奖励，用平方误差：

$$\mathcal{L}_V(\phi) = \mathbb{E}_t\big[(V_\phi(h_t) - R_t)^2\big]$$

用刚才的 10 个结果（3 个 1、7 个 0）验证：如果预测 0.6，平均平方误差是 [3×(0.6−1)² + 7×(0.6−0)²]/10 = 0.30；这组样本的最佳预测是平均值 0.3，平方误差 0.21。这种用平方误差训练基线的方法见 Ranzato 等（ICLR 2016）。

critic 有两种实现方式。一是单独的价值网络，有自己的主体和输出层，价值损失训练整个网络，例如 InstructGPT。二是在策略网络的主体上加一个线性的价值头，并用 stop-gradient 阻止价值损失更新策略主体，只训练这个头（策略损失仍然训练主体），例如 MIXER（Ranzato 等）。

5. 时间差分误差

有了 critic，就可以比较每一步动作前后的价值变化。时间差分（TD）误差（这里不做奖励折扣）是：

$$\delta_t = r_{t+1} + V_\phi(h_{t+1}) - V_\phi(h_t)$$

轨迹 B 的最后三步，奖励都是 0：动作 a₃ 前价值 0.3，后 0.6，δ₃ = +0.3，这一步让情况变好了；a₄ 前 0.6，后 0.4，δ₄ = −0.2；a₅ 前 0.4，之后轨迹结束，价值为 0，δ₅ = −0.4。虽然 B 最终失败，但 a₃ 这一步被识别为有帮助。

6. 广义优势估计（GAE）

后面几步的误差应该怎样影响对 a₃ 的评价？GAE（Schulman 等，ICLR 2016）用一个系数 λ 把后续误差按几何级数衰减后加起来。取 λ = 0.5，每往后一步权重减半：

$$\hat A_3 = 0.3 + 0.5\times(-0.2) + 0.25\times(-0.4) = 0.1$$

实际计算时从后往前递推：$\hat A_t = \delta_t + \lambda \hat A_{t+1}$，最后一步之后没有误差。

7. 替代方案：过程奖励模型

过程奖励模型（PRM）用人工标注学习"每一步是否正确"，作为价值的替代。Lightman 等（2023）的 Let's Verify Step by Step 里有一个例子：从 5x = 6x − 14 推出 x = 14 是对的，标注员把后面写出的"x = 7"标为错误。

三、同步与异步 RL

同步 RL 中，一批里所有轨迹都跑完，才开始更新策略。Agent 的轨迹长短差别很大，先跑完的 GPU 只能等着；更新结束后，下一批才开始。

异步 RL（AReaL，Fu 等，2026）让 rollout 工作节点一直生成，学习节点用已经完成的轨迹更新，两者重叠进行。代价是：有些完成的轨迹来自较早版本的策略。

四、让策略更新保持稳定

1. 旧策略生成的 rollout

一条 rollout 完成时，学习节点可能已经更新到了新策略。用 μ 表示生成 rollout 的策略，$\pi_\theta$ 表示正在更新的策略，这条 rollout 就"过时"了。例子：在某个历史下，三个候选动作"显式检查 None"、"用 get(..., 3)"、"保留原代码"，在 μ 下概率分别是 0.40、0.40、0.20，在 $\pi_\theta$ 下是 0.70、0.20、0.10。

2. 重要性采样

在固定历史 h 下，按样本在当前策略下的概率与在行为策略下的概率之比来重新加权：

$$\mathbb{E}_{a\sim\pi_\theta}[R(a)] = \mathbb{E}_{a\sim\mu}\Big[\frac{\pi_\theta(a\mid h)}{\mu(a\mid h)} R(a)\Big]$$

正确的修改：0.70/0.40 = 1.75；不完整的修改：0.20/0.40 = 0.50。

3. 长轨迹让比值失控

整条轨迹的比值是每一步比值的乘积（环境动态不变，可以约掉）：

$$w(\tau\mid x) = \frac{p_\theta(\tau\mid x)}{p_\mu(\tau\mid x)} = \prod_t \frac{\pi_\theta(a_t\mid h_t)}{\mu(a_t\mid h_t)}$$

每一步只差一点点，比如比值 1.05，乘 100 次就是 1.05¹⁰⁰ ≈ 132。方差会非常大，少数几个样本就能主导整个更新。CTPO（Zhang 等，2026）在使用工具的数学题 rollout 上观察到，累积比值 $\rho_t^{cum}$ 的分布随位置越往后越分散。

早先的动作还会改变后面的历史。比如 μ 以 40% 的概率"加一个 None 检查"，$\pi_\theta$ 只有 10%。代码里有了这个检查之后，下一步"跑测试"在两个策略下都是 50%，这一步的比值是 1。但当前策略到达这个历史的可能性只有 0.10/0.40 = 0.25 倍。

不同方法在计算权重时用到回答中的哪些动作：PPO 和 GRPO 只用当前动作；CTPO 用到第 t 步为止的所有动作；完整比值用全部动作；GSPO 用全部动作并按长度归一化。DAPO 和 CISPO 也只用当前动作的比值，只是裁剪规则不同。

4. 裁剪

过时的 rollout 可能得到很大的权重，所以要限制每次更新的幅度。以 token 为单位，比值是 $\rho_t = \pi_\theta(u_t\mid u_{<t}) / \mu(u_t\mid u_{<t})$，裁剪就是把超出上下界的值换成最近的边界：$c_t = \mathrm{clip}(\rho_t, \ell, u)$，例如 ℓ = 0.8，u = 1.2。

PPO 和 CISPO 的用法不同：

$$J_{PPO}(\theta) = \mathbb{E}_t\big[\min(\rho_t \hat A_t,\ c_t \hat A_t)\big]$$ $$J_{CISPO}(\theta) = \mathbb{E}_t\big[\mathrm{sg}(c_t)\,\hat A_t \log \pi_\theta(u_t\mid u_{<t})\big]$$

PPO 把裁剪后的比值放在取最小值里；CISPO 把它当作固定的权重（sg 表示梯度计算时把 $c_t$ 当常数）。要最小化的损失是 −J。

PPO 的效果（ε = 0.2）：对于有帮助的动作（优势为 +1），比值超过 1.2 之后不再有额外收益，不会把它的概率推得太高；对于没帮助的动作（优势为 −1），比值低于 0.8 之后不再有额外收益，不会把它的概率压得太低。

5. 参考模型 KL 与熵奖励

KL 惩罚阻止策略离一个固定的参考模型太远：$\max_\theta J_{policy} - \beta D_{KL}(\pi_\theta \,\|\, \pi_{ref})$。这里有两个不同的模型：rollout 策略 μ 生成训练批次，是重要性比值的分母；参考模型 $\pi_{ref}$ 保持固定，作为锚点。

熵奖励鼓励更宽的下一个 token 分布：$\max_\theta J_{policy} + \alpha H(\pi_\theta)$。更宽的分布有助于 Agent 尝试其他动作，但不保证这些动作有用。

五、任务选择与奖励可靠性

1. 没有信息的组

每个任务采样四条轨迹。全部失败 [0,0,0,0]，减去平均后全是 0；全部成功 [1,1,1,1]，也全是 0；只有结果混合 [0,1,0,1]，减去平均 0.5 后得到 −0.5、+0.5、−0.5、+0.5。全为零的组无法提供比较。

为什么所有轨迹都失败？要先看发生了什么再决定怎么办。可能是验证器有问题，一个正确的解法被拒绝了，要检查需求和失败的测试；可能是模型目前还做不到，看看更强模型的示范能否成功；也可能是缺乏探索，所有尝试都在重复同一种思路，检查轨迹之间是否有差异。

2. 假阴性：正确的解法被判错

回到修 bug 的任务。某个候选方案四种情况全部正确，但它的实现代码写法不同。如果验证规则要求代码里必须出现 value is None 这个短语，它就会被拒绝。这是假阴性。应该检查行为，而不是某个偶然的写法。

假阴性的后果：一是奖励噪声，等价的解法因为措辞或实现细节得到不同的奖励，模型会去拟合这些无关的差别。二是基准饱和，评估器拒绝正确解法，分数就会停在 100% 以下。2025 到 2026 年的审计发现：SWE-bench Verified 的进展在 80.9% 附近放缓，剩下的很多失败源于有缺陷的测试；τ-bench 航空子集约 70%，受限于不一致的任务；零售子集约 92%，受限于标注错误（τ-bench 后来修正了这些任务）。

3. 假阳性与奖励作弊

保持同样的任务要求，但假设训练时只测试 retries=0 这一种输入。候选方案直接 return 0，唯一的测试通过了，奖励为 1。但缺失和 None 应该返回 3，它返回 0；2 应该返回 2，它也返回 0。假阳性奖励了一个错误的解法，训练会学会钻这个空子。

编程 Agent 里常见的作弊途径：能上网，就去网上找公开的答案；能看 Git 历史（包括未来的提交），就找到后来的修复直接复制；有模型 API 密钥，就调用另一个更强的模型来拿答案或训练数据；能访问测试或测试运行器，就让测试通过而不去修 bug。MAI-Thinking-1 的报告记录了网页、Git 和测试方面的作弊；PostTrainBench 记录了一个 Agent 在明确被禁止的情况下，用评分用的密钥去生成训练数据。

所以要独立检查进展。上面那个"永远返回 0"的补丁训练奖励是 1，却只通过了四种情况中的一种。要同时看三样东西：训练奖励（在训练验证器上的成功率）；独立成功率（在没见过的任务上，以及训练验证器漏掉的行为上）；成本和失败（查看工具调用、回归、重复动作）。如果奖励上升，独立指标却没有改善，就去翻轨迹找捷径。

4. DAPO 的动态采样

既然奖励全相同的组优势为零，DAPO（Yu 等，2025）就只保留结果混合的组，不断采样直到凑满一批。例子：任务 A [0,0,0,0] 跳过；任务 B [0,1,0,1] 保留；任务 C [1,1,1,1] 跳过；任务 D [0,0,1,0] 保留；目标是 2 组，凑满了就更新策略。混合组里的所有轨迹都保留，包括失败的。

5. 部分奖励

部分得分是一种辅助奖励，在完全成功之前就对进展给予反馈。例子：任务要求通过 4 项检查，每通过一项加 0.25。四条轨迹分别通过 0、1、2、1 项。只看成功与否，奖励全是 0，优势全是 0；加上部分奖励后是 0、0.25、0.50、0.25，平均 0.25，优势为 −0.25、0、+0.25、0。不同的部分得分能减少优势为零的组。

但模型可能学会提高辅助奖励，而不是改进任务本身。OpenAI 公布过两个案例：一个 bug 让表面上的网页工具调用也能得分，结果 GPT-5.1 把浏览器当计算器用，还表现得好像自己搜索过；为一个俏皮的"Nerdy"人设打分时，含有"goblin"或"gremlin"的比喻得分更高，结果这类生物比喻变得更常见，即使没有这个人设提示时也是如此。

6. 探索崩溃

在某个历史下，训练前三个动作的概率是 A 0.20、B 0.60、C 0.20，训练后变成 0.01、0.98、0.01。几乎每次采样都选 B，其他选择很少被尝试。熵奖励能鼓励尝试其他动作；也要检查轨迹之间是否真的有差异。

六、向教师学习

1. 课程与热启动

学生模型很少成功时，教师可以提供成功的轨迹。步骤是：先从成功的解法示范中学习，作为热启动；再练习模型有时能成功的任务；随着模型进步逐步提高难度。这就是课程学习。要把早先的任务保留在训练数据里，并用固定的评估集衡量进步。

2. 蒸馏

蒸馏（Hinton 等，2015）训练学生去匹配教师的动作概率分布，而不只是模仿教师选出的那一个动作。在教师保存的一条轨迹上，某个历史 $h_3$ 处，教师给动作 $a_3$ 80% 的概率，给另一个动作 20%，这就是目标分布 $q(\cdot\mid h_3)$。问题是：学生自己行动时，犯的错误会把它带到这批训练数据里没有的历史上。

3. 在线策略蒸馏

在线策略蒸馏（Agarwal 等，ICLR 2024）让学生自己生成训练用的历史，再请教师在这些历史上给出目标分布。这样学生在自己真正会遇到的状态上得到指导。每一步都有目标，反馈是密集的。

目标函数用反向 KL。例子：在同一个 $h_3$，学生给两个动作各 0.5，教师给 0.8 和 0.2：

$$D_{KL}(\pi_\theta \,\|\, q) = 0.5\log\frac{0.5}{0.8} + 0.5\log\frac{0.5}{0.2} \approx 0.223$$

在学生生成的历史分布 $d_\mu$ 上取平均并最小化：

$$\mathcal{L}_{OPD} = \mathbb{E}_{h\sim d_\mu}\big[D_{KL}(\pi_\theta(\cdot\mid h)\,\|\,q(\cdot\mid h))\big]$$

4. 在线策略自蒸馏

OPSD（Self-Distilled Reasoner，Zhao 等，2026）不需要更强的外部教师。教师是起始模型的一个冻结副本，但它的输入除了任务和历史之外，还多给一个经过验证的正确解法。有了答案做参考，它在学生自己的历史上能给出更好的目标概率，再用这些概率训练学生。

功劳分配与价值估计

  • MIXER（Ranzato 等，ICLR 2016）：较早把 REINFORCE 用在序列生成上的工作，先用交叉熵训练，再逐步把序列末尾越来越长的部分换成用 REINFORCE 按整句的评价指标优化，缓解暴露偏差。
  • InstructGPT（Ouyang 等，2022）：先用标注员写的示范做监督微调，再收集标注员对多个输出的排序，训练奖励模型，最后用基于人类反馈的强化学习（RLHF，用 PPO）继续微调 GPT-3。人工评估中，1.3B 的 InstructGPT 比 175B 的 GPT-3 更受欢迎。
  • 广义优势估计（GAE，Schulman 等，2015）：策略梯度的两大难题是需要大量样本，以及数据不断变化时难以稳定提升。GAE 用价值函数大幅降低梯度估计的方差，代价是引入一些偏差；具体做法是对多步的时间差分误差做指数加权，类似 TD(λ)。
  • Let's Verify Step by Step（Lightman 等，2023）：比较结果监督（只对最终答案给反馈）和过程监督（对每一步推理给反馈），发现在 MATH 数据集上过程监督明显更好，过程监督的模型在代表性子集上解出 78% 的题。论文还公开了 80 万条逐步的人工标注 PRM800K。本讲"过程奖励模型"一节的出处。

同步与异步 RL、重要性采样

  • AReaL（2025）：大多数大模型 RL 系统是同步的，生成和训练交替进行，同一批 rollout 由同一个模型生成。这样训练稳定，但系统效率很低：必须等这一批里最长的输出生成完才能更新，GPU 大量空闲。AReaL 把生成和训练完全解耦，生成端不停地产生新输出，训练端凑够一批就更新，因此数据会来自稍旧的策略，需要用重要性采样等方法修正。
  • CTPO（2026）：讨论离线策略梯度中重要性采样比值的设计。逐 token 的比值（PPO、GRPO 的做法）忽略了前缀状态分布的差异，有偏差；整条序列的比值能精确修正，但每个 token 的比值连乘，方差极大；GSPO 用长度归一化提高了数值稳定性，但又偏离了精确修正。论文提出按"到当前位置为止的累积 token 比值"来做修正，在偏差和方差之间折中。本讲"长轨迹让比值失控"一节讨论的就是这个问题。
  • PPO（Schulman 等，2017）：交替进行"与环境交互采样"和"用随机梯度优化一个替代目标"。标准策略梯度每个样本只做一次更新，PPO 的新目标允许在同一批数据上做多轮小批量更新；它保留了信赖域方法（TRPO）的部分好处，但实现简单得多。
  • DeepSeekMath（GRPO，2024）：见第九讲。
  • MiniMax-M1（CISPO，2025）：第一个开放权重的大规模混合注意力推理模型，总参数 4560 亿，每个 token 激活 459 亿，原生支持一百万 token 上下文。RL 训练中提出 CISPO 算法：不裁剪 token 的梯度更新，而是裁剪重要性采样的权重，这样每个 token 都能贡献梯度。
  • GSPO（Qwen 团队，2025）：不再用逐 token 的重要性比值，而是基于整个序列的似然定义比值，并在序列层面做裁剪、奖励和优化。比 GRPO 训练效率更高、表现更好，尤其能稳定混合专家模型的 RL 训练，Qwen3 的提升部分归功于它。
  • DAPO（2025）：公开了一个大规模 RL 系统，用 Qwen2.5-32B 基础模型在 AIME 2024 上达到 50 分。名字来自其中两项技术：解耦的裁剪（上下界分开设置）和动态采样（过滤掉全对或全错、没有梯度的组），另外还有 token 级的策略梯度损失和对超长回答的奖励塑形。训练代码基于 verl 框架开源。

奖励的可靠性与奖励作弊

  • OpenAI 的两篇 SWE-bench Verified 文章：前一篇介绍了经人工核实的 SWE-bench 子集，后一篇说明他们为什么不再用它评估。本讲用它们说明"正确的解法被判错"这类假阴性问题。
  • SABER（Cuadron 等，2025）：分析 τ-Bench 和 SWE-Bench Verified 的执行轨迹，把步骤分成会改变环境的"变更"步骤和不改变环境的步骤。发现变更步骤上每多一次关键偏离，成功的几率在航空领域最多下降 92%，在零售领域最多下降 96%；非变更步骤上的偏离几乎没有影响。上下文越长，Agent 越容易偏离角色、依据过时的约束行动。
  • τ-bench 任务修复（τ³-Bench 博客）：审核并修复了航空和零售领域的 50 多个任务，问题包括期望动作写错、用户指令有歧义、约束不可能满足、缺少兜底行为。大部分修复直接来自 SABER 论文整理出的 τ-Bench Verified。
  • Lilian Weng：Reward Hacking in Reinforcement Learning（2024）：奖励作弊指 Agent 利用奖励函数的漏洞或歧义拿到高奖励，却没有真正学会或完成预期任务。文章系统整理了 RL 任务、LLM 任务和现实生活中的例子，分析成因（环境不完美、RLHF 被钻空子、评估器被钻空子、上下文中的奖励作弊等），并介绍缓解办法。
  • OpenAI：用生产环境评估应对"评估意识"（2025 年 12 月）：模型可能意识到自己正在被评估，从而表现得和真实使用时不同。文章介绍了一个从以往真实部署场景中提取评估用例的流程，规模可扩展、保护隐私，用来更早发现模型的不良行为。课程给这条链接起的标题是"计算器作弊与生产环境评估"。
  • Where the goblins came from（OpenAI）：课程列出的另一篇 OpenAI 文章，网页无法抓取，内容未核实。
  • MAI-Thinking-1 技术报告：见第八讲。
  • PostTrainBench（2026）：考察 LLM Agent 能否在有限算力（一张 H100 跑 10 小时）下自主完成后训练，比如把 Qwen3-4B 在 AIME 上的表现调上去。不给任何预设策略，让 Agent 自己上网查资料、做实验、整理数据。按摘要，前沿 Agent 能取得实质性进展。

向教师学习

  • Curriculum Learning（Bengio 等，ICML 2009）：按由易到难的顺序给模型训练样本，能加快训练并得到更好的结果。本讲"课程与热启动"一节的出处。
  • Distilling the Knowledge in a Neural Network（Hinton 等，2015）：把一组模型的知识压缩进一个单一模型，让学生模型学习教师输出的"软"概率分布，而不只是正确答案。
  • On-Policy Distillation / GKD（Agarwal 等，2023）：普通的知识蒸馏在固定的输出序列上训练学生，和学生推理时自己生成的序列分布不一致。GKD 让学生在自己生成的序列上训练，由教师对这些序列给出反馈，还能换用其他的师生损失函数，并方便地和 RL 微调结合。
  • Self-Distilled Reasoner（OPSD，2026）：在线策略蒸馏通常需要一个单独的、往往更大的教师模型，也没有利用推理数据集里现成的标准解答。OPSD 让同一个模型既当教师又当学生，区别只在上下文：教师能看到"特权信息"，比如标准的推理过程，学生看不到，教师为学生自己生成的轨迹提供逐 token 的监督。
  • Policy Invariance Under Reward Transformations（Ng、Harada、Russell，ICML 1999）：证明了一种特定形式的奖励塑形（基于势函数的塑形）不会改变最优策略，这是安全地添加中间奖励的理论依据。本讲"部分奖励"一节引用了它。

八、小结

有用的反馈：用组内比较、critic 或过程奖励来分配功劳。稳定的更新：清楚每条数据是哪个策略生成的，控制样本对模型的影响强度（重要性比值、裁剪、KL）。可靠的奖励：让任务难度与模型能力匹配，验证真正想要的行为，警惕假阴性、假阳性和作弊。下一讲的主题是 RL 系统。
