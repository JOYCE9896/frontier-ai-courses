第三讲：长上下文 Agent 的上下文管理

Agent 的历史越来越长时，模型结构、训练、推理缓存和上下文压缩分别怎样应对

主讲：Graham Neubig · 2026 年 9 月 1 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容）

一、问题从哪里来：Agent 的上下文会不断变长

上一讲说过，Agent 是一个循环：每一轮，模型要重新读一遍全部上下文，然后输出一个动作，动作的结果再追加进上下文。这意味着上下文只增不减。

幻灯片用一组数字说明这件事有多贵。假设固定前缀（系统提示和工具定义）是 6K token，每轮新增 5K。第 1 次调用输入 6K，第 2 次 11K，第 3 次 16K，第 4 次 21K，第 5 次 26K。每次调用的输入长度线性增长，但把每次的输入加起来，累计处理量是 6K、17K、33K、54K、80K，按平方速度增长。

Agent 的上下文里都装了什么？课程统计了 1,500 次 OpenHands 会话，平均每次会话 77,922 个 token。其中工具返回的结果占 37%，系统提示和工具定义占 23%，工具调用占 20%，用户消息和模型推理各占 9%，其余约 2%。工具结果是最大的一块，比如一份很长的日志或一个大文件的内容。

Graham 在课上补充了几处细节。这些会话都是解决单个任务的短会话，不是那种连续好几天的长会话；他自己就经常和一个编程 Agent 连续工作一整天。系统提示和工具定义占 23%，这个比例偏大，因为 OpenHands 的系统提示有一万五到一万八千 token，他说 OpenHands 对"应该怎么干活"有很多自己的主张；一般编程 Agent 的这部分在八千到两万 token 之间，取决于加载了多少工具。另外，模型推理占 9%，直接回复用户只占 2%，也就是说模型用在思考上的 token 大约是用在跟人说话上的五倍。

他还提醒，用 Claude Code、Codex 这类产品时很容易把这一切当成理所当然，但服务商其实在做很难的工程：一个几万亿参数的模型，要在几秒内一次次地响应。以 Codex 为例，据他说有两千五百万日活用户，每个人每隔几秒就发一次请求。

由此产生两个挑战。一是容量：模型能不能真正用上这么长的上下文里需要的证据？这由模型结构、位置编码和训练方式决定，需要评估来测量。二是效率：系统能不能负担得起？这由注意力计算、KV 缓存占用的内存、缓存复用和压缩决定，影响成本和延迟。

二、背景：模型推理是怎么进行的

1. 推理服务的组成

一个请求（提示词加生成参数）先进入调度器，调度器负责排队、把多个请求合成一批、分配到合适的机器。然后分两个阶段计算：预填充（Prefill）一次性处理提示词的所有位置；解码（Decode）每一步只生成一个新 token，循环进行。两个阶段之间靠 KV 缓存连接，它是每个请求持续存在的状态。最后生成的 token 以流式返回。这个框架来自 DistServe（Zhong 等，OSDI 2024）。

2. 什么是 KV 缓存

Transformer 在处理每个 token 时，会为它算出一个 Key 向量和一个 Value 向量（后面讲注意力时会解释它们的用途）。生成新 token 时，新 token 需要和之前所有 token 的 Key、Value 做计算。如果每生成一个 token 都把前面所有 token 重新算一遍，会非常浪费。所以系统把算过的 Key 和 Value 存下来，这就是 KV 缓存。

预填充阶段为提示词里的每个位置算出 K、V 并写入缓存，这个阶段计算量大，延迟随提示长度增长。解码阶段每步读取缓存、算出一个新 token、再把新 token 的 K、V 追加进去。解码必须一步步顺序进行，瓶颈主要在于从显存读取缓存的带宽。

3. 衡量推理服务的指标

  • TTFT（Time To First Token）：从请求到达到第一个 token 输出的时间，主要由预填充决定。
  • TPOT（Time Per Output Token）：相邻两个输出 token 之间的间隔，由解码决定。
  • 吞吐量：单位时间内完成的 token 数或请求数。
  • 成本：输入 token、命中缓存的输入 token、输出 token 分别计费。

Graham 打开 OpenRouter 的页面举例：同一个 GLM 5.2 模型，不同服务商的输出速度差别极大，最慢的一家每秒只有三个 token 左右，快的几家每秒几百个。他还指出，看重哪个指标取决于用法。你在命令行里和编程 Agent 来回交互时，会很在意 TTFT 和 TPOT；如果 Agent 在后台跑一整夜的任务，就几乎不在乎速度，更在乎吞吐量和成本。他自己的公司也在为编程 Agent 提供服务，和推理服务商谈合作时，对方常会先问"你更看重哪一项"，再据此调整系统。

4. 注意力的计算

注意力是 Transformer 的核心运算。输入矩阵 $X$ 的每一行是一个 token 的向量。先用三个矩阵做线性变换，得到查询 $Q = XW_Q$、键 $K = XW_K$、值 $V = XW_V$。然后：

$$A = \mathrm{softmax}\left(\frac{QK^\top}{\sqrt{d_k}} + M\right), \quad O = AV$$

这个式子的意思是：每个 token 用自己的查询去和所有 token 的键做点积，得到相关程度的打分；除以 $\sqrt{d_k}$ 是为了让数值不至于太大；$M$ 是因果掩码，未来位置设为负无穷，保证每个 token 只能看到它之前的内容；softmax 把打分变成加起来等于 1 的权重；最后用这些权重对所有值向量加权求和，得到输出。

问题在于，$n$ 个 token 两两之间都要打分，计算量是 $O(n^2)$。上下文长度翻倍，这部分计算翻四倍。

5. 标称长度不等于有效长度

模型宣称支持多长的上下文，不代表它真能用好这么长的内容。幻灯片引用了 Greg Kamradt 在 2023 年对 GPT-4 做的"大海捞针"测试：在一段很长的文字的不同位置藏一句关键信息，再问模型这个信息。结果显示，信息放在某些位置、或者上下文很长时，模型找不到它。

Graham 解释了这个测试的具体做法：研究者拿了一大堆 Paul Graham（创业者、Y Combinator 的负责人）写的文章，在中间某处插入一句"旧金山吃三明治最好的地方是某某"，然后问模型"旧金山吃三明治最好的地方是哪里"。文章越拼越长，较弱的模型在超长上下文下就开始答错。现在更常用的同类基准是 RULER 和 HELMET。

他问学生长时间用 Agent 时见过哪些失败。学生说最常见的是忘了前面说过的话，比如对话中途交代过不要做某件事，它后来还是做了。第一讲里 Agent 删除邮件的事故就是这一类。在 Agent 场景里这个问题尤其严重，因为用户的指令是在对话过程中一条条追加进来的。

三、为长上下文设计的模型结构

1. 基本思路：局部计算为主，定期全局查看

标准注意力是全局的，每个 token 都和整个序列做比较。另一种做法是局部计算：每个 token 只看附近固定数量 $w$ 个 token，计算量从 $O(n^2)$ 降到 $O(wn)$，当 $w$ 固定时是线性的。但只看局部会丢失远处的信息。

Graham 让学生估算一下规模：现在主流模型的上下文长度在 256K 到一百万之间，各家都在往一百万靠，谁也不想在别人都有一百万时自己只有 256K。一百万个 token 两两比较，是 $10^{12}$ 次，也就是一万亿次比较；每次比较又是两个高维向量相乘，一条序列的计算量会到 $10^{20}$ 左右的量级。几乎所有解决办法都属于同一类：给每个位置"最多和多少个位置比较"设一个固定上限。这个上限不一定是一个局部窗口，只要是固定的数就行。

现在的长上下文模型普遍采用混合结构：连续若干层做便宜的局部计算，然后插一层能访问完整历史的全局计算，如此重复。幻灯片列出了几个 2026 年的模型，局部层和全局层的比例大多在 3:1 到 5:1 之间：

这些结构用到了四种反复出现的机制：滑动窗口注意力、线性注意力或循环模型、稀疏注意力、KV 压缩。下面逐个说明。

2. 滑动窗口注意力

注意力公式不变，只改掩码：第 $i$ 个位置只能看到第 $i-w+1$ 到第 $i$ 个位置，窗口外的都设为负无穷。计算量从 $O(n^2)$ 降到 $O(nw)$。代价是这一层没法直接取到远处的 token。这种做法见于 Longformer（Beltagy 等，2020）。Graham 补充了一个要点：虽然每一层只看前面一两个块，但上一层的每个块本身已经汇总了它前面一两个块的信息，所以层数叠加之后，能看到的范围会逐层扩大。

3. 从 softmax 注意力到线性注意力，再到 Delta 规则

这一部分是本讲数学最多的地方，课程按五步演进来讲，每一步只改一处。

第一步，标准 softmax 注意力。第 $t$ 步的输出是：

$$a_{ti} = \frac{\exp(q_t^\top k_i/\sqrt{d_k})}{\sum_{j=1}^{t}\exp(q_t^\top k_j/\sqrt{d_k})}, \quad o_t = \sum_{i=1}^{t} a_{ti} v_i$$

它要保留之前每一个 token 的 $k_i, v_i$，缓存随长度增长，每解码一步要做 $t$ 次比较。

第二步，线性注意力（Katharopoulos 等，ICML 2020，论文标题是 Transformers are RNNs）。把 softmax 权重换成简单的点积 $q_t^\top k_i$，就可以交换求和顺序：

$$o_t = \sum_{i=1}^{t} (q_t^\top k_i) v_i = \Big(\sum_{i=1}^{t} v_i k_i^\top\Big) q_t = S_t^\top q_t$$

括号里的部分可以记成一个固定大小的矩阵 $S_t$，并且可以递推更新：$S_t = S_{t-1} + k_t v_t^\top$。这样不管历史多长，模型只需要保存这一个矩阵，像循环神经网络一样逐步更新。问题是每次都是往里"加"，旧的信息不会被擦掉，不同内容会互相干扰。

第三步，DeltaNet（Schlag 等，ICML 2021）。写入前先用当前记忆预测一下 $k_t$ 对应的值 $\hat v_t = S_{t-1}^\top k_t$，算出误差 $e_t = v_t - \hat v_t$，只把误差写进去：

$$S_t = S_{t-1} + \beta_t k_t e_t^\top$$

$\beta_t$ 在 0 到 1 之间，控制修正力度。这样只沿着 $k_t$ 的方向修正，和它无关的记忆保持不变。

第四步，Gated DeltaNet（Yang 等，2024）。在修正之前，先把整个记忆乘一个衰减系数 $\alpha_t$（0 到 1 之间），让旧信息整体淡化：$\tilde S_{t-1} = \alpha_t S_{t-1}$。$\alpha_t$ 管整体保留多少，$\beta_t$ 管针对性修改多少。$\alpha_t = 1$ 时就退回 DeltaNet。

第五步，Kimi Delta Attention（KDA，Kimi 团队 2025）。把单个衰减系数换成一个向量，每个特征维度有自己的衰减速度，有的信息记得久，有的忘得快：

$$S_t = (I - \beta_t k_t k_t^\top) D_t S_{t-1} + \beta_t k_t v_t^\top, \quad D_t = \mathrm{Diag}(\alpha_t)$$

所有维度衰减速度相同时，KDA 就退回 Gated DeltaNet。

Graham 对这几步的直观解释是这样的。softmax 的作用是把一组任意实数变成加起来为 1 的权重，从而能在很多历史 token 里只关注少数几个相关的。这是注意力最大的卖点。线性注意力去掉了 softmax，也就失去了"相互比较、挑出重点"的能力，表达力变弱；换来的是可以利用矩阵乘法的结合律，把全部历史压成一个状态矩阵 $S_t$。这个矩阵本身就是一个从查询映射到值的线性函数，和注意力做的事情一样，而且每来一个新 token 只需要常数时间更新一次，于是整体复杂度从 $O(n^2)$ 降到 $O(n)$，连窗口大小 $w$ 都不需要了。

后面几种改进，本质上都是想让这个状态矩阵更好地预测"如果做完整注意力，应该得到什么值"。DeltaNet 的 $\beta_t$ 相当于学习率：先看当前矩阵对 $k_t$ 会给出什么值，和真正的 $v_t$ 相比算出误差，再朝减小误差的方向把矩阵推一小步。Gated DeltaNet 的衰减是为了解决另一个问题：线性注意力没有机制阻止很久以前的某个古怪的键持续影响后面的预测，每一步都让矩阵整体衰减一点，就相当于给久远的历史打折扣，衰减越强，模型越"局部"。Qwen 系列用的是 Gated DeltaNet；GLM 和 Kimi 用的是每个维度各自衰减的 KDA。课上跳过了 Mamba，Graham 说它的思路和这些很像，只是数学更复杂一些。

4. 稀疏注意力

稀疏注意力让每个查询只看一部分键，再在这部分里做 softmax。有两种选法。固定模式与输入无关，比如"附近窗口内的位置，加上几个固定的全局位置"，成本可预测，但不能根据查询内容调整（Longformer 采用这种）。内容相关模式由一个学出来的选择器 $g$ 给每个键打分，挑出分数最高的 $K$ 个（DeepSeek Sparse Attention，2025），能按需检索，但选择器选错了，相关的键就被漏掉。

课上 Graham 讲得更具体一些。固定模式最早见于 OpenAI 大约五年前的稀疏注意力论文，比如每隔 512 个 token 才做一次全局注意力。这样复杂度仍然是序列长度的平方，但计算量少了 512 倍，已经足以处理需要的长度。内容相关模式的做法是：先用一种极便宜的方式粗算一遍注意力，比如把查询和键投影到非常小的维度上再算，挑出分数最高的 $K$ 个位置，再只在这 $K$ 个位置上做完整注意力。有学生问粗算时用什么相似度，Graham 说一般是点积，是否先做归一化他也不确定。两种方式他都见过被广泛使用：固定模式只要写一个核函数就能跑，非常便宜；内容相关模式需要算两遍，但可能更准。

5. KV 压缩

另一条路是减小缓存本身。GQA（Ainslie 等，2023）让多个注意力头共用一组 K、V。MLA（DeepSeek-V2，2024）更进一步：缓存里只存一个低维的潜在向量 $c_t^{KV} = W^{D} z_t$，用的时候再通过每个头各自的矩阵还原出这个头的 K 和 V：$k_t^{(h)} = W^{UK(h)} c_t^{KV}$，$v_t^{(h)} = W^{UV(h)} c_t^{KV}$。

Graham 补充了两种压缩的区别。GQA 减少的是 K、V 头的数量，通常是把查询头数除以 4 或 8；只有一组 K、V 的极端情况叫多查询注意力（MQA）。这之所以重要，是因为缓存的只有 K 和 V，没有 Q，KV 缓存小了，一张 GPU 上能同时服务的请求就多了。MLA 则不减少头数，而是把每个头的 K、V 变小。两者也可以同时使用。

四、怎样训练长上下文模型

1. 由短到长的训练流程

长文本数据少、训练贵，所以通常分三段：先用 4K 到 8K 的短序列做预训练，数据多、成本低；再用长文档和拼接序列做继续训练，拉到 32K 到 128K；最后用任务轨迹和合成课程做长度适配，达到 128K 以上。

Graham 解释了为什么难：128K 个连贯的 token 已经比绝大多数维基百科条目长得多，差不多是一本书的长度，而互联网上的书并没有那么多。他还特别说明，把许多短文档拼接成一条长序列可以提高训练效率，也能让模型习惯处理窗口靠后位置的内容，但学不到跨文档的全局连贯，因为你拼在一起的十篇文档之间本来就不该互相关注。要真正适应超长上下文，必须有连贯的长数据。

2. 位置编码：模型怎么知道 token 的顺序

注意力本身不区分顺序，把输入打乱，结果只是跟着重新排列。所以需要位置编码告诉模型每个 token 在第几位。位置编码的选择，直接决定模型能不能处理比训练时更长的文本。

  • 绝对位置编码：给第 $t$ 个位置一个向量 $p_t$，加到词向量上：$z_t = E[x_t] + p_t$。可以是学出来的固定大小的表，也可以用正弦函数算出来：$p_{t,2\ell} = \sin(t/\omega_\ell)$，$p_{t,2\ell+1} = \cos(t/\omega_\ell)$，$\omega_\ell = 10000^{2\ell/d}$。
  • 旋转位置编码（RoPE，Su 等）：不加向量，而是把 $Q$ 和 $K$ 的每一对维度按位置旋转一个角度，$\tilde q_i = R(i) q_i$，$\tilde k_j = R(j) k_j$。两者点积时，旋转会抵消成 $q_i^\top R(j-i) k_j$，打分只取决于两个 token 的相对距离。$V$ 不变。
  • 无位置编码（NoPE，Kazemnejad 等，NeurIPS 2023）：什么都不加，靠因果掩码或循环结构本身隐含的顺序。这样就不存在"超出训练长度的位置没见过"的问题，但仍然需要训练模型掌握长距离的行为。Kimi K3 用 NoPE 加循环的 KDA。

NoPE 这一条很反直觉。Transformer 入门课里通常会讲：没有位置编码，第 1 个位置的"cat"和第 5 个位置的"cat"表示完全相同，模型分不清顺序。Graham 说这在最初的编码器加解码器结构里可能成立，但在今天的因果掩码模型里已经不成立了。他请学生猜原因，有学生答对了：因为因果掩码。第 2 个位置的"cat"只能看到它前面 1 个 token，第 5 个位置的"cat"能看到前面 4 个 token，从第一层注意力开始，两者的表示就已经不同了。如果模型里还有 Gated DeltaNet 这类带衰减的结构，本身就带有局部偏向，就更不需要位置编码。所以各家模型里，大约一半用 RoPE 或部分 RoPE，一半完全不用位置编码。对于双向注意力的模型，所有 token 互相可见，仍然需要位置编码。

3. 让 RoPE 支持更长的上下文

如果模型用 RoPE 训练到长度 $L$，直接用到更长的 $L'$，会出现训练时没见过的旋转角度。位置插值（Chen 等，2023）的做法是把位置按比例缩小：$R(t) \to R(t/s)$，$s = L'/L$。这样长位置的角度仍落在训练见过的范围内。

YaRN（Peng 等，ICLR 2024）改进了这一点。RoPE 的不同维度旋转速度不同：转得慢的维度（长波长）负责远距离位置，完全插值；转得快的维度（短波长）负责区分相邻 token，保持不变，否则近处的细节会被搞乱；中间的维度混合处理。YaRN 还调整了注意力温度，抵消长度扩展后注意力分布变得过于平均的问题。幻灯片提醒，温度公式 $\sqrt{1/\tau} = 0.1\ln s + 1$ 是在 LLaMA 模型上拟合出来的经验配方，不是通用常数。

Graham 解释了直接外推为什么不行。原因有两个：一是训练时从没见过相隔超过 $L$ 的两个 token 互相关注；二是 RoPE 只编码了相对距离，但因果掩码等其他因素也在影响模型，不能指望 RoPE 自己就能泛化到更长的序列。常见的修复方法是调整 RoPE 里控制每步旋转角度的参数 $\theta$，按扩展的倍数把位置"拉伸"。YaRN 的思路和 KDA 有相似之处：让一部分维度负责远距离、一部分维度负责近距离，因此不同频率的维度拉伸程度不同。

5. 长上下文数据

数据有四种来源：长文档（书、代码库、多文档语料），结构自然连贯；拼接样本，把多条短数据拼成长序列，利用率高，但要处理好边界，防止不同样本之间互相泄露信息；Agent 轨迹，包含动作和观测，能教会模型长程恢复、状态跟踪和工具使用；合成任务，可以把证据和干扰信息放在设计好的位置上。

幻灯片比较了 Kimi K3、GLM-5、Nemotron 3 Ultra、DeepSeek V4 的数据配方，总结出共同点：连贯的长文本来源，加上答案依赖远处证据的任务，加上逐步增加的长度。

Graham 说，这部分公开的细节很少。闭源公司（Anthropic、OpenAI、Google）连模型结构都不公开；开源模型必须公开结构，否则别人没法运行，所以它们保密的是数据配比和训练策略。从这些模型的技术报告里能看到的数据来源大致有：清洗过的书籍和视频文档、代码仓库文件、issue 和 PR、长文档问答、科研论文和技术报告，还有大量合成任务；长度通常按 8K、64K、256K、1M 这样逐级提高。他还见过有人用专利文本训练，因为专利数据公开且数量大，彼此之间还能相互关联。Agent 轨迹现在是一个很重要的来源，因为 Agent 只要跑一会儿就能产生很长的轨迹。

6. 上下文并行

序列长到一张卡放不下时，可以把序列切成 $P$ 段分给 $P$ 张卡，每张卡的内存降为 $O(nd_k/P)$。各卡在计算自己那块注意力的同时，把 K、V 沿环形传给下一张卡，通信和计算重叠进行。总计算量仍是 $O(n^2 d_k)$，结果是精确的，不是稀疏近似。代表方法是 Ring Attention（Liu 等，2023）和 Megatron 的上下文并行。

Graham 先问学生训练时还有哪些并行方式。回答是数据并行和模型并行。模型并行又分几种：专家并行把不同专家放在不同机器上；张量并行把参数矩阵切开；流水线并行把不同的层放在不同设备上。上下文并行对 Agent 格外重要，因为 Agent 需要在很长的上下文上训练，超过大约 32K 之后基本就离不开它。

他也提醒了一个实际的麻烦：做模型结构的人想用 KDA，做基础设施的人就得为 KDA 写一个支持上下文并行、能反向传播的计算核函数。他自己曾想对一个约 35B 的 Qwen 模型做上下文并行训练，结果发现网上找不到任何支持 Gated DeltaNet 的上下文并行核函数，只能自己写或者放弃。标准注意力和滑动窗口注意力都有现成的实现，难的是那些非标准的注意力。

五、提示缓存与 KV 缓存复用

1. Agent 的每次调用都共享前缀

Agent 第 2 次调用的输入，就是第 1 次的输入加上第 1 次的输出和工具结果。所以前面的部分完全一样，已经算过的 KV 缓存可以直接复用，只需要对新增部分做预填充。随着循环推进，可复用的前缀越来越长。这一思路见于 Prompt Cache（Gim 等，MLSys 2024）。

实测上，Prompt Cache 发现重新计算的开销增长得比加载缓存快，交叉点取决于硬件。2026 年的论文 Can I Buy Your KV Cache? 指出，一次性的预填充成本可以分摊给多次读取，每次调用的成本会逼近复用那一步的下限。课程也提醒：实际物理成本和服务商的 API 定价是两回事。

Graham 在课上说，到第 50 步时，如果什么优化都不做，可复用的前缀会是新增输入的 50 倍左右，缓存能省下的量非常可观。缓存之所以便宜，是因为只需要把存好的结果读出来，而不必重新计算，特别是 Transformer 里开销很大的前馈网络部分可以整个跳过。

Graham 问学生：运行 Agent 时，缓存命中率多少算好？有人说 80% 到 90%，有人说 95% 以上。他的经验是 90% 到 95% 说明一切正常，低于这个数，可能在哪里吃了亏。他还指出，输出 token 一般比输入贵五倍左右，所以输出和命中缓存的输入之间差了约 50 倍。

OpenRouter 还公布了各服务商的缓存命中率排名，差别明显。Graham 说这不完全说明服务商好坏，也可能和各家的负载类型有关，但有两个因素确实会影响命中率：一是缓存路由做得好不好，二是缓存多久被淘汰。服务商不会一直替你保留缓存，因为它占用大量显存。学生有人说接近一小时；Graham 记得 Anthropic 以前是 5 分钟，只要对话不停就一直在缓存里，停下来就会被淘汰，现在可以付一点额外费用延长到一小时。对用户不利的一点是：无论服务商的路由和淘汰策略做得多差，价格都一样，你可能只是因为缓存被过早清掉而多付钱。

有学生问服务商是否会分层存放缓存，热的放在 GPU 显存里，冷的放到内存或磁盘。Graham 说他不确定，这值得研究；另一位学生补充说，通常会从 GPU 卸载到 CPU 内存，因为显存太宝贵。Graham 还认为，服务商的内部方案很可能比开源库更精细，因为推理服务就是它们的核心竞争力。

3. 服务端如何管理缓存

  • 分页 KV 缓存（vLLM 的 PagedAttention，Kwon 等，SOSP 2023）：把缓存切成固定大小的块，用一张块表记录逻辑位置到物理位置的映射，和操作系统管理虚拟内存的方法相同，避免显存碎片。
  • RadixAttention（SGLang，Zheng 等，2023）：用基数树存储所有请求的前缀。新请求进来时，匹配已有的最长前缀直接复用，只追加后缀；两个请求共享一段前缀时，把节点拆开共享；显存不够时，淘汰最久没用的叶子节点。
  • 缓存感知路由（SGLang v0.4）：请求发给哪台机器，要同时考虑哪台机器缓存了最长的匹配前缀和它的排队长度。比如一台机器匹配 18K 但排队 2 个，另一台只匹配 2K 但空闲，路由器按"可复用前缀减去排队惩罚"打分决定。

Graham 介绍了这两个库的来历。vLLM 最初的核心创新就是 PagedAttention：把显存按块组织，一条序列的缓存可以分散在第 7、1、3 块，用索引串起来。这样可以同时并行生成很多序列，一条生成完毕就把它占的块整块释放。SGLang 最初的核心创新是 RadixAttention，专门用来复用已经缓存的前缀，当时主要针对 ChatGPT 这类聊天产品：用户接着上一轮继续聊，前面的对话就可以复用。现在它对 Agent 更重要，因为 Agent 的对话更长、请求更频繁。按 SGLang v0.4 的发布说明，缓存感知的负载均衡让吞吐量最多提高到 1.9 倍，缓存命中率提高到 3.8 倍。

4. 写提示词时如何照顾缓存

稳定前缀：指令、工具定义、示例放在最前面，保持不变。变化的内容往后追加：新的用户消息和观测结果。避免无谓的变动：在前缀里放时间戳，或者每次调整工具 Schema 的顺序，都会让缓存失效。测量复用情况：关注缓存命中的 token 数、TTFT 和被淘汰的情况。

课程也强调，缓存只是省掉了重复的预填充，模型看到的历史长度并没有减少，上下文窗口仍然会被填满。这就引出了最后一个话题。

对只写 Harness、不部署模型的人来说，Graham 的结论是：一定要小心，不要无意中把缓存弄失效。缓存只在整段前缀完全相同时才有效。他举了几个在 OpenHands 里考虑过、最后放弃的做法。第一，绝对不要每一步都改系统消息，那样等于完全没有缓存。一个很自然的想法是把当前日期时间写进系统消息，让 Agent 知道现在几点，但时间每一步都在变，缓存每一步都会失效；真要加，就加在最后一条用户消息或最后一个工具结果里。第二，每一步换一个模型。比如想让某一步用最贵的模型、后面三步用便宜模型来省钱，但换回贵模型时，它的缓存早已失效，你要按十倍价格重新付整段前缀的费用。所以如果想靠切换模型省钱，切换次数要非常克制。

六、上下文压缩（Compaction）

1. 一个例子

压缩前的历史：观测到 CI 任务 30 分钟后超时；动作是查看任务日志；观测到一份 2.4 万行的日志，里面反复出现"address already in use"；动作是设置 --workers=1 重跑；观测到测试通过，日志保存在 /tmp/ci.log。

压缩后只剩：目标是修复 CI 超时；原因是端口冲突；已验证 --workers=1 能通过；证据在 /tmp/ci.log。下一步动作是用测试过的 worker 设置提交 PR。

Graham 问谁在日常用编程 Agent 时见过"正在压缩上下文"的提示，又问谁看到它时会高兴，没有人举手。原因很简单：压缩做得不好，Agent 就会忘事，转头去做完全不同的事，甚至删掉你的文件。

2. 把压缩看成状态估计

课程给了一个形式化的描述。完整历史是 $H_t$，压缩器 $\mathcal{C}$ 在 token 预算 $B$ 之内把它变成工作状态 $\hat s_t = \mathcal{C}(H_t; B)$，$|\hat s_t| \le B$。目标是让模型基于压缩状态做出的后续动作，和基于完整历史做出的动作尽量一致：

$$p(A_{\text{future}} \mid H_t) \approx p(A_{\text{future}} \mid \hat s_t)$$

这里有三个要求：行为保真（后续决策不变）、表示有界（不超过预算）、可恢复（原样保留关键锚点，并保留指向原始证据的链接，需要时能找回来）。

3. 哪些内容保留，哪些丢弃

  • 原样保留：锚点，也就是目标和约束条件；最近的一段历史，也就是正在进行的尝试和刚拿到的结果。
  • 编码保留：检查点，包括已做的决定、进度和各种编号。
  • 外部存放：证据库。比如 2.4 万行的日志，上下文里只留 3 个失败点、执行的命令和文件路径，完整内容存到外面（MemGPT 的思路）。
  • 丢弃：重复内容和已经被取代的旧尝试。

Graham 对锚点做了说明：常见的锚点是用户在会话开头说的话。有学生说 Agent 会忘记会话开头的内容，他认为这可能是所用 Harness 的设计缺陷，因为好的 Harness 会特意保护会话开头，不去压缩它；当然有时也确实无法避免。关于证据库，他说至少在命令行编程 Agent 里，完整的历史通常都存在磁盘上某个位置。即使压缩丢了信息，只要知道存在哪里，就可以让 Agent 回去读完整历史，找回之前的结果。

4. 压缩策略要做的四个决定

  1. 何时触发：达到 token 阈值、服务商报告上下文溢出，或者用户手动要求；要给下一次输出预留空间。
  2. 压缩哪部分：保护开头，压缩较早的中间部分，保留最近的尾部；切分点要落在完整的对话轮次或工具调用边界上，不能把一个调用和它的结果拆开。
  3. 用什么替换：可读的摘要、结构化的检查点、服务商提供的不透明对象，或者干脆开一个新上下文。
  4. 失败时怎么办：保持历史不变、重试或重置、保留可搜索的完整历史。

幻灯片提到 Codex、OpenCode、Pi、Hermes、OpenHands 都实现了各自的压缩策略。

课上对这几项又补充了几句。触发方式里，手动触发就是很多编程 Agent 里的 /compact 命令；自动触发可以设一个上限，比如超过 200K token 就压缩，也可能是服务商强制要求。替换内容方面，有的 Harness 要求模型通过一次工具调用来写摘要，规定摘要里必须包含哪些项目，这就是结构化摘要；有的只写自由文本。Graham 说据他所知，OpenAI 会把上下文压缩成一个加密的对象，用户读不到内容，因为他们不想让别人学走压缩算法。

5. 反复压缩会漂移

每次压缩都以上一次的摘要为基础：$\hat s_{k+1} = \mathcal{C}(\hat s_k \oplus R_k)$，其中 $R_k$ 是新产生的历史。这会导致信息逐步走样。课上的例子：原始历史写的是"使用 CUDA 12.4"，第一次摘要变成"使用 CUDA 12.x"，第二次变成"使用较新的 CUDA"，第三次这个约束就消失了。对策是：锚点原样复制；保留最近的尾部；需要时回去检索原始证据。

6. 怎样评估压缩效果

课程建议用"续做"来评估：先在历史里埋下约束、决定和产物，再用实际的压缩策略压缩，然后让 Agent 继续做，观察它后续的决定。指标有四个：状态回忆（约束和编号是否还记得）；任务成功（后续是否做对）；效率（token、延迟、成本）；稳定性（多次压缩后是否仍然可靠）。

Graham 讲了 OpenHands 早期的一次教训。他们做了一个较早的生产级压缩算法（当时叫 compression），花了大约一个月，在 SWE-bench 上评估，结论是分数一点没降，还省了很多 token。可一放到真实使用中，就出了很低级的错：每压缩一次就提交一个 PR，因为它忘了自己已经提交过，结果同一个功能收到五个 PR；还会忘记用户在对话中途追加的指令。原因是 SWE-bench 的任务都是单轮的，只有一条用户消息，而他们的算法恰好把后续的用户消息压缩掉了。他的结论是：除非你的基准足够全面、覆盖了所有使用场景，否则光跑基准不够，还必须在真实使用中测试。

课程最后有学生问：子 Agent 算不算一种管理上下文的办法？Graham 说算，会在后面讲规划和多 Agent 时专门讨论。

七、参考资料导读

这一讲没有指定阅读，但列了四十多篇参考资料。下面按主题说明每篇讲了什么，方便按需查阅。

推理服务

  • DistServe（Zhong 等，OSDI 2024）：以前的推理系统把预填充和解码放在同一批 GPU 上一起算，两者互相干扰，资源分配也被绑在一起。预填充影响 TTFT，解码影响 TPOT，延迟要求严格时只能顾一头，或者多配机器。DistServe 把两个阶段拆到不同的 GPU 上，各自按需分配资源和并行方式。本讲的推理流程图就来自这篇。
  • Needle in a Haystack（Greg Kamradt）：大海捞针测试的开源代码，可以在不同上下文长度、不同插入深度下测试模型的检索准确率。

注意力结构

  • Attention Is All You Need（Vaswani 等，2017）：Transformer 的原始论文，完全用注意力取代循环和卷积，训练更容易并行。
  • Longformer（Beltagy 等，2020）：把局部窗口注意力和少量按任务设定的全局注意力结合起来，计算量随序列长度线性增长，可以直接替换标准自注意力，在长文档任务上超过了 RoBERTa。
  • Transformers are RNNs（Katharopoulos 等，2020）：把自注意力写成核函数特征的线性点积，利用矩阵乘法的结合律把复杂度从 $O(N^2)$ 降到 $O(N)$，并指出这样的 Transformer 在生成时和循环神经网络等价，超长序列上的自回归预测最多快 4000 倍。
  • Linear Transformers Are Secretly Fast Weight Programmers（Schlag 等，2021）：证明线性注意力和上世纪九十年代的"快速权重"模型形式上等价。论文指出纯加法的更新会让记忆容量受限，于是改成类似 Delta 规则的更新，让模型更容易修正键到值的映射。这就是 DeltaNet 的来源。
  • Gated DeltaNet（Yang 等，2024）：观察到门控（可以快速整体擦除记忆）和 Delta 规则（可以精确修改某一条记忆）是互补的，把两者结合起来，并设计了适合现代硬件的并行训练算法，在语言建模、检索、长度外推和长上下文理解上超过了 Mamba2 和 DeltaNet。
  • Kimi Linear（Kimi 团队，2025）：提出 KDA，把 Gated DeltaNet 的门控细化到每个维度。论文称这是混合线性注意力第一次在公平比较下，在短上下文、长上下文和强化学习扩展几种场景里都超过完整注意力。
  • DeepSeek-V3.2（2025）：提出 DeepSeek Sparse Attention（DSA），在长上下文场景下大幅降低计算量，同时保持效果；论文还介绍了大规模强化学习和 Agent 任务合成。
  • GQA（Ainslie 等，2023）：提出分组查询注意力，并给出一个办法：用原预训练算力的 5% 把已有的多头注意力模型改造成 GQA，质量接近多头注意力，速度接近 MQA。
  • DeepSeek-V2（2024）：提出 MLA，把 KV 缓存压缩进一个潜在向量。和 DeepSeek 67B 相比，KV 缓存减少了 93.3%，最大生成吞吐量提高到 5.76 倍。

位置编码与长度扩展

  • RoFormer（Su 等，2021）：提出 RoPE，用旋转矩阵编码绝对位置，同时在自注意力里自然地体现相对位置；它还有一个性质，token 之间的依赖随相对距离增大而衰减。
  • The Impact of Positional Encoding on Length Generalization（Kazemnejad 等，2023）：在一系列推理和数学任务上系统比较了五种位置编码，发现最常用的几种（ALiBi、RoPE、绝对位置编码）在长度泛化上都不理想，而不加位置编码的 NoPE 反而表现更好。
  • Position Interpolation（Chen 等，2023）：把 LLaMA 这类 RoPE 模型的上下文扩展到 32768，只需不到 1000 步微调。做法是把输入的位置编号线性缩小到原训练范围内，而不是直接外推，因为外推会产生极大的注意力分数，把自注意力彻底搞坏。
  • YaRN（Peng 等，2023）：比之前的扩展方法少用 10 倍的 token 和 2.5 倍的训练步数，让 LLaMA 有效使用远超原预训练长度的上下文，还能外推到比微调数据更长的长度。

2026 年的长上下文模型

  • Kimi K3（2026 年 7 月）：总参数 2.8 万亿、每个 token 激活 1040 亿的混合专家模型，原生支持视觉，上下文一百万 token。结构基于 KDA 和 Attention Residuals；896 个专家中每个 token 激活 16 个。论文称整体扩展效率比 Kimi K2 高约 2.5 倍。
  • GLM-5（2026 年 2 月）：采用 DSA 降低训练和推理成本，同时保持长上下文效果；另一个重点是异步强化学习基础设施，把生成和训练解耦，提高后训练效率。GLM-5.3-Flash 是它的轻量后续版本。
  • DeepSeek V4（2026）：包括 1.6 万亿参数（激活 490 亿）的 Pro 版和 2840 亿参数（激活 130 亿）的 Flash 版，都支持一百万 token。用两种压缩注意力（CSA 和 HCA）混合来提高长上下文效率，预训练超过 32 万亿 token。
  • Inkling（Thinking Machines，2026 年 7 月）：从零训练的开放权重模型，总参数 9750 亿、激活 410 亿，上下文最长一百万 token，在 45 万亿 token 的文本、图像、音频和视频上预训练；同时预览了激活 120 亿参数的 Inkling-Small。
  • 另外还列了 Qwen3.8-Flash-Next 的发布博客和 Nemotron 3 Ultra 的技术报告，对应本讲表格里的两行。

训练基础设施

  • Ring Attention（Liu 等，2023）：分块计算自注意力和前馈层，把长序列分布到多台设备上，并让 K、V 块的通信和注意力计算完全重叠。能处理的长度是以往内存优化方法的"设备数"倍，而且是精确计算，不做近似。
  • Megatron 上下文并行文档：说明上下文并行和早先的序列并行的区别。序列并行只切分 Dropout 和 LayerNorm 的激活，上下文并行把网络输入和所有激活都沿序列维度切开；除了注意力，其他模块都可以照常运行。

缓存与定价

  • Prompt Cache（Gim 等，2023）：很多提示词有重复片段，比如系统消息、提示模板、作为上下文的文档。把这些片段的注意力状态预先算好存在服务器上，出现时直接复用，能显著降低首个 token 的延迟。论文用一套 schema 明确定义哪些片段可复用，并保证复用时位置正确。
  • Can I Buy Your KV Cache?（2026）：观察到大量 Agent 都在重复同一件事：为了读同一份文档，各自从头做一遍预填充，算出一模一样的 KV 缓存。论文的提议很简单：由发布者把文档的 KV 缓存算好，其他 Agent 付费加载，跳过预填充。实验表明结果逐 token 完全一致；在 Qwen3-4B 上，复用比预填充便宜 9 到 50 倍，文档越长差距越大。
  • 各家 API 的定价页（DeepSeek、Z.AI、Kimi、OpenAI、Anthropic）：本讲价格表的数据来源。以 Z.AI 为例，GLM-5.3 普通输入每百万 token 1.4 美元，命中缓存 0.26 美元，输出 4.4 美元，缓存存储限时免费。
  • PagedAttention / vLLM（Kwon 等，2023）：借鉴操作系统的虚拟内存和分页，几乎消除 KV 缓存的显存浪费，并支持在请求内和请求间共享缓存，同等延迟下吞吐量提高 2 到 4 倍。
  • SGLang / RadixAttention（Zheng 等，2023）：SGLang 包括前端语言和运行时，运行时用 RadixAttention 复用 KV 缓存，用压缩有限状态机加速结构化输出，吞吐量最多提高 6.4 倍。

上下文压缩

  • MemGPT（Packer 等，2023）：借鉴操作系统的分层内存，在快、慢两层存储之间搬运数据，让模型在有限的上下文窗口里表现得像拥有更大的内存。本讲"证据外部存放"的思路来自这里，第四讲还会详细讲。
  • LongLLMLingua（Jiang 等，ACL 2024）：通过提示词压缩，在长上下文场景下同时降低成本、提高效果。
  • ReSum（2025）：网页搜索 Agent 需要大量探索，但上下文窗口有限。ReSum 定期调用一个外部工具，把交互历史压成简短摘要，从而可以无限探索；因为普通 Agent 并不习惯基于摘要推理，作者又提出 ReSum-GRPO，用强化学习让模型适应这种压缩后的上下文。
  • Codex、OpenCode、Pi、Hermes Agent、OpenHands 的代码仓库：本讲提到的五个实现了压缩策略的开源 Harness，可以直接读它们的实现。

八、小结

长上下文是一整套系统问题。增长：Agent 循环不断吸收指令、动作和环境观测。推理：预填充、解码、稠密注意力和 KV 内存各有瓶颈。结构：局部、循环、稀疏和压缩机制决定哪些历史仍可访问。缓存：稳定的前缀能省掉重复的预填充，但不会减少模型看到的历史。压缩：要保住意图、精确的任务状态、最近的工作和恢复途径，并用续做测试来评估。
