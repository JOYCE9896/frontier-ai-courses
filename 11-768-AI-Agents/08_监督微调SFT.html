第八讲：Agent 的监督微调

把录下来的 Agent 运行轨迹变成模型权重：数据怎么选，损失算在哪里，怎样知道训练有效

主讲：Yueqi Song · 2026 年 9 月 17 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容）

一、从轨迹到权重

主讲人 Yueqi Song 是 Graham 的学生，也是后面讲到的 Agent Data Protocol 的第一作者。开场时她问谁训练过 Agent、谁在 Agent 上做过 SFT，举手的人比她预想的多。这是训练部分的第一讲，她先总体介绍"训练 Agent"是什么意思，再讲 SFT 的具体问题，最后过渡到后面三讲的强化学习。

1. 一条轨迹长什么样

以 SWE-Gym（Pan 等，2024）为例，一条记录下来的轨迹依次是：系统消息（Harness 的提示词）；用户消息（issue 内容）；助手消息（一段思考加一条 bash 命令）；观测（测试输出）；助手消息（思考加一次文件编辑）；观测（diff）……最后助手提交。Agent 在沙盒里拿到一个 issue 和两个工具（bash 和文件编辑器），产生了思考、命令和命令返回的观测，最后由仓库自己的测试决定这次运行是否成功。

2. 为什么要改权重

第四讲列过更新 Agent 的三个位置。上下文窗口和外部产物（技能、记忆）几秒钟就能更新。改权重的好处是：改一次，之后每次调用都有新行为，提示里不用额外加任何东西。代价是：每改一次都要跑一次训练；你没法打开权重看改了什么；这个改动也没法搬到另一个模型上。

模型从轨迹中学到的东西包括：怎样写出这个 Harness 真能执行的工具调用；对话变长时怎样继续下去，因为它学的轨迹本身就很长；工具结果长什么样，所以它会停下来等结果，而不是自己编一个。但数据里的其他东西也会一起学进去：多余的评论、重复的命令、明明有多种解法却只会一种。

3. SFT 在整个训练流程中的位置

按 token 量看，训练流程是一个不断收窄的过程：预训练约 20 万亿 token（Nemotron 3 Ultra）；中期训练 1.43 万亿（K2 Horizon）；SFT 3320 亿（K2 Horizon）；RL 没有固定语料，靠 rollout 和奖励。越往后，token 越少，每个 token 被筛选得越仔细。

Song 提到，"中期训练"的定义各家很不一样，泛指预训练和后训练之间的任何训练，有人甚至把 SFT 也算作中期训练，但通常 SFT 被归入后训练。她还指出一个区别：预训练、中期训练和 SFT 都能找到固定的语料来训练，RL 通常没有固定语料，学的是模型自己的 rollout。

Kimi K3 的流程是：SFT 建立 Agent 的基础能力；RL 在不同推理强度下培养各领域专家；在线策略蒸馏把这些专家合并成一个模型。它的技术报告说，SFT 阶段为后续 RL 建立一个高质量的"冷启动"策略。冷启动指 RL 开始时所用的检查点。在 K3 里，模型在任何 RL 之前，就在 SFT 阶段学会了调用工具和完成长任务。

有人会问：为什么不直接做 RL？DeepSeek-R1-Zero 确实在基础模型上直接做了 RL，完全没有 SFT。但它的下一个模型又把 SFT 加了回来：R1 先用几千条精选样本做 SFT，因为 R1-Zero 的回答会混杂多种语言，很难读懂。

4. SFT 和 RL 的对比

监督微调强化学习
学什么录下来的轨迹，不管是谁生成的自己的 rollout，由奖励打分
信号每个 token 都有目标每条 rollout 一个数字
需要数据和 GPU实时环境、沙盒、可检查的奖励
擅长学工具调用、格式、长任务把模型已经会尝试的能力磨得更好
卡住的情况示范有错、太窄或用完了起点太弱，或奖励无法检查

二、轨迹怎样变成训练序列

1. 套上聊天模板

把轨迹送进聊天模板，就得到一整串 token。例如一段 Qwen 格式的片段： 

<|im_start|>tool
3 failed, 41 passed
<|im_end|>
<|im_start|>assistant
The test compares floats. Fix it.
<tool_call>
str_replace(...)
</tool_call>
<|im_end|>

<|…|> 这样的标记各是一个特殊 token，其余是 Agent 写的和看到的内容。

2. 损失只算在助手的 token 上

训练时并不是所有 token 都要预测。给每个 token 一个掩码位 $m_t$，只有属于助手输出的 token 为 1，其余为 0。损失是：

$$\mathcal{L}(\theta) = -\sum_{t:\, m_t = 1} \log p_\theta(x_t \mid x_{<t})$$

最小化它，就是在给定前面所有内容的条件下，提高每个录下来的动作的概率。系统提示、用户消息和观测只作为条件上下文，不作为预测目标。道理很简单：工具的输出是环境给的，模型不应该学着自己生成它。

有学生问：为什么不把观测也拿来训练？Song 说只训练助手消息是 Agent SFT 的通用经验法则，因为观测和用户内容来自用户或环境，不是助手预测出来的；但确实有论文训练了观测并发现有用，可以帮助模型预测环境状态，值得自己做消融实验看看。Daniel Fried 补充了一个例子：Meta 发布的代码世界模型（CWM）就训练模型输出工具调用的结果，也就是预测代码执行的结果。这对需要理解执行语义的任务很有帮助，但也会占用模型的一部分容量，模型太小的话可能损害其他能力。它对 Agent 基本能力的影响还是开放问题，但对世界建模和规划可能很有用，属于比较实验性的方向。

3. 掩码怎样构建

分三步：模板把对话渲染成一个字符串，同时记下每段助手内容从第几个字符开始、到第几个字符结束；分词时把字符位置转换成 token 位置；助手范围内的 token 标 1，其余标 0。训练开始时，角色信息已经没有了，训练器只看到字符串和这些掩码位。

框架设置项掩码怎样产生
TRLassistant_only_loss=True模板渲染时标出助手范围（需要模板里有 {% generation %} 标记）
Axolotlroles_to_train、train_on_eos在渲染后的字符串里找每一轮的角色头
LLaMA-Factorytrain_on_prompt、mask_history编码时把整轮标记为训练或忽略

三个框架做的是同一个决定，只有 TRL 把它放在模板里。

Song 说她做 Agent SFT 时很喜欢用 LLaMA-Factory：可以先生成 rollout 或合成轨迹，放进它的训练框架，指定要训练的模型就能开始；也可以用参数指定训练整条轨迹，还是在某个位置截断，或者连上下文也一起训练。

4. 轮次结束 token 必须算进损失

看这一段：<|im_start|>assistant 换行，"I'll run the failing test."，工具调用 bash(cmd="pytest -q")，<|im_end|>。开头的角色头 <|im_start|>assistant 在推理时由 Harness 提供，永远不是预测目标。但结尾的 <|im_end|> 是模型自己要生成的停止信号，必须在掩码内，否则 TRL 的文档说"模型可能学不会停下来"。

而且"轮次结束"其实是三种不同的事：结束这条消息、交给工具执行、完成整个任务。Kimi K3 的模板用不同的 token 把它们区分开，比如 [end_of_msg]。

Song 说，不同模型的轮次结束 token 写法各不相同，Qwen 是 <|im_end|>，Kimi、Llama 又各不一样，训练前一定要看清所用模型的聊天模板，否则会在后训练时把模型弄糊涂。她观察到，大家在设置训练数据时经常搞混哪些部分算损失、哪些只是上下文。

5. 推理内容要不要训练

对 <think>…</think> 这样的推理块，有两个开关要分别决定：它是否留在上下文里，以及它是否参与训练。留在上下文里，它能解释后面的动作；参与训练，它就变成模型自己写推理的风格。Nemotron 的做法是：因推理预算被截断的推理内容保留在上下文里，但人为截断的那个位置不算损失。

有学生问为什么有时要把推理内容屏蔽掉。Song 解释：推理可能比实际的工具调用或完成任务的部分长得多，会让模型只学会写很长的推理，却把最终动作弄混。以软件工程任务为例，我们希望模型推理下一步做什么，但不希望它光推理、不去真正执行下一步。推理和执行都重要，下一节的 BalanceSFT 就是针对这个问题。

6. 助手轮次内部的加权

BalanceSFT（Hao 等，2025）指出一个问题：推理文字很长，在损失里占了大头，而真正需要做对的是短短的工具调用。它提出两个组件：SSB 学一个权重，在损失里平衡推理 token 和工具调用 token；HDR 对困难样本重新采样。多轮任务上的提升比单轮更大，两个基础模型上都是如此。

7. 按样本数配比和按 token 数配比不一样

MAI-Thinking-1（微软 AI，2026）按样本数平衡了数据配比，但损失是按 token 算的。STEM 和编程的轨迹长得多，最后几乎占了全部 token。所以按轨迹条数平衡配比之后，一定要检查换算成 token 是什么比例。

课后有学生问配比该怎么定。Song 说基本靠实验：先在小比例的数据、小规模的模型上试，确认有效再扩大。比如 MAI 选择让 STEM 和编程占 56%，也是他们通过实验确定的。Daniel 补充，如果有评估集，可以计算模型在评估集上的损失，用来辅助选择数据配比，但这只是近似，因为你并没有真的在那个配比上训练过。

8. 一个没人做过的实验

主讲人说，他们找不到任何已发表的实验，专门改变 Agent SFT 的掩码并测量影响。仔细做过掩码实验的都是单轮指令微调，不是 Agent。唯一一个"不掩码提示反而有帮助"的案例（Instruction Modelling，Shi 等，2024；另见 WIT，Chatterjee 等，2025），条件是提示长、回答短、数据少，而 Agent 轨迹在这三点上正好相反。这个实验在 8B 规模上很便宜，但还没有人做。

三、选择哪些轨迹

1. 轨迹从哪里来

谁跑的任务全部保留只保留通过的
更强的模型普通蒸馏SWE-Gym、Nemotron、OpenThoughts-Agent
模型自己MAI（在自己的推理运行上）专家迭代（下一讲）

大多数 Agent SFT 数据在右上格：更强的模型能写出比学生更好的轨迹，任务自带的测试让筛选好轨迹变得便宜。下面一行是模型自己生成训练数据，反复循环就是专家迭代，下一讲会讲。

2. 从更强的模型蒸馏

SWE-Gym 让 GPT-4o 和 Claude 跑任务，得到 491 条通过仓库测试的轨迹。只用这 491 条微调一个 32B 的 Qwen 模型，它在两个 SWE-Bench 子集上的分数都提高了 10 分以上。在任务集不变、只增加采样轨迹数量的实验里，准确率到采样预算用完时仍在上升。他们不缺任务，缺的是采样更多轨迹的算力。

Song 补充了两点。一是数据量增加到一定程度会饱和，训练的模型越小，越容易饱和。二是有学生问：如果没有更强的模型可以蒸馏怎么办？她说 MAI 的做法是蒸馏自己；前沿的闭源实验室（比如 OpenAI、Anthropic）更多依靠 RL 获得 Agent 能力，SFT 主要是冷启动，让模型学到一般能力，因为 SFT 从根本上受限于教师模型的水平，没有更好的教师，就只能靠 RL。按 SWE-Gym 的论文摘要，用 SWE-Gym 训练最多带来 19 个百分点的绝对提升；再配合训练出来的验证器做推理时扩展，在 SWE-Bench Verified 和 Lite 上分别达到 32.0% 和 26.0%。

3. 成功的轨迹里也有坏习惯

Nemotron 3 Ultra 的报告举了几个例子，这些运行都通过了测试：有的只读文件从不修改；有的大部分轮次都在"改一下、跑一下测试"地循环；有的在最终补丁里留下了 print( 调试语句。报告的原话是，这些"如果直接用作 SFT 数据，会教给模型不好的行为"。因为损失会复制每一个动作，不管好坏，模型会把乱七八糟的过程和修复一起学进去。

4. 按形状过滤

OpenThoughts-Agent（Raoof 等，2026）发现，效果最好的过滤方法只是数轮次，丢掉少于 5 轮的运行。轮次只说明一次运行做了多少工作，不说明做得好不好：一个 4 轮的干净修复会被丢掉，一个 40 轮的混乱运行会被保留。但平均来看，它仍然有帮助。

Song 解释了为什么短轨迹值得怀疑：一条轨迹短，可能是一次就做对了，这样 Agent 学不到从错误中恢复的能力；也可能轨迹本身就是错的，或者生成过程中遇到了错误而提前结束。

5. 选择教师模型

同一篇论文比较了 5 个教师模型。GPT-5.3-Codex 在基准上本身是最强的，但用它的轨迹训练出来的学生最弱。排行榜名次在这里给出了错误的信号。相比之下，试两个教师、保留更好的学生，成本很低。

有学生问：GPT-5.3-Codex 自己能写出正确的工具调用，为什么拿它的轨迹训练别的模型效果最差？Song 说可能有多种原因，比如它擅长解决任务本身，但它的思考方式或解题方法和学生模型差别太大，生成的轨迹对学生不太管用。排行榜名次只说明谁自己做得好，不说明谁教得好。

6. 任务来源最重要

在所有因素里，任务来源对结果的影响最大。不同来源帮助不同的基准，所以在调其他参数之前，先把精力花在这里。混合最好的 4 到 8 个来源；再多也没有帮助。

课上的例子是：SWE-smith 的数据对 SWE-bench Verified 帮助最大，对 Terminal-Bench 帮助就小得多。所以要先试出哪些任务来源对你关心的基准有用，再针对性地训练，而不是把能找到的数据全都拿来训练。

数据扩展的实验：两条曲线都从同一个 1 万条的数据集出发，只是额外数据的来源不同。在同样的任务上增加更多运行，曲线会变平；增加新任务，曲线持续上升。

7. 课堂讨论

同一个任务跑回来三条轨迹：A 是 4 轮就解决的短运行；B 是一条长运行，做错了一次编辑，看到测试失败后恢复过来；C 在 11 次什么都没改变的尝试之后才解决。你要保留哪些？保留的那些，哪些动作算损失？"最少轮次"过滤器会在哪些答案上判断错？

课堂上的讨论是这样的。一位学生选 B：因为只在助手的动作上算损失，测试输出本身不重要；四轮做对的价值不如学会在长轨迹里观察测试结果、从错误中恢复。Song 追问 B 的缺点，学生说数据更多、训练算力更多，模型可能学会做多余的动作。Song 补充了一个更关键的风险：模型可能学会那次错误的编辑本身，却没学会恢复。A 的问题正好相反：一开始就做对是好行为，但如果第一步做错，模型不知道怎么恢复。她的结论是 A 和 B 最好都保留，让数据尽量覆盖对你的基准最有用的各种能力。至于"最少 5 轮"的过滤器，它会把干净的 A 丢掉，却可能保留混乱的 C。

课后还有学生问：错误的中间步骤要不要算损失？Song 认为最终结果必须正确，但中间错误的编辑也要训练，因为模型正是通过这些学会从错误中恢复。Daniel 补充说，强化学习在轨迹层面会隐式地做这种加权：一条轨迹得到的奖励越高，它的梯度权重越大。但如果模型犯了错又恢复了，RL 也会同样强化那个错误；要是你知道哪些是错误、用更聪明的方式设计损失，可能会做得更好，只是这类方法不太好实现。所以最常见的做法仍然是看整条轨迹的奖励，要么只挑正确的轨迹做 SFT，要么交给 RL 算法去处理。

四、多个数据集统一格式

每个 Agent 数据集都由不同团队用自己的格式构建。比如同样是网页，有的保存 HTML，有的保存可访问性树。要把两个数据集放在一起训练，就得先写两个定制的转换器。

Agent Data Protocol（ADP，Song 等，ICLR 2026 口头报告，主讲人是第一作者）提出一种统一表示：把每个数据集读一遍，改写成有类型的动作和观测。对于网页，HTML 和可访问性树都保留，不必二选一。这样每个数据集只转换一次，每个 Harness 也只适配一次，而不是每一对组合都写一个转换器。

数据统一之后，还要针对要训练的 Harness 渲染出来。OpenHands、SWE-Agent 和 AgentLab 的动作不同，同一条轨迹在各自那里看起来不一样。系统提示和上下文变长时的处理方式也在这一步设定。渲染完要检查：工具调用能否被解析，每个调用是否都带有思考，对话是否以正确的方式结束。

多样性和专用数据的对比：在同样的 Harness、同样的模型、同样的评估下，只改变训练数据配比。用混合数据训练，比用对应领域的单一数据训练效果更好，即使是在那个领域自己的基准上。

Song 解释了 ADP 要解决的具体麻烦：比如想同时用 Go-Browse 和 Mind2Web 两个网页数据集训练 OpenHands，前者用可访问性树表示网页，后者用 HTML，就得分别写两个转换器，工程量很大。有了统一格式，每个数据集只需转换一次到 ADP，再从 ADP 转换一次到你要的格式。按论文摘要，作者认为 Agent SFT 的瓶颈不在于缺少数据来源，而在于大量数据分散在各种格式、工具和接口里；ADP 是一种轻量的表示语言，充当各种 Agent 数据集和下游统一训练流程之间的"中间语"，能表达 API 和工具使用、浏览、编程、软件工程等多种任务。她还指出，OpenThoughts-Agent 研究的是单个数据来源对不同基准的作用，而 ADP 这组实验比较的是多个来源混合和单一来源的差别。

有学生问：这是参数高效微调，还是和预训练一样的全量训练？Song 确认是全量训练，只是数据不同。Daniel 补充说，可以把 SFT 看作预训练，区别只是数据被格式化成带结构标签的聊天格式，并且损失加了掩码，通常不监督模型输出工具调用的结果；损失函数本身仍是预训练用的交叉熵。它属于带教师强制（teacher forcing）的模仿学习：上下文是固定的录像，训练时不从模型采样。后面几讲会讲让模型自己生成训练数据的方法。还有学生问现在还用不用 LoRA 这类低秩适配，Song 说资源充足的实验室更倾向全量微调，她自己为了效率用过低秩适配。

2. 混合专家模型的路由

前沿模型大多是混合专家模型（MoE）：模型里有很多"专家"子网络，每个 token 只被路由到其中几个。而公开论文里微调的模型大多是稠密模型。用窄的 Agent 数据微调 MoE 时，少数几个专家会接收大部分 token，其他专家几乎不被训练。MAI 的做法是：在 SFT 阶段把路由的负载均衡约束加得非常强，比 RL 阶段强一千倍，并把 dropout 提高到 0.15。

Song 建议，开始做 SFT 之前，先读一两份前沿实验室的技术报告或公开论文，里面有大量可以直接用上的经验。

3. 拼接完整对话

训练用固定长度的序列。拼接（packing）是把几条对话装进一个序列，而不是用大量填充符补齐。Nemotron 3 Ultra 的做法：每条对话放进剩余空间最贴合的那个序列；任何对话都不切分、不截断，这是为了避免幻觉而有意做的选择；相同的提示不放进同一个序列；拼好后再打乱顺序。

4. 模板漂移

Transformers 文档写道："聊天模板应该始终和模型训练时的格式一致。"训练用的模板和部署用的模板必须一模一样，连空白字符都要一致。有一个隐蔽的问题：同一条轨迹渲染两次，一次后面接了一条工具消息，一次没有，可能得到两个不同的字符串。原因是模板里有条件判断的思考块，追加工具消息后，前面助手轮次的渲染方式变了，前缀就对不上了。

5. 已公开的训练材料

K2 Horizon 的模型卡有一张逐阶段的训练表，包括步数、token 数、序列长度和每个阶段的目的，上面的配置数字就来自这里。它还链接了 Weights & Biases 上的训练记录，可以看真实的损失曲线，并提供每个阶段的中间检查点。Nemotron 把后训练的检查点、训练数据和配方一起公开了。读一读这些材料能学到很多。

Song 特别推荐 K2 Horizon：它是一个完全开放的模型，训练细节和数据都公开，连训练时的损失曲线都能在 Weights & Biases（一个常用来监控训练损失的平台）上看到，可以看到企业级模型真实的训练过程；还提供各阶段的中间检查点，可以在它的预训练检查点上继续训练或做后训练。她说正式的技术报告可能还没发布，发布后建议读一读。

有学生问，现在还有没有"先 SFT、再针对具体任务做一轮小规模微调"这样的流水线？Song 说闭源模型通常希望你只用一个模型，可能是经过模型融合后的单一模型；开源模型 K2 Horizon 则在 SFT 和 RL 之后又做了多轮微调。

六、怎样知道训练有效

1. 训练和实际运行的错位

训练时每次只评判一个动作，而且总是接着录下来的轨迹往下走。部署时没有录像，模型的每一个动作都会改变它接下来看到的内容。假设同一个前缀（issue 加第一次编辑）之后，录下来的是编辑 A，测试通过，提交。如果模型做了一个看起来合理、但不同的编辑 B，测试失败，它就进入了训练中从未出现过的状态。损失低并不能保证它在那里会怎样。这个问题和 DAgger（Ross 等，2011）研究的模仿学习问题相同。

Song 强调，训练损失可以用来监控训练是否顺利，但不能代替真正的评估，因为训练时模型总是接着录像往下走，部署时它接着的是自己。模型走到一个训练中从没出现过的状态时，能否恢复取决于它从错误中恢复的能力，这是前面选择轨迹时要考虑的。DAgger 这篇论文的出发点是：模仿学习这类序列预测问题里，未来的观测取决于之前的预测，违背了统计学习常用的独立同分布假设，所以理论上和实践中表现都会变差。

2. 在目标 Harness 中评估

在相信任何数字之前，先检查能否把 20 个样本训练到过拟合。如果损失降不下来，问题出在上游。然后在 Harness 里运行模型，在结果可以检查的任务上评估。读别人公布的数字要小心，有时它们是几个 Harness 里最好的那个。数据划分要和想说明的结论匹配：同一个任务的所有运行放在同一边；如果要说明模型能泛化到新仓库，就按仓库划分。

3. 跨 Harness 的稳健性和其他能力的退化

在一个系统里收集的轨迹，除了任务本身，还会教给模型这个系统的惯例。在多个 Harness 里收集数据，是各家实验室避免训练出"只能在一个系统里用"的模型的办法。

训练一种能力，其他能力也会跟着变，不管你有没有测量。数据配比是控制手段，而按样本数平衡不等于按 token 数平衡。所以那些你没打算提升的能力也要评估。

Song 举例：如果在 OpenHands 里收集轨迹训练，模型可能没法很好地迁移到 Claude Code 或 Codex。想要一个好的软件工程模型，也应该训练推理能力，因为这些能力会迁移。不要只在一个关心的领域里刷基准分数。

七、交给 RL

OpenThoughts-Agent 的实验显示：完全不做 SFT 直接做 RL，基础模型几乎没有变化；只做 SFT，离 SFT 加 RL 能达到的水平差得很远。最好的配方是从一个"有意没有训练到自身最佳分数"的检查点开始 RL。论文的原话是："当 SFT 模型的选择考虑到了 RL 时，RL 带来的提升最大。"

Song 的看法是：在整个训练流程里，SFT 是模型获得通用 Agent 能力最多的阶段，RL 则用来提升特定领域的能力和推理。Nemotron、K2 Horizon 这些前沿工作都有类似发现。所以她把 SFT 看作为 Agent 能力做冷启动的先验，它要为后面的 RL 服务。

八、参考资料导读

这一讲没有指定阅读，参考资料主要是技术报告和训练框架的文档。

技术报告与模型卡

  • Kimi K3（2026）：2.8 万亿参数的混合专家模型，每个 token 激活 1040 亿参数，原生支持视觉，上下文一百万 token。后训练在通用、Agent 和编程领域以及多种推理强度下做强化学习。本讲引用了它"SFT、RL、在线策略蒸馏"三段式的后训练流程和区分三种"结束"的模板设计。
  • Kimi K2（2025）：1 万亿总参数、激活 320 亿的混合专家模型，提出 MuonClip 优化器，在 15.5 万亿 token 上预训练，全程没有出现损失尖峰；后训练的重点是大规模的 Agent 数据合成流水线，以及在真实和合成环境中交互的联合强化学习。
  • DeepSeek-R1（2025）：见上文。R1-Zero 说明纯强化学习就能激发推理能力，R1 又加回了 SFT 冷启动以解决可读性问题。
  • Nemotron 3 Ultra 技术报告（NVIDIA）、MAI-Thinking-1 技术报告（微软 AI）：本讲大量训练细节的来源，包括成功轨迹中的坏习惯、拼接策略、推理截断的处理、MoE 路由均衡和数据配比。
  • K2 Horizon 模型卡（IFM，375B 总参数、激活 23B）：公开了逐阶段的训练表和训练记录。它的聊天模板支持 JSON、XML、Markdown 等多种工具展示格式和工具调用格式，也能看出各家在工具格式上的差异。

数据与方法

  • OpenThoughts-Agent（Raoof 等，2026）：指出 SWE-smith、Nemotron-Terminal 等开放工作通常只针对一个基准，怎样训练出在多种 Agent 任务上都能泛化的模型还不清楚。项目公开了完整的数据整理流程，做了一百多个对照消融实验，逐一考察流程的每个环节，得出任务来源和多样性最重要等结论。
  • SWE-Gym（Pan 等，2024）：见上文。
  • Agent Data Protocol（Song 等，2025）：见上文。
  • BalanceSFT：课程网站上这一条链接到的是 FunReason 论文（2025），它提出"自我修正多尺度损失"（SRML），在训练中动态平衡推理过程和函数调用准确性各自的损失，并用 LLM 自动清洗训练数据，目的同样是解决推理 token 压过工具调用 token 的问题。
  • Instruction Modelling（Shi 等，2024）：不只在输出上算损失，也在指令和提示部分算损失。在 21 个基准上，很多情况下都能提升表现，最好的情况在 AlpacaEval 1.0 上提升超过 100%。作者发现关键因素是指令和输出的长度比例以及训练数据的多少，而 Agent 轨迹在这两点上都和它相反。
  • On the Effect of Instruction Tuning Loss on Generalization（WIT，Chatterjee 等，2025）：系统研究在指令微调损失中给提示和回答分别加不同权重的影响，提出加权指令微调，作为"只在回答上算损失"的更好替代。
  • DAgger（Ross、Gordon、Bagnell，2011）：见上文。它的解决办法是让学习者按自己的策略运行，由专家为它实际访问到的状态标注正确动作，再把这些数据加回训练集，这就是后面几讲"让模型自己产生训练数据"的思路来源。

训练框架文档

  • Transformers 的聊天模板和 apply_chat_template 文档、TRL 的 SFTTrainer 和训练用聊天模板文档、Axolotl 的对话数据格式文档、LLaMA-Factory：本讲掩码设置表格的来源。Axolotl 用 Jinja2 模板把消息列表转换成提示，可以用分词器自带的模板、内置模板或自定义模板。

九、小结

Agent 的 SFT 把轨迹套上聊天模板变成一串 token，只在助手生成的 token（包括轮次结束 token）上算损失。数据选择比训练参数更重要：任务来源影响最大，新任务比同一任务的更多轨迹更有用，教师模型要实际试，成功的轨迹里也可能有坏习惯。多个数据集可以通过统一格式合并，再针对目标 Harness 渲染。训练时要注意 MoE 路由、拼接和模板一致性。评估要在目标 Harness 中跑真实任务，并检查其他能力是否退化。SFT 最终是为 RL 准备一个好的起点。
