第十七讲：Agent 与人类工作

Agent 现在能做什么、做不了什么，怎样用任务、环境和评估把它训练到能干活，以及人的工作会怎样变化

主讲：Zora Wang（CMU，客座讲座）· 2026 年 10 月 27 日
资料来源：课程幻灯片（共 62 页）以及它引用的论文摘要
本讲录像尚未公开（截至 2026 年 11 月 7 日），本文不含课堂口述。这份幻灯片以图表为主，文字很少，图表的解读是整理时根据图和论文摘要写的，可能和讲者的强调有出入。录像发布后再对照补充。“第 17 讲”是按官网课表的顺序推算的编号，幻灯片本身没有写。

一、本讲的结构

幻灯片分三部分。第一部分做现实检验：Agent 能做什么，不能做什么。第二部分讲怎样把 Agent 做到能干活，拆成任务、环境、评估三个组件，每个组件都有还没解决的问题。第三部分讲只有能力还不够，以及人的工作接下来会怎样。

二、现实检验：Agent 能做什么

先看增长。幻灯片引用 Anthropic 的报告《AI 如何改变 Anthropic 的工作》：日常用户把编程 Agent 用得最多的是调试（超过一半的人），其次是理解和探索代码、实现新功能。METR 测量了模型有 50% 把握完成的软件任务有多长，这个时长大约每 7 个月翻一倍。图上最新的模型已经到了 16 小时左右，而 METR 标注超过 16 小时的测量结果并不可靠。

在基准测试上，分数看起来很高。幻灯片摘了一张模型对比表，这里列其中三行：

Agent 编程（SWE-Bench Pro）80.3%69.2%58.6%54.2%

电脑操作（OSWorld-Verified）85.0%83.4%78.7%76.2%

同一页还放了 SWE-bench Verified 的历史曲线：GPT-4o 在 2024 年 11 月约 30%，几个月后的模型已经到 60% 到 70%。下一页用 GPT-6 Astra 的官方示例（一块电路板从设计图到三维效果）说明电脑操作已经相当流畅。

三、现实检验：Agent 不能做什么

1. 真实任务的完成率低

Remote Labor Index（RLI）让 Agent 做远程工作市场上真实的外包项目，例如给一篇论文排版成 IEEE 格式，或者依据 PDF 图纸做集装箱房的建筑方案和三维模型，再和人类交付物比较。幻灯片上的榜单：

5Fable 515.83
6Opus 4.88.33

图上没有标单位。RLI 论文首版摘要报告的最高自动化率是 2.5%。如果榜单用的是同一口径，涨幅很大，但最好的模型仍然只完成约五分之一的项目。这张表和上一节 80% 上下的基准分数放在一起看，差距很明显。

2. 研发精力和实际就业错位

这是 Zora Wang 自己的研究。论文分析了 43 个基准的 72,342 个任务，把它们对应到美国的职业类别，再和就业人数、资本规模对比。下面是幻灯片图中的几行：

基准任务最集中的是计算机与数学，而这一类只占就业的约 5%。这里面有一部分原因是实际限制：餐饮、运输主要是线下工作，目前的电脑 Agent 本来就碰不到。不过管理的资本规模最大，基准任务只有 676 个，这一块就很难用“线下工作”解释。

3. 单独强的 Agent，合作时未必强

CollabSkill 让真实的工作者和 Agent 配对做任务（93 名工作者，386 个工作会话）。幻灯片上的对比很直观：

两个排名正好反过来。同页另一张图的横轴是补丁膨胀率（Agent 补丁长度除以标准补丁长度，只统计成功的补丁），各模型大致在 1.2 到 1.6 之间。也就是说，就算补丁通过了测试，也通常比标准答案长不少，人审查起来更费力。同页引用的立场论文《人类在 AI 编程 Agent 研究里缺席了》提出人机协作的四个维度：任务对齐、可验证性、可引导性、适应性。

4. 融不进实际工作流程

MIT NANDA 的企业调查列出了 Agent 难以进入核心工作流程的四个原因，比例都在五成到六成多：

  • “它不会从我们的反馈中学习。”
  • “每次都要手动提供太多上下文。”
  • “没法按我们的工作流程定制。”
  • “遇到边界情况就出错，也不会适应。”

Anthropic 那份报告里的雷达图也说明，各类职业的实际使用范围（红色）远小于理论覆盖范围（蓝色）。幻灯片还回头质疑了 METR 那张曲线：用任务时长衡量自动化公平吗？50% 的成功率对真实工作来说够吗？

社会的反应也不一致。幻灯片摆了几条新闻标题：比尔·盖茨警告 AI 对美国就业的冲击；路透社报道 Meta 用 AI 替换员工的计划如何破产；BBC 报道福特因 AI 质检比不上老技师而重新招人。

四、怎样把 Agent 做到能干活：任务

训练或评估一个工作 Agent，需要三样东西：环境（它在哪台电脑上操作）、任务（人交给它什么）、评估（做得好不好）。任务的来源有下面几种。

来源做法特点
O*NET 数据库美国职业数据库，把每个职业写成一组任务覆盖数千个职业，是很多工作的起点
GDPval雇平均 14 年经验的从业者编写任务对 GDP 贡献最大的 9 个行业，44 个职业，220 个任务；数量仍然有限
Remote Labor Index雇 358 名自由职业者提供项目补上 O*NET 没覆盖的长尾工作；240 个项目，覆盖 Upwork 64 个类别中的 23 个
JobBench只选专家真正想交出去的任务130 个任务，35 个职业；最好的模型只达到 45.9%
OpenCUA自动采集人的电脑操作约 2.25 万条轨迹（Windows、Mac、Ubuntu）；不打扰用户，但有隐私问题，也很难看出用户的意图
BAGEL、NNetNav让 Agent 自己探索网页，生成任务再去解决主要用于训练

JobBench 的出发点和其他几个不同。GDPval 按经济价值选任务，隐含的目标是替代人。JobBench 问的是人想让 Agent 做什么。幻灯片举的例子是：人愿意自己打磨一篇观点文章，不愿意清理大量数据。同样是记者这个职业，GDPval 的任务是依据现成材料改一篇文章，JobBench 的任务是整理多年的证据，交叉比对多份水质数据，这才是记者想交出去的负担。

很多基准并没有测到它声称的东西

这里要引入一个概念，构念效度（construct validity）：一个基准的分数，能在多大程度上证明它想衡量的那件事。Bean 等人统计了 LLM 基准论文的做法，图上有几个数字：

  • 要测的能力有公认定义的占 40.9%，定义有争议的占 37.4%，没有定义的占 21.7%。
  • 方便抽样指只用手边容易拿到的数据。60.7% 的基准没有这样做，27.0% 部分这样做，12.3% 完全这样做。
  • 只有 16.0% 用了统计检验，84.0% 没有。
  • 46.6% 没有讨论构念效度。

幻灯片接着再次放出前面的职业错位图，标题改成了“大多数基准没有测量重要的东西”。

五、环境

任务需要在一个可复现的环境里跑。常见的做法有三种。

  • 手动部署开源软件：TheAgentCompany 用 Rocket.Chat 代替 Slack，用自托管的 GitLab 代替 GitHub。优点是可复现，缺点是费人力。
  • 让编程 Agent 自动部署：Gym-Anything 从 O*NET 的 894 个职业出发，找出约 16,600 个软件，筛到约 3,400 个可以沙盒部署的，再选约 500 个覆盖 22 个职业大类，最后在算力预算内建成 200 个环境。一个编程 Agent 负责安装和配置，另一个审计 Agent 检查配置是否正确。
  • 以文件为中心的环境：Terminal-Bench 把数据文件和依赖装进 Docker，Agent 在容器里工作，再由测试脚本判分。

数据的来源也有两种：抓取真实数据（TheAgentCompany 和 WebArena，例如把 GitHub 数据导入自托管的 GitLab），或者合成（Gym-Anything）。理想的数据要真实，符合实际工作；要多样，覆盖不同职业；还要有难度，任务周期长，有干扰信息。

问题同样有两个。第一，开源替代品和人实际用的软件不一样。幻灯片并排放了 Google Docs 和 LibreOffice 的界面，差别一眼可见。第二，真实数据很难拿到。图上把 TheAgentCompany 里简单的财务表格和一份复杂的财务报表放在一起对比。

六、评估

1. 从可验证到模糊

人的工作可以排在一条线上。一端是修 GitHub issue，能跑测试，对错明确。中间是数据清洗和分析。另一端是室内设计，好坏很难用规则判定。幻灯片标出，大多数人类工作落在中间到模糊这一段。

可验证的任务直接执行就能判分，例如 SWE-bench 跑测试，Lean 这样的形式化证明助手检查证明。幻灯片提到 OpenAI 2026 年 9 月发布的纳维-斯托克斯问题解答就附带了 Lean 形式证明。

开放性任务用执行判分就不够了。TheAgentCompany 的评估代码只能检查“幻灯片里有没有出现某个职位名称”这类规则，判断不了内容好不好。

2. 用细则让模型当裁判

所以现在常用细则（rubric）：把“好”拆成一条条可以判断的标准，再让模型逐条打分。细则的来源在不断演变。

做法例子说明
专家手写GDPval质量高，一个任务的细则可以很长
模型生成CollabSkill提示词要求总分 100，分四类：正确性 40、完整性 20、任务要求 25、技术质量 15。需要细致设计提示词并人工核对
随训练演化DR Tulu（第 10 讲）对比不同轨迹，生成更难的细则，持续提供学习信号。主要用于训练
从人机交互中归纳TAHI把用户交互的信号转成可判分的细则，随会话推进逐步细化

TAHI 是 Zora Wang 本人参与的工作。例如初始细则只有“HTML 文件能在浏览器打开、柱宽合适、文字清晰”，用户提出要排序、把标题设成 32 像素之后，这些要求就进入最终细则。论文报告，在写作和视觉创作两个领域，为 30 个人、600 个任务做适配后，Agent 的单独任务成功率提高了 4.5% 到 20.9%。

3. 还没解决的问题

  • 裁判有偏差：模型倾向于偏袒自己的输出。在标准完全客观的情况下，如果输出其实没达标，模型评自己时错判为达标的可能性，比评别人时最多高出 50% 以上。多个裁判合用能缓解，但无法完全消除。幻灯片还列了输出随机、视觉判断差等问题。
  • 完美的细则很难写：幻灯片的说明是，细则仍然因模型而异，也因用户而异。
  • 基准会饱和和污染：OpenAI 宣布 SWE-bench Verified 已经饱和，原因是测试设计的问题和公开仓库造成的数据污染，它已不能反映前沿模型的编程能力。LiveCodeBench 的图也显示，模型在训练截止日期之后发布的题目上，分数明显下滑。这也是它要持续用新题目的原因。

幻灯片的总结是：评估既昂贵，目标还在不断移动。

七、光有能力还不够

1. 人和 Agent 怎样配合

Human Agency Scale（HAS）把人的参与程度分成五级。H1 是 Agent 独立完成，H2 是 Agent 在几个关键节点需要人输入，这两级由 Agent 主导，属于自动化。H3 是人和 Agent 合作，做得比任何一方单独做都好。H4 是 Agent 需要人的输入才能完成，H5 是任务完全依赖人的参与。H3 到 H5 属于增强。

CowPilot 让用户在网页任务中途接管并引导 Agent。另一项研究（Huq、Wang 等）发现用户的介入方式可以分成四种，并训练 Agent 意识到当前的模式和自己的自主程度。

模式用户怎样介入
放手（Hands-off）全程不介入，完全交给 Agent
接管（Takeover）偶尔介入，几乎都在任务末尾，一旦介入就不再交回控制权
上手（Hands-on）频繁且大量介入，经常在接管和交还之间切换
协作（Collaborative）介入少而小，通常较晚，并且习惯把控制权交还给 Agent

2. 效率低

Agent 系统里有大量重复工作，多 Agent 尤其明显。OpenAI 关于纳维-斯托克斯问题的报告写到，产生这个解答的小组里有上万个并发 Agent；而另一个结果（欧拉正则性的反证）是近 100 个 Agent 合作约 50 小时做出来的。规模相差百倍，幻灯片用红框圈出了这几个数字。

另一张图来自开放科学问题基准，比较了各模型的执行时间中位数：DeepSeek-V4-Pro 19.5 小时，GLM-5.3 13.9 小时，Opus 5 7.5 小时，Fable 5 7.0 小时，Kimi-K3 5.6 小时，Opus 5.5 5.3 小时，Opus 4.8 4.8 小时，Sol 5.6 2.9 小时，Astra 6 1.3 小时。同一模型的不同运行之间差距能到几十倍甚至更多，幻灯片圈出的 Opus 5.5 和 Sol 5.6 各有一次运行超过 100 小时。

3. 隐私和安全

幻灯片放了 Summer Yue 的一条推文：明明告诉 OpenClaw “行动前先确认”，它还是飞快地开始清空收件箱，手机上喊停也不管用，只好跑到 Mac mini 前手动停掉。

安全基准的数量已经翻了一倍以上，但很多问题要靠实际观察才能发现，静态基准测不出来。例如用户只是请 Agent 新建一个 SSH 用户，并只为这个用户开启密码登录，Agent 却改了全局 SSH 配置。这类意外行为的输入本身没有任何恶意。

4. 工作的乐趣被自动化了

Ranjit 等人对比了任务的 AI 暴露度和它给人带来的意义。暴露度高的任务，往往是“产出有形的成果”“需要新想法或创造力”“带来成就感”“让我觉得有意义”这类；暴露度低的任务，往往是“建立人际关系”“需要情绪感知”“受益于面对面交流”。也就是说，如果不加设计，最先被自动化的可能是人觉得最有成就感的部分。

八、工作的未来

最后一部分汇集了几项经济学和劳动研究。

  • 影响面广：《GPTs are GPTs》估计，约 80% 的美国劳动者至少有 10% 的工作任务会受影响。受影响最大的是写作和编程，收入较高的职业（翻译、税务顾问、网页设计师）暴露度可能更高。
  • 确实在裁员：幻灯片摆了华尔街可能裁员 20 万、美国联邦政府裁员、IBM CEO 谈 AI 裁员后转投其他岗位的新闻标题。
  • 自动化不等于替代：WORKBank 调查了 1,500 名工作者，46% 的职业任务上，他们表达了希望自动化的意愿。工作中有很多人不想做的部分。图上还圈出一片区域：工作者很想自动化，但 AI 能力和研发都还没跟上。
  • 工作不是固定的集合：Acemoglu 和 Restrepo（2019）指出，自动化取代劳动的同时，技术也创造出人有比较优势的新任务，这种“恢复效应”抵消了替代效应。
  • 工作的形状会变：幻灯片引用了 normaltech.ai 的“决定-执行-交付三明治”：传统工作里“执行”占最大一块，有了 AI 之后“执行”变得很薄，“决定”和“交付”占了主要部分。一些任务被自动化，相关技能贬值，人要适应，动机和判断力变得更重要。
  • 年轻人可能更吃亏：Brynjolfsson 等人的“煤矿里的金丝雀”研究，图中是 22 到 25 岁的职场新人，2022 年底之后，暴露度高的岗位就业走低，暴露度低的岗位继续增长。

最后一页放的是 Arvind Narayanan 对普林斯顿新生讲的话。幻灯片圈出了其中一句：用 AI 要增加自己的认知负荷，不能减少。“To learn deeper, not faster. There is no learning without the cognitive sweat.”（要学得更深，不求更快。脑子不费力，就没有学习。）幻灯片的标题是：人的工作本身也是训练和学习的一部分。如果新人的执行工作都被 Agent 做完，他们从哪里积累判断力？幻灯片没有直接给出答案。

九、本讲小结

  • 基准分数高，真实外包项目的完成率低，这两件事同时成立。
  • Agent 研发过度集中在编程任务上；单独能力强也不代表和人合作时强。
  • 做工作 Agent 需要任务、环境、评估三样东西。三样都有成熟做法，也都有没解决的问题，其中开放性任务的评估最难。
  • 除能力以外，还要考虑人机配合、效率、安全和工作的意义。
  • 工作内容会变，执行的比重下降，判断和动机更重要，职场新人受影响较大。
