第四讲：词法分析的实现

从词法规格到程序的流水线：正则表达式、NFA、DFA、查表；用正则表达式切分输入的算法和它的三处歧义（最长匹配、规则优先级、错误规则）；有限自动机的定义和运行，ε 移动，DFA 与 NFA；Thompson 构造把正则表达式变成 NFA；子集构造和 ε 闭包把 NFA 变成 DFA；表驱动的实现和时间空间的取舍

主讲：Fredrik Kjolstad（2026 年春季）；录像主讲：Alex Aiken
资料来源：课件（2026 年 4 月 9 日）、录像第 4 周（04-01 Lexical Specification 到 04-05 Implementing Finite Automata）

一、开场：构建大系统的几条建议

WA1 这一讲布置，一周后晚上 11:59 前在 Gradescope 交。课件先给了几条做大型系统的建议，是写编译器项目时用得上的：

  • KISS（Keep It Simple, Stupid）。
  • 不要过早优化。
  • 把系统设计成可测试的。
  • 改一个能工作的系统，比让一个系统开始工作容易。

配了四句名言。Barbara Liskov："写好软件不容易……这和看重简单、不看重复杂有很大关系。"Brian Kernighan："调试比写代码难一倍。所以如果你把代码写得尽可能聪明，按定义你就不够聪明去调试它。"Tony Hoare："构造软件设计有两种方法：一种是让它简单到明显没有缺陷，另一种是让它复杂到没有明显的缺陷。第一种难得多。"Alan Perlis："简单不在复杂之前，而在复杂之后。"

二、整体路线

这一讲要回答：怎样把一份词法规格变成真正能做词法分析的程序。路线是四步：

$$\text{词法规格} \to \text{正则表达式} \to \text{NFA} \to \text{DFA} \to \text{查表实现}$$

先补几个记号。不同工具的正则写法略有差异：

  • 并：$A + B$ 也写作 $A \mid B$。
  • 可选：$A + \varepsilon$ 写作 $A?$。
  • 范围：$\text{'a'} + \text{'b'} + \cdots + \text{'z'}$ 写作 [a-z]。
  • 排除范围：[a-z] 的补集写作 [^a-z]，即除 a 到 z 以外的任意字符。这一条上次没讲，但很重要。

三、用正则表达式切分输入

上一讲定义的只是一个判断：$s \in L(R)$ 吗？回答是或否。词法分析要的是把输入切成一个个 token，光有是或否不够，需要在正则表达式上做一点扩展。

  1. 给每个 token 类别写一个正则表达式：Number = digit⁺，Keyword = 'if' + 'else' + ⋯，Identifier = letter (letter + digit)*，OpenPar = '('，等等。
  2. 把它们并起来得到一个总的表达式 $R = R_1 + R_2 + \cdots$，匹配所有 token 的所有词素。
  3. 设输入是 $x_1 \ldots x_n$。对 $1 \le i \le n$，检查前缀 $x_1 \ldots x_i \in L(R)$ 是否成立。
  4. 如果成立，那么这个前缀一定属于某个 $L(R_j)$，也就是说它是第 j 类 token。
  5. 把 $x_1 \ldots x_i$ 从输入里去掉，回到第 3 步。重复，直到输入为空。

这个算法有几处没说清楚的地方，正好是有意思的地方。

歧义一：吃多少输入

如果 $x_1 \ldots x_i \in L(R)$，同时更长的 $x_1 \ldots x_k \in L(R)$ 也成立，选哪个？比如输入开头是 ==，是一个赋值 = 还是一个比较 ==？

规则：选最长的那个，叫"最长匹配"（maximal munch）。理由是人就是这样读的：看到 == 不会看成两个等号，看到 how 不会看成三个字母，会一直往下读到分隔符为止。工具照人的习惯来，几乎总是对的。

歧义二：用哪个 token

如果同一个前缀既属于 $L(R_j)$ 又属于 $L(R_k)$，选哪个？比如 if 既符合关键字的表达式，也符合标识符的表达式。

大多数语言的规定是关键字永远是关键字，标识符不包括关键字。可要写一个明确排除所有关键字的标识符表达式很困难，letter (letter + digit)* 自然得多。所以用优先级解决：选列在前面的规则，j < k 就选 j。在规格文件里把关键字写在标识符前面即可。

歧义三：没有规则匹配

如果输入的某个前缀不属于任何规则怎么办？这完全可能发生，编译器不能就这样卡住或崩溃，要告诉程序员错误在哪、是什么错误。

最好的办法是不让这种情况发生：写一条匹配所有"坏"字符串的规则，放在最后，优先级最低。放在最后有个好处，写这条规则时可以粗糙一点，它和前面的规则有重叠也没关系，因为只有前面所有规则都不匹配时它才会生效。匹配到它时，打印错误信息，附上在文件里的位置等。

小结

正则表达式给字符串模式提供了简洁的记号，用于词法分析时要加几条小扩展来消除歧义和处理错误。Aiken 提醒：最长匹配和优先级这两条规则交织在一起，会出现一些微妙的情况，不一定得到你想要的结果，写规格时要仔细考虑规则的顺序和写法。好在有很好的算法，只需扫描输入一遍，每个字符只需几次查表。下面讲怎样做到。

四、有限自动机

正则表达式是规格，有限自动机是实现。两者能定义的语言完全一样，都是正则语言，这门课不证明，但会用到这个事实。

一个有限自动机由以下部分组成：

  • 输入字母表 $\Sigma$。
  • 有限的状态集 $S$。"有限"就是它名字的来源。
  • 一个开始状态 $n$。
  • 接受状态集 $F \subseteq S$。
  • 一组转移 $s_1 \xrightarrow{a} s_2$，读作"在状态 $s_1$ 看到输入 a，就转到状态 $s_2$"。

自动机从开始状态出发，每次读一个输入字符，按转移走。读完输入时如果停在接受状态，就接受；否则拒绝。拒绝有两种情况：读完了但停在非接受状态；或者中途卡住了，当前状态在当前输入上没有转移，根本走不到输入末尾。自动机的语言就是它接受的字符串的集合。

画图时，状态是圆圈，开始状态有一条没有起点的箭头指进来，接受状态画双圈，转移是带标签的边。

例子

  • 只接受 "1"：开始状态 A 经 1 到接受状态 B。输入 "1"：从 A 读 1 到 B，输入指针到了末尾，在接受状态，接受。输入 "0"：A 上没有 0 的转移，卡住，拒绝。输入 "10"：读 1 到 B，B 上没有 0 的转移，卡住；虽然 B 是接受状态，但没读完输入，拒绝。
  • 任意个 1 后面跟一个 0（字母表 {0,1}）：最短的串是单个 0，所以 A 经 0 到接受状态 B；0 前面可以有任意个 1，在 A 上加一个 1 的自环。输入 110：A→A→A→B，接受。输入 100：A→A→B，B 上没有转移，卡住，拒绝。

自动机运行时的"格局"由当前状态和输入指针位置组成。输入指针总是向前移动，从不后退。

ε 移动

到目前为止，自动机每走一步都要吃掉一个输入字符。ε 移动是一种新的转移：从状态 A 到状态 B，不读输入，输入指针不动。可以看作一次"免费"的移动。走不走 ε 移动由自动机自己选择。这是第一次出现自动机可以做选择的情况。

DFA 和 NFA

  • 确定性有限自动机（DFA）：每个状态在每个输入上恰好一个转移，没有 ε 移动。
  • 非确定性有限自动机（NFA）：一个状态在一个输入上可以有零个、一个或多个转移，可以有 ε 移动。

Aiken 指出，其实 ε 移动就足以造出非确定性：一个状态在输入 a 上有两条转移，可以改写成先走两条 ε 移动到两个新状态，每个新状态各有一条 a 转移。所以两者的根本区别只在于有没有 ε 移动。

DFA 对每个输入只走一条路径，完全由输入决定。NFA 可以选，走着走着可能同时处在很多个状态里。NFA 的接受规则是：只要存在一种选择方式，能在读完输入时到达接受状态，就接受，其余的路径是否失败无关紧要。

看一个例子：状态 A、B、C，C 是接受状态；A 在 1 上回到 A，在 0 上可以去 A 也可以去 B；B 在 0 上去 C。输入 100：读 1 后可能状态集是 {A}；读 0 后是 {A, B}；再读 0，从 B 能到 C，从 A 能到 A 或 B，于是是 {A, B, C}。最后的集合里有接受状态 C，所以接受。规律是：每一步 NFA 处在一个状态集合里，读下一个字符时，把每个状态所有可能的移动都考虑进来，得到下一步的状态集合。

NFA 还可以"离开"状态：在课件的另一个演示里，某条路径走到没有转移的地方就消失了，集合缩小。

两者比较

  • NFA、DFA 和正则表达式的表达能力相同，都只能描述正则语言。
  • DFA 执行更快，没有选择要考虑，沿一条路径走就行；NFA 要跟踪一个状态集合。
  • NFA 通常小得多。对同一个语言，最小的 DFA 可能比最小的 NFA 大指数倍。

所以两者之间是空间和时间的取舍：NFA 紧凑，DFA 快。

五、正则表达式变成 NFA

对每一种正则表达式定义一个等价的 NFA，按表达式的结构从小到大归纳地构造（这就是 Thompson 构造）。记号：用一个方框表示表达式 M 的 NFA，只标出它的开始状态和接受状态，不关心内部结构。这样构造出来的机器都只有一个接受状态。

  • ε：开始状态经一条 ε 边到接受状态。
  • 单个字符 a：开始状态经一条 a 边到接受状态。
  • 连接 AB：已经有 A 的机器和 B 的机器。用 A 的开始状态作为整体的开始状态；A 的接受状态不再是接受状态，从它连一条 ε 边到 B 的开始状态；B 的接受状态是整体的接受状态。意思是：先认出属于 A 的一段输入，到达 A 的末尾时不读输入就跳到 B 的开头，再把剩下的部分当作 B 的串来读。
  • 并 A + B：新加一个开始状态，从它分别连 ε 边到 A 和 B 的开始状态；A、B 的接受状态各连一条 ε 边到新的接受状态。开头的非确定选择就是在猜"这个串属于 A 还是 B"。按 NFA 的接受规则，只要有一个猜对的选择就行。
  • 迭代 A*：新的开始状态和新的接受状态。开始状态有一条 ε 边直接到接受状态，保证接受空串；另有 ε 边进入 A 的开始状态；A 的接受状态有 ε 边回到整体的开始状态（再来一遍），也有 ε 边到整体的接受状态（到此为止）。这样就能认出零个或多个 A 的串。

例子：$(1+0)^*1$

按构造一步步来：先造只接受 1 的机器（C 经 1 到 E）和只接受 0 的机器（D 经 0 到 F）；用并的模板把它们合起来，新开始状态 B 经 ε 到 C、D，E、F 经 ε 到新接受状态 G；把这一块套进迭代的模板，新开始状态 A、新接受状态 H，A 经 ε 到 B 和 H，G 经 ε 到 A 和 H；再造一个接受 1 的机器（I 经 1 到 J），从 H 连 ε 边到 I。整体开始状态是 A，接受状态是 J。共十个状态 A 到 J。

六、NFA 变成 DFA

ε 闭包

一个状态的 ε 闭包是从它出发、只走 ε 移动能到达的所有状态，包括它自己。这是递归的，可以走任意多步 ε 移动。在上面的 NFA 里：

  • ε-closure(B) = {B, C, D}。
  • ε-closure(G) = {A, B, C, D, G, H, I}：G 到 H 和 A，H 到 I，A 到 B，B 到 C 和 D，从这些状态出发再也到不了新的状态。

关键观察

NFA 任何时刻处在某个状态子集里。如果 NFA 有 N 个状态，非空子集有 $2^N - 1$ 个。这是个很大的数，但它是有限的。所以可以造一个 DFA，让它的每个状态对应 NFA 的一个状态子集，用确定的方式模拟 NFA。

子集构造

NFA 有状态集 $S$、开始状态 $s$、接受状态集 $F$ 和转移关系。定义对状态集合的转移：$a(X) = \{ y \mid \exists x \in X,\ x \xrightarrow{a} y \}$，即从集合 X 中任一状态读 a 能到的所有状态。构造的 DFA：

  • 状态：S 的子集。
  • 开始状态：ε-closure(s)。NFA 从 s 出发，在读第一个字符之前就可以走 ε 移动，所以它一开始可能处在的状态集就是 s 的 ε 闭包。
  • 接受状态：$\{ X \mid X \cap F \neq \emptyset \}$。只要集合里有一个 NFA 的接受状态，就说明 NFA 有某种走法能接受，那就够了。
  • 转移：$X \xrightarrow{a} Y$ 当且仅当 $Y = \text{ε-closure}(a(X))$。先看读 a 能到哪些状态，再加上之后能走的 ε 移动。对每个 X 和 a 这样的 Y 只有一个，所以是确定的。

这样得到的 DFA 状态有限，有开始状态和接受状态，每个输入只有一个转移，没有 ε 移动。它维持的性质是：每走一步，DFA 的状态记录的就是 NFA 读了同样的输入之后可能处在的状态集合。

例子

把所有子集都列出来太多了，而且很多子集用不到。实际做法是从开始状态出发，只构造需要的状态：

  • 开始状态：ε-closure(A) = {A, B, C, D, H, I}。
  • 从它读 0：只有 D 经 0 到 F，ε-closure(F) = {F, G, H, I, A, B, C, D}。
  • 从它读 1：C 经 1 到 E，I 经 1 到 J，再取 ε 闭包得 {E, J, G, H, I, A, B, C, D}，除了 F 以外的所有状态。里面有 NFA 的接受状态 J，所以这是 DFA 的接受状态。
  • 从后两个状态读 0 都回到 {F, G, H, I, A, B, C, D}，读 1 都回到 {E, J, ...}。

得到一个三状态的 DFA，它接受 NFA 接受的那些串，也就是以 1 结尾的 0、1 串。

七、实现 DFA

DFA 可以用一个二维表 T 实现：一维是状态，一维是输入符号。对每个转移 $S_i \xrightarrow{a} S_k$，令 $T[i, a] = k$。运行时，在状态 i 读到输入 a，查 $T[i, a]$ 得到 k，转到状态 k。

把上面的 DFA 状态叫作 S（开始）、T、U（接受），转移表是：

01
STU
TTU
UTU

驱动它的代码只有一个循环： 

// A is the transition table, input is a null-terminated string
int i = 0;
int state = 0;              // start state S
while (input[i]) {
    state = A[state][input[i++]];
}
// accept iff state is an accepting state

每读一个字符只做一点下标运算和一两次查表。Aiken 说很难想象有比这更快、更紧凑的过程。

压缩表格

这张表的三行完全一样。可以改成一维表：每个状态一项，存一个指针，指向描述"读 0 去哪、读 1 去哪"的那一行；相同的行就共享同一份。词法分析用的自动机里重复的行很常见，而 DFA 的状态数可能达到 $2^N - 1$，虽然通常不会膨胀到最坏情况，但表可能相当大，这种技巧能大幅压缩。代价是多了一次间接寻址，内层循环要多解引用一次指针，会慢一点。

直接用 NFA

有时规格转成 DFA 代价太大，表格大得离谱，不如直接用 NFA。NFA 也可以用表表示：每个 NFA 状态一行，列是 0、1 和 ε，表项是状态的集合（因为可能有多个转移），比如 A 在 ε 上到 {B}，B 在 ε 上到 {C, D}，C 在 1 上到 {E}。这张表一定比较小，大小受 NFA 状态数和字母表大小限制。但内层循环贵得多：每一步要维护一个状态集合，对集合里每个状态查它能去哪，还要把所有 ε 移动都走完，才能得到准确的下一个状态集合。

小结

实现词法规格的核心是把 NFA 转成 DFA：把用正则表达式写的通用高层规格，变成完全确定、每个输入字符只需几个操作的程序。实际工具（比如 flex）提供速度和空间的取舍：DFA 快但不紧凑，表可能大到成为实际问题；NFA 慢但简洁。工具通常用配置文件或命令行选项让你选择更靠近完整的 DFA，还是更靠近纯 NFA。
