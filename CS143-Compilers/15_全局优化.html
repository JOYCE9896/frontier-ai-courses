第十五讲：全局优化

把常量传播和死代码消除推广到整个控制流图，全局常量传播的正确性条件；全局数据流分析的共同特征和"保守总是安全的"；用 ⊥、常量、⊤ 三种抽象值做常量传播，八条局部规则和不动点算法；循环为什么需要 ⊥；抽象值的序和最小上界，算法为什么终止、为什么是线性的；活跃性分析和全局死代码消除；前向分析和后向分析

主讲：Fredrik Kjolstad（2026 年春季）；录像主讲：Alex Aiken
资料来源：课件（2026 年 5 月 21 日）、录像第 15 周（15-01 Dataflow Analysis 到 15-05 Liveness Analysis，按小节转载的播放列表）

一、从局部到全局

要讲全局优化，先得讲数据流分析。回顾基本块里的常量传播和死代码消除： 

X := 3              X := 3
Y := Z * W    =>    Y := Z * W    =>    Y := Z * W
Q := X + Y          Q := 3 + Y          Q := 3 + Y

常量赋值可以向前传播到 X 的使用处（基本块是单赋值形式时尤其容易）；如果 X 的这个值在程序别处都没用，赋值就是死的，可以删掉。

这些优化可以推广到整个控制流图。第一个例子： 

        X := 3
        B > 0
       /      \
Y := Z + W    Y := 0
       \      /
      A := 2 * X

第一个基本块有一个测试，为真去一个块，为假去另一个块。这里把 A := 2 * X 里的 X 换成 3 是安全的。第二个例子只多了一句： 

        X := 3
        B > 0
       /      \
Y := Z + W    Y := 0
X := 4         |
       \      /
      A := 2 * X

这里就不能把 X 换成 3，因为左边那条路上 X 被赋了 4。有意思的是，X 只被赋过常量，可是在 A := 2 * X 这一点 X 的值仍然未知：从左边来是 4，从右边来是 3，换成哪个都不对。

正确性条件

要把对 x 的一次使用换成常量 k，必须知道：

(**) 在到达这次使用的每条路径上，对 x 的最后一次赋值都是 x := k。

第一个例子到达 X 的使用只有两条路，X := 3 在两条路上，而且是最后一次赋值，所以可以替换。第二个例子左边那条路上最后的赋值是 X := 4，不能传播任何常量。

这个条件不容易检查，"所有路径"包括绕过循环的路径和穿过条件分支的路径。检查它需要全局分析，即对整个控制流图的分析，这一族技术叫全局数据流分析。

全局分析的共同特征

  • 优化依赖于知道程序执行中某个特定点上的某个性质 X，比如这一点上 x 是否一定是常量。想知道的是一个很局部的事实。
  • 但要证明任一点上的 X，需要关于整个函数的知识，要对通向这条语句的所有路径做推理：从方法入口出发，穿过循环、越过条件分支。一般来说这很难，有些问题精确求解代价极高。
  • 救星是：保守总是可以的。如果优化要求 X 为真，那么我们想知道的是"X 一定为真"或"不知道 X 是否为真"。说"是"就必须是对的，不能出错；但说"不知道"永远是安全的，最坏不过是不做这个优化。所以只要在声称性质成立时总是对的，用近似的、并非总能给出精确答案的技术也没问题。

全局数据流分析就是解决具有这些特征的问题的标准技术，全局常量传播是需要它的一个优化。

二、全局常量传播

在 (**) 成立的任何一点都可以做全局常量传播。下面只讨论对单个变量 X 在所有程序点上计算 (**)。推广到所有变量很容易，一个简单但低效的办法是对方法体里每个变量各算一遍。

在每个程序点给 X 关联下面三种值之一：

值读法含义
⊥bottom这条语句不可达（从不执行）
cX = 常量 c，已经证明在这一点 X 总是这个常量
⊤topX 不是常量。说"不知道 X 是否为常量，X 可能是任何值"总是安全的

⊥ 不那么直观，直觉上它和 ⊤ 相反：如果不知道一条语句到底会不会执行，就说 X 在那里是 ⊥，意思是据我们所知这一点从未被到达，那 X 是什么值都无所谓。它在常量传播乃至所有全局数据流分析里都起着很重要的作用。

手工分析一遍

对第二个例子逐点标注。注意程序点在语句之间，每条语句前后各有一个程序点：

  • 入口之前，不假设前面有什么代码，为了安全，X = ⊤。
  • X := 3 之后，X = 3。说"这一点 X = 3"指的是赋值执行后、条件判断执行前 X 等于 3。
  • 条件分支不修改也不读 X，两个分支上 X 都还是 3。
  • 右边 Y := 0 不影响 X，之后仍是 3。左边 Y := Z + W 之后仍是 3，X := 4 之后是 4。
  • A := 2 * X 之前的那一点，和"X := 4 之后""Y := 0 之后"是不同的程序点：前两个点还知道自己在哪条路上，这一点是两条路的汇合处，不知道从哪来。一条路上是 3，另一条是 4，没有哪个常量能给它，只能是 X = ⊤。A 的赋值不影响 X，之后仍是 ⊤。

有了每个程序点上的常量信息，做优化就很简单：看用到 x 的语句处关联的信息，如果 x 在那里是常量，就把这次使用换成常量。关键问题是怎样在任意控制流图上系统地算出这些性质。

三、规则

所有数据流分析算法都遵循一条基本原则：复杂程序的分析，可以表达为一些简单规则的组合，每条规则只描述相邻语句之间信息的变化。做法是把信息从一条语句"推"或"传递"到下一条。对每条语句 s，计算 x 在 s 紧前和紧后的值：

  • $C(s, x, \text{in})$：s 之前 x 的值；
  • $C(s, x, \text{out})$：s 之后 x 的值。

C 代表常量信息。下面定义传递函数，把信息从一条语句传到另一条。设语句 s 的直接前驱语句是 $p_1, \ldots, p_n$。

前驱的 out 到 s 的 in

  1. 如果对某个 i，$C(p_i, x, \text{out}) = \top$，那么 $C(s, x, \text{in}) = \top$。在某条通向 s 的路上不知道 x 是不是常量，就不知道 x 在 s 处是不是常量，因为执行可能就是从那个前驱来的。
  2. 如果 $C(p_i, x, \text{out}) = c$，$C(p_j, x, \text{out}) = d$，且 $d \neq c$，那么 $C(s, x, \text{in}) = \top$。不知道运行时走哪条路，就不知道是哪个常量。手工例子里就是这种情况。
  3. 如果对所有 i，$C(p_i, x, \text{out})$ 是 c 或 ⊥，那么 $C(s, x, \text{in}) = c$。从值为 c 的那些路来，x 当然是 c；⊥ 表示那个前驱从不执行，不可能从它那条路到达 s。所以只要执行到达 s，x 就一定是 c。
  4. 如果对所有 i，$C(p_i, x, \text{out}) = \bot$，那么 $C(s, x, \text{in}) = \bot$。所有前驱都不可达，s 自己也不可能执行。

s 的 in 到 s 的 out

  1. 如果 $C(s, x, \text{in}) = \bot$，那么 $C(s, x, \text{out}) = \bot$。s 之前的点到不了，之后的点当然也到不了。
  2. $C(x := c, x, \text{out}) = c$，c 是常量。不管之前 x 是什么，执行完 x 就是 c。这条和规则 5 冲突（之前可能是 ⊥），规则 5 优先：能说之后是 ⊥ 就说 ⊥；只有之前是某个常量 d 或 ⊤，也就是据我们所知控制能到达这里时，才用规则 6。
  3. $C(x := e, x, \text{out}) = \top$，e 是不是常量的表达式（比常量复杂的任何东西）。不去猜那个计算的结果，就说不知道。同样规则 5 优先。
  4. $C(y := \ldots, x, \text{out}) = C(y := \ldots, x, \text{in})$，如果 $x \neq y$。给别的变量赋值，x 之前是什么（⊥、常量或 ⊤），之后还是什么。

算法

  1. 对程序的每个入口语句 s，令 $C(s, x, \text{in}) = \top$。入口肯定会执行，但对 x 一无所知。
  2. 其他所有地方令 $C(s, x, \text{in}) = C(s, x, \text{out}) = \bot$。直觉上是说：除了入口，我们还没证明控制流图里任何别的语句真的会执行，先假设它们都不执行。这一点很重要。
  3. 重复，直到所有点都满足规则 1 到 8：挑一个不满足规则的 s，用相应的规则更新。

这是一种约束满足的做法：在控制流图里找按规则信息不一致的地方，更新信息使之一致。在手工例子上跑一遍：开始时只有 X := 3 处不一致（之前是 ⊤，之后却是 ⊥），更新为 3；于是下一条语句变成"可达但之后是 ⊥"，不一致，按规则 8 更新为 3；接着单前驱的地方 in 要等于前驱的 out，两个分支都变成 3；对别的变量赋值，前后相同；X := 4 之前可达，常量赋值，之后是 4；汇合处两个前驱不一致，是 ⊤；A 的赋值前后相同，之后也是 ⊤。此时所有程序点的信息都满足规则，算法结束。

四、循环和 ⊥

分析循环无疑是整个问题里最有意思的部分，⊥ 的必要性和它紧密相关。 

        X := 3
        B > 0
       /      \
Y := Z + W    Y := 0   <--+
       \      /           |
      A := 2 * X          |
        A < B  -----------+

看语句 Y := 0。要算出它之前 X 是不是常量，需要知道它两个前驱处 X 的值：X := 3 那一边，和 A := 2 * X、A < B 回来的那条回边。而回边上的信息依赖于它的前驱，沿着边往回追，又依赖于 Y := 0 本身。信息依赖于前驱，递归追下去，就会绕着循环转回来。这就是难题所在：前驱的信息依赖于自己，怎么办？

数学里处理这类递推关系或递归方程有一个标准办法：从一个初始猜测出发打破循环，这个初始近似并不指望是最终结果，只是让计算能开始。因为有环，所有程序点在任何时候都必须有值，给它们赋一个初始值，这就是 ⊥ 的用途。初始值 ⊥ 的意思是"就目前所知，控制从未到达这一点"。

分析：除入口外所有点都设为 ⊥（包括两条路汇合之后的那一点）。X := 3 之后不一致，改为 3；条件分支不改 X，两个分支都是 3；Y := Z + W 之后是 3。现在到了关键处：Y := 0 的一个前驱给出 3，另一个前驱（回边）据目前所知从未被到达。先假设那条路从不走，它就没有贡献，所以 Y := 0 之前 X = 3。这样就打破了环、开始了计算：先假设环上最后一条边从不执行，如果这个假设不对，以后会发现的，那里的值会变成 ⊥ 以外的东西，到时再更新。继续：Y := 0 之后是 3；汇合处两边都是 3，A := 2 * X 之前是 3；之后是 3；条件判断不改 X，回边上是 3。回边的信息变了，现在知道控制能到达这条边，要重新检查：Y := 0 的两个前驱都是 3，之前的结论"Y := 0 之前 X = 3"仍然一致。没有任何不一致的地方了，分析完成：除入口外所有点上 X 都是常量 3。

五、序和终止性

分析里用来计算的 ⊥、常量、⊤ 叫抽象值，以区别于程序运行时真正计算的具体值（真实的对象、数字等）。抽象值一般代表一组可能的具体值，在常量传播里真正抽象的只有 ⊤，它代表所有可能的运行时值。

给抽象值排序，可以简化分析的表述：

$$\bot < c < \top$$

画成图，低的值画在下面：⊥ 在最底下，所有常量（…, −1, 0, 1, …）在中间一层，⊤ 在最上面。⊤ 是最大值，⊥ 是最小值，所有常量在中间且互不可比。这和数值大小无关，0 并不小于 1，任意两个不同常量都不可比。

有了序，就能定义最小上界 lub，即比所有参与者都大（大于或等于）的最小元素：lub(⊥, 1) = 1，lub(⊤, ⊥) = ⊤，lub(1, 2) = ⊤（两个不可比的常量，比两者都大的最小元素只有 ⊤），lub(⊥, 2) = 2，lub(2, ⊤) = ⊤。在这个简单的序里，不可比的东西的 lub 总是 ⊤。规则 1 到 4 其实就是在算 lub：

$$C(s, x, \text{in}) = \text{lub}\{ C(p, x, \text{out}) \mid p \text{ 是 } s \text{ 的前驱} \}$$

为什么终止

算法的终止条件是"反复应用规则直到没有变化"。但光这么说并不能保证最终会没有变化：也许每次更新都引入新的不一致，永远到不了全部一致。序说明了为什么这不会发生：

  • 除入口外，所有值从 ⊥ 开始，即序的最底层。
  • 仔细看规则就会发现，它们只能让一个程序点上的值增大：⊥ 可以变成常量，常量可以变成 ⊤。到了 ⊤ 就没有更大的元素了。
  • 所以每个 $C(s, x, \_)$ 最多变两次。

因此算法关于程序规模是线性的：步数 ≤ 要计算的 C 值的个数 × 2 = 程序语句数 × 4（每条语句有 in 和 out 两个值，每个最多变两次）。

六、活跃性分析

全局传播常量之后，希望消除死代码。在第一个例子里，把 A := 2 * X 的 X 换成 3 之后，X := 3 可能就没用了，如果 X 在程序别处不再使用，可以删掉它，这是一个真正重要的优化。但前提是 X 在别处没有使用，"没有使用"要说得更准确些。 

X := 3
X := 4
Y := X

第二次写入的 X 的值是活跃的，可能在将来被使用（这里不只是可能，是一定会被使用，因为只有一条路，路上在下一次给 X 赋值之前就读了 X）。一般只要求有被使用的可能。第一次写入的值是死的：在任何使用之前就被 4 覆盖了，这个值永远见不到天日。

定义：变量 x 在语句 s 处活跃，如果

  • 存在某条语句 s' 使用 x；
  • 存在一条从 s 到 s' 的路径；
  • 这条路径上没有对 x 的中间赋值。

不活跃就是死的。如果赋值 x := ... 之后 x 是死的，这条语句就是死代码，可以从程序里删掉。但为此先要有活跃性信息：要把"x 将来会不会被用到"这个全局性质，变成程序中某个特定点上的局部信息，才能做局部的优化决定。

规则

和常量传播一样，用相邻语句之间传递信息来表达活跃性。它比常量传播简单，因为是布尔性质，非真即假。

  1. $L(p, x, \text{out}) = \bigvee \{ L(s, x, \text{in}) \mid s \text{ 是 } p \text{ 的后继} \}$。x 在 p 之后紧接着活跃，当且仅当从 p 出发的某条路上会用到 x 的值，所以对 p 所有后继的入口处 x 的活跃性取"或"。
  2. 如果 s 在右边引用了 x（读了 x），那么 $L(s, x, \text{in}) = \text{true}$。x 马上就要被用到。
  3. 如果 e 不引用 x，那么 $L(x := e, x, \text{in}) = \text{false}$。语句覆盖了 x，而右边不读 x，x 在这条语句之前的值永远不会被读，在那一点是死的。
  4. 如果 s 不引用 x（既不读也不写），那么 $L(s, x, \text{in}) = L(s, x, \text{out})$。之后活跃，之前也活跃；之后死，之前也死。

算法：初始令所有 L 为 false；重复直到所有语句满足规则 1 到 4，挑一个不满足的语句，用相应规则更新。

例子

x := 0
L:
    if x == 10 goto exit
    x := x + 1
    goto L
exit:          # x is dead here

一个数到 10 就退出的傻程序。假设出口处 x 是死的。初始所有点都是 false。x := x + 1 读了 x，所以它之前 x 活跃。这条语句既读又写 x，但"读则活跃"的规则优先，因为读发生在写之前：x 的旧值确实被用了。x == 10 的判断也读了 x，它之前 x 活跃。沿着边往回推：回边上活跃，初始化块的出口也活跃。再绕回来，循环体里已经知道是活跃的，不用再改。入口处呢？x := 0 写 x，右边不读 x，所以入口处 x 是死的：进入这段代码时 x 是什么值，将来都不会被用到。这就是每个程序点上正确的活跃性信息。

终止性

值只会从 false 变成 true，不会反过来。按序的说法，这里只有两个值，false < true，一切从最底层开始，只能往上升。每个值最多变一次，所以保证终止。算完活跃性，消除死代码就很简单了。

七、前向分析和后向分析

  • 常量传播是前向分析：信息从输入推向输出，和计算的方向相同。X 在上面被赋了常量，下面用到 X，常量就向前流到使用处。
  • 活跃性是后向分析：信息从输出推回输入，逆着执行的方向流向程序开头。

文献里还有很多别的全局流分析，常量传播和活跃性是其中最重要的两种。几乎都可以归为前向或后向，也有一些重要的分析两者都不是，信息双向推送。而且几乎所有全局流分析都遵循同样的方法论：用局部规则联系相邻程序点之间的信息，把分析整个控制流图这个复杂问题，拆成一组只在很局部的范围内传播信息的规则。
