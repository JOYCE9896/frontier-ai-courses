二、编程语言的经济学

讲语言的设计和实现细节之前，Aiken 先讲语言在现实世界里怎样运作：为什么有的语言被人用，有的没人用。他提了三个问题。

为什么有这么多语言

不同的应用领域有各自的需求，而且常常互相冲突，很难造出一门对所有场合都好用的语言。三个例子：

领域需要什么代表语言
科学计算（大规模工程计算和科学模拟）很好的浮点支持，很好的数组和数组运算支持（最常见的数据就是大型浮点数组），并行FORTRAN。它本来就是为科学计算设计的，后来演变得和最初的版本毫不相像，但一直守住了这个用户群
商业应用数据持久、不能丢；好的报表工具；能对数据提问（数据分析）SQL。关系数据库及其语言主导这个领域
系统编程（嵌入式、控制设备、操作系统）对资源的细粒度控制；时间要求，比如实时约束，网络设备必须在一定时间内响应C，某种程度上还有 C++

这几个领域最看重的东西互不重合，很难把它们装进一个系统里还都做好。

为什么还在出新语言

Aiken 的出发点是一个看起来不相关的观察：一门语言最大的成本是培训程序员。设计一门语言通常只需要一个人或很少几个人，写一个很好的编译器大概十到二十人。真正的成本在所有用户身上：几千、几十万、上百万程序员学这门语言，花的钱买书上课，还有他们花的时间，这些时间是真实的经济损失。

从这个观察可以推出几条预测：

  • 用的人多的语言变得慢。改动一门被很多人用的语言，哪怕是一点语法、一个小功能、编译器接口的小改变，都要把整个社区重新教一遍。用户越多，变化越慢，最流行的语言会越来越"僵化"。实际看到的情况和这个预测很一致。
  • 新语言起步很容易。一开始用户是零，培训成本也是零；用户很少时改语言也不贵。所以新语言变得快，能很快适应新情况，拿新语言做实验很便宜。
  • 程序员什么时候会放弃一门广泛使用的老语言，换一门新语言？当生产效率的提升超过培训成本的时候。
  • 综合起来：语言在填补空白的时候最容易被采用。信息革命还在进行，新的应用领域不断出现：前些年的互联网催生了 Java 等一批语言，后来的移动应用也带来了很多新技术。老语言变得慢，很难适应新领域，所以新机会出现、又有足够多的程序员时，往往会出现新语言。
  • 新语言往往像老语言。一部分原因是真正全新的东西很难想出来，另一部分是经济上的好处：利用人们已经会的东西，降低培训成本。最经典的例子是 Java 有意设计得很像 C++，好让 C++ 程序员容易转过来。

什么是好语言

这里情况就不清楚了。Aiken 只说一句：语言设计没有公认的衡量标准。人们提过很多度量，但大多数人不相信它们，更没有共识。看看程序员论坛里那些近乎宗教的争论就知道，研究者之间也没有共识。

有人很认真地提过一个标准："好语言就是有人用的语言。"Aiken 不同意。这个度量清楚，衡量的是流行程度，也许用的人多的语言确实有它的道理；但照这个逻辑推到底，Visual Basic 就是最好的语言。他说自己不反对 Visual Basic，它是一个设计得不错的系统，但它的设计者自己大概也不会说它是世界上最好的语言。决定一门语言是否流行的因素有很多，技术上的优秀可能都排不上最重要：更重要的是它是否填补了一个没有更好工具的领域，一旦被接受、用户多了，惯性和历史会让它存活下去。所以今天还有 FORTRAN、COBOL，如果今天从头设计，这些语言都能设计得好得多。

两条要记住的结论：应用领域的需求互相冲突，很难设计一个面面俱到的系统；培训程序员是语言的主要成本。两条合在一起就解释了新语言为什么不断出现。

三、思想史：抽象、类型、复用

抽象

抽象就是脱离具体细节。课件引了 Andrew Koenig 的话："抽象是有选择的无知。"抽象有几种方式：

  • 通过语言和编译器：写高层代码，很少依赖具体机器。
  • 通过函数：给行为一个抽象的接口。
  • 通过模块：导出接口，隐藏实现。
  • 通过类和抽象数据类型：把数据和对它的操作捆在一起。

要造任何复杂的系统都离不开抽象。核心是信息隐藏，只暴露必要的东西，同时让你能在高层推理程序的性质。

类型

一开始类型很少：FORTRAN 只有标量和数组，LISP 在静态上不区分类型。后来人们认识到类型有帮助：

  • 能表达并强制执行抽象。
  • 编译器能报告很多常见错误，有时甚至能保证程序"安全"。
  • 帮编译器优化代码。

近来大家对类型很感兴趣，在各种参数化的形式上做实验，发展得最好的是函数式编程。

复用

复用是利用软件系统里的共同模式，目标是像大规模生产那样生产软件组件。复用很难。两种流行的办法：类型参数化（List(int)、List(double)），以及类和继承（C++ 的派生类）。C++ 和 Java 两样都有。继承让你能对已有的抽象做特化、扩展、修改，以及隐藏行为。

趋势和为什么学这门课

语言设计上，出现了很多新的专用语言，而流行语言会一直存在下去（也许永远），比如 FORTRAN 和 COBOL。编译器则越来越必要、越来越复杂，推动它的是新语言和新体系结构之间不断拉大的距离。

课件列了学语言和编译器的五条理由，从第五到第一：

  1. 增强表达能力。
  2. 更好地理解程序的行为。
  3. 更快地学会新语言。
  4. 学会构建一个大而可靠的系统。
  5. 看到很多计算机科学的基本概念在实际中怎样运作。

四、Cool 语言

Cool 是 Classroom Object Oriented Language（课堂用的面向对象语言）。它独特的设计要求是：编译器必须能在一个学季里写完。Aiken 说，世界上 Cool 编译器的数量远远超过 Cool 程序的数量，编译器可能有成千上万个，程序大概只有几十上百个，这大概是唯一一门编译器比程序多的语言。这也说明了它的设计重点：编译器好写比程序好写重要得多，所以语言里有些怪地方，是专门为了好实现而做的，日常编程用起来会不方便。

Cool 想让你尝到现代语言实现的几个方面：抽象、静态类型、通过继承复用、内存管理，还有一些后面遇到再讲。很多东西被省掉了：没有数组、浮点运算、异常等等。

类和对象

Cool 程序是一组类定义。必须有一个特殊的类 Main，里面有一个特殊的方法 main。所有 Cool 代码都写在类里面。类是属性（attribute，相当于 Java 的字段）和方法的集合，类的实例是对象。 

class Point {
    x : Int <- 0;
    y : Int;        (* use default value *)
};

课件里赋值写成 ←，源文件里写成 <-。一个对象可以看作一个记录，每个属性占一个槽。new Point 创建一个 Point 类的新对象，没写初值的属性取默认值，Int 的默认值是 0。

方法和信息隐藏

class Point {
    x : Int <- 0;
    y : Int <- 0;
    move(newx : Int, newy : Int) : Point {
        {
            x <- newx;
            y <- newy;
            self;
        }   -- close block expression
    };      -- close method
};          -- close class

方法可以用 self 指当前对象。在 Cool 里方法是全局可见的，属性是类私有的，只能被这个类的方法访问，外部想读写就得提供方法： 

class Point {
    ...
    x() : Int { x };
    setx(newx : Int) : Int { x <- newx };
};

每个对象都知道怎样找到方法的代码，就好像对象里有一个指向方法代码的槽。实际实现为了省空间，同一个类的所有实例共享这些指针：对象里只放一个指针，指向这个类的方法表。第十二讲讲对象布局时会细讲。

继承

class ColorPoint inherits Point {
    color : Int <- 0;
    move(newx : Int, newy : Int) : Point {{
        color <- 0;
        x <- newx;
        y <- newy;
        self;
    }};
};

用子类把点扩展成带颜色的点，形成类的层次结构。ColorPoint 的对象有 x、y、color 三个槽，move 方法被重新定义（覆盖）。

类型

  • 每个类都是一个类型。
  • 基本类：Int 整数，Bool 布尔值（true、false），String 字符串，Object 是类层次的根。
  • 所有变量都必须声明类型，表达式的类型由编译器推出来。
  • 如果 A 是 B 在类层次里的祖先，那么 x : A; x <- new B; 是类型正确的：凡是需要 A 的地方都可以用 B。
  • 类型安全：类型正确的程序在运行时不会出现类型错误。

动态分派

p : Point;
p <- new ColorPoint;
...
p.move(1, 2);

方法通过分派（dispatch）调用。p 的静态类型是 Point，动态类型是 ColorPoint，p.move 必须调用 ColorPoint 的那个版本。有继承时怎样正确地分派，是面向对象语言里很微妙的一部分。调用一个单参数方法 e.m(a) 的步骤：

  1. 求出实参 a 的值。
  2. 求出 e 的值（得到一个对象）。
  3. 找出 e 的类。
  4. 在这个类的方法表里找到 m 的代码。
  5. 把 self 绑定到 e 的值，形参 x 绑定到实参的值。
  6. 运行方法体。

表达式

Cool 是表达式语言：每个表达式都有类型和值，能放代码的地方就能放任意表达式。方法没有 return 语句，方法体的值就是方法的返回值。

结构写法
循环while E loop E pool
条件if E then E else E fi
分情况case E of x : Type => E; ... esac
算术+、- 等
比较<、= 等
赋值x <- E
基本输入输出out_string(s)、in_string() 等

结束关键字是开始关键字倒过来写：loop/pool、if/fi、case/esac。

内存管理

每次调用 new 就分配内存；对象不再可达时，内存自动回收，由垃圾回收器完成。Cool 有自己的垃圾回收器，第十七讲讲。

课程项目

一个完整的编译器，把 Cool 编译成 MIPS 汇编，不做优化。MIPS 是 1980 年代设计的真实指令集，有一个几乎在任何机器上都能跑的模拟器 SPIM，所以整个项目很容易移植。项目分四次编程作业，可以一个人做，也可以两人一组。Aiken 在录像里补充了一点：各个阶段是"即插即用"的，每个阶段都有独立的参考实现。比如做语义分析时，可以拿参考编译器的词法分析、语法分析和代码生成，把自己的语义分析插进去测试。这样就算某个阶段没做好，也不影响做下一个阶段。

五、演示一：Hello World

录像里 Aiken 现场写了三个 Cool 程序，故意犯了不少错误，正好展示编译器报什么错。Cool 源文件扩展名是 .cl，编译器叫 coolc，模拟器叫 spim。

最简单的程序： 

class Main {
    main() : Int { 1 };
};
  • 类声明以 class 开头，接类名和一对花括号，每个类声明以分号结尾，类里每个特征（属性或方法）也以分号结尾。
  • Main 类的 main 方法必须存在、不能有参数，程序从它开始运行。
  • 第一次编译报语法错误，因为漏写了返回类型。Cool 方法必须声明返回类型：方法名和参数表后面接冒号和类型。
  • coolc one.cl 生成 one.s，spim one.s 运行，输出里有一行"COOL program successfully executed"，后面是执行的指令数、读写次数、分支数等统计。程序没有输出，因为没让它输出。

要输出，得用内置的 IO 类： 

class Main {
    i : IO <- new IO;
    main() : Int {{
        i.out_string("Hello World!\n");
        1;
    }};
};
  • 块表达式 { e1; e2; ... } 按顺序求值，块的值是最后一个表达式的值。块里每个表达式都要以分号结尾，漏掉最后一个分号会报语法错误。
  • 一开始只写了 i : IO;，编译通过，运行时报"dispatch to void"：声明变量不会创建对象，i 没有值（void，相当于空指针）。要用 new IO 初始化。new 总是带一个类型参数。

同一个程序的几种写法：

  • 去掉块，方法体只写 i.out_string("...")，编译报错："inferred return type IO of method main does not conform to declared return type Int"。out_string 返回的是 IO 对象本身。把返回类型改成 IO，或者更宽松地写成 Object（类层次的根，每个类都是它的子类）就行。
  • 不要属性 i，在方法里直接 (new IO).out_string("...")。
  • 让 Main 继承 IO，于是 Main 自己就有 out_string，可以写 self.out_string("...")；分派时不写对象，默认就是 self，所以最后可以只写 out_string("...")。

六、演示二：阶乘

先读一个字符串再原样打印：out_string(in_string().concat("\n"))。要做整数运算，需要字符串和整数之间的转换，课程提供了一个用 Cool 写的库 A2I（ASCII to integer），让 Main 继承它，就能用 a2i 和 i2a。编译时把库文件一起列在命令行上，coolc fact.cl atoi.cl，编译器把所有文件当一个程序处理；忘了加会报"undefined class A2I"。

递归版本： 

class Main inherits A2I {
    main() : Object {
        (new IO).out_string(i2a(fact(a2i((new IO).in_string()))).concat("\n"))
    };

    fact(i : Int) : Int {
        if (i = 0) then 1 else i * fact(i - 1) fi
    };
};

循环版本，用 let 声明局部变量： 

fact(i : Int) : Int {
    let fact : Int <- 1 in {
        while (not (i = 0)) loop
        {
            fact <- fact * i;
            i <- i - 1;
        }
        pool;
        fact;
    }
};
  • 局部变量可以和方法同名，都叫 fact，Cool 不会弄混，因为变量和方法扮演不同的角色。
  • 累乘变量要初始化为 1，Int 默认是 0。
  • let 由变量声明和一个主体组成，let 的值是主体的值；while 循环体只能是一个表达式，所以要用块；let 的主体也是块，最后一个表达式 fact 就是整个方法的值。
  • 赋值和初始化都用 <-。

Aiken 演示了一个他自己一段时间不写 Cool 就会犯的错：习惯了 C 或 Java，把赋值写成 fact = fact * i。编译通过，运行后进入死循环，最后内存耗尽（"out of heap"）。原因是 Cool 里 = 是比较运算符，fact = fact * i 是一个合法的布尔表达式，只是什么都没改，i 永远到不了 0。至于为什么这个循环会不断消耗内存，课程后面才讲。

七、演示三：链表

先用 let 一次声明多个变量，用逗号分隔（是分隔符，最后一个后面没有逗号），后面的变量可以用前面已经声明的变量： 

let hello : String <- "Hello ",
    world : String <- "World!",
    newline : String <- "\n"
in
    out_string(hello.concat(world.concat(newline)))

然后写一个链表类： 

class List inherits A2I {
    item : Object;
    next : List;

    init(i : Object, n : List) : List {
        {
            item <- i;
            next <- n;
            self;
        }
    };

    flatten() : String {
        let string : String <-
            case item of
                i : Int => i2a(i);
                s : String => s;
                o : Object => { abort(); ""; };
            esac
        in
            if (isvoid next) then
                string
            else
                string.concat(next.flatten())
            fi
    };
};

class Main inherits IO {
    main() : Object {
        let hello : String <- "Hello ",
            world : String <- "World!",
            i : Int <- 42,
            newline : String <- "\n",
            nil : List,
            list : List <-
                (new List).init(hello,
                    (new List).init(world,
                        (new List).init(i,
                            (new List).init(newline, nil))))
        in
            out_string(list.flatten())
    };
};
  • init 返回 self，方便把调用串起来。
  • Cool 里没法直接写出空指针，它叫 void，但没有对应的符号。办法是声明一个不初始化的 List 变量 nil，它的值就是 void。
  • isvoid e 判断是否为空。
  • 写成 flatten(next) 是错的，应该是对 next 分派 next.flatten()。
  • 链表要能装任意对象，打印时就得在运行时区分对象的实际类型，用 case：每个分支给对象起个新名字并按类型处理，分支以分号结尾（let 的绑定用逗号分隔，case 的分支用分号结尾，Aiken 当场把两者弄混了一次）。
  • 默认分支调用 abort() 终止程序，但 abort 的类型是返回 Object，而 case 的这个分支需要是 String 才能让 let 的类型对上。办法是放进一个块里，先 abort，再随便放一个字符串，块的类型就是 String。Aiken 说这样写很难看，但这是让类型检查器接受的办法。
