第八讲：自底向上分析

归约和逆向的最右推导，移进归约分析和栈，两种冲突；句柄，句柄只出现在栈顶；活前缀，活前缀构成正则语言；LR(0) 项，识别活前缀的 NFA 和 DFA，有效项；LR(0) 分析和它的冲突，SLR 用 Follow 集改进，优先级声明其实是冲突消解；SLR 分析的完整演示，用 goto 表和 action 表的高效算法，LR(1) 和 LALR(1)，两个练习例子

主讲：Fredrik Kjolstad（2026 年春季）；录像主讲：Alex Aiken
资料来源：课件（2026 年 4 月 21 日和 23 日两次课）、录像第 7 周（07-05 Bottom-Up Parsing、07-06 Shift-Reduce Parsing）、录像第 8 周（08-01 Handles 到 08-08 SLR Examples）

一、归约

自底向上分析比确定性的自顶向下分析更通用，效率一样，而且用到了自顶向下分析的全部思想。它是大多数语法分析器生成工具采用的方法。

自底向上分析器不需要提取左因子的文法，可以回到"自然"的文法（这里的"自然"加了引号，因为仍然要把 + 和 * 的优先级写进文法里，自底向上分析器也处理不了二义文法）：

$$E \to T + E \mid T \qquad T \to \texttt{int} * T \mid \texttt{int} \mid (E)$$

自底向上分析把输入串归约到开始符号，也就是把产生式反过来用：在串里找到和某条产生式右部匹配的子串，换成左部。分析 int * int + int：

串用的产生式
int * int + intT → int
int * T + intT → int * T
T + intT → int
T + TE → T
T + EE → T + E
E

从下往上读，这就是一个普通的推导；从上往下（分析器实际的方向）读，叫归约。再仔细看从 E 往下的推导：E → T + E 后展开的是右边的 E，然后是右边的 T，然后是 T → int * T 里的 T……每一步展开的都是最右边的非终结符。

重要事实一：自底向上分析逆向地追踪一个最右推导。Aiken 说，以后在自底向上分析上遇到问题，回到这个基本事实总会有帮助。

从树的角度看：自顶向下分析从开始符号出发，不断展开当前边界上的非终结符，让树逐渐长大；自底向上分析从所有叶子（全部输入）出发，在它们上面搭起一棵棵小树，再把已经搭好的子树粘成更大的树，最后剩下的几棵子树合成一棵以开始符号为根的完整语法分析树。

二、移进归约分析

重要事实一有一个推论。设 $\alpha\beta\omega$ 是自底向上分析的一步，下一次归约用 $X \to \beta$，那么 $\omega$ 一定是终结符串。因为 $\alpha X \omega \to \alpha\beta\omega$ 是最右推导的一步，X 是最右边的非终结符，它右边不可能有非终结符。

这些在最右非终结符右边的终结符，正好是分析器还没读的输入。于是用一条竖线 | 把串分成两半：右边是还没检查的输入（全是终结符），左边是终结符和非终结符混合、分析器已经处理过的部分。竖线不是串的一部分。开始时所有输入都没检查：$|x_1 x_2 \ldots x_n$。

自底向上分析只需要两种动作：

  • 移进（shift）：把竖线右移一位，把一个终结符读进左串。$ABC|xyz \Rightarrow ABCx|yz$。
  • 归约（reduce）：在左串的右端反向应用一条产生式。如果有 A → xy，则 $Cbxy|ijk \Rightarrow CbA|ijk$。

例子的完整过程：

格局动作
| int * int + int移进
int | * int + int移进
int * | int + int移进
int * int | + int归约 T → int
int * T | + int归约 T → int * T
T | + int移进
T + | int移进
T + int |归约 T → int
T + T |归约 E → T
T + E |归约 E → T + E
E |

注意只能在竖线紧左边归约，所以总要先读进足够多的输入才能归约。

栈

因为归约只发生在竖线紧左边，左串可以用栈实现，栈顶就是竖线的位置。移进把一个终结符压栈；归约从栈里弹出零个或多个符号（产生式右部），再压入一个非终结符（产生式左部）。

冲突

在某个状态下，可能不止一个动作都能导向合法的分析：

  • 既能移进又能归约，叫移进归约冲突。
  • 能按两条不同的产生式归约，叫归约归约冲突。

Aiken 的经验：归约归约冲突几乎总是坏事，通常说明文法有严重问题，如果你为课程项目写的文法出现了它，你一定做错了什么。移进归约冲突也不好，但往往容易消除，几乎是意料之中的，大概需要用优先级声明来消掉。无论哪种，都说明分析器在某个状态下不知道该做什么，要么改写文法，要么给它一点提示。课件说你们在项目里会遇到这些冲突。

三、句柄

关键问题：什么时候移进，什么时候归约？看格局 int | * int + int。栈顶有 int，可以按 T → int 归约成 T | * int + int。这是致命的错误：文法里没有以 T * 开头的产生式，之后不管怎样归约，都回不到开始符号 E。所以栈顶有某条产生式的右部，并不意味着就该归约。

直觉：只有归约的结果还能继续归约到开始符号时才归约。形式地，设有最右推导

$$S \to^* \alpha X \omega \to \alpha\beta\omega$$

那么在 α 之后的位置按 X → β 归约，叫作 $\alpha\beta\omega$ 的一个句柄（handle）。句柄就是一个能归约、并且之后还能一路归约回开始符号的位置（用特定的产生式，在特定的位置）。我们能够而且必须在句柄处归约。这里只说了句柄是什么，还没说怎样找句柄，找句柄占了语法分析剩下的大部分内容。

重要事实二：在移进归约分析里，句柄只出现在栈顶，从不出现在栈内部。这就是能用栈的理由：所有动作都发生在焦点的紧左边，不需要深入串的内部。

非正式的证明，对归约次数做归纳：开始时栈为空，成立。刚归约完一个句柄时，栈顶是最右的非终结符；因为这是最右推导，下一个句柄只能在它右边，不可能在最右非终结符的左边；一串移进动作就能到达下一个句柄。所以移进和归约两种动作就够了，竖线从不需要左移。自底向上分析算法都建立在识别句柄的基础上。

四、识别句柄：活前缀

坏消息：对一般的文法，没有已知的高效算法能识别句柄。好消息：有一些启发式方法能猜出句柄，对某些相当大的文法类别，这些启发式总能猜对。这里用的启发式对应的就是 SLR 文法。

文法类别的包含关系：所有 CFG ⊃ 无二义 CFG ⊃ LR(k) ⊃ LALR(k) ⊃ SLR(k)，课件还画了更小的 LR(0)。LR(k) 是已知最一般的确定性文法类之一（L 从左到右扫描，R 最右推导，k 个 token 向前看）；实践中大多数自底向上工具用的是 LALR(k)；这里主要讲它的简化版 SLR(k)（Simple LR）。这些包含关系都是严格的。

分析器在每一步能看到的是它已经建好的栈，看不到全部输入。从这里出发：

定义：如果存在某个 ω 使得 $\alpha | \omega$ 是移进归约分析的一个合法格局，就说 α 是一个活前缀（viable prefix）。α 是栈，分析器知道；ω 是剩下的输入，分析器顶多能看到它开头的一个 token。

  • 活前缀不会超过句柄的右端。
  • 叫活前缀，是因为它是句柄的前缀。
  • 只要栈里是活前缀，就还没有检测到语法错误。

Aiken 说这个定义本身并不深，只是给"合法的分析状态"起了个名字。它的用处在于引出：

重要事实三：对任何 SLR 文法，活前缀的集合是一个正则语言。（录像里说的是"对任何文法"。）这个事实一点也不显然，但它是自底向上分析的关键，所有自底向上分析工具都建立在"活前缀可以用有限自动机识别"之上。下面演示怎样构造识别活前缀的自动机。

项

项（item）是在右部某处加了一个点的产生式，点表示焦点。T → (E) 的项有四个： 

T -> .(E)
T -> (.E)
T -> (E.)
T -> (E).

X → ε 只有一个项 X → .。这些项通常叫 LR(0) 项。

识别活前缀的难处在于，栈里大多数时候只有产生式右部的零碎片段，有完整的右部就能归约了。但这些片段不是随机的，它们总是某些产生式右部的前缀。

例子：输入 (int)，格局 (E | ) 是合法的。(E 是 T → (E) 右部的前缀，再移进一个 ) 就能归约。项 T → (E.) 描述的就是这个状态：这条产生式我们已经看到了 (E，希望接下来看到 )。点左边是已经看到、已经在栈上的东西；点右边是归约之前还要等着看到的东西，可能看得到也可能看不到。

栈是前缀的栈

栈里可能叠着很多个右部前缀：$\text{Prefix}_1\ \text{Prefix}_2 \ldots \text{Prefix}_n$。设 $\text{Prefix}_i$ 是 $X_i \to \alpha_i$ 右部的前缀，那么：

  • $\text{Prefix}_i$ 最终会归约成 $X_i$。
  • $\text{Prefix}_{i-1}$ 所在产生式缺的那一部分以 $X_i$ 开头，即存在 $X_{i-1} \to \text{Prefix}_{i-1} X_i \beta$。
  • 递归地，$\text{Prefix}_{k+1} \ldots \text{Prefix}_n$ 最终会归约成 $\alpha_k$ 缺的那部分。

我们总是在最上面的前缀上工作，在右端移进和归约；每次归约都会把它下面那个前缀往完整右部推进一步；上面的前缀都被归约掉以后，才轮到下面的前缀。

例子：输入 (int * int)，格局 (int * | int)。从栈顶往下：

  • "int *" 是 T → int * T 右部的前缀。
  • "ε" 是 E → T 右部的前缀。这里栈上还什么都没有，等 int * T 归约成 T 以后，这个 T 会归约成 E。
  • "(" 是 T → (E) 右部的前缀。

（课件从栈顶往下列时还多写了一层 ε 和 E → T，意思相同。）用项的栈记录：T → (.E)、E → .T、T → int * .T，意思是"T → (E) 看到了 (，E → T 什么都还没看到，T → int * T 看到了 int *"。每个项的左部最终会成为下面那个项右部缺失部分的一部分。

所以要识别活前缀，就是要识别一串产生式的部分右部，其中每一个最终都能归约成它前一个的缺失后缀的一部分。

五、识别活前缀的自动机

  1. 给文法 G 加一条新的开始产生式 $S' \to S$。这只是一个技术细节，好让新开始符号只出现在一处，方便给开始状态命名。
  2. NFA 的状态就是 G 的项（包括新开始产生式的项）。NFA 的输入是栈，从栈底读到栈顶。
  3. 对项 $E \to \alpha.X\beta$，加一条转移 $E \to \alpha.X\beta \xrightarrow{X} E \to \alpha X.\beta$。X 可以是终结符或非终结符。意思是：已经在栈上看到了 α，如果接下来栈上是 X，那当然可以，点右移一位。
  4. 对项 $E \to \alpha.X\beta$ 和每条产生式 $X \to \gamma$（X 是非终结符），加一条 ε 转移 $E \to \alpha.X\beta \xrightarrow{\varepsilon} X \to .\gamma$。意思是：栈上接下来未必是 X 本身，可能是某个最终会归约成 X 的东西，也就是由 X 推出的东西。这时 α 是这条产生式在栈上的全部，这里是栈里下一个右部的开头。
  5. 每个状态都是接受状态：自动机能读完整个栈，栈就是活前缀。不是每个状态在每个符号上都有转移，很多栈会因为自动机卡住而被拒绝。
  6. 开始状态是 $S' \to .S$。

对例子文法加上 S' → E，NFA 相当大。Aiken 逐个状态推了一遍：从 S' → .E 出发，栈上看到 E 就到 S' → E.（读完全部输入、归约到旧开始符号后到达的状态）；否则 ε 转移到 E → .T 和 E → .T+E。这里用上了非确定性的猜测能力，不知道栈上会出现哪条产生式的右部（这两条甚至没有提取左因子），让 NFA 去猜，两条都试。点移到最右端的项，比如 E → T.，就表示可能遇到了一个可以归约的句柄。

有效项

如果有最右推导 $S' \to^* \alpha X \omega \to \alpha\beta\gamma\omega$，就说项 $X \to \beta.\gamma$ 对活前缀 $\alpha\beta$ 是有效的。分析了 αβ 之后，有效项就是项的栈的栈顶可能是什么。更简单的说法：对活前缀 α，DFA 读完 α 停在状态 s，s 里的项就是对 α 有效的项，描述了读完 α 后的状态。

一个项通常对很多前缀都有效。T → (.E) 对 (、((、(((、…… 都有效：从开始状态读一个 ( 到状态 6，以后每个 ( 都在状态 6 自环，而这个项就在状态 6 里。

六、LR(0) 和 SLR

LR(0) 分析

设栈里是 α，下一个输入是 t，DFA 读 α 后停在状态 s：

  • 如果 s 含有项 X → β.，就按 X → β 归约。β 完整地在栈顶，而且这个项对整个栈都是有效的。
  • 如果 s 含有项 X → β.tω，就移进，等价于说 s 有一条标着 t 的转移。

LR(0) 的冲突：某个状态有两个归约项 X → β. 和 Y → ω.，是归约归约冲突，信息不够决定按哪个归约；某个状态既有归约项 X → β. 又有移进项 Y → ω.tδ，是移进归约冲突，下一个输入是 t 时不知道该移进还是归约。

例子的 DFA 在 LR(0) 规则下有两个移进归约冲突：状态 5 里可以按 E → T 归约，下一个输入是 + 时也可以移进；状态 3 里可以按 T → int 归约，下一个输入是 * 时也可以移进。

SLR 分析

SLR 对 LR(0) 的改动很小，只在归约条件上加一条：只有当 $t \in \text{Follow}(X)$ 时才按 X → β 归约。

理由：LR(0) 的决定完全基于栈的内容，没有利用接下来的输入。如果把栈顶的 β 换成 X，而下一个输入是 t，那推导里 t 就紧跟在 X 后面。如果 t 根本不可能跟在 X 后面，这个归约就没有意义。

如果在这些规则下还有冲突，文法就不是 SLR 的。这些规则是一种检测句柄的启发式，结合了两样信息：栈的内容（DFA 告诉我们栈顶可能有哪些项）和接下来的输入。对没有冲突的文法，这个启发式是精确的，这样的文法就定义为 SLR 文法。

回到例子：Follow(E) = {), $}，Follow(T) = {+, ), $}。状态 5 里，下一个输入是 + 就移进，是 ) 或 $ 就按 E → T 归约，其他都是错误。状态 3 里，* 就移进，+、)、$ 就按 T → int 归约。冲突消失了，这个文法是 SLR(1) 的。

优先级声明

SLR 比 LR(0) 好，但仍然不是很一般的文法类，比如所有二义文法都不是 SLR 的。用优先级声明告诉分析器怎样消解冲突，可以让 SLR 分析更多文法。

最自然也最二义的文法 $E \to E + E \mid E * E \mid (E) \mid \texttt{int}$，它的 DFA 里有一个状态同时包含 E → E * E. 和 E → E . + E，这是移进归约冲突。这就是 * 和 + 谁优先的问题：归约就是先把 E * E 合起来，先算乘法；移进 + 就是先处理加法，因为它到了栈顶。声明"* 比 + 优先"，冲突就按归约来消解。

"优先级声明"这个名字有误导性。这些声明并不定义优先级，它们定义的是冲突消解：在这里做这个动作而不做那个。在 + 和 * 这种简单文法里，冲突消解的效果恰好和想要的优先级一致；在各部分相互作用更多的复杂文法里，它们未必像你预期的那样强制优先级。好在工具一般都能把分析自动机打印出来，可以看到冲突具体是怎样消解的。Aiken 建议做分析器时，尤其是比较复杂的，一定要检查分析自动机，确认它在做你想要的事。

七、SLR 分析算法

未优化的版本：

  1. 设 M 是 G 的活前缀 DFA。
  2. 初始格局是 | x1 ... xn $。
  3. 重复直到格局变成 S | $：设当前格局是 $\alpha|\omega$，在当前栈 α 上运行 M。如果 M 拒绝 α，报语法错误（α 不是活前缀）。如果 M 接受 α 并停在项集 I，设 t 是下一个输入：若 X → β. ∈ I 且 t ∈ Follow(X)，归约；否则若 X → β.tγ ∈ I，移进；都不行就报错。

Aiken 指出，"M 拒绝 α 就报错"这一步其实不需要。最后一步"都不行就报错"已经保证不会形成不合法的栈，错误在那里就被抓住了，不会把不可能构成活前缀的符号放进栈。如果最后一步有冲突，文法就不是 SLR(k) 的，k 是向前看的数量，实践中 k = 1。

Aiken 提醒注意 int * T 那一步：DFA 不只是在原路径上多走一步，栈顶的符号被换成了非终结符 T，DFA 从栈底重新读，走了一条不同的路径到达状态 4。到了 T | $，栈内容变化更大，DFA 走向完全不同的方向。最后到达只有 S' → E. 的状态，下一个输入是 $，接受。

改进：记住每个前缀上的状态

每一步都在整个栈上重新运行自动机很浪费。每一步只有栈顶的少数符号变化，大部分栈不变，重复的工作很多。办法是记住自动机在栈的每个前缀上的状态：栈里不再只放符号，改放二元组 ⟨符号, DFA 状态⟩。对栈 ⟨sym₁, state₁⟩ … ⟨symₙ, stateₙ⟩，stateₙ 是 DFA 读完 sym₁ … symₙ 后的状态。栈底放 ⟨dummy, start⟩，dummy 是随便一个占位符号，start 是 DFA 的开始状态。

两张分析表：

  • goto 表：如果 $\text{state}_i \xrightarrow{A} \text{state}_j$，则 goto[i, A] = j。它就是 DFA 的转移函数写成数组。
  • action 表，按状态 $s_i$ 和终结符 t 索引：
    • $s_i$ 含项 X → α.tβ 且 goto[i, t] = k，则 action[i, t] = shift k。意思是：栈顶状态是 $s_i$，下一个输入是 t，可以把 t 移进栈；移进时要压入的是一个二元组，状态应该是从 $s_i$ 读 t 到达的状态，goto 表告诉我们是 k。
    • $s_i$ 含项 X → α. 且 t ∈ Follow(X) 且 X ≠ S'，则 action[i, t] = reduce X → α。
    • $s_i$ 含项 S' → S.，则 action[i, $] = accept。
    • 其他情况 action[i, t] = error。
Let input = w$ be initial input
Let j = 0
Let DFA state 1 be the one with item S' -> .S
Let stack = <dummy, 1>            // <symbol, state>
repeat
    case action[top_state(stack), input[j]] of
        shift k:      push <input[j++], k>
        reduce X -> A:
                      pop |A| pairs,
                      push <X, goto[top_state(stack), X]>
        accept:       halt normally
        error:        halt and report error

归约时先弹出右部长度那么多个二元组，这时栈顶的状态就是 DFA 读完剩下的栈之后的状态；压入左部 X 时，要知道 DFA 从这个状态读 X 会到哪里，查 goto 表。

有意思的是，这个算法只用到 DFA 状态和输入，栈里的符号从来没有被真正用到，完全可以只在栈里放状态来做分析。但那样就把程序扔掉了，后面的类型检查和代码生成还需要程序，所以语义动作仍然需要这些符号。

LR(1) 和 LALR(1)

SLR 叫"简单"是有原因的，实践中它太简单了，一些常见结构不是 SLR(1) 的。广泛使用的自底向上算法基于更强的 LR 文法，区别是把向前看放进项里：LR(1) 项是一个二元组（LR(0) 项, 向前看的 token）。比如 [T → . int * T, $] 的意思是：如果看完了 T → int * T 的整个右部，只有当向前看是 $ 时才归约。这比用整个 Follow 集更精确，能更细地追踪在特定的产生式序列里实际可能出现哪些向前看。细节见龙书。bison 生成的自动机严格说是 LALR(1) 的，是对纯 LR(1) 自动机的一点优化，但用的是同样的"LR(0) 项加向前看"的项。课件建议去看看自己的分析器的 LR(1) 自动机，读懂这种项会有帮助。

八、两个练习

S → S a | b

它生成一个 b 后面跟任意个 a 的串。文法是左递归的，这对自底向上分析器不是问题，LR 分析器完全接受左递归文法。加上 S' → S。不先建 NFA 再做子集构造，直接推 DFA 的状态：

  • 开始状态：S' → .S。点紧挨着非终结符 S，NFA 里有 ε 转移到 S 所有产生式的初始项，所以还有 S → .Sa 和 S → .b。这三个项是第一个状态。
  • 读 b：只有 S → b.。
  • 读 S：S' → S. 和 S → S.a。
  • 从后者读 a：S → Sa.。

只有一个项的状态不可能有冲突；开始状态没有归约项，也不可能有冲突。唯一要看的是 {S' → S., S → S.a}：可以按 S' → S 归约，也可以移进 a。Follow(S') 只有 $，所以输入结束时归约，输入是 a 时移进。没有冲突，文法是 SLR(1) 的。

S → S a S | b

  • 开始状态：S' → .S，S → .SaS，S → .b。
  • 读 b：S → b.。读 S：S' → S.，S → S.aS。
  • 从后者读 a：S → Sa.S，点又挨着 S，加上 S → .SaS 和 S → .b。
  • 从这个状态读 b 到 S → b.；读 S 到 {S → SaS., S → S.aS}；从这里读 a 又回到 {S → Sa.S, ...}。

没有哪个状态有两个归约项，所以没有归约归约冲突。{S' → S., S → S.aS} 同上一个例子，没有冲突。{S → Sa.S, ...} 没有归约项。剩下 {S → SaS., S → S.aS}：按 S → SaS 归约要求下一个输入在 Follow(S) 里。由 S' → S，$ ∈ Follow(S)；由 S a S 里第一个 S 后面跟着 a，a ∈ Follow(S)；最后一个 S 在产生式末尾，给出 Follow(S) ⊆ Follow(S)，没有新东西。所以 Follow(S) = {$, a}。问题来了：输入是 a 时，归约项说应该归约，S → S.aS 说应该移进。这个状态有移进归约冲突，文法不是 SLR(1) 的。
