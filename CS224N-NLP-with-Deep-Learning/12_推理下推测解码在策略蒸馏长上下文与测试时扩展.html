第十二讲：推理（下）：推测解码、在策略蒸馏、长上下文与测试时扩展

推测解码及其变体，在线与离线、在策略与离策略强化学习，RL 基础设施带来的离策略漂移，在策略蒸馏，长上下文的难点、位置编码与 RoPE，长上下文扩展的做法，以及测试时计算扩展

主讲：Yejin Choi
资料来源：课件（Stanford 课程网站公开，2026 年冬季；课堂录像只对选课学生开放，本文依据课件整理）

一、推测解码

问题：用大语言模型生成很慢。直觉：不是所有 token 都一样难生成。想法：用小语言模型的生成辅助大模型生成。Google Research（Leviathan 等，2022 年 11 月）和 DeepMind（Chen 等，2023 年 2 月）独立提出了同样的想法。

课件的例子：草稿模型（1B）先连续生成几个 token，比如 "dogs love chasing after cars"，目标模型（100B）一次前向计算就能同时算出这些位置上自己的概率，然后逐个决定接受还是拒绝：草稿模型给的概率是 $p_i$，目标模型给的是 $q_i$，如果 $q_i \ge p_i$ 就接受；否则以概率 $q_i/p_i$ 接受（比如以 0.8/0.9 的概率接受 "chasing"）；一旦拒绝，就从调整后的分布中重新采样这个位置，后面的草稿作废。这个过程虽然从小模型采样，效果却和从目标模型采样完全一样，正式证明见 Chen 等 2023 的附录 I。

推测采样是一种拒绝采样：从容易采样的分布 $p$（小模型）采样，来得到复杂分布 $q$（大模型）的样本。用 6000 万参数的 T5-small 当草稿模型、110 亿参数的 T5-XXL 当目标模型，在输出完全相同的情况下加速 2 到 3 倍。

  • 动态推测解码：每次迭代自适应调整"前瞻"长度（候选 token 数），用一个轻量分类器或置信度阈值即时决定草稿模型继续起草，还是交给目标模型验证（Mamou 等 2024，以及 Hugging Face 博客）。
  • 通用推测解码：原始方法要求草稿模型和目标模型的分词完全相同，通过重新编码和对齐技术，可以支持分词不同的模型。
  • EAGLE-3：EAGLE-1 让草稿模型钻进目标模型的内部表示去"读心"（特征层面的推测）；EAGLE-2 用上下文感知的动态草稿树；EAGLE-3 融合不同层的特征。
  • 后缀解码（SuffixDecoding，Oliaro 等 2025），一种极端的推测解码。

后缀解码与 EAGLE-3 对比：后缀解码无需模型，用后缀树缓存并匹配提示和过去输出中的重复序列；在 CPU 上做推测，GPU 负责目标模型的验证；起草约每 token 20 微秒，极快；最适合高度重复的任务（编程、Agent 循环、RAG、SQL 生成）；不需要训练，即插即用。EAGLE-3 基于模型，用一个训练过的小 Transformer 头预测目标模型未来的隐藏特征；起草头在 GPU 上运行，和主模型共享显存；起草较慢，需要一次 GPU 前向计算；最适合开放式任务（创意写作、一般聊天、不可预测的推理）；需要在目标模型的特征空间上训练一个小的辅助头。

更好的推测解码算法在快速发展，常用推理引擎都支持多种选择。课件列了一张支持情况表：EAGLE-3、SuffixDecoding、Medusa、草稿-目标模型、DFlash（2026）在 vLLM、TRT-LLM、HF TGI、HF Transformers、SGLang 中的支持程度各不相同，比如草稿-目标模型方式五个引擎都支持，SuffixDecoding 目前只有 vLLM（Arctic）和 SGLang（测试版）支持。

二、离策略漂移与在策略蒸馏

四种强化学习

  • 在线 RL：训练时 Agent 可以和环境交互。
  • 离线 RL（批量 RL）：只从预先记录的数据集（人的日志或以前的 Agent）学习，Agent 不能"探索"或尝试新动作。
  • 在策略 RL：训练数据完全由当前策略生成，策略一更新，旧策略产生的旧数据就当作"过期"丢掉。例子有 REINFORCE、PPO、GRPO。
  • 离策略 RL：Agent 从任何策略（旧策略、别的策略，甚至人）产生的数据中学习，把经验存在回放缓冲区里反复使用。例子有 DQN。

在线还是离线，看 Agent 能否和环境交互；在策略还是离策略，看训练用的轨迹是否来自最新的策略。在线离策略 RL 很常见：Agent 和模拟器交互（在线），但把一切存进回放缓冲区以后再学（离策略），比如 DQN；还有异步 RL，以及因 RL 基础设施优化而出现"离策略漂移"的 PPO。离线在策略 RL 则不存在（除非勉强解释）。

RL 基础设施与离策略漂移

异步 RLHF（Noukhovitch 等 2024）：经典 RLHF 是同步的，浪费 GPU 吞吐量。PipelineRL（Piché 等 2025）做飞行中权重更新：生成引擎在生成过程中接收新的模型权重，短暂暂停、加载新权重，然后继续正在生成的序列，于是产生混合策略的序列，前面的 token 由较旧的策略生成，后面的由较新的策略生成。

实践中为什么会出现离策略情况，轨迹为什么会"过期"：有意的异步 RL；每个批次做多步梯度更新；大的回放缓冲区；生成和训练分在不同集群（一个为推理优化，一个为梯度计算优化），集群之间要传权重，带来延迟。

离策略为什么是问题：梯度估计有偏；重要性权重爆炸；奖励被钻空子的问题被放大。缓解办法：PPO 裁剪；对参考策略的 KL 惩罚；不用评论家/优势估计的算法（缩短离策略漂移的窗口），比如 GRPO 或 REINFORCE；更少的轮数；SGLang/vLLM 带权重流式传输的连续批处理；PipelineRL 的飞行中权重更新。

在策略蒸馏

在策略蒸馏（也叫广义知识蒸馏）最早由 Gu 等（2023）和 Agarwal 等（2023）提出，后来经 Qwen3 技术报告和 Thinking Machines 的博客广为人知。之前的蒸馏方法以教师为中心（所以对学生而言是离策略的）；在策略蒸馏以学生为中心（对学生而言是在策略的）。

KL 散度衡量 Q 和目标 P 的差别。前向 KL 是"寻均值"或"覆盖质量"的：以 $P(x)$ 加权，惩罚 P 有质量而 Q 没有的地方，Q 会覆盖 P 的所有模态，高估支撑集，用于变分推断（ELBO）。反向 KL 是"寻众数"或"模态坍缩"的：以 $Q(x)$ 加权，惩罚 Q 有质量而 P 没有的地方，Q 集中在 P 的一个模态上，低估支撑集，用于 RLHF，KL 惩罚让策略靠近参考模型。

几种方法对比（Agarwal 等 2023）：

  • SFT：在标准答案上的负对数似然，上下文是真实数据，硬标签。
  • 知识蒸馏（KD）：前向 KL，上下文是真实数据，软分布，覆盖质量。
  • 序列级知识蒸馏（SeqKD）：在教师输出上的负对数似然，上下文由教师生成，硬标签，覆盖质量。
  • 广义知识蒸馏（GKD）：反向 KL，上下文由学生生成，软分布，寻众数。

前三种是离策略的，GKD 是在策略的。反向 KL 意味着上下文来自学生自己的生成，这消除了训练和测试的不匹配（暴露偏差），学生学会从自己的错误中恢复；寻众数的性质鼓励学生在自己最好的行为上清晰、自信，而不是分散地覆盖教师的所有模态。

和 RL 比：SFT 是离策略的，奖励信号稠密，GPU 需求轻；RL 是在策略的，奖励稀疏，GPU 需求重；在策略蒸馏是在策略的，信号稠密，GPU 需求轻，可以看作兼得 SFT 和 RL 的好处。

一个很好的用途是开源模型的领域适配，比如在某个领域的语料（公司内部文档）上微调 Qwen-8B，可以看作一种中期训练。简单地在已经后训练过的现成开源模型上做中期训练，会损害之前后训练获得的能力（比如指令遵循）；中期训练（70%）获得新领域知识后，在指令微调数据集上做在策略蒸馏（30%），可以恢复指令遵循能力。

三、长上下文扩展

扩展推理需要扩展长上下文。需要很长上下文窗口（10 万到 200 万 token）的应用：要理解整个代码库的软件工程任务；要仔细审阅几百页文件的法律分析；以长期交互历史为条件的个性化聊天；要在不同解题策略间反复试错的极难数学题。

长上下文为什么难：数据限制，大多数互联网文档不够长，撑不起超长上下文窗口的预训练；计算/内存限制，标准注意力需要平方级计算；位置嵌入的泛化限制，在短序列上训练的模型不能很好地泛化到长序列。

互联网数据的典型文档长度（约略 token 数）：Common Crawl 网页 600 到 1200，包括博客、新闻、落地页，很多"文档"非常零碎；维基百科 500 到 1500，有些条目很长，但中位数条目相对简短；arXiv 科学论文 5000 到 10000 以上，是大多数数据集中最长的"自然"文档之一；Project Gutenberg 书籍 5 万到 10 万以上，是数据的"长尾"，少见但对长程依赖很关键；GitHub 代码 100 到 5000，差别很大，很多脚本很短，库很长。

位置编码

  • 正弦位置嵌入（Vaswani 等 2017）。
  • 学习的位置嵌入：随机初始化，通过反向传播学习，在早期大语言模型中广泛使用，比如 BERT、RoBERTa、GPT-2、GPT-3、ALBERT、ELECTRA、BART。无法为没见过的位置定义位置嵌入，也不能泛化到训练时没见过的位置；但让模型自己学位置编码，效果更好。这成了长上下文扩展的主要瓶颈，所以最近的大语言模型已不再使用。

RoPE 旋转位置嵌入（Su 等 2021）：算出 query 和 key 向量之后，乘以旋转矩阵；旋转只作用于 query 和 key，不作用于 value。RoPE 把向量的维度两两分组，在二维平面上按位置旋转来编码位置，完整的旋转矩阵是由这些 2×2 旋转块组成的分块对角矩阵。相对距离：位置 $m$ 的 query 和位置 $n$ 的 key 相乘时，$(R_m q)^\top(R_n k) = q^\top R_m^\top R_n k = q^\top R_{n-m}k$，因为转置的旋转矩阵往回转。虽然各自的旋转矩阵都不同，到 q 和 k 相乘时，旋转角只取决于相对距离：位置 10 和 11 上的 "Taylor" 和 "Swift"，与位置 100 和 101 上的结果完全相同。

原始正弦编码与 RoPE（LLaMA、PaLM 等）对比：前者是加性的，在第一层前加到输入嵌入上；后者是乘性的，在每个注意力层作用于 Q 和 K。前者会增大 token 嵌入的范数；后者保持范数。前者在数学上包含相对距离，但因为是加性的，到算 QKV 注意力时信息已经混在一起；后者通过旋转角包含相对距离，算注意力时信息清晰可用。前者外推很困难；后者可以配合位置插值、NTK 缩放、YaRN 等长上下文扩展技术。

长上下文扩展的做法

  1. 修改位置编码。截至 2026 年，RoPE 缩放似乎是最常见的一类方法。线性插值（位置插值）：把位置索引按比例缩小，让模型看到熟悉的相对位置，Meta 用它把 LLaMA 从 2K 扩展到 32K 以上，需要少量微调。NTK 感知插值：调整旋转的基频，而不是线性压缩位置，更好地保留高频分量；有"动态 NTK"变体，推理时根据序列长度调整缩放。YaRN：把 NTK 缩放和注意力温度修正以及一个斜坡函数结合，对不同频段区别对待，低频插值、高频外推。
  2. 渐进/分阶段训练。常见配方（LongLLaMA、LongAlign、Llama 3.1 等）：从基座模型（比如 4K 到 8K 上下文）开始；修改位置编码；在长文档上继续预训练，序列长度逐步增加（比如 8K、32K、64K、128K），数据量通常相对小（几十亿 token，不是几万亿）；在长上下文指令数据上微调。不需要完整的预训练预算，通常原预训练 token 的 0.1% 到 1% 就够适配。
  3. 数据工程。在继续预训练的数据混合中上采样长文档（书、代码库、长文章、拼接的相关文档）；合成长上下文任务：大海捞针式检索、长程问答、多文档摘要；LongAlign 式的指令微调，任务专门要求模型用分布在整个上下文中的信息；长上下文的 self-instruct：用强模型生成长上下文的指令-回答对。
  4. 修改注意力架构。稀疏/滑动窗口注意力结合全局注意力 token（Longformer 式）；FlashAttention（及 FlashAttention-2/3），训练时把内存从 $O(n^2)$ 降到 $O(n)$；分组查询注意力（GQA）或多查询注意力（MQA），减少 KV 缓存内存，推理时支持更长上下文。

四、测试时计算扩展

这个概念因 OpenAI 2024 年 9 月发布 o1 而广为流行，在此之前有 Google DeepMind 2024 年 8 月的论文，更早在 2023 年 5 月的《Let's Verify Step by Step》中也不那么明确地出现过。问题是：不只扩展训练时计算，能不能扩展测试时计算？与其训练更多，能不能让模型想得更多？

那篇 DeepMind 论文挑战了大语言模型开发的主流范式，显示聪明地扩展测试时计算，带来的提升可以比单纯扩大模型参数更大：在固定的推理预算下，用聪明的测试时计算策略的小模型可以胜过用标准解码的大模型。要做计算最优的分配，就要在模型大小（预训练 FLOPs）和生成的样本数或修订步数（测试时 FLOPs）之间找平衡。

评估的测试时扩展策略：Best-of-N 采样，生成 N 个独立解，用验证器选最好的；加权 Best-of-N，从计算最优的温度分布中采样；顺序修订，用模型的自我批评反复改进单个解；带 PRM 的束搜索，保留多个候选解，根据步骤级奖励剪枝；多样束搜索，鼓励探索不同的解法。评估的验证方法：结果监督的奖励模型（ORM），训练来预测解是否正确；过程监督的奖励模型（PRM），训练来评估每一步推理是否正确；领域专用验证器，用于解可以检查的问题（比如执行代码）。

主要发现：在 MATH-500 上，优化了测试时计算的 140 亿参数模型达到或超过了大 4 倍的模型；在他们的实验设置中，计算最优的策略给预训练和推理分配大致相等的 FLOPs；顺序修订策略在需要改进和纠错的任务上扩展得尤其好；与 ORM 加束搜索相比，PRM 让计算使用效率高 4 到 8 倍。实践上的结论：不要默认用最大的模型；要在验证上投入，高质量的奖励模型，尤其是 PRM，能大幅改善测试时扩展。
