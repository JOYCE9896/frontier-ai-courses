01. 课程目标：深度强化学习是什么，和监督学习的两个区别

录像位置 0:00:00–0:04:52 · Course overview

Chelsea 先做自我介绍：她是这门课的讲师，Stanford 助理教授，研究方向是强化学习、机器人和语言模型。今天的学习目标有三个：深度强化学习到底是什么；怎样表示行为，才能去优化行为；怎样把一个问题写成强化学习问题。

“强化学习”和“深度”分别指什么

强化学习（Reinforcement Learning，RL）在这门课里指序列决策问题：系统要根据一连串信息做多次决策，观测一次，做一个动作，再观测，再做动作。课程会讲这类问题和它的各种解法，包括模仿学习、无模型和基于模型的强化学习、离线和在线强化学习、多任务和元强化学习，并且会特别多讲一些语言模型的强化学习和机器人的强化学习。“深度”指的是课程强调能扩展到深度神经网络的方法，不适用于深度网络的方法会讲得很少。

和监督学习的区别

监督学习里有一批输入输出对 $(x, y)$，目标是学一个从 $x$ 映射到 $y$ 的函数。数据是带标签的，模型被直接告诉该输出什么；而且通常假设这些数据点从同一个分布独立同分布（i.i.d.）地采样。

强化学习的目标是学习行为。记号也换了：输入叫状态 $s$，输出叫动作 $a$，做映射的函数叫策略 $\pi(a\mid s)$。和监督学习比有两个大区别：

  • 没有人直接告诉你正确答案，只能从间接得多的反馈里学。
  • 数据来自经验，而且经常是正在学的这个策略自己产生的经验，所以数据分布取决于当前策略，不再是一个固定分布上的 i.i.d. 采样。

这里的“行为”范围很广：控制机器人的电机、和人对话的聊天机器人、打游戏、开车、在网页上操作的 agent 等。

课程覆盖不了深度强化学习的全部内容，所以重点放在各类方法背后的核心概念，让大家以后能自己读懂更前沿的方法；同时重视实现，希望大家最后能自己动手写出这些算法。例子主要来自机器人、控制和语言模型，但很多技术适用面更广。想多学理论和其他应用的，可以选 CS234。

02. 为什么学深度强化学习，以及它用在哪里

录像位置 0:04:52–0:10:13 · Why study deep RL / Applications of RL

她列了五个理由，再逐个展开。

  1. 超出监督学习的 (x, y) 例子。很多场景里 AI 模型的预测会带来后果。她举 Spotify 的例子：算法推荐或直接播放了一首歌，这个决定会影响下一次该推荐什么，比如不该再放同一首，也许应该留在同一个曲风。要把这些后果考虑进来并据此优化行为，就需要强化学习的框架。还有一些场景拿不到直接监督：给 Cursor、Copilot 这样的编程助手反馈“这次做得好”或“做得差”，这种反馈不是正确输出本身，是更间接的信号。从间接信号学习，或者优化任意目标，都可以写成强化学习问题，所以它比监督学习灵活得多。
  2. 它已经广泛用于表现很强的 AI 系统。
  3. 从经验中学习看起来是智能的基本组成部分，也是做出新发现、而不只是模仿数据的前提。
  4. 还有很多有意思的开放研究问题。
  5. 她说上周末跟朋友说自己在做“为什么学深度强化学习”的好几页幻灯片，朋友说这问题不难，答案就是 OpenAI 一百万美元的总薪酬。如果前四条打动不了你，这条也算一个动机。

她又把第一条说得更具体：决策问题到处都是，没法直接写成监督学习；任何 AI agent 都属于这一类；系统要和人交互（聊天机器人、推荐系统），或者决策会影响未来的结果和观测，形成反馈回路，这些都是强化学习问题；没有标签、目标不只是准确率、或者目标不可微时，也用得上强化学习。

已经落地的例子

  • 腿式机器人：在仿真里用强化学习训练，再迁移到真实世界，做出像小狗一样的四足机器人和会跳舞的人形机器人，都是真实机器人上跑的深度强化学习策略。
  • 机械臂操作：一台机器人从烘干机里取出衣物并叠好，另一台叠简单的折纸。这两个用的是模仿学习，也在本课范围内。
  • 围棋：几年前 DeepMind 用深度强化学习训练的系统打败了李世石（Lee Sedol）。她特别提到第 37 手（Move 37），这一手让所有围棋专家都意外，是人类之前没想到的策略。这说明强化学习可以用来发现新解法，在需要做实验才能发现的领域（比如治疗疾病）也许同样有用。
  • 语言模型：几乎所有现代语言模型的后训练都用了某种形式的强化学习，更高级的推理能力尤其如此。
  • 交通控制：研究在人类驾驶的车流中插入自动驾驶车，提高道路通行量。
  • 训练生成模型：让生成结果更贴合提示词。让基础模型画“骑自行车的海豚”，结果不太像；用强化学习优化之后，画面能真正符合提示。
  • 芯片设计：一篇论文用强化学习设计了 Google 生产环境 TPU 里用的芯片。

03. 从经验中学习，和尚未解决的研究问题

录像位置 0:10:13–0:15:17 · Learning from experience / Research challenges

为了说明“从经验中学习是智能的基本组成”，Chelsea 讲了自己的经历。本科毕业后她加入了一个做机器人强化学习的实验室，座位旁边就有一台机器人，实验室的一位博士后经常在上面跑强化学习实验。让她着迷的是能亲眼看到机器人随时间学会东西：一开始它完全不会把玩具飞机的两个零件插到一起，最后能做得相当好。强化学习带来的这种“越练越好”的能力，是其他机器学习系统没有的。

不过那台机器人是“闭着眼”的，没有用摄像头，她觉得这是根本性的局限。于是她和那位博士后做了后续项目，加上摄像头，让机器人在真实世界里学会把红色积木塞进形状分类盒。随着反复练习，成功率越来越高，学习结束时大约 95% 到 100%。之后她（当年更年轻的她）把积木拿在手里递过去，机器人也能把积木放进去。这些任务很简单，也是很久以前的事了，现在已经有能叠衣服和跳舞的机器人；她喜欢放这些视频，是因为它们直观展示了真实世界里的强化学习过程。

开放的研究问题

  • 机器人怎样学会表示任务的好坏？
  • agent 怎样把行为泛化到很多不同场景，而不只是一个场景？
  • 能不能在大规模、多样的数据集上应用这类系统，并从其他任务和目标迁移？
  • 能不能用强化学习学长时程任务，比如做一顿饭或解一道很难的数学题？
  • 机器人能不能完全自主地练习？

关于最后一点，她放了一段“幕后”视频：机器人练习把冰球打进球门，每试一次都要重新开始，可它不会自己把场景复原，于是她的朋友 Yevgen 一直在帮它把冰球摆回去。她说 Yevgen 干的活比机器人还多，这样没法收集大量数据。课程会讲到的相关主题包括奖励学习、离线强化学习、多任务和元强化学习、分层、推理和无需复位（reset-free）的强化学习。

有学生问：机器人在真实世界学习时，奖励是怎么来的？她说在那个例子里，奖励是物体位置和目标位置之间距离的负数。形状盒的例子里机器人手里一直拿着积木，所以能用机械臂的位置推算积木在哪；冰球例子里冰球上贴了动作捕捉标记来测位置。这些做法都只对特定任务有效，一般情况下很难做到，这就是需要奖励学习的原因。

04. 把经验写成数据：状态、观测、动作、奖励，马尔可夫性质

录像位置 0:15:17–0:23:24 · Modeling RL problems / Markov property

机器人练习时拍下的那段视频，或者聊天机器人的一段对话，要怎样写成可以学习的数据？她依次定义了几个量。

  • 状态（State）$s_t$：$t$ 时刻世界的状态。挂毛巾的机器人例子里，状态可以是机械臂的位置、毛巾的位置和挂钩的位置；如果拿不到毛巾的位置，也可以是机器人摄像头拍到的图像加上关节位置。
  • 观测（Observation）$o_t$：agent 在 $t$ 时刻看到的东西。它和状态的区别在于观测不一定包含做决策所需的全部信息，可能还要用到过去的观测。聊天机器人的例子里，可以把用户最新发的一条消息当作当前观测，只看这一条不足以决定该怎么回复，需要把之前的对话历史也给它。
  • 动作（Action）$a_t$：$t$ 时刻做的决策。
  • 轨迹（Trajectory）$\tau$：一次和环境交互的完整记录，是状态（或观测）和动作的序列 $(s_1, a_1, \ldots, s_T, a_T)$。数据集因此是一堆轨迹，而不是一堆 $(x, y)$ 对。
  • 奖励函数（Reward Function）$r(s, a)$：告诉你一个状态和动作有多好。很多情况下只依赖状态，比如毛巾离挂上去还有多远、有没有挂上；聊天机器人的例子里可以是用户高不高兴、点了赞还是踩。轨迹也可以连同每一步的奖励一起记录。

马尔可夫性质

状态和动作的序列可以看成一条马尔可夫链。还用挂毛巾的例子：第一个状态是毛巾在桌上、机械臂在初始位置；机器人做一个动作（把手臂移到某处），当前状态和这个动作共同决定下一个状态（机械臂动了，毛巾可能没动，也可能被移动了）；然后再做动作，再得到下一个状态。

环境怎样变化由动力学（Dynamics）描述，例如 $p(s_3\mid s_2, a_2)$：手臂和毛巾在空间里怎样移动，取决于它们之前在哪、机器人做了什么。要点是 $s_3$ 只依赖 $s_2$ 和 $a_2$，不依赖 $s_1$；给定 $s_2$ 之后，$s_3$ 和 $s_1$ 条件独立。这个条件独立性就叫马尔可夫性质（Markov Property），它在强化学习里很有用，可以把问题拆开，不用操心前面所有步的依赖。一般地写成

$$p(s_{t+1}\mid s_t, a_t)\ \text{与}\ s_{t-1}\ \text{独立}$$

动力学通常是未知的，我们无法预测未来。

如果只有观测，情况就不同了。观测是当前状态的函数，可能缺信息。这时 $o_3$ 不仅取决于 $o_2$ 和 $a_2$，还和 $o_1$ 有关，因为过去的观测能帮你推断看不到的状态。

课堂问答

  • 实践中需要多少历史观测才能推断出状态？她说很依赖领域。很多机器人任务里只用当前传感器读数就够了，但也看传感器是什么。触觉传感器的信息通常比视觉少，不接触的时候什么都不知道，接触之后才知道很多，所以比图像更“部分可观测”；如果同时有图像，表示就完整得多。
  • 奖励为什么写成状态和动作的函数，而不只是状态？她举人形机器人学走路的例子：自然的奖励是向前走了多远，只依赖状态；但如果不想让机器人耗费太多能量、让电机一直绷着，就要加一项对施加扭矩的惩罚，这一项依赖动作。很多情况只依赖状态就够了。
  • 观测只是状态的一部分，为什么未来观测和过去观测不独立？她回到触觉的例子：接触、离开、再接触，此时紧挨着的上一个观测对当前状态说明得不多，更早的那个观测反而信息多，所以预测 $o_3$ 时同时以 $o_2$ 和 $o_1$ 为条件能知道更多。熟悉概率图模型的同学把中间变量边缘化掉也能看出这一点。

05. 两个建模例子：机器人和聊天机器人

录像位置 0:23:24–0:26:48 · Formulation examples

机器人

  • 状态：机器人上所有摄像头的 RGB 图像、各关节位置、各关节速度。这是机器人系统常见的状态表示。图像和关节位置维度不同，神经网络的结构要能接收不同维度的输入。
  • 动作：下一时刻的目标关节位置。关节现在在 90 度，也许下一步命令它转到 92 度。
  • 轨迹：图像序列（也就是一段视频）、关节位置序列、命令关节位置序列。时间通常离散化，比如 20 Hz：视频每秒 20 帧，关节读数每秒 20 次，动作命令也每秒 20 次。她说自己刚学的时候觉得这不太直观，人不会觉得自己每秒做 20 次决策，但对机器人这样的物理系统，这往往是表示数据和行为最实用的方式。
  • 奖励：毛巾挂在钩上时为 1，否则为 0；也可以再加一项对动作扭矩的惩罚。

聊天机器人

  • 这里大概没有紧凑的状态表示，所以用观测：用户最新的一条消息。
  • 动作：聊天机器人的下一条消息，可能是一句话，也可能是一大段。
  • 轨迹：这次对话的记录。和机器人不同，时间步不按固定的 20 Hz，用户隔多久回复都可能，时间按“用户下一次回复”来划分。
  • 奖励示例：用户点赞得 1，点踩得 $-10$，没有反馈得 0。

接着她让大家两两讨论，为自动驾驶、网页 agent 或自选的例子写出状态/观测、动作、轨迹和奖励。

讨论中的问答

  • 自动驾驶为什么算观测而不是状态？她说两种写法都可能，取决于传感器细节。如果只有激光雷达（LiDAR）测到的周围深度和前方的图像，就缺少周围车辆的速度信息，而一辆车是停着还是以 60 英里每小时行驶，对未来影响很大。可以把一段激光雷达历史（比如 3 秒）拼起来当作状态，从中得到速度。这是后面反复出现的做法：处理观测时用一小段历史来构成状态表示。
  • 挂毛巾的奖励是“挂上为 1，否则为 0”，如果机器人从来没碰巧挂上，就一直拿不到信号，怎么学？她说那段视频里，他们先给机器人演示了几次作为初始化，帮助解决后面会讲的探索（Exploration）问题。奖励很稀疏、又没有朝目标逐步引导时，这类演示数据对启动强化学习通常很重要。
  • 一位同学提议网页 agent：状态是网页的 HTML 和 URL 等信息，动作是和网页交互，奖励是任务有没有完成。
  • 既然传感器都不完美，是不是什么都应该当观测？她说担心传感器噪声时，总可以选择按观测建模；但如果要加很多历史，代价可能很大。所以有时即使信息不全，也会近似地当作状态处理，比如传感器每一万次才失灵一次、给出一张全黑图像，技术上算观测问题，但考虑到对算法的影响，仍可以当状态用。
  • 观测可以是当前的全部信息，也可以是和上一时刻的差值吗？她说这是取舍问题；如果要纳入很多历史，用差值压缩可能很合理。

06. 用策略表示行为，生成轨迹

录像位置 0:26:48–0:38:32 · Representing behavior / Generating trajectories

从状态或观测映射到动作的东西叫策略（Policy），几乎总是记作 $\pi$。它可以是一个神经网络：卷积网络、Transformer、简单的全连接网络，也可以是线性函数。输入是状态、观测或观测序列，输出是动作。网络参数一般记作 $\theta$，所以写成 $\pi_\theta(a_t\mid s_t)$ 或 $\pi_\theta(a_t\mid o_t)$。

用策略做动作的流程：观测状态 $s_t$，从网络里采样一个动作 $a_t\sim\pi_\theta(\cdot\mid s_t)$（也就是跑一次前向传播选出动作），在真实世界执行，再观测下一个状态 $s_{t+1}$。这个过程的产物就是一条轨迹。用策略生成轨迹的过程常叫 rollout 或 episode。一个 episode 可以理解成一次尝试，学习就是一次又一次地尝试；rollout 这个词的意思是交替经过策略和动力学，把这个过程“滚动展开”成一条轨迹。

只有观测时：给策略记忆

只有观测、没有状态时，解决办法是给策略记忆，把多个观测一起输入。如果有真正的状态，就不需要记忆，只输入当前状态即可。这样很方便，因为大量记忆会占用计算机或 GPU 的内存。但如果只有观测，就基本没有选择，只能给策略提供记忆，这时可以用序列模型。语言模型就是用序列模型读入之前的观测。

课堂问答

  • $T$ 是当前时间步还是整条轨迹？她说大写 $T$ 表示轨迹的结束，也就是一条轨迹里状态和动作的个数；小写 $t$ 表示某一个时间步，从 $t=1$ 到 $t=T$。
  • 同时把观测和状态都输入策略有用吗？如果状态真的包含全部信息，它的信息严格多于当前观测，再加观测没有用。只有在只有观测的时候，加历史才有帮助。
  • 为什么观测历史有帮助？过去的观测能提供更多关于真实状态的信息。语言模型的例子里，用户说的每句话是一个观测，之前的观测会告诉你很多关于当前“世界状态”的信息：如果用户第一句让你写一段代码，你写了，他又给了反馈，那把这些历史都带上才能完整描述当前状态。
  • 也可以分两步：先推断状态，再从状态预测动作。如果你对底层状态的好表示有想法，这种做法可能有用；其他情况下直接从观测到动作更简单。

07. 强化学习的目标：轨迹分布、期望回报和折扣

录像位置 0:38:32–0:47:09 · The RL objective / Stochasticity and discounting

强化学习的目标是最大化奖励，而且要最大化整条轨迹上的奖励，不只是某一步的奖励，所以先写成奖励之和：

$$\max \sum_{t=1}^{T} r(s_t, a_t)$$

但这个量不是确定的：同一个策略在世界里执行多次，拿到的奖励和每次都可能不一样。她问大家，变化来自哪里？

随机性的来源

  • 环境是随机的：下一个状态不只由当前状态和动作决定，还有随机性。动力学是一个分布，不是确定函数。
  • 策略也不一定是确定的。
  • 有同学提出奖励函数本身可能随机。她说通常把奖励建模成确定的函数，让随机性来自状态和动作；如果你不知道状态、只有观测，奖励看起来才像随机的。做奖励学习时你可能对奖励不完全确定，也可以在学习中利用这种不确定性，这个可以课后再聊。
  • 目标可能随时间变化。这时奖励函数会变，通常会把它当作另一个决策过程来建模；也有需要非平稳决策过程的场景。一般可以把这种随机性放进状态里，比如有一个看不见的潜在目标是状态的一部分，奖励函数仍保持确定，这样做不损失一般性。

所以主要的两个随机来源是环境动力学和策略。开车的例子里，其他车的行为是随机的，你自己的车也不会每次都做同样的决定。

轨迹的概率

要最大化奖励，需要先写出轨迹的概率分布，也就是“未来会怎样展开”的分布。初始状态也有随机性：初始条件会变，打牌时发牌的结果每次不同。从初始状态出发，策略选动作，然后动力学带来随机的下一状态，如此往复。一条轨迹的概率等于初始状态概率乘以每一步策略概率和动力学概率的连乘：

$$p_\theta(\tau) = p(s_1, a_1, \ldots, s_T, a_T) = p(s_1)\prod_{t=1}^{T} \pi_\theta(a_t\mid s_t)\, p(s_{t+1}\mid s_t, a_t)$$

（录像里她口头说成了“初始概率加上连乘”，写在幻灯片上是乘积。）有了这个分布，最大化奖励就是最大化这个分布下奖励和的期望：

$$\theta^\star = \arg\max_\theta\ \mathbb{E}_{\tau\sim p_\theta(\tau)}\left[\sum_{t} r(s_t, a_t)\right]$$

她指出这个式子和监督学习的目标长得不一样：策略 $\pi$ 甚至没有直接出现在期望里面，它是通过影响轨迹分布 $p_\theta(\tau)$ 起作用的。我们要找的是能带来最高奖励的策略，整门课很大一部分都在讲怎样优化这个目标。

有学生问 $T$ 必须固定吗？不必，可以变长，固定只是写起来方便；比如聊天时可以理解为消息的长度。

折扣因子

上面的写法对整条轨迹上的奖励一视同仁，也就是说你关心眼前的奖励和关心将来的奖励一样多。有时你更看重眼前：如果 $T$ 是一千年，你大概不太在乎一千年后的奖励。所以还可以给奖励乘上一个随时间变化的权重，常用的是折扣因子（Discount Factor）$\gamma$ 的 $t$ 次方：

$$\mathbb{E}_{\tau\sim p_\theta(\tau)}\left[\sum_{t} \gamma^{t}\, r(s_t, a_t)\right],\quad 0 \lt \gamma \le 1$$

$\gamma=1$ 时就是原来的形式；$\gamma$ 越小越“贪心”，越看重近期奖励。几讲之后还会细讲折扣因子。

插话：为什么要随机策略

  • 探索：想从自己的经验里学，就得尝试不同的东西。学网球不该一遍遍用完全相同的技术，要试不同策略才能找出哪个最好，这可以用一个会尝试多种做法的随机策略来表示。
  • 建模多样的数据：数据来自不同的人或系统，他们解决问题的方式不同。要建模这些做法，策略也需要是随机的。这时可以借用生成模型的工具，把策略看成给定状态或观测下动作的生成模型，而不只是一个从 A 映射到 B 的网络。

08. 价值函数、Q 函数和几类算法

录像位置 0:47:09–0:52:58 · Value functions / RL algorithm types

价值函数和 Q 函数

怎样判断一个策略好不好？不知道策略有多好，就没法让它变好。描述这件事的术语是价值函数（Value Function）。策略 $\pi$ 在状态 $s$ 的价值记作 $V^\pi(s)$，意思是从 $s$ 出发、之后一直按 $\pi$ 行动，未来奖励之和的期望；它就是上面的目标式，只是起点换成了 $s$：

$$V^\pi(s_t) = \sum_{t'=t}^{T}\mathbb{E}_{\pi}\left[r(s_{t'}, a_{t'})\mid s_t\right]$$

和它很接近的是 Q 函数（Q Function）$Q^\pi(s, a)$：从 $s$ 出发，先做动作 $a$（这个动作可能和 $\pi$ 会选的不同），之后再按 $\pi$ 行动，未来奖励之和的期望：

$$Q^\pi(s_t, a_t) = \sum_{t'=t}^{T}\mathbb{E}_{\pi}\left[r(s_{t'}, a_{t'})\mid s_t, a_t\right]$$

今天不深入，下周开始会大量用到，所以先让大家熟悉这两个量。

算法类型

  1. 模仿学习（Imitation Learning）：模仿一个能拿到高奖励的策略。
  2. 策略梯度（Policy Gradient）：直接对上面的目标求导，从练习和经验中学习。
  3. Actor-Critic：估计当前策略的价值，用它改进策略。
  4. 基于价值的方法（Value-based）：估计最优策略的价值，再从中得出好的策略。
  5. 基于模型的方法（Model-based）：学习环境动力学的模型，预测未来，用来改进策略或做规划。

为什么有这么多算法

监督学习里有梯度下降，简单好用。强化学习没那么简单，不同算法做的取舍不同，适用的假设也不同。要考虑的因素包括：

  • 用策略收集数据有多容易、多便宜？在仿真器里收集大量数据很便宜；要人手写回复或和真人交互就贵得多。
  • 各种监督有多容易拿到？有没有演示？有没有细致的奖励？
  • 稳定性和易用性重要，还是数据效率重要？如果不需要海量数据，也许你有更多时间去调超参数。
  • 动作是什么样的：维度多高，连续还是离散？
  • 动力学模型好不好学？

术语回顾：MDP 和 POMDP

最后她回顾了今天的术语：状态、观测、动作、奖励函数，加上初始状态分布和动力学，合起来构成马尔可夫决策过程（Markov Decision Process，MDP）；如果只有观测，叫部分可观测马尔可夫决策过程（POMDP）。她特意留到最后才给出这个名字，因为叫什么并不重要，但以后有人说 MDP，你就知道指的是这种强化学习问题的写法。还讲到了轨迹、策略、强化学习的目标、价值函数和 Q 函数。

这一讲的要点

  • 强化学习研究序列决策：从间接反馈中学习行为，数据由正在学习的策略产生，不是 i.i.d.。
  • 经验写成轨迹 $\tau=(s_1,a_1,\ldots,s_T,a_T)$，配上奖励 $r(s,a)$；状态满足马尔可夫性质，观测不满足，需要给策略历史或记忆。
  • 轨迹分布 $p_\theta(\tau) = p(s_1)\prod_t \pi_\theta(a_t\mid s_t)\,p(s_{t+1}\mid s_t,a_t)$，目标是 $\max_\theta \mathbb{E}_{\tau\sim p_\theta(\tau)}\left[\sum_t \gamma^t r(s_t,a_t)\right]$。
  • 随机性来自初始状态、环境动力学和策略；随机策略用于探索和建模多样的数据。
  • $V^\pi(s)$ 和 $Q^\pi(s,a)$ 衡量策略从某状态（或状态加动作）出发的未来期望奖励，后面几讲会大量使用。
  • 算法分为模仿学习、策略梯度、Actor-Critic、基于价值、基于模型几类，选哪类取决于数据成本、监督形式、稳定性与数据效率、动作空间和动力学是否好学。
