第六讲：机器级编程（二）：控制

条件码是什么、怎样被设置，cmp 和 test，用 set 指令读出比较结果，跳转指令与 if-else 的两种翻译方式（条件跳转和条件传送）以及为什么条件传送有时更快，do-while、while、for 三种循环怎样变成跳转，switch 语句的跳转表

主讲：Randal E. Bryant
资料来源：课堂录像（2015 年 9 月 17 日，YouTube 转载自 CMU 官方 Panopto 录像；本文依据录像字幕整理）、课件
教材对应：CS:APP 第 3.6 节

一、开头：炸弹实验要开始了

数据实验当晚截止，炸弹实验当晚发布。Bryant 说这一讲和上一讲的内容已经足够开始炸弹实验的前几关，周一的习题课还会讲更多。前两个实验给的时间很充裕，但别因此拖到最后才动手：一旦上手就能一路推进，可上手之前有一段学习曲线。机器级编程这个"六集系列"给你的理解，远远超出一般程序员对系统的了解：程序为什么会崩溃、崩溃信息是什么意思。

课后有同学问：寄存器是内存的一部分吗？是缓存的一部分吗？都不是，寄存器是处理器里单独的存储，C 程序完全看不到它们。这一讲讲怎样在机器层面控制指令执行的流程，用它实现条件语句、循环和 switch；过程调用下一讲单独讲。

二、条件码

除了 16 个整数寄存器，处理器状态里还有两样东西和控制有关：%rip，即指令指针，存放当前正在执行的指令的地址（IA32 里叫 %eip）；以及条件码，几个一位的标志。x86 实际有八个左右的标志，和课程相关的是四个，名字值得记住：

  • CF（进位标志）：把两个数当无符号数相加时，最高位进位出来一个 1，说明结果超出了字长，即无符号溢出。
  • ZF（零标志）：刚算出的结果是 0。
  • SF（符号标志）：刚算出的结果最高位是 1，即作为有符号数是负的。
  • OF（溢出标志）：补码溢出。数据实验里学过怎样判断：两个操作数符号相同、而结果的符号与它们不同，就溢出了；符号相反的两个数相加不可能溢出。

这些标志不是直接设置的，而是很多算术指令的副作用。比如 addq 算出 t = a+b 的同时设好这四个标志。上一讲那个古怪的 lea 不设条件码。大多数时候这些标志被完全忽略，只有做条件操作时才用到它们。

专门设置条件码的指令

cmpq b, a 像是计算 a-b，但不保存结果，只按减法的规则设置四个标志：a == b 时 ZF 为 1，a-b 作为有符号数为负时 SF 为 1，等等（CF 和 OF 要按减法而不是加法来理解）。要注意操作数的顺序又是反的。Bryant 顺带解释：x86 上有两种汇编写法，Intel 和微软用一种，Linux 用另一种，两者操作数顺序相反，熟悉一种再去读另一种，就像在另一侧车道开车，很容易出事。他自己读代码时看到 cmp，会在注释里把两个操作数倒过来写，提醒自己比较的是什么。

testq b, a 像是计算 a&b，不保存结果，只设置条件码：结果为 0 时 ZF 为 1，结果为负时 SF 为 1。test 通常用在只想看一个值本身是零、是负还是正的时候，所以最常见的写法是两个操作数相同，比如 testq %rax, %rax，因为一个数和自己按位与还是它自己。另一个用途是让其中一个操作数做掩码。

三、读出条件码：set 指令

利用条件码有两种方式：根据条件把某个寄存器设成 0 或 1；或者根据条件跳转。直接读出整个状态寄存器也可以，但很少见。

setX 指令根据条件码的某种组合，把目的地（一个单字节寄存器）设成 0 或 1，其余 7 个字节不变。名字对应含义：sete（相等或为零，看 ZF）、setne（不等）、sets（为负，看 SF）、setns（非负）、setg 和 setge（有符号的大于、大于等于）、setl 和 setle（有符号的小于、小于等于）、seta 和 setb（无符号的高于和低于）。有符号比较要把是否溢出考虑进去，因为溢出会影响比较的结果，比如 setl 的条件是 SF 异或 OF。Bryant 说，这就是前几讲用补码运算和位级行为"折磨"大家的原因，残忍是有理由的。

为了配合 set，每个寄存器的最低字节都可以单独访问，名字也很古怪，比如 %al 是 %rax 的最低字节，%dil 是 %rdi 的最低字节（L 代表 low）。

例子：函数 gt(x, y) 返回 x > y。生成的代码是三条指令加 ret：cmpq %rsi, %rdi 比较 x 和 y（注释里写成 x:y）；setg %al 如果大于就把 %rax 的最低字节设为 1；movzbl %al, %eax 把这一个字节零扩展复制到 %eax。最后一步是因为 %rax 的高 7 个字节还是之前留下的东西，需要清零。这里又有一个 x86-64 的怪规则：任何结果为 32 位的指令，都会自动把寄存器高 32 位清零；而单字节和双字节的指令只改自己那部分。所以 movzbl 写 %eax 就足以把整个 %rax 的高位都清零。Bryant 说这是 AMD 的某个人决定的，也许是个好主意，但真的很容易让人困惑。复习一下参数约定：第一个参数在 %rdi，第二个在 %rsi，返回值放在 %rax。

四、条件分支

跳转指令

指令通常一条接一条执行，跳转指令可以让执行转到别处，跳过一些指令或跳回之前的位置。jmp 是无条件跳转；其他是条件跳转，只在条件码满足时才跳，名字和 set 指令一一对应：je、jne、js、jns、jg、jge、jl、jle、ja、jb。

用条件跳转实现 if-else

例子是 absdiff(x, y)：如果 x > y 返回 x-y，否则返回 y-x（Bryant 也提醒，如果有 TMin 参与会出问题，这里不管）。生成的代码：先 cmpq %rsi, %rdi 比较 x 和 y；如果 x <= y 就 jle .L4 跳到标号 .L4；不跳的话，把 x 复制到 %rax、减去 y、返回；.L4 处把 y 复制到 %rax、减去 x、返回。汇编里"名字加冒号"是标号，它只出现在汇编代码里，汇编器会把它换算成跳转的目标地址，读汇编时比看地址方便。课上有同学问为什么总是先把值 mov 到 %rax 再做减法：因为返回值必须在 %rax，而算术指令都是双操作数、结果覆盖第二个操作数，所以典型模式是先把一个值放进 %rax，再以 %rax 为目的做运算，就像 C 里每次运算都只能写成 x -= y 的形式。

为了不必每次都盯着汇编，Bryant 用"goto 版 C 代码"来表示控制流。C 里有一个不常被提起的 goto 语句，可以在代码里放标号并跳过去，它看起来很像汇编。一般规则是：对于"如果 test 就算 then 表达式，否则算 else 表达式"，编译成"如果 !test 就跳到 Else 处；算 then 表达式；跳到 Done；Else 处算 else 表达式；Done 处汇合"。在 absdiff 这种小函数里，两支各自直接 ret，不必汇合；后面还有更多代码时，就要汇合到一处继续往下执行。课上有人问编译器为什么选择对条件取反而不是反过来，Bryant 说他认为这完全是任意的，但 GCC 一贯这么做。

条件传送

另一种实现方式在代码里很常见，从软件开发者的角度有点反直觉：把 then 和 else 两个结果都算出来，最后再选一个。看似浪费，但对简单的计算反而更快。

Bryant 用油轮比喻现代处理器：它沿直线航行时飞快，却很难停下或转向。处理器采用流水线，一条指令还没执行完就开始取后面的指令，可以同时处理 20 条以上。遇到分支时，它会做分支预测，猜这次跳不跳，然后沿着猜的方向继续往前做。它猜得很准，九成到九成八的时候都对。猜错了就得停下、倒回、换个方向重新开始，在糟糕情况下要浪费约 40 个时钟周期。像绝对值这种分支，正负很难预测，猜错的概率接近一半。条件传送指令把"选择"变成一条普通的传送：两个值都已算好，最后只需决定是否把某个值复制进寄存器，不需要让整条流水线转向。

absdiff 的条件传送版本：两次 mov 和 sub 分别算出 x-y（放在 %rax）和 y-x（放在 %rdx），然后 cmp，最后 cmovle %rdx, %rax：如果 x <= y，就把 %rdx 复制到 %rax。cmovle 里的 le 是"小于等于"，不是字长。Bryant 说，前面那个跳转版本是他专门用编译选项禁止条件传送才得到的，因为 GCC 很想用它。

为什么不总是用条件传送？有三种情况不能用：两支计算都很昂贵，比如一支破解密码、一支求第 n 个素数，不该两个都算；有风险的计算，比如用条件判断指针是否为空再解引用，不能为了省时间先去解引用一个可能为空的指针；有副作用的计算，执行任一分支会改变程序的其他状态。所以 GCC 只在两支都是简单、安全、无副作用的计算时才用条件传送，而这种情况恰好足够常见，值得这么做。

五、循环

C 有三种循环：while、for，以及一种 Bryant 说自己一辈子只用过大约六次的 do-while，但它最容易实现。

do-while

do-while 先执行循环体，最后检查条件，满足就回去再做一遍。翻译成 goto 版：在循环体前放一个标号 loop；执行循环体；如果条件成立就 goto loop。课上的例子是 pcount，数一个 64 位数里有几个 1（每次把最低位加到结果上，再把 x 逻辑右移一位，直到 x 为 0），它在某些届的数据实验里曾是一道题。生成的汇编几乎逐行对应，关键是最后一条 jne .L2，跳回循环开头。

while

while 和 do-while 的区别只是检查放在开头，第一次进入前也要检查，条件不满足就一次都不执行。GCC 有两种翻译方式。

用 -Og 时是"跳到中间"（这个叫法是 Bryant 自己起的，别的文献里找不到）：先 goto 到循环末尾的条件检查处，由检查决定是否进入循环体，之后就和 do-while 一样。

用 -O1 时是"守护加 do-while"：先做一次条件检查，不满足就跳过整个循环；满足就进入一个 do-while 循环。Bryant 提到，实际开发中公司最常用的是 -O2，课程用 -Og 是为了让代码好读。

for

for 循环有四部分：初始化、条件、更新、循环体。它的语义等价于：先做初始化，然后 while (条件) { 循环体; 更新; }。比如用 for 写的 pcount：初始化 i = 0，条件 i < WSIZE（int 的字节数乘以 8，即字长），更新 i++，循环体取出第 i 位加到结果上。转成 while 之后再用上面的方法翻译。-O1 那种"守护加 do-while"的好处在这里体现出来：初始条件常常显然成立，比如 0 < 32，编译器能看出来，就把开头那次检查整个删掉。

六、switch 语句与跳转表

Bryant 说，循环基本是"只能用跳转和测试时你会想到的做法"，switch 却完全不同，在普通 C 代码里没有对应物，炸弹实验里还会遇到。

课上的例子（除了演示原理没别的用处）有几个典型特征：case 2 做完一步后没有 break，"落入"了 case 3；case 5 和 case 6 共用一段代码；没有 case 4，也没有 case 0；有 default。每个 case 的值必须是整数常量，顺序不限。Bryant 对"落入"语法评价很直白：这是编程语言史上最糟糕的设计决定之一，造成的心碎和莫名其妙的 bug 比 C 的任何其他部分都多，而 Java 等语言修掉了 C 很多危险的地方，却偏偏保留了它。他的建议是：如果确实需要落入，一定写注释说明"我是故意的"；多个 case 共用代码则是正常用法，不需要注释。

跳转表

如果禁止用 switch，大概会写成一长串 if-else if。但编译器不这么做。它把每个 case 的代码块编译好放在内存里，再建一张跳转表：第 i 项是 case i 对应代码块的起始地址。执行时用 x 作为下标直接从表里取出地址跳过去，就像数组访问不必从头逐个找一样。这样无论有多少个 case，都是常数步到达；而一串 if-else 平均要比较 n/2 次。

例子的汇编大致是：参数 x、y、z 分别在 %rdi、%rsi、%rdx。先 cmpq $6, %rdi，6 是最大的 case 值；然后 ja .L8，大于 6 就跳到默认分支 .L8。这里用的是无符号的 ja（高于）而不是有符号的 jg，这是个巧妙的技巧：负数当作无符号数是一个很大的正数，所以一条 ja 同时处理了 x > 6 和 x < 0 两种情况。最后是关键的一条 jmp *.L4(,%rdi,8)：以 .L4 为表的起点，取第 x 项（每项 8 字节），跳到它存的地址。

跳转表本身也写在汇编文件里，用 .quad 伪指令声明 7 个 8 字节的项（对应 x = 0 到 6），每项写一个标号，具体地址由汇编器填。从表的内容就能看出 switch 的逻辑：第 0 项和第 4 项都是默认分支的 .L8，表里的"空洞"用默认分支填上；第 5、6 项是同一个标号，两个 case 共用代码；顺序则和代码块在文件里的位置没有关系。

各个代码块

break 在这个函数里直接变成 ret，因为 switch 算出的值就是返回值，编译器不必汇合到一处再返回。落入的处理很有意思：GCC 发现变量 w 的初值 1 很少用到，就延迟初始化。case 2 的代码块做完除法后跳到合并点；而直接进入 case 3 时需要 w 的初值，所以 case 3 的代码块开头先把 w 设为 1，再进入合并点。这样两个代码块，第二个跳到第一个的中间。设 w = 1 时用的是 32 位的 movl，再次利用了"32 位操作清零高 32 位"的规则。除法的写法很古怪，书里有，课上不讲。

课上的追问

  • case 值有负数怎么办？编译器会加一个偏置，让最小的 case 变成 0，避免负下标。最小值是 5700 这类也一样处理。
  • case 值很稀疏怎么办，比如只有 0 和一百万？不会建一百万项的表，而是改用 if-else。聪明的地方在于：case 值都是编译时已知的常量，编译器可以排序，建一棵平衡的二分判断树，用对数次比较找到目标，而不是线性的一串比较。编译器有自己判断用哪种方式的规则，可以做实验反推。

小结：实现条件结构的手段只有三种：条件跳转、条件传送、跳转表，加上下一讲的过程调用，程序里一切改变执行流程的东西都由这些基本功能拼出来。从 C 到机器码，常常要把几条底层指令拼在一起实现一个高层结构。
