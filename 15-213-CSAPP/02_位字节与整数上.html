第二讲：位、字节与整数（上）

为什么用二进制，十六进制怎样读，C 的数据类型各占几个字节，布尔代数和位运算，用位向量表示集合，位运算和逻辑运算的区别，移位，无符号数和补码的编码，有符号与无符号之间的转换和 C 的隐式类型转换陷阱，符号扩展和截断

主讲：Randal E. Bryant
资料来源：课堂录像（2015 年 9 月 3 日，YouTube 转载自 CMU 官方 Panopto 录像；本文依据录像字幕整理）、课件（第二、三讲共用）
教材对应：CS:APP 第 2.1 到 2.2 节

一、一切都是位

计算机里的一切都用位（bit）表示，每一位是 0 或 1。同一串位，按不同方式解释，可以是一条指令、一个数、一个集合或一段文字。

二进制并不是一开始就理所当然的。人有十根手指，所以世界大多用十进制；Bryant 提到，宾夕法尼亚大学造的第一台电子计算机 ENIAC 就是十进制的，每一位十进制数用十个真空管表示。后来人们才意识到应该全部用二进制。二进制的好处来自电子实现：把连续的电压划成两段，低于某个阈值算 0，高于另一个阈值算 1，只要噪声和电路的不完美不越过阈值，得到的就是干净的信号。用双稳态元件存一位也比存一个模拟量容易得多，这就是数字处理胜过模拟处理的根本原因。

整数的二进制表示是每一位对应 2 的一个幂。小数也一样：小数点（这里应该叫二进制小数点）右边第一位的权重是 $2^{-1}=1/2$，第二位是 $1/4$，以此类推，这是浮点数的基础，第四讲细讲。

十六进制

32 位或 64 位的数写成一长串 0 和 1 太难读，所以通常每 4 位一组，写成十六进制，用 A 到 F 表示 10 到 15。一个字节（8 位）正好是两个十六进制数字，范围是 00 到 FF，即十进制 0 到 255。C 里十六进制常量写成 0xFA1D37B，大小写都行。这学期会大量盯着十六进制数看，要练到看一眼就能写出对应的二进制。Bryant 的办法是：0 到 9 已经很熟，再专门记住几个特例，1010 是 A，1100 是 C，1111 是 F，B、D、E 在它们中间推出来。

C 的数据类型各占几个字节

C 的类型声明一般不直接说明一个值占几个字节，因为 C 诞生于 16 位字长的年代，字长后来从 16 位涨到 32 位再到 64 位，C 用的是一组因机器而异的含糊名字。这门课只用 x86-64，在这台机器上：

二、布尔代数和位运算

布尔代数是 19 世纪 George Boole 提出的，用代数的方式表示逻辑：1 代表真，0 代表假。四种基本运算：与（A&B，两个都是 1 才是 1）；或（A|B，任一个是 1 就是 1）；非（~A，翻转）；异或（A^B，恰好一个是 1 时为 1）。把它用到数字电路上的是 Claude Shannon，他本科在密歇根大学学过逻辑课，后来在 MIT 读硕士时把这个当时冷门的逻辑分支和用继电器搭的电路联系了起来。Bryant 说，这大概是人类历史上影响最大的一篇硕士论文。

这些运算可以对整个字按位进行，每一位独立运算。C 里的符号就是 &、|、^、~，可用于任何整数类型（long、int、short、char 以及无符号版本）。例如对 char 来说，~0x41 是 0xBE，0x69 & 0x55 是 0x41，0x69 | 0x55 是 0x7D。能直接在语言里做这么底层的位操作，是 C 受欢迎的原因之一，在实践中也很有用。

用位向量表示集合

一个 $w$ 位的位向量可以表示 $\{0,1,\dots,w-1\}$ 的任意子集：第 $j$ 位（从右往左数，最右边是第 0 位）为 1，表示 $j$ 在集合里。比如 01101001 表示 $\{0,3,5,6\}$，01010101 表示 $\{0,2,4,6\}$。于是 & 是交集，得到 $\{0,6\}$；| 是并集，得到 $\{0,2,3,4,5,6\}$；^ 是对称差，得到 $\{2,3,4,5\}$；~ 是补集。Bryant 提到，后面讲 I/O 时会遇到一个系统调用，用来查询"哪些网络连接有数据可读"，它内部就是用这种方式，用一千位左右的位向量表示连接的集合。

别把位运算和逻辑运算搞混

C 还有一组长得很像的逻辑运算：&&、||、!。它们不按位运算，而是把整个值当作真或假：0 是假，任何非零值都是真，结果总是 0 或 1。比如 !0x41 是 0，!0x00 是 1，!!0x41 是 1，0x69 && 0x55 是 1。逻辑运算还有提前终止：p && *p 先判断 p 是否为空指针，是空就不再去解引用。Bryant 提醒，把 & 写成 &&、| 写成 ||，是 C 新手乃至老手都会犯的常见错误，因为两者语法相似、含义也沾边，混用一定出问题。

移位

左移 x << y 把位向量向左移 y 位，左边移出去的丢掉，右边补 0。右移 x >> y 向右移，右边移出去的丢掉，左边补什么有两种：逻辑右移补 0；算术右移复制原来的最高位。比如 10100010 算术右移 2 位得到 11101000，逻辑右移得到 00101000。为什么需要算术右移，等讲完负数的表示（下一讲的除法）就明白了。

移位量小于 0 或大于等于字长，在 C 里是未定义行为。直觉上把 8 位数左移 8 位应该得到 0，但大多数机器上会得到 x 本身，因为硬件只看移位量的低 3 位，相当于先对 8 取模。有的机器是这样，有的不是，C 不做保证。

三、整数的两种编码

设一个数有 $w$ 位，从低到高是 $x_0, x_1, \dots, x_{w-1}$。无符号数的值就是各位按 2 的幂加权求和：

$$B2U(X) = \sum_{i=0}^{w-1} x_i\cdot 2^i$$

补码（two's complement）只有一处不同：最高位的权重是负的。

$$B2T(X) = -x_{w-1}\cdot 2^{w-1} + \sum_{i=0}^{w-2} x_i\cdot 2^i$$

最高位因此叫符号位，它是 1 时这个数一定是负的，因为只有它的权重为负。表示有符号数还有别的方法，但补码用得太普遍，几乎不会遇到别的。

Bryant 建议用很小的字长举例子来建立直觉，别一上来就写 32 位。拿 5 位来说，各位权重是 16、8、4、2、1。01101 作为无符号数是 8+4+1=13，作为补码也是 13（最高位是 0）。10110 作为无符号数是 16+4+2=22；作为补码，最高位权重是 -16，所以是 -16+4+2=-10。同一个位模式，两种解释差了 32，即 $2^5$。

表示范围

5 位无符号数最小 0，最大 11111 即 31，等于 $2^5-1$。补码最小的是 10000 即 -16，只有符号位为 1，其他全 0；最大的是 01111 即 15。一般地：

  • $UMax = 2^w - 1$，位模式全 1。
  • $TMin = -2^{w-1}$，位模式 100…0。
  • $TMax = 2^{w-1}-1$，位模式 011…1。
  • 补码里全 1 的位模式永远是 -1，比如 5 位的 11111 是 -16+8+4+2+1=-1。

C 程序可以引入 limits.h，里面定义了 ULONG_MAX、LONG_MAX、LONG_MIN 等常量，具体值随平台而定。Bryant 开玩笑说，据说微软换到 64 位字长是为了能表示比尔·盖茨的身家，而 32 位已经足够他日常记账。

两个值得记住的关系。第一，$|TMin| = TMax+1$，范围不对称，负数比正数多一个。原因是最高位为 0 的那一半位模式里要分出一个给 0，正数就少了一个。这个不对称是无数麻烦的根源，比如 x < 0 ? -x : x 这样实现的绝对值，对 TMin 返回的还是 TMin，所以做测试时总要把 TMin 放进去。第二，$UMax = 2\cdot TMax + 1$：TMax 是 0 后面跟一串 1，乘 2 就是左移一位，再加 1 就是全 1。

另外，在表示范围内，每个位模式对应唯一的一个数，每个数也有唯一的位模式，所以两种编码都可以反过来，从数得到位模式。

四、有符号与无符号之间的转换

C 在有符号和无符号之间转换时，规则是位模式不变，只换一种解释。课件把它记作 T2U 和 U2T。最高位为 0 的数，两种解释相同；最高位为 1 的数，两种解释差 $2^w$：

$$T2U(x) = \begin{cases} x, & x \ge 0\\ x + 2^w, & x < 0\end{cases}$$

以 4 位为例，补码 -1（1111）转成无符号是 15，-8（1000）转成无符号是 8，0 到 7 不变。在图上看，就是补码的负数那一半被整体搬到了无符号的上半段。

为什么要关心这个？Python、Java 里没有这个问题，因为 C 是少有的把无符号作为显式类型的语言。直接声明为无符号并按无符号使用还好，麻烦在于隐式转换：

  • 常量默认是有符号的，后面加 U（或 u）才是无符号，比如 4294967259U。
  • 把有符号值赋给无符号变量，或者反过来，会按上面的规则隐式转换。
  • 一个表达式里只要有一个操作数是无符号的，另一个有符号的操作数就会被隐式转成无符号，再做运算。比较（<、>、==、<=、>=）也一样。

于是有这些反直觉的结果（32 位）：-1 < 0U 是假的，因为 -1 被转成了无符号的 UMax；2147483647U > -2147483647-1 是假的，因为右边是 TMin，转成无符号后是 $2^{31}$，比左边大；-1 > -2 在转成无符号后依然成立，因为 -1 变成 UMax，-2 变成 UMax-1。课件把 TMin 写成 -2147483647-1，Bryant 解释，直接写 -2147483648 会让编译器因为一些晦涩的原因出错，limits.h 里也是这么写的。

两个真实的坑

第一个：倒着遍历数组。写一个从 n-1 往下数到 0 的循环，条件是 i 大于等于 0。如果 i 被声明成无符号（毕竟是数组下标），这个条件永远成立，i 从 0 再减 1 会变成 UMax，于是访问远远越界，多半引发内存错误。

第二个更隐蔽：i 声明成有符号的 int，但循环条件里写的是类似 i - sizeof(char) >= 0 的东西。sizeof 返回的是无符号类型，于是整个比较变成无符号比较，同样永远为真。Bryant 说，你盯着这样的代码看一千遍也看不出它为什么崩溃，这是 C 的怪癖之一，如果能重来，C 的设计者大概会换一套规则，可惜为时已晚。

五、扩展和截断

符号扩展

把一个 $w$ 位的补码数扩成 $w+k$ 位而保持值不变，规则是把符号位往左复制 $k$ 份。

为什么成立：看 4 位的 1110，它是 -8+4+2=-2。复制一次符号位变成 5 位的 11110，新的符号位权重是 -16，原来的符号位变成了 +8，-16+8=-8，正好等于原来那一位的 -8，其余位不变，所以值还是 -2。每复制一次都是这个道理。正数的符号位是 0，复制 0 自然不改变值。无符号数扩展则直接在左边补 0（零扩展）。

一个实用的读数技巧：看到一个以一串 F 开头的位模式，就知道它是一个离 0 不远的负数，因为它是符号扩展出来的。

截断

反过来，把一个数砍短，就是直接丢掉高位。对无符号数，这相当于取模：5 位的 11011 是 27，丢掉最高位得 4 位的 1011，是 11，就是 27 mod 16。对补码就怪一些：5 位的 10011 是 -13，截成 4 位的 0011 变成了 +3。可以这样理解：-13 的位模式按无符号看是 19，19 mod 16 = 3，再按 4 位补码解释。截断在实际程序里很常见，负数可以变正数，正数可以变负数，各种奇怪的事都会发生。下一讲讲算术运算时会看到更多例子。
