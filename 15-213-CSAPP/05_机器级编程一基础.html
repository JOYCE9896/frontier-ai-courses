第五讲：机器级编程（一）：基础

为什么要读编译器生成的汇编，Intel x86 的历史和它"像英语一样"的演化，指令集架构与微架构，程序员能看到的机器状态，从 C 到可执行文件的几步，反汇编工具，x86-64 的 16 个整数寄存器，mov 指令和内存寻址方式，lea 指令和算术运算

主讲：Randal E. Bryant
资料来源：课堂录像（2015 年 9 月 15 日，YouTube 转载自 CMU 官方 Panopto 录像；本文依据录像字幕整理）、课件
教材对应：CS:APP 第 3.1 到 3.5 节

一、这门课怎样学机器级编程

Bryant 说，从这一讲开始进入这门课真正的核心。"机器级编程"指的是考虑机器为执行你的程序而执行的每一条指令。机器程序有两种形式：目标代码，即处理器实际执行的一串字节；汇编代码，即目标代码的文本形式，方便人读。两者一一对应，所以他会混用"机器代码"和"汇编代码"这两个说法。

以前很多学校有一门"汇编语言程序设计"课，作业是用汇编写排序、链表之类的东西，现在没人想用汇编写这些，学生也不喜欢，这类课就从课程体系里消失了。这门课的角度不同：除了极少量，不自己写汇编，而是大量阅读 GCC 生成的代码，看它和输入的 C 代码是什么关系，高层的结构怎样用底层代码实现：过程怎样调用，数组和结构体怎样表示。这部分要占好几讲。课程只讲一种机器：64 位的 Intel 指令集。

二、Intel x86 的历史

x86 这个叫法来自第一款 8086，之后是 80286、80386 等，共同点是都以 86 结尾。Bryant 把 x86 比作英语：它是一层层特性堆积、演化出来的，并不优雅，就像英语拼写和读音不一致、到处是不规则变化。每一步决定局部看大概都对，全局看却不是。有很多指令集更干净、更好懂，但就像大家学英语而不学世界语，x86 更有用。

x86 是所谓的 CISC（复杂指令集计算机）。上世纪 80 年代出现了 RISC（精简指令集计算机）的理念，风靡一时；在它之前的设计本来没有名字，是 RISC 的支持者给它们起了"复杂指令集"这个略带贬义的名字。x86 的手册是两大本，指令有 500 多条，从十进制算术到十进制浮点什么都有，但只要关注 GCC 为常见程序生成的那一小部分就够了。按理说这样的设计不该成功，但 Intel 公司实力太强、半导体工艺领先竞争对手太多，硬是让它活了近四十年，速度上追上了 RISC，在低功耗方面差一些。

  • 8086（1978）：最早的单芯片 16 位微处理器之一，它的一个变种是最初 IBM PC 的基础，地址空间 1 MB。
  • 386（1985）：第一款 32 位 Intel 处理器，即 IA32，加了"平坦寻址"，从此个人电脑能跑 Unix 这类系统了。到 2015 年夏天之前，这门课一直教 IA32。
  • Pentium 4E（2004）：第一款 64 位 x86 处理器。64 位机器也能运行 32 位代码，所以软件可以慢慢迁移，用了大约十年。
  • Core 2（2006）：第一款多核 Intel 处理器。
  • Core i7（2008）：四核，课程的"鲨鱼"服务器用的就是这一代。

单个处理器的速度一直稳步提高，直到 2004 年左右遇到功耗墙：芯片功耗接近 100 瓦，想象一个 100 瓦灯泡装在盒子里拼命吹风散热，很难再往上走，时钟频率从此停在几 GHz。于是厂商在一块芯片上放多个处理器，即多核。2015 年最新的 Broadwell：桌面版 4 核、3.3 到 3.8 GHz、65 瓦；服务器版 8 核、2 到 2.6 GHz、45 瓦。芯片上除了处理器核心，还集成了连接内存（DDR）、外设（PCI）、硬盘（SATA）、USB 和以太网的电路。服务器功耗反而更低，因为一屋子计算机放在一起时，功耗是最大的问题。

AMD 和 64 位的故事

AMD 历来跟在 Intel 后面，稍慢但便宜得多，两家打过激烈的专利官司，结果是交叉授权，AMD 也能生产 x86 处理器。2001 年 Intel 想彻底换掉 IA32，和惠普合作推出全新的 64 位架构 IA64（安腾，Itanium）。它的理念纸面上很好，但过于激进，依赖编译器奇迹般的优化能力，市场上失败了；Intel 投入太多，不好认错。2003 年 AMD 用演化的办法做出了 x86-64：就是把寄存器加宽、把 32 位扩到 64 位这些显而易见的事。Intel 只好在 2004 年推出几乎一样的 EM64T，"灰溜溜地跟在 AMD 后面"。后来 Intel 重整旗鼓，在半导体工艺上领先全球，AMD 又落后了。

另一大类处理器是 ARM，原意是 Acorn RISC Machine。Acorn 是一家英国公司，想自己造个人电脑，不买 Intel 的芯片，自己设计了处理器。作为电脑厂商它彻底失败，但它的指令集足够简单、功耗低，还能定制。ARM 现在是一家总部在英国剑桥的公司，它不卖芯片，卖设计的授权，手机芯片上 ARM 核心只占一小块，其余是图形、通信等电路。Bryant 说要讲好 ARM 得重写一本书，所以课程只讲 x86-64，GCC 编译时用默认或 -m64 参数即可。

三、几个定义和程序员看到的机器

指令集架构（ISA，也简称架构）：写汇编或机器码需要了解的那部分处理器设计，比如指令集规范和寄存器。它是 1960 年代出现的重要抽象：编译器以它为目标，硬件设计者自己决定怎样实现，有的实现快但费硬件，有的慢但省硬件。微架构：架构的具体实现，比如缓存大小和核心频率，这门课很少涉及。例子：Intel 的 x86、IA32、安腾、x86-64 是不同的 ISA；ARM 也有好几代 ISA。

从机器级程序员的角度，能看到一些 C 里看不到的状态：

  • 程序计数器（PC），在 x86-64 里叫 %rip，存放下一条要执行的指令的地址。
  • 寄存器文件：少量存放频繁使用数据的位置，不用地址访问，而是用名字指定。
  • 条件码：几位状态信息，记录最近一次算术或逻辑运算的结果（是否为 0、正负等），用于实现条件分支，下一讲讲。
  • 内存：按字节寻址的数组，存放代码、用户数据，以及支持过程调用的栈。

这个视图本身也是抽象的：每个程序看起来都有自己独立的字节数组，实际上是操作系统和硬件用虚拟内存造出来的；缓存完全不可见，没有指令能直接操作缓存，唯一的区别是重复访问会更快。

四、从 C 到可执行文件

一个较大的程序由多个 C 文件组成，还会用到库。编译分几步：编译器把 C 代码翻译成汇编代码（文本）；汇编器把汇编翻译成目标代码（二进制）；链接器把各个文件的目标代码和静态库合并成可执行程序；有些库在程序开始运行时才动态链接进来。

命令行上 gcc -Og p1.c p2.c -o p 一次完成这一切。gcc -Og -S sum.c 只做第一步，生成 sum.s。-O 后面跟的是优化级别：不加则完全不优化，生成的代码很啰嗦难读；-O1 在新版 GCC 里做了太多变换，对这门课来说太难读；GCC 新增的 -Og（为调试优化）只做显而易见的优化，代码可读又不至于面目全非，课程统一用它，这是 GCC 特有的选项。Bryant 也提醒：在非鲨鱼机器上（学校的其他 Linux、Mac）GCC 版本和设置不同，结果会很不一样，所以课程作业都在鲨鱼机器上做。

课上的例子是一个函数 sumstore：调用另一个函数 plus 算出 x+y，存到指针 dest 指向的位置。生成的汇编只有六行：push、两条 mov、call、pop、ret。真实的 .s 文件里还有很多以点开头的行，那些不是指令，而是给调试器和链接器的伪指令（比如声明这是一个全局函数），书和课件里都删掉了，自己生成时看到不必惊慌。

汇编的特点

数据类型方面：有 1、2、4、8 字节的"整数"，用来存数据值和地址（地址就是无类型的数），存储时不区分有符号和无符号；浮点数有 4、8、10 字节的，用另一组寄存器处理；代码本身是一串编码指令的字节；没有数组、结构体这样的聚合类型，它们只是内存里连续分配的字节，是编译器人为构造出来的。操作方面，每条指令能做的事很有限：对寄存器或内存里的数据做一次算术运算；在内存和寄存器之间传数据；转移控制，包括无条件跳转、过程调用和返回、条件分支。循环、条件、switch 都是在这些底层功能上搭起来的。

sumstore 的目标代码一共 14 字节。x86 指令短的只有 1 字节，长的可达 15 字节。比如 C 里的 *dest = t：t 一般在寄存器里（这里是 %rax），指针 dest 也在寄存器里（%rbx），一条 mov 指令把 8 字节的值写到 %rbx 指向的内存，编码只要 3 字节。Intel 的术语里，"字"（word）因为 8086 的历史是 16 位，"双字"是 32 位，"四字"（quad word）是 64 位，所以 movq 的 q 就是四字。

反汇编

汇编器把文本变成字节，反汇编器反过来，看一串字节就能认出"这是一条 mov 指令"并打印出来。注意，变量名这些信息在机器码层面已经全部丢失，只剩寄存器和内存位置。工具有两个：objdump -d sum 会反汇编整个可执行文件，里面还有很多你没写过的函数（程序启动时用的底层函数），中间能找到 sumstore，并看到每条指令的字节和地址，比如 push 1 字节、mov 3 字节、call 5 字节（要编码调用的目标位置）；调试器 gdb 里用 disassemble sumstore 也能看，用 x/14xb sumstore 可以查看从 sumstore 开始的 14 个字节。即使没有源代码，只要有二进制文件，就能这样逆向。Bryant 以前上课演示反汇编 Windows 上的 Microsoft Word，结果收到邮件说他违反了最终用户许可协议，因为那些"我同意"条款里有一条是不得逆向工程。他的观点是：Word 也只是一个可执行文件，是一串编码指令的字节。

五、寄存器

x86-64 有 16 个存整数和指针的寄存器，名字很古怪，反映了它的演化史：%rax、%rbx、%rcx、%rdx、%rsi、%rdi、%rsp、%rbp 这 8 个是字母名字，%r8 到 %r15 这 8 个是数字名字。用 %r 开头的名字访问的是 64 位，把 r 换成 e（如 %eax）访问的是低 32 位，处理 long 的代码里会看到 %r，处理 int 的代码里会看到 %e。还可以访问低 16 位和最低的 1 字节。

历史上，IA32 只有 8 个 32 位寄存器（%eax 等），而且可以访问它们的低 16 位，这是 8086 留下的；前四个还能单独访问两个字节，那是比 8086 更早的 8 位机 8080 留下的。x86-64 把寄存器数量翻了一倍，这很有帮助，IA32 寄存器少得让人沮丧。那些字母名字很久以前有特定用途，所以按用途命名，现在早就和用途无关了。

唯一特殊的是 %rsp，栈指针，它有专门的用途，不能随便用；其他寄存器基本都可以存程序数据。IA32 时代还有一个用于过程调用的帧指针 %rbp，现在通常也不这么用了。

六、mov 指令

movq 源, 目的 把 8 字节从源复制到目的。注意顺序：源在前，目的在后。操作数有三种：

  • 立即数：编码在指令里的常数，写作 $0x400、$-533，像 C 的常量，用 1、2 或 4 字节编码。
  • 寄存器：16 个之一，比如 %rax。
  • 内存：寄存器给出的地址处连续的 8 字节，最简单的写法是 (%rax)。

组合起来只有五种合法情况：立即数到寄存器（类似给临时变量赋常量）、立即数到内存（往内存存常量）、寄存器到寄存器、寄存器到内存（类似 *p = temp）、内存到寄存器（类似 temp = *p）。立即数不能当目的；为了方便硬件设计，不能一条指令从内存直接复制到内存，要先读到寄存器再写出去，用两条指令。

内存寻址方式

(R) 表示用寄存器 R 里的值作为地址，相当于 C 的指针解引用。D(R) 在寄存器的值上加一个常数偏移 D，对访问数据结构很有用。最一般的形式是

D(Rb, Ri, S)，地址 = Rb + S × Ri + D

Rb 是基址寄存器（16 个都可以），Ri 是变址寄存器（除了 %rsp），S 是比例因子，只能是 1、2、4 或 8，D 是 1、2 或 4 字节的常数偏移。各部分不用时可以省略，比如 (Rb,Ri)、D(Rb,Ri)、(Rb,Ri,S)。这是为数组访问设计的：Ri 是数组下标，要乘以元素大小，int 乘 4，long 乘 8，这就是比例因子的来历。设 %rdx 是 0xf000、%rcx 是 0x0100：

表达式计算地址
0x8(%rdx)0xf000 + 0x80xf008
(%rdx,%rcx)0xf000 + 0x1000xf100
(%rdx,%rcx,4)0xf000 + 4×0x1000xf400
0x80(,%rdx,2)2×0xf000 + 0x800x1e080

例子：交换两个数

经典的 swap 函数：参数是两个 long 指针 xp 和 yp，先把 *xp 和 *yp 读到两个临时变量，再交叉写回。它正好编译成四条 movq 加一条 ret。x86-64 的规则是参数放在固定寄存器里，第一个参数在 %rdi，第二个在 %rsi（最多六个寄存器传参，第七讲细讲），这在函数开始执行前由调用者设好。编译器自己决定临时变量放哪，这里 t0 用 %rax、t1 用 %rdx。

Bryant 强调要能在脑子里模拟每条指令的执行。假设 %rdi 是 0x120、%rsi 是 0x100（真实地址不会这么小，只为举例），内存 0x120 处是 123，0x100 处是 456：第一条 movq (%rdi), %rax 从 0x120 读出 123 放进 %rax；第二条 movq (%rsi), %rdx 从 0x100 读出 456 放进 %rdx；第三条 movq %rdx, (%rdi) 把 456 写到 0x120；第四条 movq %rax, (%rsi) 把 123 写到 0x100。两次读、两次写，交换完成，全部工作都由 mov 完成。

七、算术和逻辑运算

lea：计算地址的指令

Bryant 预言这条指令一定会让大家困惑、给助教发邮件求解释。leaq 源, 目的（load effective address，加载有效地址）的源写法和内存操作数一样，目的必须是寄存器。它看起来像 mov，但它只做地址计算，然后把算出来的地址本身写进寄存器，并不去读内存。它的本意是实现 C 的取地址 &，比如 p = &x[i]。

它同时也是做算术的好工具，编译器很爱用，因为 x + k*y（k 是 1、2、4、8）一条指令就能算完。课上的例子：C 里写 x * 12，编译器生成 leaq (%rdi,%rdi,2), %rax 算出 3x，再用 salq $2, %rax 左移 2 位乘以 4，得到 12x。

双操作数指令

addq、subq、imulq、salq（算术左移，同 shlq）、sarq（算术右移）、shrq（逻辑右移）、xorq、andq、orq，格式都是 op 源, 目的，效果是"目的 = 目的 op 源"。有两点要记住：目的同时也是一个源操作数，类似 C 的 x += y；操作数的顺序和直觉相反，源在前、目的在后，比如 subq 是"目的 = 目的 - 源"。除了右移分算术和逻辑两种，这些指令不区分有符号和无符号，因为前两讲说过，加减乘在位级上对两者完全相同。

单操作数指令

incq（加一）、decq（减一）、negq（取负）、notq（按位取反，相当于 C 的 ~，不是 !）。

例子：一串算术

课上的 arith 函数对三个参数 x、y、z 做了一系列加法、乘法和移位：t1 = x+y，t2 = z+t1，t3 = x+4，t4 = y*48，t5 = t3+t4，返回 t2*t5 之类的组合。生成的汇编里多次用 lea 做加法，有移位，只用了一次乘法，而源代码里有两次乘法。编译器在想办法用更便宜的指令实现你的要求：y*48 是先用 lea 算出 3y，再左移 4 位（3×16=48）；"x+4" 里的 4 没有单独出现，而是直接用 lea 的偏移字段在别的加法里一起加上了。Bryant 要求回去仔细核对课件上每条指令旁的注释是否正确，务必搞懂 lea。另一个要点是：生成的代码正确实现了 C 函数，但底层不一定按你写的那个顺序、那些运算一步步做。

小结：机器级编程的世界和 C 很不一样；x86 很古怪，就像英语而不像拉丁语，设计得并不好，但只能接受它。
