第三讲：位、字节与整数（下）

无符号和补码的加法、溢出的两种方向，乘法和截断，用移位做乘以和除以 2 的幂以及负数除法的偏置技巧，取负的"取反加一"，什么时候该用无符号数，内存是一个字节数组，字长和对齐，大端和小端，字符串的表示，以及一组整数谜题

主讲：Randal E. Bryant
资料来源：课堂录像（2015 年 9 月 8 日，YouTube 转载自 CMU 官方 Panopto 录像；本文依据录像字幕整理）、课件（第二、三讲共用）
教材对应：CS:APP 第 2.3 节和 2.1.3 到 2.1.5 节

一、开场的提醒

Bryant 先转达了助教们的请求：提问之前先读书，再读一遍作业说明，可能再读一遍，然后再问。很多问题的回答只是"看书的这一页、作业说明的这一段、给你的文件的这一部分"。上一讲讲的是位模式怎样解释成无符号数和补码，这一讲讲在它们上面做算术会发生什么。每部分先讲更直观的无符号情形，再讲补码，例子仍然用 4 位这样的小字长。

二、加法

无符号加法

两个 $w$ 位的无符号数相加，真正的和可能需要 $w+1$ 位。计算机不会为此加位，它直接丢掉第 $w+1$ 位，只保留低 $w$ 位，没有警告、没有错误，悄无声息。结果等价于模 $2^w$ 的加法：

$$UAdd_w(u,v) = (u+v) \bmod 2^w$$

例子：4 位里 13（1101）加 5（0101），按小学竖式逐位进位，真正的和是 18，要 5 位；丢掉最高位得到 0010，即 2，就是 18 mod 16。画成三维图，横轴是 $u$、纵轴是 $v$，和本该是一个斜面一路涨到 30；实际上一过 15 就像跌下悬崖一样掉回 0，再重新往上涨到最多 14（30-16）。跌下的地方就叫溢出，效果是从和里减掉了 $2^w$。

补码加法

补码加法用的是和无符号加法完全相同的位级操作，同一套硬件、同一个算法。这是补码成为主流表示的重要原因。比如 4 位补码里 1101 是 -3，加上 5（0101），同样丢掉进位，得到 0010，即 2，正好是 5-3。-3 加 -5 再加 3 也对。

4 位补码的范围是 -8 到 7。结果超出这个范围就溢出，分两种：

  • 负溢出：两个负数相加得到正数。-3（1101）加 -6（1010）得到 0111，即 7。真正的和 -9 表示不了，7 和 -9 正好差 16。
  • 正溢出：两个正数相加得到负数。7（0111）加 5（0101）得到 1100，即 -4。12 的位模式本来就是 1100，只是现在最高位是符号位，按补码读成了 -4。

于是补码加法的结果图有三块区域：中间是正常区，和落在表示范围内；一角是负溢出区，结果被加了 $2^w$；另一角是正溢出区，结果被减了 $2^w$。Bryant 说，无符号的模运算还有点数学上的美感，补码溢出看起来就毫无用处，但它就是这样，我们只能接受。数据实验里会把这些情况弄得很清楚。

三、乘法

乘法遵循同样的原则：表示不下就只留低 $w$ 位。两个 $w$ 位数的真实乘积最多需要 $2w$ 位（加法只需要 $w+1$ 位），总不能每乘一次字长就翻倍，所以截断到 $w$ 位。无符号乘法依然是模 $2^w$ 的运算：4 位里 3 乘 5 得 15，表示得了；5 乘 5 是 25，8 位表示是 00011001，丢掉高 4 位剩 1001，即 9，等于 25 mod 16。

补码乘法更奇怪：不仅高位被丢掉，剩下的最高位还决定了结果的正负，而这和两个操作数的符号毫无关系。5 乘 4 是 20，低 4 位是 0100，结果 4；5 乘 5 低 4 位是 1001，按补码读是 -8+1=-7。两个正数相乘得到负数，第一讲开头 50000 的平方就是这个现象。

同样神奇的是，只要结果在表示范围内，用无符号乘法的规则算补码乘法也是对的。例子：-3（1101）乘 -2（1110）。按无符号看它们是 13 和 14，乘积 182，十六进制 B6，低 4 位 0110 就是 6，正好是 $(-3)\times(-2)$。所以低 $w$ 位的乘积对无符号和补码完全一样，可以用同一套硬件。如果要乘积的高 $w$ 位，两种解释的结果不同，机器有不同的指令，但 99% 以上的情况只用低位。

用移位乘以 2 的幂

左移 $k$ 位等于乘以 $2^k$。道理很简单：数值是各位按 $2^i$ 加权求和，左移一位相当于每一位的权重都变成 $2^{i+1}$，整个和就翻倍。即使有位被移出去也没关系，乘法本来就要截断到 $w$ 位。无符号和补码都成立。

你在 C 里写乘以 4，编译出的汇编里常常是左移 2 位。原因是历史上乘法指令很慢，移位一个时钟周期，乘法要 11、12 甚至 30 个周期；现在课程用的机器上乘法只要 3 个周期，但 3 毕竟比 1 多，编译器会自己判断什么时候用别的运算替代更划算。比如乘以 12 可以写成乘以 8 加乘以 4，即两次移位一次加法。

用移位除以 2 的幂

无符号数右移 $k$ 位（逻辑右移）等于除以 $2^k$ 再向下取整。6（0110）右移一位是 3，再右移一位是 1，而 3/2 = 1.5，整数除法的规则是向零舍入，结果 1 没错。

有符号数要用算术右移，这就是算术右移存在的理由：除法要保持符号。-6（1010）算术右移一位得到 1101，即 -3，对的。再右移一位得到 1110，即 -2，但 -3/2 应该向零舍入得 -1。问题在于算术右移是向负无穷舍入的。修正办法是先加一个偏置 $2^k-1$ 再移位：这里 $k=1$，偏置是 1，1101 加 1 得 1110，再右移得到 1111，即 -1，正确。

$$\lfloor (x + 2^k - 1) / 2^k \rfloor = \lceil x/2^k \rceil \quad (x < 0)$$

编译器在你写"除以 16"时就会生成"加偏置再右移"的代码，因为除法指令真的很慢，即使在现代机器上也要 30 多个周期，能用移位和小技巧替代时编译器一定替代。顺带一提，C 标准只规定无符号数必须逻辑右移，有符号数的右移方式没有规定；但实际上几乎所有机器对有符号数都做算术右移。

取负：取反加一

手算一个数的相反数有个现成办法：把所有位取反，再加 1。6 是 0110，取反得 1001，加 1 得 1010，即 -6；对 1010 再取反加一又回到 0110。也就是 $-x = \sim x + 1$。用它可以验证一个重要事实：TMin（1000）取反是 0111，加 1 又是 1000，所以 $-TMin = TMin$，这让 TMin 成为几乎所有整数谜题的反例。

四、什么时候该用无符号数

加法和乘法在位级上对两种表示完全相同，结果只要不溢出就正确；溢出时也不是乱来，有规律可循。但有符号和无符号的混用这么容易出错，要不要干脆取消无符号数？Java 就是这么做的：所有整数都是补码，只加了一个 >>> 运算符表示逻辑右移，因为很多位操作技巧需要它。另一种更现代的做法是允许两种类型，但禁止隐式转换，必须显式转换。Bryant 认为后者更好。可惜 C 会隐式转换。

上一讲倒着遍历数组的坑，有一种反直觉但被推荐的写法。CMU 软件工程研究所计算机应急响应小组（CERT）的 Robert Seacord 写的安全编码书被视为这方面的标准，他建议循环变量用 size_t（64 位无符号），从 cnt-2 开始往下减，循环条件写成 i < cnt。i 一直在减小，条件什么时候会失败？就是 i 从 0 再减 1、绕回到 UMax 的时候，这恰好是该停下的时刻。理由是 C 标准不保证有符号数溢出的行为（虽然大家都默认是补码），却保证无符号运算是模运算，0 减 1 一定得到最大值，所以这样写在任何符合标准的实现上都正确。Bryant 说他自己也开始这样写，习惯了还行，只是乍看很怪。不过它只是把陷阱挪了位置：如果 cnt 本身是个被转成无符号的负数，条件几乎总成立。

真正该用无符号数的场合：做模运算的时候，比如大多数加密算法；以及把位当作集合而不是数来用的时候。

五、内存里的表示

内存是一个大字节数组

从程序员的角度，甚至从汇编程序员的角度，内存就是一个从 0 编号到某个最大值的巨大字节数组，地址就是数组下标。x86-64 的地址是 64 位的，但目前的机器只允许用 47 位。

$2^{47}$ 有多大？一个估算技巧：$2^{10}=1024\approx10^3$，也就是每 10 个二进制位大约相当于 3 个十进制位。于是 $2^{20}\approx10^6$，$2^{30}\approx10^9$，$2^{40}\approx10^{12}$，$2^{47}\approx128\times10^{12}$，即 128 TB。几块硬盘能装下这么多，但没人买得起这么多内存。实际上操作系统只允许访问其中某些区域，访问其他区域会触发段错误。程序以为自己拥有一个平坦的大字节数组，这个假象是硬件和操作系统合作造出来的，背后在内存不同区域之间、甚至内存和磁盘之间搬来搬去，这就是后面要讲的虚拟内存，连汇编程序员也基本看不见。

字长

"字长"如今没有严格定义，大致指指针的大小，或者硬件标准支持的、能直接做算术和存取的最大数据块。说 64 位机，是指它常规地处理 64 位数值、地址是 64 位的，即使现在只能用 47 位。字长也不完全由硬件决定：用 GCC 编译时可以加参数选择生成 64 位或 32 位代码，64 位机器为了向后兼容也能运行 32 位代码；而在 64 位代码里，int 仍然只有 32 位。所以 Bryant 说，没有精确定义时，"字"只是指一块数量不定的位。

对齐

多个字节可以组成一个字，字的地址是它最低那个字节的地址。通常会让字对齐：4 字节的字放在地址为 4 的倍数的位置（0、4、8、12），8 字节的字放在 8 的倍数上。编译器会尽量保持对齐，因为硬件对齐访问更快。

大端和小端

一个多字节的字，字节按什么顺序存？小端（little endian）把最低有效字节放在最低地址，大端（big endian）把最高有效字节放在最低地址。这两个名字来自《格列佛游记》，原书当然和计算机无关。以 4 字节的 0x01234567 为例，从低地址到高地址，大端存成 01 23 45 67，和我们书写的顺序一致；小端存成 67 45 23 01，看起来很别扭。

以前人们会为此激烈争论，但计算机并不在乎，只要统一约定就行。现在大端机器越来越难找：x86 全是小端；手机里几乎都是 ARM 处理器，硬件可以配置成任一种，但在主流操作系统下都以小端运行；以前的 Sun 工作站和改用 x86 之前的 Mac 所用的 PowerPC 是大端的。唯一常见的大端场合是互联网：32 位的字在网络包里按大端发送，所以网络接口处要做转换。

课上用一个小函数 show_bytes 演示：给它一个起始地址和字节数，它把每个字节的地址和十六进制值打印出来（把地址转成 unsigned char 指针，当作字节数组逐个读，打印地址用 printf 的 %p，它会自动适应机器的指针长度）。在 x86 上看 int 15213（0x00003B6D），从低地址起依然是 6D 3B 00 00，最低有效字节在前。打印出的地址以很多 7f 开头，说明在 47 位地址空间的高端。同一个程序在不同机器上，甚至在同样的硬件和操作系统上，指针的值也可能不同，所以不能把指针从一台机器直接拷到另一台。

字符串

无论大端还是小端，字符的顺序都一样。C 的字符串是一串字节，每个字节是一个字符的编码（ASCII，比较老派，现在也有能表示非英语文字的编码，但 C 标准仍停留在 ASCII），最后一个字节是 0，叫空终止符。所以字符串在不同机器上的表示是一样的。

六、整数谜题

最后是一组判断题，Bryant 说这类题有在考试里出现的"讨厌习惯"。设 x、y 是 int，ux 是 x 转成的无符号数。每条要么证明总是成立，要么举一个反例：

  • x < 0 能推出 x*2 < 0 吗？不能。反例 TMin，乘 2 等于左移一位，变成 0。找反例的通用办法：先试 TMin。
  • ux >= 0？总成立，无符号数不可能为负。
  • 如果 (x & 7) == 7，那么 (x << 30) < 0？成立。低三位都是 1，左移 30 位后剩下的两个 1 跑到了最高两位，符号位是 1。
  • ux > -1？永远不成立。-1 被转成无符号的 UMax，没有比它大的。
  • x > y 能推出 -x < -y 吗？不能。取 y = TMin，-TMin 还是 TMin。
  • x * x >= 0？不能，溢出可以得到负数。
  • x > 0 且 y > 0 能推出 x + y > 0 吗？不能，正溢出。
  • x >= 0 能推出 -x <= 0 吗？成立，任何正数都能取负。
  • x <= 0 能推出 -x >= 0 吗？不能，TMin 没有对应的正数。正负的不对称导致这两条答案不同。
  • (x | -x) >> 31 == -1？x 为 0 时左边是 0，不成立；x 非零时 x 和 -x 至少有一个符号位是 1，或起来符号位为 1，算术右移 31 位得到全 1，即 -1。这个性质很有意思。
