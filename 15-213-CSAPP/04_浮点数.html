第四讲：浮点数

二进制小数和它的两个局限，IEEE 754 标准的符号、阶码、尾数三段式，规格化数和偏置阶码，非规格化数和正负零，无穷大与 NaN，用 8 位的迷你格式把所有值列一遍，向偶数舍入，浮点加法和乘法为什么不满足结合律，C 里的 float 和 double 互相转换，以及一组浮点谜题

主讲：David R. O'Hallaron
资料来源：课堂录像（2015 年 9 月 10 日，YouTube 转载自 CMU 官方 Panopto 录像；本文依据录像字幕整理）、课件
教材对应：CS:APP 第 2.4 节

一、二进制小数

浮点数是计算机表示实数的方式。先从熟悉的十进制小数类比：3.14 的意思是 $3 + 1\times10^{-1} + 4\times10^{-2}$。二进制小数一样，只是底换成 2：二进制小数点左边各位的权重是 1、2、4……，右边是 $1/2$、$1/4$、$1/8$……

$$b = \sum_{k=-j}^{i} b_k\cdot 2^k$$

几个例子：$5\frac34$ 是 101.11（4+1，再加 1/2+1/4）；$2\frac78$ 是 10.111；$1\frac{7}{16}$ 是 1.0111（1/4+1/8+1/16 = 7/16）。把 101.11 右移一位得到 10.111，正好是除以 2；左移则乘以 2。小数点右边全是 1 的数，比如 0.111111…，很接近 1 但比 1 小，写作 $1.0-\varepsilon$，右边的位越多，$\varepsilon$ 越小。

这种表示有两个局限。第一，只能精确表示形如 $x/2^k$ 的有理数，其他数的二进制展开是无限循环的：1/3 是 0.0101010101…，1/5 是 0.001100110011…，连 1/10 都是 0.0001100110011…，所以 0.1 在计算机里从来不是精确的。第二，$w$ 个位里小数点只能放在一个固定位置：小数点往左挪，能表示更多小数位、精度更高，但能表示的数的范围变小；往右挪，范围变大，精度变低。浮点数的"浮点"，就是让这个小数点能浮动，用有限的位同时获得尽可能宽的范围和尽可能高的精度。

二、IEEE 754 浮点标准

O'Hallaron 说，1985 年以前浮点数简直是一场灾难：每家计算机厂商有自己的格式，同一个程序换一台机器，行为不同，舍入不同，计算机科学家普遍讨厌浮点数。1985 年 IEEE（电气电子工程师学会，也是重要的标准制定机构）推出了 IEEE 754 标准，此后所有主要 CPU 都支持它。课件补充了一点：这个标准主要由数值分析专家而不是硬件设计者主导，它对舍入、上溢、下溢都有很好的规定，但硬件上很难做得快。

数值形式和编码

浮点数表示的是类似科学计数法的形式：

$$V = (-1)^s \times M \times 2^E$$

符号 $s$ 决定正负；尾数（significand，有时叫 mantissa）$M$ 通常是 $[1.0, 2.0)$ 之间的小数；阶码 $E$ 用 2 的幂给数值加权。编码时分三段：最高位是符号位 s；接着是 exp 字段，它编码 $E$ 但不等于 $E$；剩下的是 frac 字段，它编码 $M$ 但不等于 $M$。

扩展精度是非标准的，课上不再讨论。按 exp 字段的值，浮点数分成三类：规格化数、非规格化数和特殊值。

规格化数

exp 既不是全 0 也不是全 1 时，是规格化数，这是最常见的情况。

阶码用偏置表示：$E = Exp - Bias$，其中 $Exp$ 是把 exp 字段当作无符号数读出的值，$Bias = 2^{k-1}-1$，$k$ 是 exp 的位数。单精度 $k=8$，偏置是 127，Exp 的取值是 1 到 254，所以 $E$ 的范围是 -126 到 127；双精度偏置是 1023，$E$ 从 -1022 到 1023。（课上口头算范围时把 0 和 255 也算进去了，得到 -127 到 128，但 exp 全 0 和全 1 是留给另外两类的，课件上的 -126 到 127 才是规格化数的范围。）

为什么阶码不用已经学过的补码，而用这种偏置编码？O'Hallaron 的解释是：用偏置编码，最小的阶码对应全 0，最大的对应接近全 1，阶码越大编码值越大，于是两个浮点数可以直接当作无符号整数比较大小，得到的结果是对的。偏置取在范围中间，是为了让 0 附近的阶码正负对称。

尾数用"隐含的 1"编码：规格化数总是把数调整成 1.xxx 的形式，再相应调整阶码。比如 100.01 写成 $1.0001\times2^2$。既然小数点左边永远是 1，就不必存它，frac 只存小数点右边的部分，白赚一位精度。frac 全 0 对应 $M=1.0$，frac 全 1 对应 $M=2.0-\varepsilon$。

例子：float F = 15213.0。15213 的二进制是 11101101101101，规格化成 $1.1101101101101\times2^{13}$。frac 取小数点后的部分，右边补 0 凑够 23 位；$E=13$，所以 $Exp = 13+127 = 140$，即 10001100；符号位是 0。拼起来就是这个 float 的位模式。

非规格化数

规格化数永远有隐含的 1，越靠近 0 就越受限制，而且根本表示不了 0。所以 exp 全 0 时，定义为非规格化数：阶码取 $E = 1 - Bias$（而不是 $0 - Bias$），尾数没有隐含的 1，$M = 0.xxx$，frac 原样就是尾数的小数部分。

  • exp 全 0、frac 全 0，表示 0。这很好：全 0 的位模式就是 0。但符号位可以是 1，所以有 +0 和 -0 两个零。
  • exp 全 0、frac 不为 0，表示最接近 0 的那些数，它们是等间距分布的。

特殊值

  • exp 全 1、frac 全 0，表示无穷大，正负都有。浮点数溢出时变成无穷大，这和补码溢出后"绕回来"完全不同，而且是"粘性"的，对无穷大做任何运算还是无穷大。比如 1.0/0.0 和 -1.0/-0.0 得到 $+\infty$，1.0/-0.0 得到 $-\infty$。
  • exp 全 1、frac 不为 0，表示 NaN（Not a Number，非数），用于没有数值结果的情况，比如 $\sqrt{-1}$、$\infty-\infty$、$\infty\times0$。

画在数轴上，从左到右是：NaN，$-\infty$，负的规格化数，负的非规格化数，-0 和 +0，正的非规格化数，正的规格化数，$+\infty$，NaN。

三、用迷你格式把所有值列一遍

O'Hallaron 和上一讲 Bryant 的建议一样：理解数值编码最好的办法，是用很少的位做例子。比如想理解补码的 TMin 和 TMax，就假设一个 3 位的补码系统，把所有可能列出来。浮点数也一样。课件用了一个 8 位的格式：1 位符号，4 位 exp，3 位 frac，偏置是 $2^3-1=7$。除了位数，它和 IEEE 格式完全一样，有规格化数、非规格化数、0、无穷大和 NaN，而且小到可以把正数全部列出来：

  • exp=0000、frac=000：非规格化，$E = 1-7 = -6$，$M=0$，值为 0。当作无符号整数读也是 0。
  • exp=0000、frac=001：$M = 1/8$，值为 $1/8\times2^{-6} = 1/512$，这是能表示的最小正数。
  • exp=0000、frac=010：$M=2/8$，值为 $2/512$。每把 frac 加一，值就加 $1/512$。
  • exp=0000、frac=111：$M=7/8$，值为 $7/512$，最大的非规格化数。
  • exp=0001、frac=000：进入规格化数，$E = Exp - Bias = 1-7 = -6$，和非规格化数的阶码一样；$M = 1.000 = 8/8$，值为 $8/512$，最小的规格化数。
  • exp=0001、frac=001：$M = 9/8$，值为 $9/512$。

从 $7/512$ 到 $8/512$ 是平滑衔接的。这就是非规格化数的阶码定义成 $1-Bias$ 而不是 $-Bias$ 的原因，O'Hallaron 称赞这个设计很巧妙。继续往上，最大的规格化数是 exp=1110、frac=111，值为 $15/8\times2^7=240$；exp=1111、frac=000 是无穷大。

课件还画了一个 6 位格式（3 位 exp、2 位 frac、偏置 3）在数轴上的分布：值在 0 附近很密，阶码每加一，间距翻一倍。放大看，0 附近的非规格化数和紧接着的第一组规格化数间距相同，再往外每一组间距是前一组的两倍。同一个 exp 值下的数是等间距的。

IEEE 编码的几个好性质

浮点的 0 和整数的 0 位模式相同，全是 0。除了 NaN，几乎可以直接用无符号整数比较来比较两个浮点数的大小，包括非规格化数与规格化数之间、规格化数与无穷大之间。需要注意的是要先比较符号位，要把 -0 当作等于 +0，而 NaN 的比较结果该是什么本身就说不清。

四、舍入

两个浮点数相加或相乘，结果未必能放进现有的位数里。浮点运算的模型是：先假设有无穷多位，算出精确结果，再舍入到可用的位数：

$$x +_f y = \mathrm{Round}(x+y),\qquad x\times_f y = \mathrm{Round}(x\times y)$$

如果阶码太大就上溢，如果尾数位不够就舍入。

四种舍入模式

用"舍入到整数美元"举例，对 1.40、1.60、1.50、2.50、-1.50 五个金额：

模式1.401.601.502.50-1.50
向零舍入1112-1
向下舍入（向负无穷）1112-2
向上舍入（向正无穷）2223-1
向偶数舍入（默认）1222-2

向偶数舍入：不到一半就舍，超过一半就入，正好一半时舍入到使最后一位为偶数的那个值。所以 1.50 变 2，2.50 也变 2。IEEE 默认用它，其他模式只能写汇编才能切换。选它的理由是统计上无偏：其他三种模式都有系统偏差，比如对一组正数求和，总是会偏高或偏低；而正好一半的情况，向偶数舍入大约一半时候向上、一半时候向下。

这个规则可以用在任何一位上。舍入到百分位：7.8949999 不到一半，舍成 7.89（即使 9 是奇数，只有正好一半时才看奇偶）；7.8950001 超过一半，入成 7.90；7.8950000 正好一半，百分位的 9 是奇数，所以入，入的机械做法是在要舍的位置加 5 然后进位，得到 7.90；7.8850000 也正好一半，8 是偶数，直接截断得 7.88。

二进制舍入

二进制里，最低位是 0 就是"偶数"；要舍掉的部分是 100…0 就是"正好一半"。例子是舍入到 1/4（小数点后保留 2 位）：

值二进制舍入后动作结果
2 3/3210.0001110.00不到一半，舍2
2 3/1610.0011010.01超过一半，入2 1/4
2 7/810.1110011.00正好一半，入（使末位为偶）3
2 5/810.1010010.10正好一半，舍（末位已是偶）2 1/2

要领是认出"一半"的标志，决定舍还是入：舍就截断，入就在保留的最后一位加 1 并进位。

五、浮点乘法和加法

乘法：$(-1)^{s_1}M_1 2^{E_1}\times(-1)^{s_2}M_2 2^{E_2}$，结果的符号是 $s_1 \oplus s_2$（异或），尾数是 $M_1\times M_2$，阶码是 $E_1+E_2$。然后修正：如果 $M\ge2$，把 $M$ 右移一位、$E$ 加一；$E$ 超出范围就上溢成无穷大；$M$ 位数太多就按向偶数舍入塞进 frac。最费事的是尾数相乘。

加法：概念上把两个数看作二进制小数，先对齐小数点，再相加，然后规格化（右移或左移，使尾数落在 1 到 2 之间并调整阶码），阶码太大就上溢，最后舍入。

数学性质

第一讲说过，int 不是整数，float 不是实数。和补码一样，浮点数有很可预测的数学性质，只是和实数不完全一样。加法满足：封闭（结果可能是无穷大或 NaN）；交换律；0 是加法单位元；除了无穷大和 NaN，每个元素都有加法逆元；除了无穷大和 NaN，满足单调性（$a\ge b$ 可推出 $a+c\ge b+c$）。但不满足结合律：$(3.14+10^{10})-10^{10}$ 得 0，因为 $10^{10}$ 太大，加上去时 3.14 的位被舍掉了；而 $3.14+(10^{10}-10^{10})$ 得 3.14。问题通常出在动态范围很大的场合，大数和小数相加减。

乘法同样封闭、可交换、以 1 为单位元、满足单调性（乘以正数时），但不满足结合律，也不满足对加法的分配律。例子：$(10^{20}\times10^{20})\times10^{-20}$ 得无穷大，因为第一步就上溢了，之后一直是无穷大；$10^{20}\times(10^{20}\times10^{-20})$ 得 $10^{20}$。分配律的反例：$10^{20}\times(10^{20}-10^{20})$ 得 0，而 $10^{20}\times10^{20}-10^{20}\times10^{20}$ 得 NaN。

这是个问题吗？O'Hallaron 讲了自己的经历：他做过很多科学计算，用有限元方法模拟南加州地震时洛杉矶的地面运动，全部是单精度浮点数，运算顺序无法保证每次一样，但从没遇到过结合律带来的问题。原因是自然界通常是平滑的，相邻两块地面的晃动幅度不会相差悬殊，模拟自然现象时很少出现巨大的动态范围。金融这类非自然的系统就可能出现。所以程序员要对自己数据的动态范围心里有数，并且记住，改变运算顺序可能得到不完全相同的答案。

六、C 里的浮点数

C 有两种浮点类型：float 是 IEEE 单精度，double 是 IEEE 双精度。上一讲 int 和 unsigned 之间转换时，位模式不变，只是换一种解释；而在 int、float、double 之间转换时，位模式会彻底改变。

  • double 或 float 转 int：截掉小数部分（向零舍入）；超出范围或是 NaN 时，C 标准没有规定，在课程机器上通常得到 TMin。
  • int 转 double：精确，因为 double 的尾数有 52 位，足以放下 32 位整数。
  • int 转 float：float 只有 23 位 frac（加隐含位共 24 位），放不下所有 32 位整数，所以按舍入模式舍入。

和其他运算一样，转换也可以看成先得到精确值，再舍入到目标格式的位数里。

七、浮点谜题

设 x 是 int，f 是 float，d 是 double，且 f 和 d 都不是 NaN：

  • x == (int)(float) x？不一定，float 的尾数位不够，转换时会丢位。
  • x == (int)(double) x？总成立，double 的尾数位够用。
  • f == (float)(double) f？总成立。
  • d == (double)(float) d？不一定，double 转 float 会丢精度，也可能溢出。
  • f == -(-f)？总成立，取负只是翻转符号位。
  • 2/3 == 2/3.0？不成立，前者是整数除法得 0，后者是浮点数 2/3。
  • d < 0.0 能推出 (d*2) < 0.0？成立，即使 d*2 溢出，也是溢出成负无穷，仍小于 0。
  • d > f 能推出 -f > -d？成立，这是单调性。
  • d * d >= 0.0？成立。
  • (d+f)-d == f？不一定，因为不满足结合律。

O'Hallaron 的结论：浮点数不是真正的实数，但性质很可预测；最需要警惕的是它不满足结合律。
