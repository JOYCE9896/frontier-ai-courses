第八讲：机器级编程（四）：数据

一维数组在内存里怎样存放，数组名和指针的异同，指针运算的隐式缩放，一组区分"数组的指针"和"指针的数组"的练习，二维数组的行优先存放与元素地址公式，多级数组和变长数组的代码，结构体的布局与对齐，以及 SSE 浮点运算的初步

主讲：Randal E. Bryant
资料来源：课堂录像（2015 年 9 月 24 日，YouTube 转载自 CMU 官方 Panopto 录像；本文依据录像字幕整理）、课件
教材对应：CS:APP 第 3.8 到 3.9 节，浮点部分为 3.11 节

一、从标量到聚合数据

前几讲的程序只处理 int、long 和指针这些标量数据。C 有两种把多个数据组合起来的方式：数组，存放很多个相同类型的元素；结构体（struct），存放几个类型可以不同的字段，按名字访问。两者可以任意嵌套：结构体的数组、含数组的结构体等等。这一讲看它们在内存里怎样表示，以及操作它们的代码长什么样。

要点在于：机器代码层面没有高级语言意义上的数组或结构体，它们只是一段连续存放的字节。分配内存、在访问元素或字段时算出正确的地址，都是 C 编译器的工作。好消息是这类需求太常见了，机器专门提供了为它设计的指令和寻址方式，现在回头看，上一讲那些复杂的寻址方式就很好理解了。Bryant 还说，学的第一门汇编语言最难，换一台机器学第二门、第三门会容易得多。

二、一维数组

声明 T A[L]，T 是元素类型，L 是元素个数。设 T 占 K 字节，那么数组占 $L\times K$ 字节的连续内存：12 个 char 占 12 字节，5 个 int 占 20 字节，3 个 double 或 4 个指针各占 24 和 32 字节。设起始地址是 $x$，第 $i$ 个元素就在 $x + K\cdot i$。

这个声明做了两件事：分配空间；让数组名 A 可以像一个指向第 0 个元素的指针那样使用，参与指针运算。数组和指针的这种可互换性是 C 在当年独有的、至今也少见的特性。以 int val[5] 为例，起始地址 $x$：

  • val[4] 是最后一个元素的值。
  • val 的类型是 int *，值是 $x$。
  • val + 1 是 $x+4$，不是 $x+1$。
  • &val[2] 是 $x+8$。
  • *(val + 1) 就是 val[1]；val + i 就是 $x + 4i$。

指针运算会隐式按元素大小缩放：对 char 指针加 1，地址加 1；对 int 指针 ip 做 ip++，地址加 4，这样它才指向下一个 int。所以 C 里 *(ip + 2) 和 ip[2] 完全等价，只是两种写法。写 C 时不用自己乘元素大小，否则会被逼疯，但编译器生成代码时一直在悄悄做这个乘法。

数组名和指针有一处不同：可以 ip++ 改变指针，但不能 val++，数组名的值由声明固定。课上的几个问答：下标可以是负数吗？可以，规则一样，算出的地址比起点小，完全是合法的 C，而且这学期一定会用到。两个指针能相加吗？不能，只能一个指针加一个整数（编译器知道哪个是指针，会给整数缩放）；两个指针可以相减。下标越界呢？C 不检查，读到的是越界处的任何东西，可能是非法地址导致段错误，更常见的是读到一个莫名其妙的值，而如果是写，就会破坏内存里已有的数据。

数组访问的代码

课上用了一个"邮编"例子：#define ZLEN 5，typedef int zip_dig[ZLEN]，再声明 cmu、mit、ucb 三个数组。Bryant 顺带讲了好的写法：别在程序里散落"魔法数字"，用 #define 给常量起个有意义的名字；复杂的数据结构用 typedef 拆开声明，因为 C 的声明语法很快就会变得晦涩。三个数组各占 20 字节，课件里画成首尾相接的，但实际地址无法控制，只能确定每个数组本身是连续的 20 字节。

函数 get_digit(z, digit) 返回 z[digit]，编译成一条 movl (%rdi,%rsi,4), %eax：z 在 %rdi，digit 在 %rsi，地址 = %rdi + 4×%rsi，读出 4 字节放进 %eax（int 放在 32 位寄存器里）。x86 费心加上这种带比例因子的寻址方式，就是因为这类操作太常见。（课堂上有同学指出课件这一页把寄存器写错了，Bryant 当场确认并说会改正。）

把数组每个元素加一的循环：用的是上一讲的"跳到中间"结构，i 在 %rax 里，真正干活的是一条 addl $1, (%rdi,%rax,4)。算术指令的目的操作数可以是内存，这条指令先读内存、做加法、再把结果写回去，正好就是 z[i]++。Bryant 说，C 的指针运算是一群一辈子写汇编的人想出来的：他们想让程序看起来像高级语言，又保留在汇编里学会的所有技巧。C 最初是为了写 Unix 操作系统而设计的，在那之前操作系统都直接用汇编写。所以 C 的 ++、+= 和机器指令之间有很紧密的对应。

三、数组和指针的区别：一组练习

Bryant 现场出了一组题（课后补进了课件）。对每个声明，问三件事：表达式能否编译；会不会造成空指针或坏指针的解引用；sizeof 是多少。核心区别是：声明一个数组会真正分配它的空间；声明一个指针只分配指针本身的 8 字节，不分配它所指的东西。

声明含义sizeof(An)sizeof(*An)*An 可能出错吗
int A1[3]3 个 int 的数组124不会
int *A2指向 int 的指针84会，指针未初始化

再进一步是三个组合声明。读 C 声明的规则（Kernighan 和 Ritchie 的书里有很好的一节专门讲）是从名字开始由内向外读；另外要查运算符优先级表：方括号的优先级（第 1 级）高于星号（第 2 级）。

  • int A1[3]：**A1 无法编译，因为 *A1 已经是 int，不能再解引用。
  • int (*A3)[3]：括号让 A3 先和 * 结合，A3 是一个指针，指向一个 3 个 int 的数组。sizeof(A3) 是 8，sizeof(*A3) 是 12，sizeof(**A3) 是 4。*A3 和 **A3 都可能出错，因为只分配了指针，它没有被初始化去指向一个真正的数组。
  • int *A4[3]：方括号优先，A4 是一个 3 个元素的数组，每个元素是 int 指针。sizeof(A4) 是 24，sizeof(*A4) 是 8，sizeof(**A4) 是 4。*A4 不会出错，数组本身已经分配了；**A4 可能出错，比如数组被初始化成全 0，就是三个空指针。
  • int *A2[3] 和 A4 一样，不加括号就是同一个意思。

有同学问：C 里数组不是不知道自己有多大吗，sizeof 怎么知道是 24？答案是编译器知道很多：声明时就写了 3 个元素、每个指针 8 字节。运行时机器不做边界检查，但声明时大小必须是已知的。函数参数里写的空方括号 int a[] 则等价于指针声明，不分配空间。Bryant 说，如果觉得这些混乱，说明很需要真正搞懂指针和数组，否则写 C 会在这上面耗掉无数小时；而现在能看懂编译后的代码，这些问题就清楚多了。

四、多维数组

声明 T A[R][C] 是 R 行 C 列的二维数组，共占 $R\times C\times K$ 字节。存放顺序是行优先：先放第 0 行的全部 C 个元素，再放第 1 行，依此类推。为什么是这个顺序？还是那条由内向外的读法：int A[3][5] 的意思是 A 是一个 3 个元素的数组，每个元素本身是 5 个 int 的数组。所以每一"行"作为一个整体连续存放，布局直接来自声明语法。

邮编例子推广一下：zip_dig pgh[4] 是 4 个邮编组成的数组，展开就相当于 int pgh[4][5]。

C 里可以只写一个下标 A[i]，它表示第 i 行，即一个 C 个元素的数组，起始地址是 $A + i\cdot C\cdot K$。元素 A[i][j] 的地址是：

$$\&A[i][j] = A + i\cdot(C\cdot K) + j\cdot K = A + (i\cdot C + j)\cdot K$$

先跳过 i 整行，再在这一行里跳过 j 个元素。编译器生成的代码就是用 lea、比例寻址和移位的组合算出这个地址，再做一次内存访问。比如 int pgh[4][5] 取 pgh[index][dig]：先用 lea 算出 5×index，再在寻址里乘 4 加上 dig，相当于行号乘 20、列号乘 4。（Bryant 课上发现这一页的代码示例在课件里漏掉了，只好口头讲。）

多级数组：指针的数组

另一种写法：先有 cmu、mit、ucb 三个数组，再声明 int *univ[3]，三个元素分别指向这三个数组。这在数据结构上和二维数组不同：univ 是 3 个指针，每个指针指向一个 5 个 int 的数组，而 C 在这种声明里不记录被指数组有多长。

取 univ[index][digit] 的代码需要两次内存访问：先把 digit 左移 2 位（乘 4）；然后用 addq univ(,%rdi,8), %rsi 从 univ 数组里按 index×8 读出一个指针，加到缩放后的 digit 上；最后从得到的地址读出 int。对比二维数组 pgh[index][dig]：所有地址计算（行乘 20、列乘 4）做完后只读一次内存。C 代码看上去完全一样，但底层数据类型不同，访问方式就不同。

固定大小、变长和手工计算的二维数组

以前在 C 里，如果矩阵的大小编译时不确定，只能自己写宏，按行优先手工计算下标。1999 年的 C99 标准开始允许把数组大小作为参数传给函数，比如 int var_ele(long n, int A[n][n], long i, long j)，也允许在算出 n 之后声明 n 个元素的数组，编译器会正确处理。对比生成的代码：16×16 的固定数组取 A[i][j]，行号乘 64 用移位就行，三条指令算完地址再读一次；而 n×n 的变长数组，n 编译时未知，必须用一条乘法指令算 n×i，乘法相对昂贵，然后再用 lea 和比例寻址算出偏移。课件里还有一个三层嵌套的例子，Bryant 说想折磨自己的话可以去看。

五、结构体

结构体的基本思想很简单：分配足够容纳所有字段的连续空间，字段按声明的顺序排列；编译器记住每个字段从哪个偏移开始，访问字段时从结构体起始地址加上偏移。结构体的引用就是它的起始地址。

课上的结构体 rec 有三个字段：一个 4 个 int 的数组 a（偏移 0，占 16 字节）、一个 int 下标 i（偏移 16）、一个指向下一个 rec 的指针 next（偏移 24）。取 &r->a[idx] 时，因为 a 就在开头，和普通数组访问一样，用 leaq (%rdi,%rsi,4), %rax 算出地址。（课件里这个例子有处笔误，同学指出 a 应该有 4 个元素，Bryant 认同。）

更完整的例子是一个沿链表前进的循环：每一步取出 r->i，把 val 存进 r->a[i]，再令 r = r->next，直到 r 为空。对结构体的三次引用对应三条指令：movslq 16(%rdi), %rax 取 i，这里用的是带符号扩展的 movslq，因为 i 是 int，但要当作数组下标参与 8 字节的地址运算；movl %esi, (%rdi,%rax,4) 把 val 存进 a[i]；movq 24(%rdi), %rdi 取 next。然后测试 r 是否为空（空指针就是 0）。C 代码和 x86 指令几乎一一对应，这也再次说明那些寻址方式为什么存在。

对齐

机器通常希望一个 K 字节的基本数据的地址是 K 的倍数，这叫对齐。为此编译器分配结构体时会在字段之间插入不用的填充字节。例子：一个结构体依次是 char c、int i[2]、double v。c 在偏移 0，占 1 字节；i 是 int，地址要是 4 的倍数，所以跳过 3 个字节，从偏移 4 开始，占 8 字节到偏移 12；v 是 double，要 8 的倍数，再跳过 4 个字节，从偏移 16 开始。结构体本身的起始地址也会保证是 8 的倍数，这样 v 的实际地址才是 8 的倍数。

为什么要对齐？这是硬件的事：内存系统不是一次取一个字节，现在多数机器一次取大约 64 字节的块。一个数据如果因为地址没对齐而跨越两个块的边界，硬件甚至操作系统要多做几步。在 x86 上，未对齐的数据照样能正确执行，只是可能慢一点；在有些机器上，未对齐访问会直接引发内存错误。数据大小一般是 1、2、4、8 字节（也有 16 字节的，这里不讲），对 2 的幂对齐的地址，看地址的二进制末尾有几个 0 就知道对齐到了多少。

编译器的两条规则：每个字段按它自己的对齐要求放置；整个结构体的大小要补齐到其中最大对齐要求的倍数，必要时在末尾加填充。末尾填充的理由是结构体数组：只要数组起点是 8 的倍数，每个元素的大小又是 8 的倍数，那么每个元素的起点都是 8 的倍数，元素内部的字段也都对齐了。比如一个含 double、int、char 的结构体，大小会被补成 24 而不是 17。结构体的对齐要求取决于它所含字段里要求最高的那个；只含 float 和 int 的结构体，对齐要求是 4。数组字段的对齐只看它的元素类型，因为对齐只和最底层的基本类型有关，从不会一次从内存读整个数组。

有同学问能不能让编译器不对齐。Bryant 说更好的办法是调整字段的声明顺序，减少浪费。前面的例子浪费了 3 + 4 个字节；把 int 放在最前，再放 char，再放 double……更一般的贪心原则是：把大的字段放在前面，依次往小排，因为对齐要求都是 2 的幂，这样做能把浪费降到最少。这件事 C 编译器不会自动替你做，只能写代码的人自己安排。

六、浮点运算初步

x86 浮点的历史很复杂。很早以前有一块和 8086 搭配的芯片 8087，在当时是工程杰作，第一次把完整的 IEEE 浮点硬件放进一块芯片，甚至是和 IEEE 浮点标准本身一起开发的。但它的编程模型丑陋得可怕，书的第一版讲过它，第二版挪到了网络旁注里，第三版干脆删掉了。

后来为了支持视频等需要大量数值处理的应用，x86 加入了一类叫 SSE 的指令（SIMD 扩展），更新的机器上又发展成 AVX，鲨鱼机器支持 SSE3。它有 16 个独立于整数寄存器的特殊寄存器 %xmm0 到 %xmm15，每个 16 字节，可以把它当作 16 个 char、8 个 short、4 个 int、4 个 float 或 2 个 double 来运算。有人发现可以直接用这套指令实现普通的标量浮点运算，绕开旧的 x87，于是现在的机器就这样生成浮点代码。

指令举例：addss 是"标量单精度加法"，只加寄存器最低位置的一个 float，形式和 addq 类似；addps 是"打包单精度加法"，一条指令同时做 4 个 float 的加法，这就是 SIMD（单指令多数据）；双精度也有对应的 addsd 和 addpd。第十讲讲代码优化时会看到，用好这些打包指令能大幅提高性能。

浮点参数的约定很简单：浮点参数依次放在 %xmm0、%xmm1、%xmm2……，返回值在 %xmm0，所有 xmm 寄存器都是调用者保存，没有被调用者保存的。整数（指针）参数和浮点参数混合时，按参数列表的顺序，整数类的依次用 %rdi、%rsi 等，浮点类的依次用 xmm 寄存器，互不干扰。比如一个参数是 double 指针、一个是 double 值的函数，指针在 %rdi，值在 %xmm0；函数体里有从内存读到 xmm 寄存器、在 xmm 寄存器之间相加和复制、再写回内存的指令，看上去和整数代码很像，只是换了寄存器和指令。基本原理不难，复杂在于指令数量极多（单精度、双精度、开平方等），比较操作尤其麻烦，用常数时也有各种技巧。书里有讲，这门课不深入。
