补充七：Blockstack：命名、区块链的非货币用途与去中心化应用

2020 年第 20 讲，接在比特币之后。为什么看 Blockstack；什么是去中心化应用，传统网站的问题，新架构把应用代码和用户数据分开；一个共享待办清单的例子；会出什么问题；为什么 Blockstack 从命名入手；Zooko 三角：唯一、人类可读、去中心化；把名字记录嵌进比特币区块；这种名字空间适合去中心化应用吗；各个组件：Blockstack 服务器、Atlas、Gaia；注册名字的两笔交易；存储、校验、新鲜度、加密；私钥管理；一组讨论题；结论

主讲：Robert Morris（2020 年春季 6.824 第 20 讲）
资料来源：2020 讲义、FAQ、课堂录像、阅读：Blockstack 白皮书；更详细的是作者 USENIX ATC 2016 的论文

一、为什么看 Blockstack

它涉及讲义作者感兴趣的三个问题：

  • 怎样构建一个命名系统，即一个 PKI（公钥基础设施），这是一块关键的缺失部件；
  • 区块链在加密货币之外的一种用途；
  • 一种很不同的网站架构，也许有一天会更好。

Blockstack 是一个真实的系统，由一家公司开发，有一些用户和为它写的应用。但应该把它看作对"事情可以怎样不同、怎样更好"的一次探索，而不是"事情就该这样"。

二、去中心化应用

以一种把数据所有权交到用户手里、从中心控制的网站手里拿出来的方式构建的应用。这个大愿景有很多新的（和老的）探索，比特币的成功（和它的性质）激发了很多近期的活动。

旧的：典型的（中心化的）网站

[user browsers] -- net -- [site's web servers w/ app code] -- [site's DB]

用户的数据藏在专有的应用代码后面，比如博客文章、gmail、piazza、reddit 评论、照片分享、日历、病历等。这种安排很成功，容易编程。为什么不理想？

  • 用户想看自己的数据，就得用这个网站的界面；
  • 网站规定（并且会改变！）谁能访问的规则；
  • 网站可能窥探，把信息卖给广告商；
  • 网站的员工可能出于私人原因窥探；
  • 令人失望，因为那往往是用户自己的数据！

从设计的角度看：最大的接口划分在用户和"应用加数据"之间；应用和数据的整合对网站所有者很方便；但 HTML 作为接口是面向界面的，通常不擅长让用户控制和访问数据。

新的：去中心化应用

[user apps] -- [general-purpose cloud storage service] -- [naming/PKI]

这种架构把应用代码和用户数据分开：最大的接口划分在"用户加应用"和数据之间，所以"用户的数据"有更清楚的概念，由用户拥有和控制，就像你拥有笔记本或 Athena 账户里的数据一样。对存储系统的要求：在云上，任何设备都能访问；通用的，像文件系统；由拥有数据的用户付费和控制；用户之间可以共享（在权限范围内），以支持多用户应用；一个用户的应用之间可以共享（在权限范围内）；类似现有的 Amazon S3 这类服务。

意义何在？

  • 用户更容易换应用，因为数据不绑在应用（或网站）上；
  • 更容易有查看多种数据的应用：日历和邮件，或者备份，或者文件浏览器；
  • 隐私，防窥探（假设端到端加密）。

去中心化应用可以怎样工作：一个简单的例子

一个两个用户共享的待办清单：两个界面，带复选框的列表和"添加"按钮；两人都往里加要做的事；两人都能把一项标为完成。一个公共存储系统，U1 和 U2 各自拥有一些键值数据。用户在自己的计算机上运行应用，也许是浏览器里的 JavaScript；应用读另一个用户的公开数据，写自己用户的数据。应用没有任何关联的服务器，只使用存储系统。每个用户建一个放待办事项的文件和一个放"完成"标记的文件；每个用户的界面代码定期扫描另一个用户的待办文件。要点：服务是存储，独立于任何应用，所以用户可以换应用、自己写应用、加密以防窥探、删除待办清单、备份、和邮件应用整合等。

会出什么问题

去中心化很痛苦：

  • 每个用户一份类文件系统的存储，远不如专门的 SQL 数据库灵活；
  • 没有可信的服务器来做比如查看拍卖出价而不泄露出价这样的事；
  • 用密码学实现隐私和认证让其他一切都更难；
  • 对用户和程序员都别扭。

当前的网站架构工作得很好：容易编程；对软件和数据的中心控制让修改（和调试）很容易；有好的性能和可靠性方案；容易施加应用特定的安全措施；有成功的收入模式（广告）。

三、命名：Zooko 三角

为什么 Blockstack 专注于命名

  • 名字对应人类用户，比如 "robertmorris"；
  • 名字 → 用户数据（在 Gaia 里）的位置，这样多个用户能交互；
  • 名字 → 公钥，用于端到端的数据安全：我能检查我取回的确实是你的真实数据；我能加密我的数据，只有你能解密；因为存储系统不可信；
  • 缺少一个好的全球 PKI，已经让很多本来很好的安全想法受挫，所以 Blockstack 从命名开始。

Blockstack 声称命名很难，用"Zooko 三角"概括

  1. 唯一的（全局的），即每个名字对每个人意义相同；
  2. 人类可读的；
  3. 去中心化的。

声称：三者都有价值（可以争论……）；任何两个都容易，三个都要很难。每一对的例子：

  • 唯一 + 人类可读：电子邮件地址；
  • 唯一 + 去中心化：随机选择的公钥；
  • 人类可读 + 去中心化：我的联系人列表。

为什么三个都要很难？能给这三种方案中的任何一种加上缺少的那个性质吗？不能，似乎都立刻走进了死胡同。

Blockstack 怎样三者兼得

比特币产生一条有序的区块链；Blockstack 把声明名字的记录嵌进比特币区块；如果我声明 "rtm" 的记录在比特币链上是第一个，"rtm" 就归我。唯一（即全局相同）吗？人类可读吗？去中心化吗？（讲义留作问题：比特币保证所有人对区块顺序达成一致，所以第一个声明在全局唯一；名字是人自己选的字符串；没有中心权威。）

这种名字空间适合去中心化应用吗

唯一（即全局）有价值吗？

  • 有：我也许能记住我已经知道的名字；
  • 有：我能把一个名字给你，你能用它；
  • 有：我能看一份 ACL，猜出它的意思；
  • 没有：从全局池子里选出的人类可读名字不太可能很有意义，比如 robert_morris_1779，那是我吗，还是别人？"rtm@mit.edu" 呢？
  • 没有：我怎样找到你的 Blockstack 名字？我怎样验证一个 Blockstack 名字真的是你？

其他（可能不好的）想法：只用公钥，不要人类可读的名字，每个人各自保留一份写着自己能理解的名字的"联系人列表"，天然去中心化，不"唯一"，所以不需要比特币；一个能可靠地核实人类身份的中心实体。

四、Blockstack 的各个组件

  • 客户端：浏览器、应用、blockstack.js。
  • Blockstack Browser：本意是运行在客户端机器上。
  • 比特币的区块链。
  • Blockstack 服务器：读比特币链；解释 Blockstack 的命名记录，更新数据库；服务客户端的命名 RPC：名字 → 公钥 + zone 哈希。
  • Atlas 服务器：存储"zone 记录"。比特币里的名字记录映射到 Atlas 里的一条 zone 记录；zone 记录指出我的 Gaia 数据存在哪里；以内容哈希为键，所以条目不可变；可以把 Atlas 看作只是为了减小 Blockstack 在比特币交易里占用的大小；Atlas 在每台服务器上保存完整的数据库。
  • Gaia 服务器：每个（终端）用户一块单独的存储区域；键 → 值；后端是 Amazon S3、Dropbox 等，Gaia 让它们看起来都一样；大多数用户用 Blockstack 提供的 Gaia 存储；用户的个人资料（profile）包含用户的公钥、每个应用的公钥；用户可以有很多其他文件，放应用数据；应用可以对 Gaia 里的数据签名和/或加密。
  • S3、Dropbox 等：Gaia 的后端。

注册名字

怎样注册一个 Blockstack 名字？由用户（运行 Blockstack 软件）来做，用户必须拥有一些比特币。两笔比特币交易：预订（preorder）和注册（registration）。

  • 预订交易：把注册费付给一个"销毁"地址（burn address）；hash(名字)。
  • 注册交易：名字（不哈希）；所有者的公钥；hash(zonefile)。

Blockstack 的信息藏在交易里，比特币不看它，但比特币的签名和哈希覆盖了这些 Blockstack 信息。讲义留了几个问题：为什么要两笔交易？抢跑（front-running）：如果直接发带明文名字的注册交易，别人在它被打包之前看到这个名字，就可以抢先注册；先只公开名字的哈希，就没人知道你要哪个名字。为什么要注册费，毕竟没有真实成本？（FAQ：防止恶意者大量注册、占光所有有用的名字。）如果客户端试图注册一个已被占用的名字呢？如果两个客户端同时注册同一个名字呢？（比特币对交易排定唯一顺序，先上链的赢。）攻击者能改变一个名字到密钥的绑定吗，毕竟任何人都能提交任何比特币交易？Blockstack 自己能改变名字到密钥的绑定吗？

存储

讲义留的一组问题：

  • 客户端怎样知道去哪取数据？从拥有者的用户名和一个键开始（应用大概用周知的键，比如 "profile" 或 "todo-list"），经比特币/Blockstack、hash(zone)、Gaia 地址；
  • 客户端怎样检查从 Gaia 取回的是正确的数据？
  • 客户端怎样知道 Gaia 来的数据是新鲜的（最新版本）？拥有者写的时候签了名；别人从哪里得到拥有者的公钥来检查签名？（从 Blockstack 的名字 → 公钥映射。）
  • Gaia 怎样知道是否允许一个客户端写、改、删？
  • 为了隐私的加密怎么办？如果只有拥有者应该看到数据？如果除了拥有者还有另一个用户应该看到？如果只有 6.824 的学生应该看到？

私钥

  • 永远不离开用户的设备，所以除了你的设备和 Blockstack 的软件，你不必信任任何东西；你的每台设备都有一份你的主私钥。
  • "主"私钥只有 Blockstack Browser 能看到，太敏感了，不能让应用看到或使用它；用口令保护，用户活跃时以明文存在。
  • Blockstack Browser 发放每个应用的私钥，所以每个应用多少有各自独立的加密存储；这让同一个用户的不同应用很难合作，有时这就是你想要的，有时你确实想在自己的应用之间共享。

五、讨论

这里有一些可以琢磨的问题，关于命名，关于去中心化应用。可以把它们看作批评，也可以看作有待进一步发展的方向。

  • Blockstack 能用作电子邮件的 PKI，把 rtm@mit.edu 映射到我的公钥吗？Blockstack 名字和电子邮件地址比起来如何？一个 Blockstack 名字意味着什么？
  • 为什么 PKI 普遍很难？丢失的口令和密钥，怎样找回（母亲的娘家姓？短信？邮件？）；一个名字意味着什么，和"真实"身份有什么联系？怎样从"我想和谁说话"的直觉概念走到一个名字？有一些进展，比如 Keybase。FAQ：如果每个电子邮件地址都关联一个公钥呢？好主意，但从没有哪个方案获得多少采用。深层的问题是怎样在互联网这样大的开放系统里安全地找到别人的公钥；即使有一个完全可信的全球登记处，它也没有可靠的办法核实电子邮件地址或身份的所有权，不知道申请为 rtm@mit.edu 登记公钥的人是不是真的 rtm@mit.edu；登记处如果有腐败员工或被要求守法，还可能故意给你错误信息。去中心化的 PKI 在保证注册者就是本人这一点上更弱。即使在 MIT 的 Kerberos 这样有限的场景里也很难做到真正的安全：有人告诉 IS&T 说他就是你、丢了密码或私钥、需要恢复账户访问，他能接管你的账户吗？很可能能，这类故障一直在发生。Keybase、Signal 等现代通信系统会加密，但密钥发现仍是它们的弱点，FAQ 作者熟悉的里面 Keybase 做得最好。
  • 对命名和 PKI，去中心化有很大的价值吗？能不能有一个中心化但安全的命名系统？对一个全球规模的系统，我们都能信任谁？一个中心权威实际能提供什么价值？去中心化会让采用更容易吗？
  • Blockstack 能用证书透明那样的方案代替比特币吗？CT 不能解决冲突，只能揭示冲突；不同的 CT 日志可能顺序不同，所以 CT 说不出谁先来；是比特币的挖矿解决了分叉、强制达成一致。Blockstack 的收费对防止垃圾注册等似乎至关重要，而这依赖加密货币。总的来说，开放的区块链似乎只有和加密货币一起才有意义。FAQ：恶意者大概会往基于 CT 的个人命名系统里大量注册、占光所有有用的名字；CT 用于网站证书时，人们得先从 CA 买一张有效证书才能登记到 CT，但不清楚怎样为个人名字建类似的东西。FAQ 作者猜，没有加密货币的开放（公共）区块链，不能有足够强的分叉解决机制来支持 Blockstack 式的命名，因为它们不能收费、不能挖矿（甚至不能用权益证明，因为没有钱可以押上），但这只是猜测。
  • Blockstack 对程序员方便吗？所有代码都在客户端，没有特殊的服务器，所以很难有属于应用而不是属于某个用户的数据，比如索引、投票计数、Reddit 或 Hacker News 首页的排名；没有 SQL 查询；基于密码学的访问控制、组、撤销等；很难既查看其他用户的秘密又保守这些秘密，比如 eBay；也许只有用户热情很高时才值得。FAQ 展开了：存储接口限于键值，没有 SQL 那样强大的查询，查询还很慢（每次都要跨互联网）；安全必须用密码学实现，只给拥有者读的数据没问题，共享数据就很别扭，可以为每个允许的读者加密一次，或者用一个唯一密钥加密一次、再为每个允许的用户加密这个密钥，要支持大组（比如 EECS 的所有人）又复杂一层，尤其是控制组成员的人和拥有数据的人不同时，要撤销访问（比如有人离开 EECS）就更复杂；很多网站要用到用户不该看到的数据，比如在 eBay 上，我运行的软件要告诉我是否正在领先，这需要它知道别人的出价，但我不能被允许直接知道别人的出价，如果 eBay 的软件跑在我的电脑上（Blockstack 就是这样），我可以改它让它告诉我它知道的一切，真正的 eBay 把软件跑在自己的服务器上、把出价存在自己的数据库里，而 Blockstack 的要点正是拒绝这种安排；Blockstack 有一个专门做索引的方案，但它是中心化的。
  • 去中心化的、用户拥有的存储对用户隐私有好处吗？比信任 Facebook、Google 等网站保护数据隐私（防其他用户、黑客、它们自己的员工）更好吗？Blockstack 的存储提供商能看到你访问了什么吗？如果你电脑上的应用窥探你呢？毕竟写应用的大概还是 Facebook 之类。基于密码学的访问控制真的可行吗？你仍然得信任提供商保存你的数据，并提供最新版本；既然信任它到这个程度，为什么不信任它保密呢？FAQ：Blockstack 能改善安全的主要方式是数据在存储系统里是加密的，即使存储大概还是由今天的 web 存储你数据的那些公司运营（AWS、Azure、Google Cloud），它们也读不了，加密的数据也能抵御利用 bug 闯进存储服务的人。但有几个重要的前提：你仍然要运行别人写的应用软件；共享加密数据的技术目前相当别扭，管理密钥是难题；用户保管私钥的记录很糟，比特币钱包这类私钥系统里，用户经常丢失密钥、丢失存密钥的设备、运行偷密钥的恶意软件。
  • 去中心化的、用户拥有的存储对用户控制有好处吗？用户想经常为同样的数据换应用吗？想在多个应用里用同样的数据吗？考虑到不同应用的格式不同，这两件事一般行得通吗？
  • 用户愿意为自己的 Gaia 存储付费吗？

FAQ：去中心化会显著改变用户体验吗？按现状很可能让用户体验更糟。Blockstack 在隐私和用户控制上原则上有好的性质，但不清楚大多数用户有多在乎，他们大概不愿意为此牺牲多少功能或便利；至少目前，在 Blockstack 里开发功能复杂的应用比在传统的中心化网站里难得多。一致性哈希（consistency hash）是什么？Blockstack 自己的交易序列也可能分叉，比如不同的 Blockstack 节点运行不同版本的软件、接受交易的规则不同；不小心的话可能永远注意不到这种分叉，而它可能藏着恶意行为（攻击者也许能利用版本差异让一些节点看到某笔交易、另一些忽略它）。Blockstack 用一致性哈希保证任何这样的分叉都会被注意到：分叉之后，每个节点只关注同一个分叉上后来的交易，忽略其他分叉上的。在比特币之上做这件事很微妙，不能简单地在每笔交易里放上一笔交易的哈希，因为一个节点很可能并不知道所有最近的交易，所以 Blockstack 用了一种更松的方案，一种前序哈希的跳表，让节点能判断自己和别人看到的历史有多接近相同。

六、结论

讲义作者从 Blockstack 带走的东西：

  • 整体的去中心化愿景很有吸引力；
  • 整件事建立在一个 PKI 之上，这方面的任何进展都会很好，一个把所有用户映射到他们公钥的通用映射会很有用；
  • 令人惊讶的是能有去中心化的、人类可读的名字分配，但不清楚去中心化的人类可读名字是不是个好主意；
  • 把云上的数据和应用分开听起来是个好主意，但开发者会讨厌它（比如没有 SQL），不清楚用户会知道或在乎，不清楚用户愿不愿意为存储付费；
  • 为隐私做端到端加密听起来是个好主意，但私钥管理很麻烦、很脆弱，加密让共享和访问控制很别扭；
  • 你仍然得信任厂商的软件，它跑在你的笔记本上而不是厂商的服务器上，不清楚这算多大的胜利。

话虽如此，如果 Blockstack 或类似的东西能成功，那会很好。
