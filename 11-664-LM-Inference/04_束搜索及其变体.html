第四讲：束搜索及其变体

寻找众数的解码，贪心解码的三个毛病，束搜索与长度归一化，多样化束搜索，随机束搜索与 Gumbel-Max 技巧，束搜索的诅咒与似然陷阱，"如果束搜索是答案，问题是什么"，以及束搜索为什么不太用了

主讲：Amanda Bertsch · 2025 年 9 月 4 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容） · 主要阅读：Diverse Beam Search（Vijayakumar 等，2016）；Stochastic Beams and Where to Find Them（Kool 等，2019）

一、寻找众数的解码

上一讲的方法都是从某个分布（原分布或每步修改过的分布，比如 top-k 里 $k$ 个 token 每步都在变）里采样。这一讲换成优化的视角：给定输入（证据）和模型参数（先验），找单个最可能的输出，也就是输出分布的众数（mode）。这叫寻找众数的搜索，也叫 MAP 解码（最大后验）。

只生成一个 token 时很简单，对 logit 取 argmax 就完了。生成序列就复杂了。基线是贪心解码：每一步取最可能的 token。算起来很简单，但从一个 token 变成多个 token 时有几个问题：

  • 不保证找到真正的众数。前几个 token 也许还行，然后到了一个分岔点：两个 token 概率相近（比如 eats 和 sees），当前步概率稍高的那个后面没有高概率的续写（下一步最高只有 0.1），稍低的那个后面却有一个概率很高的续写。乘起来，贪心得到的序列概率明显低于另一条，而那一条甚至不一定是真正的众数。
  • 重复陷阱。GPT-3 那个时代的例子（来自与 GPT-3 合写的短篇小说 Ghosts）：开头说"把空间站变成飞船"，还算合理，然后开始绕圈子，"我在向前旅行，我在向后旅行，我在横着旅行"，再往后完全失控，陷入不断重复同样十几个 token 的循环。为什么？模型的训练数据里既有正常的文字，也有很多退化的东西，比如同一个字符反复出现、网站上抓下来的格式很糟的 XML。一旦进入有点重复的区域，就越来越接近它在预训练里学到的重复文本：出现过一次，后面有很多可能的续写；出现过两次，最可能的就是第三次，然后第四次、第五次。随机解码有机会采样到不一样的东西、跳出陷阱；总取 argmax 则不断强化重复。老模型、小模型用贪心时这很常见。
  • 把低概率的词往后推。比如想表达需要一个高概率词和一个低概率词才能说清的意思，"The dog was seen by Jane"不如"Jane saw the dog"流畅自然，但 Jane 这种实体名通常比 the、dog 概率低得多，贪心会一直选概率更高的词，直到句子里没地方了才不得不输出 Jane，于是得到有点别扭、颠倒的句子。

Graham 补充：这在用最大似然训练的基座模型里特别常见，指令模型里少一些，强化学习训练的模型更少，因为它若采样出重复的东西会得到低分，等于对重复有显式的偏置，所以可以靠训练修。但如第一讲说的，可以靠训练修，也可以靠推理修，如果你就要用一个容易这样的模型，只能靠推理。他还指出，重复不一定来自低质量文本，GitHub 上那么多 CSV 文件，就有大量合理的重复。Amanda 补充，Dolma 论文里有例子：Reddit 上一个获得大量点赞的帖子，就是字母 M 重复很多遍，来自一个模拟微波炉声音的版块。

学生问：如果训练数据里就有重复两次后接别的内容的序列，模型还会继续重复吗？Amanda 说如果在这个序列本身上训练，大概会记住"重复两次再接别的"这个结构；能否用这类数据一般性地教模型跳出重复，她不确定。另一个学生问重复越多，条件分布在重复 token 上是否越尖：她认为几乎总是如此，但没专门可视化过。新的模型会不会更少掉进去？会，因为有 RLHF 和指令微调，也因为训练得更好、数据更多、更大的模型本来就不太容易掉进去。用很拟人化、不严谨的说法，模型是"自己把自己说进了"空间的这个角落，在完全重复之前已经开始半重复，因为那是容易预测的下一个 token。

二、束搜索

既然贪心不是最好的办法，但仍想要接近众数的高概率输出，答案是束搜索（beam search）：不硬性地只认概率最高的那个 token，因为在一个概率较高但不是最高的 token 后面，可能藏着高概率的续写。所以保留几个选项，免得错过在之前某一步是第二、第三好的路径。它是一种广度优先搜索，每一步都扩展出多个选项，再剪回去免得不可控，然后生成下一步的候选。也可以看作 Viterbi 解码的近似：每一步都探索所有词表 token 就是精确探索，但解码超过一两步就不可行了。

1. 一步步走一遍

以"When my cat gets hungry"（幻灯片上配了一张猫的照片）为前缀，束宽 3。第一步取概率最高的三个：she、he、it。从每个再扩展出最可能的三个续写，得到九个选项，比如 she meows、it will，分数是一路乘起来的概率。剪回三个：这里碰巧两个来自第一条束、一个来自第二条，也可能三个来自三条不同的束，或者全来自最上面那条。再扩展成九个，再剪……

某一步选中的一个是句尾 token，于是"When my cat gets hungry, she meows"成了一个完整的候选，另外还有六个解码到一半的候选，共七个而不是九个，没关系，还是要剪回三个。但这七个放在一起打分有什么问题？学生答：句尾那个不公平。是占了便宜还是吃亏？占便宜。概率单调递减，第 4 步的东西平均概率远低于第 3 步的。

2. 长度归一化

为此要按长度归一化分数。实际看的是对数概率而不是概率（为什么用对数概率？学生答数值稳定：概率越来越接近 0，硬件不喜欢很接近 0 的小数）。最简单也常见的做法是用对数概率除以到目前为止的长度：句尾那条除以 3，其余除以 4。这样句尾那条仍然可能被剪掉，随着其他候选变长，它们可能更划算。持续到达到最大长度，或者前三条束都以句尾结尾，最后再按归一化分数重排，返回最高的。

其他归一化：未归一化的分数就是对数概率；除以长度；除以 $|Y|^\alpha$，$\alpha$ 是超参数，Hugging Face 叫 length penalty，设为 0 就是不归一化，设为 1 就是除以长度，也可以按先验设得更低或更高；也可以写成加性的奖励；机器翻译文献里还会定义相对于预期长度的奖励，比如知道你的分词器下 6 个 token 的英文句子通常对应 7 到 8 个 token 的法文，就可以约束输出长度接近预期，现在不常用了。

学生问：有没有一种归一化能让所有长度处在完全平等的地位？$\alpha$ 无论取多少都会偏向一边。Amanda 认为这是局部归一化的代价，要保证这一点，得有一个独立于模型概率的"真实概率"概念。Graham 补充：这就像机器翻译里那种方法，可以定义一个你预期的长度分布（英文 30 个词的句子，法文是 20 个词的概率多少、21 个多少……），把这个先验乘进语言模型的概率里，它不必是均匀的，可以是任何你定义的分布；但这要用户自己定义合理长度的先验。

3. 算法小结

  1. 设定束宽 $k$。
  2. 开始：取概率最高的 $k$ 个 token 作为初始的束。
  3. 扩展：对每条束取概率最高的 $k$ 个续写，得到 $k^2$ 个选项（有束以句尾结束时更少，它不再扩展）。
  4. 剪枝：按某个基于对数概率的打分函数（通常加长度归一化）剪回分数最高的 $k$ 个。

三、多样化束搜索

束搜索给出 $k$ 个输出，但它们常常很相似：开头是一个高概率的东西，沿着那条路的很多续写也都是高概率的。例子（Vijayakumar 等 2016）：束宽 6 给一张火车穿过树林的图片配说明，六条都是"一辆蒸汽火车在……行驶"的变体。让六个人写说明，大概会得到六个都合理又很不同的句子。答案不止一个时，希望得到几个都不错、彼此又有差别的输出。

改哪一步？改束宽没用，取开头最可能的 $k$ 个也挺合理，所以改第 3、4 步：改变"最高概率续写"的定义，加入多样性这个额外标准。多样性很难绝对地定义，让它可行的关键想法是：不追求每个输出都多样，只要求每组新输出与之前已经解码出的东西不同，迭代进行。

1. 分组

把束分成 $G$ 组，$B$ 是总束数。$G = 1$ 时就是普通束搜索。$G = 3$、$B = 3$ 的例子：第一组完全照常扩展；第二组扩展时，对与第一组本步结果太相似的词施加惩罚。第一组有 she meows、she starts，第二组原本会是 he meows、he starts，惩罚后它的前三变成了 he yells、he is；第三组再考虑前面所有六个，这里碰巧已经足够不同，不用改。

高效的关键：不必在每一步依次处理各组，只要在时间上错开。比如 $B = 6$、$G = 3$：第一组在第 6 步，它就是普通束搜索，不依赖别人；第二组在第 5 步，用第一组第 5 步的结果施加惩罚；第三组在第 4 步，第一、二组的第 4 步都已确定。原本 $T$ 步结束，现在需要 $T + G - 1$ 步。剪枝只在组内进行。等于在三种略有不同的设置下各做一次束搜索，概率按前面各组修改过。算法上每一步：第一组做一步普通束搜索；之后每组把对数概率加上来自之前各组的多样性惩罚，再做一步束搜索；全部到句尾后返回一组解。只要一个就取最高分，但用多样化束搜索通常是为了看全部输出。

  • $G = 1$：退化为束搜索。
  • $B = G$：每组一条束，相当于多样性感知的贪心搜索。他们发现这个效果很好，实际中把组数设成束数。
  • $1 < G < B$：组内束搜索，组间感知多样性。

学生问为什么不在组内也惩罚，毕竟开头的相似才是问题。因为想让组内同时解码；不过这个直觉正对应他们的发现：每组越小，输出越多样，所以实际中每组只有一条束。

2. 怎样定义多样性

  • Hamming 多样性：按一个 token 在（之前各组）活跃束里已出现的次数成比例地惩罚。在他们的设置里略好于其他，也是 Hugging Face 实现的那种。
  • 累积多样性：只惩罚在同一时间步用了相同的 token。Hamming 有点不公平：第一组在句首说了 the，第二组 20 个 token 之后说 the 也会被罚。
  • n 元多样性：惩罚任何精确匹配的 n 元组，既罚单个 token，也罚更长的序列，重复整段更长的字符串比重复一两个词罚得更重。Amanda 在白板上举例：第一组里有 the cat yells，第二组要生成的东西如果匹配这些前缀，匹配得越长，罚得越重。学生问第二组和第一组前缀相同是否可能：第一步不可能，开头取的 $k$ 个都不同；之后取决于惩罚强度，惩罚很小而 cat 又遥遥领先时仍可能选它。
  • 嵌入多样性：惩罚与之前各组 token 的 word2vec 嵌入太接近的 token，这有点暴露了论文的年代，相当于当年版本的语义相近惩罚。他们发现不值得额外的计算。这也说得通，多样化束搜索给出的是表面形式不同、语义上可能仍接近分布中心的输出。

四、随机束搜索

另一条路基于一个简单想法：想要多样性，我们知道怎么得到，就是采样而不是取 argmax。在束搜索里，把"扩展最好的 $k$ 个"换成"采样 $k$ 个"。问题是束搜索希望有 $k$ 个不同的东西，五条束都是同一个 token 没意义，即使它概率很高。所以要无放回地采 $k$ 个。

  • 迭代：从 $|V|$ 个 token 里采一个，把它移除并重新归一化，再从 $|V|-1$ 个里采……束宽为 $k$ 就要做 $k$ 次，每次扩展都如此，比 argmax 慢得多。学生问这和直接取 top-k 有什么不同：这里是按分布采样，不是取 argmax。
  • 拒绝采样：一次采一大批（比需要的多两三倍，批量采样便宜），去掉重复的。分布较平、尾巴较肥时还行；分布极尖时采一两百个可能只得到一两个不同的，计算量不确定，可能很贵。

1. Gumbel-Max 技巧

更好的办法要绕道去看 Amanda 认为现在最酷的数学小技巧之一。Emil Gumbel 是一位德国数学家，研究极值分布。典型例子是洪水：每场雨都能测到洪水线，但你还关心每年的最高水位，即某个分布在一段时间内的最大值。Gumbel 分布描述的就是这种最大值。概率密度为（$z = (x-\mu)/\beta$）：

$$f(x) = \frac{1}{\beta}e^{-(z + e^{-z})}$$

也叫双指数分布，因为有 $e$ 的 $e$ 次方。$\mu$ 是位置，$\beta$ 是尺度；只改 $\mu$ 时形状不变，只是沿横轴平移。学生问 $\mu$ 是均值吗：其实是众数，是峰顶的位置，不完全是均值；$\beta$ 越大分布越平、右尾越长，这里总设为 1。

关键性质：一组随机变量 $X_i$，各自服从位置为 $\mu_i$ 的 Gumbel 分布，那么任一个 $X_i$ 是其中最大值的概率为

$$P\big(X_i = \max_j X_j\big) = \frac{e^{\mu_i}}{\sum_j e^{\mu_j}}$$

这就是 softmax。推导留给第一次作业（只证两个变量的情形，可以再用归纳法推广），写出累积分布函数做积分，很多项会抵消，只有这个分布才能这样。所以从未归一化的 logit $z_i$ 采样有两种办法：对 logit 做 softmax 再采样；或者给每个 logit 加上独立抽取的标准 Gumbel 噪声 $g_i\sim\text{Gumbel}(0,1)$，取最大的那个：

$$\arg\max_i\,(z_i + g_i)\ \sim\ \text{softmax}(z)$$

加上位置为 0 的噪声，相当于得到一组位置为 $z_i$、尺度为 1 的 Gumbel 变量，于是上面的性质成立。Amanda 说"做完数学之前它像魔法"，Graham 说"我做完数学还是觉得像魔法"。

2. Gumbel-Top-k

这有什么用？用它找到最大的那个，把它移除，剩下的 $|V|-1$ 个 Gumbel 加噪 logit 里最大的，恰好是新分布的 softmax 样本。所以不取 top-1 而取 top-$k$，就得到 $k$ 个按 logit 参数化的分布无放回采样的样本，一次完成。

3. 剪枝时怎么打分

还没完。如果采到 $k$ 个之后只按对数概率打分剪枝，就前功尽弃了，只会留下原本概率最高的，还不如直接取 top-$k$。所以要把每一步的采样决定"带下去"，把加了 Gumbel 噪声的对数概率作为分数的一部分。但又要小心：分数要单调不增，而每步都在加噪声，可能加得太多，使第 $t+1$ 步的分数高于第 $t$ 步，这不合理，还会干扰长度归一化。办法是带着 Gumbel 修正后的对数概率，但把它截断，不超过父节点的值（算法里的第 14 步）。

学生问：这样截断不就改变了噪声的分布吗？是的，此时已不再是严格的 Gumbel-Max。但扩展时需要 Gumbel-Max，剪枝时不需要：扩展时对加噪 logit 取 top-$k$，得到的就是严格的样本；剪枝打分时才截断。可以设想另一种变体：扩展时用 Gumbel 技巧采样，剪枝时完全用不加噪的对数概率。这里是折中：不直接用加噪的分数（可能随时间升高），又不完全丢掉它们（那样就丢掉了采样的承诺）。学生理解为对采样结果做一次阈值截断，Amanda 说这样想挺好。

4. 结果

Kool 等人的图：横轴是输出多样性（用 n 元相似度衡量），纵轴是 BLEU（一个 n 元质量指标），虚线上方是一组输出里最好的、中间实线是平均、下方是最差的；绿色是束搜索，黄色是随机束搜索，红色是采样，蓝色是多样化束搜索（DBS）。每个点对应一种参数设置（比如温度、截断、多样性惩罚强度）。随机束搜索的输出更多样，但并不更差，这个性质很好：它比采样质量高得多，因为仍然按（修改过的）对数概率剪枝；又因为有采样，比束搜索更多样。平均表现更好，最好的那个也很好（束搜索的最好结果有时仍更高一点）。用随机或多样化束搜索时，关心的是得到几个都合理的输出，而不只是第一名。

学生问：同样质量下采样更多样，为什么不直接采样？要看需要：想要超过某个多样性水平，就得用随机束搜索，付出多样性与质量的权衡；但最好的那一个总是随机束搜索更高。Gumbel 技巧让随机束搜索能在和多样化束搜索差不多的时间内完成，否则只能迭代采样或拒绝采样；单用 Gumbel 技巧直接采样，就等于图上红色的采样，加上束搜索的扩展与剪枝框架，输出才更好。能否在随机束搜索里配合 top-p？可以，在用 Gumbel-top-k 之前先截断分布，但 top-p 要用 softmax 后的概率，Gumbel 要用未归一化的 logit，两样都得保留。温度呢？温度就是在 softmax 之前把 logit 乘一个系数，随机束搜索里就是在加 Gumbel 噪声之前乘。

五、束搜索的性质

1. 束宽与束搜索的诅咒

束宽小：解码更快；并行解码所有束时也更省内存；但搜索错误更多，更可能找不到真正的最高分输出，精确解码需要束宽等于词表大小。束宽大：慢些、更占内存，但更接近真正的最高分输出。而且下游表现更差。这特别反直觉，明明更接近众数了。这叫束搜索的诅咒：2018 到 2020 年前后在当时的各种模型和任务上，束宽增大时，束搜索返回的第一名在下游的表现反而下降（Yang 等 2018）。两种解释：

  • 长度归一化不完美：概率随长度单调递减，搜得越多，输出平均越短，对很多下游任务越来越短没好处。那篇论文表明，某些任务上把长度比或长度惩罚设对，就能消除这个下降。
  • 众数本身是退化的、不好的，我们并不想找到它。搜索错误在某种程度上编码了有益的归纳偏置。

两种说法都有证据。

2. 众数是我们想要的吗

分布底部显然有不想要的东西：概率很低的、换了语言的、无关的符号比如随机表情、很不可能的续写。但顶部的那些在质量和概率上都很接近。比较开放的生成里，语义相同的内容的概率可能分散在多种说法上：最可能的单个续写是"猫坐下了"，但"猫跑开了"的三种说法加起来概率多得多，也许其中之一才是更好的输出。一周半后会讲怎样找语义或特征空间上一致的输出。

更糟的是众数可能完全退化。很多尤其是较老的模型，费尽力气精确搜索整个词表，得到的众数是空字符串。以重复文本为条件时，之后的众数很可能又是一次重复，很难逃脱，而我们想要的也许是别的高概率输出。

3. 似然陷阱

Daphne Ippolito 读博时的论文（Zhang 等 2020）把模型对一些续写的对数概率与人对其质量的评分画在一起，提出似然陷阱：尤其在较老、没做 RLHF 或指令微调的模型里，分布最顶端、概率绝对最高的那些，反而不如仍然很可能的那些受人喜欢。这里说的仍是模型对数概率的前四分之一个百分位，但不完全在众数上。最受人喜欢的输出靠近众数，但不在众数。这是一种模型错误：如果模型完美地代表了我们想要的东西，人最喜欢的就该在众数。Amanda 没有 GPT-5 级别的同类图，但有理由猜测随着模型变好、用更接近人类偏好的目标训练，这个问题会减轻。不管怎样，这意味着束搜索越善于找众数，得到的东西可能越不讨人喜欢。

4. 束搜索的祝福

如果束搜索编码了某种有益的搜索错误，那是什么？If Beam Search is the Answer, What was the Question?（Meister 等 2020）设计了一个束搜索恰好在求解的精确目标，与诅咒相对称作束搜索的祝福。他们认为，较小束宽的束搜索更倾向于让局部信息密度均匀，信息密度均匀性定义为各 token 负对数似然的标准差（在信息论风格的工作里负对数似然也叫 surprisal）。束宽在一定范围内越小，负对数似然的标准差越低，各 token 的信息密度越均匀。他们认为这是束宽较小时无意中强加的一个好性质，和上一讲局部典型采样的思路相呼应。

六、束搜索怎么了

最近两年用模型或调 API，你大概都没在用束搜索，前沿模型基本不再用它。没有确切答案，Amanda 的几个猜测：

  • 模型更好了，贪心和简单的采样就能得到好输出，精心设计 token 级解码没那么关键；模型错误更少，似然陷阱不那么严重。
  • 维护多条束需要更多显存或更多时间，模型越大越麻烦。
  • 我们现在在不同尺度上做搜索，比如在句子或段落之上，接下来几周会讲，仍然是在搜索空间里优化，只是尺度不同。
  • 工业界和学术界也不同。vLLM 社区有个讨论串：开发者说没人用束搜索了，能不能删掉？然后几十个人跳出来说"绝对不行，我在工业界做的某件特定的事离不开它，你一改一切都完了，Spotify 就不能用了"，Spotify 真的是其中一个例子。很多更专门的场景里，它仍然是完全合理的方案。

八、小结

把解码当作找众数的优化问题时，贪心解码不保证找到最可能的序列，会掉进重复陷阱，还会把低概率的词往后推。束搜索每步保留 $k$ 个候选、扩展到 $k^2$ 再剪回 $k$，用长度归一化避免偏向短序列，是 MAP 解码的近似解。它的输出往往很相似：多样化束搜索把束分组、在时间上错开，每组对与前面各组相似的 token 施加惩罚（Hamming 多样性最实用）；随机束搜索用 Gumbel-Top-k 一次完成无放回采样，再把截断后的加噪分数带入剪枝，得到更多样又不差的输出。精确解不一定更好：束宽越大下游越差，原因可能是长度归一化不完美，也可能是众数本身退化（空字符串、重复、似然陷阱），小束宽的搜索错误反而带来了均匀信息密度这样的好偏置。如今前沿模型很少用束搜索，搜索转向了句子和段落的尺度，但不少工业场景还依赖它。
