第二讲：概率复习与生成基础

用一个二元模型复习条件概率、采样与温度，用采样估计算不出来的量，为什么只有温度 1 才无偏，边缘化与隐变量，GPT-2 上不同温度的输出，贪心解码为什么也不确定，用 LLM 作评委评估，以及最简单的元生成：用大模型重排序小模型的输出

主讲：Graham Neubig · 2025 年 8 月 28 日
资料来源：课程主页（本讲没有幻灯片，用 Jupyter 笔记本演示） · 课堂录像（本文依据录像字幕整理课堂口述内容） · 课堂代码

一、本讲安排

这一讲不用幻灯片，而是在笔记本里演示本课会用到的算法的最小例子，课程主页有代码链接，可以在 Colab 上跑（需要把库文件复制进去）。有些内容对部分人来说很基础，但 Graham 发现这些概念并没有他以为的那么普及，所以先让大家对齐。四部分：概率基础；一个很简单的 Transformer 实现；生成算法以及用语言模型作评委来评估；元生成算法，也就是从多个输出里挑最好的重排序算法。

二、概率基础

1. 条件概率与二元模型

自回归语言模型基于条件概率：给定前面所有 token，预测下一个 token 的概率，即 $P(Y\mid X)$，$X$ 是前面的 token。Graham 问：除了 Transformer 还学过哪些语言模型？有人说词嵌入。词嵌入是语言模型吗？先回到定义。学生答"给定之前的 token 预测下一个"，那是自回归语言模型的定义；"生成文本"、"生成 token 序列"也不是上周的定义。上周的定义是：给序列分配概率。自回归模型通过预测下一个 token 来给序列分配概率。

word2vec 其实是一个工具包，包含两种方法：根据周围的 token 预测中间的 token，或者根据中间的预测周围的，以此学习嵌入。它违背了从左到右的原则，所以不是自回归模型，非要把它变成给序列打概率的语言模型很费劲，它不是为此设计的。BERT 也类似，叫掩码语言模型，但很难让它给序列分配概率。学生又提到扩散模型、循环神经网络；学过老派 NLP 的知道 n 元模型（有人说 BM25，那更像一种加权方法）。

n 元模型根据前 $n-1$ 个词预测下一个词。笔记本里搭了一个假的二元模型（$n=2$），词表很小：句首、the、cat、dog、park、mat、sat、ran、walked、played、on、in、too、quickly、slowly、句尾，概率是 Claude 帮忙编的。给定句首，下一个可能是 the；给定 the，下一个是各种名词；给定 cat，可能是 sat、ran、walked、played。它满足自回归分解，还额外做了马尔可夫假设：只看前一个词，更早的都丢掉。课上问有谁在课上实现过 n 元模型，只有很少人举手，Graham 感慨这在五年前还是标配。这里用它只因为算得快、便于演示。

2. 采样与温度

从语言模型采样是最简单的推理算法，也是很特殊的一个。从开始 token 出发，用条件概率采样下一个词，更新上下文，重复，直到遇到结束 token 或最大长度。所有自回归模型都这样做，Transformer 的区别只在"更新上下文"一步要跑过很多层、把表示加进 KV 缓存等。最大长度很重要，否则用神经模型时可能无限生成下去、耗尽内存。

温度采样是常用方法，想法是让分布更尖或更平，以得到更多高概率或低概率的输出：

$$P_T(i) = \frac{\exp\big(\log P(i)/T\big)}{\sum_j\exp\big(\log P(j)/T\big)}$$

$T = 1$ 时，什么都没变：分母是概率之和 1，指数和对数抵消，就是原分布。$T\to\infty$ 时，所有值都变成 1，得到均匀分布（在无穷处可能无定义，说的是极限）。$T\to 0$ 时，最大的那个 token 相对其他 token 变得无穷大，得到独热向量，总是选最可能的 token（如果有几个 token 概率完全相同，则在它们之间均匀分布）。实现上就是对数概率除以温度再做 softmax（取指数再归一化），然后从调整后的分布采样，接到序列后面。

二元模型采样出"the dog played"、"the cat played quickly"、"the dog played in the park walked"。最后一句像花园小径句：读到最后一个词之前都说得通，最后一个词让整句不通。我们用大 Transformer 而不是二元模型，就是因为二元模型是很差的语言模型，会产生很多不自然的东西。

3. 用采样估计量

已知条件概率 $P(y\mid x)$，想知道两个词相邻出现的联合概率（随便看两个相邻的词，前一个是 $x$、后一个是 $y$ 的概率）。学生想用"两个词不同时出现的概率"来求，但总的来说，从条件概率解析地求出联合概率也许可行，但很难；对 Transformer 更是不可能。办法是采样：用模型生成大量句子，数相邻词对的出现次数，除以词对总数，就估计出了联合概率。

这很有用。比如想知道一个基于 Transformer 的模型在某个提示下有多大比例生成有害内容，没有解析解可以算，但可以采样一百万个输出，看其中有害的比例，得到期望值。

同样可以从采样序列估计条件概率：数二元组次数，除以前一个词的次数。因为这里知道真实的条件概率，就能检验估计是否准确。看 cat|the、sat|cat、the|on、on|sat 几个：只采样 100 个时，有的碰巧估得很准（真实值 0.5，正好估出 0.5），但很多估成了 0，比如 sat 后面接 on 的概率；采样数增加到 500、1000、5000、10000，估计逐渐收敛到真实值，整体误差随采样数下降。采样越多，估计越好。

学生问这和温度有没有关系。有，温度改变了概率。温度 1 是很特殊的温度，是唯一能看到真实分布的温度：把条件概率连乘得到序列的联合分布，只有按温度 1 采样，才是对这个联合分布的无偏采样。实验验证：温度 1 时误差一路下降；用有偏的温度采样，误差会停在某个水平，得不到正确估计；温度为 0（贪心）偏差更大（Graham 的代码没处理好温度 0 的情况）。这很重要，因为几乎没人用温度 1 采样，有些模型强制使用温度 1，比如 OpenAI 的 o1 推理模型不允许设别的温度，但很多模型出于各种原因（后面会讲）用别的温度。除非温度是 1，否则得到的就不是模型真正的语言分布，而是一个有偏的分布。

为什么要做推理？一种目的是得到好的输出，那么用任何能给出最好输出的推理算法都行；另一种目的是理解语言模型本身的性质，那么温度 1 采样是得到模型真实分布的唯一办法。课上又问这对模型训练为什么重要，有学生答出了要点：要匹配互联网上文本的真实分布，原则上要采无穷多的文本才能得到无偏样本（"无偏"在这里也取决于你下载了哪些网站）；反过来，只在小样本上训练，就无法很好地估计全部文本的样子，有过拟合风险。归根结底都是这个道理。

4. 边缘化

边缘化就是对变量求和，比如对 $y$ 求和得到 $x$ 的概率：

$$P(x) = \sum_y P(x, y)$$

为什么叫"边缘"？学生答对了：在联合概率表里，把每行或每列的和写在表格的边缘。在 PyTorch 里就是一次对某个维度的求和。用前面从采样估计的联合概率边缘化，得到"当前词"的边缘概率：句首符号最高；句首永远不可能是下一个词，所以它作为"下一个词"的概率为 0。所有这些都无需解析计算，靠采样就得到了。（课上把采样数调大想看误差降到 0，因为 Python 循环实现很慢，没有降得像预期那么快，Graham 有点担心代码有 bug，说回去检查，理论上无偏采样的误差应该趋于 0。）

5. 隐变量

隐变量是隐藏结构，不是输入，也不是关心的输出，但会影响最终输出，所以想把它纳入模型。它必须是概率变量，不是隐藏的嵌入。如今语言模型里最常见的隐变量是推理：推理模型在给出最终答案前生成很长的思维链，希望它能提高答案质量。$X$ 是输入提示，$Z$ 是推理轨迹，$Y$ 是最终答案。模型先生成思维链再生成答案，计算的是两者的联合概率；如果不关心思维链，可以采样很多条，对它们求和（边缘化），得到 $P(Y\mid X)$ 的估计：

$$P(Y\mid X) = \sum_Z P(Y, Z\mid X)$$

这就是被广泛使用的自洽性方法，之后要讲的最小贝叶斯风险也与之相似。加入推理让 $Y$ 的概率更准，所以这样估计效果更好。在二元模型的例子里，可以把第一个词当 $X$、最后一个词当 $Y$，中间所有词就是隐变量，这和思维链差不多。

学生问有没有人用大于 1 的温度。Graham 几乎没见过，一般 1 就是上限，下一部分会看到原因。

三、一个简单的 Transformer

假定大家都上过 NLP 或深度学习课，所以不细讲。这个实现的好处是很简单：Hugging Face transformers 里 GPT-2 的实现约两千行，这个只有几百行，基本就是 GPT-2。规模：GPT-2 small 有 12 层、12 个头、嵌入维度 768（词表约五万）；medium 有 24 层、16 个头、维度 1024；large 有 36 层、20 个头、维度 1280。除了层数，大部分维度比如今常用的模型小约十倍。

四、生成与评估

1. 不同温度下的 GPT-2

温度取 0（贪心，确定性的）、0.5（较保守，集中在高概率的输出）、1（唯一的"真"采样）、1.5（更有创意、更多样）。提示是"人工智能的未来是"，每个温度生成三次。用 Mac 的话推荐用 Apple Silicon 的加速（MPS），快很多。

  • 贪心：三次都一样，"人工智能的未来是不确定的。'我们不确定未来会是什么样，'Michael S. Schweinfeld 博士说。"不知道是不是真有此人，贪心解码大概不会太有创意。
  • 0.5："如果你是软件开发者、正在寻找创建和部署应用的新方法，那它是个问题"；"清楚的，世界的未来是光明的。未来是光明的。未来是光明的"；"很光明，很像计算机的未来，我不确定'智能'这个词"。
  • 1："基本悬而未决，许多人热切期待……"夹杂着奇怪的人名和地名；"清楚的，Facebook 刚刚跳出来"；"会很有意思，它会改变我们思考和对待人的方式"。
  • 1.5："人工智能的未来横跨联盟、盟友和设计者帮派之间的冲突……"完全跑偏。这大概回答了为什么不用大于 1 的温度。

2. 贪心解码为什么也不确定

贪心解码总能得到同样的结果吗？不能。用温度 0 调用 GPT-4 或 Claude，可能得到不同结果。有学生说因为还是在按概率采样，但温度 0 时选的就是 argmax。另一位学生说对了：浮点误差会传播。这很棘手，和模型运行的硬件有关。GPU 有大量线程同时运行，做求和有两种方式：一种是按线程编号依次相加，但要加大量的锁，而有的线程会因为 GPU 温度之类的原因略快一点，加锁严重损害效率，所以理论上可以开启 GPU 的确定性模式，实际上部署服务的人都不这样做；另一种是谁先算完谁先加，第 7 号线程先完成就先加，然后是 2 号、1 号、3 号，每次相加的顺序都不同，看起来像随机。浮点数按不同顺序相加，舍入会不同，于是产生极小的差异。但在选词表项时有 argmax，生成 1000 个 token 里只要有一次最大项变了，之后的一切都会改变。所以用 Claude 时可能五次都一样，第六次不一样。

两件事让它更严重：混合专家模型，除了在 token 上取 argmax，还要在专家上取 argmax，argmax 多了很多；Agent，比如编程 Agent 要做大量预测。Graham 他们想用 Claude 复现编程 Agent 的结果时，即使在同一个实例上用贪心也从来得不到同样的结果。

学生问：既然有这种硬件带来的随机性，设成 0 的温度实际上相当于多少，比如 0.01？Graham 说这是个好主意，不知道答案。用多块 GPU 会加剧吗？取决于在哪里聚合，一块 GPU 和另一块之间的差异大概比一块 GPU 内线程之间的差异更大，所以会。量化会让问题更严重吗？会，舍入误差更多。能否借此推断 OpenAI 用了什么量化？好主意，Graham 说如果有人能证明出来，期末项目给 A+，不过标准会很高。

3. 评估：确定性指标与 LLM 作评委

凭肉眼定性分析不能总这样做，Graham 自己就没法很好地判断中文输出，也看不了成千上万个例子。第一种办法是能直接从文本计算的确定性指标。这里用多样性：单个输出内的多样性，是不同词数与总词数之比；跨生成的多样性，看两个输出之间词或二元组的重合，重合越少越多样。也可以测长度等。

另一种流行的办法是用语言模型作评委，好处是只要问语言模型一个关于输出的问题，就能很容易地做很强的事。例子：让 Claude "给这段文字的流畅度和连贯性打 0 到 10 分，10 分为完美，只回答一个数字"。（课程会给每人约 50 美元的 API 额度，以及 AWS 额度；为简单起见这里没有并行调用，实际应该并行。）结果：贪心解码的流畅度 5.3 分，还不错，但多样性很低，三次都一样；温度越高多样性越高，流畅度越低。这是很常见的问题，样本越多样，质量越低，温度采样尤其如此。下一讲会讲很多在多样性和质量上帕累托更优的方法。

对 LLM 评委的提醒：不要盲目相信。语言模型在很多事上是很差的评委，尤其是它自己都不擅长的事，不擅长解数学题的模型通常也不擅长评判数学题。还有人报告评委偏爱自己的生成，Claude 喜欢 Claude，GPT 喜欢 GPT，不是总成立，但有时成立。

五、元生成：重排序

本课的一大主题，最简单的元生成算法就是重排序：用 GPT-2 small 生成，用更大更强的 GPT-2 medium 计算输出的概率来重排序。

等待运行时，Graham 问：用小模型生成、再用大模型计算输出概率，这种常用的推理方法叫什么？学生答推测解码（speculative decoding）。这里做的不完全是它。推测解码通常用小模型生成 5 到 10 个 token，再用大模型一次检查，直到小模型出错的位置为止；之所以快，是因为 GPU 上成批计算 token 快得多。后面会讲。

输出例子："人工智能的未来光明而充满希望"、"人工智能的未来是香蕉紫色大象"、"人工智能将改变许多行业"。这次小模型给的概率总是比大模型低，不算有趣。更有意思的是看各个模型偏好哪些输出。因为是从小模型生成的，小模型偏好大多数输出很正常，有意思的是中等模型更偏好的那些。这里用的是每个 token 的平均对数概率，而不是整个序列的对数概率：上一讲看到越长的输出对数概率绝对值越大，按长度归一化，长短不同的输出才能放在同一基础上比较，也能避免"中等模型比小模型更偏好多少"受长度影响。

中等模型最偏好的几个："人工智能的未来正以很有趣的方式成形，下一期我们将探讨机器学习能否完成复杂任务"；"人工智能的未来重新回到技术前沿……"；"人工智能的未来岌岌可危，他警告说，临界点是否即将到来？但冠军高尔夫能否实现美国梦？"（Graham 说有点想读这篇文章）。有学生觉得句子更简单。Graham 的看法是它们用词更出人意料，同时大体仍然流畅。他对更强（通常也是更大）的模型的总体印象是：它们更可能生成有意思、有点出人意料但又不太离谱的句子。他比较过 DeepSeek 和 GPT-5 写文章：DeepSeek 总能写出很好的文章，但有点泛泛、无聊；GPT-5 写的确实有点意思，这是如今最强模型的差别所在。GPT-2 这种弱模型达不到那个水平，但原理相同，强模型更会建模低频词这类低频现象。

学生问元生成在下游的目的是什么：提升整体质量。比如有一个很强但无法高效用来生成的重排序器，比如一个去核实信息的 Agent，你不想在生成时运行它，但愿意用它确认文本里没有幻觉，在五个候选上跑一遍。自洽性也是一种元生成：生成多个输出再做多数投票。另一个学生问 DeepSeek 和 GPT-5 的差别在训练还是推理：两者都是推理模型、都让它们推理了，所以大概在训练，不过 GPT-5 具体怎么做不完全清楚。

七、小结

语言模型给序列分配概率，自回归模型通过条件概率逐个预测 token，word2vec 和 BERT 不是这样设计的。采样从起始 token 开始反复按条件概率取下一个 token；温度把对数概率除以 $T$ 再做 softmax，$T\to 0$ 是贪心，$T\to\infty$ 是均匀分布，只有 $T = 1$ 是对模型真实分布的无偏采样。很多算不出来的量（联合概率、有害输出的比例）可以靠采样估计，样本越多越准，但只有温度 1 时才收敛到真值。边缘化是对变量求和，把思维链当隐变量边缘化掉就是自洽性的思路。GPT-2 上温度越高越多样、越不流畅，温度超过 1 会跑偏；温度 0 的贪心在 GPU 上也不确定，因为浮点加法的顺序会变，混合专家和 Agent 会放大这种差异。评估可以用多样性这类确定性指标，也可以让 LLM 作评委，但评委有偏好，不能盲信。最简单的元生成是用大模型的长度归一化对数概率重排序小模型的输出，强模型偏好用词出人意料又仍然流畅的句子。
