第一讲：语言模型与推理导论

语言模型的定义与采样示例，Transformer 每层的计算量从哪来，推理用的硬件，训练与推理的根本差别，生成算法、元生成与隐变量，搜索错误与模型错误，多样性与质量，以及课程安排

主讲：Graham Neubig · 2025 年 8 月 26 日
资料来源：课程主页（本讲的 HTML 幻灯片未能获取） · 课堂录像（本文依据录像字幕整理课堂口述内容） · 课堂代码 · 主要阅读：From Decoding to Meta-Generation（Welleck 等，2024）第 1、2 节

一、这门课讲什么

这是一门新开的课，讲的是研究中发展很快的前沿话题，所以 Graham 很希望听到大家想多听或少听什么。我们天天在用语言模型：ChatGPT、Google 搜索、Copilot 和 Cursor 做代码补全，Codex、Jules、OpenHands 这样的编程 Agent，还有各行各业的专门应用，比如法律领域的 Harvey、医疗领域的 Abridge。这门课默认大家上过 NLP 或深度学习课，第一讲主要是统一记号和术语。

二、语言模型

语言模型给 token 序列分配概率，可能以图像等其他东西为条件，但本课主要关心输出是自然语言或代码这样的 token 序列。对序列 $X = x_1, x_2, \dots, x_L$，最常用的是自回归模型：

$$P(X) = \prod_{i=1}^{L} P(x_i\mid x_1, \dots, x_{i-1})$$

也就是第一个 token 的概率，乘以给定第一个 token 时第二个的概率，依此类推。主要的反例是扩散模型，它的推理算法完全不同，只占一讲；没有特别说明时，都指自回归模型。

1. 无条件采样

Graham 用一个较小的模型 Qwen3-1.7B 的基座版本，从句首开始采样了 100 个序列（Qwen 没有句首 token，就从句尾 token 开始，效果差不多）。推理时要决定何时停止，这里遇到句号或换行就停。按概率分成高、中、低三组：

  • 高概率："3."、"4."、"0)" 加换行这类，对数概率约 −4.22，采样足够多次会得到很多这样的结果。有学生猜"乐意为您效劳"，但这是基座模型，没有做过指令微调。
  • 中等概率：大量代码和数学，可能有些运气成分。
  • 低概率（在 100 个样本里最低，其实仍算高概率）：大多是中文。有学生说是"政治中文"，大概能猜到 Qwen 在什么数据上训练的。

2. 条件生成

实际使用时我们要做有用的事，通常是以前面的序列为条件生成后面的序列。把输入记为 $X$，输出记为 $Y$，前者叫前缀或查询，后者叫补全或回答。数学上就是在自回归分解里省掉前面那些 token：

$$P(Y\mid X) = \prod_{j=1}^{|Y|} P(y_j\mid X, y_1, \dots, y_{j-1})$$

前缀用"卡内基梅隆大学最好的地方是"。学生猜"计算机科学"（Graham 说这句子有点怪）、"教授们"（谢谢恭维）。实际采样：高概率的有"它的多样性"、"它是一个社区"（这算是有点敷衍的夸奖）；中等概率的长一些，比如"它的位置和它建立的充满活力的社区"；低概率的更长，比如"它注重跨学科，学生主修计算机科学、数学和工程"，计算机科学总算出现了。

除了内容，还注意到什么？长度：越短的概率越高。学生解释：乘上一个小于 1 的数，结果总是更小。概率都小于 1，乘的次数越多，乘积越小。

三、模型的计算成本

大家应该都学过甚至实现过 Transformer。现在的大模型是仅解码器结构：嵌入、位置编码、带掩码的多头注意力（不看未来的 token）、层归一化、前馈网络、再层归一化，最后线性层做预测。还有混合专家、RNN、Mamba 这类状态空间模型，后面的课会讲。推理时很关键的是建模成本，主要来自两部分：自注意力，有一部分随序列长度平方增长；前馈层，又宽又重。再乘以层数 $N$，大模型的层数可能很多。

课堂小测：在现代大模型里，自注意力和前馈网络哪个更贵？有人选前馈，然后 Graham 说这是个陷阱题，取决于上下文长度。

1. 每层的浮点运算量

以如今广泛使用的分组查询注意力（GQA）Transformer 为例。普通的多头注意力把隐藏向量切成若干头，每个头的查询与键相乘，用来给值加权；GQA 让多个查询头共享同一组键和值，以节省内存。设序列长度 $L$，隐藏维度 $d$，每头维度 $d_h$，查询头数 $n_h$，键值头数 $n_{kv}$，前馈维度 $d_{ff}$。所有项都乘 2，因为矩阵乘法里每个乘法都伴随一次加法：

  • 查询投影：$2Ld\cdot n_hd_h$，每个头都要算。
  • 键、值投影：各 $2Ld\cdot n_{kv}d_h$，因为分组共享，比查询少。
  • 注意力计算：$QK^\top$ 和乘 $V$ 合计约 $4L^2n_hd_h$，每个位置的查询都要和所有键相乘，这是平方项。
  • 输出投影：$2L\cdot n_hd_h\cdot d$。
  • 前馈网络（SwiGLU 有门控、上投影、下投影三个矩阵）：$3\times 2Ld\,d_{ff}$，完全线性于序列长度。

所以注意力可以拆成随长度平方增长的部分和线性部分，前馈完全是线性的。

2. 以 LLaMA 3.1 为例

选 LLaMA 3.1 系列是因为它有一个很大的稠密模型 405B，这种架构也被很多其他模型采用。三个模型分别有 32、80、126 层，隐藏维度约 4000、8000、16000，注意力头数大致成比例，GQA 的键值头都是 8 个，MLP 维度约是隐藏维度的 3.5 倍，最大上下文长度 128k。

画出各部分计算量随上下文长度的变化：总计算量按大 O 看随上下文平方增长。上下文较短时（1000 也不算很短），绿色的 MLP 部分占主导，因为它比其他部分大 3.5 倍；注意力的线性投影也花很多，真正把注意力向量相乘反而不多。上下文长了，注意力的平方部分开始占主导，想把注意力扩展到很长的长度就成了问题。对推理来说，这意味着很贵，而且长上下文会成为限制。这还只是理想情况，只算浮点运算，不考虑处理器能否高效用满这些算力。

学生问为什么是 3.5 倍。一是人们做过实验，这在计算与准确率之间权衡得不错；它应该比隐藏维度大，这样才能学到组合特征。二是隐藏维度往往是 2 的幂，而 3.5 倍不是，但实际计算 GPU 利用率时，按线程划分这样的大小反而利于利用率。Graham 说要回去查一下确切的理由。

四、硬件

这门课的另一大主题是怎样让推理高效，这需要了解硬件。

  • CPU：通用计算，但线程并行度不高，不太适合神经网络所需的运算，大模型很少用，小模型还会用。
  • NVIDIA GPU：大家都在用的黄金标准。AMD 等的 GPU 硬件很好，但软件生态支持不如 NVIDIA，用的人没那么多。服务器级的有 A100、H100、B200，有钱就租或买；也有便宜一些的游戏卡，仍然比 CPU 强得多。
  • 专用硬件：Google TPU 可能是第二常用的，Google 自己大量使用，Google Cloud 上也能租到。GPU 起初是为游戏做的，现在可以说是专门为训练 AI 模型做的，因为 NVIDIA 的钱都从这来；TPU 则从一开始就为此设计，内存大、互联快。还有 Cerebras、Groq 等。

课程的 GPU 资源：已有算力（比如 LTI 的 Babel 集群）可以直接用；课程会申请 AWS 额度，但从申请到发放很久，最好有备选；Google Colab Pro 每月 9.99 美元，学生可能免费。工业场景里，Graham 用过 Modal 和 RunPod，适合快速拉起一批 GPU 或无服务器 GPU；作业里要搭一个推理服务器，真部署的话他会用无服务器端点。训练则有 San Francisco Compute Company、Prime Intellect 这类 GPU 市场，Prime Intellect 甚至有像股票行情一样的 H100 价格走势。

五、训练与推理的差别

这是讲推理的课，作业都不需要训练，但要讲清楚两者最重要的差别。训练通常先在海量文本（几乎整个互联网）上预训练，再在指令数据上后训练或微调，最近还有大量强化学习。目标是用最大似然估计学习参数，让模型分布逼近真实分布，最大化数据的对数似然；做前向、反向计算梯度，按学习率更新参数；实际中用 GPU 对大批文本做张量运算。

训练时，所有 token 事先都知道，嵌入层之后，一大块一大块地逐层算过去，最后预测并把损失加起来，整个数据只需每层走一遍。顺利的话，训练可以把 GPU 完全占满，浮点利用率很高。

推理时给定提示 $X$，要生成续写。两大做法：采样，从模型的分布里随机抽；搜索，找使某个分数最大的输出，这个分数不一定是概率，很多情况下不是。推理时块变小了：前缀的三个 token 走一遍，然后生成一个、再走一遍，一个、再一遍……自回归地走到句尾符号。学生说出了关键：训练时 token 全都已知，每层只需走一步；这里前缀 3 个 token 加生成 3 个，每层要走 4 步。每一步都有固定开销，要向 GPU 派发任务、等 GPU 算完；而且 GPU 有大量线程，每步可能用不满。怎样克服这个挑战，是本课很大一部分内容。

学生问：生成新词时不需要更新前面词的嵌入吗？不需要，因为用了掩码注意力，计算前面位置的表示时把后面的输入都屏蔽了，位置 3 不能依赖位置 4 的词。这很重要：自回归分解里生成每个 token 只以之前的 token 为条件，否则链式法则不成立，也没法这样计算，实践上更新所有之前的 token 也很麻烦。例外是扩散模型，它不完全是从左到右生成。另一个学生问这是否和马尔可夫假设有关：马尔可夫假设是认为很久以前的 token 无关，Transformer 通常并不这样假设。

六、本课的几类算法

1. 生成算法

课程分三部分，第一部分是基本的生成算法（也叫推理算法）：自回归模型里通常一次生成一个 token，或者像束搜索那样一次一个 token 同时维护多个假设。最简化的形式：生成函数接收模型和作为前缀的 token 列表，在没生成完之前，用模型算概率，从中按某种方式取一个 token 接到 $Y$ 后面。实际中为了效率不会这样往列表里追加，但思想如此。从第三讲开始讲各种变体。

2. 元生成

元生成（meta-generation）是 Graham 他们在课程参考的综述里提出的术语，不算很标准，指的是把生成 token 序列当作子程序的一类算法。最常见的例子是重排序：给定生成模型、重排序模型、候选数 $N$ 和前缀，生成 $N$ 个候选，用重排序器打分，返回分最高的。学生问是不是要等到句尾 token 才重排序：这里没有定义"完成"，可以是遇到句尾 token，也可以像前面采样时那样遇到句号或换行，甚至可以每生成五个 token 就重排序一次。

3. 隐变量

最近很受关注，比如 o1、R1 这类推理模型。有时我们要建模的不只是展示给用户的答案，最常见的是思维链。比如输入"Transformer 论文发表多少年了"，隐变量是"现在是 2025 年，论文 2017 年发表，2025 − 2017 = 8"，输出是"Transformer 论文发表已经 8 年了"。这被证明能显著提高准确率，最近人们还专门训练模型这样做。隐变量给推理带来两个问题：

  • 效率：课上问谁让模型想过五分钟以上、十分钟以上，都有人举手。很厉害，但这是效率问题，你希望尽快拿到答案。
  • 很多时候并不关心隐变量本身，只想要答案，GPT-5 就不展示完整的思考过程。既然不给用户看，就可以考虑多条思维链，找出在多种推导方式下最好的输出，比如用十种方法解一道数学题，选出现最多的答案，这叫自洽性（self-consistency）。

4. 评估

大多数时候我们要的不是高概率的输出，而是某种意义上好的输出，两者不一定一致。"好"可以是人类偏好，可以让大模型像人一样打分（LLM 作评委），可以是确定性的指标（数学题只有一个答案就直接比对；BLEU、ROUGE 这类文本指标现在少用了）。强化学习的人会称之为奖励，Graham 会把评估指标和奖励混用。

七、搜索错误与模型错误

做推理的人都应该知道、但不是人人都知道的重要概念。设模型给输出的打分为 $S_\theta(Y)$（概率模型就是概率），奖励或评估指标为 $R(Y)$，算法找到的输出为 $\hat Y$。

  • 搜索错误：搜索算法没找到模型分数最高的输出，即存在 $Y'$ 使 $S_\theta(Y') > S_\theta(\hat Y)$。分数可以是最高概率，也可以是在思维链上边缘化后最一致、边缘概率最高的输出。如果问题是搜索错误，可以用更好的推理算法缓解，比如从贪心换成束搜索，从束搜索换成 A* 等。
  • 模型错误：模型打分最高的输出 $\hat Y = \arg\max_Y S_\theta(Y)$ 按你关心的评估指标并不好，即存在 $Y'$ 使 $R(Y') > R(\hat Y)$。模型把高分给了差的输出。（Graham 在课上发现自己幻灯片里这条的写法不对，当场改正，说第一次开课，欢迎大家帮忙找错。）

区分它们很重要。模型错误"正确"的解法大概是把模型训练得更好，或者换一个更好的打分函数、决策准则、重排序方法。Graham 说以前观点更强硬时，他会说这不该靠推理来修；但见过足够多的人通过推理成功修好，现在也认为可以。只是要明白，通过推理修模型错误，意味着故意不去找分数最高的输出，以得到更好的输出，相当于"弄坏"推理算法。调推理算法提分数时要记着这一点，讲束搜索与采样时还会再谈。

学生问：推理的目标是采样还是优化，想要多个样本还是众数？Graham 说两种都被叫作推理，统计学背景的人可能有更严格的定义。学生又问，如果是采样，第一种就算不上搜索错误。这部分讨论确实针对"想得到好输出"的情形。人们现在用采样来得到好输出，很大程度上是因为模型有缺陷。最好的模型做代码生成、数学推理时，人们反而更多用搜索，常常就是贪心，它不算好的搜索算法，但更可能得到高概率序列，因为模型训练已经修掉了很多问题。以前贪心是坏主意，会不停重复，下一讲在 GPT-2 上就能看到贪心完全崩坏。

学生问搜索错误和模型错误的多少是否取决于怎样定义"好"。模型错误是，搜索错误不是，它的定义里只有模型分数。怎样判断存在搜索错误？换更好的搜索算法看能否找到更好的假设，比如扩大束宽，找不到不能证明当前最优，但算是证据；A* 能证明找到了最优，但在神经网络上不可行。模型错误则只要生成很多假设，找到一个满足条件的就证明存在。

八、多样性与质量

argmax 搜索多样性低，只取最好的一个就没有多样性（除了 GPU 数值不稳定带来的微小差异）；N-best 搜索的前 $N$ 个常常只差一个 token。采样多样性高，但有时质量较低，尤其模型不错、模型错误少时，精确搜索通常给出最好的结果。两者各有用处。什么时候需要多样性？学生说创意写作。Graham 说如果有一个评估创意的好指标并优化它，也许每个提示只需一个输出；但如果要给作家看十个不同的输出让他挑，就需要多样性。还有学生说合成数据集，要模仿真实数据分布；以及强化学习，要采样足够多样的输出来代表真实的变化范围。

回顾：我们希望输出的评估分数高；可能希望低延迟，提示输入后很快得到输出；作为 OpenAI、Anthropic 这样的模型提供方，要高吞吐，同时服务数百万请求；为了模型训练或给不同用户不同输出，可能要高多样性。优先级取决于应用。

九、课程安排

  • 第一部分，生成：概率复习（下一讲主要用 Jupyter 笔记本，快速示范概率基础、Transformer 的简单实现、生成算法、元生成和效率），常用采样方法，束搜索及其变体，A* 与最佳优先搜索，其他受控生成方法。
  • 第二部分，推理、工具与 Agent：思维链与中间步骤，自我修正，推理模型，工具调用，Agent 与多 Agent 通信。
  • 第三部分，元生成，即把生成当作子程序来扩展推理时计算：最小贝叶斯风险与多样本策略，奖励模型与 Best-of-N 重排序，"系统而非模型"，推理扩展与模型规模的对比，外部验证器，token 预算与训练时蒸馏。
  • 第四部分，效率与系统优化：定义效率，库的实现与优化，KV 缓存优化，草稿模型与推测解码，稀疏注意力等替代建模方式。

不会讲的：模型训练只在与推理算法相关时简单涉及；模型架构讲得很少；评估和奖励模型讲得不多；推理基本只针对文本数据。

评分：15% 是小测或课堂参与，其中约 5% 是每人在学期中做一次约五分钟的论文报告，介绍一篇相关论文；60% 是三次作业；25% 是期末项目。作业都是共享任务（shared task），有三个任务，分别代表人们用语言模型做的不同类型的事，对推理算法也有不同挑战：数学推理；多项选择问答，选项有限但可以用思考这样的隐变量提升准确率，评估也很简单；开放式生成，评估很棘手，需要的推理少，更多是打磨输出。作业依次是生成算法（约 9 月底）、元生成算法如重排序和最小贝叶斯风险（约 10 月底）、硬件与优化（约 11 月底）。期末项目把它们合起来：你来当 OpenAI，推出自己的 GPT，提供一个 API 端点，课程组调用它测延迟、吞吐和准确率，你可以专攻其中一项，但不能有任何一项特别差。前三次作业为期末项目打基础。12 月有海报展示。

助教自我介绍：Amanda Bertsch 是五年级博士生、首席助教兼共同讲师，与 Graham 和 Matt Gormley 合作，会讲约一半的课，兴趣是长上下文、扩展推理时计算，以及在推理时改装模型、改变其行为；Vashisth Tiwari 是一年级博士生，兴趣是让小模型更好，无论是压缩还是合成数据、蒸馏；Clara Na 是五年级博士生，做效率方向。Graham 自己在推理方面的兴趣是推理能力、Agent 和工具使用。

课上征集反馈：GPU 基础，会有一讲硬件；多个用户的请求怎样批处理，讲 vLLM、SGLang 时会讲，这是它们的主要创新之一；模型大小怎样影响准确率、能否借此提速，会讲用大模型与做大量展开再重排序之间的权衡；RAG 大概不讲，嵌入查找也基本不讲，在"系统而非模型"一讲里简单提到；怎样为问题选搜索算法，第一部分会讲很多；推理模型背后到底在做什么，Graham 也希望知道答案，推理模型那讲会尽量讲；蒸馏会讲，剪枝更偏模型侧，也许会稍微提；多模态模型不讲 token 序列以外的生成，解码器如果一样，推理过程可能变化不大，但这不是他的专长。

十一、小结

语言模型给 token 序列分配概率，自回归模型把它拆成逐个 token 的条件概率，序列越长概率越低。Transformer 的计算量由注意力和前馈层组成，上下文较短时前馈层主导，上下文变长后注意力的平方项主导。推理和训练最大的不同在于：训练一次就能并行算完所有已知的 token，推理要一个 token 一个 token 地走，每一步都有固定开销且难以用满 GPU。本课会讲生成算法、把生成当子程序的元生成算法、思维链这类隐变量带来的效率问题，以及怎样评估输出。分析时要区分搜索错误（没找到模型最喜欢的输出）和模型错误（模型最喜欢的输出不够好），前者靠更好的搜索解决，后者原则上靠更好的模型，用推理去修它相当于有意不找模型最优解。多样性和质量之间要按应用权衡，延迟、吞吐也要一起考虑。
