第三讲：常用采样方法

局部归一化，校准与幻觉，熵、交叉熵与困惑度，祖先采样的长尾问题，温度、top-k、top-p 与 epsilon 截断，从有偏硬币讲典型性，局部典型采样与 η 采样，以及怎样选择采样策略

主讲：Amanda Bertsch · 2025 年 9 月 2 日
资料来源：课程幻灯片 · 课堂录像（本文依据录像字幕整理课堂口述内容） · 主要阅读：A Thorough Examination of Decoding Methods in the Era of LLMs；Trading Off Diversity and Quality in Natural Language Generation

一、模型是一个条件概率分布

接下来几讲由 Amanda 主讲。这一周讲采样和一些经典解码方法，之后再讲需要同时考虑多个已解码 token 的现代推理算法。今天只讲采样：先讲作为概率分布的模型以及刻画它的几个量，再讲两类采样方法：简单的截断和温度方法，以及利用这些量的更精细的方法。

今天的视角是：模型就是一个条件概率分布，不关心它怎么来的，只知道给定输入和已输出的 token，每一步都有一个词表上的下一个 token 分布。

1. 局部归一化

今天讲的模型是局部归一化的：每一步得到的就是这一步上的一个分布，而不是每步得到一个不一定是分布的分数、最后再归一化。所以序列分数单调不增，每多一个 token 就乘一个 0 到 1 之间的数。这也意味着前缀一旦概率低，就没法在后面补回来。

例子："2023 年的美国总统是"，接下来一个是"Barack Obama's former VP"（巴拉克·奥巴马的前副总统），一个是"Joseph Biden's daughter"（约瑟夫·拜登的女儿）。从整句看，前者显然更好；但它以概率很低的 token 开头的话，整体概率永远高不起来。这不是说前者一定比后者概率低，模型学的是所有句子的分布，这种说法可能很常见，"daughter"的权重也可能很低；但一旦给开头分配了较低的概率质量，就没法回头说"其实这句该有更多概率，开头有点误导"。

对比全局归一化的模型：每一步得到一个分数，可以远大于 1，比如 A 得 3.1，就能把 A 抬到其他候选之上，局部归一化做不到。用局部归一化是因为训练简单快速，不用担心序列层面的约束；代价是推理时想施加全局约束得多费心思。这学期后面很多方法其实就是想办法给只用局部归一化训练的模型施加全局约束。本课之后不再讲全局归一化，有兴趣可以看幻灯片下方那篇论文（An Empirical Investigation of Global and Local Normalization for Recurrent Neural Sequence Models Using a Continuous Relaxation to Beam Search），或者上概率图模型课。

2. 校准

如果模型的置信度与正确的概率高度相关，就说它是校准的（calibrated）。比如一道多选题，模型给 B 分配 50% 的概率，希望 B 大约一半的时候是对的，这样就能直接把 logit 当作置信度。模型通常校准吗？学生说现在还不错，以前很差，RLHF 会影响校准。图示：BERT 校准得还算合理（Desai 和 Durrett 2020）；GPT-4 技术报告里，RLHF 之前在 MMLU 上的校准曲线非常好，RLHF 之后就差了。预训练模型够强、数据够好时，似然与真实答案的可能性对应得不错；后训练很有用、通常给出更好的输出，但会破坏这个性质，所以后训练过的模型的概率就不能直接当置信度了。

3. 幻觉

模型通常会给一些错误输出分配非零概率，即使有比较明显的标准答案，它也不会把 100% 的概率放在 2+2=4 上。这可好可坏。Kalai 和 Vempala 2023 的理论结果是：只要模型是校准的，就不可能完全消除这种给非事实内容分配概率的情况，即使预训练数据全部是事实。

二、分布的统计量

1. 熵

通常在单个解码步上、对整个词表计算：

$$H(p) = -\sum_x p(x)\log p(x)$$

分布完全均匀时，熵高还是低？课上两种答案都有。这是香农的信息论意义上的熵：熵高意味着在最压缩的编码方案下需要更多比特来编码，因为没有什么先验倾向。完全均匀时要很多比特才能指定其中任何一个，熵高；分布很尖，比如 100% 在一个 token 上，就可以用很短的表示说"总是 token X"，熵低。

2. 交叉熵

更关心相对于某个真实分布的熵，即交叉熵：

$$H(p^*, p) = -\sum_x p^*(x)\log p(x)$$

真实分布 $p^*$ 怎么来？语言模型里一般看训练文档中实际的下一个 token，构造一个独热向量，是正确的下一个 token 就是 1，否则 0（也有把概率平滑开的变体）。训练过模型就见过交叉熵损失，就是在一批 token 上算这个；独热向量乘对数概率，等价于正确下一个 token 的负对数似然。

3. 困惑度

$$\text{PPL} = 2^{H(p^*, p)}$$

困惑度、交叉熵和真实分布与模型分布之间的 KL 散度有一个有趣的联系，第一次作业会遇到。一种号称直观的解释：困惑度为 6，相当于模型预测下一个 token 时掷一个六面骰子，掷出 1 才猜对。

三、采样（一）：截断与温度

1. 祖先采样与长尾

最简单的是直接按未修改的模型分布采样，叫祖先采样（ancestral sampling）。它精确地恢复模型分布，模型分布是花了大力气训练出来的，这看起来很合理，那今天可以下课了吗？可惜直接从模型分布采样有不少病态，今天主要讲长尾。Amanda 2022 或 2023 年做这页幻灯片时写的是"LLaMA 有 32000 个 token"，现在是"LLaMA 3 有 128k 个 token"，这大概是现代模型词表大小的中位数。在合理的前一两百个 token 之外，每个 token 都有一点点概率，加起来就很快：图上那条细线是概率质量的 50% 分位，从那之后的长尾占了一半的概率。每一步都采样、一段文本要采样一两百次，从长尾抽到很奇怪的东西的几率就相当可观。

2. 温度

上一讲见过：用温度重塑分布，让尾巴更平、更薄。温度 1 是原分布；小于 1 让分布更尖，峰更高，长尾里的质量更少；大于 1 让分布更平，想要更多样的输出时可以用来提高抽到原本不太可能的东西的几率。Hugging Face 里是 model.generate(do_sample=True, num_beams=1, temperature=0.8)。

3. 截断

另一大类做法：既然长尾有问题，就把它截掉。

  • top-k 采样：只从最可能的 $k$ 个 token 里采样。取决于分布有多尖，可能包含很多或很少概率质量。例子 $k=6$：解码完"The"后，接下来合理的选项很多，前六个只占 68% 的概率；解码完"The car"后，合理的后续少得多，前六个占了 99%。有点怪：有时只覆盖合理选项的一小部分，有时又包括一些概率很低的 token。参数是 top_k=k。
  • top-p（核）采样：改为规定要覆盖多少概率质量，比如 94%。第一步几乎包含了图上所有 token，第二步只包括前三个。直觉是从最可能的 token 开始，不断加入 token，直到达到这么多概率质量。参数是 top_p=p。
  • epsilon 采样：也许我们不在乎只取最可能的，只担心别取到概率非常低的，于是只截掉概率不超过某个小 $\epsilon$ 的部分（例子 $\epsilon = 0.05$）。所有 token 都有合理概率时就从整个分布采样，有很多不够格的就把它们去掉。参数是 epsilon_cutoff=e。

截掉一部分后分布不再归一化，要重新归一化，再在子集里采样。Hugging Face 里祖先采样是 do_sample=True, num_beams=1。

小测：这些参数的默认值是多少？学生答 top-p 常是 0.95，top-k 常是 50。这有一半是陷阱题：不指定时库里确实有默认值，但大多数模型会在自己的 generation config 里指定。LLaMA 3.1 的温度是 0.6、top-p 0.9；Qwen3 设置了 do_sample=True。模型提供方这样做，是因为不同模型在稍有不同的设置下效果最好，他们做过详尽的超参数搜索看哪个在评估上最好。所以指定生成参数时，先查库的默认值，再查模型 config，然后把你在意的都显式覆盖。这也让你知道常用的设置是什么。

四、采样（二）：典型性

接下来讲一个更复杂、用得少一些的算法，因为它提供了另一种思考采样的直觉。

1. 有偏的硬币

一枚不均匀的硬币，60% 的时候正面朝上，连抛 100 次并按顺序记下结果。单次最可能的结果是正面，两次最可能是两个正面，三次是三个正面，所以 100 次里所有可能序列中最可能的单个序列是 100 个正面。但抛出这个结果会让你吃惊吗？会。典型的结果大概是约 60% 正面、40% 反面的某种组合。最可能的东西不一定"典型"。

2. 随机过程里的典型性

要严格定义典型，借用随机过程的概念：把语言模型看成一个过程，每一步按分布发出一个 token，再以它为条件继续，相当于在词表空间里随机游走。要定义典型性，过程需要满足：

  • 离散：输出空间有限。
  • 平稳：概率不依赖绝对位置。可以依赖之前的 token，但不能因为是第 300 步还是第 0 步而不同。
  • 遍历：可以从一个很长的样本推断出分布的性质，不必聚合很多小样本。为此必须能从任何状态到达任何输出。

满足这些时，可以定义过程的熵率，不看单步的熵，而是在无限生成下取平均：

$$H(Y) = \lim_{T\to\infty}\frac{1}{T}H(Y_1, \dots, Y_T)$$

如果每一步都从同一个分布独立采样（像那枚硬币），熵率就等于那个分布的熵；语言模型每步的条件都在变，所以不是。长度 $T$、阈值 $\varepsilon$ 下的典型集，是所有长度恰为 $T$、每个符号平均负对数概率接近熵率的序列：

$$\left|-\frac{1}{T}\log p(y_1, \dots, y_T) - H(Y)\right| < \varepsilon$$

这抓住了硬币例子的直觉：100 个正面很可能，但其平均负对数概率离熵率很远，熵率暗示的是大约六四开的结果。这个定义形式清楚，长度趋于无穷时还有保证。

能用到语言模型上吗？离散：输出空间就是词表，有限。平稳：有学生问熵每步都在变，怎么和平稳相容？可以想成滑动窗口或二元模型，只关心前面若干个 token，第 20 步和第 2000 步都只以窗口内的东西为条件，窗口外发生了多少事无所谓；有限上下文窗口的模型就是这样，那就姑且算平稳。遍历：学生说每个 token 都有非零概率，似乎可以；但生成了句尾 token 就停止，用随机过程的话说这是吸收态，概率质量掉进去就出不来，于是不能从任何地方到达任何地方。看起来白推导了一通数学。

3. 局部典型采样

Locally Typical Sampling（Meister 等 2022）的妙处在于：既然全局典型性没法有原则地定义，就把它当北极星，做一个不那么有原则的局部近似，希望随时间逼近。不要求整个序列接近熵率，只要求每个新 token 接近它"预期"携带的信息量。怎样衡量一个 token 预期携带多少信息？看熵。而且我们本来就是一次采样一个 token，全局约束本来也难满足。算法：

  1. 计算当前步 logit 分布的条件熵 $H$（这一步只有一个熵值，它是分布层面的性质）。
  2. 按每个 token 的负对数概率与 $H$ 的接近程度重新排序：$\big|-\log p(y_t\mid y_{<t}) - H\big|$ 越小越靠前。
  3. 对这个新顺序用 top-p 截断，从最接近 $H$ 的 token 开始累加概率，直到达到阈值。
  4. 采样。

直觉是每一步都接近该步的熵，平均下来就接近熵率。奇怪之处在于它不再是截掉长尾，而可能截掉概率相当高的 token。学生问这和 top-p 有什么不同：关键在第二步，按与 $H$ 的接近程度排序，而不是按概率排序；只有当 $H$ 恰好落在最高概率处时才退化成 top-p。

幻灯片上的问题：条件熵高还是低时，最高概率的 token 更可能落在局部典型集里？答案是低。分布很尖、熵很低时，$H$ 接近 0，而最高概率 token 的负对数概率也接近 0，所以最可能的 token 正好最"典型"。分布很平、熵很高时，$H$ 比较大，最高概率 token 的负对数概率远小于 $H$，被选中的反而是分布中间那些 token。课上大家（包括 Amanda）在白板上把这个方向推了好几遍才理顺，Amanda 说熵的高低和概率的高低在她脑子里也很反直觉，值得反复提醒自己。

4. 这是值得优化的东西吗

论文的论证带一点认知科学风格的信息论：人类语言大概就是这样。他们拿大量人写的文本，用一个较强的语言模型计算每一步 logit 分布的熵和实际 token 的负对数概率，发现人写的下一个 token 几乎总是接近该步分布的熵，不同领域有些差异。论点是这是有效传递信息的方式：不想总说非常出人意料的话，那就是胡言乱语；也不想总说最显而易见的话，那就没传递任何信息。

学生问：对自然语言很直观，但事实性输出呢？如果只有一个概率很高的续写，这还成立吗？Amanda 说这可能是区别所在；但很少真的只有一个合法的下一个 token，除了数学或代码，任何事实的自然语言描述都有多种说法，有的更典型，有的不那么典型。

祖先采样和局部典型采样，谁的输出困惑度更高？学生答对了：局部典型采样更高。它把分布重塑得接近熵，而熵通常不在分布最尖的那一端，于是输出携带的信息量略高。训练时希望困惑度很低，说明分布学得好；解码时有时希望困惑度略高一些。同一家族的另一个方法是 Mirostat 解码，方向相反：指定想要的困惑度，用不断更新的方式生成 token，使最终困惑度接近这个值。它们都源于同一个想法：要优化的是信息量随时间的某种度量，而不是困惑度本身。

5. η 采样

用同样原则做截断的方法：同时施加 epsilon 截断和对局部典型性的近似。一个阈值像 epsilon 采样那样固定，另一个随分布的熵移动，只采样概率高于阈值的 token，阈值为 $\min\big(\eta, \sqrt{\eta}\,e^{-H}\big)$。实际上通常和局部典型采样或 epsilon 采样差别不大，但算得快一些。

五、怎样选择采样策略

Amanda 很希望能直接说"总用这个，别用那个"，但没那么简单。

  • 想想问题有多开放："写一个关于青蛙的创意故事"有大量正确答案，可能更在乎多样性而非唯一最好的故事；"给五岁孩子解释太阳系"答案范围也很宽；"马萨诸塞州首府是哪"选项就窄得多。
  • 多试几个。这些都是极简单的改动，代码只改八个字符，可以用小模型生成一堆来试。但要注意大小模型表现很不一样：同一种解码方法的搜索错误相同，模型错误却随模型对相关训练数据的拟合程度剧烈变化，小模型会表现出很多大模型上看不到的采样病态，所以要在你真正研究的模型上试。
  • 看输出。很重复或退化的，或者往很奇怪的方向走的，可能是从长尾采样了；退化成胡话，那肯定是长尾。采样一百次得到一百个一样或很相似的结果，也许该重视多样性，扩大采样的尾部范围。
  • 模型越来越好，这些策略没那么关键了，用模型或 Hugging Face 指定的默认值一般就能得到合理输出；用小模型或老模型时值得多花点时间。
  • 小心用什么设置做评估，不同设置下表现可能差别很大。Amanda 问了做模型评估的朋友，答案和她猜的一样：多试试。有朋友在训练语言模型，在评估集上扫了一遍参数，找到一个各检查点表现都比较稳定的区间（大概是温度低于 0.7、top-p 高于 0.7 之类），然后对所有评估都用这个设置。在验证集上扫几个，选一个策略，坚持用下去。如果针对每个评估过拟合最好的解码策略，拿你模型去用的人不太可能也帮你这样做。那些 generation config 里的数字也不是凭空来的。

学生问语言模型能否根据问题类型自己选择解码策略。隐含地它已经在做：2+2= 的下一个 token 分布极尖，而"Graham 最喜欢的颜色是"的分布平得多，模型学到的分布本身就适应了问题的开放程度。在系统层面当然也可以做：接收用户提示、传给模型之间，可以按请求调整生成设置，很合理，Amanda 不知道有相关工作，但不会意外有人这么做。

另一个学生问分布有哪些可研究的性质，比如怎样量化分布的"参差不齐"。最直接的是校准：模型越可能答对，分布应越尖。Amanda 个人猜数学或代码这类答案空间更受限的任务分布更尖，但那取决于模型学到的数据，不是必然的。熵能部分反映这一点，也可以看均值、中位数等统计量；实际中人们多在更粗的粒度上看，比如语料上的困惑度、一批数据上的交叉熵；做 ICL 里约束解码标签、或者关心多选题 A、B、C、D 上的分布时，才会细看单个分布。Graham 补充：参差不一定是问题，推理链有很多正确的说法，熵高的地方不一定危险，有时只是同一个词或句式有很多说法；而真正容易出错的地方可能只有两个选项，比如 533 还是 534，熵只有 $\log 2$，并不高，但仍然是问题。Amanda 补充：把一篇文档的困惑度随位置画出来，开头一两个 token 的困惑度极高，很多图干脆截掉前一百个 token，因为从零开始的选择太多，之后逐渐下降再趋平，但这不代表模型大部分错误出在最开始的几个 token，只说明那里合法的选项更多。

从这一讲开始，每次课后有学生做论文报告。

  • Mirostat: A Neural Text Decoding Algorithm that Directly Controls Perplexity；The Curious Case of Neural Text Degeneration（Holtzman 等）：核采样；Forking Paths in Neural Text Generation。
  • An Empirical Investigation of Global and Local Normalization for Recurrent Neural Sequence Models Using a Continuous Relaxation to Beam Search。

七、小结

解码的每一步，我们都拿到模型在词表上的一个概率分布。现代模型是局部归一化的，前缀概率低就无法挽回；预训练模型往往校准得不错，RLHF 会破坏校准，而校准的模型一定会给错误输出留一点概率。熵衡量分布有多平，交叉熵衡量相对真实分布的不确定性，困惑度是它的指数。直接从这个分布采样很简单，但长尾里大量小概率加起来，会让很多不想要的输出混进来；温度、top-k、top-p、epsilon 截断通过重塑或截断分布得到更好的输出。典型性提供了另一种视角：最可能的序列不一定典型，局部典型采样让每个 token 的信息量接近当前分布的熵，人写的文本大体如此。怎样选：看任务有多开放，多试几个，看输出，评估时在验证集上选定一个设置并坚持使用。
