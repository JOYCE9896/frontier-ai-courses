这一讲讲什么

前面几讲的策略都是反应式的：拿一帧观测 $o_t$，输出一个动作。这一讲要解决这种策略的两个问题：没有记忆，以及一步一个动作带来的抖动。Oier Mees 的路线是把机器人问题重新表述成序列建模问题：先讲自回归模型和 Transformer，再讲 Transformer 怎样扩展成 LLM、怎样接上视觉变成 VLM，最后讲怎样把机器人动作也变成 token，包括 RT-2/OpenVLA 的分箱、ACT 的动作分块，和他参与的 FAST 动作 tokenizer。上一讲（第 6 讲）讲的是生成模型；下一篇是同一周的嘉宾讲座，Ted Xiao 讲机器人学习的三个时代；第 8 讲讲世界模型。

01. 反应式策略的局限和自回归分解

录像位置 0:00:00–0:04:49

两个问题：记忆和平滑

他先回顾：到目前为止看的主要是反应式策略（reactive policy），拿单个观测 $o_t$ 喂给策略得到动作。理论上可行，但在真实世界里很容易出问题，因为一张快照通常装不下状态的全部信息。具体有两个问题。

  • 记忆。反应式策略不知道几秒前自己做了什么、做过什么决定、世界当时是什么样，而这些可能很重要，比如自动驾驶车开在结冰的路上。只看一张静态图，也很难判断行人在怎样移动、估计任何速度或运动，就有撞到人的风险。
  • 动作平滑。到目前为止的单步预测模型通常只预测下一个时间步的一个动作。在真实世界里这容易导致轨迹不平滑、一顿一顿的，因为每一步的决定都不太一样，有时会出现抖动、来回振荡的行为。

这一讲的修法就是序列建模和 Transformer。

部分可观测和轨迹概率

他说实际中机器人并不在 MDP（马尔可夫决策过程）里运行，而是在部分可观测 MDP（partially observable MDP，POMDP，智能体看到的观测不等于完整状态）里。要真正理解状态，需要对历史或轨迹，也就是观测和动作的序列，进行推理。他把课上一直在用的轨迹概率公式拿出来：

$$p(\tau) = p(s_1) \prod_{t=1}^{T} \pi_\theta(a_t \mid o_t)\, p(s_{t+1} \mid s_t, a_t).$$

这里的策略只是单步、反应式的 $\pi_\theta(a_t \mid o_t)$。世界是序列化的，策略却不是，他说这是一个根本的不匹配。于是自然的问题是：能不能直接对整条轨迹建模，而不只预测下一个动作？

自回归分解

最一般的思路是自回归模型（autoregressive model）。它来自概率的链式法则：任何联合分布，不管多复杂、多高维，都可以分解成条件分布的乘积，

$$p(x_1, x_2, \dots, x_T) = \prod_{t=1}^{T} p(x_t \mid x_1, \dots, x_{t-1}).$$

整个序列的概率等于第一个元素的概率乘以第二个元素的条件概率，依此类推。这一讲要回答的问题是怎样对这些条件分布建模。如果序列维度很高，比如高分辨率视频或复杂的机器人轨迹，条件会变得很长、很难处理，没法用一张大查找表。

02. 从 RNN 到注意力，位置编码

录像位置 0:04:49–0:11:00

RNN 的三个问题

最早用来处理这些条件分布的是循环神经网络（recurrent neural network，RNN）。想法很简单：有一个隐状态 $h_t$ 概括目前见过的一切，新输入到来时递归更新，$h_t = f(h_{t-1}, x_t)$。好处是能处理变长输入。实际中有三个严重的失败模式：

  • 长程依赖。要把信息从第 1 步传到第 100 步，梯度要穿过中间全部 99 步，通常会爆炸或消失。LSTM 有所缓解，但没彻底解决。
  • 难以并行。RNN 是自回归的，很难并行化。
  • 瓶颈问题。不管序列多长，全部历史都被压进一个固定大小的向量，这是一个绕不过去的信息瓶颈。

所以 RNN 能走一段路，但在实际中难以扩展。

注意力

他说大多数人已经熟悉 Transformer，这里简单回顾一下让大家在同一起跑线。Transformer 用注意力（attention）代替循环。注意力的关键性质是任意两个位置之间的路径长度是 $O(1)$：图上最后一个词可以一步直接关注第一个词，不必经过中间所有词。这同时解决了 RNN 的三个问题：长程依赖变得容易；没有循环，训练可以完全并行；没有固定大小的瓶颈，每个 token 都能直接访问其他每个 token。

具体怎么做：对序列里每个 token，要算一个融合了序列其余部分信息的新表示。注意力要回答的是“应该看序列的哪一部分”，这就是它学的东西。相关性用一个查询（query）向量和一组键（key）向量的点积来算，用 softmax 归一化使其和为一，再对值（value）向量加权平均：

$$\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\Big(\frac{Q K^\top}{\sqrt{d_k}}\Big) V .$$

他给的理解方式是一个“软的、可微的字典查找”：普通字典只取一个条目，这里同时取出所有值，按每个键和查询的匹配程度加权混合。因为所有操作都可微，模型不仅学表示，也学最优的搜索策略。

位置编码

注意力只算 token 之间的点积，实际上是一个集合运算，不知道顺序。他举的例子：“the robot picked up the spoon”和“the spoon picked up the robot”，如果不做处理，注意力模式完全一样。修法是加位置编码（positional encoding），把顺序信息直接注入 token 表示。主要有两种：

  • 绝对位置编码。Attention Is All You Need 原论文的做法，在 token 嵌入进入 Transformer 之前加一个固定向量。简单好用。局限是测试时序列如果比训练时长，就会失败，因为超出了分布。
  • 相对位置编码。不编码在序列里的绝对位置，编码 token 之间的距离，比如直接给注意力分数加一个偏置。这样在例子里，“spoon”关注“robot”时只知道两者相隔四步，不管它们在序列的哪里。这能推广到没见过的长度。他说很多现代基础模型都建立在基于相对距离的类似扩展上。

03. 原版 Transformer 和 teacher forcing

录像位置 0:11:00–0:13:45

编码器-解码器

原版 Transformer 是为机器翻译设计的：给一个源语言句子，生成另一种语言的目标句子。这分成两步，先理解源句，再生成目标句，所以有编码器-解码器的划分。

  • 编码器用双向自注意力，每个 token 能看到所有 token，过去和未来都能看。这合理，因为整个输入都已给出，要得到每个 token 尽可能丰富的表示。
  • 解码器用因果自注意力（causal self-attention），他强调这一点很重要：每个 token 只能关注自己和之前的 token。右边那个三角形掩码在 softmax 之前把未来位置的注意力分数设成负无穷，使它们归零。这让自回归生成成为可能：每一步只能以已经生成的内容为条件。
  • 中间是交叉注意力（cross-attention），编码器和解码器在这里交流。解码器问的是：“根据我目前生成的内容，源句里哪些部分现在对我有用？”所以查询来自解码器，键和值来自编码器。

因果掩码写成公式就是在 softmax 前加一个掩码矩阵 $M$，$M_{ij} = 0$（$j \le i$），$M_{ij} = -\infty$（$j > i$）：

$$\mathrm{softmax}\Big(\frac{Q K^\top}{\sqrt{d_k}} + M\Big) V .$$

teacher forcing

训练很简单，用 teacher forcing：训练时不在乎模型在某一步犯错。不把模型自己可能错误的预测喂回去，总是喂前面 token 的真实值，要求它用交叉熵损失最大化下一个正确 token 的似然：

$$\mathcal{L}(\theta) = -\sum_{t=1}^{T} \log p_\theta(x_t \mid x_{<t}).$$

好处是 Transformer 只需一次前向传播就能算出整个序列所有位置的损失，而 RNN 要对每个 token 做一次前向。

04. 语言的 tokenization：BPE

录像位置 0:13:45–0:17:48

什么是 token

用到机器人之前，要先问一个更基本的问题：token 到底是什么？怎样把输入离散成 Transformer 能处理的单元？从 Transformer 起源的语言说起，有两个明显的极端：

  • 字符：词表很小，但序列很长，模型要费很大力气才能对它们建模。
  • 单词：序列短，每个 token 都有意义，但遇到没见过的词怎么办？预训练词表可能表示不了它。

两个极端都不好，理想的是中间的东西：比字符大、比单词小的单元，能优雅地处理没见过的词，同时让序列长度可控。序列长度要紧，因为注意力是平方复杂度。这就是子词（subword）tokenization。

BPE 算法

常用的算法是字节对编码（byte pair encoding，BPE），他说它是对文本做自底向上的聚类。按幻灯片上的伪代码：从最基本的构件开始，即数据集里所有不同的字符；然后反复找最频繁的相邻 token 对，合并成一个新 token；重复 $K$ 次，直到词表达到想要的大小。实际中常见的子词因为到处出现，会很早被合并，序列就变短，这对 Transformer 很重要，因为它的内存占用是平方级的。

另一个好处是泛化：测试时遇到全新的词，大概率能把它拆成一串已知的子词单元。

具体例子是一句话：“the robots melted the robots unbearably cheesy fondue”。动画演示了 BPE 怎样在这一句上一步步合并子词，结果从 54 个字符压缩到 34 个 token，减少了 37%。

他说关于 BPE 要知道一个细节：压缩率随语料规模增长。训练 tokenizer 的数据越多，越多的常见模式被合并，序列越短，Transformer 越高效。现代 LLM 在互联网规模的数据上训练，词表大约 10 万个 token，压缩率可以达到这个例子的三到四倍。

05. 扩展到 LLM 的几项工程改动

录像位置 0:17:48–0:20:24

从原版 Transformer 到大语言模型，他简单讲了几项让它们能在大规模上工作的工程决定。

  • 结构简化。GPT 这类现代 LLM 完全去掉编码器，只用解码器（decoder-only）。用下一个 token 预测训练解码器更容易扩展，而且数据足够时，因果解码器表示上下文的能力和双向编码器一样好。
  • 字节级 BPE。不在字符上做，在原始字节上做，基础词表覆盖了所有可能的输入。他说前一页讲 BPE 能泛化到没见过的词，这没错，但用字节级 BPE 还能覆盖像 emoji 这种前面那个伪代码算法处理不了的东西。
  • RoPE（Rotary Positional Encoding，旋转位置编码）。他说这是位置编码问题的一个优雅解法：不把位置向量加到嵌入上，而是把查询和键向量各旋转一个与其位置成正比的角度，这样点积只取决于 token 之间的相对距离，和绝对位置无关。
  • Flash Attention 解决内存瓶颈。标准注意力要把完整的 $n \times n$ 注意力矩阵存出来，内存是 $O(n^2)$，序列很长时这成了限制。Flash Attention 把计算切块放进快速的 SRAM，从不实际存下这个矩阵，内存降到 $O(n)$，结果相同。

RoPE 的性质可以写成（以二维为例，背景补充）：位置 $m$ 的查询和位置 $n$ 的键分别乘上旋转矩阵 $R_m$、$R_n$，则

$$(R_m q)^\top (R_n k) = q^\top R_{n-m}\, k,$$

点积只依赖相对位置 $n - m$。

06. GPT 系列、涌现和苦涩的教训

录像位置 0:20:24–0:23:26

GPT-1 到 GPT-3

  • 2018 年的 GPT-1 还处在“预训练加微调”的范式：在大约 10 亿 token 上训练，但在某个窄任务数据集上做监督微调之前，模型对任何具体任务都没什么用。
  • 一年后的 2019 年 GPT-2，参数和 token 都扩大约 10 倍，开始看到零样本泛化（zero-shot generalization）：模型能做没被明确要求做的任务，因为它从文本里学到了足够多的世界结构。
  • 2020 年的 GPT-3，1750 亿参数、3000 亿 token，出现了上下文学习（in-context learning）：在提示里给几个例子，模型就能找出这些输入输出对的规律，用到新输入上，不需要任何梯度更新。

他说令人惊讶的是，这种能力是规模的结果，自己冒出来的。

苦涩的教训

这直接连到 Rich Sutton 2019 年说的“苦涩的教训”（The Bitter Lesson）。论点很简单：回看过去 70 年的 AI 历史，最终胜出的方法往往并非领域知识最巧妙、特征设计最精细的那些，胜出的是能随算力扩展的方法。不管是国际象棋、语音识别还是围棋，手工方法都会有一段时间有竞争力，但最终被用更多算力的通用方法超过。

他说 GPT-3 论文里那张图是很好的例证：13 亿参数的模型，不管提示里放多少例子，曲线基本是平的；扩到 1750 亿参数，模型变成了少样本学习者（few-shot learner）。这也不是有人专门设计出来的，是规模带来的涌现。如果这在语言上成立，他说今天这个领域想回答的问题就是：扩大机器人数据时，会涌现出什么？

07. 算力最优的缩放：Chinchilla

录像位置 0:23:26–0:27:25

模型和数据要同比例扩大

如果规模要紧，下一个问题是怎样最优地扩展。早期 GPT 之后的几年，社区似乎认为把模型做大是主要办法。Hoffmann 等人的 Chinchilla 论文精确地算出事情并非如此。主要发现：给定固定算力预算，模型规模和数据量应该按相同比例扩大。

左边的图画了不同模型规模在不同算力预算下的包络线。算力预算低时，最优选择其实是小模型：一个训练到最优点的 7500 万参数模型在低 FLOPs 处正好落在包络线上，而同样算力下训练的 100 亿参数模型还没训够，位于包络线上方。中间和右边的图画了模型规模、训练 token 数随算力的变化，可以看到 GPT-3 其实训练不足：相对于 token 数，它太大了；参照的是 Chinchilla 论文推出的最优缩放前沿（绿色虚线）。论文还发现，要达到算力最优，大约每个参数需要 20 个 token。

作为背景，训练算力常用 $C \approx 6ND$ 估算（$N$ 是参数量，$D$ 是训练 token 数），他说的结论对应 $N^\ast \propto C^{0.5}$、$D^\ast \propto C^{0.5}$，以及 $D^\ast \approx 20 N^\ast$。

先小规模试，再外推

他说缩放律在实际中有一个有用的推论：训练大模型之前就能预测它的表现。把全部算力押到一次昂贵的大训练（比如下一个 GPT-6）之前，先在不同模型规模和算力预算下做一批便宜的小实验，再外推大模型的表现，沿着 isoFLOP 曲线的那条线就能看出来。

Llama 3 为什么故意“过度训练”

右图画了不同模型的训练 token 数对模型规模。早期 GPT 模型都训练不足；Llama 1、Llama 2 和 Chinchilla 更接近算力最优前沿；Llama 3 远在前沿上方，训练用的 token 比算力最优公式建议的多。为什么？他说算力最优只在你只关心训练成本时才是正确策略。如果模型要服务几百万用户，你其实想要一个推理更便宜的小模型，哪怕要稍微过度训练，这是一个有意的选择。

08. 视觉 tokenization：ViT

录像位置 0:27:25–0:30:39

Transformer 是很强的通用序列模型，有了 LLM，可预测地扩展，规模上有涌现能力。但他说对机器人来说语言只是一半，机器人要感知世界才能做决策。下一个自然的问题是怎样让 Transformer 和 LLM 处理视觉观测。

他说大家可能在某次作业里见过，这里简单回顾图像 tokenization。Vision Transformer（ViT）论文的作者之一 Alexey Dosovitskiy（他说两人在 Freiburg 有交集，当时 Alexey 在那里做博士后），另一位作者 Lucas Beyer 课程后面会来做现场嘉宾讲座。ViT 的想法很简单：把图像块（patch）当 token。拿一张 224×224 的图，切成 16×16 的块，得到 196 个块；把每个块展平成向量，做线性投影，再加位置编码告诉 Transformer 每个块来自图像的哪里，就完成了：

$$N = \Big(\frac{224}{16}\Big)^2 = 14^2 = 196 .$$

这 196 个 token 在 Transformer 看来和文本 token 完全一样。他说这和语言里 BPE 的思路相似：找到合适的单元，变成向量，剩下的交给 Transformer。语言的单元是子词，图像的单元是块。接口一样，就可以在同一个序列里混用文本 token 和视觉 token。

现在“一切都是 token”，但这引出一个问题：如果只是把图像 token 和文本 token 拼在一起，Transformer 不知道哪些来自图像、哪些来自文本、它们之间怎样对应。理想情况下，我们希望模型能把文本 token “apple” 和图像里苹果所在边界框对应的视觉 token 联系起来，这样之后用语言指令让机器人捡起苹果时，它能理解我们要它做什么。怎样教模型对齐这两种模态？

09. 多模态融合：CLIP、LLaVA、Flamingo

录像位置 0:30:39–0:35:27

CLIP：双塔对比学习

最早的回答之一是 OpenAI 的 CLIP。它训练两个独立的编码器，所以叫双塔：图像用 ViT，文本用 Transformer。然后用对比学习（contrastive learning，让匹配的样本对在嵌入空间里靠近、不匹配的远离）在共享嵌入空间里对齐它们。做法简单：一个 batch 里有 $N$ 个从互联网上抓来的图文对，全部编码后算一个 $N \times N$ 的余弦相似度矩阵，再用一个温度参数控制分布的熵或尖锐程度。损失写出来是（对图像侧，文本侧对称）：

$$\mathcal{L}_{\text{img}} = -\frac{1}{N} \sum_{i=1}^{N} \log \frac{\exp\big(\cos(u_i, v_i)/\tau\big)}{\sum_{j=1}^{N} \exp\big(\cos(u_i, v_j)/\tau\big)} .$$

这样得到的视觉表示在语义上和语言对齐：苹果的图片和“apple”这个词在这个模型的嵌入空间里会挨在一起，这就是我们想要的。

LLaVA：早期融合

LLaVA 目标不同。CLIP 学的是两种模态的共享嵌入空间，里面没有 LLM；LLaVA 问的是怎样把视觉信息直接注入一个预训练好的 LLM，让它像对文本一样对图像推理。回答是早期融合（early fusion）：图像过一个冻结的 CLIP 视觉编码器得到块嵌入，再过一个小的可训练 MLP 连接层调整到合适的维度，然后直接放在文本 token 序列前面。LLM 在整个统一序列上做标准自注意力，结构不做任何改动。

设计上要紧的是哪些冻结、哪些训练：CLIP 编码器一直冻结，利用它的全部预训练；MLP 连接器学怎样把视觉嵌入投影到 LLM 的 token 空间；LLM 在视觉指令数据上微调，学会遵循基于图像的指令。

Flamingo：门控交叉注意力的晚期融合

第三种来自 Flamingo 论文，叫通过门控交叉注意力的晚期融合（late fusion），和 LLaVA 的早期融合对照。区别在视觉怎样、在哪里注入语言模型。LLaVA 把图像 token 放在文本序列前面，所有东西走同一个自注意力；Flamingo 让 LLM 的自注意力只处理文本，在每一层通过门控交叉注意力注入视觉信息。

具体是：视觉编码器保持冻结，用 Perceiver Resampler 把它的输出压缩成固定大小的一组键和值；在 LLM 的每一层插入一个新的交叉注意力块，文本 token 作为查询，去关注这些视觉键和值。他说整个方法巧妙的地方是 tanh 门，初始化为零：

$$y = x + \tanh(\alpha) \cdot \mathrm{XAttn}(x, v_{\text{img}}), \qquad \alpha_{\text{init}} = 0 .$$

训练开始时交叉注意力的贡献正好为零，模型和原 LLM 完全一样；随着训练进行，门慢慢打开，视觉信息流进来。他说这是一种很有原则的做法，既保住预训练的语言能力，又慢慢学会融入视觉。

10. 原生多模态和三种范式的取舍

录像位置 0:35:27–0:38:32

从头联合训练

LLaVA 和 Flamingo 有同一个基本假设：从预训练语言模型出发，再想办法加上视觉。第三种思路问的是：如果把这些都扔掉，从头联合训练所有东西呢？这就是原生多模态模型（native multimodal model）。不去改造语言模型来处理图像，而是在所有模态上同时训练一个统一的 Transformer：图像、音频、视频、文本都行，以任意顺序、任意组合交错。输入完全灵活，图像 token 后面接文本，音频后面接视频，任意混合。模型没有一个“主模态”外加其他模态，只看到一串 token，学着对它们联合推理。

他说吸引力很明显，原则上这是把苦涩的教训推到极致，没有偏向任何模态的结构偏置；当然它也是训练成本最高的。

现在的 VLM 属于哪一种

  • 早期融合（预训练 LLM 加视觉适配器）在开源社区最流行：LLaVA、PaliGemma（字幕作 PolyGemma）、Gemma 3 等。配方一样，换更好的视觉编码器、更好的基座 LLM，再迭代。
  • 晚期融合是比较小的一族。
  • 原生多模态是大型闭源模型正在收敛的方向，比如 Gemini、GPT-4o、GPT-5，也越来越多地出现在更大的开源前沿模型里，比如 Llama 4 和 Qwen 3.5。

他说取舍在于灵活性和可扩展性之间（他口误说成 preservation 后改口）。早期融合跨模态交互最丰富，图像和文本在自注意力里自由混合，但要微调 LLM，可能损伤它的能力。晚期融合完美保住预训练 LLM，但视觉和语言只能通过交叉注意力通路交流，交互受限。原生多模态去掉所有约束，代价是一切从头训练。

他回顾这条脉络：从用于更好语言翻译的 Transformer，到作为通用推理者的 LLM，再到能感知和推理世界的 VLM 和原生多模态模型。每一步都是同一招：找到给新模态做 tokenization 的正确方式，喂进同一个架构，然后扩大规模，先是文本和图像，再是音频和视频。

11. 动作 tokenization：分箱

录像位置 0:38:32–0:42:49

机器人作为多模态序列预测

问题就很明显了：能不能对机器人动作做同样的事？把动作 token 化，和观测、语言放进同一个序列，训练一个能对它们联合推理的模型？这样机器人学习就可以看成多模态序列预测问题：有语言 token、图像 token，模型输出的不再是回答用的文本 token，而是能指挥机器人电机的动作 token。可以沿用同样的下一个 token 预测架构，不改任何根本的东西，只加新的机器人动作 token。用注意力机制，相当于在问“我的全部历史里哪些和我现在该做什么有关”，这也在解决开头说的记忆问题。

RT-2 和 OpenVLA 的分箱方案

动作是连续的，不是离散的。第一种绕过的办法是离散化。RT-2 和 OpenVLA 这类模型用的是简单的“每维、每时间步”分箱（binning）方案：

  1. 分位数归一化（quantile normalization）：对每个动作维度，在训练数据上算动作分布的第 1 和第 99 百分位，把动作裁剪到这个范围内，再用这两个分位数归一化到 $[-1, 1]$。这样离散化在每个机器人、每个维度上都一致、可比较。
  2. 把每个维度离散成 256 个箱。
  3. 接进 LLM 的词表。

归一化写成式子是

$$\tilde{a}^{(d)} = 2\, \frac{\mathrm{clip}\big(a^{(d)}, q_{01}^{(d)}, q_{99}^{(d)}\big) - q_{01}^{(d)}}{q_{99}^{(d)} - q_{01}^{(d)}} - 1 \;\in [-1, 1].$$

他说 RT-2 原本用最小-最大归一化，但它对离群值处理得不好：可能要把大部分分布挤进前三个箱，剩下 253 个箱都浪费在表示那一个离群值上。

怎样接进 LLM 词表

每个动作维度有 256 个箱，怎样和 LLM 连上？一种常见做法是覆盖词表里最不常用的 token：如果有 256 个动作 token，就把词表里频率最低的 256 个 token 换掉。他说这些往往是一些奇怪的中文符号或字符。覆盖后 LLM 就和动作 token 接上了。此时模型可以用和 LLM 一样的交叉熵损失、一样的架构做下一个 token 预测。

12. 动作分块和 ACT

录像位置 0:42:49–0:46:37

一次预测 K 个动作

他回到开头的两个问题：记忆，单个观测无法反映世界的完整状态（字幕作 can capture，从上下文看是 can't）；平滑，每一步独立决策会产生抖动或不连贯的行为。记忆靠序列建模和 Transformer 解决，平滑问题的直接答案是动作分块（action chunking）。想法是不只预测下一步，让模型预测未来一段轨迹，即接下来的 $K$ 个动作：

$$\pi_\theta(a_t, a_{t+1}, \dots, a_{t+K-1} \mid o_t).$$

最基本的版本在图的上方：查询模型一次，得到一个块，比如接下来 4 个时间步的轨迹，执行完再查询模型拿下 4 个动作，依此类推。因为 4 个动作是一起规划的，不是单步模型那样一个个来，动作更流畅。

长块的问题和时间集成

如果块变长，比如为了适应更高频率的控制（比如你有一台人形机器人），要预测长度 100 的动作块，就有一种失败模式：执行完全部 100 个动作才重新查询模型，这期间（他说的是两秒）机器人是“瞎”的，什么都不更新，中间可能发生没预料到的坏事。

一种解法是时间集成（temporal ensembling），在图的下方：每个时间步都重新查询模型，每个时间步都保留多个互相重叠的预测。对任一时间步，把多次查询给出的预测用指数衰减的权重组合起来，

$$\hat{a}_t = \frac{\sum_i w_i\, a_t^{(i)}}{\sum_i w_i}, \qquad w_i = \exp(-m\, i),$$

其中 $a_t^{(i)}$ 是第 $i$ 次查询对时刻 $t$ 的预测（式子按 ACT 论文的写法补出，课上只说了“指数衰减权重”）。这样既保留了分块的平滑性，又能在每一步对新观测作出反应。

ACT 和 ALOHA

ACT 是 Tony Zhao 的论文，他说 Tony Zhao 是上周嘉宾 Cheng Chi 在 Sunday Robotics 的联合创始人。这篇论文提出用动作分块做灵巧双臂控制。设置是双臂 ALOHA 机器人，50 Hz 控制，模型一次预测 100 个动作的块。机器人做 14 自由度的关节控制，所以每次前向传播预测 1400 个值。这项工作表明，动作分块在很灵巧的任务上效果很好，比如插电池，需要很精确、协调的双臂动作，几乎容不得抖动或不平滑。以 50 Hz 做独立单步决策的反应式策略在这类任务上会很吃力，而规划平滑的 2 秒轨迹块的策略执行起来流畅得多。

13. 高效的动作 tokenization：FAST

录像位置 0:46:37–0:52:07

高频下朴素分箱为什么会坏

大的动作块有助于平滑的高频灵巧控制。但 ACT 没有用 LLM，也不是自回归地预测 1400 个值或 token。在 VLA 里这样做很快就会出问题，频率越高越严重，因为 token 彼此越来越像：频率越高，相邻两步之间差别越小，看一帧再看下一帧，几乎没有运动。自回归模型的学习信号来自每个新 token 带来的新信息，token 高度相关时，下一个 token 的边际信息量接近零。他强调，这意味着模型只要学会复制上一个动作 token 就能得到很低的预测误差，学不到真正的灵巧技能。幻灯片最右边的图显示，用这种朴素分箱方案在 10 Hz、20 Hz 这样较高的控制频率上自回归训练 VLA，性能开始下降。

找动作的“子词”

明显的解法是压缩。不对每个动作单独 token 化，要找一个更紧凑的表示，像 BPE 里的子词那样抓住运动中有意义的结构。也就是为机器人轨迹找到相当于语言子词、图像块的单元：比单个时间步大，比整条轨迹小。

怎样最好地压缩？LLM 里用 BPE，适合离散领域，但机器人是连续数据流。可以用 VQ-VAE，但那又多一个要训练的模型，复杂度更高。他说更高效的压缩办法是从信号处理借来的离散余弦变换（discrete cosine transform，DCT），JPEG 压缩用的就是它。

DCT 加 BPE

机器人动作块是平滑轨迹，平滑信号的能量大多集中在低频（他先口误说成高频，随即改正）。对每个动作维度做 DCT，就从时域转到频域：

$$C_k = \sum_{n=0}^{N-1} a_n \cos\Big[\frac{\pi}{N}\Big(n + \frac{1}{2}\Big) k\Big], \qquad k = 0, \dots, N-1 .$$

得到一个稀疏的频率矩阵，大多数高频系数接近零。对这些系数缩放并取整，把矩阵展平，低频分量排在前面，再对得到的整数序列跑 BPE。BPE 会把零压掉，合并频繁出现的系数组合，得到一串紧凑、密集的 token，可以直接接进已有词表。这就是 FAST（字幕里出现过 fast organization，应是 FAST tokenization）。

结果

  • 左图：自回归 VLA 的性能在 5 Hz 以后不再崩，还能继续提高。他说压缩做了它该做的事，保留重要的信息，丢掉冗余的高频相关性。
  • 右图是测试时的收益。他们把 π0 改成自回归，在 PaliGemma 骨干上用 FAST tokenization，和 Physical Intelligence 用流匹配生成动作的原版 π0 比较，他们的模型收敛到同样性能快 5 倍。他说这是他在 Berkeley 时和 Physical Intelligence 的合作。
  • 他说最酷的结果之一是在 DROID 数据集上训练的模型能在野外零样本完成语言指令任务，他们在 Berkeley、Stanford 和 University of Washington 的陌生厨房里测试，效果很好。
  • 还能以 50 Hz 做复杂的长时程双臂操作任务，比如叠衣服。

他说这同时推进了通用性和灵巧性两条轴，而这两者通常互相拉扯：要么做 ACT 这样精确但窄的专才策略，要么做 OpenVLA 这样覆盖广、但一般不够灵巧做精细操作的通才策略。这项工作在两方面都有进展。工作的另一个产出是一个现成可用的 tokenizer，放在 Hugging Face 上，可以用来训练 VLA。

14. 小结

录像位置 0:52:07–0:55:12

他总结：这一讲从一个简单的观察出发，反应式策略有根本局限，一张世界快照装不下完整状态，每步独立决策会产生抖动。修法是把机器人重新表述为序列建模问题。然后搭起一套工具：

  • Transformer 提供可扩展的序列建模架构，可以 $O(1)$ 访问历史的任何部分。
  • 扩展 Transformer 得到有涌现能力的 LLM。
  • 通过早期融合、晚期融合或原生多模态训练扩展到视觉，得到能对图像和语言联合推理的 VLM。
  • 最后一步扩展到机器人动作，这并不简单，因为朴素 tokenization 在高控制频率下会坏，需要 FAST 这类基于压缩的方法，才能让自回归动作生成在机器人需要的频率上工作。

他说贯穿整讲的核心想法就是把苦涩的教训用到机器人上：找到正确的表示，用通用、可扩展的架构，然后让数据和算力去完成剩下的工作。
