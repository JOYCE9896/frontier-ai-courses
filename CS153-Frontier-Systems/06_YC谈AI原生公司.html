第六讲：YC 谈 AI 原生公司

SAFE 怎样成为早期融资的标准，Garry Tan 用 Claude Code 和 Agent 的实际做法（技能、解析器、skillify、记忆系统），以及 Diana Hu 讲的闭环公司、新的组织角色、评估和创业机会

主讲：Anjney Midha · 嘉宾：Garry Tan（Y Combinator 总裁兼 CEO）、Diana Hu（Y Combinator 合伙人）
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、资本也需要标准

Anjney 说这门课的前身之一，是他大二时 Peter Thiel 在斯坦福开的 CS 183"如何创业"（后来成了《从 0 到 1》这本书），第二年 YC 由 Sam Altman 组织开了类似的课，还有 Terry Winograd 的新生研讨课 CS 43N。Garry 当年在斯坦福读书，后来把斯坦福的精神带到了硅谷，这次回来讲课算是闭环。

他把这一讲和第一讲联系起来。这门课讲的是系统：从土地、电力、能源（Scott Nolan）到芯片（上周的黄仁勋），整个系统在被重写，以打通前沿进步的瓶颈，资本是其中之一。第一讲说过，算力今天是瓶颈，部分原因是算力还处在"标准化之前"的时代；工业革命中电力能成为人人可用的稳定基础设施，靠的是标准（比如交流电与直流电之争的结果）和执行标准的机构（建电网的公用事业公司）。他 2011 年来到硅谷时，风险投资也处于标准化之前，一团混乱，每家 VC 都在用自己的条款和创始人谈。这时 Paul Graham 和 Jessica Livingston 推出了新标准 SAFE（未来股权简单协议），一份放在网上的两页法律文件。当时作为学生他觉得"不过是个法律文件"，现在回头看，这是硅谷历史的转折点：云计算和 SaaS 降低了创新的边际成本，但风险投资没跟上，SAFE 成了早期融资的标准，YC 也因执行这一标准成了规范种子轮融资的机构。他说 AMP 在算力方面也许有一天会开源一份"未来算力简单协议"，系统设计不只是工程上的事，在任何领域都可以用来打通瓶颈。

二、Garry Tan：一个人的软件工厂

Garry 是斯坦福 2003 届，说自己在这个教室里睡着过很多次。他说 SAFE 是法律工具，今天要讲的是代码，而且 Markdown 也是代码；他们那一代人建了互联网、手机和社交网络，这一代人要为整个社会建"认知层"。Diana 说，YC 投的公司里有很多一年内从零做到几千万美元收入，以前要四五年、花几亿美元才能做到这种 B 轮水平。Garry 说，团队和人仍然有价值，但以后不只是人，而是人和带有记忆、评估、客户反馈循环的 Agent 一起工作。

他讲了自己的经历：2008 年进 YC，融了约 400 万美元，雇了 10 个人，做了简单的博客平台 Posterous，三年后以 2000 万美元卖给 Twitter。两年里 10 个人加上那些资本做出来的所有软件，他现在用每月 200 美元的 Claude Code Max 套餐，大约五天就能做出来，在座任何人都可以。他说 2026 年，一个六人团队可以做到 1000 万美元收入。

去年年底他看到 Steve Yegge（著名博主和工程师，早期 Google 员工）写道，用 AI 编程 Agent 的人比用 Cursor 和聊天的工程师效率高 10 到 100 倍，而 Anthropic 内部大约是 2005 年 Google 工程师的 1000 倍。他打开 Claude Code 试，最后写了大约一百万行代码。

他回应了几种常见批评。"全是 AI 垃圾"：大模型确实啰嗦，有些是样板代码，但建自己的软件工厂，就是要防止这些默认发生。幻觉确实存在，这正是要控制的。能快速写出演示代码，但要上生产，得有 80% 到 90% 的测试覆盖率，这是他每天用二十来次的 plan-eng-review 技能存在的主要原因。他承认用代码行数说事曾惹过麻烦，并为此道歉：代码行数单独看可能是错误指标，真正的标准是它对你和客户是否有用、有没有人付钱；而且 Claude Code、模型和他的工具都没有让模型多写代码，反而在追求精简。

他从去年 12 月几乎不写代码，到现在开源项目 GStack 有 8.7 万星，GBrain 有 1.3 万星，每天约 1.5 万人在用。他说去年 Claude Opus 4.5 出来之前大家谈的是 copilot，现在谈的是软件工厂。

从潜在空间里调出特定角色

他在做 GStack 时偶然发现，把模型潜在空间里已有的特定"角色"调出来很有用。最常用的 /office-hours 技能，是 YC 已有做法的蒸馏：YC 有十五六个合伙人，创始人来做 office hours 时，合伙人主要问问题是什么、客户是谁、你怎么知道、要做什么。他们拿了三四个月、几千次对话的记录蒸馏成一份内容，再删掉 90%，就是开源的 /office-hours。另一个是 plan-ceo-review：它了解你要做的东西，然后问"这件事的十倍版本、理想形态是什么"。他做产品经理和创业时就想这样：先想清楚最理想的样子，再让现在做的东西在一条从现在通往那里的直线上。

他还说要"煮沸海洋"。在公司里，有人提出过大的想法时，别人会说"别想着煮沸海洋"；他的经验是，现在一个人坐在终端前能做 500 到 1000 人的工作，那么社会对创始人、公司、小团队能做什么的预期都差了一千倍。这甚至体现在模型权重里：问 Claude Code 要多久，它说三周，你批准计划，一小时就做完了，模型本身还没跟上这个现实。

代码和 Markdown 的分工

Garry 说 YC 现在都在用 OpenClaw 和 Hermes Agent，它们教会了他新的基本概念。他每次做 Agent 系统出问题，都是因为放错了地方：要么把该用代码做的确定性工作写进了 Markdown 技能里，要么把该由大模型做的事写进了代码里。例子：把参加晚宴的八个人的简介交给 Claude 或 ChatGPT，让它搜索每个人、写档案、安排座位，在潜在空间里很容易；换成 800 人的晚宴或 6000 人的 Startup School，模型就做不了了，会产生幻觉。这时就需要把潜在空间和确定性空间结合起来。

技能文件是什么？有人嘲笑说"不就是一堆 Markdown 文件"。他说技能就是一份操作手册，就像你要反复办活动，会在笔记本上写下第一步定场地、第二步定邀请名单，任何人或 Agent 读完都知道怎么做，步骤可以有分支，可以很复杂。关键是技能可以调用代码。他说 YC 的创始人现在不再自己打电话办事，就像不再打开 VS Code 自己写代码一样（他说他和 Karpathy 等很多人已经不打开编辑器了）：可以让 Twilio 打电话，用 Gemini Live 去预订或购买。Google 曾在大会上演示让 Gemini 打电话帮你预约，后来一直没上线，你现在不用等了。

确定性的事就该用代码。他举例说，OpenClaw 总以为他在英国格林尼治的时区，他就用 TypeScript 写了一个 context-now.mjs 并配上测试，接入系统，每次直接告诉 Agent 现在几点、接下来有什么安排，不让潜在空间去猜，否则它会说"现在凌晨三点了，你怎么还没睡"，而实际上是下午。

解析器和 skillify

用 Claude Code 久了，会看到 CLAUDE.md 太长的警告。解决办法是解析器（resolver）：CLAUDE.md 里堆满了你在各种情况下要求它怎样做的指令，把它改成"需要写更新日志时，才加载 changelog.md"，Agent 就有一个总目录，只在需要时加载相应指令。他说这听起来很简单，却是好 Agent 的核心。比如要处理签名，就该去找"行政助理"技能，到他的 brain 仓库里查对应的流程，他称之为技能包。

他每天用二十来次的另一个操作叫 skillify。比如"保存这篇文章"：先做一次，看输入输出，调到满意后对 Agent 说 skillify。写技能和写代码只占十步里的两步，其余都是为了确保这个不完美、更像人类组织的系统能稳定工作：

  • 为代码写单元测试；
  • 为技能文件写大模型评估；
  • 写集成测试；
  • 在 agents.md 里加解析器触发条件并测试；
  • 用大模型当评委，检查触发条件足够宽、真的会被触发；
  • 检查可解析性（check resolvable），避免重复，不要有好几个技能做同一件事；
  • 端到端冒烟测试；
  • 确定它在记忆和仓库里放在哪里，即数据结构。

他说这就像金融机构里有 10% 到 20% 的人只做合规，以前不懂为什么，现在明白了。他说 Hermes Agent 在测试这部分还有缺陷，可能快修好了。

记忆系统 GBrain

GBrain 是在 Karpathy 讲过的"知识 wiki"基础上做的三层记忆系统。他一开始也用知识 wiki，但它只靠 grep，规模一大就不行了，于是加了向量搜索、排序融合、反向链接，以及带类型的知识图谱数据库；接下来要加一个"认识论"系统，区分哪些是某个人的直觉或信念、哪些是公认的知识，并追踪变化。他说创始人的历程就是：你有一个别人还不相信的直觉，然后花一两年、五年去证明它；他希望知识系统能发现"斯坦福有个人当初相信 X，后来把它做成了"。现在 GBrain 的数据结构是为他自己设计的，V1 之前他要做"完全动态的本体"（他从 Palantir 学到的词），让研究者、记者、政治人物都能有自己的结构。

他说这些概念都是他一周一周摸索出来的，skillify 是他凌晨三点用 OpenClaw 时冒出来的，发到 X 上火了，他引用 Alan Watts 的话说"我不是大师，只是个表演者"。他发现这些概念能对应到公司：

  • 技能：有某种能力的员工；
  • 解析器：组织架构图，谁负责什么；
  • 归档规则、信息在 brain 里存放的位置：内部流程；
  • 检查可解析性：审计和合规；
  • 触发条件评估：绩效考核。你以为写在 agents.md 里就会触发，其实也得检查。

三、Diana Hu：闭环的公司

Diana 说，AI 原生公司的关键是从根本上改变公司的运行方式。今天的公司基本是开环系统：人做决定，结果很久才反馈回来，信息损耗很大，误差不断累积，最后偏离轨道；闭环系统（比如 PID 控制器）有紧密的反馈，误差能控制住，机器人系统就是这样工作的。传统公司的信息存在人的脑子里、Slack 私聊里、没写下来的会议里，还有各种"感觉"，决策就这样做出来。现在可以把它变成闭环：把 Hermes 或 OpenClaw 这样的 Agent 嵌入所有决策，让它能读取公司产生的每一份材料。学生做项目也可以做一个小版本：Agent 连上 GitHub 代码库和 Discord，记录和队友的所有会议，然后建议接下来最该做什么、该修哪些 bug，并存进记忆。

她说这样做的公司人均收入至少一两百万美元，而像 Salesforce 这样的上市公司人均收入不到六位数，至少是十倍的差距。YC 自己的工程团队这样做之后，冲刺周期缩短一半，产出是原来的十倍。她提到 Jack Dorsey 写过关于 Agent 化组织的文章：组织变得很扁平，中层管理需求减少，因为中层过去主要在做有损的信息传递。公司里剩下三种角色：

  • 人人动手做：每个人都是交付东西的个人贡献者，非技术人员也能用工具搭建，比如销售自己搭整套约电话、约会议的自动化流程。
  • DRI（直接负责人，Apple 的说法）：公司的每个结果都对应一个负责人，由他协调个人贡献者完成，比如"本周末收入提高三倍"，他去协调销售约电话、工程上线功能，通常是创始人。
  • AI 创始人：站在未来的边缘，试遍所有工具，把最新的东西带进公司。她说 Agent 编程的大变革发生在去年年底 Claude 4.5 出来时，不在前沿的人就没法把这些创新带进公司。Garry 插话说，还停留在去年 copilot 水平的人"撑不下去"。

品味和评估

要避免"AI 垃圾"，不能委托出去的是品味。写代码、交付代码的成本趋近于零，但判断好坏、做出好东西的品味不会。品味体现在评估里：通用基准（比如 MMLU）不能告诉你产品是否有效、是否惹恼了用户；最终的评判是用户是否真的想要，而每个领域都不同，没法自动化。你要深入细节：是否遵循了指令，答案是否正确，是否维护了客户的信任，是否达成了业务目标，是否符合领域规则。这仍需要人在回路里，发现哪里出错，把某次交互或某个流程标注为错误，需要你亲自、费力地看所有轨迹。

Garry 说他还没发布、但会发布的是"跨模型评估"：让 Opus、GPT-5.5、DeepSeek-V4 等前沿模型一起评估输入输出、打分，再反馈给原来的子 Agent 说明下次怎么改，反复迭代，用元提示把结果做到比第一版好十倍。他说很多 YC 创始人说 Claude Code 像"有多动症的 CEO"，Codex 像"几乎不说话、智商 200 的 CTO"，两个一起做交叉分析，才能零 bug 发布。Diana 总结了评估的三步：根据你的产品（视频、语音、消费、B2B SaaS 都不同）捕获轨迹；把失败案例检测出来，转成评估；不断重放，让系统自我修复、自动改进提示。Garry 说，听讲没用，要自己打开 Hermes Agent 和 Claude，装上 GBrain，试试里面四十个技能，再把自己的做法 skillify、开源。

四、现在创业的机会

Diana 说这可能是历史上最好的创业时机。常见的切入方式是：选一个痛苦的工作流程，深入客户内部，自己当前线部署工程师。例子：

  • Salient：为贷款服务做语音 Agent，拿下了美国几家顶级银行。
  • Happy Robot：嵌入货运代理行业，做 Agent 自动化和卡车司机的协调、时间安排等繁琐工作，去年完成 B 轮，一年收入增长十倍。
  • Reducto：做文档处理。她说所有 Agent 都需要读文档，文档处理做好了，检索增强、记忆都会变好，所以给 Agent 做工具也是大机会。

这些公司增长快，是因为部署的是完整的解决方案，而不是演示或副业项目。创始人往往没有相关行业背景，比如 Happy Robot 的创始人不是物流出身，"不在训练集里"，他们靠跟岗或直接去行业里工作，学会所有细节，再把重复劳动和混乱领域里的工作自动化。这些流程过去靠电话、邮件、电子表格散落各处，嵌入系统的 Agent 能把它们串起来。

她展示了 Anthropic 发布的各行业使用情况图：软件开发的渗透率约 50%，而后台、金融、数据、学术、网络安全、客服等领域还有大片空白，她认为能容纳成百上千家 AI 独角兽。Garry 说"我们还在第一局的第一个投球"。她还给了 YC 的数据：过去只有最顶尖 1% 的公司能做到每周增长 10%（Paul Graham 定的标准），Airbnb 那一批大概只有 Airbnb 和另一家做到；最近几批的平均水平是三个月增长三倍，这在 YC 历史上从未有过。她最后说，这门课的期末项目是"一人前沿实验室"，而这个实验室也可以变成一人公司。
