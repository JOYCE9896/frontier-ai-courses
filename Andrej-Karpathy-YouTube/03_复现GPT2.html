复现 GPT-2（124M）

用 PyTorch 从检查公开权重开始，走到训练、加速、分布式和评估

演讲：Andrej Karpathy · 发布：2024 年 6 月 9 日 · 时长：4 小时 1 分
资料来源：Let's reproduce GPT-2 (124M)（依据公开视频章节与英文自动字幕整理）

一、先让公开 checkpoint 对得上

复现的第一步不是训练，而是把 GPT-2 的结构和 Hugging Face checkpoint 完全对齐：词和位置嵌入、因果自注意力、MLP、LayerNorm、残差连接、输出投影及权重共享。对同一输入得到相同 logits，才能说明张量形状、转置方向、参数命名和初始化没有悄悄出错。

随后用 tokenizer 将前缀变成 token，按 temperature、top-k 等规则从 logits 采样，并循环把 token 接回输入。采样结果是最直观的端到端 sanity check：模型、词表和解码器任何一环错位，文字都会立刻异常。

二、训练循环的最小闭环

训练批次的输入为 $(B,T)$ token，目标是整体右移一位的同一序列；模型输出 $(B,T,V)$ logits，再用交叉熵衡量真实下一个 token 的负对数概率。先在一个 batch 上过拟合，是检查数据、loss、反向传播和优化器是否连通的最快方法。

真正训练前还要处理数据加载与验证切分、token embedding 和 lm head 权重共享、初始化尺度、残差分支的初始化、AdamW、梯度裁剪、warmup 加 cosine learning-rate decay，以及用梯度累积把多个小 batch 合成所需总 token batch。这些并非装饰，训练稳定性和最终损失都会受它们影响。

三、速度来自系统性消除浪费

视频依次测量并优化 GPU 利用率：使用 Tensor Cores 与 TF32、在合适场景选 bfloat16、通过 torch.compile 减少 Python 开销与融合 kernel、采用 FlashAttention，并让矩阵尺寸更贴合硬件。每步都先计时，再解释为何更快；不能把某个单独技巧当成普适魔法。

当单卡无法容纳或吞吐不够时，用 DDP 把 batch 分到多张卡，每张卡计算局部梯度，再做 all-reduce。关键是让每个进程读取不同数据分片，并把全局 token batch、学习率日程和验证指标保持一致。

四、评估决定“复现成功”的含义

只看训练 loss 不够。视频加入独立验证集、定期文本采样和 HellaSwag 多选评估，最后把 124M 训练曲线与 GPT-2/GPT-3 公开报告对照。相近的损失和评估分数比“能生成像英文的文本”更严格，也更容易定位差异来自数据、训练 token 数还是实现。

数据是复现中最难完全相同的部分。Karpathy 对比 GPT-2、GPT-3 所用数据与 FineWeb/FineWeb-Edu 等现代公开集：架构代码可以复制，数据分布、清洗和去重则直接改变模型学到的语言世界。

复现清单

  • 先比对单 batch logits 与公开权重。
  • 用单 batch 过拟合验证训练通路。
  • 记录 tokens/sec、显存、loss、验证 loss 和下游评估，而非只看代码能跑。
  • 每项性能优化独立计时，避免“更快”只是偶然波动。
  • 把数据版本、随机种子、总训练 token 与超参数写进实验记录。
