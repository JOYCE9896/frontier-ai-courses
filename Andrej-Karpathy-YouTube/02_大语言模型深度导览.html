大语言模型深度导览

从 next-token prediction 到后训练、推理和安全：一张把 ChatGPT 拆开的全景图

演讲：Andrej Karpathy · 发布：2025 年 2 月 5 日 · 时长：3 小时 31 分
资料来源：Deep Dive into LLMs like ChatGPT（依据公开视频章节与英文自动字幕整理）

一、LLM 是怎样产生文本的

语言模型的任务始终是根据已有 token 预测下一个 token。token 是文本切分后的离散单位，并不等于一个字或一个词；同一句话的字符数、词数与 token 数都可能不同。推理时模型反复输出下一个 token，采样策略决定它更保守还是更多样，聊天界面只是把一条带角色标记的 token 序列显示成气泡。

预训练把海量互联网文本变成“读到前文、预测后文”的训练例子。模型并没有检索一份原始网页库，而是在参数中压缩出统计规律；所以它会形成语言、事实和模式的广泛能力，也会有知识截止日期、罕见事实记不准和自信地编造的可能。

二、Transformer 为什么能工作

输入 token 先变成向量，再经过多层 Transformer。自注意力让一个位置从序列中挑选与当前预测有关的位置；MLP 则在每个位置上做非线性变换。位置编码、残差连接和归一化让许多层能够稳定叠加。Karpathy 用 GPT-2 和 Llama 的实际权重说明：训练与推理不是两套神秘机制，推理只是固定参数上的一次前向计算与循环采样。

模型的能力并不均匀。他称其为“锯齿状智能”：在一些组合、拼写、计数或边缘推理问题上会意外失败，在另一些任务上又非常强。把流畅表达误认为普遍可靠，是使用 LLM 时最常见的错误。

三、从文本补全到助手

预训练模型只会续写互联网文本。要成为助手，需要监督微调：用人工编写或筛选的对话告诉它怎样遵从指令；随后可用偏好数据和强化学习，让回答更有帮助、更安全、更符合评价标准。RLHF 不是让模型“学会真理”，而是把一个外部奖励信号变成调整行为的训练目标。

推理模型进一步在可自动验证或可评价的任务上训练更长的思考轨迹。它们会花更多 token 检查、分支和回退，常在代码、数学和复杂约束任务上更强，但仍可能基于错误前提长篇推演。长思考是额外计算，不是正确性的证明。

四、模型需要外部世界

参数中的知识不等于实时世界。搜索、浏览器、计算器、Python 和数据库等工具，都是让模型发出结构化请求、由外部程序执行、再把观察结果写回上下文的循环。工具调用把“看起来会算、会查”转变为可检查的实际操作，但也引入了权限、提示注入、错误执行与来源质量的问题。

图像、音频和视频也能被编码成 token 或连续表示，因此模型可做视觉理解、语音对话和生成。不过不同产品的多模态链路可能是端到端模型，也可能是多个模型串接；接口看起来一样，不代表准确性、隐私边界和延迟相同。

五、安全不是后加的按钮

视频最后区分三类风险：用户直接要求越权内容的 jailbreak；网页、邮件或文档中夹带恶意指令的 prompt injection；以及训练数据或反馈被污染。系统提示、训练对齐和内容过滤都有用，但都不是绝对边界。真正接工具的 Agent 还需要最小权限、隔离执行、可信输入通道、确认步骤和可审计日志。

这节的实用结论是：把 LLM 当成强大的概率程序，而不是可信的数据库或独立主体；对每个任务明确证据从哪里来、哪些操作允许自动执行、错了以后怎样发现和撤销。
