Karpathy 是怎么讲的：频道全部视频背后的底层思路

把 17 条视频放在一起看：他选什么题、怎么搭结构、怎么让人听懂、怎么让人信任。写给想做类似知识类自媒体的人

整理：Joyce（@JOYCE9896）· 依据：本栏目 13 篇视频笔记、视频字幕与描述、YouTube 公开元数据（播放量为 2026 年 10 月抓取时的数字）

先说结论

看完全部视频，我认为他的讲法可以归结为一句话：他把“自己怎样弄懂一件事”的过程原样摊开给观众看。从空白文件开始，先估计结果应该是什么，再跑出来看对不对，不对就查原因，查清了再往下走。观众跟着走完一遍，得到的是理解，而不只是信息。

下面分八个部分展开：频道的数据和结构；他为什么有资格这样讲；十条底层原则；两种视频的结构模板；语言习惯；制作和配套；数据给出的提示；以及对做中文知识类内容的人，哪些可以直接借鉴，哪些需要调整。

几个直接能读出来的现象：

  • 长视频没有吃亏。播放最高的是 3 小时 31 分的《Deep Dive》，1,000 万；第二是近 2 小时的《Let's build GPT》，809 万。观众愿意为“讲透”花时间。
  • 两个峰值都踩在大众最关心的时刻。《Let's build GPT》在 ChatGPT 爆红两个月后发布，开头就是“你们都听说了 ChatGPT”；《Deep Dive》在 DeepSeek-R1 引发热议时发布，后半段专门讲 R1。
  • 系列内部播放逐集递减。makemore 从 131 万降到 30 万。每一集都是上一集的前置，后面的观众只是前面的一部分。
  • 面向一般观众的三条，播放总和远超技术系列。但技术系列是他在社区里的信用来源，一般观众视频的说服力很大程度建立在“这个人亲手写过 GPT”之上。
  • 更新不规律。两年半 12 条正片，有时一个月两条，有时间隔大半年。他显然以“做完、做好”为准，而不是固定节奏。

二、他为什么有资格这样讲

视频描述里他的自我介绍是：2015 年 OpenAI 创始成员，2017–2022 年特斯拉 AI 高级总监，现在创办 Eureka Labs，在做一所“AI 原生的学校”。背景信息：他读博期间在 Stanford 参与创建并主讲了 CS231n 课程，这是很多人入门深度学习的课。

这对理解他的讲法很重要。他敢说“micrograd 就是你需要的全部，其余都是效率”“RLHF 不是 RL”这种判断，观众也愿意接受，是因为他亲手做过、在一线做过。他的很多讲法技巧（坦白不确定、展示自己的 bug、给个人偏好）在一个已有信用的人身上是加分项。没有这个背景的人，需要用别的方式建立信任，第八部分会讲。

三、十条底层原则

1. 亲手从零做一遍，才算真的懂

Zero to Hero 系列的每一集都从空白的 Jupyter 笔记本开始。micrograd 不用 PyTorch，用 100 行 Python 写出自动求导；第 4 集不用 loss.backward()，在张量层面手写全部梯度；分词器从 UTF-8 字节开始手写 BPE；GPT-2 从加载权重写到 8 卡训练。

他在第 4 集开头解释了为什么：反向传播是“有漏洞的抽象”，不理解底层就会搬起石头砸自己的脚。他还拿出网上一段真实的错误代码作证据。这个原则也决定了他的叙事顺序：先让你看见里面，再把它封装起来。手算梯度做到观众觉得烦，才封装成 _backward；自己写 Linear、BatchNorm、Sequential，再说“现在你们已经解锁了 torch.nn”。

2. 开头先亮出终点

  • micrograd：“到这集结束，你会理解 micrograd 的全部。”结尾他真的逐个文件过了一遍来兑现。
  • Let's build GPT：先展示训练好的模型生成的“莎士比亚”，再从空文件开始。
  • 复现 GPT-2：先加载 OpenAI 的权重生成文本，“从终点开始”。
  • 分词器：先列出一串大家遇到过的 LLM 怪现象，说答案都在分词里，结尾逐一解释。
  • Deep Dive：开头问“你在和什么说话”，结尾用三个半小时的内容回答这个问题。

效果是观众从第一分钟就知道这几个小时要去哪儿，中途每一段都能挂到这个目标上。长视频能让人看完，靠的是这根线。

3. 先估计，再验证，差距就是教学点

这是他最有辨识度的习惯。任何数字出来之前，他先说“我预期它应该是多少”：

  • 27 个字符均匀分布时，初始损失应该是 $-\ln(1/27) \approx 3.29$，实际是 27，于是引出初始化问题（makemore 3）。
  • GPT-2 词表 50,257，初始损失应约 10.82，实际约 11，说明初始化没问题（复现 GPT-2）。
  • TF32 理论上快 8 倍，实际只快 3 倍，于是讲内存带宽瓶颈。
  • 推动输入之前先问观众“输出会变大还是变小”（micrograd）。

预期和结果一致，观众建立信心；不一致，就自然引出下一个知识点。这比直接讲“初始化很重要”有力得多，因为观众亲眼看到了一个具体的“不对劲”。

4. 用一个心智模型统领全局

面向一般观众时，他不罗列知识点，而是给几个能反复调用的模型：

  • “大语言模型就是两个文件”“一个 1TB 的有损 zip 文件”。
  • 聊天气泡底下是一条一维 token 序列，上下文窗口是工作记忆。
  • 参数里的知识是模糊回忆，上下文里的是工作记忆。
  • ChatGPT 的回答是“一个标注员在神经网络里的即时模拟”。
  • 课本讲解、例题、练习题，对应预训练、监督微调、强化学习。
  • “瑞士奶酪”：大部分地方很强，随机有洞。

这些模型的用处在于能推出行动：既然上下文是工作记忆，就把原文贴进去；既然每个 token 计算有限，就让它写代码；既然有洞，就要核实。观众记住一个模型，就能自己推出十条建议。

5. 同一个问题，给多条路，再比较

  • bigram 先用计数做，再用神经网络做，得到完全相同的损失和采样结果，最后证明 W 就是那张计数表（makemore 1）。
  • 拼接嵌入用 cat、unbind、view 三种写法，顺着 view 讲到张量的存储结构（makemore 2）。
  • “对过去求平均”写三个版本：for 循环、矩阵乘法、softmax，第三版直接通向自注意力（Let's build GPT）。
  • tanh 先当整体实现，再拆成 exp 和除法，结果一样，说明“原子操作”的粒度是自己定的（micrograd）。

多条路走到同一个终点，观众会真正相信两种说法是一回事，也知道每种写法的取舍。

6. 从极小的例子出发，再一次放大

先用 emma 一个名字的 5 个样本，每个都能打印出来逐一检查，确认没问题再换成 22.8 万个，代码一行不改。矩阵乘法的反向传播，用 2×2 的 $D=AB+C$ 在纸上展开；广播的坑，用 3×3 矩阵演示；BPE 先用维基百科上 aaabdaaabac 的例子。

小例子的作用是让观众能“在脑子里跑一遍”。规模放大时，观众已经知道每一步在做什么。

7. 保留错误，甚至制造错误

  • 真实的失误他不剪：闭包写成了函数调用、忘了 zero_grad（“这辈子第 20 次犯，还是在镜头前”）、张量忘了移到 GPU、采样时 BatchNorm 还在训练模式。
  • 他也会故意设计错误：b = a + a 的梯度覆盖、去掉 keepdim=True 后的广播错误、BatchNorm 对三维输入只在第 0 维求均值。
  • 在面向一般观众的视频里，他展示产品的失败：深度研究漏了 xAI、数据分析悄悄把 N/A 换成 0.1、模型说 9.11 比 9.9 大。

每个错误之后都跟着“为什么错、为什么错了还能跑、怎么发现的”。观众学到的是调试的方法，这比正确答案更可迁移。错误也让他显得真实，观众会觉得“原来高手也这样”。

8. 明确区分事实、推测和偏好

他的视频里有大量这类句子：“5/3 这个数从哪来我不知道”“RLHF 为什么有效，这只是我最好的猜测”“这个解释我没读过论文，是别人告诉我的”“我不喜欢这个层”“我更喜欢 tiktoken 的做法”“这是个人风格”。还有在描述里写“我希望当时说了的几件事”，并标出口误的时间点。

这种区分让他的确定判断更有分量：观众知道他说“是”的时候是真的有把握。对知识类内容来说，这是长期信任的来源。

9. 新知识挂在旧知识上

系列内部的回收很密集：tanh 的导数 $1-t^2$ 在第 1 集写过，第 3 集用它解释饱和为什么杀死梯度；残差连接为什么有效，回到第 1 集“加法平均分配梯度”；LayerNorm 直接改第 3 集 BatchNorm 的一个维度；logits 被解释成“对数计数”，接上第 1 集的计数表；正则化被解释成“平滑”。

这让系列像一个整体，也让观众每次都有“原来是这样”的回报。代价是后面的视频门槛越来越高，播放量也随之递减。

10. 原理最终要变成行动

技术视频的结尾总有可以做的事：打败 2.17 的验证损失、读 Bengio 的论文、做 trigram、写自己的 GPT-4 分词器、训练 GPT 做加法。一般观众视频则把原理翻译成使用习惯：换话题开新对话、把原文贴进去、算数让它写代码、拼写任务别直接问、YAML 比 JSON 省 token、提示末尾别加空格。

看完能做点什么，观众才会觉得时间花得值。

四、两种视频的结构模板

模板 A：从零构建（Zero to Hero 型）

  1. 动机：为什么要做这个（上一集的局限，或一个大家关心的产品）。
  2. 终点预览：成品长什么样，或参考实现能做到什么。
  3. 最小基线：最简单能跑的版本（bigram、懒加大上下文），记下一个指标。
  4. 一个核心技巧单独讲透：用玩具例子（3×3 矩阵、小表达式），必要时给几种写法。
  5. 逐个加组件，每加一个报一次指标：2.5 → 2.4 → 2.28 → 2.24 → 2.08 → 2.06 → 1.48；或 1000 → 333 → 300 → 130 → 96 → 93 毫秒。
  6. 中途出问题：效果变差、bug、和预期不符，借此引出下一个概念。
  7. 接回真实世界：对照 PyTorch 源码、nanoGPT、论文的超参数表、GPT-3 的规模。
  8. 收尾：总结学到的、坦白没做到的、留一个可以挑战的数字和练习。
  9. 视频之外：GitHub 仓库（每步一个提交）、Colab、练习、勘误。

模板 B：给一般观众的心智模型（Deep Dive 型）

  1. 一个贯穿的问题：“输入框后面是什么，你在和谁说话”。
  2. 按流程分阶段：预训练、监督微调、强化学习，每段先讲“做什么”，再讲“为什么”。
  3. 每个阶段配现场演示：在 Hyperbolic 上玩基础模型、在 Tiktokenizer 里看 token、在 ChatGPT 里问 9.11。
  4. 插入“心理学”章节：幻觉、自我认知、需要 token 来思考、拼写、参差不齐的智能。每条都给出使用建议。
  5. 一个主类比，放在最合适的位置：教科书类比放在讲完两个阶段之后，用来引出第三个。
  6. 展望和资源：未来趋势、怎么跟进、在哪里用。
  7. 回答开头的问题：把全部内容收束成一段话。

《怎样使用 LLM》是模板 B 的实用变体：开头复习底层模型，然后按功能逐个讲，每个功能都是“我的真实例子 → 怎么用 → 什么时候用 → 哪里会出错”。

五、语言和表达习惯

  • 口语化，第一人称，大量 “let's”。“我们来写”“我们看看会发生什么”。观众是一起做事的人，而不是听课的人。
  • 短句、可记住的说法。“其余都是效率”“非常昂贵的自动补全”“模型需要 token 来思考”“你在和一个标注员的模拟说话”“RLHF 不是 RL”“瑞士奶酪”“vibe coding”。每句背后都有一段推理，它们是观众转述和传播时会用的句子。
  • 类比少而准。整体上他讲得很直接，类比只在关键处用一次，并且马上落到代码或演示上：query 是“我在找什么”，key 是“我有什么”；dlogits 是推力和拉力。
  • 不怕带情绪。“这张图像刀子扎眼睛”“分词是我最不喜欢的部分”“我被 BatchNorm 坑了无数次”“PyTorch 文档会骗你”“看到这个直方图你会冒汗”。
  • 幽默来自真实。“恭喜 Scale AI 团队 2025 年成为 2 万亿美元公司”“可惜没多睡一会儿”“不是因为我是霉粉，不过她挺酷的”。
  • 给具体数字而不是形容词。140GB、500 行 C、6,000 块 GPU、12 天、200 万美元；600 美元一天复现 GPT-2；10TB 文本压缩 100 倍。
  • 说出具体的人、产品、工具名，并给态度。FineWeb 博客、Lambda、Together、Hyperbolic、LM Studio、SuperWhisper、Perplexity、Cursor。他推荐也吐槽，所以推荐可信。

六、制作和配套

制作很轻

  • 场景：酒店房间（Intro to LLMs 在感恩节假期的酒店，WaveNet 在京都），背景随意。
  • 画面：屏幕录制为主，空白 Jupyter、VS Code、Excalidraw 白板、浏览器里现场操作。没有动画和花哨剪辑。
  • 长度：讲完为止，不为平台节奏压缩。
  • 录完的不完美直接保留，口误在描述里更正。

准备工作却很重。《Intro to LLMs》的幻灯片他说花了一整个长周末；复现 GPT-2 需要提前跑通全部代码、租 8 卡机器、跑一夜训练；每一集的代码都有完整的 git 提交历史。轻的是形式，重的是内容。

视频之外的资产

  • 代码仓库：micrograd、makemore、nanoGPT、minbpe、build-nanogpt、llm.c。build-nanogpt 每一步都是一次提交，可以逐步对照视频。
  • Colab 笔记本：从 makemore 2 开始提供，“不需要安装任何东西”。
  • 练习：每集描述里有习题，第 4 集干脆说“这条视频不是用来看的，是用来做的”。
  • 社区：Discord 频道。
  • 白板文件：Deep Dive 和 How I use LLMs 的 Excalidraw 原文件公开。
  • 完整的章节标注：每条视频描述里都有细到几分钟的章节，长视频可以跳着看。

这些资产让一条视频变成一门可以反复使用的课，也让他的内容在视频之外持续被引用和分享。

七、数据给出的几点提示

  • 时机加深度最强。播放最高的两条都是“大家正关心的话题”加“讲得最透的版本”。只有时机没有深度，或只有深度没有时机，都到不了这个量级。
  • 入门的那一集决定系列上限。micrograd 431 万，后面的 makemore 逐级减少。系列第一集要能独立成立，让没看过前面的人也能进来。他后来的 Let's build GPT 也在开头说“建议先看 makemore”，但内容本身可以独立看懂，结果播放远超整个 makemore 系列。
  • 一般观众视频和硬核视频互相成就。硬核视频给他信用，一般观众视频把信用变成影响力。
  • 即兴实验不涨量但有价值。Stable Diffusion 短片只有几万播放，但它们展示了他对新工具的好奇和动手速度，属于“人设”的一部分。

八、对做中文知识类内容的你：可以怎样借鉴

可以直接照做的

  1. 每期先写出“开头的问题”和“结尾的回答”，再填中间。确保观众第一分钟就知道要去哪儿。
  2. 每个重要结论配一个现场演示或可复现的例子。代码类就跑代码；工具类就当场操作；概念类就找一个具体的小例子算一遍。
  3. 养成“先说预期，再看结果”的讲法。“我猜它会……我们看看。”差距本身就是内容。
  4. 为整个栏目设计三五个统领性的心智模型，在每期里反复调用，并让它们推出具体的使用建议。
  5. 保留真实的卡壳和错误，只要你接着讲清楚原因。这对讲课录屏尤其适用。
  6. 明确标注三类话：我确认的事实、我的推测、我的个人偏好。这和你现在笔记网站“依据录像整理、不编造”的原则是一致的。
  7. 把内容挂在你已有的作品上：笔记网站、动手练习、往期视频，让每期都能回收前面的知识，也让观众自然地去看更多。
  8. 每期给一个能做的动作：一个练习、一个可以挑战的数字，或一条马上能用的建议。
  9. 视频之外配资产：笔记网页、代码、练习、勘误。你的 frontier-ai-courses 网站已经是这样的资产库，可以和视频互相导流。
  10. 描述里写详细章节，长视频可跳读，也方便被引用。

需要调整的

  • 信任基础不同。他的判断有人信，因为他亲手做过 GPT。还没有这种背景时，用“可验证”来补：引用原始资料（论文、课程录像、官方文档）、给出可运行的代码、说明自己怎样核对过。你的笔记网站已经在用“依据录像整理”的方式，这条路是对的。
  • 中文平台的节奏。3 小时的视频在 YouTube 能到千万，在国内平台未必。可以保留“讲透”的完整版，同时把每个章节剪成能独立成立的短片，短片的结尾指向完整版和笔记网页。他每条视频的章节划分本身就适合这样拆。
  • 系列的门槛。做系列时，第一集要能独立看懂，并且尽量选大家正关心的话题做入口。后续集数会递减，这是正常的，不必为此改变深度。
  • 情绪和吐槽要基于具体体验。他的吐槽之所以不讨人厌，是因为每次都有具体的事例（某个页面、某个参数、某个报错），并且同时给出替代方案。
  • 类比的使用。他的类比很少，而且只在关键处出现一次，就落到代码或演示上。这和“不要用太多类比，要简单直接地讲清楚”的要求是一致的，可以把他当成正面例子。
