怎样使用 LLM

不要把聊天机器人当作一个会背答案的人：先辨认模型、上下文与工具，再让它成为可核验的工作伙伴

演讲：Andrej Karpathy · 发布：2025 年 2 月 27 日 · 时长：2 小时 11 分
资料来源：How I use LLMs（本文依据公开视频英文自动字幕和章节整理）

一、先建立正确的心智模型

Karpathy 的出发点很朴素：聊天产品看起来像两个人轮流说话，底层却是在共同续写一条 token 序列。用户写入一段 token，模型继续预测 token；聊天程序用特殊标记区分 user、assistant 和系统信息。新建聊天，就是清空这条序列，重新开始一个上下文窗口。

他把预训练模型形容为一个“有损、概率性的互联网压缩包”。预训练把大量文本中的统计结构压进网络参数；后训练再用对话和偏好数据，把它塑造成愿意回答问题的助手。这个比喻不是说模型真的保存了互联网副本，而是提醒读者：模型给出的内容是根据参数中的模式生成的回忆，不是对某个资料库的逐字检索。

这也解释了知识截止日期和幻觉。昂贵的预训练不会每天重做，罕见、刚发生或需要精确数字的事情尤其不应只依赖模型的内部知识。对常见、稳定、低风险的问题，模型可以是很好的第一问；对医学、财务、法律、产品规格和重要决策，则要回到原始资料或专业人士核验。

上下文不是免费记忆

上下文窗口相当于当前任务的工作记忆。无关的旧对话会占用注意力、使模型偏题，也会增加推理延迟和成本。因此切换任务时应开新聊天；只有之后的问题确实依赖前文时，才保留同一条对话。这个习惯比反复追加“请忽略之前的内容”更可靠。

二、先看自己实际在用什么模型

视频录制于 2025 年初，界面和订阅档位已经可能改变，但判断方法仍然适用：免费档通常有较小、较快、额度更有限的模型；付费档才可能提供更强模型、更高消息上限、联网、推理或研究功能。不要只看产品名，也要看当前会话的模型选择器、功能开关和额度说明。

Karpathy 会交叉询问多个模型，把它们当作一个“LLM council”。这并不等于少数服从多数：它的用途是发现不同答案、获得不同检索路径，或找出值得进一步查证的假设。对于旅游、构思、写作和非关键的判断，这种并行视角很有价值；对于事实问题，最终证据仍应来自可点击、可追溯的来源。

推理模型何时值得等

推理模型会在回答前生成更多中间 token，常通过强化学习学到检查假设、尝试不同路线和回退等策略。它们更适合数学、代码、逻辑与需要多步约束的困难问题；代价是更慢、也通常更贵。Karpathy 的建议是先用普通模型快速尝试，答案不可靠或任务明显困难时，再打开 reasoning/thinking 模式，而不是为每次简单问答都等待漫长推理。

他用梯度检查失败的代码作演示：普通模型列出许多可能性，推理模型则花时间检查参数打包和解包的顺序，找到了真正的错配。这个例子说明“思考更久”可能提高成功率，但不构成正确性保证；仍应运行测试或最小复现验证补丁。

三、给模型工具，别要求它假装全知

1. 搜索：处理最新和可变的信息

联网搜索的工作方式是：模型提出查询，应用执行搜索、读取网页，再把结果文本与来源放入上下文，模型据此组织回答。它适合新闻、日程、公司产品、股市、旅行风险和小众问题。若你已知道问题依赖近期信息，主动打开搜索比等待模型自行判断更稳妥。

搜索回答里的引用不是装饰：应该打开关键来源，检查它是否真的支持结论、日期是否合适、是否只是二手转述。搜索只是在模型原有记忆之外加入了材料，并不会自动消除误读、错引或把多份来源混在一起的风险。

2. 深度研究：一份起点，不是一份结论

深度研究将长时间搜索、阅读和推理组合起来，产出带引用的长报告。视频用补充剂成分为例：先明确希望覆盖人体研究、动物研究、作用机制和安全性，再让系统查找资料。它特别适合比较产品、初步了解陌生领域、列出论文与争议，但花几分钟得到的报告只能当研究草稿。

Karpathy 特意展示了失败案例：要求列出美国主要 LLM 实验室时，报告遗漏重要对象，也混入不符合筛选条件的组织。这正是使用方式的边界：用它快速建立问题地图、收集待读来源和追问方向，不用它替代自己的筛选、原文阅读和事实核对。

3. 上传文件：把具体材料放进工作记忆

对论文、PDF、书中章节或自己的文档，与其问模型“你记得这篇吗”，不如直接上传或粘贴相关段落。先要求摘要、术语表或论证结构，再沿着阅读过程逐项追问，会比单独读陌生领域资料更容易保持理解。上传后的解析可能丢失版式、图片或公式细节，所以涉及图表、扫描件或精确引文时，应先让模型转录关键内容并人工核对。

四、代码工具能把语言模型变成执行者

Python、数据分析与图表

大数计算不该交给纯文本生成。带 Python 或其他解释器的产品会让模型写程序、运行程序、把输出回填上下文，再据此回答；这比它在“脑中”估算可靠得多。不同产品接入的工具不同，缺少解释器的模型可能给出看似接近却错误的算术答案，因此应确认工具调用记录和实际输出。

ChatGPT 的 Advanced Data Analysis 一类功能可以整理表格、写绘图代码和生成图表。Karpathy 把它比作能力很强但容易疏忽的初级分析师：演示中模型把缺失年份默默设为一个数值，又在趋势外推的文字说明里报错数量级。实用原则是检查数据来源、查看它实际执行的代码、追问隐含假设，并用独立计算验证关键数字。

Artifacts 与代码 Agent

Claude Artifacts 一类功能会把生成的前端代码直接在浏览器中运行，适合小型闪卡工具、交互图、流程图和一次性原型。它不是完整的线上产品：通常没有可靠后端、数据库、权限、测试和持续维护。把它当作沟通想法和快速试用的界面，而不是自动可上线的软件。

真正的代码库需要能读文件、改多个文件、运行命令和查看测试的代码 Agent。Karpathy 展示 Cursor 的 Composer 在本地 React 项目中创建井字棋、安装依赖、修改样式和添加效果；也特别指出外部命令、下载文件和 Git 提交等动作应由人确认。所谓 vibe coding 可以显著压缩样板工作，但代码所有权没有消失：开发者仍要读 diff、运行测试、检查依赖来源和回滚异常改动。

五、多模态：输入输出不再只有文字

语音：转写与原生语音是两件事

最容易使用的是语音转文字：手机内的麦克风或系统级听写先把语音转成文本，再像普通聊天一样发送；文字回答再可选地由 TTS 朗读。Karpathy 的建议是日常问题尽量直接说，以降低输入摩擦；人名、库名和精确拼写仍值得手动检查。

Advanced Voice Mode 则让模型直接处理音频 token，而非只处理转写文本。这样它可感知停顿、语气等音频信息，并实时说话、讲故事或调整表达方式。产品会不断调整功能和安全边界，演示中出现的具体声音和模式不应被视为现行承诺；更稳定的判断是区分“语音只是输入法”与“音频是模型原生模态”。

NotebookLM：用材料生成可听的概览

NotebookLM 把上传的文本、网页或 PDF 作为来源，可在其上问答，也能生成双人播客式的音频概览。它适合散步或通勤时预览不熟悉的论文和主题，但同样要把音频当作导航：它帮助判断哪些部分值得回到原文深读，不能替代原文和引用。

图像与视频：先确认模型看到了什么

图像可被切成视觉 token 并进入上下文。对营养标签、表格、化验单、公式截图或字幕，Karpathy 推荐两步走：先让模型转写为结构化文本，人工确认数字和字段，再要求解释、分类或提出问题。医疗材料尤其如此：它可以帮助准备与医生讨论的问题，却不应替代诊断。

图像生成适合缩略图、图标与概念图；视频输入可以用手机摄像头指向物品并提问，视频生成则能从提示词合成短片。两者都可能失真、误认或产生版权和隐私问题。不要上传他人的敏感资料，也不要把生成画面当作现实证据。

六、把重复工作变成个人工具

跨会话的 memory、custom instructions 和 custom GPT 解决的是不同层次的问题。记忆是产品保存的用户偏好摘要，通常会被加入后续对话；需要定期检查、编辑或删除。自定义指令是每次对话都附带的全局偏好，例如回答风格或学习语言时的默认语体。它们都会影响输出，因此不应写入密码、身份信息或不愿在未来对话中出现的内容。

Custom GPT 的本质通常是把一份经常复用的提示词保存为可重复启动的任务。Karpathy 用韩语学习举例：一个 GPT 从句子抽取可导入闪卡软件的词汇；另一个先整体翻译，再逐项解释；第三个对电视剧字幕截图做 OCR、翻译和拆解。核心技巧不是神秘功能，而是清楚描述任务、规定输出格式，并提供几组“输入—理想输出”的 few-shot 示例。

一个可复用的设计模板

  1. 明确每次变化的输入与保持不变的任务目标。
  2. 给出所需输出的字段、顺序和语言，不只说“翻译得详细一点”。
  3. 加入少量有代表性的正确示例，覆盖常见边界情况。
  4. 用真实输入测试；发现不稳定之处后，修改指令或补一组示例。
  5. 为涉及 OCR、事实、计算或敏感领域的步骤保留人工复核点。

七、把整套工作流压缩成一张检查表

  • 稳定、低风险、常见的问题：先用普通聊天模型；把答案当作有用的初稿。
  • 困难的代码、数学和逻辑任务：再尝试推理模型，并用测试、计算或反例验证。
  • 最新、可变或小众的事实：开启搜索，打开并核对引用链接。
  • 需要系统比较的陌生主题：用深度研究收集来源和争议，再读关键一手材料。
  • 正在读的材料：上传相关页面；先确认转录和摘要，再沿阅读过程追问。
  • 精确计算、数据和图表：使用解释器，但要检查数据、代码、单位、缺失值和假设。
  • 重复出现的个人任务：把经过验证的提示词、格式和示例封装成自己的工具。

视频的主线不是推荐某一个网站。产品、模型名、订阅和按钮都会变化；更耐用的能力是辨认任务需要的是内部知识、外部证据、计算、文件上下文还是多模态输入，并在人与工具之间保留恰当的验证环节。
