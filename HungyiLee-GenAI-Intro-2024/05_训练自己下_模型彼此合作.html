第5讲：提示技巧（下）：让模型彼此合作

用一个模型给其他模型分配任务（FrugalGPT），让模型互相讨论代替自我反省，讨论的几种组织方式，用裁判模型判断讨论何时结束，用提示词让模型敢于反对，给模型分配不同角色组成团队并给团队“打考绩”，以及由 AI 组成的小镇

主讲：李宏毅（Hung-yi Lee，台湾大学电机系）· 上课日期：2024 年 3 月 22 日 · 时长：25 分钟 · 整理：Joyce（@JOYCE9896）
资料来源：课堂录像（台大公开，2024 年春季，本文依据录像字幕整理）· 投影片（原件在 Google Drive，此处链接课程主页）

这一讲的内容

这是“在不训练模型的情况下强化语言模型”这条线的最后一讲。前两讲讲的都是怎样对一个模型下提示词：神奇咒语、补充信息、拆解任务、让模型反省、使用工具。这一讲把单个模型换成多个模型，问的是：手上有好几个语言模型时，怎样让它们合作，得到一个模型单独做不到的结果。

他从《葬送的芙莉莲》动画里芙莉莲和弟子费伦合作打败芙莉莲复制体的剧情讲起，引出“合作”这个主题；然后依次讲分配任务的模型、模型之间的讨论（用 Claude 和 GPT-3.5 讨论怎样把“葬送的芙莉莲”译成英文的现场演示）、讨论的组织方式和停止条件、给模型分配不同角色组成团队，最后提到由语言模型村民组成的虚拟小镇。

01. 开场：芙莉莲和她的复制体

录像位置 0:00:00–0:03:18

他说今天的故事要从最近几集的《葬送的芙莉莲》讲起，并先把剧情复述一遍（视频标题里也提醒了开头有剧透）。这几集里，芙莉莲和其他魔法使（包括她的徒弟费伦）在考一级魔法使资格，其中一关是攻略一座迷宫（字幕作“灵洛的王座”，即零落王墓）。迷宫里有“水镜恶魔”，它能复制进入迷宫的人的能力，于是复制出一个芙莉莲的复制体来防卫迷宫。复制体没有颜色，可以和本体区分开。

芙莉莲是活了上千年的魔法使，全力施展时没人打得过她，就算她自己也不一定打得赢自己的复制体。但她相信自己和费伦一起上就能赢。费伦是她的弟子，是人类，只学了几年魔法。

接下来他故意把剧情讲歪：本体和复制体互放雷、放火，还用上了“地爆天星”“螺旋手里剑”之类的忍术，芙莉莲最后用神之卡召唤出欧贝利斯克巨神兵；费伦从背后偷袭复制体，打断了它的手，复制体“瞪眼壁咚”一下，费伦飞出去粘在墙上晕倒，他说那其实是六道佩恩的忍术“万象天引”；复制体因此露出破绽，被芙莉莲一击击倒。（这些是他混入的《火影忍者》《游戏王》梗，用来逗乐。）

然后他收回来：这个故事说明合作的重要性。千年魔法使也可能有致命破绽，和一个人类合作，能发挥本来发挥不了的力量。GPT-4 能力很强，但如果和其他语言模型合作，可以得到一加一大于二的效果。怎样让模型彼此合作，有很多方式，下面逐一讲。

02. 让合适的模型做合适的事：分配任务的模型

录像位置 0:03:18–0:05:43

一个专门判断“交给谁”的模型

第一种合作方式：手上有一堆语言模型，它们能力不同，使用成本也不同，比如 GPT-4 的价格比 GPT-3.5 高很多。可以再训练一个模型，它可以是语言模型，也可以不是，它的工作只有一件：新任务进来时，判断这个任务该交给哪个模型处理。比如它决定交给模型 A，任务就送给模型 A，用户看到的是模型 A 给的答案。

GPT-4 已经最强了，为什么还要合作

他预想有人会问：GPT-4 可能已经是最厉害的模型，它跟其他模型合作有什么意义？他的回答是，GPT-4 有一个大缺点：太贵。输入是比较简单的问题时，这个分配工作的模型可以判断问题太简单，用不着 GPT-4（他用了“杀鸡焉用牛刀”这个说法），交给便宜的模型就够了。

他还说，今天在一些语言模型的展示平台上，你没办法确定为你服务的是不是同一个模型。有些平台已经在用这种让模型合作的技术，你问不同的问题，真正出来回答的可能是不同的模型，只是作为用户很难察觉。

想知道怎样用一个模型主导、决定哪些模型出来做事，他推荐论文 FrugalGPT（arXiv 2305.05176），并说他过去上课的录像专门讲过这个技术。这类方法可以让模型合作，达到比 GPT-4 更好的效果，成本还更低。

YouTube 说明里他补了一条：这听起来有点像 Mixture-of-Experts（MoE），但不是。MoE 要改动神经网络本身的架构，这部分要等课程讲完神经网络再谈。

03. 从反省到讨论：Claude 和 GPT-3.5 翻译“葬送的芙莉莲”

录像位置 0:05:43–0:11:27

反省是自问自答，讨论是两个模型轮流

他先回顾前面讲过的“让模型反省”：有一个任务输入，语言模型得到一个输出，再把输出给自己看一遍，问自己这个输出对不对；反省之后也许会得到不同的输出。反省的过程只有模型自己跟自己自问自答。

换成两个模型就是讨论：语言模型 A 先给一个答案，语言模型 B 根据 A 的答案产生新答案，A 再根据自己之前的答案和 B 的答案产生新答案，这样来回就形成类似讨论的过程。他说这张幻灯片可能有点抽象，所以接着给了一个具体演示。

现场演示：把“葬送的芙莉莲”译成英文

起因是 PTT 的 C_Chat 版有人问“葬送的芙莉莲”应该怎样翻成英文。官方英文名是 Beyond Journey's End，但这个名字没有把“葬送的”这几个字翻出来。他想看大型语言模型会怎么翻。

  • 第一轮，Claude：给它任务（把“葬送的芙莉莲”翻成英文）和故事梗概。对 Claude 来说这很容易，它给出 The Buried Laurel。他评价这是很直白的翻译，直接把“葬送”翻成 Buried。
  • 为什么选 GPT-3.5 做对手：他说没有找 GPT-4 或 Gemini，因为它们可以联网搜索，一搜就会知道官方译名，那就没意思了。所以让 Claude 3 和 GPT-3.5 讨论。
  • 第二轮，GPT-3.5：同样给任务和漫画故事梗概，再附上 Claude 3 的答案，说“我先提供另一个可能的答案给你参考”，问它有没有更好的翻译，有的话请提供。提示词里特别加了一句括号：你不需要完全同意我的看法。他说这句括号很重要，不加的话 GPT-3.5 很容易回一句“你的翻译实在太棒了”，讨论就结束了。GPT-3.5 给出 Entombed Frieren（字幕写作 Fleuriem），理由是 Entombed 传达了被埋藏、被困住的意象。
  • 第三轮，Claude：把 GPT-3.5 的答案交给 Claude，同样问有没有更好的翻译。Claude 给出 Frieren's Atonement。
  • 第四轮，GPT-3.5：再把 Claude 的翻译交给 GPT-3.5，它给出 Frieren's Redemption。
  • 第五轮，Claude：Claude 说 Frieren's Redemption 是很好的翻译，比之前提出的 Entombed、The Buried 和 Atonement 几个版本都好，是一个极佳的英译。讨论到这里结束，两个模型得到了它们都觉得最好的翻译。

他随后说明：这个翻译不一定是最好的。“葬送”有好几层意思，本来就不好翻，他觉得模型的翻译也没有切中要害。这个演示只是想让大家看到，两个语言模型讨论事情时大概是什么样子。（字幕里的英文译名有听写错误，这里按读音写成 Frieren。）

真实使用时不需要人搬运对话

演示里是他手动把一个模型的回答复制给另一个模型。他强调实际做的时候不需要人在中间搬来搬去：作业三已经教过怎样通过 API 调用语言模型，完全可以写一个程序，让两个模型直接对话、彼此讨论。这里手动搬运只是为了展示。

04. 讨论为什么比反省有用，模型越多越好吗

录像位置 0:11:27–0:13:09

反省很少推翻自己

他引用一篇 2023 年 5 月的论文（arXiv 2305.19118），对“自我反省”和“多模型讨论”做了比较。图的纵轴是每一次互动时，语言模型推翻先前答案的可能性（图上标为 Avg. Disagreement）；横轴是互动次数，从 1 到 5。

结果是：自我反省时（图中 Self-Reflection），模型推翻自己之前答案的比例比较低。他说这很好理解，之前的答案就是模型自己给的，它大概挺认同，所以不管反省几次，推翻的次数都有限。多模型讨论时（图中 Multi-Agent Debate），模型能接收到另一个模型的输入，也就是新的刺激，推翻之前错误答案的机会更高。

模型越多、回合越多，正确率越高

另一篇论文（arXiv 2305.14325）让多个模型一起解数学题，纵轴是解题正确率。左图横轴是参与讨论的模型数量：模型越多，最后得到正确答案的概率越高（图上从 1 个模型约 67% 升到 7 个模型约 95%）。右图横轴是讨论回合数：回合越多，结果越好，这也符合直觉。

但讨论很多回合也可能没用。这篇论文最后停在四个回合，因为三个回合和四个回合的结果已经很接近了。

05. 多个模型用什么方式讨论

录像位置 0:13:09–0:14:48

模型一多，就出现新问题：用什么方式讨论？他介绍论文 Exchange-of-Thought（arXiv 2312.01823），这篇论文尝试了几种讨论方式。他说不用深究，只是想让大家知道讨论可以有各种变化。以三个模型 A、B、C 为例（幻灯片上的四种结构名称为 Memory、Report、Relay、Debate）：

  • 每个模型都贡献一个答案，所有答案汇整在一起，每个模型都能看到所有人的答案（Memory，Fully Visible）。
  • A 是老板，B 和 C 是下属，B 只向 A 汇报，C 也只向 A 汇报，B 和 C 之间没有交流（Report，Central Visible）。
  • A 把结果交给 C，C 交给 B，B 再交回 A，像接力（Relay，Neighbor Visible）。
  • B 和 C 彼此讨论、辩论，A 像裁判，评断 B 和 C 谁说得好（Debate，Peers Visible）。

哪种方式最好？他说现在不用去记，因为这篇论文的结论是没有找到最好的方式，不同任务最合适的讨论方式不一样。怎样让模型讨论得最有效，还是一个研究中的问题。

06. 讨论怎样停下来：裁判模型和“反对”的提示词

录像位置 0:14:48–0:17:13

裁判模型

让模型讨论，还要决定讨论什么时候结束、不同模型是否已经达成共识、可以得出最终结论。这时需要引入一个裁判模型。模型 A 和模型 B 各自提出意见，裁判模型读完两者说的话后发表评论；如果它认为没有达成共识，讨论就继续。

具体做法很简单：把 A 和 B 说过的话贴给裁判模型，问它这两个模型有没有达成共识，没有就说没有，有就说有。他说以今天大型语言模型的能力，往往能相当准确地判断两段输出是否一致。幻灯片上的流程是：A 说“我觉得……”，B 说“我不同意……”，裁判判定“未达成共识，讨论继续”；A 再说“那我觉得……”，B 说“有道理……”，裁判判定“达成共识，结论是……”。裁判模型也可以根据讨论过程做摘要，给出最后的答案。

真正的麻烦是讨论太早结束

他预想有人担心：讨论会不会一直停不下来，大家莫衷一是、无法达成共识？他说现阶段不用担心这个，要担心的反而是讨论太快结束、根本讨论不起来。因为这些语言模型现在被训练得“温良恭俭让”，有人质疑它的想法时，它很容易退缩。所以让模型讨论时，一定要下合适的提示词，刺激它、逼它反对对方的想法。

两篇论文的发现：

  • arXiv 2305.19118 试了不同程度的“反对”提示词（幻灯片上列出 Level 0 到 3）。最强的一级是叫模型“为反对而反对”，对方说什么都反对（Level 3：双方必须在每一点上都不同意，不能有任何共识），这样不一定得到最好的结果。最好的是告诉它不需要完全同意对方的看法，可以表达自己的意见（Level 2，也是论文的默认设置：It's not necessary to fully agree with each other's perspectives, as our objective is to find the correct answer）。这样讨论进行得最顺利。
  • arXiv 2305.14325 有类似发现：如果叫模型“根据另一个模型的意见来回答”（Based off the opinion of other agents），讨论会很快结束；如果说“另一个模型的看法当作参考就好”（Using the opinion of other agents as additional advice），讨论会更热烈、持续更久。论文也发现比较长的讨论能得到比较好的结果。

前面演示里那句“你不需要完全同意我的看法”，用的就是这个思路。

07. 团队需要不同的角色

录像位置 0:17:13–0:21:16

勇者小队和“七步之内”

他说一个团队里有不同角色，也许运作得更好。常见的勇者小队组成是：负责远程输出的魔法使、负责“奶”（治疗）的僧侣、负责近身攻击的剑士、负责“坦”（扛伤害）的矮人。

接着他讲了漫画最新连载的一段剧情，先郑重提醒有剧透、不想听的把耳朵捂起来，并说明看动画的观众还没看到这一段。剧情是有人要去暗杀芙莉莲的师祖赛莉耶（字幕作“施主”）。其他人觉得不可能，赛莉耶是上古时代的“大神”，有毁天灭地的大能。芙莉莲说还是有可能的：“七步之外，魔法快；七步之内，斧头快”，一个人类杀手只要接近赛莉耶，还是杀得了她。她举例说，只要在七步之内，修塔尔克取费伦的首级如探囊取物；费伦听了很害怕，躲到芙莉莲背后，修塔尔克则很受伤。暗杀有没有成功，连载还没演到。

他由此说：团队里需要不同的角色，彼此合作才能发挥大的力量。讨论时也可以引入不同能力的模型扮演不同角色。

用语言模型组成项目团队

假设任务是让大型语言模型写程序、完成一个项目。项目里也许需要一个主导进度的 project manager，一个写程序的，一个做测试的。可以让不同的语言模型扮演这些角色。怎样让模型扮演不同角色，他给了两种方式：

  • 模型本来就有不同专长。比如 Code Llama，做一般任务可能不如其他大型语言模型，但它特别擅长写代码，他形容它是个“肥宅工程师”，可以扮演工程师的角色。
  • 直接用提示词告诉模型“你是一个 project manager”“你是一个 programmer”“你是一个 user”。模型读了这些提示词后，也许就能发挥不同的潜力，变成不同的角色。

多个模型合作的流程是：把项目交给 AI project manager，它做好规划（先做 A，再做 B，然后 C……）后交给 AI programmer；programmer 写好程序后交给负责试用的 AI user；user 把测试结果和建议（比如“加上某某功能”）交回 project manager，由它决定下一步怎么规划。

他说这并非不可能，幻灯片上引用了相关论文（arXiv 2303.17760）。如果真能让语言模型彼此合作，每个人都可以当一家公司的 CEO，带领一支由语言模型组成的团队，“把一个人活成一个团队”。（YouTube 说明里他注明，这句话是从罗振宇 2024 年跨年演讲听来的。）

08. 优化团队，以及现成的模型团队项目

录像位置 0:21:16–0:23:39

给模型打考绩

除了组建团队，还可以优化团队。他引用 2023 年 10 月的论文 Dynamic LLM Agent Network（arXiv 2310.02170）。他说这个优化方式说穿了就是“打考绩”：根据刚才的工作内容，问每个语言模型觉得其他成员做得怎样，让它给其他模型打分（幻灯片示例：Programmer: 10，User: 8；Project manager: 7，User: 9……）。把分数加起来，分数低的以后就不让它参与工作。

他提醒，这些都是学术论文，测试的多是比较简单的任务。语言模型团队在真正复杂的任务上，比如真的开发一个软件项目，能不能成功，还是未知数。

MetaGPT 和 ChatDev

如果想体验带领语言模型团队，已有一些开源项目，比如 MetaGPT 和 ChatDev。里面有各种语言模型“员工”：Product Manager、Architect、Project Manager、Engineer 等。你直接给它们下指令，它们真的会试着做事，至于做得好不好是另一回事。

他说看过一个 YouTuber 用 ChatDev 写网站，还真的去网上接单。ChatDev 背后调用的是 ChatGPT（GPT-3.5 或 GPT-4），所以要花钱，但成本很低，写一个网页只要 1 美元，他对外报价 2 美元。这个 YouTuber 说如果真接到单子，会再录一支视频分享。他说自己一直没有等到下一支视频，看来是没接到。

对未来的设想

他说这种合作更像是语言模型未来能做的事。以现在的能力，让它们组成公司去解决真实世界里很复杂的项目，可能还力有未逮。但这提供了一种设想：将来打造语言模型时，也许不需要一个真正全能的模型，模型可以专业分工；不同团队打造的模型组合成一个团队，每个模型只要专注在自己的专业领域。他说这也许是语言模型未来一个可能的发展方向。

09. 由 AI 组成的社群

录像位置 0:23:39–0:25:20

语言模型能组成公司，再进一步也许能组成社群。他提到 2023 年 4 月 Stanford 发表的论文（arXiv 2304.03442）：他们做了一个语言模型的小镇，所有村民都是语言模型。他说之前的录像讲过，所以只放了链接（YouTube 说明里的延伸阅读《让 AI 村民组成虚拟村庄会发生甚么事？》）。

他强烈推荐大家去看，说语言模型之间还会发展出淡淡的恋爱故事。他还说，如果没听过本课前面讲的各种提示技巧，看那支视频可能会觉得有些难；但现在课上已经讲过各种强化语言模型能力的技巧，看的时候可以想一想，小镇里用到的每个技巧都是到目前为止课上讲过的，所以看到这些 AI 怎样互动、怎样在日常里组成村落，不会觉得太离奇。

最后一张幻灯片回到本系列开头的图：在不训练模型的情况下强化语言模型的五类方法，到这一讲全部讲完。

他是怎么讲的

讲的顺序

开场用将近三分钟讲动画剧情，最后落到一句“合作的重要性”，再把芙莉莲换成 GPT-4、费伦换成其他模型。这样“为什么最强的模型还需要合作”在一开始就有了答案的雏形：最强的也有破绽。

主体按合作方式从简单到复杂排：一个模型分配任务（不交流）→ 两个模型讨论 → 多个模型讨论 → 讨论的结构 → 讨论的停止条件 → 有角色分工的团队 → 优化团队 → 社群。每一步都接在上一步留下的问题上：讨论先从上一讲的“反省”引出（自问自答换成两人对答）；讲完“越多模型越好”立刻问“那么多模型怎么讨论”；讲完讨论方式再问“讨论怎么停”；回答“停不下来”时反转成“停得太快”，引出提示词设计。

演示放在抽象定义之后：先给 A、B 两个方框来回的幻灯片，他自己说“可能有点抽象”，马上接一个具体的翻译演示，演示完再给论文数据支撑。

结尾把这一讲和前四讲连起来：AI 小镇里用的每个技巧都是课上讲过的，同时关上“不训练模型强化语言模型”这一单元，下一讲进入训练。

每个概念用了什么例子

  • 合作的价值 → 芙莉莲和费伦合打复制体，收尾句「这个故事告诉我们合作的重要性 这个铺陈非常的长」（0:02:29）。
  • 分配任务的模型 → GPT-4 太贵，简单问题交给便宜模型，「杀鸡焉用牛刀」（0:04:08）；补充“展示平台上为你服务的不一定是同一个模型”。
  • 模型讨论 → Claude 3 与 GPT-3.5 来回五轮翻译“葬送的芙莉莲”（0:06:35）。
  • 讨论胜过反省 → 论文柱状图，“推翻先前答案的可能性”对比；解释为“之前的答案是它自己的，它蛮认同”（0:11:27）。
  • 讨论结构 → A 当老板、B 和 C 当下属，或 A 当裁判看 B、C 辩论（0:13:09）。
  • 模型太容易让步 → 「因为这些语言模型他们现在的训练 就是温良恭俭让」（0:15:38）。
  • 团队角色 → 勇者小队（魔法使、僧侣、剑士、矮人），以及“七步之内斧头快”的连载剧情（0:17:13）。
  • 模型有不同专长 → Code Llama，「他的专长就是他是个肥宅工程师」（0:19:38）。
  • 优化团队 → 「这个优化团队的方式说穿了也没什么 就是打考绩」（0:21:16）。
  • 模型团队的实际能力 → YouTuber 用 ChatDev 接单，成本 1 美元、报价 2 美元，「但我始终没有等到下一支影片 看来是没有接到案子」（0:22:53）。

简化了什么、跳过了什么

  • FrugalGPT 只讲概念，细节指向他过去的录像。
  • Exchange-of-Thought 的几种讨论结构他明说“不需要深究”“目前还不需要真的去记”，因为论文没找到最好的方式。
  • YouTube 说明里补充：分配任务的做法听起来像 MoE，但不是，MoE 要改神经网络架构，留到讲完神经网络再谈。
  • Generative Agents 小镇不展开，直接给过去录像的链接。
  • 引用论文时只讲图上的结论（纵轴横轴是什么、趋势如何），不讲实验设置。

怎样处理误解和提问

  • “GPT-4 已经最强，和别的模型合作有什么意义？”他先替听众问出来，再用成本回答。
  • “讨论会不会停不下来？”他先认可这个担心，再翻转：现阶段要担心的是讨论太快结束，「现阶段你不需要担心这个问题 你需要担心的是这个讨论太快结束」（0:15:38）。
  • 直觉“模型越多、回合越多越好”他先说这很直觉，再用数据确认，并补一个限制：回合太多可能没用，论文停在四轮。
  • 演示里人在中间复制粘贴，他担心学生以为实际也要这样，专门说明可以写程序用 API 让模型直接对话，并关联到作业三。
  • 演示得出的译名，他说明「当然这个翻译其实不一定是最好的啦」（0:09:52），提醒演示的目的只是展示讨论的样子。
  • 论文结果的适用范围：学术论文多测在简单任务上，复杂项目能不能成还是未知数。

现场演示

  • 工具：Claude 3 和 GPT-3.5，他手动在两边复制答案。不用 GPT-4 或 Gemini 的理由是它们能联网，会直接搜到官方译名。
  • 提示词结构：任务 + 故事梗概 +“我先提供另一个可能的答案给你参考”+“你有更好的翻译吗？如果有的话请提供”+ 括号“你不需要完全同意我的看法”。他点出括号那句的作用：没有它，GPT-3.5 会回「啊你的翻译实在太棒了 然后讨论就结束了」（0:08:13）。
  • 输出依次是 The Buried Laurel → Entombed Frieren → Frieren's Atonement → Frieren's Redemption，最后 Claude 认可 Redemption，讨论结束。
  • 这个括号里的提示后面又被论文结论（Level 2 默认提示最好）印证，演示和论文前后呼应。

其他手法

  • 动漫梗贯穿全讲：开场芙莉莲剧情里故意混进《火影忍者》的“万象天引”“螺旋手里剑”、《游戏王》的“欧贝利斯克巨神兵”，还说水镜恶魔“在三国演义里面也有出现”（司马徽号水镜）。翻译演示的题目也选芙莉莲，中段再用一次连载剧情。
  • 剧透前做足提醒：「以下真的有一个爆雷 你不想听的就真的把耳朵摀起来」（0:18:03），并区分看动画和看漫画的观众。
  • 用职场词汇讲多模型系统：老板与下属、项目经理、CEO、打考绩、接单，听众不需要先懂 multi-agent 这个词。
  • 带金句收尾一个小节：「你就可以把一个人活成一个团队」（0:20:28），出处放在视频说明里。
  • 回扣前面的课：反省来自上一讲，API 调用来自作业三；结尾说小镇里「他其实用的每一个技巧 都是我们到目前为止的课堂上 已经讲过的事情」（0:24:28）。
