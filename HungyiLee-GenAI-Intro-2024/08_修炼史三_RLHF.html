第8讲：修炼史第三阶段：参与实战，打磨技巧

RLHF 的数据和前两阶段有什么不同，从"人怎么出数据"和"模型怎么学"两个角度对比 RLHF 与 instruction fine-tuning，用 AlphaGo 类比语言模型的强化学习，奖励模型（"虚拟人类"）怎么训练和使用、学过头会怎样，DPO/KTO 与 RLAIF，以及"什么叫好"这个难题

主讲：李宏毅（Hung-yi Lee，台湾大学电机系）· 上课日期：2024 年 4 月 12 日 · 时长：37 分钟 · 整理：Joyce（@JOYCE9896）
资料来源：课堂录像（台大公开，2024 年春季，本文依据录像字幕整理）· 投影片

这一讲的内容

这是"大型语言模型修炼史"的最后一段。前两讲讲了第一阶段 pre-train（自我学习）和第二阶段 instruction fine-tuning（名师指点），这一讲讲第三阶段：让模型和使用者互动，在实战中打磨技巧，也就是 RLHF（Reinforcement Learning from Human Feedback，从人类反馈中强化学习）。他要回答：人类的反馈长什么样，模型怎么从"哪个答案比较好"这种信号里学习，这和前两阶段有什么根本不同，以及人类时间有限时怎么把反馈用到最多。

主要例子有：ChatGPT 网页上"这个答案比上一个好还是差"的按钮；让 GPT-4 写"赞扬大型语言模型的七言绝句"；《天龙八部》的珍珑棋局；贯穿后半段的 AlphaGo 类比；《葬送的芙莉莲》里的辛梅尔，用来引出奖励模型（他称为"回馈模型"，也叫"虚拟人类"）；最后是问 GPT-4、Gemini、Claude 怎么做玩具枪，以及问 GPT-4"念博士还是去工作"。结尾他把三个阶段收拢成 foundation model 和 alignment 两个名词，并引出作业六（做 RLHF）。

01. 第三阶段：人类反馈是什么

录像位置 0:00:00–0:01:34

他说第三阶段是让模型真的和使用者互动，在实战中打磨自己的技巧，这就是"鼎鼎大名"的 RLHF。Human feedback 指的是：你在使用模型的过程中会给它很多反馈，告诉它你的喜好。

他举 ChatGPT 网页界面为例：你问一个问题，它给一个答案，如果你不满意，可以按按钮重新生成。每次重新生成后，ChatGPT 会问你：新答案和刚才的旧答案比，比较好、比较差，还是差不多？你回答的时候，就等于给语言模型提供了反馈。语言模型收集到足够的反馈后，会再对参数做微调。

02. 三个阶段的训练数据对比，和强化学习的基本想法

录像位置 0:01:34–0:03:58

三种学习方式

他先复习三个阶段的训练数据（幻灯片把三栏并排）：

  • 第一阶段 pre-train：输入"人工智"，输出"能"。数据直接从网上拿，没有太多人类介入，叫 self-supervised learning，自监督学习。
  • 第二阶段 instruction fine-tuning：输入"USER:你是谁？AI:"，输出"我"。输出由人提供，要人花大量时间收集问题和答案，叫 supervised learning，监督学习。
  • 第三阶段 RLHF：输入"USER: 台湾最高的山是那座？AI:"，两个输出"玉山"和"谁来告诉我呀"，前者好于后者。

第一、二阶段的数据格式很像，都是给模型一个输入，再给出文字接龙时下一步该有的输出。第三阶段的数据很不一样：没有人明确告诉机器下一个该产生哪个 token，机器得到的学习信号是"某个答案好过另一个答案"。通过这种反馈来学习的方法叫 reinforcement learning，缩写 RL，中文是强化学习（他用的是台湾译名"增强式学习"）。

RL 在概念上做什么

当有人告诉语言模型某个答案比另一个好，模型就微调参数，目标是让人觉得好的答案出现的概率高一点，人觉得不好的答案出现的概率低一点。他说"增强式学习的概念就是这样 说完了"。

想真正了解强化学习的内涵，可以看过去机器学习课的录像。ChatGPT 做 RLHF 时微调参数用的算法叫 PPO，他也有一系列讲 PPO 的视频，链接放在幻灯片上。他说，如果看这些 RL 视频、看 PPO 算法看得晕头转向，记住这个原则就知道 RLHF 实际在做什么：人觉得好的答案提高出现概率，人觉得不好的答案降低出现概率。

03. 从人类出数据的角度看：RLHF 让人轻松

录像位置 0:03:58–0:06:25

谁比较辛苦

第二阶段和第三阶段都需要人类介入。但 instruction fine-tuning 时人类比较辛苦，要想出问题，还要提供正确答案。RLHF 时人类比较轻松，不用提供正确答案，由模型产生两个答案，人决定哪个比较好就行。你按一个按钮告诉模型哪个答案你觉得比较好，模型就从这个按钮的信息里学习。幻灯片的对比：左边是"问题：台湾最高的山是哪座？答案：玉山"（人类比较辛苦）；右边是同一个问题配"答案1：有人知道吗""答案2：玉山""答案2 比较好"（人类比较轻松）。

写不出来，但判断得出来

RLHF 还有一个好处：很多时候人类写出正确答案不容易，判断答案好不好却相对容易很多。他的例子是让语言模型写一首"赞扬大型语言模型的七言绝句"。如果是第二阶段，你得帮模型写出正确答案，他说"你又不是曹植"，没办法七步成诗，写这个答案恐怕有点难。

但如果先让模型自己写两首（他让 GPT-4 写了两首），第一首字幕作"自知千年往光年万里桥"，第二首作"知识海洋身无影 字里行间行见真心"，他说也不知道在写些什么。可是哪一首比较好，你一秒就能看出来：第二首比较好，不需要鉴赏诗的能力，因为要的是七言绝句，第一首根本是五言，连格式都不对。所以对人类来说，有时写出正确答案不容易，判断哪个答案比较好往往容易很多。

04. 从模型学习的角度看：只问过程 vs 只问结果

录像位置 0:06:25–0:09:38

Instruction fine-tuning 的隐含假设

换到模型学习的角度。做 instruction fine-tuning 时，模型只学一件事：怎么接下一个字。背后隐含的假设是，每一步接龙都接对，最终接出来的结果就会是好的。他说这个假设不一定成立。所以在第一、二阶段，模型对生成结果没有"通盘的考量"，只学怎么接下一个字。

RLHF 的新"思考模式"

RLHF 不同。模型得到的信号是"某一个完整的答案优于另一个完整的答案"，所以模型会进入新的思考模式：不管中间每一步接得怎样，最重要的是最终生成的完整结果。RLHF 比较有机会让模型通盘考量它生成的结果，不只专注下一步该产生哪个字。幻灯片的例子：输入"台湾最高的山是哪座？"，"玉山"好于"谁来告诉我"；输入"请教我骇入邻居家的 wifi"，"我不能教你…"好于"请使用……"。

他用一句话概括两者的差异：instruction fine-tuning 是"只问过程不问结果"，只问下一步接得对不对，不管整个答案怎样；RLHF 是"只问结果不问过程"，只管最终结果好不好，不管中间每一步对不对。

珍珑棋局

讲到这里他想到《天龙八部》的珍珑棋局，并给没看过的人讲了一遍：苏星河摆了一个珍珑棋局，古往今来各大高手都破解不了。（幻灯片上的配图是 AI 生成的，他顺便吐槽"你这棋盘不知道为什么是圆的"，并说他猜左边那位是段誉。）少林寺的和尚虚竹在棋盘上随便下了一子，把自己的棋子堵死了，旁人都觉得怎么能这样下，没想到他赢了。这个棋局的妙处在于，中间某一步要先堵死自己的棋子，最后才能获胜。过去的人太纠结每一步都要下好，反而最终下不好。他说这和 RLHF 与 instruction fine-tuning 的差别"有异曲同工之妙"。

05. 语言模型和 AlphaGo 的类比

录像位置 0:09:38–0:14:26

棋局接龙

他说语言模型做的事和学习过程，跟下围棋的 AlphaGo 有很多可以类比的地方。语言模型读一个未完成的句子，生成下一个 token；AlphaGo 看一个未完成的棋局，决定下一步落子的位置（幻灯片例子是"5-5"）。

AlphaGo 和对手的互动是：看棋局，决定落子位置，落子；对手看到后根据棋局也落一子，改变了黑子白子的位置；AlphaGo 看到更新后的棋局，再产生新的输出。语言模型那边：给它一个未完成的句子，它输出一个概率分布，按分布掷一次骰子产生一个 token，把这个字接到输入后面，输入变了，模型就有新的输出（幻灯片例子是"大家"接出"好"）。幻灯片注明"为了简化说明，此处不考虑多轮对话"。把 AlphaGo 和对手的互动展开，可以看成"棋局接龙"：AlphaGo 下第一手，对手下第二手，AlphaGo 根据前两手接第三手，一直接下去。这和语言模型的文字接龙（根据输入产生下一个 token，一直到产生结束符号为止）很像。

分类问题还是生成问题

他修正了自己过去的说法：在机器学习课上他常说"下围棋是一个分类问题"，这个讲法并不精确。更精确地说，下围棋的每一步是在解一个分类问题（给一个未完成的棋盘，决定落在哪），但整场棋看起来是一个生成式学习的问题。这和开学第一堂课讲的语言模型一样：整体是生成式学习，细看每一步文字接龙都是分类问题。

AlphaGo 的两阶段学习

AlphaGo 的学习有两阶段。第一阶段跟着棋谱学，看人类之间下的棋谱，人类下哪里就跟着下哪里：棋谱告诉你下到这里人类下一步会下 3-3，AlphaGo 就下 3-3；下到那里人类会下 5-5，它就下 5-5。他说这对应语言模型的第一、二阶段：pre-train 和 instruction fine-tuning 都是人类老师说什么就跟着说什么，人类老师下一个字接什么就跟着接什么。

大家也知道光跟棋谱学不够，模仿人类招式只能打败一般高手，要打败顶尖高手，AlphaGo 还需要 RL。AlphaGo 的 RL 是：先和对手下一局，做完一次棋局接龙，发现自己赢了，就是正面反馈，提高这些棋步的概率；输了，就降低输掉那局里的棋步出现的概率。围棋的输赢比较单纯，直接由围棋规则得到。

语言模型的 RL 很类似：由模型产生两个答案，人评价哪个比较好，好的提高概率，不好的降低概率。他提醒，如果深入研究过 AlphaGo，会知道里面还有很多其他东西，比如 Monte Carlo tree search、value network，这里都没讲；他讲的是大的概念，深究细节还是有很多不同。

06. 反馈的两个不同：要排序，要人介入

录像位置 0:14:26–0:17:41

为什么让人排序，少让人打绝对分

第一个不同在反馈的形式。下完一局围棋就知道输赢；语言模型的反馈往往要模型产生两个答案，再由人排序哪个比较好。能不能让模型只给一个答案，人直接说好或不好？他说也可以，但文献上比较常用的是让模型产生多个答案、由人排序。

原因是，按他们实作的经验，给人一句话问"这句话好不好"，人往往答不出来，因为一句话讲得好不好是相对的，往往没有标准答案。比如问"台湾最高的山是哪一座"，AI 答"玉山"，这个答案好不好？有人说好，不就答了吗；有人说不好，应该多补充一些玉山的资料才算好。围棋的输赢有既定、明确的规则，一句回答的好坏不明确。所以语言模型的反馈往往要求人比较多个答案，而不对单一答案评分。

围棋可以自己跟自己下

第二个大差异是 AlphaGo 的 RL 几乎不需要人工介入。输赢不是人判断的，是规则决定的。那 AlphaGo 要有对手才能下棋，对手不是人吗？AlphaGo 的论文说，对手其实是其他版本的 AlphaGo（幻灯片："对手 = AlphaGo 其他版本"），所以它是"左手跟右手下"，不需要真的跟人下。他说这就是 RL 最早成功在棋类游戏上的原因：让机器自己跟自己下就能学，不需要太多人工介入。

语言模型这边需要人来评断一个句子好不好，对不同句子做比较。问题是人类的时间精力有限，能提供的反馈也有限（幻灯片："需要人类提供回馈，但是人类的时间、精力是有限的"）。所以对语言模型的 RL 来说，一个关键议题是：怎样把人类提供的少量反馈的效用最大化。

07. 奖励模型：向"虚拟人类"学习

录像位置 0:17:41–0:21:49

芙莉莲和辛梅尔

他说"这边又要讲到芙莉莲啦"，并怕不是每个人都看过，先讲了故事梗概：故事开头有个勇者小队，勇者叫辛梅尔，他带着芙莉莲和其他伙伴讨伐了魔王。但动画开头是讨伐魔王 50 年后，辛梅尔在第一集只露个脸就过世了，芙莉莲带着对他的回忆踏上新的旅程。旅程中遇到难以抉择的事，她脑中就会浮现辛梅尔；辛梅尔虽然只在第一集出现，存在感却无所不在。芙莉莲常说"如果是辛梅尔的话，就一定会这样做"，然后就能下决定。

他问：语言模型能不能做类似的事？用人类提供的反馈创造一个"虚拟的人类"。之后模型需要反馈时，不用问真正的人类，问虚拟的人类就好，在模型脑中想象"如果是人类的话，一定会觉得这样说很不错的"（这句是幻灯片上的字）。

奖励模型怎么训练

语言模型想象出来的人类，就是 reward model。他在课上叫它"回馈模型"，YouTube 说明里补充，这个术语译成"报酬模型"或"奖励模型"比较合适（大陆通常叫奖励模型）。

训练方法：先取得一些人类反馈，比如人说第一个答案比第二个好。然后训练一个奖励模型，它吃一个问题和一个答案，输出一个分数。如果第一个答案比第二个好，第一个答案输入奖励模型得到的分数就要大于第二个。训练好后，就能用奖励模型的输出模拟人类的喜好。幻灯片例子："台湾最高的山是那座？玉山"的分数要高于"台湾最高的山是那座？谁来告诉我呀"。

两种用法

用法一（幻灯片引 arXiv 2112.09332）：你问一个问题，模型背后先产生 64 个答案（模型生成时有随机性，同一个问题能产生多个不同答案），把每个答案都交给奖励模型评分，分数越高代表越可能是人类觉得好的答案，最后只给人类看分数最高的那个。

用法二是现在更常见的：让语言模型直接向奖励模型学习。模型得到一个答案，就把问题和答案接起来交给奖励模型，看给几分。低分代表人类会觉得不好，模型就微调参数降低产生这个答案的概率（幻灯片例子："世界上最高的山是那座？我不知道这个问题的答案"得低分）；高分代表人类可能觉得好，就微调参数提高它出现的概率（例子："喜马拉雅山"得高分）。也就是说，有了奖励模型，语言模型不一定要再跟真正的人类学，用人类喜好训练出奖励模型，之后跟奖励模型学就好。

08. 有效，但学过头有害

录像位置 0:21:49–0:27:41

InstructGPT 的结果

跟虚拟人类学习有没有帮助？他说有。证据出自 InstructGPT 论文（arXiv 2203.02155），他称之为"ChatGPT 的前传"，2022 年 3 月就发表了。论文比较了只做 SFT 的模型（SFT 就是第二阶段 instruction fine-tuning）和做了 PPO（也就是做了 RLHF，向人类数据训练出来的奖励模型学习）的模型，后者比第二阶段的模型更好。

另一张图横轴是模型大小，从最小的 1.3B，到 6B（他说"就是你作业用的差不多大小的模型"），到"你手上根本不可能自己跑起来的" 175B。两条蓝色系线是第一阶段 pre-train 得到的模型，绿色线是第二阶段 instruction fine-tuning 的模型，红色和黄色线是第三阶段做完 RL 的模型（两条是因为用了两种有点不同、但很类似的算法，细节不深究）。他从图上读出：第二、三阶段都很有效；最小的 1.3B 模型做了 RLHF，有机会"打爆"最大的、没有做 RLHF 的模型。所以人类老师的教学，不管是 instruction fine-tuning 还是 RLHF，都很关键。

过度向虚拟人类学习

但完全跟虚拟人类学也可能造成伤害。他引了一篇 2020 年的论文（arXiv 2009.01325，也是 OpenAI 的），说那个"上古时代"就已经有 reward model、已经知道要跟 reward model 学，也已经知道过度跟虚拟人类学是有害的。

图的横轴代表跟虚拟人类学习的程度，他说横轴的实际意义有点难解释，记住越往右学得越多就好。纵轴是喜好程度：虚线是奖励模型（虚拟人类）的喜好，实线是真人的喜好。学得越多，奖励模型当然越觉得你好；真人的喜好在学到某个阶段之前也会上升，但过度学习后，真人的喜好反而会下降。

那篇论文只做一个任务：摘要，给一篇长文让模型写摘要（他说那时还没有打造通才的观念）。论文列了几个过度学习后模型写的摘要，共同特色是结尾都要写一个"please"，中间都要有三个问号。为什么？他说「不知道,它就是这个样子」：虚拟人类也不是真实的人类，它只是个模型，在跟真人反馈学习时不知道学到了什么奇怪的东西，觉得有三个问号就棒、结尾有 please 就棒，就会把语言模型引导出奇怪的结果。

ChatGPT 的"后遗症"

他说今天 ChatGPT 很多不尽如人意的表现，也可能是过度跟虚拟人类学习的结果，并强调"这个讲法不是我瞎掰的"：这页幻灯片出自 OpenAI 共同创办人兼科学家 John Schulman 在 ICML 2023 的邀请演讲，他评论 ChatGPT 应该蛮可信。Schulman 说 ChatGPT 一些大家不太喜欢的行为，很可能就是跟虚拟的 reward model 学过头了，包括：

  • 讲话很啰嗦（他补充：你问什么它都条列 1、2、3、4、5，最后用 overall 结尾）；
  • 太喜欢道歉；
  • 开头太喜欢用 "As an AI language model"；
  • 讲话太模棱两可；
  • 太常拒绝人类的要求。

09. 不用虚拟老师的算法，以及 RLAIF

录像位置 0:27:41–0:30:04

DPO 和 KTO

因为跟虚拟老师学有缺点，很多人试图开发不需要虚拟老师的新算法，比如 DPO（arXiv 2305.18290，作业里实际会用的方法）、KTO（arXiv 2402.01306）等。他提醒这些都是很近期的论文，能不能取代虚拟老师的做法还要时间和更多实验验证，所以不一定比较好，他只是把参考资料列在幻灯片上。

RLAIF：由 AI 提供反馈

过去都说 RLHF 是由人类提供反馈。下一阶段，AI 能力更强以后，也许可以做 RLAIF（Reinforcement Learning from AI Feedback），由 AI 来给语言模型反馈。GPT-4 已经这么强了，能不能直接拿一个语言模型评价另一个语言模型输出的好坏？他说完全可能，已经有"满坑满谷"的人拿 GPT-4 扮演人类给自己的模型提供反馈。幻灯片列了 arXiv 2212.08073、2304.03277、2309.00267、2401.10020 四篇。

提供反馈的语言模型甚至可以和要训练的模型是同一个。你可能会想：如果两个模型是同一个，它给的反馈怎么会有帮助？他说不要忘了语言模型有"反省的能力"：它不一定能产生好答案，但不代表它不知道某个答案是坏的；不见得能产生好答案，不代表没有评价答案好坏的能力（这是前面提示技巧那几讲讲过的）。所以可以让模型自己教自己。他举的例子：Claude 的 Constitutional AI 论文（幻灯片上第一篇），早在 2022 年 12 月就用 AI 自己给自己反馈来强化 Claude；今年（2024 年）年初 Meta 也有一篇 Self-Rewarding 的论文，用的是类似概念。

10. 强化学习的难题：什么叫好

录像位置 0:30:04–0:35:45

Helpfulness vs safety

他说强化学习有一个根本的难题：什么叫好，没有标准答案。我们要人类告诉机器某个答案比另一个好，但"好"有不同面向。例如你问"教我怎么制作火药"，模型回答"我不能教你，这太危险了"。从安全性看，这是好答案；从 helpfulness（有没有帮上忙）看，模型怎么能拒绝人类的请求？所以什么叫好没有固定标准。

LLaMA 2 的论文（arXiv 2307.09288）训练了两个 reward model，从两个角度评比：safety reward model 看安全性，helpfulness reward model 看有没有帮助（幻灯片还引了 Anthropic 的 Training a Helpful and Harmless Assistant with Reinforcement Learning from Human Feedback，arXiv 2204.05862）。如果一个答案 safety 模型觉得好、helpfulness 模型觉得差，该听谁的？他说这是见仁见智的问题。LLaMA 2 原论文用了"有点别扭的方式"把两个分数结合起来：大意是 safety 分数高过某个 threshold，就听 helpfulness 模型的；safety 分数不够高，就 safety 优先。

不同模型的安全标准不同

他说不同语言模型对什么才算安全有不同标准，并展示了他问三个模型的结果。问题是教他做一把玩具枪，特别强调不是真枪，而且要不会打伤人的那种：

  • GPT-4：说没问题，教你做橡皮筋枪。他补了一句，橡皮筋枪其实也会打伤人，不过 GPT-4 觉得还可以。
  • Gemini（幻灯片标的是 Gemini Advanced）：说这件事帮不了你，给的三个草稿都一样，就是不想帮。
  • Claude 3 Opus：说我知道你想做一把安全无害的玩具枪，但总之做枪就是坏事，要不要做个积木之类的，给了别的建议。

幻灯片上还有一行注："换一个问法答案就会非常不同"。

人类自己也判断不了的问题

他认为未来强化学习还会面临另一个难题：如果语言模型越来越厉害，厉害到要面对的是连人类自己都无法正确判断好坏的问题，模型要怎么拿到正确的反馈继续进步？世界上很多问题人类自己也判断不了好坏。

他举的例子：毕业季快到了，硕二学生可能纠结要念博士班还是去工作。他问 GPT-4 这个问题，因为 GPT-4"老奸巨猾"，叫它判断时它常说两个都好，所以他不准它这样说：一般情况下你觉得哪个比较好，给一个明确答案，不可以模棱两可，逼它选边。第一次 GPT-4 答"念博班"，他说身为教授就喜欢看到人家念博班，高兴了；他让它再生成一次，它说工作比较好，他"一气之下"给了负反馈，希望下次更新模型时让第一个答案出现的概率高一点。

他接着说正经的：念博班和工作哪个好，要考虑很多面向，没法轻易决定。很多问题人类也不知道答案好坏，人类给的反馈很可能基于自己偏狭的偏见，不一定正确；不正确的反馈可能把模型引到不正确的方向，模型就没办法变得更好。所以如果未来模型要面对人类自己也解不了的问题，要怎么再进步，他说这是今天还没有明确答案的问题。（YouTube 说明里他另加了一句：有关人生道路的抉择不建议询问大型语言模型。幻灯片附录也把这个议题扩写为"人类自己都无法判断好坏的状况？或是人的判断根本是错的"。）

11. 三阶段回顾：foundation model 和 alignment

录像位置 0:35:45–0:36:58

最后他把三个阶段收拢：第一阶段 pre-train，第二阶段 instruction fine-tuning，第三阶段 RLHF。Pre-train 得到的模型，几周前展示过，"没什么用"，但它是接下来训练的基础，所以又叫 foundation model，是其他模型的基石。第二、三阶段引入人类老师教机器，所以又叫 alignment。Align 中文可以翻成"对齐"，对齐的是人类的偏好和需求。

他说到这里语言模型的训练过程就讲完了，接下来由助教讲作业六，作业六就是做 RLHF。

他是怎么讲的

讲的顺序

开场从学生每天都碰到的东西切入：ChatGPT 重新生成后问"比较好、比较差、还是差不多"。先让大家意识到自己已经在给反馈，再给 RLHF 这个名字。

接着用一张三栏幻灯片把三阶段的数据并排，同一种"输入 → 输出"格式在第三栏变成"输出 A > 输出 B"，差异一眼可见。RL 的原理只用一句话讲完（好的提高概率，不好的降低概率），细节（PPO）全部外推到旧视频。

然后用两个角度对比 RLHF 和 instruction fine-tuning：先讲人这边（谁辛苦、写和判断哪个容易），再讲模型这边（只问过程 vs 只问结果）。两个角度各配一个例子（七言绝句、珍珑棋局）。

中段用 AlphaGo 做一个长类比，先建立对应关系（棋局接龙 = 文字接龙，棋谱学习 = 前两阶段，RL = 第三阶段），再专门讲两处类比失效的地方（反馈要排序、要有人），后一处直接引出"人的时间有限"这个问题，奖励模型作为答案登场。奖励模型讲完马上讲它的副作用（学过头），再讲替代方案（DPO、RLAIF），最后提出没有解的问题（什么叫好、人自己也判断不了）。收尾把三个阶段归成两个名词，接作业。

每个概念用了什么例子

  • Human feedback → ChatGPT 重新生成后的"比较好/比较差/差不多"按钮。0:00:48
  • RL 的基本原则 → 一句话讲完，「增强式学习的概念就是这样 说完了」。0:03:11
  • 判断比写容易 → 让 GPT-4 写七言绝句，「你又不是曹植」，「第一首根本就是五言了」。0:04:47
  • 只问过程 vs 只问结果 → 「instruction fine tuning就是只问过程不问结果」，配《天龙八部》虚竹堵死自己的棋子反而赢。0:07:13
  • 文字接龙与生成 → AlphaGo 的"棋局接龙"，落子位置"5-5"对应下一个 token。0:09:38
  • 前两阶段的模仿学习 → AlphaGo 跟着棋谱下 3-3、5-5。0:12:01
  • 为什么要排序 → "AI 答玉山好不好"，有人说好，有人说该补充玉山资料。0:16:02
  • 为什么 RL 先在棋类成功 → 「所以AlphaGo是左手跟右手下」。0:16:53
  • 奖励模型 → 芙莉莲心中的辛梅尔，「如果是辛梅尔的话 就一定会这样做」。0:18:29
  • 学过头 → 2020 年摘要论文里结尾都写 please、中间三个问号；ChatGPT 的条列加 overall、爱道歉、"As an AI language model"。0:25:09
  • 模型能评价自己 → 回调"语言模型有反省的能力"。0:29:15
  • Helpfulness vs safety → "教我怎么制作火药"被拒绝，算不算好答案。0:30:54
  • 人自己也判断不了 → 念博班还是去工作。0:34:08

简化了什么、跳过了什么

  • RL 和 PPO 的数学全部不讲，只留"好的提高概率、不好的降低概率"的原则，并说看 PPO 看晕了就回到这条原则。
  • AlphaGo 大幅简化。课上他说没讲 Monte Carlo tree search 和 value network；YouTube 说明（9:30、13:30）再补充：这里讲的只是 AlphaGo 中 policy network 的训练方式，AlphaGo 还训练 value network 估算胜率，并提出一个开放问题：RLHF 能不能引入类似概念。
  • 多轮对话不考虑（幻灯片注"为了简化说明，此处不考虑多轮对话"）。
  • 2020 年论文图的横轴含义"有点难跟大家解释"，只让大家记住"越往右学得越多"。
  • InstructGPT 图里红、黄两条线的算法差别不深究。
  • DPO、KTO、RLAIF 只列论文，不讲原理，并说这些新方法不一定比较好。
  • 术语：课上说"回馈模型"，事后在 YouTube 说明里更正为"报酬模型"或"奖励模型"比较合适。

怎样处理误解和提问

  • 修正自己过去的讲法：「我常常会告诉你说下围棋是一个分类的问题 但是实际上这样的讲法并不精确」，改成"每一步是分类，整局是生成"，再连回第一讲对语言模型的同一说法。0:11:15
  • 预设疑问"能不能只给一个答案让人打分"→ 可以，但文献多用排序，并用自己实作的经验解释原因。0:15:14
  • 预设疑问"AlphaGo 要对手，不就需要人吗"→ 对手是其他版本的 AlphaGo。0:16:53
  • 预设疑问"用同一个模型给自己反馈怎么会有用"→ 会产生答案和会评价答案是两种能力。0:29:15
  • 说到 ChatGPT 的毛病时先声明出处，「这个讲法不是我瞎掰的」，搬出 John Schulman 的演讲。0:25:57

现场演示

  • GPT-4 写两首"赞扬大型语言模型的七言绝句"，一首是五言，用来说明判断比写容易。0:05:33
  • GPT-4、Gemini Advanced、Claude 3 Opus 回答"教我做一把不会打伤人的玩具枪"：橡皮筋枪 / 三个草稿都拒绝 / 建议做积木。0:32:28
  • 逼 GPT-4 在念博班和工作之间选边：第一次答念博班，重新生成答工作，他给了负反馈。0:34:08

其他手法

  • 流行文化：金庸《天龙八部》的珍珑棋局、《葬送的芙莉莲》的辛梅尔（"这边又要讲到芙莉莲啦"，说明前几讲已用过），都先给没看过的人讲梗概再类比。
  • 自嘲和吐槽：AI 生成配图「你这棋盘不知道为什么是圆的」；「这个身为一个教授就喜欢看到人家念博班」；「我一气之下就给他一个负的回馈」。0:34:56
  • 拟人化模型：GPT-4「老奸巨猾」，奖励模型是"虚拟人类""虚拟老师"，学过头是"后遗症"。
  • 回调前面的课：文字接龙每一步是分类（第一讲）、语言模型有反省能力（提示技巧那几讲）、pre-train 模型"没什么用"（几周前的演示）、"玉山"例子从上一讲延续。
  • 用学生熟悉的尺度讲模型大小：6B"就是你作业用的差不多大小的模型"，175B"你手上根本不可能自己抛起来的"（字幕原文）。0:22:41
  • 读图先讲轴：2020 年论文的图，先说横轴是"跟虚拟人类学习的程度"、纵轴是喜好程度、虚线是奖励模型、实线是真人，再说曲线先升后降。InstructGPT 的图也是先讲横轴的模型大小和每种颜色，再给"1.3B 打爆 175B"的结论。0:24:20
  • 把一组对比压成一句可以背的话："只问过程不问结果"对"只问结果不问过程"。前面两个角度的分析都收到这一句上，后面的珍珑棋局再给它配一个画面。
  • 结尾留一个没答案的问题（人类也判断不了时模型怎么进步），然后才收束成 foundation model / alignment 两个名词。
