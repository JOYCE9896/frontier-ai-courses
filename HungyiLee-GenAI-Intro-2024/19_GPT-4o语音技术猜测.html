加课：GPT-4o 背后可能的语音技术

GPT-4o 语音模式和旧版语音界面的区别，语音版语言模型怎样把声音压成 Speech Unit 来做"声音接龙"，预训练和对齐分别可能怎么做，以及让模型同时听、说、看的一种做法；全部是他根据已有论文的推测

01. GPT-4o 语音模式特别在哪里

录像位置 0:00:00–0:02:50

开头他说明听众定位：这部视频面向没有语音技术背景的人，如果已经是语音领域专家，内容可能太科普；他假设听众修过生成式人工智能导论，没看过的可以先看课程视频（幻灯片放了"《生成式人工智慧导论》连载中"的页面）。

GPT-4o 最引人注目的技术之一是语音互动。同一时期 Google 也发布了 Project Astra，同样做了语音互动，说明各大厂都很重视这一块。幻灯片上放了两家的 demo 视频链接。

他列出 GPT-4o 语音模式（Voice Mode）的四个特点：

  • 语音风格丰富。说到语音合成，大家往往想到"Google 小姐"，只有一种语调；GPT-4o 可以用文字指令要它换语调，比如讲快一点、轻声细语，甚至用唱的。
  • 能理解语音内容以外的信息，用白话说就是能"察言观色"。比如它可能听得到一个人的喘气声，知道这人气喘如牛。
  • 能发出非语言性的声音，比如笑声。他说看过 demo 就会发现这是一个很爱笑的模型，动不动就笑。
  • 自然而即时的互动。demo 里有人说"我们来做一个有趣的尝试"，话还没说完 GPT-4o 就说了一声"哇"，然后那人才说"我要你去做某件事"。

他建议没看过 OpenAI demo 的人先去看一下再继续。

02. 常见误解：手机版的语音界面不是 GPT-4o 语音模式

录像位置 0:02:50–0:07:30

你用到的可能还是旧版

他先澄清一个很多人有的误解。视频是 5 月 19 日晚上录的，到那时为止多数人应该还没有 GPT-4o 的语音模式。很多人会说"我有啊，我可以用语音跟 ChatGPT 互动"，但那是 ChatGPT 手机版本来就有的语音界面：在页面右下角点语音按钮就能进入。实际试过会发现，这个界面没有 demo 里的种种功能，比如用不同语气讲话、可以打断它说话。大家可能也收到过 OpenAI 的消息：Voice Mode 还没真正发布，只是 coming soon，会在接下来几周陆续开放。

旧版语音界面是三个系统串起来的

旧版的做法是：先用语音识别把语音信号变成文字，把文字丢给语言模型（比如 ChatGPT），语言模型给出回应，再用语音合成把回应变成语音信号。幻灯片例子是用户说"你好吗？"，ChatGPT 回"好久不见"。如果语音识别和语音合成跑得够快，这种界面也能做到蛮自然即时的互动，但和 GPT-4o 的 demo 比还有差距：

  • 语音转成文字后，语言模型可能不知道说话人的情绪。
  • 语音合成只是把语言模型的输出念出来，只有一种说话风格。

串接加模块，其实也做得到一部分

他说自己看 demo 时也想过，会不会只是在原系统上加了一些额外模块：

  • 在语音识别之外加声音事件检测、情绪识别模块，把检测到的情绪（比如"（高兴）"）放在识别结果后面一起丢给语言模型，语言模型就有机会知道这句话的情绪。幻灯片引用了几篇这方面的论文（arXiv 2402.12786、2312.15316 等）。
  • 让语言模型在文字之外多输出一些符号，比如在句子后面加"（笑）"，再丢给语音合成系统，也许就能合成出笑声。他说有些语音合成系统真的可以，比如 Suno AI 开发的 Bark，文字里打一个"笑"，合成结果真的会有笑声。
  • 让 ChatGPT 产生一段指令告诉语音合成系统用什么语气，比如"用愉快的语气"。很多语音合成系统看得懂文字指令，代表性的例子是 Meta 的 AudioBox。

所以用现有技术串起来，也不是不可能打造 GPT-4o 那样的语音界面；只是很多系统串在一起，即时性可能不好，需要大量工程手段加速，才能做到真正即时的回应。

03. GPT-4o 是端到端的单一模型，以及免责声明

录像位置 0:07:30–0:09:20

不过 GPT-4o 的博客已经说了，它的语音模式是一个 end-to-end（端到端）的模型。幻灯片引用原文："With GPT-4o, we trained a single new model end-to-end across text, vision, and audio, meaning that all inputs and outputs are processed by the same neural network." 也就是只用一个模型处理所有事情，不是上一页那种复杂的串接架构：这个单一模型听语音信号作为输入，产生对应输出。它其实是多模态模型，也能看图片和视频，但这部视频只讨论声音部分。

04. 语音版语言模型：在 Speech Unit 上做声音接龙

录像位置 0:09:20–0:15:15

先复习文字语言模型的训练

文字语言模型的训练有三步：Pretrain（预训练），用大量没有标注的数据训练；Fine-tune（微调），用少量有标注的数据微调；RLHF，用使用者反馈的数据微调。Fine-tune 和 RLHF 合起来又叫 Alignment（对齐）。不熟悉的话可以看他过去的上课录像（第 6–8 讲），也可以看最近发布的生成策略视频（第 15 讲）了解生成式 AI 的基本原理。

语音版语言模型做的是"声音接龙"

语言模型做文字接龙：给一个未完成的句子，猜接下来输出哪个文字 token。语音版语言模型能听一句话给你回应，背后的逻辑可能很类似：听一段声音，猜接下来应该产生什么声音，也就是"声音接龙"。

挑战：声音太复杂

表面上两者很像，但语音版有独特的挑战。第一个是语音比文字复杂得多：采样率 16kHz 的声音，一秒钟由一万六千个采样点、一万六千个数值组成。如果声音接龙是一个采样点一个采样点生成，一秒钟的声音就要接龙一万六千次，很花时间。所以现在做语音接龙，通常不直接在语音信号上做，而是先压缩。

编码器、codebook 和 Speech Unit

  • 编码器（encoder）里可能有一个 codebook（码本），里面是一大堆 code，每个 code 代表某种类型的声音：可能某个 code 代表人发出的 /b/ 音，某个代表人的笑声，有的甚至代表非人类的声音，比如狗叫。
  • 一段声音输入编码器，编码器用 codebook 来表示它，于是一段声音被表示成一个 code 的序列。这些 code 又叫 speech unit，可以看作声音的单位。
  • 再训练一个解码器（decoder），读这些 speech unit，转回声音信号。
  • 编码器和解码器一般也是神经网络，需要用训练数据训练。想了解把声音变成 Speech Unit 再解回来的技术，幻灯片放了两篇：一篇综述（arXiv 2402.13236）和 Codec-SUPERB（arXiv 2402.13071）。

语音版语言模型在 Unit 上接龙

声音进来先经过 encoder 变成一串 unit，unit 作为语音版语言模型的输入；模型预测下一个 unit，再经过 decoder 产生声音信号。所以模型不需要产生复杂的声音信号，只需要产生 unit。代表性的语音版语言模型有 Meta 的 GSLM（arXiv 2102.01192）和 Google 的 AudioLM（arXiv 2209.03143）。他说这不是很新的技术，GSLM 在 2021 年初就有了。

他还给了另一种看法：编码器可以看作一种很特殊的语音识别，只是输出换成了 speech unit；解码器可以看作一种特殊的语音合成，只是输入换成了 speech unit。（字幕此处两次都说"解码器"，按上下文第一次应为编码器。）

05. 文字还是 Speech Unit：混合编码器与说话人分段标记

录像位置 0:15:15–0:19:25

为什么不直接用语音识别和语音合成当编码器、解码器

他预先替听众提问：为什么不直接拿语音识别和语音合成当编码器和解码器？确实可以把语音识别想成一种很特别的压缩方式，文字本来就可以看作语音的浓缩版。问题是文字只代表语音里内容这一面的信息。假设有人说"好好笑"，接着"哈哈哈哈"笑了几声，语音识别可能只识别出"好好笑"，笑声就不见了；再用语音合成把"好好笑"还原，笑声的信息就丢了。用 Speech Unit 的好处是可能保留文字无法表达的信息。

但 Speech Unit 是在"重造轮子"

坏处是，很多 unit 本来就对应某个文字 token。本来已经有文字可以表示语音里的这些信息，编码器还要用新符号再表示一遍，像是重造轮子。

混合编码器、混合解码器

所以另一种可能是把编码器和语音识别结合，他叫它"混合编码器"；把解码器和语音合成结合，叫"混合解码器"。一段声音里能识别成文字的部分用文字表示，无法用文字表示的部分用 Speech Unit 表示。"好好笑"后面接"哈哈哈哈"，"好好笑"用文字，笑声用一个特殊符号；混合解码器看文字加特殊符号，转回声音信号。他说不知道 GPT-4o 会不会采取这种混合策略，也许只用编码器、没用语音识别；他只是觉得混合编码器有额外的好处，后面会再提到（见第 06 节）。

说话人分段标记（Speaker Diarization）

还需要一种技术叫 Speaker Diarization，即说话人自动分段标记。GPT-4o 的 demo 里，有两个以上的人跟它说话时它知道谁是谁，所以他认为应该用到了这种技术：给一段声音信号，系统能标出哪些段落是同一个人讲的，比如这段和这段是说话人 A，这段是说话人 B。

他猜测的输入表示

综合起来，他猜语音版语言模型看到的一段声音可能是这样表示的：同时用混合编码器和说话人分段标记，用"A:"这样的特殊符号标出哪段是 A 说的，能用文字表示的地方用文字，不能用文字表示的地方用 Speech Unit 的特殊符号。幻灯片上的例子是"A: 好好笑（笑声） B:（笑声）"。

06. 预训练：大量声音数据，加上文字的知识

录像位置 0:19:25–0:27:55

声音数据从哪里来

文字语言模型用大量文字数据训练，语音版语言模型同理可以用大量声音数据训练，做 speech unit 的接龙。声音数据去哪找？他说很直觉，网上有这么多影音平台。OpenAI 显然在做这件事：4 月《纽约时报》报道 OpenAI 用了超过一百万小时的 YouTube 视频来训练它们的模型。他说刚看到报道时很困惑，为什么要用 YouTube 视频训练语言模型，难道文字数据全部用完了？但如果 OpenAI 是在训练语音版语言模型，用 YouTube 视频就完全说得通。

背景音乐也学进去了？

网上的视频五花八门，很多不是干净的语音，背后有音效、背景音乐。拿这些训练，模型会不会把音效和背景音乐都学进去？他说很有可能，并放了一段 GPT-4o demo 让大家仔细听：GPT-4o 讲话时背景有钢琴声。当然不能排除现场正好有人在弹钢琴，但如果说 GPT-4o 讲话时可能自带音效或背景音乐，他一点也不意外。他觉得这也挺酷，以后讲话都自带 BGM，可以说这不是 bug，是 feature。

为什么能产生戏剧性的声音：BASE TTS

demo 里 GPT-4o 能产生很多样、很戏剧化的声音。他引用 Amazon 2024 年 2 月发表的论文 BASE TTS: Lessons from building a billion-parameter Text-to-Speech model on 100K hours of data（arXiv 2402.08093）：用超过 10 万小时的语音训练语音合成模型，参数在十亿（billion）级别。这个大小在文字领域不算大，但对语音合成模型已经很大。论文发现，过去语音合成系统数据不够，合出来的声音很平淡，他说看动漫的人知道这叫"棒读"，讲话不带情绪；有了大量数据，模型就能理解要读的内容，并据此给出适当的变化。

他播放了论文的 demo。句子里有 whisper（轻声细语）这个词："A profound sense of realization washed over Matty as he whispered, ..."。论文说没有对输入文字做任何特殊处理，模型直接读文字，但读到 whisper 时自动知道要用比较轻的声音念，这是从数据里自己学到的。他说这个合成没有很戏剧化，GPT-4o 的 demo 更戏剧化，叫它轻声就能讲得更轻；也许把数据从十万小时扩到一百万小时就会有这种效果。但他从来没有用这么多数据训练过语音合成系统，所以这只是猜测。

只靠语音数据不够：算一笔账

他认为只用语音数据训练显然不够，必须利用文字信息。理由是算一下一百万小时语音背后有多少文字：一百万小时是六千万分钟，一般人一分钟大约讲一百多个文字 token，六千万分钟就是 60 亿个文字 token。60 亿听起来不少，但 LLaMA 3 用了 15 兆（15 万亿）个文字 token 训练。他在视频里说一百万小时语音只有 LLaMA 3 预训练数据的 250 分之一，幻灯片也写 250 倍；YouTube 说明栏勘误为 2500 倍（15 万亿除以 60 亿是 2500），他补了一句"语音和文字的差异真的好大"。所以只听了一百万小时语音的模型，也许能学到语音的信息，但知识会很不足。

怎么利用文字信息

  • 用原有的文字语言模型做初始化。OpenAI 早就有很强的语言模型，可能不会浪费这些模型学到的知识。通俗地说，就是去教原有的语言模型听懂语音。语音被表示成一堆 unit，对语言模型来说这是一种全新的语言、有自己独特的符号系统，教它听懂语音就像让它学一门新语言。
  • 另一种可能是把语音符号和文字全部倒在一起训练。

他说这里能体现混合模式的好处：如果表示一段声音时不只用 unit、也用文字，语言模型学起来可能更容易，因为文字符号的意思它早就知道，只要花力气理解新符号（比如笑声）是什么意思。他强调这只是猜测，利用文字信息的方法还有很多，幻灯片列了几篇（arXiv 2310.08715、2402.05755）。

07. 对齐：用语音对话微调

录像位置 0:27:55–0:31:10

只有预训练不够。文字模型只做预训练根本没法好好回答问题，需要 alignment，用有标注的数据微调。文字模型要收集这样的对话：人说"你是谁"，模型回答"我是人工智能"；人说"教我黑进邻居家的 Wi-Fi"，模型回答"我不能教你"。语音模型则可能要收集语音对话：让一个人当使用者、一个人扮演 AI，然后微调语音版语言模型，让它听前者说话、产生后者的回应。

固定一个声音：Sky

光这样可能还不够。demo 里是固定某一个人的声音，比如现在 ChatGPT 语音页面可以选声音，选了 Sky 就只用 Sky 的声音讲话。想让模型用 Sky 的声音讲话，对齐时可能要收集大量 Sky 和其他人的对话，比如由某位配音演员代表 Sky，录很多她和别人的对话。幻灯片上的例子是"A: 念这个故事… Sky: 好啊，那我开始念""A: 快速从一数到十 Sky: 一、二、三、四…"。

是不是要录很多 Sky 的对话？他给了两个"也许不用"的理由：

  • 回想文字模型那几讲说过的，Fine-tune 往往不需要太多数据，模型预训练时已经有很丰富的知识，Fine-tune 只是画龙点睛。也许做完语音预训练后，模型已经很会模仿各种人说话，只要听过几句 Sky 的话就能学会她的说话方式，所以对齐时只需要少量数据。
  • 就算没有很多 Sky 的对话录音，也许可以用语音转换（voice conversion，把一个人的声音转成另一个人的声音）技术，把对话里各种人的声音都转成 Sky 的声音，得到大量 Sky 和别人对话的录音。幻灯片引用了 OpenAI 关于合成语音挑战与机会的文章。

08. 语音界面的难题：什么时候说、什么时候停

录像位置 0:31:10–0:35:35

文字界面有明确的开始和结束

到这里，语音版语言模型看起来和文字语言模型很像，但两者有根本区别。用文字和 ChatGPT 互动时，开始和结束都很明确：打完一句话按 Enter，ChatGPT 就知道轮到它，不用猜；不想让它讲了，按右下角的停止按钮，它就明确知道不再生成。

语音界面要靠猜

  • 什么时候开口：有人对 AI 说"我们来做一件有趣的事"，然后稍微停顿。这时 AI 要猜，是该接话问"什么事"，还是这个人还没讲完、应该等他讲完再回答。
  • 什么时候停：有人叫它讲故事，它开始讲一个无聊的故事，"山上有座庙，庙里有个老和尚"，无限循环下去，人听得厌烦，说"停停停，这不是我要听的"。模型知不知道要停？有人会说只要人一说话就停，他说这不是最好的方法，因为人讲话不一定是要它停，也许人正在和 AI 合唱。

所以要让语音版语言模型和人自然互动，模型要能同时听和说。原来的文字接龙里听和说是切开的，模型说的时候很难同时听。

一种解法：听和说分成两个频道（Dialogue GSLM）

一种可能的解法是把听和说分开。这个技术以前就有，模型叫 Dialogue GSLM（arXiv 2203.16502），2022 年就有了，听不太懂可以参考这篇论文。做法是把听和说分成两个频道：一个是听的频道，相当于模型的麦克风，听人在说什么、外界发生了什么声音；另一个记录模型自己发出过什么声音。两个频道分开，不直接混在一起。

他一步一步走了一遍 demo 里的对话：

  • 人说了个"我"，感觉话还没说完，模型就输出 silence（安静）。安静可能也由某些特殊的 speech unit 表示，就是不说话。
  • 人继续说到某个段落，"我们来做个有趣的尝试"，模型根据人说的话判断他说完了、轮到自己，输出一个"wow"，表示很兴奋。
  • 接下来如果人仍然安静，模型知道可以继续说，也许说"我好期待"。
  • 如果人还在出声，"我要你做某件事"，模型知道人还没说完，就输出代表安静的符号，继续保持安静。

他说这不是唯一让模型同时听和说的方法，只是其中一种可能的解法。

09. 同时听、说、看

录像位置 0:35:35–0:38:12

模型也许不只要同时听和说，还要同时看。GPT-4o 的 demo 里模型可以一边看东西一边说话，所以可能不只有听和说两个频道，还有一个视觉频道专门读取外界的图像输入。

OpenAI 的例子：比 Ya 的人

OpenAI 有个 demo：模型正在描述房间里的灯光，讲得很起劲，这时有个人跳进画面比了个 Ya 的手势，模型无视这个画面继续讲灯光。然后人打断它："等一下，你有没有看到什么奇怪的东西？"他说模型显然看到了比 Ya 的人，只是讲灯光讲得太投入，没觉得需要评论。被问到时，模型会对每个频道做 Attention（注意力机制，从所有信息里挑出和当前问题相关的部分），不只是自己正在生成的频道，还有听的频道、看的频道，收集所有信息后得到答案："有个人比了 Ya"。

Google Project Astra 的例子：眼镜

Project Astra 的 demo 有一个很类似的例子，他说看起来大家都觉得需要这种例子来展示模型能力。有人拿着手机随便走随便拍，中途拍到一副眼镜，模型当时没有评论，人也没提。人先和模型聊"我们现在在哪里"，模型说在国王十字车站（King's Cross）附近；然后人问"有没有看到我的眼镜"。这时眼镜已经不在画面里，但模型会对过去的信息做 Attention，从过去看到的图像、听到的声音里收集信息，知道看到过眼镜，眼镜在桌上。他说这是一种蛮自然的互动模式。

技术部分到此结束。想了解更多语音版语言模型的论文，他附了一个链接（github.com/ga642381/speech-trident），里面收集了很多相关论文。

他是怎么讲的

讲的顺序

先给观众一个"看得见的目标"：列出 demo 里 GPT-4o 能做的四件事（换语气、察言观色、笑、抢话说"哇"）。接着不直接讲新技术，而是先拆掉一个误解，说明大家手机上用的是旧版串接系统，并讲清旧系统怎么工作、缺什么、加模块能补到什么程度。这样"端到端单一模型"出场时，观众已经知道它要替代的是什么。

然后是免责声明，之后整个技术部分都挂在课程已经讲过的骨架上：先复习文字模型的三阶段训练和生成策略，再按"语音版语言模型怎么表示输入、怎么预训练、怎么对齐"的顺序走，每一步都是"文字模型这样做，换成语音会遇到什么不同"。语音特有的东西（unit、笑声、说话人、背景音）都在这个对照里出现。

最后才讲文字模型里不存在的问题：什么时候开口、什么时候停、怎么一边看一边说。这部分回到开头列的 demo 特点（"话没说完就说哇"），首尾呼应，也把最难、最没有现成答案的部分放在最后。

每个概念用了什么例子

  • 察言观色：听到喘气声知道人「气喘如牛」；能笑，「他动不动就会笑」（0:01:36）。
  • 旧版串接系统：用户说"你好吗？"，经语音识别、ChatGPT、语音合成回"好久不见"；缺点是听不出情绪、只有一种风格（0:04:05）。
  • Speech Unit：codebook 里的 code 分别代表 /b/ 音、笑声、狗叫声（0:12:23）。
  • 文字会丢信息："好好笑"加"哈哈哈哈"，语音识别只留下"好好笑"（0:15:44）；只用 unit 又像「那你等于是要这个编码器呢 去重造轮子」（0:16:30）。
  • YouTube 训练数据：从《纽约时报》报道切入，「那时候我刚看这个报导的时候就很困惑」（0:19:48），再把困惑解释成"其实是在训练语音模型"。
  • 数据里有背景音：让观众听 demo 里的钢琴声，「所以我们可以说这不是一个bug 这是一个feature」（0:21:40）。
  • 平淡的合成语音：「这个如果你有看动漫的话 你知道这就叫做棒读」（0:22:29），再播放 BASE TTS 读到 whisper 自动变轻的样本。
  • 语音数据不够：一百万小时换算成 60 亿 token，对比 LLaMA 3 的 15 兆 token（0:25:00）。
  • 对齐只需少量数据：回调文字模型那几讲，「Finetune只是画龙点睛」（0:29:57），用 Sky 的声音当具体对象。
  • 何时停：无限循环的「山上有座庙 庙里有个老和尚」（0:32:19），以及"人说话不一定是要它停，可能在合唱"的反例。
  • 多频道 Attention：OpenAI demo 里比 Ya 的人，「只是在讲灯光的时候他讲得太爽了」（0:36:18）；Astra demo 里找眼镜（0:37:08）。

简化了什么、跳过了什么

  • 只讨论声音，GPT-4o 的视觉部分只在最后"同时看"时提到。
  • 编码器和解码器怎么训练、codebook 怎么来，没讲，指向综述和 Codec-SUPERB。
  • RLHF 在复习时提到，但语音版的部分只讲了 Fine-tune 式的对齐，没讲语音上的 RLHF。
  • Dialogue GSLM 只讲了两个频道的概念，具体结构请大家看论文；他说明这只是"某一个可能的解法"。
  • 利用文字信息的其他方法只列论文，不展开。
  • 一处数字口误：视频里说 250 分之一，说明栏勘误为 2500 倍。

怎样处理误解和提问

  • 主动纠正观众的误解：手机版现有语音界面不是 GPT-4o 语音模式，并给出录制日期（2024/05/19）作为时间锚点。
  • 把不确定说在明处：单独一页免责声明，之后每个推测都加限定，比如「我不知道GPT-4O会不会采取这样混合的策略啦」（0:17:19）、「所以这只是个猜测」（0:24:11）。说明自己没用过这么多数据训练语音合成，所以无法确认。
  • 预先替观众提问并回答：为什么不直接用语音识别和语音合成当编码器？是不是要录很多 Sky 的对话？是不是人一说话就停下来？每个都给出反例或替代方案。
  • 对 demo 里的现象给出保留：钢琴声「当然我们不能排除现场正好有人在弹钢琴的可能啦」（0:21:40）。
  • 没有现场学生提问（这是录制的视频）；开头说明起因是「有很多同学问我对于GPT-4o有什么看法」（0:00:00）。

其他手法

  • 沿用课程里的叫法，把新东西套进旧框架："文字接龙"变成"声音接龙"，训练仍是 Pre-train、Fine-tune、RLHF 三步。
  • 用生活化的词替代术语："察言观色""Google 小姐""棒读"。
  • 用新闻报道做钩子：《纽约时报》说 OpenAI 用了一百万小时 YouTube 视频。
  • 用简单的乘除法让规模差异变直观（一百万小时到 60 亿 token，再对比 15 兆）。
  • 拟人化描述模型行为："讲得太爽了"所以没理比 Ya 的人。
  • 每个推测都配一篇已发表的论文或已有系统作支撑：串接方案配 Bark、AudioBox，Speech Unit 配 GSLM、AudioLM，戏剧化语音配 BASE TTS，同时听说配 Dialogue GSLM。推测的部分和有出处的部分分得清楚，观众能看出哪句是猜、哪句有证据。
  • 反复强调"这不是很新的技术"：GSLM 2021 年初就有，Dialogue GSLM 2022 年就有，把 GPT-4o 的效果拆成几项早已存在的研究的组合。
