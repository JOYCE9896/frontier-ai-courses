Doug O'Laughlin：用 Claude Code 做投研，和这一轮内存短缺

Claude Code 上线一周年，SemiAnalysis 的 Doug O'Laughlin 讲他怎样用它做金融研究、为什么说 Excel 和 Bloomberg 这类“分析师的 IDE”要过时，再谈 Microsoft 与 Oracle 的资本开支、TPU 的窗口期，以及 HBM 挤占 DRAM 产能带来的内存短缺和“上下文配给”

主持：swyx · 嘉宾：Doug O'Laughlin（SemiAnalysis 研究员，Substack“Fabricated Knowledge”作者，早年在 Twitter 上的匿名账号叫 Value Mule）· 发布日期：2026 年 2 月 24 日 · 时长：2 小时 7 分 · 整理：Joyce（@JOYCE9896）
资料来源：Claude Code for Finance + The Global Memory Shortage: Doug O'Laughlin, SemiAnalysis（本文依据 Latent Space 官方播客文字稿、视频章节和节目说明整理，是中文转述，不是逐字翻译；观点属于说话人，内容以发布当天为准）

这一期的内容

这期是 Claude Code 上线一周年的特别节目，节目说明把它叫作“double pod”：前半段讲 Claude Code，后半段讲内存。嘉宾 Doug O'Laughlin 早年是做股票的买方投资者，2018 年因为 ASML 迷上半导体，2020 年在自己的 Substack“Fabricated Knowledge”上写过一篇《GPT-3 and the writing on the wall》，判断摩尔定律放缓加上 scaling law 带来的需求，会让 NVIDIA 成为最大受益者。后来他和 Dylan Patel 一起做 SemiAnalysis。节目开头提到的那张图也出自他：他用 Claude Code 抓取 GitHub 上带 Claude Code 署名的提交，算出大约 4% 的 GitHub 代码由 Claude Code 写成（他说更新后已接近 5%），并预测年底会到 25% 到 50%。

这一期只有 swyx 一个主持人，他到 Doug 那边录的，碰上了暴风雪。围绕的问题有：Opus 4.5 之后 Claude Code 在研究工作里能做到什么、做不到什么；用 AI 做研究的“卫生习惯”（hygiene）和初级分析师会不会失去成长路径；GDPval 的结果是否已经够得上 AGI；AI 资本开支和 19 世纪铁路建设比有多大；Excel、Bloomberg、IDE 会不会被 agent 取代；Codex 和 Claude Code 谁领先；Microsoft 为什么在 OpenAI 上退了一步、Oracle 的发债为什么出了问题；TPU 的成本优势能维持多久；HBM 为什么会把整个 DRAM 市场挤空，上下文窗口会不会因此停在 100 万 token。swyx 追问最多的是“AI 产出的东西你凭什么信”和 Microsoft 到底算不算失误；两人分歧比较明显的地方，是 Doug 对 Conductor 这类中间层工具不看好，swyx 则把它比作多云策略，认为各有取舍。视频里没有插播广告。

01. 开场：AI 是初级分析师，以及两人的旧交

节目位置 0:00:00–0:03:40 · AI Slop vs Expertise / Reconnecting and Origin Stories

冷开场

视频开头先放了一段后面正片里的话（原位置在 0:47 前后，第 08 节会细讲）。Doug 说这东西“一直在犯错”，他把它当成初级分析师：初级分析师去收集那些麻烦的信息，上面的人把信息汇总起来做决定。过去，初级分析师（他自己就当过）做得多了，会长出一层“元层面”的思考，知道自己擅长哪类分析、命中率稳定，于是变成专家。他认为这种元学习（meta-level learning）现在的模型还没有；全世界花几万亿美元的人都相信它会出现，“最好会出现”。对他的公司来说，AI 把每个专家的能力放大了很多，但你仍得自己动脑，不能直接把 AI 产出的“slop”（粗制滥造的 AI 内容）交出去，他一眼就能看出哪些是 slop。

两人怎么认识

swyx 说两人第一次见面是在某届 NeurIPS（Doug 记得是温哥华那届）的会后派对，在那之前已经是很多年的网友。大约 2017、2018 年 Twitter 早期，Doug 还是匿名账号 Value Mule。Doug 说那是他最早的账号，后来又开了第二个，现在还有第三个主账号；最老的那个金融账号他当作“遗留账号”，不想公开。他说自己不太爱出差，可能会去韩国的 ICML。swyx 是专程去找他录的，碰上了“四年来第一场暴风雪”。

02. 从 ASML 迷上半导体，卖方研究看不到的东西

节目位置 0:03:40–0:06:44 · Falling for Semiconductors

swyx 说外界常听到 Dylan Patel 的故事，这次想讲 Doug 自己的故事：你原来是价值投资者，是不是有个导师把你拉进了半导体？Doug 说没有导师，是他自己钻进去的。他说自己当年与其说是价值投资，不如说偏重“质量”，想买那种能长期复利的好公司。他找到的那家是 ASML，2018 年，看完 ASML 又去读制造这些设备有多复杂、谁做得出来，一路读到教科书，越钻越深，整个半导体产业链都是从这里展开的。

swyx 想调出 Asianometry 的视频，Doug 说那个频道的作者 John 很厉害，有一整个播放列表讲光刻机的每个环节。Doug 说他最喜欢的一点是，这些东西都是科幻小说一样的技术，除了“会说话的智能机器人”之外，半导体制造本身就是科幻，他一直觉得这是人类造过的最重要的东西。

swyx 接着讲自己当过分析师，覆盖 TMT（科技、媒体、电信）这个巨大的板块，从 Sprint、Viacom 到 ASML 都在一个人手里。Doug 说 T、M、T 其实是三个完全不同的产业，2000 年前后才走得比较近，后来就分开了。swyx 说他当年也飞台湾，参加 Credit Suisse 这类券商组织的调研行程，但总觉得自己没搞懂，因为看到的东西都经过投资者关系部门过滤；要像 Doug 那样钻进教科书去学技术才行。可是对投资者来说，很难把底层技术和“这个季度、这一年意味着什么”连起来：基础知识太多，而且你会默认一切都已经计入股价，买卖产能传闻的台湾投资者、美国的 TMT 投资者都消息灵通。

03. 摩尔定律终结的判断，和 NVIDIA 这条大浪

节目位置 0:06:44–0:12:31 · Moores Law Thesis and Nvidia

旧剧本：半导体是成熟行业

Doug 说他跟别人不一样的地方有两点。一是年轻气盛，相信“这件事很重要，别人都没看见”，这挺有用。二是让他“激进化”的那个判断：他真心相信摩尔定律已经死了。那时候学一个行业要读券商写的行业入门报告（primer），报告里说半导体是成熟行业，八九十年代和 2000 年代还不成熟，现在已经整合完毕，增长不快。大家用的还是 2000 年代初的老剧本，很多人讨厌硬件，觉得半导体没那么值钱，软件才最值钱（他顺口说现在软件反而被看衰了，但这不在今天的话题里）。

他的看法是，每天造出一颗新芯片本身就是科幻，人们把它当成理所当然。等到芯片没法再按原来的速度缩小，过去白拿的性能提升就没有了，大家只能认真想办法，于是懂得做好芯片的公司获得了定价权。NVIDIA 是最好的例子：并行计算之外，它懂芯片、网络、设计、scale-up（把很多芯片连成一个大系统）的每个环节；过去只是“CPU 每年变好”就结束了。

2020 年那篇 GPT-3 文章

他说自己最喜欢的一篇文章是 2020 年在 Fabricated Knowledge 写的《GPT-3 and the writing on the wall》。逻辑简化下来就是供给和需求：scaling law（模型越大、数据和算力越多，效果按规律变好）让需求大涨，摩尔定律放缓让供给变慢，这对半导体很有利，并行计算会很重要，结论是 NVIDIA 差不多是唯一的受益者。他说这个长期预测他很满意，但他没想到幅度会这么大：当时会觉得“NVIDIA 应该不错”，结果 NVIDIA 成了全世界市值最高的公司。swyx 提醒，那时他写的论点不止这一个，也有没应验的；Doug 说他对自己的长期记录挺满意。他还说，CoWoS（TSMC 的一种先进封装工艺，把 GPU 和 HBM 封在一起）当年是冷门技术，现在居然算得上有点名气了。

和 Dylan Patel 的相识

他说认识 Dylan，是因为 Dylan 是他觉得全世界唯一一个跟他一样“半导体上头”的人，两人在私信里吵各种问题，后来才在会议上见面，只一起去过一次台湾。Dylan 是技术优先，他偏金融背景。他说自己有 ADD，总在追有意思的东西，擅长看趋势，2019 年就迷 TikTok；他的体会是，看到一个很大、自己又很有把握的浪，就值得全押上去，于是他围着这个判断重新安排了自己的生活。swyx 说后面还会聊内存周期和光通信，但这一期先围绕 Claude Code 一周年。

04. Claude Code 觉醒：4% 的 GitHub、卖方研究、评分表和上下文腐烂

节目位置 0:12:31–0:33:15 · Claude Code Awakening

用招聘案例题测 agent

swyx 调出那张“4% 的 GitHub 代码”图，Doug 说已经更新过，现在大概是 5%，而且生成代码越来越容易，这个数还会涨。swyx 问一个分析师为什么这么迷 Claude Code。Doug 说人终究是工具的使用者；基金经理或分析师的工作是找信息优势，用别人没用过的方式把信息拼起来，所以必须掌握最强的工具。

他说一年多以前（大约 3、4 月）就开始把 SemiAnalysis 的招聘案例题丢给各种 agent 做。这道题用于招核心研究岗的金融分析师：给一家公司，做分析，按指定格式交回来。他的想法是，agent 真正成熟时应该能一次做完人类要花 24 小时的多步骤难题；他常开玩笑说，它们会先打败最差的那批答卷。他用 ChatGPT 的 agent 模式、Claude Code、Gemini CLI 都测过，结论是“还差一点”。他也在 Opus 4 上 vibe coding（用自然语言让模型写代码，自己不怎么看代码）做过副业项目，很费劲，要反复反馈。

转折点是 Opus 4.5（他口头说成“Claude Code 4.5”）。他在圣诞节后有空，大概 12 月 26、27 日，未婚妻身体不舒服，他一个人折腾，加上当时有双倍用量额度。结果它开始“一次做成”（one-shot）各种 MVP，你让它改进，它还会解释你在做什么，而且你能在一定程度上信任它的结果。他之前也试过 GPT-5.2 时期的 Codex，从没顺畅地以 agent 方式跑通过。他说现在他已经离不开 Fast 模式。

财务模型精确 5% 没有意义，卖方研究的问题

swyx 问主要是不是做 Excel。Doug 说一般是仪表盘、Excel 之类混着用。它一次做个基础财务模型、把信息从一处搬到另一处还算可以，没到人类水平；但他说懂投资的人都知道，模型准 5% 从来不会让你做出更好的投资决定，没人靠“我的每股收益预测比别人紧一分钱”炒好股票。

他顺势批评卖方研究（sell side，投行和券商的研究部门）：这是三四十年投行业务的遗产，公司上市需要有人去讲它、发行证券，研究员给买入、卖出、持有的评级，最大的“卖点”是你的公司 IPO 后我们会覆盖你。后来银行监管变了，研究质量也散了，他说这是一个“40 年老、快撑不住的商业模式”。SemiAnalysis 不追每股收益的那一分钱，他认为那只是机械维护；他们擅长判断技术变化及其连锁影响。他举例：AMD 的 Helios 机柜如果按时出货、哪天能开始产出 token，会让 AMD 的收入差出几十亿美元；某种网络技术、某个瓶颈也是一样。把拐点的时间和幅度判断准，对股价影响最大。他强调 SemiAnalysis 是独立研究机构。

swyx 说他们像是“三项全能”：懂技术、懂金融，再加一种只抓要紧事、其余都不管的能力。Doug 说这就是分析师和基金经理之间的老对话：“真正要紧的只有一到三件事，把它们找出来。”比如这个 SerDes（芯片间高速串行收发电路）比那个好，大多数情况不重要，但某个情况下会打开一个巨大的机会。难的是产业链又深又宽，去网络技术会议上和一群博士聊激光器，你自己没有博士学位，光是“交学费入场”就很贵。

从个人持仓到“一切都是 skill issue”

他说自己还是个“股票人”，虽然在 SemiAnalysis 不能交易半导体和 AI 相关股票。他先让 Claude Code 把自己的持仓和笔记整理到一起，再做组合、跑基础风险分析，然后让它按他的投资风格建一套框架给持仓打分、再反过来攻击这些判断。迭代几轮后他发现，这个工具能很快把他的思考方式系统化，能做的事“什么都行”。他的口头禅是“现在一切都是 skill issue”（做不成是你不会用）。

那张 GitHub 图就是这样来的。网上一堆人跟他一样陷入“Claude Code 精神错乱”，他想知道哪些是真的。他听说 Claude Code 在提交记录里会留署名，就让 Claude Code 去抓所有提交：它想出系统的做法，用 BigQuery 每天拉一次数据（GitHub 的接口相对开放），算增长和占 GitHub 的比例，现在用一个 cron 定时任务每天更新。他说自己很爱看指数趋势，从没见过增长这么快的。swyx 提到之前有个叫 PR Arena 的项目，但它只看合并率，没问“占 GitHub 百分之多少”这个问题。

Doug 说那张图本身也是 Opus 4.5（或 4.6）画的。他让模型读了大约 70 本数据可视化的书，总结成很短的要点，做成一个“按 SemiAnalysis 配色和格式画图”的 skill（Claude Code 里可复用的说明文件），以后任何数据都能套用。swyx 说读 70 本可能是浪费，Doug 说 token 几乎免费，读 70 本和读 3 本成本差不多。他还会让模型“陪我在视觉上头脑风暴，怎样更好地呈现这些信息”，它会主动提出做成时间线。“You can just do things”现在是他的口头禅。

编码只是信息工作的一部分

他认为大家只从程序员的角度看这件事，可编码是所有信息工作的一个大子集。他引用了 Byrne Hobart（字幕作 Brian Hobart）很早以前的一条推文：做金融和写代码都是在搭抽象，Excel 就是巨大的抽象。他觉得编码其实更难，“难的都自动化了，简单的凭什么不能？”它会在边角犯错，但可以用办法把它逼到正轨上。他最喜欢用评分表（rubric）：“我在意 X、Y、Z，每项满分 10 分，打分”，这能缓解模型输出的随机性。

swyx 问评分表是和任务写在同一个提示里，还是任务做完再单独评。Doug 说两种都用。swyx 的理解是放一起模型能自我迭代，放后面它更会认真对待评分表。Doug 更喜欢分开：每个上下文窗口都是一次重新打开，放在一起会让信息混杂，结果带偏见；而且 Opus 4.6 很“谄媚”，什么都说“好的我来做”，分开评能减轻这种漂移。他说他现在对“怎么设计这些流程”有了自己的品味，比如 context rot（上下文腐烂：对话越长、上下文里杂讯越多，模型表现越差），有人第一次把它讲出来时他觉得“谢天谢地有人说了”。他还提到一个《人鼠之间》的梗图：Claude Code 跑到 500 万 token 已经乱掉，“是时候让它安息了”。

压缩、100 万上下文和子 agent

swyx 问他怎么做压缩（compact，把长对话压成摘要继续用）。Doug 说有了新的 100 万 token 上下文后，他尽量在一个窗口里做完一个项目，他做的项目不大。他觉得 100 万是大事：skill 和 CLAUDE.md（Claude Code 每次启动都会读入的项目说明文件）在 100 万里占比小得多，而 20 万的窗口会一遍遍被冲掉；子 agent（subagent）有自己的上下文窗口，结果贴回来，也省主窗口。他的看法是压缩只是把噪音一起压进去，最好的做法是在 100 万以内做一个高质量的项目。

swyx 提到 Anthropic 研究部门发过一份基于生产流量的报告，类似他们版本的 METR 图，显示软件工程占了大约 50% 的使用量，很多人说“软件工程有了 PMF，下面还有一长串别的”。swyx 的问题是：如果那些其实也都是软件工程呢，从 50% 涨到 80% 也没有阻碍。Doug 说他的“大脑洞”是：芯片在最上游，然后是 AI，再然后是软件工程，都是同一条算力链的延伸；代码是机器和真实世界交汇的地方，会成为解决其他一切问题的语言。

他的例子是 Claude for Excel 比“Claude Code 用 Python 调 Excel 的 skill 写进文件”差得多，swyx 问即使他们投入了那么多也差？他说是，“为什么要把汽车发动机塞进马车里”。Excel 那层抽象是为人类阅读做的格式；如果模型同样能把数据拼好，就应该更多考虑“给机器消费”的软件。他现在不在 PowerPoint 或 Excel 里画图，直接让它用 Matplotlib 出图。swyx 担心和以前的图风格不一致，Doug 说新图比旧图好，水印一样，提高信息流转速度更要紧，新图很快会比旧图多。swyx 说这让他想起 Bloomberg，“你们快变成 Bloomberg 了”。

05. Agent 集群：Claude 的 agent team 和 Kimi 的 swarm

节目位置 0:33:15–0:37:44 · Agent Swarms Reality Check

swyx 说自己有个有争议的看法：Anthropic 没有在 agent swarm / agent team（多个 agent 分工协作）上做 RL 训练。Doug 立刻同意：那只是实验功能，全靠提示词实现，效果很差。子 agent 还行，因为通常带着 CLAUDE.md 去做一件事；agent team 不行。他试的任务是把很多家公司、各自不同的 KPI 汇总进一个仪表盘，让它分组去做。

他说 Kimi K2.5 的 agent swarm 反而很好用。他拿它做过以前普通人碰不到的事：对模型做内部基准测试，“这组题每道做 20 次，比较表现，再定性分析 X 和 Y 的区别”。三个月前这完全不是他能做的，现在可以。他的体验是 Kimi 2.5 的 swarm 明显提升了模型表现，Claude 的 agent team 明显拉低表现，因为显然没做过 RL，只是在上下文里“知道”该怎么做。

swyx 说 Kimi 发过文章讲他们为此做了大量 RL，他自己也试过，界面里给每个 agent 起小名字挺可爱，但很费算力：跑一个 swarm 大概要 16 个节点的 H100，“你我都跑不起”。Doug 认为这是下一步方向：单个 agent 会继续变好，这只是又一个可以爬的基准；接下来比的是能把多少个 agent 串成更长的链条一起工作，可以看作推理问题的横向扩展。为此需要不会乱掉的上下文窗口和足够好的 token 效率。他的结论是 Claude 的 agent team 还是实验，会变好，Kimi 2.5 说明这条路现在就能用。

swyx 岔开说了几句中国模型：以前说中国 AI“小虎”是 DeepSeek 和 Qwen，后来冒出 Kimi（Moonshot AI）、MiniMax，Z.ai 存在更久但最近更活跃。他观察 Kimi 更在意产品化，DeepSeek 和 Qwen 不太在乎；Qwen 背靠 Alibaba，有办法产品化，但像 Gemini 一样，母公司别的事太多。Doug 说 Kimi 推得很猛，节目里提到了 Kimi Claw 等产品。

06. OpenClaw 的安全边界，和 Zapier 的创新者困境

节目位置 0:37:44–0:41:13 · Claude Bot Security Limits

Doug 问 swyx 有没有玩过 OpenClaw（一个常驻的个人 AI 助手项目，早先叫 Clawdbot，字幕里写作 Claude Bot）。他自己试过，一开始很兴奋，让它读邮件、看日历，随后意识到这东西很容易被提示注入（prompt injection：别人把指令藏在邮件或网页里，骗 AI 执行），这些又是重要的私密信息，于是退回来，“Claude Code 的精神错乱对我来说暂时够了”。swyx 的做法是开好几个邮箱，给 bot 一个安全的，表现好再升级权限；但 OpenClaw 没让他满意。Doug 也说不满意，不明白大家在激动什么。他说即使在专注的终端里，Claude Code 也会犯错：.env 里明明有他让它用的 API，CLAUDE.md 里也写了，它还是不用，“这不是真正的 AGI”，harness（包在模型外面、负责调工具和管上下文的那套程序）也还要你自己去驯服。它不是完美的 skill 执行者，每次注意力窗口会变，有时偷懒有时不偷懒，但做大量信息工作已经够用。

swyx 用 Discord 收发信息，他发现很多人用 OpenClaw 搭的东西，其实用 Zapier（老牌自动化工作流工具）也能做，而且更安全。Doug 说 Zapier 他也用过，并不好用。他认为区别在于 Claude Code 这类东西能把事情做完：Zapier 也许也能做完，但你可能花 8 小时点来点去、复制粘贴、确认安全，而 Claude Code 四分半钟就做完了，“早到但用错了机制，也没关系”。swyx 说这里有创新者困境：Zapier 的用户已经习惯在固定轨道上跑的严格流程，公司很难转向，所以一位联合创始人离开了。他说“你的先验会变成你的牢笼”（your priors become your prison），Doug 很喜欢这句。

07. Doug 的 Claude Code 配置：少量 skill、大量 API，预测内存价格的周末项目

节目位置 0:41:13–0:46:53 · Claude Code Workflow Setup

配置：内部 API 服务器，少即是多

swyx 问他的具体配置，用不用 hooks（在特定事件发生时自动运行的脚本）。Doug 说他只有几个基础 skill，加上大量 API；他们正在把 SemiAnalysis 的部分数据做成内部 API 服务器，让所有研究员都能调用，拿到一个基础层的上下文，他认为上下文才是最要紧的。swyx 说 hooks 被低估了，比如可以用 hook 做 Ralph Loop（让 agent 反复跑同一个任务直到完成的一种用法）。Doug 承认自己用得不多，只在调用 skill 时跑一些。一开始他也试过各种 hook 和复杂组合，经历了“Gastown、Ralph Loop 时代”，觉得那预示了未来，但目前保真度不够，撑不起很复杂的多轮流程，所以他转向“少即是多”：一组精干的小 skill，带足够的上下文；每次会话开头先说清楚这次要做什么，目标是在一个上下文窗口里完成。

例子：用时间序列模型预测 NAND 和 DRAM 价格

他的例子是一个“大概率行不通”的项目：微调一个时间序列基础模型来预测 NAND 和 DRAM 价格。先尽量收集数据，再微调、评估。他选了 Chronos 2（字幕作 Chronus 2），因为它支持协变量（covariates，和目标一起输入、可能影响价格的其他变量）。他让一个 agent 用 Serper 或 Exa 这类搜索 API 去找各种数据源，另一个 agent 处理“价格数据本身不完美”的问题，还让它推荐按小时租哪种 GPU。整个项目做成 SemiAnalysis 内部的 Vercel 仪表盘，好的话也许对外。反复迭代后，他得出结论：这个模型大概不行。

swyx 问是不是因为市场状态（regime）的问题。Doug 说是。他说这也是他对“一群年轻人拿 LLM 玩炒股比赛”有意见的原因：他们没学过金融，不知道过去确实能大体预测未来，直到基本面变了、宏观转向、风险偏好从 risk on 变成 risk off。swyx 说他曾给 Cognition 的人解释过这些，状态一变，规则会完全反过来。Doug 补充，每个状态几乎都是孤例，样本量因此变小，最后只能给出一些经验规则和一份检查清单。

但这个周末项目（他说烧了不少 token）留下了副产品：他手里有了能找到的所有内存价格数据，加上公司付费 API 后面的数据和其他增强数据源，还有各种协变量，比如 WFE（晶圆厂设备支出）、消费者信心和所有宏观指标。他接下来要让模型把每一轮内存周期的开始、中段、结束各由什么引起总结出来，放进一个公司内部能分享的仪表盘，“今天大概就能做完”。他说你可能觉得这只是收集信息，但从来没人做过：他自认是写半导体周期最多的人之一，尤其是八九十年代到 2010 年代的老周期；第一次做时，他是读旧年报、查每年 GDP、做一张巨大的表、再串出叙事，那是一辈子的工作量，像一个博士课题，现在一两天做完。

08. 研究的“卫生习惯”，初级分析师的处境，Heartbeat.md

节目位置 0:46:53–0:59:41 · Hygiene and Junior Analysts

swyx 的质疑：你凭什么能挑出它的错

swyx 反驳：这样的话你自己就没有足够的一手专家信息去批判报告背后的推理；而且你们要是给客户交了 slop 被抓到，后果很严重。Doug 承认里面有 slop。他说现在整件事成了一场“卫生习惯”（hygiene）的游戏。他放心这样做，是因为他自己做过那些功课，脑子里有大量“embeddings”，他靠的直觉背后是海量信息、预设情景和模式识别。接着就是开场那段“初级分析师”的话：模型还没有那层元学习；它对专家是巨大的放大器，而 SemiAnalysis 是一家满是专家的公司。

他的困扰是，以后对新人、初级员工用 AI 也许要更严：你得真的动脑，不能把 slop 交上来。没有认知投入的 slop 一眼就能看出来，最后那 5% 的“手工活”才要紧。他自己知道那 5% 是什么，几条经验规则就能改好：“这是最后 5%，我认为应该这样，按这些假设改，回车，好了。”他说目前人还必须在环里，总有一天模型会超过人；但现在如果不管它，它会把噪音越叠越多，最后全是上下文腐烂。他的说法是，在这个 agent 集群里，人是那颗“CPU”，这已经是巨大的倍数放大。

他为什么说自己“AGI 上头”了

他说这足以让他觉得 AGI 到了，前提是他对 AGI 的定义：能不能自动化或改变很多普通岗位、很多信息工作，他说是，100%。他不讨论 ASI（超级智能），那像宗教。数据分析是最好的例子：每季度让系统找出一些有意思的信息，他想象不出一个普通的 22 岁新人能赢过一个设计得当的 agent 系统，这类岗位看起来确实有风险。他说 Opus 4.5 的能力让 agent 第一次能做更大块的信息工作。它还是常犯错，不一定会调用 skill，上下文越长越笨，但能做很长的任务，只要你最后把关、产出可用的信息，就很有价值。

客户会用吗

swyx 问他有没有把 SemiAnalysis 的客户也带进 Claude Code。Doug 说他在纽约办公室要求每个人都试；至于客户（基金那边），整体比较保守，但你问任何一个分析师用不用 AI，都会说每天都用。他的推理是：他是最前沿的使用者，判断过这个工具很有用，“哪怕犯错我也会一直用”；其他人和他足够像，有优势就会用。他预测从 24 个月的视角看，Claude Code、Cowork（Anthropic 面向非程序员的桌面 agent 产品）之类会成为所有信息工作的基础配置。他朋友的基金经理刚发现 Cowork，让它读邮件，很喜欢。他说每个人的“那个时刻”不同，他的这次像当年第一次用 GPT-3.5 或 GPT-4：明知它会编，仍然比自己搜几个小时强，而且类比和模式匹配能力很强。

swyx 提到 xkcd 那张“自动化值不值得”的图，说 Claude Code 会把坐标轴撑爆。他的理解是，Claude Code 每次投入的注意力也许不如人，但能快速、并行地起很多个，所以你多了几次“握方向盘”的机会；人只有一次，用 Claude Code 也许有三次，而审核本身就是思考。Doug 同意，但担心另一面：他的专家判断是在“手机之前”的时代练出来的，现在注意力被短视频耗掉，他提到最近一家公司的财报电话会、地铁跑酷（Subway Surfers）那类分屏视频、酒吧里放的 B-roll 频道。他觉得这类技术很容易上瘾，他庆幸自己有积累能驾驭，但后来的人会很危险。

他说更麻烦的是：如果你从没花过人的认知去做那些事，就成不了好的审核者。他举例：你知道“估值是唯一重要的东西”，但如果这家公司在造假，两条就冲突了，你得知道自己脑中的哪条经验会覆盖另一条，这只能从经验里来。如果只做审核，可能就建立不起这些判断。swyx 概括为“只查错，不做原创思考”，Doug 说这是危险所在，也是他说的卫生习惯：一直按按钮很上瘾，但有时你得真的思考。

夜间批处理和 Heartbeat.md

swyx 说可以把元学习建模成每晚跑一个批处理任务，回看当天所有工作、提取经验。他喜欢 OpenClaw 里的 Heartbeat.md（让 agent 定时醒来、自己检查和反思的配置文件），觉得大家低估了它：这是 agent 第一次“一直在线、一直反思”。Soul.md 则更多是设定性格。Doug 说这是一个可以看清的设计模式：我们每天的工作，多半就是坐下来、在一次会话里做完一个项目、起身喝咖啡、再回来。如果 Heartbeat.md 能跨会话总结经验、只专注一类工作，比如客服 agent，它能看到每一次历史工单，这是任何人都装不下的上下文，再加一些验证防止搞砸，“感觉就是 AGI”。他说现在可以用更大的积木搭东西，积木可能是一整个业务。他说自己原本不算 AGI 派，Opus 4.5 让他的时间线提前了很多。

09. GDPval、AI 会不会通缩，以及铁路周期

节目位置 0:59:41–1:06:51 · GDPval and Economic Impact

GDPval 过了 70%

swyx 介绍 GDPval（OpenAI 推出的测评）：可以理解为一个覆盖更广的基准，覆盖可以建模的白领职业，挑的是在 GDP 中占比大约 2% 到 5% 以上的职业，所以叫 GDPval。人类专家和模型做同样的任务，50% 代表和行业专家打平。从 GPT-4o 到 Opus 4.1 有明显上升，此后 GPT-5.2 和 Opus 4.5 已经超过，现在是“70 多”，意味着模型稳定地胜过行业专家。swyx 问：这不就是 AGI 的定义吗？

Doug 说他认为是。有人盯着 ASI，那是在移动球门；会不会出现“机器神”、修格斯（Shoggoth，AI 圈常用来指代难以理解的大模型的梗）会不会来跟我们对话，他保持开放，会经常改主意，现在直觉上感觉不到。但就 GDPval 这个版本，也就是做白领工作，他说是，而白领工作占了世界工作的很大一部分。他最喜欢的数据是：曾经 90% 的人务农，今天不到 1%。他觉得这次会有类似规模的转变，不一定那么剧烈；目前他的体验是大家反而更累了。他说感觉像蒸汽机发明、火车来了，知识工作会全部改变。

经济的“千层蛋糕”与第五层

swyx 说他做宏观时学过一个经济发展阶段理论（名字想不起来）：先是农业为主，然后发现制造业，然后白领工作，然后成熟的金融业，像一层层蛋糕，旧的层占比下降，新的上升。Doug 说他的理论是会打开第五层，他相信人类会发明新的工作，人类适应性很强，地球上从最冷到最热的地方都有人住。但变化太快，5 到 10 年的落差对社会会很剧烈，而且就发生在我们这一代。

为什么还没体现在 GDP 里：一个“民科”猜想

他说自己好奇的是什么时候能在实体经济里大规模看到它。有人会说互联网时代也一样。他自称“完全是民科理论，别当真”：如果 AI 是高度通缩的呢？他最近聊到，GDP 最初是为了算一次世界大战（他记不清一战还是二战）里能从正常经济中抽多少资源去打仗而发明的。他“最辣”的观点是 GDP 这个指标会被 AI 严重挑战：信息工作按服务时长计价，如果把信息工作拆成单位，做出来的会多很多，但价值多少不知道；供给暴增可能带来通缩，也许会有一场“AI 的大萧条”，然后大家才学会怎么用它。swyx 说有可能。

铁路：他最喜欢的资本周期

Doug 说他在 Fabricated Knowledge 上写过一篇铁路的长文。大家起初都拿互联网做类比，但这次的建设规模已经远远超过互联网：他记得互联网那轮全部算下来按实际美元大约 1 万亿，按累计算今年已经远超。铁路更有意思，也更疯狂：农业之后，铁路是最早叠上去的一层。他的一个结论是银行业基本是被铁路“发明”出来的，因为需要融资，钱多到大约 85% 的票据都是铁路债务。他最喜欢的轶事是，在美联储成立之前，Andrew Carnegie 就是“美联储”，swyx 说那时是个人在扮演这个角色。他研究过镀金时代，那一轮建设规模大、部署时间长，前后 45 年，有三次繁荣和崩溃。他认为这一次会更快，因为信息流动快了，但不会一次涨完跌完，会是好几轮周期：先有一轮“小铁路周期”，再有一轮大的，现代铁路就是从中诞生的。

10. 资本开支占 GDP 多少，钱从哪来，Claude Code 一年值多少钱

节目位置 1:06:51–1:11:32 · Railroad CapEx Parallel / Funding Bubbles and Demand / AI as Junior Analysts

铁路的数字和今天

Doug 说铁路建设每年的资本开支占 GDP 高个位数，持续了大约 10 年，而今天的支出“完全在这个轨道上”。swyx 建议用占 GDP 的百分比来比，他说光 Stargate 就相当于美国 GDP 的 2%，而且还会涨，当然不会都在一年里花。两人查到的铁路数字是：资本开支占 GNP 的 4.8%，占全部固定资本形成的 25%。Doug 说加上 Stargate、Anthropic、xAI、Meta，我们已经在铁路建设的水平上了；swyx 说应该会超过，Doug 先说“大概”，又改口“我们会做到”。

钱从哪来

Doug 说他担心“钱从哪来”。swyx 开玩笑说这是个很朴素的担忧，Doug 说一点也不朴素，每个资本周期都是这样：规模大到“必须建，价格无所谓”，然后某天回头一看，“那价钱可真贵”，泡沫就是这样来的；他也提到中东的资金。他的框架是有一条需求曲线和一条供给曲线，没人知道它们何时相交，但总有一天会；每年我们都在探索需求曲线，同时尽力部署供给。他不想说“数字永远涨”，那在智识上不诚实。

他个人的需求：一年 2 到 3 万美元

但 Claude Code 是他第一次觉得“需求涨得太多了，我个人都在狂吞”。他说 Max 订阅已经不够用，现在走 API，用 Fast 模式加 100 万上下文，“这是成瘾级别”。swyx 说有人一口气买五个 Max。Doug 估算它对他每年值 2 到 3 万美元，甚至更多，他无法定价，不知道弹性。swyx 说你等于花钱雇一个完全听话的初级分析师；Doug 问那要多少钱，swyx 说 9 万美元，而且它能并行，你可以有 100 个；管不好一个“一年 2 万”的初级分析师，那是你的 skill issue。Doug 同意，但说这东西才两三个月大，就像 iPhone 刚出来第一个月，没人会骂你不会设置。

他说在最前沿的好处是能看到设计模式实时长出来。他提到 SemiAnalysis 一位经历过整段技术史的资深同事 Tanch：早期互联网时，大家并不确定浏览器会赢，有人以为会是“远程网页文件服务”，那时也在找设计模式。他认为现在又是这样，大家要一起摸索最好的卫生习惯、设计模式、抽象层级，至于会冲击多少 SaaS，谁也不知道。

11. IDE 之死：Excel、Bloomberg，以及 Codex 对 Claude Code

节目位置 1:11:32–1:23:43 · Death of the IDE

Excel 和 Bloomberg 是分析师的 IDE

swyx 说两个月前 Gas Town 的作者 Steve Yegge 在节目里说 2026 年是 IDE（集成开发环境，程序员写代码的主软件）死掉的一年，他两三周前也觉得“他完全说对了”。Doug 说他日常用的从来不是 IDE，是 Bloomberg 和 Excel；他认为软件会先走到这一步，金融业还没到，但“Excel 是分析师的 IDE，Bloomberg 也是”，这些都会结束。他回忆学 Bloomberg 要看视频、记各种子菜单和快捷键、哪个函数该用在哪，“这是马车时代”。能完美检索和分析信息的 agent，可以在没有历史包袱的更好界面里把这些拼起来。

所以他最辣的观点是 Microsoft 损失最大：Excel 是通用的、给人做信息工作的 IDE，PowerPoint 和邮件也是，这些是被设计成广泛通用的基础抽象层，他觉得这已经不重要了，Claude Code 或 Cowork 会摧毁这一切。他说他打心底相信，因为他已经有过那个时刻：“我再也不会在 Excel 里画图了。”

swyx 说他很难放手，因为他太熟悉在 Excel 里直接操作。他说他的第一家创业公司就是想做 Bloomberg 的替代品（字幕里提到 Sentieo），Doug 说自己当过 Sentieo 的客户，还记得它被收购时的不满。swyx 的结论是 Bloomberg 其实是三样东西：聊天网络（像 Slack）、很好的新闻、数据源，UI 不是重点。Doug 说他在努力把 Bloomberg 从 SemiAnalysis 拿掉，改用一家数据商的 API（字幕不清），全面转向“API 加 Claude Code”，前提是可信、可核验的数据源。swyx 说交易员不行，他们需要 Bloomberg 的聊天网络，交易还受监管记录；Doug 同意，但说对分析师来说可以。他说以往每一代 AI 出来他都觉得“我还是要用 Bloomberg”，这是第一次觉得不在乎了，Bloomberg 的边际价值已经比不过它的笨重。swyx 说这一下省掉每年 1 到 2 万美元。

年底预测：25% 到 50%

swyx 问他对 Claude Code 年底占比的预测，是不是 25%。Doug 说那是“极度保守”的数字：按目前速度大概是 50% 左右，他想给一个 95% 置信区间内的数，25% 在区间里，所以大致在 25% 到 50% 之间。他说公开能看到的只是一部分，看不到的比例可能更高。

Codex：编程很强，但“只想写代码”

swyx 问他是否也在看 Codex。Doug 说他们被骂成“Codex 黑”，但他其实觉得 GPT-5.3 Codex 很好。他之前写过一篇文章（付费部分），论证 Claude Code 和 Anthropic 强在 token 效率和上下文腐烂处理比 ChatGPT 好，结果 5.3 Codex 一出来，这条论点就不成立了，“他们回来了”。他喜欢 Opus 4.6，因为他虽然用编程的方式和它交互，做的却是广义的信息工作。Codex 为了在 SWE-bench（软件工程基准）上赢，被 RL 训练得太想写代码：你让它去搜一些网站，它会去写一个爬虫程序；他只想让它直接读网页内容。他说 Codex“编程上头”，泛化到非编程任务不如 4.6，比如做评分表、做研究。但他对 Codex 很乐观，他们也在追踪，Bloomberry 的图上 Codex 份额不小，Claude Code 领先。

他承认统计口径有问题：Codex 不在每次 commit 上署名，只在 pull request 上署名，按 PR 算两者比例接近得多，Roon 等 OpenAI 的人因此说他们没算进去，他承认确实没算。他赌 OpenAI 一旦有新的预训练模型，再配上 5.3 Codex 那套很强的 RL 栈，局面会翻转。swyx 指出图上 GitHub Copilot 排第一，Doug 说没听过身边谁用 Copilot，swyx 说那是旧金山泡沫，很多 Windows 用户你根本不接触；Copilot 的 ARR 他认为至少 10 亿美元。他们还谈到统计方法：VS Code 插件的每日安装量只是一种口径，Claude Code 默认不走插件，NPM 下载是另一种，Anthropic 现在也有自己的安装器，很难精确追踪。

Doug 在看的另一个信号是 Codex 回暖：OpenAI 说 1 月到 2 月用户翻倍。他有点怀疑，因为 ChatGPT 入口巨大，弹个窗口就能导走大量用户。swyx 说 Codex 负责人 Alexander Embiricos 刚在 Lenny 的播客上说他们在网页端投入还不够，所以他认为弹窗的贡献接近零。Doug 说 Codex 的 Mac 应用很好，编程方面他很看好，只是非编程任务用不顺。

Conductor 和中间层

swyx 问他用不用 Conductor（一个能同时调用 Codex 和 Claude Code 的工具）。Doug 说没用过。swyx 说第一方应用会偏向自家模型，Conductor 让你按任务挑选，算是干净的超集。Doug 对此存疑：建在一个增长很快、钱又多的平台之上的东西，他不看好。他用 PaaS 举例：当年 IaaS、PaaS、SaaS 三层，PaaS 夹在中间，总被上下两层吃掉，中间层除非理由特别充分，往往会死。不过他也说，眼下他喜欢让两个模型互相审，让它们互相吵很有用，可能会试试。swyx 说这像云计算里的多云之争：多云能用各家最好的，单云能吃透一家的细节功能，没有对所有人都对的答案。两人都说喜欢看这场“赛马”，也提醒自己第二名的规模也很大；Doug 说 2017 到 2020 年的科技圈很无聊，现在很有意思。

12. Microsoft 与 Oracle：租给“蛮族”的城墙，发债的流动性问题，TPU 外卖

节目位置 1:23:43–1:36:46 · Microsoft and Oracle Stakes

“Microsoft 退出 AI”这个标题

swyx 说 Doug 上 TBPN 时，节目给他起的标题是“Doug O'Laughlin 认为 Microsoft 退出了 AI”。Doug 说他没回看，他的原意不是“退出”，是“损失最大”：Microsoft 是人类用来做信息工作的横向软件公司，“我画不出更大的靶子了”，而且体量比 Salesforce 大得多。他说 Microsoft 还有 Azure，没出局；问题在 Azure 和 OpenAI 的关系。

他的比喻是古罗马雇蛮族当雇佣兵守城，swyx 接话说像《权力的游戏》里的黄金团。蛮族每年变强，终有一天会说“我们自己翻墙进来就行”；Microsoft 每年把 GPU 租给这些“蛮族”，自己的城墙和护城河就越来越破。swyx 说这像当年 Google 和 Yahoo。Doug 说历史上这种局面只能二选一，两头都做不好会落到第三种更差的境地：要么全力做 Azure，变成“哑管道”，就像电信时代的 Charter；要么不理这些人，自己投入、抄他们的功能、修护城河，那就要为了股价少投 Azure。后者很难，因为 Microsoft 的股价主要押在未来几年的 Azure 收入上；他估算剔除 Azure 的 Microsoft 只值 8 到 10 倍市盈率，Steve Ballmer 时代就跌到过 10 倍左右，后来靠 Azure 和 Office 365 才拐上去。

是不是失误

swyx 说这是他见过最奇怪的决定之一：Microsoft 是 OpenAI 的领投方，拿着协议，却有意识地退了一步，问到底发生了什么。Doug 说他认为这是财务决定，是关于股东、ROIC（投入资本回报率）和愿意烧多少现金的讨论。他判断 Google 和 Meta 的自由现金流会降到零附近，Microsoft 没有。Satya 不是创始人，是职业经理人，有董事会，swyx 说他是在“负责任”。Doug 说这种负责任就是创新者困境：今天要不要最大化股东价值和现金流，还是相信 AI 会杀掉核心业务、押上整个公司。他的看法是 Satya 不是信徒，“不怕修格斯”，觉得 AI 只是新的 Lotus 或 Excel 那样的工具。

他说 Microsoft 在财报电话会上讲过，他们本可以增长得更快，但要把资源投回内部能力。他的解读是“少雇蛮族，把钱拿回来修城墙”。2023 年第一次大交易时大家以为 Microsoft 会通吃，它有分发渠道，会有完美的产品；现实是 Claude for Excel、Claude for PowerPoint 就是 Microsoft 本该做出来的东西，而 Anthropic 还不是它的主要“蛮族”，只是“山那边的部落”，夜袭一次就能把城堡洗劫一空。所以 Microsoft 被卡在中间，会继续往回收：做内部训练、做更多基础模型（swyx 问是不是 MAI，他说是）、用它能接触到的权重。他对此怀疑，因为执行一直很糟；swyx 说还要再看，毕竟是全球最大的公司之一。

Oracle：方向没错，节奏和发债搞砸了

swyx 反问：Oracle 接了 Microsoft 让出的盘子，那 Oracle 算不负责任吗？Doug 说 Oracle 的规模让它算是不负责任，接盘本身没错，但整件事是“乌龙球”：信息传递搞砸了，融资也搞砸了。它一开始太激进，那个季度说出了 4000 亿美元的数字，许诺了全世界，然后尽可能多地融资，这又是它第一次做这么大的建设，于是出现延期，市场开始说“踩刹车”。他认为如果分阶段做，管好预期，今年已部署 GPU 带来的收入可以部分自我造血，走一条平滑的路径，不搞一次性大爆炸。

他说真正出问题的是债务那一侧。他提醒自己的数字是很早以前算的、不精确：假设整个投资级 TMT 债大约 5000 亿美元，Oracle 大约占 1350 亿。每次发一笔巨大的新债，都要给投资者更好的条件才能让人买你的而不是别人的，于是整个指数跟着下跌，swyx 说这是供给问题。Doug 说他从没想到会碰上这样一个瓶颈：市场里能吸收的债务供给。超大规模云厂商（hyperscaler）历史上一直靠自有现金流，从没大规模发过债，第一次出手规模就完全不同。他认为 Oracle 是在一个流动性不好的市场里太激进了，应该一点点加仓式地进去；Oracle 的 CDS（信用违约互换，反映市场对违约风险的定价）引发恐慌，他认为很大程度是机械性的供需问题，Oracle 付得起。

他接着说“反过来讲”：Microsoft 本可以完全用内部资金做这件事，这才是失误，因为 Microsoft 的举债成本和美国政府一样，按信用评级，它在资本层面就比 Oracle 多 2% 的利润空间，这没法比。他说现在 Microsoft 在摇摆：一边在 Copilot 上很防守，Satya 亲自当 Copilot 的产品经理，一边从 Azure 后撤，而竞争对手在抢供给。他认为 Microsoft 必须选一个方向，并说有新信息他会改观点。

TPU 开始对外卖

1:34 左右 swyx 转到 TPU：以前买不到当代 TPU，现在 Google 开始对外供应。Doug 说他觉得是 Sergey Brin 不想输。过去 DeepMind 的思路是把 TPU 都囤起来，为什么要给 Anthropic？他认为去年 Gemini 3 之前，Google 发现自己囤着一堆 TPU，消费端却被打得很惨，那囤着有什么用。

他说 SemiAnalysis 在 TPUv8 的文章里写过：他们认为 Nvidia 的 Rubin 会更有竞争力，Ironwood（TPU v7）是 TPU 相对 Nvidia 的 TCO（总拥有成本，含购买、电费、运维）优势最大的一代。处在最强点时有两种选择：榨利润，或抢份额；他认为通过 Anthropic 对外卖是在抢份额。他估算 TPU 在 Google 内的价值可能在 1 万亿美元左右，前提是拿到 30% 左右的市场份额；大家一直在试图攻破 Nvidia 在商用芯片（merchant silicon）上的护城河，现在 TPU 的领先幅度最大。但当年做 TPU 的核心团队很多已经去了 OpenAI 等公司，分散了，差距可能会缩小。所以他认为 Google 应该现在抢份额：一旦有了装机量，客户就有升级的动力。AMD 的大问题就是没有装机基础，没人是从旧 AMD 卡升级。TPU 的软件生态、硬件、网络都已成熟，又有一个真正会用的外部大客户，“想要份额，现在就是时候”。

13. TPU 的窗口期和供应链：HBM4 与 Rubin，黄仁勋的酒局

节目位置 1:36:46–1:41:53 · TPU Window Opens / Supply Chain Reality Check

swyx 问 JAX 是否在学术界相对 PyTorch 占上风、会不会帮 TPU 赢。Doug 说他在这方面没有特别的视角。他最期待的是 SemiAnalysis 的 InferenceX 基准以后会加入 TPU，那能用数字说话；他们预计按价格算 TPU 会表现很好，是目前 TCO 最优的，领先幅度不小。他说 Anthropic 的态度很清楚，甚至 OpenAI 在完全不受限的情况下也会尽量多吃 TPU v7，在 Rubin 出来之前它是最抢手的。但供应链才是现实，TPU 买不到那么多。这个 TCO 优势现在处于最大开口，等黄仁勋那边把东西理顺、产品有竞争力，窗口就会关上。他说最大的瓶颈可能是 TSMC，一层层追溯都回到晶圆厂，光模块那边也一样。

他说 TPU 的系统架构设计得很巧、很稳定，而且已经证明可以在上面预训练大模型，这对 OpenAI 是一记重击，不过他认为 OpenAI 很快会调整好。他的判断是这个故事大概能讲一到两年，接下来他们认为 TPU v8 对 Rubin 的竞争力会弱一些，窗口开始关闭。swyx 问技术原因，他说是 HBM（高带宽内存，叠在 GPU 旁边、给芯片高速供数据的内存）：HBM4 对 HBM3。他说 Nvidia 总是把油门踩到底，像 F1 赛车一样拉满；TPU 更像一个可复制、稳定性很高的大型 pod，这符合 Google 做基础设施的传统。他认为 GB200 如果按时、稳定地推出，会完全压过 TPU v7，但它延期了，也不稳定。

他说在供应链上 Nvidia 无人能比，它掌控整条供应链。HBM 涨价也会落到 TPU 头上。黄仁勋在亚洲和韩国厂商、TSMC 的人挨个喝“爱情酒”（love shots），屏幕上有三星会长，还有 Hyundai 的会长，他说这样做是为了拿到芯片。swyx 问 Sergey 会不会也去台湾喝酒拿货，Doug 说不会。他说 TPU 有机会，但受各种瓶颈限制产量有限；Nvidia 会拿到性能最好的 HBM，在机柜密度路线图上排第一，用最好的连接器，整个系统又会被拉到极限。TPU v7 这颗芯片三四年前就设计完了，人才分散的影响会越来越明显。他们目前的判断是，HBM 和内存的 scale-up 会让 Rubin 占优，这决定上下文窗口能做多大。

14. HBM 挤压：3 到 4 倍的换算比，DRAM 还可能再涨 100%，CXL 复活

节目位置 1:41:53–1:48:14 · HBM Memory Squeeze

为什么 HBM 会吃掉 DRAM

swyx 说他喜欢 SemiAnalysis 分析的一点是，问题不止在上下文窗口和 KV cache（模型生成时缓存的中间结果，上下文越长占内存越多），KV cache 还要卸载到 HBM 以外的内存，整条内存链像瀑布一样被挤，他说像一次轧空。Doug 纠正说那是供给挤压，不是轧空。两人提到 SemiAnalysis 新发的《Memory Mania》文章里的换算比：swyx 给听众解释，HBM 需求大，而一个单位的 HBM 大约要消耗三倍于普通 DDR 的产能，良率也不完美，总会损耗一部分。Doug 说比例是三比一到四比一，下一代可能更高。

他打比方说（他自己写过一篇叫“super oil”的文章）：发明了一种更高级的航空燃油，造它的唯一办法是把其他燃油大量浓缩精炼，所以只要这边有需求，那边立刻短缺。他说“我们刚走出 NAND 和 DRAM 史上最惨的一轮”，他能追溯到的类似一次是 1996 年前后（他口头用的词是 shortage，但从上下文看说的是那轮下行：厂商现金流转负、没人投资、甚至可能破产）。与此同时新需求来了，尤其是 HBM：每一比特 HBM 对 DRAM 产能相当于 4 倍的乘数，于是所有 DRAM 产能都被占了。

两年追不上

他说上一轮太惨，没人投洁净室和设备，这些是交期三年的东西，洁净室本身就要两年建成，大家都停了；现在需求“比上帝还多”，KV cache 的卸载又把中间那层内存也吃掉了。看供需，他认为两年内追不上。SemiAnalysis 的结论是 DRAM 价格可能再涨 100%。再涨 100% 他认为会出现需求破坏：swyx 问具体什么样，他说超大规模厂商在边际上少买一点。讽刺的是，美国很多数据中心都在延期，原定 12 个月上线的变成 18 个月，于是可以和内存价格“玩胆小鬼游戏”，把采购往后推。另一边，现有的订单会尽量提前，重复下单、三倍下单，内存厂看到巨大需求；到某个时点买家会说“提前够多了，反正电力也卡着”，订单放缓。他说历史上内存价格就是从这里开始崩的。但他看整体需求和已采购的电力容量，缺口仍然很大。

他说 AI 交易里最明显的一条腿就是投资内存产能：SK hynix、Samsung、Micron，以及半导体设备（semicap）都在大涨。swyx 说他在之前的基金时，赚的钱很大一部分来自 Micron。两人提醒听众，这会影响到手机：swyx 为录播客设备买了一张 SD 卡花了 100 美元，Doug 说那还只是 NAND，又说起 64GB DRAM 的价格；他自己打算提前换 iPhone，因为 iPhone 的内存一旦按现货价采购，价格会上涨 100%。swyx 开玩笑说以后要买旧 iPhone 拆内存。

CXL 复活

Doug 说这个玩笑其实有真实版本：CXL（一种让 CPU 外接、共享内存的互联标准）是云时代很热的一项技术，做 CPU 的内存扩展、把 CPU 和 DRAM 做成弹性池子。它一直没起来，因为 HBM 这条高性能路线压倒了一切。现在它会起来，原因是大家会把 DDR4 和能找到的每一点旧内存装进机柜，通过 CXL 挂上去。他说自己曾经是 CXL 多头，后来看清它要死了，现在“它回来了”，唯一目的就是把旧芯片汇集起来接到新系统上。

15. 上下文配给时代，权重烧进芯片，CPU 也开始紧张

节目位置 1:48:14–1:57:43 · Context Rationing Era

上下文窗口会停在 100 万

swyx 说包括 Sam Altman 在内，大家都在预测更长的上下文窗口，但实际已经在 100 万左右停了两年。Doug 说他也一直在想这件事：不会到 1 亿，更不会到万亿，“就是这样了”，可能五年、十年。资本主义会不会把供给补上？大概会。但他猜计算史上常见的做法会出现：给上下文窗口做分档定价，比如免费版 ChatGPT 只给 1000 token 的上下文，然后对 100 万收 100 倍的价。“100 万上下文就像一座豪宅”，swyx 说你现在就住在豪宅里。Doug 说他当场想到一个词“上下文配给”（context rationing），以后可能发券，“你今天能用这么多上下文”，大家得学会省着用。

Doug 反过来问 swyx：从论文看，超长上下文的效果会掉，模型并没有真用上全部上下文，那 1 亿的上下文还有意义吗？swyx 说 1 亿的版本今天就有，但各有毛病，没有用全注意力：用状态空间模型（SSM）甚至 LSTM 也能处理 1 亿 token，但并没有对每个 token 都充分注意。他认为长上下文的曲线会在算法上继续改进，但永远不会全部用满。swyx 说对他来说重要的是，Doug 代表的是软件这一侧永远绕不过去的物理约束。两人又开玩笑说明年可能按上下文窗口计费，还提到最近的递归语言模型（RLM，让模型反复复用同一个上下文窗口），Doug 说他对这块是外行。

Taalas：把权重烧进芯片

swyx 问 Taalas（字幕作 Talus）：这类定制 ASIC 把模型权重直接烧进芯片，就不需要内存。Doug 说他没研究过，但觉得说得通，时机也正好。传统问题是能不能做大，可现在很多生产环境里的模型比人们以为的小，swyx 说都被蒸馏得很小了。Doug 说权衡在于：能不能把一个效率足够好、处在帕累托前沿上的模型直接烧进硅片，不需要内存、可以无限扩展，还是要追求长上下文那一端的性能。他认为 Taalas 有它的位置，因为市场在分化；prefill 和 decode 分离（把处理输入和逐字生成拆到不同硬件上）就说明，追求性能的推理服务会成为一个细分市场，训练和大规模生产是另一块，我们一直用同一套词描述，其实应该拆开看。

swyx 问为什么 Etched 这些公司没先做到。Doug 说 Etched 的思路是做一个很大的脉动阵列（systolic array，一种矩阵乘法专用的计算结构），押的是一切都受算力限制，但他看到的生产问题都出在内存上，而且 Etched 没有把权重烧进芯片，这是两回事。swyx 说最快的办法就是什么都不传输。Doug 说他对 AI 加速器初创公司的命中率评价很低，因为“它们在哪？”，在 Cerebras 和 Groq 之前都被认为失败了，即便现在大家也在问拿 Groq、Cerebras 做什么。swyx 提到 SambaNova，Doug 说那家更有意思，但交易方面有各种问题，他跟得不多。

CPU 短缺：一个“阴谋论”

swyx 问他之前提过的 CPU 短缺。Doug 先讲一个他自称“阴谋论”的观察：最近网络服务好像经常宕机，而且是所有云同时，不只 AWS，也不只 GitHub 和 Azure。原因可能有两个：一是 vibe coding 写出的代码被直接上了生产；二是现在正好处在 COVID 时期那批采购的 5 到 6 年换代周期，2020、2021 年大家买了大约 1000 亿美元的 CPU 等设备，现在到寿命了。正常情况会大规模更新，但大家把预算都挤去买 AI，CPU 只做维持性资本开支。讽刺的是，编程 agent 生成的海量软件要跑在 CPU 上；RL 训练用的 RL gym（模拟软件环境供模型练习的训练场）也大量用 CPU。量级不如 GPU，但趋势很大。所以他认为 CPU 短缺一部分来自换代周期，一部分来自 Claude Code 带来的软件增量，还有 RL 的真实需求。swyx 补充，生产环境里的 agent、RLM、OpenClaw 都要算力。Doug 说这块过去两年严重投资不足，只要上面加一点点斜率，就会短缺。

swyx 打趣“半导体分析师说半导体数字会涨”，Doug 说“那你告诉我哪里错了”。他说最离谱的是内存价格会涨到我们得选择让哪些东西涨价：低端手机可能没有了，今年可能买不到游戏显卡，因为你的出价只有市场价的一半。他说历史上内存从没成为这种程度的约束，这种短缺会怎样被消化，很值得观察。

16. 怎样写作，和走完大陆分水岭步道的六个月

节目位置 1:57:43–2:07:39 · Writing And Trail Lessons

写作：每周一篇，第二天早上动笔

swyx 问他怎么写作。Doug 说进入 SemiAnalysis 后写得少了一点，但还在坚持写 Fabricated Knowledge，因为他和写作有很深的连接。LLM 出现之前，他最强的信息能力是读和综合：速度快、吞吐大、理解度还可以。朋友读完博士，他去读论文能大致明白；迷上半导体时他硬啃教科书，理解不深，但能读下去。他从小就是重度读者，开 Substack 是想讲自己的故事，读得多自然就爱写。

他说最有帮助的是从 2021 年 10 月起每周都写，连续了很久，最近断了一些，因为 SemiAnalysis 加 Fabricated Knowledge 很难兼顾；2024 年全年都在坚持，硬规定每周一篇，尽量两篇。所有讲写作的人都说同一件事：多写。swyx 说他现在每个工作日都写。Doug 说他不喜欢 LLM 写的文字，只用它做构思、列提纲、做研究：把凌乱的想法交给它整理成提纲，他看着提纲一边构思一边写。他喜欢《On Writing Well》这本非虚构写作经典，已经把它总结成一个 skill，让模型按这本书的风格指南帮他改稿。

swyx 问他有没有维护选题清单，swyx 自己放在 Apple Notes 里。Doug 说从来没有，他都是“一次成稿”：一个想法在脑子里转一阵，攒够信息能写出一份粗糙提纲时，就一口气写完。swyx 说他怕忘，所以用“mise en place 写作法”（借用厨房备料的说法）：平时异步地往一个地方塞数据点、引语，到时候再统一“下锅”。Doug 说他的预写大多在脑子里，也会丢在 SemiAnalysis 的 Slack 里，需要时搜出来。他最推荐的技巧是：预写、思考、做提纲，什么都做，就是不写正文，然后去睡觉，第二天早上开一个新标签页直接写，“早上新鲜的上下文窗口”是他的头号写作建议，通常能直接写到 60% 到 75%。

CDT：六个月、约 2800 英里

swyx 说自己从来没休过假，总觉得这个时候休息就会落后；他刚听说一位 OpenAI 的朋友休了一年骑车穿越日本。Doug 在 AI 之前做过一次长期休假：美国有三条长距离步道，阿巴拉契亚步道（AT）、太平洋山脊步道（PCT）和大陆分水岭步道（CDT）。他走的是 CDT，最长也最偏远。他说按每英里算 AT 其实最难，但他选 CDT 是因为它最让他害怕，他想如果这辈子只有一次机会，就做最难、最有成就感的那个，事实上之后也再没机会。他是 2021 年走的，在那篇 GPT-3 文章之后。他觉得错过了 Substack 增长很大的一年，swyx 说他后来发展得也不错。

全程六个月，路线约 2800 英里，他实际走了 2850 英里左右，基本一个人，路上会遇到人。他听有声书听到厌烦，听音乐也听到厌烦，无聊到极点。他说在那之前，人总是被一个情境推到下一个情境，你以为了解自己，知道什么激励你、遇到事怎么反应；走完之后，他对自己的认识更清楚了，知道自己的界限在哪，哪些事太吓人、太难他不会做。他说那是浓缩的、很强烈的一段人生；回到马斯洛需求层次的底层很有意思，今天聊的这些都很抽象，人类本来是为在泥地里求生而进化的。他经历了“最低的低谷和最高的高峰”：又饿又怕又孤独，问自己在干什么，也有“活着真好”的时刻。他推荐年轻时去走，后悔没在大学毕业后就去。他说，自我掌控是最重要的“工具使用”，swyx 用这句话结束了节目。
