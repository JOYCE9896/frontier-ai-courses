Diogo Almeida：为什么在 OpenAI 做不出 Jev

TypeSafe 创始人讲他们的第一个“System One 模型” Jev：一个输出给代码直接用的判断型 API 模型，三种原语 choice、score、noulli，为什么拒绝公开榜单和拒答，怎样把 AI 工作流拆成小决策，以及他对 RLHF、RLVR、neo-lab、“Pacing the Frontier”和 KV cache 的看法

主持：swyx · 嘉宾：Diogo Almeida（TypeSafe 联合创始人兼 CEO，曾在 OpenAI 参与 InstructGPT，是那篇论文的作者之一）· 发布日期：2026 年 9 月 21 日 · 时长：2 小时 22 分 · 整理：Joyce（@JOYCE9896）
资料来源：Why I couldn't build Jev at OpenAI — Diogo Almeida, TypeSafe Co-founder & CEO（本文依据 Latent Space 官方播客文字稿、视频章节和节目说明整理，是中文转述，不是逐字翻译；观点属于说话人，内容以发布当天为准）

这一期的内容

Diogo Almeida 在 OpenAI 做过指令跟随模型，是 InstructGPT 论文的作者之一，后来离开创办 TypeSafe（TypeSafe AI）。录这期节目的那一周，TypeSafe 刚发布第一个模型 Jev。Jev 是一个通过 API 调用的模型，他们把这类模型叫“System One 模型”或“large programmable model”：输出给代码直接消费，不拿来聊天。它的调用结果是三种类型之一：choice（从一组选项里选一个）、score（打分）、noulli（带概率的是或否），每个结果都带校准过的置信度。产品主打“每美元智能”（intelligence per dollar），名字来自 Jevons 悖论。节目说明提到，发布视频的播放量约 4000 万。节目说明还给出了 TypeSafe 训练方法的名字 RLCD，全称 Reinforcement Learning for Calibrated Decisions（针对校准决策的强化学习），这个方法没有公开发表。

这一期只有 swyx 一位主持人。节目围绕几个问题展开：Jev 跟 RLHF 聊天模型、RLVR 推理模型的训练目标有什么不同；为什么 Diogo 认为 API 不应该拒答，也不该做安全对齐；为什么他反对公开 benchmark；开发者应该怎样用 Jev 把一个大提示词拆成很多个小判断；他为什么说就算给他 10 亿美元也不会做预训练；他在 OpenAI 的经历，以及他对多数 neo-lab 的批评。swyx 追问最多的地方有三处：模型会不会悄悄量化、要不要给出版本稳定的承诺；没有微调时，校准不准该怎么办；还有拿 Jev 做多跳推理时效果下降。swyx 和他看法明显不同的地方，一是 API 是否可以拒绝用于战争，二是“Pacing the Frontier”到底是不是误导公众。Diogo 自己说话常常跑题，节目里有大量插话和玩笑，下面按章节顺序整理。节目没有广告。

01. 发布周的状态和开发者社区

节目位置 0:00:00–0:04:19 · Intro / Jev Launch Week and the AI Economic Revolution

swyx 开场说，Diogo 这一周发布了 Jev，整个时间线都在讨论它，问他现在感觉如何。Diogo 说情绪上“从没这么糟过”，作为技术型 CEO 要四处救火，整个人快散架了。精神上他很兴奋。他说多年来他一直觉得整个 AI 圈像游乐场的哈哈镜屋，大家都在说奇怪、不合理的话；这一周他第一次觉得自己和现实同步了，大家终于看到 AI 可以比原先以为的多做很多事，“由 AI 带来的经济革命又回到了桌面上”。他反复说要感谢开发者。

swyx 提到 Diogo 前一天说过，他宁可把时间给社区的 town hall，也不先见 VIP 和投资人。Diogo 说跟“重要人物”谈话让他觉得有点不对劲，在他排得满满的日程里如果没有社区，他会觉得别扭；理想状态是一直和社区待在一起，他甚至想过边走去录音棚边开一场 town hall。swyx 说他们的 Discord 已经有 10 万人，Twitter 也火了。两人还开了几个玩笑：Diogo 在 AIE 上请大家关注他，却没报自己的账号；他发帖说“我们占了三个热门话题”，结果被人指出那是他自己的个性化推荐页。

02. Jev 是什么：System One 模型和每美元智能

节目位置 0:04:19–0:07:23 · What Is Jev? System One Models and Programmable AI

一类新模型

swyx 请他给“没听说过的人”一个标准定义。Diogo 先说，这个问题让他松了口气，因为现在不用再跟父母解释了，ChatGPT 能替他解释。

他说需要一类新模型。他们不执着于名字，目前最准确的叫法是 System One 模型。他们刻意没有叫它“决策模型”，因为 System One 的范围比决策更大，具体他不能多说，只说“我们还有存货”。他也没想到这次会成为公司的大发布。swyx 打趣说应该叫“低调的研究预览”，Diogo 说某种程度上确实是。

他对这类模型的描述是：机器原生（machine native）、System One、大型可编程（large programmable）。目标是让代码成为模型输出的消费者。他拿三类模型对比：预训练大语言模型的目标是补全互联网文本；RLHF 模型（基于人类反馈的强化学习，用人的偏好打分来训练聊天和指令跟随）是为了回复文字；RLVR（基于可验证奖励的强化学习，用程序能自动判对错的任务来训练，推理模型主要靠它）和 RLHF 处在一个模糊的灰色地带。Jev 这类模型的输出直接交给代码使用，公司因此叫 TypeSafe（类型安全）。

他说他们最想要的是让 AI 尽可能强大，而他们认为做到这一点的方法是把 AI 和软件整合起来，所以从外部接口到模型内部，所有设计都为软件优化。

名字来自 Jevons 悖论

Jev 是他们第一个 large programmable model。它为“每美元智能”优化，名字来自 Jevons 悖论（Jevons Paradox：资源用得越省、越便宜，总消耗量反而越大），这个词是 swyx 先接上的。Diogo 说他很喜欢跟人辩论可靠性、成本、校准和速度哪个最重要；Jev 这个名字以后会用在处于每美元智能前沿的系列模型上。他说做机器学习，只要做得好，一切都是取舍，而他们在这个方向上全力投入。

03. RLHF 的模式坍缩、校准和 Yann LeCun 那张图

节目位置 0:07:23–0:11:58 · RLHF, Mode Collapse, Calibration, and Yann LeCun

模式坍缩

swyx 说，校准（calibration：模型说有 70% 把握的事，实际上大约 70% 是对的）是以前大家讨论不多的东西。他们和 Hugging Face 的 Clémentine Fourrier 录过一期，结论是 RLHF 后的模型会坍缩到“你最想听的答案”或“最可能的答案”，不反映模型自己内部的置信度。Diogo 说想借这个话题多讲几句，因为听说这个节目的听众最懂技术。

他说发布视频里的每一句话他都核对到极其精确，听说这很少见。视频里讲了 RLHF 的一个缺点，几乎没人注意：mode dropping。swyx 问这和 mode collapse（模式坍缩：生成分布只剩少数几种常见输出，少数情况被丢掉）是不是一回事，他说是同一件事。

为什么 LeCun 的那张图“数学上显然，经验上不对”

Diogo 说他的“辣评”是他很认同 Yann LeCun，觉得 LeCun 的观点是最接近准确的之一。但 LeCun 有一张著名的幻灯片，说大语言模型注定失败：序列越长，出错的概率不断累积。swyx 当场把图调了出来。Diogo 说这是他最喜欢拿来教人的例子，它看起来在数学上显而易见，经验上却不成立。

他给的解释是：如果模型学到的是覆盖整个分布、校准良好的分布，它不会因为离群输出受到太重的惩罚，所以一部分时间会落在分布之外。GAN 之前的生成模型就是这样，所以生成的图片很模糊。GAN 会 mode drop，丢掉少数类别，只生成常见的那些，所以不会出现这种累积错误。语言模型也一样：要生成很长的字符串还不出错，它们必须极度保守，因为明显的错误一眼就能看出来，看似正确的细微问题却很难发现。于是校准对字符串的概率分布来说是“毒药”。他说这就是为什么字符串模型不擅长做决策，把字符串模型硬拿来做决策效果很差。

JEPA 和 scaling law

swyx 问 LeCun 开出的解法，也就是 JEPA（joint embedding predictive architecture，联合嵌入预测架构，在表示空间里做预测的世界模型）这类东西，是不是对的方向。Diogo 说他不该多谈机器学习内部的事，但他的风格除了“不着调”就是务实。他是不是 scaling law 的拥护者要看情况：scaling law 告诉你投入多少能变好多少，通常意味着用指数级增长的资源换次线性的提升，除非那点提升很值钱，否则这笔投资看起来不划算。他关心的是用手头已有的东西做出最大的不同。他说 JEPA 是很酷的早期研究，至于现在是否实用，他不评论。

他说研究界散落着很多未经打磨的“钻石”，因为大家不知道怎么选对任务。这次发布对 TypeSafe 是好事，对“程序化 AI”这个方向好处更大：会有人在 Jev 上淘金，也会有人平行地去探索各种让软件更强的接口方式，大家回到“早期互联网的能量”。他说这和大家习惯的“抱歉你做不了，scaling law 只有大实验室能玩”很不一样。

04. 可编程 AI 为什么不该拒答，安全对齐放在哪一层

节目位置 0:11:58–0:18:50 · Programmatic AI, Refusals, and Safety Alignment

拒答是类型错误

Diogo 说 Discord 上很多人问他为什么反对安全对齐、Jev 为什么不拒答。他说他不反对安全这个原则，但安全对齐通常和用户的利益不一致，而拒答“显然是一个类型错误”。如果你是人，在用 Claude Code 之类的工具，它说“抱歉，我不能读 DNA.py”，这很烦，但你能绕过去，他说这是被迫适应的“斯德哥尔摩综合征”。可如果这个模型是一个在后台运行的依赖，它拒答了怎么办？如果别人在用你这个依赖，他们根本不知道底下是什么系统。因为某个用户发了一条奇怪的消息，软件就随机地坏掉，他说这“简直疯了”。他认为这种做法来自不懂软件、不懂编程的人，他们执着于“AI 同事”这种“无马马车”式的想象，没去挖掘 AI 的全部能力。

swyx 接话说，你要的是一个到处都能用的核心，类似“cognitive core”。Diogo 说对，这个核心必须足够通用，要能用在将来各种奇怪的用法上。他们当然没有在那些用法上训练过，那为什么能用？他笑说“因为我们在更奇怪的东西上训练过”。

能力对齐和安全对齐

他区分了两种对齐。能力对齐是做用户想做的事，这对软件工程师很好：东西越可预测，需要测试和摸索的就越少。他承认 Jev 离这个目标还很远，要像数据库查询那样可靠到“不用想”，还差很多个 9。安全对齐在他看来是指令跟随的反面，是去执行别人的指令，swyx 补充说是“实验室的价值观”。他说这放在 ChatGPT、Claude 这样的产品里说得通，比如它们不想做不适合工作场合的角色扮演，可能是用户里有家长和孩子，这是它们的选择。但放在 API 里就完全不能接受，因为开发者得围绕它编程，这很反用户。

swyx 提出反对：如果被拿去杀人呢？他说色情内容是私事，可 AI 确实会被用在战争里，公司有理由不希望自己的 API 被这样用。Diogo 说在一些务实的场合可以持这种立场，但通用技术的底层不是那个地方。他当然希望自己的东西不被用来杀人，希望它被用来做好事，他愿意在这上面“把拇指压在秤上”，但不会在技术层做，因为那会让智能“碎裂”（fracture）。每次让模型过拟合某些奇怪的东西，它的智能就更碎一些，而现在的模型已经碎得很厉害。

他说智能会更像数据库，而不是同事。数据库不负责检查自己是不是被拿去做坏事，他举了 CIA 的例子，然后自己说其实不太清楚 CIA 具体做什么。还有一件让他觉得奇怪的事：有人在 Slack 上问“我们要部署这个，可以吗？”他的回答是“兄弟，我们是 API，你是开发者，这不关我的事”。他认为合理的边界是，任务应该被拆成小块，API 提供方不该知道整体任务是什么，也不该知道下游用户在做什么，这样才能给工程师最大的能力。他们讨论过做开源和公益，但现在完全没时间。他说只要他还在掌舵，这类偏向就不会进入技术层。

05. 为什么拒绝公开 benchmark

节目位置 0:18:50–0:22:12 · Why TypeSafe Rejects Public Benchmarks

使用条款的误会

swyx 先替他澄清一件事：TypeSafe 的使用条款里有一条关于 benchmark 测试的限制，引起了误解。swyx 说那是预览期写的，正式发布时没删，现在会删掉。Diogo 说团队做了很多他都不知道的事，他已经让团队去和律师确认，他们显然不会阻止别人做这类测试。

为什么反对公开榜单

他说自己极度反对公开 benchmark，对作为代理指标的私有 benchmark 态度中立。swyx 问是担心饱和还是担心有人在公开榜单上训练作弊。Diogo 说作弊很容易，但还有更深的原因。假设两年后形成了一个行业，很多公司做和他们类似的事，那大家卖的都是“每单位的智能”，每美元或每秒。人们执着于成本和速度，但成本和速度是你付出的代价，你要换回来的是智能，智能才是最重要的。问题在于智能有一种说不清的东西，他用法语说 je ne sais quoi，swyx 接了一句“好模型的味道”。

他说发布两小时后，网上出现了一波“这东西真的能用”的反馈，传播得比发布视频还广。人们能感觉到他们有多在乎这一点，他认为这才是长期的根本。公开 benchmark 是让人信任智能的一种手段，但很容易被刷。就算有人不想刷，也还是会刷。他说早年每个实验室都有一个团队专门收集长得像 MMLU 的数据，好让分数好看，这是“多绕了几步的刷榜”。他的结论是，长期来看只能靠口碑和信任，直到你把模型放进自己的工作流，在那个工作流上评估、测量，形成自己的判断。公司要做的是不断提高可靠性的 9 的个数。他还说，如果他们愿意发布一个笨模型，一年半以前就能发布 Jev。

06. “最苦涩的教训”：数据、算力和选对任务

节目位置 0:22:12–0:26:28 · The Bitterest Lesson: Data, Compute, and the Right Task

北极星任务

Diogo 借机讲他写过的文章《The Bitterest Lesson》（最苦涩的教训）。他先粗略复述了 Sutton 苦涩教训里算法和算力的关系（文字稿这里转写为 Suchin，原句不清），然后说数据比算力重要得多，而选对任务、定好北极星（North Star，长期目标）是最难也最重要的事。节目说明引用了文章里的一句话：你优化什么就得到什么，机器学习里最苦涩的教训是它最重要的部分根本不是机器学习。

他说在大语言模型领域，这种“换任务”发生过两次，也许算 2.2 次：RLHF 把任务换成了指令跟随，当时没人想到这可行；RLVR 对方向做了一个很小的修改；现在是他们的 RLCD，新任务的目标是让程序处在循环里（programs in the loop）。

数据实验室

swyx 问他们是不是自称“数据实验室”而不是“模型实验室”，他说完全是。在他看来，模型能力就等于数据，数据极其复杂，是数据带来了那些 9。他说公司招“无限多”的数据人员。

swyx 问好的数据人员是什么样，并提到 Diogo 说过他们的数据全部是合成数据，但“合成”只是表面，背后是有品味、有耐心的人逐条看、指出问题、回去重新生成。Diogo 说这很复杂，他给数据人员做入职培训的讲座比这期节目还长，只能讲个大概：

  • 第零点：数据取决于任务。任务的形状决定数据的形状。RLVR 的数据是环境（environment，模型可以在里面尝试并得到自动评分的任务场景），RLHF 的数据是人类反馈，他们也有自己独有的一类数据。
  • 他们不想用用户数据训练，即使能拿到。他说现在提什么条款用户可能都会同意，但真实世界的数据偏差太大，大量用户问的是同样的东西，呈幂律分布，会让模型过拟合、碎裂。
  • 他们瞄准的是多年后的“科幻未来”：这类模型成为通用基础设施，被一层层埋进技术栈深处，用在今天想象不到的地方。他打比方说大语言模型像 UDP，他们的模型像 TCP，上面可以建各种东西。就算拿到今天的全部数据，也只会过拟合到今天，将来就不管用了。

他说数据人员有点像艺术家：研究模型的认知核心（他说他们的核心比别家都更不“参差”），找出参差不齐的地方，然后以一种在过去、现在、未来各个维度上都成立的方式精准地修补。swyx 总结为“处理一般情况，不处理特殊情况”，他同意，并说每次都需要很多智慧。

07. RLCD 和三种 RLHF、RLVR 的区别

节目位置 0:26:28–0:30:11 · RLCD vs. RLHF and RLVR

swyx 说 Diogo 批评过他的思路受 RLVR 影响太深，这很公平。他接着追问：RLCD 显然有秘方，据他所知没发过论文，Diogo 能不能让大家相信这不是为了听起来酷而造的新词？Diogo 说没发，暂时还没有。他先反问：RLHF 是什么？他说 RLHF 至少指三件不同的事：

  • 最早的是 Paul Christiano 等人教机器人后空翻的工作，swyx 当场查到是 2017 年。Diogo 说它的思路是能不能用这种方法学会难以明确写出规则的东西。他还顺带指出 PPO 本身不一定来自人类反馈。
  • 第二个是 OpenAI 的 learning to summarize 工作，在语言模型上做 PPO（Proximal Policy Optimization，一种常用的强化学习算法），去完成定义得不太清楚的任务。他说这篇他没有署名，参与的人后来帮了 InstructGPT，并提到了 Dai 和 Radford（Alec），向他们致意。
  • 他自己所说的 RLHF，是“指令跟随”这个任务。PPO 那部分不重要，重要的是定下“这是一个有价值的方向”这样的北极星。他说 DPO 及其各种后继方法也算 RLHF，虽然它们没有用那篇论文里的算法。

按这个意思，RLCD 是一个新任务、一个新的北极星。他说他不认为这是行话，他尽量精确地表达。swyx 复述他的理解：北极星是可编程的 AI，把人从循环里拿掉（RLHF 是为人调的），这样能把能自动化的都自动化。Diogo 说基本正确，并补充一点：要务实，要清楚语言模型现在能做好什么，如果某种程序化类型很酷但技术还没准备好，没有推出也不算悲剧。

但他说 Jev 出现之前的世界是一场悲剧。他承认这听起来很傲慢，但他在有公司之前很久就这么想了，swyx 作证他说了三年。他说自己一直这么说是因为以为这事很简单，以为整个项目一周就能做完，结果“错得离谱”，他向 OpenAI 的同事道歉，当年他说过“我马上就能解决”。

08. AI 这么强，为什么还没自动化多少工作；发布后的数据

节目位置 0:30:11–0:41:24 · Why Powerful AI Still Hasn't Automated the Economy

有引擎没接口

他说承诺过多、兑现不足也是悲剧，AI 在这上面很极端，RLVR 和 RLHF 都是主要的“肇事者”。他在演讲里常问：AI 能解决数学里的千禧年大奖难题，为什么连最基本的工作都还没自动化？那些机械的、不需要聪明人做、也没人觉得有意思的工作，现在还得靠人做，因为我们有一台超级自动化引擎，却没有接到这些有经济价值的工作上的“插头”。

他说就算 TypeSafe 明天消失，别人可能要一两年才能追上，具体多久他不知道；如果模型质量重要，他们会领先很久。但不管怎样，这件事已经改变了技术史的走向，整个领域会去探索这个空间。swyx 帮听众转述：不要把 TypeSafe 和 Jev 的成功理解为“多了一种新模型类型，然后一切照旧”，还有五种别的模型类型值得探索，“让百花齐放”。Diogo 说回到了技术乌托邦：不再是“我的 coding agent 有时能用，最好的都被大公司藏在内部”，现在是“创造又回到了菜单上”。

宣言和“秘密总体规划”

Diogo 说他的演讲像吊胃口，因为没说清自动化怎么实现。swyx 审过他们的宣言，说有些地方有点含糊，问第一步是什么、智能产品是什么；swyx 说他问 Diogo 要模型，Diogo 只说“模型快来了”。swyx 说他当时主要反对宣言里“composable”这个词，但很喜欢“build Prod, not God”（做生产系统，不做神）这句口号，节目标题也用了这句。宣言里有一份“秘密总体规划”，Diogo 说是 swyx 的主意，swyx 说这学的是 Elon Musk 创办 Tesla 时那份规划。swyx 说当时 Diogo 只给了他一半的故事，没有 Doom 演示，也没有数字。Diogo 说问题在于他不相信 benchmark。

他说不做 benchmark 让他们吃了大亏。去年融资时没人信他们，投资人只要 benchmark，他们拒绝了，认为那会奖励不良行为者。swyx 说选难走的路，最后会建成自己想待的公司。Diogo 说结果很好，他没什么遗憾。

为什么离开 OpenAI

他说前一晚谈离开 OpenAI 的原因时情绪很激动，而且发布后他得改措辞。原来的说法是：如果 AI 寒冬真的来了，而他没有拼尽全力去阻止，他会认为自己负有个人责任，一方面因为 RLHF 这个方向（他认为它拉大了承诺和兑现之间的差距），另一方面因为没有全力投入这个他认为会“印出价值”的方向。现在他觉得自己担心的那个寒冬已经避免了。发布不到一周，数字已经无可否认地显示它被用于真实工作。

发布后的数字

swyx 问具体数字。Diogo 说他不太跟踪，都是团队告诉他。他说已经越过了每天若干 token 的里程碑（具体数字在节目里被消音），而且这不是一闪而过的峰值，夜里也一直在跑，说明是机器在调用，不只是人在试。

  • 他认为注册数不重要，并承认一个失误：网上有人夸他们是营销天才，其实他们没有营销人员（他说也在招），只是在做真实、搞笑、不拘礼节的自己，然后拼命把人从候补名单里放出来。
  • 他夸平台团队，说他们在“史无前例的发布”期间的可用性比 Anthropic 还多几个 9。
  • 他说开发者平台的候补名单注册没意义，很多人根本不是开发者，进来试几个查询，不明白这不是聊天机器人，会问“我的 ChatGPT 2 在哪”。他没有精确算过，但他的感觉是全世界每个人都写几个查询，加起来也只是一个重度用户的一个 for 循环的零头。
  • 他说候补名单可以随便放人，真正可怕的是速率限制：一旦有人从中获得价值，就会要大量配额，因为软件就是这样，前期花力气把机械任务写清楚，之后它产生的价值远大于投入，你还能把它变成别的东西的依赖。

他说一切都靠可组合性（composability）产生，他们要的是涌现，是当催化剂，所以会尽量去和开发者沟通，包括他穿着垃圾袋开 Discord town hall，也包括长篇播客。

播放量和 NeoLab

swyx 说发布视频有 3600 万次播放，Diogo 说已经 3800 万。swyx 拿来比较的有 Navier-Stokes 那条视频的 7400 万（文字稿转写为 Navio），以及 Fable 5 的视频（文字稿是 57，节目说明写的是 1500 万）。swyx 说如果在 2026 年创办一家 NeoLab，他们现在是第一。Diogo 说他不在乎当 NeoLab，公司甚至做了恶搞 NeoLab 的周边，其中一件写着“有产品的 NeoLab”。他在乎的是成为一个可靠的开发者平台。swyx 说他原以为可靠性主要指校准，其实也包括可用性和可扩展性。Diogo 说可用性是一部分，但更重要的是“智能本身的可靠性”。

09. 可靠性、鲁棒性和确定性

节目位置 0:41:24–0:49:40 · Reliability, Robustness, and Determinism

智能的可靠性

他说可靠性是指模型能多稳定地做你想让它做的事。他认为大推理模型很聪明，但不够可靠：很多工作看起来它们足够聪明、也有经济动机去自动化，可它们连实习生的可靠程度都达不到，因为它们是为别的目标优化的。他想先自动化简单的工作，再自动化难的，他觉得这是常识。他的目标是可靠到别人不用试就知道能用，像编程里的心流状态：遇到不简单的分支逻辑，直接写一个 System One 查询，结果出来就能准确地分支。他说这会是一段很长的苦路。

没有 seed，同输入同输出吗

swyx 注意到 API 没有 seed（随机种子），问同样的输入是不是总得到同样的输出，如果不是，为什么。Diogo 说可靠性是个“兜底词”，AI 不能自动化某件事，原因总是某种可靠性问题，可能是类型安全，可能是确定性，也可能是能力参差不齐。确定性（determinism：同样的输入得到同样的输出）对单元测试有点意思，但他认为它是错误的北极星。他更看重鲁棒性（robustness）：相似的输入得到相似的输出。他说大语言模型在这方面不可靠到离谱。他们的测试方法是在提示词里插入 UUID 这类随机串（nonce），语义上是同一个问题，应该得到相似的输出。他说人们被 AI 做决策坑到，往往就是在这里。

他说也可以做确定性，这对某些用例可能有价值，欢迎大家在评论里说服他。但确定性可以拿去换更低的成本，而他们要一直处在每美元智能的前沿，为此“做了很恶心的事”。他提到同事劝他别说他们的模型是“弗兰肯斯坦的怪物”，因为有负面含义，他觉得那个怪物其实是无辜的好人，又承认自己没读过原著。他顺带感谢幕僚长 K 组织了这期节目。他说现在他们在这件事上最强，也要一直保持。

他总结：只要有人能说服他们确定性有价值，而且没有严重的 GPU 短缺，他们可以做确定性模型，代价是每美元智能更低。swyx 说根据 OpenAI 和 Anthropic 的经历，他会被同行压力推着去做，用户就算被告知不需要也还是会要。Diogo 说团队说他的品牌之一是“不可动摇”，那是“固执”的好听说法。swyx 说他们以前吵过，Diogo 在开发者问题上每次都对，但只要给出正确证据，他也能丢掉先验。Diogo 补充说他认为 GPU 会紧缺很久，每美元智能更低就意味着同样的智能要消耗更多 GPU；他们的目标除了签企业客户，更想把模型交到尽可能多的人手里，让大家去做奇怪的实验，开启一场“加州淘金热”。

量化和版本承诺

swyx 提醒他：当你说“不承诺确定性、为每美元智能不择手段、GPU 紧张”，就会有人担心你们会把模型量化（quantize：降低权重精度以省显存和带宽，可能降低质量），让发布时的模型悄悄变差。他说 OpenAI 和 Claude 早期同一个模型名下的模型并不总是同一个，建议 TypeSafe 公开承诺：发布之后不再改动。Diogo 回应说部署后再改模型“是疯了，我们在乎开发者”。

10. 模型版本、LTS、速度和每美元智能

节目位置 0:49:40–0:55:33 · Model Versioning, LTS, Speed, and Intelligence per Dollar

快速迭代，暂不承诺长期支持

他说第一方产品可以随便改，API 不行。但他们打算比大家习惯的模型提供商快得多地发布新模型，不承诺长期支持（LTS），因为还有很多可改进的地方。他说有可能临时为现在的 Jev 1.13.0 做 LTS，因为用的人太多，开发者讨厌依赖被破坏。另一条路是让线上的模型版本四分五裂，这对谁都不好，swyx 说总不能同时跑一百个版本。他说他们在做相关研究，想要一种“最对开发者友好”的长期支持方式，但当前模型还不是，他不承诺能一直保留完全相同的模型。他保证每一版都会更聪明，并说在模型已经很聪明的地方，版本之间的差异往往比同一个字符串模型调用两次的差异还小；大的变化出现在从“参差不齐”变成“好用”的地方。

swyx 说给模型做 LTS 的一个好处是可以移植到其他芯片上，Diogo 回答“无可奉告”。

每美元智能和每秒智能

swyx 提到推理技术树这一年发展很快，可以换到 Cerebras、Etched 这类芯片上获得巨大的加速。Diogo 说每秒智能（intelligence per second）是另一个指标，他们内部也讨论过“每美元乘每秒智能”之类的指标。但 Jev 这个品牌代表每美元智能最好，他在内部追着人要求：不管模型聪明多少，都必须在每美元智能的最优区间里（文字稿此处转写不清）。至于每秒智能，他说再看。很多行业极度依赖实时性，对它们来说每秒智能意味着很多钱，他希望两边都做，让市场来纠正他。

swyx 说这也关乎规模，规模大了每一微秒都要乘以数十亿、数万亿次。Diogo 说要看任务在后台跑得多深：后台的大型 MapReduce 类查询，延迟没那么重要，成本更重要；面向用户的实时场景，有 100 毫秒到 1 毫秒的预算，这个区间很神奇，就算已经低于 100 毫秒，时间再减半也意味着能多做一倍的串行智能调用。他说他喜欢每秒智能的用例，但不认为那会是 Jev 的生态位。

又快又便宜的象限

swyx 说别的模型通常提供的取舍是“更快但更贵”，Jev 受欢迎的一个原因是它占了“更快也更便宜”这个几乎空着的象限，同时智能大致不变。Diogo 说“智能不变”这句话分量很重，那就是难点。swyx 问既然不做公开 benchmark，内部怎么衡量。Diogo 说当然有内部评测，否则没法保证模型在每美元智能上处于最优，他们会把不同成本的方案画出来比较。但不去刷内部评测需要很强的纪律，必须当作最高优先级。他说他不反对测量，危险在于有其他激励，他在这件事上“意志如铁”：不要自欺欺人地高估模型有多聪明，要求真。

11. API 的三种原语：choice、score、noulli

节目位置 0:55:33–0:59:57 · Inside Jev's API and Programming Primitives

名字

swyx 说这是唯一会问这种细节的节目：Jev 有三个原语，choice、score 和 noulli。noulli 这个词哪来的？Diogo 说它像布尔值（true/false），但是连续的。名字来自 Bernoulli（伯努利分布，取值只有是和否两种、各带一个概率的分布），所以拼写很怪，是从 Bernoulli 截出来的一段，而它实际上就是一个伯努利概率。他们为名字争论了很久，考虑过 Pbool、Pool，他想叫“pool party”但没人同意。他们的理由是，他们是一群不拘礼节的人，程序员不在乎名字。Jev 这个名字内部也有很多人讨厌，后来都道歉了，只有一位还坚持，是他和 swyx 共同的朋友，她想把 Jev 叫作 Meow。

为什么是三个新概念

他说三个原语都是新概念，编程语言里没有现成对应的类型，这是有意的：它们和已有类型很接近，但不完全一样。比如 score 不是 int，如果用 Instructor 或 Pydantic 之类的库把 int、float 直接映射成 score，就会出问题。他们宁可清楚，也不追求让人一眼看懂。

swyx 以开发者关系的角度追问：难道不想直接接入大家已经在用的东西吗，比如写“怎样把 Jev 和 Instructor 一起用”？Diogo 说他们有自己的 SDK，也许哪里已经有这类集成，他落后太多，社区也会有人做。他说这一段让他紧张，因为他没复习文档，文档还在不停变。

映射到编程原语

  • score 类似 LLM-as-judge（让模型给输出打分）。你可以叫它“判断”。
  • noulli 可以看作概率，但在他们的系统里一切都是概率。
  • choice 最接近函数调用，但他说函数调用是个“很恶心的东西”，后面再讲 OpenAI 的内幕。choice 是在代码里暴露 switch/match 语句的正确方式，干净地对应一个 enum，你愿意的话可以把它展开成函数调用，选择本身才是关键。

他总结为：choice 对应在 enum 上的 switch 语句，noulli 对应 if 语句，score 对应排序或者大于、小于的阈值判断。他说这一直是他们的设想，以后会有更多类型，也都会对应编程原语。

12. 怎样用 Jev：结构化输入、拆解成小决策、阈值和微调

节目位置 0:59:57–1:19:57 · How to Build with Jev: Structure, Decomposition, and Small Decisions

输入也应该是结构化的

swyx 请他给打算深度使用 Jev 的人一些经验。Diogo 说几个月来没人问过他这个问题，他很高兴。他说模型是为将来埋在程序深处而设计的，他们“不带讽刺地”相信那会比今天任何人想象的都大；模型可能还没准备好，但他们会一直朝那个方向做，不会只在浅层任务上刷分。

他说大家常以为输入都是字符串，其实状态（state）、指令、判断标准都可以是结构化的 JSON 对象，程序可以把它们放到正确的位置，不用塞进模板。如果你用模板把东西拼成 system message，那是旧思路。在程序里，你不会把所有数字转成字符串再传，只有打印给人看时才那样；在计算机内部，应该传递带语义的嵌套结构。他说模型已经为此做了不少优化，但嵌套层级越多越难推理，他们正在这个方向上努力，也建议开发者这样写，代码会更清楚、更不依赖实现细节。可以把它想成一个“AI 函数”：我的状态里，哪些变量该传进这个函数？

他说 system message 是“恶心的全局变量”：所有东西、所有指令一次塞进去，然后指望每条指令都被执行到，而不是把问题并行地分开问。

多问、问小、能测量

他说这条建议不是为了让他们多赚钱：多问问题，把问题拆小，彻底分解。不管模型今天能不能做好，他认为这一周带来的最大好处会是大家的 AI 代码库变得更好。把问题拆成简单的决策，每一个都很容易评估。以前的做法是一个大 system message，可能再加一个大模型来检查它有没有照做。他说像“不要读这个子目录”“不要把 API key 传给 DeepSeek”这种要求，应该在程序层面基本得到保证。机器学习模型永远没有绝对保证，但拆开后就能测量，swyx 补充说可以验证它是不是真的被调用了。Diogo 说他们的接口本身就很容易验证，这应该让人松一口气。

swyx 说以前大家不这么做，是因为调一个小模型还是太慢太贵。他自己测过：一条把所有东西塞进 system prompt、得到一个大输出的流水线，和拆成 100 个小问题的流水线相比，后者更慢、更贵，效果还更差。拆开还很麻烦，问题之间会重复一些内容。Diogo 说那样的结果很难依赖，而软件需要在后台运行，“如果我们的东西不能在后台跑，我会心碎”。

怎么拆

swyx 问有没有什么拆法被证明有效。Diogo 说他喜欢拆到最小的语义单元。他说自己大概是所有人里查询这个模型最多的，他的查询写得很结构化、很明确，在问题里清楚地指出指的是什么（他喜欢用反引号），因为他们有意让模型严格按字面理解：编程需要严格的指令跟随，编程的艺术就是这个，AI 做的是扩大可以被跟随的指令的种类。他承认有时偷懒会写得混合一些，但大型生产系统应该不断加问题，并且让加问题这件事变得很容易，然后用代码实现精确的行为。

他举了拒答的例子。不要问“这里我该拒绝吗？”虽然这也是 System One 能处理的任务，答案大概也不错。更好的做法是针对各种可能需要拒绝的情形分别问独立的问题，这样你在明确规定自己要什么，不让模型去猜。如果发现“它没拒绝，是因为我没写到这种情况”，他说这很好，这就是软件工程：加一个问题、加一个阈值、把它存成测试用例，这个问题就永远解决了。软件不会因为 context rot（上下文腐烂：上下文太长时模型对前面内容的利用变差）而忘掉它，你可以一直测量。模型在某些因素上不完美时，可以基于真实样本为每个因素选阈值。他把这称为“没有机器学习的机器学习”。

模型还不够好的地方

他说有些事模型可能还不够好。他看到有人拿模型做自动交易会有点害怕，觉得应该交给专业人士，那是很高层次的任务。swyx 说就算模型够好，有效市场也会让它很快失效。Diogo 说这种情况也可以拆开评估，发现某方面不够聪明就先不部署，或者做取舍，或者偏向安全。比如模型还不擅长识别“VIP 客户带着讽刺语气”这种组合，那就在这种时候转给人工，这也是置信度估计的用处。

校准错了怎么办，要不要微调

swyx 追问：用户能拉的杠杆主要是阈值，可如果校准本身错了呢？Diogo 说他从没说过校准完美。swyx 说校准可能在局部有偏差，这时他会想微调，但 TypeSafe 不提供；现在出了错，他只有两个选项：改提示词或拆得更细，或者调置信度阈值，这不太让人满意。Diogo 承认模型会错很多东西。他们有“报告问题”按钮，也可以去 Discord 抱怨；每个版本都会明显更好，如果不能带来大的提升，他们就会放慢发布。他说承认 AI 有不完美的地方是务实的，“够好”取决于用例：人类做很多工作时也会犯错，但期望收益很高，配合合适的阈值，大量工作即使有错误也能完成。

关于微调，他说可以想象，但有顾虑。在“人们需要什么和人们想要什么”这个问题上，通用模型有一种说不清的优势：在一百万个其他任务上都好，可能让它在你这个窄任务的边缘情况上也更好，窄化可能破坏这一点。他不想推出一个“巨大的脚枪”。swyx 说 OpenAI、Claude，好像还有 Gemini，都推出过微调又收回了，微调现在基本是开源模型的领域。Diogo 说那些服务确实不怎么样，收回可能更好。swyx 说另一种可能的回答是：我们的模型很不一样，seed、量化、输出 token 这些都不适用，微调也不适用。

Diogo 说他对这种可能性很开放，并强调下面是愿望不是承诺：

  • 随着每美元智能越来越便宜，也许能做出很小的近似模型作为智能的代理。会不会有一天大家不再写正则表达式，因为用 AI 的成本比正则的复杂度还低？某些窄用例可能需要微调才能过线。
  • 他更希望靠校准加模型级联解决：模型很有把握就接受，置信度居中就交给更大的模型，依次往上。
  • 如果他们拥有整条帕累托前沿（Pareto frontier：在成本和效果之间无法再同时改进的一组最优点），黑客可以自己挑模型，企业也许想要更动态的方式：根据技术栈不同部分需要的智能，自动选不同大小的模型，甚至自动微调。他说这只是在“构思科幻”。

swyx 问会不会推出不同大小的 Jev，他说当然，他也不知道大家需要多少智能。

“文化是市场不奖励时你仍然做的事”

他说现在有人劝他们别急着发新东西，因为现在已经够好了，他觉得这很没劲。他喜欢一句话，大意是“文化是在市场不奖励你时你仍然做的事”，希望大家拿这句话约束他。他说也许将来他们代表的东西会显得理所当然，公司变成像 Visa 那样无聊的公共设施，他也不再穿粉色西装。他想继续做酷的事，让人意识到这只是开始，这次发布本来只是低调的研究预览，机器原生智能还会走得很远。

swyx 问是不是会有不止一个尺寸、不止一个模型。他说都会有，但不想像 OpenAI 的产品团队那样到处乱扔东西试错，一切都要放在统一的愿景下，也就是宣言里的三个方向。他说这三点是一组坐标轴，所有赌注都要落在里面，模型上会做一些很奇怪的东西，因为是机器原生的，人类不需要完全理解，只要有价值。swyx 请他给个提示，他说有人想把它们叫“决策模型”，他们的原语确实是决策，但他不会这么叫，因为还有不属于决策的机器原生类型。

swyx 说网上有人说“我一年前就做过决策模型，Jev 不新也不酷”，但 Diogo 确立了这个类别，而且就 swyx 所见，Jev 在数字上仍然胜过所有模仿者。Diogo 立刻说他不在乎 benchmark，不管输赢他都反对。他说他想让软件工程师借助 AI 变得超级强大。他说在那个“AI 寒冬”的方向上，AI 如此强大却被如此低估地使用，让他很难过，他不想做一个认为所有技术都好的纯技术乐观派，但他认为之前的情况是一种“浪费到荒唐”的状态。他说这几天哭得太多，不想在录音里再哭。

swyx 说他已经做完了从零到一的难关，Diogo 说他不觉得难的部分已经过去，除非所有东西都被自动化、GDP 真的增长了。他说大家太关注速度和成本，太不关注可靠性，而可靠性才让人愉快、让人信任。swyx 提到宣言里有一句“五年内 TFP 增长率达到 3%”（TFP 是全要素生产率），说他从没见过哪家实验室关心 TFP。Diogo 说这才是经济革命，也和 OpenAI 章程当年的立场一致。

13. “反向 SaaS 末日”、System One 与 System Two、发布前后

节目位置 1:19:57–1:34:50 · The Inverse SaaS-pocalypse and AI Disappearing into Software

AGI 的定义和经济数据

Diogo 说 OpenAI 的章程没变，但他们试图把 AGI 的定义挪到“1000 亿美元利润”之类的东西上。他说他不是要黑 OpenAI，AGI 本来就没有清楚的定义。按“完成世界上大部分有经济价值的工作”这个定义，他们得回答：为什么模型能做千禧年难题，却只完成了世界上有经济价值工作的零头？他认为现在所有模型在这一项上大致打平，都是零；也许已经开始了，但他猜还不到 1%。真正发生时，会体现在经济统计数据里。他认为它不会造成大规模失业，会带来很多变化，世界会变得更好。

让 AI 消失在背景里

他说他厌倦了 AI 总是当主角，世界应该变得更让人愉快，AI 只是帮忙。swyx 接话说“消失在背景里”，他说对。他在演讲里常问：2019 年的软件、SaaS 已经很值钱，现在是 2026 年，尽管 AI 这么强，软件基本还是老样子，只是侧边多了个聊天框，而这个聊天框不能做公司要承担后果的决策，因为不可信。他说这很荒唐，经济动机这么大，他认为会出现“反向 SaaS 末日”（inverse SaaS-pocalypse）：SaaS 会被 AI 大幅增强，因为 SaaS 公司最清楚哪些东西值得自动化。

什么是 System One 问题

swyx 问什么是 System One 问题，什么是 System Two 问题（借用心理学里快速直觉判断和慢速推理的区分），因为现在大家什么都想用 Jev 做，一定会有失败。Diogo 说这是个难题，说实话这是经验问题，就像 scaling law 是经验规律一样。他拿机器人举例：钱投了很多，机器人现在还不太行，他认为原因不一定是钱不够，可能是经验结果还没到。

他说从经验上看，预训练出来的“高度浓缩的智能”基本上是 System One 思考者，System One 最能描述大语言模型擅长什么。他说 RLVR 在 System Two 思考上做了不可思议的事，他很敬佩，也不认为它会导致 AI 末日，不过概率也不是零，因为说零是校准错误。但他说这对模型来说是件怪事，模型在这上面很脆弱。他对比说，ChatGPT 早期大家说它很通用、什么都能做一点，只是数学不行，连 GSM8K（小学数学题数据集）都做不好；现在大家谈 RLVR，说它脆弱、参差不齐，为什么能做某件很怪的事；数学能力不只是尖刺状，还是分形的。

他用北极星来概括三者：RLHF 是取悦人类；RLVR 是优化 benchmark，因为 benchmark 的定义就是“程序可验证的简单输出”，凡是归入 RLVR 的东西按定义都是 benchmark；RLCD 是让模型在程序化使用中可靠。

多跳推理和“不做推理”

swyx 说他第一天拿到权限就拿 Jev 测了很多东西：单跳推理很好，是最先进水平，他说单跳任务不该用 Jev 以外的东西；多跳推理就开始下降，跳数越多越差。Diogo 说这又回到经验问题，取决于能从模型里挖出什么。他们想尽可能挖出智能，他把自己的工作描述为解锁、打磨、雕刻智能，同时补上能力的空缺。但这些属性取决于那些“浓缩的核心”里有什么，以及把它们“拼接”在一起后能得到什么。System One 只是恰好描述了什么有效。

他说他们不做“latent reasoning”，也就是用字符串推理。swyx 问 latent reasoning 不是指在模型内部推理吗？Diogo 说他也不完全确定，他的理解是以前推理痕迹是保密的，所以被当作答案的隐变量，叫 latent reasoning；在模型内部推理的那种以前叫 continuous reasoning。swyx 说那 Jev 永远不会有推理版本，因为违背 System One 的承诺。Diogo 说他的承诺是为机器原生做一切必要的事，有些推理形式没那么慢、没那么低效和脆弱，完全有可能。他说他是务实的人，不对方法做承诺，只对 ROI 北极星做承诺，并说他们仍然渴望在世界上占一席之地，就当这次发布没发生过。

视觉、长上下文，给用户“想要的”还是“需要的”

swyx 说视觉是 Jev 没有的一大能力，大家看了 Doom 演示第一个就想要视觉。Diogo 先开玩笑说“我视力挺好”，然后说一切都有可能。他说这是内部的一个争论：在隐身的两年里，他们给的是他们判断用户需要的东西；现在要不要给用户嘴上说想要的？上下文长度就是例子。他说据他所知，他们的模型在长上下文下不退化方面是最好的，而别家是“用户要什么就给他们那个蠢东西”。他认为往两边走太远都不好：只给你认为对的，会变成 Anthropic 式的“保姆国家”思维，很反开发者；全给用户想要的，又把搞清楚智能那种说不清的东西的负担推给开发者。他们想在保持信任的同时把用户当成能做知情决定的成年人，他说还没有答案，接下来几天这会是他最大的争论之一，因为没想到会火，需要准备后续发布。

swyx 说他从没见 Diogo 这么投入过，大概最近两个月，Diogo 说是幕僚长逼他的，他还去参加了 swyx 的写作工作坊，说很有用。

被低估的部分：cookbook

swyx 问还有什么被低估或误解的。Diogo 说他会对每一项都长篇大论，所以只说一点：团队在 cookbook（示例集）上投入了很多心血，本想放进发布博客，但太长、太偏重度用户。发布前他们很担心，他们说的东西听起来像“奇怪的外星工具”，以为教育用户会成为巨大的瓶颈。现在看大概不再是问题，用户做的东西远超预期，用户的用例比他们自己的还酷，比如电脑操作那类。他说 cookbook 不是 AI 生成的垃圾，都来自解决真实客户问题，“里面有真正的 alpha”。

发布前的验证和 PMF

swyx 问发布前做了多少验证。Diogo 说反响其实很差，团队里非技术的同事很担心，觉得没人懂、没人要，像在卖维生素不是卖止痛药，讨论过要不要派 FDE（forward deployed engineer，驻场工程师）去帮客户写周边软件。发布前几乎没有收入。技术同事是坚定的信徒，觉得它的计算特性在很多维度上都“爆表”，他自己其实很害怕，所以拼命投入。最常见的情况是，试用的人里超过一半根本没明白；明白的人会说“很酷，但怎么过采购流程”。他们最后决定目标市场是开发者，让开发者去找用例，其他人自然会跟进。

他说他想质疑“产品市场匹配”（PMF）这个概念：发布前有产品也有市场，客户说“不确定能不能解决我们的问题”；发布后一下子爆了，大家都说“要尽可能多的配额，我们能不能直接给你们 GPU”。他认为这和营销关系不大，是一群有热情的开发者和他们产生了共鸣，再带动了其他人。他说公司要永远感谢这些开发者，不想像有些公司那样从开发者起家然后转向企业。他在想怎样推出对开发者比对企业更好的东西，说“我有在做”。他前一天染头发也是为了这个，他说在公司最重要的时刻不跟开发者说话会让他觉得不对，请大家监督他，如果他变了就拿起草叉。

14. 语音控制电脑的演示和四类主要用例

节目位置 1:34:50–1:40:17 · Computer Use, Dark Data, and Jev's Biggest Use Cases

语音 + 电脑操作

swyx 放了一段社区做的演示：用语音让电脑在新笔记里把标题改成 hello，打开 Arc 浏览器搜 Norbert Wiener，打开 x.com，打开 Photo Booth。Diogo 说他之前只见过一个航空公司浏览器操作的例子，这个语音的是第一次看到。视频里刷到一条推文写着“传闻 Anthropic 工程师把 Claude 当神崇拜”，swyx 说“而你在这儿做 Prod”。swyx 总结说，用 Jev 当决策模型，可以用语音操作整台电脑。

Diogo 说就像他反对刷榜一样，他也反对只看演示，他要确认它稳定可用。他很喜欢大家这样玩，想让团队也去玩、找出弱点再解决。他说手腕疼的时候很想要这个。swyx 问有哪些大公司来找过他们，Diogo 说他完全脱离了一线，别人给他看过截图，看起来“是所有公司”。

他们从第一性原理梳理的用例

他说 coding agent 显然是巨大的用例，他想稍后单独讲，先讲他们发布前就梳理好的几大类：

  • 暗数据（dark data）。大公司囤了大量数据，但因为太贵没用大模型处理过，他们很想分析这些数据，这是“数据科学家的梦”。他认为暗数据加 coding agent 会是最赚钱的两类，因为量最大。
  • 实时场景。需要智能在循环里的产品，他猜这些公司的 CEO 或 CTO 都清楚每缩短 10 毫秒产品能好多少，swyx 补充说电商尤其如此。他也提到各种助手类产品，还说他很想玩用 Jev 做的自动战斗类游戏，可以指挥自己的队伍，“但在我还有工作时别做得太好”。
  • “验证一切”：验证所有 LLM 调用，类似可观测性。他顺带给了一条文档里的建议：并行问题很便宜，如果你有一个很长的状态，要问很多问题，就给每条消息加 ID，然后针对每个 ID 提问，这样状态只付一次钱，可以问很多问题。swyx 说这等于主张每做一次推理模型调用，就该配 1 次、10 次或 100 次 Jev 调用。Diogo 说他希望大家少花钱，具体比例按问题来定。
  • “智能软件”：本身可组合、能做以前做不到的有趣事情的软件，比如社区里有人在 Jev 之上做编程语言，他觉得很酷。他说如果知道怎么发额度就好了，他们的基础设施还很早期，他想给这些项目送额度。

他说电脑操作算是实时方向里冒出来的，有点出乎意料；如果它可靠，他很兴奋，他猜还能让模型在这类用例上好很多。

15. Jev 会怎样改变 coding agent

节目位置 1:40:17–1:42:29 · How Jev Could Reshape Coding Agents

他说 coding agent 这边正在发生一件让人意外的事。Claude Code 和 Codex 大概是第一和第二，他说自己不太跟进，swyx 说大致如此。但它们是围绕“单模型世界”设计的，这对它们说得通，因为一直以来都是同一个模型、不同档次的智能在卖。开源的 coding agent 现在都很兴奋，在试着接入 Jev，大概在做各种奇怪的尝试。

他认为所有 coding agent 现在大致持平，因为“一个 while 循环能做的事有限”。一旦有人找到某个只能用他们的 agent 做的杀手级用例，大家就会涌过去，他们就有了垄断；但开源的 agent 都能复制这一点。他不知道 Claude Code 和 Codex 会怎么办，因为它们是围绕单模型设计的，他认为这会让 coding agent 的竞争变得很怪。他说他个人很想和它们集成，想和所有人集成；它们以后也许会做竞品，但作为基础设施，他的工作不是在这上面表态。

他说他写了一份关于 coding agent 设计模式的内部文档，正在让团队审，希望走回家后就能发出来。swyx 说 coding agent 公司应该也很想和他合作，Claude Code 和 Codex 和 Jev 一起用也有空间。

16. AI 安全、“Pacing the Frontier”和 RLVR 的局限

节目位置 1:42:29–1:49:32 · AI Safety, Frontier Pacing, and the Limits of RLVR

背景

swyx 说他最近参加了一个研究者聚会，大家真心担心节奏问题，认为公众还没准备好，应该放慢；他提到 Diogo 在 OpenAI 时经历了最早的显眼事件之一“the blip”，多米诺骨牌一路倒下，到现在每家前沿实验室都联署了一份文件，表示要控制前沿推进的节奏（Pacing the Frontier）。Diogo 说这是危险话题，但他“为危险而活”，还说公司品牌其实是“不羁和混乱”。

他的简短回应

他说这很复杂，他想以后正式写一篇回应，先说个短版。他认为 RLVR 其实不在于“可验证奖励”，那条路在推理革命之前就一直失败。他讲了一段历史：RLHF 刚兴起时，有三个不同的工作现在都被归入后训练，指令跟随是最不受待见的“私生子”。他去找预训练团队说“这才是魔法”，对方说“我们跑了那么多次模型扫参，你要我们等人工评测来挑模型？”当时大量资源给了代码生成团队，他们努力在单元测试上做强化学习，虽然有一些成功，但没做成，因为那需要推理。

所以他说 RLVR 除了奖励，还涉及整个形状，其中包括推理这个中间隐变量：为了让模型尽可能强、能解最难的题，你让它在中间做任何它想做的事。他认为“Pacing the Frontier”的讨论视角太窄，因为它假定所有人都要做更多 RLVR。他说他的模型显然不需要更多 RLVR，对他们的形状来说，最优量是零。

他说这有点像障眼法：他们想继续做那件看起来危险的事，因为它能做危险的事。有人说问题可能出在沙箱，他说当然是，而且本可以轻松解决，但他们选择不解决，因为让模型在“做任何事”这个类别里做得越多，模型就越强。他认为这里存在责任的稀释：把“必须做 RLVR，而且要做得越来越多，要在中间给模型做任何事的权力”当成前提，那结论自然是“我们正走向危险的世界”。swyx 总结说这些推理内部自洽，但起点的前提是有替代选项的，Diogo 同意。

他说在“最苦涩的教训”的意义上，很少有人创造过正确的任务、新的北极星，大语言模型里大概是 2.2 次，RLHF 和 RLCD，RLVR 算 0.2，他说这还算大方，也可以算 0.5 或 1，他不在乎。他认为大家在这件事上思路很封闭，该负责的是研究者，不是公众，公众只是以为 OpenAI 和 Anthropic 在尽力而为，他们不是了解真实可选项的专家。

“照我的意思做”

swyx 说他也在唤醒大家。Diogo 说他的目标是给软件工程师希望，让他们去自动化一直想自动化的东西，说服实验室换方向不在他的目标里。他说他写过一篇关于他想要的 AI 未来的文章，团队没让他发。里面有很多小事，比如“do what I mean”（照我的意思做，不照我说的字面做）：以前做不到，因为计算机太死板、太字面；刚才那个电脑操作演示就是“照我的意思做”。他说世界会出现很多人们想象不到的顺滑程度，但他不想过度承诺，不认为马上会发生。

17. 为什么给 10 亿美元也不做预训练；多模态和后训练

节目位置 1:49:32–1:56:48 · Why Diogo Wouldn't Pre-Train with $1 Billion

中期训练和预训练

swyx 问他对中期训练（mid-training：在预训练和后训练之间，用更有针对性的数据继续训练）有什么看法。Diogo 说这都是一个连续谱，swyx 说就是“更花哨的课程学习”。Diogo 说它是一种省钱的办法，不用再预训练一次。他说智能在每个层次都有说不清的东西，他自称“shape rotator”（偏数理思维的人），不擅长发现这些，但喜欢别人发现后教他，他们的数据团队就很擅长看数据。他喜欢思考能力是怎样被放进模型的：微调能很快对齐，而反复看到的东西会被越来越深地烤进模型，直到变得鲁棒，System One 的东西就是最终变鲁棒的那部分。

他说他喜欢所有形式的训练，但不会全自己做，因为太贵。他的原则是，跟投资人私下说的话也要公开跟大家说。他之前私下说过：如果给他 10 亿美元，他不会做预训练，他现在仍这么认为。他说作为 AI 工程师，你可以对现有模型切分、拼接，“拼接怪物”不优雅，但能解决问题。

一个全能模型，还是拆开

swyx 问：应该做一个具备所有能力的超级模型，还是继续拆开？OpenAI 一度朝 omni 模型方向走，4o 就是；后来又有一段时间分成聊天调优的主线和编码调优的模型。Diogo 说这是两回事。多模态有点特殊，其他模态有时有帮助，有时有害。他说大家似乎在远离语音（他强调语音和音频不同），因为它对其他能力泛化不好，这可能会被解决。他说这些都是经验问题：scaling law 衡量的是务实意义上一个东西有多好，不等于“砸钱就会变好”，可能有些东西无论怎么扩大规模都不够好。他的理解是电脑操作还没解决，他希望 TypeSafe 能出一份力，但也可能无论收集多少数据都解决不了，需要更好的方法。

后训练让智能碎裂

他说他讨厌让智能碎裂，“聊天优先”的后训练就会这样。为聊天优化基本就是纯 RLHF，而大家常抱怨的那些问题是 RLHF 内在的：谄媚（sycophancy）、过度自信、幻觉，还有在 LM Arena 上占优的那种风格，粗体、斜体、表情符号，不简单回答问题，写一大篇，最后再问你一个后续问题，让它像真人在聊天。他说这些都源于字符串很怪：要不跑偏，模型就得失去校准、要 mode drop、要过度自信，因为一旦出错，错误很明显，奖励模型会狠狠惩罚。这会扭曲整个概率空间，还会和推理模型相互作用，因为模型是一种“简单的线性东西”，容易作弊。他说研究智能的艺术在于研究这些细微之处，他在 OpenAI 时大家没在研究，只是“聊天、聊天、聊天”，他说现在大家对 Jev 也是一样。swyx 说给我一个目标我就去优化，Diogo 说有人会说可以同时优化两个目标，但那恰好就是碎裂的过程。

swyx 说他其实也把智能切成了 System One 和 System Two，只是不同意别人的切法。Diogo 辩护说他们没有丢掉 System Two 任务，你可以让 Jev 去做，那时智能的回答是“不知道”，表现为置信度很低、不确定性很大，也许一些启发式方法能稍有改善。他们也关心这些任务，只是认为那不是这种智能天然擅长的。

不给模型植入身份

他说所有碎裂都会让模型变笨。比如让模型说它是 OpenAI、Qwen 或 Claude，他不会在模型里写“你是 TypeSafe 的 Jev”，因为那会让它碎裂；他要模型反映互联网的认知、做到正确，这样才能得到平滑、可预测的智能。swyx 说身份对 API 也许是特例，Diogo 说对第一方产品是，对 API 不是：用 ChatGPT 做聊天机器人的人不希望它说自己是 ChatGPT，他们想让它说自己是 Chipotle 之类。swyx 说他们弥补的方式是提供一个 Jev skill，让 coding agent 学会怎么用 Jev。

18. TypeSafe 背后的 OpenAI 经历

节目位置 1:56:48–2:03:10 · The OpenAI Story Behind TypeSafe

感恩节的那次训练

swyx 问这段两年多的历程，Diogo 说其实更像四年。swyx 记得他有一次在感恩节前后“英雄式冲刺”，取消了所有安排，说大家都在度假，他要拿走 OpenAI 的 GPU 去做这件事，那是 TypeSafe 之前的时刻。Diogo 问那是不是正好是“政变”（coup）期间，然后说是的。他说现在没时间讲政变的内幕，下次再讲，并说政变很烦人。

InstructGPT 和“这是不是 AGI”

他说这个问题在 ChatGPT 发布之前就在他脑子里了。他当时觉得 ChatGPT 团队在做对的任务，做的是 AI 研究员不擅长、成功的产品人擅长的事：很在乎体验。他说 OpenAI 里这样的人很少，那些人做得很好。swyx 说那段从 GPT-3 到 3.5 的路上还有 AI Dungeon，是一个没人预料到的用例。

他说他曾很努力地推动部署 InstructGPT。早期版本甚至是用他自己写的、没发表的算法训练的，因为清洗 PPO 数据太慢，他觉得“这太好了，必须交到用户手里”。它几乎立刻拿下了当时大语言模型市场的 50% 份额。他说他当时真的在想：“它在‘指令进、指令出’上超过人类，这是不是 AGI？”他认为每个人都应该能回答为什么那不是 AGI，因为它看起来很聪明。他自己的答案是：它最后几乎只被用来写营销文案，比如 Jasper AI、Copy.ai，写现在被叫作“slop”的网页内容，他们担心自己让互联网变得更糟。

从经济革命倒推

他回到原点思考缺了什么：模型明显聪明，但没能创造价值，缺的是什么？他当时在做更多哲学思考。他的问题是：从一场由 AI 驱动的经济革命倒推，到那时，如果 AI 以 API 的形式存在，调用它的会是人还是代码？他判断绝大多数是代码（“很多个 9”），但所有优化都投在人这一端。他说想通的那一刻他意识到，这就是北极星。

他写了一份文档，跟 Sam 谈过，他说 Sam 的反应是“这太好了，你应该去做”，他回答“Sam，我有工作要做”。他当时以为这太显而易见了，Anthropic 一定已经在做，他们已经晚了；他还说 OpenAI 更擅长追赶而不是创新，说 ChatGPT 是 Claude 的翻版，Anthropic 内部有个东西只是没发布，swyx 补充说是 Slack 里的 Claude。他说推理大概算 OpenAI 首创，研究很出色，但他不确定那是不是人们需要的产品；coding agent 也是 Claude 先做的。

从训练模型到创业

后来指令跟随团队宣布“我们赢了，指令跟随解决了，不需要再做了”，他在想下一步做什么，就开始自己训练模型。他以为一周能完成，结果用了很多年。中间他看到了“生命迹象”，但显然没成功，不然早就部署了。他想看看从研究角度彻底押注这个方向会怎样，因为前面说的那个理由：如果 AI 寒冬来了，他会认为自己负有个人责任。

他找过其他公司，说想在这个方向上建一个实验室，对方有兴趣。他问哪个更快，在这里做还是创业，对方说创业，他就决定创业。swyx 说他找了 Eric 和 Sacha。Diogo 说他先找的是 Eric；对 Sacha 他其实没想挖人，只是问她“我是不是疯了，是不是我在 OpenAI 的泡泡里太久了，外面早有解决办法？”Sacha 说“我加入”，他说“你在一家创业公司上班”，她说“我现在就把它关了”，他让她再想想，她说有道理，想了想，还是加入了。两周内他们就拿到了融资，大家搬进他的公寓办公，他说这很糟糕，因为他有洁癖。他们一直做下去，最终做出了显示“生命迹象”的研究。

19. 为什么他认为多数 neo-lab 方向不对

节目位置 2:03:10–2:09:29 · Why Diogo Thinks Most Neo-Labs Are Getting AI Wrong

给前沿实验室里不得志的人的建议

swyx 问：如果有一个像他当年那样的人，在前沿实验室里拿不到资金、资源或关注，该不该像他那样出来？Diogo 说要想想怎么回答才不得罪人，然后说：除非有他不懂的经济逻辑，否则他认为大多数 neo-lab（新创立的模型实验室）是垃圾，不想和它们并列。

他的理由有两条。第一，他并不看重研究员本身，他看重的是在乎数据和任务的人；需要研究员，但他们得真正在乎选对任务。看重纯粹的研究履历是反过来的，因为那通常不创造价值。第二，从纯务实的角度，他不认为创办 neo-lab 创造价值，反而在毁掉价值：从零重做别人做过的工作，推动前沿的概率很低。他说跟他聊过的大多数 neo-lab 没有方向，只想要钱去玩自己的实验；如果有方向，他很支持。

所以他的建议取决于动机。想玩研究，前沿实验室可能是最好的地方。他个人建议不要那样，世界更需要被解决真实问题驱动的人，问题可以是探索性的，但最好有自己坚持的原则。如果你想做对的任务，那就一定去做，去打破“单一心智”，swyx 接话说“蜂巢思维”。他说“Pacing the Frontier”来自一种对 AI 的特定看法：AI 是一个极其参差不齐的超级天才。他认为这是可以解决的，而且和现实不符。

“这是政治问题”

swyx 说为公平起见，他要转述他接触过的 Anthropic、OpenAI，还有 SpaceX 的人的立场：这更多是政治问题，不纯粹是 x-risk（生存风险）问题。他说对方告诉他之后，他明白了，这和 2028 年大选有关，并强调这只是那个房间里的讨论，不代表整个公司。Diogo 说这让他对人性有点失去信心，也许他只是天真的技术人。swyx 说由谁执掌监管这些技术的政府开始变得重要，实验室应该想清楚。

Diogo 说他完全同意在这件事上有立场很重要，但他害怕误导别人，因为误导常常会反噬。他说他不谈政治，但认为新冠期间人们过度依赖权威和过度自信来引导大众行为，应对远非最优，余波至今对世界很不好。即使为了更大的善，或者自认为的更大的善，他也不喜欢误导。swyx 说他不认为那是误导，只是在解释“为什么是现在”，Dario 在 5 月也说过类似的话。Diogo 说如果“为什么是现在”是这样来的，那在风险和目的之间就有一点误导，有一种潜在的不坦诚，值得指出，也应该承认。他说希望 TypeSafe 永远不卷进这种事，公司变大后也许避免不了，但他想尽量保持纯粹的技术人。swyx 开玩笑说“Jev 选总统”，Diogo 说他宁愿相信 Jev 的决定。

20. 摆脱 KV cache 的 coding agent、多 Agent 的未来和招聘

节目位置 2:09:29–2:22:22 · Coding Agents Beyond the KV Cache and the Multi-Agent Future

留给别人的任务：智能游戏

swyx 问：你选了可靠、可编程、可组合、便宜这个北极星，还有哪些任务你想交给别人去做？Diogo 很兴奋，给了一个好玩的和一个又好玩又有价值的。好玩的是游戏：他看到 Allie 做的 Doom 演示，让 NPC 控制东西，觉得那只是概念验证。他是 Stardew Valley 的粉丝，那个游戏很静态，但依然很吸引人，他觉得能讲出更多好故事。他说不需要在游戏循环里每帧调用 Jev，那可能太贵，就算只是给 NPC 做简单的状态机，也能做出很有吸引力的世界。他有点遗憾自己没法做这些。

摆脱“KV cache 暴政”的 coding agent

他最想有人探索的是摆脱 KV cache 暴政的 coding agent（KV cache：模型推理时缓存之前 token 的中间计算结果，前缀不变时可以复用，省时省钱）。他写过一篇文章叫《KV Cache Rules Everything Around Me》，他说搜索时发现网上没人用过 C-A-C-H-E 拼写的“cache rules everything around me”。他写这篇是想解释 coding agent 怎样工作、KV cache 怎样工作，它能解释很多事：为什么路由很难，为什么子 agent 似乎不好用，为什么上下文压缩（compaction）这么难。他还想发一份更长的想法文档，团队可能会否决，他说“信不信由你，我说了不算”。

swyx 问 KV cache 怎么把人锁住。Diogo 说它把你锁在一个模型上，为了高效你只能不断往后追加，于是你没法做软件的最佳实践，比如状态管理、抽象和分解。为什么不能给子 agent 一个简单点的任务？因为你要传来传去的状态。要传递这些状态，你需要比读取它的那个智能便宜得多的智能。他说这里有很多有趣的研究可做，比如不同的编程模式，就像大家在玩递归语言模型（recursive language models）那样。他列了一串想法：

  • 显式地给所有状态打标签。
  • coding agent 按子任务工作，为什么子任务的全部状态都要传回父任务？能不能聪明地处理？
  • 如果有一棵带标签的子任务树，需要时可以在树里搜索相关上下文。
  • 如果上下文变便宜，就可以很便宜地回看历史上下文。他说每次都从零开始，然后去解决一个叫“持续学习”的问题，这有点奇怪；那其实是内存管理问题，因为没有聪明的方式查找记忆。
  • 并行的子 agent 可以读彼此的状态，因为都在内存里；agent 群可以在资源上加锁，并且聪明地协调，不用最基础的锁，比如问 Jev“谁先写”。swyx 说“用 Jev 解决锁”。
  • 只读的进程，比如给人汇报 agent 在做什么的总结 agent，为什么不能方便地共享状态？它需要读部分上下文，判断哪些在被真正写入、哪些只是探索。

他说如果有聪明人花大量时间重新思考 coding agent 的体验，会很酷，那会是他的梦想。swyx 推荐他看 PrimeAgent（文字稿写法），说它和 RLM 的工作有关，节目上一位坐在这把椅子上的嘉宾 Alex 就聊过，这个方向有人在做，但还不流行。Diogo 说他希望每个人都去玩些怪东西，不保证有用，但技术上很有意思；等他们知道怎么发额度，他想资助这样的人。

当 CEO 和在 OpenAI 时的无力感

swyx 祝贺他，说从认识他到现在他变了很多，找到使命后精力充沛。Diogo 说他自认为“零分创业型人格”，不喜欢创业公司，从没想当 CEO，无法想象有人做两次，做一次就够糟了。第一次融资时投资人问他敬佩哪些 CEO，他说“呃，为什么要敬佩那些人”，他觉得有名的那些好像都有不少见不得人的事。

他说在 OpenAI 时他很无力。现在说真话容易一些，因为至少有一些证据表明这个方向行得通。当时他像在一座疯人院里，大家都在说“ChatGPT 放进所有东西里”“怎么让 ChatGPT 对开发者好用”，他心想“你们在说什么”。他说函数调用的接口很疯狂，为什么要部署它，这对开发者很不友好，是“在 hack 之上的 hack 之上的 hack”。他常说：如果每个函数没有一个真正的偏置值（bias），就把他从任何涉及函数调用的项目里撤下来。swyx 理解为类似置信度但没校准，或者一个概率。Diogo 举例说，如果动作只有拒绝和允许，Disney 需要设的拒绝阈值和 AI Dungeon 不一样，但用函数调用只能在提示词里说“拜托拜托”，这对开发者是很荒唐的接口，大家忍了好几年。他说 skills 也一样；现有的 coding agent 因为能力参差不齐而高度过拟合自己的 harness，不太会用外部工具和 MCP；为什么大公司不能让开发者轻轻推一下，比如“多调用这个，很有用”？现在的办法只能是在 system message 里哀求。

招聘和“智能的 AWS”

最后 swyx 问招聘。Diogo 说下一次大发布“可能比你想的更快”。他们在招：

  • 数据人员，他们内部叫“model capabilities”。他说数据在业内有点像贬义词，他想让这些人地位最高，又改口说想让所有人地位平等。他说他最自豪的是同事不怎么尊重他，会捉弄他、开他玩笑，他认为这是好文化的标志。
  • 营销人员和社区负责人。他觉得自己是不错的创始营销，但团队会说“闭嘴，去做 CEO 的事”。swyx 说营销不只是“辣”，也要做常规的事。
  • 平台人员，把 Jev 部署到各地。他说他们对地理位置更敏感，因为光速成了瓶颈。他为欧洲用户难过，因为那里还没有服务器，欧洲用户只快了大约 3 倍，而不是 100 倍。swyx 开玩笑说欧洲的生活节奏本来就慢。
  • 做更多“智能形状”的人。他说目标不只是做 Jev 这一个产品，也不想当只会一招的公司。他认为会出现一个“智能的 AWS”，他想往这个方向走，但说一定是他们就太傲慢了。他说现在做的 System One 智能像是 TCP 那一层，后面还有七层。swyx 说他还推荐过 Temporal 当第八层。

节目在两人互相道谢中结束，Diogo 说这是他第一次上这个节目，不会是最后一次。
