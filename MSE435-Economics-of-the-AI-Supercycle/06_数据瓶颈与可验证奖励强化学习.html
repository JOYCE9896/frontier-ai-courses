第六讲：预训练的数据瓶颈、代码与可验证奖励、产品使用数据的反馈循环

为什么预训练快用完了公开文本，可验证奖励的强化学习怎样用计算换数据，为什么代码是最适合强化学习的领域，Cursor 怎样利用用户行为改进模型，以及为什么企业不该等下一代模型

主讲：Apoorv Agrawal · 嘉宾：Yash Patil（Applied Compute 创始人兼 CEO，前 OpenAI 研究员）

一、预训练遇到数据瓶颈

第六讲开场，Yash Patil 讲了深度学习当前面临的一个大问题：经典的预训练缩放定律（Pre-training Scaling Laws）正在接近数据的上限。据 Epoch AI 估计，人类在互联网上留下的、质量足以用于训练的公开文本，有效存量约为 300 万亿个 token（90% 置信区间为 100 万亿到 1000 万亿）。按目前的趋势，语言模型会在 2026 到 2032 年间把这些数据用完。GPT-4、Claude 3.5、Llama 3 这一代前沿模型，已经用掉了其中很大一部分。

如果继续扩大预训练数据规模，会遇到两个难以绕开的问题：

  • 模型崩溃（Model Collapse）：互联网上由早期大模型生成的文本越来越多。用这些数据反复训练下一代模型，生成内容的分布会逐渐变窄，多样性下降，最终输出变得混乱。
  • 新增数据的价值越来越低：人类写的网络文本大部分是重复内容和日常闲聊。多给模型喂一万亿个论坛帖子的 token，对它在高等数学证明、复杂系统设计和严谨法律推理上的能力几乎没有帮助。

所以，过去五年"只要堆算力和数据就能升级"的做法走到了头。前沿模型竞争的重点，转向了后训练（Post-Training）和强化学习（RL）。

二、可验证奖励的强化学习：用计算换数据

Yash 曾在 OpenAI 参与后训练的核心研发。他讲了新一代推理模型怎样绕过数据瓶颈：用可验证奖励的强化学习（RLVR），以计算量换取数据质量。流程是：

  1. 给出一个问题（Prompt）。
  2. 模型在沙盒里并行生成几千条不同的解题过程（Rollouts）。
  3. 一个确定的验证程序检查最终结果，对就是 1，错就是 0。
  4. 只用通向正确答案的过程来更新模型的策略。

在这种方式下，模型不再只是模仿人类写好的标准答案，而是在大量算力的支持下，通过反复尝试和自我对弈，自己摸索出长链推理、反思修正和多步规划的能力。人类没有提供新的数据，投入的计算本身转化成了模型能力的提升。

三、为什么代码最适合强化学习

为什么几乎所有顶尖 AI 实验室都把大量精力放在让模型写好代码上？

代码有客观的裁判

如果让模型写一篇散文，或者预测宏观经济走势，人类专家对"好不好"总会有分歧，强化学习时就容易出现奖励作弊（Reward Hacking）。代码则有现成的客观裁判：编译器和单元测试。一段代码要么通过所有测试（奖励为 1），要么在某一行报错（奖励为 0）。这种不需要人工参与、可以大规模并行的确定反馈，最适合强化学习。

另外，代码是连接现实中几乎所有软件系统的通用接口：银行结算系统、医院病历、卫星测控网络和企业数据库，都可以通过代码脚本和 API 调用来操作。模型一旦精通代码，就不只是在聊天窗口里回答问题，而是能直接操作数字化的业务系统。

这也解释了为什么 AI 在代码以外的领域（如做商业演示文稿、法律合规审核、创意设计）进步较慢：这些领域缺少像编译器那样便宜、客观、难以被钻空子的评估体系（Evals）。谁能为某个垂直行业建立防作弊的自动评估环境，谁就能在这个行业复制代码领域的强化学习循环。

四、案例：Cursor 怎样利用用户的使用数据

很多人以为 AI 编程工具 Cursor 只是在 VS Code 外面接了 Claude 的 API。Yash 在课上指出，Cursor 的自研模型 Composer 每天在后台收集全球数十万工程师数以千万计的细微编辑动作。这种真实使用环境中的数据，质量远高于任何公开的代码库，Cursor 由此建立了一个基于用户行为的反馈循环：

  • 记录用户的反应：系统给工程师补全了一段代码，用户是 0.2 秒内按 Tab 接受，还是 3 秒后按 Cmd+Z 撤销？接受之后有没有手动改变量名？终端随后有没有报构建错误？
  • 把行为转成训练数据：Cursor 把这些开发者无意中产生的交互信号，自动整理成偏好数据对（Preference Pairs）。
  • 持续在线训练：用这些源源不断的反馈，Cursor 在开源基座模型上持续做 DPO（直接偏好优化）和小幅的策略更新。通用大模型实验室算力再多，只要没有开发者每天在用的编辑器入口，就拿不到这类数据。

五、为什么不该等下一代模型

课程最后的问答环节，有学生问："很多企业高管私下认为，现在花钱整理私有数据、训练自己的小模型是浪费；只要等一两年，OpenAI 发布下一代模型，通用能力的大幅提升自然会解决企业的问题。这种等待策略是不是最省钱？"

等待不等于谨慎

Yash 的看法是：未来的基础模型通用能力会越来越强，但它仍然不会了解某家跨国物流公司十几年积累的仓储数据，也不会知道某个工厂设备的异常处理规则。通用模型是面向所有人训练的，不会为某一家企业的业务专门适配。

真正的差距在于积累的时间。今天就开始搭建私有数据后训练流程、建立本行业评估体系的企业，正在积累别人没有的领域微调经验。新一代基座模型发布时，这些企业只需几周就能把新模型换进已有的流程，业务表现再次领先；而一直在等的企业，即使拿到最新模型，也还不知道怎样让它在自己的业务里跑通第一个测试。
