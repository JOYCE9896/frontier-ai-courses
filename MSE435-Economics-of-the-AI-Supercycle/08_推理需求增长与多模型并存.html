第八讲：推理需求的十亿倍增长、多模型并存与推理云的客户粘性

"十亿倍"是怎样估算出来的，为什么不会只剩两家模型公司，企业为什么会从闭源 API 迁到自己精调的开源模型，为什么客户很少更换推理云，以及前沿实验室为什么不自己做这门生意

主讲：Apoorv Agrawal · 嘉宾：Tuhin Srivastava（Baseten 联合创始人兼 CEO）

一、推理需求增长十亿倍的估算

第八讲开场，Apoorv Agrawal 这样介绍嘉宾："未来几年，全球推理算力会增长十亿倍，而正在建设承载这些算力的管道的人，就坐在我们面前。"嘉宾 Tuhin Srivastava 曾在 Gumroad 做机器学习架构，现在是 Baseten 联合创始人兼 CEO。他带全班做了一次推算，说明"十亿倍"不是公关说辞：当 AI 的工作方式从人偶尔提问，变成 Agent 全天候自主执行任务，按每个任务消耗的 token 推算，就会得到这个量级。

为什么训练算力有上限，推理算力却几乎没有？

  • 预训练算力会趋于平缓：预训练规模受限于人类可用的高质量数据总量，以及几家科技巨头每年几百亿美元的资本支出。绝对数字很大，但增长终会放缓。
  • 推理算力会成倍放大，Tuhin 分了四个阶段估算：
    • 第一阶段（人提问）：全球 10 亿知识工作者，每人每天向 ChatGPT 提 10 个问题，每次生成 300 个 token。这是现在的基线。
    • 第二阶段（Agent 代为执行）：每个工作者有 5 个 Agent 在后台全天候工作，监控邮件、审查合同、跑自动化测试、对账。人的每一条指令会在后台变成几百次工具调用，token 消耗放大 1000 倍。
    • 第三阶段（推理时长思考）：随着思维树搜索（Tree-of-Thought）这类方法普及，复杂任务要求模型在给出答案前做上万步的假设和验证，token 消耗再放大 1000 倍。
    • 第四阶段（机器之间持续交互）：物联网、高频金融交易、工业控制系统里的机器彼此交互，形成不受人类作息限制的持续循环，总消耗最终达到基线的 10 亿倍（109）。

二、为什么不会只剩两家模型公司

主流科技媒体和很多投资人有一种看法：OpenAI 和 Anthropic 会像当年操作系统领域的微软和苹果一样，垄断全球的智能供给，企业只要订阅它们的闭源 API 就行。

Tuhin 在课上反驳了这个看法，并分析了企业在规模扩大后为什么会走向多模型并存。

长期依赖闭源 API 的问题

毛利率被压缩：AI 应用还在验证原型时，每月几十万 token 的 API 账单无关紧要；业务做大、每月处理几十亿 token 时，按零售价付的 API 费用会吃掉公司 70% 以上的毛利，应用公司实际上成了闭源模型厂商的分销渠道。

被平台抢先的风险：把大量企业客户的商业提示词、交互逻辑和边缘案例持续发给一家闭源厂商，等于在帮它积累训练数据，也暴露了自己的核心商业信息。模型厂商只要在下一个版本里推出同样的原生功能，一家估值几亿美元的创业公司的业务就可能很快失去价值。

工程上无法掌控：前沿实验室的公共 API 是为全球海量并发设计的，遇到流量高峰时，企业业务就会遇到无法预测的限流和延迟飙升。严肃的跨国银行或医疗系统，不会接受把核心业务交给别人控制。

三、企业的典型路径：先用闭源 API，再大规模迁移

Tuhin 根据 Baseten 平台上数百家客户（如 Patreon、Descript、Writer）的实际发展过程，总结出企业落地 AI 的典型路径。企业把核心业务从闭源 API 迁移到用自有数据精调过的开源模型、并部署在私有推理云上之后，推理总费用平均下降 80% 到 90%。

  • 第一阶段（从 0 到 1 验证）：95% 依靠前沿闭源 API。产品还是雏形时，团队追求开发速度，直接调用 GPT-4 或 Claude 测试可行性，不在乎单次调用的成本。
  • 第二阶段（找到产品市场匹配、规模快速扩大）：发现毛利问题。用户量突破临界点，每月 API 账单涨到几十万甚至几百万美元，管理者发现原本以为的 80% 软件毛利，在财报上缩水到 20%。
  • 第三阶段（迁移和私有化精调）：90% 转向开源模型和私有推理云。企业用前沿闭源模型整理和标注内部业务数据，把能力蒸馏到一个中等规模的开源模型上（如 8B 或 70B 参数的 Llama、Mistral、DeepSeek），再部署到 Baseten 这类专用推理云上。

结果是：在具体的业务任务上，精调过的开源小模型的准确率和完成度能达到甚至超过通用的顶级闭源模型，单次响应速度快 3 到 5 倍，综合算力成本下降一个数量级。

四、推理云的客户为什么很少更换

在传统公有云市场上，AWS、Azure 和 Google Cloud 之间的竞争常常变成价格战，虚拟机和对象存储被看作可以随时打包迁走的标准商品。

Tuhin 指出，在所有 AI 基础设施里，专用推理云却是客户流失率最低、粘性最强的生意。

为什么企业很少更换推理服务商？

  • 推理直接就是产品体验：后台日志归档系统延迟 100 毫秒、甚至停机 5 分钟，用户察觉不到；但推理服务抖动 50 毫秒或出现冷启动停顿，正在和 Agent 对话或使用实时语音的用户会立刻感觉系统卡住，正在执行的自动化交易甚至可能出错。
  • 线上部署的调优很脆弱：一套在生产环境跑通的开源模型部署，背后固定了特定的张量并行方案（Tensor Parallelism）、KV 缓存的显存池划分策略、vLLM 或 TensorRT-LLM 的算子级优化，以及按真实并发曲线调好的冷启动预热策略。换一家云厂商，这些参数都要花几周重新调，没人愿意冒核心业务出问题的风险。

五、前沿实验室为什么不自己做推理云

有学生问："既然推理的市场这么大，拥有最强科学家和数万张 GPU 的 OpenAI 和 Anthropic，为什么不自己把企业私有化推理的业务做了？"

研究机构和基础设施运营商的组织差异

Tuhin 的回答是，两类公司的核心任务不同。对 OpenAI、Anthropic 来说，公司的最高目标是通用人工智能（AGI），最顶尖的研究员和管理层的精力必须放在数万卡集群上的下一代模型预训练、前沿强化学习算法和架构创新上。

专业推理云的核心任务则是可靠的工程交付。企业私有化推理要应对成千上万家企业零碎的具体需求：打通不同企业的 VPC 内网，优化冷启动（怎样让一个 70B 模型的容器在 2 秒内启动），在多个大洲调度混合云里零散的 GPU，适配各种魔改过的开源模型结构的算子。

如果前沿实验室分出核心工程人才去做这些细碎的定制工作，不仅会分散组织的战略重心，也违背了"把每一分钱都投入前沿突破"的对投资人的承诺。所以专业推理云和前沿实验室之间是互补关系，而不是你死我活的竞争。
