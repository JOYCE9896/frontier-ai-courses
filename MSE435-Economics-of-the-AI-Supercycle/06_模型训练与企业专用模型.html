第六讲：模型训练与企业专用模型

从 AlexNet 到推理模型的几个关键节点，预训练和后训练分别在做什么，为什么各家都先攻代码，评估为什么是最受保护的资产，企业为什么要训练自己的模型，以及持续学习和非 Transformer 架构

主讲：Apoorv Agrawal · 嘉宾：Yash Patil（Applied Compute 创始人兼 CEO，前 OpenAI 研究员）
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、嘉宾的经历

Yash Patil 是斯坦福 2025 届本科毕业生，在德州奥斯汀长大。他说自己在高中是好学生，在斯坦福是"坏学生"：不是成绩差，而是基本不去上课，看网上的录像，把时间花在做项目上。他通过朋友偶然认识了 Sam Altman，他说 Sam 很愿意帮助刚起步的年轻人。大一暑假，他和朋友放弃了实习去做自己的项目，给 Sam 发了一封冷邮件，Sam 给了一笔小钱让他们付饭钱和房租。项目最后关掉了，他回到学校，大二时主要在组织斯坦福的黑客马拉松 TreeHacks。

2022 年底 ChatGPT 发布，他觉得"这是我见过最酷的东西"，脑子里只剩下这件事，又给 Sam 发邮件问怎样能去做这个。Sam 介绍他去 OpenAI 的 Residency 项目，很多 OpenAI 员工就是通过这个项目从学术界或其他行业转过来的。2023 年初他加入 OpenAI 的后训练团队。第一年做评估（evals），他给学生的建议是：进一家公司，就去做那件最棘手、没人愿意做的事，大家会因此喜欢你。第二年推理模型开始出现，当时主要在竞赛数学上训练，性能提升让全公司都很震撼。他和一个朋友想试试把这些模型用到竞赛编程和数学以外的地方，拼凑了一个能浏览网页、写代码的 Agent 给领导看，大家很兴奋，于是成立了一个叫"长周期任务"的团队，他主要负责其中的 Agent 编程研究，后来发展成了 Codex。

大约一年前他离开 OpenAI 创办了 Applied Compute。他看到的空白是：模型越来越聪明，但放进企业里，就像一个对你的业务一无所知的天才。而世界上大部分数据就在企业里，企业积累了大量专有数据。Applied Compute 帮企业用前沿实验室训练推理模型的同样技术，训练自己的专用模型。

二、模型发展的几个关键节点

Yash 先讲了深度学习：它是一种从数据中学习底层表示的机器学习方法，输入大量数据和算力，得到由数百万到数十亿参数组成的模型，人们其实不知道这些参数在做什么，但它们很擅长预测，比如大语言模型预测下一个 token。AlexNet 之前，人们手工设计特征，比如用简单的分类器检测图像的边缘；AlexNet 把 GPU、大型数据集 ImageNet 和神经网络结合起来，证明了扩大算力和数据能大幅提高预测准确率。他说，这也是"我们不再理解模型在做什么"的开始。

之后的几个节点：

  • Transformer：Google Brain 的研究人员提出的新架构，在现有硬件（GPU）上效率高得多。相比之前的循环神经网络、LSTM，它用注意力机制大幅提高了预测下一个 token 的效果，并且能处理很长的序列。
  • 2018 到 2019 年的预训练时代：在海量文本上训练模型预测下一个 token，预测错了就通过反向传播调整权重，让它更可能预测出真实的下一个 token。
  • 缩放定律：OpenAI 的 Kaplan 缩放定律表明，模型做得越大，效果越好，GPT-3 印证了这一点，是第一个似乎具备某种通用智能的模型。之后的 Chinchilla 缩放定律指出，存在一种计算最优的扩展方式：参数量要增加，训练数据也要相应增加。
  • 基于人类反馈的强化学习（RLHF）和偏好调整：基座模型只会预测下一个 token，会大量编造、不直接回答问题、可能说出不安全的内容，需要通过这些方法让它对普通人有用。然后是 GPT-4 带来的又一次跃升。
  • 推理模型：2024 年 OpenAI 发布 o1，开辟了一个新的扩展维度，即测试时计算。Yash 特别强调，思维链是完全涌现出来的行为：模型回答问题前会思考、自我纠正，但没有人专门训练它这样做，只是把它放进受约束的强化学习环境、投入大量算力，这种推理能力就出现了。再结合工具使用，就有了 Claude Code、Codex、深度研究这类能长时间工作的 Agent，也就是现在所说的"AI 同事"。

瓶颈在哪里

Yash 说瓶颈一直在变：先是训练所需的算力，然后是合适的架构，然后是能撑起预训练的数据量（整个互联网），然后是让模型可用的偏好调整，现在是强化学习环境，最新一代模型就是靠它学会推理的。他认为下一个瓶颈是持续学习。训练方法一直在变得更节省数据：预训练需要读完整个互联网，而人学一样东西不需要读那么多；后训练更节省一些；最节省的是强化学习环境。大家心目中 AGI 或 ASI 的"圣杯"，是模型做一次就能从很稀疏的反馈中学会，就像人碰一次热炉子就知道它烫，现在的模型还做不到。

三、为什么各家都先攻代码

Apoorv 问：为什么各大实验室都把软件工程作为第一个前沿？Yash 给了三个原因：

  • 各家做的是可验证奖励的强化学习（RLVR），需要一种确定的方式检查模型做得对不对。代码和数学很适合：可以编译代码，可以跑单元测试，看代码是否在做正确的事。
  • 代码很容易大量生成合成数据，而且互联网上本来就有大量代码 token，基础很好。
  • 很多研究者（包括他自己）认为编程模型在某种意义上是"AGI 完备"的：把任何任务拆到底都是编程任务。这也是为什么 Claude 等模型常常写代码来完成任务，而不是调用某个专门的工具，代码成了和真实世界交互的通用语言。

那么不涉及代码的工作，比如做幻灯片，怎样也做好？Apoorv 说他这堂课的幻灯片格式全是用 Claude 做的。Yash 说，模型可以写代码生成表格、设置标题格式，这部分是功能性的；如果还想优化美观，可以加一个根据人类偏好训练的奖励模型，判断幻灯片好看还是难看，把代码执行的结果和这个奖励结合起来，同时优化"做得对"和"做得好看"。

四、预训练、后训练和数据

预训练是一项巨大的工程：拿几万亿个 token 的互联网数据，投入大量算力，用 Transformer 训练神经网络学习语言中的规律，结果是某种形式的智能。Yash 把它理解为"压缩"：把人类的全部知识，也就是互联网，压进一组权重里。预训练需要的算力比后训练多几个数量级。

预训练出来的模型只会预测下一个 token。比如你写"我该邀请谁来吃晚饭"，它可能接着列一串随机的名字，而它应该说"我不知道你的邀请名单，请告诉我这些人是谁"。后训练就是告诉模型什么是好的输出、什么是坏的输出：让它学会用户提问、助手回答的对话格式，学会安全准则，比如有人问怎样制造武器时不告诉他。后训练的方法有监督微调（SFT）、偏好调整（RLHF），以及可验证奖励的强化学习（RLVR）。他推荐课程阅读材料里 Andrej Karpathy 关于 RLVR 的文章，那是 2025 年最突出的进展。

两种训练里稀缺的都是数据。按 Chinchilla 缩放定律，模型和数据要一起扩大，而互联网上的数据已经快用完了，而且只有前沿实验室有足够的算力和数据做这种规模的预训练，资本门槛极高。

数据从哪里来

Apoorv 提到 Ali Ghodsi 两周前说过，以后世界上大部分 token 会是 AI 生成的。2030 年训练的模型，数据从哪里来？Yash 说，预训练这边比的是规模：有人开始收购旧图书馆的古籍去扫描，以获得更多 token；也有大量投入在合成数据上，比如把一份原始文档扩展成多出几个数量级的 token，看能否从中学到更多。但他认为预训练现在更关注的是新的架构，更好地利用已有的数据，因为原则上学这些东西不应该需要互联网规模的数据。

强化学习环境是另一种数据：构建一个让模型行动的世界，让它去做很多事，用算力换取对高质量数据的需求，也就是从每个样本或每次尝试中学到更多。以代码为例，预训练是读一个代码库、学会里面所有的 token；强化学习则是说"去实现这个功能"，让模型试几百上千次，每次检查它做对了没有，得到一组有对有错的奖励，从中学到的东西比单纯预测下一个 token 多得多。Scale AI 这类公司的全职工作就是提供这类数据。

评估为什么最受保护

当模型按奖励函数训练时，最重要的是知道什么是好、什么是坏。评估就是给定一个任务，衡量模型表现如何的基准。它之所以重要，是因为评估决定了路线图：SWE-bench 开启了编程模型的竞赛，因为大家第一次有了一个衡量"有用的编程"的目标可以优化。Yash 认为 SWE-bench 本身有很多缺陷，之后出现了好得多的新评估。做法是：想爬哪座山，先用评估把它定义出来，强化学习就像一台"把评估分数拉满的机器"，用和评估相似（但不是同一批，以免过拟合）的数据建训练流程，把山爬上去，再去下一个评估。

对企业来说也一样。摩根大通和高盛对好坏的标准不同，运营方式也不同，会有自己的评估。于是形成了两层：模型实验室优化通用的评估，企业优化自己的评估。Applied Compute 做的就是中间这一层专门化，帮企业针对自己的评估优化模型。

五、为什么要训练企业专用模型

Applied Compute 由 Yash 和另外两位联合创始人创办，他们都是斯坦福学生，也都曾在 OpenAI。他讲了个小故事：他加入 OpenAI 时，Sam 问他认识的最聪明的人是谁，他说了其中一位；几个月后 Sam 又问这位同样的问题，答案是第三位，三个人就这样都去了 OpenAI。

他们的核心判断是：未来通用模型是"主力"，决定了下限；但要拉高上限、和竞争对手拉开差距，需要针对每家企业的需求训练专用模型、搭建专门的系统。

例子一：DoorDash 的菜单提取

DoorDash 每年有超过 10 万家新商户入驻。商户提供的是大量非结构化信息，包括菜单的照片。把菜单照片变成 DoorDash 上的店铺页面很难，因为 DoorDash 有一套很具体的格式规范：哪些选项附加在哪道菜上，哪些可以自由搭配，什么算加料，什么算特殊配料。通用模型做不好这件事，他们也试过各种提示词。最后的办法是：让人修正模型生成的菜单，记下差异，在训练时把模型的输出和人工修正后的标准答案对比，量化错误率，直接以降低错误率为目标优化。所用的是基于 Transformer 的视觉语言模型（VLM），而不是以前的 OCR 模型。Yash 说这个例子说明，企业只要定义清楚什么是好、什么是坏，就不需要琢磨提示词，可以直接朝想要的结果优化。

等下一代模型不就行了？

Apoorv 问：如果"GPT-17"开箱就比专门训练的模型好，企业是不是等着就行？Yash 说，企业在乎的是在任何时间点都处在前沿，GPT-17 还很遥远。他也不相信会出现一个控制一切的超级模型，世界很分散，数据也分散在各处。而且现在训练自己模型的回报很高：强化学习已经很节省数据，所需算力比预训练少一个数量级，效果却比 SFT 和 RLHF 好得多。

预训练和后训练的投入比例是多少？Yash 来的路上查了一下：DeepSeek V3 的预训练用了约 240 万到 250 万 H800 GPU 小时，而得到 DeepSeek R1 的强化学习训练用了约 15 万 GPU 小时，大约是预训练的 5%。但这个比例在上升：现在各家会在一个甚至多个数据中心的规模上做强化学习，因为后训练也有缩放定律（黄仁勋讲过三条缩放定律：预训练、后训练、测试时推理），可以大幅增加每一步的批量，让模型在尝试任务时做更多推理。在他们扩展 o1、o3、Codex 和深度研究的过程中，看到的规律是强化学习投入的算力越多，效果越好，几种扩展是叠加的。

例子二：两秒内查 bug

他们最近和 Cognition（Windsurf）一起上线了一个模型：你写完代码保存文件时，一个在两秒内运行完的模型检查你写的代码，告诉你有没有 bug。通用模型做不到，因为性能、成本和延迟之间有一条取舍的边界。拿一个小模型，专门把它训练得很擅长查 bug，就能同时拥有小模型的成本和速度，以及大模型的效果。

Yash 认为不能只盯着一层，要同时考虑模型、外层程序（harness）和上下文：很多应用层公司在外层程序上做了大量创新，借此从模型中榨出价值；没有合适的数据，模型就不知道该做什么。前沿系统通常是一组模型的组合：通用模型擅长调度，速度快的子 Agent 或用分布外的专有数据训练的 Agent 由它来指挥。他还提到企业信用卡公司 Ramp 的实验室训练了一个强化学习模型，在电子表格里做快速搜索，以此改进产品体验。

六、新的训练技术

持续学习

持续学习指的是从很稀疏的反馈中学习：系统上线后，了解 AI 被怎样使用、它的行为带来了什么后果，再据此更新系统，让它越用越好。Yash 认为这会是一个渐进的过程，而不是某个天才想法一下子解决，因为很多时候卡在数据获取上：Agent 上线后，是否放在了能给出反馈的人面前？是否掌握了判断好坏所需的全部上下文？

他举了两个例子。一是 Cursor 的 Composer：在开源模型基础上用 Cursor 自己的编程数据训练的编程模型。他们把模型放到真实使用中，收集使用数据，根据隐含的奖励做在线训练，比如用户接受了代码建议还是撤销了。收集数据、训练一步，再收集、再训练，效果持续提升。Apoorv 问横轴上的"步数"换成时间是多少，Yash 说大概是几天到几周，每一步可能要几个小时。离线做 RLVR 时，环境可以重放，同一个任务有确定的奖励，可以并行试几百上千次；线上做不到，因为用户在用、环境在变，所以 Cursor 的做法是攒一个很大的批量，用大量对话把梯度的噪声平均掉，再走一步，希望方向大致正确。

二是 Applied Compute 自己在做的"上下文库"（context base）：让 Agent 离线花算力分析大量文档和过去人与 Agent 交互的记录，从中提炼经验，提高之后的表现。他们看到在不同推理强度下，用同样多的 token，效果有明显提升。他认为持续学习的创新会出现在模型权重更新、上下文和外层程序这三个方面。

非 Transformer 架构

班上讨论过 Transformer 效率不高、很耗电。Ali Ghodsi 说过，飞机飞行远不如鸟有效率，但人比鸟重，所以飞机仍是主流。Transformer 会不会也这样？Mamba 等其他架构有没有机会？

Yash 的看法是：扩大 Transformer 的规模是有效的，有一个很简单的配方能让模型越来越聪明。与其自己去想一个更好的架构，更可能是继续扩大规模，让 AI 告诉我们更好的架构是什么。如果这个架构碰到了墙，也许会看到架构上的创新，相关研究也确实很有意思，但他的观点是专注扩大 Transformer。

另一方有 Ilya Sutskever、Yann LeCun 这样很聪明的人。他们的核心论点是：学习语言的底层表示不应该需要预训练那么多的数据，人就不需要，所以应该有更好的架构。但现在各家在算力上的投入，连同直接为这个架构优化的芯片，是一艘很难掉头的大船。主导这些投入的实验室目前仍在加大对 Transformer 的投入，新架构的研究还都在实验阶段。

七、快问快答

如果不做 Applied Compute，会做什么？Yash 说他们和很多 AI 公司都碰到了算力短缺，需求远超供给。他认为为算力供电的能源，以及更高效的芯片，会有很大的创新空间。虽然他没有硬件或芯片设计背景，但他会去看硬件，把模型训练和芯片设计结合起来协同优化。

看多和看空：他看多算力和芯片供应商，比如英伟达，会继续赢下所有实验室的订单。但他也指出，英伟达在芯片上拿走约 75% 的利润率，实验室在花几千亿美元，也许拿出几百亿去做自己的芯片设计，把模型训练、架构和芯片放在内部一起优化，即使芯片效果只有英伟达的 80%，算下来也可能多出不少。所以英伟达会领先，但最大的客户可能自己做芯片，这是一个风险，只是很难做到。

他不太看好数据市场。做强化学习任务的数据公司会被挤压：你帮客户把模型在某类任务上训练得很聪明，下次客户要新任务时，你就得花更多钱、更多时间去造一个更难的任务。而且模型越来越强，很多强化学习任务利用的是"生成和验证之间的差距"，比如写代码时留出单元测试、让模型去做、再用测试检查结果，这不需要人来做；模型越聪明，越能搭出好的合成数据流程。他承认"数据要完了"的说法每隔几年就出现一次，但数据一直没死，只是在变。最好的数据创业者擅长转向下一波，比如机器人数据、第一人称视角数据（戴上 GoPro 采集），所以他认为现在的强化学习环境生意会很难做。

最喜欢的 AI 产品：图像生成模型 Image Gen 2。他不擅长设计，常常把一篇论文丢进去，它会生成一份清楚的图解，说明东西是怎样工作的。Apoorv 说，这堂课幻灯片里最好看的一页，就是他把课程大纲丢给这个模型生成的。
