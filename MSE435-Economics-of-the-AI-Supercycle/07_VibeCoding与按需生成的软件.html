第七讲：Vibe Coding、按需生成的软件与"慢一点反而更好"的交互

用自然语言编程意味着什么，为什么固定功能的 SaaS 会受冲击，为什么 AI 产品里用户愿意等更久，以及面向 token 的网关该怎样设计

主讲：Apoorv Agrawal · 嘉宾：Guillermo Rauch（Vercel 创始人兼 CEO，Next.js 作者）

一、从写语法到描述意图：Vibe Coding

第七讲的嘉宾是 Vercel 创始人兼 CEO Guillermo Rauch（人称"G"），他在前端和云部署领域很有影响力。他在阿根廷布宜诺斯艾利斯郊区长大，少年时靠读英文技术手册自学编程，先后写出了实时通信库 Socket.io、数据库框架 Mongoose 和 React 全栈框架 Next.js，并把 Vercel 做成估值近百亿美元的开发者基础设施公司。他后来推出的生成式界面平台 v0，每天根据自然语言描述生成数百万个可以直接上线的前端组件，是 Vibe Coding 的代表性工具之一。

"Vibe Coding"这个词由前 OpenAI 研究员 Andrej Karpathy 提出，在科技界引起了两极分化的争论。Guillermo 认为，Vibe Coding 不是不负责任地乱写，而是软件工程历史上又一次抽象层次的提升：

  • 第一次（1950 年代）：从插拔物理跳线、打孔纸带，到汇编语言。当时的老工程师感叹："不懂机器码的不叫程序员。"
  • 第二次（1970 年代）：C 语言和高级编译器普及，程序员不用再手动管理 CPU 寄存器。
  • 第三次（2000 年代）：带垃圾回收的高级语言（Java、Python、JavaScript）流行，开发者不用再做指针运算和手动释放内存。
  • 第四次（现在）：自然语言成了新的编程语言，大模型充当编译器。工程师的工作从写分号、括号和导入语句，转向设计系统架构、定义数据流和把关验收测试。

二、软件变得可塑：固定套装的 SaaS 受到冲击

Guillermo 的一个判断是：传统 B2B SaaS 的商业模式正在受到冲击，原因是它缺乏可塑性（Plasticity）。一套年费几十万美元的 CRM 或 ERP，80% 的按钮和表单和企业的日常业务没有关系，但因为是成套产品，企业仍要付全款，还要让全体员工花几个月学习怎么用。

过去，做一个软件系统要招产品经理、架构师、前后端工程师和测试人员，开发周期 6 到 12 个月，预算几百万美元。为了分摊成本，软件厂商只能设计面向整个行业的通用产品。这种软件一旦做完就很难改，改一个字段都要走一遍繁琐的工程变更流程。

借助 v0 和编程 AI，做软件的成本和时间缩短了几个数量级。一家医疗诊所或跨境电商公司，业务负责人只要花 15 分钟描述自己的客户特征和订单状态流转，系统就能生成一个连接内部数据库的小型 CRM 界面。Guillermo 认为，未来的企业软件不再是从外部大厂买来的固定套装，而是根据业务场景随时生成、用完就丢的软件。

三、反常现象：亚马逊的 100 毫秒法则在 AI 产品里不成立

Web 2.0 时代二十年里，互联网产品经理普遍遵循亚马逊的 100 毫秒法则：网页加载每慢 100 毫秒，电商转化率就下降 1%；网页白屏超过 3 秒，一半以上的用户会直接关掉。快速响应是那个时代产品设计的基础。

AI 产品里，用户愿意为"想得更久"多等

Guillermo 根据 Vercel 平台上数百万真实用户的交互数据指出，情况反过来了：用户不但愿意等，而且愿意为更深入的思考付更多钱。

当用户在 v0 或高端编程 Agent 里输入一个复杂的全栈应用需求，如果系统 0.5 秒就弹出一段粗糙的代码，用户往往觉得被敷衍，甚至直接放弃。但如果系统展示出清楚的工作过程，比如"正在扫描仓库依赖……正在编写路由接口……正在安装第三方包……正在沙盒里编译测试……"，即使用户等了 30 到 60 秒，只要最后得到一个完整可用、没有编译错误的应用，满意度和付费转化率反而更高。

他的解释是：在 Web 2.0 时代，用户等的是页面渲染；在 Agent 时代，用户等的是一个虚拟团队替他完成大量工作。衡量价值的标准，从加载速度变成了每次交互完成了多少工作。

四、面向 token 的网关：AI Gateway

Guillermo 详细讲了 AI 应用需要的一种新网络组件：AI Gateway，相当于面向 token 的 CDN。在传统网络里，Akamai、Fastly 和 Cloudflare 把静态图片和网页缓存在离用户近的节点上，解决了跨洋网络的延迟和抖动。到了大模型时代，每一次 API 请求都是无法预知内容的动态流式传输，缓存方式要重新设计。

成千上万个企业 Agent 在生产环境里高频运行时，如果直接调用模型厂商的 API，会遇到几个工程问题：厂商间歇性限流（Rate Limits），高并发下 P99 延迟大幅上升，以及大量重复推理的开销。Vercel 的 AI Gateway 起到调度和缓存的作用：

  • 语义缓存（Semantic Caching）：如果两个用户或 Agent 的问题在语义上高度相似，系统直接在边缘节点返回之前验证过的答案，不必再调用昂贵的前沿模型，可以为企业省下 50% 以上的 API 费用。
  • 跨厂商故障转移（Dynamic Failover）：Anthropic 的 Claude 服务出现网络波动或过载时，网关在 10 毫秒内把未完成的流式请求连同上下文转到 OpenAI 的 GPT-4o 或 Google 的 Gemini，保证业务不中断。
  • 统一的监控和安全防护（Observability & Guardrails）：实时记录每一次 Agent 工具调用消耗的 token，防范提示注入攻击，并满足企业合规审计的要求。

五、能源与智能

这一讲最后讨论了一个更大的视角：人工智能通常被看作一场软件和算法的变革，但从物理上看，它也是一个能量转换的过程，在芯片里把电能转化为有用的信息。

能量输入，智能输出

"我们这一代人看到的智能涌现，是能量和信息的转换：能量从一端输入，智能（token 和逻辑）从另一端输出。这意味着，关于软件生产力上限的任何讨论，最终都会碰到人类获取和转化能源的上限。所以，可控核聚变、小型模块化反应堆（SMR）、地热开采、常温超导材料的研发，和开发 Next.js、v0 这样的软件并不矛盾，在经济上是同一件事的两端：谁掌握了最充足、最便宜的清洁能源，谁就掌握了生产算力和智能的根本条件。"
