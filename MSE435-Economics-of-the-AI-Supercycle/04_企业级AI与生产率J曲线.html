第四讲：企业级 AI 落地、生产率 J 曲线与企业私有数据

"软件已死"的说法错在哪里，电动机普及的历史说明了什么，为什么通用模型在企业里不够用，为什么企业更多选开源模型，以及为什么 IT 咨询外包反而更忙了

主讲：Apoorv Agrawal · 嘉宾：Ali Ghodsi（Databricks 联合创始人兼 CEO，UC 伯克利客座教授）

一、软件行业会因为 AI 而消失吗

2024 年，风险投资人 Chris Paik 的长文《软件的终结》（The End of Software）在科技投资圈引起很大反响。当时华尔街对 SaaS 板块普遍看空，Salesforce、Workday、ServiceNow 这些千亿美元公司的估值倍数明显下降。文章的核心观点是：当 AI 写代码的边际成本降到接近零，传统软件的高利润就无法维持，软件作为一门生意的时代结束了。

Ali Ghodsi 是 Databricks 的 CEO。这家数据和 AI 平台服务着超过 20000 家企业客户，包括全球最大的投行、电信运营商和制造企业，年度经常性收入（ARR）达数十亿美元。他在这一讲开头明确反驳了这个观点。

Ali 认为，把"写代码成本下降"直接等同于"软件需求消失"，是只看了一个变量。他引用了经济学里的杰文斯悖论：19 世纪瓦特改良蒸汽机，煤炭的利用效率提高了好几倍，英国的煤炭总消费量却没有减少，反而因为蒸汽机被用到越来越多的地方，增长了上百倍。同样，当写一行代码的成本从 10 美元降到 0.0001 美元，人们对高度定制、按需生成的软件的需求，会从企业核心业务扩展到每一个边缘流程，全社会消耗的代码总量会大幅增加。

二、生产率 J 曲线：电动机替代蒸汽机的历史

过去两年，全球企业在大模型和 GPU 上投入了数百亿美元，但宏观的劳动生产率和 GDP 数据里还看不到明显的拐点。不少怀疑者因此认为 AI 只是资本的自我炒作。

Ali 引用了经济史学家保罗·大卫（Paul David）关于电动机普及的经典研究来回应。

电动机发明后，为什么工厂生产率长期没有增长

1880 年代，爱迪生和特斯拉已经发明了实用的直流和交流电动机，工厂主们纷纷引入电力设备。但在之后近 30 年里，美国制造业的全要素生产率几乎没有增长。

原因是工厂的组织方式没变。当时的工厂都是围绕一台中央蒸汽机设计的：蒸汽机又大又重，工厂只能建成四五层的楼，由中央蒸汽机带动一根贯穿整栋楼的竖直传动轴，再通过大量皮带把动力传到各个车间。电动机刚出现时，工厂主只是把楼底的蒸汽机拆掉，换上一台同样巨大的电动机，继续带动原来的传动轴和皮带。燃料费省了一点，但机械摩擦损耗、皮带频繁断裂停工、采光差、空间狭窄这些问题都没解决。

直到 30 年后，新一代的企业家和工程师才拆掉多层厂房，改建单层的长条形厂房，给每台机床装上独立的小电机。生产工序不再受传动轴的限制，亨利·福特的流水线由此出现，制造业生产率随后迎来了 20 世纪最快的增长。

Ali 认为，现在的企业级 AI 正处在类似电动机普及初期的阶段。大多数《财富》500 强企业的管理层，只是把 ChatGPT 或 Copilot 当作一个插件，加在 1990 年代设计的 Jira 工单、SAP 报表和层层人工邮件审批的旧流程上。这相当于"只换电机、不改厂房"，不仅带不来生产率的大幅提升，还因为要人工核实 AI 编造的内容而增加了协调成本。生产率真正大幅提升，要等到企业按照多个 Agent 自主协作的方式，把业务流程彻底重新设计之后。

三、上下文问题：通用模型为什么在企业里不够用

很多创业公司认为，只要给企业搭一个通用的检索增强生成（RAG）系统，或者直接调用前沿大模型，就能很快取代企业的初级客服和技术支持团队。

Ali 讲了 Databricks 自己的经历。Databricks 的工程能力很强，他们试用了市面上所有知名的 AI 自动客服产品，希望能自动处理客户的技术支持工单。结果没有一家能胜任，大部分供应商看到真实的工单细节后直接承认"以现在的技术做不到"。客户的问题通常是这样的："我们的 Spark 集群在 AWS 和 Azure 之间做联邦查询时，触发了一个内核层面的竞争条件，发生了内存泄漏。"这种问题在任何公开的教科书或 GitHub 仓库里都找不到现成答案。

这就是决定企业级 AI 成败的上下文问题：

  • 通用知识便宜，而且各家模型都差不多：模型知道林肯哪年出生，会用 Python 写快速排序，会起草标准商业合同。这部分能力在各个基础模型之间高度相似。
  • 真正有价值的信息都在企业内部、而且往往没有成文：过去五年工程师在 Slack 私聊里的调试记录，数据库里没有存档的复杂表结构变更，某个大客户的脾气和历史上给过的特殊条款。这些数据存在企业防火墙内的私有数据平台里，公开的模型从来没见过，连企业内部的普通员工也很难拼凑完整。

Ali 的结论是：算法和模型权重本身不构成企业的长期优势；企业私有数据的来源管理、访问权限，以及检索相关上下文的质量，才是企业级 AI 竞争的关键。

四、反常现象一：企业更多选择开源模型

在普通消费者看来，OpenAI 的 GPT-4o 或 Anthropic 的 Claude 3.5 Sonnet 体验很好，闭源的商业 API 似乎已经占据了市场。

企业客户的实际选择

在 Databricks 服务的大型银行、主权财富基金、跨国药企和军工客户那里，情况正好相反。没有哪家顶级投行或癌症研究中心，会允许最机密的未公开交易记录、客户社会保障号或新药分子专利数据，通过外部的公共 API 离开自己受控的虚拟私有云（VPC）。

这些企业大多选择 Meta Llama、Mistral 或 DeepSeek 这类开源权重模型，部署在自己完全掌控的 Kubernetes 集群或托管的数据平台里，再用企业私有数据做后训练和微调。对这些企业来说，数据必须留在自己手里，没有商量余地。

五、反常现象二：AI 让 IT 咨询外包更忙了

一般的看法是：既然 AI 能自动写代码、自动迁移系统架构，埃森哲（Accenture）、德勤（Deloitte）、印孚瑟斯（Infosys）这类靠向企业派遣大量 IT 实施人员赚钱的公司，迟早会被淘汰。

Ali 透露的实际情况正好相反：全球各大咨询外包公司的订单不但没有减少，反而因为 AI 大幅增长。

原因是，要让 AI 在企业里真正发挥作用，企业首先要把几十年前建的老系统拆开重建：那些用 COBOL、早期 Java 单体架构，甚至几十层 Excel 宏搭起来的系统，要全部拆分成适合现代 API 调用的微服务。大企业内部没有足够的人手，能在维持日常业务的同时完成这些改造。为了在 12 个月内抢先用上 AI，企业高管们正在以很高的价格，向外部咨询公司签下数以亿计的重构合同，要求他们"组织几百个小组，用 AI 工具并行地大规模重构代码"。

六、长期规律：利润会回到技术栈的上层

课程最后，Ali 谈到了英伟达市值和硬件主导地位的长期走向。从经济学和科技史的角度看，现在英伟达拿走全行业大部分利润的倒三角状态，不可能永远维持。

从 1960 年代的大型机，到 1980 年代的个人电脑，再到 2000 年代的 x86 服务器和云计算，每一轮技术创新的超额利润，最初总是被率先突破的底层硬件公司拿走，比如当年的 IBM 和英特尔。但随着硬件标准化、代工产能扩张、系统架构成熟，硬件不可避免地变成大宗商品。最终，超额利润会沿着技术栈向上转移，集中到最接近终端业务、掌握企业私有数据、并控制用户界面和工作流的数据和智能平台。
