第五讲：OpenAI 怎样建设算力

算力和收入为什么同步增长，推理为什么会占 80% 以上，一个吉瓦意味着多少 GPU 和多少钱，Agent 怎样改变计算的形态，为什么需要多种芯片，以及推理为什么暂时不会搬到离用户更近的地方

主讲：Apoorv Agrawal · 嘉宾：Sachin Katti（OpenAI 工业算力负责人，前英特尔 CTO）
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、嘉宾和开场

Sachin Katti 曾在斯坦福任教 15 年，横跨电气工程和计算机科学两个系，创办过一家网络创业公司，之后担任英特尔 CTO 并负责英特尔的 AI 业务，去年 11 月加入 OpenAI，负责"工业算力"。Apoorv 说，很难找到比他更了解"从电子到 Agent"整条链路的人。

Apoorv 开玩笑说，英特尔花了十年想让大家相信它是一家 AI 公司，最近两周终于做到了。Sachin 说英特尔的形势在好转，有两个顺风：一是全世界的供应严重不足，任何真正有制造能力（而不只是设计能力）的公司都会受益，而英特尔几乎是美国唯一还能制造先进芯片的公司；二是随着 Agent 的使用方式，CPU 正在重新变得重要。他说执行上还有很多事要做，市场总是走在故事前面。

二、算力和收入同步增长

Apoorv 展示了 OpenAI CFO 年初发表的一张图：OpenAI 过去三年的算力容量，以及到本十年末的目标，算力曲线和收入曲线几乎重合。

Sachin 说，他和团队的工作就是为 OpenAI 提供训练和推理所需的全部算力，"让这条曲线往右上走"。对前沿实验室来说，收入是一个滞后指标：收入基本上就是"有多少算力"乘以"算力利用得多好"。过去三年，OpenAI 的算力每年增长到 3 倍，收入也每年增长到 3 倍，目前看不到这种相关性结束的迹象。他提到 GPT-5.5 发布后两周内，Codex 的使用量有明显的两位数增长，而且人们已经不只用它写代码，也用来做一般的知识工作，token 用量和任务复杂度都在上升。

他强调 OpenAI 仍然是一个研究实验室，目标不只是收入最大化，而是为研究提供尽可能多的算力，让研究人员可以不受限制地探索新想法、新模型。图上 30 吉瓦的目标是一个理想目标，分给研究和产品两部分；按现在的趋势，他们不认为会用不完。

训练与推理的比例

Sachin 说，最初大家以为缩放定律只适用于预训练。现在缩放定律已经扩展到算力的整个生命周期：预训练；用强化学习做后训练，这主要是推理负载；生成合成数据，因为真实世界的数据已经不够用了，这也主要是推理负载；以及 ChatGPT、Codex 这些产品本身，当然是推理。所以算力越来越多地用于推理，现在推理已经占多数。而且"推理"不只是产品，训练下一代模型的研究中也有很大一部分是推理。他们预测将来 80% 以上的算力会用于推理。

Apoorv 问：推理比例上升，是否意味着每吉瓦能带来的收入也会上升？Sachin 说会，消耗的 token 越多，收入相应越多。但 OpenAI 的使命是让 token 更便宜，他们同时在三个方向上努力：改进硬件和软件，让每个 token 的生成成本更低；提升模型能力，让每个 token 更"聪明"；改进 Codex 这样的外层程序（harness），让完成每个任务需要的 token 更少。目的是让这些智能尽可能地普及。

三、建设算力最难的是什么

Apoorv 问他工作中最难的部分是什么：采购、确保交付，还是瓶颈在电力、芯片或土地上？Sachin 说"以上全部"。AI 的"算力"包括芯片、内存、网络、电力、冷却、数据中心建筑、发电、配电和土地，这些都要在吉瓦级的规模上同时到位。所以他们采购的不是算力，而是整条供应链，要清楚地知道每个部件从哪里来。

第二件事是协调这条供应链，让所有环节同时到位、让算力真正运行起来。一个吉瓦大约是 50 万块 GPU。说到六个或十个吉瓦，就是很多的芯片要协同工作、供电、冷却、保持运行。很大一部分工作是在签完合同之后才开始的：怎样确保供应商真的按承诺交付，怎样设计系统让它在这种规模下协同工作，怎样让它以芯片的最高性能稳定运行。这些芯片现在很脆弱，对冷却和电力波动很敏感，一有波动算力就会下降。他说："有趣的部分是签合同，难的是签完之后的一切。"

对社会基础设施的影响

Sachin 举了一个例子：如果在佐治亚州或密歇根州建一个吉瓦级数据中心，它是电网的一个巨大用户。大型训练任务是同步进行的，所有芯片的负载会同时升降，在电网上造成几百兆瓦的快速波动。电网从来不是为此设计的，处理不好可能导致整个州停电。所以他们花很多时间设计系统，避免对国家其他基础设施造成附带损害。

他们也在考虑怎样降低供应链风险：怎样把晶圆厂和内存工厂转移到世界其他地方，怎样摆脱对电网的依赖，改用天然气，将来越来越多地用核能。他认为这些会带来基础设施的投资和创新，让 AI 以外的整个社会受益，因为在这之前这些事缺少推动力。

他还提到 Sam Altman 一直说的愿景：我们已经习惯每个人都有一部手机、每一两年换一部，那么每个人拥有一块 GPU 也不算疯狂。一块 GPU 功耗约 1 到 2 千瓦，按 70 亿人算是 7 太瓦（7000 吉瓦），比现在讨论的规模还大两个数量级。如果相信那样的世界，还有很长的路要走。Apoorv 问 30 吉瓦相对美国用电量是什么概念，Sachin 说他记不清具体数字，但美国各大云厂商加起来计划建约 100 吉瓦的算力，大约相当于电网容量的五分之一甚至更高，会占美国电力容量的两位数百分比。能源只用于人类消费的时代已经过去了。

算力优势体现在哪里

有传言说 OpenAI 的算力比其他实验室多很多。Sachin 说，你们已经能看到：GPT-5.5 是一个大模型，服务成本很高，但没有使用限制，每个订阅能用的 token 更多，他们几乎每天或每周都会重置额度，让人们多用。这就是算力优势在日常使用中的体现。光把智能做出来没用，还要能大规模交付。Apoorv 提到，这门课向两家实验室申请编程工具的订阅，Codex 团队很快就给了。

四、Agent 怎样改变计算

Sachin 回顾了工作负载的演变。ChatGPT 刚推出时是"一次性推理"：问一个问题，立刻得到答案，结束。2024 年的突破是推理（reasoning），模型可以先思考再回答，这增加了推理的计算量，但它仍然是被动的，只给答案，不替你做事。

Agent 这个词本身就包含"能动性"：它要闭环，不只是思考和建议，还要去尝试、看结果、迭代、再给出改进的答案。它会去找相关数据、去搜索；生成代码后会启动一个虚拟机跑测试；做幻灯片时会打开 PowerPoint 看看效果，然后根据结果推理、迭代。从计算机科学的角度看，聊天机器人的计算图很简单：用户、一次推理调用、一个答案。推理模型是多次推理调用。Agent 则是一个复杂得多的有向无环图：推理调用、工具调用、数据库或搜索查询、启动强化学习的虚拟机环境，再回到推理调用，如此往复。这需要更复杂的计算基础设施，以及更聪明地决定图的哪一部分在哪里运行。

让人成为瓶颈

Sachin 用一张半开玩笑的幻灯片说明现状：你给 Agent 一个任务，它去思考、试各种工具，可能要几分钟甚至几小时；你转而去做别的事，等它回来问你一个决定时，你得重新把所有上下文想起来。他们的目标是反过来，让人成为瓶颈：AI 完成得很快，不停地问你下一步做什么。更准确的说法是让人进入"心流"状态：一切都快速、互动、它知道你要什么并迅速完成。

要经济地实现这种体验，只靠 GPU 不行，需要多种不同的计算硬件：GPU、CPU，还有各种加速器。比如 Cerebras 适合极快的推理；也可能有专门处理超长上下文的加速器，能把整个任务的状态保存在内存里，不用反复调入调出，这对编程很有用，因为要把整个 GitHub 项目放在上下文里。用户体验会推动大家优化 Agent 计算图的每一个部分，建算力的人要做的是把每部分负载匹配到最合适的硬件上，同时兼顾效率和性能。

为什么会有多种芯片

Apoorv 提到前一天的财报季：Amazon 的 Trainium 芯片年化收入约 500 亿美元，Alphabet 的数字更大，当然最大的还是英伟达。Sachin 不愿点名看好哪一家，但他认为世界需要更有韧性的算力供应链，在任何一个环节上只依赖一家都是危险的，市场也在反映这一点，工作负载的复杂化也在推动多样化。

他提到一个容易被忽视的原因：台积电分配晶圆的方式。台积电之所以很成功，是因为它努力让多个客户都成功，这符合它的商业利益，它不想只依赖一个大客户。台积电是供应链上唯一的咽喉，晶圆会分给多家公司，所以必然会有多种芯片。在 Google、Amazon、OpenAI 这样的规模上，每一家都必须学会使用所有这些芯片，没有选择。

五、推理为什么不急着搬到离用户近的地方

训练需要同步运行的连贯集群；推理的负载更不规律、更难预测，为了降低延迟，似乎应该把算力放到离用户更近的地方，像 Cloudflare 那样建很多小集群。Sachin 说将来会这样，但还没到时候，原因有两个。

一是规模效应仍然很大。在一个地方建 50 兆瓦的算力，每兆瓦的成本远高于在一个地方建一个吉瓦。原因之一是人工：美国尤其缺人，与其在全国各地凑一个个 50 兆瓦的小项目，不如集中人力建大的。

二是技术原因。对 Agent 负载来说，生成第一个 token 的时间仍然在 400 到 500 毫秒，因为模型要先把所有上下文读进来。以 Codex 为例，你的提示词要和整个代码库合在一起作为上下文，Codex 模型的上下文现在是 40 万 token，这 40 万 token 都要先经过注意力计算（预填充阶段），才能生成第一个输出 token。之后再加上应用把提示词转成 token、发到云端、负载均衡到合适的 GPU，这些只增加几十毫秒。几百毫秒的首 token 延迟，远大于把算力放近一点能省下的网络延迟。所以在一段时间内，推理仍然会集中在大型集群里；等到能把很聪明的模型蒸馏得足够小，才可能放到离用户更近的地方。

他讲了一个有意思的经历：今年早些时候 OpenAI 引入 Cerebras 后，生成 token 的速度快了很多，结果系统里原本不起眼的其他延迟，包括应用和 API 本身的延迟，一下子都暴露出来了。为了跟上 Cerebras，他们不得不改造 OpenAI 的 API 基础设施，在每一层削减延迟，前一天刚在 OpenAI 博客上发了文章。他认为"每减少 30 到 50 毫秒延迟，就能提高用户参与度、收入和留存"的说法是真的，延迟会成为所有公司竞争的一个维度。

六、最被误解的地方

每位嘉宾都说算力是最大的瓶颈。Apoorv 问：关于 AI 基础设施，有什么是大家理解错了的？

Sachin 认为，被低估的变化是现在的系统还很简单：一大块计算单元，只连着一层内存，也就是 HBM。通用计算也经历过这个阶段：CPU 一开始也是这样，后来加了多级缓存，又加了闪存、硬盘。AI 计算的系统架构还处在很早期。

另一个变化是 AI 正在生成下一代 AI 基础设施。他们越来越多地用最新的模型设计下一代芯片，以及运行下一代模型所需的底层软件。现在的模式是：实验室训练模型，别人独立设计芯片交给实验室，实验室再想办法让它跑起来。他们希望变成：下一代模型在训练的同时，也在弄清楚自己最适合在什么样的芯片和系统上运行。他说离那个世界已经不远了，而且这可能是唯一能缩短算力周期的办法：一款芯片从构思到量产通常要 3 年，变化这么快，3 年太长了。Apoorv 说，3 年前 ChatGPT 刚刚发布，感觉像是很久以前。

七、价值会落在哪一层

按黄仁勋说的五层（能源、芯片、基础设施、模型、应用），长期价值会落在哪里？Sachin 说历史总是相似的：移动互联网时代，钱一开始被电信运营商和基础设施建设者赚走，然后转到应用层，再转到云服务层。他看不出这次有什么不同，现在利润在基础设施层，随着时间推移会转到平台和应用。Apoorv 开玩笑说，现在每个应用似乎都在被 OpenAI 和 Anthropic 吞掉。

做多什么、做空什么？Sachin 说他做多 OpenAI，"用脚投票"。认真地说，他会做多技术栈最底层，因为美国已经忘了怎样建造很基础的基础设施：怎样大规模造变压器、电池，怎样发电和配电，怎样做冷却，怎样生产这些系统需要的各种部件。这一层服务不足，而且差异化可以持续，因为它既有技术门槛又有规模门槛，建成了别人很难复制。他在斯坦福任教 15 年，看到电气工程的选课人数不断下降，尤其是晶体管、材料这些底层方向，而真正能推动这件事的就是这些。他强烈鼓励学生关注这一层。

做空的方向：任何只是在模型外面包一层的产品。模型变化太快，越来越能自己想办法达成结果，只做一层包装很难。他也不认为 OpenAI 或 Anthropic 想自己做所有应用。他更怀疑的是"应用"这个概念本身：如果将来我们和计算机打交道的方式是"这是我想要的结果，你去想办法"，那么应用只是今天达到结果的拐杖。

第一家市值 10 万亿美元的公司？他说简单的答案是英伟达，他希望 OpenAI 也能到，而如果 OpenAI 到了，英伟达一定也到了。

基础设施里最大的未解决问题？他认为结构性的问题是逻辑芯片和内存芯片的晶圆产能不够：逻辑芯片靠台积电、三星、英特尔，内存靠美光、SK 海力士、三星，市场高度集中，整件事只依赖很少几家公司。再往下挖，所有这些都需要 ASML 的光刻机，那是整条供应链唯一的咽喉。

八、学生提问

下一步的效率提升从哪里来？Sachin 说，短期到中期，主要来自调度软件、外层程序（harness），以及让模型更省 token。中长期看是新的内存架构，因为除非 Transformer 被取代，计算单元的形态已经确定，变化的是计算单元周围的内存架构。

关于 Stargate，Sachin 说 Stargate 就是他的工作：怎样交付所有这些算力。一个吉瓦大约要花 700 亿美元，规模巨大，运营也很难，一个吉瓦就是 50 万块 GPU 要管理、要配人。所以他们现在更看重"多快拿到算力"，而不只是算力的总量，这决定了他们在哪里加大投入，也是为什么他们更喜欢集中的大块算力，太多零散的小块运营上很难快速上线。

开源权重模型越来越强，怎么看？Sachin 说开源模型在生态里有自己的角色。前沿模型的智能需要多出几个数量级的算力，他们不认为这会改变，缩放定律仍然成立，所以会继续投入前沿智能。开源模型会追赶，把智能蒸馏进更紧凑的形态，他们不认为这是问题。但他说，六个月的智能领先是巨大的领先，没有理由放慢对前沿智能的投入。
