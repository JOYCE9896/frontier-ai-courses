第七讲：编程 Agent 与面向 Agent 的基础设施

编程 Agent 怎样扩大了写软件的人群，云服务为什么要从"部署网页"转向"部署 Agent"，面向 Agent 的基础设施包括哪三部分，软件会不会因为生成太容易而贬值，以及为什么编程 Agent 总选 Vercel

主讲：Apoorv Agrawal · 嘉宾：Guillermo Rauch（Vercel 创始人兼 CEO，Next.js 作者）
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、嘉宾

Guillermo Rauch 创办了 Vercel，也是 Next.js 的作者，Next.js 是世界上最流行的 React 框架。Vercel 现在是最重要的开发者基础设施公司之一，估值 93 亿美元。Apoorv 介绍了他的经历：在布宜诺斯艾利斯郊区长大，小时候自学编程，靠读软件手册学会了英语（因为当时几乎没有西班牙语的手册），11 岁就远程接 JavaScript 外包项目。他高中辍学，搬到旧金山闯荡创业圈。为了拿到 O-1 签证，他写了一本书，就是 2012 年由 Wiley 出版的《Smashing Node.js》。Guillermo 说他很多事都是在"困难模式"下完成的：高中辍学对申请美国签证很不利，原来大家很看重学位。所以"别辍学，或者辍学也行，各有利弊"。

二、Vercel 的出发点和现在的变化

Guillermo 说，Vercel 建了一整套工具，尤其是开源工具，塑造了很大一部分现代互联网。即使不直接用 Vercel，在麦当劳网上点一个巨无霸、在保时捷官网订一辆车，用的都是 Vercel；用 OpenEvidence、Grok 这类系统，交互的 Agent 也托管在 Vercel 上。押注开源，来自他在阿根廷少年时代渴望免费工具和免费信息的经历，他希望让尽可能多的人用上他的技术。在开源之上建立一门很好的生意，本身是反主流的，他提到 Databricks 也是这样做的。

创业之初他最在意的是开发者体验。当时有 AWS、Google Cloud 和 Azure，但都很难用：他作为一个资深工程师，想用当时最新的 React 和 Kubernetes 部署自己创业公司的网站，竟然花了几周。他觉得部署一个网站不该这么难。他决定服务 JavaScript 开发者：只要你会做一个前端项目（应用中用户看到的那部分），他就给你部署的能力，而且能扩展到全世界、在哪里都很快。他当时估算全世界大约有 2000 万这样的开发者。那时编程训练营很火，三个月学会 React 就能找到工作，现代 JavaScript 工具的学习门槛确实不高。

现在的变化是：AI 和编程 Agent 大大扩展了能写软件的人群。再往前看，编程最初只是能接触大学大型机的一小群人的事，编程和技术的历史就是一部不断向更多人开放的历史，而 AI 带来了软件创作市场有史以来最大的一次扩张。具体到 Vercel，从去年 10 月起，特别是 Claude Opus 4.5 这个编程模型出现后，越来越多的人在 Vercel 上部署。他说 Vercel 成了编程 Agent 的"花生酱和果酱"：编程 Agent 是花生酱，正在涂满全世界，而软件需要有地方部署。

他创业时的一个观点是：写代码不会让你与众不同，把代码部署出去、放到用户面前才会。用户真正用上运行中的软件，学习才开始。他一直觉得奇怪，从 Freshmeat 到 SourceForge 再到 GitHub，人们热衷于把软件存成一行行代码，但随便打开一个 GitHub 仓库，往往很难跑起来，世界上堆满了跑不起来的软件。编程 Agent 没有人类那种"在我电脑上能跑就放在我电脑上"的倾向，它们很喜欢部署，Vercel 就是它们的部署层。

三、云在变：从页面到 Agent

Apoorv 开玩笑提到"Elon 网络服务"，Guillermo 说，如果 Amazon 今天才开始做 AWS，可能不会叫"Amazon Web Services"，因为今天人们想创造和交付的东西是 Agent，也许会叫"Amazon Agent Services"。Vercel 正在为这种新的部署对象，也就是 AI 应用和 Agent，建一整套基础设施和框架。

他举了几个变化：

  • 请求的时长：Amazon 的经验是页面加载越快，用户买得越多，他们的数据显示每慢 100 毫秒，转化率下降 1%。过去的互联网建立在"请求立即得到响应"的基础上。现在 Agent 出去为你做事，从几秒变成几分钟、几小时，现在有的 Agent 要工作一整天才交出报告、分析或软件。Vercel 上有平台在替人创办公司，背后部署的 Agent 负责维护、推广和扩大这些公司。所以需要为这种长时间运行的任务建新的基础设施。
  • 计算的需求方：AWS 的 EC2 让"刷卡就能拿到一台电脑，要一百万台就付一百万台的钱"成为现实。弹性计算是为人写的代码设计的，从经济上看，能卖出多少算力，受限于有多少程序员。现在能写软件的人可能扩大了 10 倍、20 倍甚至 100 倍，而且 Agent 也在写软件、修软件、保护软件。网络安全领域已经能看到聪明模型的影响，有攻击的 Agent，也有防守的 Agent。为 Agent 写的代码提供算力的需求很大。
  • 交付的东西：过去 Vercel 交付的是像素，也就是界面；现在交付的是 token 形式的智能，这也在改变定价和商业模式。大家都在讨论 SaaS 和按席位收费的终结、按 token 收费的兴起。

但他强调这不是非此即彼。他仍然很看好以人为中心的体验：Agent 做出来的东西，人还是要在丰富的界面里看到。他甚至预测会出现一个更有趣、更天马行空的互联网。他小时候用过微软的 Encarta 百科全书，选一个主题就有生动的互动体验，比如学吉萨金字塔时很精彩；而现在打开维基百科是一大面墙的文字，右边配一张照片。他预测借助视频生成、3D 模型生成，会出现最有沉浸感的体验，Vercel 上已经有平台在做实时 3D 渲染。

四、面向 Agent 的基础设施

Guillermo 把"面向 Agent 的基础设施"分成三部分。

1. 给编程 Agent 用的基础设施

用 Claude Code、Codex 或 Vercel 的 v0 写出的软件，需要部署在某个地方。编程 Agent 对世界有自己的"先入之见"，因为它们从互联网上大量关于 Next.js、React 和 Vercel 开源软件的内容里学习过。一份报告显示，Vercel 的界面组件库 shadcn 在编程 Agent 的选择中占 90.1%，接近垄断；部署 React 或 Next.js 时选 Vercel 的比例是 100%，报告也只称之为"接近垄断"。比如你让 Agent 做一个 SaaS 应用，它很可能用 shadcn。

为什么 Agent 要复用已有的软件？理论上，它可以每次都从头造一切，自己写 Linux 内核、网络系统、操作系统，但这不经济。开放的基础设施给了 Agent 一个现成的目标去搭建。HashiCorp 创始人 Mitchell Hashimoto（最近加入了 Vercel 董事会）把这称为"积木经济"：如果想让 Claude Code、Codex 或 Grok CLI 选择你的技术，就要想清楚能给 Agent 提供什么样的、符合 Agent 使用习惯的积木。

2. 未来的软件就是 Agent

你会构建自己的 Agent。他当天刚听一个人介绍 AI 原生学校的构想，仍然有老师、学校和学生，但交付的是 Agent，而不是一组互相链接的网页。Vercel 自己做了一个客服 Agent，现在回答了 93% 的用户咨询，他们会衡量客户和 Agent 对话是否和人工一样满意。这让业务效率大大提高，也让他们能为更多人提供免费支持。

老互联网的很多东西都能找到对应：上线网站时前面通常有 CDN，Akamai、Fastly 这些公司是为了扩展、加速和保护页面与像素的传输而出现的。token 也需要同样的东西。Vercel 做了 AI Gateway，相当于"token 的 CDN"：来自 Anthropic、Gemini 等的 token 需要被观测、能故障转移、需要安全保护、很多情况下需要加速和缓存，现在还可以做负载均衡。他提到一个段子：对 GPT-5.5 说一句"谢谢"，就要动用几百块 GPU 回一句"不客气"。设想一个聪明的 CDN，遇到"谢谢"就交给背后一个小模型回答，或者用语义缓存直接返回。

沙盒相当于 Agent 时代的 EC2，是最基本的计算单元。给模型一台电脑，就能从中榨出更多"智商"。模型在后训练阶段就被交给 Docker 容器去练手。这和人一样：新员工入职第一件事就是 IT 部门发一台装好软件的电脑；对 Agent 也一样，"这是你的电脑，随便用"。但就像个人电脑革命带来了病毒、钓鱼邮件和"尼日利亚王子"诈骗，Agent 也可能被骗去泄露数据，所以 Vercel 在做一系列保护沙盒的安全产品，他认为针对 Agent 的网络安全会形成全新的产品类别。

3. 由 Agent 自动运维的云

第三部分是让云本身像自动驾驶汽车一样运转。大规模运行软件的人都知道被值班呼叫折磨的滋味。他转述 Stripe 创始人的一个故事：他一听到鸭子叫，压力激素就飙升，因为他的值班呼叫铃声以前是鸭子叫，一响就意味着 Stripe 出故障了。Vercel 已经自动化了很多这类痛苦，但他说不会夸大，痛苦仍然存在，还是要盯着、要防止性能逐渐下降。他设想的是一切自动配置、自动优化，Agent 在背后完成工作，然后来告诉你"我刚把你的软件优化到两倍速度，这是代码修改"，甚至已经上线并测出客户转化率提高了。

客户例子

Meta 多年来自建了大量基础设施，但他们需要很快的速度，工程师在用编程 Agent，Vercel 由此进入，现在承载着 Meta 超级智能实验室的很多工作。Meta 不必采购那么多软件，而是"vibe coding"出工具，加快了模型训练，meta.ai 的上线也因此快了很多。Notion 也在用 Vercel 的基础设施为自己加入 AI 和 Agent 能力，比如一个为这堂课做笔记的 Notion 转录 Agent 就可以跑在 Vercel 上。他总结说，Vercel 在做的是"AI 或 Agent 的 AWS"，从开发工具到基础设施的全栈云。

五、软件会被生成到不值钱吗

Apoorv 说，如果软件正在死去，Vercel 就像劈开森林的砍刀。有没有客户用 v0 或 Vercel 自己做的软件替换了上市公司的软件产品？

Guillermo 认为，最好的软件永远是最贴合你自己的。SaaS 有一种奇怪之处：一群很聪明的产品经理和设计师关起门来，琢磨什么样的通用界面能让最多客户满意，然后推向全世界，希望获得指数级的采用。比如一个报销工具，"我的公司可以去适应这个工具"，换个客户也许只需翻译一下标签。但这仍然是"最小公分母"式的软件。

他不认为这是"软件之死"，在他看来软件从没像现在这样活跃、迭代这么快。一位创业公司的首席工程师对他说："你们的平台很危险，我们 CEO 在写软件。"这位 CEO 用 v0 现场写了一个停车场管理系统，替换掉原来的软件，省了不少钱。帕洛阿尔托没几家聪明的公司在做停车场软件，有一大类软件质量本来就不高，现在一两句提示词就能做出一个针对自己问题的好版本。

另一种模式是：记录系统（数据库）保留，自己做一个高度贴合业务的展示层。Vercel 内部就重新做了一整套"Salesforce"：销售了解客户、商机、该怎样推销，这些都是自动生成的，只用了两个人做。但他们仍在使用 Salesforce 建立的很多工作流和数据库，这不是二选一。所以他认为，一方面人们低估了有多少现成的应用会被扔掉、被快速生成的软件替代；另一方面人们也高估了底层记录系统、访问控制这些东西被取代的可能，这些可以复用。那些提供了适合 Agent 使用的接口（MCP、命令行工具和其他 API）的 SaaS 公司，会很好地融入这个世界，不会被编程 Agent "杀死"。

做出来就扔的软件

Apoorv 问：vibe coding 应用的留存率是大家最关心的问题，这种定制软件周六早上做着好玩，周三早上还需要吗？Guillermo 说各种情况都有。有的软件只为一次客户电话而存在：很多客户购买 Vercel 和 v0 是因为他们是售前工程师，见客户时直接带一个定制版本的软件，而不是一份幻灯片。三次电话后需求变了，就全部扔掉重做。从这个意义上说，软件变成了一次性的，或者说几乎免费。

但这反而带来了更多使用。他引用 Shopify CEO Tobi Lütke 说的"AI 的反身性"：一旦你知道只要一句提示词就能拿出一个高保真的原型和别人沟通，你就再也不会放弃这种方式。他多年前写过一篇文章，题目大意是"很难放弃效率"。有工程师感叹"我再也回不去以前那样写代码了，脑子已经不那样工作了"。但他也承认，很多 Agent 辅助的工程仍然很难，Vercel 的很多基础设施软件，有时要召集三个 Agent 加上很多聪明的人一起看一行代码才能判断对错，很多软件仍然会长期存在。

最大的变化是用户群体。有客户在 X 上私信他："我遇到一个错误。我其实不知道 Vercel 是什么，是我的 Agent 把我带到这里部署的，部署得挺开心，现在出问题了。"他的回应是："能把你的 Agent 介绍给我吗？"他会请对方给出对话记录，交给工程师，也许能变成评估用例，弄清楚客户的 Agent 是怎样走进死胡同的。以前是工程师直接告诉他"我看了文档，你说的 API 是错的，报这个错"。他认为将来会变成 Agent 之间直接沟通：客户的 Agent 给 Vercel 的 Agent 提功能请求或 bug 报告，Vercel 的 Agent 再在 token 预算、截止时间和 CEO 的偏好之间决定优先级，软件就这样产生。

六、为什么编程 Agent 总选 Vercel

Apoorv 指着幻灯片问：86 次里 Claude 86 次选了 Vercel 部署，界面组件选 shadcn 的比例约 90%，这是怎么做到的？是和 Anthropic 签了企业协议，还是 Agent 真的凭实力搜出来的？Guillermo 说"都有"，他"既不能确认也不能否认存在扩大 Vercel 使用的协议"。但有因果关系：多年来他们产出了大量高质量的内容，API 对人和 Agent 都好用。

他举了 Tailwind CSS 的例子。他很早就重押 Tailwind，这在人类开发者圈子里很有争议，因为它看起来很怪。代码有美感，可以看起来对称、漂亮，也可以像一堆垃圾，Tailwind 让代码更像后者，一行写得很长，对他这样有强迫症的人来说很难接受，但他克服了自己的偏见。Tailwind 带来的是"局部推理"：设计一个组件（比如幻灯片预览组件）时，可以只看这一处就理解它的样式，把它拿给别人放进 Google 的另一个页面也能完美工作。这让代码在经济上可扩展。Next.js 和 React 都有这种性质，Facebook 团队也是在工程师越来越多的情况下得出同样结论的。

对 Agent 来说，局部推理更重要，因为上下文窗口有限，现在最多 100 万 token，不可能装下人类所有的代码。此外，还有用于训练和检索的大量内容（编程 Agent 也会上网搜），以及这套技术能把 Salesforce 当作无界面的后端 API、把应用层放在 Vercel 上。Apoorv 总结为"可组合"，Guillermo 同意：可组合是 Agent 规模化的前提。

为什么什么都做

Vercel 的产品覆盖从沙盒、对话到工作流的很多环节，每一项都有独立的公司在做。Guillermo 说他只把"A+"的产品放在幻灯片上，很多不行的会被放弃或降低优先级。他的理由是：Agent 很重要，可能是"最后一类软件"，他们在为构建 Agent 提供工具和基础设施，不能不参与这个增长最快的经济体。Vercel 的产品理念是用自己的平台开发自己的产品：AI Gateway 就建在 Vercel 上，复用了计算平台和全球网络，他们甚至开源了做法，别人可以做一个和它竞争的网关。他说这复用了约 95% 的"火箭引擎"，和给页面做 CDN 用的是同一套。沙盒复用的是平台上每次部署都在用的虚拟化技术。Vercel 的使用量在短短几个月里增长到 3 倍，每日部署数从 1 月起翻了一番，他很高兴地说几乎没出问题，每次部署都会创建并销毁一台临时的计算机，这些经验直接用在了沙盒上。

七、价值会落在哪里

Apoorv 说，至少在 2026 年，价值更多落在模型以下：芯片、数据中心、电力、冷却和能源；模型以上，在编程、客服、法律等领域有一些价值，但很集中。Guillermo 说，token 经济中流向编程 Agent 的比例很大，编程 Agent 可能是通往 AGI 最有希望的路径，甚至就是那条路。Vercel 的运气在于建了编程 Agent 做有用的事时所需要的基础设施。他认为这会有很多类似的机会：判断现在是巨大泡沫还是人类最激动人心的篇章，要看是否在交付有用的产品和服务；而模型要有用，就需要沙盒、部署平台和域名。

他提到 Codex 团队告诉他，很多人想给自己做出来的东西起个名字、买个域名，结果是通过域名先找到了 Vercel。他早年押注让域名购买和配置变得极快极简单，因为 DNS 配置很痛苦，而人有了想法常常先去买域名。他自己的域名多到续费时都觉得心虚，花了不少钱，他安慰自己说这是"数字地产"。这个押注回报很好：用户有了新想法，就来到 Vercel。他们的目标是成为"地球上任何新想法的前门"。他认为帮助这些想法落地、变得有用的企业都会做得很好，安全会是一个巨大的问题，他现在想得很多的是怎样管理 Agent、给它们设护栏、保护整个互联网的安全。他们一直在招工程师，从编程 Agent 这一个用例带来的需求就还有大量东西要做，所以他不认为工程师的时代结束了。

八、快问快答

看空：他很早就预言了任何静态数据或内容生意的衰落，比如 Stack Overflow 这种汇集编程问答的网站。他不想点名公司，但看空一个类别：所有认为代码稀缺、很难写的公司，比如各种拖拽式搭建工具，"带辅助轮的编程"。他一直讨厌这类软件，觉得它居高临下、限制太多，把用户当成怕代码的小孩，建立在这个前提上的公司都要认真考虑转型了。他也看空不开放的公司：编程 Agent 想要直接拿到原始数据和信号，不想先和销售聊三个月需求和痛点，而是要按用量付费、即时注册、立刻拿到 token。很多软件生意其实没有产品，只有一份"电子宣传册"，要和企业销售聊好几年才可能有点软件出来。

看多：任何以"token 的速度"前进的公司。他最近在公司内部写了一篇文章：工程师被教导要设置速率限制，这对系统健康很有用，比如一屋子聪明人坐在帕洛阿尔托说"没有公司会每分钟部署超过 100 次"，于是写进代码。但现在没人知道真实的需求和合适的额度是多少。他当然仍要防范滥用、做客户身份验证，因为背后是超级计算机，不能让人两秒钟用掉一万亿美元的算力再求对方付钱。但作为一种刺激，他对公司说"不要再设速率限制了"，这和按用量付费的模式是一致的。现在有一家三个月前还不存在的 YC 公司，在 Vercel 上产生了大量部署，让他们发现"原来我们还有这个速率限制"，没人想到某个基础设施会有这么大的需求。

如果不做 Vercel 会做什么：太空科技，"能不能尽快去火星"。他喜欢人类成为多行星物种的愿景，作为一个"高可用、多可用区、多区域、多层故障转移"的基础设施人，他连在旧金山的住处都是按结构安全性挑的，选了一处历史上从没在地震中倒塌过的挡土墙边。他也对能源很兴奋：他认为我们看到的智能涌现是一种能量的双向流动，能量进去，智能出来，所以裂变、聚变、地热等任何突破都让他很兴奋。
