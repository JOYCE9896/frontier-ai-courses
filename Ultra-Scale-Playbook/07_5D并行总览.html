这一章讲什么

前面六章把五种并行方式逐个讲完了：数据并行和 ZeRO、张量并行和序列并行、上下文并行、流水线并行、专家并行。这一章把它们放在一起比较。它要回答的问题是：这些策略之间有什么相似和区别，哪些可以高效地组合，哪些最好分开用。

读完应该能说出每种方法省的是哪块显存、沿哪个维度切、主要瓶颈是什么，以及为什么张量并行通常留在节点内、ZeRO-3 和流水线并行放在节点之间。具体怎样一步步选出一套训练配置，放在下一章 寻找最佳训练配置。

01. 五种并行和三档 ZeRO 回顾

原书小节：5D Parallelism in a Nutshell（开头部分）

到这里，扩展模型训练能用的五种并行策略都已经出现过，每一种沿一个不同的维度切分：

  • 数据并行（Data Parallelism，DP）：沿 batch 维度切，每张卡拿一部分样本，模型完整复制。
  • 张量并行（Tensor Parallelism，TP）：沿隐藏维度（hidden dimension）切，把一个权重矩阵拆到多张卡上。
  • 序列并行和上下文并行（Sequence / Context Parallelism，SP/CP）：沿序列维度切，每张卡处理一段 token。
  • 流水线并行（Pipeline Parallelism，PP）：沿模型的层切，每张卡负责连续的若干层。
  • 专家并行（Expert Parallelism，EP）：沿 MoE 的专家维度切，不同专家放在不同卡上。

另外还有三档 ZeRO（Zero Redundancy Optimizer，在数据并行的各个副本之间分摊存储、去掉重复）可以和数据并行叠加，用来省显存：

  • ZeRO-1：在 DP 副本之间切分优化器状态（optimizer states）。
  • ZeRO-2：切分优化器状态和梯度。
  • ZeRO-3：切分优化器状态、梯度和参数。

（这五个维度在 TPU 语境下的对应讲法见 How to Scale Your Model 第 5 章。）

02. 流水线并行和 ZeRO-3 的对比

原书小节：5D Parallelism in a Nutshell

作者先把流水线并行和 ZeRO-3 放在一起比，因为两者很像，又有几处重要的不同。

相似的地方：两者都把模型权重分到多张 GPU 上，并且沿模型深度方向（一层接一层）安排通信和计算。比如 ZeRO-3 会在算当前层的同时预取（prefetch）下一层的权重。所以在这两种方法里，每个设备上执行的都是完整的层运算。TP 和 EP 不一样，它们在每个设备上算的是一层里的一部分。

（原书旁注：这里说“一层”是为了简化。实际的切分单位取决于具体实现，可能是几层、一层，甚至一层的一部分。）

不同的地方，原书列成了下表：

ZeRO-3流水线并行
每个计算单元存的是一层的一部分完整的一层
通信传输的是权重激活值
编排方式与模型无关（model-agnostic）与模型无关
实现难点模型切分和通信的处理很复杂高效的 PP 调度（schedule）很难写
扩展时的偏好偏好大的 $mbs$ 和 $seq\_len$，用来掩盖通信偏好大的 $grad\_acc$，用来掩盖气泡

表里的缩写：$mbs$ 是 micro-batch size，每次前向/反向处理的小批量大小；$seq\_len$ 是序列长度；$grad\_acc$ 是梯度累积（gradient accumulation）的步数，即攒几个 micro-batch 的梯度再更新一次参数。气泡（pipeline bubble）是流水线里部分 GPU 等上游数据、处于空闲的时间。

两者解决的是同一个问题，选哪个取决于你想让通信传权重还是传激活值。它们可以组合，但实践中很少这样做：要摊薄两者叠加的通信开销，全局 batch size 得大幅增加，于是要在全局 batch size、模型大小、网络带宽和训练效率之间做取舍。如果确实要组合，ZeRO-3 应当配置成在一串 PP micro-batch 期间把权重留在显存里，尽量减少不必要的通信。

ZeRO-1 和 ZeRO-2 只切优化器状态和梯度，和流水线并行很容易组合，两者互补，也不会带来新的难题。例如 DeepSeek-V3 的训练用的就是 PP 加 ZeRO-1。

03. 张量并行怎样和其他方法组合

原书小节：5D Parallelism in a Nutshell

张量并行（连同序列并行）和流水线并行、ZeRO-3 天然互补，可以组合。原因是 TP 依赖矩阵乘法的分配律：权重和激活值可以先切开各自算，最后再合并。

为什么不只用 TP？前面章节已经讲过它的两个限制：

  • TP 的通信在计算的关键路径（critical path）上，也就是计算必须等通信完成才能往下走。扩展到一定程度后，通信开销开始占主导，很难继续扩展。
  • ZeRO 和 PP 与模型无关，TP 却要仔细处理激活值的切分：在 TP 区域沿隐藏维度切，在 SP 区域沿序列维度切。这让它实现起来更麻烦，而且要懂具体模型的结构，才能保证每一处的切分方式都对。

所以组合多种并行时，TP 一般留给节点内的高速通信，ZeRO-3 或 PP 用在跨节点、带宽较低的并行组上。PP 的通信模式需要的带宽更少；ZeRO-3 的通信更容易和计算重叠。组合这些技术时主要考虑的是，怎样把 GPU 高效地分到每个并行维度的组里，让吞吐最大、通信开销最小，同时记住 TP 的扩展限制。例如，做 TP 通信的那组 GPU 应当放在同一个节点内。

（节点内 NVLink 和节点间网络的带宽差别，见 How to Scale Your Model 第 12 章。）

04. 上下文并行和专家并行

原书小节：5D Parallelism in a Nutshell

上下文并行和专家并行也能帮助切分激活值，可以看作 TP 的补充。CP 负责长序列，EP 让 MoE（混合专家）模型能分布式训练，两者组合也没有什么特别的问题。

上下文并行

CP 针对超长序列训练，把激活值沿序列维度切到多张 GPU 上。大多数模块，比如 MLP 和 LayerNorm，都能独立处理切开后的序列片段；attention 块需要通信，因为每个 token 都要看到整个序列的 key 和 value。CP 一章讲过，这一步用 Ring Attention 的方式处理，计算和通信相互重叠，效率不错。序列长到极端（128k token 以上）时，即使用了完全激活重计算（full activation recomputation，反向时把前向的激活值全部重算一遍，换取不存它们），attention 所需的显存在单张 GPU 上也放不下，这时 CP 就很有用。

专家并行

EP 针对 MoE 模型训练：把各个专家分到不同 GPU 上，计算时把 token 动态路由到对应的专家。EP 的主要通信是 all-to-all（每张卡都给其他每张卡发一份不同的数据）：先把 token 发到分配给它的专家，再把结果收回来。这会带来一些通信开销，但能让模型容量大幅增加，因为每个 token 在推理和训练时只经过总参数里很小的一部分。从分布式训练和推理的角度看，专家数变得很多时，把专家分到多张 GPU 上才有必要。（原书旁注：例如 DeepSeek-V3 有 256 个专家。）

📝 原书注：EP 和 DP 处理输入的方式相似，每张卡拿不同的输入，所以有些实现把专家并行看作数据并行的一个子集。区别在于 EP 用专门的专家路由，DP 则是所有 GPU 用一模一样的模型副本处理输入。

（MoE 的参数量和计算量怎么算，见 How to Scale Your Model 第 4 章。）

05. 各方法作用在模型的哪一部分

原书小节：Scope and focus

不同并行策略影响最大的是模型里不同的子模块：

  • 张量并行（和序列并行）切分权重和激活值，影响整个模型的计算。
  • 上下文并行主要影响 attention 层，因为只有那里需要跨序列通信，其他层各自处理切开的序列。
  • 专家并行主要影响 MoE 层（它们替换了标准的 MLP 块），attention 层和其他组件不变。
  • 流水线并行和 ZeRO 不特别针对某个子模块。唯一的例外是流水线并行要求各阶段的模块和层负载均衡，所以第一层和最后一层常常要特殊处理，因为它们多了 embedding 层。
张量并行 + 序列并行上下文并行专家并行
沿隐藏维度/序列维度切分权重和激活值沿序列维度切分激活值切分专家的权重和激活值
通信用于矩阵乘法（列切分/行切分的 linear）通信用于 attention 的 key/value通信用于把 token 路由到专家
需要针对具体模型实现除 attention 外与模型无关除 MoE 层外与模型无关
偏好节点内的高带宽通信偏好长序列需要模型有 MoE 层

作者的结论是，这些技术没有哪一个能单独解决扩展问题，实际中常常要把它们以某种方式组合起来。能不能总结出几条规则，帮人找到一个好的起点？这是下一章的内容。

这一章的要点

  • 五个并行维度：DP 切 batch，TP 切隐藏维度，SP/CP 切序列，PP 切层，EP 切专家；ZeRO-1/2/3 依次在 DP 副本间切分优化器状态、梯度、参数。
  • PP 和 ZeRO-3 都沿模型深度切权重、每个设备算完整的层运算；ZeRO-3 传权重，偏好大的 $mbs$ 和 $seq\_len$，PP 传激活值，偏好大的 $grad\_acc$。
  • PP 和 ZeRO-3 能组合但很少用，因为要大幅加大全局 batch size；若组合，ZeRO-3 应在一串 PP micro-batch 期间把权重留在显存里。
  • ZeRO-1/2 和 PP 互补、容易组合，DeepSeek-V3 用的是 PP + ZeRO-1。
  • TP（+SP）靠矩阵乘法的分配律，能和 PP、ZeRO-3 组合；但它的通信在关键路径上、扩展有上限，且需要针对模型实现，所以 TP 组放在节点内，ZeRO-3 或 PP 跨节点。
  • CP 主要影响 attention，用 Ring Attention 重叠计算和通信，适合 128k+ token 的序列；EP 主要影响 MoE 层，通信是 all-to-all，专家很多时才需要（DeepSeek-V3 有 256 个专家）。
  • 省显存对照：DP 省激活值，PP 省参数，TP+SP 省参数和激活值，CP 省激活值，EP 省专家参数，ZeRO-1/2/3 分别省优化器状态、加梯度、再加参数。
  • 没有单一技术能解决扩展，通常需要组合。
