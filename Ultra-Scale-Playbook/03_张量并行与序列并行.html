03 · 张量并行与序列并行

ZeRO 切不动激活；张量并行把矩阵乘法按行或按列切到多张 GPU 上，连激活一起分摊，序列并行再把 LayerNorm 和 dropout 沿序列维度切开

作者：Nouamane Tazi、Ferdinand Mom、Haojun Zhao、Phuc Nguyen、Mohamed Mekkouri、Leandro von Werra、Thomas Wolf（Hugging Face）· 2025 年 2 月发布 · 整理：Joyce（@JOYCE9896）
资料来源：The Ultra-Scale Playbook 中的 “Tensor Parallelism (and Sequence Parallelism)” 一章（本文依据原书英文网页整理，是中文转述和讲解，不是逐字翻译；图片引自原书，版权归原作者）

这一章讲什么

上一章用 ZeRO 把参数、梯度和优化器状态分到了数据并行的各张卡上。但 ZeRO 不切激活，一旦激活显存超过预算就没办法了。这一章讲张量并行（Tensor Parallelism，TP）：它把权重、梯度、优化器状态和激活都切开，而且计算前不需要先把它们收集完整。代价是通信落在了计算的关键路径上，很难藏起来。

章节顺序是：先用一个矩阵乘法讲清按列切和按行切；再把两种切法组合进 Transformer 的 MLP 和 attention；然后看 TP 扩展到 8、16、32 张卡时吞吐和显存怎么变；最后讲序列并行（Sequence Parallelism，SP），它把 TP 管不到的 LayerNorm、dropout 沿序列维度切开。读完应该能说清：TP 每层要做几次什么通信，为什么 TP 一般不超过一个节点的 8 张卡，TP+SP 把单卡最大激活降到多少。

01. 张量并行的基本原理

原书小节：Tensor Parallelism（开头部分）

两条矩阵乘法性质

张量并行利用的是矩阵乘法 $A \times B$ 的两条数学性质：

$$\begin{aligned} &\text{1.} \quad A\cdot B = A \cdot \begin{bmatrix} B_1 & B_2 & \cdots \end{bmatrix} = \begin{bmatrix} AB_1 & AB_2 & \cdots \end{bmatrix} \\ &\text{2.} \quad A\cdot B =\begin{bmatrix} A_1 & A_2 & \cdots \end{bmatrix} \begin{bmatrix} B_1 \\ B_2 \\ \vdots \end{bmatrix} = \sum_{i=1}^n A_i B_i \end{aligned}$$

第一条说，把 $B$ 按列切成几块，分别和 $A$ 相乘，结果按列拼起来就是 $A B$。第二条说，把 $A$ 按列、$B$ 按行对应切开，各自相乘后把结果加起来，也得到 $AB$。在神经网络里，矩阵乘法通常写成 $X \times W$：$X$ 是输入或激活值，$W$ 是线性层（Linear layer）的权重。

在张量并行中，张量沿某个维度切成 $N$ 份（shard，分片），分到 $N$ 张 GPU 上。矩阵可以按列切，也可以按行切，对应列并行和行并行。两种切法需要的通信原语（communication primitive，GPU 之间交换数据的基本操作）不一样。

（同一概念在 TPU 语境下的推导见 How to Scale Your Model 第 3 章）

按列切：column-linear

第一种是按列切（column-wise，也叫 column-linear）。把完整的输入矩阵复制到每个 worker 上，这一步叫 broadcast（广播，把一份数据从一张卡发给所有卡）；权重矩阵按列切开。每张卡用完整输入乘以自己那部分权重，最后用 all-gather（全收集，每张卡把自己的那块发给其他所有卡，最后人人都有完整结果）把结果拼起来。

代码：Picotron 中列并行 TP 的实现，见 picotron/tensor_parallel/tensor_parallel.py 第 54–123 行。

按行切：row-linear

第二种是按行切（row-wise，也叫 row-linear），权重矩阵按行切成几块。这时输入也得切开，所以要用 scatter（分发，把一份数据切成几块，每张卡拿一块），原书说这是全书介绍的第四个分布式通信原语，它替代了列并行里的 broadcast。每张卡上的结果形状已经对了，但只是部分和，要加起来才是最终结果，所以还需要一次 all-reduce（全归约，把各卡的张量逐元素求和，再让每张卡都拿到求和结果）。

代码：Picotron 中行并行 TP 的实现，见 picotron/tensor_parallel/tensor_parallel.py 第 125–189 行。

这几种通信原语的具体做法，原书附录有专门讲解（见 12 篇）。

02. Transformer 块里的张量并行

原书小节：Tensor parallelism in a transformer block

Transformer 由两种主要模块组成：前馈多层感知机（MLP）块和多头注意力（multi-head attention，MHA）块。两者都可以做张量并行。

MLP 块

前馈部分的切法是：先一个 column-linear，再接一个 row-linear。前向时这相当于一次 broadcast 复制输入，加一次 all-reduce。实际训练中连 broadcast 都不用做，因为可以保证各 TP rank（rank 指并行组里的一张卡）上的输入本来就是同步的。反过来先 row-linear 再 column-linear 效率更低，因为两个线性层之间还得插一次 all-reduce；先列后行可以省掉这次中间通信。

多头注意力块

attention 块的做法类似：Query（Q）、Key（K）、Value（V）三个投影矩阵按列并行切开，输出投影当作 row-linear。对多头注意力来说，列并行有很自然的含义：每张 GPU 负责一个或一组注意力头（attention head）的计算。同样的方法也适用于多查询注意力（multi-query attention，MQA，论文）和分组查询注意力（grouped query attention，GQA，论文），这两种结构里多个 query 头共用 key 和 value。

TP 在这两个块上效果好，是因为它们都有天然相互独立的维度。attention 块可以沿 num_attention_heads 维切，每个头独立计算；MLP 块可以沿 hidden_dim 维切，前馈网络在这个维度上的运算互不依赖。

TP 度数的上限

由于 QKV 投影是沿 num_attention_heads 维切的，TP 度数不应超过注意力头数。用 GQA 时，有 $num\_attention\_heads$ 个 query 头，但只有 $num\_kv\_heads$ 个 key/value 头（$num\_attention\_heads >= num\_kv\_heads$）。这时仍然可以设 $TP = num\_attention\_heads$，但要保证 K/V 头在各 GPU 之间正确同步。例如 Llama-3 8B 有 32 个 query 头、8 个 key/value 头，TP 理论上可以开到 32，但实现时要小心处理各 TP worker 之间 K/V 头的同步。

通信落在关键路径上

TP 不是万能的。它把好几个分布式通信原语直接放进了模型的计算路径，这些通信很难像 ZeRO 那样完全藏到计算后面（overlap，通信和计算同时进行）。最终性能取决于两边的权衡：一边是计算和显存上的收益，一边是多出来的通信开销。

看 TP 版 MLP 的操作时间线（MHA 同理）：每个 decoder 层的前向里，all-reduce 是一个同步点，没法和计算重叠。这段暴露出来的通信是必须的，因为最后的 LayerNorm 之前要先把各 TP rank 的部分结果合起来。

原书的两条旁注：用分块矩阵乘法（block matrix multiplication）配合异步通信/计算，可以部分藏住这段通信。比如 Megatron-LM 和 Nanotron 实现了 all-gather 与 FC1（第一个全连接层）计算的部分重叠：矩阵乘法结果的一部分先发给另一张 GPU，剩下的部分还在计算中。

TP 确实减少了矩阵乘法的激活显存，因为中间激活被切到各卡上了。但 LayerNorm 这类操作还是要收集完整激活，所以显存收益没有拿全。另外，TP 的通信量很大，严重依赖网络基础设施。这次 all-reduce 无法完全藏在计算后面，会直接加到前向的关键路径（critical path，决定前向最少要花多长时间的那串操作）上。这仍是活跃的研究方向，例如 Domino（Domino: Eliminating Communication in LLM Training via Generic Tensor Slicing and Overlapping）在探索如何把这部分重叠做到最大。

LayerNorm 和 dropout 的问题

还能从这个技术里挖出更多收益吗？LayerNorm 和 dropout 仍要在每张卡上收集完整激活，抵掉了一部分显存节省。办法是把这些剩下的操作也并行起来。

原书的 📝 注释：在 TP 训练里，all-gather 之后各 TP rank 看到的激活是一样的，所以 LayerNorm 权重的梯度在反向后不需要 all-reduce，它们天然保持同步。dropout 则不同，要在各 TP rank 之间同步随机种子，保证行为确定。

下一步就是张量并行的一个小而自然的扩展：序列并行。

03. 序列并行

原书小节：Sequence parallelism

序列并行（SP）把模型中 TP 不处理的部分（如 dropout 和 LayerNorm）的激活和计算也切开，但切的是输入的序列维度，不是隐藏维度。

原书的 📝 注释：“序列并行”这个词有点被用滥了。本节说的序列并行和张量并行紧密绑定，只作用于 dropout 和 layer normalization。序列更长时 attention 计算会成为瓶颈，需要 Ring Attention 之类的技术，这些有时也被叫作序列并行，但原书把它们称作上下文并行（context parallelism）以示区分。所以书里出现“序列并行”时，指的是和张量并行一起用的那种；上下文并行则可以单独使用（见 04 篇）。

为什么 LayerNorm 不能按隐藏维切

这些操作要访问完整的隐藏维度才能算对。比如 LayerNorm 要在完整隐藏维度上算均值和方差：

$$\text{LayerNorm}(x) = \gamma \cdot \frac{x - \mu}{\sqrt{\sigma^2 + \epsilon}} + \beta$$

其中 $\mu = \text{mean}(x)$ 和 $\sigma^2 = \text{var}(x)$ 都是沿隐藏维度 $h$ 计算的。所以这些操作虽然计算量很小，却占不少激活显存。序列并行改为沿序列维度切分，把这部分显存分摊到各 GPU 上。

难点在于这些转换既要高效、显存低，又要保证结果正确。

纯张量并行时，前向中：

  • f 是 no-op（空操作，什么都不做），因为激活已经在各 rank 上复制了一份。
  • f* 是 all-reduce，用来同步激活、保证结果正确。

反向中：

  • f* 是 no-op，因为梯度已经在各 rank 上复制了一份。
  • f 是 all-reduce，用来同步梯度。

f 和 f* 叫共轭对（conjugate pair）：在同一个方向上，一个是 no-op 时另一个就是 all-reduce，换到另一个方向就反过来。

序列并行用的是另一对操作 g 和 g*。SP 区域里刻意不用 all-reduce，因为那要收集完整激活，会抬高峰值显存，SP 就白做了。这里会用到 reduce-scatter（归约分发，先逐元素求和，再把结果切块，每张卡只拿一块）。

一步一步走一遍（以 MLP、2 张卡为例）

原书在这里调侃了一句“像某个著名 LLM 说的，let's take it step by step”。

开头的 LayerNorm（SP 区域）

  • 输入张量 X1* 和 X2*，形状 $(b,s/2,h)$，进来时已经沿序列维度切开。
  • 每张 GPU 在自己的那段序列上独立算 LayerNorm，得到 Y1* 和 Y2*。

第一次转换（SP → TP）

  • g 操作（all-gather）把 Y1 和 Y2 拼回完整序列长度。
  • 恢复出 Y，形状 $(b,s,h)$，因为 column-linear 层需要完整的隐藏维度 $h$。

第一个线性层（TP 区域）

  • A1 和 A2 是 column-linear 层，所以把 Y 沿隐藏维度切开。
  • 每张 GPU 独立做 GELU（一种激活函数）。
  • Z1* 和 Z2* 的形状是 $(b,s,h/2)$。

第二个线性层（TP 区域）

  • B1 和 B2 是 row-linear 层，所以恢复出隐藏维度。
  • W1 和 W2 形状为 $(b,s,h)$，需要相加。

最后一次转换（TP → SP）

  • g* 操作（reduce-scatter）一边做求和以保证前面 row-linear 的结果正确，一边沿序列维度分发。
  • W1* 和 W2* 的形状是 $(b,s/2,h)$。

最大激活降到 $\frac{b \cdot s \cdot h}{tp}$

序列并行的一大好处是降低了需要存储的最大激活尺寸。只用张量并行时，好几处都要存形状为 $(b,s,h)$ 的激活；加上序列并行后，激活要么沿序列维切，要么沿隐藏维切，最大激活尺寸降到 $\frac{b \cdot s \cdot h}{tp}$。

TP+SP 的通信比 TP 多吗

可以说多，也可以说不多。普通 TP 的前向里，每个 Transformer 块有两次 all-reduce；SP 里每个块有两次 all-gather 和两次 reduce-scatter，操作次数是 TP 的两倍。但一次 all-reduce 可以拆成一次 all-gather 加一次 reduce-scatter（见附录 “Ring AllReduce” 一节，12 篇），所以两者的通信开销其实相同。反向同理，只是每个操作换成它的共轭（no-op ↔ allreduce，allgather ↔ reducescatter）。

原书对两组测试的观察：

  • 两种方法的最大性能跌幅都出现在 TP=8 到 TP=16 之间，因为这时从只在节点内通信（NVLink）变成了跨节点通信（EFA，AWS 的节点间网络）。
  • TP 加 SP 节省的激活显存，让能放下的批量比只用 TP 大得多（对照两张表，TP=32 时最大批量 20 对 100）。

原书的 📝 注释：SP 区域里各 LayerNorm 处理的是序列的不同部分，所以它们的梯度在各 TP rank 上不同。为了让权重保持同步，反向时要对这些梯度做 all-reduce，和数据并行同步权重的方式类似。不过 LayerNorm 参数很少，这点通信开销很小。（注意这和前面纯 TP 时的结论相反：纯 TP 下各 rank 看到的激活相同，LayerNorm 梯度天然同步。）

TP+SP 的两个局限

TP+SP 还有两个限制。第一，序列长度继续增长时，TP 区域里的激活显存还是会爆，因为那里每张卡处理的是完整序列。第二，如果模型大到 TP=8 都放不下，跨节点互联会带来严重的减速。

第一个问题用上下文并行解决（见 04 篇），第二个用流水线并行解决（见 05 篇）。原书接下来先讲上下文并行。（TPU 上 TP 的切法和通信量推导见 How to Scale Your Model 第 5 章）

这一章的要点

  • 张量并行利用矩阵乘法的两条性质：按列切 $B$ 结果按列拼接；按行切则各部分相乘后求和 $\sum_i A_i B_i$。
  • column-linear：输入 broadcast，权重按列切，输出 all-gather。row-linear：输入 scatter，权重按行切，输出 all-reduce。
  • MLP 用先 column-linear 后 row-linear，前向只需一次 all-reduce，省掉中间通信；attention 的 QKV 列切（每卡负责一部分头），输出投影行切。
  • TP 度数不应超过注意力头数；GQA 下可以开到 query 头数，但要处理 K/V 头的同步（Llama-3 8B：32 个 query 头，8 个 K/V 头）。
  • TP 的 all-reduce 在关键路径上，难以和计算重叠；超过 8 卡跨节点后吞吐骤降（3B 模型：TP=8 到 16 降 42.7%，16 到 32 降 65.6%）。
  • TP 让参数、梯度、优化器状态按比例缩小，但 LayerNorm、dropout 要完整激活，激活显存省得有限。纯 TP 下 LayerNorm 梯度天然同步；dropout 要同步随机种子。
  • 序列并行把 LayerNorm、dropout 沿序列维度切开；SP→TP 用 all-gather（g），TP→SP 用 reduce-scatter（g*），反向取共轭。
  • TP+SP 下单卡最大激活降为 $\frac{b \cdot s \cdot h}{tp}$；70B 模型用 TP+SP=16 能放下 16k token 序列。
  • TP+SP 每块两次 all-gather 加两次 reduce-scatter，通信开销和 TP 的两次 all-reduce 相同；同样难以重叠，通常 TP≤8，留在节点内。
  • SP 下 LayerNorm 梯度在各 rank 不同，反向要 all-reduce，开销小。
  • TP+SP 的两个局限：序列更长时 TP 区域激活仍会爆（交给上下文并行）；模型大到 TP=8 放不下时跨节点很慢（交给流水线并行）。
