第四讲：从工具、代码和反馈中学习

三篇论文，三种反馈来源：ReAct 把推理和行动交替进行，RLEF 用代码执行结果做强化学习，Constitutional AI 让模型按一套人写的原则批评和修改自己

主讲：Aakanksha Chowdhery
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、反馈从哪里来

大多数人用大模型是在聊天场景里，但要在现实任务中有用，模型必须和现实环境、工具、代码交互，并从交互中学习。前两讲讲了推理时扩展和验证，这一讲在此基础上读三篇论文：ReAct（工具调用，把推理和行动结合起来），RLEF（用代码执行反馈训练代码模型），Constitutional AI（模型批评自己，作为改进的反馈循环）。三者都是让模型改进自己的方法，区别在于反馈来自哪里：与环境的交互、某种批评机制，或者以已知的正确答案为依据。

二、ReAct：推理和行动交替进行

ReAct 的出发点是人做事的方式：先想一想（比如为什么要来上这门课），想好了才有理由行动；行动后会得到关于环境的新观察（来上课后发现喜不喜欢），据此再推理（也许去做作业，然后又决定别的事）。思考和行动之间的这种循环，对改进大模型的输出也很有用。

今天的模型推理已经是内置的，但回看过去几年，这不是开箱即有的。模型过去很难把推理和行动结合起来，一个原因是会产生幻觉，不知道环境里实际发生了什么：问 Gemini、ChatGPT 或 Claude 今天的气温，它没有当前信息，除非去搜索。没有和现实世界的联系（grounding），就没法采取行动再把结果带回推理。之前有两类做法：思维链能展示中间步骤，但这些步骤基于模型内部状态，没有外部反馈，未必有依据；WebGPT 这类模型学习和网页浏览器（一种工具）交互，在交互轨迹和人类偏好上微调，但没有推理过程。ReAct 把两者结合起来，而且只靠提示：先让模型针对任务一步步思考，得到推理轨迹，附在提示里；再问应该采取什么行动，去执行。它交替进行，思考 1、行动 1、思考 2、行动 2，每一步都影响下一步，就像你渴了往厨房走，发现没水了，再决定去超市。

这在需要依据的任务上帮助很大：HotpotQA（跨 Wikipedia 的多跳问答）、FEVER（事实核查）需要关于现实世界的知识；WebShop 要模型在网上买东西，要通过一连串工具调用确定搜什么商品，再完成购买。另一个好处是轨迹更可解释，人更能信任模型的回答。

怎样保证模型生成的行动是有效的？一种常见做法是把它更多地当作分类问题：给出有效行动的子集，告诉模型"这是你的推理，这是世界的状态，这些是可选的行动"，让它选下一步。她在 Google 和机器人团队合作的一项工作里也用了这种方法，机器人的行动必须有效，不能没有行动列表。

实现上用的是冻结的 PaLM 加少样本示例：示例里有思考、行动和观察，再让模型给出下一步。例子来自 HotpotQA："除了 Apple Remote，还有什么设备能控制 Apple Remote 最初设计用来交互的那个程序？"标准提示答错；思维链展示了中间步骤，答案仍不完全对；只行动（搜索 Apple Remote，再搜 Front Row）最后得出"已停产，给不出好答案"。ReAct 则先想"我要搜 Apple Remote，找到它最初设计用来交互的程序"，搜到它是 2005 年前后推出的遥控器，最初用来控制 Front Row 媒体中心；再想"接下来搜 Front Row"，没搜到，换成"Front Row (software)"，查到是已停产的媒体中心软件，再思考，给出了答案。她说现在打开 Qwen 等模型的思考模式，会自动看到这类过程，因为模型已经在这类轨迹上蒸馏过，学会了工具调用。

学生问模型怎么知道自己知道什么、什么时候该搜索？她说这有相互矛盾的看法：有人说模型很清楚自己知道什么；但让模型给自己的输出打置信度，它们通常过于自信、没有校准好，这仍是研究问题。做应用时，关心的不是模型是否知道自己知道什么，而是让它用对工具，得到有依据的知识。搜索结果互相矛盾怎么办？她说这要由用户决定，可以像第二讲那样用多数投票增加信心，或者在交给用户前验证答案；但搜索结果带来的幻觉比单靠模型内部状态容易控制得多。还有学生问能不能研究思考和观察在 KV 缓存中的表示（观察来自环境，不是模型生成的），她说可以用开源模型做成项目。为什么把思考也写成 token？因为语言模型在语言上训练，有推理 token 作为合适的中间表示，有助于输出正确的行动。

结果

在 HotpotQA 和 FEVER 上，行动空间很简单：搜索 Wikipedia 页面、在页面里查找字符串、结束任务，模拟人怎样用 Wikipedia。基线有标准提示、思维链、思维链加自一致性（就是多数投票）、只行动；还有两种组合：ReAct 若干步后失败就退回思维链自一致性，或者多数答案出现次数不到一半时退回 ReAct。结果：ReAct 普遍好于只行动，但不总是好于思维链，在 FEVER 上更好，在 HotpotQA 上不一定；把思维链自一致性和 ReAct 以任一方向组合，就能超过标准方法。说明要把模型内部知识和外部知识恰当结合，用推理作为中间环节。错误分析显示：思维链的主要失败模式是幻觉，ReAct 能通过搜索检索知识，错误更少、更可信。能微调时 ReAct 更好，再加强化学习还会更好，下周会讲。

在决策类任务上（网页浏览、机器人、游戏环境等），以 WebShop 为例：按用户指令买东西，比如找一个带抽屉的床头柜，在模拟环境里评估是否成功。和模仿学习（即监督微调）、模仿学习加强化学习相比，ReAct 的得分和成功率都更高，但仍远低于人类专家：66.6 对 82.1（课上给出的数字）。成功率低的一个原因是多步任务中错误会层层累积。

ReAct 的局限：行动空间很大时需要更多示范，放不进上下文；需要多步推理，推理成本更高。但总体上它在问答、事实核查和决策任务上表现更好，幻觉更少，决策轨迹更好。

课堂讨论

如果环境反馈有噪声或错误怎么办？学生提到：加一层反思，让 Agent 先推理环境给的东西；能够回退，因为噪声可能让它陷入重复循环；更好的置信度指标；同一任务做多次取最好。还应该考虑哪些认知机制？学生提到：人的认知因任务而异，有时靠经验，有时一步步想，有时要先想清楚再行动；她归纳为任务分解、并行的思考方式、记忆和过往经验。还有学生说人会调整推理和行动的比例，有的任务要多想再动手；她说现在一些模型确实想得太多，简单任务也有很长的思考轨迹，怎样让模型别想太多是很有意思的方向。也有学生提出按子任务给不同模型做基准，再按各自强项分配任务，类似复合系统，她说可以做成项目。

三、RLEF：用执行反馈训练代码模型

课上大多数人都用 Claude Code，很多工程任务已经交给这些 Agent。要让编程 Agent 很强，需要理解用户意图，并从生成的代码得到反馈、在此基础上迭代。RLEF 是最早表明执行反馈能大幅提高代码模型表现的论文之一。它是端到端的强化学习微调框架：行动是生成的代码，观察来自执行反馈，也就是运行测试、收集通过与否；根据测试是否通过给二元奖励，用 PPO 训练。

核心是一个迭代反馈循环，同时用到训练时和推理时的执行反馈：

  1. 模型拿到自然语言的题目描述，生成代码。
  2. 在一组公开测试上评估；失败了就把执行反馈交给模型再试一次，直到通过或达到轮数上限。
  3. 最终的解答在一组私有测试上评估，决定奖励，用于 PPO 更新策略。

左边是用当前策略做推理时反馈循环，右边是根据执行结果更新策略，让模型持续自我改进。例子：写代码检测回文子串，第一轮生成一个基本解法，公开测试超时；拿到反馈后，模型做了优化，通过了公开测试，再提交到私有测试。关键之一是"两级测试"：公开测试是一小部分，迭代时提供即时反馈、引导解法改进；私有测试在生成过程中完全隐藏，只用来产生奖励信号，模型没法简单记住测试输出。另一个设计是"混合的 token 级和轮次级策略"：策略模型逐个 token 生成代码，对生成过程有细粒度的控制；但价值函数在轮次级别计算，对整个回复评估，用提示的最后一个 token，所有 token 共享一个优势值。她说这更接近 GSPO 那样对整个序列给奖励，而不是逐 token 给。

学生问公开测试从哪来、怎样判定失败。她说是在训练循环里设计的：比如 CodeContests 自带一组测试，留一部分作公开测试用于推理时反馈，另一部分作私有测试用于训练；失败就是真的运行 Python 测试没通过，把结果附在上下文里，让模型生成第二个解法。作业里会做类似的事，不是针对代码，而是在数学题里找出生成解答中的错误。

为什么有效

结果基于 Llama 3.1，稍旧，但很清楚：在竞赛编程题 CodeContests 上训练后，验证集和测试集上的解题率随采样预算（横轴是对数刻度）都明显提高。原因是：基础模型并不会从错误解答和执行反馈中受益，真正起作用的是训练时每一轮都看到执行反馈，并且能泛化到其他基准。论文分析了第一、二、三轮的错误数、代码改动数和错误类型：经过 RLEF 后，后续几轮里错误输出更少，模型开始真正修复输出；没有这个迭代循环，改动往往是错的。也就是说，既利用了多样本的多样性，修改也更有针对性，因为能看到哪里错了。作业里也会用到这个思路。

学生提了几个问题。反馈只有对错，题目又简单，难题是不是需要错误轨迹等更多信息？她说很可能，可以做成项目。只奖励最终结果，会不会鼓励模型多试几轮而不是第一次就做对？她说取决于错误类型，复杂问题可能确实需要多轮；这里有推理时反馈，提交到 PPO 前已经有几次机会自我纠正。这背后又是过程奖励和结果奖励之争，在不同领域、不同基准上可能要做不同选择。为什么能泛化？可能因为竞赛题比较难。监督微调能否比得上？她说在推理轨迹上做监督微调也能拿到一部分收益，有论文这样说，但一般认为强化学习能解决稍微新一些的问题、泛化多一些，而监督微调对同领域的东西肯定有效。为什么 RLEF 错误输出少了、超时错误却多了？她说可能是模型能自己修复错误了，但测试超时说明解法仍不对，很多是领域相关的。

讨论题：代码库太大放不进上下文怎么办？学生提到：先搜索需要的信息，判断信息够了再动手；为每个文件写简短摘要；把代码建成图、做相似度检索（类似 RAG），在循环中判断信息是否足够。她说这正是 Claude Code 在做的：先找出相关部分，再在那里改代码，SWE-bench 就是针对这一点的基准。搜索、摘要、表示都是解决它的第一步，然后再决定打什么补丁、测试是否通过，Azalia 实验室的 CodeMonkeys 论文也针对类似的思路。

四、Constitutional AI：让模型按原则批评自己

这里要改进的是"无害性"：希望模型有帮助，同时无害。传统做法是 RLHF：给人看两个模型输出，问哪个正确、有用、足够具体，按人的偏好训练奖励模型，再用它来"爬坡"。比如 PaLM 的微调中，加上 RLHF 后，随着模型变大，回答明显变好。但这很难扩展，收集几万个人工标签非常耗时繁琐。

既然模型能推理，Anthropic 提出用人写的一套原则（称为"宪法"）来描述期望的行为，人只需要写宪法，不必一直在循环里。这之所以可行，是因为模型越来越会遵循指令：要求它按某种格式回答，它能做到；问它"这个回复有没有某种行为"，它能如实回答。他们写了 16 条原则，作为提示来判断回复是否符合宪法、批评模型自己，再要求它修改。例如：

  • 批评：指出回复中有害、不道德的地方；修改：删掉这些内容。
  • 批评：是否有性别偏见，说明理由；修改：去掉所有痕迹。
  • 批评：是否不适合小孩；修改：改写成合适的。

这要求模型能识别这些行为，并能按要求重写。流程分两阶段：

  1. 监督学习阶段：用红队提示让模型回答，按宪法批评、修改，在这些自我批评和修改生成的数据上微调。随着修改次数增加，无害性提高，有用性下降（让模型遵循一组固定原则会让它没那么有用），但两者之和单调提升。
  2. 强化学习阶段：用第一步的回复和宪法，以 AI 反馈训练一个偏好模型，再微调模型使这个偏好模型的分数最大，让模型的回答尽量周到、尊重、礼貌。这就是用宪法训练的偏好模型代替 RLHF 里的大量人类反馈。

学生问宪法要修订怎么办，能不能不重训就更新、彻底去掉旧规则？她说一方面 RLHF 通常是模型训练的最后阶段，后训练只占约 5% 的算力，更新比较频繁，宪法要改可以按一定频率做；另一方面，这涉及持续学习，怎样让模型遵守新行为、忘掉某些知识，仍是开放问题，有通过可解释性方法"抵消"某些知识的研究，但还没有证明能让模型真正忘掉。

结果：横轴是训练序列数，纵轴分别是有用性 Elo 和无害性 Elo（人更偏好哪个）。和只用有用性 RLHF、有用加无害的 RLHF（都是人类反馈）相比，Constitutional AI 和加了思维链的 Constitutional AI 有用性相当或略低，但无害性高得多；她说这是 Claude 模型很强的一点，现在这套技术被各家模型使用。学生指出加了思维链的版本有用性更低，她说这更多和有用与无害之间的反向关系有关，需要找到平衡。

学生问监督阶段是不是只是让模型批评自己、再在自己的输出上微调，提高这些输出的概率，没有显式反馈？她说是的，这一步在很多地方都会用到；只要微调规模比基础模型的训练小得多，就不会丢掉原有能力，但输出分布会偏向这些回复。怎样确认 AI 反馈准确？她说训练偏好模型时要有测试集或验证集，通常会让它给一些样本打分、和人的判断对比，确保和人一致，只是不需要上万个人工标签。

以无害性 Elo 为纵轴、有用性 Elo 为横轴：预训练基础模型分数不高；只追求有用的 RLHF 把前沿推向有用性；有用加无害的 RLHF 是另一条曲线；宪法监督学习仍不如 RLHF；宪法强化学习加思维链在有用和无害之间得到了最好的帕累托前沿。推广来说，凡是希望模型遵循一组可能互相冲突的指令的场景，都可以用这种原则式方法。后续工作包括比较 RLAIF 和 RLHF、Self-Refine（用自我反馈迭代改进），以及用强化学习教模型自我纠正。她提醒，让模型批评自己往往更难，因为模型可能过于自信，用其他模型组成共识来批评有时效果更好，这是活跃的研究领域，也可以做项目。

五、小结和问答

  • ReAct：让模型在现实中行动并结合反馈和推理，得到有依据的回答，更好地回答问题、核查事实，在游戏、网页浏览等环境中做出有用的决策，轨迹也很可解释。后来很多工作在此基础上改进工具调用，现在很多模型开箱就会调用工具，但这是让语言模型结合推理和行动的基本构件。
  • RLEF：编程 Agent 要做对，需要执行反馈并迭代地纳入它，单元测试是最好的执行反馈来源之一，这也减少了在竞赛编程等任务上达到最先进水平所需的预算。
  • Constitutional AI：让模型遵循人写的原则来产生自我改进的反馈，推广到任何能让模型遵循规则的场景。反馈信号足够时，就能让模型超越训练数据本身。

有学生问是否有系统地结合认知行为科学和大模型的研究。她说现在确实在借鉴人解决问题的方式：拆解任务、分析、并行尝试。但最终要回答的是：推理空间里的搜索能否自动化。如果搜索空间定义清楚（比如行动有限的游戏），就可以让模型自己去探索；而交给模型的很多任务没有定义清楚的搜索空间，需要在真实环境（搜索工具等）里获得经验、收集观察，所以才用语言空间的这种方式。

这些改进大模型的技术怎样迁移到 Agent？她问学生 Agent 的定义，学生说是相互连接、有记忆和会话、能调用函数的大模型。她说这里讲的还不算完整的 Agent，没有会话和记忆，但 Agent 的基本构件之一就是让模型按某种方式回应，所以这些很有用。有了强化学习的后训练，ReAct 这种人工设计的框架会不会变得不重要？她说既是也不是：如果能定义要探索的搜索空间，是；但很多任务的搜索空间没有定义好，比如会计、金融、法律 Agent，要遵循的步骤非常领域化。ReAct 定义的是一种顺序和工作流（推理、行动、再推理），而完成用户任务的工作流仍然很依赖领域，很难跨领域通用。还有学生问能否直接在生成时限制有害内容，她说某种程度上有这么做，数据也会被过滤，但模型在互联网上训练，再多限制也去不干净。
