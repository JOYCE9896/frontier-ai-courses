第五讲：规划与多步推理

三篇论文：LATS 把蒙特卡洛树搜索引入语言 Agent，SPRINT 教推理模型把相互独立的步骤并行执行，SWiRL 用离线合成的多步数据和逐步奖励训练模型推理和调用工具

主讲：Azalia Mirhoseini
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、LATS：语言 Agent 树搜索

第一篇是去年 ICML 的《Language Agent Tree Search Unifies Reasoning, Acting, and Planning in Language Models》。多步任务不仅要推理，还要根据推理采取行动，并搜索、优化通往正确答案的轨迹。以规划旅行为例：推理是想清楚要做什么，比如预算是多少、去哪里；行动是收集信息，比如浏览网页、生成查询去搜 Reddit 或旅行博客；搜索是根据收集到的信息改进计划，比如考虑别的目的地、找当地可做的事。

这篇论文要解决的是：不只是让大模型生成一个计划再执行，而是鼓励它探索多种计划和路径，因为模型（至今仍是）不太擅长生成多样的解法、多步优化。论文把强化学习和多步规划里已有的技术，包括蒙特卡洛树搜索（MCTS），引入大模型的推理路径，并让模型在与环境交互时获得的反馈用于改进后续的规划和搜索。比如"规划去夏威夷的旅行"，模型可能想到问去过的朋友、看相关的 subreddit；框架给每个行动打分，据此决定扩展哪一支，比如行动一分数高，就扩展它，去问朋友 A 和朋友 B 的意见，再按回答质量打分继续扩展。有些行动可以并行执行，同时兼顾探索和利用，这就是 MCTS 的作用。

和之前工作的区别：Math-Shepherd 是用验证器给推理轨迹打分来引导搜索；LATS 打分依据的是模型所采取行动的结果，还加入了模型对轨迹的反思和来自环境的观察。和 ReAct 相比，多了记忆、反思和更多规划。它结合了思维链（把推理拆成若干步）、树展开（通过生成行动形成一棵树，在上面搜索和规划）和 ReAct 的反馈。

六个阶段

以"穿过迷宫找到出口"为例，初始观察是"你在一个昏暗的房间里，左右各有一扇门"：

  1. 选择：按 UCT（见下）选一个节点来扩展。
  2. 扩展：从这个节点采样几个行动，比如开左门、开右门、在房间里找线索。
  3. 执行和观察：在环境里执行每个行动，把观察附到上下文里，比如开左门看到"一条挂着画的黑暗走廊"。
  4. 评估：给新状态打分，取两个分数之和。一是用大模型当评委，直接让它给这个状态的前景打 0 到 1 分；二是自一致性分数：假设采样了 50 个行动并归类，某类行动被采样得越多分数越高，比如行动 A 占 75%，它的自一致性分数就高。
  5. 模拟：比如贪心地选分最高的状态 A 一直扩展下去，直到成功、失败或达到扩展预算。例子里从 A 出发选择"走向楼梯"，幸运地看到了标得很清楚的出口。
  6. 反向传播和反思：用这条轨迹的结果更新沿途各状态的分数；无论成败，模型都写下对这条轨迹的反思，分析成功或失败的原因。论文说反思对整体质量提升很大。

UCT（应用于树的上置信界）直接来自 MCTS 文献，用来平衡探索和利用：只按当前最高价值走，可能错过眼下价值低、但最终价值更高的节点。公式是

$$\text{UCT}(s) = V(s) + w\sqrt{\frac{\ln N(p)}{N(s)}}$$

第一项是利用，第二项鼓励探索，$w$ 是超参数，$N(p)$ 是父节点被访问的次数，$N(s)$ 是当前节点被访问的次数。相对父节点而言，一个节点被访问得越少，第二项越大，越鼓励去访问它。学生问为什么是这个形式，她说背后有数学和理论上的直觉，但没有证明这是最优的界，只是被认为是比较好的平衡方式。反向传播时，一条轨迹结束后用它的回报 $r$ 更新沿途每个状态的价值：

$$V(s) \leftarrow \frac{V_{\text{old}}(s)\,(N(s)-1) + r}{N(s)}$$

结果：在 HotpotQA（每道题按设计至少要检索两个 Wikipedia 页面）上，随着采样的轨迹数增加，表现显著提升，反思和推理轨迹在最后又带来很大提升，也就是说它提供了一种把更多推理时算力有效转化为更好解法的机制。在 WebShop（比如"找一张已经组装好的小型便携桌子，某种颜色和表面处理，在某个价位"）上，不做任何微调、只在测试时使用，就能接近人类专家的结果。它模块化、容易移植。缺点是成本：反向传播和树展开都要额外花很多算力，论文没有分析成本收益；另外它假设行动可以撤回，但有些行动不可逆，比如付款，这时很难照搬。

讨论中，有学生说 UCT 来自多臂老虎机，论文有没有试别的探索算法？她说没有，那一整套文献都可以拿来试，论文的主要贡献是搭了一个平台，别人可以放进别的优化方法。轨迹里重复出现的行动怎么处理？她说在同一个父节点下重复的行动会增加计数，体现在 UCT 里；这里构造的是树，不是全连接的图。

二、SPRINT：让推理模型并行思考

这是她们 2025 年的新论文。观察是：o1、Gemini 2.5 Pro 等推理模型遇到难题会想得更久，想得越久准确率越高。DeepSeek-R1 训练过程中，AIME 数学题的成绩上升，平均回复长度也在上升。但这些长推理里，很多步骤彼此独立：尝试另一种方法，把任务拆成可以并行做的子任务，验证前面的步骤。看推理轨迹的依赖图，有很多计算互不依赖，没必要等模型一个个按顺序生成。

SPRINT 是一个用在后训练（微调）阶段的框架：让推理模型用"规划者"制定解题计划，再由多个可以并行运行的"执行者"执行，计划和执行可以反复交替，从而加速推理。

怎样教会模型生成这种并行轨迹？她说这里有一个值得记住的通用思路：想让模型学会某种行为时，可以用大模型自己来制造微调数据。具体做法：

  1. 让 DeepSeek-R1 对问题生成推理轨迹和回答。
  2. 让 GPT-4o 读这条轨迹，把它切成若干步，并标出每一步哪部分是规划、哪部分是执行，有的规划对应多个执行。
  3. 再让模型判断各步之间的依赖关系，构成一个有向无环图，比如第 2 步和第 4 步都依赖第 1 步，但彼此独立。
  4. 把可以同时做的步骤打包：先做第 1 步，第 2、3 步完全可以并行。
  5. 把轨迹改写成带标签的格式（规划 1、规划 2 写在一起，然后执行 1、执行 2），对模型做监督微调。

推理时，模型会输出这些标签：先生成规划 1 和规划 2（因为它们相互独立），然后两个执行同时进行，执行可能是调用工具（比如用计算器或 Python 算一个式子），结果同步回上下文，再生成下一批规划。为什么重要？多步推理的推理成本很高，等模型输出很久也让人不耐烦；顺序执行时，规划 1、执行 1、规划 2、执行 2 一个接一个，而并行后，独立的执行可以同时进行。

学生问，如果后面发现前面的规划错了要回头改，模型怎么记得哪个规划对应哪个执行？她说这里教模型的只是：只要能生成可以并行执行的规划，就不要等规划 1 执行完才生成规划 2；模型仍能看到全部上下文，需要回头修改时照样可以。这会不会改变"预测下一个 token"的结构？不会，仍然是下一个 token，只是有了标签，我们知道有两个独立的规划，就可以把它们分出去并行运行。

训练配方：在 MATH 数据集上生成约 6000 条思考轨迹，保留并行度较高的，在 DeepSeek-R1-Distill 7B 上用改写后的轨迹做监督微调。她们原本的目标是最大化并行、减少顺序生成的 token，结果发现准确率也提高了：模型似乎喜欢这种更有结构的思考方式。和基线 R1-Distill 7B 相比，准确率提高约 3.5 个百分点，顺序 token 数也比 32B 模型少得多。在 MATH 上，和准确率相当的方法比，顺序 token 数减少约 40%。还有跨领域泛化：只在数学上训练，在 Countdown 和 GPQA Diamond 上也有更多并行机会、更高准确率。

其他观察：难题需要更多轮的规划和执行；早期阶段并行和探索更多，后期收敛到较少的规划，深入一条路。节省的顺序 token 在需要多想的难题上更大，思考 token 少的简单题并行机会少，这样做甚至可能比基线差。她提到 Claude Sonnet 4.5 的系统卡里，提示鼓励模型尽量多用工具，至少 100 次，说明现在解决的问题越来越难，每个问题处理的 token 远远超过八千到一万。

学生问，各分支单独看都对，合在一起却错了，以哪个为准？她说无论顺序还是并行，所有内容最后都在上下文里，模型要在给出最终答案前解决矛盾；两种方式都可能出现矛盾，而这里的规划多是同一问题的不同步骤，而不是不同解法。并行的任务耗时不均怎么办？可能会有拖后腿的，但总时间受限于最慢的那个，而不是两者相加；如果某个执行太简单，她们会把它并入规划，凑成更大的块，负载均衡也可以作为优化方向。并行度和任务有关，有的任务天然更并行，但她们发现数学、GPQA 等很多推理问题都存在并行性。这里用的是监督微调，强化学习（如 GRPO）可能带来更多收益和更好的泛化；工具调用的重叠、真正实现墙钟时间上的加速，也是可以做的工作。

三、SWiRL：逐步强化学习，离线合成多步数据

第三篇是她们即将在 COLM（蒙特利尔）上发表的工作。很多现实任务需要多步推理和工具使用：用搜索引擎回答多跳问题、解数学题、做软件工程项目、规划旅行、分析数据。难点在于：一步推理加工具调用已经复杂，多步时错误会层层累积；在训练过程中实时调用工具很麻烦，工具会失败、会慢，而训练本来就耗时；RLHF、RLAIF、执行反馈等方法大多针对单步任务优化，奖励只看最终答案，再往前分配给各个行动，对生成步骤的过程缺乏把控。

设计目标：模型能解决复杂的多步推理任务；知道什么时候调用工具，生成正确的调用查询；在多步中保持准确，能从错误中恢复，知道什么时候停止、给出最终答案；训练时避免调用工具；能泛化到新的工具和任务。

做法分两部分。

  1. 离线合成多步数据。给模型一个题目，告诉它有哪些工具，每一步可以推理、调用工具或给出最终答案。模型采取第一个行动（比如推理后调用工具），执行工具，把环境的回应给模型；再把原题、之前的行动和结果一起给它，让它采取下一个行动，如此迭代，每道题会有 1 到 3、5 步不等。然后用大模型当评委，给每一步打分：在之前上下文的条件下，这个行动好不好。这一切都可以离线、大规模并行地做。之后可以按不同方式过滤数据：过程过滤（只保留每一步都被评委判为好的轨迹）、结果过滤（只保留最终答案正确的轨迹，不管各步分数），或两者都要。
  2. 强化学习训练。例子："Glen ... 和 Rossling 谁更年长？"第一步行动是"我应该先搜第一个人的年龄"，评委给出奖励；然后把训练数据里已有的环境回应给模型，让它采取下一步，搜第二个人的年龄，再给奖励；最后它输出带答案标签的最终答案，也有奖励。关键是训练时不调用工具：给模型看题目和到第 $k$ 步为止的行动及环境回应（都来自离线数据），让它采取下一个行动，只根据这个行动本身拿奖励来做强化学习优化，不执行它。所有工具调用都在离线标注阶段完成。评委没有专门训练，只是提示。

学生问评委看不到工具的输出，怎么打出合理的分数？她说评委评的是模型为调用工具生成的查询本身，而不是工具的输出：模型问"某人的年龄"，不知道答案也能判断这是个好问题。这相当于给这一步提供了过程奖励，之前的工具调用结果则已经包含在离线数据的上下文里。优化目标是：给定之前所有的状态和行动，单个行动的期望奖励，对第 1 步到第 $k$ 步的每个行动都这样做。

推理时，提示告诉模型可以用什么工具（比如计算器，用特定标签包住要算的式子），信息足够时用答案标签给出最终答案。模型输出一个工具调用，真的去执行，把结果给模型，再提示它"这是题目，这是之前的思考和工具调用结果，继续用工具，或者给出最终答案"，迭代进行。

实验和发现

用 Gemma 2 27B 生成多步合成数据，题目来自 HotpotQA 和 GSM8K，约 5 万条轨迹，按过程过滤、结果过滤、两者都过滤和随机等方式处理。

  • 过滤方式：一开始有点反直觉，只做过程过滤（评委多数认为各步合理，但不看最终答案对不对）的数据，比只要结果正确、或过程和结果都正确的数据训练效果更好。原因可能是，如果只用模型本来就答对的轨迹，就帮不了它解决原来解不出的题；过程合理但没答对的轨迹，能教它用不同方式思考。
  • 泛化：只在 GSM8K（数学，用计算器）上训练，在 HotpotQA 上准确率从约 65% 提高到约 75%；直接在 HotpotQA 上用搜索工具训练，是从约 65% 到约 73%。反过来也成立：在 HotpotQA 上用搜索训练，在 GSM8K 上用 Python 也表现很好。所以模型学到的不只是用某个工具，而是怎样分步思考、怎样调用工具。
  • 数据规模：在 HotpotQA 上用搜索训练，训练样本从 100 增加到 1 万条，在完全不同的数学任务 GSM8K 上的表现也随之提高。她说这是这篇论文最重要的一张图：在容易造数据的环境里合成数据，教模型多步思考和用工具，这种行为能泛化到全新的工具和领域，扩大规模可能是很有力的方法。
  • 解释：对比强化学习前后每一步的平均过程奖励，模型每一步的过程正确性在分布内（HotpotQA）和分布外（GSM8K）都提高了。
  • 和监督微调比：同样的数据做监督微调，多步强化学习明显更好。监督微调需要过程和结果都正确的数据才最好，只用过程过滤的数据效果更差，这说得通：监督微调是模仿学习，照搬轨迹，结果错的轨迹会拖累表现；强化学习则给模型在已有步骤基础上采取新行动的机会，并按这个新行动给奖励，所以能跳出来。
