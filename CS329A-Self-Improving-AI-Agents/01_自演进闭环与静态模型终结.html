第一讲：课程概览：从大语言模型到 Agent

缩放规律和涌现能力，ChatGPT 背后的指令微调和 RLHF，推理时扩展（反复采样），推理模型，Agent 和 Agent 工作流是什么，以及这门课怎样安排

主讲：Aakanksha Chowdhery（Stanford 兼职教授，Reflection AI）、Azalia Mirhoseini（Stanford 计算机系助理教授）
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、缩放规律

这是两位老师第二次开这门课。两人在 Google Brain 认识，Aakanksha 现在是 Stanford 兼职教授，同时在创业公司 Reflection AI 做研究；Azalia 是计算机系助理教授，在 Google DeepMind 参与过 Gemini，也在 Anthropic 参与过 Claude。课上以硕士生居多。课程网站是 cs329a.stanford.edu。

Aakanksha 先回顾大语言模型的发展。GPT-3 出来后最令人震惊的一点是：模型参数越多，效果越好。BERT、T5 不错，但参数一加，表现好得多。这引出了大语言模型的缩放规律：横轴是投入的算力，纵轴是测试损失，算力越多损失越低；把横轴换成数据集大小，或者换成参数量（Transformer 的层数等），也是同样的规律。这是 GPT-3 以及后来的 ChatGPT、PaLM、Gemini 的基础，一直到大约去年才开始出现饱和的迹象。

从 2018 到 2024 年，模型规模几乎一直在增长：BERT 3.4 亿参数，GPT-2 15 亿，GPT-3 1750 亿，PaLM 5400 亿，GPT-4 估计有上万亿。"大"语言模型的"大"就是这个意思。模型变大带来三件事：

  • 在自然语言、推理等各种基准上持续变好。
  • 学会了少样本学习。以前要针对某个领域微调模型，现在只要在提示里给几个例子，模型就能照着做。比如任务是"把英语翻译成法语"，直接让它翻译 cheese，没在这个任务上专门训练也能答对，叫零样本学习；再附上几个翻译例子，叫少样本学习。这让做原型变得极其容易。
  • 出现涌现能力：有些能力只在大模型上才出现，比如推理。

思维链

Azalia 说，模型变大后不仅损失按缩放规律可预测地下降，还会出现以前没有、也无法提前预测的新行为，其中最重要的是思维链。普通的提示是给一道数学题和它的答案作为例子，再问一道类似的题；思维链则在例子里写出推理过程。比如："Roger 有 5 个网球，又买了 2 罐，每罐 3 个，现在一共有几个？"不只说"11"，而是写"Roger 一开始有 5 个，2 罐每罐 3 个是 6 个，5 加 6 等于 11"。模型熟悉了得出答案的过程，就能用它解新题。这道题现在任何 10 亿参数的模型都会做，但思维链这个性质至今仍然成立，对推理模型、"思考"模型以及过去一年的很多进展都非常重要。

这个性质也随规模出现。LaMDA、GPT、PaLM 三个模型在一个数学数据集上的结果显示：小模型（比如 80 亿参数左右）用不上思维链，给了也没用；模型变大后才能利用上下文里给出的推理过程，把题解得更好。还有些任务，比如模运算、拼字还原，小模型做不了，到某个规模突然就会了。所以前沿实验室仍然想继续推高缩放规律，既为了自然的进步，也为了看到更多这类涌现行为。

二、ChatGPT 多做了什么：指令微调和 RLHF

ChatGPT 于 2022 年 11 月发布，5 天就有了 100 万用户，比很多著名软件和服务都快。它能比 GPT-3 这些模型跳出一大步，除了扩大规模，还有两项关键创新：指令微调和基于人类反馈的强化学习（RLHF）。

整个流程是这样的。预训练是起点，也是最简单的一步：让模型在各种文本数据上预测下一个 token。预训练后的模型见过互联网和书里的一切，统计上了解世界，但并不真正懂得是非对错，也不会遵循指令。下一步是对齐，让模型符合人的目标、偏好和价值观，这个问题至今没有完全解决。比如在基础模型上用精心收集的高质量数据，针对"是否合理""是否安全"做微调，模型在这些指标上就会明显变好。

  1. 用高质量数据继续做下一个 token 预测的微调，方法和预训练一样，但数据质量高得多，比如书籍、创意写作，公司会花几百万甚至上亿美元购买这类数据。
  2. 指令微调：用"指令—问题—答案"形式的数据训练模型遵循指令，比如"请回答：氮的沸点是多少？"再给出答案；也可以是思维链微调，示范怎样一步步得到答案。过去两年这类数据通常是人工数据、模板和合成数据的组合，数据的质量和覆盖面对模型质量影响很大。做完这一步，模型就更像今天的模型了：能来回对话，知道怎样理解问题、怎样一步步得到答案。
  3. RLHF：不再只用"提示—标签"做监督学习，而是用人的偏好训练一个奖励模型。公司花很多钱请人（有时是专家）对模型生成的回答打分，判断哪个对哪个不对，据此训练奖励模型；再用奖励模型代替人，引导模型的参数，让它生成奖励模型认为好的回答。奖励可以有多种：正确性、有用性、具体性、无害性等，按重视程度给不同权重。

预训练、高质量数据微调、指令微调、RLHF，这几步是 ChatGPT 区别于 GPT-3 等早期大模型的核心。

三、推理时扩展

直到大约一年半前，主要的手段还是预训练和微调；之后人们发现，推理阶段也是让模型更强的前沿，这打开了很多新的研究方向。

Azalia 介绍了她实验室去年夏天的工作"Large Language Monkeys"，名字来自无限猴子定理：让一只猴子在打字机上一直打下去，总有一天会打出莎士比亚全集。他们让大模型当这只猴子：对同一道题反复让模型解很多次（可以看作并行采样），再假设有一个验证器或选择机制挑出正确的那个作为最终输出。比如写代码的题，验证器可以是单元测试，跑一遍看哪个生成的代码通过了所有测试。这样做之所以可行，是因为模型的输出不是确定的，可以用温度参数控制输出的多样性。

结果：在数学和编程基准上，把每道题的采样次数从 1 增加到 10000，看"覆盖率"，也就是至少有一个样本答对的题目比例。只采样一次时，Llama 3 8B 等小模型比 GPT-4o 差；采样次数增加后，它们在所有任务上都超过了 GPT-4o 采样一次的结果。这说明模型知道的东西比问一次得到的多得多。这叫推理时扩展，因为没有动模型参数，只是在推理时用不同方式产生生成结果，用来得到更好的答案、解更难的题。有些题一万个解里只有三四个是对的，可见扩展推理对发掘模型能力有多重要。

学生问了几个问题。为什么不直接遍历所有可能的答案？Azalia 说可能答案的空间大得多，随机搜索或树搜索根本碰不到，相比之下一万次采样已经很省了，而有些题（比如 MiniF2F 里接近 IMO 难度的题）一个 70 亿、80 亿参数的小模型都能解出来。延迟呢？并行采样可以同时跑，延迟问题不大，但算力成本有取舍，后面会讲。没有验证器怎么办？有验证器要容易得多，没有的话有一整套研究在训练"大模型当评委"、大模型奖励函数、带工具的大模型等，后面有专门一讲。温度能不能一直调高？不能，太高就会输出乱码，大约超过 1.2 效果就不好了，有其他技巧可以增加答案的多样性。

四、推理模型

DeepSeek 的模型（老师们说是 2024 年 12 月）、OpenAI 的 o1 系列、Gemini 的思考模型，核心创新是把微调和推理时扩展结合起来：有了推理时扩展，就有了一台生成大量合成数据的引擎。比如答案已知的数学题，可以让模型生成很多条通往正确答案的解法；编程题也可以在推理时生成大量高质量数据。这些数据再拿来微调模型，让它变得更好。Azalia 说这一点没有上限，模型能通过推理时扩展变得多好、再把它带回训练，就是这门课最关心的"自我改进"。

Large Language Monkeys 展示的是覆盖率随采样数呈对数线性增长（前提是有验证器）。OpenAI 去年 9 月发布 o1 时，展示的是 pass@1（只回答一次的正确率）在很难的 AIME 数学题上，随推理时算力（对数刻度）呈对数线性提升。以前这种规律只在训练中出现，现在在不改变参数量的情况下，推理时也出现了。

动机和人一样：难题需要想得更久、考虑更多策略。思考模型会经历几个步骤：分析问题；把任务拆成更容易处理的子任务；尝试某个做法，看反馈（比如跑代码测试、用计算器、或自己评判答案），再调整；自我纠正；行不通就回退，换一种做法。这些能力有一部分可能来自人工整理的训练数据，但很大一部分是模型在微调和基于合成数据的强化学习过程中自己获得的。

她举了 o1 的例子：让它写一个 bash 脚本，输入一个矩阵，输出它的转置。模型像人一样先想重要的部分："用户要一个 bash 脚本，先弄清输入输出格式"；然后拆解任务，先解析输入，把矩阵存成数组的数组；中途常常会说"等等，这里可能不对，需要修正"。和过去的思维链不同的是，这条思维链是模型自己生成的。和 GPT-4o 比，o1 这类推理模型在数学计算、数据分析、编程上更好，但在个人写作、文字编辑上不一定更好。

学生问，提升是来自把推理过程写出来，还是来自"要求模型一步步想"本身？Azalia 说，训练数据让模型成了一个通用的思考者，拆解问题、回退、分析这些技能是在思考优化过程中学到的，现在能泛化到别的问题上。Aakanksha 补充：刚预训练完的基础模型也能做一些推理，但会生成各种推理链，不知道哪条是对的；训练和推理时扩展做的很多事，就是让模型学会哪条是对的，所以推理模型提升的是 pass@1，而反复采样提升的是 pass@k（覆盖率）。

推理和最终答案会用不同的模型吗？Aakanksha 说推理能力一般随模型规模上升，要用也是用大模型生成推理轨迹，再让小模型总结答案。Azalia 补充，至少目前，模型更喜欢自己生成的推理轨迹，哪怕别人的轨迹来自更好的模型。推理模型是怎样学会推理的？没有公开工作完整讲清楚，两者都有：指令微调数据里的思维链示范了一些思考方式，也可能有模板，但模型的泛化远超训练数据和指令；课上会讲结果奖励模型和过程奖励模型怎样提供反馈。采样次数能否随题目难度变化？她们说据她们所知还没有公开工作专门做这个，有后续工作用奖励模型来引导采样，如果奖励模型对难度有感知，就可以对没解出的题多采样，这是个有意思的方向。

五、从大模型到 Agent

Aakanksha 说，聊天机器人和推理模型基本还是单轮的，不会替你完成任务。最近几个月让人意外的是，Claude Code、Deep Research 这类 Agent 让人们真正完成了现实中的工作流程，端到端地完成你交给它的任务。比如想在 Stanford 附近租一年房子，模型能浏览很多网站、做分析、总结各个选项的优缺点，这以前做不到；用 Claude Code 或 OpenAI 的编程 Agent Codex，只用英文下指令就能改文件、找测试用例，已经成了软件工程师日常的生产力工具。

Agent 和聊天机器人的区别在于：给它一个目标，它会规划步骤，与环境交互，根据反馈修正，直到完成目标，或者回来说做不到。有目标、朝目标采取行动、获取反馈、决定何时停止，这些让 Agent 不同于聊天。它可能需要调用模型之外的工具，同时要一直记着自己在做的任务，所以需要某种记忆。

现在 Deep Research 这类较简单的任务已经能端到端完成，但大多数场景仍是比较固定的"Agent 工作流"：比如一个模型给出解答，另一个模型评判、决定是否接受；或者像 Deep Research 那样对多个输入调用模型再汇总。对开放性问题，由人按自己的做法把流程图搭好，再用大模型评估反馈，比让 Agent 完全自由地与环境交互更容易。在编程和研究这两个领域，已经开始看到后者的"生命迹象"。

工作流里常见的组成部分：

  • 大模型调用：给指令或输入，让模型输出。
  • 验证器：能检验输出对不对，比如给代码跑单元测试。数学、代码这些规则明确、可验证的领域，验证是给模型反馈、让它纠正的好办法，后面有专门一讲。
  • 评论者或评委：用大模型当评委。
  • 工具调用：比如 Deep Research 要搜索网页，或者查询天气。

编排方式有：提示链（像推理模型那样把任务拆成子任务，串起来完成）；路由（复杂的任务走更复杂的调用流程，简单的走简单流程）；并行（比如 Deep Research 同时让多个调用研究不同关键词，再汇总；或者拆成相互独立的子任务再合并）；编排者（一个中心模型做规划，像 Claude Code 会先列计划再按计划调用）；评估者或评委（不从用户或单元测试获得反馈，而是用大模型当评委）；以及验证器。这些工作流要求模型更擅长规划、多步推理和自我改进，犯错时能自己纠正，单靠现有推理模型还做不到，这些是后面几讲的内容。

以编程 Agent 为例：Agent 现在基本通过终端和计算机交互，你给它一条要实现某个功能的指令，它会浏览代码仓库、搜索文件、查看和编辑代码，在终端执行命令，根据输出决定接着改哪个文件、看哪个文件。这个循环去年还不太可靠，现在在编程 Agent 上开始可靠了。学生问是什么变了，Aakanksha 说范式基本一样，主要是模型更强、强化学习更好，可验证奖励的强化学习和训练时扩展都奏效了；模型变好后自我改进循环就转起来了，因为可以生成任务，而且任务越来越可靠。比如她们去年的工作 CodeMonkeys：如果能为生成的代码再生成单元测试，并检验这些测试是否让结果更好，就是很好的验证方式。

Aakanksha 说这就是"生成—验证差距"：模型很容易生成大量内容，可能是胡话也可能有用，但到底有没有用，需要反馈；创意写作能有多少反馈？人的反馈会成为瓶颈。能获得好反馈的领域，模型才能持续改进，而稳健的验证很难，Azalia 后面会讲她实验室组合多个验证器的工作。

有学生问：预训练里已经有了这些逻辑能力，为什么强化学习之后跳升这么大？Aakanksha 说这仍是活跃的研究领域，是强化学习带来提升，还是预训练的多样数据本身，目前没有共识，两者都有帮助。按"预训练后反复采样至少能采到一个对的"这种看法，反馈只应提高 pass@1、不应提升模型本身，为什么跳升这么大还没被完全理解；也有一些迹象表明持续做强化学习能持续提升模型。

她还强调，即使给了 Agent 目标，它也要先澄清用户意图，因为用户往往没把问题说清楚；然后搜索相关文件，采取行动，并且需要某种验证，比如通过测试，甚至自己生成需要通过的测试。关键问题是：交给它一个任务，你怎么知道它会完成你要的？

Agent 已经在哪些地方有用

  • 重复性的软件工作：代码迁移、版本升级、重构代码库，数据工程里抽取和清洗数据、数据仓库迁移，以及写单元测试，交给编程 Agent 容易得多。
  • 客服：这是最吃力不讨好的工作之一。可以做实时转写、知识辅助（客服不必什么都知道，可以问大模型、调出相关文章，比只靠索引搜索好）、智能回复、通话总结，也开始出现端到端的方案。
  • 研究报告：过去要做文献综述、逐篇总结、再综合，现在可以交给大模型，还能读比人更多的文章。比如给它"2022 年冬奥会开幕式"，它会找参考资料、列提纲、判断哪些相关、总结每篇的相关内容，再合成一篇完整的文章，作业里会让大家试。
  • AI 科学家：在想点子、迭代实验、撰写论文等阶段协助科学家（例子来自 The AI Scientist 论文）。模型虽然会产生幻觉，但它读过整个网络，能想出很多领域内研究者未必想到的点子，是很好的头脑风暴工具。

有学生问推理和思维链是训练时特意加进去的，还是偶然发现的提示技巧，有没有别的涌现行为？Aakanksha 说思维链不是刻意设计的，是给模型难题时发现有推理链效果更好，GSM8K 上的工作最早显示了这一点，到 PaLM 这样的大模型时发现影响很大（PaLM 甚至能解释笑话），之后才有了推理模型；模型读过整个网络，见过很多有条理的内容。Azalia 补充：思维链最初是涌现的，但推理模型是专门训练来推理的，会学会什么时候需要多想、什么时候不需要。自我纠正、回退这些，可以说是涌现，也可以说模型见过这类行为，又在微调中被强化了，很难说清。

六、课程安排

课程的主题框架和上次一样，会请前沿实验室的嘉宾来讲后训练的演变、多模态 Agent、机器人等。有三次作业（比上次多一次），占成绩的 50%；课程项目占 50%，2 到 4 人一组（也可以一人），会提供 API 额度。项目要有研究性质，有假设、有要回答的问题、有预期的改进或要分析的性质，不能只是综述，或者搭个应用演示一下。可以做的例如：新的评估数据集或基准；研究现有 Agent 系统的可靠性；拿一个现有基准用自己的想法去"爬坡"；或者针对课上读的论文，改进它们、质疑它们的某个设计决定并做评估。项目有几个节点：10 月初交提案，两周后中期报告要有实际进展，最后交报告（权重很大）并在 12 月 12 日参加海报展示，会有业界的人来。上一次开课时有学生的项目发表成了论文。课程录像之后会放到 YouTube 上。
