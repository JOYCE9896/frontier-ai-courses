第九讲：未来的研究方向

课程回顾；自我改进循环的三个瓶颈及对应工作（多 Agent 微调保持推理多样性、DeepSeekMath-V2 的元验证、Absolute Zero 让模型自己出题）；"每瓦智能"与本地推理；以及测试时扩展、合成数据飞轮和持续学习中的开放问题

主讲：Aakanksha Chowdhery、Azalia Mirhoseini
资料来源：课堂录像（Stanford Online 公开，本文依据录像字幕整理）

一、这学期讲了什么

Aakanksha 先回顾：课程从大模型概览讲起，然后是过去一年的测试时扩展和训练时扩展，核心循环由验证器和验证反馈驱动，得到奖励，再用强化学习甚至搜索算法让模型在数学、编程上爬坡；之后有一讲讲开放式探索（不只靠奖励驱动，而是在定义好的探索空间里让模型自由探索，讲了 AlphaEvolve 等）；再到用工具搭建端到端的 Agent 工作流；多步任务需要查知识库，于是讲检索和记忆；走向现实工作流需要更好的规划和多步推理，以及怎样评估下一代模型；还有几位嘉宾讲了后训练、多模态 Agent、机器人和推理等。Azalia 补充，有一位嘉宾讲了符号方法，属于工具使用的范畴，也能用来生成合成数据。（这些讲次中，开放式探索和嘉宾讲座没有公开录像，本站的九讲对应 Stanford Online 公开的九段录像。）

课程名是"自我改进的 Agent"，重点在 Agent：有目标，与环境交互，收集反馈，用反馈修正步骤，能指导自己的过程、使用工具、完成目标。目前大模型单靠自己还不足以完成完整的目标，所以常常由人把大模型和工具编排成工作流；但在编程 Agent 等场景，已经看到工作流能由 Agent 自己推动。搭建这些工作流需要编排大模型、验证器（提供奖励，可能用大模型当评委）、工具调用、搜索算法（并行调用）；因为要朝目标推进，需要规划、多步推理、方向错了能纠正，并持续提升能力，这就是自我改进。

这一讲挑了一些论文的关键思想，覆盖两个方向：自我改进，以及智能的效率。自我改进方面，前面讲的推理时扩展和训练时扩展仍局限在数学、编程这样的窄领域，有三个问题：怎样让推理链足够多样，持续推动循环并跨领域泛化；怎样做稳健的验证，甚至"元验证"；训练用的提示目前是人静态挑选的，怎样突破数据瓶颈，让循环自己挑数据。

二、多 Agent 微调：保持推理链的多样性

预训练是对互联网规模数据的压缩，指令微调需要真实的人类数据（人的偏好）。替代办法是用大模型生成的合成数据迭代微调：生成可能的解，过滤掉错的（拒绝采样），只在好的上微调，STaR 等变体还会加入推理链。但如果只用一个模型生成数据，解会很相似，几轮到几十轮后提升就停了，根本问题是缺乏多样性：预训练数据由人类长期产生，很多样；单个模型对一组提示的回答即使温度很高也不够多样。直觉上的办法是用多个各有专长的 Agent。

论文训练了生成 Agent 和评论 Agent：生成 Agent 先各自给出初始答案；之后多轮"辩论"，每个生成 Agent 会参考其他 Agent 回答的汇总（可以用模型总结，也可以直接拼接）再生成新回答；评论 Agent 评论更新后的答案并选出最好的。和以前学过的自我批评不同，这里批评的是多个 Agent 的回答，生成阶段就有了多样性，相当于"免费"得到了多数投票。生成模型从同一个基础模型微调而来，每轮把与多数投票一致的输出筛出来，对这些"提示—回答"对做监督微调；评论模型在混合的轨迹上微调，包括一开始就对的，以及在辩论中被纠正过来的，让它学会区分对错。她说最简单的"穷人版"做法，就是用不同的模型、不同的提示来获得不同的回答，实践中也常这样做。

结果（数学数据集，三个开源模型，因为要微调所以只能用开源模型）：横轴是微调轮数，用多 Agent 微调，负对数似然（表现的代理指标）能持续下降，Llama 3 反应更明显；更有意思的是嵌入差异度（越高越多样）一直保持较高。单 Agent 微调的准确率会塌掉或不再提升，多 Agent 能在多轮微调中持续改进，在 GSM8K 这样的相邻领域也更好（论文较早，数字不算高）。也就是说，要实现自我改进，提供给模型的推理链必须足够多样，多模型或多 Agent 是一种办法。

三、DeepSeekMath-V2：元验证

验证很难。通常只看结果：数学题或定理证明的最终结果是否与标准答案一致，这就是结果奖励模型。验证那一讲问过：推理链错了会不会把模型带偏？过程奖励模型又很难建。现有的强化学习假设最终答案和标准答案一致就给奖励，这让 AIME 等数学基准趋于饱和，但答案对不代表推理对；定理证明需要严格的逐步推导，最终结果给不了这种信号。大模型主要在定量推理上训练，生成的证明可能在数学上无效，让它验证，它会说错误的证明是对的，所以"大模型当评委"在这里不管用；而专家能看出某一步并不从上一步推出，或者推理有缺口。

DeepSeekMath-V2 最近发布，表明至少在定理证明上，可以搭建自动化的自我验证循环：

  • 先让人在没有参考解答的情况下指出证明中的问题，据此训练大模型找出证明的问题。
  • 验证器（大模型当评委）找出问题，按 0、0.5、1 给证明打分。
  • 加一个元验证器，审查验证器的分析：它指出的问题是否真的存在？分数是否与这些问题相符？因为验证器可能在推理链有误时给出正确分数，或者编造错误。元验证的评估质量由专家标注。
  • 验证器改进生成器，生成器生成更难的证明，再改进验证器，形成循环。一旦用人工数据为"找出错误证明"打好基础，后续标注就可以自动化。

结果：基于 DeepSeek-V3 的基础模型，强化学习循环基于 GRPO，在 IMO 和 CNML 的题目上，仅靠生成—验证的迭代优化，8 轮中 pass@1 的证明得分持续上升；从 32 个证明中选最好的（best@32），在 2024 年 IMO 预选题上的证明得分接近 42%。她说一位嘉宾讲过 Gemini 版本的类似工作，这是最近发布的开源版本。启示：最好的证明会得到更高的验证分数，生成器学会区分高质量和有缺陷的证明，自我验证让改进循环更好。推广到其他领域需要：基于大模型的验证器能在没有参考解答时找出问题；再加一层元验证，减少验证器"幻觉"出来的问题；给生成器额外的激励，通过认真推理提高质量。这仍受限于验证相对容易的领域。

四、Absolute Zero：让模型自己出题

第三个问题是在什么数据、什么提示上训练。现在的训练栈要么用人工整理的推理轨迹做监督学习，要么在可验证奖励的强化学习中由专家整理问答对：数学要数学专家，IMO 题要 IMO 专家，编程要优秀的程序员。模型越来越强，找到足够多的专家和任务会成为限制。这篇论文走到另一个极端：同一个模型既出题又解题，不需要外部数据和人工提示。她说这个想法很新，还没被广泛采用，但很有希望，在某些领域可行。

它以编程为领域，构造三类任务：

  • 演绎：生成程序和输入，环境执行得到输出。
  • 溯因：同样生成程序和输入，由环境计算输出（课上说与演绎类似，具体在要求求解的部分不同）。
  • 归纳：从已有程序中采样一个，为它生成新的输入，加一段描述函数的自然语言，环境执行。

出题者会以过去生成的例子为条件，明确提示要保持多样。出题的奖励针对难度：把题交给解题者，成功率为 0 则奖励为 0，非零时奖励为 1 减去平均成功率，太简单（总能解）和不可能（总解不出）的题都不要，选中等难度、解题者有时成功有时失败的题，这样模型才能学到东西；模型变强后，出题者会学着出更难的题。出的题还要验证：在编程中可以执行检查程序完整性和有无错误、做安全检查、多次运行同样输入看输出是否确定，防止出题者"钻空子"出垃圾题。每个"输入、输出、程序"三元组连同成功和失败次数存入一个缓冲区，出题者从中采样参考，形成随时间演化的课程学习。解题阶段验证答案、给准确率奖励，出题和解题一起更新模型。

结果：在编程基准上，出题端完全不用人工整理的数据，就达到了最先进的水平，超过用几万个专家示例训练的模型。涌现的现象：复杂度指标随时间上升；循环设置正确时，程序和答案的多样性提高；出题者生成的题越来越难。出题者和解题者有点像博弈中的对手，但总体上互相促进。只在自己出的编程题上爬坡，在编程和数学基准上都表现很好，数学上的提升有些出人意料；越大的模型收益越大。

Azalia 补充，这和 SWiRL 的发现一致：模型自己生成训练数据，不仅能提升生成数据所在的任务，还能迁移，SWiRL 里在带检索的多跳问答上生成更多合成数据、做强化学习，模型在调用 Python 解数学题上也变好了，反之亦然；而且更大的模型更能吸收这种数据飞轮、更能泛化。她认为一个有意思的研究方向是：只在能自动验证、能生成合成数据的多样任务上做自我改进，能把前沿推多远，能否泛化到没有自动验证的领域，从而在不可验证的领域减少甚至不需要标注数据。当然这需要大量算力。

Aakanksha 总结这三点：要实现真正的泛化和推理，推理链需要多样性，怎样做到仍是开放问题；需要更好的验证，越能摆脱只靠人类专家验证的瓶颈越好，建奖励模型很难；数据选择本身，人能整理的提示有限，突破这一点对下一代自我改进模型很重要。

学生问哪些 AI 应用不属于可验证的问题。Azalia 说一类是验证很慢的：科学发现、芯片设计中要跑几天的仿真才能得到一个奖励信号、要去湿实验室做的化学实验。强化学习微调要几百上千步迭代，测试时扩展也要求验证几乎即时，最多等几分钟、一小时，不能等几天或等人来给奖励。Aakanksha 补充，真正不可验证的还有创造力和主观的指标，比如创意写作，可以建模，但模型稍有偏差，Agent 就可能钻奖励的空子。怎样处理芯片设计、生物发现这类难验证的领域？Azalia 说一种办法是离线收集大量仿真或实验数据，训练一个能预测结果质量的奖励模型，在强化学习循环里代替真实仿真，但它的泛化取决于数据量，可能不准。Aakanksha 举了 KernelBench：能编译执行、看代码对不对、拿到一些指标，但有个课程项目在读性能剖析数据，问题变复杂后，把多个内核串起来、找出没优化的部分去改就难多了，通常做法是把问题拆成模型现在能做的子问题，再配上参考解答作为知识库。

五、每瓦智能与本地推理

Azalia 讲她们最近和 Chris Ré 教授、John Hennessy 教授及一大批合作者的工作：看模型和硬件加速器两方面的趋势，思考未来 AI 推理的负载会是什么样，需要多大的模型、什么样的加速器。

现在是"大型机时代"：ChatGPT、Gemini 这些大模型都在云上运行，有的是闭源的，开源的大模型也多在云上跑。算力需求在爆炸：课上提到 Google Cloud 的推理算力在 20 个月左右增长了约 1200 倍，NVIDIA 每年约 10 倍增长，满足这些需求需要约 250 吉瓦的数据中心，需要越来越多的能源。Google 处理的 token 数，从去年 2 月的约 160 万亿增长到今年 10 月的约 1.3 千万亿，是历史上增长最快的算力需求之一。

但从一个超大规模的 ChatGPT 用户数据集看，约 77% 的请求是实用指导、查询信息、写作这类任务，很多并不需要最好的前沿模型，较小的本地模型就能答好。用户会随着聊天机器人变好而提出更复杂的问题，但绝大多数查询仍偏简单。另一方面，本地推理加速器在进步：自 2012 年以来，本地加速器的 GPU 显存提高了约 126 倍，现在的 MacBook 有约 100 GB 内存，用 INT8 等量化版本，一些最大的模型也能在本地运行。

所以她们要回答：本地推理能在多大程度上重新分配推理需求？为此定义了"每瓦智能"（intelligence per watt）：

$$\text{IPW} = \frac{\text{平均任务准确率}}{\text{平均功耗}}$$

能力方面看模型能解决多大比例的单轮和推理类查询，这里"本地模型"指激活参数不超过 200 亿的模型；效率方面看在本地硬件上每瓦能得到多少有用的计算。研究覆盖 20 多个本地模型（Qwen、GPT-OSS、Llama 3 等）、企业级和本地加速器，100 万条来自 ChatGPT 的查询，以及 Natural Reasoning、MMLU-Pro、SuperGPQA 等推理基准，指标包括准确率、能耗、延迟、算力等，所有数据都开源。

发现：

  • 本地模型已经很好，而且进步很快：自 2023 年以来，能解决的聊天查询比例提高了 3.1 倍，只用了两年，现在能解决上述查询中约 88.7%。
  • 本地加速器的效率落后于企业级芯片，比如 Apple M4 Max 的每瓦智能比 B200 低约 1.5 倍。B200 为语言模型负载做了极致优化，M4 要兼顾很多别的负载，而且设计芯片时并没有预期大模型会在本地运行，芯片设计者的重点都在云端。
  • 过去两年每瓦智能提高了约 5.3 倍，其中约 3.1 倍来自更好的模型，约 1.7 倍来自更高效的硬件。

这些趋势说明，越来越多的流量将来可以由笔记本、手机等边缘设备上的模型处理。

六、开放问题

  • 测试时扩展和合成数据飞轮的基本原理：现在是靠强化学习、收集数据、再微调，但为什么会有这种性质？反复问模型同一个问题、正确答案冒出来时发生了什么？怎样把成功的轨迹最好地蒸馏回模型？
  • 持续学习：人解决问题、学习新东西时，大脑在持续发展，技能越来越好；模型则是离线收集一段时间的经验，过一阵再微调，不是边做边学。怎样把成功和失败的经验以更自然的方式带回模型，不同于现在这种异步的"生成数据再微调"？
  • 高吞吐、低延迟的测试时扩展基础设施：反复采样、对之前的生成来回修改、工具调用，和主流的单轮聊天很不一样，系统和推理优化有很多机会，她实验室做过 Hydragen、Tokamak 等工作，这些方法越来越主流，就越需要专门优化底层系统。
  • 预训练有很多有意思的工作（Aakanksha 是预训练专家），这门课主要讲后训练和测试时扩展；连接微调、在线学习和测试时扩展的合成数据飞轮与持续学习，有很多未解决的挑战。
  • 从全部上云到更多本地运行的转变，需要能在本地和云端模型之间按需求和复杂度平滑分流的混合推理引擎；需要面向本地加速器的高能效模型架构和内核，这方面关注远少于云端；能源会是最宝贵的资源，每瓦智能这类指标、对能耗和功率的更好测量和优化会越来越重要，现在很少有人把它作为优化目标。

七、问答

学生问，从成功和失败中持续学习，更可能体现在长期记忆系统等围绕模型的架构上，还是模型本身？Aakanksha 说持续学习和长期记忆的类比在人身上成立，但在此之前，在多步推理中从成败中学习、把技能保留下来、更新到权重或部分权重中，也就是学会新技能、学会怎样学习，这是我们现在没有的能力；比如机器人能否看视频学会怎样做一件事，而不是靠大量任务示范。Azalia 补充，上下文学习是实现持续学习的一种方式：如果有无限长、模型能完美访问并从中学习的上下文，把正面和负面经验都放进去，也许就是一种持续学习，但现实中上下文到一百万或几百万 token 时，模型对上下文的推理能力会下降；课上讲过的 Cartridges 是另一种方式，不改动模型权重，而是把知识放进激活值，也就是 KV 缓存。所以持续学习不一定要微调模型，也可以大幅增加有效上下文长度。学生追问实践中哪个更容易，不断更新权重还是更新记忆库？Aakanksha 说取决于应用：如果是知识库，更新数据库、让模型学会去查，显然更容易；但如果要教模型在新领域推理，旁挂的记忆系统往往做不到，更新权重效果更好；机器人的跨形态泛化也一样，光靠记忆系统做不到，那是技能迁移问题。

有学生说，Absolute Zero 用的后训练数据像是让 Agent 自己创造环境，有没有让 Agent 自己创建环境的论文？Aakanksha 说在窄领域智能的时代，可以为游戏写仿真当作玩具任务的环境；现在环境之所以重要，是因为它们是现实任务的代理。关键不是有没有让 Agent 创建环境的论文，而是要代表哪些任务：如果容易模拟，用 Agent 还是用软件来创建都很直接，问题是它能否合理代表模型怎样与现实世界交互并得到反馈；游戏的探索空间有限，比较容易写成代码做仿真。

最后两位老师感谢大家。Aakanksha 说这是一个快速演进的领域，现在教的东西下次开课时可能已经成为历史，但基本技术会长期有用，因为新东西仍建立在它们之上。Azalia 说很多话题很新，她们准备课件时也在学习，希望大家学到新技能，在研究、工作中做出更多好工作。
