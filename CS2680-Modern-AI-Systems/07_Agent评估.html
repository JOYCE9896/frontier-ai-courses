第七讲：Agent 设计（四）：Agent 评估

组件级和端到端两种评估，基准的演变史，pass@k 与 pass^k 等指标，GAIA、BFCL、WebArena、OSWorld、SWE-bench、τ-bench、Terminal-Bench、TheAgentCompany 八个代表性基准各测什么、怎样打分，以及数据泄漏、单轮指令、非确定性、副作用和基准饱和这些难题

主讲：Juncheng Yang
资料来源：课件（2026 年 9 月 30 日；课程不录像，本文依据课件整理），以及课程网站的参考笔记 Agent evaluation and benchmarks

一、开头：关于 AI 使用和会话日志

讲者先讲了作业 1 里观察到的情况。课程要求提交完整的 Claude Code 会话日志（在 macOS 和 Linux 上位于 ~/.claude/projects/），缺了会扣分。用 AI 本身不扣分，但有些部分应该是学生自己的工作，尤其是作业的书面总结，它是写给自己的反思。他统计了用 Claude 帮忙写总结的同学，做法从"润色自己写的"到"几乎原样贴 Claude 的输出"都有，有两份总结里甚至还留着 Claude Code 的 TODO。另外有三位同学试图删掉历史记录。课程把篡改会话日志视为违反学术诚信，讲者的原话大意是：AI 写的文字即使没有历史记录也很容易看出来，而把历史藏得天衣无缝比写作业还难。

二、两种评估方式

评估 Agent 可以看里面，也可以只看结果。

组件级评估拆开 Agent 看各部分：规划（任务分解得好不好）、工具使用（能不能发现、选对工具，参数填得对不对）、记忆（抽取、整合、检索）、出错后能不能恢复。第六讲的记忆基准就属于这一类。

端到端评估只看任务层面的三个数：成功率（任务做成了没有）、成本（每个任务花多少钱）、延迟（多久做完）。作业 3 就按这三个数排名。

三、基准是怎样一路演变过来的

把十年间的基准按时间排开，能看出评估目标在一步步变大：

  • 2018 年以前测语言建模和窄任务，如 Penn Treebank、WikiText、SQuAD 阅读理解。
  • 2018 到 2019 年测迁移学习和通用语言理解，如 GLUE、SuperGLUE、HellaSwag。
  • 2020 到 2022 年测基础模型的能力，如 MMLU（多学科知识）、GSM8K 和 MATH（数学）、HumanEval（写函数）。
  • 2023 到 2024 年开始测 Agent、工具使用、长上下文和多模态，如 Chatbot Arena、WebArena、GAIA、SWE-bench、OSWorld、τ-bench。
  • 2024 到 2025 年追求更难、更稳健、更新，如 MMLU-Pro、LiveCodeBench（持续加入新题，防止模型背过）、FrontierMath、Humanity's Last Exam。
  • 2025 到 2026 年范围更大、指令更不具体、更接近真实使用，如 GDPval、BrowseComp、Terminal-Bench、ARC-AGI-3。

换个角度看，"成功"的含义也变了：最早是给真实文本分配高概率；然后是答案和标准答案一致；再是人或模型评委更喜欢这个回答；再是代码能通过可执行的测试；到 Agent 时代，是环境最终达到了要求的状态。

四、指标

早期基准用的指标有：困惑度（模型在没见过的文本上平均负对数似然的指数，越低越好，大致表示模型每一步在多少个候选里犹豫）；准确率或 F1；偏好或胜率。

衡量能力时，Agent 评估常用两个看起来很像、意思相反的指标。pass@k：同一个任务跑 $k$ 次，至少一次成功就算过，它衡量的是"有没有能力做到"。pass^k（由 τ-bench 提出）：跑 $k$ 次，必须次次都成功，它衡量的是"能不能稳定做到"。如果单次成功率是 $p$，且各次独立，那么

$$\text{pass@}k = 1-(1-p)^k,\qquad \text{pass}^k = p^k$$

举个数：$p=0.8$、$k=4$ 时，pass@4 约为 0.998，pass^4 约为 0.41。同一个 Agent，按前者看几乎总能做成，按后者看一半以上的时候会出错。上线给用户用的 Agent 更该看后者。

成本方面，大家通常只算 LLM 的费用，容易忽略工具调用的成本，以及缓存未命中带来的额外开销。延迟方面，也不能只算 LLM 的时间，工具执行、等待和重试都算在内。

基准评估的循环

Agent 基准的评测程序大致都是同一个结构：对每个任务，先把环境重置到任务的初始状态；然后在没有终止、预算没用完的前提下循环：观察环境，Agent 根据任务说明、观察、历史和可用工具决定一个动作，环境执行动作。结束后由任务评估器打分，它能看到的材料有三样：Agent 的最终答案、环境的最终状态、整条轨迹。不同基准的区别主要在于评估器看哪一样。

五、八个代表性基准

GAIA：能不能查到并给出正确答案

GAIA（Mialon 等，2023）有 466 道人写的问题，需要上网、读表格和 PDF、看图片、听音频、做计算，答案很短，是一个数字、一个字符串或一个列表。它不规定工具接口，每个 Agent 自带搜索、浏览器、Python、shell，所以测的是整个 Agent 系统，不只是 LLM。难度分三级：第 1 级不超过 5 步、最多一个工具；第 2 级 5 到 10 步、多个工具；第 3 级步数不限、工具很多。

例题：附件表格里有一串电影，找出同时满足两个条件的那部，查出导演，报出导演的出生地。Agent 可能搜索、打开网页、下载 PDF、提取表格、跑 Python，但评估器把这些过程全部丢掉，只比较最终答案（归一化格式后是否完全相同），得分是答对的比例。好处是评分干净；局限是它测不到会改变外部世界的动作，比如发邮件、订机票、改数据库、提交表单。

BFCL：工具接口用得对不对

Berkeley Function Calling Leaderboard（Patil 等，ICML 2025）专测函数调用。例子：用户说"订下周一从波士顿到芝加哥最便宜的航班"，可用工具有查航班、订航班（需要航班号和乘客编号）、查天气。正确做法是先查航班，挑最便宜的，再订。常见错误有两种：自己编一个乘客编号（应该问用户）；调用和任务无关的查天气。打分方式是检查调用的语法树或真正执行，多轮任务每一轮都检查状态和回复。第 4 版加入了网页搜索和记忆。课件提醒看分类得分，别只看总分。

WebArena：能不能完成一个网页工作流

WebArena（Zhou 等，ICLR 2024）在本地自建了购物网站、后台管理、Reddit 式论坛、GitLab、地图和维基百科，共 812 个任务。Agent 看到的是网页的无障碍树（浏览器为读屏软件生成的页面结构文本），动作是对元素编号点击或输入。例题：在 GitLab 里新建一个 issue，指派给某人，加上 documentation 标签。打分不看过程，而是检查最终状态：这个 issue 是否存在、负责人和标签是否正确；其他任务检查最终网址、页面内容、后端状态或文字答案。后来 ServiceNow 做了 WebArena-Verified，改成结构化输出，去掉了 LLM 评委，改为对 HTTP 记录做确定性检查。

OSWorld：能不能操作一台真电脑

OSWorld（Xie 等，NeurIPS 2024）给 Agent 一台完整的桌面虚拟机，369 个任务涉及浏览器、办公软件、文件和系统应用，有些要跨应用。Agent 看到的是屏幕截图，动作是鼠标和键盘。例题：在表格里加一列计算结果，排序，另存为 result.xlsx。打分检查最终状态：单元格、公式、文件位置，或者设置和应用配置。2026 年的 OSWorld 2.0 有 108 个长工作流，常常超过 1 小时、几百步，设了约 27 个检查点给部分分。

SWE-bench：能不能修好真实仓库里的 issue

SWE-bench（Jimenez 等，2024）取自真实 GitHub 项目的 issue。Agent 搜仓库、读实现和测试、跑测试、改文件、调试，最后交一个补丁。打分是把补丁应用到仓库上跑测试，通过就算解决。例题：某个库函数在传入空索引时错误地抛出异常，要改成返回空结果，同时不破坏原有行为。它有一系列变体：Verified（经人工核查的子集，OpenAI 2024）、Lite（300 题子集）、Multilingual（9 种语言）、Multimodal（issue 里带图）、Pro（更难，要改多个文件）。

τ-bench：能不能一边和用户对话一边守规矩地改数据

τ-bench（Yao 等，2024）有两个交互方：一个由 LLM 扮演的模拟顾客，一个受航空公司政策约束的 Agent，Agent 可以调 API 改航空公司数据库。政策比如"基础经济舱不能改签"。例题：顾客说"我想把明天的航班改到晚上那班"。Agent 应该先核实身份、查订单、搜航班、解释差价、得到确认，再调用改签接口。

打分时奖励是两项相乘：最终数据库和标注的目标状态一致才得 1；给用户的回复包含了必需的信息才得 1；两项都满足才算成功。只读调用可以随便做，但意外的写操作直接判失败。前面讲的 pass^k 就是这个基准提出的。现在的 τ³-bench 修正了一些题目，加了更多领域、知识检索和语音评测。

Terminal-Bench：能不能在 shell 里做完一件真实的事

Terminal-Bench（Merrill 等，2026）的任务不只是修仓库里的 bug，还包括系统管理和服务器配置、数据处理、模型训练、安全、科学工作流。每个任务打包成三样东西：一份任务说明、一个 Docker 容器、一套测试脚本。Agent 在容器里用 shell 工作，结束后测试检查系统的最终状态，轨迹本身不打分。2.0 版有 89 个任务，4.0 版删掉了已经饱和的题，剩 66 个，人写的参考解答不公开，超时上限 8 小时。一个代表性任务是：在一个正在运行的键值服务上切换到新协议，不能断开连接，延迟也要保持住。

它介于 SWE-bench 和 OSWorld 之间：SWE-bench 只在一个仓库里改文件，看代码和测试输出；OSWorld 用鼠标键盘操作任意桌面应用，看截图；Terminal-Bench 用 shell 命令配置、调试、修复、构建，看终端输出。它不需要预测鼠标坐标，所以能单独测长程推理和系统交互能力。

TheAgentCompany：模拟一家公司

TheAgentCompany（Xu 等，2024）搭了一家虚拟公司：GitLab 放代码，Plane 管工单，ownCloud 存文档，RocketChat 做团队聊天，同事由 LLM 模拟。175 个任务覆盖软件、项目管理、数据科学、人力和财务。一个完整的工作可能是：读工单，在聊天软件里问同事，查仓库，写代码，跑测试，更新工单，再回报结果。

它给部分分，每一步设检查点。得分公式是

$$S_{\text{partial}} = 0.5\cdot\frac{\text{已完成检查点}}{\text{总检查点}} + 0.5\cdot S_{\text{full}}$$

其中 $S_{\text{full}}$ 是整个任务全部完成时为 1、否则为 0。所以 8 个检查点完成 4 个得 0.25，完成 7 个得 0.44，全部完成得 1。这样设计是为了既奖励进度，又让"真正做完"占一半的分量。

基准Agent 在哪里工作打分看什么

BFCL函数和 API 接口调用、参数和由此产生的状态

六、评估 Agent 为什么难

数据泄漏不只发生在训练里

课件把泄漏分成四层。训练泄漏：题目或人写的修复已经在训练数据里。评测时泄漏：Agent 上网搜到了这道题后来的修复，照抄。环境泄漏：沙盒里能看到未来的提交或隐藏的测试。基准过拟合：提示和 Harness 是对着公开测试集反复调出来的。这里有个两难：Agent 评估需要真实的工具（比如联网搜索），可工具越真实，泄漏面越大，因为基准本身可能就搜得到。

更一般地说，今天的"Agent 表现"可以看作很多部件的函数：LLM、提示、Harness、工具、检索器、记忆、环境。每个部件都可能带进基准信息：基础模型预训练时见过题；微调时用了基准的解答当训练轨迹；少样本示例取自测试题；RAG 的语料库里索引了答案；记忆里存着之前做这套题的记录；网页搜索搜到了公开的解答；环境暴露了未来的 Git 提交；Harness 里写了针对基准的启发式规则；研究者反复看失败的测试题再去调系统。所以只说"模型没在测试集上训练过"，对 Agent 评估来说远远不够。

只有一轮用户指令

大多数基准给 Agent 一条完全说清楚的指令，提示进去，最终状态出来，中间没有用户。真实工作却是模糊的，会被修改，会被打断：约束没说全，做到一半被纠正，目标会变。只按单轮打分，等于奖励"自信地猜"，因为问一个澄清问题要花步数，却不加分。讲者提到，大家在作业 1 里用 Claude Code 的方式就是多轮的。他认为应该补测三种能力：目标不明确时会不会问；中途被纠正后会不会重新规划；约束能不能跨轮次带下去。

还有更多

  • 成本和延迟：只看成功率不够。同样做成了，一次跑 200 步花 40 美元，一次跑 12 步花 0.30 美元，显然不一样。
  • 非确定性：同一个 Agent、同一个任务，结果可能不同，只跑一次的分数是噪声而不是信号。
  • 安全和副作用：没有任何机制惩罚在通过任务的路上删了文件、发了邮件、花了钱。
  • 指标本身：只看结果，会让侥幸成功或不安全的运行也过关；要求轨迹和参考轨迹一致，又会让另辟蹊径的正确做法判错。

讲者顺带说，MaDSys 组正在做一个用真实流量评估 Agent 的研究平台，欢迎每周能投入 20 小时以上的同学加入。

基准饱和得越来越快

课件列了几个基准从发布到被前沿模型追上的时间：GLUE（2018）用 14 个月达到人类水平 87.1；MMLU（2020）用 39 个月达到专家水平 89.8；GPQA Diamond（2023）用 10 个月超过博士专家的 69.7；SWE-bench Verified（2024）用 22 个月从 33% 涨到 95%；ARC-AGI-2（2025）用 11 个月达到普通人的 60；ARC-AGI-3（2026）6 个月内从 0.5% 涨到 62.7%。这里"饱和"指前沿模型达到了人类基线，或者顶尖模型之间已经拉不开差距。按课件的时间线，到 2026 年 9 月，从 SQuAD、GLUE 到 MMLU、HumanEval、GPQA 等大部分早期基准都已饱和，仍然开放的是 Humanity's Last Exam、ARC-AGI-2/3、Terminal-Bench、GDPval、SWE-bench Pro、Remote Labor Index、OSWorld 2.0 这一批。

方面过去现在的前沿
评估对象基础模型模型加提示、工具和 Harness

七、真实世界的 Agent：能力、成本、速度一起看

一个真正好用的 Agent 要同时看能力、成本和速度。三个指标不能简单加成一个分数，课件用帕累托前沿来比较：如果 A 在每个指标上都不比 B 差，并且至少一个指标更好，就说 A 支配 B。没有被任何人支配的那一批是第 1 名（帕累托前沿）；把它们拿掉之后，剩下的里面没被支配的是第 2 名，以此类推。作业 3 就按这三个指标评估。下一讲讲怎样做出性价比高的 Agent。
