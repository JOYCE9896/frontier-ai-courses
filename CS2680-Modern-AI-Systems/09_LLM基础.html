第九讲：高效 LLM 服务基础（一）：LLM 入门

一个 LLM 请求的生命周期（分词、调度、预填充、解码与采样、反分词与流式输出），以 Llama 3 70B 为例拆解 Transformer 的每一层、参数分布和 KV 缓存大小，估算预填充时间和显存需求，混合专家模型，以及滑动窗口、MLA、线性注意力、状态空间模型、稀疏注意力、循环 Transformer、扩散语言模型这些新架构对服务的影响

主讲：Juncheng Yang
资料来源：课件（2026 年 10 月 19 日；课程不录像，本文依据课件整理）
课程推荐阅读：Transformer、Llama 3、Mixtral
零基础读前预备：分词、注意力与 Transformer、解码

一、第二部分开始

从这一讲开始进入课程的第二部分：为 LLM 和 Agent 服务的系统。第二讲曾说"先把 LLM 当作会推理的黑盒"，现在要打开它。这一讲讲两件事：一个请求在服务端经历什么，以及模型内部怎样算。课件说明两点前提：这里讲的是传统自注意力 Transformer；GPU 部分不讲细节，目的是建立直觉（GPU 放在第十讲）。

二、一个 LLM 请求的生命周期

从提示到流式输出的文字，一共六个阶段：分词、调度、预填充、解码、反分词、流式输出。后面四个里，解码到流式输出这几步对每个输出 token 都重复一遍。两个关键阶段对应两个用户能感受到的指标：预填充决定首 token 延迟（TTFT），它把整段提示一次前向计算完；解码决定每秒输出多少 token，每个输出 token 需要一次前向计算。

第一步：分词

文字先被切成 token，token 不等于单词。英文里平均 3 到 4 个字符一个 token。课件的例子"Serving is hard"被切成 Serv、ing、is、hard 四个 token，对应四个整数编号，三个词变成了四个 token。token 数量决定成本和显存占用，不同模型的分词器也不一样，所以同一段话在不同模型上的 token 数和价格可能不同。

现在常用的是字节级 BPE：从 256 个字节值出发，反复找出现最频繁的相邻一对，合并成一个新 token，直到词表达到预定大小。因为起点是字节，任何文字都能被表示，不存在"未知词"。词表越大，同样的文字切出的 token 越少，但模型的嵌入表也越大。

第二步：调度和批处理

请求是一个个独立到达的，GPU 却喜欢一批一起算（原因第十讲会讲）。调度器决定每一步谁来跑。现代推理引擎用连续批处理：请求可以在任何一步加入或离开批次，不用等凑齐一整批。课件的示意是：第 $t$ 步批里有 R1、R2、R3 和一个空位；第 $t+1$ 步 R2 完成离开，R4 加入；第 $t+2$ 步 R5 补上空位。能接纳多少请求，受限于 KV 缓存还剩多少显存。

第三步：预填充

整段提示在一次前向计算里跑完，所有提示 token 并行地做注意力。这一步计算密集，成本随提示长度增长。它生成提示部分的 KV 缓存，并输出第一个 token，所以它决定首 token 延迟。

第四步：解码和采样

之后每生成一个新 token 做一次前向计算，KV 缓存每步增加一个 token 的量。解码受限于显存带宽（每一步都要把权重和 KV 缓存从显存读一遍，计算却很少），所以要把很多请求批在一起，让一次读取服务多个请求。KV 缓存满了，就只能抢占某个请求或让新请求排队。

每次前向计算输出的是词表里每个 token 的分数（logits），采样从中挑出下一个 token。温度为 0 时总是选最高分的；大于 1 时分布更平，更多 token 有机会被选中。top-k 只从最可能的 $k$ 个里采样，比如 $k=50$，$k$ 是固定的。top-p（核采样）选出累计概率达到 $p$（比如 0.9）的最少的那批 token，模型很确定时候选很少，不确定时候选变多。同一个模型、同一个提示，这些设置会改变答案，也会改变它跑多久，因为输出长度变了。

第五步：反分词和流式输出

生成出的 token 编号随时转回文字发给用户，用户看到的是一个词一个词地冒出来。一个汉字或表情符号可能由几个字节级 token 组成，不完整的字符要先缓存起来，凑齐再发。遇到停止 token、长度上限，或者用户断开连接，流就结束。提前结束能早点释放 KV 缓存占用的显存。

三、打开模型：以 Llama 3 70B 为例

负载方面另有两个量：序列里的 token 数 $n$（比如 2 万），以及并发请求数 $B$（比如 16）。

整体结构

LLM 是一摞相同的 Transformer 块。输入是整数 token 编号；嵌入层把每个编号变成一个 8192 维的向量；然后依次经过 80 个 Transformer 块，每块里有自注意力（在 token 之间混合信息）和前馈网络（对每个 token 单独做变换），各带归一化和残差连接；最后的 LM head 给词表里每个 token 打一个分，softmax 把分数变成概率。

每个块的计算可以写成两行：

$$h = x + \mathrm{Attn}(\mathrm{RMSNorm}(x)),\qquad y = h + \mathrm{FFN}(\mathrm{RMSNorm}(h))$$

这里有三个概念。RMSNorm 把向量除以它各分量平方的均值再开方（即均方根），再乘以每一维一个可学习的增益，作用是把数值大小拉回稳定范围。Pre-norm 指在每个子层的输入端做归一化，这样很深的网络也能稳定训练。残差流指 $x$ 一路流过全部 80 个块，每个子层只是往上面"加一点更新"，而不是整个替换掉。

自注意力

自注意力让每个 token 读取它之前的每个 token。每个 token 产生三个向量：查询 Q（我在找什么）、键 K（我能提供什么）、值 V（我要传递什么），分别由输入乘以学到的权重矩阵得到：$Q = XW_Q$，$K=XW_K$，$V=XW_V$。$X$ 是 $n\times d$ 的矩阵，每行一个 token；每个头的 $W_Q$ 是 $d\times d_k$，所以 $Q$ 是 $n\times d_k$。

$$\mathrm{Attention}(Q,K,V) = \mathrm{softmax}\!\left(\frac{QK^\top}{\sqrt{d_k}} + M\right)V$$

一步步看：$QK^\top$ 是 $n\times n$ 的分数矩阵 $S$，第 $i$ 行第 $j$ 列是第 $i$ 个查询和第 $j$ 个键的点积，表示 token $i$ 该从 token $j$ 读多少。除以 $\sqrt{d_k}$ 是因为点积是 $d_k$ 个乘积的和，维度越大数值越大，不缩放的话 softmax 会过于尖锐。$M$ 是因果遮罩，对角线以上设为负无穷，让每个 token 看不到自己之后的 token。softmax 把每一行变成和为 1 的权重 $A$。最后 $AV$ 让每个 token 的输出是所有值向量的加权混合。课件的例子里，"The cat sat on the" 中第四个 token 那一行的权重是 0.1、0.2、0.5、0.2，加起来为 1，后面的位置被遮掉。

注意力的计算量是 $O(n^2)$

$QK^\top$ 和 $AV$ 每个大约要 $2n^2d$ 次浮点运算，每层合计约 $4n^2d$。序列长度翻倍，这部分计算翻四倍。如果把分数矩阵 $S$ 完整存下来，内存是 $n^2\times$ 头数 $\times$ 层数 $\times 2$ 字节，$n=8192$ 时就是 $8192^2\times64\times80\times2$ 字节，约 690 GB。FlashAttention（Dao 等，NeurIPS 2022）的做法是分块计算 softmax，从不把整个 $S$ 存下来，这是长上下文能跑起来的前提之一。

多头注意力

Q、K、V 被切成 $H=64$ 个头，每个头 $d_k=8192/64=128$ 维，各自独立做带遮罩的注意力，最后拼接起来，再乘一个输出矩阵 $W_O$ 混合。总计算量和一个 8192 维的单头一样（$64\times128=8192$），所以切头改变的是能学到什么，而不是成本。不同的头会学到不同的模式，课件举例：有的头专门看前一个 token，有的看第一个 token，有的看附近几个 token，有的看整段上下文。

共享键值头，缩小 KV 缓存

解码时，每个 token 的 K 和 V 要缓存下来供后面使用。每个 token 的 KV 缓存大小是

$$KV = 2\times L\times H_{kv}\times d_k\times \text{每个值的字节数}$$

最前面的 2 是 K 和 V 各一份。标准多头注意力（MHA）每个查询头都有自己的键值头；分组查询注意力（GQA）让几个查询头共用一组键值头；多查询注意力（MQA）让所有查询头共用一组。以 8 个查询头为例，GQA 用 2 个键值头，缓存缩小到 1/4；MQA 用 1 个，缩小到 1/8。

Llama 3 70B 用 GQA，64 个查询头共享 8 个键值头。代入公式：$2\times80\times8\times128\times2$ 字节 $=327{,}680$ 字节，即 320 KB 每 token。如果是 MHA（64 个键值头），就是 2.5 MB 每 token，大 8 倍。一段 8 万 token 的对话，GQA 需要约 26 GB 的 KV 缓存，MHA 需要约 210 GB。

注意力那一行：Q 和输出投影各是 $d\times Hd_k$，K 和 V 各是 $d\times H_{kv}d_k$。前馈网络有三个矩阵（Llama 用的 SwiGLU 结构有两个输入投影和一个输出投影）。可以看出，前馈网络占了每层参数的八成以上。

四、系统直觉：权重、计算、KV 缓存

三个经验公式就能估出很多东西。权重占用约等于 2 字节乘以参数量，Llama 3 70B 是 141 GB。每个 token 的计算量约等于 2 倍参数量（每个参数做一次乘法、一次加法），即每 token 1410 亿次浮点运算。KV 缓存每 token 320 KB。

课件算了一个例子：Llama 3 70B 用 BF16 跑在两张 H200 上，合计算力 1978 TFLOP/s、显存带宽 9.6 TB/s、显存 282 GB；提示长度 $n=80{,}000$。

$$T_{\text{prefill}} \approx \frac{B\,(2Nn + 2Ldn^2)}{\text{FLOP/s}},\qquad \text{显存} \approx W + B\,n\,KV$$

第一项 $2Nn$ 是所有参数对每个 token 的计算，第二项 $2Ldn^2$ 是注意力里随长度平方增长的部分。代入一个请求：$2\times706\text{亿}\times8\text{万}\approx1.13\times10^{16}$，加上 $2\times80\times8192\times(8\text{万})^2\approx0.84\times10^{16}$，合计约 $1.97\times10^{16}$ 次运算，除以 $1.978\times10^{15}$ 每秒，约 9.95 秒。显存是 141 GB 权重加 $8\text{万}\times320$ KB $\approx 26$ GB，合计约 167 GB，两张卡放得下。

换成 64 个这样的并发请求，预填充总计算要 637 秒，显存需要约 1779 GB，远远超过 282 GB。这就是课件留下的问题：怎样支持更长的序列？下面的新架构，以及后面几讲的批处理、分页和并行，都是在回答它。

五、混合专家模型（MoE）

MoE 把每个块里的前馈网络换成一个路由器加一组较小的专家网络。比如 8 个专家，路由器为每个 token 选出得分最高的 2 个，只运行这 2 个，再把输出加权求和。这样模型总参数很多，但每个 token 实际用到的只有一小部分。

对系统的含义是：显存随总参数量增长（所有专家都得放在显存里），计算随激活参数量增长（每个 token 只算选中的专家）。

六、选读：新架构对服务的影响

这部分课件标为进阶内容，每种架构都落到一个问题上：KV 缓存或计算量会不会随上下文无限增长。

  • 滑动窗口注意力：每个 token 只看最近 $w$ 个 token，KV 缓存最多存 $w$ 个。再穿插几层全局注意力保住远距离的回忆。Mistral 7B 每层都是局部的，$w=4096$；Gemma 2 局部和全局一比一交替；Gemma 3 是 5 层局部（$w=1024$）配 1 层全局。在 12.8 万上下文时，Gemma 3 的 KV 缓存比全用全局层少约 6 倍。
  • 多头潜在注意力（MLA）：每个 token 只缓存一个压缩后的潜在向量，需要时再从它展开出 K 和 V。多做一点计算，少占很多显存；解码时展开矩阵可以合并进查询和输出权重。DeepSeek-V2 相比 DeepSeek 67B，KV 缓存减少 93%，生成吞吐提高 5.8 倍。
  • 线性注意力：用一个固定大小的状态矩阵（$d_k\times d_v$）代替不断增长的 KV 缓存，每个 token 把自己的"键乘值"加进状态，查询从状态里读。Gated DeltaNet 先让旧状态衰减，再覆盖新键指向的内容，两个门分别控制忘多少、写多重。Qwen3-Next 的 48 层里，36 层是 Gated DeltaNet，12 层是普通注意力，只有这 12 层有 KV 缓存；Kimi Linear 和 Qwen3.5 也是 3 比 1 的配方。效果是四分之三的层在任何上下文长度下都只占固定大小的状态。
  • 状态空间模型（如 Mamba）：同样保持固定大小的状态，每个通道一个小向量，衰减和写入的系数由当前 token 决定（"选择性"），所以模型能决定保留什么。它的根源是信号处理和 RNN，用硬件友好的并行扫描在片上内存里计算，Mamba-2 把它变成矩阵乘法。Mamba 报告生成吞吐最高达到 Transformer 的 5 倍。
  • 稀疏注意力：DeepSeek-V3.2 先用一个很轻的索引器（少量头、FP8、每 token 一个 128 维的键）给所有过去的 token 打分，选出前 2048 个，主注意力只读这 2048 个。每个 token 的计算量被封顶，但所有 token 的 KV 仍然要存着。
  • 循环 Transformer：同一个块反复用 $K$ 次，加深度只加计算、不加权重。一个 35 亿参数的循环深度模型在推理任务上随 $K$ 增大而变好。代价是每次循环都是串行的，延迟随 $K$ 增长。
  • 扩散语言模型：从一串遮住的 token 出发，经过几步并行的细化，每步填上一部分。LLaDA（2025）是从零训练的 80 亿参数模型，用了 2.3 万亿 token，和 Llama 3 8B 相当；Dream 7B 从 Qwen2.5 7B 的权重出发，网络仍是 Transformer。一次前向能填很多个 token，但步数太少会损失质量。

课件还提到多 token 预测（一次预测后面几个 token），没有展开。
