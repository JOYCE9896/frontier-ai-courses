第十四讲：数据（二）：转换、过滤、去重与配比

HTML 和 PDF 转文本，基于分类器的过滤（语言、质量、毒性），过滤阈值为什么依赖训练量，MinHash 与局部敏感哈希去重，数据配比与 epoch 陷阱，回归式配比方法，以及推理与编程 Agent 的后训练数据

主讲：Percy Liang
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、转换：从 HTML、PDF 到文本

上一讲说数据不会从天上掉下来：互联网由在线服务构成，数据要么有人转储，要么要爬；之后还要处理；还有服务条款、版权等社会因素，要么拿许可，要么诉诸合理使用。这一讲看数据处理流水线：转换、过滤、去重、配比，最后讲一点后训练数据，特别是现在大家怎样用合成数据。前半部分主要针对预训练。

原始数据不是文本。看看 Common Crawl 里面，是 HTML，有时是 PDF，GitHub 则是目录。大部分精力花在 HTML 上，因为网络大多是 HTML。处理相当依赖启发式：去掉导航、广告等样板，提取正文。什么算正文并不总是清楚，通常去掉页眉页脚和菜单，但有时导航元素也有助于学习网页长什么样。图片和表格怎么办？这本质上是有损过程：HTML 是层级结构，渲染后是视觉的，要线性化成 token 序列。表格尤其麻烦，简单表格可以转成 Markdown，嵌套表格就很难，到某一步只能放弃或近似。

HTML 转文本通常基于规则，因为规则很快，而且这一步不需要太多智能。也许可以引入基于模型的处理，但必须非常快，还得真有更聪明的作用。你看数据时总会发现瑕疵，因为规则总有失败率。上一讲提到工具的选择确实影响结果，在 DCLM 的扩展评估上 Resiliparse 比其他工具好。

PDF：Hugging Face 发布了 FinePDFs 数据集，博客里有很多细节。不用阅读器打开，PDF 文件内部是一堆需要渲染的东西。PDF 和网页一样散布在互联网上，Common Crawl 里也有一些，但它主要关注文本；有时 URL 没有扩展名，取回来之前都不知道是不是 PDF。Common Crawl 里很多 PDF 被截断了（因为文件大），需要重新抓取。拿到 PDF 后怎么转文本？有的只是扫描件，本质上是图片，所以主要是跑 OCR，用视觉语言模型，比处理文本贵得多。PDF 只占互联网的很小一部分，但很有价值：愿意费事做成 PDF，多半有些有意思的东西要说，所以 PDF 的平均质量高于 HTML。PDF 需要更多清理和过滤，而且缺少版面之外的语义信息：HTML 有 h1、p 等标签，PDF 生来就是为了排版，不一定保留语义结构。

二、过滤

有了文本，还远没完成，下一步是过滤。抽象地说：你有一小批想要的高质量目标数据 $T$，和大量原始数据 $R$（上一步刚转换出来的 token），目标是从 $R$ 中找出与 $T$ 相似的子集。几乎所有过滤都符合这个框架，用途包括：语言识别（训练英语或德语模型就过滤掉其他语言）；质量过滤，这是最主要的用途，要百科式的信息而不是垃圾；毒性过滤，互联网有很多恶心内容，也许不想拿来训练。

过滤算法要从目标数据泛化，因为目标数据你已经有了，不能只找回它；还必须极快，因为要跑在整个互联网上，可能是 100 万亿 token 量级，最后通常只留下个位数百分比的数据。一般做法：基于 $R$ 和 $T$ 估计一个模型，得到打分函数，按分数保留 $R$ 中的样本。

  • 生成式：在目标数据上估计一个模型，必须便宜，所以通常不训练大语言模型，比如用 KenLM 训练一个 5-gram 模型，按困惑度打分。
  • 判别式，现在更常见：$T$ 作正例，$R$ 的随机子集作负例，可能做平衡，训练分类器。常用 fastText，因为快，它就是词袋上的线性分类器。然后给每个新文档打分，按质量要求设阈值，保留样本，有时随机保留，有时确定性保留。

上一讲提到，几年前很多数据集刻意不用基于模型的过滤，以免引入太多偏差。现在基本都会用一些，因为除非算力非常充足（那样也不太需要过滤，全部拿来训练就行），大多数人算力有限，必须聪明地过滤，否则就是把 FLOP 浪费在低质量内容上。

几个实例：

  • 语言识别：Meta 训练了一组 fastText 语言识别模型，支持 176 种语言，在多语言网站上训练（维基百科、翻译网站、各语言网站），可以直接用。相比其他任务这比较容易，看几个词就知道是西班牙语还是日语；有语码混用、方言等细节，不能说完全解决，但不是训练好模型的瓶颈。阈值通常靠经验选。
  • 找特定类型数据，比如数学：OpenWebMath（2023）要构建大型数学语料，流程有几步：用规则看是否含 LaTeX 命令；用在 Proof-Pile（已知的数学数据集）上训练的 KenLM 打分，困惑度低于阈值才保留；再训练 fastText 分类器判断是不是数学写作。含 LaTeX 的门槛低一些，不含的门槛高一些。得到 150 亿 token，论文显示这样有针对性收集的数据训练出的模型，数学比用 20 倍未经这样过滤的数据训练的模型更好。质量过滤是工具，没有通用的质量定义，你把质量定义为数学，就能拿到数学数据，数学就会变好。
  • GPT-3：正例是维基百科、WebText（高赞 Reddit 帖子的外链）和一些书，负例从网上采样，训练线性分类器，分数够高才保留。
  • Llama 1：正例是被维基百科引用的页面，而不是维基百科文章本身，思路相同。
  • Microsoft 的 phi-1：原始数据是 The Stack 的 Python 子集；写一个"判断教育价值"的提示，让 GPT-4 给 10 万条子集分类，正例作为目标；再训练一个便宜的分类器（他们用随机森林，fastText 大概也行）筛选全部数据。用这个数据集训练，比用原始数据更快达到更高性能。目标数据本身来自昂贵的分类器，再用便宜的分类器外推。
  • 毒性：Jigsaw Toxic Comments 数据集来自一个帮助人们更好地在线讨论的项目，数据是维基百科的讨论页（有争议的条目会吵得很凶），标注了是否有毒，同样可以定义正负例训练分类器。

阈值依赖于训练量

一个细节：你想要什么样的数据，取决于要训练什么样的模型，特别是训练多少 token，所以不存在最优阈值，不能说 0.9 就是最好的。直觉上，训练越久，越能容忍低质量数据；训练越短，越需要高质量数据。（如果有魔法，训练久的时候当然想要更多高质量数据，但数据池就那么大。）

Michael Ryan 的初步实验：157M 参数的模型，数据池很小（Common Crawl 的极小部分），不断加长训练。蓝线是 DCLM 过滤后的数据，损失下降，每段对应一个 epoch，数据不多所以很快要重复，第二遍仍然在学，最后开始过拟合。Resiliparse 线基本是不过滤的数据，一开始差得多，但继续训练、开始重复后下降变慢得较晚。趋势是：不重复时高质量数据更好；token 很多时高质量数据就不那么好了。用高质量数据你本来也不会进入那个区间，会在过拟合前停下，但即使在那一点，也比用低质量数据训练更久要差。

学生问每个点只跑一次，要不要置信区间。他说理想情况下应该，论文里少见是因为训练很贵；他们自己做实验时，至少预训练通常比较稳定。学生问如果有更多高质量数据、训练更久，会不会也收益递减。他说任何有限数据集最终都会收益递减，但那条曲线会更低、一直往下走。

小结：过滤对训练好模型非常关键，尤其算力有限时。无限算力就不必过滤，训练一个巨大的模型吃下所有数据；现实中人人都要过滤。做法是弄清好数据长什么样，训练分类器外推到其余数据。好数据可以是你很喜欢、想要更多的现成数据集，也可以是给语言模型写个提示，对大数据池做初筛，用这些好数据训练更小的分类器，再外推到全部。

三、去重

过滤后只剩我们认为高质量的数据，但通常仍有重复：

  • 完全重复：镜像网站的意义就是复制，爬虫不一定聪明到识别镜像；fork 仓库也是，即使改了几个文件，99% 仍相同。
  • 近似重复：不是镜像或衍生，只是文本相同、差几个 token，可能是复制或来自同一来源。例子：服务条款和许可证（MIT 许可证到处都是，除非抄的时候打错字，否则是完全拷贝，但所在页面的其余部分不同）；很多网站相同的页眉页脚；10 亿词基准里一些文章只差一个逗号，不知道为什么；模板化内容，像广告，把 Canada 换成 USA。在这些只换了实体的变体上训练，就是浪费 GPU。

更极端的：C4 的一次审查发现某个防毒面具的商品描述出现了 61000 次，非常诡异，网络就是这么怪。这也是为什么要看数据。

为什么去重？首要原因是训练更高效，减小数据量而不损失信息；还能避免记忆，比如重复很多次的版权内容或隐私内容会被记住。主要是别浪费 FLOP。和去重相关的去污染可能更重要：确保测试集不在训练集里，是同一类操作。

设计空间：对什么去重，句子、段落还是文档？怎样算匹配，完全相同、有公共子项，还是公共子项比例够高（近似去重）？找到重复后，全部删除还是保留一个？算法上的关键挑战是：去重本质上是项与项的比较。过滤是对单个项做判断，可以并行，是线性时间；去重不能做 $n^2$ 的两两比较，网络规模下必须是线性时间。去重文献用哈希函数解决这个问题。

哈希函数把字符串等值映射成更小的值（字符串或整数），不同项映射到同一值叫碰撞。有抗碰撞的密码学哈希（用于密码学、比特币等），也有更快的、用于哈希表的哈希，碰撞不是世界末日，这里用后者。

完全去重概念上很简单：哈希，相同的只保留一个，可以写成 MapReduce 风格，方便并行扩展。C4 做的是完全去重，单位是三句话的片段，保留一个，删掉其余。他说这有点怪：发现两个文档有相同的三句话，就从其中一个里挖掉这三句，破坏了连贯性，但他们就是这么做的。完全去重对混乱的网络数据不够，因为有大量近似重复。

MinHash

近似匹配先要定义相似度。用 Jaccard 相似度：两个集合交集大小除以并集大小。比如 $A = \{1,2,3,4\}$，$B = \{1,2,3,5\}$，交集 $\{1,2,3\}$，并集 $\{1,2,3,4,5\}$，Jaccard 为 0.6。它在 0 到 1 之间，0 表示不相交，1 表示相同。两个文档 Jaccard 超过某个阈值（比如 0.99）就算近似重复。怎样在线性时间内找到它们？

第一步是 MinHash：一种随机哈希函数，使得碰撞概率恰好等于 Jaccard 相似度：

$$\Pr[h_{\min}(A) = h_{\min}(B)] = \text{Jaccard}(A, B)$$

通常希望哈希函数让不同元素映射到不同值、避免碰撞；这里反而想要碰撞，但要按相似度控制：相似的东西更常碰撞。做法很简单：对集合里每个元素做哈希，取最小值（取最大也行，只是一种打破平局的方式）。直觉：把两个集合画成特征矩阵，行是元素 1 到 5，随机哈希相当于对元素做了一个随机排列；看 $A$ 中排第一的元素和 $B$ 中排第一的元素是否相同。每个元素排第一的概率相同：如果排第一的是 1、2、3 之一，两边相同；如果是 4 或 5，就不同。所以碰撞概率是 3/5，正好是 Jaccard。课上用 100 个不同种子的哈希函数验证，匹配比例约 0.6。关键是不用两两比较，各自算 MinHash，找碰撞即可。

局部敏感哈希（LSH）

但一次碰撞并不说明 Jaccard 超过阈值，它只是以 Jaccard 的概率发生，很随机，方差很大，单独用不可靠。局部敏感哈希是理论计算机科学的经典想法，用来把概率"锐化"：希望 Jaccard 超过阈值时几乎必然碰撞，低于阈值时几乎不碰撞。

做法：用 $n$ 个独立的哈希函数，分成 $b$ 个带（band），每带 $r$ 个。比如 12 个哈希函数分成 3 带，每带 4 个：$h_1$ 到 $h_4$，$h_5$ 到 $h_8$，$h_9$ 到 $h_{12}$。定义：如果存在某一带，其中所有哈希函数都给出相同的值，就说 $A$ 和 $B$ 碰撞。带内是"与"，带间是"或"。设 Jaccard 为 $s$：

  • 某一固定带完全匹配的概率是 $s^r$，随 $r$ 指数下降，通常很低；
  • 有至少一带匹配的概率是 $1 - (1 - s^r)^b$。

比如 $s = 0.8$，5 个带，每带 10 个哈希函数，碰撞概率约 0.4。以相似度为横轴画这个函数，是一条 S 形曲线：相似度 0 时为 0，1 时为 1，中间有一个"相变"，这正是我们想要的：低于阈值时碰撞概率尽量低，高于时尽量高。

  • $b = 10$，$r = 10$ 时，相似度从 0.7 到 0.98，碰撞概率约从 0.25 到 1。设阈值 0.9 的话，低于阈值的也可能碰撞（假阳性），可以再过滤，高于阈值的大多保留。
  • 增大 $r$（每带的哈希函数数）：曲线变陡并右移，更难匹配，低相似度的碰撞概率从 0.25 降到 0.08 左右。
  • 增大 $b$（带数）：曲线左移，更容易匹配，因为有更多机会；0.9 的碰撞概率从 0.72 升到 0.92，低相似度的也会上升，但不多。

增大 $b$ 和 $r$ 可以让相变任意陡峭，代价是计算更贵。一篇去重论文用的是 $b = 20$、$r = 450$，可以感受一下量级。相变发生在阈值

$$s^\ast \approx \left(\frac{1}{b}\right)^{1/r}$$

处：想按 Jaccard 大于 0.9 过滤，就选 $b$、$r$ 使这个值为 0.9，再调大它们让相变更陡。在这个阈值处一带匹配的概率是 $1/b$，碰撞概率约为 $1 - (1 - 1/b)^b \approx 1 - 1/e \approx 0.63$，这是相变的中心，随 $b$、$r$ 增大，以下的趋于 0，以上的趋于 1。LSH 适用于任何哈希函数，用于语言模型数据去重时配合近似 Jaccard 的 MinHash，叫 MinHash LSH。

还要注意：数据集往往是多个来源合起来的，重复不仅在单个数据集内，也在数据集之间，应该对整体去重，这一点有时被忽略。

四、数据配比

至此我们把原始 HTML 或 PDF 转成文本，过滤出高质量的，去了重，得到更小的高质量文档集合，这通常是对单个来源做的。但语言模型用多个来源训练：Marin 的网站上列出了下一个模型要用的数据来源，有 Nemotron、FinePDFs、Institutional Books、代码等。早期的 The Pile 给每个组成部分分配一个权重。权重从哪里来？

数据配比就是在来源上的一个分布。常见做法：

  • 凭感觉手动设，这和第一性原理正好相反，但比你想象的更常见，较新的论文也常是用某种方法后再手动微调。
  • 均匀采样：每个来源概率相同。
  • 按比例：按各来源的 token 数采样。合理，但一个巨大的低质量数据集会吃掉大量 token，也不够好。
  • 直觉上应该提高高质量来源的权重，但有两点要注意：一要保证多样性，文学、代码、论文这些来源无法比较，不能说这篇论文比这段代码质量高，想让模型各方面都好，不能把权重都压在论文上；二是每个来源都是有限的，给小来源太大权重，它很快就用完，只能反复重复同样的 token，这很糟。

具体例子：低质量来源 10 万亿 token，高质量来源 100 亿 token（高质量的通常更小）。朴素地各占一半，训练 1 万亿 token（指训练步数乘批大小，不是唯一 token 数）。低质量来源每个 token 的平均 epoch 数是 $0.5 \times 1\text{T} / 10\text{T} = 0.05$，只有 5% 会被碰到一次；高质量来源是 $0.5 \times 1\text{T} / 10\text{B} = 50$，需要 5000 亿高质量 token，实际只有 100 亿，每个数据点要重复 50 次。他说一些大模型训练就在这里栽过跟头：只看数据质量定一个分布然后采样，没看每个来源有多少数据。学生问为什么需要 50 个 epoch，他说不需要，最好情况是浪费算力，最坏是过拟合；要点是如果不仔细看，定了配比就会不知不觉跑 50 个 epoch，所以一定要检查每个来源实际跑了多少 epoch。学生问训练时配比怎样体现：填一个批时，为每个元素采样它来自哪个来源，再用该来源的序列填，通常一个序列来自一个来源，不是按 token 采样；一般每个批里都是混合的，以降低方差。

这个问题很早就有人注意到。UniMax 论文研究多语言模型，有些语言资源很少。之前的工作把按比例的分布取某个幂来压平；UniMax 更明确：均匀采样各来源，但对 epoch 数设硬上限，比如某个来源最多 20 个 epoch，到了就不再取，转向其他来源，相当于安全网。约束是来源概率乘训练 token 数不超过上限乘来源大小，有简单的程序在此约束下求配比。

回归式配比

50 个来源就要定 50 个数，按比例不够，估计质量再按质量采样也是启发式。最有原则、也最容易理解的是回归式配比方法，比如 RegMix：

  1. 在小规模上（比如 3 亿参数）尝试很多不同的配比，训练一群小模型，每个模型在某个目标指标上得到一个损失（下游评估、困惑度等）；
  2. 用这些点拟合回归模型，从配比权重映射到损失，得到一个很便宜的"用这个配比训练会得到什么损失"的预测器；
  3. 优化这个函数，得到最优配比，用它训练大模型。

和缩放规律相似：用便宜的计算找答案再放大。设计选择：

  • 尝试哪些配比：需要一个"分布上的分布"，通常用狄利克雷分布。
  • 回归方法：线性模型、梯度提升树等，对数线性模型效果往往不错。
  • 目标：常基于下游评估，要非常小心别过拟合。预训练应该训练通用模型，不是拟合某些下游评估；如果评估里都是代码题，你当然会给代码数据加权，这不难想到，然后想让它写诗时才发现过拟合了。按比例和均匀配比没有这个问题，因为不看下游评估。
  • 小规模和大规模差多少：成本与准确性的取舍。模型太小可能不具代表性；模型太大，那就等于在最大规模上调超参数，太贵，做这些就没意义了。

AI2 的一篇配比论文（Olmix）有一张表汇总了属于这个框架的各种方法：代理模型通常是几千万参数，采样多少配比，用狄利克雷还是指数分布，回归模型和优化方法。

这里有两个信念上的跳跃：一是回归模型在优化出的最优配比处仍准确。随机采一个配比，按经典的泛化，分布内预测没问题；但优化会把你推向覆盖较少的极端区域。二是小规模的最优配比能迁移到大规模。在开源社区的规模上似乎大体成立，至少没有明显不成立；但显然有依赖规模的效应，比如前面讲过训练 token 越多，低质量数据越可以接受，最优点不会一样，只能希望结果还好。

一个必须处理的规模效应：低质量数据 10 万亿 token，高质量 100 亿。小模型、少 token 训练时不会重复数据，优化可能说"维基百科太好了，全用维基百科"；按这个配比训练大模型，就会对高质量数据重复很多遍而过拟合。解决办法：

  • 限制 epoch 数，Olmix 就这么做。
  • 模拟 epoch：让小规模看起来像大规模，这是课程反复出现的主题，就像 Tatsu 讲的 μP，参数化模型使超参数能迁移。小规模不重复、大规模重复，对数据集的操作在性质上就不同。所以按比例对各来源下采样：小规模运行 100 亿 token、大规模 1 万亿 token，就把每个来源都下采样到 1/100。这样小规模下也只拿到维基百科的极小一部分，会发现大量重复，损失很差，优化就会转向更平衡的方案，在小规模上模拟大规模下的数据稀缺。

学生问下采样后数据集太小怎么办。他说确实可能，那样最优解会给它很小的权重，放大后也许正好；可能有舍入误差，比如本该训练一次的数据意外地一次都没训练，可以规定每个数据至少训练一次来绕过。学生问配比能否用在单个多样数据集内部。他说这点刚才忘了讲：Nemotron 和 OLMo 的工作中，比如拿到 Common Crawl，可以按领域分组（AI2 有 WebOrganizer 可以按主题分组），也可以按质量分档，得到"领域 × 质量"的二维网格，每个格子都是一个配比单元；这是自动确定领域的一种方式，再加上别人给的额外来源。

小结：怎样为维基百科、Common Crawl、代码、从别处抓的数学数据分配权重？回归式配比是一个不错的思考框架：在小规模上估计从配比到损失的函数，优化，再推广到大规模。要注意 epoch 和过拟合问题，用 epoch 上限或模拟 epoch。教训是：优化任何东西都要非常小心，很容易优化错目标。

五、后训练数据

前面的预训练或中期训练数据大体与任务无关（除了回归配比要最小化某个损失，但数据本身仍相对无关任务），目的是培养基本技能。后训练数据就很依赖任务了。他不做全面综述，只介绍几个近期有意思的数据集，尤其是大家很关心的编程。

一般配方：定义一组环境（对代码来说可能是 GitHub 仓库），定义一组任务或提示，从强模型或教师那里收集回答。所以至少在开源社区，大部分后训练数据都是合成的。也可以用人代替强模型，但慢而且贵；几年前在前沿就得花大钱请很多人写回答，现在前沿也可以用人机混合的方式。总之有个教师给出回答。

  • OpenThoughts：o1 出来后大家关注推理（主要是数学和科学），怎样得到好的后训练数据？最终用教师模型生成了 120 万个样本。问题来源很多：Stack Exchange、NuminaMath 等人类来源，以及一些合成来源；编程类有练习题、代码高尔夫（不算真实），也有代码审查（更真实），还有数学、化学等，是很多人参与的大项目。他们对怎样生成回答做了相当全面的分析：用少数几个来源比用所有来源好；对每个问题采样多次（比如 16 次）有帮助；更强的模型不一定是更好的教师，比如 QwQ-32B（现在看又老又小）比当时最强的开源模型之一 DeepSeek-R1 更适合当教师；基本的答案过滤没有帮助。流程：各来源汇入，去重，随机下采样问题，生成多个答案。120 万是样本数，除以 16 才是实际问题数。
  • SWE-smith：最近大家很关心 Agent 编程模型，不只是生成代码，而是做软件开发。给定仓库，用语言模型自动生成任务：一个 Agent 先让仓库可用（安装依赖等），再生成任务，通常是以某种方式修改代码、引入 bug，验证后得到任务实例。任务是合成的，但有 5 万个，在去年已经很多。
  • NVIDIA 的 SWE-Zero：观察是软件工程任务和数学不同，依赖很重，大多数 GitHub 仓库根本跑不起来，要装各种依赖，回滚到 PR 当时的版本还常常过时，是一场噩梦。他们不为每个仓库做 Docker 镜像，而是发现模型已经强到不执行代码也能解决很多任务：允许执行时约 80%，不允许时也接近 70%，说明模型对代码有某种内在的语义理解。于是生成了 30 万条 Agent 轨迹，都来自真实 GitHub PR，比 SWE-smith 的合成任务更真实。用 OpenHands 脚手架，处理了很多细节，比如防止 Agent 投机取巧：通常的指令是"探索、测试、实现"，他们的版本是"不能运行 Python 代码，只能用 sed、grep 等基本操作"。从一个大的编程模型蒸馏，并过滤掉无视指令仍去执行的轨迹。另有 1.3 万条需要执行反馈的轨迹（SWE-Hero）。先在 SWE-Zero 数据上微调，再在 SWE-Hero 数据上微调，取得了一些进展，虽然离前沿还远。
  • SWE-rebench：又一个大量收集 PR 的尝试。这类工作大同小异：拿一堆 GitHub 仓库，尝试安装（大多会失败），再努力一点，然后用语言模型给出回答。
  • 当天刚发布的一项工作：把 SWE-Zero 的思路扩展到 1200 万条 Agent 轨迹。SWE-Zero 的好处是非常轻量：用 SWE-rebench 的任务，原本要求能执行，只有 3.2 万个跑得起来，12 万个跑不起来，而 SWE-Zero 不在乎能不能执行，全都能用。因为数据量大，用的是很小的模型。

数据集越来越复杂：从不需要环境的数学，到编程，编程数据集也在迅速变大。提示有几种取舍：完全合成；半合成，真实环境加合成任务；完全真实。回答通常来自强模型，但它也得是好教师。代码环境很麻烦，有大量过滤等细节没时间讲。

六、小结

过滤：定义什么是好的，训练轻量分类器，扫过网络抓取，得到符合要求的小子集。去重：避免过拟合、节省 FLOP。配比：在小规模上试配比，外推到大规模。还看了一些后训练数据。他最后说，很多数据工作非常琐碎、高度依赖领域，需要盯着具体例子才能做出高质量数据集，这一讲并不能代表数据工作的真实样子，但希望让大家对数据的全貌有个概念。
