第十三讲：数据（一）：数据从哪里来

"在整个互联网上训练"到底指什么，抓取的技术与法律限制，版权、许可与合理使用，Common Crawl、维基百科、GitHub、arXiv 等来源，以及从 BERT 到 Nemotron 的预训练数据集演变

主讲：Percy Liang
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、为什么数据最重要

现在你们知道了给定数据怎样训练模型，上一讲讲了什么是好模型，这周两讲讲应该用什么数据训练。Percy 认为数据是语言模型中最需要做对的东西。一个理由是看公司公开了什么：Llama 3 论文完全公开了架构（开源权重，当然要公开），甚至讲了训练流程，但对数据几乎只字不提，只说"我们使用了多种数据来源"。保密有充分的理由：一是竞争，数据是秘方，不想让对手知道；二是版权责任，说出用了某些数据可能会被起诉。

数据是机器学习的老话题。基础模型之前，数据工作意味着为监督学习标注数据；现在预训练的人工标注少了，但仍有大量整理和清洗工作。本质没变：数据一直是瓶颈，也会一直是，因为它是长尾问题，随人力扩展。做架构和系统的人数有限，而数据工作，尤其是想让一个基础模型什么都能做的时候，很容易并行地投入很多人，所以模型开发者的数据团队往往很大。

数据出现在流水线的不同阶段：

  • 预训练：原始数据，比如网页文档；
  • 中期训练：更高质量的数据，增强某些能力、加长上下文等；
  • 后训练：对话记录，或者做强化学习时的环境，更贴近具体任务。

实际上界限比较模糊，也可能不止三个阶段，但大致的趋势是从大量低质量数据走向少量高质量数据。文献里的"基座模型"通常指预训练加中期训练之后，指令模型或对话模型指后训练之后；但界限已经模糊到"基座模型"是什么都说不清了，最近最大的模型干脆没有基座模型，比如只发布 Qwen 3.5 397B，看不到中间检查点。AI2 的 OLMo 这样的开源模型能看到全过程：预训练有网页、学术论文、数学网页、证明等；中期训练有更高质量的网页数据、指令数据，合成数据也常放在这里；后训练有对话日志、更多数学推理和代码，安全也在这时做。这些数据集是什么、怎么选、怎么处理，就是这两讲的主题。这一讲按课程一贯风格从头讲起：数据从哪里来。

二、"整个互联网"其实拿不到

走廊里常听到"语言模型在整个互联网上训练"。Percy 说这在类型上就对不上：要那样，得是一个在互联网上做事的强化学习 Agent，预训练不是这样。稍准确些的说法是"在公开的万维网上训练"，但这也不太准确。

网络其实是世界上一堆在线的服务器，你发请求、拿回响应。你不能直接在在线服务器上训练，所以要有爬虫（不一定是你自己建的）：从一组种子 URL 出发，发现有哪些网页，边爬边下载。但跑一个爬虫也拿不到所有网页：

  • 很多内容是动态的：现在很多网站其实是应用，URL 不能完整指定内容，往往要点按钮、提交表单才能看到，比如 Discord 不能简单地爬出所有内容。很多内容在所谓"深网"里，不是传统那种沿超链接爬网页能拿到的。
  • 需要认证：有些页面要登录账号，通常还要付费，比如 Facebook、X、LinkedIn、纽约时报，大量内容锁在这些围墙花园里。如果你是 Facebook，不用爬，直接有数据；xAI 可以在 X 上训练；其他人拿不到。
  • robots.txt：放在网站根目录（比如 nytimes.com）的文件，说明哪些爬虫可以爬什么。很多爬虫被禁止，比如 OAI-SearchBot、PerplexityBot、ClaudeBot 等。这不是法律限制，只是做个好公民应该遵守的约定。
  • 技术拦截：很多网站用 Cloudflare 之类检测和拦截机器人，弹验证码；还会封 IP 或国家、限速。
  • 法律限制：服务条款常写着"如果你是机器人，请离开"或"不得用于 AI 训练"；即使条款没写，内容本身可能有许可证，或者你没有训练许可。

这些限制随时间在增加。Shayne Longpre 等人的 Consent in Crisis 考察了常用数据集中 URL 的技术限制（robots.txt）和法律限制（服务条款）：2023 年中之前基本平稳，之后完全禁止的网站比例迅速增长，接近 50%；服务条款也一样，2016 年几乎没人写，现在大多数页面都有，而且大多禁止用于 AI。所以虽然 2020 年左右还能爬互联网，现在能合法爬取的部分小得多。

这些规则有时会被有意或无意违反。有网站抱怨 Anthropic 的爬虫 24 小时内访问了它们的服务器一百万次，Read the Docs 也被狂刷过。他希望现在已经改正。这说明即使不谈版权，爬取本身也有问题：违反服务条款或 robots.txt，或者造成大量服务器负载，花对方的钱，也拖慢其他用户。

还有影子图书馆，比如 LibGen、Anna's Archive，完全无视版权、绕过付费墙，把大量需要付费的书和文章免费放出。它们收到很多下架令和诉讼，被封锁，但会在其他国家建服务器绕过。做这些的人认为是在解放本应免费的知识，但从法律上讲这是盗版和侵权，后面还会回到这一点。

小结：互联网庞大、混乱、有点吓人，你拿不到全部，有技术和法律两方面的限制。下次有人说"我在互联网上训练"，你可以把这些告诉他。

三、版权

假设你遵守服务条款和限速，是个好公民，还有一个问题：你被允许用这些数据训练吗？这个问题还没完全解决，但过去一年有不少进展。法律框架是知识产权法，目的是激励智力成果的创作，所以要记住法律的精神不是技术上对一切说不，而是激励创作。知识产权包括版权、专利、商标、商业秘密，和语言模型数据最相关的是版权法。

版权法可以追溯到 18 世纪的英国，1709 年政府和法院开始为激励创新和创作而规范版权。美国现代版权的基础是 1976 年的版权法：版权保护"固定在任何有形表达媒介上的原创作品"。几点说明：

  • 不是什么都能有版权：汇编本身通常不行，比如电话簿，除非编排有创造性。
  • 版权保护表达，不保护思想：不能给快速排序算法申请版权，但可以对它的某个实现主张版权。
  • 1976 年后门槛大大降低：以前要发表才有版权，现在只要固定下来就有，不需要任何登记。专利要花很多钱申请；版权门槛很低，你在网站上放点东西就有版权了。要起诉的话需要登记，也只要 65 美元，比律师费少得多。
  • 版权有期限，课上说约 75 年（美国的具体期限因作品类型而不同，常见的是作者终身加 70 年），到期后进入公有领域，人人可以自由使用。逻辑是激励创新：保护创作者一段时间，之后就没有必要了。

所以互联网上基本所有东西都有版权。那用任何东西训练都侵权吗？不一定。使用有版权的作品有两条路：

  1. 获得许可。许可来自合同法，许可人授予被许可人在许可范围内使用作品的权利，相当于说"别告我"。知识共享（Creative Commons，2001 年创立）让作品像在公有领域一样可以自由分发，维基百科、OpenCourseWare、可汗学院等都用它；它填补了公有领域和既有版权之间的空白，否则要等 75 年。公有领域和 CC 许可的内容可以用。其他内容要拿到许可，有钱可以付费，模型开发者和内容平台之间有很多授权训练数据的交易。
  2. 主张合理使用（美国版权法第 107 条）：没有许可也可以用。有四个因素，都不是硬规则，而是到了法庭上要权衡的倾向：
    • 使用的目的和性质：教育用途比商业用途更可能是合理使用；有转化性比原样托管更有利。
    • 作品的性质：事实性的比虚构的更可能是合理使用，关于二战的事实页面受保护程度不如一首很有创意的诗。
    • 使用的数量和比例：用一小段比用全部好。
    • 对原作品市场的影响：和版权的初衷相关。如果你提供替代品，减少原作者靠作品赚钱的能力，就不利；如果转化后进入新市场，就较有利。

合理使用的例子：看电影写摘要；重新实现某个算法的思想而不复制代码；作家协会诉 Google 案，Google Books 展示有版权书籍的片段，打了 11 年官司，最终以有利于 Google 的结果了结，这也为判断语言模型训练是否属于合理使用提供了先例。对机器学习的人来说可能有点新：版权不只关乎逐字记忆，很多论文关注逐字记忆，但那只是侵权的一种方式。情节和角色可以有版权，比如哈利·波特这个角色；也有例外，比如戏仿，看起来像衍生作品，但只要是在调侃它，就更可能是合理使用。版权很多是关于语义和经济的，绝不是 n-gram 重叠。

对语言模型的含义：复制数据本身，哪怕不训练，就可能已经侵权（版权的英文就是 copy right）；训练模型直觉上有转化性，和重新托管作品很不一样，模型训练是借数据学习一般性的思想、了解世界，而不只是具体表达；但不论如何，语言模型确实可能影响市场，这对合理使用不利。所以合理使用有点滑。即使有合理使用或许可，服务条款还可能禁止你获取作品，比如 YouTube 上的视频，条款禁止用机器人下载或抓取，这是另一层限制。

法律进展：

  • 2023 年纽约时报起诉 OpenAI，说用他们的新闻训练，还能诱导 ChatGPT 几乎逐字生成新闻文章。他记得还在审理中。
  • 针对 Anthropic 的案子指控其盗版了数百万本书并用来训练 Claude。去年的里程碑式裁决说，这种情况下的训练属于合理使用；但盗版本身仍然违法，这和训练无关。有意思的是 Anthropic 也买过书并扫描（拆掉装订、扫描数字化供自己用），法院认为这是合理使用，但不能先盗版再买书来抵消。最终 Anthropic 支付 15 亿美元与作者和解，约每本书 3000 美元。
  • 针对 Meta 的案子：指控其用作者的书训练（这在 Llama 论文里被披露了，后面会讲）。紧接着 Anthropic 案的判决也认为训练属于合理使用；Meta 还用种子下载了书，这部分仍在审理，如果先例成立，对 Meta 不妙。

小结：训练目前被认定为合理使用，或至少没有被认定为不是；但这些裁决范围很窄，不等于用任何有版权内容训练都是合理使用。盗版书显然违法。这个领域还在快速变化。学生问许可改变后怎么办，他说自己不是律师，但他认为原来许可下的内容应该还能用；许可通常不针对固定的文档集合，比如 Reddit 不断有新内容，许可改变意味着之后的新内容不能用。

四、几种具体来源

Common Crawl

大多数模型开发者有自己的爬虫，以完全掌控数据。不想自己建爬虫的人可以用 Common Crawl：2007 年开始，每月爬一次，每次 30 亿到 50 亿网页，和之前的抓取有重叠，但会尽量收新页面，官网说累计 3000 亿网页（他说乘一下对不上，但官网这么写）。网上有多少 URL 很难估计，Google 说其搜索索引至少 100 PB；一次 Common Crawl 约 20 亿网页、约 372 TB，不含图片。

爬取概念上很简单，细节全在实现里：从一批 URL 出发做图遍历，从队列取 URL、下载、把页面上的超链接加入队列，通常在很多机器上并行。要决定下载哪些页面；遵守 robots.txt，别压垮服务器；网站会变，要有策略常下载经常变的页面，不浪费时间在不变的页面上；URL 是动态的，同一 URL 可能因浏览器状态不同给出不同内容，许多 URL 又可能指向同一内容，不小心就会大量重复，镜像网站更是专门重复。

Common Crawl 发布两种格式：WARC 是原始 HTTP 响应；WET 是转换后的文本，必然有损。HTML 转文本有很多工具，比如 trafilatura 和 Resiliparse，转换方式确实有影响：DataComp-LM 论文的消融显示，trafilatura 和 Resiliparse 比 Common Crawl 自带的 WET 文件好。

维基百科、GitHub、arXiv

网络并不均匀，不是随便抽一部分网站就行，有些角落有特别有价值的高质量内容：

  • 维基百科：2001 年开始，现在有约 6700 万篇文章，覆盖多种语言。它不允许原创思想，一切要有引用，所以可以说它没有网上没有的东西；但它也引用书，而书不容易拿到。条目要有知名度，不是谁都能有词条。任何人都能写，这是 wiki 的激进之处，他至今觉得能运作是个奇迹：破坏会被管理员（现在大概也有机器人）回滚；和所有同侪生产系统一样，少数人干了大部分活，有人编辑了 500 万次。维基百科每隔几周发布一次完整转储，可以直接下载，不需要也不应该去爬。一个有趣的插曲：Carlini 等人发现可以投毒，因为转储时间有规律，在转储前一刻编辑，转储完成后编辑被回滚，但转储里已经有了恶意内容；能往网页里注入内容，就可能让模型对某个触发短语（比如 iPhone）产生负面情感。他的结论是：考虑对手时，所谓高质量内容里也可能有坏东西。这个漏洞后来应该修了。
  • GitHub：代码不仅对编程能力重要，对一般推理也重要。2008 年开始，课上说有约 4.2 亿个仓库，其中公开的约 2800 万。仓库是带提交历史、issue、PR、评论的目录。代码有大量重复（复制或 fork）。GitHub 认为可以用任何带宽松许可（MIT、Apache 等）的公开仓库训练。两类数据：仓库本身，用 Git 协议下载，不要爬；元数据（issue、PR 等），可以从 GH Archive 获取每小时的事件流快照，几乎每条评论、每个星标、每个操作都有记录，他觉得这很有意思。Software Heritage 基金会关注仓库，汇集了 GitHub 以及 GitLab、Bitbucket 等较小平台的仓库。
  • arXiv：1991 年起用于分享论文，从物理开始，现在覆盖很多领域。约 300 万篇投稿，每篇有元数据、PDF，可选 LaTeX 源码。"在 arXiv 上训练"是什么意思并不清楚，要把 PDF 转文本，或者用 LaTeX 源码（一堆文件）。没有同行评审，但有审核；作者可以保留权利或选择 CC 许可，所以许可很清楚。元数据都是宽松许可，可以随便用；CC 许可的论文可以下载使用，他认为大部分 arXiv 论文都是 CC 许可。同样，不要爬，可以批量下载。

学生问模型生成的数据能不能用，他说后面会讲，简短的回答是大概可以。学生问用 Common Crawl 时怎么保证不包含盗版书网站，他说做不到，Common Crawl 里很可能有不该用的受版权保护的书和内容，只能诉诸合理使用；记住一切都有版权，书和你的网站在这点上没本质区别，只是出版的书作者真要打官司可能更容易保护自己。真要非常谨慎，后面有办法。

五、预训练数据集的演变

接下来看从 2019 年左右开始实际用于训练模型的数据集，注意各种收集和过滤方法的设计选择。

  • BERT（2018）：只用维基百科和书。书来自 Smashwords，一个任何人都能上传电子书的网站（2024 年约 50 万本）。2015 年有篇论文抓取了其中免费的书做成 BooksCorpus，那时大家都不在意这些，它在学术界用了很多年，后来因为违反服务条款被下架：免费能拿到不等于合法。BERT 的序列是文档而不是句子，之前的语言建模研究都以句子为单位。
  • GPT-2（2019）的 WebText：当时人们知道 Common Crawl，但觉得太乱。他们想了个巧办法：取 Reddit 上 karma 大于 3 的帖子的外链页面，好帖子应该链接好网站，得到约 100 万网页、40 GB 文本。没有发布，但有开源复现 OpenWebText，用得很多。
  • CCNet（当时的 Facebook）：目标是大规模高质量预训练数据，特别关注低资源语言，不想要只适用于英语的人工流程。做了去重；训练分类器做语言识别，只保留目标语言；质量过滤的思路是保留像维基百科的文档：用维基百科训练的语言模型给新文档打分，概率高说明像维基百科。因为能拿到多得多的数据，效果超过只用维基百科。这个工具后来出现在别的工作里。
  • C4（Google，2019）：这篇报告以 T5 模型和"所有 NLP 任务都是文本到文本"出名，但 C4 数据集也是重要贡献。当时大家觉得 Common Crawl 对自然语言基本没用：小数据集质量高，Common Crawl 一团糟，在上面训练出来都是垃圾，问题是怎样从中取出更大的高质量子集。C4 用规则：保留以标点结尾、超过 5 个词的行；去掉少于 3 句的页面；去掉含有任何脏词的页面；去掉"使用条款"之类的样板文字；有意思的是去掉含花括号的内容，过滤掉了大量代码，显然当时没考虑代码模型；只保留英语。结果是 1560 亿 token、约 800 GB 文本，比 GPT-2 的 40 GB 大得多。后来的分析显示其中有很多维基百科，专利也很常见。他们也用 Reddit 外链的思路做了一个类 WebText 数据集，用 12 次 Common Crawl 转储只得到 17 GB，而 WebText 有 40 GB，说明 Common Crawl 并不完整。
  • GPT-3：自己处理的 Common Crawl，训练质量分类器区分他们认定的高质量内容和其余内容；扩展版的 WebText（和 Common Crawl 有重叠，但分布更集中）；论文里称为 Books1 和 Books2 的"基于互联网的书籍语料"，具体是什么至今是个谜；维基百科。做了模糊去重，共约 570 GB、4000 亿 token。
  • The Pile（EleutherAI）：GPT-3 之后的开放努力之一，一群人在 Discord 上一起找高质量来源，至今仍很多样：Common Crawl、PubMed、Books3、arXiv、GitHub、维基百科、IRC、另一个书籍语料、哲学论文等，还有 Enron 邮件（Enron 2002 年破产后邮件被公开，是少数邮件数据集之一，分布有点怪）。书籍方面：Project Gutenberg 1971 年开始，只收经过版权确认的书，大多是公有领域；PG-19 是 2019 年之前的 Gutenberg 书籍。Books3 描述为来自影子图书馆 Bibliotik 的约 20 万本书，包括你喜欢的作者的所有书，2020 年没人在意，大家拿来训练，后来被下架，现在不能也不应该再用。Stack Exchange（2008 年起的用户问答）有意思在于它是问答格式，很接近真实应用：通常认为预训练数据是维基百科这样的原始文本，但网上有些部分本身就像监督数据，也许帮助模型学会某些问答行为，不是一切都神奇地"涌现"；它还有投票数等元数据可用于过滤，也提供可直接下载的转储。
  • Gopher 的 MassiveText（DeepMind，2021）：Gopher 从未发布，后来被 Chinchilla 取代，但数据描述很好，他建议去读，只是没说数据里具体有什么。MassiveWeb 只保留英语、去重，质量过滤用人工规则，部分原因是规则更可控；还有 C4、书籍、新闻、GitHub、维基百科，没说怎么来的。可以看到"用规则"和"用分类器"两派的分野。他们得到了海量文本，但模型只用了很小一部分。
  • Llama 1（2022 年左右）：他说这大概是最后一批详细描述数据处理的非完全开源模型之一。Common Crawl 用 CCNet 处理，但分类的是"页面是否被维基百科引用"，而不是是否像维基百科，思路是维基百科文章本身风格太固定，而被它引用的页面大概是好页面；C4；GitHub（处理成宽松许可）；维基百科；Books3 和 Project Gutenberg；arXiv（用 LaTeX 处理）；Stack Exchange，共 1.2 万亿 token。Books3 给他们惹了大麻烦：等于向全世界宣布用了它，一追溯，来自 The Pile，再追溯，来自影子图书馆。这就是现在大家不再谈数据的原因。数据没发布，但描述足够详细，Together 据此复现了 RedPajama v1，又被别处使用；RedPajama v1 最初也含 Books3，后来去掉了。早期关于版权的决定影响深远。
  • RefinedWeb：主张"只要网页数据就够了"，不用 GitHub、arXiv、Stack Exchange 这些专门来源。认真做了 HTML 到文本的转换，用 Gopher 的规则过滤（保留像英语的内容），明确说避免基于机器学习的过滤，以免引入偏差、选出过窄的子集；去重后 5 万亿 token，发布了约 6000 亿。
  • FineWeb（Hugging Face）：复现并改进 RefinedWeb，用当时所有的 Common Crawl 转储，同样用人工规则过滤以免引入偏差，去重，去除个人信息，得到 15 万亿 token。数据集越来越大。
  • Dolma（AI2）：自己处理的 Common Crawl，加上 The Stack、C4 等；Reddit 数据来自 Pushshift 项目，那时还能拿到；AI2 有自己的学术论文抓取（Semantic Scholar），据此做了论文数据集。Common Crawl 处理：语言识别用模型，质量过滤仍避免用模型，用规则加分类器去除有毒内容，得到 3 万亿 token。
  • DCLM（DataComp-LM）：他认为这大概是基于模型的质量过滤开始成为常态的节点。初衷是定义一个标准流程，让大家以统一方式试验数据方法，但大家主要直接用它发布的数据集。DCLM-Pool 是完全未过滤的 Common Crawl 处理结果，有 240 万亿 token，可能比任何人实际训练用的都多，但大量质量很低。流程：只保留英语，用规则缩小范围，去重，再做基于模型的过滤，最后只剩约 1.4%，效果相当好。分类器的正例有点奇怪：OpenHermes（GPT-4 生成的指令数据）和 ELI5（一个 Reddit 版块的问答）；负例来自 RefinedWeb，基本就是网络本身。训练一个 fastText 分类器（可以看成线性分类器），得到 3.8 万亿 token，这个"神奇的"分类器胜过他们试过的其他方法。一段时间里它在开源社区是质量过滤的金标准。
  • Nemotron-CC（NVIDIA）：认为 DCLM 过滤太激进，删掉了大部分数据，只剩 3.8 万亿 token，需要更多。做法更精细：让现有模型给网页按教育价值打分，生成标签，训练 fastText 分类器；也用 DCLM 的分类器；并大量使用合成数据，这是较早重用合成数据做预训练的主要数据集之一：低质量数据让语言模型改写成更像维基百科的样子；高质量数据让语言模型生成各种任务，比如根据维基百科文章生成问答、摘要、提取关键信息。得到 6 万亿 token，比 DCLM 大得多，其高质量子集胜过之前的数据集。作为参照，Llama 3 用 15 万亿 token 训练，Qwen 3 用 36 万亿；但论文里的 token 数不一定是唯一 token 数，可能包含重复，训练两个 epoch 就是两倍，要小心看。

这些方法在某个层面上很相似：拿一份网络抓取，决定用规则还是用模型过滤；用模型的话，要定义什么是好数据，训练分类器，对所有文档打分筛选。存在取舍：可以拿到 240 万亿 token 但质量很低，也可以只要 1 万亿，中间有个最佳点。

代码：The Stack

2022 年已经很清楚代码会非常重要。The Stack 第一版克隆了 1.37 亿个仓库，保留宽松许可的，去掉完全重复和近似重复，得到约 3 TB 代码。2024 年的 The Stack v2 增加了 GitHub 的 issue、评论、PR 等元数据，来自 Software Heritage 的仓库，以及爬取的各种文档网站。处理包括：去掉二进制文件和恶意软件；过滤机器人生成的 PR 等；去重；去除个人信息；对大量 PR 等做下采样，保持代表性、控制数据量。他觉得一个巧妙的做法是：Python、C 等语言很多，Nim 这类低资源语言很少（他之前都没听说过），于是把代码编译成 LLVM 中间表示，把低资源语言和中间表示并排放在一起，模型就能学到数据少的语言和数据多的共享底层表示之间的映射。再加上其他各种好数据，The Stack v2 主要是代码，加上训练编程模型用的其他东西。PR 和元数据本身不是线性序列，要线性化，关键决定是给多少上下文：一个事件可能只改了一行代码，学习它大概需要周围几行，甚至整个文件。最终训练的 token 像一种类 XML 结构：PR、一系列 diff、评论事件、审查状态等。模型学的不只是生成代码，还有围绕代码的软件开发过程。

只用宽松许可数据：Common Pile

互联网上几乎所有数据都有版权，有些是宽松许可，有些在公有领域；可以诉诸合理使用，但还没定论。如果你非常厌恶风险，认为"不确定可以就是不行"，就是 Common Pile 的做法：只用宽松许可数据，能训练出多好的模型？他们搜遍互联网找值得训练、且宽松许可的数据：The Stack v2 和代码；很多政府文件是宽松许可的；wiki；部分网页；一些新闻网站；学术论文；在线论坛；公有领域内容；教育资源等，共 8 TB，对宽松许可数据来说已经相当多。

这比看起来难得多，不是看到 Apache 或 CC 就算数：

  • 许可洗白：人们对许可很随意，可能拿有版权的作品贴个 CC BY 就放上网，任何人都能这么写，很难判断真假。
  • 汇编的许可不延伸到单个作品：比如 Dolma 整体是宽松许可，但其中单个作品未必是。Hugging Face 上很多数据集标着宽松许可，深挖下去单个作品并不是。
  • 他们放弃了合成数据：用未授权数据训练出来的模型生成的数据，地位不清楚。技术上那些开源权重模型是 MIT 许可，怎么用都行，但那些模型多半也用未授权数据训练过，严格说有点像数据洗白。

结果：和第一代 LLaMA、MPT、Qwen 等比较，在一系列基准上不算差，肯定不如 Qwen，但胜过 2023 年左右的老模型。他的结论是可以做得还行，但不训练更多 token 仍很难竞争；这不是定论，努力的话也许能从公开宽松许可数据中榨出更多。

六、小结

数据是很丰富的话题，不是从天上掉下来的，也不是去 Hugging Face 下载一下就完事。数据要有来源，而且有技术和社会两方面的背景：最上层的互联网是一堆在线服务，要有人做原始数据的工作，可能是网站提供转储，也可能是有人建爬虫；再有人决定怎么处理成可用形式，过滤、转换、去重，这些都影响最终模型的质量。过滤大概是最重要的环节之一，从 200 多万亿 token 到不到 3 万亿，缩减巨大，值得很多关注。很多语言模型的架构大致相同，数据怎么处理可能带来很大差异。数据还有很多法律和伦理问题，远超这一讲能覆盖的。而且这个过程很乱，不像课程其他部分那样有第一性原理，目前很多是凭感觉：定义一个分类器、一条规则、设个阈值。所以有很多改进的机会，做作业四时可以想想有没有更好的办法，这可能成为研究方向。下一讲继续讲数据，包括后训练数据和更多过滤方法。
