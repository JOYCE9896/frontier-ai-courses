第五讲：GPU 与 TPU

GPU 和 CPU 的设计哲学有什么不同，SM、线程、warp、block 和内存层级，TPU 与 GPU 的异同，让 GPU 变快的六个技巧（避免分支、低精度、算子融合、重计算、内存合并访问、分块），解释矩阵乘法吞吐量的怪异曲线，最后用这些拼出 FlashAttention

主讲：Tatsunori Hashimoto
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、为什么要懂硬件

这是系统部分的开始，接下来是 GPU、并行和推理。Tatsu 说系统是整个技术栈里最"讲得通"的部分，每一步都能推理，但刚接触 GPU 时会觉得既神奇又怪异。班上大约四分之一的人上过 GPU 编程课。他承诺讲完后大家能看懂一张图：横轴是方阵的维度，纵轴是矩阵乘法的吞吐量，按理矩阵越大吞吐越高，但图上有各种怪异模式，某些尺寸慢得多。即使不做系统，研究架构时也需要懂模型在硬件上怎样执行，才能有效利用资源。他说自己并不是做系统的，推荐几份资源：Horace He 的博客，爱好者社区 GPU MODE（原来叫 CUDA MODE），以及 Google 那本讲 TPU、现在也讲 GPU 的书，书里有练习，作业里会有类似的题。

这一讲分三部分：GPU 的硬件和编程模型；六个让 GPU 变快的技巧；用这些重新发明 FlashAttention，作为"胜利巡游"。

二、GPU 的硬件和编程模型

算力越多，语言模型越好，这是通行的货币；更快的硬件、更好的利用率、更多的芯片、更好的并行都能推动进步。如果是 90 年代，会关注时钟频率：CPU 串行执行指令，让指令越来越快。晶体管变小、频率变高的登纳德缩放在 2000 年代走到了头，晶体管数量继续增加，但更小不再意味着更快，有基本的物理原因。于是转向横向扩展：让更多单元并行执行，这就是 GPU 和并行的故事。从 K20、M40 到 P100、V100，浮点运算能力开始超指数增长，几乎所有的算力增长都来自 GPU：2017 年 V100 引入了张量核心（Tensor Core），之后有结构化稀疏、FP8 等低精度格式。

CPU 为快速串行执行设计，处理复杂的分支和控制流，控制单元大、算术逻辑单元少，追求低延迟。GPU 追求吞吐：一个任务可能要很久才完成，中途可能停下去做别的再回来，但所有任务加起来的总吞吐很大，靠的是成百上千个轻量的计算核心并行执行。

GPU 的基本单元是流式多处理器（SM），可以看作一个核心，是独立的计算单元，内部有多个流处理器并行执行线程，能访问各种内存。A100 有 128 个 SM（课上说法），每个可以独立编程、独立执行任务。更重要的是内存：

  • 寄存器：最快、最小。
  • L1 缓存和共享内存：在每个 SM 内部，约二三十个时钟周期就能读到。
  • L2 缓存：在芯片上，但慢一些。
  • 全局内存（HBM）：在计算芯片外的存储芯片上，比 L1 慢约十倍。说 H200 有 144 GB 内存，指的就是全局内存。

为什么不把整块芯片都做成共享内存？贵几百倍，也耗电得多，所以实际的加速器都有层级，要用好层级。被 NVIDIA 收购的 Groq 就用了大量 SRAM，对推理等负载很有用，但多数加速器仍是层级结构。学生问共享内存和 L1 缓存的区别：缓存自动存最近访问的数据，你控制不了；共享内存是可编程的，你可以主动放东西进去、取出来。

执行模型有三个角色：

  • 线程：轻量的并行执行单位，遵循 SIMT 模型，一组线程执行完全相同的指令，只是输入不同，这是可编程性和效率之间的取舍。
  • 块（block）：一组线程，保证在同一个 SM 上运行，因而共享该 SM 的共享内存，这对后面的分块很重要。
  • warp：调度单位，32 个编号连续的线程一起执行，减少调度开销。同一 warp 里的线程执行相同指令，调度器决定下一个执行哪个 warp。

内存模型：设备代码可以读寄存器（比如存数组起止地址），读 SM 内的本地内存，读块内共享的共享内存（线程间要传递或复用的数据放这里），读远处的全局内存（要付延迟），还有不常用的常量内存，必要时还能和主机（CPU）内存来回传数据。关键是：一旦出了共享内存就会慢，所以要组织块以减少全局内存读取，这是整讲的主线。

TPU

多数人写代码会用 GPU，但 TPU 越来越流行，而且是 GPU 的"另一条进化路线"，能看出什么相同什么不同。有意思的是两者高层上很相似，是趋同进化：要造节能的机器学习加速器，最后会走到同一个地方。TPU 更简单、更专门为机器学习优化，控制单元更轻，矩阵乘法单元更大；同样有专门的矩阵乘法电路、并行向量运算部件、控制系统，同样有慢的高带宽内存和快的本地内存。最大的区别其实在芯片之间的网络，而不是单个芯片。Google 的那本书有一张表，把 GPU 的每个概念对应到 TPU：GPU 的张量核心几乎完全对应 TPU 的 MXU，底层都是脉动阵列，把数据流进流出做矩阵乘法。一个很容易混淆的地方：TPU 把它的处理器叫"TensorCore"，GPU 把矩阵乘法单元叫"Tensor Core"，要看上下文区分。

主要区别在单元数量：H100 约有 132 个 SM、528 个矩阵乘法单元；TPU 只有两个并行单元、8 个矩阵乘法单元（大致可比的规模）。TPU 靠少量很大的矩阵乘法单元，GPU 靠大量较小的单元，后者更灵活，TPU 则被锁定在大矩阵乘法上。他说他最近一篇论文扫描批大小，只扫到 64，因为张量核心不接受小于 64 维的输入。但两者都依赖快慢内存的层级和矩阵乘法单元，所以这一讲的核心概念在两者间通用。

GPU 很成功：要更多吞吐就加 SM，只要内存带宽跟得上；编程看似简单，因为是 SIMT，写的是"这些指令作用在所有输入上"，有点像函数式编程；线程很轻，可以随时停止和启动，某个 warp 卡住时调度器可以换另一个，提高吞吐。早在张量核心之前，人们就意识到图形硬件的大规模并行适合科学计算，有论文利用着色器做矩阵乘法，他说那是很酷的黑客作品。V100 之后 NVIDIA 有了专门做矩阵乘法的硬件，矩阵乘法成了机器学习中唯一享有特权的运算，比其他浮点运算快十倍以上，所以近期任何能随算力扩展的架构都会以矩阵乘法为核心。

硬件各部分增长速度不同：总算力增长很快，内存带宽增长较慢，设备间互联带宽也慢。早期计算和内存差距不大，没人太在意内存；越往后差距越大，所以今天讲的优化大多是内存优化，充分利用硬件越来越难。学生问未来芯片会不会因此改变布局，他说推理领域更疯狂：去年开始流行预填充与解码分离，矩阵乘法密集的预填充放在一种芯片上，受内存带宽限制的解码放在另一种芯片上；有个中国开源模型（Step 3）甚至把不同层分开，注意力放在一种加速器上，MLP 放在另一种上。差距越大，利用宝贵快速内存的技巧就越值钱。学生还问 L2 为什么比 L1 慢，他说主要是物理距离和互连（两者都是 SRAM），TPU 在 L2 对应的那层上做了不同取舍，所以快得多，这是它的卖点之一。

三、让 GPU 变快的技巧

屋顶线模型：在某个点之前受内存限制，吞吐随算术强度沿对角线上升；之后受计算限制，变平。要在平的部分，就要提高"每次读内存做的计算量"。第一个技巧和内存无关，是 GPU 特有的；其余都是尽量减少内存搬运。

  1. 避免分支（控制发散）：GPU 上同一 warp 的线程必须执行同一条指令。写一个 if 语句，CPU 会选一个分支执行；GPU 上实际是两个分支都执行一遍，不属于当前分支的线程被屏蔽、闲着等待。所以有条件语句时会出现大段计算空档。这就是为什么 GPU 代码里实现 ReLU 往往是乘以掩码，而不是用 if 更新一半元素。
  2. 低精度计算：NVIDIA 投入最多的方向之一。那条超指数增长曲线有相当一部分来自数字表示：FP32 到 BF16 到 INT8。位数减半，要搬的字节就减半。比如对长度为 $n$ 的向量做 ReLU，FP32 时每次运算读 4 字节、写 4 字节，共 8 字节对应 1 次浮点运算；降低精度就减半（他提醒这个"每次运算多少字节"是算术强度的倒数）。实际的低精度矩阵乘法很复杂：在张量核心里先把输入降精度再相乘，部分和用全精度累加，输出可能是 FP32。难点不在于降精度，而在于决定每个操作用哪种格式：矩阵乘法的权重和激活也许可以低精度，softmax、指数也许要 FP32 或 BF16，花了好几年靠缓慢的经验工作，才知道哪些能降、怎样降还能保持训练稳定。

    到了 FP8 就没有统一格式了：E4M3（4 位指数 3 位尾数）和 E5M2 用在不同地方。传统 FP8 训练给整个张量一个 FP32 的缩放因子，因为只有 4 位指数，很容易上溢下溢；但一个矩阵里不同部分的数值大小可能差很多，于是有了 MXFP8：每 32 个元素一个缩放因子，缩放因子本身也是 8 位（E8M0，只有指数位，都是 2 的幂），元素用更多尾数位。问题是转置后缩放的分组模式不一样，要重新量化，所以实际训练时每个量化矩阵存两份，一份原矩阵、一份转置。还要决定只量化哪些"安全"的层（学生说首层和末层难量化，他说末层对损失影响是一阶的，量化容易不稳定、损失上升）。综合下来，FP8 训练在矩阵乘法上大约省 20% 到 30%，视矩阵大小可能更多，但不是两倍，因为量化本身有开销；他说很多前沿实验室为了算力收益在用 FP8 训练。MXFP4 已经实现：所有可能的值就是 $-6$ 到 $6$ 之间那几个，每 16 个数一个 E4M3 的缩放因子。有论文用 FP4 训练过，但他没听说在实际中用它训练大模型，他认为下一代模型可能会用。学生问缩放因子要不要训练，他说训练时没有梯度，是实现方式决定的，比如扫描取最大最小值，或用历史统计量；推理时可能会拟合。学生问结构化稀疏，他说 MoE 就是一个成功的结构化稀疏例子，Chris Ré 等人研究过很多结构化矩阵，但表示能力的损失和算力收益相抵，实践中效果一般。学生问量化的最佳实践，他说大致是训练一个更大的模型再量化，结合量化感知训练和训练后量化，还有很多没弄清楚，业界团队也还在做量化的"科学"。

  3. 算子融合：把 GPU 想成工厂，内存是仓库，计算单元是车间，中间一条小传送带。算力上去了，传送带就是瓶颈，操作多的时候来回搬尤其糟糕。不如建一个大车间，原料一次进、成品一次出。比如计算 $\sin^2 x + \cos^2 x$，PyTorch 的计算图是 sin、cos、各自平方、相加，朴素执行时每一步都从全局内存读、再写回。融合成一个内核，只读一次全局内存，在 SM 里算完，再写回一次。这种简单的融合编译器能自动完成，比如 torch.compile 或 JAX 的编译，复杂的融合有时要手工做。
  4. 重计算：反向传播时通常保存前向的激活。比如连续三个 sigmoid，前向要读 $x$、写三个中间结果，反向再读回来，共 8 次内存读写，算术强度很低。如果计算很便宜、内存很贵，可以把中间激活都扔掉：前向只写最后的输出；反向时读入输出梯度和 $x$，现场重新算出中间值，写出 $x$ 的梯度，共 5 次内存访问，多花一点计算，省下内存访问。用系统的眼光就会想到重计算。
  5. 内存合并访问：全局内存是 DRAM，按"突发段"读取：访问一个位置时，同一段里相邻的几个值几乎是免费一起读出来的（比如一次可以返回 128 字节），因为存储单元排成网格，选中一行（或一列）的代价高，之后读其中多个元素就便宜了。如果一个 warp 的所有线程访问落在同一个突发段里，就叫合并访问。对按行存储的矩阵：如果每个时钟周期每个线程读一列中的一个元素，每次都落在不同的突发段，实际上把整个矩阵都读了，只为取一列；反过来按行读就能一次满足所有线程。所以行优先还是列优先值得考虑。
  6. 分块（tiling）：影响最大的技巧，尽量利用内存层级，把访问分组、放进共享内存。矩阵乘法中，朴素做法下每个输入元素要从全局内存读 $n$ 次（$n\times n$ 的矩阵）。把矩阵切成小块：比如先把 $M$ 左上角的块和 $N$ 左上角的块从全局内存载入共享内存（只付一次慢速传输），输出块也放在共享内存，在共享内存里把两块相乘、累加部分和，算完再写回。分块大小为 $T$ 时，每个输入从全局内存读 $n/T$ 次，在块内读 $T$ 次，全局内存访问减少 $T$ 倍；极端情况 $T=n$，从全局内存只读一次。学生问 PyTorch 会不会自动做，他说任何矩阵乘法内核底层都做分块，自己写特殊运算时要考虑类似的局部复用；PyTorch 也不完美。

    分块很强大但也复杂。块大小 128×128 时，256×256 的矩阵正好切成四块；维度加 1，就多出两条几乎空的细长块。所以块大小要权衡，取决于合并访问、加速器共享内存大小和矩阵尺寸。torch.compile 的 max-autotune 选项开了之后会跑十几分钟的基准测试，就是在试各种块大小，往往能带来不小的提升。和合并访问有关的另一个问题：如果突发段正好是块的宽度，读一块几次就够；矩阵尺寸差 1，块的边界和突发段错开，读一块至少要两倍的读取。这时要做填充，把突发段的边界和块对齐。所以 Andrej Karpathy 做 nanoGPT 速通时说，把词表大小从 50257 改成 50304，速度提高了 25%，填充反而变快了。学生问要不要考虑块大小，他说除非自己写内核，块是更底层的事，但要注意矩阵的尺寸，最好是 2 的幂，至少能被 32 整除。

四、解开矩阵乘法曲线之谜

  • 对角线上升的趋势：屋顶线模型，每次内存读取要有足够的计算才能喂饱计算单元。
  • 分成几条线：按矩阵维度的整除性上色，只能被 1 整除（连偶数都不是）或只能被 2 整除的吞吐很差；能被 8、16、32 整除的好得多，16 和 32 表现一样好。不是因为 2 的幂有魔力，而是 16、32 足够大，能凑满突发窗口，读整块时能合并访问，对齐影响很大。
  • 周期性的骤降：从 1792 到 1793，吞吐突然大跌。块大小是 256×128，1792 时有 98 个块；1793 时两个维度的块数都加 1，变成 120 个块。这本身不至于跌这么多，关键是 A100 有 108 个 SM：98 个块一轮就能放下，120 个块放不下，做完 108 个后还剩 12 个，要再跑一轮，大部分 GPU 都闲着。这叫波次量化（wave quantization）。

小结：在 GPU 上让机器学习负载变快，主要是内存、内存、内存：合并访问，融合操作减少读取，必须读的就复用（分块，放进共享内存），以及用其他资源换内存（量化、重计算）。学生问为什么不多放 SRAM，他说一是造价高，二是要靠得很近、信号传播难，三是 SRAM 需要持续供电才能保持数据，很耗能，考虑总拥有成本时不想要巨大的 SRAM 芯片。整除数大于 32 还有用吗？对这个现象没用，只要能被突发大小整除就行。为什么是 108 个 SM？"得去问黄仁勋。"学生问晶圆级芯片，他说他不熟，听说编译非常复杂，会有波干涉之类可怕的效应。

五、FlashAttention

FlashAttention 是注意力能力近年最大的改进之一，完全来自系统：从 PyTorch 的朴素实现变成一个精巧融合的内核，延迟大幅下降，内存效率高，可以做更大的注意力，很多收益来自减少从 HBM 搬运的数据。论文说只做了两件事：分块和重计算，使内存访问次数低于平方级。现在这些我们都懂了。

注意力有三次矩阵乘法（算 $Q$、$K$、$V$ 相关的乘法）和一个 softmax。矩阵乘法用分块做，论文的图 1 就是分块矩阵乘法。难点是 softmax 是全局操作，把所有块联系在一起，看起来不能分块。关键在于在线 softmax：普通算法是先求最大值（为了数值稳定要减去它），再对所有元素取指数，再归一化；在线算法边看边算，维护目前为止的最大值和指数和，每遇到更大的数就替换最大值并修正已有的累加和，最后除以累加器。因为是在线的、逐块进行，不需要看到其他块就能处理当前块，可以算出当前块的结果、保存少量部分统计量，继续往下。

FlashAttention 2 论文里有一张图：虚线框里的在 SRAM 中分块完成，蓝色框在 HBM 中。计算 $QK^\top$ 的分块乘积，留在 SRAM 里取指数；在每个块上维护运行中的 softmax 统计量，移到下一个块时保留部分和（数量很少，可以放在共享内存或寄存器里）；最后以分块形式乘上 $V$，再在最后做除法。尽量一起完成，不来回搬运。反向传播时，如果保存激活，还得存一个 $n^2$ 大小的注意力矩阵；FlashAttention 不存，而是在反向时逐块重新计算，这就是重计算那部分。

总结：要理解硬件，GPU 驱动着规模和算力，要一直懂到底层细节，才明白为什么做某些决定，他不希望大家盲目照搬"矩阵维度取 32 的倍数"，而是真正明白原因；算力增长的方式意味着要以矩阵乘法为核心，计算与内存的差距意味着要仔细考虑数据搬运；FlashAttention 这类工作以及对硬件敏感的架构设计，对未来系统的性能至关重要。
