第十五讲：后训练：SFT 与 RLHF

从 GPT-3 到 ChatGPT：指令微调数据的演变，风格、知识与幻觉，安全微调，中期训练，RLHF 的数据和标注者，模型标注，PPO 与 DPO，以及过度优化和模式坍缩

主讲：Tatsunori Hashimoto
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、从 GPT-3 到 ChatGPT

现在离开预训练，进入 Tatsu 所说的语言模型中更乱的部分。数据总是乱的，但后训练在很多方面几乎是手艺活。到目前为止，你大概能做出加强版的 GPT-3：多用点 FLOP、多点数据，可以比 GPT-3 好一点。但 GPT-3 这种又大又强的基座模型，能带来的用处终究有限。如果你最早接触的是 ChatGPT，回头去用 GPT-3，会觉得"这是什么，有什么用？"，只能做文案之类不需要可靠性和指令遵循的小任务。这一讲从 GPT-3 走到接近 ChatGPT，下一讲从 ChatGPT 走到 o1 这类思考模型，这个过程叫后训练。

他强调指令遵循有多了不起：塞进一个又长又复杂的提示，拿回很合理的回答。在 GPT-3 时代，细粒度控制基本不可能，只能放一些少样本示例，示例够好才能得到合理结果；到 GPT-3.5、GPT-4，模型能一次性完成很长的、程序化的提示。预训练始终是基础：不预训练、只靠后训练，什么都得不到，因为预训练以广泛多样的方式扩展。有了预训练，还要从这锅"原始汤"里提取想要的行为，这需要明确得多的数据收集、引导，以及大量麻烦的工程。他说架构那些东西你也许觉得乱，但远不能和真实后训练的乱相比。

要先说明：关于前沿后训练的信息相当稀少，这一讲引用的材料很多相当老，是 ChatGPT 竞争白热化之前的。比如 RLHF 论文 Learning to Summarize from Human Feedback 很详细，附录里有详细的标注指南，告诉标注者怎样给反馈；2022 年 Anthropic 的 HH 论文也类似。竞争加剧后，几乎没有厂商愿意公开后训练过程，数据是商业秘密，所以不可能讲现代模型的标注指南之类的东西。开源模型的配方很多依赖蒸馏，和前沿实验室真正做的人类数据收集（很麻烦、很棘手）性质很不同。他举了一个例子：2023 年 Scale AI 的内部文件泄露，里面很坦率地讨论后训练数据，比如想让 Google Bard 变好，但搞不清为什么 GPT-4 好那么多，于是要逆向分析，让标注者写出比 GPT-4 更详细、更好的回答。这种竞争一直在发生，所以有些细节讲不了。

算法上我们相当清楚发生了什么，但算法不是秘方，杠杆在数据。RLHF 论文的配方很直接，两步：先收集示范数据，每个提示由标注者写参考回答，做监督微调（SFT）；再做某种强化学习，让模型行为更符合人类认为好的回答。

二、SFT 数据

SFT 的方法大家都会，基本和预训练一样，唯一真正的区别是训练数据，所以这部分几乎全讲数据。他按时间顺序梳理了开源世界里 SFT 数据的发展：

  • FLAN（Google，用于 T5 等）：NLP 领域已经收集了很多输入输出形式的监督数据集，全拿来训练。很合理，但后来证明不是正确的做法。
  • Self-Instruct 及其后续：模型越来越好，甚至可能比部分标注者好，为什么不让模型自己生成高质量回答？
  • 蒸馏式的 Alpaca，以及 Berkeley 的 Vicuna（用网上用户分享的提示作为输入来蒸馏）。
  • 完全由人驱动的 OpenAssistant，有点像维基百科，一群人一起写提示和回答。
  • 新一代的 WizardLM、Tülu 3 等：语言模型是很好的合成数据生成器，用越来越复杂的方式生成指令数据。
  • 最近重点不再是聊天，而是 Agent 和工具使用，出现了生成工具使用和 Agent 数据的新一代 SFT 流程。

闭源世界里，公司可能互相蒸馏，也收集人类数据，怎样收集人类数据是重要成分，这些讨论都没有反映。学生问输入输出对的正确性有多重要。他说这个问题很微妙：顶层答案是尽量收集最高质量的回答，坏数据会教模型做坏事；但事实上你可以用各种奇怪的东西做 SFT，模型照样学会遵循指令，Percy 以前的学生有篇论文甚至不用回答就把模型训练得能遵循指令。预训练的泛化让你可以用较差的数据蒙混过关。

看具体数据：

  • FLAN：多任务后训练的思路很有前瞻性，要做下游任务，就把所有下游任务收集起来训练。但内容有点怪：比如一封邮件后面接一句"为这封邮件写一个主题行"，右边是主题行。你大概从没这样提示过模型，更别说指令放在最后。原因是它由现有数据集生成：Enron 邮件数据集有正文和主题，就能做成主题预测任务；摘要任务取自某个大型摘要数据集，"为这篇文章写要点"，但和 ChatGPT 比摘要很短，仔细看还常有幻觉，包含输入里没有的细节。原始 NLP 数据集质量并不高，训练时会继承它们的缺陷，结构上的不自然也一路带下去。另外，构建 FLAN 时的一个理论是后训练也需要规模，所以用了海量数据；后来发现数据集小得多也行：足够强的预训练模型，用很少的高质量样本就够了，因为预训练的泛化能带你走很远。所以 FLAN 在质量与数量的权衡上站错了位置，当然在探索完整个空间之前无从知道。
  • Alpaca：ChatGPT 出来后，他的学生蒸馏 ChatGPT 的输出得到输入输出对，输入更自然，输出更长更像聊天。他们发现这些样本能可靠地让模型表现出类似 ChatGPT 的行为，但只在原版 LLaMA 上，预训练和后训练都要到位。大家意识到有了这类聊天数据，做出类 ChatGPT 系统其实不难，细节仍然难，但能走大部分路。
  • OpenAssistant：当时大家很乐观，觉得只要收集到足够高质量、足够大的指令数据集，就能追上闭源大实验室。OpenAssistant 是大规模众包，志愿者写难而有趣的提示和高质量回答，像维基百科那样在规模上做出高质量的东西。很令人钦佩，产出了相当多数据（他记得一万多条），之后项目停滞。回答很长、很详细，是专家水平。
  • 最新的指令数据：产品从聊天界面走向完整的 Agent 系统，要工具调用、待办清单（用过 Claude Code 或 Codex 就知道它会列清单逐项勾掉）。比如 NVIDIA Nemotron 的 SFT 数据有很大一块是 Agent 式样本，不仅有 assistant 字段里的回答，还有和文本并行的工具调用，都是直接监督进模型的。数据越来越结构化。

几个大的转变值得记住：一是"聊天化"，经典 NLP 数据集即使质量高，也像是输入到程序化输出，人们不想和 NLP 基准说话，想和人说话，于是转向更详细、更像人的回答；二是转向更高质量的标注者和更多细节，比如请专家写回答；三是工具使用，以及找到合适的接口和 API。

收集 SFT 数据要注意什么

假设你负责收集 SFT 的人工标注数据，要考虑格式、回答中放多少知识、要多少数据、安全数据怎么收集等。

长度和风格的变化是后训练很大的一部分。人们说 Claude 的语气和 ChatGPT 不同、ChatGPT 太啰嗦，这些都是数据收集者有意的决定，各数据集的回答长度差别也很大。评估偏好时，风格因素影响极大：人们很容易选带项目符号列表、更长更详细的回答。这在"给你两个回答选哪个好"的评估中很自然，更详细、更像列表的回答通常确实不错，但会让聊天机器人的语气和人明显不同。如果看的是用户参与度信号（大多数公司都看），很容易自欺，以为数据更好了，实际模型能力没变。在一些后训练数据集上训练，AlpacaEval 这类偏好指标变化很大，但标准基准几乎不变，模型并没有更聪明，只是参与度信号变了。所以风格控制和能力控制要分开考虑。

知识与幻觉：OpenAssistant 本意是最高质量的后训练数据，常有这样的回答：引用一篇文章，比如 Bivens, J. 和 Mishel, L. 关于企业高管薪酬的文章。在上面做 SFT 同时教了两件事：通过下一个 token 预测，教模型关于这个引用的知识；同时教模型"回答时给出参考文献是好的"。后者有时会出问题：模型会错误泛化，编造参考文献而不是给出真实的，因为模型不一定知道某个文献是真是假。一种民间说法（他认为没错，也有不错的实证支持）是：在 SFT 阶段训练模型说出它不知道的事实，会让它产生幻觉，因为它同时在泛化知识和格式，"格式 + 未知知识"等于教它硬说出不知道的东西。有研究显示，用模型不知道的信息训练会导致幻觉和对知识的过拟合，只用已知事实训练则没有这个问题。John Schulman 的论点是这就是需要强化学习的原因。他说 Schulman 是做强化学习的（PPO 是他提出的），当然支持 RL，但论点是对的：要让模型知道自己知道什么、不知道什么，必须依赖策略本身，不能由外人把知识硬塞给它。

所以，如果模型本来不知道，最高质量的数据也未必该拿来训练；长尾知识有时反而有害，尤其和"参考文献："这种标记一起出现时，会迫使模型在后面写出一条文献。知识存储是很微妙的概念，不能只想着"把知识塞进去"，后训练阶段放什么监督要很小心。学生问长尾知识怎么定义：没有正式定义，他以前用维基百科文章长度作为知名度的代理，训练不知名的内容，模型幻觉更多。学生问 RL 为什么能帮助减少幻觉。他给了一个民间解释：假设模型内部激活里有一个"我知道"的方向。SFT 强迫它生成参考文献，于是不管知不知道都生成；RL 时你可能发现，在"我知道"方向上生成参考文献得到好奖励，在"我不知道"方向上生成得到坏奖励，于是学会把内部的"知道与否"映射到是否输出参考文献。如果模型内部某处知道自己知道什么，RL 能把它提取到输出策略中；如果完全不知道，RL 也帮不了，它解决不了校准本身的问题。学生追问 SFT 不也会惩罚吗？他说 SFT 隐式地惩罚任何不是这个确切序列的东西，它本身没做错，这个序列是对的；问题在泛化：一个样本同时教了模板和知识内容两件纠缠的事，按模板错误泛化就麻烦了。

安全

到了后训练就要直面真实使用：预训练的人住在象牙塔里压缩世界，后训练的人要考虑有人用你的系统做政治操纵和虚假信息，做个性化的鱼叉式钓鱼，你在某种意义上是防止滥用的最后一道防线。各公司实际执行安全控制的方式，就是让系统拒绝恶意输入，这落在后训练团队身上。公开的安全 SFT 信息比能力 SFT 还少。Llama 2 的描述已经算比较详细，但连安全微调用了多少样本都没说，他觉得很离谱。框架都一样，平衡两件事：违规率（放过多少坏请求）和误拒率（有人问"怎么 kill 一个 Python 进程"，机器人说"我不能让你杀死任何东西"，用户会很恼火），要在两者之间找好的帕累托权衡。数据量通常是几千到几万条，Llama 2 大概几千条。

现在想看后训练怎么做，最好的参考大概只有 Tülu 3，AI2 为 OLMo 做的后训练流程，是少数能看到一个性能不错的完整后训练流程的地方。它的安全部分约 5 万条，生成方式很简单：之前的 WildChat 项目给很多人免费的聊天访问，换取他们的对话记录；从中过滤出试图做的不安全行为和越狱尝试，大规模挖掘，再构造偏好的回答：抵抗越狱，或者拒绝。从闭源公司的技术报告和模型卡看，做法类似：看使用数据，找出不安全行为，让标注者打地鼠。

如果没玩过 SFT，你会惊讶于对足够强的模型，引导它只需要很少样本。做安全微调，拿 500 条（找到或合成不安全的请求，写上拒绝），遵循恶意指令或仇恨言论指令的比例就会大幅下降，对模型只是很小的推动，却带来全面的安全改善。可以理解为预训练后的模型里已经有一根"安全还是不安全"的轴，不需要多少样本就能拉出来。但能用少量样本引导，不代表更多样本没用：OpenAI、Anthropic 想划出很细的安全界限，就需要大规模数据收集。

小结：SFT 最好的情况是提取预训练中已有的行为，把模型的正确模式拉出来，这时指令微调效果很好，很少的高质量数据就能让模型按你想的做；加入事实正确的数据有时反而会伤害幻觉表现；不需要很多数据，可以重质量不重数量。学生问怎么知道某个行为已经在预训练里，他说这就是他说法不严谨的地方，其实不知道；能知道的是哪些东西不在预训练里，比如很罕见的编程语言，用 SFT 很难泛化过去。学生问有说法 SFT 会破坏特征、RL 只是上调或下调它们，他说两者界限很模糊，比如专家迭代看起来就是加了些花样的 SFT；区别更多在反馈类型：SFT 是密集的教师监督，RL 是策略自己产生输出、自己受强化，所以可能偏离得没那么远。

方法与中期训练

方法是最无聊的部分，就是梯度下降，loss.backward() 就完了（他把这张图放上去几乎是开玩笑）。但有一个重要趋势：把指令微调变成预训练的一部分。以前预训练和后训练是分开的，先在网页数据上预训练，再后训练；后来大家想，为什么不混在一起？现在大量高质量数据、甚至指令数据，被混进训练末尾的衰减阶段，这能扩大指令微调的规模，也能加重高质量数据的权重，效果很明显，据他所知大家都在这么做，大多数发布报告里都有中期训练或"第二阶段预训练"，换了数据配比。他的一个不满：现在别人说"这是基座模型"，某种意义上是谎言，传统意义的基座模型是预测互联网数据的下一个词，而现在的基座模型在 UltraChat 等专门为聊天合成的数据上预训练过。

MiniCPM 很清楚地展示了两阶段配比的变化：第一阶段是标准预训练，各种互联网数据；第二阶段换成更高质量、更像聊天的数据：Stack Exchange 问答、UltraChat 和其他 SFT 数据，通用预训练数据的比例下降。学生问这类数据是否屏蔽提示：不屏蔽，是纯预训练，提示也预测，不过有些 SFT 配方也预测提示，差别不大。学生问衰减阶段的数据质量是不是更低：正好相反，衰减阶段被认为最重要，最接近部署，学习率也最低，所以放最高质量的数据。

学生问中期训练和后训练的配比怎么定。他说预训练和后训练的配比都很依赖试错，有很多论文提出算法，但都不太可靠。两阶段训练的好处是中期训练比完整预训练短得多，每做一次完整预训练的时间可以做十来次中期训练实验，几乎能蛮力搜索。他听说的常见做法是在衰减阶段做大量便宜的数据消融，估计各数据的质量，再反过来决定预训练阶段的配比。为什么不让预训练全是高质量数据？因为 token 不够，全用维基百科很快就用完了。从消融结果到配比要具体问题具体分析，有系统的方法（拟合模型等），但往往脆弱，他听到的说法是比想象中更靠试错：消融某个领域，按影响大小排序，再决定放什么。一个泄露的例子：Meta 因为用书训练被起诉，法庭文件里有研究者做消融、估计各个书籍子集有多大用处的记录，这就是实际的做法。

三、RLHF 的数据

第二阶段是 RLHF：根据评分者（或奖励模型）对回答好坏的判断，上调或下调模型的不同输出。他先强调一个概念上的重要区别：预训练是对序列做生成建模，SFT 也是，只是换了分布，可以用生成建模的思路去想，就是拟合一个分布。RLHF 不再是拟合分布的游戏，而是最大化奖励的游戏：找一个策略（仍是分布）最大化某个下游奖励，比如用户在平台上停留多久、能解多少数学题，我不在乎是否模仿了某个分布。所以策略完全可以坍缩到每个输入只有一个回答，只要奖励高就行。

为什么不一直收集 SFT 数据，而要做强化学习？一是人"说"想要的和"生成"的有差距。他以前一项研究请自由撰稿人写新闻摘要，发现有几位标注者更喜欢 ChatGPT 前身模型的输出，而不是自己写的。他们怀疑这些人没认真标注，去访谈，对方说："我看了，觉得这写得挺好的。"他们是专业写手，摘要质量也检查过，但看到时才意识到"原来这样写更好"。人不是最优系统，评判和生成不同，所以有时要让人给输出打分，而不只是写示范。二是有些领域验证比生成容易，比如数学，验证证明比生成证明容易得多，DeepSeek 等走了用模型自我验证的路。RLVR 是另一个世界，下一讲再讲推理模型。

RLHF 的大致流程：SFT 后的模型已经能遵循一些指令；输入提示，模型生成几个输出（通常温度 1 采样，SFT 后的模型相当多样）；评分者对这些输出排序，有时只是二选一；在排序上训练奖励模型，用标准强化学习方法最大化奖励模型给的分数。通过奖励模型，是因为训练一个验证器可能比直接训练一个好模型容易。

数据通常是成对评分：界面上两个 AI 回答，选哪个更好。想深入了解，推荐读 InstructGPT 的附录，那几乎是最后一次能看到业界数据收集过程。InstructGPT 要求按有帮助、真实、无害三个标准评分：有帮助指写得清楚、对国际化敏感、不给过长的回答；真实指不幻觉；无害指不安全的要指出，偏好拒绝回答可疑提示的回答，作为训练聊天机器人的综合目标说得通。另一个公开的闭源实验室标注例子是 Google Bard，标注者泄露的：结构类似，要有帮助、呈现要好，用李克特量表而不是成对比较；指南不长，但能看出要求不含不准确信息、连贯、便于阅读等。

标注者

之后变化很大。总体上标注者分布向专家、高成本方向移动。Scale AI 一个平台的调查（不代表全部，但大概是合理的子集）：七成多是本科或硕士学历，众数年龄 35 岁左右，任务多是创意写作、技术写作等。过去一两年还出现了很多定制化的标注者，因为实验室想把系统部署到真正的白领工作中，需要医生、律师来标注回答、写 SFT 数据。OpenAI 等公司内部有这样的项目，时薪中位数在 50 美元以上，有些专家超过 100 美元。所以如果你心中的标注者是海外的低成本成对比较，那不是全貌；现在有大量很定制化、很昂贵的标注，但它是金字塔，低成本可扩展的标注并没有消失。

获取这类数据很难，所以报酬高、数据收集创业公司多。现在的难点是确认标注者真的是人在做，没有用 AI：做过问卷研究或众包的人都发现有人用 ChatGPT 答题，几乎无法阻止。时间压力下也很难得到真正正确的回答：Google Bard 那个例子与一场劳资纠纷有关，标注者说要在一分钟内核实长篇聊天回答的正确性，根本做不到。除了专家标注，仍有大量低薪标注团队，Scale AI 早期把很多低成本标注外包出去，惹了不少麻烦。就像现代经济的高低薪两极分化，标注也是这样。

标注者的人口构成对模型影响出人意料地大，因为后训练是发布前最后的塑造步骤。他和 Percy 的一位博士后在指令微调早期做过研究：用标准民意调查问题问语言模型，看它的观点最接近哪类人群。基座模型比较接近新教徒或天主教徒的观点，离佛教徒、印度教徒较远；后训练之后，离新教徒和天主教徒更远，更接近佛教徒、印度教徒和无神论者。他们觉得奇怪，为什么是这三类？翻 InstructGPT 附录看标注者构成，大量是东南亚人和美国西海岸的人，大致对得上。他还提到近年发现很隐蔽的偏好也能通过数据传递，比如让一个模型"喜欢猫头鹰"，用它生成看似无关的数据，在上面训练的模型也会继承对猫头鹰的偏好，这类"潜意识"的迁移很难察觉，要很小心。他也承认语言模型政治观点这类研究有时很脆弱。

标注者是谁也影响更实质的错误类型。Hosking 等人比较了真正在意做好工作的专家标注者和平台上的普通众包工人：非专家更看重格式；专家更看重事实性和前后一致。事实性更难检查，没有专家自然就查不出来。学生问怎样算高质量标注者。他说没有可以机械套用的金标准。一种是足够详细的标注指南应该是半客观的，比如定义事实性，甚至给客观标准（Google 搜索前三页没有与之矛盾的内容），不遵守指南就是不好。另一种是标注者间一致性，但它只反映方差，不反映偏差：有些任务本来方差就大（"你喜欢这个吗？"），一致性没意义；问"是否属实"一致性应该高，但即使完全一致，也不知道问对了没有；如果大家都用 ChatGPT，方差也会是 0。学生问公司招更多专家是因为质量更高，还是因为数据只有他们能答？他说更多是后者，比如核对 Bluebook 法律引用格式需要训练有素的律师，还有各种隐性知识；但平台总体上也在转向更高质量的标注者，部分原因是 LLM 太好用了，不当面监督的话，人们会用最便宜的 LLM 生成像样的答案，很多标注公司的卖点就是"我们有真人在做真事，并为你核实"。

用模型标注

学生问用领域模型当标注者有什么问题。他说要分开看：领域模型是否好，以及该不该用模型标注数据。模型标注很好，如果你不在前沿、只想追上前沿，模型标注很好，现代模型大概比随便找来的众包工人好得多；但领域模型能否比强大的开源通用模型更好，常常很难，所以用领域模型标注没有特别的优势。

GPT-4 出来时，他和学生比较过 GPT-4 的标注和精心整理的人类标注：系统排名很接近，人与模型的一致性也不错，成本低一个数量级。当时还不清楚开源世界会走向昂贵的人工标注，还是一切都变成从更强模型蒸馏。现在已经过去足够多年，答案是：如果只想在能力上追上前沿，人工收集数据基本没有空间了。一个有启发的例子：Hugging Face 做开源模型 Zephyr 时想完全不用模型蒸馏，不用任何模型标注或模型数据，花了大量时间精力从 OpenAI 等用的同一批供应商那里收集人类数据，结果很耗时、昂贵，效果也不比模型标注好，最后还是用了 AI 反馈。他们认真试过了。现在 SFT 和 RLHF 中，模型生成的 UltraChat 和 UltraFeedback 已成为标准；Tülu 3 整个流程都用模型标注。模型很会遵循指令，容易扩展，能收集你想要的数据。当然，想推进前沿就不能这么玩（少数情况除外），仍然很依赖人类数据收集。学生说 Zephyr 是 7B，很小，他说那时 7B 是很体面的开源规模，大家都爱 Llama 7B；不知道他们在更大模型上有没有试，但在那个规模上没看到差别，换成大模型突然出现大差别会让他很意外。

不纯是蒸馏的模型生成数据也有：Anthropic 早期的 Constitutional AI，让模型生成安全数据，再用它训练模型自身，得到更安全的模型，是很早的自我后训练数据生成循环；Self-Instruct 是以能力为中心的类似想法。但如果要律师、科学家那样的世界知识，没有人来标注就拿不到。模型也会有和人一样的偏差，有时更严重：模型生成数据那波浪潮之后，有研究显示把回答一直拉长，模型评委给的胜率就一直上升，唯一的例外是 GPT-3.5，它不是在刷长度，而是真的更好；还有一篇很好的论文显示，只针对长度做 RLHF 就能在很多基准上表现不错。

四、RLHF 的算法

目标：最大化从策略中采样得到的奖励。他说这是"婴儿版强化学习"，有人会说这是老虎机问题，不是真正的多轮 RL，大致没错，所以算法也很简单。InstructGPT 论文的公式 2 几乎就是这样：

$$\max_{\pi_\theta}\; \mathbb{E}_{x,\, y\sim\pi_\theta}\left[r(x, y)\right] - \beta\, \mathrm{KL}\left(\pi_\theta \,\|\, \pi_\text{ref}\right)$$

第二项是 KL 散度，意思是希望靠近预训练（或 SFT）模型，不要走太远而退化。Stiennon 等人的论文也一样，奖励是学到的成对反馈模型：训练一个二分类器判断一对样本中哪个更好，再在这个奖励上爬山。

PPO（简述）

起点是策略梯度恒等式：想最大化采样自策略的奖励，就求梯度，把梯度推进期望里，得到

$$\nabla_\theta\, \mathbb{E}_{y\sim\pi_\theta}[r(y)] = \mathbb{E}_{y\sim\pi_\theta}\left[r(y)\,\nabla_\theta \log \pi_\theta(y)\right]$$

看起来就像加权的 SFT。问题是每走一步优化都要重新采样，而采样很贵（系统部分讲过推理很难，训练才是算术强度高的好活），希望采样一次、复用多次，这叫离策略。走多步又不能走太远，否则局部奖励估计会失控，这就是 TRPO：做策略梯度，但用重要性加权修正，并约束离当前位置不远。PPO 说约束不好处理，改用启发式的裁剪，阻止算法走到离原策略太远的地方。细节下一讲讲，现在只需了解"策略梯度 → 离策略 → PPO"这条线。

DPO

PPO 的公式已经很吓人了，很多年里很多人问：能不能去掉 PPO？他列了一些合理但效果不好的想法，免得大家在研究中重复：做 SFT，好样本前加"好"标记、坏样本前加"坏"标记，生成时以"好"开头（把 RL 归约成 SFT），不行；只在好样本上训练，效果不太好；训练奖励模型，选出奖励模型认可的输出再训练，有些效果但不如 RL。最终出现了比 PPO 简单得多、效果不错、看起来很像 SFT 的 DPO。

DPO 去掉了奖励模型，也去掉了所有在策略的东西。直觉很简单：深度学习就是朝好的方向走梯度，所以对好样本的对数似然走正梯度，对坏样本走负梯度，相当于一边 SFT、一边"负 SFT"，这是最朴素的做法；两者适当加权，就得到相当好的算法。推导：

  1. 从上面的 RLHF 目标出发。唯一的强假设：策略 $\pi$ 不是神经网络，而是所有可能的策略（非参数），这样可以求出闭式解：

    $$\pi_r(y\mid x) = \frac{1}{Z(x)}\,\pi_\text{ref}(y\mid x)\exp\left(\frac{1}{\beta} r(x, y)\right)$$

    即把参考策略按奖励做指数倾斜：奖励很差的指数下调，很好的指数上调。
  2. 反解出隐含的奖励：$r(x, y) = \beta\log\frac{\pi_r(y\mid x)}{\pi_\text{ref}(y\mid x)} + \beta\log Z(x)$。
  3. 把它代入成对偏好（Bradley-Terry）模型的损失，$Z(x)$ 抵消，得到 DPO 目标：

    $$\mathcal{L}_\text{DPO} = -\mathbb{E}\left[\log\sigma\left(\beta\log\frac{\pi_\theta(y_w\mid x)}{\pi_\text{ref}(y_w\mid x)} - \beta\log\frac{\pi_\theta(y_l\mid x)}{\pi_\text{ref}(y_l\mid x)}\right)\right]$$

    $y_w$ 是胜出的回答，$y_l$ 是落败的回答。

他认为最直观的是看梯度：对每对标注过的样本，提高胜者的似然，降低败者的似然，步长取决于隐含奖励模型错得多厉害。如果模型已经给胜者很高的隐含奖励，就走小步；如果错得离谱，认为两者差不多，就走大步。这比 PPO 简单得多，只是求梯度，而且效果还不错。有一段时间大家执着于 DPO 和 PPO 哪个好，他认为除非你在前沿训练最好的模型，可能差别不大，DPO 对 Llama 够用，对他也够用。Llama 的技术报告里有一个外循环：SFT，DPO，用 DPO 模型生成候选做拒绝采样，重复；外循环之下，核心的 RLHF 原语就是 DPO。

之后出现了很多变体：SimPO 改变了加权，不用 $\pi_\text{ref}$，而是用长度归一化；长度归一化的 DPO 用来避免刷长度。但这些变体似乎都没那么重要。他觉得有意思的是结论很依赖实验设置：AI2 有论文说从 DPO 换到 PPO 结果更好，Tülu 2 的论文又说 DPO 做对了能胜过 PPO，取决于怎么执行。要点是这些 DPO 变体离正确做法够近，在很多情况下表现不错：只要步长设对，"朝好的走正梯度、朝坏的走负梯度"效果就相当好。

五、RLHF 要注意的问题

  • 过度优化：这可能是最大的问题。InstructGPT 出来时，大家很兴奋，真有人在问能否靠 RLHF 一路做到超级智能，只要收集够多的点赞点踩。结果很难：用力推进 RLHF，就会开始过拟合学到的奖励模型。所以 KL 正则项在很多情况下很关键，至少在优化过程很强时。
  • 模式坍缩：RL 后的模型多样性低得多，集中在少数几种输出上。这回到前面说的：RLHF 模型不再是建模一个自带多样性的分布，而是一个策略，只要奖励好就可以坍缩。GPT-4 那时 OpenAI 公开的少数图里有一张承认仍有开放问题：RLHF 后模型校准变差。他认为至今没人真正解决；Anthropic 也论证过它天然就不校准，有时能重新校准，但不总是能。这在下一讲 RLVR 中很重要，因为熵和探索对模型探索所有可能解、在很难的问题上取得进展至关重要。

总结：RLHF 的数据收集很难，后训练之所以复杂混乱，很大程度上因为要拿到好数据，而好数据总是很难。RLHF 算法相当复杂，PPO 尤其难，下一讲会讲一些；好在有一个更简单、效果不错的变体 GRPO，作业里要做。RLHF 的一大问题是过度优化，过渡到下一讲的问题是：有没有不会被过度优化的奖励，让你能一直砸算力、模型表现单调变好？这就是 RLVR 影响如此之大的原因之一。
