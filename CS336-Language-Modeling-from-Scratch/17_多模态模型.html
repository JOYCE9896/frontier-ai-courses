第十七讲：多模态模型

怎样把图像变成 Transformer 能处理的 token：CLIP 与 SigLIP，LLaVA 系列和 Qwen-VL 系列的视觉语言模型做法（适配器、动态分辨率、M-RoPE、分阶段训练），以及把一切离散化的 Chameleon

主讲：Percy Liang
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、为什么讲多模态

Percy 原计划多讲强化学习，但他只剩一讲，觉得不讲多模态这门课就不完整，因为所有主要模型都是多模态的。这本身可以是一整门课，这里只做概览。

到目前为止课程只讲语言模型。语言模型已经很通用，可以从任意文本到任意文本，各种语言、代码、诗歌，甚至 DNA。但世界是多模态的：文本、图像、音频、视频。人们心中的北极星是"全模态模型"（omni model），输入任意模态的任意组合，输出任意组合：给一张图和一段视频问问题，生成图像，把音频转成图像，等等。这一讲不会搭出完整的全模态模型，主要讲怎样让模型摄入图像。

怎么做？现实是 Transformer 效果很好，尽管大家努力尝试别的东西，在各种模态的大规模场景下它仍是最好的，所以要想办法用它。Transformer 是为文本设计的，"说"的是 token：输入一串 token，输出一串 token。这里把 token 的概念扩展到连续的 token（可以看作 token 的嵌入）。关键是一个 token 应该代表某种有语义的信息单元：自然语言里的子词多少有意义，而单个像素本身毫无意义。所以必须把音频、图像等转换成离散或连续的 token。文本其实也要这样做，第一讲讲了分词，BPE 还行，你可以希望有更好的分词器或完全不用分词器，但也不算最糟。非文本模态就得费更多脑筋，找出相当于 BPE 的东西，把图像变成 Transformer 能消化的东西。要回答两个问题：怎样把图像、视频、音频输入 Transformer；怎样生成它们。这一讲主要讲第一个。

二、CLIP

回到 2021 年。CLIP（contrastive language-image pre-training）是现代视觉语言模型很多工作的基础。当时 GPT-2、GPT-3 已经出现，语言已进入基础模型时代；视觉还主要依赖 ImageNet 这样的大型标注数据集，在上面训练 ResNet，加数据增强，表现很好。OpenAI 的研究者想：能否利用网上大量图像和文字说明？就像语言那样，直接抓取互联网，很嘈杂，但模型够大就能从中理出有用的东西。

思路很直接：给一批图像文本对，比如 32000 对。每张图用图像编码器编成向量 $I_1, \dots, I_N$，对应文本编成向量 $T_1, \dots, T_N$。目标是：$I_1$ 和 $T_1$ 是一对，所以希望它们的点积远大于 $I_1$ 与其他所有文本的点积；反过来，$T_1$ 与 $I_1$ 的点积也要大于 $T_1$ 与其他所有图像的点积。相当于 $2N$ 个 softmax 分类问题。代码上：得到 $N\times d$ 的图像嵌入和文本嵌入，归一化，求点积，除以温度，计算交叉熵，就像样本排成 $N\times N$ 矩阵结构的多类分类。

细节：

  • 数据：论文没有多少细节，大致是拿一批查询去网上搜索，挖出图像文本对，共 4 亿对，没有发布。OpenCLIP 复现并扩展了 CLIP，发布了 LAION-5B，50 亿张带文字描述的图像，经过大量处理。有意思的是，他们用 CLIP 做数据过滤，再训练 OpenCLIP，有一点自举，但至少能指出模型用的是哪个数据集和代码。
  • 分辨率：网上的图片尺寸各异，又长又窄或又高又窄，而神经网络不喜欢动态尺寸。所以做了有点启发式的处理：缩放到短边 336（或 224），再中心裁剪成正方形。这是为了方便，后面会看到可以做得好得多；当时作者想的是 ImageNet 分类，物体通常在中间，裁掉一些背景关系不大。
  • 视觉编码器：试过 ResNet 和刚出现的 Vision Transformer（ViT），ViT 最好，所以说 CLIP 一般指 ViT 版本。ViT 把图像切成小块（原 ViT 是 16×16，CLIP 用 14×14），每个块就是一个向量，相当于一个 token，加上位置嵌入，送进标准 Transformer。输出是一串向量，可以平均得到一个向量；CLIP 发现用注意力池化更好：先取全局平均作查询，再对各位置的键值做一轮注意力，得到一个更有信息的向量。最好的是 ViT-L/14：大号 ViT（他记得约 24 层），14×14 的块，RGB 三通道，336×336 分辨率；为了速度，先在低分辨率训练，后期才用高分辨率。
  • 文本编码器：GPT-2 风格的 Transformer（同一个组做的 GPT-2），在序列前加 BOS、后加 EOS，取最高层 EOS 位置的激活作为整个序列的表示。

学生问为什么用图文对而不只用图像。他说有一类工作（比如 SimCLR）基于数据增强学图像表示：裁剪、扰动、旋转，要求同一张图的嵌入相近，对低层细节有用；但增强再多也不能从一种狗变到另一种狗，有了文本才能得到更高层的语义表示。学生问位置嵌入能否更聪明，因为图像是二维的。他记得 CLIP 论文试过二维版本，发现差别不大，但要记得它们关心的是分类，对分类也许无所谓，后面会看到考虑空间结构的位置嵌入。

2021 年让大家兴奋的主要结果：在 ImageNet 上，零样本的 CLIP 胜过在 120 万张 ImageNet 图像上训练的 ResNet。那 120 万张标注花了 Mechanical Turk 工人大量时间；CLIP 用的是更"自然"的网络数据（当然也是网上很多人的劳动），能利用现有数据就可以零样本。零样本做法：拿一张图，和各个类别标签的文本嵌入求点积，选最高的。学生问一批里如果多张图的说明都有"狗"会不会让模型混乱。他说这个过程总是嘈杂的，平均而言不会总有狗，有时是苹果或猫；而且这些图来自网页，文字是旁边的文字或 alt 属性，非常嘈杂，研究发现图片说明不一定直接描述图中内容，图里是狗就没必要写"一只狗"。它能奏效有点出人意料，也需要大量数据过滤，随便拿网上的图文肯定太嘈杂。

CLIP 还试了另一种目标：从图像预测文本，用词袋或语言模型。有点意外的是，用更强的模型（语言模型）反而更差，至少效率更低，不如词袋版的 CLIP。这说明至少对他们要学的表示（以及 ImageNet 分类）来说，精确建模说明文字的 token 序列，对获得图像的大致表示并不那么重要，最后会回到这一点。

小结：CLIP 编码的图像捕捉了语义，因为和文本配对，文本通常讲的是语义；设计决策基于图像分类，不太细粒度，但后面会看到它仍是稳健的起点。技术上的缺点是需要很大的批（比如 3 万），批大小 1 显然不行，10 也不行；softmax 在整个批上计算，不好分解，而普通语言模型训练中批内各序列可以并行，最后汇总就行。

SigLIP

Google 的 SigLIP（sigmoid loss for language image pre-training）可以看作改进版 CLIP。CLIP 做多类分类：一对图文是正例，与其他所有图像或文本对比；SigLIP 更简单，对任意一个图文对判断是否匹配，就是二分类，矩阵对角线是正例，非对角线是负例。算法：取嵌入、归一化、求点积，标签对角线为 1、其余为 -1，再做 log-sigmoid。学生问是否需要复杂的采样策略（对比方法常要平衡正负例或用难负例），他说至少最初版本就是直接在同样的矩阵上做。

数据来自 Google 2022 年另一个图文模型用的 WebLI 数据集，十亿级图文对，还对含文字的图像做 OCR 形成更多图文对，做了过滤，是多语言的。主要卖点是训练效率高得多：CLIP 在 256 块 TPU v3 上训练 10 天，SigLIP 在 32 块 v4 上 5 天。v4 的单卡 FLOP/s 其实不比 v3 快（好在同一个 pod 能放更多、互联更好），在这个规模上甚至慢约 60%；CLIP 大概也没有为最大吞吐量优化代码。SigLIP 展示了怎样并行：回想系统讲，可以看作数据并行，每个设备存一部分图文对，但样本之间有交互，不像语言模型那样完全可分解。第一轮每个设备算本地图文对的损失，然后传递文本，比如设备 1 收到 $T_5$ 到 $T_8$，就能算这一块的负例，再收到 $T_9$ 到 $T_{12}$，轮转一圈直到覆盖所有非对角块。另一个好处是损失与批大小解耦：CLIP 的损失和批大小绑定，换批大小就是换了损失函数；SigLIP 在小批（小于 16k）时方差大一些，但期望上是同一个损失，所以小批时比 CLIP 好得多，CLIP 批太小时损失会退化。他们也发现批可以开得更大，但没用，32k 基本就是临界批大小。

三、视觉语言模型：LLaVA 系列

有了 CLIP 和 SigLIP 这样的图像编码器（这个版本输入固定尺寸，比如 336×336，输出带语义的向量），就可以搭视觉语言模型（VLM）。两个系列：LLaVA 和 Qwen-VL，大的模板很相似，细节不同。基本思路是把这些嵌入注入语言模型，更像中期训练或后训练：拿现成的图像编码器和现成的 LLM 缝在一起，而不是从零训练。

LLaVA（2023）：当时 GPT-4 等闭源模型能做视觉推理，LLaVA 显示开源模型也能做一些，不如 GPT-4，但大家能看到内部是什么。组成：

  • 视觉编码器：CLIP，用最好的 ViT-L/14。
  • 文本解码器：Vicuna，第一代 LLaMA 在 ShareGPT 对话上微调得到（人们把和 ChatGPT 的对话分享到那个网站，现在大概已经关了）。
  • 数据：基于 MS COCO，Mechanical Turk 工人给图片标了边界框和描述。他们把描述和检测到的物体喂给 GPT-4，让它生成问题或对话、详细描述、复杂推理，共合成 15.8 万条。
  • 结构：图像经 CLIP 得到向量，但它和文本不在同一空间，乘一个矩阵 $W$ 投影到文本嵌入空间；文本用普通嵌入。图像和文本都变成向量序列，一起送进标准 Transformer。某种意义上就是把图像转成"文本 token"，以利用预训练好的语言模型。
  • 训练两阶段：第一阶段冻结视觉编码器和语言模型，只训练 $W$，叫对齐阶段，因为随机的 $W$ 得到的东西根本不像任何自然语言 token 的嵌入，要让它们看起来像；第二阶段仍冻结视觉编码器，训练 $W$ 和语言模型，在"图像 + 对话、描述或推理"到文本的数据上微调。

论文里一个例子：一张图，问"这张图有什么不寻常？"，模型能指出通常不会在小货车的车尾熨衣服。他们还强调，即使用户提示没问不寻常之处，模型也会谈到；GPT-4 当然能做到，当时其他模型不行。

LLaVA-OneVision（2024）：LLaVA 之后有 LLaVA-1.5、LLaVA-NeXT 等一系列论文，他用这一篇概括这些创新。配方基本相同，但想支持更多多模态应用：单张图、多张图、视频（采样帧，本质是图像序列）。视觉编码器升级为 SigLIP；文本解码器用当时大概最好的 Qwen 2；投影器（适配器，把视觉编码器的输出变成语言模型的输入）换成两层 MLP。就像升级系统的零件，大体系统不变。

数据处理：想做 OCR 就要保留很细的信息，否则 j 看起来像 i。CLIP 缩放裁剪到 336×336，文档这样一裁就看不清了。解决办法是 LLaVA-1.5 提出的 AnyRes：把图像切成多块，每块是视觉编码器接受的分辨率（比如 336×336），分别编码成向量再拼接。视觉编码器处理不了高分辨率，就不降采样，而是裁成小块分别看。超高分辨率图像或视频 token 太多，再做降采样。好处是自适应，Transformer 本来就能处理任意长度的句子，图像也可以是任意分辨率。具体做法：比如一页论文，一路是整页降采样后的编码，另一路切成编码器分辨率的小块分别编码，拼接所有块，太多就插值减少。

图像、多图、视频本质上都是图像，但他们为了各模态大致可比而人为调整：视频可能很长，不想让数据集被大量重复的帧主导。单张图用降采样全图加最多 9 个裁剪块；多张图只用基础分辨率，"有一张图就仔细看，有多张就远远看"；视频每帧用更低分辨率、更少 token，最多 32 帧，否则会遇到上下文长度问题，后面会看到处理多模态的一大部分是处理长上下文。

数据：他们说要精选高质量数据而不只是数量，换个说法就是非常有针对性：很多都是具体任务，视觉问答、关于表格的问答等，显然是后训练领域，为让模型做这些任务而构造任务。他们也毫不掩饰地大量蒸馏 GPT-4，他说这不理想，但没有标注预算就是这么做。有单图、多图、视频，有些任务很具体，比如给两张图找不同。训练三阶段：第一阶段只训练投影器做对齐；第二阶段训练完整模型，用高质量、偏知识的数据；第三阶段用像下游任务的样本。之前两阶段、现在三阶段，他不确定有什么原则性的理由。

有意思的发现是模态间有迁移：图表数据只有单图的，却能泛化到多图，训练时从没见过同时给一张表格和一张图表来提问，测试时给两张图也能对话；训练时 OCR 只有单图数据、关系推理只有多图数据，却能泛化到给一堆截图生成描述，这对 GUI Agent 很有用；"视觉提示"（在图上画个圈，表示要处理这部分）只有单图数据，却能泛化到视频："描述视频中被标出的球员"，那个球员跨越多帧。他第一次看时觉得这是在逐个针对任务，像监督学习；但任务够多时模型似乎能迁移，这让人放心。

小结：相当标准的 VLM 模板，视觉编码器加投影器接到语言模型；数据整理投入很多，大量使用合成的任务数据。LLaVA 系列的好处是少数不仅开源权重、也开源数据的工作，能真正复现和研究。

四、Qwen-VL 系列

  • Qwen-VL（2023）：视觉编码器用 OpenCLIP（基本就是 CLIP 编码器）；适配器是一层交叉注意力，加入二维位置嵌入，映射到固定的 256 个向量，不太动态（编码器当时也不动态），后来改了。有特殊标签：图像标签、边界框标签、指代描述标签。训练三阶段：第一阶段叫"预训练"，但不是从零开始，用大规模低质量数据（14 亿样本），冻结语言模型，训练视觉编码器和适配器，这点和 LLaVA 不同，它训练视觉编码器；第二阶段用更高质量的任务数据，VQA、图表问答等常见数据集，训练全部参数；第三阶段指令微调，冻结视觉编码器，训练适配器和语言模型。例子里有中文；他们也希望视觉模型能包含语言模型的能力，语言模型能写代码，视觉模型也要能；给一张图问"谁能打过蜘蛛侠，绿巨人"，能输出边界框（不是图像，只是坐标）；还能做 OCR、比较等。
  • Qwen2-VL：更大的视觉编码器；开始做动态分辨率，和 LLaVA-OneVision 一样意识到要处理不同尺寸的图像，做视频更是需要。一张图可能映射成约 11000 个 token，一个很小的公式图片可能只有 8 个 token。做法类似 AnyRes：每个 224×224 的块用 ViT 编码（从 OpenCLIP 的 ViT 出发，会被微调），为了减少上下文，把每 2×2 压成 1 个，最终每块约 66 个 token。视频每秒采 2 帧，最多 16000 个 token 左右。位置嵌入用了多模态旋转位置编码（M-RoPE）：RoPE 让向量内积只依赖于距离，一维中距离就是隔了多少 token；M-RoPE 有高、宽、时间三个维度，每个位置（块）是一个三元组坐标，对每个维度算 RoPE 再拼接。初始化用 Qwen 语言模型，三阶段训练，展示了视频理解、数学、代码、函数调用等能力。
  • Qwen3-VL（去年）：变化不算结构性的，但大概确实影响质量。用 Qwen 3 的一系列稠密和 MoE 模型，它们非常好，对最终质量很有帮助。重视长上下文理解，上下文可达 256K，对长视频很重要。视觉编码器用 SigLIP 2（改进版 SigLIP，架构相同，设计成向后兼容）。改进了 RoPE：之前把前一段维度分给时间、下一段给宽、再下一段给高；RoPE 的每个分量对应不同频率，这样可能时间维全是低频、高度维全是高频，于是改为交错分配，让各个轴都能用到高低频率。加了显式的视频时间戳：以前时间隐含在位置编码中，每帧位置不同，自然有时间概念；现在用 token 显式表示时间，比如"0 秒"，大概因为可以直接引用"两秒后发生了什么"。按样本长度的平方根归一化逐 token 损失：视频样本很长、单图样本很短，如果每个 token 一视同仁，视频会主导；细节不太清楚，他认为是按长度平方根归一化每个样本，降低超长样本的影响。适配器用了 DeepSeek 团队提出的 DeepStack：视觉编码器本来就计算出一叠多层的视觉嵌入，把它们直接加进语言模型的残差流，是更深层的融合，而不是把视觉编码器当黑箱只输出一串向量。训练：预训练四个阶段，先训练适配器，再在越来越长的序列上训练（8K、32K、256K），大部分 token 在第二、三阶段；后训练三阶段：长思维链数据上的 SFT、知识蒸馏、一些强化学习。他说到这里基本是系统论文，他只挑了核心新想法，还有大量细节差异。和 Gemini、GPT-5、Claude Opus 4.1 等闭源模型比，Qwen 模型在很多基准上相当强。

学生问这些模型怎样生成视频、怎样决定输出是视频还是文本。他说这些模型不生成视频或图像，多模态都在输入端，总是生成文本；除 RL 外的大多数阶段，每个 token 都有监督，就是数据集里的内容，没有 LLM 评委打分；RL 阶段可以尝试不同的奖励。学生问多模态训练在系统上是否更难：肯定不更容易。数据集更大，光是加载视频就很麻烦；讲语言模型时没关注数据加载，因为很便宜，这里要考虑，同样要让数据加载和计算异步进行。视频和图像 token 更多，所以有前面的归一化，避免过度加权视频，也可以像数据配比那一讲那样按合理的方式加权；但文本 token 也很多，模型用几十万亿 token 训练，他认为多模态 token 并不远多于文本 token。学生问对齐阶段语言模型是否必须预训练好：是的，否则对齐没意义；语言模型冻结，只训练适配器连接给定的视觉编码器和语言模型，选一个 token 预算（比如 670 亿）训练就行，没有自适应的停止阈值。学生问视觉编码器参数是否小得多：是的，比如 LLaVA 的语言模型 720 亿参数，投影器只有约 7200 万，ViT 一般不到 10 亿。原因是视觉编码器做的是很局部的操作，看一个很小的块，理解这个块，不需要多少知识，也不做推理，模型的大部分能力仍在语言模型里。

后来的 Qwen 模型数据细节不多，可以看 LLaVA 论文或 AI2 的 Molmo 论文（他没时间讲）。从 Qwen-VL 到 Qwen 3，框架没变，主要是扩大规模、整理更多数据集、意识到要处理长上下文、改进图像处理等。

五、Chameleon：把一切离散化

Meta 2024 年的 Chameleon 思路很不同。到目前为止 VLM 都把图像编码成向量注入语言模型，因为是语言模型，只能生成文本，不能生成图像。可以给 VLM 加一个扩散头来生成图像；Chameleon 说：把一切都映射成离散 token 会怎样？他说美学上这很吸引人，也许因为他是做语言的：分析和生成图像的方式一样，一切都是离散 token，想生成图像就给文本提示，生成更多 token；也可以反过来。论文例子：提示"我很无聊，给我看看鸟"，输出文字、图像、文字、图像交错。某种意义上这是全模态模型的愿景：文本和图像真正在同一空间里，办法是让一切看起来像文本。

要把图像映射成离散 token，用的是 2017 年的 VQ-VAE（向量量化变分自编码器）：学一个映射，把图像映射到连续向量，再"舍入"到最近的码字。有一个码本，比如 8000 个码字，是对应各种图块的原型向量，选最近的作为表示，这是编码器；解码器拿码字重建图像，用重建损失训练（因为舍入不可微，还要加别的项，没时间讲）。最终 512×512 的图像变成 1024 个 token，每个来自 8000 大小的词表。他们为新的数据训练了新的分词器。训练就是普通的语言模型训练，没有适配器，不用调视觉编码器，只有一个语言模型，这是吸引人的地方。仍有两个阶段（语言模型训练通常也有两个或更多阶段）：第一阶段是大量无监督的文本和图文数据，第二阶段混入高质量数据。

问题：训练不稳定。文本和图像虽然在同一空间，行为很不同，叫它们离散 token 掩盖不了里面是图像的事实。文本 token 熵较低，大多数词可以预测；图像 token 熵很高，你不知道这个 token 到底是哪种蓝。混合训练导致参数范数增长，损失不稳定，他们用 QK 归一化和 z-loss 正则控制范数增长，一定程度上缓解了。他不展示结果，只是想强调这种做法的优雅：一个模型，真正平等地对待所有模态。缺点是性能不太好；离散化肯定损失信息，比如 OCR，小字离散化后就读不出来了；多模态训练本来就棘手，Qwen 那里已经要调权重，这里更严重。VQ-VAE 流行过一阵，很多人用它生成图像，因为 Transformer 只能生成离散的东西，就把数据都变成离散形式；后来扩散模型兴起，在生成上变得可行，这类方法就没那么流行了。

六、小结

现在的前沿模型被期望是多模态的，甚至"原生多模态"、全模态。Gemini、GPT 发布时都宣传原生多模态，也确实能处理各种模态，但没有任何构建细节。他推测大概是连续编码器（不想丢信息）加上扩散模型做生成，这只是推测。根本挑战是怎样处理非文本模态。理解和生成之间有一种对称，但没有通用的编码器：CLIP 只关心分类，捕捉高层语义，向量可以较小；做 OCR 或生成图像就需要很细的细节，这也是扩散模型擅长的原因，能精细优化高频信息。处理多模态要仔细平衡各模态的权重，比如视频的信息密度低于文本，不能让视频压倒文本。目前最好的做法大概仍是连续编码器：CLIP 已有五年，它或类似的思路仍是捕捉图像语义的首选；Transformer 仍在核心；扩散模型（这一讲没讲）很适合生成。这部分没有作业，他鼓励感兴趣的人自己训练一些这样的模型试试。
