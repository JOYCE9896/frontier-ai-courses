第一讲：课程概览与分词

为什么要"从零"构建语言模型，小规模实验学得到什么、学不到什么，效率为什么是贯穿全课的主线，五个作业分别讲什么，以及字节对编码（BPE）分词器怎样工作

主讲：Percy Liang
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、为什么要从零构建

这是 CS336 第三次开课，授课的是 Percy Liang 和 Tatsunori Hashimoto（Tatsu），助教有 Marcel、Herman 和 Steven。Percy 说他做语言模型二十年，大部分时间是小模型；两年前开课时没想到有这么多人想学怎样从零构建语言模型，尤其现在编程 Agent 可能一次就能写出一个语言模型。Tatsu 说这是他教过最有意思的课，Percy 总笑他每年都得重做架构部分的课件，因为每年都在变。去年起所有讲座都放到了 YouTube 上。今年不变的是"从零"的理念；变化是会多讲一些混合专家模型，并且因为 Agent 流行，长上下文及其所需的东西变得重要。

开这门课的原因是研究者正在和底层技术脱节：十年前 AI 研究者都自己实现、训练模型；八年前大家下载 BERT 这类预训练模型来微调；今天很多人只靠提示模型。提示本身没问题，抽象层次提高总体是好事，但抽象会"泄漏"，你想让模型做某件事而它做不到时，没有办法补救；如果做基础研究，只靠提示会大大限制你能探索的设计空间。所以他认为，要做基础研究，必须完整理解语言模型怎样工作，而理解的方式是动手构建。

问题是语言模型已经工业化了：据说三年前 GPT-4 的训练花了约 1 亿美元，现在可能到了 10 亿量级（他说这是猜测），各大实验室建的 GPU 规模惊人；而且没有公开细节，2023 年 GPT-4 的报告明确说，由于竞争格局和安全考虑，不公开模型是怎样构建的。我们可以做小模型，但小模型未必能代表前沿模型。两个例子：

  • 在小规模时，MLP 层大约占 44% 的浮点运算；扩大到 1750 亿参数时，约占 80%。所以大规模下重要的东西和小规模不同，你在小规模优化注意力，到了大规模未必有同样的收益。
  • 能力随规模涌现：小模型在零样本或少样本学习上似乎什么都做不好，到了某个临界规模才突然大幅改善。小规模实验可能看不到某些现象。

那么能学到什么可迁移的东西？他把知识分成三类：机制（Transformer 是什么、模型并行怎样工作）、思维方式（怎样榨干硬件、认真对待规模）、直觉（哪些数据和建模决策能带来好的表现）。这门课能把机制和思维方式教好，尤其强调剖析和基准测试一切、追求效率，这些能迁移到更大规模；而关于建模和数据决策的直觉未必能跨规模迁移，那需要到能做大规模实验的地方去获得。有些设计决策本来就无法论证，只能靠实验：Noam Shazeer 提出 SwiGLU 激活函数的论文结论里很坦白地写道"我们不给出解释，我们把这些架构的成功归因于神的恩赐"。

关于"苦涩的教训"，他说常见的误读是"只有规模重要，算法不重要"，正确的理解是"能随规模扩展的算法才重要"。可以简单地把模型准确率看作效率乘以资源：效率是产出除以投入，资源就是投入。规模越大效率越关键：小实验慢一倍可以多等一会儿，大规模训练要花几亿美元，5% 的提升都是大事。OpenAI 2020 年的一篇论文显示，2012 到 2019 年 ImageNet 上的算法效率提高了 44 倍，硬件进步再乘上算法进步，才有效率和准确率的巨大提升。所以本课的框架是：给定数据和算力预算，能构建的最好模型是什么。预训练主要讨论算力预算，假设数据多于算力；如果数据有限或者手上藏着大量 B200，可能就是数据受限。总之是最大化效率。

二、简短的历史

语言模型由来已久：Shannon 在 50 年代就用语言模型测量英语的熵；n-gram 模型长期用于机器翻译和语音识别，帮助生成通顺的文本。现代语言模型的谱系来自神经网络：90 年代的 LSTM；Yoshua Bengio 2003 年的第一个神经语言模型（一个只看短上下文的前馈网络，不是 LSTM）；seq2seq 大胆地把整句话压缩成一个向量；Adam 优化器；为机器翻译发明的注意力机制，以及在此基础上同样为机器翻译开发的 Transformer；扩展到混合专家、模型并行，2010 年代出现了大量架构、系统和优化器方面的想法。2010 年代末，ELMo、BERT 在大量文本上训练，再在问答等下游任务上微调，大幅提升效果；Google 的一篇论文已经预示了"提示进、回答出"的模式。

他认为是 OpenAI 通过拥抱规模打开了闸门：2018 年左右的 GPT，扩大到 GPT-2，再借助缩放规律训练出比当时大十倍以上的 GPT-3，展示出上下文学习等涌现行为。Google 随后训练了一个巨大的模型，结果训练不足；当时还未并入 Google 的 DeepMind 找到了算力最优的缩放规律。GPT-3 对很多人是一记警钟，出现了很多复现尝试：草根组织 EleutherAI 做了开放数据集和模型，但算力有限，模型不大；Meta 的第一个大模型 1750 亿参数，一看就是复现，但不太好，遇到很多硬件问题；还有 Hugging Face 的 BigScience 项目，这些模型都不算强。过去三年，开源生态变化很大：Meta 的 Llama、Llama 2、Llama 3 带头，Mistral 加入，然后是一批中国模型，人人都听说过 DeepSeek 和 Qwen（他说字节跳动、腾讯也各有模型，很难跟上）。现在开放权重的模型已经接近闭源模型，看你问谁、怎样评测，可能略落后或相当，在业界被广泛使用。另一条线不只发布权重，还发布论文、代码和数据：AI2、NVIDIA，以及他参与的 Marin 项目。他强调开放生态，是因为没有它这门课就不可能存在：就是因为还有关于大型 MoE 和强化学习系统的论文发表，我们才能窥见前沿模型的构建方式、拼凑出各个部分；当然很多细节缺失，比如 Qwen 的论文无法复现，数据配比尤其不公开，但总比没有好得多。

过去十年，"语言模型"的含义变了：从用来微调的东西，到用来提示的东西，到 ChatGPT 时代可以对话的东西，再到 Agent 时代。他说给它一页文字，它就能完成很复杂的 Agent 编程任务，这超出了十年前任何人的想象。但基本原理变化不大：仍然在 GPU 和内核上构建，仍然用梯度或随机梯度类方法优化，仍然是 Transformer 和注意力，架构有些变化但不大。规格变了：要求更长的上下文，推理效率更加重要。所以这门课不用彻底重写，只改了讲最新中国模型架构的两部分。

他用的是"可执行讲义"：看起来像 Python 程序，因为它就是一个 Python 程序，只是渲染成了便于阅读的样子，讲课时逐步执行。

三、课程安排

课程网站 cs336.stanford.edu。这是 5 个学分的课，有 5 个作业，很繁重，有一条评价说作业一相当于 CS224N 的五个作业加起来（他说可能夸张了，但估计时保守一点好）。为什么要上：首先是像他一样有强迫症般想弄懂事物怎样运作的好奇心；上完课你会有更强的研究和工程能力，有信心进入新环境并应对任何问题。他刚到 Stanford 时教统计学习理论，让学生读论文时能看懂所有数学；领域转向系统和实证之后，这门课是类似的东西，给你足够的深度，让其他东西都显得容易。为什么不该上：这个学期想做出研究成果，要先和导师说，否则会有意外；想学最热门的新技术，有很多研讨课更合适，这门课不讲多模态、不深入讲 Agent；如果你有个应用领域想得到好结果，建议先提示模型，再微调，最后才考虑自己预训练，因为又麻烦又贵，但很好玩。

不选课的人可以在家跟着学：所有讲义都放在网站上，录像之后会发布到 YouTube，但真正学会靠做作业。作业的理念是：不提供脚手架代码，但提供大量单元测试，确保你构建的东西是对的，避免"交上去只知道对或错"的稀疏奖励。大部分作业可以先在笔记本电脑上实现并检查正确性，再用提供的集群做真正的训练、或用 GPU 测内核性能。多数作业有排行榜，比如在给定预算下把困惑度降到最低，Marcel 和 Herman 当年就是排行榜高手。

关于 AI：编程 Agent 现在已经好到能做完所有作业，但把作业一的 PDF 丢给 Claude Code 显然什么也学不到；同时 AI 对答疑和辅导很有用。所以课程提供一个 agents.md 文件（等价于一段提示），要求 AI 以教学为导向：它会回答关于代码的问题、澄清理解，但不会在作业要你实现 Transformer 时替你写出来。如果用 AI，必须带着这段提示用。今年第一次这样做，请大家反馈。算力由 Modal 提供平台额度，和去年 SSH 进集群不同，是 API 方式，他起初怀疑，用下来觉得挺好。

四、五个部分

1. 基础：从零训练一个语言模型

前两周。组成部分：分词、定义架构、实现优化器和训练器。

  • 分词：模型操作的"原子"是什么。分词器在原始输入（字节）和整数序列（token）之间转换，概念上是对文本的切分。这一讲讲 BPE，它把输入切成高频出现的块。从效率看，分词把很长的字节流缩短成更少的 token；更微妙也更重要的是，它实现了自适应计算：有些地方很多字节可以压成一个 token，而稀有或有意思的部分保留为多个 token。他说每年都希望不用再教分词，梦想是端到端直接处理字节，比如最近的 H-Net 看起来有希望，但还没在前沿规模上验证，前沿模型仍在用分词器。
  • 架构：Transformer 有了很多改进，Tatsu 会详细讲：激活函数、位置编码、归一化（防止数值爆炸）；注意力是序列长度的平方，有很多减少注意力计算的方法；更进一步是状态空间模型，或等价的线性注意力，比如 Mamba、Gated DeltaNet，通常与注意力混合效果不错；MLP 层从原来的稠密层变成了混合专家，这已成为构建计算高效的 Transformer 的主流范式，并且需要不同的训练技巧；还有看似无聊但很重要的"形状"问题：多少层、多少头、隐藏维度、专家数。
  • 训练：损失函数（默认是预测下一个 token，人们发现预测多个 token 有帮助）；优化器（过去用 Adam，越来越多用 Muon，比如 Kimi K2）；初始化（听起来无聊，但对大模型的训练稳定性影响巨大）；学习率调度、正则化、批大小；以及 MoE 特有的东西。看起来都是超参数，但以有原则的方式仔细设定，是一次训练爆掉、毫无用处和达到最先进水平之间的区别。

作业一要实现 BPE 分词器、Transformer、损失函数、优化器和整个训练栈，做资源核算，弄清浮点运算花在哪里，在 TinyStories 和 OpenWebText 上训练模型，并在排行榜上尽快降低困惑度，类似 NanoGPT 的 speedrun。总体要点：分词、建模、训练看似是独立部分，其实都在平衡三件事：模型要有表达力；训练要稳定，大量工作是让参数和梯度的范数保持在合适的区间，既不爆炸也不消失；以及效率，比如投影到低维空间可以更快，但效果是否一样好，这种权衡是这个领域的核心。

2. 系统：榨干硬件

  • 资源核算：弄清浮点运算和内存花在哪里。比如用 1 万亿 token 训练一个 70 亿参数的模型要多少浮点运算？大约是 $6ND$（$N$ 是参数量，$D$ 是 token 数），下一讲会推导。
  • 硬件：内存不在计算单元所在的地方，要把参数或激活从内存搬到计算单元，算完再搬回去，这常常是瓶颈。比如 B200 在 BF16 下约 2.25 PFLOP/s，内存带宽约 8 TB/s。会讲屋顶线分析，判断一个计算是受计算限制还是受内存限制（一般是内存）；还有基准测试和剖析。一台 DGX B200 有 8 块 GPU，用 NVLink 连接；上千块 GPU 就是多台这样的机器，用 InfiniBand 或以太网连接。
  • 内核：内核是在 GPU 上运行的函数，PyTorch 的原语对应启动特定的内置内核。对某些计算，可以写定制内核让 GPU 更快，核心原则是组织计算以减少数据搬运。比如要先后计算两个操作，通常要从高带宽内存（HBM）读、算、写回，再读、算、写回；算子融合只读一次、两个都算完再写回，省很多时间。分块（tiling）是同一思想更复杂的版本。GPU 越来越复杂，会尽量让大家了解它的一些特性。
  • 并行：上千块 GPU 时原则不变，只是 GPU 之间搬数据更贵。会讲 gather、reduce、all-reduce 这些经典集合通信操作；模型参数、激活、梯度和优化器状态要分片到多块 GPU 上，再把正确的数据送到正确的节点计算、写回。可以按数据、模型、层、序列、专家来切分，各有取舍。
  • 推理：越来越重要，不只聊天时用，强化学习的 rollout、测试时计算、生成合成数据、评估都要用。分两个阶段：预填充，把提示的所有 token 前向一遍、建立键值对，很像训练；解码，一次生成一个 token，很快就受内存限制，这是推理难的原因。加速方法：剪枝大模型得到便宜的模型、量化、蒸馏；推测解码，用便宜的模型先猜一串 token，再让完整模型并行检验，猜对了就全部接受；专门的推理内核；作为服务时，请求在不同时间到来，要想办法组批，而训练时批是预先定义好的。

作业二用 Triton 实现内核，做一些并行训练，助教们可能会改版。他推荐 Google 一些人写的《How to Scale Your Model》，对屋顶线分析、Transformer 的计算等提供了很好的概念理解，虽然讲的是 TPU，但高层概念相通，现在也新增了讲 GPU 的一章。

3. 缩放规律

假设有 $10^{25}$ 次浮点运算（几千万美元的算力），该训练什么模型？搞砸了就是一大笔钱，而且那个规模下只能训练一次，没法照常调超参数。关键的观念转变是：不要只想着训练一个模型，而要想一个"缩放配方"，即从算力预算到一组超参数（一个配置文件）的映射。对给定配方，在小规模上做一批实验，拟合缩放规律，预测目标规模下的损失。这样可以用小规模实验去优化面向大规模的配方，并在真正训练前预测能达到的损失，还能拿去融资："我做了小实验，我认为能训出 GPT-5 水平的模型，请给我很多钱。"

他说另一个误解是缩放规律是自然定律，它们不会自动出现，要通过精心构建配方才能"让它存在"。配方必须能外推：随着规模变大，学习率是不变还是下降，批大小增加多少。为了得到可预测的缩放规律，要考虑怎样参数化模型才能实现"超参数迁移"，即小规模用的超参数在大规模上同样适用，或是其可预测的函数；如果学习率在某个规模是 $10^{-5}$、在另一个规模是 $10^{-4}$，就没法猜出大规模的学习率。所以可预测性至少和最优性一样重要。

经典问题：给定浮点运算预算，该训更大的模型还是用更多 token？这就是 Kaplan 等人和 Chinchilla 的算力最优缩放规律：对每个预算（比如 $6\times10^{18}$ 到 $3\times10^{21}$）扫描不同模型大小，取最好的，拟合出预算到参数量的曲线，幸运的话大致是直线，不幸的话散得到处都是，说明无法可靠预测。粗略的经验法则是训练 token 数约为参数量的 20 倍，比如 700 亿参数的模型训练约 1.4 万亿 token，具体数字随数据集和架构变化；这也没考虑推理成本，现在很多模型较小，但训练的 token 远超算力最优，因为推理时想要小模型。Marin 项目在"预注册"结果：在不同预算上拟合缩放规律，把预测外推到 $10^{22}$ 次浮点运算，那个大模型正在训练，可能当晚就完成，下节课报告预测得准不准。

作业三定义一个训练 API：你提交超参数配置，返回一个损失。实际上是课程组离线训练了一批模型做成缓存，看起来像在训练。建议拟合缩放规律并外推，最后给定一个预算，评估你的模型落在哪里，模拟手握一亿美元预算时的高压场景，只是风险很低。

4. 数据

数据质量基本决定模型有多好；也可以说数据反映了你想让模型做什么：说多种语言、对话、做长时间的 Agent 编程。先讲评估，它定义了你想要的能力。内部评估用于模型开发，要求随规模平滑变化（要可预测），看的是相对表现，因为困惑度的绝对数值没什么意义；外部评估是给客户、审稿人看的，生态效度很重要，两者用途不同，常被混为一谈。困惑度至今仍是衡量模型内在质量的好方法，不用担心"刷榜"；评估数据最好是互联网上没有的，避免污染。语言模型号称通用，所以需要很多样的评估，可以平均成一个数，但平均往往混杂了很多不同的东西。

数据不会从天而降，要主动整理：抓取的网页、书（现在有争议）、arXiv 论文、GitHub 代码等，2021 年的 The Pile 就很多样。法律问题很重要：用有版权的数据训练是否合理使用，有时要授权，很多 GitHub 代码没有许可证，你是假定可用还是保守地假定不可用？数据也不只是文本，有 HTML、PDF、代码目录，需要处理：转换成文本、过滤（Common Crawl 里随便一个文档通常很差）、去重、混合多个来源，以及最近很活跃的合成数据（把真实数据改写得更接近下游任务，或者改写成 Wikipedia 风格等）。数据可用于预训练、中期训练（通常是放在预训练末尾的高质量数据，包括大型代码仓库、书籍等长上下文数据）和后训练（对话、带工具调用的 Agent 轨迹）。作业四从原始网页抓取数据出发，做过滤、去重、清洗，他说这是"脏活"，但是从零构建语言模型的重要部分。

5. 对齐

前面都是全监督（预测下一个或几个 token），模型到这一步应该已经不错了，还可以用弱监督进一步改进，因为批评往往比生成容易：不一定有某个提示的标准回答，但可以说明什么是好的。基本模板是：模型生成回答，由人、验证器或大模型评委打分，更新模型偏好更好的回答，可以用 PPO、GRPO 等强化学习算法，偏好数据可以用更简单的 DPO。强化学习不稳定、难调，他个人倾向于尽量待在全监督里，最后不得已再用强化学习，"有些人不知为什么就是喜欢做强化学习"。大规模做强化学习、最大化吞吐还有很多系统挑战：要有推理服务器和训练服务器，推理服务器生成 rollout，尤其环境涉及代码执行时，是一整套编排；有的 worker 落后会带来离策略问题，要在"同策略"和最大化吞吐之间不断权衡。作业五还在定，去年是实现 DPO 和 GRPO 并在数学基准上跑通，今年希望更贴近现实。

再次强调效率，包括数据效率和计算效率：你有数据、有算力、内存和通信带宽，要在固定资源下按某种评估造出最好的模型。从这个角度看很多设计：系统显然是计算效率；分词也是，用原始字节在今天的架构下计算效率很低；很多架构改动是为了减少内存或浮点运算，很多是为了更快的推理；数据过滤也是，坏数据不一定伤害你，但固定预算下花在坏数据上的时间就是没花在好数据上的时间；缩放规律就是用小得多的模型做有效的超参数调优。如果将来变成数据受限，具体决策可能改变，但思维方式不变。

五、分词

他推荐 Andrej Karpathy 讲分词的视频。原始文本是 Unicode 字符串，语言模型是在 token 序列（通常表示为索引）上的概率分布，所以需要一个把字符串编码成 token、再把 token 解码回字符串的过程，能完整往返的就是分词器。

分词器有些让人恼火的特点，这也是人们想去掉它的原因：一个词和"空格加这个词"是不同的 token，很多 token 都是"空格加词"的形式，"hello"和" hello"是两个毫不相干的索引；数字有时每几位一个 token，有时可预测有时不可预测，有的分词器让每个数字单独成为 token，但会让 token 数暴增。GPT-5 的分词器能把字符串编码成索引再解码回来，分词器必须能往返，不能往返就有问题。

压缩率是每个 token 平均多少字节。比如一个 20 字节的字符串被分成 8 个 token，压缩率是 2.5。压缩率越大序列越短，因为注意力是平方复杂度，这很好。增大词表可以提高压缩率，但会带来稀疏性，因为词表里每个元素都被当作独立的东西；现在的分词器（尤其多语言的）有 10 万到 20 万个 token。

几种朴素做法：

  • 字符级：每个 Unicode 字符是一个整数（Python 的 ord），约 15 万个字符，词表很大但不算离谱；更大的问题是很多字符很少出现，词表利用率低，压缩率也不好。
  • 字节级：用 UTF-8 编码，有的字符一个字节，有的多个字节；所有数都在 0 到 255 之间，词表小，但压缩率是 1，序列很长。
  • 词级：按空格或正则表达式切块，以前 NLP 就这么做。每个 token 有意义，因为词有稳定的语义，压缩率不错；但词表等于训练数据中不同块的数量，可能很大，而且可能无界，测试时遇到没见过的 token 只能用丑陋的 UNK 标记，还会搞乱困惑度的计算。

实际用的是字节对编码（BPE）。它很早就用于数据压缩，后来被引入神经机器翻译，GPT-2 第一次把它用于大语言模型。思路是在原始文本上训练分词器，构建贴合数据的词表；稀有的序列会拆成更小的单位，而不是变成 UNK；常见序列成为一个 token，稀有序列被拆成多个。算法：把语料看成一个长字节序列，每个字节起初是一个 token；反复找出出现最频繁的相邻 token 对，把它合并成一个新 token。

例子："the cat in the hat"。先转成字节，统计相邻对出现次数，(116, 104)（即 t 和 h）出现两次，取第一个最高频的对，创建新 token 256 代表"th"加入词表，把序列中所有的 116 104 替换成 256；下一轮找到 (256, 101) 合并成 257，再合并得到 258。序列越来越短，词表越来越大，这个玩具例子的压缩率是 1.5。对新文本编码时，按训练时的合并顺序依次应用这些合并；解码得到原字符串。

这个实现是对的，但极慢。作业一要让它变快：编码时会遍历所有合并（数量约为词表大小减 256），应该只遍历相关的合并，需要建索引；要处理特殊 token，概念不深但对现代分词器很重要；实际上不是对整个字符串分词，而是先把文本切成块（预分词）再对每块分词，快得多；Python 不够快的话可以用 Rust、C 等实现。

小结：分词器在字符串和 token 之间转换；字符级、字节级、词级各有严重缺点；BPE 是数据驱动的有效启发式。即使将来去掉分词，替代方案也要满足两个性质：Transformer 需要在序列的某种抽象上操作，这在视频、DNA 这类单个单位信噪比很低的数据上最明显，需要先抽象到能建模的层面；块的大小要可变，实现自适应计算，不能对所有字节一视同仁。下一讲讲资源核算，他称之为"入门版系统"，之后再回到架构。
