第八讲：并行（二）：大规模训练的并行策略

TPU 与 GPU 的网络哲学，ZeRO 1、2、3（FSDP）怎样几乎免费地省内存，流水线并行和零气泡调度，张量并行、序列并行和激活内存，专家并行，怎样组合成"4D 并行"，以及 OLMo、DeepSeek、Llama 3、Gemma 2、Qwen 3 等实际训练的并行配置

主讲：Tatsunori Hashimoto
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、为什么要并行，以及硬件

上一讲 Percy 讲了并行的底层机制，这一讲 Tatsu 讲现代语言模型训练中并行的各种细节。在最大规模上，要同时用上多种并行策略，所谓"4D 并行"，甚至更多。作业中要根据给定的网络拓扑和模型找出最优并行策略。最后会看一些公开了细节的大规模训练。

并行要解决两个瓶颈：算力，单块芯片不够，最快的超级计算机有 EFLOP/s 级的算力，单块 GPU 远远不及；内存，模型太大放不进一块 GPU，要切分。一个贯穿全讲的概念是：节点内并行连接很快，可以做通信很贵的事；节点间通信慢，要用更尊重通信约束的方法。讨论是算法层面的，以集合通信原语为单位计算通信量。要记住 all-reduce 等于 reduce-scatter 加 all-gather，后面一个算法就是靠这点"免费"得到收益。

TPU 和 GPU 的网络很不同。TPU 的网络是环面网格（toroidal mesh）：可以想成一个网格，两端绕回来相连（实际是三维的），每块芯片只和邻居相连，拓扑简单，可以无限扩展，邻居数量不随规模变化。GPU 的哲学是"全互联"，网络像一棵树（叫胖树）：最底层的 GPU 连接极快，成组连成 pod，pod 之间通过骨干交换机相连，节点越多树越大，通信成本越高或拓扑越复杂。所以只和邻居通信时 TPU 很好，成本低，同样功耗下每条连接可以更强；通信模式随机、难以预测时 GPU 更灵活。Bill Dally 和 Jeff Dean 也讨论过：GPU 适合 MoE 这种 token 路由到不同专家、通信模式不清晰的情况；TPU 适合可预测切分的稠密模型（比如张量并行）。他说本来讲到这里就结束了，结果当天早上 Google 发布了第八代 TPU 8i 和 8t，他一看 8i 是树形拓扑，转向了更全互联的连接；这说得通，现在的语言模型是 MoE，推理时 token 在专家之间路由，带宽到处飞，需要全互联；8t（训练芯片）的跨机架连接也更像 GPU，有一个叫 Virgo 的全互联交换网络。他认为这是一种趋同进化，工作负载在决定需要什么样的网络。

他还提到华为昇腾的思路：单芯片比 H200 差很多，矩阵乘法慢；但用一整个机架的光纤交换把 384 块芯片连起来，用数量弥补单芯片的慢。代价是功耗是同等 NVIDIA 系统的四倍。就像只用 SRAM 的芯片：如果愿意付电费，可以用蛮力解决很多通信问题、更激进地横向扩展；如果要在功耗和制造上都高效，就会走到另一个地方。这是很有意思的硬件取舍。

现在的计算单位不是 GPU，而是整个数据中心。我们想控制内存用量、控制能调动的算力，并且尽量无损地用上所有资源。

二、数据并行与 ZeRO

数据并行最简单。先忘掉 Adam，用普通 SGD，批大小 $B$：把批切到 $M$ 台机器上，每台 $B/M$ 个样本，各自算梯度，再同步求和。算力上，只要每块 GPU 有足够样本就完美扩展；通信上，每个批要通信约 2 倍参数量（梯度一来一回）；内存上完全没有节省，每块 GPU 都有完整模型和同样大小的激活。

内存情况其实很糟：要存的远不止参数。按精度不同，经验法则是大约 5 份权重、每个参数 16 字节：参数本身；梯度；也许还要高精度的累加器；Adam 还要一阶和二阶矩，可能要用高精度存。累加器、一阶矩、二阶矩统称优化器状态，是内存的大头。朴素数据并行把这些全部复制到每块 GPU，内存随加速器数量线性浪费。可以把优化器状态切分到不同 GPU，再切分梯度，极端情况下切分所有东西，课件里的例子是从 120 GB 降到 1.9 GB。问题是代价多大，他说令人惊讶的是很多是免费的。

  • ZeRO 第一阶段：只切分优化器状态，每个 worker 负责更新参数的一个切片。每个 worker 用自己的数据算出完整梯度；用 reduce-scatter 把梯度发出去，每个 worker 只拿到与自己负责的那片参数对应的、所有人梯度之和（通信量约为参数量）；每个 worker 用自己的优化器状态更新自己那片参数；再用 all-gather 把更新后的参数发回给所有人。朴素数据并行是一次 all-reduce（2 倍参数量）；第一阶段是 reduce-scatter 加 all-gather，正好等于一次 all-reduce，通信量完全一样，内存省下来了，是免费的。
  • ZeRO 第二阶段：再切分梯度。难点在于连完整梯度都不能构造出来。办法是系统上的技巧：反向时沿计算图往回走，每算完一层的梯度，就立刻把它归约发给负责的 worker，不再需要的梯度立即释放。逐步做和一次性做通信量一样，所以也没有额外成本，最后同样 all-gather 参数。
  • ZeRO 第三阶段（即 FSDP）：连参数也切分，每块 GPU 任何时候只看到参数、梯度、优化器状态的一片。做法是沿计算图按需收发参数：前向时，对某一层先 all-gather 它的权重，前向完就释放；反向时，需要激活（保留着）和该层参数，再 all-gather 一次参数，反向算出梯度后立刻 reduce-scatter 出去，释放权重，如此逐层重复，最后更新权重。通信是两次 all-gather 加一次 reduce-scatter，多了一次 all-gather；而且每层都在通信，看起来开销很大。他说反直觉的是，它几乎没有开销，靠两个思想：一是扫过计算图，做必要的通信后立即释放内存；二是计算与通信重叠。PyTorch FSDP 论文里的图显示：all-gather 第 0 层后做前向 0，做前向 0 的同时已经在 all-gather 第 1 层，以此类推。只要计算足够多、网络足够快，计算时间长于通信时间，通信就能藏在计算下面，只有一些小气泡。实际运行 FSDP，GPU 利用率很接近单卡。作业里要实现 FSDP，写一个包装器包住任意模块即可：all-gather，计算，释放，反向时重复。

学生问这是不是从下一块 GPU 拿梯度来算上一层，他说那是流水线并行；这里每块 GPU 都完整地走一遍整个模型，只是没有一块 GPU 同时持有全部参数，每个计算操作之间请求参数、释放参数。为什么通信量不乘以层数？因为每次通信只涉及一小层，加起来和一次对整个网络做 all-reduce 相当。实际效果：在 8 块 A100 上，基线连 7B 模型都放不下，用 ZeRO-3 能放下约 500 亿参数的模型；换成其他 GPU 大致按显存线性换算。

为什么不能到此为止？一是数据并行消耗的是批大小这种资源：批大小为 8，就不能用超过 8 块加速器；批大小也不能无限增大，有一个"临界批大小"，超过之后再加样本的收益不如多走一步 SGD，无限大的批不如无限多的单步。于是要在"小批、GPU 闲着"和"大批、优化受损"之间取舍。二是内存问题仍在：第一、二阶段不切参数；第三阶段切了参数，但激活等内存一点没减。所以需要更细粒度地切分模型。

三、模型并行

模型并行也切分参数，但概念上的区别是：现在要通信的是激活。FSDP 切了参数，但只是一个包装器，正常计算，在计算前把参数传来传去；模型并行中，比如一层在 GPU 0、下一层在 GPU 1，就要传它们之间的激活。包括流水线并行（切层）、张量并行（切矩阵）、专家并行（把专家分到不同地方）。

流水线并行

按层切，放到不同 GPU 上，前向传激活，反向传部分梯度。朴素做法的图很糟：4 块加速器，每块负责四分之一的模型，横轴是时间：第 0 块计算完交给第 1 块，然后就闲着直到最后，任何时刻只有一块在工作，反向也是如此，这些空闲就是"气泡"。解决办法是流水线化：把批切成微批，第 0 块处理完一个微批就交出去，开始处理下一个。气泡占用的时间与有效计算之比大约是

$$\frac{\text{气泡}}{\text{计算}} \approx \frac{p - 1}{m}$$

$p$ 是流水线级数，$m$ 是微批数，所以要很大的批才能把气泡压到接近 0，这又是批大小作为资源的另一种花法。

坊间说法是：并行代码看起来还算合理、大家都看得懂，直到你实现了流水线并行。那为什么还要用？因为相比数据并行能省内存（层被切开了），能和数据并行组合；更重要的是通信性质很好：只传激活（$B\times S\times H$），是点对点的而不是全互联，几乎总比传整个参数矩阵的数据少。所以流水线并行放在最慢的网络链路上，比如跨数据中心或跨较慢的 pod。NVIDIA 的 Megatron 论文有很好的参数扫描：批大、流水线级数大时，利用率接近不用流水线并行；批小时利用率迅速下降。

更聪明的调度可以继续减少气泡。DeepSeek 论文里巧妙地安排前向和反向的顺序，让不同微批的前向块穿插在反向块之间。更聪明的是"零气泡流水线"：反向时每个节点要做两件事，把偏导数继续往回传（B），以及计算本层权重的梯度（W）。B 对流水线很关键，因为下一级要等它；W 是计算图上的叶子，什么时候算都行。所以尽快算 B，把 W 推迟到计算有空档时再做，几乎能把流水线填满，取决于 W 和 B 的工作量。他说这很复杂，但很聪明。

张量并行

流水线并行切深度，张量并行切宽度：矩阵乘法可以拆成小矩阵乘法再把部分和相加，和分块是同一个思想。以 MLP 为例：输入 $X$，乘 $A$，过 GELU，乘 $B$ 降维，输出 $Z$。张量并行把 $A$ 按列切成两块，$B$ 按行切成两块，并行计算，最后合并。前向中，函数 $f$ 是恒等（把 $X$ 复制两份），$g$ 是 all-reduce（合并结果）；反向中两者对调，$g$ 是恒等，$f$ 要把偏导数求和，这种对偶在写张量并行时很重要。具体切法：每个 Transformer 块中，MLP 的输入投影和注意力的投影按列切；MLP 的降维投影和注意力的输出投影按行切；层归一化、非线性、MoE 的路由器这些小东西在各机器上完整复制，不值得切。

张量并行很吃通信：每次矩阵乘法都伴随激活大小的 all-reduce，而且很频繁，所以只在节点内做。GPU 一个盒子里 8 块紧密相连，最多到 8；跨节点后互联慢得多，性能会大跌。这就回到 TPU：TPU 没有"8 块快、出了节点就慢"的区分，只有一个大网格，可以在规则的通信模式下保持高带宽，所以 TPU 的拥护者会说可以做很大规模的张量并行，TPU 和 GPU 上张量并行与流水线并行的比例会很不同。

比较两者：都切模型，都省参数和可能的激活。张量并行没有流水线气泡，网络够快时可能达到满利用率，复杂度也低（只是切矩阵乘法）；缺点是通信量大得多，从 $B\times S\times H$ 的点对点，变成大约 $8\times B\times S\times H$ 量级的 all-reduce，而且不是点对点而是全互联。所以有高速互联时用张量并行，其他时候多半用流水线并行。

激活内存和序列并行

最朴素的看法是内存就是参数，再加上优化器状态；但 PyTorch 剖析器显示的实际内存还有大量动态部分：激活（图上一大块红色的峰），以及反向时要存的梯度，内存峰值出现在开始往回扫之后、激活还没释放的时候。对更大的模型、中等长的序列，激活远远超过参数内存，所以省内存的策略必须处理激活。

经验公式：全部存储时，每层激活内存约为

$$SBH\left(34 + \frac{5AS}{H}\right)$$

$S$ 是序列长度，$B$ 是批大小，$H$ 是隐藏维度，$A$ 是注意力头数。$SBH$ 的依赖是根本的：每个序列位置、每个批元素、每个隐藏维度都要存点东西。$5AS/H$ 这一项来自平方级的注意力（包括 dropout），用 FlashAttention 重计算可以去掉。张量并行把 MLP 部分（34 里的 24）和注意力头部分除以张量并行度 $T$，这是大头；但层归一化、dropout、注意力和 MLP 的输入（残差，反向要用）不随 $T$ 减少，剩下 $10SBH$ 的惩罚。他说如果你是 Google、想用上千块 GPU 做张量并行，这部分就很可惜。

序列并行（他说这个名字很误导，后面的上下文并行才更配这个名字）：把剩下这些轻量操作（层归一化等，计算很少）沿序列维度切分，在需要时 all-gather、用完 reduce-scatter，概念上很像 FSDP，按需物化。前向 $g$ 是 all-gather，$\bar g$ 是 reduce-scatter，反向时对调。结果：

  • 不并行：$SBH(34 + 5AS/H)$；
  • 张量并行：$SBH(10 + \frac{24}{T} + \frac{5AS}{HT})$；
  • 张量并行加序列并行：$SBH(\frac{34}{T} + \frac{5AS}{HT})$，完全线性；
  • 再加选择性的激活重计算（去掉 softmax 那部分）：$\frac{34\,SBH}{T}$。

最后这个是正常训练中激活内存比较合理的下界，手算模型能否放进 GPU 时可以用：至少要这么多激活内存，再加优化器状态、参数、梯度。学生问 MLP 能不能也重计算，他说可以，但要在反向时再跑一遍 MLP，很贵；注意力的重计算便宜一些，可以逐块做，而且不想付平方代价。

专家并行

大多数大模型都是 MoE，可以利用专家并行：和张量并行类似，切分 FFN，有通信代价，只是切的是整个 MLP（不同专家放到不同设备）。系统行为上也像张量并行，是高带宽的并行原语，也能减少激活。NVIDIA Megatron 的并行指南说：MoE 层在专家并行和张量并行之间应优先用专家并行，因为矩阵切得太细，矩阵乘法变小，利用率下降；路由稀疏的 token 激活比路由稠密的张量并行激活容易；既然有 MoE，不如把专家分到各设备上。

但专家并行仍然很复杂。DeepSeek 的 DeepEP 库（他最喜欢的 DeepSeek V3 时期成果之一）直接看底层 GPU 网络原语，合并操作、让硬件处理某些操作，让 MoE 的路由和分发尽量高效；NVIDIA 有类似的 HybridEP 库。难在：每个 MLP 都要做大量 all-to-all，把 token 路由到各处，而且对延迟很敏感，因为计算在等 token 到达。DeepSeek 为了榨干性能，甚至找到了未公开的 PTX 指令来加速网络通信。

组合时，其他并行基本可以像乐高一样拼，专家并行有额外约束：老的库里，数据并行和专家并行的副本是同一组，比如数据并行度 8，专家也分到这 8 个副本上，这限制了专家并行的上限，也约束了数据并行和张量并行怎样配合。还有一个问题：MoE 只改 MLP，不改注意力，专家并行只并行了 MLP；注意力需要较高的张量并行度来切分，但对 MLP，张量并行和专家并行都高时矩阵被切得太小，利用率很差。所以近年的系统把注意力和 MoE 层的张量并行解耦，各用各的，组合更复杂但更有效。

上下文并行

上下文并行（环形注意力）把很长序列的激活切分到不同加速器，按环形把数据传给需要的设备，契合 TPU 的网格拓扑，环形注意力的原论文显示在 TPU 上效果很好。用于长上下文扩展阶段和模型服务。他不细讲，因为和前面的概念重叠。

四、组合起来

他做了一张大表，把各策略的缺点标红，说明没有哪种策略严格占优，都是取舍。比如 FSDP 很好，但不减激活，还消耗全局批大小；为了减激活加张量并行，它不消耗批大小，但需要快网络；为了利用慢链路，再用其他策略。所以很多大规模架构会组合多种策略。学生问流水线和 FSDP 能否用于 MoE，他说当然可以，前沿模型都大量使用数据并行（或 FSDP）、流水线并行和张量并行；标准建议是专家并行像张量并行一样到 8 左右，现在大家不太遵守了。

并行可以算：每种切分策略每层多少计算、多少通信，不同设备分给不同策略时怎样扩展。可以画出在给定批大小和并行策略下 GPU 的利用率（计算时间与通信时间之比），只要计算时间长于通信时间，原则上通信能藏起来。直观上：每芯片批大小足够大（比如 2000）时，只用 FSDP 就完全受计算限制；批变小后 FSDP 会变成受通信限制，这时加入张量并行，把曲线向小批方向推，再加别的策略继续推，这就是 3D、4D 并行。

处方其实很简单：

  1. 在模型放进内存之前，用一切必要手段切分模型：快速互联内用张量或专家并行（每台机器 8 块 GPU，就用 8）；然后用流水线并行或 ZeRO-3（FSDP）切到能放下。
  2. 放下之后，其余 GPU 全部用数据并行。
  3. 批太小就用梯度累积提高利用率。

Megatron 的 MoE 并行指南说的就是这些，只是顺序相反：尽量少用模型并行、尽量多用数据并行；张量并行和专家并行留在一个 NVLink 盒子内；跨节点用流水线并行；MoE 优先用专家并行；长序列用上下文并行。序列并行通常是和张量并行一起用来减激活的附加项。学生问传闻中的"循环 Transformer"会不会改变这些，他说不太相信那些传闻；如果是，可能会影响 FSDP，因为 FSDP 依赖"取权重、扔权重"，循环中不扔；但它参数效率高得多，很多模型并行可能就不那么重要了。

NVIDIA 与 Matei Zaharia、Deepak Narayanan 等人的一篇较早的论文（网络基础没怎么变，仍很有参考价值）做了大量大规模并行训练：随着规模扩大，数据并行先开到最大，张量并行增加到 8 就停，之后流水线并行不断增加，到最大规模时数据并行反而减少到 6，因为需要大量张量和流水线并行来放下模型，剩余预算才给数据并行。即使到极多的 GPU，利用率仍然很平稳，这也是为什么人们敢建巨型数据中心甚至跨数据中心训练。论文还显示张量并行超过 8 就出问题；流水线并行需要大批来保持利用率；激活重计算反直觉地有用：多做计算省下内存，内存换成更大的批，利用率反而更高。

五、实际训练的并行配置

  • OLMo（AI2，7B，在 Dolma 数据上训练）：完全用 FSDP，在很多加速器上扩展得出奇地好，他说很多 7B 左右的模型纯用 FSDP 训练。
  • DeepSeek V1：数据并行加 ZeRO-1，加张量、序列和流水线并行。DeepSeek V3（MoE）：流水线并行加专家并行，不用张量并行，专家并行很激进，64 路，把 8 台机器组成一个专家并行域，并借用流水线调度的技巧避免专家并行出现低利用率时段。
  • 零一万物的 Yi：ZeRO-1 加张量和流水线并行，经典组合；到 MoE 时把张量并行换成专家并行。
  • Llama 3 405B：报告给出了各阶段的完整并行分解。主预训练阶段是张量并行 8、上下文并行 1、流水线并行 16、数据并行 128；最后的长上下文扩展阶段加大上下文并行、减少数据并行，处理这个很吃内存的阶段。它是巨大的稠密模型，所以用张量并行。训练期间 GPU 故障了 148 次（课上数字），所以除了快速并行，还需要冗余来应对故障，这是分布式系统的挑战。
  • Gemma 2（Google）：只用 FSDP 加张量并行和序列并行。他说这印证了 Google 的说法：在 TPU 上不需要流水线，在大环面网格上做张量并行就行；能否无限扩展他不确定，但在 Gemma 的规模上成立。
  • NVIDIA 的 Megatron Bridge 仓库发布了很多推荐配置：Mixtral 8x22B 是专家并行 8、流水线并行 4，再加张量并行 4（用于注意力层），符合专家并行约 8 的建议；Nemotron 3 Super 沿用 DeepSeek V3 的思路，大量专家并行，加上上下文并行（因为做长上下文扩展）；Qwen 3 沿用 DeepSeek 的配方，专家并行 32、流水线并行 8、张量并行 2（切注意力矩阵）。NVIDIA 的基准测试还显示，张量并行内部的各种子配置也会明显影响性能，系统集成很重要。

共同点：尽可能多用数据并行，把数据并行域开到最大；张量并行几乎总在 8 以下；专家并行有时可以很大，部分要归功于 DeepSeek V3 为大规模专家并行训练建的基础设施。

总结：要考虑多 GPU、多节点甚至多数据中心的并行，有快链路也有慢链路，有消耗批大小等各种资源的技术，要把所有方法都用上；但组合它们有相当简单的经验法则，最终能几乎充分利用计算硬件。下周讲缩放规律。
