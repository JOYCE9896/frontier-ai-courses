第四讲：注意力的替代方案与混合专家模型

长上下文怎样控制成本：线性注意力、Mamba 2、Gated DeltaNet 和 DeepSeek 稀疏注意力；混合专家模型（MoE）为什么流行，路由怎样设计，怎样训练（负载均衡损失），系统问题，以及 DeepSeek V1 到 V3 的演进

主讲：Tatsunori Hashimoto
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、长上下文的成本

上一讲是对基本 Transformer 的调整，这一讲讲两项更复杂的发展：改注意力块，用架构改动支持长得多的上下文，多数做到对序列长度线性依赖；改 MLP 块，用混合专家模型在同样的计算下拥有更多参数。

各大厂商都在争相提供越来越长的上下文，以支持 Agent 等复杂工作负载。随着序列变长，前馈层的计算线性增长，注意力是所有位置两两相连，平方增长，很快超过前馈层：大模型在较短序列时前馈是主要成本，序列很长时注意力成为问题。已有的工具：一是上一讲的混合方式，比如每八层一层全局注意力，其余是局部注意力；二是系统工程。他强调常数因子非常重要，受经典理论训练的人容易只看大 O，但 FlashAttention 对注意力成本的影响巨大：它把注意力运算重新安排成对系统友好的形式，尽量减少内存搬运，在某些长度上比原生 PyTorch（短序列时只有 30 到 40 TFLOP/s）快一倍左右；而且因为不再实际构造巨大的注意力矩阵，有些原本放不进内存的长度也能运行。它不解决平方复杂度，但常数因子很强大。要到五百万、一千万 token，这些技巧可能就不够了，需要线性复杂度的方法。

过去尝试很多，有些走了弯路；近两年出现了一套在大规模上被验证有效的配方，所以今年他第一次讲线性注意力。

二、线性注意力及其扩展

核心思想：乘法的结合律

注意力可以写成 $\rho(QK^\top)V$，其中 $\rho$ 是逐行的 softmax。先忽略 softmax，假设 $\rho$ 是恒等映射，就可以改变括号的位置：

$$(QK^\top)V = Q(K^\top V)$$

左边先算 $QK^\top$，代价是 $O(n^2 d_k)$，$n$ 是上下文长度，可能上百万；右边先算 $K^\top V$，代价依赖于 $n\,d_k\,d_v$，键值维度通常是几千到几万，没人的隐藏维度有一百万。结合律改变了对序列长度的依赖。

更妙的是，在自注意力（因果）情形下，右边的乘法可以写成 RNN：从左到右扫描时，维护一个状态

$$S_t = S_{t-1} + k_t v_t^\top,\qquad y_t = q_t^\top S_t$$

这和上面的稠密形式等价。所以线性注意力兼得两种好处：训练时用稠密形式，可以并行；推理时用 RNN 形式，状态大小固定，一直往前传。缺点是它是线性的，表达力不够。MiniMax M1 是一个规模相当大、表现很好的中国开源模型，用 7:1 的混合：七层线性注意力加一层完整的 softmax 注意力，表现可以和 o3、DeepSeek R1 等竞争，对上下文长度的依赖温和得多。到目前为止，还没有人在大规模上证明完全线性的注意力可行，下面讲的都是混合架构。

Mamba 2：加一个遗忘门

Mamba、Mamba 2、Mamba 3 是 Albert Gu、Tri Dao 等人的状态空间模型家族，最初从状态空间理论推导而来，但从机制上看是线性注意力的简单扩展。线性注意力的主要问题是状态总是全部往前传；从 LSTM 时代就知道，要能决定什么时候传、什么时候遗忘。所以加一个门 $\gamma_t$：

$$S_t = \gamma_t\, S_{t-1} + k_t v_t^\top$$

$\gamma_t$ 只依赖当前输入 $x_t$，不依赖状态，所以计算仍然简单，仍有并行（稠密矩阵乘法）和循环两种等价形式。（Mamba 2 还有一项类似残差连接的 $D\,v_t$ 项，让当前 token 的值直接通到输出，不是状态更新的核心。）NVIDIA 的 Nemotron 3 用 Mamba 2 作为轻量层，间或插入完整的 softmax 注意力，表现可以和 Qwen 3 思考模式、GPT-OSS 比，在长上下文下吞吐量很好。他说这些是开源的"小前沿模型"，不是最大的前沿模型。

Gated DeltaNet

经验法则是：只要门只依赖输入、不依赖状态，就保留了并行训练和循环推理的对偶性，可以把循环做得更复杂。Gated DeltaNet 可能是现在用得最广的状态空间模型，Qwen 3.5 在大规模上使用了它。它在 Mamba 2 的基础上加了第二个门 $\beta_t$，控制是否把当前信息写进状态（$\beta_t=0$ 就是不写入），很像 LSTM 的输入门和遗忘门，虽然推导出发点很不同。另一个来自 DeltaNet 的改动是更新方向：写入当前键 $k_t$ 的信息时，同时擦除状态中已有的同一方向的内容，状态更新里乘上 $(I - \beta_t k_t k_t^\top)$，近似一个投影掉 $k_t$ 方向的投影算子（没做单位归一化，所以不完全是）。这个更新在快速权重编程、测试时训练等领域也被重新发明过，从求解某种元学习最小二乘问题出发，会得到完全一样的解。

Qwen 3.5 及其前身 Qwen3-Next 是最好的开源模型之一，用 3:1 的 Gated DeltaNet 与注意力混合：表现几乎不受影响，推理特性很好，随着上下文变长，Qwen3-Next 的解码吞吐量远高于 Qwen 3。严格对照的研究不多，字节跳动 Seed 和 UC Santa Cruz 的一项研究比较了不同混合比例：最好的几种架构（包括 Gated DeltaNet）在线性层比例较低时几乎没有损失，超过某个点后长上下文表现明显下降，完全改成 RNN 时所有架构都明显变差；问答等任务也是同样的趋势。单键检索这类任务，各种长上下文架构都专门优化过。

学生问并行形式和循环形式是否等价。他说第一步去掉 softmax 时是有损的，之后线性形式到循环形式的等价是精确的。他还说，经过检验的方法大多收敛到了这种简单的、类似线性注意力的循环形式，最后很像 LSTM。

DeepSeek 稀疏注意力（DSA）

另一类高效注意力。DeepSeek V3.2 提出 DSA：不对所有 token 做注意力，而是先用一个轻量的"索引器"从长上下文中挑出一小部分 token，再对这部分做完整注意力。索引器计算 $q$ 和 $k$ 的内积，过 ReLU，乘上由前面 token 得出的权重，得到每个位置的分数，取 top-k 个位置参与注意力。索引器很轻，完整注意力只在很小的子集上做。DSA 和 GLM 都表明不必一开始就带着它训练：先训练普通 Transformer，在长上下文扩展阶段再插入索引器、训练模型适应它，额外成本很小。DeepSeek V3.2 和当时的 Claude Sonnet 4.5、Gemini 3 等前沿模型相当，预填充和解码的成本随长度增长比上一代没有稀疏注意力的 DeepSeek 平缓得多。GLM 5（他认为是最好的开源模型之一）也采用了 DSA，并做了消融：完整使用 DSA 训练，相比全注意力几乎没有损失，即使在 RNN 类架构很难做好的长上下文检索任务上。

它不是线性的，索引器仍要对所有位置算 $q$、$k$ 内积，是平方的，但可以做得很便宜：用更低精度、投影到更低维度、让权重很小；后面的完整注意力虽然也是平方，但只在长度为 $k$ 的子集上，$k$ 可以控制，通常和短上下文的长度相近。又一个"别太纠结是否平方，常数因子很重要"的例子。常见流程是：短上下文预训练、长上下文扩展、后训练。他说能把一个看起来很吓人、不可微的 top-k 插上去还能用，有点出人意料；下半讲会看到 top-k 选择不必那么可怕。

学生的问题：去掉 softmax 会不会带来稳定性问题？他说没听说，softmax 往往才是问题来源，可能反而更稳定。未来的注意力会是什么样？他说可能是把这些成功的技巧都组合进去，另外更高一层是用后训练让模型自己管理上下文，比如压缩、检索，很多工作会是把这些层整合起来。能做 FP4 注意力吗？可以，但 softmax 对下溢上溢很敏感，低精度可能有问题，这也是索引器的部分动机：用低精度做选择，再用全精度计算，值向量能更精细地加权。状态空间模型相比 Transformer 的缺点？主要是表达力：softmax 注意力的全连接非常强大，而且好训练。过去注意力相对 LSTM 的优势是能并行训练，现在有了线性注意力的对偶性，并行这一点解决了；但有限的状态要把所有信息带下去，就会丢信息，除非状态和上下文一样大，那成本就很高。

三、混合专家模型（MoE）

是什么，为什么流行

概念上 MoE 不改变游戏，它只是一个更高效的 MLP。要理解它，一是因为现在大家都在发布 MoE；二是它有一些有趣的机制组件，这些原语会在很多地方出现。普通 Transformer 块是注意力、归一化、前馈网络；MoE 把一个大前馈网络换成多个前馈网络（专家），再用某种机制决定每个输入用哪个。假设有四个和原来一样大的专家，参数就是四倍，但每次前向和反向只付一个专家的成本。早期论文就是从参数出发：想要更多参数又不想付更多计算，就这样做。

流行的原因是：保持总计算量不变、只增加稀疏参数，模型普遍会变好，说明更多参数即使每次只激活一部分也有好处。Google 的 Switch Transformer（Fedus 等人，2022）显示，激活参数不变、专家数增加，语言建模的测试损失持续下降；相同训练算力下专家越多效果越好。AI2 的 OLMoE 论文也看到同样的结果，训练速度约为稠密模型的两倍。DeepSeek V2 等早期 DeepSeek MoE 出来时，激活参数少得多，MMLU 表现却一样好甚至更好。MoE 还提供了另一个并行维度：每个专家是天然的一块，可以放到不同设备上，把激活路由过去，这就是专家并行（后面系统部分讲）。学生问这会不会有通信瓶颈，他说要付把激活送过去的通信成本，换来更多的总算力和更少的内存，是否划算取决于网络拓扑等。

西方有几个开源的大型强 MoE：Llama 4、OpenAI 的 GPT-OSS，但他说西方的开源发布基本停滞了；很多 MoE 的研究和训练发生在中国：Qwen、DeepSeek、MiniCPM 做了最早的一些工作，Qwen1.5-MoE 激活 27 亿参数，好于当时很多 7B 模型，这些早期成果说服了开源社区。他特别推荐 DeepSeek 的早期 MoE 论文，里面有大量消融：用稠密层、哈希路由、Switch 路由会怎样等。DeepSeek V3、V3.2、GLM 等很强，他认为未来几年的大模型会是 MoE。

为什么流行得这么慢？Google 2022 年就在推，2024 年以后才真正流行，做研究的人多数还在用稠密模型。因为 MoE 很复杂：基础设施复杂，专家难以高效并行，参数多、放不进单个设备，训练还容易爆掉。也有人把注意力块做成专家，但更少见，也更难驯服，几乎所有大模型都只替换前馈层。

学生问训练时专家也是稀疏的吗？他说是，这正是难点：如果训练时激活所有专家，就能看到哪个专家适合哪个输入，学会路由很容易；但训练时只激活 $k$ 个，不知道其他专家会怎样，却要学会路由，这有强化学习、多臂老虎机的味道，但实际上不用这些方法解决，而是靠启发式和深度学习的"魔法"。路由的粒度是 token 级，路由器非常简单，就是一次矩阵乘法，不会去判断这是不是医学问题，而是"这个 token 看起来像日语，送给 7 号专家"。

路由

设计 MoE 有三个维度：路由函数、专家的大小和数量、训练方法。路由总是选 top-k，可以是 token 选专家、专家选 token，或全局分配。几乎所有 MoE 都用 token 选专家的 top-k；OLMoE 的实验中 token 选择比专家选择的验证损失更低、下游分数更高。

  • 最常见的路由器是一次线性投影：每个专家一个向量，与输入做内积，选最接近的 $k$ 个。Switch Transformer、GShard（Google 早期论文）、Grok、Mixtral、DBRX、DeepSeek 等都用。$k$ 各不相同。
  • 哈希路由：不学习，直接对输入哈希、分给不同前馈网络，居然也有收益，只是不如 top-k，常作为论文基线，实际部署不用。
  • 强化学习学路由：把路由器当策略来学，Bengio 2013 年的早期工作就是这样，对受经典学习理论训练的人来说这是最自然的思路，但开销大、随机性高，而简单的 top-k 配一组启发式就能用，所以不常见。
  • 线性分配：计算所有 token 与专家两两配对的分数，用线性分配精确求最优分配。他作为喜欢"讲得通"的人很喜欢这个想法，但太贵，没在大规模上见过。

top-k 路由的公式：对输入 $u$ 计算每个专家的分数 $s_i = \text{softmax}(u^\top e_i)$，取前 $k$ 个作为门 $g_i$（其余为 0），输出是 $u + \sum_i g_i \,\text{FFN}_i(u)$。他说这和 DSA 很像，在 H-Net 等工作里也会看到这种模式。

DeepSeekMoE 开创了现在广泛使用的两个设计：细粒度专家（把专家切成更小的块、数量更多）和共享专家（有些处理所有 token 都需要，于是让一部分专家始终激活、绕过路由器，其余专家可以更专门化）。他们的消融显示：从 Google GShard 式的 16 个大专家、没有共享专家，到细粒度切分加一个共享专家，两项都带来明显提升，共享专家在 TriviaQA、Natural Questions 上尤其明显。OLMoE 的对照研究认为细粒度、多专家有帮助，但共享专家帮助不大，两者在这点上略有分歧。早期的 MoE 有三个来自 Google，西方早期还有 Mixtral、DBRX、Grok；DeepSeek V1 提出细粒度加共享专家后，大家都跟着 DeepSeek 走，就像稠密模型都以 Llama 为标准，Qwen 3.5、GLM 等现代模型都还在用。学生问共享专家怎样并行，他说共享专家没有并行收益，每个激活都要经过它，可以把它复制到各设备，用内存换通信。

训练：负载均衡

训练时不能激活所有专家，否则要付全部专家的计算；但稀疏就意味着门控决策不可微，也看不到没选的专家会怎样。可选方案有：用强化学习优化门控策略（不流行）；随机扰动（类似探索与利用）；一堆处理稀疏门控、平衡专家分配的启发式。实际用的是第三种。

  • 强化学习：Clark 等人 2020 年的研究表明可以用，但梯度方差大、复杂，不是最优，论文里提出的其他方法就轻松超过了 REINFORCE。
  • 随机近似：来自 Noam Shazeer 等人最早的 MoE 论文，在路由分数上加与输入尺度相关的噪声，再取 top-k 和 softmax。两个专家分数接近时会随机选一个，反向传播会加强有用的专家，相当于打破平局、多探索一些。Fedus 等人 2022 年用了均匀的乘性扰动来让专家更稳健，后来的 Google 论文去掉了，后续消融显示不加这些随机技巧，稳定性和最终质量反而更好。

直接做梯度下降会出现"富者愈富"：被选中的专家得到更多信号，权重变强，于是更常被选，最后包揽一切，这就是专家坍缩（或专家"饿死"）问题，是要用启发式解决的核心。办法是在建模损失上加一个负载均衡损失。Switch Transformer 的版本是：

$$\text{loss} = \alpha\, N \sum_{i=1}^{N} f_i\, P_i$$

其中 $N$ 是专家数，$f_i$ 是一批中被分派给专家 $i$ 的 token 比例，$P_i$ 是路由器分配给专家 $i$ 的总概率质量。他说这很难从第一性原理推出来，看它对 $P_i$ 的梯度最清楚：梯度就是 $f_i$，也就是说分到的 token 越多，压低其概率质量的梯度越大，作用是把热门专家压下去。

据此可以重建 DeepSeek V1、V2 的 MoE：正常损失直接穿过专家反向传播，不管不可微和探索的问题；加上与 Switch Transformer 相同的按专家均衡损失；DeepSeek 很注重系统，还加了按设备均衡的损失，形式相同，只是把专家换成设备，让各台机器的利用率都满。DeepSeek V3 用了每个专家一个偏置项，用在线学习的技巧来均衡，去掉了一部分辅助损失，但最后仍需加一些辅助损失防止极端不均衡，目前还没有能完全去掉的方案。

能不能不要负载均衡损失？OLMoE 做了消融：去掉后损失明显变高；看专家的使用情况，几乎所有 token 都去了两个专家，大量参数在训练的大部分时间里什么都没做；有均衡损失时所有专家都被使用。他说令人惊讶的是，对一个不可微、做 top-k 的复杂对象，只要加一个均衡损失，然后假装梯度能直接穿过，模型就训练得很好：有用的专家会被强化，这是正反馈，而均衡把它抵消掉。同样的技巧也用在 DSA、H-Net（去掉分词器的尝试）里，他认为 top-k 选择配合均衡或其他辅助损失会成为未来架构设计的一个基本成分。

学生问专家真的是某个领域的专家吗？他说有论文可视化了哪些 token 激活哪些专家，因为路由器很简单，专家并不是"医学专家""法律专家"，而是标点去某个专家、某些符号去某个专家、非英语字符集去另一个专家，没有语义上的"华尔街日报专家"。为什么既要按专家均衡又要按设备均衡？他说按专家均衡如果完全执行，在专家平均分布时自然也会按设备均衡，但把专家损失调到完全均匀会损害训练动态；设备均衡足够重要，值得多加一点损失。

系统问题

  • 并行：数据并行受批大小限制，模型并行受模型能切分的位置限制，加上专家并行就多了一个维度。一块 GPU 上有多个专家时，不要做多个小矩阵乘法，可以利用硬件原生支持的结构化稀疏（块对角是最简单的形式）高效地把专家和输入相乘，这是硬件与架构协同设计的一面。
  • 通信：专家并行要把激活在设备间传来传去，开销很大。Nemotron 3 的新做法是：共享专家不需要通信，可以保持高维；要发给路由专家的激活先投影到低维再做集合通信，既省通信又不必缩小整个隐藏维度。
  • 随机性：如果专家不均衡，热门专家的 token 队列会越积越长，以前的 MoE 推理代码到一定长度就悄悄丢弃 token，返回 0 假装没事，于是别的用户的请求可能把你挤出队列，让你的结果变差。现在 MegaBlocks 等常用开源框架是"无丢弃"的，不再有这个问题。
  • 稳定性：路由又引入了一个 softmax。Barrett Zoph 等人在 Google 早期专门写过 MoE 稳定性的论文。办法是只对路由器用 FP32，以及对路由器加 z-loss；OLMoE 的消融显示，不加 z-loss 训练损失曲线尖峰很多。
  • 微调：参数太多，微调时容易严重过拟合，稠密模型训练和验证损失接近，稀疏模型差距很大。办法是只微调非 MoE 的前馈层，或只微调注意力（最近的 MoE 工作中很常见），或者用大量数据（比如 140 万个样本）基本重训。
  • 升级改造（upcycling）：从训练好的稠密模型出发，把 MLP 复制成多个专家，随机初始化路由器，继续训练，由于输入分配的随机性，专家会逐渐分化。早期论文显示这比继续训练稠密模型好。MiniCPM 把 2.4B 模型升级成 134 亿参数的 MoE，几乎白得了提升；Qwen1.5-MoE（激活 27 亿）从 Qwen 1.8B 升级而来，是最早的大规模成功案例之一。他说今年没再看到升级改造的模型，因为大家直接用 MoE 训练主力模型了。

DeepSeek V1 到 V3

  • V1：已是很多现代 MoE 的原型，共享加细粒度专家，标准 top-k 路由加辅助均衡损失，他说是 MoE 的"柏拉图理想"。
  • V2：放大规模，两个共享专家、更多细粒度专家，加了设备路由和通信均衡两个组件，都是为系统优化而加的辅助损失。他说成功训练语言模型不只是深度学习，还要尊重系统。
  • V3：仍是共享加细粒度专家，均衡方式改为无辅助损失的方法，专家加权改成 sigmoid 加 softmax。V3 还有多头潜在注意力（MLA）：不直接生成 $Q$、$K$、$V$，而是先把隐藏输入压缩成低维的潜在向量 $c$，再由 $c$ 生成 $Q$、$K$、$V$，KV 缓存只需存 $c$，大大节省；麻烦是和 RoPE 在 KV 缓存时冲突，要用一些不压缩的维度单独编码位置。还有多 token 预测（MTP）：一次预测多个未来 token，有统计上的理由，也相当于内置了推测解码器，可以加速解码（Percy 讲推理时会谈），但没怎么流行。

总结：MoE 利用稀疏性，拥有比所付计算更多的参数；路由问题看似很难，但非常简单的方法在大规模上也很好用；MoE 会长期存在。
