第二讲：PyTorch 与资源核算

张量占多少内存，浮点格式（FP32、FP16、BF16、FP8、FP4）的取舍，用 einops 写张量运算，浮点运算怎么数、MFU 是什么，算术强度和屋顶线分析，训练一步为什么是 6ND 次浮点运算，以及梯度累积和激活检查点

主讲：Percy Liang
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、开场：两道估算题

Percy 先报告上一讲提到的 Marin 预注册实验：训练已经完成，实际损失和缩放规律预测的相差在 0.05 以内；外推到 GPT-5 水平的表现，也能算出对应的损失（当然要看缩放规律有多可靠）。

这一讲讲资源核算。目标是在有限资源（算力、内存，数据在本课一般不是限制）下训练最好的模型，也就是最大化训练的计算效率；要优化效率，先要弄清一次计算的计算和内存特性。到课程结束时，希望大家能回答这类问题：

  • 在 1024 块 H100 上，用 15 万亿 token 训练一个 700 亿参数的模型要多久？浮点运算总数约为 $6 \times$ 参数量 $\times$ token 数，查规格表得到 H100 的速度，假设 MFU 为 0.5，算出每天能提供的浮点运算，得到约 143 天。
  • 用 8 块 H100 和 AdamW，最大能训练多大的模型？H100 有 80 GB 高带宽内存，每个参数需要 $2+2+4+4$ 字节（后面解释），算出约 530 亿参数。这里没算激活，激活取决于批大小和序列长度。

这些都是粗略的"信封背面"估算，目的不是精确算出每样东西，而是把握大致的形状。这一讲的机制很简单，就是 PyTorch 和张量怎样工作；想传达的思维方式是：写每一行代码都要想到它的性能特征。今天没有机器学习的"魔法"，那留给下一讲的 Tatsu。

二、张量和浮点格式

参数、梯度、优化器状态、数据、激活，所有东西都存在张量里。比如 DeepSeek-V3.2 模型本身就是一堆形状和精度各异的张量。张量的内存就是元素个数乘以每个元素的大小。

  • FP32（单精度）：32 位，1 位符号、8 位指数（决定动态范围）、其余是尾数（决定精度）。"单精度"这个名字来自科学计算，当年那是基准，要更高精度就用 FP64 双精度。深度学习反过来，32 位已经很多，计算不需要数值模拟那样的高精度。PyTorch 默认创建 FP32 张量，一个 4×8 的矩阵占 $32 \times 4 = 128$ 字节。GPT-3 前馈层里的一个矩阵约 2.3 GB。
  • FP16：只有 5 位指数，动态范围差，比如 $10^{-8}$ 会直接变成 0，太大太小都表示不了。早年用 FP16 训练会遇到下溢、上溢、NaN，很不稳定。
  • BF16：2018 年提出，同样 16 位，但把一些位从尾数挪到指数，动态范围和 FP32 一样，精度更差。深度学习里很值得：要避免上溢下溢，而计算本来就粗糙、随机，不需要那么高的精度。

降低精度既省内存又省时间：16 位运算一般更快（比如快一倍，但不总是），而后面会看到，减少内存本身也能省时间。训练小模型、不想操心，用 FP32 完全可以，但每个数 4 字节，很占内存；用 FP16 风险太大；BF16 是比较好的平衡点，但也可能有风险。常见做法是混合精度训练：参数、激活、梯度用 BF16，优化器状态用 FP32。PyTorch 的 AMP 库可以自动处理：在安全的地方（比如矩阵乘法）转成 BF16，在指数运算等地方保留 FP32。

更激进的：FP8 四年前提出，已经标准化，有两个版本，一个动态范围更大，一个精度更高，NVIDIA 的 Transformer Engine 支持。去年 NVIDIA 推出了 NVFP4，每个值只有 4 位，所有可表示的值能在一行里写完（在 $-6$ 到 $6$ 之间）。直接这样用训练不好，实际上值分成块，每块有一个缩放因子可以整体放大缩小，所以单个值的动态范围超过 4 位，但相邻的值不能一个极大一个极小。今年发布的 Nemotron 3 Super 就是用 FP4 训练的。这些很多是 NVIDIA 软件栈在底层完成的，不是你创建张量时标成 FP4 就行。学生问能不能低到 1 位，他说要区分训练和推理：很多低比特的做法是先用 BF16 训练，再量化到一两位，这比训练一个 1 位的语言模型容易得多，他认为还没人训出过可信的 1 位模型。

PyTorch 默认把张量放在 CPU 上，要快就得移到 GPU，别忘了。（他的讲义在笔记本上执行，没有 GPU，有些代码只展示不运行。）

三、einops：给维度起名字

看到 x @ y.transpose(-2, -1) 这种代码，很容易搞不清 $-2$、$-1$ 是哪一维。einops 是一个用命名维度操作张量的库，受爱因斯坦求和记号启发，可以看作带好记账的广义矩阵乘法。

  • einsum：比如 einsum(x, y, "seq1 hidden, hidden seq2 -> seq1 seq2")，右边没出现的维度（hidden）被求和掉。对所有变量的取值枚举，把 $x$ 和 $y$ 对应元素相乘，累加到结果里。批量的例子写成 "batch seq1 hidden, batch seq2 hidden -> batch seq1 seq2"，不需要转置，命名本身就完成了转置。可以用 ... 代表任意多个批量维度，语言模型里常有批、序列、头等维度，这样写出的代码不依赖输入张量的形状。
  • reduce：sum、mean、max、min 的推广。比如 reduce(x, "... hidden -> ...", "sum")，右边没出现的维度被归约。学生问会不会更快，他说底层是同样的原语，可以看作语法糖。
  • rearrange：一个维度实际代表两个维度时很有用，常见于把矩阵展平后又要拆开。比如 3×8 的矩阵，8 其实是 2×4，可以写 rearrange(x, "... (heads hidden1) -> ... heads hidden1", heads=2) 拆开，做完变换再合回去。拆分的顺序由括号里的顺序决定。

他说习惯需要一点时间，但值得：用了 einops，转置、归约都变得流畅。

四、浮点运算和 MFU

计算成本用浮点运算数衡量，一次浮点运算是加法或乘法这样的基本操作。他的一个"心病"是 FLOPs 这个词有歧义：小写 s 的 flops 是浮点运算的次数，衡量计算量；FLOP/s 是每秒浮点运算次数，衡量硬件速度，有时也被很混乱地写成大写 S 的 FLOPS，他总是写 /s 来区分。说 H100 有 989 TFLOP/s，指的是后者；说 GPT-3 用了多少次浮点运算，指的是前者。

H100 规格表上 BF16 写的是 1979 TFLOP/s，实测发现达不到，细看脚注，那是稀疏矩阵的数字，稠密要除以 2。8 块 H100 跑一周，约 $5 \times 10^{21}$ 次浮点运算。

线性模型：$B$ 个数据点，每个 $D$ 维，映射到 $K$ 维输出，$X$ 是 $B\times D$，$W$ 是 $D\times K$，矩阵乘法的浮点运算数约为 $2BDK$：每个三元组一次乘法加一次加法（严格说加法少一次，忽略）。逐元素运算的浮点运算数就是矩阵大小，比如 $m\times n$ 矩阵相加是 $mn$。对足够大的矩阵，没有其他运算比矩阵乘法更贵，所以主要关注矩阵乘法（内存方面另说）。学生问亚立方复杂度的矩阵乘法算法，他说实际优化主要是和系统协同设计，而不是渐近意义上的算法；加法和乘法在硬件上成本基本一样。注意 $B$ 是数据点数，$DK$ 是参数量，所以线性层前向的浮点运算是 $2 \times$ token 数 $\times$ 参数量，这会推广到 Transformer。

实际花多少时间要测。在 GPU 上计时要在操作前后调用 torch.cuda.synchronize()，因为 GPU 异步运行，不同步的话调用立即返回，你会以为快得惊人；最好多次运行取平均。实际 FLOP/s 是浮点运算数除以实测时间，它和规格表承诺的数不同。模型浮点利用率（MFU）定义为实际 FLOP/s 除以承诺的 FLOP/s（不算通信等开销）。你不可能超过承诺值，通常更少：现代模型能到 0.5 就该满意了；单纯的矩阵乘法也许能到 0.8；如果只有 0.1，说明哪里出了问题。学生问承诺值是什么，他说是规格表上已经除以 2 的数，在此之上一般只能拿到一半左右。数据类型也影响 FLOP/s：现在 FP32 很慢，因为硬件不再为它优化，BF16、FP8 快得多。

五、算术强度和屋顶线

为什么 MFU 只有 0.5？硬件的卡通图是：高带宽内存在一边，计算核心在另一边，计算时要把输入从内存送到计算单元，算完再送回去。所以耗时取决于两件事：加速器的计算速度，以及内存带宽。H100 规格表上 FLOP/s 是 $1979\times10^{12}/2$，内存带宽是 3.3 TB/s。张量的大小不只决定能不能放进内存，也决定搬运要多久，从而影响速度。

例子：对一个 $N=10^6$ 维的 BF16 向量做 ReLU（逐元素取 $\max(x,0)$）。读 $x$ 要搬 $2N$ 字节，写回 $y$ 又是 $2N$ 字节；浮点运算是 $N$ 次比较。通信时间是字节数除以带宽，约 $10^{-6}$ 秒；计算时间是浮点运算数除以 FLOP/s，约 $10^{-9}$ 秒。假设通信和计算可以完全重叠（数据一到就开始算），总时间取两者的最大值，约 $10^{-6}$ 秒，实际上不能完全重叠，会有开销。通信时间大于计算时间叫受内存限制，反之叫受计算限制。ReLU 显然受内存限制。

另一种看法：加速器的强度是 FLOP/s 除以字节/秒，即每搬运一个字节能做多少次浮点运算，H100 约为 295，可以记住"约 300"。算法的算术强度是这个工作负载实际每字节做了多少浮点运算：

$$\text{算术强度} = \frac{\text{浮点运算数}}{\text{搬运的字节数}}$$

ReLU 是 $N/(4N) = 0.25$。算术强度小于加速器强度就受内存限制，大于就受计算限制，两种说法等价。看到 0.25 这样的数，就该知道很糟。

  • GELU：搬运同样是 $4N$ 字节，每个元素约 20 次浮点运算，算术强度约 5，仍远小于 295，受内存限制。所以虽然 GELU 计算多得多，单独算它和 ReLU 一样快，瓶颈不在计算。
  • 点积：读两个 $2N$ 字节，写一个标量 2 字节，浮点运算约 $2N$，算术强度约 0.5，受内存限制。
  • 矩阵乘向量：读 $2N$ 和 $2N^2$，写 $2N$，浮点运算约 $2N^2$，算术强度只高一点点，仍受内存限制。
  • 矩阵乘矩阵（$N\times N$）：搬运 $3\times 2N^2$ 字节，浮点运算 $2N^3$，算术强度约 $N/3$，比如约 340，终于受计算限制了。直观上，传 $N^2$ 个数却算 $N^3$ 次，比值是 $N$ 的量级，矩阵越大越好。这就是人们说要大批量、大矩阵的原因：低于加速器强度时，把东西做小并不会变快；超过之后才真正喂饱 GPU。

Transformer 本质上是一串大矩阵乘法，中间夹着一些别的运算，这是有意设计成高算术强度的。预告推理那一讲：推理时一次生成一个 token，本质上是矩阵乘向量，所以受内存限制；训练时整个序列一起处理。算术强度也和精度有关，这里默认 16 位。MFU 低的一个原因就是内存瓶颈。学生问既然大多受内存限制，加速器的计算能力是不是过剩了，为什么这样设计？他说讲 GPU 时再谈，如果有答案，可以告诉黄仁勋。

屋顶线图：横轴是算术强度，每条竖线对应一个算法；纵轴是实现的 FLOP/s；每条折线对应一种加速器。算术强度低（ReLU、点积）时，实现的 FLOP/s 远低于峰值，随强度增加而上升，超过某一点后受计算限制，不可能超过峰值，曲线变平，像屋顶。

六、训练一步的浮点运算：6ND

用一个简单的深层网络做例子：输入 $B\times D$，$L$ 层，每层是 $D\times D$ 的矩阵乘法，再接逐元素 ReLU，参数量是 $D^2 L$。为了看清梯度，简化成两层线性：$h_1 = x W_1$，$h_2 = h_1 W_2$，用 einsum 写。看第二层：前向是一次矩阵乘法，浮点运算 $2BD^2$。反向传播要算两样东西：

  • 对输入的梯度（往回传的消息）：$\partial L/\partial h_1 = (\partial L/\partial h_2)\, W_2^\top$，在 einsum 里写成 "batch out, in out -> batch in"，对 out 维求和。他说学微积分时总记不清转置放哪边，einsum 一看形状就清楚。
  • 对参数的梯度：$\partial L/\partial W_2 = h_1^\top (\partial L/\partial h_2)$，对 batch 维求和。

浮点运算数都是各维度之积，和对哪一维求和无关，所以反向恰好是前向的两倍，因为要算两个梯度。推广到所有参数：前向 $2 \times$ 数据点数 $\times$ 参数量，反向 $4 \times$ 数据点数 $\times$ 参数量，合计

$$\text{训练浮点运算} \approx 6ND$$

这就是常见的 $6ND$ 的来历，只是把前向和反向数清楚。对 Transformer 也是好的近似，前提是上下文不太长；上下文很长时会出现上下文长度平方的项，不在这个核算里。

七、优化器和内存

为了不和作业一重复，他用 2011 年的 AdaGrad 举例：它介于 SGD 和 Adam 之间，是看梯度二阶矩的 SGD（动量看一阶矩，Adam 两者结合）。优化器有"优化器状态"，AdaGrad 存的是梯度平方的累加和：每步从状态取出，用当前梯度更新，存回，再用它更新参数（除以累加和的平方根）。作业一要自己实现 Adam。

这个网络的内存：

  • 参数：$D^2 L$ 个，BF16 每个 2 字节。
  • 激活：$2 \times B \times D \times L$ 字节，每层一份。
  • 梯度：参数的一份拷贝，BF16。
  • 优化器状态：习惯上用 FP32 以保证稳定，人们试过 BF16，但要对平方求平均、累积很多步，不稳定。AdaGrad 每个参数 4 字节；Adam 存一阶和二阶矩，8 字节。（他指出课件里这里有个笔误，应按参数个数计算。）

所以优化器状态占了很大一部分内存；开头"每个参数 $2+2+4+4$ 字节"就是参数、梯度和 Adam 的两份 FP32 状态。内存有两重作用：要能放进 HBM，还要搬到计算单元；优化器状态一般不是计算速度的瓶颈，但会限制能放下多大的模型。

减少内存的两个办法

  • 梯度累积：批大小一般要足够大以保证稳定，直到某个"临界批大小"（Tatsu 后面会讲），但激活内存随批大小增长，会爆内存。做法是把批拆成微批，每个微批算梯度后不清零、累加，每"批大小除以微批大小"步更新一次参数并清零梯度，代码改动很小。
  • 激活检查点（也叫梯度检查点、重计算）：训练默认要存所有层的激活（推理不用算梯度，只需存当前层），内存 $2BDL$ 字节。办法是前向时只保留部分层的激活，反向时从最近的检查点重新计算缺失的激活，用重算换内存，这是系统里的通用技巧。在 PyTorch 里对某层用 torch.utils.checkpoint 即可。比如对每个"线性加 ReLU"块做检查点，就不用存 ReLU 之前的值，内存省一半，反向时再从 $h_2$ 算出来。极端情况是什么都不存，内存最省，但重算是 $L^2$；折中是每隔 $\sqrt{L}$ 层存一个检查点，激活内存和重算开销都是 $\sqrt{L}$ 量级。

八、小结

  • 参数、梯度、激活、优化器状态、数据，都在张量上操作；用 einops 思考张量运算。
  • 每个训练步的浮点运算约为 $6 \times$ 批中 token 数 $\times$ 参数量。
  • 算术强度和屋顶线分析能判断计算是受内存限制还是受计算限制：矩阵乘法受计算限制，其余基本都受内存限制。
  • 梯度累积和激活检查点减少内存，从而能用更大的批。
