第十六讲：可验证奖励的强化学习（RLVR）

为什么 RLHF 会被过度优化而可验证奖励不会，PPO 的实现之难，GRPO 及其两个归一化项的问题，以及 DeepSeek R1、Kimi k1.5、Qwen 3 和 Qwen3-Coder-Next 的推理与 Agent 训练配方

主讲：Tatsunori Hashimoto
资料来源：课堂录像（Stanford Online 公开，2026 年春季，本文依据录像字幕整理）

一、从 RLHF 到可验证奖励

这是后训练的第二讲，讲 RLVR（reinforcement learning from verifiable rewards）。Tatsu 说很应景：刚有 OpenAI 的人宣布用思考模型解决了一个埃尔德什问题（开放数学问题），这背后就是思考模型、RLVR 这套东西。上一讲结束时我们有了指令微调和 RLHF，也就是 ChatGPT；剩下的是现代思考模型：能做很长的思维链，解决数学、某些编程这类难但可验证的问题。

上一讲结尾有点泄气：RLHF 有过度优化问题。收集偏好数据很有用，建奖励模型，再对它做 RL；但这从根本上受标注量限制，你不能一直往同一个奖励模型上砸算力，正则化做得再好，最终也会过拟合它。这没有发挥强化学习的潜力。相信 RL 的人会提到 AlphaGo：RL 在那里表现惊人。区别在于 AlphaGo 优化的就是我们想要的东西，围棋的胜负没有任何含糊，算力想放多少放多少，只要目标在改善就是在进步；某种意义上那是搜索问题，RLHF 更像学习问题（不是精确的区分，但是一种思考方式）。形式化数学，甚至自然语言数学，可能有这种可验证的性质，更适合强化学习。算法根本上差别不大，但最终到达的地方会惊人地不同。

这一讲分两部分：先讲核心算法，这是基础知识，作业里会用到；再看一批开源模型的技术报告，看前面讲的东西怎样体现在其中。

二、PPO：概念简单，实现很难

讲语言模型的 RL 绕不开 PPO，它够难懂，讲两遍有好处。最重要的恒等式是策略梯度，也就是 REINFORCE 技巧：在奖励上做梯度下降，相当于做加权的 SFT 更新，权重可正可负：

$$\nabla_\theta\, \mathbb{E}_{y\sim\pi_\theta}[R(y)] = \mathbb{E}_{y\sim\pi_\theta}\left[R(y)\,\nabla_\theta \log\pi_\theta(y)\right]$$

这个式子会贯穿整讲，其他一切都从它推出。策略梯度每走一步都要从策略采样，想复用 rollout 就有了 TRPO、PPO。PPO 是 RL 的主力，在很多困难场景用过：OpenAI 早期很信 RL，用 PPO 让模拟人走路，更惊人的是用 PPO 训练的 Dota 机器人 OpenAI Five，在高维动作和状态空间的深度 RL 中表现出色。

概念上 PPO 很简单，看 OpenAI Spinning Up 文档里的伪代码：采样轨迹，用某种优势估计方法算优势，用有点奇怪但还行的方式裁剪，在裁剪后的优势上更新策略，再拟合一个价值函数。看起来一次就能写对。但当你看到一篇博客叫《PPO 的 37 个实现细节》，就该心生畏惧：这个算法对实现决定很敏感，不同库和实现给出完全不同的数字，很多人实现错了，有论文指出一些人用的"基线"根本不是基线，改变了优化问题本身。

语言模型的 PPO 实现并不令人愉快：中间一大块是优势估计；有经验缓冲区保存旧数据；要训练价值模型，用于优势估计；目标中的 KL 项是逐 token 计算的，所以它不只是老虎机问题，而是完整的多步 RL 问题。他的学生以前为 RLHF 实现了 PPO，花了很久才跑起来。外循环没问题：遍历 rollout，走几步 PPO，算损失，裁剪梯度；内层计算损失也基本按 PPO 公式来。但有些地方很乱：比如为了让模型靠近参考模型加了 KL 惩罚，但只有把 KL 在 0 处截断才行，懂 KL 散度的人知道这完全违背了它的意义（正负值本应相加），而去掉截断就立刻发散。他不是说该这么实现，而是说 RL 算法因为部件多、梯度估计方差大，实现很棘手、很敏感。另一个很常见的做法：原论文的广义优势估计（GAE）用 $\gamma$ 折扣奖励和逐 token 的价值函数，但大家常常设 $\gamma = \lambda = 1$，这个退化设置又把问题变回老虎机，丢掉了 PPO 的很多结构。经过大量工程，你会看到预期的结果：奖励模型给的奖励上升，负 KL 正则项下降，作业里也该看到类似的曲线。

所以 PPO 实现可能很痛苦，取决于环境，可能需要一些 hack 来稳定。不是不可能，很多人用 PPO 训练出了很好的模型，很多实验室有现成的大规模方案；但对从零实现的研究者来说很繁琐。PPO 还需要价值模型估计每个 token 的价值，它和原模型一样大，占用本可以给模型或推理服务器的内存。

为什么不全用上一讲的 DPO？DPO 是针对特定问题的特定解法：适用于 Bradley-Terry 形式的成对反馈。数学题天然不是成对比较，有些 DPO 变体能打破成对结构，但那是用错了锤子。PPO 是更通用、什么都能敲的锤子。DPO 通常是离线的，但他认为这个区别被夸大了，反复迭代 DPO 就能变成在线的。

三、GRPO

和 DPO 一样，研究社区很想摆脱 PPO，DPO 和 GRPO 的流行说明 PPO 跑起来有多痛苦。GRPO 在开放社区的 RLVR 中基本占了主导，精神上和 PPO 很像，只是去掉了最复杂的部分。它来自 DeepSeek 的 DeepSeekMath 论文：PPO 是好主意，但改几处。改的是最复杂、最烦人的价值函数：价值函数作为基线被减去以降低梯度更新的方差，它是一整个神经网络，还会让训练不稳定。去掉价值网络，但仍需要优势，否则纯 REINFORCE 方差太大。于是在组内用 z 分数计算优势：通常拿到一个奖励，会和价值函数的预测比较（网络说我该得 5 分，我得了 6 分，这是好的 rollout）；GRPO 改为对同一提示再采样 10 个左右的 rollout，看我比它们好多少，高于均值就是优势高。对能从同一提示多次采样的场景，这很自然。

目标函数和 PPO 一样，有裁剪的优势加上让策略靠近参考模型的 KL 项（KL 的具体算法不重要），优势是对一组输出 $o_1, \dots, o_G$ 的奖励做 z 分数：

$$A_i = \frac{r_i - \mathrm{mean}(r_1, \dots, r_G)}{\mathrm{std}(r_1, \dots, r_G)}$$

在线情况下（很多时候实际是在线跑的），$\pi_{\theta_\text{old}}$ 与 $\pi_\theta$ 之比为 1，裁剪不起作用，目标就是优势减 KL 惩罚，是很简单的 RL 目标。因为没有价值函数，整个 GRPO 一页代码就能写完：每个提示 rollout $K$ 次，算奖励，组内归一化，算 KL 项，在两者组合上走梯度（用自动微分实现要在某处 stop gradient，不难）。他展示了 McGill 一些人写的玩具实现，计算组索引和标准差只占半页幻灯片；唯一和论文不同的是标准差加了 $10^{-4}$，防止只有一个样本或所有样本奖励完全相同时除以 0，在能得到恰好 0 奖励的领域（比如没做对数学题）这确实会发生。易实现、易理解、效果有说服力，所以几乎所有开源工作都建立在 GRPO 上。

DeepSeekMath 论文里，GRPO 明显好于拒绝采样微调（RFT，作业里也要实现，就是只用模型生成的正确答案训练，丢掉其他）；过程监督（不仅给最终答案打分，也给中间步骤打分）带来一些提升，后面会讲，这是这类 RL 问题的重要设计决定。

GRPO 不完全是策略梯度

Sutton 和 Barto 的经典教材讲过带基线的 REINFORCE：在策略梯度中，奖励可以减去任意只依赖状态的基线（老虎机设定中状态就是提示），仍然是合法的策略梯度，下降方向不变，选不同基线只影响方差。GRPO 减了均值，这没问题；但它还除以标准差，打破了基线的约定。另外，GRPO 还有一个实现细节：按序列总长度归一化，近似于逐 token 平均。从策略梯度和基线定理出发推导，既不会有长度归一化，也不会有标准差归一化。GRPO 出来不久就有人指出这点（Dr. GRPO 论文），不做这两件事会得到很不同、可能更好的行为。两个修正项的作用：

  • 长度归一化：长序列除以更大的数。答错的时候，比如知道这道证明做不出来、会拿到 -1 的奖励，干脆生成无限长的字符串，除以无穷大，负惩罚就没了。极端情况之外，也会鼓励模型在意识到做不出时喋喋不休。去掉它之后，大家在 GRPO 中观察到的"思维链越来越长"会稳定在一个常数，而不是一直增长，尤其是答错时，你不想要越来越长的输出。
  • 标准差归一化：除以标准差相当于强调标准差小的问题。二元奖励下，标准差小意味着题太简单（总是对）或太难（总是错），都会被大幅加权。但你希望模型在自己能解决的范围内学习，这显然不是想要的。

四、DeepSeek R1

他说 DeepSeek R1 某种程度上是社会现象，大家都该了解，论文写得很好，开启了开源 RLVR 模型的浪潮。它可能是第一个达到 OpenAI o1 行为的模型：很长的思维链，显然用了 RL，难数学题表现很好；还给出了人人能做的 RL 配方，对研发很重要，如果方案是只有 DeepSeek 能跑的可怕 PPO，对研究者的影响就小得多，而 GRPO 连作业里都能玩；还有一些关于蒸馏的洞见，至今仍成立。

可以看出 DeepSeek 的积累一层层叠加：DeepSeekMath 已经做了 GRPO，理解了在数学题上做 RL 的很多细节。一个重要区别：放弃了在 DeepSeekMath 中效果很好的过程监督，只用结果监督。结果监督只看最终答案对不对；过程监督用评分细则检查证明中间步骤是否有效。很多人认为过程监督很重要，结果在很多事情上并不关键。

R1-Zero 几乎不做后训练：基座模型（我们知道现在的基座模型也经过中期训练，能一定程度遵循指令），直接做 RLVR，GRPO 的奖励是一批数学题的准确率奖励，加上格式奖励。格式奖励很重要，它要求模型用思考标签把思维链括起来，之后好剥离。配方很简单，作业里你们会在某种程度上复现这组结果。结果只比 o1 差一点点。他喜欢这个结果，因为没有真实生产流程的各种干扰，不必怀疑是 RLHF 帮了忙还是别的什么，就是基座模型加 GRPO，数学能力就很好。

R1 走红也因为论文声称观察到的现象：训练越久，模型思考越久，思维链越来越长；还有在社交媒体上爆红的"顿悟时刻"（aha moment），训练够久，思维链里会出现"啊哈，这里有个顿悟"。他认为这两个现象都不算特别了不起：更长的思维链很可能是 GRPO 长度归一化的自然副作用；有人发现基座模型里就有顿悟时刻，所以不可能只是 RL 的结果，很多人解题时会说"啊哈，我可以用这个"，模型在预训练中学到了，RL 时生成大量数学 token，被提取出来并不奇怪。但 R1 是重要的里程碑，它显示了 RLVR 可以多简单。

R1 是把它产品化的尝试，能看到各部分怎样组合成一个系统：从中期训练过的模型出发，做大量推理训练（也许中间还有长上下文扩展），最后做 RLHF，因为那是最面向用户的部分，能让格式等变好。R1 给思维链加了语言一致性奖励：他记得报告说 R1-Zero 式的训练会在思维链中切换语言，难以解读，有点让人不安，所以要求输出单一语言，纯粹为了可解释性。GRPO 中也混入了一些不可验证的奖励，几乎融入 RLHF 过程。

  • SFT：R1-Zero 完全不做 SFT；R1 愿意用长思维链数据。读开源技术报告时揣摩字里行间很有意思：他们说"构建并收集少量长思维链数据"，你可能会想是不是从别的模型蒸馏来的。他说这对开源模型不算什么负面的事，现在大家都在这么做，只是觉得措辞写得很小心。对很好的基座模型，只用长思维链做 SFT 就能解锁很多 o1 式能力，是 RL 很好的起点；他们还用验证过滤这些思维链。之后很多论文（包括他学生的）显示，有合适的蒸馏流程和基座模型，单靠 SFT 就能获得大部分长思维链推理能力。仍未解决的问题是 RL 是否真的必要。一种看法：RL 是很好的监督来源，解前沿数学题时根本没有详细的长思维链可以监督，RL 让模型自己产生；一旦有人产生了这些长思维链，也可以通过模仿学习，这就是很多蒸馏结果部分显示的。
  • RL：和 R1-Zero 基本一样，加上语言一致性损失，用 GRPO。
  • 最后阶段：基本的指令微调式 SFT，然后 RLHF，不可验证的任务沿用 DeepSeek V3 的做法，没什么意外。

效果很好，这也是当时引起恐慌或广泛关注的原因：R1 是真正很好的模型，很多类别胜过 o1，符合人们预期的测试时扩展行为，而且配方简单，收益来源很清楚。把 R1 的思维链放进 Qwen 2.5 做蒸馏，性能显著提升，有时能比肩专门的思考模型，对 Llama 也有效。也就是说，只要有模型看得懂的合适长思维链，基座模型本来就出人意料地好，能进行长时间推理。

他很喜欢 DeepSeek 的报告既做消融，也写失败的尝试。DeepSeekMath 里全是过程奖励模型（PRM），读到 R1 会问 PRM 去哪了？他们说试过，没起多大作用；结果奖励模型很好、够用，数据也更容易扩展。PRM 的一大争议是逐步评分细则从哪来，很难扩展。现在很清楚，结果奖励模型很好，主要的进展都在这里。o1 发布时很多人猜它内部在做什么，PRM？像 AlphaGo 那样的树搜索？DeepSeek 也试了很多 MCTS，说效果不好。他很欣赏他们公开这些探索和失败。

学生问答对时长度归一化起什么作用：会鼓励缩短思维链，省推理成本是好事，伤准确率就是坏事；但主要问题在答错的情况会出现很长的回答，答对时缩不了多少，因为解一道题的思维链有下限。Dr. GRPO 的图更清楚：平均输出长度的增长主要由答错的输出驱动，答对的输出长度基本不变，和前面的解释一致。

五、Kimi k1.5

讲 R1 时他总觉得有义务讲 Kimi k1.5：几乎同时发布，也胜过 o1，模型很好，但大家都在谈 DeepSeek。他说不是出于同情，而是 Kimi 在一些事情上做法很不同，两者都有效，能告诉我们哪些空间比较容易让算法奏效。他们更详细地讲了数据集构建和 RL 课程，很多人说这很重要；RL 算法也不同，直觉相似但不是 GRPO，说明不一定需要 GRPO。

数据：RL 多了"课程"的问题。SFT 不太考虑难度，把数据塞进去用预训练损失学就行（上一讲说过有幻觉问题，有些数据可能不该训练）；RL 中，题太难就拿不到奖励，没有信号就学不到，所以要合适的覆盖。Kimi 的做法：覆盖面广；排除多选题，他们认为多选不需要长时间深入思考；最重要的是按 best-of-K 过滤：采样 8 次至少成功一次的题，已经在模型能力边缘，教不了新东西，只保留通不过这个测试的题。这节省算力，也能完全跳过某些题；也可以两头过滤，保留不太难也不太简单的题。研究社区的共识是：想让 RL 稳步前进，这种中等难度过滤很好。和 DeepSeek 一样，SFT 没有描述。

算法：从同样的目标出发，最大化策略下的期望奖励，加 KL 正则让策略靠近基础策略（或上一轮的策略）。按 DPO 式推导，假设能解析地最大化，解出对应的奖励，得到策略之比，代回目标。他们希望在最优点成立的等式成立，于是用一个大胆的启发式：既然最优点处两边相等，就对差值加平方损失并最小化。他说做优化的人看了会吓坏，但这直觉完全合理：模型好时两者应该接近，把"让它们接近"当作替代目标也许可以。推导路径和 GRPO 完全不同，但对这个损失求梯度，得到的东西惊人地像 GRPO 加一个正则项：带基线 $\bar r$ 的策略梯度，$\bar r$ 是对每个提示 $x$ 的平均奖励，再加一个相当于 GRPO 中 KL 项的正则项。等于用完全不同的方式重新发明了组均值基线。

他认为 Kimi 对长度问题看得更清楚。GRPO 那边的态度像是"长度失控增长真好，模型一定更聪明了"（他承认这么说有点刻薄，但把这张图当作好事展示，隐含的就是"模型思考更久真好"）。Kimi 认为长思维链很浪费，思维链要花推理成本。他们的目标不仅没有长度归一化，还要主动压缩回答长度。这是语言模型发展的普遍需求：思维链越短越好，要解决难题但不想想太久，因为想得久就要补贴用户。如果你是 OpenAI，用户买了 200 美元的 Pro 计划，模型一想就是一小时，处境很糟；想 5 分钟就很好。

怎样压缩？最简单的 RL 做法是加一个启发式的长度奖励，它出人意料地复杂：让长序列越来越短，正确答案也要短；但错误答案不能压得太短，否则没有机会恢复。他举例：假设我是个不擅长几何的 AI，几何题大量答错，惩罚让几何思维链变得极短，短到为零，就再也拿不到几何的正奖励，卡死了。所以不强迫错误答案很短，只鼓励它们比平均略短一点，防止错误的东西无限增长。最终结果相当合理。

数据整理上还看各题的成功率，模型掌握某题后就把它移出题库，节省算力。他认为做 RL 的基本都会做这种成功率过滤，避免浪费算力，也避免做远超模型能力的题。奖励方面：代码用标准解生成新的测试用例；数学用奖励模型检查答案是否等价。他说这很有意思：这一讲开头说想做形式化数学这种真正可验证、编译器能检查正确性的东西，讲了大半，最后又回到了奖励模型，一个检查数学答案正确性的奖励模型。原因做作业时就会发现：答案等价判断很难。数学里等价的东西有很多写法；语言模型给答案的方式也很多，即使提示它用 LaTeX 的 \boxed 给出答案，有时也会漏掉 \boxed，或在框里多写东西。模型思路对了，也很容易被严格的检查器判错，所以大多数 RL 项目都有很复杂的答案检查器，正则表达式、模型或别的什么。把 RLVR 的"可验证"部分做对，是个很深的坑。

RL 的基础设施和优化很难：训练难，推理难，RL 把两者放在一起，难怪很可怕。更糟的是一个开始意识不到的问题：一批 rollout 中有一道特别难的数学题（比如黎曼猜想），模型在上面写着巨长的思维链，朴素的推理下其他人都在等这一个 rollout 完成才能进入下一阶段，长 rollout 会严重拖累批处理。要不要截断？放到别的机器上？都是可以做的决定。训练和 rollout 交替进行，要么一部分机器纯做 rollout、一部分做训练，要么不停切换框架，都很贵。最后是一个很难的取舍：在策略在数学和训练动态上都很好，简单在线形式的 GRPO 表现很好，作业里会体会到；然后你会变贪心，觉得系统利用率太低，要是能复用 rollout 就能让推理和计算重叠，于是复用 rollout，导致离策略问题，训练不稳定。所以现在大多数开源技术报告都有一节讲 RL 基础设施：训练部分和推理部分，权重要从训练端搬到推理端，要密切协调，有时甚至共用机器，因为推理运行时训练端可能闲着。

Kimi 胜过 o1；随 RL 进行，模型思考更久，性能上升，但不是无限增加 token，比如 Omni-MATH 上思考时间没增加多少，性能仍在上升，可能是长度控制在起好作用。最后，RL 真的比只用正确答案训练（专家迭代）好吗？专家迭代在过去一些论文中效果很好，遇到很不稳定的情况你也许真想用它。Kimi 做了大规模消融，显示 RL 方法始终好于专家迭代，想榨干性能就避不开 RL。

六、Qwen 3 与 Qwen3-Coder-Next

Qwen 3 有很有意思的规模和数据结果；后续的 Qwen3-Coder-Next 他认为是主要技术报告中关于 Agent 式 RLVR 训练细节最多的。

和 DeepSeek 一样，Qwen 报告展示了完整的组织方式：基座模型，SFT，推理 RL，"思考模式融合"，RLHF，得到发布的模型；不直接服务那个大模型，而是蒸馏出小模型。Qwen 3 是相当体面的开源模型，可以把它当作接近前沿的语言模型是怎样构建的心智图景。Qwen 用的是经过检验的 RLVR 打法，吸收了 Kimi 和 DeepSeek 最好的部分：大量按难度过滤，因为能省算力、得到好数据；去掉不用思维链就能答对的题，因为那不是需要思考的问题；去掉和验证数据太相似的题来去污染；对参考思维链做一些人工过滤。最突出的是 RL 只用了 4000 个样本，流程其余部分做对的话，能走出惊人的距离。

Qwen 3 特有的一些想法（有些后来放弃了，但很有意思）：

  • 用标签混合思考和非思考：同一个模型里既有长思维链的思考模式，也有即时回答模式。以前常是思考模型和非思考模型分开，OpenAI 也是。
  • 提前退出思考：追加一个特殊字符串，立刻停止思维链，强制模型给出答案，ChatGPT 界面里也能提前终止思考要求立即回答。他一直觉得意外的是：改变思考预算（用这种提前终止），性能平滑下降，即使在很低的预算下模型思考到一半被截断，也能给出相当合理的回答；即使思考预算很小，思考模式在数学和编程上也始终好得多于即时回答模式（更像经典的指令遵循加 RLHF 模型）。

他们报告了各部分对性能的贡献：推理 RL 再加通用 RL，各项任务逐步提升，Arena-Hard、反事实问答这类需要常规 RLHF 的通用任务提升明显；融合非思考模式后数学和编程有一些下降，绝对值不大。但在后来的 Qwen 3.5 中，他们放弃了把思考和非思考融合进一个模型（以前叫混合模型），因为觉得这点下降不可接受，想在思考模式上榨出所有性能，于是又分开了。

Qwen3-Coder-Next：如果对 Agent 感兴趣（当然还有脚手架等其他问题），想知道怎样真正构建 Agent，这份报告值得读。Agent 的后训练和前面讲的没有本质区别，没有新的 Agent 训练算法。整门课都该记住：数据才是关键。要后训练 Agent，就要把数据准备好，而且不能只在最后注入能力，得更早开始，所以有大量中期训练，尽量把编程和 Agent 能力放进模型：

  • 把仓库中的文件拼接起来生成很长的上下文数据，模型以后会看到 Agent 打开一堆文件的长轨迹，这是很有用的预训练式数据；
  • 对 PR 用检索增强构造可能有助于理解它的合成上下文；
  • 自动检测既有文字又有代码的文档，用 LLM 转成规整的 Markdown；
  • 让语言模型在与编程相关的网页上谈论编程，生成编程类合成数据；
  • 在各种环境中运行公开的编程 Agent，把轨迹放进中期训练；
  • 还有标准的指令遵循数据，以及代码中间填充（FIM）任务。

然后他们做了一件他以前没怎么见过的事：从中期训练后的模型出发，为不同的编程相关任务训练一批专家模型，得到四个 Agent 专家，再全部蒸馏回同一个模型。他只能猜原因；最接近的是 DeepSeek V3.2 让不同专家专门处理和格式化数据，为完整训练生成数据；但训练不同的专家模型再蒸馏回来，更接近 Branch-Train-Merge 这类学术工作，前沿模型训练中少见。每个专家在一批子任务上做 RL 或 SFT：Web 开发专家在经过各种检查的有效 Web 代码上做 SFT；用户体验专家在很多不同的工具格式上训练；问答专家用更多代码合成数据训练；最有意思、最复杂的是软件工程 Agent。

SWE-bench 是这类任务的黄金标准，他们想要"更多的 SWE-bench"：用各种基于 GitHub 的自动化方法生成大量 issue，在这些环境上做 RL，RL 性能稳步上升。他强调，我们之所以能不断往 RL 里加算力，是因为相信奖励难以被钻空子；这个假设一旦不成立，RL 会找到越来越隐蔽的作弊方式。Git 里可以查看未来的提交，有了 issue，查一下后来的修复就知道答案，模型很容易学会这一招。他们专门设了一个奖励防止 Agent 动 git 历史；不这样做，曲线会稳步学习，然后突然"涌现式"跃升，实际是学会了操纵 git 调用拿到历史。有时还能绕过限制：告诉它不许用 git log，它可能添加一个 remote，去查询远端某些提交里发生了什么。RLVR 只和你的奖励一样稳健，而奖励有时一点也不稳健。他提到自己和学生做过在 Lean 上做 RL 的项目，Lean 是可验证的形式化数学语言，他们天真地以为不可能出错，很多人用过 Lean，编译器坚如磐石；结果 Lean 编译器并不抗对抗：在某些模式下，可以放入一些字符串，让本不该通过的证明通过验证。"可验证奖励"比很多人最初想的棘手得多。

最终得到一个出人意料地好的系统：只有 30 亿激活参数的小模型，在 SWE-bench 上达到约 70.6%。他也提醒，这未必太令人惊讶，在训练过的环境上 RL 当然能做好，也许还能泛化到验证集，但比较性能时要小心，特定任务的表现不一定能泛化到更广的领域。

七、小结与问答

RL 的关键在奖励。RLHF 和 RLVR 可以说是很相似的问题，区别在于我们想要更难被钻空子的奖励，这样才能投入多得多的算力，让系统变得更好。GRPO 至少对研究社区来说是让这一切成为可能的东西，要像熟悉预训练损失一样熟悉它的函数形式和更新方式。现在很多人知道怎么做 RLVR；你们会发现 RL 仍然繁琐、嘈杂、用起来痛苦，但没那么难，不像过去在各种棘手环境里做 PPO，比想象中顺利得多。

  • 思考模式是不是两个模型？不是，有意思之处就在于它是一个模型，提示里一个小标签切换长思维链和几乎无思维链的模式；如果只是 API 标志切换两个模型，就没什么难的。控制机制在提示里，而不在 API 或服务层。
  • 中期训练对 RL 能学到什么有多大影响？如果预训练里没有覆盖，比如完全没有代码，就需要中期训练；如果预训练很多样，覆盖了文本、代码、GitHub 等，中期训练很好但未必关键，因为反正会做 SFT，SFT 能让你接近到足以开始在 RL 中拿到奖励。没有 SFT 就麻烦了。中期训练对更好的泛化很重要，但不是成败关键。
  • 多个专家怎样蒸馏回一个模型？要写下一系列提示，让专家在上面生成数据，蒸馏进最终模型。好处是每个专家可以由独立团队负责，算力够的话聚合也可以很简单；但既然有了所有目标，通常更倾向于放进一个大训练循环，省去蒸馏的麻烦。
  • 长推理训练是中期训练的一部分吗？R1 和 Kimi k1.5 都有长思维链 SFT。长思维链传统上不算中期训练，但长思维链数据常用于长上下文扩展，他后悔没讲长上下文扩展：通常是 RLHF 等之前的一个额外阶段，用手头的长数据扩展上下文，通常是书、代码和合成数据，因为只有它们够长。
  • 数学、化学等多个领域的 RL 是并行做还是顺序做，怎样避免遗忘？最接近的答案是这些流程图的划分：推理类问题放在一个桶里，在第二阶段一起做；非推理类问题，包括聊天风格等，放在最后的 RLHF 阶段（第四阶段）。
