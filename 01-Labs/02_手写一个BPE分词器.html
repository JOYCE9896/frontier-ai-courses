练习 02：手写一个 BPE 分词器

不用任何现成的库，一百行 Python 写出字节级 BPE：看它怎样一步步学会合并规则，词表大小怎样影响序列长度，以及为什么同一句话中文比英文贵

对应作业：Stanford CS336 作业 1（Basics）的 BPE 分词器部分。这里的代码另外写过，不是作业答案；作业版本还要求更快的训练算法。
零基础读前预备：分词；最好先读完练习 01 的"准备数据"一节
完整代码：01-Labs/code/bpe/（bpe.py、demo_small.py、train_tinystories.py、explore.py）

一、要做的是什么

练习 01 里，模型看到的不是文字，而是一串编号：先把文字切成 token，再把每个 token 换成编号。当时切分用的是现成的 tokenizers 库，8 秒就训练好了，但它内部怎样决定"little 算一个 token、hippopotamus 要拆成几块"，我们没有看到。

这一篇自己从头写这个分词器，用的算法叫 BPE（Byte Pair Encoding，字节对编码）。GPT、LLaMA、Qwen、DeepSeek 这些模型用的都是它或它的变体。整个算法的思想只有一句话：从单个字节开始，反复把最常一起出现的两个相邻块合并成一个新块。

分四步：

  1. 看看文字在计算机里是什么样子（字节）。
  2. 在一句绕口令上手动跟一遍 BPE，看清每一次合并。
  3. 在 2 万篇 TinyStories 上训练一个 4096 词表的分词器。
  4. 用它做实验：编码解码、词表大小的影响、几个奇怪的切分，以及中英文的对比。

二、文字在计算机里是字节

计算机存文字，最终存的是一串 0 到 255 之间的整数，每个整数叫一个字节。把字符变成字节的规则叫编码，现在几乎都用 UTF-8：英文字母和常用符号各占 1 个字节，带重音的拉丁字母占 2 个，汉字一般占 3 个，emoji 占 4 个。 

print("=== 1. 文字在计算机里是字节 ===")
for s in ["a", "cat", "é", "地", "猫咪", "😀"]:
    b = s.encode("utf-8")
    print(f"{s!r:6} -> {len(s)} 个字符，{len(b)} 个字节: {list(b)}")

运行输出：

'cat'  -> 3 个字符，3 个字节: [99, 97, 116]
'é'    -> 1 个字符，2 个字节: [195, 169]
'地'    -> 1 个字符，3 个字节: [229, 156, 176]
'猫咪'   -> 2 个字符，6 个字节: [231, 140, 171, 229, 146, 170]
'😀'    -> 1 个字符，4 个字节: [240, 159, 152, 128]

为什么要从字节开始，而不是从"字符"开始？因为世界上的字符有十几万种，而字节只有 256 种。以 256 个字节作为最初的词表，任何文字（中文、阿拉伯文、emoji、乱码）都能表示出来，不会出现"不认识的字"。这叫字节级 BPE。代价是：一个汉字一开始要拆成 3 个 token，要靠后面的合并才能变回一个。

三、预切分

在合并之前，先把文本粗略切成"词"，规定 BPE 只能在一个词的内部合并，不能跨词。否则模型可能学到"the cat"中间带空格的这种 token，或者把"dog."和"dog!"当成两个不相干的东西。这里用一个正则表达式（一种描述文字模式的写法）来切：一串英文字母（前面可以带一个空格）算一个词，一串数字算一个词，一串其他符号算一个词，空白单独算。 

# 预切分：先把文本粗切成"词"，BPE 只在词的内部合并，不会跨词。
# 依次匹配：带可选前导空格的英文字母串、数字串、其他符号串（包括中文），以及空白。
PRETOKEN = re.compile(r" ?[A-Za-z]+| ?[0-9]+| ?[^\sA-Za-z0-9]+|\s+(?!\S)|\s+")

def pretokenize(text):
    return PRETOKEN.findall(text)

运行输出（空格显示成 ␣）：

=== 2. 预切分 ===
['Once', '␣upon', '␣a', '␣time', ',', '␣Lily', '␣had', '␣3', '␣cats', '!', '␣', '␣她很开心。']

注意空格是粘在后一个词的前面的："␣upon"而不是"upon"。这样"upon"出现在句首和句中时是两个不同的 token，模型也就知道了这里有没有空格，解码时能一字不差地还原。中文没有空格，"␣她很开心。"整个被当成了一个词，这个简单的规则对中文并不合适，第九节会看到它的后果。GPT-2、GPT-4 用的正则表达式更复杂一些，比如会把 's、'll 这类缩写单独切出来，但思路一样。

四、BPE 训练算法

训练过程：

  1. 预切分，统计每个词出现了几次。"the"出现 10 万次，不必处理 10 万遍，处理一遍再乘以 10 万就行。
  2. 把每个词拆成单个字节。
  3. 数一数所有相邻的两个块一起出现了多少次。
  4. 挑出现次数最多的那一对，合并成一个新块，记下这条合并规则。
  5. 在所有词里执行这次合并，回到第 3 步，直到词表达到想要的大小。

词表大小 = 256 个字节 + 学到的合并规则条数。要 4096 的词表，就学 3840 条规则。 

def merge_pair(tokens, pair, new):
    """在一个 token 序列里，把所有相邻的 pair 换成 new。"""
    out, i = [], 0
    while i < len(tokens):
        if i < len(tokens) - 1 and (tokens[i], tokens[i + 1]) == pair:
            out.append(new); i += 2
        else:
            out.append(tokens[i]); i += 1
    return out
def train(text, vocab_size, log=None):
    """从文本学 vocab_size - 256 条合并规则。返回合并列表，每条是 (左, 右)，都是 bytes。"""
    # 1. 统计每个"词"出现几次。同一个词不管出现多少次，只需要处理一次，再乘上次数。
    word_counts = Counter(pretokenize(text))
    # 2. 每个词先拆成单个字节。词表一开始就是 256 种字节。
    words = {w: [bytes([b]) for b in w.encode("utf-8")] for w in word_counts}
    merges = []
    while 256 + len(merges) < vocab_size:
        # 3. 数所有相邻的两个 token 一起出现了多少次
        pairs = Counter()
        for w, toks in words.items():
            for a, b in zip(toks, toks[1:]):
                pairs[(a, b)] += word_counts[w]
        if not pairs:
            break
        # 4. 取次数最多的一对；次数相同时取字典序大的，保证结果确定
        best = max(pairs, key=lambda p: (pairs[p], p))
        new = best[0] + best[1]
        merges.append(best)
        if log is not None:
            log(len(merges), best, pairs[best], words)
        # 5. 在所有词里把这一对合并成新 token
        for w in words:
            if len(words[w]) > 1:
                words[w] = merge_pair(words[w], best, new)
    return merges

代码里的 Counter 是 Python 自带的计数器，pairs[(a, b)] += 次数 就是"这一对又见到了这么多次"。max(...) 那一行挑次数最多的一对；如果有几对次数一样，就按字典序挑，这样每次运行结果都一样。

一步步看：

  • 第 1 次，p 和 e 挨在一起出现了 4 次（Piper 里 1 次，peck 里 1 次，peppers 里 2 次），合并成 pe。
  • 第 3 次合并的是 pe + r，左边的 pe 是第 1 次合并的产物。新块还能继续参与合并，所以块会越来越长：第 5 次 pi + ck 得到 pick，第 7 次 ␣ + pick 得到 ␣pick。
  • 每次合并后，各词的切分都变短了一点。8 次合并后，"␣picked"从 7 块变成了 2 块（␣pick | ed）。
  • 第 1 次其实有平局："␣ + p"也出现了 4 次（picked、peck、pickled、peppers 前面的空格）。这里按字典序挑了 p + e。规则换一下，合并顺序就不一样，CS224N 第十三讲的课件用同一句绕口令演示时，第一步合并的就是"_ + p"。结果略有差别，但道理相同。

六、编码与解码

训练得到的是一张有先后顺序的合并规则表。拿到一段新文字时怎样切？先预切分、每个词拆成字节，然后在当前所有相邻对中，找训练时最早学到的那条规则，执行它；重复，直到没有任何一对能合并。为什么按训练顺序？因为训练时就是按这个顺序合并的，后面的规则是建立在前面的结果之上的（比如要先有 pi 和 ck，才能有 pick）。

解码更简单：每个编号查出对应的字节，拼起来，再按 UTF-8 变回文字。 

class Tokenizer:
    def __init__(self, merges):
        self.merges = merges
        self.rank = {pair: i for i, pair in enumerate(merges)}   # 合并规则的先后顺序
        self.vocab = [bytes([b]) for b in range(256)] + [a + b for a, b in merges]
        self.id_of = {tok: i for i, tok in enumerate(self.vocab)}
        self.cache = {}

    def encode_word(self, word):
        if word in self.cache:
            return self.cache[word]
        toks = [bytes([b]) for b in word.encode("utf-8")]
        while len(toks) > 1:
            # 在当前相邻对里，找最早学到的那条合并规则来用；一条都用不了就结束
            pairs = [(self.rank.get(p, float("inf")), p) for p in zip(toks, toks[1:])]
            r, p = min(pairs)
            if r == float("inf"):
                break
            toks = merge_pair(toks, p, p[0] + p[1])
        ids = [self.id_of[t] for t in toks]
        self.cache[word] = ids
        return ids

    def encode(self, text):
        return [i for w in pretokenize(text) for i in self.encode_word(w)]

    def decode(self, ids):
        return b"".join(self.vocab[i] for i in ids).decode("utf-8", errors="replace")

    def pieces(self, text):
        """返回每个 token 对应的字节，方便看切分结果。"""
        return [self.vocab[i] for i in self.encode(text)]

    def truncated(self, vocab_size):
        """BPE 的合并是一条条按顺序学的，所以只取前 vocab_size-256 条，就得到一个更小词表的分词器。"""
        return Tokenizer(self.merges[: vocab_size - 256])

词表   512： 337,651 个 token，平均每个 token 2.35 个字节   例句切分：The | ␣little | ␣girl | ␣was | ␣happy | .
词表  1024： 257,275 个 token，平均每个 token 3.08 个字节   例句切分：The | ␣little | ␣girl | ␣was | ␣happy | .
词表  2048： 218,768 个 token，平均每个 token 3.63 个字节   例句切分：The | ␣little | ␣girl | ␣was | ␣happy | .
词表  4096： 200,638 个 token，平均每个 token 3.95 个字节   例句切分：The | ␣little | ␣girl | ␣was | ␣happy | .
  • 词表 256 就是只有字节、一条规则都没有：一个字节一个 token，"The little girl was happy."要 26 个 token。
  • 只加 256 条规则（词表 512），token 数就减少了一半多，每个 token 平均 2.35 个字节。最常见的词（the、little、was）在最早的规则里就合成了。
  • 之后收益越来越小：词表从 2048 翻倍到 4096，token 数只少了 8%。后面学到的规则都是少见的词，用得少，省得也少。

词表不是越大越好。序列短，模型每次能看的内容就多，计算也省；但词表越大，嵌入矩阵越大（练习 01 里它占了 157 万参数），少见的 token 在训练中出现得少，它们的向量也就学得差。现在的大模型在两者之间取折中，词表一般在 10 万到 26 万之间（CS224N 第十三讲列了各家模型的数字），因为它们要覆盖几十种语言和代码；TinyStories 只有简单英文，4096 就够了。

八、几个奇怪的切分

=== 3. 切分的怪现象 ===
'strawberry'       -> st | ra | w | berry
' strawberry'      -> ␣straw | berry
' Strawberry'      -> ␣St | ra | w | berry
' strawbery'       -> ␣straw | ber | y
' hippopotamus'    -> ␣h | ipp | op | ot | am | us
' 2026'            -> ␣ | 2 | 0 | 2 | 6
' 12345'           -> ␣ | 1 | 2 | 3 | 4 | 5
' Kallini'         -> ␣K | all | in | i
  • 同一个词，切法取决于前面有没有空格、是不是大写："␣strawberry"是 ␣straw | berry 两块，句首没有空格的"strawberry"变成 st | ra | w | berry 四块，大写的"␣Strawberry"又是另一种。对模型来说这是几串完全不同的编号，它得从数据里自己学会它们是同一个词。
  • 这也是常被提到的"大模型数不清 strawberry 里有几个 r"的原因之一：模型看到的是 ␣straw 和 berry 两个编号，看不到里面的字母，要回答就只能靠记忆。
  • 拼错一个字母（strawbery），切分就变了：berry 变成了 ber | y。
  • 在儿童故事里，数字和 hippopotamus 这种长词很少出现，所以没学到相应的规则："␣2026"被拆成 ␣ | 2 | 0 | 2 | 6，河马被拆成六块。分词器只学会了它训练数据里常见的东西。
  • CS224N 第十三讲的客座讲者 Julie Kallini 的姓"␣Kallini"被拆成 ␣K | all | in | i，是用常见的片段拼出来的。BPE 不会遇到"不认识的词"，最差也能退回到单个字节。

九、同一句话，中文比英文贵多少

最后拿两句意思相同的中英文，用三个分词器比一比：本练习只在英文故事上训练的分词器，GPT-2 的分词器（2019 年，词表 5 万，训练数据以英文网页为主），GPT-4o 的分词器（2024 年，词表约 20 万，OpenAI 发布时说明它对很多非英语语言的压缩比以前好）。后两个通过 OpenAI 公开的 tiktoken 库调用。 

pairs = [("The little cat is playing in the garden.", "小猫在花园里玩。"),
         ("Thank you very much for your help today.", "非常感谢你今天的帮助。")]
encs = {"本练习的分词器（只在英文故事上训练，词表 4096）": tok.encode,
        "GPT-2 的分词器（词表 50257）": tiktoken.get_encoding("gpt2").encode,
        "GPT-4o 的分词器（词表约 20 万）": tiktoken.get_encoding("o200k_base").encode}
for en, zh in pairs:
    print(f"\n英文：{en}\n中文：{zh}")
    for name, enc in encs.items():
        print(f"  {name}：英文 {len(enc(en))} 个 token，中文 {len(enc(zh))} 个 token")
print("\n本练习的分词器怎样切中文：", show(tok, "小猫在花园里玩。"))
g4 = tiktoken.get_encoding("o200k_base")
print("GPT-4o 的分词器怎样切中文：", " | ".join(vis(g4.decode_single_token_bytes(i)) for i in g4.encode("小猫在花园里玩。")))

运行输出：

英文：The little cat is playing in the garden.
中文：小猫在花园里玩。
  本练习的分词器（只在英文故事上训练，词表 4096）：英文 9 个 token，中文 24 个 token
  GPT-2 的分词器（词表 50257）：英文 9 个 token，中文 17 个 token
  GPT-4o 的分词器（词表约 20 万）：英文 9 个 token，中文 8 个 token

英文：Thank you very much for your help today.
中文：非常感谢你今天的帮助。
  本练习的分词器（只在英文故事上训练，词表 4096）：英文 9 个 token，中文 33 个 token
  GPT-2 的分词器（词表 50257）：英文 9 个 token，中文 21 个 token
  GPT-4o 的分词器（词表约 20 万）：英文 9 个 token，中文 7 个 token

本练习的分词器怎样切中文： <e5> | <b0> | <8f> | <e7> | <8c> | <ab> | <e5> | <9c> | <a8> | <e8> | <8a> | <b1> | <e5> | <9b> | <ad> | <e9> | <87> | <8c> | <e7> | <8e> | <a9> | <e3> | <80> | <82>
GPT-4o 的分词器怎样切中文： 小 | 猫 | 在 | 花 | 园 | 里 | 玩 | 。
  • 本练习的分词器从没在训练数据里见过中文，所以没有任何关于中文的合并规则。"小猫在花园里玩。"8 个字，每个字 3 个字节，就成了 24 个 token，每个 token 只是半个字都不到的一个字节（输出里的 <e5> 是字节的十六进制写法，单个字节没法显示成字）。
  • GPT-2 的分词器见过一些中文，合并了一部分，但还是要 17 个 token，几乎是英文的两倍；第二句是 21 对 9。
  • GPT-4o 的分词器每个汉字都是一个完整的 token，中文（8、7 个）和英文（9 个）差不多。

这件事不只是技术细节。按 token 收费的 API，同样的意思用 GPT-2 那样的分词器写中文，要付大约两倍的钱；上下文窗口按 token 算，中文能放进去的内容也少一半；模型对每个字要预测好几步，也更难学好。CS224N 第十三讲讲的"分词带来语言间的不公平"（Petrov 等 2023 发现同样的内容在不同语言间 token 数最多差 15 倍）说的就是这个。解决办法就是这一篇看到的：让分词器的训练数据里有足够多的各种语言。
