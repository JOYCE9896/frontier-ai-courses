这一讲讲什么

Caiming Xiong 在 Salesforce AI Research 带团队做多模态模型和智能体。他开场说，上一周同学们刚听过同一个方向的课（Ruslan Salakhutdinov 讲多模态自主智能体），他希望能带来一些新的东西。这一讲他只谈“电脑使用”（computer use）这类多模态智能体：模型看着屏幕，用键盘和鼠标替人完成任务。

他把要做好这类智能体拆成三块：环境和基准（要能重新配置、能扩展，不能只是静态数据集）；数据（模态多样、规模大、覆盖面广的轨迹数据）；模型（把视觉、语言、推理、动作统一在一个模型里）。三块各配了自己团队的代表工作：OSWorld、AgentTrek 和 TACO、Aguvis。录像里没有问答环节。幻灯片最后还有一段讲长视频和记忆（BLIP-3-Video 用 32 个 token 表示一段视频、GenS 生成式帧采样），录像在 Aguvis 讲完后就结束了，这部分没有讲到，本文只在末尾按幻灯片列一下标题。

01. 开场：为什么是多模态智能体

录像位置 0:00:00–0:04:47

基准一个个被做满

他先放了一张图（幻灯片注明出自 Jason Wei 的一条推文）：过去四五年里，几乎所有基准都被做到饱和，现在剩下的是今年新提出的 Humanity's Last Exam。他说不确定今年能不能解决它，但相信到年底会有好得多的成绩。

既然前沿基础模型已经这么强，接下来该拿它们做什么？他的回答是智能体。他的团队认为，多模态 AI 智能体是下一代应用。理由是人们希望智能体不只读文字，还能听、能看、能说；而且人在电脑上做的大多数事都要跨多个应用和界面。由视觉-语言-动作模型（vision-language-action model，VLA，即同时接收图像和文字、输出可执行动作的模型）驱动的智能体，可以让数字操作更容易、更自动化，提高人的生产力。

已经能看到的几类多模态智能体

  • 编程智能体：很多同学在用 Cursor、Replit、Devin 这类编程助手。它们不只接受代码文本，也能让你上传截图，再根据图片生成代码或修 bug。幻灯片上列了 SWE-bench（让模型解决真实 GitHub issue 的基准）和 MLE-bench（评估机器学习工程任务的基准）。
  • 网页智能体：在浏览器里替你自动完成操作。幻灯片列了 World of Bits、Mind2Web、WebArena、BrowserGym。
  • 手机智能体：在手机应用里做同样的事。
  • 实体智能体：他放了 Figure AI 的机器人 Helix 的视频，不只是人和一台机器人交互，还能让两台机器人借助基础模型协作。

这些智能体有的已经上线，有的还在研究阶段，有的在演示阶段。他认为这类应用会越来越多，所以问题变成：怎么开发它们，难点在哪，该把精力放在哪些部件上。

02. 现有基准缺什么，OSWorld 想补什么

录像位置 0:04:47–0:12:34

三块议程

他列出今天的议程：环境和基准、数据、模型。第一块，他要的是交互式环境，要可配置、可扩展，光有静态基准不够；第二块是怎么拿到训练数据；第三块是该在什么样的模型上构建。

电脑任务往往是跨应用的工作流

人每天用电脑浏览网页、剪个人视频、管理文件、做分析、写代码。这些任务常常不只碰一个应用，而是一条经过多个应用的工作流，界面可能是图形界面（GUI），也可能是命令行（CLI）。多模态智能体可以按人的高层自然语言指令，自动完成这些交互。

他用的例子来自幻灯片：“Update the bookkeeping sheet with my recent transactions over the past few days in the provided folder.”（用文件夹里最近几天的交易记录更新我的记账表。）他说这种任务很无聊，谁都想有个智能体代劳。但要信任智能体，先得有基准。

现有基准的两类问题

他认为当前的主要障碍是缺一个建立在真实交互环境上的基准：能覆盖多样、复杂的真实电脑使用场景，支持不同的操作系统、界面和应用。智能体通过了这样的基准，才能放心拿来日常用。

  • Mind2Web：任务很真实，但每个任务只有一条人类演示，没有可执行的环境。这等于默认每个任务只有一种解法，这并不成立；按这种方式评测，会错判那些用别的路径做对的方案。幻灯片总结为：没有基于执行结果的评测，也不能支持交互式学习和真实探索。
  • WebArena：有可执行环境，但简化了观测空间和动作空间，只覆盖少数几个网站域名上的网页导航。这限制了能测的用例，也测不了需要在多个应用和界面之间来回切换的开放式真实任务。

OSWorld 的定位

为了补上模型开发用的模拟环境和真实使用场景之间的差距，他们做了 OSWorld（Xie et al., 2024）。他称之为第一个可扩展的、真实的电脑环境，既能用来开发多模态智能体，也能用来做基准测试。

说它“真实”，是因为智能体可以不受限制地用键盘和鼠标操控真实的电脑应用。说它不是固定的评测集，是因为你可以自己配置任务，以交互方式执行，用来评估涉及任意应用的开放式电脑任务，比如软件开发或者修图。用户想定义新任务时，不必为每个领域单独搭一个模拟环境，OSWorld 可以作为统一的真实电脑环境，让用户自己控制想关心的场景。

03. OSWorld 的一轮任务：配置、观测、动作、评测

录像位置 0:12:34–0:21:40

第一步：任务配置文件

每个任务从一条自然语言指令开始。OSWorld 给每条指令配一个初始状态配置文件，里面有三部分：怎样准备初始环境（下载哪些文件、打开什么）、评测前的后处理、怎样评测。幻灯片上的记账表任务配置大致如下（节选）：

{
  "instruction": "Please update my bookkeeping sheet with the recent transactions
                  from the provided folder, detailing my expenses over the past few days.",
  "config": [
    {"type": "download", "parameters": {"files": [
        {"path": "/home/user/Desktop/my_bookkeeping.xlsx", "url": "https://drive.google.com/uc?id=xxxx"},
        {"path": "/home/user/Desktop/receipt_0.jpeg", "url": "https://drive.google.com/uc?id=xxxx"}]}},
    {"type": "open", "parameters": {"path": "/home/user/Desktop/my_bookkeeping.xlsx"}}
  ],
  "evaluator": {
    "postconfig": [{"type": "activate_window",
                    "parameters": {"window_name": "my_bookkeeping.xlsx - LibreOffice Calc"}}],
    "result":   {"type": "vm_file", "path": "/home/user/Desktop/my_bookkeeping.xlsx"},
    "expected": {"type": "cloud_file", "dest": "my_bookkeeping_gold.xlsx"},
    "func": "compare_table",
    "options": {"rules": [{"type": "sheet_fuzzy", "rules": [{"range": ["A1:A8"]}]}]}
  }
}

第二步：在虚拟机里初始化

配置写好后，OSWorld 在虚拟机里按配置把环境初始化成任务开始时的状态，相当于模拟一个人做到一半的工作现场。他说这样很方便：同一个虚拟机可以一次次恢复到初始状态反复测试；而且虚拟机是隔离的安全环境，不用担心测试时造成不可逆的破坏。

第三步：智能体收到什么观测

环境准备好，就可以让智能体来交互了，可以用 GPT-4V 搭，也可以用任何开源模型。智能体能拿到：

  • 用户的自然语言指令；
  • 屏幕截图；
  • 无障碍树（accessibility tree，a11y tree，操作系统为读屏软件提供的界面元素结构化文本描述，网页上对应的是 DOM 树）；
  • 自定义的数据流，比如终端输出。

幻灯片左边是 Set-of-Marks（SoM，在截图上给每个可交互元素画框、标编号，编号对应无障碍树里的信息），右边是无障碍树。他说不是每个智能体都要用全部观测：纯视觉的智能体可能只看截图，纯文本的可能只用无障碍树，看你怎么设计。

第四步：智能体输出什么动作

智能体最终生成可执行动作，比如在某个坐标点击、拖动、勾选框、操作键盘鼠标。每个动作用一段代码表示，由模拟器在虚拟机里执行，然后返回新的观测。OSWorld 用的是 Python 库 pyautogui 来控制鼠标和键盘。幻灯片上的例子是“monitor the system CPU for 30s and output the results”（监控 CPU 30 秒并输出结果），智能体的动作序列是：

pyautogui.click(focus_x, focus_y)
pyautogui.click(terminal_x, terminal_y)
pyautogui.typewrite('sar 1 30 > ...', interval=0.5)
# then the agent outputs: Done

这个“观测、动作”的循环一直重复，直到智能体输出终止动作（完成或失败），或者到达最大步数。他们实验里最大步数设为 15 和 50 两档。

第五步：基于执行结果的评测

任务结束后，OSWorld 读取环境的最终状态，用基于执行的奖励函数打分：达成目标得正奖励，部分达成给 0 到 1 之间的分数，完全失败得 0。

他强调，他们认为不存在一种通用的判断成败的方法，所以把评测做成开放的：用户可以针对每个任务自己写评测脚本，有的任务要检索信息，有的要做匹配。按样例（example-wise）设计评测指标，不套用一个固定指标。这样能容纳多样的任务，复杂的开放式真实任务也评得更可靠。

04. OSWorld 基准里的 369 个任务

录像位置 0:21:40–0:27:44

任务从哪来

在环境之上，他们还做了一个基准：369 个真实电脑任务，涉及常用的网页和桌面应用、操作系统文件读写、多应用工作流，覆盖办公、日常、专业等场景。每个任务都是他们在网上做了大量检索、根据真实电脑使用案例整理出来的。然后请有计算机背景的人在初始化好的环境里实际操作、录下轨迹，并手写大量基于执行的评测脚本来判断任务是否完成。

按幻灯片，每个任务标注三样东西：来自真实用户的任务指令、模拟人工作进行到一半的初始状态配置、一个定制的基于执行的评测脚本。

任务分布

  • 总共 369 个任务，其中约 100 个是工作流任务，要在多个应用之间跳转；268 个（约 70%）是单应用任务。
  • 约 20% 的任务改编自已有数据集（他提到的数据集名字字幕不清）。
  • 有 30 个“不可行”任务（infeasible，字幕里听成 invisible）。他的理由是智能体也要学会对用户说不，加入这类任务让测试更全面。
  • 另有 43 个 Windows 任务，不只有 Ubuntu。
  • 为 369 个样例写了 134 个评测脚本，他说这个比例很高，体现了按样例设计评测的思路。

和其他基准对比

他们从几个维度对比了现有基准：是否提供可控的可执行环境、是否容易扩展到新环境、是否支持多模态、能否做跨应用任务、能否从中间状态开始任务等。OSWorld 在这些维度上覆盖得更全。

他们还和 WebArena 比了任务难度。人完成 WebArena 任务的中位时间大约 30 到 40 秒，OSWorld 大约 100 到 110 秒，而且有相当数量的任务要 900 秒甚至更久。他说这说明 OSWorld 任务的复杂度比现有基准高。

05. 模型成绩和影响成绩的因素

录像位置 0:27:44–0:36:20

实验设置

他们测了当时最好的开源和闭源模型。幻灯片上列出：开源的 Mixtral 和 CogAgent，闭源的 GPT-4、Gemini-Pro、Claude-3；温度 1.0，top-p 0.9；每一步把最近 3 次观测和动作作为历史上下文。提示词比较复杂，幻灯片左边贴了全文。

按观测方式分四种设置：

  1. 只给无障碍树（纯文本模型也能直接跑）；
  2. 只给截图（纯视觉）；
  3. 截图加无障碍树；
  4. Set-of-Marks。

无障碍树通常很长，含大量冗余信息，所以他们做了简化来缩短文本长度。

结果怎么读

  • 表格最下面是人类表现，成功率大约 70% 到 75%。最好的开源和闭源模型都远远落后。他特别说明，这些都是日常任务，不是特别难的任务。
  • 人在不同类型任务上的表现很稳定，上下浮动 3% 到 5%；模型的表现则随场景大幅波动。即使是同一家公司的模型也差很多，比如在 Set-of-Marks 设置下 GPT-4 和 GPT-4o 相差约 10 个百分点，而成绩本身只有 20% 左右。
  • 这张表是去年的结果。今年各家出了新模型，有大幅提升，但离人类还很远。

幻灯片的结论还有两条：无障碍树和 SoM 的效果因模型而异；只看截图的设置成绩更低，但从长远看它应该是最终形态。

截图分辨率

他们对截图做降采样，看成功率怎么变。原因是多数视觉语言模型（VLM）训练时用的分辨率比现在的屏幕低。结果是分辨率越高，GPT-4 在只看截图设置下的表现越好。在截图加无障碍树的设置里，趋势还是上升，但有噪声、没那么清楚。他的解释是无障碍树里有额外的文本信息，削弱了分辨率的影响。

历史上下文长度

他们改变放进上下文的历史步数。基于文本（无障碍树）的设置里，GPT-4 随着历史步数增加而变好；只看截图的设置里，加历史反而更差。他的解释是当前基础模型处理文字比处理原始图像强，模型还没有针对电脑使用场景训练好。他认为开源社区和闭源公司都需要提升基础模型的视觉能力，才能做出更好的电脑使用智能体。

但文本历史有效率问题。无障碍树很长，第 90 百分位大约 6k token。要放更多历史，就得想办法让无障碍树更精简，比如先挑出相关信息再送进系统；可这一步可能要再训一个大模型来做信息处理，会增加延迟。

跨系统一致性和鲁棒性

  • 同一模型在 Ubuntu 和 Windows 上的表现相关性很高。他的推论是，在一个环境里训练好的模型应该能有效迁移到另一个环境，用 OSWorld 框架做开发是有效的。
  • 他们改变应用窗口在屏幕上的位置和大小，结果差异很大，说明现有基础模型对界面布局和噪声这类扰动不够鲁棒。

06. 近期进展：Claude computer use 和 OpenAI Operator

录像位置 0:36:20–0:39:33

好消息是这个方向最近进展很快。

  • Anthropic 推出 Claude 3.5 和 3.7 的电脑使用功能后，OSWorld 成绩从约 14%、15% 提到约 22%（15 步设置），但离人类的 72% 还很远。把步数从 15 增加到 50 会更好，差距仍然很大。
  • OpenAI 推出了 Operator，背后的模型叫 CUA（Computer-Using Agent）。在他们最近的结果里，它明显好于 Claude 3.5，在 200 步的设置下能达到 38%。他说四个月前大概只有 15%，进步很快。

他补了一句：200 步是很宽的预算，OSWorld 里多数任务 15 步、最多 20 步就能完成。所以从效率看，提升空间还很大。

他对环境和基准这一块的小结是：电脑使用智能体已经有很大进展，但还有很多要改进的地方。

07. 数据难题和 AgentTrek 的思路

录像位置 0:39:33–0:45:57

为什么智能体数据比 LLM 数据更难拿

他认为训练智能体的数据挑战比训练 LLM 更大。智能体任务是多步的，一条数据是一整条轨迹（trajectory，即一连串“观测、推理、动作”的记录）。困难有几层：

  • 互联网上没有现成的大规模轨迹语料可以直接爬，这和 LLM 可以用现成文本语料不同；
  • 就算有钱雇人标注，标注轨迹也极其耗时，成本和时间都限制了规模，不利于规模定律（scaling law）；
  • 人工标注的成本和复杂度让多样、大规模的轨迹数据很难收集。

他的问题是：那为什么不让模型自己合成？

AgentTrek：用网上教程引导回放

AgentTrek（Xu et al., 2024）的全名是“通过网页教程引导回放来合成智能体轨迹”。出发点是：互联网上有大量教程类文本，一步步教人怎么在 GUI 环境里完成各种任务。人读这些教程，就能学会怎样在不同应用里完成任务。这些教程覆盖很多场景，可以系统地把它们筛出来。

但这些文本是写给人看的，有很多噪声描述和 HTML 格式。所以要从中抽出有用的知识和步骤，把非结构化文本变成结构化的智能体轨迹，附上任务的高层描述，让智能体可以拿来训练、模仿人完成任务的方式。

三个阶段

  1. 从互联网自动收集教程：用一批启发式规则和 fastText 之类的分类器从网上数据里筛出教程，再用 LLM 转成结构化格式。
  2. 引导回放生成轨迹：让一个视觉语言模型智能体按结构化教程的步骤，在真实环境里一步步执行，记录下高层任务描述、每一步的观测、每一步的推理和最终动作。然后用一个单独的评估器检查轨迹质量，过滤掉差的、低质量的轨迹。
  3. 训练模型验证：用这些数据微调智能体模型，看在不同基准上是否有显著提升。

08. AgentTrek 流水线细节和效果

录像位置 0:45:57–0:58:21

阶段一：筛教程

起点是 RedPajama、DCLM 这类大型网页语料。先用关键词、结构特征等启发式规则过滤，这一步就去掉了 99% 以上的数据（他后来说，经过六步启发式过滤后，去掉的超过 99.9%）。再从剩下的数据里抽一个子集，让 LLM 标注是不是好的 GUI 教程（幻灯片上贴了分类用的提示词）；用这些标注训练一个 fastText 分类器，对整个过滤后的数据做分类。

他们还让人抽样核查 LLM 的标注，F1 分数大约 88% 到 89%。他们发现对很长的文档，LLM 判断得比人还好，因为教程埋在长文里时人容易漏看。他说这不意外。所以长文本的分类交给 LLM。

标注和改写成五个字段

筛出的教程再过一轮 LLM，按预先定义的格式改写，供阶段二使用。五个字段是：

  1. 平台和目标环境：操作系统、软件版本、相关依赖，用于设置初始状态；
  2. 任务描述：一句简洁的问题陈述，也就是指令；
  3. 前置条件：需要的依赖、工具和背景知识；
  4. 分步指令：操作步骤，包括命令语法和动作顺序；
  5. 预期结果：任务成功时应该看到什么，用于验证。

阶段二：引导回放和质量评估

把结构化教程交给一个 VLM 智能体，它在环境里按“观测、动作”循环一步步执行。执行完后把全部观测、动作和中间推理记录下来，形成整条轨迹。再交给另一个 VLM 评估器判断轨迹的质量和正确性，保证留下的是高质量数据。幻灯片上的样例一边是观测序列，一边是每一步的推理和对应的动作代码。

和已有数据集比

  • 规模：他们展示的是 1 万条轨迹，他说这不是上限，只是目前做了这么多，可以做得更大。
  • 复杂度：他说数据的复杂度不低，每条轨迹有不少步（具体步数字幕不清）。
  • 信息量：每一步有 HTML、无障碍树、推理过程，还可以有视频和截图，覆盖很多不同网站。

他认为 AgentTrek 保持了多样性和真实性，因为数据来自真实世界；同时解决了人工标注的规模问题和预算问题。幻灯片还给出了轨迹在不同网站和不同领域上的分布。

效果

他们在 WebArena 上做了对比：用 AgentTrek 数据训练的模型，明显超过用其他数据训练的开源模型，也超过一些闭源模型。他说这说明合成轨迹质量够高，可以用来训练基础模型做智能体。

收获和局限

  • 利用互联网语料仍然重要，因为它提供了多样的任务来源和知识。
  • 轨迹里的推理和反思很重要，模型部分会再讲到。
  • 问题在于每条指令仍然只有一条轨迹，而一个任务可能有多种解法。所以它还只是模仿学习。

他给的出路是和 OSWorld 结合：先用 AgentTrek 数据做监督微调（SFT），再拿同样的高层指令到 OSWorld 里跑第二阶段的强化学习（RL），解决探索的问题。幻灯片写作“from imitation learning to reinforcement learning in environment”“Combine with OSWorld (SFT→RL)”。

09. TACO：用合成的“思考加动作”数据提升理解

录像位置 0:58:21–1:10:17

问题：多模态模型自己需要调用动作吗

前面的数据合成是为了让模型在外部任务上会操作。他接着问：同样的思路能不能用来提升模型自身的能力，比如理解？视觉语言模型本来就是为理解训练的，但开源模型在理解上离完美还很远。网上能不能爬到这种数据？他的回答是基本没有，所以要合成。

幻灯片列了开源多模态模型做不好的四类问题：细粒度 OCR、视觉定位和计数、多步识别加推理、需要外部知识。这些任务要么需要更细的视觉能力，要么需要推理，要么需要外部知识。他的想法是让模型自己能调用动作（工具），以此提升理解。

TACO 和 CoTA

TACO 是多模态动作模型，用合成的 CoTA（Chains-of-Thought-and-Action，思维链加动作链）数据训练。加上动作调用能力后，模型面对一个问题会生成思考和动作，拿到观测结果后再思考、再调用，直到得出答案。他展示的例子里，LLaVA 原本答错的题，TACO 通过调用定位等视觉函数、查询外部文本知识、把视觉 OCR 和计算组合起来答对了。

合成流水线

他说细节很多但不复杂，分上下两部分。

基于模型的生成：取 15 个图像问答（image QA）数据集的图片和问答对作为输入，提示前沿模型：给你这张图和这个问题，请用动作列表里的动作生成思维链和动作；如果列表里没有相关动作，就只生成思维链。然后验证输出答案是否正确，正确就保留；不正确，就把这一对转成直接回答的样本。所以得到的数据有三种：带动作的思维链、只有思维链、直接回答。

程序化生成：这条路没有现成问答，只有图片。先用检测模型、深度估计模型、OCR 模型等（也可以有人工标注的框）得到图片的标注，再用人工设计的模板生成问答对，同时按公式合成回答问题所需的动作链。模板类型包括计数、2D 空间推理、3D 空间推理、理解和计数混合等，目的是模拟回答不同类型问题需要的推理和动作调用。

幻灯片上的动作集：OCR、GetObjects、LocalizeObjects、EstimateObjectDepth、EstimateRegionDepth、GetImageToTextsSimilarity、GetImageToImagesSimilarity、GetTextToImagesSimilarity、DetectFaces、Crop、ZoomIn、QueryLanguageModel、QueryKnowledgeBase、Calculate、SolveMathEquation。

实验发现

  1. 要让多模态基础模型具备推理和动作调用能力，必须微调。few-shot（少样本示例）或上下文学习不起作用。
  2. 加了动作能力后，模型能解决之前解决不了的题，理解能力确实提高了。他说即使是理解能力，也可以通过加外部工具、用函数调用来增强，这不算特别意外，但正面结果给了提升理解的另一条路。按幻灯片，最好的 CoTA 数据配方让 TACO 在 8 个基准上平均比只用指令微调的基线高 1% 到 4%，在 MMVet 上最多高 15%。他提到的基准还有 BLINK、MMMU 等，几乎所有任务都有提升，说明是整体理解能力在变好，不是只提升了某一个基准。
  3. 质量比数量重要，不是加得越多越好。按幻灯片：最小的纯 CoTA 数据集，比混合了 CoTA、CoT 和直接回答的更大数据集平均表现更好；过滤掉“动作没用”的数据集也带来提升。
  4. 幻灯片还有一条：加入程序化生成的数据在部分基准上有收益，但平均成绩没有提升。

他的小结：动作调用能力应该是多模态 LLM 的默认能力；CoTA 微调远好于 few-shot CoTA；CoTA 数据能稳定提升只用直接回答数据做指令微调的基线；质量比数量重要。他说最后一点不新，但还是从这里得到了验证。

10. Aguvis：纯视觉的 GUI 智能体要解决的三个问题

录像位置 1:10:17–1:19:28

他说到这里，环境、基准、数据合成这几样工具大家都有了，可以开始做自己的多模态智能体。最后一块讲模型。他声明不是说这就是最好的模型，现在每过一阵就有更好的，他希望大家从中拿到一些设计上的思路。

三个问题

  1. 界面的文本表示五花八门：多数 GUI 智能体依赖文本表示。网页是 HTML 或 DOM 树，桌面操作系统是无障碍树（AXTree），手机是另一种 XML。它们都很长，界面越复杂越长。纯视觉就只有一种表示：不管背后的代码长什么样，看到的就是一张图。
  2. 动作空间也不统一：不同系统用不同工具，同一个平台上观测表示不同，动作空间也不同。幻灯片对比了 Mind2Web 的简化浏览器 API、基于 HTML 的 Playwright 浏览器 API、VisualWebArena 的增强浏览器 API、基于视觉的 PyAutoGUI。他说这不算大问题，但会妨碍跨环境学习，也没法把不同来源的训练数据合在一起用，不利于扩展。
  3. 视觉定位（grounding）能力弱：grounding 指把“点击提交按钮”这样的描述对应到屏幕上的具体坐标或元素。他们在手机、桌面、网页三种场景测试，发现闭源模型的定位能力差得出人意料。他的解读是这些模型没有真正针对电脑使用场景优化。
  4. 不推理就直接出动作：现有方法训练智能体直接生成底层动作（比如一行 pyautogui 代码），中间没有推理。这样在需要仔细规划的复杂真实场景里会很吃力，而 LLM 从文本语料里学到的规划知识本可以迁移过来。

（幻灯片把第 1、2 条合为一条，总共列三条。）

Aguvis 的对应设计

Aguvis（Xu et al., 2024）是统一的纯视觉 GUI 智能体：

  • 纯视觉：直接在屏幕截图上操作，不依赖平台特有的文本表示，所以更容易泛化到不同界面。
  • 统一动作空间：定义一套标准化的动作格式，把不同数据集转到同一格式，从而能用上更多现有数据；再通过训练提升定位能力。
  • 显式推理，即内心独白（inner monologue）：训练时把推理过程放进数据。他认为这是更关键的一点，因为能利用 LLM 已经记住的知识和推理模式，让动作模型更鲁棒。

在每一步交互里，智能体在观测和最终动作之间多生成两部分：思考（thought）和底层指令（low-level instruction）。开始时拿到的是高层指令，智能体先像思维链那样把问题拆成小步，再为当前这一步写出一句底层指令，最后生成具体的动作代码。他说这样分层推进，智能体更鲁棒、更准确。

11. Aguvis 的训练、数据和评测

录像位置 1:19:28–1:28:21

两阶段训练

  1. 第一阶段：定位（grounding）。他们用了一个技巧叫 grounding packing：把基于同一张截图的所有定位样本拼接成一个多目标定位样本。这样提高了训练效率，成绩也略有提升。
  2. 第二阶段：规划和推理。在训练数据中加入内心独白，让智能体在生成动作之前先生成中间思考和底层指令。

数据怎么来

因为是纯视觉，不同数据集很容易合并：统一格式、统一动作输出，就能用上大部分现有数据，组成新的训练集。

内心独白是用前沿模型（GPT-4o）生成的：给它观测截图（把目标 UI 元素高亮）、任务的最终目标、之前的动作、这一步的动作代码，让它补写出思考和底层指令。幻灯片上的例子是：原数据只有目标、之前的动作和这一步的动作；增强后多了思考和底层指令两部分。

最终的 Aguvis Collection 是一个开源的统一大规模 GUI 智能体数据集：第一阶段 100 万条以上的 GUI 定位数据，第二阶段 3.5 万条带显式内心独白的多步轨迹。

评测

  • GUI 定位：在不带规划器的纯定位任务上，Aguvis 明显超过现有模型。只做完两阶段训练、一个模型同时负责定位和规划推理时，第二阶段反而进一步提升了定位成绩，达到最好水平。
  • 离线评测：在 Mind2Web 上各项指标都更好；在 AndroidControl 上也是。
  • 在线评测：浏览器场景用 Mind2Web-Live（和 Mind2Web 不同，它提供动态网页环境），手机场景用 AndroidWorld，Aguvis 都表现最好。

他特别指出一点：Aguvis-7B 加上 GPT-4o 做规划器，也能达到最好水平。这说明 Aguvis 的定位能力更强，而定位能力的提升会直接提高最终的规划任务成绩。他认为定位这一块还有很大提升空间。

消融分析

  • 两个训练阶段都有贡献。内心独白对高层推理和底层定位都很关键。
  • 内心独白帮助解决更难的任务。他们对比了“自主规划”和“强制规划”（强制模型每一步都必须生成内心独白），强制规划能纠正约 20% 的定位错误。幻灯片左边给了两个有无内心独白的对比例子。
  • 跨平台收益：Aguvis 只在网页和手机轨迹上训练，没有专门在电脑使用场景上训练，但在桌面任务 OSWorld 上表现仍然不错。用 Aguvis-72B 做定位、GPT-4o 做规划，成绩比 Claude computer use 还好。

小结

他给的两条收获：Aguvis 是一个统一框架，只用视觉观测就能在不同平台上稳定工作；他认为纯视觉范式在电脑使用和 GUI 场景上优势很大，并说 OpenAI 做 Operator 的路线和他的看法一致。第二条是，尽管进步很多，定位和结构化推理都还要提升，不要只顾着提升推理，定位那一侧的提升空间更大。

幻灯片上没讲到的部分

幻灯片第 84 到 106 页是“长视频遇上多模态智能体”，录像里没有讲。按幻灯片标题，内容包括：xGen-MM-Vid（BLIP-3-Video，用一个时间编码器把一段视频压成 32 到 128 个视觉 token，对比其他模型的 4608 个）作为“在线记忆”，以及 GenS（Generative Frame Sampler，基于 Aria 微调，按用户指令预测相关帧区间和置信分数，训练数据 GenS-Video-150K）作为“离线记忆”。最后的总结页把整讲归为环境（OSWorld）、数据（AgentTrek、TACO）、模型（Aguvis 的定位和推理，BLIP-3-Video 和 GenS 的记忆）。
