01. 聊天模型和智能体模型有什么不同

录像位置 0:00:00–0:06:53

两类模型

幻灯片上的定义：

  • 早期的聊天模型是“对齐人类的模型”，目标是让交互最大化人类偏好。早期用的技术是 RLHF（reinforcement learning from human feedback，基于人类反馈的强化学习），模型被训练得和人类偏好对齐得很好：跟你聊天，理解你在说什么，让你感觉更好。
  • 智能体模型是“对齐环境反馈的模型”，目标是在人类偏好之外，让交互最大化可验证的奖励（verifiable reward，可以由程序判断对错的奖励）。后来几乎所有前沿实验室和模型厂商都给模型加上了智能体能力。和这类模型对话，它要先理解你的意图（所以仍要最大化人类偏好），同时还要帮你完成任务。

评价任务完成质量时，通常不用一般的奖励模型，因为有些任务只有少数几个正确答案，也有明显错误、绝对不能给的答案。人类偏好的情况不一样。

聊天模型是怎么训的

他简单回顾：收集大量人和助手的对话；按人类偏好给助手的回答排序，可以众包请很多人来标；用这些偏好数据训练一个奖励模型（reward model），判断助手的某个回答好不好；有了高质量奖励模型，再训练语言模型去最大化人类偏好。算法有很多，他把 SFT（supervised fine-tuning，监督微调）也列进来。SFT 常被说成是严格模仿专家行为，但即使有了奖励模型，SFT 也用得很多：用奖励模型对助手生成的多个回答打分，只挑排名很高的，在这些回答上做 SFT，这就是拒绝采样（rejection sampling）。也可以用 PPO、GRPO 这类强化学习算法。目标是你和这个模型聊天时，觉得它很投入、很懂你。

还缺什么

幻灯片左右对比：

  • 对话不可验证，往往没有唯一正确答案，所以需要对偏好建模；对话只需要和用户交互。
  • 很多任务只有一个或少数几个正确答案，也有明显错误的答案；需要和很多实体（用户和环境）交互，才能理解完整的状态。

他说 LLM 的一个关键应用就是智能体任务。企业应用里，很多任务需要和人（有时是多个人、多个助手）以及其他实体深度交互，包括特定的代码仓库、特定的软件系统和很多工具。LLM 要理解这些实体给的反馈，理解环境的完整状态，执行任务时要给出正确答案，而且要有清楚的验证器判断对不对。错误答案会让整个系统崩掉。有人说可以用其他确定性系统去修补，但大家发现，如果 LLM 本身给出正确答案的能力不够强，即使在上面做很多软件工程，也很难做出可靠的系统。

所以今天的模型被训练成好的智能体。用户不再问“你好吗”去开启一段闲聊，而是有一个明确的目标，有时很模糊，但总有想完成的事：订机票，和服务系统打交道。评估输出的方式有很多：人写的评分细则（rubric）、写下来的标准答案、环境状态的完整记录、大量单元测试。拿到这些信号，再用 SFT、PPO、GRPO 等后训练算法改进模型。最终目标是一个强智能体模型，通过在沙盒里使用复杂工具来最大化正确性。

02. 训练可验证智能体的三步

录像位置 0:06:53–0:11:30

他说这是社区很多人在关注的问题，三步每一步今天都很难，需要业界和学术界很多人合作。

  1. 拿到好的可验证训练数据。没有高质量训练数据，就做不出高质量的智能体 LLM。
  2. 评测。收集了数据、定好训练方法、训完模型，还要弄清它到底好不好。他说有一种很危险的倾向：觉得收集的数据够全面了，只测和数据对得上的东西，看起来一切都很好，一放到真实环境里就开始坏。幻灯片的说法是：可验证智能体是智能的，所以要先定义什么是智能。
  3. 训练配方：怎样把可验证数据喂给模型。

什么叫可验证的智能体，他举了具体例子。一是解数学题：模型可以用 Python 等工具，写很多代码、理解问题，最后给出答案，比如答案是 2，要确认它精确地等于正确答案。二是软件工程：模型写出一段代码，可以用很多不同的单元测试检查，全部通过才算对。他说这其实很复杂，能建的验证器多种多样，社区现在的挑战是还没有足够强的验证器，覆盖不了智能的各种边角情况。

第三步也很复杂，很多人在拼命研究：有了好数据，也知道怎么评测，怎样喂数据才能让模型的智能真正提高？他说可以把构建可验证智能体想成培养一个人。在公司里带一位新工程师，你先给他一些指示，比如代码该怎么写、软件系统该怎么操作；他开始写代码、和系统交互、提工单，有时犯错，然后收到反馈。对人，你可以直接说“这是反馈，下次做好点”；对机器，最难的是把这种自然的人际互动变成算法能实现的东西：模型第一次尝试出错，我给了很详细的反馈，怎么保证下次它做同一道题时质量真的提高？做不到，就复制不了人类学习的这个反馈回路，系统的智能就会碰到天花板。

03. 训练数据：环境、工具、验证器

录像位置 0:11:30–0:21:43

三个组成部分

他说这三者在有些文献里被合在一起，但他认为它们不同，要分开看：

  1. 环境（environment）：模型被训练去读入告诉它环境当前状态和用户意图的 token。环境可以是代码仓库、网页浏览器等。以编程智能体为例，它接收你的指令，在一个组织好的代码仓库里生成代码，仓库里可能有 bug 要修。环境编码了整个仓库的状态，比如代码文件的前后文、已加载的大量文件、要处理的下游任务，也包括人们为让各部分协同工作而预先设好的系统提示。
  2. 工具（tools）：模型被训练去生成供软件工具使用的 token，这些工具给模型提供额外的相关信息，帮它从验证器那里拿到更高的奖励。用软件工程的话说，就是给系统额外的 API。比如用户问今天天气，LLM 不该知道，但它知道自己能调用某个天气 API，就要生成精确的 API 调用，外部系统返回具体信息，LLM 消化后把最终答案给用户。工具可以提供信息，也可以改变环境状态：工作环境的状态很复杂，为完成任务可能要改某些状态，用户自己可能都不知道。强智能体要能分解任务，找出该调用哪些工具，必要时改变环境状态，最后给出答案。
  3. 验证器（verifier）：模型被训练去生成能让验证器给出最高奖励的 token。验证器告诉你任务是否真的成功，例如代码的单元测试、证明的数学检查器、网页任务的 DOM 脚本（检查浏览器里的任务是否真的完成）。他说这里也有很多微妙之处：你给出了正确答案，但用了太多步、太多 token，也许该扣分。所以最好别把验证器看成只判断对错的一个数，而是一个向量，从多个角度评价模型。

多样性和覆盖面

幻灯片上的原则：要训练模型理解很多不同环境、使用很多不同工具、在很多不同验证器下都做得好，环境和验证器的多样性至关重要。他说这也是整个社区过去两年学到的教训：只在很少的环境、很有限的验证下工作时，别被骗以为系统很好，一超出数据的范围系统就会坏。关键挑战是覆盖面够不够。

幻灯片列了很多组合：

  • 环境：数学环境、浏览器环境、销售助手环境、编程环境；
  • 工具：软件 API 工具（天气、新闻等），数据库工具（search_database、update_database、run_sql），浏览工具（search_google 等），编程工具（run_python 等）；
  • 验证器：Math-Verify、证明检查器、单元测试、真实状态验证器（ground truth state verifier）。

他举例说，现在用 ChatGPT 问数学题，它有时会调用 Python 写个脚本验证答案。又如企业软件里的销售助手：销售人员可能要问天气、看新闻，还要访问系统里的数据库，了解客户是谁、和客户进展到哪一步，这就要写出精确的查询语句，并能消化数据库的输出。

验证器质量

他特别强调验证器质量，说这是目前开源社区很欠缺的东西。很容易想到一条规则来验证某个答案，就把它当成一个验证器。但社区里反复出现的情况是：每次以为建好了高质量验证器，后来都发现漏掉了一些边角情况。他举了一个已经被社区讨论过的基础例子：

  • “我买一杯 50 美分的饮料，给了 1 美元，能找回多少？”答案写成 1/2、2/4 等都对，验证器应该全部判对。
  • 同样的问题加一句“请给出最简形式”，那只有 1/2 对，2/4 不对。

他说构建验证器时这类错误很容易犯，而且代价很高：现在的模型已经很强，简单问题都能答对，只在难题上偶尔出错；如果这时验证器也错了，没捕捉到问题里的细微要求，就没法再提升模型。幻灯片写着“验证器质量很重要，对难的提示尤其如此”，要尽量少的假阳性和假阴性。

假阳性和假阴性哪个更糟？他说按经验两种都要尽量压低。不同应用里两类错误的权重不同，但总能找到某种应用，其中一类错误会造成灾难性后果，而且你想尽量少做事后修补模型输出的软件工程。

04. 评测：对智能体的五个期望和整体评测

录像位置 0:21:43–0:31:42

为什么评测要单独做

评测数据和训练数据相关，但他们会从不同角度看，甚至专门处理训练时没关注的方面。原因是希望训练能泛化：不可能收集到世界上所有数据，人和互联网、浏览器交互，做数学证明，工程师写代码，产生的数据基本无穷无尽。所以要建一条好的流水线，在训练数据有了扎实覆盖之后，模型能泛化到没见过的环境。评测要捕捉的就是这一点。幻灯片的标题是：先要知道“能用”是什么意思，才知道什么方法能用。

五个期望

  1. 能用很多不同的工具。只会用少数工具，给它一个新工具或者用户改了工具，系统就坏了，这不能接受。
  2. 能用于很多不同的用例。用户今天可能想出一个新用例，系统也不能坏。在系统一上能用，换到 API 稍有不同的系统二上也要继续能用。
  3. 能在模糊的指令下工作。他说这一点在人机交互里一再被提出。早期设计智能体评测时，用户总有很清楚的目标，说“请做这个”，LLM 表现得很聪明，能分解问题、执行任务、正确调用 API。但后来大家发现，真实环境里人们和智能体交互时，常常根本不知道自己想做什么，随便问问题，希望智能体告诉他们该怎么做。这需要很聪明的系统：既要通过主动和人对话理解人的意图，又要产出格式很精确的输出，才能和格式死板的软件系统交互。
  4. 能在很多不同的软件系统下工作。比如你给 Cursor 做的系统效果很好，换到另一个系统就完全坏掉，这不理想，还会让人怀疑模型的智能，可能它不够聪明，理解不了这些变化。
  5. 稳健。和人、和软件系统交互时有太多事可能出错：人可能不清楚自己要什么，软件系统也会出问题。你希望模型像一个很聪明的人，像能排查日常各种问题的优秀工程师那样行事。

幻灯片强调这些都需要定量追踪。

现有的基准和 harness

幻灯片把现有评测和上面五点对应起来：

  • 现成基准（对应 1、2）：智能体编程有 SWE-bench、TerminalBench、Aider；工具调用有 TauBench、BFCL（也出自 Berkeley）、ComplexFuncBench；知识类有 HLE（Humanity's Last Exam）、BrowseComp 等。
  • 智能体 harness（对应 4）。harness 指包在模型外面、给它提供工具和交互方式的那层框架。SWE-bench 可以在 OpenHands、MiniSWE（只有 bash）、OpenSWE、Aider-SWEBench 下跑；HLE 可以带搜索 harness 跑，也可以不带搜索。
  • 针对性的“单元测试”式评测（对应 3、5）：结构化输出遵循（StructEval 等），带条件指令的指令遵循（IFBench 等），长轨迹（NexusBench 等）。

他说过去几年社区做出了一些很重要的基准，越来越难，进展也很大，一些过去被认为很难的任务现在模型已经能解，带来了很大的生产力提升。SWE-bench 要求解决很复杂的 GitHub issue，往往要用很多工具。他特别强调 harness：同一个复杂的 GitHub issue，在一个环境里可能有个叫“打开文件”的函数，直接调用即可；在另一个环境里没有这个函数，要用别的命令行工具完成同样的事。所以检验解 SWE-bench 的能力时，不该只用一种 harness，要试很多种：给你这套工具、那套工具、格式稍有不同的工具，是否在所有情况下都能解出来。能做到，说明智能已经到了某个门槛。TauBench、BFCL、ComplexFuncBench 覆盖了很多工具和应用场景，避免过拟合某个特定应用。

结构化输出遵循是社区很早就关注的：很多时候要模型输出 JSON，就希望它是完全正确的 JSON，不需要我事后写复杂的代码去纠正 LLM 的错误。过去有很多尝试，想用软件工程工具减轻 LLM 的负担，但大家最后发现，如果 LLM 本身不够聪明，产不出高质量的 JSON 或结构化输出，事后基本没人能修好，因为很多问题涉及对系统很细致的理解，需要很高的智能，没法用简单规则修复。

整体评测

幻灯片上的“整体测量”：Humanity's Last Exam（一般科学知识）、AIME（数学）、STEMQA、SWE-bench（编程），配上 Google 搜索 harness、Python 代码解释器、OpenHands harness 或不带工具。原则是测很多任务，在不同 harness 下测，保持对智能的定义是整体的。他说这很重要，因为我们想用这些系统提高生产力，而科学家、工程师、研究者在实际中面对的系统太复杂了，系统要足够聪明才帮得上忙。

好的评测要考虑：

  1. 很多任务和验证器；
  2. 让智能体在基准的沙盒里以很多不同方式探索，看换 harness 时准确率怎么变。如果有时掉得很厉害，可能说明训练里有什么做错了，要想办法修；
  3. 每个任务里有很多工具，让智能体学会在不同动作空间里用工具。理想情况下始终是同一个模型，由它自己判断该怎么做。

幻灯片上的结论：选一套基准，就是在定义什么是智能，必须确保它是整体的、好的测量。他说评测需要整个社区的帮助，只有一起做，才能看清现有智能体系统的局限并取得进展。

05. 怎样衡量基准本身的质量

录像位置 0:31:42–0:38:27

假设你已经有了很多评测，数学、代码、换 harness，看到了不错的数字。你确定没有过拟合这些基准吗？可能在迭代后训练的过程中，你收集的某些数据和评测数据很像；或者整个社区里某些模型已经被污染，某些评测已经失效。在 SWE-bench 上看到高分，你确定模型真的强吗？他说社区里有一项很重要的工作，就是持续检查评测本身的质量。幻灯片列了三个维度：

  • 难度（hardness）：早期 LLM 不够聪明时，有些基准所有模型分数都很低；现在比如 GSM8K，人人都考得很高。你说在上面提高了 5 个点，不清楚是不是真进步，可能你用的基座模型早就见过和 GSM8K 很像的数据。要持续监控难度。
  • 区分度（separability）：同一个问题问很多个 LLM，理想情况下强的答得好，弱的答得差，这时我们说基准能区分模型能力。如果强弱模型分数差不多，也许应该放弃这个基准，因为训练或别的评测环节一定出了什么问题，损害了它的可信度。
  • 多样性（diversity）：要有好的覆盖。如果一个数据集只有 50 个彼此很像的提示，高分说明不了系统真的好。

他接着回答了一个关于私有基准的问题（见“问答”）。他说理想的情况是有多得多的基准被提出来。私有基准好，但如果是静态的，大家反复去拟合，还是会失去可信度。公开基准方面，如果社区能在各种环境里持续产出越来越多的基准，就很难有人全部过拟合。有一种说法：世界上只有五个基准，你可以把它们都“刷榜”（benchmax），声称在这五个上最好，但在别的基准上可能不行；如果社区一起做出十亿个基准，覆盖现实中我们做的一切（数学、编程、computer use，等等），有人说自己把这十亿个都过拟合了，那也许已经实现 AGI 了，因为在乎的东西都覆盖到了。

所以基准建设是很强的社区工作，只有越来越多人做出覆盖自己用例的高质量基准才能成功。他个人觉得这是学术界能做出很大贡献的地方，因为很多人在做很多不同的课题，能发现现有智能体训练里缺的东西。

06. “训练”一个智能体是什么意思

录像位置 0:38:27–0:42:29

他说训练很复杂，新算法每天都在出，他要讲的是原则：让智能体在你的环境里尝试不同的动作，看哪种最能到达最终答案；哪种结果最好，就让模型强化并重复它。

幻灯片上的图：给智能体一个任务，它进行 5 次尝试，每次在环境里调用不同的工具（工具 1、2、3），获取不同信息，做出最终决定，然后验证器判断每次对不对、花了多少成本：

尝试结果成本
1正确2
2正确1
3错误10
4错误1
5错误5

即使还没说怎么训，目标已经清楚：训练结束时，模型能生成正确的轨迹，最好成本也最低，最终评测里可能还有别的方面要考虑。整个训练过程中他强调两个特点：

  1. 每次尝试要彼此很不一样。你希望模型强化或抑制很多种不同风格的尝试，这样泛化最好。他拿教小孩举例：如果孩子能想出几种差别很大的方法，有的对有的错，给出详细反馈后，他学得很快；如果他只能想出一个答案而且是错的，告诉他错了，也给了一些信息，但对训练算法来说更难起作用，至少对很多算法而言，信息量不够。
  2. 但每次尝试都要花算力去采样和处理。让 LLM 试一下，完全错；试 100 次，全都完全错，那就不好，每次都花很多钱和资源。不要那种连一点正确可能都没有的“傻”尝试。

他说这是一个两难：题太简单，所有尝试都对，模型什么都学不到；尝试很多次全失败，花了很多钱和资源，还得花大量时间想怎么让它学会。社区至今还在找处理这个问题的正确方法，把它和人类学习过程联系起来，会引出很多有意思的问题。他说接下来介绍的是社区现有的做法，不一定是最好的；从机器学习理论的角度看，有些做法甚至不太对。训练 LLM 的一个大问题是理论基础往往和现有实践接不上，需要整个社区一起提出更好的表述。

07. 先模仿再探索：SFT 和 RL 两个阶段

录像位置 0:42:29–0:49:06

幻灯片：训练智能体就是最大化模型用工具达到正确性的能力，先训练模仿，再训练探索。

第一阶段：SFT，模仿

SFT 是模仿学习（imitation learning）：模仿那些达到正确结果的示范轨迹，目标是尽量减少傻的、没有意义的尝试。一开始 LLM 什么都不会，给它任务，它输出一堆垃圾，就是前面说的花钱又没进展的傻尝试。为了让系统启动，你会准备示范轨迹：针对某个查询，以人的身份展示正确的一串动作，比如访问这个数据库、调另一个 API、和另一个系统对话，把整条轨迹给它看，让它下次遇到同样的问题时复现出来。

第二阶段：RL，探索

模型进入“有时还会错，但不是全错，有时相当接近”的阶段后，就让它自己探索，因为自己探索得越多，学得越好。他用上学类比：如果教授只给出精确答案让你抄，不让交作业给教授批改，也没有反馈，那么每个人犯错的方式不同，我有某种特定的错误，想知道自己错了，却没人告诉我，来了新题，我不知道自己容易犯哪类错。所以真正的学习方式，是让模型探索，强化达到正确的轨迹，抑制没达到的。还要让模型产生很多样的轨迹：如果你会错，我希望看到你错，然后告诉你错了；如果所有答案都对但都一样，就学不到多少。要强化当前模型多样的好尝试，抑制多样的坏尝试，两边都要多样，因为多样性加速学习。

为什么两个阶段都要

他说这和人的学习对得很好，很直观。幻灯片上的流程：

  • SFT 阶段：最大化采样到示范轨迹的似然，最小化采样到其他东西（比如傻尝试）的似然。SFT 只是为了在 RL 时能用可承受的算力采样到有意义的轨迹。两点要求：示范样本要多样；SFT 要轻。
  • Rollout 阶段：为任务、环境和工具采样有意义但差别很大的动作。这里算力有限，要尽量多样，同时尽量有意义。
  • 奖励和优势计算阶段：判断每个动作序列有多正确，某些动作有多罕见、多有用。
  • 反向传播阶段：强化好的动作，抑制坏的动作，让下次生成更多正确答案、更少错误答案。他说这一步看来最难。

示范要多样：如果给的 SFT 样本很少、风格很像，模型到了 RL 阶段可能生成不出多样的尝试，这很糟。SFT 要轻：如果做了很重的 SFT，等于对训练集里每个问题都告诉模型“这是唯一正确答案，记住它”，模型就会失去自己想答案的能力。而训练数据再大，也覆盖不了我们和人交互的方方面面，只教它严格照着示范答，遇到分布外的任务一般会失败。

最难的是更新这一步，他又用上课类比：教授布置任务，大家交作业，最难的是确保下一次来新任务、大家再交作业时，答案真的变好了。人在这点上差别很大，同样的反馈，面对新任务时每个人给出的答案不同；算法也一样，给不同 RL 算法同样多的数据，最后系统质量不同。幻灯片的总结：SFT 只是用来抑制无意义和低质量的尝试，RL 才真正强化智能。

08. 算法还没收敛，以及 RL 的三根支柱

录像位置 0:49:06–0:56:56

理论和实践的缺口

在回答一个关于去掉 SFT 阶段的问题时（见“问答”），他回到训练算法的核心问题：今天并不清楚什么才是正确的训练算法。熟悉机器学习理论的人知道，现在 SFT 和 RL 组合的算法表述和理论并不吻合；如果从理论出发，在简化模型上研究，你不会这么做，会做别的，而在简化模型上别的方法会好得多。他说这是个大问题，所以在架构、算法、更好地利用预训练和后训练数据上做更多探索很关键：最好能在可实现的前提下更靠近理论原则。他鼓励大家深入研究，认为算法还远没收敛；后面讲的算法问题，他绝不是说那些就是对的方法，或者十年后还会对，只是想展示人们跑这些算法时观察到的现象，希望能激发大家设计更好的算法。

他还说，把人类学习的一切和 LLM 学习结合起来会很有意思，这一讲就在尝试这么做。我们对人怎么学得更好有一些直觉，但很多人自己都不知道是怎么学会的：做了点什么，得到反馈，下次做了别的。而这里我们得写出算法，这最难，我们并不知道该怎么写。人类学习里要学的东西太多，评价一个人的方式也太多，就像学生要考各门课，所有考试真的公平、真的在以正确方式培养学生吗？他说这个领域绝对还在婴儿期，还没弄清训练和部署这些系统的正确方式，但已经有一些有意思的观察。

三根支柱

幻灯片：好的 RL 算法的核心是三根支柱。

  • 训得更久：核心是保持熵的平衡，控制模型输出长度的增长。不希望出现这种情况：拿到数据集，模型试一两次后就不再“尝试”了，每次都给出完全一样的答案，饱和了。人能不断获得反馈，提出方案，得到反馈，下次提出更好的方案，最后也许能做出很了不起的东西，比如做前沿研究、发明广义相对论。门槛很高，但很快就进入平台期肯定不好。
  • 在更难的提示和任务上训：核心是用和当前任务相关、而当前模型成功率低（但不是零）的任务和提示来训。只给人很简单、早就会做的任务，学不到新东西；只给 LLM 极难的任务，比如证明黎曼猜想，谁都解不了，也没有进展。把人类学习的直觉转化为 LLM 学习，是一个很大的正在进行的研究课题。
  • 在更多样的回答上训，配高质量的奖励反馈：核心是每个提示看到尽量多不同的、有意义的回答。他类比：只学一门课的人，没法回答其他课考试里的问题。

09. 训得更久：熵坍塌和三种干预

录像位置 0:56:56–1:04:59

熵坍塌

社区里有很多关于熵机制（entropy mechanism）或熵坍塌（entropy collapse）的观察，也有很多相关的指标捕捉类似的东西。他用的是 The Entropy Mechanism of Reinforcement Learning for Reasoning Language Models（arXiv 2505.22617）里的图：横轴是训练步数，纵轴两条曲线，一条是性能提升，一条是剩下的熵。

这里的熵指 LLM 生成下一个 token 时，那个概率分布的熵。作为背景，词表上分布 $p$ 的熵是 $H(p) = -\sum_{v} p(v)\log p(v)$。熵大，采样下一个 token 的不确定性高，同一个提示采样两次很可能得到两条差别很大的轨迹；熵很低，比如模型每次都以 99% 的概率确定下一个 token，采样多少次都只能得到同一条轨迹，因为只有一条轨迹概率极高。

图显示，如果不干预，很多算法随着步数增加，奖励确实上升，模型开始产出高质量答案，但熵也在下降，最后模型只学会给出一种答案。问题是：能不能既产出高质量答案，又不出现熵坍塌？答案都对，但仍然多样，能继续探索，理想情况下每个问题都能想出五个不同的正确答案。他说这很难，对很难的任务，人也很难想出五个不同的正确答案。幻灯片上的问题是：什么干预能在熵和奖励曲线之间取得更好的权衡，权衡得不那么激进，从而训得更久？

干预一：减少有偏更新，别做 off-policy

引的是 On-Policy RL with Optimal Reward Baseline（arXiv 2505.23585）。on-policy 指让奖励模型或验证器评判的，只是 LLM 自己当前产生的尝试，不根据别人或别的权重产生的答案来给奖励；off-policy 则相反。他用学生类比：答案是学生自己写的，教授给详细反馈，学生学得最多；学生抄来的答案，你给反馈，学生也能学，但学得没那么好。

图上，随着训练步数增加，on-policy 和 off-policy 的训练奖励以相似的方式上升，都在变好；但 on-policy 训练出的策略和初始策略之间的 KL 散度更小，熵也保持得更高。幻灯片标注为“更好的熵控制，更好的泛化”。在 MATH500、AIME 24、AIME 25 等基准上，on-policy 一般得到好得多的结果。

干预二：平衡更新强度，正确地裁剪

出自 DAPO 论文（arXiv 2503.14476），DAPO 是 GRPO 的一个变体。他说这里很技术化，不多讲。背景补充：GRPO 和 PPO 一样用一个似然比

$$r_t(\theta) = \frac{\pi_\theta(o_t \mid q, o_{<t})}{\pi_{\theta_\text{old}}(o_t \mid q, o_{<t})}$$

它应该在 1 附近波动。为了训练稳定，要对它裁剪：低于 $1-\varepsilon_\text{low}$ 截在下界，高于 $1+\varepsilon_\text{high}$ 截在上界。PPO 也有这种裁剪，原来上下用同一个 $\varepsilon$。DAPO 的一个重要观察是要把两个 $\varepsilon$ 解耦，让 $\varepsilon_\text{high}$ 比 $\varepsilon_\text{low}$ 更大（这个做法叫 Clip-Higher）。幻灯片的说法是：$\varepsilon_\text{high}$ 给低概率 token 的概率上升留出更多空间，也就是鼓励模型提高原本低概率 token 的概率，好好探索。图上用了 Clip-Higher 的紫色曲线，性能更高，生成熵也保持较高，没有坍塌。

他说讲到这里大家可能看出来了，整个系统里有很多 hack，所以他再次强调这些 hack 未必代表最终的最佳做法，尤其多年以后，但希望 hack 背后的洞见能传达出来。解耦裁剪阈值确实让一些人觉得是 hack，但效果相当好。

干预三：直接鼓励熵，加一个损失

既然训久了模型只会给一种答案，自然也可以加一个损失函数，把熵维持在某个水平。构造这个损失有很多技巧，比如设一个目标熵水平，让损失把生成熵引向这个水平，还有很多探索空间。他引的是 Skywork Open Reasoner 1（arXiv 2505.22312）：用一个特定的熵损失，在训练中鼓励熵增加，让熵不坍塌，图上测试准确率也更高。

10. 在更难、更合适的题上训练

录像位置 1:04:59–1:12:18

幻灯片：目标是在更相关、难度有意义的提示和任务上训练。不能直接把难题扔进去指望它奏效，要确保更难的提示仍能提升模型，办法是确保模型的置信度和奖励有意义地相关。

置信度和优势的协方差

还是 Entropy Mechanism 那篇论文，以及社区里很多论文，在想怎样区分模型在难题和简单题上的表现。他们追踪的量是整条序列的对数概率和强化学习里所用优势之间的协方差，大致是

$$\mathrm{Cov}\big(\log \pi_\theta(y \mid x),\ A(y, x)\big)$$

（幻灯片上写的代理量是 Cov(pi_theta(y|x) * A(y,x), log_pi_theta(y|x))，这里按他口头的解释写成上式。）不看细节，它衡量的是模型生成高质量答案时的置信度和最终表现是否对齐。理想情况是模型生成正确答案时很有信心，生成错误答案时很不确定，这样下次提示时更可能生成正确答案。

右边的图把训练数据按准确率分成子集，分别画训练曲线。准确率很低的子集（紫色曲线，准确率 0.1125）上，这个协方差一直很低，说明模型没法有信心地生成正确答案；对很简单的题，协方差一般更高。他说这也是一个要追踪的重要指标。

训练集的难度怎么配

左边的图是关于怎样构造训练集的有意思观察：在几个不同的训练集上训练，在同一个验证集上看验证准确率。训练集包括 DAPO 的数学数据、GSM8K、Eurus 的 RL 数据和其中更难的子集（字幕作 double mass、yours data、yours difficult，按发音和这篇论文推断）。幻灯片注明验证集用了 MATH500、AIME 24、AMC24、OlympiadBench 和 OMNI-MATH。

  • 不同数据点对应不同的熵，总体趋势是熵越高，最终表现越好，这是好的趋势。
  • 只在 GSM8K 上训练，最终验证准确率很低，因为 GSM8K 太简单，在太简单的数据上训，不该指望模型在很难的任务上表现好。
  • 更有意思的是：只用难题子集训练的曲线，反而低于用完整 RL 数据训练的曲线，而完整数据里既有难题也有不那么难的题。这说明现在的学习范式下，盲目扔进超难的提示，“希望你能学会，我给你很好的反馈”，可惜 LLM 本身或现有算法都不够聪明，学不会。要把不同类型的数据很好地组合起来。

幻灯片的话：不能在太简单的题上训，也不能盲目扔进超难的题。

改进学习信号：GRPO-LEAD

他介绍了 GRPO-LEAD 论文（arXiv 2504.09696，字幕作 GRP lead）里的一种做法，很直观，但也有人觉得是 hack。几个直觉：

  • 简单的提示答对了，也许不该给那么多奖励，因为你本应早就掌握了；幻灯片标题是“难题答对多奖励”；
  • 题答对了，但答案太长，也要扣分，题不难，本该给简单的答案；
  • 答错了，给负反馈。

论文显示，按难度或按优势调整不同样本的权重，性能会提升；显式惩罚很长的生成等做法，质量也会变好。他说这能引出很多有意思的想法，但这个问题显然还是开放的，社区并没有找到最终的解法。

11. 采样得更好：GenSelect 和 DeepConf

录像位置 1:12:18–1:15:29

最后一根支柱是采样：采样得更好，才能在更多样、奖励质量更高的回答上训练。回到最初的直觉，如果采样不出大量多样且高质量的答案，就会有麻烦。幻灯片写着要扩大算力来保证拿到好的回答，分两类：扩大每个答案的算力（并行推理），以及在推理过程上做束搜索。

GenSelect：并行推理再选一个

并行推理（parallel reasoning）的想法可以很简单，变体很多，他讲的是 GenSelect（arXiv 2507.17797）。不让 LLM 直接给答案，而是先让它产出比如 32 个不同的答案，再给一个提示，让它从这 32 个里选一个。图上最终准确率好得多，因为模型有更多时间去找正确答案，能挑出更好的那个。幻灯片的说法是“把所有采样答案丢进去，挑最好的一个”。

DeepConf：只让有信心的轨迹投票

DeepConf（arXiv 2508.15260）是改进多数投票（majority voting）的。没有复杂采样方法时，同一个提示采样 32 次，得到 32 个答案，做多数投票。问题是 32 条轨迹里有些质量很低，如果能在很早就知道，就不该让它们参加最后的投票，只让可能成为正确答案一部分的轨迹参加。DeepConf 追踪每条轨迹的生成置信度，置信度很低的轨迹，说明模型自己都不确定在做什么，就不纳入多数投票，或者给很低的权重。幻灯片：只对置信度高于阈值的采样答案做多数投票。结果上，同样用 GPT-OSS-120B，DeepConf 比普通多数投票（consensus）更好，因为确实丢掉了一部分坏输出。

接下来社区该做什么

  1. 建一个集合，整理环境和验证器，用来扩大智能。从个人贡献者、公司、研究者那里众包环境、评测和配方，把多样、高质量的信号集中在一处，用来扩大 RL 的规模。
  2. 找出“智能”的最佳定义：分析各个基准的优缺点，把它们放进这个集合，让每个人在扩大 RL 时都能用，确保对智能的测量是整体的。
  3. 发布能训得更久、在更难的提示上训、产生多样回答的算法：稳定、有意义、回答多样，也放进集合，让大家能在所有整理好的环境上用。

开放问题

他说这一讲分享了一些观察，真正希望的是激发大家对这个领域的兴趣，这个领域还很不成熟，很多事没弄清楚。总的视角是弥合人类学习和系统学习之间的差距：人在很多不同环境里活动，对某些课比别的更用心，既靠自己探索也跟老师学，还经常在各种任务上被评估智能。怎样让模型做到这些？幻灯片列了四个问题：

  1. 人从很多环境里学习，模型也应如此。开源环境、评测和算法的集合，正确的设计是什么？
  2. 人会对某些课更用心，模型也应如此。什么算法能做到这点又不损害稳定性？
  3. 人既从自己的探索中学，也跟老师学，模型也应如此。正确的平衡是什么？能不能同时做？
  4. 人的智能会被评估，模型也应如此。怎样比较不同的智能定义？

他最后欢迎学术界加入，一起做出最强的智能体智能。

问答

提问的声音没有录进来，以下按他的复述整理。

公开基准的数据都是公开的，有没有人做私有基准来追踪进展？（0:35:40）

他说当然有，很多个人、社区成员和公司都想做私有基准来检验进展。但他认为大家更想看到的是多得多的基准被提出来：私有基准好，但静态的基准被反复拟合，仍会失去可信度；如果社区能持续在各种环境里产出更多基准，就很难有人把所有基准都过拟合。后面接着讲了五个基准与十亿个基准的说法（见第 05 节）。

NVIDIA 有工作说某些情况下可以去掉 SFT 阶段、多做 RL，怎么看？（0:48:36）

他说有一些工作，其中也有 NVIDIA 的，讨论在某些情况下去掉 SFT 阶段、做更多 RL，顺便说这也是很多前沿实验室展示出的趋势：在 RL 上消耗更多算力。他由此回到核心问题：今天并不清楚正确的训练算法是什么，SFT 加 RL 的表述和机器学习理论对不上（详见第 08 节）。

如果模型其实只是在做模式匹配，怎样训练它做批判性思考、发明新东西？（0:51:45）

（问题按他的复述推断：有人认为模型可以看成是在做模式匹配，而我们希望它能批判性思考、能发明新东西。）他说首先，很难弄清 LLM 到底在做什么。想想人怎么学：很多时候解考试题、上课，我们也在做模式匹配，教授讲一道题和答案，下一道题很像，我们也在做很相似的事。所以他个人觉得，把人类学习的一切和 LLM 学习结合起来会很有意思，这也是这一讲想展示的（后续见第 08 节）。
