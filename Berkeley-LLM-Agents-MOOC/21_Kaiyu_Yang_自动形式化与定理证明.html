这一讲讲什么

Kaiyu Yang 是 Meta FAIR 的研究科学家，讲题在幻灯片上是“Formal Reasoning Meets LLMs: Towards AI for Mathematics and Verification”（形式化推理遇上 LLM：面向数学和验证的 AI）。他是 LeanDojo 的作者，也是立场论文《Formal Mathematical Reasoning: A New Frontier in AI》的作者之一。他提到自己在上一讲（Thomas Hubert 讲 AlphaProof）时也在 Zoom 上听课。

这一讲的主线是：现在训练数学 LLM 的办法（SFT 加可验证奖励的 RL）依赖大量数据和可验证性，所以只在大学前的数学和有数字答案的题上有效；要做高等数学和证明，需要加入形式化推理。然后他讲两类任务：定理证明（给出 Lean 里的命题，让模型生成证明）和自动形式化（把教科书里的自然语言数学翻译成 Lean）。两类任务各用一个具体领域（奥数不等式、欧氏几何）来说明：一般情况下难以处理的问题，限定到特定领域后可以变得可处理。录像在他说“欢迎提问”时结束，后面的问答没有录进来；讲课中间有一个同学的提问，记在“问答”一节。

01. 数学和编程为什么是 AI 竞赛的中心

录像位置 0:00:00–0:04:08

大模型军备竞赛里的数学和编程

他说现在是大语言模型的军备竞赛，各家领先公司每隔几个月就发一个新模型，竞赛的中心是数学和编程。OpenAI 发布 o1 时的图表突出的是数学竞赛 AIME 和编程竞赛 Codeforces；Google 发布 Gemini、xAI 发布 Grok 时也都突出数学和编程能力。

几个时间点：

  • 2023 年 11 月，英国对冲基金 XTX Markets 设立 AIMO 奖，奖金 1000 万美元，奖给能拿 IMO 金牌的 AI。
  • 2024 年 7 月，Google DeepMind 宣布 AlphaProof 和 AlphaGeometry 达到银牌水平，他说这是上一讲的内容。
  • 想超出高中竞赛数学，Epoch AI 推出了 FrontierMath 基准，收录专业数学家出的研究级数学题。不久之后 OpenAI 宣布 o3 能解出其中 20% 以上。这很出人意料，因为 FrontierMath 刚发布时，大家以为语言模型要好几年才能有实质进展，结果不到一年就有了突破性结果。

为什么大家关注数学和编程

  • 它们是复杂推理和规划的代理任务。推理和规划对人类智能很重要，也是当前语言模型的主要挑战之一。让模型会推理、会规划，就能解锁无数应用，比如旅行规划、让智能体帮你安排日历邀请。
  • 它们相对容易评估。数学题可以核对答案，代码可以跑单元测试。如果让模型写一部犯罪小说或者作一首交响曲，就难评估得多。他说犯罪小说也需要推理，作交响曲肯定需要规划，只是没那么好评估。

他特意说的是“相对”容易，因为他们并不认为核对答案或跑单元测试是完美的评估，只是合理的评估，后面会再回到这一点。

02. 数学 LLM 怎么训练：SFT 和 RL

录像位置 0:04:08–0:10:22

他接着简要介绍训练语言模型解数学题的主要技术，说这里讲数学，但大部分也适用于编程，后面会看到两者联系很深。最先进的数学 LLM 主要用两种技术训练：监督微调（SFT）和强化学习（RL）。他只讲高层思路，强调对数据和可验证性的依赖。幻灯片上的两句口号是：SFT，“Good data is all you need!”；RL，“Verifiability is all you need!”

监督微调

幻灯片上是一条流水线：

  1. 起点是在互联网规模文本和代码上预训练的通用语言模型。
  2. 继续用数学相关的网页文档训练，比如数学论坛（他举了 Math Overflow 和 Stack Overflow 这类网站）、arXiv 论文，得到“基础数学 LLM”。它见过大量数学，但还不会解题。
  3. 再用大量带分步解答的题目微调，得到“微调后的数学 LLM”。
  4. 可选地，在解答里使用外部工具，比如 Python，得到“工具集成的数学 LLM”，模型不只生成自然语言推理，也能调用工具。

幻灯片上的例题：两个复数 $x$、$y$ 的平方和是 7，立方和是 10，列出 $x+y$ 所有可能的值。工具集成的解答写道“用 sympy 计算并打印 $x+y$ 所有可能的值”，代码输出 [-5, -5, 1, 1, 4, 4]，去重后答案是 $\boxed{-5, 1, 4}$。

他说这条流水线里最重要的是数据集：继续预训练要从网上收集文档，进一步微调要标注大量带分步解答的题目。他认为收集数据集是整条流水线里最贵的部分之一，因为没法完全自动化，要靠人去标注、清洗、转换成可用的数据。幻灯片上写，目前最大的公开数据集规模约 90 万条（NuminaMath-1.5）。

只有最终答案时：用 RL

如果数据集只有最终答案、没有中间步骤呢？这是不想花大价钱请人标注、但能便宜地拿到只带最终答案的数据的情况。他说照样能用，办法是强化学习：只给题目和最终答案，训练模型生成解答。

流程是：把题目给语言模型，模型生成带中间步骤和最终答案的解答；把最终答案和标准答案对比，判断对错。比如一个解答给出 $\boxed{-5, 1, 4}$，是对的；另一个给出 $\boxed{-2, 6}$，是错的。验证结果当作奖励信号，正确为 1、错误为 0，再用 GRPO 这类算法优化模型以获得高奖励。（GRPO，Group Relative Policy Optimization，是一种强化学习算法：对同一道题采样一组解答，用组内奖励的相对高低来更新模型，不需要单独训练价值模型。）

他说这个方法很简单，也很强大。想法已经存在几十年了，但第一次证明它能用来训练推理语言模型的是 DeepSeek-R1，时间很近。这个思路势头很猛：就在一个月前，强化学习的两位先驱 Richard Sutton 和 Andrew Barto 获得了 ACM 图灵奖。

RL 的前提：可验证

强化学习的关键是可验证性：你必须能判断解答对不对，否则就没有奖励。如果题目有数字答案，总能和标准答案比较；但如果是定理证明题，要你生成一个证明，没有简单的办法判断证明对不对，还能做强化学习吗？他说后面会回到这个问题。

小结

按幻灯片：最先进的数学 LLM 约等于强预训练模型，加上这两种后训练技术，再加上出色的工程。他说算法很直接，几乎每家领先的工业实验室用的都是同样的算法，真正拉开差距的是谁的基础设施、工程和数据集更好。幻灯片写作“the devil is in the details”，例子是数据整理和清洗、训练和推理的基础设施。

03. 两个差距：高等数学和写证明

录像位置 0:10:22–0:14:59

有了这么强的配方，AI 会很快“解决数学”吗？他的回答是绝对不会，还有几个差距。

差距一：从大学前数学到高等数学

现有成功大多在大学前的数学上，比如 IMO、AIME。给语言模型更高等的数学题，它们还是吃力。他引用了 Terry Tao 的话：他试用 OpenAI o1，发现它在最高等的研究级数学任务上仍然吃力。他说这在意料之中，研究数学按定义就是新的，新的就没有多少数据可以训练。

o3 在 FrontierMath 上的结果是高等数学题，但有几点要注意：

  • Epoch AI 和 OpenAI 之间有资金关系，是后来才披露的。
  • 他认为更重要的一点是，FrontierMath 和真正的数学研究有区别。FrontierMath 的题被设计成有数字答案，题目很高深，但故意设计成有数字答案。这有点反直觉，因为高等数学里大多数问题没有数字答案；他们这样设计，是为了能评估模型。

幻灯片上的问题是：没有数字答案的题怎么解？

差距二：从猜答案到写证明

这就引出第二个差距：现在的模型很擅长猜答案，但怎样让它写证明？最近的研究发现，语言模型连很基础的证明都写不好。

  • Putnam 是面向本科生的数学竞赛。有人用 OpenAI 的推理模型做最近一届 Putnam，结论是“很不满意 ChatGPT 在最近的 Putnam 考试中的表现”，多数答案在 10 分里只值一两分，这是由人类数学家判分的。（幻灯片标注的来源是 Kevin Buzzard 2024 年的文章《Can AI do maths yet? Thoughts from a mathematician》。）
  • 另一篇论文（幻灯片：Petrov et al., “Proof or Bluff? Evaluating LLMs on 2025 USA Math Olympiad”）评估了语言模型在美国数学奥林匹克 USAMO 上写的证明，所有模型得分都在 5% 左右，很低。

他说这些模型犯的错，一经指出很容易看出来，但藏在长证明里就很难发现。例子是让模型证明一个简单的不等式：$a, b, c$ 满足某个条件，推出某个结论。模型在把一个已有的不等式两边乘以正数时，本应保持不等号方向，却把方向弄反了。指出来就是很简单的错误。

04. 缺的那一环：形式化推理和 Lean

录像位置 0:14:59–0:18:28

只靠 LLM 不够

他认为目前训练语言模型的方法不足以解决这些问题，因为它严重依赖数据和可验证性。幻灯片总结了两方面：

  • 数据稀缺：只适用于数据丰富的领域，比如大学前数学，处理不了高等数学和证明。
  • 缺少可验证性：解答只能靠和标准答案比较来评估，只适用于有数字答案的题，比如 GSM8K、MATH，不适用于高等数学的大多数问题。

他说高等数学里大多数问题都要证明，而在证明上没有可验证性。

形式化数学推理

他们最近在 arXiv 上发了一篇立场论文（Yang et al., “Formal Mathematical Reasoning: A New Frontier in AI”, 2024），认为缺少的重要一环是形式化推理：把数学推理建立在形式系统上。形式系统可以是一阶逻辑、高阶逻辑、依值类型论（dependent type theory），甚至是计算机程序及其语义、形式规范。

形式系统的作用是验证证明并给出自动反馈。这有两个用处：

  • 自动反馈可以缓解数据稀缺，模型从自动反馈中学，不需要收集那么多人造数据；
  • 可以做验证，从而严格地评估模型的推理。

所以他们认为，要往前走，必须把形式化推理和 LLM 的非形式推理结合起来。

Lean 简介

他简要介绍这一讲关注的形式系统 Lean，也就是 AlphaProof 用的那个。Lean 是证明助手（proof assistant，也叫交互式定理证明器），本身是一种编程语言，用来写形式化的数学和软件。

他举了一个 Lean 文件的例子：先定义自然数，一个自然数要么是 0，要么是另一个自然数的后继；再定义两个自然数的加法，就是一个递归函数；然后陈述并证明关于自然数和加法的定理，比如 $a + b = b + a$。用 Lean 写形式化数学，和用 Python 写软件很像。

文件里的证明有语义，对应一棵证明树。树根是要证的原定理，证明的每一步把当前目标分解成若干更简单的子目标，递归下去直到所有子目标都解决。幻灯片上的例子是证明 add 0 n = n：

-- goal
n : ℕ
⊢ add 0 n = n

-- tactic: induction n  ->  two subgoals
⊢ add 0 0 = 0                      -- closed by: rfl
n' : ℕ
ih : add 0 n' = n'
⊢ add 0 (n' + 1) = n' + 1          -- closed by: simp [add, ih]

这里每个节点由“局部上下文”（已知条件，比如 n : ℕ）和“目标”（⊢ 后面的部分）组成，节点之间的边是一个 tactic（策略，也就是证明的一步操作）。

文件再组成更大的单元，一个项目可以有很多文件，可以在 GitHub 上开源。比如你的项目定义了实数，别人的项目可以在你的实数定义上构建，形式化优化理论。他说这和开发软件很像。

AI 加 Lean 的一个成功例子就是 AlphaProof：用 Lean 生成大量定理和证明并验证，再做搜索和强化学习来训练模型。

05. 用 LLM 证明定理：LeanDojo 和 ReProver

录像位置 0:18:28–0:25:07

两个任务

  • 定理证明：输入是定理陈述，模型生成证明，两者都用 Lean 形式化写成。Lean 能检查证明对不对，所以模型没有幻觉的空间。
  • 自动形式化：输入是非形式数学，比如教科书内容，模型把它翻译成形式数学。（幻灯片引了 Wu et al., “Autoformalization with Large Language Models”, NeurIPS 2022。）

生成下一步

做定理证明最直接的办法是：把要证的东西给模型，让它生成证明的一步（tactic），或者整个证明。能生成下一步的话，就可以用搜索把一步步串成完整证明。所以核心问题是怎样生成下一步。

直接的办法是用人写的形式证明做监督学习，让模型学会生成下一步。这个思路由来已久：早期工作用经典机器学习算法，比如 k 近邻（幻灯片引 TacticToe 2018）；2019 年前后开始用深度神经网络（幻灯片引了 GamePad、HOList 和他本人 2019 年在 ICML 发表的工作）；再后来用大语言模型（幻灯片引 Polu and Sutskever 2020、HyperTree Proof Search 2022、PACT 2022 等）。他说直到用上大语言模型，性能才真正大幅提升，因为模型在预训练中学到了大量数学知识，可以用在定理证明上。

LeanDojo

他重点讲的是 LeanDojo（Yang et al., NeurIPS 2023）。论文提供了用于 Lean 定理证明的开源数据集、工具和模型。和之前的方法相比，区别有两点：

  • 完全开放。之前基于 LLM 的证明器都是私有的，在私有实验室里做，不公开数据集和模型。
  • 提出了一个生成下一步的新模型。

流程是：从人写的 Lean 代码里抽取数据，包括定理和证明、每个证明的步骤、证明中用到的引理（premise）以及这些引理的定义；用抽出来的数据集训练机器学习模型；训练好的模型和 Lean 交互，证明新定理。录像里他说抽出约 1 万个定理和证明（字幕如此），幻灯片上 LeanDojo Benchmark 的数字是 98,641 个定理和证明、217,639 个 tactic、129,162 个前提。

ReProver：检索增强的证明器

ReProver（Retrieval-Augmented Prover）的动机是：证明定理时几乎从不从零开始，总要用已有的引理。要用已有引理，模型得知道有哪些引理，并判断哪个有用。

  1. 输入是一个证明状态（要证的目标）和一个引理库。
  2. 检索：把状态和每条引理都编码成向量，计算状态和每条引理的相似度，取最相似的若干条。
  3. 生成：把检索到的引理和状态拼在一起，交给另一个语言模型生成下一步。

（从做法上看，这是把 RAG，即检索增强生成，用到了定理证明上。）他说模型很简单，真正重要的是数据集从哪来，而 LeanDojo 可以从 Mathlib 等 Lean 项目里抽取数据。

典型的神经定理证明器

幻灯片总结成两部分：

  • 证明搜索（左边的树）：从初始状态出发，模型生成多个可能的下一步，执行后得到新的证明状态，反复进行直到找到证明。这里可以用任何搜索算法，比如深度优先搜索或蒙特卡洛树搜索。图上的例子是对 add 0 n = n 尝试 induction n、cases n、exfalso 等，有的分支走不通。
  • tactic 生成（右边）：在证明树的每个节点，把当前状态（局部上下文加目标）交给语言模型，模型给出建议，可选地还会参考形式化数学库里的引理。

专家迭代

LeanDojo 之后出现了很多改进工作。一个是专家迭代（expert iteration）：证明器哪怕不太好，也拿它去尝试证明新定理，过程中得到一些新证明，加进训练集；训练集变好了，就训出更好的证明器，如此反复。他说实验显示多跑几轮通常会提升，直到饱和。

06. 无限的动作空间和奥数不等式证明器 LIPS

录像位置 0:25:07–0:33:15

两个局限

抽取人写的证明、训练模型生成下一步，是很好的一步，但有局限：

  • 还是数据。语言模型在训练数据多的领域效果好，但网上人写的形式证明比 Python 代码少得多，而新的数学研究本来就缺数据。
  • 定理证明这个任务本身。和 AI 已经成功的下围棋比，区别在于围棋是 19×19 的棋盘，可选的动作受棋盘大小限制，是有限的；数学里动作空间可以说是无限的，证明一个定理时你可以做的事有无穷多种。动作空间无限，只靠人造数据集很难均匀覆盖；就算用强化学习，也很难高效探索。

LIPS：先缩小动作空间

为了解决动作空间的问题，他们在一个很有限的领域里做了尝试：证明奥数里的不等式（Li et al., “Proving Olympiad Inequalities by Synergizing LLMs and Symbolic Reasoning”, ICLR 2025）。这类题是几个实数 $a, b, c$ 满足某个前提，要证明某个结论。选这个领域，是因为它的证明很有规律。人一般做两件事：

  • 套用已有的引理，比如 AM-GM 不等式（算术平均不小于几何平均）或柯西-施瓦茨不等式；
  • 把当前式子改写成另一种形式，让某个已有引理变得可用。

即使只有这两类动作，空间还是很大。幻灯片上的例子：$a, b, c$ 是正实数且 $a^2 + b^2 + c^2 = 1$，证明

$$\frac{1}{a^2+2} + \frac{1}{b^2+2} + \frac{1}{c^2+2} \le \frac{1}{6ab+c^2} + \frac{1}{6bc+a^2} + \frac{1}{6ca+b^2}$$

AM-GM 可以有不止一种用法，也可以用 Titu 不等式，还可以选择把式子改写成别的形式。幻灯片标注“一步之内就有 1 万种以上的可能选项”，分支因子极大，实际上是无限的。

先看 o1 怎么做

在动手之前，他们把很多不等式题交给 o1，人工检查它写的证明，发现大量错误。检查了 20 道题：

求解者20 道奥数级不等式证出的题数
o1-preview0/20
o3-mini3/20
DeepSeek-R14/20
人类金牌选手15/20（他说至少能证 15 道）
LIPS16/20

（幻灯片注明这些题来自 IMO 比赛、各国国家队选拔考试和训练小测。）

方法：缩放归符号工具，改写归 LLM

他们把证不等式的步骤分成两类：

  1. 缩放（scaling）：用一个已知引理（比如柯西-施瓦茨）替换当前不等式的一部分。例子是要证 $ab + bc + ca \le a^2 + b^2 + c^2$，发现左边的一部分可以套柯西-施瓦茨，得到右边那个式子。缩放的特点是可选项有限：引理只有有限多个，每个引理只有有限多种套法，所以可以把所有可能的缩放枚举出来。幻灯片上是把两变量的柯西-施瓦茨 $u_1v_1 + u_2v_2 \le \sqrt{u_1^2+u_2^2}\sqrt{v_1^2+v_2^2}$ 和当前式子做模式匹配，枚举 $u_1, u_2, v_1, v_2$ 的各种取法，再用符号工具剪枝。
  2. 改写（rewriting）：把当前式子变成等价的另一种形式（比如约分）。改写的空间是无限的，任何式子都有无数种改写方法。幻灯片上的例子是提示 LLM 按规则 $xy + yz = y(x+z)$ 改写，LLM 把 $ab + bc + ca \le a^2 + b^2 + c^2$ 改写成 $a(b-a) + b(c-b) + c(a-c) \le 0$。

他说关键的洞见是，做了这个分类之后，有限的缩放可以用符号算法全部枚举，无限的改写交给大语言模型。然后把符号算法和语言模型生成的下一步合起来，用一些启发式规则过滤（幻灯片上是先符号过滤、再让 LLM 排序），减少要证的目标数量，提高搜索效率。这个系统叫 LIPS（LLM-based Inequality Prover with Symbolic Reasoning）。

结果

LIPS 解出的题比 DeepSeek-R1 和 o3 多得多，在那 20 道题上证出 16 道，超过人类金牌选手的 15 道；在几个竞赛级数据集上也和现有方法做了比较，达到最好水平。

他展示了一个有意思的例子。题目来自 Evan Chen（美国 IMO 队教练）的讲义，Evan Chen 在讲义里说这道题“AM-GM alone is hopeless here”（单靠 AM-GM 在这里没希望）。LIPS 找到的证明只用了 AM-GM，加上巧妙的改写。他说这说明系统能找到人类不知道怎么找的证明。

收获和开放问题

定理证明的难点是怎样高效地探索一个可能无限的动作空间。这很难，但如果针对某个特定数学领域，可以用领域知识给动作空间加上结构，让它变得可行。能不能把这个方法推广到一般领域，是开放问题。

07. 自动形式化的两个难点

录像位置 0:33:15–0:36:24

自动形式化是在非形式数学和形式数学之间架桥，把非形式翻译成形式。这里有两个略有不同的子问题：

  • 命题的自动形式化：输入非形式命题，输出 Lean 里的形式命题。
  • 证明的自动形式化：输入非形式命题、非形式证明和形式命题，只输出形式证明。

命题：没有可靠的自动评估

例子是非形式命题“素数有无穷多个”。一个形式命题写成：对任意自然数 $n$，存在 $p$，$p \ge n$ 且 $p$ 是素数。这显然是正确的形式化，因为它蕴含无穷多。但它不是唯一正确的写法：

  • 把 $p \ge n$ 改成 $p > n$，意思一样；
  • 还可以改得更不一样，比如再要求 $n$ 也是素数。

任何人都很容易看出这三个命题略有不同但说的是一回事。可这对机器学习是个问题：模型输出其中一个，怎么知道它和标准答案等价？

你可能想检查逻辑等价，但现实是一般情况下检查两个定理是否等价在计算上不可行。实践中研究者只能用启发式规则或人工评估：人工评估很贵，也不可复现；代理指标（比如 BLEU 这类文本相似度）不准确。

证明：非形式证明里到处是缺口

人写的证明即使很严谨，也不够严谨到可以直接形式化，常有缺口。一类是显式缺口，比如数学家常说“这种情况留给读者”，模型没法从文字里看出该怎么做，只能自己想出来。还有更隐蔽的缺口，后面会讲。要自动形式化证明，模型得把这些缺口全部补上，这可能极难。

两个难点合起来：命题没有可靠的自动评估；证明需要补全推理缺口。

08. LeanEuclid 和《几何原本》命题 24 的漏洞

录像位置 0:36:24–0:44:30

限定领域：欧氏几何

他们这个项目想同时解决这两个问题。听上去不可行，但他说这个项目的教训是：一般情况下难以处理的问题，限定到一个很具体的领域就可能变得可处理。他们选的是欧氏几何，数学最古老的分支之一，两千多年来一直被用来考验人的智力；最近因为 AlphaGeometry 能解 IMO 级几何题，又受到 AI 界关注。他们想说明欧氏几何不只是定理证明的好领域，也是自动形式化的好领域。

LeanEuclid 基准

他们收集了一个自动形式化欧氏几何的基准，叫 LeanEuclid：48 道题来自欧几里得《几何原本》第一卷，另外一百多道（幻灯片写 125 道）来自已有数据集 UniGeo。每道题有图、非形式的定理陈述和非形式证明。

例子是第一卷命题 1：给定两点 A、B，可以作一个等边三角形。他们手工在 Lean 里做了形式化，和非形式版本对应得很紧：第一步以 A 为圆心作圆 BCD，B 在圆上；第二步作另一个圆，找两圆的交点；再把点连起来，就是等边三角形。形式证明只有五六步，每一步都和非形式证明的做法一一对应。

他们对第一卷全部 48 个定理和证明都这样做了。他说这在审美上让他很满意，据他们所知，他们是第一个在 Lean 这样的证明助手里忠实地形式化《几何原本》的。他们刻意让形式证明和非形式证明一一对应，而后面会看到，这并不总是容易的。

命题 24：欧几里得漏掉了一种情况

形式化过程中他们发现了《几何原本》里几处很有意思的错误。他挑了一个讲，用来说明形式化怎样帮你严格检查证明，找出你以为已经很严谨的证明里的 bug。

第一卷命题 24：两个三角形有两组对应边相等，$|AC| = |DF|$，$|AB| = |DE|$，并且 $\angle BAC > \angle EDF$，那么 $|BC| > |EF|$。

欧几里得的证明。先把左边的三角形移过去和右边的三角形重叠，C 移到 G，再连接 F 和 G。问题变成比较 EG 和 EF 两条边（移动后 BC 落在 EG 上）。这更容易，因为两条边现在在同一个三角形里，按书中前面证过的定理，同一个三角形里大角对大边，所以只要证明两个角的大小关系：$\angle EFG > \angle EGF$。

注意到 $\triangle DGF$ 是等腰三角形（$|DG| = |DF|$），按前面证过的引理，等腰三角形两底角相等：$\angle DGF = \angle DFG$。于是：大角 $\angle EFG$ 包含 $\angle DFG$，所以比它大；$\angle DFG = \angle DGF$；$\angle DGF$ 又比小角 $\angle EGF$ 大。所以大角大于小角，证毕。

他说这看起来很平凡，但证明其实是错的，并问台下有没有人知道为什么。对这张图来说证明没问题，可如果图长成另一个样子呢？

另一种图。同样的步骤：移三角形，连 G 和 F，想证 $x > y$（$x = \angle EFG$，$y = \angle EGF$），想用等腰三角形的两个底角 $\alpha$。可在这张图里，$\alpha$ 不在 $x$ 里面，而在 $x$ 和 $y$ 的外面，没法再把它当作夹在中间的角来比较，原来的论证在这张图上不成立。

修补。他说幸好能修，不然他们大概能发一篇更大的论文。修法如下：

  • $\angle DGE = \alpha + y$ 是一个三角形的内角，所以 $\alpha + y < \pi$，这很显然；
  • $\angle DFE = 2\pi - \alpha - x$，同样小于 $\pi$。

两式相加，$\alpha$ 消掉：

$$2\pi - x + y < 2\pi \;\Longrightarrow\; x > y$$

他说这个证明和欧几里得的很不一样。所以他们认为欧几里得在这里犯了错，或者严格说不算错：这个证明有两种情况，两种情况略有不同，一种比另一种难，欧几里得略过了难的那种，只讲了简单的。他说这是和 AI 关系不大的题外话，但展示了 AI 和 Lean 怎样让东西更严谨。

09. 命题等价检查、图形推理和实验

录像位置 0:44:30–0:52:07

解决难点一：检查命题是否等价

这个基准的第一个好处是能检查自动形式化出来的命题对不对。有一个标准答案，要检查模型生成的命题是否和它逻辑等价。两个定理 $T_1$、$T_2$ 等价，当且仅当能证明

$$T_1 \Longleftrightarrow T_2$$

也就是分别证明 $T_1 \Rightarrow T_2$ 和 $T_2 \Rightarrow T_1$。他们用的自动推理工具是 SMT 求解器（SMT solver，一类能自动判定一阶逻辑公式在算术、几何等理论下是否成立的程序）。

前面说等价检查一般不可行，为什么这里可行？因为欧氏几何的定理有特定的形式，不是一般的定理。又一次说明，一般情况下难处理的问题，在特定领域可以变得可处理。

解决难点二：图形推理的缺口

另一个问题是证明的自动形式化。欧氏几何证明里有一类众所周知的缺口，叫图形推理缺口（diagrammatic reasoning gap）。他又用命题 1 来说明。

欧几里得的证明：以 A 为圆心、过 B 作圆；以 B 为圆心、过 A 作另一个圆；取两圆交点 C，把点连起来，就得到等边三角形。他问台下有没有人不同意，没人举手。问题是：我们证明了 C 存在吗？证明了两个圆真的相交吗？没有。而且因为这是命题 1，只能用公理，没有已有的引理可用；如果你试着只用欧几里得的公理证明两圆相交，是证不出来的。没人去证，因为在图上太显然了。

可要把这个证明翻译成 Lean，就成了问题。Lean 不知道图是什么，也不知道图上什么是显然的，所以得把“图上显然”形式化。他提到上一讲有人在 Zoom 上问过怎样在 Lean 里形式化欧氏几何，他认为这和那个问题密切相关：最重要的事情之一，就是怎样形式化“在图上显而易见”这个概念。

幸好这个问题已经有人解决了。CMU 哲学系教授 Jeremy Avigad（幻灯片：Avigad et al., “A formal system for Euclid's Elements”, 2008）提出了形式系统 E，找出了一组不在欧几里得公理体系里的公理，可以看作没说出口的隐藏公理，即“图形规则”。一个事实如果是这些公理的推论，它就是“图上显然”的。这样“图上显然”就有了可计算的含义，可以实现一个自动推理算法去推导显然的事实。他们在 Lean 里实现了系统 E，并用 SMT 求解器自动做图形推理。

整套流程

  1. 基准里每道题有图、非形式数学、人写的标准形式命题。
  2. 模型做命题自动形式化，生成一个形式定理；用 SMT 求解器证明它和标准答案互相蕴含，检查等价。
  3. 模型再做证明自动形式化，生成一个证明，交给 Lean。
  4. Lean 找出证明里的一组缺口，交给 SMT 求解器，判断这些缺口是不是图上显然的。
  5. 全部通过，就判定这是一个正确的形式化。

他说这个基准提供的是一套可以严格评估自动形式化的协议。

实验

他们做了很简单的实验：不训练模型，只用 GPT-4 和 GPT-4V（能看图），给几个示例（few-shot），让它们自动形式化定理陈述。图上横轴是示例数量，蓝色是 GPT-4，绿色是 GPT-4V。两个结论：

  • 示例越多效果越好，但给到 5 个甚至更多，正确率也只有大约 20%，很低，说明自动形式化很有挑战。
  • GPT-4V 比 GPT-4 稍好，说明把图也给模型，它对几何题的理解更强。

收获和开放问题

他们找出了自动形式化的两个难点：命题难以评估，证明的缺口太多；通过限定到特定领域，分别做出了命题等价检查器和补全所有缺口的工具。开放问题仍然是怎样推广到更广的数学领域。

他最后说，定理证明和自动形式化两个任务都讲完了，欢迎提问。录像到此结束。

问答

讲课中间的提问（0:26:06）：录像里听不到提问内容，从回答看，是在他讲完动作空间无限、强化学习难以探索之后，有同学问这些方法有没有用课程式学习（curriculum，先学简单样例、再逐步加难）。他说这是个好问题。前面讲到的工作都只用监督学习，所以不涉及课程。但如果用强化学习，自然会让模型先从比较简单的样例学起，再尝试泛化。他说看最近用强化学习做定理证明的工作，一个主要难点就是怎样挑选给模型的样例：既不能太简单，也不能太难。
