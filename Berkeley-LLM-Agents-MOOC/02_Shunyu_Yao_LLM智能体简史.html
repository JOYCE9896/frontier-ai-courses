01. 什么是智能体，什么是 LLM 智能体

录像位置 0:00:00–0:04:09

他先问全场：谁觉得自己知道 LLM 智能体的定义？举手的大概只有三个人。他说这说明这个领域还在变。要定义 LLM 智能体，先要定义 LLM 和智能体。LLM 大家都知道，剩下的是“智能体”。在 Google 图片里搜 agent 会搜到特工，但在 AI 里，这个词出了名地宽泛，从自动驾驶汽车、下围棋的程序、玩电子游戏的程序到聊天机器人，都可以叫智能体。

智能体的定义

他的定义是：一个能和某种“环境”交互的“智能”系统。智能体会对环境采取行动（action），从环境得到观察（observation）。按环境分：

  • 物理环境：机器人、自动驾驶汽车等。
  • 数字环境：玩 Atari 游戏的 DQN、Siri、AlphaGo 等。
  • 如果把人看作环境，聊天机器人也是一种智能体。

所以定义智能体要先定义什么是“智能”、什么是“环境”。有意思的是，“智能”的标准一直在变：60 年前，一个用三行规则写的聊天机器人就会被认为有智能，现在连 ChatGPT 都不让人惊讶了。他留了一道思考题：你怎样定义智能？

三个层级

  • 第一层，文本智能体（text agent）：行动和观察都是语言。它不一定用大模型，AI 早期就有文本智能体。例子：ELIZA、LSTM-DQN。
  • 第二层，LLM 智能体：用大模型来决定行动的文本智能体。幻灯片上的例子：SayCan、Language Planner。
  • 第三层，推理智能体（reasoning agent）：用大模型先推理、再行动。例子：ReAct、AutoGPT。幻灯片上注明这是这个领域和这一讲的重点。

他说第二层和第三层的区别后面会讲清楚。

02. LLM 之前的文本智能体：ELIZA 和 LSTM-DQN

录像位置 0:04:09–0:06:08

ELIZA（1966）是最早的聊天机器人之一，靠人写的规则运行。它做的事情就是不停地反问你、复述你说的话，但人们觉得它很像人。这类基于规则的智能体有明显的局限：规则往往针对具体任务，每到一个新领域都要重新写规则；规则在简单领域之外基本行不通。你为聊天机器人写了很多规则，换成玩游戏的智能体又要写一大堆。

LSTM-DQN（2015，EMNLP 论文 Language Understanding for Text-based Games using Deep Reinforcement Learning）代表 LLM 之前另一种很流行的范式：用强化学习（RL，智能体根据环境给的奖励信号反复试错、调整策略的学习方法）来做文本智能体。想象一种文字游戏，观察和动作都是文字而不是像素和键盘，同样有奖励，可以用 RL 优化奖励，智能体就能表现出一定的语言智能。它的局限是：仍然针对特定领域，每个新领域都要训练新的智能体；需要标量奖励信号，而很多任务没有；需要大量训练，这是 RL 的特点。

LLM 带来的希望是通用性和少样本学习（幻灯片引了 GPT-3 论文 Language Models are Few-Shot Learners，NeurIPS 2020）：训练时只是在海量文本上预测下一个 token，推理时用少量示例提示就能解决各种新任务。

03. 从问答看两条线：推理和行动

录像位置 0:06:08–0:13:45

一张简化的历史图

他给了一张自己说“明显过度简化”的图：2020 年左右有了 LLM，起点他认为是 GPT-3。人们把它用到各种任务上，有一类是推理任务（比如符号推理问答），对应 CoT、零样本 CoT、self-consistency 等方法；另一类他称为行动任务，比如游戏、机器人、RAG。这两条线后来汇合，出现了推理智能体，代表是 ReAct。没有推理的那部分，他称为“LLM 智能体，但不是推理智能体”。有了推理智能体之后，一方面出现了新应用和新基准（网页浏览、软件工程、科学发现），另一方面出现了新方法（记忆、学习、规划、多智能体等）。

以问答为例

为了简化，他先只看一个任务：问答。问“1+2 等于几”，模型答 3，这就是问答，直观，也是 NLP 里最有用的任务之一。但用大模型做问答会碰到各种问题：

  • 需要推理：比如 GSM8K 里的鸭蛋题，Transformer 很难直接输出答案。上一讲讲的 CoT 就是为了解决这个。
  • 需要知识：比如“英国现任首相是谁”。模型如果是 2024 年之前训练的，而英国首相又换得很勤，就可能答错。
  • 需要计算：比如“34324329 的质因数分解是什么”，不能指望 Transformer 直接算出来，需要超出自回归生成的计算手段。

各自的解法

  • 代码增强计算：让模型先生成程序，运行程序得到结果（幻灯片引了 Program of Thoughts Prompting）。这样可以回答质因数分解、第 50 个斐波那契数这类问题。
  • RAG：假设有额外的语料（比如 Wikipedia 或某家公司的文档）和一个检索器（比如 BM25、DPR），检索器可以看作一个搜索引擎，根据问题从语料里取出相关信息，拼到模型的上下文里，模型就更容易回答。问题是，如果没有现成的语料呢？比如今天旧金山的天气，不可能在任何现成语料里。
  • 工具使用（tool use）：在正常生成句子的过程中引入特殊 token 来触发工具调用，比如计算器、Wikipedia 搜索、天气 API、翻译这类专用模型（幻灯片引了 TALM 和 Toolformer）。这很强大，但这种格式不是自然文本，互联网上没有哪篇博客或 Wikipedia 文章长这样，所以要专门微调模型；而且这样很难在一段文本里多次调用工具。
  • 既要知识又要推理：有人提出交错进行 CoT 和检索（IRCoT），或者生成追问（Self-ask）等方法。

他说当时的局面有点零散：问答看起来是一个任务，实际上有一大堆基准（知识密集型问答、多跳知识问答、符号推理、数学推理、常识问答……），各自以不同方式考验模型，人们给每个基准想一种解法（RAG、Self-ask、IRCoT、CoT、PoT、工具使用、WebGPT 等）。他当时的问题是：能不能有一个简单、统一的解法？要做到这一点，需要一个超越单个任务和方法的更高层的抽象。

04. ReAct：推理和行动交替进行

录像位置 0:13:45–0:20:02

推理或者行动

他找到的抽象是推理和行动。推理就是 Chain-of-Thought，它是一种灵活、通用的方式，用来增加测试时计算（test-time compute，推理阶段花更多计算让模型想得更久），能解更复杂的问题。但只用 CoT 就没有外部知识和工具，再大再聪明的模型也不知道今天旧金山的天气。

前面说的 RAG、检索、代码、工具使用，在某种意义上都是“行动”范式：把模型看作智能体，环境可以是检索器、搜索引擎、计算器、API 或 Python。和外部环境交互的好处是能灵活、通用地补充知识、计算和反馈；缺点是没有推理，后面会看到这为什么是个麻烦。

ReAct 的做法

在 ReAct 之前，模型要么生成推理，要么生成行动。ReAct 的想法就是两者都生成。他说这能让两者互相促进：推理帮助行动，行动帮助推理；而且简单直观，他认为这就是人解决任务的方式；同时适用于各种领域。用幻灯片上的说法，推理是更新内部信念，行动是获取外部反馈。

具体做法：要解决一个任务，就写一个提示，里面放一条示范轨迹：给一个示例任务，由人写下自己怎么想（Thought）、做了什么（Action），以及沿途得到的观察（Observation）。比如用 Google 回答问题，就写下想了什么、搜了什么、Google 返回了什么，一直写到任务完成。然后给一个新任务，模型会生成一个想法和一个行动；行动被解析后送进外部环境，得到观察；“想法、行动、观察”追加到模型上下文里，模型再生成新的想法和行动，如此循环。

只用一个示例叫 one-shot prompting，用几个叫 few-shot prompting，有很多示例时也可以拿来微调模型。所以他说 ReAct 是一种使用模型的方式，和用提示还是用微调无关。

例子：7 万亿美元能不能买下三家公司

他在 2024 年 3 月做这页幻灯片，当时的热门话题是：如果我今天有 7 万亿美元，能买下 Apple、Nvidia 和 Microsoft 吗？如果不能，还差多少？提示很简单：你是一个回答问题的智能体，有两个动作，search[query] 用 Google 搜索（也可以用来算数），finish[answer] 返回答案；输出格式是 Thought 和 Action。

GPT-4 当时的表现：

  1. 想法：需要找到这三家公司当前的市值，加起来，判断 7 万亿够不够。行动：搜索三家公司当前市值。
  2. 观察：搜索结果恰好包含所有市值（Nvidia 1.832 万亿、Microsoft 3.015 万亿、Apple 2.836 万亿美元）。
  3. 想法：有了市值，加起来看够不够。行动：用搜索引擎当计算器，搜“1.832 trillion + 3.015 trillion + 2.836 trillion”，得到 7.683 万亿。
  4. 想法：还需要额外 6830 亿美元。行动：finish。

他说这和人解决任务的方式很像：先想一想情况，做点什么获取更多信息，再根据信息继续想。他还开玩笑说，如果今天再问，钱会差得更多，因为 Nvidia 涨了很多。

人为制造的干扰

然后他故意给“对抗性”的观察。第一次搜索，他让结果返回“nothing found!”。这时推理发挥作用：模型想到搜索没结果，那就逐个公司去搜市值。他再次捣乱，搜 Apple 市值时只返回股价“'price': 180.75”。推理再次起作用：模型凭常识判断这是股价不是市值，市值等于股价乘以流通股数，于是去搜 Apple 的流通股数，接着对三家公司都这样做，最终解决任务。

他的结论：行动显然在帮助推理，提供实时信息或做计算；同时推理也在不断指导行动，规划、并在出现意外时调整计划。用不同的示例和不同的工具，同样的方式可以解决各种问答任务。

05. 超出问答：文本游戏，推理是一种内部行动

录像位置 0:20:02–0:25:26

很多任务可以变成文本游戏

他说更有意思的是，这个范式不局限于问答。只要意识到很多任务能变成文本游戏：比如一个电子游戏，可以用视频或图像描述模型把画面转成文字，再用一个控制器把语言动作转成键盘操作，这样就能用 ReAct 来解（幻灯片引了 ALFWorld 和 ALFRED）。

大模型出来以后，做强化学习、机器人、游戏的人也开始用这种方法：把观察转成文本，让模型生成文本动作，再转回原来的动作格式（幻灯片引了 Inner Monologue 作为“只行动、不推理”的例子）。

只行动不推理的问题

问题在于，有时很难直接从观察映射到行动：一是你可能从没见过这个领域；二是从观察到行动需要思考，如果没有思考这一步，模型只能模仿示例里“观察到行动”的映射。

例子来自一个模拟厨房里做家务的游戏（ALFWorld）。任务是“把胡椒瓶放到抽屉上”。只行动的智能体：去抽屉 1，打开，看到洗碗海绵和勺子；去水槽，看到海绵、锅铲和勺子；然后“从水槽拿胡椒瓶 1”，什么都没发生；它再试一次，还是什么都没发生……水槽里根本没有胡椒瓶，但它没有思考能力，只会一直重复、一直失败。他说这就是语言模型在模仿，它没被训练成像智能体一样解决任务。幻灯片上的评语是：没法系统地探索，也没法利用反馈。

他们的做法很简单：再加一种动作，叫“思考”。思考是一种很特别的动作，因为可以想任何东西。在这个游戏里，环境定义的动作只有“去某处”“拿起某物”之类，但你可以想任何事。ReAct 版本的智能体先想：“首先要找胡椒瓶，它更可能在柜子（1 到 6）或台面（1 到 3）上……”然后依次查看柜子 1 到 6、台面 1 和 2，在台面 3 上找到胡椒瓶，拿起；再想“找到了，下一步要放进抽屉 1”；去抽屉 1，打开，放进去，完成。思考帮它规划、跟踪进度，出错时重新规划。

为什么说推理智能体不一样

他从更理论的角度解释。所有以前的智能体，从电子游戏、AlphaGo 到自动驾驶，有个共同点：行动空间由环境定义。比如玩 Atari 游戏，动作就是上下左右，你可以玩得好或坏，但行动空间是固定的。语言智能体、LLM 智能体或推理智能体的不同在于，多了一种“增强的行动”：推理。这种行动可以是任何语言，空间是无限的：可以想一段话、一句话、一个词，也可以想一千万个 token。它对外部世界没有任何影响，不管想什么，地球和你玩的游戏都不会变；它只改变你自己的上下文，也就是你的记忆，再据此改变后面的行动。所以他说推理是智能体的内部行动，而且这种行动的空间是无限的语言空间，这是推理智能体和以往智能体的根本区别。

06. 长期记忆：Reflexion、Voyager、Generative Agents、CoALA

录像位置 0:25:26–0:38:07

有了推理智能体之后，任务和方法都有很多进展，他说没法全讲，方法上只讲一件事：长期记忆。

上下文窗口是短期记忆

换个角度看推理智能体：它有一个短期记忆，就是语言模型的上下文窗口，想法、行动、观察都追加在里面。这个短期记忆有几个问题：

  • 只能追加，只能往后接新 token。
  • 上下文有限：两年前可能是一千 token，现在一百万，明年也许一千万，但总有上限。
  • 注意力有限：即使有一千万 token 的窗口，做长任务时里面也会有很多干扰信息。
  • 不能跨任务保留：假设某个智能体今天证明了黎曼猜想，如果不微调模型，下次还得从头再来，而且不保证明天还能证出来。

他说这有点像金鱼，民间说法是金鱼只有三秒记忆：你能做出很了不起的事，但记不住就得重做一遍，很可惜。

长期记忆就像人的日记：你记不住每天的每个细节，但会把重要的经历、知识、技能写下来，以后读，可以读也可以写，并且能跨越新的经历保存下来。也像一位数学家写论文证明了黎曼猜想，别人读论文就能会证，不必重新解一遍。

Reflexion：从失败里写下教训

最简单的长期记忆形式是 Reflexion（Language Agents with Verbal Reinforcement Learning），它是 ReAct 的一个简单后续。比如做编程题：你可以写程序、运行、推理，最后测试，有测试没过。没有长期记忆，就只能再试一次。有了长期记忆，就可以反思：“我没过这个测试，是因为忘了某个边界情况，下次写这个程序要记得。”把这条信息保存下来，下次写程序时读出来，表现就会更好。

这对编程尤其有效，因为编程有很好的反馈，即单元测试结果。幻灯片上的 HumanEval pass@1（一次生成就通过测试的比例）：GPT-3.5 零样本 48.1，GPT-4 零样本 67，GPT-4 加 Reflexion 91。幻灯片还请大家参考 Self-refine、Self-debugging 等工作。

“言语”强化学习

他说 Reflexion 是一种新的学习方式。传统强化学习是：做一件事，得到一个标量奖励（比如 -4），然后把奖励反向传播回去更新策略的权重，有很多算法做这件事。幻灯片上概括为两点：通过标量奖励学习（信号稀疏），通过更新权重学习（要做信用分配，即判断哪一步该为结果负责）。Reflexion 不同：反馈可以是任何东西，代码执行结果、编译错误、老师的文字反馈都行；学习靠的是更新语言，不靠梯度下降，这里的语言指一份关于任务知识的长期记忆，这份语言再影响策略以后的行为。

更复杂的长期记忆

  • Voyager：一种基于代码的技能记忆（幻灯片称为 procedural memory，程序性记忆）。比如在 Minecraft 里学会了用 API 代码造一把剑，就记下来；下次要打僵尸，先调出造剑的技能，不必从头试。他说课程后面的讲者会讲到这项工作。
  • Generative Agents（Interactive Simulacra of Human Behavior）：一个小镇里有大约 20 个像人一样的智能体，有工作、有生活、有社交。它们有情景记忆（episodic memory）：每个智能体记下发生过的所有事件的日志，每小时都有，是你能想到的最详细的日记。以后要做决定时可以查日志，比如把孩子送到某处，就能检索出来再去接。它们还有语义记忆（semantic memory）：看着日记反思，得出关于别人和自己的结论，比如“Jim 是个好奇的人”“我其实喜欢电子游戏”，这类知识会影响以后的行为。

模型参数也是长期记忆：CoALA

最后一步是意识到，语言模型本身也可以看作一种长期记忆。“学习”（改进自己、改变自己）可以通过微调神经网络参数来做，也可以通过往长期记忆里写一段代码或文字、之后再检索出来来做。如果把神经网络和文本库都看作长期记忆，就得到一个统一的学习抽象：智能体有推理能力，它在一种特殊的短期记忆（语言模型的上下文窗口）上推理，再加上各种形式的长期记忆。

他说这几乎足以表达任何智能体，并推荐了他的论文 CoALA（Cognitive Architectures for Language Agents）：任何智能体都能用三部分描述，记忆（信息存在哪里）、行动空间（智能体能做什么）、决策过程（在行动空间里选哪个行动）。

他留了两道思考题，说答案在论文里：

  • 外部环境和内部记忆有什么区别？智能体打开一个 Google Doc 写东西，算长期记忆，还是改变外部环境的行动？智能体从一份互联网存档里检索知识，算行动还是从长期记忆检索？对人或自动驾驶汽车这类物理智能体，内外很好分，皮肤以外是外部，以内是内部；对数字智能体怎么分？
  • 长期记忆和短期记忆怎么区分？如果模型有一千万 token 的上下文，还能说它只是短期记忆吗？他提醒，这些术语来自人类心理学和神经科学。

07. 智能体极简史：符号、深度强化学习、语言

录像位置 0:38:07–0:43:21

前面是从 LLM 出发看智能体的发展。他接着把视角放大到整个智能体的历史，看推理智能体和以前的范式有什么不同。他声明这张“极简史”一定是错的，只为说明问题，不要太当真。

  • AI 早期是符号 AI 智能体，有点像编程，把和各种环境交互的规则都写出来。幻灯片上的例子有 SHRDLU、专家系统、认知架构、Deep Blue。
  • 然后是“AI 寒冬”。
  • 深度学习之后是强化学习智能体，通常是深度 RL，有从 Atari 到 AlphaGo 的很多突破，幻灯片上还列了 OpenAI Five、MuZero。
  • 最近才有了 LLM 智能体。

开头讲的 ELIZA 是典型的符号 AI 智能体，LSTM-DQN 是文本领域典型的深度 RL 智能体。

从观察到行动，用什么“语言”

他说三种范式要解决的问题一样：从环境得到观察，要产生行动。区别在于从观察到行动的过程中用什么表示，或者说用什么“语言”。

  • 符号 AI 智能体：先把观察映射成符号状态，再用符号状态推出行动，类似 if-else 规则，把所有可能的复杂观察映射成一组逻辑表达式。
  • 深度 RL 智能体：观察可以是像素、文本或任何东西，但都被神经网络处理成某种嵌入（向量或矩阵），再用它推出行动。
  • 语言智能体或推理智能体：直接用语言作为中间表示，用语言思考，比如“让我们一步步想……房间很暗，所以我需要一盏灯，灯在卧室，所以我应该……”。他说这是人做事的方式。

符号状态和神经嵌入的问题是：设计或训练它们要花大量精力。想想 Waymo 这种自动驾驶汽车，可能写了上百万行规则和代码；很多智能体要训练上百万步。而且两者都针对具体任务，为自动驾驶写的百万行代码没法拿去玩游戏，训练来玩游戏的智能体也没法开车。

语言不同：不用做太多，因为大模型已经有丰富的先验知识，用提示就能搭出智能体，很方便；而且很通用，你可以想怎么开车、怎么玩游戏，也可以想该买哪套房子、考虑按揭利率。还有一点，符号状态和深度 RL 的向量通常是固定大小的，而思考可以任意长，一段话或一句话都行，这带来了推理时可扩展（inference-time scaling）这个新维度。他说这就是推理智能体从根本上不同的原因。

08. 新任务：数字自动化、WebShop、SWE-bench、ChemCrow

录像位置 0:43:21–0:52:00

数字自动化

前面的例子基本是问答和玩游戏，这也是 NLP 和 RL 的主流范式。他认为语言智能体打开了更多应用，特别是他称为“数字自动化”的方向：想象一个助手能帮你提交报销、写代码、跑实验、找相关论文、审稿。如果都能实现，大家本科两年就能毕业，博士三年，拿终身教职也只要三年，一切都会加速。

但在 ChatGPT 之前，这方面几乎没进展。Siri 是 ChatGPT 之前最先进的数字智能体，基本什么都做不了。他认为原因是：需要对真实世界的语言（以及其他模态）做推理，序列到序列的映射不够，写代码要想清楚写什么、为什么写；还需要在开放的行动空间里、在很长的时间跨度上做决策。

以前的基准没有这些挑战

LLM 智能体出现之前的智能体基准，大多是合成任务，规模小，不实用，幻灯片上列了 MiniWoB、TextWorld、BabyAI（比如“走到蓝色的球那里”）。这限制了智能体研究：就算有世界上最好的智能体，没有好任务也没法证明进展，在网格世界里做到 100% 又说明什么？他说 LLM 智能体的历史一方面是方法越来越好，另一方面同样重要、甚至更重要的是任务越来越实用、越来越可扩展。

WebShop（2022）

这是他和合作者在 2021 到 2022 年做的。智能体帮你网购：给它一条找某类商品的指令，它像人一样浏览网页，点链接、输入搜索词、查看不同商品、返回重新搜索，搜索要换说法时还得想怎么改。找到合适商品后选好各种选项，点击购买，环境会给一个 0 到 1 之间的奖励，表示选得多好。这就是标准的强化学习环境，只不过观察和行动都是文本，而且很实用。

他说 WebShop 是第一次有人基于大规模真实互联网数据搭建大规模复杂环境：他们爬取了 116 万件 Amazon 商品，搭了网站，并根据指令和商品属性的匹配程度自动给奖励。它比网格世界难得多，既要理解真实领域里的图像和语言，也要在长时间跨度上做决策，比如浏览十件商品、换十种搜索词才能找到完全匹配的。

WebArena 和 SWE-bench

沿着网页交互的方向，后续工作（幻灯片列了 WebArena，2023）让智能体在网页上做购物以外的各种任务。也可以做其他实用任务，比如软件工程：SWE-bench（2023）给定一个 GitHub 仓库和一个 issue（“这个东西不工作，帮我修”），要求输出一个能解决问题的文件 diff，用 pull request 里的单元测试评估。任务定义很干净，但很难，要像软件工程师一样和代码库交互、写单元测试、运行、反复尝试。

ChemCrow：动作延伸到物理世界

他很喜欢的一个例子是 ChemCrow（Bran et al., 2023）：用推理智能体寻找新的发色团（chromophore）。给智能体一些化学物质的数据，让它可以用 Python、互联网等工具做分析，提出新的化合物。智能体的建议随后在湿实验室里合成，这样它的行动空间就延伸到了物理世界，实验结果也可以反馈回来改进它。

他说语言智能体既能在数字世界里工作，也能在物理世界里工作；既能做订外卖这类繁琐任务，也能做软件工程、科学发现这类更需要智能和创造力的任务。

两张总结图

他回到开头那张历史图，又补了一张从任务角度看的图（幻灯片 “A minimal history of agents: Part 2”）：

  • 物理世界和人：实用（机器人、聊天机器人），但不可扩展，收集数据又贵又慢。
  • 模拟和游戏：可扩展，交互免费且无限，但不实用，从模拟迁移到现实很难。
  • 数字世界（互联网、代码、软件……）：既实用，有大量重要任务可以自动化；又可扩展，规模大、复杂度高、免费且快。

他说 LLM 智能体带来的新任务维度就是自动化数字世界里的各种事情。

09. 做研究的几条经验

录像位置 0:52:00–0:54:04

讲完历史，他总结了几条做研究的经验：

  • 最重要的工作有时是最简单的工作。Chain-of-Thought 简单到不可思议，ReAct 也是。简单是好事，因为简单意味着通用，极其简单的东西很可能极其通用，那可能就是最好的研究。
  • 但做到简单很难。要简单又通用，两样都要有：一是抽象思考的能力，要跳出具体任务和数据点，在更高层次上想；二是对具体任务、数据和问题很熟悉。
  • 他特别提醒，对各种针对具体任务的方法太熟悉，反而可能分散注意力。回想问答那段历史，那么多专门的方法，如果你只盯着这些，最后可能只是在它们之上做增量改进；如果你除了问答还熟悉很多不同的任务，并能抽象地思考，就可能提出更简单、更通用的东西。幻灯片上写的是：要熟悉任务，而不是熟悉针对任务的方法。
  • 学历史和学其他学科有帮助，它们为怎样构建抽象提供先验，也提供抽象思考的方式。

10. 未来方向之一：为智能体训练模型（FireAct）

录像位置 0:54:04–0:59:21

他说这之前是历史，之后是当前最前沿和未来。未来是多维的，他挑了五个关键词：训练、接口、鲁棒性、人、基准。选它们的理由有两条：一是很新，现在做可能有很多容易摘的果子，或者有机会做出很基础的成果；二是在学术界的条件下也能做，不必在 OpenAI（他补了一句，在 OpenAI 也挺好）。这五个话题对应他最近的三项工作：FireAct、SWE-agent、τ-bench。

训练：模型和智能体要协同

他说直到今年，语言模型和智能体基本是分开的：训练模型的人和做智能体的人是两拨人。做模型的人造出模型，做智能体的人在上面用微调或（主要是）提示搭智能体。但这些模型不是为智能体训练的。语言模型的根源是训练来生成文本，没人想到会用它做化学发现或软件工程。数据分布不匹配：没被训练做这些事，却被提示去做，表现就不是最优的。

一个办法是专门为智能体训练模型。可以先用提示搭出的智能体生成大量数据（轨迹），再用这些数据微调模型，让它更擅长当智能体。好处是：

  • 能提升互联网数据里没有覆盖的智能体能力，比如规划、自我评估、校准。互联网是语言模型训练数据的主要来源，但上面很少有自我评估这类数据，人们发布的是写好的博客，没人公开写博客时的思考过程和操作过程，而训练智能体需要的就是这些。用智能体生成这类轨迹来训练，是解决数据问题的一个办法。
  • 互联网数据快用完了，这可能是“下一个万亿 token”的来源（幻灯片上写的是 next trillion tokens，他口头说成了 next trillion dollars）。
  • 幻灯片上还列了：开源的智能体基座模型。

幻灯片上的 FireAct 结果（HotpotQA EM，精确匹配率）：Llama2-13B 用 ReAct 提示为 21.2，Llama2-13B 用 ReAct 微调为 34.4，GPT-3.5 用 ReAct 提示为 31.4。微调后的 13B 模型超过了提示的 GPT-3.5。

他打了个比方：GPU 和深度学习的协同。GPU 最初是为玩游戏设计的，后来人们发现它很适合深度学习；于是人们一边用现有 GPU 做更好的深度学习算法，造 GPU 的人一边也开始为深度学习算法造更合适的 GPU，比如专门针对 Transformer 的。他认为模型和智能体之间也应该建立这种协同。

11. 未来方向之二：智能体-计算机接口（SWE-agent）

录像位置 0:59:21–1:02:34

人机交互（HCI，human-computer interface）是计算机科学里研究了几十年的课题。思路是：如果没法优化智能体，就优化环境。同一个人写代码，用纯文本编辑器还是用 VS Code 差别很大，人没有变聪明，但环境更好，任务就做得更好。他认为智能体也一样。

具体例子：智能体怎样在操作系统里搜索文件？人在终端里用 ls、cd 等命令，这对人好用，但对智能体不是最好的接口。也可以定义一个 search 命令，一次返回一个结果，用 next 看下一个，但这对语言模型可能还不是最好的。在 SWE-agent（Agent-Computer Interfaces Enable Automated Software Engineering）里，他们发现最好的方式是专门的 search 命令，一次给出 10 个结果，让智能体自己决定看哪个文件。实验可以证明：用同一个语言模型、同一个智能体提示，接口不同，下游任务表现就不同。

幻灯片上的 SWE-bench 结果比较了三种搜索接口：汇总式搜索（Summarized，一次列出所有匹配）18.0，迭代式搜索（Iterative，一次一个）12.0，没有搜索命令 15.7。迭代式反而比没有搜索还差。

他说这个方向才刚开始，很适合学术界研究，不需要很多 GPU。它有意思还因为模型和人不一样，接口也应该不一样，不能指望 VS Code 就是语言模型最好的编程接口。人的短期记忆小，给你 10 个结果你一下读不过来，所以人的接口要设计成交互式的，有“下一个”按钮，Ctrl+F 一次只能看一个，用时间换空间。模型反过来，上下文窗口更长，Ctrl+F 应该把结果全给它。好的接口既能让智能体更好地完成任务，也能帮我们理解智能体，理解人和模型的根本差别。

12. 未来方向之三：人在回路和鲁棒性（τ-bench）

录像位置 1:02:34–1:08:43

pass@k 和可靠性是两回事

他说现有基准和人们在现实中关心的东西差别很大。典型的 AI 任务是带单元测试的编程，幻灯片引了 AlphaCode 2 的一张图：采样次数越多，有一次提交正确的概率越大。有单元测试就可以采样很多次，这时关心的是 pass@k（采样 k 次里至少一次正确的概率），即一千次、一百万次里能不能做对一次。就像证明黎曼猜想，只要做成一次。

但现实中大多数工作更看重鲁棒性。比如客服：LLM 智能体已经用于客服，但有时会出错，出错就有后果，公司可能要赔偿（幻灯片上放了新闻：Air Canada 被判须兑现其聊天机器人编出来的退款政策）。客服至少对人来说比编程或证明黎曼猜想容易得多，但挑战不同：你不关心一千次里能不能做对一次，你关心一千次是不是每次都做对，一千次里错一次都可能丢掉一个客户。他说这是要把简单的事可靠地做好，这需要不同的基准测试方式。

τ-bench

他们的新工作 τ-bench（A Benchmark for Tool-Agent-User Interaction in Real-World Domains）：

  • 任务很实用：做客服。
  • 智能体不只和数字环境交互，还要和人交互，这里是模拟的用户。客服智能体像人类客服一样，既要调用公司后台的 API，也要和用户对话，两者都要处理好才能完成任务。幻灯片上注明：智能体看不到私有数据库和用户信息，只能通过工具或聊天获取。
  • 用户不会一开始就给出全部信息。他说现在几乎所有任务（包括软件工程）都默认一开始就给全信息。用户可能只说“改签航班”，你得问“您要改哪一班？”，要和用户多轮交互才能弄清需求并帮到他。

pass^k：k 次全对的概率

这也改变了要关心的指标。对同一个任务，用同一个模拟用户采样多次。图上的虚线是 pass@k，即采样 k 次至少成功一次的概率，采样越多它越高。但这里关心的是 k 次全都成功，否则会丢客户。实线衡量的就是：采样越多，在所有任务上每次都成功的概率是多少（论文里记作 pass^k）。

他说结果显示，不同模型起点不同，能力有差别，但令人担忧的是它们都呈下降趋势：采样越多，可靠性越低，从小模型到大模型都一样。理想的曲线应该更平：能做成的事，应该能可靠地一再做成。他说基准测试需要纳入更多真实世界的要素，这需要新的设定和指标。

它们能替代什么工作

他推荐了一篇他们写的博客，讨论语言智能体的未来（幻灯片上的链接是 princeton-nlp.github.io/language-agent-impact）。一种思考方式是：它们能替代哪些工作？第一类任务不太需要智能，但需要鲁棒性，比如简单的调试、客服、长期的简单助理工作；第二类需要和人协作；第三类很难，比如从零写一篇综述或发现一种新的发色团，需要智能体用新的方式自己探索。他说很值得想清楚它们能替代哪些工作、为什么现在还替代不了、缺什么、怎么改进。
