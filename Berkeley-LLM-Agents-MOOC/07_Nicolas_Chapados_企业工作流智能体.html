01. 术语：LLM 智能体，以及 API 智能体和 Web 智能体

录像位置 0:00:00–0:09:31

开场和议程

Nicolas 说，这一讲想回答的是企业场景里的几件事：用例是什么，人类用户是谁、扮演什么角色、在做什么工作，智能体应该在什么环境里部署来帮他们。他用一个日常例子说明 ServiceNow 这类平台在做什么：早上咖啡洒在笔记本上，电脑坏了，你在手机上给 IT 服务台开一张工单，申请寄一台新电脑。今天这张工单由人工客服处理，读工单、按步骤操作、把电脑寄出去，中间有很多手工步骤。他说智能体有很大机会把这类日常问题的处理部分自动化。

议程分四块：背景（定义和企业工作流）、API 智能体（架构和 TapeAgents）、Web 智能体（概念、WorkArena、BrowserGym 和 AgentLab）、工作场所里的智能体（自动化企业工作流和工作的未来），最后给延伸阅读。

LLM 智能体的定义

幻灯片上的定义：LLM 智能体是由 LLM 驱动的实体，能自主规划并采取行动，在多轮迭代中完成目标。Nicolas 补充说，它们有一定自主性，能在环境中行动、从环境接收反馈，执行人类用户给的目标，这个过程通常要多轮。

他把 LLM 智能体和上一代智能体区分开。如果你有机器学习背景，会熟悉那种用强化学习（reinforcement learning，让智能体在环境中反复试错、按奖励信号改进策略的训练方法）训练的智能体：范围窄，架构受限，动作空间小，要在沙盒环境里长时间训练，玩游戏可以达到超人水平，但对全新任务的泛化很差。幻灯片上的说法是“A Minecraft agent can’t send emails”，他在课上说游戏引擎会很擅长玩 Minecraft，却完全写不了一封给老板的邮件。

LLM 智能体的好处在于核心的语言模型在互联网的很大一部分上训练过，见过大量关于日常软件的说明。网上有很多讲怎么用 PowerPoint、Excel 的页面，甚至有 Salesforce、SAP、ServiceNow 这类企业软件的文档和新闻组帖子。所以 LLM 已经大致知道怎么用人们每天用的软件，LLM 智能体的目标很大程度上就是利用这些知识去执行任务。幻灯片称之为“零样本任务求解器”：不需要专门训练就能做新任务。

两类 LLM 智能体

API 智能体Web 智能体
观察API 调用结果、搜索历史、用户上传的图片、聊天记录人能看到的页面，加上可访问性树（accessibility tree）或原始 DOM
动作API 调用、搜索调用、回复用户在输入框里打字、点击
优点延迟低，风险低什么都能做
缺点需要有合适的 API延迟高，风险高

API 智能体的工具集可以用比较形式化的规范描述，比如一组 API 或端点的说明，交换的主要是文本。Web 智能体像人一样用网页：点按钮、填表单、在页面之间跳转收集信息，记住一些信息在任务后面再用。（DOM 是浏览器内部表示网页结构的树；可访问性树是浏览器给读屏软件用的精简版本，只保留按钮、链接、输入框这类可交互元素和文字。）

02. 企业工作流还很手工，智能体的机会在“沙粒”任务

录像位置 0:09:31–0:17:04

一张权限工单的处理过程

Nicolas 举了一个贯穿全讲的例子。员工 John（幻灯片上写作 Jon）打不开公司内网上的一篇知识库文章，他给 IT 服务台提了工单，工单分给了 Sandy。Sandy 先查有没有知识库文章讲怎么解决这类问题，假设没找到；再查有没有类似的历史事件，找到一件，里面说要检查 John 的访问权限；她发现 John 的权限不对，改了权限，然后把工单标为已解决。Sandy 的公司比较先进，去年刚上线了生成式 AI 功能，能帮她做事件摘要、写解决记录，最后关单。

他的观点是，就算有生成式 AI 帮忙，处理日常工作事项仍然有很多手工步骤，而这类事件在全世界的公司里每天发生成百万上千万次。

企业自动化的几个阶段

幻灯片按“智能程度”和“自动化程度”两条轴排了一条演进路线：

  • 脚本化工作流：自动化变化很少的重复性数字任务（Flow Engine、集成）。
  • RPA 工作流：机器人流程自动化（robotic process automation，用软件机器人模拟人在界面上点击、录入，执行固定流程），通过界面操作自动化重复的系统动作。
  • AI 工作流：用机器学习模型（比如推荐系统、视觉模型）根据模式和反馈动态调整流程。
  • 对话式工作流：自动处理大量请求，代用户提交工单，根据用户的回答调整交互（生成式 AI、RAG、对话引擎）。RAG 是检索增强生成，先检索相关文档再让模型据此回答。
  • 智能体工作流：迭代、交互式的自动化，AI 智能体被授权进行更动态、能自我反思的过程（推理模型、智能体框架、编排）。这一层需要的智能最多，自动化的潜力也最大。

大石头已经搬完，剩下的是沙粒

Nicolas 说智能体在企业里的独特机会，是自动化海量的“低价值、低频次”任务。他先讲反面：高价值或高频次的“大石头”大多已经被自动化了，因为值得有人坐下来专门编程，比如员工入职流程；经常发生、可预测、可复制的事情，很可能已经有低代码/无代码平台或 RPA 流程在处理。

剩下的是每天做的那些小事，他称为“沙粒”：每件都太独特，没法写脚本，因为它们从不以完全相同的方式出现两次。幻灯片上的例子有排期发推文、整理邮件、更新 CRM（客户关系管理系统）、填工时表、给四家公司的 15 个人安排一次会议。用传统技术很难自动化这些，每一粒都很小，加起来却是巨大的工作量，这是智能体可能发挥作用的地方。

演示：去 GTC 怎么走

几个月前他们受邀在 NVIDIA 的 GPU 技术大会 GTC 上演讲，于是让自己的 Web 智能体帮忙查路线。画面左边是他和智能体的对话，右边是智能体在一个类 Chrome 浏览器里自动做的操作（幻灯片注明原视频长 4 倍，有很长的停顿）。他问：我要参加 GTC 2024，从 NVIDIA 总部怎么过去？智能体先去 Google 搜，再进 Google Maps，地图说不认识“GTC”这个地点。智能体回头问他要更多信息，他说是 GTC 大会。智能体重新规划，用 Google 查到大会在 San Jose Convention Center，再把它输进地图，查从 NVIDIA 总部到会展中心的路线。他说这就是他们希望很快能有的交互：智能体可以向人多问问题，自己也有一定的规划和重新规划能力。

03. API 智能体的架构和 TapeAgents 框架

录像位置 0:17:04–0:23:53

典型的单智能体架构

这张图来自 Lilian Weng 2023 年的博客，Nicolas 说前面的课大概讲过，只是统一一下概念。LLM 智能体发出动作，送到环境，环境返回观察。智能体有短期记忆（之前做过的动作和环境的响应），有规划过程（ReAct 等，幻灯片上列了反思、自我批评、思维链、子目标分解），还要能用工具，比如计算器、代码解释器、网页搜索、触发工作流。ReAct 是让模型交替输出“思考”和“行动”的提示方法。更高级的智能体还能合成新工具，存进长期记忆。

为什么需要新框架

他说，今天没人会从零写机器学习算法，大家都用 PyTorch，因为快得多、容易得多；做智能体也需要合适的软件框架，既要帮你构建和调试，也要能根据执行轨迹去优化智能体。TapeAgents 就是他们几天前开源的这样一个框架，技术报告的链接在课前阅读里。

他把现有框架分成两类：

  • 解决开发需求的框架，比如 LangGraph、AutoGen、Crew。在这些框架里，智能体是一个可恢复的模块化状态机，提供可恢复的会话、低代码组件、细粒度控制、并发、从 LLM 流式输出等能力，适合开发。
  • 做数据驱动优化的框架，比如 DSPy、TextGrad、Trace。智能体是使用结构化模块、生成结构化日志的代码，有结构化的配置、结构化的日志和优化算法。智能体本身是提示 LLM 的结果，提到提示就会有提示优化、提示工程；一部分可以手工做，让机器替你做会好得多，某些场景你还想直接优化底层 LLM，让它成为更好的智能体模型。

他说在 TapeAgents 之前，没有一个框架能同时把这两件事做好。TapeAgents 想要的是两者兼得：智能体是一个可恢复的模块化状态机，有结构化配置，生成细粒度的结构化日志，能从日志里生成微调数据，还能复用其他智能体的日志。

核心抽象：磁带（tape）

整个框架建立在一个统一的抽象上，叫“磁带”。磁带就是一份日志，记录系统里所有智能体（假设可以有多个）的思考和动作；每次调用环境执行动作，环境返回的结果也写进磁带。

他预料有人会说这不就是一份普通日志。他的回答是，磁带有相当多的结构，更重要的是它本身是一份数据：可以有智能体把其他智能体执行产生的磁带当作输入，做进一步处理。把磁带当作元数据丰富、能被下游算法处理的完整数据结构，是这个框架的力量所在。幻灯片列出了磁带的几种用途：

  • 智能体读磁带、推理，把思考和动作写到磁带上；
  • 环境执行磁带上的动作，把观察写回磁带；
  • 应用把磁带当作会话状态；
  • 开发工具用磁带做审计；
  • 算法用磁带调优智能体的提示；
  • 智能体从磁带生成微调数据。

执行模型

一个智能体（图中的 Agent B）读取到目前为止的整条磁带，选择这一步执行自己的哪个内部节点。节点是决定怎么提示 LLM 的小单元，一个智能体有几个节点由开发者决定。节点调用 LLM，LLM 提出一些思考或动作，写进磁带；然后编排器（orchestrator）调用环境执行还没处理的动作，拿到回复写入磁带，循环继续。执行模型很直接，但支持多个智能体，每个智能体还能把工作委派给子智能体，所以结构模块化、很灵活。

“磁带即数据”带来的好处：审计和调试很自然；可以有算法以磁带为输入，循环优化出更好的提示；还可以让智能体蒸馏一个复杂的“教师”智能体的工作，得到便宜得多的“学生”智能体，也就是通过磁带去优化底层 LLM。

04. 案例：把 405B 教师蒸馏成 8B 学生的填表助手

录像位置 0:23:53–0:32:08

一个两智能体的问答例子

Nicolas 先给了一个简单例子：一个回答公司财务状况的问答助手。主智能体和人类用户对话，它可以依赖一个做网页搜索的子智能体。这个两智能体结构配上前面的执行循环，就产生一条很细的磁带，记录所有智能体之间的交互、它们的内部独白和推理过程、采取的动作和环境的响应。这个例子可以用介绍用的 notebook 在笔记本电脑上复现。

GREADTH：衡量对话智能体的六个属性

目标是做出交互质量很高、运行又便宜的智能体。他们把想监控的属性拼成一个词 GREADTH（他说这个拼法是故意的）：

  • Grounded：有依据，不幻觉，永远说真话；
  • Responsive：响应用户；
  • Accurate：准确；
  • Disciplined：守规矩；
  • Transparent：透明；
  • Helpful：有帮助。

每个属性可以单独测量，也可以一起优化。

案例设置

任务是一个对话助手：把用户引导到正确的表单，并帮他把表单填完。企业里常有很复杂的表单，用来申请别人为你做某件工作。约束是对话体验要达到“五星”，他说想要 GPT-4 水平或更好的质量，同时计算成本要低。他们虚构了几家公司，训练用 FlyCorp、BigBankCorp、CoffeeCorp，测试用 DriveCorp、LuxuryCorp、ShopCorp，用来检验分布外（训练没见过的公司）的效果。

方法（幻灯片）：

  1. 用 19 个“用户智能体”（模拟用户）和一个 5 节点、基于 Llama 3.1 405B 的教师智能体对话，生成合成磁带。教师参数量大、运行很贵。
  2. 用这些磁带作为数据，微调一个 1 节点、基于 Llama 8B 的学生智能体，让它恢复大模型的表现。

结果

结果图的横轴是跑一百万轮对话的成本，纵轴是 GREADTH 分数。右上角是最大的智能体：Llama 405B 教师和零样本的 GPT-4o，分数都高，但都很贵，大约每百万轮对话 3 万到 4 万美元。用磁带当数据生成微调数据之后，微调过的 8B 学生达到和大模型相同的表现，运行成本低 300 多倍。幻灯片的结论写的是“学生以 300 倍更低的成本达到 GPT-4o 的表现”，另一页标题写的是“Student is 330x Cheaper”。

05. Web 智能体是什么，最简单的版本怎么做

录像位置 0:32:08–0:37:47

Web 智能体的循环和难点

Alex 说，有 API、有工具帮你执行的时候，API 智能体很好用；Web 智能体有望更通用，没有 API 的时候它像一个即兴演员，直接和用户界面交互，就像你我用软件那样。

结构就是熟悉的智能体循环：用户有一个目标（幻灯片的例子是“帮我的摇滚乐队订明年七八月的全球巡演”），Web 智能体是一个策略，感知环境（这里是浏览器）给出的观察，决定执行什么动作。这里的智能体就是一个 LLM，根据浏览器的观察选择动作。他列了四个难点：

  • 理解目标：弄懂人到底要什么（自然语言）。
  • 情境感知：看懂浏览器里显示的是什么，界面在展示什么。
  • 长程规划：你要的结果大多数时候不在当前页面上，要穿过一些菜单才能到达正确的页面，而这从当前的观察里不一定看得出来。
  • 动作执行：有了计划还要把动作正确执行出来，后面会看到这一点对现有智能体也很难。

最基础的 Web 智能体

假设用户说“下个长周末带我飞去 Yellowstone”。最简单的做法是拿你喜欢的 LLM 构造一个提示，里面放三样东西：任务描述（目标）；观察，比如网页的 HTML，上下文窗口够长就直接放原始 HTML；动作空间，也就是智能体允许做什么，能不能点控件、能不能填表单。把提示交给 LLM，让它根据观察输出想做的动作，再到浏览器里执行。执行一般用 Python 加 Playwright（一个浏览器自动化库），Selenium 也能做类似的事。

他用 MiniWoB 数据集里的一个例子演示提示的写法（幻灯片上的简化版）：

Task:
- Enter "Enola" into the text field and press Submit.

DOM (Web Page):
<html><body> ... </body></html>

Action space:
# Fill out a form field
fill(backend_id: str, value: str)
# Click an element
click(backend_id: str)
# Move the mouse to a location
mouse_move(x: float, y: float)

Answer Format:
<action>
Your actions
</action>

LLM 的回答可能是 fill('14', 'Enola') 然后 click('15')。他放了一个基于 GPT-4 的智能体照这样操作的录像。

已经很强，但很脆弱

接着他放了一个同样简单的智能体：GPT-4 加 ReAct 式提示，让模型先输出思考再输出动作。录像里它在替 Nicolas 填最近一次出差开会的报销单。Alex 说这让他很兴奋，可以想象这样的助手在浏览器里替我们自动完成任务，像是用户界面的下一次演进。

然后他说实话：这很脆弱。这是一个提示，现在能用；有几个很好的轶事般的例子，但要被实际采用，它得稳健，大多数时候都要成功，还要确保不会被网页里注入的内容越狱或劫持。另一个限制是慢：刚才的视频加速了 8 倍，实际上鼠标从一个点移到另一个点要等大约 15 秒，离流畅的用户界面还远。

06. Web 智能体怎么评测：几类基准

录像位置 0:37:47–0:41:55

因为需要稳健，大家花了很多力气做基准，想知道在轶事之外这些智能体实际表现如何。Alex 按类型梳理了一遍。

MiniWoB++：简单但不真实

MiniWoB 里是很简单的网页任务，比如填一个字段点提交，或者把一个方块从屏幕一边拖到另一边。是个好起点，但不真实。

基于轨迹的基准

后来出现了基于真实网站的基准。第一类基于轨迹：给人类标注者一个目标和一个网站，记录他们的动作（点了哪里、填了哪个字段），例子有 Mind2Web（Deng et al., 2023）和 WebLINX（Lù et al., 2024），有成千上万条人类生成的观察-动作轨迹。优点是网站真实。缺点有两个：评测主要看智能体的动作是否和“金标准轨迹”相似，没有考虑一个问题可能有别的解法；轨迹放在网上，可能被爬网训练的 LLM 记住。

一个例外是 NNetNav（Murty et al., 2024）。它用 LLM 生成轨迹：把智能体随机丢到互联网上某处，做一些随机动作，再回过头标注“什么目标会让人走到这里”。这样可以不靠人类标注生成成千上万条轨迹，既能用于评测也能用于微调，后面还会提到。

实时环境基准

另一个趋势是实时（live）基准：不看动作轨迹，看最终结果。比如任务做对了，数据库应该处于某个状态，那就直接检查数据库状态；或者是问答类，检查返回的答案对不对，不看你走了哪些步骤。好处是允许不同解法，被记住的风险也低，因为轨迹没有放在公开仓库里。实时基准又分两种：

  • 沙盒环境，在本地服务器上执行。例子是 WebArena 和 VisualWebArena：给一个目标，在 Reddit、GitLab 这类软件里完成操作，再检查终止条件判断是否成功。一切都在本地，带宽高，适合并行实验；缺点是只能用开源软件，本地安装复杂（比如 Docker）。
  • 开放网络环境，在远程服务器上执行。例子是 AssistantBench（Yoran et al., 2024）和他们的 WorkArena。更真实，有真实的网络延迟，可以支持非开源的网站，不用本地部署；缺点是可能不稳定，会有网络问题，跑基准需要联网。

07. WorkArena 和 WorkArena++

录像位置 0:41:55–0:50:19

基准开源，产品闭源

WorkArena 是一个远程托管的开源基准，约 600 个工作相关任务，在 ServiceNow 产品上执行（pip install browsergym-workarena）。他们的想法是，每天有几百万人在工作中用 ServiceNow，用它做基准很适合检验 Web 智能体能不能在工作场所帮上人。

最简单的一级（WorkArena L1）是和产品里几种基础组件交互：给列表排序或筛选，搜索知识库回答问题（比如“办公室 Wi-Fi 密码是多少”），读仪表盘回答“哪种物品库存最多”，填表单，下单等。

远程托管怎么实现：他们不能发一个包含 ServiceNow 的 Docker 镜像，那等于把产品代码给出去。办法是用“开发者实例”：任何人都可以在 developer.servicenow.com 申请一个产品的克隆，原本是给开发者学习写定制工具用的。基准就建在它上面：你提供实例的登录信息，智能体通过前端网页和它交互，验证则通过后端 API 查数据库状态，判断任务是否完成。

WorkArena++：真实的复杂工作流

他先放了 GPT-4 完成 L1 任务的录像：订一块 Apple Watch、读仪表盘、填表、排序列表。然后讲一个三级（L3）任务。智能体收到一张工单，指令只有一句“Please solve this.”，起点就是工单页面；工单里说不清楚怎么做可以参考知识库，并给了文章号。智能体要：

  1. 用菜单导航到知识库，找到对的文章，提取怎么继续的信息（比如怎么去仪表盘）；
  2. 打开仪表盘，读出哪种物品库存最少；
  3. 导航到服务目录（service catalog），下单补货。

三个高层步骤，中间有很多低层步骤和导航。Alex 打了个比方：把你丢进一个有很多门的房间，看不见门后是什么，你要走到对的地方，但不能探索太多，因为步数有限。

WorkArena++ 考察的能力（幻灯片分类）：

  • 规划和解决问题：一系列企业决策问题，比如工作量均衡（看哪个员工最忙，把他的一部分工作转给最闲的人）、带约束的排期、把工作分派给专家；
  • 读仪表盘并行动：比如补充 IT 资产库存；
  • 在列表、表单、知识库里搜索信息：比如查某用户的笔记本是否在保修期；
  • 读仪表盘、做计算、采取行动：预算管理（按预期回报选择投资方向）、报销管理；
  • 复杂记忆：在平台里到处收集零散信息后完成任务，比如给一个员工办离职；
  • 有些任务故意设计成不可行，智能体要识别出来，说“这做不到”，这需要批判性思考。

结果：远没有解决

他们做了人类评测，在 L2 和 L3 这些真实工作流上，人类评测者的平均成功率约 94%。L1 没有人类评测，他们最好的智能体成功率 42.7%。他说这个智能体本身不差，它在 WebArena 上达到 23.5%，是当时最高的分数之一。

到 L2，表里“很多零”（台下笑），有一点成功，但大部分任务做不对；到 L3，也就是前面那个例子，全部是零，而人类在这些任务上有 94% 的成功率。他说开头那些演示让人兴奋，但社区还有很多工作要做，他们认为这个基准能帮助推进。

为什么全是零，他总结了三类原因：

  • 规划失败：智能体只看到当前页面，不去探索；
  • 幻觉出控件：智能体会想象一个叫“solve task”的按钮，然后输出“点击 solve task”，给自己编了一条捷径；
  • 动作语法错误：输出动作时格式不对。

基准爆炸

新基准远不止 WorkArena，Web 智能体的基准加起来有几万个任务。幻灯片列出：

WebArena (Zhou et al., 2023)812

08. BrowserGym 和 AgentLab

录像位置 0:50:19–0:55:35

BrowserGym：统一的评测平台

为了统一评测，他们做了 BrowserGym（pip install browsergym），把大部分主要基准收进来，还在继续加，欢迎提 pull request。它提供：

  • 标准化的观察空间：HTML、可访问性树（HTML 的精简版本）、截图、聊天框等多种模态。
  • 标准化的动作空间：幻灯片上有三种写法，基于 bid 的 click(bid="103")，基于坐标的 mouse_click(x=47.2, y=152.6)，以及直接写 Python 的 page.get_by_label("Search").click()（标注为不安全）。bid 是 BrowserGym 自动给页面上每个控件分配的数字 ID，智能体说“点 2 号”，平台就用 Python Playwright 去执行。
  • 人类评测：WorkArena 的人类评测就是用它做的。人看到同样的聊天框和浏览器界面，可以给人分配一组任务的课程，人可以请求验证，或者放弃跳到下一个任务。

AgentLab：构建、调试和复现

AgentLab 是一套构建 Web 智能体的工具箱：提供简单的构建模块，提供理解智能体行为、找出为什么不工作的工具，还有跑大规模实验、保证可复现的工具。

其中一个工具叫 AgentXRay。他演示：选一个做过的实验，点开某个基准里的一个任务，再选一个随机种子，就能看到智能体当时看到的东西：截图、页面的可访问性树、智能体的推理过程、执行了哪些动作；顶部有一条时间线，给出性能剖析信息，推理花了多少时间、执行动作花了多少时间、走了多少步。

把可复现放在第一位

在不受自己控制的动态环境上做基准很难：网站会更新，通过 API 调用的 LLM 可能被悄悄更新，Python 包也在变。怎么让基准结果随时间仍可比较？AgentLab 正在做（GitHub 上已有一部分）：

  • 提取标准化的观察-动作轨迹；
  • 把“实验日志”上传到公开仓库，带上日期、各种包的版本、智能体配置和轨迹，尽量自动化；
  • 为主要基准做排行榜，分数可以根据上面这些信息自动复现，检查结果在环境变化之后是否仍然成立。

他说，把 AgentLab 和 BrowserGym 合起来，有了标准化的观察空间、动作空间、轨迹格式和公开的存储仓库，就有可能做分布式的轨迹收集：每个人都可以帮忙收集 Web 智能体在开放网络上的轨迹，汇成一个大仓库，以后用来微调、做出更好的智能体。幻灯片上的说法是可以在公开基准和开放网络上集体收集大规模微调数据。

09. Web 智能体的六个难题

录像位置 0:55:35–0:59:49

Alex 说有希望，他觉得未来一年这些基准上会有很大进展。幻灯片的副标题是“我们面对的毕竟是 World Wild Web”。他逐条讲了主要障碍：

长上下文理解

网站很大，动辄几万、几十万 token，连本该比原始 HTML 短的可访问性树也是这样。观察很长，而其中相关的信息很少，光是把它挑出来就是挑战。幻灯片提到检索可以帮忙，例子是 Dense Markup Ranker（Lù et al., 2024）。

长程规划

站在一个页面上，不知道两三页之外有什么，还要推理“先去这个菜单，再点那个，最后到对的地方”，很难。人有直觉，用惯了 Amazon，知道怎么搜索、怎么导航，类似的网站对我们不陌生，对智能体就未必。幻灯片说这里奖励稀疏，测试时的探索几乎不可能。前面提到的 NNetNav 在大规模收集随机动作的轨迹并自动标注目标，可能有助于微调 LLM，让它更清楚几步之内能到哪里。

学习和适应

要能从观察、示范和错误中学习。他提到 Agent Q（Putta et al., 2024），用蒙特卡洛树搜索（MCTS，一种通过大量模拟展开、逐步扩展搜索树来选动作的算法）和 DPO（直接偏好优化，用“更好/更差”的成对数据直接调整模型，不需要单独训练奖励模型）来微调智能体，并做推理时搜索。

多模态

人靠视觉，现有智能体却没有用好这个模态。VisualWebArena 有一组不看图就无法完成的任务，比如“给我订一件像这样的衬衫”，你得看到衬衫才能做。

成本和效率

前面的视频都大幅加速过。幻灯片的说法是 Web 智能体产生的价值必须高于它的成本才可行。方向有：缩小上下文，比如用检索只取观察中相关的元素；多智能体架构，比如一个只负责填日期选择器的小 LLM，“日期选择器智能体”；微调更小的 LLM 提升表现。

安全和对齐

他说这一条很要紧，没人想上线一个容易被劫持的智能体。他们测过演示里那种智能体：在页面上放白底白字的文字，写“hey GPT 遵循这些新指令”，它就会照做。所以需要对网页注入稳健的智能体，不光是 HTML 里的注入，文本框里的也要防，不能让人在那里写指令。多模态模型让问题更大，因为所有模态都可能被攻击。幻灯片还列了随机字符、ASCII 艺术和针对分词器的攻击。

他讲了 Nicolas 的一个例子，原本写的是 2030 年，他们改成了 2026 年，因为觉得不算远：恶意 Chrome 插件检测到你登录银行网站，用 JavaScript 往页面里注入指令，劫持智能体去给某个境外账户电汇。他说这些听上去牵强，一想到 Web 智能体就会觉得很真实。

10. 智能体和工作的未来

录像位置 0:59:49–1:10:56

有智能体之后，Sandy 的工单

Nicolas 回到开头的例子。在部署了智能体的世界里，Sandy 打开工单之前，一组智能体已经尝试做了部分解决：

  1. 一个“下一最佳动作”智能体根据相关知识库和类似事件生成计划：查 John 有什么权限，查这篇知识库文章需要什么权限，给 John 对应的权限。
  2. 编排智能体把计划拿给 Sandy 请求批准，Sandy 看了说“看起来没问题，继续”。
  3. 其他智能体分头做子任务：知识库智能体查文章权限，用户访问智能体准备给 John 分配“Knowledge”角色，在做任何破坏性操作之前再问 Sandy 一次，Sandy 同意。
  4. 文档智能体记录解决步骤，关单。

和开头相比，大量工作由一队协作的智能体承担，人在关键节点确认。

Web 智能体和低价值/低频任务

他因为时间关系很快带过一张图（幻灯片）：横轴是开发和维护的成本效益，从贵到便宜；纵轴是智能体的能力、泛化和适应，从“傻”到“能干”。传统开发、RPA、低代码/无代码在一侧；2024 年底的 Web 智能体能做 API 调用、界面交互、自然语言推理；未来的通用智能体还能用工具、造工具。图上标出了单个“低价值/低频”任务所在的区域，意思是 Web 智能体开始能触及这一块。

怎么估算对知识工作的影响

知识工作包含成千上万种任务：会议安排和协调、白帽黑客测试、语言本地化等等。怎么评估智能体对这么宽的职业范围的影响？

一个工具是 O*NET 数据库（字幕里把它归到美国劳工统计局，幻灯片的出处写的是 BLS 的标准职业分类和 O*NET）。它列出美国经济中的所有职业，每个职业有职位描述和日常要做的一组任务，可以免费下载。他的例子是“软件质量保证分析师和测试员”：有职位描述、任务清单和所需技能。评估影响的一个办法，就是逐条看这些任务，问每一条能被智能体自动化到什么程度。

他也展示了 McKinsey 几个月前报告里的技术采用曲线：在 OECD 国家，包括生成式 AI 在内的技术的预期采用曲线，分早期和晚期两种情景。他提醒，采用受很多因素限制，技术只是其中之一，幻灯片列的因素有：技术成熟度、集成速度、技术相对于劳动力的成本、技术扩散速度、供给约束（比如 GPU、监管）。只评估技术成熟度只能看到一部分图景。

两种评估方式：

自上而下自下而上
做法逐个分析 O*NET 里每个职业的每项任务，“猜”有 AI 之后这项任务是什么样、是否还需要人；可以用 GPT-4 自动完成把 O*NET 的每项任务对应到 WorkArena 这类知识工作代理基准里的任务，跟踪 AI 完成这些任务的能力，再映射回职业被自动化的概率
优点覆盖面广图景细致
挑战图景模糊覆盖零散

他说两种都不完美，一种模糊，一种不完整，合起来可以做三角定位，估计技术采用的可能速度、职位描述会因为部分工作交给智能体而变化多快。这类分析可以帮助决策者和公司规划员工再培训项目，让技术推进对所有人有益。

人和 AI 的两种分工

他引用了 Harvard Business School 和 BCG 几个月前的一项研究（Navigating the Jagged Technological Frontier），研究人们怎样和先进的生成式 AI 一起工作，发现了两种分工模式：

  • Centaur（半人马）：战略性地划分“人的任务”和“AI 的任务”，人规划高层任务，把大块工作外包给 AI。幻灯片列出 AI 可以从人的直觉出发，梳理问题领域、收集信息、做数据分析、润色人写的内容。
  • Cyborg（赛博格）：任务层面的紧密、细粒度协作。人可以让 AI 扮演某个角色、从例子里学任务、给出逻辑解释、深入展开、回应反驳。

他说现在还很早，用户体验和人机交互研究有很大空间，去弄清对每个人最有效的协作模式，也许取决于性格类型，肯定取决于要做的工作。

延伸资料

最后给了两张时间线。一张是 LLM 智能体框架和基准：2022 年 LangChain；2023 年 AutoGPT、AutoGen、Crew.ai，基准有 ToolBench、AgentBench、GAIA（幻灯片注：人类 92%，带插件的 GPT-4 15%）、MLAgentBench；2024 年框架有 LangGraph、LlamaIndex Workflows、TapeAgents，基准有 SWE-Bench、τ-Bench、InsightBench。另一张是 Web 智能体研究里程碑：从 2017 年的 World of Bits / MiniWoB，到 WebGPT、DeepMind 的 Learning to Control Computers、Mind2Web、WebArena（幻灯片注：最好的 GPT-4 解决 11%，人类 78%）、Google 的 WebAgent，再到 2024 年的 VisualWebArena、WebLINX、WebVoyager、WebCanvas、AssistantBench、OSWorld、NNetNav、WorkArena 和 WorkArena++（幻灯片注：当时最好的模型只有个位数表现）。

结尾他开玩笑说该让“讲课智能体”去做明年的课件了，然后感谢 ServiceNow 的同事。TapeAgents、WorkArena、BrowserGym、AgentLab 都开源，欢迎 pull request。

这一讲值得记下的原话
